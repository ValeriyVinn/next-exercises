# Autoprefixer — автоматичні CSS-префікси

> **Autoprefixer** — це PostCSS-плагін, який автоматично додає необхідні браузерні префікси до CSS-властивостей на основі заданого списку підтримуваних браузерів.
>
> Його головна мета — допомогти CSS працювати в потрібних браузерах без необхідності вручну писати всі варіанти властивостей із префіксами.

---

## 1. Що таке Autoprefixer?

Різні браузери можуть підтримувати CSS-властивості по-різному. Історично деякі властивості потребували спеціальних префіксів.

Наприклад:

- `-webkit-` — використовувався браузерами на основі WebKit та Blink для окремих CSS-властивостей.
- `-moz-` — використовувався Firefox для окремих властивостей.
- `-ms-` — використовувався Internet Explorer для окремих властивостей.
- `-o-` — використовувався старими версіями Opera для окремих властивостей.

### Приклад CSS до обробки

    .card {
        display: flex;
        user-select: none;
    }

### Можливий результат після обробки

Залежно від цільових браузерів Autoprefixer може створити приблизно такий CSS:

    .card {
        display: -webkit-box;
        display: -ms-flexbox;
        display: flex;

        -webkit-user-select: none;
        -moz-user-select: none;
        -ms-user-select: none;
        user-select: none;
    }

Це лише ілюстрація: реальний результат залежить від версій браузерів у конфігурації Browserslist і актуальних даних про підтримку CSS.

**Важливо:** Autoprefixer не додає всі можливі префікси до кожної властивості. Він визначає, які префікси потрібні для заданих браузерів.

---

## 2. Для чого потрібен Autoprefixer?

Без Autoprefixer розробник міг би вручну підтримувати кілька варіантів однієї властивості.

    .element {
        -webkit-user-select: none;
        -moz-user-select: none;
        -ms-user-select: none;
        user-select: none;
    }

Це створює декілька проблем:

- CSS стає довшим.
- Легше припуститися помилки.
- Складніше оновлювати код.
- Необхідно стежити за змінами браузерної підтримки.
- У різних проєктах можуть використовуватися різні цільові браузери.

Autoprefixer автоматизує цю роботу.

Розробник пише сучасний CSS:

    .element {
        user-select: none;
    }

Інструмент сам додає потрібні префікси під час обробки стилів.

### Основні переваги

1. Менше ручної роботи.
2. Чистіший вихідний CSS.
3. Автоматизація сумісності з браузерами.
4. Можливість централізовано визначати підтримувані браузери.
5. Інтеграція з PostCSS та сучасними збірниками проєктів.

---

## 3. Autoprefixer і PostCSS

Autoprefixer — не окремий CSS-компілятор. Це плагін для PostCSS.

### Що таке PostCSS?

**PostCSS** — інструмент, який аналізує CSS, представляє його у вигляді структури даних і дозволяє плагінам змінювати цей CSS.

У спрощеному вигляді процес виглядає так:

    Вихідний CSS
        ↓
    PostCSS
        ↓
    Autoprefixer
        ↓
    CSS із потрібними префіксами
        ↓
    Готовий CSS

У реальному проєкті можуть бути й інші етапи: Sass, CSS Nesting, оптимізація, мінімізація тощо.

### Розподіл відповідальності

| Інструмент | Призначення |
|---|---|
| CSS | Мова опису стилів |
| PostCSS | Платформа для обробки CSS плагінами |
| Autoprefixer | Додавання потрібних браузерних префіксів |
| Browserslist | Визначення цільових браузерів |
| cssnano | Мінімізація CSS |
| Vite / Next.js | Інструменти розробки та збирання проєкту |

**Запам'ятай:** PostCSS — це платформа, Autoprefixer — один із плагінів, а Browserslist допомагає визначити, для яких браузерів потрібно готувати CSS.

---

## 4. Що таке CSS-префікси?

Префікс — це частина назви CSS-властивості або значення, яка історично використовувалася для експериментальних чи специфічних браузерних реалізацій.

### Приклади

    .example {
        -webkit-user-select: none;
        -moz-user-select: none;
        -ms-user-select: none;
        user-select: none;
    }

Інший історичний приклад:

    .example {
        background: -webkit-linear-gradient(red, blue);
        background: linear-gradient(red, blue);
    }

Синтаксис залежить від конкретної властивості. Не можна вважати, що будь-яку CSS-властивість достатньо скопіювати з префіксами `-webkit-`, `-moz-` і `-ms-`.

### Чи потрібні префікси сьогодні?

Для багатьох сучасних CSS-властивостей префікси вже не потрібні в актуальних браузерах.

Наприклад, у звичайному сучасному проєкті достатньо писати:

    .container {
        display: flex;
        display: grid;
    }

Проте для окремих можливостей, особливо тих, які мають специфічні вимоги підтримки, префікси можуть залишатися потрібними.

Тому правильний підхід — не додавати префікси навмання, а використовувати Autoprefixer і відповідний список браузерів.

## 5. Browserslist — зв'язок із цільовими браузерами

Autoprefixer використовує Browserslist, щоб визначити, які браузери потрібно підтримувати.

Browserslist — це формат конфігурації, який також використовується іншими інструментами екосистеми JavaScript.

### Приклад конфігурації в `package.json`

    {
        "browserslist": [
            "> 0.5%",
            "last 2 versions",
            "Firefox ESR",
            "not dead"
        ]
    }

Це приклад синтаксису Browserslist, а не універсальна рекомендація для кожного проєкту. Перед використанням потрібно перевірити, чи відповідають вибрані критерії вимогам продукту.

### Що означають запити?

| Запит | Значення |
|---|---|
| `> 0.5%` | Браузери з часткою використання понад 0,5% у вибраних даних |
| `last 2 versions` | Дві останні версії кожного відповідного браузера |
| `Firefox ESR` | Версія Firefox із розширеною підтримкою |
| `not dead` | Виключення браузерів, які Browserslist вважає застарілими за визначеними критеріями |

Результат залежить від актуальної бази даних браузерів і правил Browserslist.

### Альтернативні запити

    "browserslist": [
        "defaults"
    ]

Або:

    "browserslist": [
        "last 2 Chrome versions",
        "last 2 Firefox versions",
        "last 2 Safari versions"
    ]

Не потрібно механічно копіювати чужу конфігурацію. Список має відповідати реальній аудиторії та вимогам підтримки браузерів.

### Важливе розрізнення

Browserslist не додає префікси самостійно.

Він визначає цільові браузери, а Autoprefixer використовує цю інформацію під час обробки CSS.

## 6. Встановлення Autoprefixer

Якщо проєкт використовує Node.js і npm, Autoprefixer можна встановити як dev-залежність.

### Крок 1. Переконайся, що проєкт має `package.json`

У терміналі, перебуваючи в кореневій теці проєкту:

    npm init -y

Виконуй цю команду лише тоді, коли проєкт ще не має `package.json`.

### Крок 2. Встанови PostCSS та Autoprefixer

    npm install -D postcss autoprefixer

Після цього в `package.json` з'являться відповідні dev-залежності.

### Для чого потрібні ці пакети?

- `postcss` — обробник CSS.
- `autoprefixer` — плагін для додавання префіксів.

**Важливо:** встановлення пакетів саме по собі не означає, що всі CSS-файли проєкту автоматично оброблятимуться. Потрібно під'єднати плагін до збірника або налаштувати окремий процес обробки CSS.

---

## 7. Налаштування Autoprefixer через PostCSS

Розглянемо базову конфігурацію для проєкту, у якому PostCSS запускається окремо.

### Структура проєкту

    my-project/
    ├── src/
    │   └── styles.css
    ├── dist/
    ├── package.json
    └── postcss.config.mjs

### Крок 1. Створи `postcss.config.mjs`

    export default {
        plugins: {
            autoprefixer: {},
        },
    };

Це конфігурація PostCSS із плагіном Autoprefixer.

### Крок 2. Додай CSS

Файл `src/styles.css`:

    .button {
        display: flex;
        user-select: none;
        transition: transform 200ms ease;
    }

### Крок 3. Запусти обробку

Для окремого запуску PostCSS можна додатково встановити CLI:

    npm install -D postcss-cli

Потім додати скрипт у `package.json`:

    {
        "scripts": {
            "build:css": "postcss src/styles.css -o dist/styles.css"
        }
    }

Після цього виконай:

    npm run build:css

Перед запуском переконайся, що тека `dist` існує. За потреби створи її вручну або додай окрему команду підготовки.

У результаті `dist/styles.css` міститиме CSS, оброблений PostCSS та Autoprefixer.

**Зверни увагу:** для більшості сучасних проєктів із Vite або Next.js окремий запуск `postcss-cli` зазвичай не потрібний. Збірник може запускати PostCSS автоматично.

## 8. Autoprefixer у Vite

Vite підтримує PostCSS і може автоматично використовувати конфігурацію PostCSS проєкту.

### Встановлення

    npm install -D postcss autoprefixer

### Конфігурація `postcss.config.mjs`

    export default {
        plugins: {
            autoprefixer: {},
        },
    };

Після цього запускай Vite звичайним способом:

    npm run dev

Або створи production-збірку:

    npm run build

Якщо в проєкті немає власного PostCSS-конфіга, Vite може використовувати вбудовану обробку CSS. Додавання конфігурації дає змогу явно під'єднати потрібні плагіни.

### Типовий цикл роботи

    Написання CSS
        ↓
    Vite обробляє CSS
        ↓
    PostCSS запускає Autoprefixer
        ↓
    Готовий CSS для браузера

### Що варто пам'ятати?

- Не потрібно вручну запускати Autoprefixer для кожного CSS-файлу.
- Зміни CSS обробляються в межах процесу розробки та збірки.
- Наявність плагіна потрібно перевіряти за конфігурацією й результатом збірки.
- Налаштування цільових браузерів впливає на результат.

## 9. Autoprefixer у Next.js

У Next.js обробка CSS відбувається в межах системи збирання фреймворку.

Next.js уже має власний процес обробки стилів, тому перед додаванням Autoprefixer потрібно перевірити, які можливості сумісності забезпечує поточна версія Next.js і чи справді потрібен окремий плагін.

### Чи потрібно встановлювати Autoprefixer?

Не завжди.

Для звичайного Next.js-проєкту не варто додавати плагіни без конкретної потреби.

Якщо проєкту потрібна власна конфігурація PostCSS, можна встановити необхідні пакети:

    npm install -D postcss autoprefixer

Приклад `postcss.config.mjs`:

    export default {
        plugins: {
            autoprefixer: {},
        },
    };

**Важливо:** власна конфігурація PostCSS може змінити стандартний процес обробки CSS у Next.js. Перед її створенням перевір документацію саме тієї версії Next.js, яку використовує проєкт, і збережи необхідні стандартні плагіни.

Не слід вважати, що цей конфіг потрібно додавати до кожного Next.js-проєкту.

## 10. Autoprefixer і CSS Modules

CSS Modules дають змогу створювати локальні стилі компонентів, наприклад у React або Next.js.

Приклад `Button.module.css`:

    .button {
        display: flex;
        align-items: center;
        justify-content: center;
        user-select: none;
    }

Сам факт використання CSS Modules не змінює принцип роботи Autoprefixer.

Якщо збірник обробляє CSS Modules через PostCSS із підключеним Autoprefixer, плагін може додати потрібні префікси.

### Приклад компонента React

    import styles from "./Button.module.css";

    export default function Button() {
        return (
            <button className={styles.button}>
                Натисни мене
            </button>
        );
    }

Тут є дві різні задачі:

- CSS Modules локалізують назви класів.
- Autoprefixer допомагає з браузерною сумісністю окремих CSS-властивостей.

Це незалежні можливості, які можуть працювати разом.

## 11. Autoprefixer і сучасні CSS-властивості

Autoprefixer не замінює перевірку браузерної підтримки.

Наприклад:

    .container {
        display: grid;
        gap: 1rem;
    }

Autoprefixer не повинен розглядатися як універсальний спосіб зробити будь-яку сучасну CSS-властивість сумісною з будь-яким старим браузером.

Він додає префікси там, де це потрібно згідно з його даними про підтримку властивостей.

### Що Autoprefixer робить?

- Додає певні браузерні префікси.
- Ураховує задані цільові браузери.
- Автоматизує відповідну частину роботи із сумісністю CSS.

### Чого він не робить?

- Не створює повноцінні поліфіли для CSS.
- Не реалізує властивості, яких браузер узагалі не підтримує.
- Не гарантує повну сумісність у всіх браузерах.
- Не замінює тестування реальних браузерів.
- Не перетворює автоматично будь-який новий CSS-синтаксис на старий еквівалент.

Наприклад, для складних можливостей CSS можуть знадобитися інші інструменти або альтернативні стилі.

## 12. Autoprefixer і postcss-preset-env

Ці інструменти пов'язані з PostCSS, але мають різні завдання.

### Autoprefixer

Основна задача — додавання потрібних браузерних префіксів.

### postcss-preset-env

Допомагає використовувати певні сучасні можливості CSS, перетворюючи частину синтаксису на варіанти, які можуть працювати в ширшому колі браузерів.

Наприклад, залежно від конфігурації та підтримки функцій, він може обробляти деякі можливості сучасного CSS.

### Порівняння

| Можливість | Autoprefixer | postcss-preset-env |
|---|---|---|
| Додавання браузерних префіксів | Так | Може використовувати Autoprefixer у відповідному процесі |
| Перетворення деяких сучасних можливостей CSS | Не основна задача | Так |
| Використання Browserslist | Так | Так |
| Є PostCSS-інструментом | Так, плагін | Так, плагін |

Не потрібно встановлювати обидва інструменти автоматично. Вибір залежить від того, які саме перетворення потрібні проєкту.

## 13. Autoprefixer і cssnano

Autoprefixer та cssnano також виконують різні задачі.

### Autoprefixer

Допомагає підготувати CSS до роботи в цільових браузерах, додаючи потрібні префікси.

### cssnano

Оптимізує та мінімізує CSS для production.

Наприклад, вихідний код:

    .card {
        margin: 0;
        padding: 16px;
        color: #000000;
    }

Після мінімізації код може стати коротшим:

    .card{margin:0;padding:16px;color:#000}

Це лише ілюстрація можливої оптимізації.

### Типова схема

    Вихідний CSS
        ↓
    Потрібні перетворення CSS
        ↓
    Autoprefixer
        ↓
    cssnano
        ↓
    Оптимізований CSS

Точний порядок плагінів залежить від задач і конфігурації. Не слід вважати, що всі інструменти завжди потрібно запускати саме в такому порядку.

## 14. Як перевірити результат роботи Autoprefixer?

Не потрібно здогадуватися, чи працює плагін. Перевіряй фактичний результат обробки CSS.

### Спосіб 1. Переглянути вихідний CSS

Якщо проєкт генерує CSS у теці `dist`, відкрий відповідний файл.

Шукай властивості, для яких Autoprefixer має додати префікси з огляду на цільові браузери.

Наприклад:

    display: -ms-flexbox;
    display: flex;

Це лише приклад можливого результату, а не гарантований вивід сучасної конфігурації.

### Спосіб 2. Перевірити конфігурацію

Переконайся, що:

1. Autoprefixer встановлений.
2. PostCSS завантажує конфігурацію.
3. Плагін включений у список.
4. Browserslist визначає потрібні цільові браузери.
5. Збірник справді обробляє потрібний CSS-файл.

### Спосіб 3. Перевірити production-збірку

Запусти:

    npm run build

Потім перевір згенеровані файли CSS.

Якщо збірник використовує іншу теку для результатів, шукай CSS саме там.

### Спосіб 4. Перевірити браузери

Навіть якщо CSS оброблений правильно, важливо перевірити його в браузерах, які реально потрібно підтримувати.

Наявність префіксів не гарантує повної сумісності.

## 15. Як подивитися підтримувані браузери?

Для роботи з Browserslist можна використовувати команду:

    npx browserslist

Вона показує список браузерів, які відповідають активній конфігурації Browserslist у проєкті.

Якщо конфігурації немає, інструмент може використовувати значення за замовчуванням або повідомити про відповідну проблему — це залежить від версії та оточення.

### Для чого це потрібно?

Команда допомагає зрозуміти:

- які браузери входять до цільового списку;
- чи підхоплюється конфігурація;
- чому результат обробки CSS відрізняється від очікуваного;
- чи відповідає список вимогам проєкту.

За потреби можна перевірити конфігурацію для конкретного середовища, якщо проєкт використовує окремі набори браузерів для розробки й production.

## 16. Типові помилки

### Помилка 1. Вважати, що Autoprefixer потрібно підключати до кожного CSS-файлу вручну

У сучасному проєкті з Vite або іншим налаштованим збірником обробка може відбуватися автоматично.

**Правильно:** один раз налаштувати процес обробки CSS і перевірити результат.

### Помилка 2. Думати, що після встановлення пакетів усе вже працює

Команда:

    npm install -D postcss autoprefixer

встановлює пакети, але сама по собі не налаштовує всі можливі збірники.

**Правильно:** перевірити конфігурацію та спосіб обробки CSS у конкретному проєкті.

### Помилка 3. Вручну додавати всі можливі префікси

    .button {
        -webkit-user-select: none;
        -moz-user-select: none;
        -ms-user-select: none;
        user-select: none;
    }

Це може бути зайвим, якщо збірник автоматично обробляє властивість.

**Правильно:** писати звичайний CSS, а потрібні префікси доручати інструменту.

### Помилка 4. Використовувати застарілий список браузерів без перевірки

Вимоги до підтримки браузерів можуть змінюватися.

**Правильно:** визначити реальну аудиторію проєкту й обрати відповідний Browserslist.

### Помилка 5. Очікувати, що Autoprefixer підтримує будь-який новий CSS

Autoprefixer не є універсальним транспілятором усіх можливостей CSS.

**Правильно:** для нових можливостей перевіряти сумісність і за потреби використовувати інші інструменти або альтернативні стилі.

### Помилка 6. Вважати, що більше префіксів завжди краще

Зайві префікси не роблять CSS автоматично надійнішим.

**Правильно:** генерувати лише те, що потрібно для визначених браузерів.

### Помилка 7. Змінювати PostCSS-конфіг Next.js без перевірки стандартних плагінів

Власна конфігурація може змінити стандартну обробку CSS.

**Правильно:** звіритися з документацією поточної версії фреймворку та зберегти потрібні плагіни.

### Помилка 8. Не перевіряти згенерований CSS

Наявність конфігурації ще не доводить, що потрібний файл обробляється.

**Правильно:** переглянути результат збірки та протестувати стилі в потрібних браузерах.

## 17. Практичні завдання

### Завдання 1. Зрозумій призначення Autoprefixer

Напиши CSS:

    .box {
        display: flex;
        user-select: none;
        transition: transform 200ms ease;
    }

Відповідай на запитання:

1. Які властивості можуть потребувати префіксів залежно від цільових браузерів?
2. Яку роботу виконує Autoprefixer?
3. Чому не варто вручну додавати всі можливі префікси?

### Завдання 2. Створи мінімальну конфігурацію PostCSS

1. Створи окремий навчальний проєкт.
2. Ініціалізуй `package.json`.
3. Установи `postcss`, `autoprefixer` і `postcss-cli`.
4. Створи `postcss.config.mjs`.
5. Додай CSS у `src/styles.css`.
6. Налаштуй скрипт `build:css`.
7. Запусти обробку.
8. Переглянь згенерований файл.

Мета — зрозуміти весь шлях від вихідного CSS до обробленого.

### Завдання 3. Зміни Browserslist

1. Додай конфігурацію Browserslist.
2. Виконай `npx browserslist`.
3. Подивись на список браузерів.
4. Зміни конфігурацію.
5. Повтори команду.
6. Порівняй результат.

Поясни, як зміна цільових браузерів може вплинути на CSS, який генерує Autoprefixer.

### Завдання 4. Досліди Flexbox

Вихідний CSS:

    .container {
        display: flex;
        flex-direction: column;
        justify-content: center;
        align-items: center;
    }

Оброби CSS через Autoprefixer.

Перевір, чи додалися префікси для твоєї конфігурації.

Не очікуй обов'язкової появи всіх історичних варіантів: результат залежить від цільових браузерів.

### Завдання 5. Підключи Autoprefixer до Vite

1. Створи невеликий проєкт Vite.
2. Додай CSS із Flexbox та іншими властивостями.
3. Підключи Autoprefixer через PostCSS.
4. Запусти `npm run build`.
5. Перевір результат у production-файлах.

### Завдання 6. Порівняй Autoprefixer і cssnano

Побудуй процес, у якому один інструмент відповідає за потрібні префікси, а інший — за мінімізацію CSS.

Поясни, чому ці інструменти не є взаємозамінними.

### Завдання 7. Перевір реальну потребу в префіксах

Обери три CSS-властивості та перевір їхню підтримку в потрібних браузерах.

Для кожної властивості запиши:

- чи потрібен префікс;
- для яких браузерів;
- чи достатньо Autoprefixer;
- чи потрібно тестувати альтернативний CSS.

## 20. Мінішпаргалка

### Встановити пакети

    npm install -D postcss autoprefixer

### Додати CLI для окремої обробки CSS

    npm install -D postcss-cli

### Створити `postcss.config.mjs`

    export default {
        plugins: {
            autoprefixer: {},
        },
    };

### Приклад Browserslist у `package.json`

    {
        "browserslist": [
            "defaults"
        ]
    }

### Перевірити цільові браузери

    npx browserslist

### Приклад скрипту для обробки CSS

    {
        "scripts": {
            "build:css": "postcss src/styles.css -o dist/styles.css"
        }
    }

### Запустити обробку

    npm run build:css

### Створити production-збірку Vite

    npm run build

### Запам'ятай головне

- **Autoprefixer** автоматично додає потрібні браузерні префікси.
- **PostCSS** забезпечує інфраструктуру для обробки CSS плагінами.
- **Browserslist** визначає цільові браузери.
- **cssnano** оптимізує та мінімізує CSS.
- **postcss-preset-env** може перетворювати деякі сучасні можливості CSS.
- Префікси залежать від цільових браузерів.
- Autoprefixer не гарантує повної сумісності CSS.
- Після налаштування завжди перевіряй результат збірки.
