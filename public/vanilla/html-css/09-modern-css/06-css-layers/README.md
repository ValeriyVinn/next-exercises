# CSS Cascade Layers (`@layer`)

## 1. Що таке CSS Cascade Layers?

**CSS Cascade Layers (`@layer`)** — це механізм CSS, який дозволяє явно керувати пріоритетом груп стилів під час каскадування.

За допомогою `@layer` можна розділити CSS на логічні шари, наприклад:

- `reset` — скидання стандартних стилів браузера;
- `base` — базові стилі елементів;
- `layout` — структура сторінки;
- `components` — стилі компонентів;
- `utilities` — допоміжні класи;
- `overrides` — спеціальні перевизначення.

Це допомагає уникнути ситуації, коли доводиться постійно збільшувати специфічність селекторів або використовувати `!important`, щоб перевизначити попередні стилі.

### Приклад без `@layer`

    /* styles.css */

    button {
        background-color: blue;
    }

    .card button {
        background-color: green;
    }

    #app .card button {
        background-color: red;
    }

У міру розвитку проєкту селектори можуть ставати дедалі складнішими. Щоб керувати стилями, доводиться враховувати специфічність кожного селектора.

### Приклад з `@layer`

    @layer base, components, utilities;

    @layer base {
        button {
            background-color: blue;
        }
    }

    @layer components {
        .card button {
            background-color: green;
        }
    }

    @layer utilities {
        button {
            background-color: red;
        }
    }

Для звичайних декларацій, які мають однакову важливість, стилі в пізнішому шарі мають перевагу над стилями в попередньому шарі.

У цьому прикладі кнопка буде червоною, оскільки `utilities` розташований після `components`.

Важливо: порядок шарів впливає на каскад, але не скасовує всі інші правила CSS. Важливість декларацій, походження стилів, специфічність і порядок оголошення також мають значення.

---

## 2. Навіщо потрібні CSS Layers?

CSS Layers особливо корисні у великих проєктах, де стилі розподілені між багатьма файлами та компонентами.

### Основні переваги

1. **Передбачуваний каскад.** Можна заздалегідь визначити, які групи стилів мають перевагу.
2. **Менша залежність від специфічності.** Не потрібно створювати надмірно складні селектори.
3. **Зручна архітектура CSS.** Стилі можна розподіляти за призначенням.
4. **Краще керування сторонніми стилями.** Наприклад, CSS бібліотеки можна розмістити в окремому шарі.
5. **Простіше підтримувати проєкт.** Розробник бачить не лише селектор, а й шар, до якого належить правило.

### Коли варто використовувати `@layer`?

- У проєктах із великою кількістю CSS-файлів.
- У дизайн-системах.
- У застосунках із багатьма компонентами.
- Коли підключаються стилі сторонніх бібліотек.
- Коли часто виникають конфлікти між базовими стилями та стилями компонентів.

Для невеликої сторінки використання шарів необов'язкове, але це корисний інструмент для розуміння сучасної архітектури CSS.

## 3. Синтаксис `@layer`

Є кілька способів оголошення шарів.

### 3.1. Оголошення шару з блоком стилів

    @layer base {
        body {
            margin: 0;
            font-family: Arial, sans-serif;
        }
    }

Усі правила всередині блоку належать до шару `base`.

### 3.2. Оголошення кількох шарів

    @layer reset, base, layout, components, utilities;

Цей запис оголошує шари та встановлює їхній порядок.

Для звичайних декларацій пріоритет зростає зліва направо:

    reset < base < layout < components < utilities

Тобто `utilities` має перевагу над `components`, якщо декларації мають однакову важливість і походження.

Оголошення порядку шарів краще розміщувати на початку основного CSS-файлу.

### 3.3. Створення шарів у різних місцях

    @layer base, components, utilities;

    @layer base {
        h1 {
            font-size: 2rem;
        }
    }

    @layer components {
        .card {
            padding: 1rem;
        }
    }

    @layer utilities {
        .text-center {
            text-align: center;
        }
    }

Шари можна наповнювати стилями в різних місцях файлу або в різних CSS-файлах.

### 3.4. Створення порожнього шару

    @layer reset;
    @layer base;
    @layer components;

Це оголошує шари без додавання правил. Пізніше в них можна помістити стилі.

Якщо порядок важливий, доцільно відразу оголосити всі основні шари в одному списку:

    @layer reset, base, layout, components, utilities;

Так легше побачити загальну структуру каскаду.

## 4. Як працює порядок шарів?

Розглянемо приклад:

    @layer base, components, utilities;

    @layer base {
        .button {
            background-color: blue;
        }
    }

    @layer components {
        .button {
            background-color: green;
        }
    }

    @layer utilities {
        .button {
            background-color: red;
        }
    }

Результат: фон кнопки буде червоним.

Причина — усі три правила:

- мають однакову важливість;
- належать до одного походження CSS;
- використовують однаковий селектор;
- розміщені в різних шарах.

Для звичайних декларацій перемагає правило з пізнішого шару.

### Важливе уточнення

Порядок шарів визначається їхньою першою появою, якщо інший порядок не був установлений раніше.

    @layer base, components, utilities;

    @layer components {
        .button {
            color: green;
        }
    }

    @layer base {
        .button {
            color: blue;
        }
    }

Хоча блок `base` написаний після `components`, правило з `components` має перевагу, оскільки порядок шарів був оголошений заздалегідь.

Не плутай два поняття:

- **Порядок шарів** — пріоритет груп стилів.
- **Порядок правил усередині одного шару** — звичайні правила каскаду, зокрема специфічність і порядок появи декларацій.

## 5. CSS Layers і специфічність

Одна з головних переваг `@layer` — можливість організувати пріоритети без надмірного ускладнення селекторів.

### Приклад

    @layer components, utilities;

    @layer components {
        #main .card button {
            background-color: blue;
        }
    }

    @layer utilities {
        .button-red {
            background-color: red;
        }
    }

    <button class="button-red">Натисни мене</button>

Якщо кнопка відповідає селектору `#main .card button`, то для звичайних декларацій у цьому прикладі шар `utilities` має перевагу над `components`, навіть попри нижчу специфічність його селектора.

Але є нюанс: HTML-кнопка повинна фактично відповідати селектору з першого правила, щоб виник конфлікт. Сам по собі селектор `#main .card button` не застосовується до кнопки поза елементами `#main` і `.card`.

### Правильна ментальна модель

Для звичайних декларацій в одному походженні каскад спочатку враховує пріоритет шару, а потім специфічність у межах відповідного рівня.

Отже, не потрібно автоматично вважати, що селектор з ID завжди переможе селектор класу. Якщо правила знаходяться в різних шарах, порядок шарів може бути важливішим за специфічність.

---

## 6. Неіменовані шари

Шари можуть бути іменованими або неіменованими.

### Іменований шар

    @layer components {
        .card {
            border-radius: 1rem;
        }
    }

Шар має ім'я `components`, тому його легко використовувати повторно.

### Неіменований шар

    @layer {
        .special {
            color: purple;
        }
    }

Такий запис створює анонімний шар.

Анонімний шар не має імені, за яким можна було б звернутися до нього в інших місцях. Його порядок визначається моментом створення.

У більшості навчальних і робочих проєктів краще використовувати іменовані шари, оскільки вони роблять архітектуру зрозумілішою.

---

## 7. Вкладені шари

Усередині одного шару можна створювати підшари.

    @layer components {
        @layer buttons, cards, forms;
    }

    @layer components.buttons {
        .button {
            padding: 0.75rem 1rem;
        }
    }

    @layer components.cards {
        .card {
            padding: 1.5rem;
        }
    }

    @layer components.forms {
        .form-field {
            margin-bottom: 1rem;
        }
    }

Підшари дозволяють деталізувати архітектуру CSS.

Наприклад:

    @layer reset, base, layout, components, utilities;

    @layer components {
        @layer buttons, cards, forms;
    }

Структура може виглядати так:

    reset
    base
    layout
    components
        ├── buttons
        ├── cards
        └── forms
    utilities

Вкладені шари зручно використовувати у великих дизайн-системах.

### Важливо

Підшари є частиною батьківського шару. Їхній порядок визначається правилами вкладеного каскаду, а не просто глобальним розташуванням усіх назв у одному списку.

Не варто створювати надмірно глибоку ієрархію без практичної потреби.

## 8. CSS Layers і `!important`

Це один із найважливіших нюансів `@layer`.

Для звичайних декларацій:

    @layer base, components, utilities;

    @layer base {
        .button {
            color: blue;
        }
    }

    @layer utilities {
        .button {
            color: red;
        }
    }

Результат: `red`.

Але для декларацій з `!important` порядок шарів працює навпаки.

### Приклад

    @layer base, components, utilities;

    @layer base {
        .button {
            color: blue !important;
        }
    }

    @layer utilities {
        .button {
            color: red !important;
        }
    }

Результат: `blue`.

Для важливих декларацій перший шар має перевагу над пізнішими шарами.

Отже:

| Тип декларації | Пріоритет шарів |
|---|---|
| Звичайна декларація | Пізніший шар має перевагу |
| Декларація з `!important` | Раніший шар має перевагу |

Це правило допомагає захищати важливі декларації, але може здивувати, якщо не враховувати його під час налагодження стилів.

### Практична рекомендація

Не використовуй `!important` як стандартний спосіб керування каскадом. Спочатку визнач правильний порядок шарів та архітектуру стилів.

## 9. Неявний шар і стилі поза `@layer`

Правила, які не належать до жодного явного шару, вважаються не-шаровими.

### Приклад

    @layer components {
        button {
            background-color: blue;
        }
    }

    button {
        background-color: orange;
    }

Для звичайних декларацій правило поза шарами має перевагу над правилом усередині явного шару.

Тому фон кнопки буде помаранчевим.

Це важливо пам'ятати, коли в проєкті одночасно використовуються CSS Layers і звичайні стилі.

### Типова помилка

Розробник створює шари й очікує, що правило в найпізнішому шарі переможе будь-яке інше правило.

Але правило поза явними шарами може мати перевагу над усіма звичайними деклараціями всередині цих шарів.

Тому для передбачуваного каскаду бажано послідовно організувати основні стилі в шарах, а не змішувати два підходи без необхідності.

## 10. Використання `@import` із шарами

CSS дозволяє імпортувати файл безпосередньо в певний шар.

### Приклад

    @layer reset, base, components, utilities;

    @import url("./reset.css") layer(reset);
    @import url("./base.css") layer(base);
    @import url("./components.css") layer(components);

Це корисно, коли стилі розділені на окремі файли.

### Важливе правило

`@import` має бути розміщений на початку таблиці стилів — до звичайних правил і більшості інших at-rules. Дозволені винятки, наприклад певні директиви `@charset` і `@layer` для попереднього оголошення порядку шарів.

Не можна довільно переносити `@import` у середину CSS після звичайних правил.

### Приклад структури проєкту

    styles/
    ├── main.css
    ├── reset.css
    ├── base.css
    ├── layout.css
    ├── components.css
    └── utilities.css

У `main.css`:

    @layer reset, base, layout, components, utilities;

    @import url("./reset.css") layer(reset);
    @import url("./base.css") layer(base);
    @import url("./layout.css") layer(layout);
    @import url("./components.css") layer(components);
    @import url("./utilities.css") layer(utilities);

Це дає змогу централізовано визначати порядок стилів.

У сучасних проєктах з інструментами збірки можна використовувати й інші способи об'єднання CSS. Головне — перевіряти, як саме збірка зберігає порядок шарів.

## 11. CSS Layers для сторонніх бібліотек

CSS Layers особливо корисні, коли проєкт використовує зовнішні стилі.

Наприклад, стороння бібліотека може містити селектори з високою специфічністю. Перевизначати їх звичайними правилами буває складно.

Якщо стилі бібліотеки можна імпортувати в окремий шар, їхній пріоритет можна контролювати через порядок шарів.

### Приклад

    @layer vendor, base, components, utilities;

    @import url("./vendor.css") layer(vendor);

    @layer components {
        .button {
            background-color: green;
        }
    }

    @layer utilities {
        .button-red {
            background-color: red;
        }
    }

Для звичайних декларацій стилі в `components` і `utilities` матимуть перевагу над стилями з `vendor`.

Це працює навіть тоді, коли селектори сторонньої бібліотеки специфічніші, якщо правила мають однакове походження та важливість.

### Перевага

Можна організувати пріоритети так:

    vendor < reset < base < layout < components < utilities

Проте порядок потрібно вибирати відповідно до конкретного проєкту. Наприклад, reset зазвичай доцільно виконувати до базових стилів, але сторонні стилі можуть вимагати окремого місця в каскаді.

## 12. Практичний приклад: невеликий сайт

Розглянемо базову структуру CSS для сторінки.

### HTML

    <!DOCTYPE html>
    <html lang="uk">
    <head>
        <meta charset="UTF-8">
        <meta name="viewport" content="width=device-width, initial-scale=1.0">
        <title>CSS Cascade Layers</title>
        <link rel="stylesheet" href="styles.css">
    </head>
    <body>
        <header class="site-header">
            <h1 class="site-title">Мій навчальний сайт</h1>
        </header>

        <main class="container">
            <article class="card">
                <h2 class="card__title">CSS Layers</h2>
                <p class="card__text">
                    Вивчаємо керування каскадом CSS.
                </p>
                <button class="button button--primary">
                    Докладніше
                </button>
            </article>
        </main>
    </body>
    </html>

### CSS

    /* 1. Порядок шарів */
    @layer reset, base, layout, components, utilities;

    /* 2. Скидання стилів */
    @layer reset {
        *,
        *::before,
        *::after {
            box-sizing: border-box;
        }

        body,
        h1,
        h2,
        p {
            margin: 0;
        }

        button {
            font: inherit;
        }
    }

    /* 3. Базові стилі */
    @layer base {
        body {
            font-family: Arial, sans-serif;
            line-height: 1.5;
            color: #222;
            background-color: #f4f6f8;
        }

        h1,
        h2 {
            line-height: 1.2;
        }
    }

    /* 4. Структура сторінки */
    @layer layout {
        .site-header {
            padding: 1.5rem;
            background-color: #1f2937;
            color: white;
        }

        .container {
            width: min(100% - 2rem, 70rem);
            margin-inline: auto;
            padding-block: 2rem;
        }
    }

    /* 5. Компоненти */
    @layer components {
        .card {
            padding: 1.5rem;
            border-radius: 1rem;
            background-color: white;
            box-shadow: 0 0.25rem 1rem rgb(0 0 0 / 8%);
        }

        .card__title {
            margin-bottom: 0.75rem;
        }

        .card__text {
            margin-bottom: 1rem;
        }

        .button {
            padding: 0.75rem 1rem;
            border: 0;
            border-radius: 0.5rem;
            cursor: pointer;
        }

        .button--primary {
            background-color: #2563eb;
            color: white;
        }
    }

    /* 6. Допоміжні класи */
    @layer utilities {
        .text-center {
            text-align: center;
        }

        .button--primary {
            background-color: #0f766e;
        }
    }

### Що відбудеться?

Кнопка матиме фон `#0f766e`, оскільки:

1. `.button--primary` оголошено в `components`.
2. Цей самий клас оголошено в `utilities`.
3. `utilities` розташований після `components`.
4. Обидві декларації звичайні та мають однакову специфічність.

Зверни увагу: в HTML кнопка має два класи — `button` і `button--primary`. Тому її базові стилі походять від `.button`, а колір визначається `.button--primary`.

## 13. CSS Layers у багатофайловому проєкті

У реальному проєкті краще відокремлювати правила за призначенням.

### Приклад структури

    styles/
    ├── main.css
    ├── reset.css
    ├── base.css
    ├── layout.css
    ├── components/
    │   ├── buttons.css
    │   ├── cards.css
    │   └── forms.css
    └── utilities.css

### Варіант з `@import`

У `main.css`:

    @layer reset, base, layout, components, utilities;

    @import url("./reset.css") layer(reset);
    @import url("./base.css") layer(base);
    @import url("./layout.css") layer(layout);
    @import url("./components/buttons.css") layer(components);
    @import url("./components/cards.css") layer(components);
    @import url("./components/forms.css") layer(components);
    @import url("./utilities.css") layer(utilities);

У файлах можна писати звичайний CSS, оскільки імпорт уже поміщає їхні правила в потрібні шари.

Наприклад, у `components/buttons.css`:

    .button {
        padding: 0.75rem 1rem;
        border-radius: 0.5rem;
    }

    .button--primary {
        background-color: royalblue;
        color: white;
    }

### Що варто пам'ятати?

- Установлюй порядок шарів у головному файлі.
- Не покладайся на випадковий порядок підключення стилів.
- Уникай дублювання однакових правил у різних шарах без причини.
- Перевіряй конфігурацію інструментів збірки.
- Не забувай про правила `!important` і декларації поза шарами.

## 14. CSS Layers і CSS Modules

CSS Modules — це спосіб локалізувати імена класів у модульних CSS-файлах. CSS Layers — це механізм керування пріоритетом каскаду.

Вони вирішують різні завдання й можуть використовуватися разом.

### Приклад CSS Modules

    @layer components {
        .card {
            padding: 1rem;
            border-radius: 0.75rem;
        }
    }

У React-компоненті:

    import styles from "./Card.module.css";

    export default function Card() {
        return (
            <article className={styles.card}>
                <h2>Навчальна картка</h2>
                <p>Приклад використання CSS Modules.</p>
            </article>
        );
    }

CSS Modules допомагають уникати конфліктів імен класів, а `@layer` — керувати пріоритетом стилів.

### Важливо для Next.js

У Next.js можна організовувати стилі через CSS Modules і глобальні CSS-файли. Проте потрібно враховувати, як саме глобальні стилі підключені, як збирається CSS і чи збережено оголошений порядок шарів.

Не варто автоматично вважати, що CSS Modules самі по собі замінюють `@layer`, або навпаки.

## 15. Типові помилки

### Помилка 1. Очікування, що специфічність завжди перемагає

    @layer base, utilities;

    @layer base {
        #app .button {
            color: blue;
        }
    }

    @layer utilities {
        .button {
            color: red;
        }
    }

Якщо обидва селектори відповідають тому самому елементу, звичайна декларація з `utilities` може перемогти декларацію з `base`, навіть попри вищу специфічність першого селектора.

**Як уникнути:** спочатку перевіряй порядок шарів, а потім специфічність.

### Помилка 2. Забути про стилі поза шарами

    @layer components {
        .button {
            color: blue;
        }
    }

    .button {
        color: red;
    }

Для звичайних декларацій червоний колір переможе, оскільки правило знаходиться поза явними шарами.

**Як уникнути:** організуй основні стилі послідовно й уникай випадкового змішування шарових і нешарових правил.

### Помилка 3. Неправильно використовувати `!important`

    @layer base, utilities;

    @layer base {
        .button {
            color: blue !important;
        }
    }

    @layer utilities {
        .button {
            color: red !important;
        }
    }

Синій колір переможе, бо для `!important` порядок шарів обернений.

**Як уникнути:** пам'ятай, що важливі декларації мають окремі правила каскаду.

### Помилка 4. Оголошувати порядок шарів у випадковому порядку

    @layer components;
    @layer base;

Якщо `components` створений першим, а `base` — другим, то для звичайних декларацій `base` матиме перевагу над `components`.

Це може бути протилежним до очікуваної архітектури.

**Як уникнути:** оголошуй порядок централізовано:

    @layer reset, base, layout, components, utilities;

### Помилка 5. Намагатися перевизначити шар тільки додаванням нового правила

Додавання нового правила в пізнішому місці не гарантує, що воно переможе. Потрібно врахувати шар, специфічність, важливість та походження декларації.

**Як уникнути:** під час налагодження перевіряй усі фактори каскаду в DevTools.

### Помилка 6. Створювати занадто багато шарів

Надмірна кількість шарів і підшарів ускладнює підтримку.

**Як уникнути:** почни з невеликої кількості логічних шарів і додавай нові лише тоді, коли вони розв'язують конкретну проблему.

## 16. Налагодження CSS Layers у DevTools

Коли стиль не застосовується, відкрий інструменти розробника браузера.

### Послідовність перевірки

1. Вибери потрібний HTML-елемент у вкладці Elements.
2. Перевір вкладку Styles.
3. Знайди декларацію, яка задає потрібну властивість.
4. Перевір, чи є конкуруючі декларації.
5. Визнач, до якого шару належить кожне правило.
6. Перевір специфічність, `!important` і правила поза шарами.
7. За потреби відкрий вкладку Computed, щоб перевірити кінцеве значення властивості.

### Приклад проблеми

    @layer base, components, utilities;

    @layer components {
        .card .button {
            background-color: blue;
        }
    }

    @layer utilities {
        .button {
            background-color: red;
        }
    }

Якщо кнопка знаходиться всередині `.card`, обидва селектори можуть відповідати їй.

Для звичайних декларацій `utilities` має перевагу над `components`, тому кнопка буде червоною, хоча селектор `.card .button` має вищу специфічність.

Під час налагодження не потрібно одразу додавати ще один клас або `!important`. Спочатку перевір, чи відповідає результат задуму архітектури шарів.

---

## 17. Підтримка браузерами

CSS Cascade Layers підтримуються сучасними браузерами.

Для навчальних і нових вебпроєктів `@layer` можна вважати стандартним інструментом організації CSS. Якщо проєкт повинен працювати в застарілих браузерах, перевір матрицю підтримки цільових браузерів і вимоги до збірки.

Важливо розуміти: CSS Layers не є заміною звичайному каскаду. Це додатковий рівень керування ним.

## 18. Практичні завдання

### Завдання 1. Визнач колір кнопки

    @layer base, components, utilities;

    @layer base {
        button {
            color: blue;
        }
    }

    @layer components {
        button {
            color: green;
        }
    }

    @layer utilities {
        button {
            color: red;
        }
    }

Питання: який колір матиме кнопка?

Очікуваний результат: `red`, оскільки `utilities` — останній шар серед шарів зі звичайними деклараціями.

### Завдання 2. Зміни порядок шарів

    @layer utilities, components, base;

    @layer base {
        button {
            color: blue;
        }
    }

    @layer components {
        button {
            color: green;
        }
    }

    @layer utilities {
        button {
            color: red;
        }
    }

Питання: який колір матиме кнопка?

Очікуваний результат: `blue`, оскільки `base` тепер є останнім шаром у визначеному порядку.

### Завдання 3. Додай `!important`

    @layer base, utilities;

    @layer base {
        button {
            color: blue !important;
        }
    }

    @layer utilities {
        button {
            color: red !important;
        }
    }

Питання: який колір матиме кнопка?

Очікуваний результат: `blue`, оскільки порядок пріоритету шарів для важливих декларацій обернений.

### Завдання 4. Перевір правило поза шарами

    @layer components {
        button {
            color: blue;
        }
    }

    button {
        color: orange;
    }

Питання: який колір матиме кнопка?

Очікуваний результат: `orange`, оскільки звичайна декларація поза явними шарами має перевагу над звичайною декларацією всередині шару.

### Завдання 5. Побудуй власну архітектуру

Створи п'ять шарів:

    @layer reset, base, layout, components, utilities;

Розподіли між ними:

- `reset` — `box-sizing`, скидання відступів;
- `base` — шрифт, кольори сторінки, базова типографіка;
- `layout` — контейнер, header, main, footer;
- `components` — кнопки, картки, форми;
- `utilities` — класи вирівнювання та відображення.

Перевір, як змінюється результат, коли одна й та сама властивість оголошена в різних шарах.

## 19. Рівні володіння CSS Layers

### Core

- Розуміти призначення `@layer`.
- Уміти створювати шари.
- Знати, що порядок шарів впливає на каскад.
- Розуміти різницю між звичайними правилами й `!important`.
- Уміти читати прості приклади з кількома шарами.

### Junior

- Самостійно організовувати базові шари проєкту.
- Розуміти взаємодію шарів і специфічності.
- Вміти пояснити, чому правило з пізнішого шару перемагає правило з ранішого.
- Знати, як поводяться правила поза явними шарами.
- Налагоджувати конфлікти стилів у DevTools.

### Middle

- Проєктувати архітектуру шарів для багатофайлового CSS.
- Організовувати сторонні стилі та стилі застосунку.
- Використовувати вкладені шари там, де це справді потрібно.
- Ураховувати CSS Layers у проєктах із CSS Modules і збіркою.
- Пояснювати особливості каскаду важливих декларацій.

### Senior

- Визначати загальну стратегію каскаду для дизайн-системи.
- Проєктувати масштабовану архітектуру стилів для великої команди.
- Враховувати шари, походження стилів, важливість і специфічність у складних конфліктах.
- Планувати інтеграцію сторонніх стилів та міграцію на шарову архітектуру.
- Встановлювати правила, які зменшують потребу в `!important` і надмірно специфічних селекторах.

    @layer reset, base, layout, components, utilities;

    @layer components {
        .card {
            padding: 1rem;

### Повторне наповнення шару

    @layer components {
        .button {
            border-radius: 0.5rem;
        }
    }

### Вкладені шари

    @layer components {
        @layer buttons, cards;
    }

### Імпорт у шар

    @import url("./components.css") layer(components);

### Пріоритет звичайних декларацій

    /* Пізніший шар має перевагу */
    @layer base, components, utilities;

### Пріоритет важливих декларацій

    /* Для !important порядок шарів обернений */
    @layer base, components, utilities;

### Правила поза шарами

    @layer components {
        button {
            color: blue;
        }
    }

    button {
        color: red;
    }

Звичайне правило поза явними шарами має перевагу над звичайним правилом усередині шару.

## 22. Що потрібно запам'ятати

1. `@layer` — це механізм керування каскадом CSS.
2. Шари допомагають визначати пріоритет груп стилів без надмірної специфічності.
3. Для звичайних декларацій пізніший шар має перевагу над ранішим.
4. Для декларацій із `!important` порядок шарів обернений.
5. Звичайні декларації поза явними шарами мають перевагу над звичайними деклараціями всередині шарів.
6. Порядок шарів краще оголошувати централізовано на початку основного CSS.
7. Шари можуть бути вкладеними.
8. CSS можна імпортувати безпосередньо в певний шар.
9. CSS Layers доповнюють звичайний каскад, а не замінюють його.
10. Під час налагодження завжди враховуй шар, походження, важливість, специфічність і порядок правил.

**Головна ідея:** CSS Layers дозволяють керувати пріоритетом груп стилів на рівні архітектури проєкту. Замість того щоб постійно ускладнювати селектори, ти заздалегідь визначаєш, які категорії CSS повинні мати перевагу.
