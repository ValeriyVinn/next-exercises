# Modern Layout Techniques

## 1. Що таке Modern Layout Techniques?

**Modern Layout Techniques** — це сучасні підходи до побудови структури вебсторінок за допомогою CSS.

Раніше розробники часто використовували таблиці, `float` і складні комбінації `position` для створення макетів. Сьогодні основними інструментами компонування є:

- **Flexbox** — для розташування елементів в одному вимірі.
- **CSS Grid** — для двовимірних макетів із рядками та колонками.
- **Container Queries** — для адаптації компонента до розміру його контейнера.
- **Subgrid** — для узгодження внутрішніх сіток вкладених елементів із батьківською сіткою.
- **Intrinsic Sizing** — для компонування з урахуванням природного розміру вмісту.
- **Logical Properties** — для стилів, незалежних від фізичного напрямку сторінки.
- **Modern Alignment** — для точного вирівнювання елементів.
- **Responsive Patterns** — для створення гнучких макетів без зайвої кількості медіазапитів.

Мета сучасного компонування — створювати макети, які автоматично пристосовуються до різних розмірів екрана, обсягу контенту та структури сторінки.

## 2. Основні принципи сучасного компонування

### 2.1. Від фіксованих розмірів до гнучких

Старий підхід:

    .container {
        width: 1200px;
    }

Такий контейнер може виходити за межі екрана на вузьких пристроях.

Сучасний підхід:

    .container {
        width: min(100% - 2rem, 75rem);
        margin-inline: auto;
    }

Тут:

- `100% - 2rem` залишає відступи з боків;
- `75rem` обмежує максимальну ширину;
- `min()` вибирає менше зі значень;
- `margin-inline: auto` центрує контейнер по горизонталі в типовому горизонтальному письмі.

### 2.2. Від позиціювання до систем компонування

Не варто використовувати `position: absolute` для побудови всього макета.

    /* Небажаний підхід для загального компонування */
    .sidebar {
        position: absolute;
        left: 0;
        top: 100px;
        width: 250px;
    }

Такий елемент вилучається з нормального потоку документа, тому інші елементи не враховують його розмір.

Краще використовувати Grid:

    .page {
        display: grid;
        grid-template-columns: 16rem minmax(0, 1fr);
        gap: 2rem;
    }

Тепер основний контент і бічна панель є частинами спільного макета.

### 2.3. Від адаптації до пристрою до адаптації до простору

Медіазапити дозволяють реагувати на характеристики viewport — області перегляду сторінки.

Container Queries дозволяють компоненту реагувати на розмір власного контейнера.

Це особливо корисно, коли одна картка може відображатися в широкій колонці, вузькому сайдбарі або модальному вікні.

## 3. Flexbox: компонування в одному вимірі

**Flexbox** призначений для розташування елементів у рядку або колонці.

### Приклад

    .navigation {
        display: flex;
        align-items: center;
        justify-content: space-between;
        gap: 1rem;
    }

    .navigation__links {
        display: flex;
        align-items: center;
        gap: 1.5rem;
    }

Основні властивості:

| Властивість | Призначення |
|---|---|
| `display: flex` | Створює flex-контейнер |
| `flex-direction` | Визначає напрямок головної осі |
| `justify-content` | Розподіляє простір уздовж головної осі |
| `align-items` | Вирівнює елементи вздовж поперечної осі |
| `align-self` | Вирівнює окремий елемент |
| `flex-wrap` | Дозволяє переносити елементи |
| `flex-grow` | Дозволяє елементу збільшуватися |
| `flex-shrink` | Визначає можливість зменшення |
| `flex-basis` | Визначає початковий розмір елемента |
| `gap` | Встановлює проміжки між елементами |

### Гнучкий рядок карток

    .card-list {
        display: flex;
        flex-wrap: wrap;
        gap: 1rem;
    }

    .card {
        flex: 1 1 16rem;
    }

Картки намагатимуться мати базову ширину `16rem`, але зможуть збільшуватися, зменшуватися та переноситися на нові рядки.

### Коли використовувати Flexbox?

- Навігація.
- Панелі інструментів.
- Рядки кнопок.
- Вирівнювання іконки та тексту.
- Розміщення елементів форми.
- Компоненти з одним основним напрямком.

**Правило:** якщо основне завдання — розподілити елементи вздовж однієї осі, почни з Flexbox.

## 4. CSS Grid: двовимірне компонування

**CSS Grid** дозволяє створювати макети з рядками та колонками.

### Приклад

    .dashboard {
        display: grid;
        grid-template-columns: 16rem minmax(0, 1fr);
        grid-template-rows: auto 1fr;
        gap: 1.5rem;
    }

Grid зручний, коли потрібно контролювати одночасно горизонтальне й вертикальне розташування елементів.

### Адаптивна сітка карток

    .card-grid {
        display: grid;
        grid-template-columns: repeat(
            auto-fit,
            minmax(min(100%, 16rem), 1fr)
        );
        gap: 1.5rem;
    }

Цей варіант дозволяє браузеру автоматично визначати кількість колонок залежно від доступної ширини.

Розглянемо основні поняття:

- `grid-template-columns` — визначає колонки.
- `grid-template-rows` — визначає рядки.
- `fr` — частка доступного простору.
- `minmax()` — задає мінімальний і максимальний розмір.
- `repeat()` — повторює визначення доріжок.
- `auto-fit` — дозволяє вмістити максимально можливу кількість доріжок і розтягнути наявні.
- `auto-fill` — зберігає місце для доріжок, які могли б поміститися, навіть якщо вони порожні.
- `grid-template-areas` — задає іменовану структуру макета.

### Коли використовувати Grid?

- Основний макет сторінки.
- Галереї.
- Каталоги товарів.
- Панелі керування.
- Складні сітки карток.
- Макети з бічною панеллю та основним контентом.

**Правило:** якщо потрібно контролювати рядки й колонки як єдину систему, почни з Grid.

## 5. Flexbox чи Grid?

| Завдання | Рекомендований інструмент |
|---|---|
| Навігація в один рядок | Flexbox |
| Іконка поруч із текстом | Flexbox |
| Рядок кнопок | Flexbox |
| Галерея з колонками й рядками | Grid |
| Макет сторінки із сайдбаром | Grid |
| Складна панель керування | Grid |
| Розподіл елементів з переносом | Flexbox або Grid |
| Картки з автоматичними колонками | Grid |
| Компонент із двома чіткими напрямками компонування | Grid |

Це не суворе правило. Flexbox і Grid можна поєднувати.

### Приклад комбінування

    .product-grid {
        display: grid;
        grid-template-columns: repeat(
            auto-fit,
            minmax(min(100%, 18rem), 1fr)
        );
        gap: 1.5rem;
    }

    .product-card {
        display: flex;
        flex-direction: column;
        gap: 1rem;
    }

    .product-card__actions {
        display: flex;
        flex-wrap: wrap;
        gap: 0.75rem;
        margin-top: auto;
    }

Grid відповідає за розташування карток, Flexbox — за внутрішню структуру кожної картки.

## 6. Intrinsic Sizing: розміри на основі вмісту

**Intrinsic Sizing** — це підхід, за якого розміри елементів визначаються з урахуванням вмісту та доступного простору.

Основні значення:

- `min-content` — мінімальний розмір, потрібний для вмісту без небажаного переповнення; точна поведінка залежить від типу вмісту.
- `max-content` — розмір, необхідний для відображення вмісту без звичайного перенесення рядків.
- `fit-content` — розмір, який намагається використати доступний простір, не перевищуючи обмежень вмісту та контейнера.
- `minmax()` — діапазон між мінімальним і максимальним розмірами.
- `auto` — автоматичний розмір, поведінка якого залежить від контексту компонування.

### Приклад

    .content {
        width: fit-content;
        max-width: 100%;
    }

### Grid із мінімальними розмірами

    .layout {
        display: grid;
        grid-template-columns: minmax(15rem, 1fr) 2fr;
        gap: 1rem;
    }

Перша колонка має мінімум `15rem`, а доступний простір розподіляється між колонками з урахуванням їхніх коефіцієнтів.

### Чому `minmax(0, 1fr)` таке поширене?

    .main {
        display: grid;
        grid-template-columns: 16rem minmax(0, 1fr);
    }

За замовчуванням Grid-елементи можуть мати автоматичний мінімальний розмір, пов'язаний із вмістом. Через це довгий текст або широка таблиця іноді розтягують колонку.

`minmax(0, 1fr)` дозволяє другій колонці зменшуватися нижче її автоматичного мінімального розміру.

За потреби окремому елементу також можна встановити:

    .main-content {
        min-width: 0;
    }

Це особливо корисно для довгих рядків, таблиць і вкладених макетів.

## 7. Container Queries: адаптація до контейнера

**Container Queries** дозволяють змінювати стилі елемента залежно від розміру контейнера, а не лише viewport.

### Приклад

    .card-wrapper {
        container-type: inline-size;
    }

    .card {
        display: grid;
        gap: 1rem;
    }

    @container (min-width: 35rem) {
        .card {
            grid-template-columns: 12rem minmax(0, 1fr);
            align-items: center;
        }
    }

Коли контейнер стає достатньо широким, картка переходить до двоколонкового макета.

### Іменовані контейнери

    .sidebar {
        container-type: inline-size;
        container-name: sidebar;
    }

    @container sidebar (min-width: 24rem) {
        .recommendation {
            display: grid;
            grid-template-columns: 6rem minmax(0, 1fr);
            gap: 1rem;
        }
    }

Іменований контейнер корисний, коли на сторінці є кілька контейнерів і потрібно чітко визначити, до якого з них прив'язаний запит.

### Коли використовувати Container Queries?

- Картки, які використовуються в різних частинах сайту.
- Компоненти дизайн-системи.
- Віджети.
- Бічні панелі.
- Компоненти, які можуть з'являтися в модальному вікні або в основному контенті.

### Важливе уточнення

Для `@container` потрібен відповідний контейнер. Наприклад, `container-type: inline-size` створює контейнер для запитів щодо його розміру по inline-осі.

Container Queries не замінюють медіазапити. Медіазапити залишаються корисними для адаптації всієї сторінки до viewport.

## 8. Subgrid: спільна сітка для вкладених елементів

**Subgrid** дозволяє вкладеному Grid використовувати доріжки батьківської сітки замість визначення незалежних доріжок.

Це корисно, коли картки мають різний вміст, але їхні заголовки, описи та кнопки потрібно вирівняти між собою.

### Приклад

    .card-grid {
        display: grid;
        grid-template-columns: repeat(3, minmax(0, 1fr));
        gap: 1.5rem;
    }

    .card {
        display: grid;
        grid-row: span 3;
        grid-template-rows: subgrid;
        gap: 0.75rem;
    }

У цьому прикладі кожна картка займає три рядки батьківської сітки та використовує її рядки як підсітку.

Щоб результат був передбачуваним, потрібно правильно спроєктувати розміщення карток і рядків батьківського Grid.

### Коли використовувати Subgrid?

- Картки з однаковою структурою.
- Порівняльні таблиці.
- Каталоги з вирівнюваними заголовками.
- Складні вкладені макети.
- Компоненти, в яких потрібно узгодити рядки або колонки з батьківською сіткою.

### Коли Subgrid не потрібен?

Якщо картки не повинні вирівнювати внутрішні елементи між собою, звичайний Grid буде простішим.

## 9. `aspect-ratio`: керування пропорціями

Властивість `aspect-ratio` дозволяє задавати співвідношення ширини та висоти елемента.

### Приклад

    .thumbnail {
        width: 100%;
        aspect-ratio: 16 / 9;
        object-fit: cover;
    }

Це типовий варіант для мініатюр відео, зображень і карток.

### Квадратні картки

    .avatar {
        width: 8rem;
        aspect-ratio: 1;
        border-radius: 50%;
        object-fit: cover;
    }

### Картка з фіксованим співвідношенням

    .video-frame {
        width: 100%;
        aspect-ratio: 16 / 9;
        overflow: hidden;
        border-radius: 1rem;
    }

    .video-frame iframe {
        width: 100%;
        height: 100%;
        border: 0;
    }

### Що потрібно пам'ятати?

`aspect-ratio` задає бажане співвідношення сторін, але фактичний розмір також залежить від інших властивостей, доступного простору та вмісту.

Не потрібно без потреби одночасно фіксувати і ширину, і висоту, якщо мета — зберегти гнучке співвідношення сторін.

## 10. `min()`, `max()` і `clamp()` у компонуванні

Функції `min()`, `max()` і `clamp()` допомагають створювати гнучкі розміри без великої кількості медіазапитів.

### `min()`

Вибирає менше значення.

    .container {
        width: min(100% - 2rem, 75rem);
        margin-inline: auto;
    }

Контейнер не перевищує `75rem` і залишає бокові відступи, коли доступного простору достатньо для такого розрахунку.

### `max()`

Вибирає більше значення.

    .section {
        padding-block: max(2rem, 5vh);
    }

Відступ буде не меншим за `2rem` або більшим, якщо `5vh` перевищує це значення.

### `clamp()`

Обмежує значення мінімумом і максимумом.

    .hero-title {
        font-size: clamp(2rem, 1.2rem + 3vw, 4rem);
    }

    .section {
        padding-block: clamp(2rem, 5vw, 5rem);
    }

Це дозволяє поступово змінювати розмір залежно від доступного простору.

### Де використовувати?

- Ширина контейнерів.
- Внутрішні відступи.
- Розміри заголовків.
- Проміжки між секціями.
- Мінімальна ширина елементів.

## 11. `gap`: сучасні проміжки між елементами

Властивість `gap` задає проміжки між рядками та колонками у Flexbox і Grid.

### Flexbox

    .toolbar {
        display: flex;
        align-items: center;
        gap: 1rem;
    }

### Grid

    .gallery {
        display: grid;
        grid-template-columns: repeat(3, minmax(0, 1fr));
        gap: 1rem 1.5rem;
    }

У Grid запис `gap: 1rem 1.5rem` означає:

- перше значення — проміжок між рядками;
- друге значення — проміжок між колонками.

### Чому `gap` зручніший за зовнішні відступи?

За допомогою `gap` можна керувати простором між сусідніми елементами без додаткових правил для першого або останнього елемента.

    /* Простий підхід */
    .items {
        display: flex;
        flex-wrap: wrap;
        gap: 1rem;
    }

Це зазвичай простіше, ніж призначати `margin` кожному елементу й окремо прибирати зайві відступи.

## 12. Logical Properties у компонуванні

Логічні властивості визначають розміри та відступи відносно напрямку письма, а не фізичних сторін екрана.

### Фізичні властивості

    .card {
        margin-left: 1rem;
        padding-right: 1rem;
        border-left: 2px solid blue;
    }

### Логічні властивості

    .card {
        margin-inline-start: 1rem;
        padding-inline-end: 1rem;
        border-inline-start: 2px solid blue;
    }

Логічні властивості полегшують підтримку мов із різними напрямками письма.

Корисні відповідності:

| Фізична властивість | Логічна властивість |
|---|---|
| `margin-left` | `margin-inline-start` або `margin-inline-end` залежно від потрібного боку |
| `padding-top` | `padding-block-start` |
| `padding-bottom` | `padding-block-end` |
| `width` | `inline-size` |
| `height` | `block-size` |
| `min-width` | `min-inline-size` |
| `max-width` | `max-inline-size` |
| `border-left` | `border-inline-start` або `border-inline-end` залежно від потрібного боку |

### Приклад гнучкого контейнера

    .content {
        max-inline-size: 75rem;
        margin-inline: auto;
        padding-inline: 1rem;
    }

Це допомагає писати CSS, який менше залежить від конкретного напрямку письма.

## 13. Modern Alignment: сучасне вирівнювання

Сучасний CSS надає єдині підходи до вирівнювання у Flexbox і Grid.

### Центрування вмісту

    .center {
        display: grid;
        place-items: center;
        min-block-size: 15rem;
    }

`place-items` — скорочений запис для `align-items` і `justify-items`.

### Центрування по головній осі у Flexbox

    .actions {
        display: flex;
        justify-content: center;
        align-items: center;
        gap: 1rem;
    }

### Розподіл елементів

    .header {
        display: flex;
        justify-content: space-between;
        align-items: center;
        gap: 1rem;
    }

### Вирівнювання всередині Grid

    .grid {
        display: grid;
        place-items: center;
    }

Важливо розрізняти:

- `justify-content` — розподіляє вміст уздовж відповідної осі;
- `align-items` — вирівнює елементи в межах контейнера;
- `justify-items` — вирівнює елементи в Grid по inline-осі;
- `align-self` — змінює вирівнювання окремого елемента;
- `place-items` — скорочений запис для двох властивостей вирівнювання елементів.

Точний напрямок осей залежить від моделі компонування та `writing-mode`.

---

## 14. Responsive Layout Patterns

Сучасний адаптивний дизайн часто можна побудувати за допомогою гнучких розмірів і Grid без великої кількості медіазапитів.

### Патерн 1. Автоматична сітка

    .grid {
        display: grid;
        grid-template-columns: repeat(
            auto-fit,
            minmax(min(100%, 17rem), 1fr)
        );
        gap: 1.5rem;
    }

Кількість колонок залежить від доступного простору.

### Патерн 2. Контейнер з обмеженою шириною

    .container {
        width: min(100% - 2rem, 72rem);
        margin-inline: auto;
    }

Контент не розтягується безмежно на широких екранах.

### Патерн 3. Дві колонки з можливістю перенесення

    .content-layout {
        display: grid;
        grid-template-columns:
            repeat(auto-fit, minmax(min(100%, 20rem), 1fr));
        gap: 2rem;
    }

Якщо простору достатньо, елементи розташовуються в кілька колонок; якщо ні — переходять у доступну кількість колонок.

### Патерн 4. Адаптивна навігація

    .navigation {
        display: flex;
        flex-wrap: wrap;
        align-items: center;
        gap: 1rem;
    }

Цей патерн дозволяє переносити елементи навігації, але для складних меню може знадобитися окрема мобільна структура.

### Патерн 5. Бічна панель і контент

    .page-layout {
        display: grid;
        grid-template-columns: 16rem minmax(0, 1fr);
        gap: 2rem;
    }

    @media (max-width: 48rem) {
        .page-layout {
            grid-template-columns: 1fr;
        }
    }

Тут медіазапит змінює структуру сторінки, коли дві колонки стають надто вузькими.

## 15. `position: sticky` у сучасних макетах

`position: sticky` дозволяє елементу поводитися як звичайний елемент потоку, доки він не досягне заданої межі прокручування.

### Приклад

    .sidebar {
        position: sticky;
        top: 1rem;
        align-self: start;
    }

    .page-layout {
        display: grid;
        grid-template-columns: 16rem minmax(0, 1fr);
        gap: 2rem;
    }

Бічна панель може залишатися видимою під час прокручування сторінки.

### Що потрібно пам'ятати?

- Потрібно задати порогову властивість, наприклад `top`.
- Елемент залишається в контексті свого батьківського компонента.
- Висота батьківського контейнера та обмеження прокручування впливають на поведінку.
- Властивості `overflow` предків можуть змінювати контейнер прокручування й результат.
- `sticky` не є заміною Grid або Flexbox — це механізм позиціювання, який доповнює компонування.

---

## 16. `display: contents`

Значення `display: contents` прибирає власну коробку елемента з компонування, залишаючи його дочірні елементи в структурі для компонування.

### Приклад

    .wrapper {
        display: contents;
    }

Це може бути корисно, коли потрібно, щоб дочірні елементи брали участь у Grid або Flexbox батьківського рівня без окремої коробки обгортки.

### Обережно

`display: contents` не слід застосовувати без потреби:

- власна коробка елемента не бере участі в компонуванні;
- фон, рамка та відступи цього елемента не відображаються як коробка;
- семантика й доступність можуть залежати від елемента та підтримки браузером.

Не використовуй цей підхід як універсальний спосіб прибрати зайвий HTML. Спочатку перевір, чи не можна простіше побудувати структуру Grid або Flexbox.

---

## 17. `overflow` і контроль переповнення

Сучасні макети повинні коректно обробляти довгий текст, таблиці, зображення та інші елементи.

### Приклад

    .content {
        min-width: 0;
        overflow-wrap: anywhere;
    }

`min-width: 0` допомагає Grid- або Flexbox-елементу зменшуватися нижче автоматичного мінімального розміру, а `overflow-wrap: anywhere` дозволяє переносити довгі рядки, коли це потрібно.

### Зображення

    img {
        display: block;
        max-width: 100%;
        height: auto;
    }

Це базовий спосіб уникнути виходу зображення за межі контейнера.

### Горизонтальна прокрутка для таблиць

    .table-wrapper {
        max-width: 100%;
        overflow-x: auto;
    }

Таблиця може зберігати свою структуру, а прокручування відбувається всередині контейнера.

Не додавай `overflow: hidden` автоматично для будь-якого переповнення. Ця властивість може обрізати тіні, фокусні контури та інші важливі частини інтерфейсу.

## 19. Типові помилки

### Помилка 1. Фіксувати ширину всіх елементів

    .card {
        width: 350px;
    }

На вузькому екрані картка може не поміститися.

Краще:

    .card {
        width: 100%;
        min-width: 0;
    }

А для сітки:

    .card-grid {
        display: grid;
        grid-template-columns: repeat(
            auto-fit,
            minmax(min(100%, 18rem), 1fr)
        );
        gap: 1rem;
    }

### Помилка 2. Використовувати Grid там, де достатньо Flexbox

Для простого рядка кнопок не обов'язково створювати складну двовимірну сітку.

    .actions {
        display: flex;
        flex-wrap: wrap;
        gap: 0.75rem;
    }

Вибирай інструмент відповідно до задачі.

### Помилка 3. Використовувати Flexbox для складного двовимірного макета

Якщо потрібно узгоджувати кілька рядків і колонок, Grid зазвичай простіший.

    .dashboard {
        display: grid;
        grid-template-columns: 15rem minmax(0, 1fr);
        grid-template-rows: auto 1fr;
        gap: 1.5rem;
    }

### Помилка 4. Забути про `min-width: 0`

Довгий контент може розтягувати Grid- або Flexbox-елемент.

    .main {
        min-width: 0;
    }

Також перевір, чи потрібно застосувати `overflow-wrap`, `overflow-x: auto` або інше правило для конкретного типу вмісту.

### Помилка 5. Використовувати медіазапити для кожного компонента

Не кожна адаптивна зміна потребує `@media`.

Для сітки карток часто достатньо:

    .grid {
        display: grid;
        grid-template-columns: repeat(
            auto-fit,
            minmax(min(100%, 16rem), 1fr)
        );
        gap: 1rem;
    }

Але медіазапити все ще корисні, коли потрібно суттєво змінити структуру макета.

### Помилка 6. Використовувати `position: absolute` для основного макета

Абсолютне позиціювання не резервує місце для елемента в нормальному потоці.

Використовуй його для накладання елементів, бейджів, декоративних деталей та інших задач, де це виправдано. Для основного компонування віддавай перевагу Grid або Flexbox.

### Помилка 7. Забувати про довгий текст

Навіть гнучка сітка може зламатися через URL, довге слово або широку таблицю.

    .content {
        min-width: 0;
        overflow-wrap: anywhere;
    }

Для таблиць краще розглянути окремий контейнер із горизонтальною прокруткою.

### Помилка 8. Застосовувати `aspect-ratio` без урахування вмісту

Співвідношення сторін не гарантує, що будь-який вміст автоматично поміститься в задану область.

Для зображень часто доречно:

    .image {
        width: 100%;
        aspect-ratio: 16 / 9;
        object-fit: cover;
    }

Для контейнерів з iframe, відео або іншим вмістом перевіряй, чи правильно задані розміри дочірніх елементів.

## 20. Налагодження макета в DevTools

Під час роботи з сучасним компонуванням інструменти розробника браузера допомагають швидше знаходити проблеми.

### Для Grid

1. Вибери елемент із `display: grid`.
2. Увімкни візуалізацію Grid, якщо браузер її підтримує.
3. Перевір розміри колонок і рядків.
4. Перевір `gap`, `minmax()` і розташування елементів.
5. Переконайся, що вміст не розтягує колонки несподіваним чином.

### Для Flexbox

1. Вибери елемент із `display: flex`.
2. Перевір напрямок осі.
3. Перевір `flex-wrap`, `flex-grow` і `flex-shrink`.
4. Перевір `justify-content`, `align-items` і `gap`.
5. Подивися, чи не заважають елементам фіксовані розміри.

### Для Container Queries

1. Перевір, чи має потрібний елемент контейнер.
2. Переконайся, що задано відповідний `container-type`.
3. Перевір умову `@container`.
4. Виміряй ширину контейнера, а не лише viewport.
5. Переконайся, що інший контейнер не перехоплює запит через структуру вкладеності.

### Загальний принцип

Коли макет не працює, не додавай одразу нові властивості. Спочатку визнач, яка система відповідає за компонування: Grid, Flexbox, нормальний потік, позиціювання чи контейнерні запити.

## 21. Практичні завдання

### Завдання 1. Навігація на Flexbox

Створи навігацію з логотипом і чотирма посиланнями.

Вимоги:

- використай `display: flex`;
- вирівняй елементи по вертикалі;
- додай `gap`;
- дозволь перенесення посилань на вузькому екрані;
- не використовуй `position: absolute` для основного розташування.

### Завдання 2. Адаптивна галерея

Створи сітку з дев'яти карток.

Вимоги:

- використай CSS Grid;
- використовуй `repeat()`;
- використовуй `minmax()`;
- автоматично змінюй кількість колонок;
- задай однакові проміжки через `gap`.

### Завдання 3. Макет із сайдбаром

Створи сторінку з бічною панеллю та основним контентом.

Вимоги:

- на широкому екрані — дві колонки;
- на вузькому — одна;
- основний контент повинен мати можливість зменшуватися;
- довгий текст не повинен створювати горизонтальне переповнення.

### Завдання 4. Гнучка картка

Створи картку з ілюстрацією, заголовком, описом і кнопкою.

Вимоги:

- використай Flexbox для внутрішнього компонування;
- використай `aspect-ratio` для ілюстрації;
- застосуй `margin-block-start: auto` або інший підхід, щоб розміщувати кнопку внизу картки;
- перевір результат з коротким і довгим описом.

### Завдання 5. Container Queries

Створи компонент рекомендації.

Вимоги:

- на вузькому контейнері зображення має бути над текстом;
- на широкому — зліва від тексту;
- використовуй `container-type: inline-size`;
- використай `@container`;
- перевір компонент у двох контейнерах різної ширини.

### Завдання 6. Subgrid

Створи три картки з заголовком, описом і кнопкою.

Вимоги:

- заголовки повинні вирівнюватися;
- описи можуть мати різну довжину;
- кнопки повинні розташовуватися на узгодженому рівні;
- реалізуй варіант із `subgrid`;
- порівняй його зі звичайним Grid.

### Завдання 7. Адаптивна типографіка

Створи заголовок і кілька секцій сторінки.

Вимоги:

- використай `clamp()` для розміру заголовка;
- використай `min()` або `max()` для відступів;
- обмеж максимальну ширину контенту;
- перевір макет на вузькому й широкому екранах.

## 24. Мінішпаргалка

### Flexbox

    .flex {
        display: flex;
        align-items: center;
        justify-content: space-between;
        flex-wrap: wrap;
        gap: 1rem;
    }

### Grid

    .grid {
        display: grid;
        grid-template-columns: repeat(3, minmax(0, 1fr));
        gap: 1rem;
    }

### Автоматична адаптивна сітка

    .grid {
        display: grid;
        grid-template-columns: repeat(
            auto-fit,
            minmax(min(100%, 16rem), 1fr)
        );
        gap: 1rem;
    }

### Контейнер із максимальною шириною

    .container {
        width: min(100% - 2rem, 75rem);
        margin-inline: auto;
    }

### Гнучка типографіка

    .title {
        font-size: clamp(2rem, 1.2rem + 3vw, 4rem);
    }

### Пропорції

    .image {
        width: 100%;
        aspect-ratio: 16 / 9;
        object-fit: cover;
    }

### Container Queries

    .card-wrapper {
        container-type: inline-size;
    }

    @container (min-width: 35rem) {
        .card {
            display: grid;
            grid-template-columns: 12rem minmax(0, 1fr);
        }
    }

### Subgrid

    .card {
        display: grid;
        grid-template-rows: subgrid;
        grid-row: span 3;
    }

### Логічні властивості

    .content {
        max-inline-size: 70rem;
        margin-inline: auto;
        padding-inline: 1rem;
    }

### Запобігання переповненню

    .main {
        min-width: 0;
        overflow-wrap: anywhere;
    }

### Sticky sidebar

    .sidebar {
        position: sticky;
        top: 1rem;
        align-self: start;
    }

## 25. Що потрібно запам'ятати

1. Flexbox найкраще підходить для компонування вздовж однієї основної осі.
2. Grid призначений для компонування рядків і колонок як єдиної системи.
3. Flexbox і Grid можна поєднувати в межах одного компонента.
4. `minmax()`, `min()`, `max()` і `clamp()` допомагають створювати гнучкі розміри.
5. `minmax(0, 1fr)` і `min-width: 0` часто допомагають уникнути проблем із переповненням.
6. Container Queries дозволяють адаптувати компоненти до розміру контейнера.
7. Subgrid допомагає узгоджувати доріжки вкладеної сітки з батьківською.
8. `aspect-ratio` допомагає зберігати пропорції зображень та інших блоків.
9. `gap` — зручний спосіб керувати проміжками між елементами.
10. Логічні властивості роблять CSS більш незалежним від напрямку письма.
11. Медіазапити залишаються важливими для зміни структури всієї сторінки.
12. Сучасний адаптивний макет має враховувати не тільки ширину екрана, а й вміст, доступний простір і контекст компонента.
13. DevTools допомагає визначити, яка система компонування спричиняє проблему.
14. Не варто застосовувати складні властивості лише тому, що вони сучасні: використовуй найпростіший інструмент, який розв'язує конкретну задачу.

**Головна ідея:** сучасне компонування CSS — це не набір окремих трюків, а система гнучких інструментів. Flexbox керує розташуванням уздовж осі, Grid — двовимірною структурою, Container Queries — адаптацією компонентів до контейнера, а intrinsic sizing і логічні властивості допомагають створювати макети, які залишаються надійними за різних розмірів і типів вмісту.
