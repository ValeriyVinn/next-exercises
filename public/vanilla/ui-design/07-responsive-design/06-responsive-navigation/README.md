# 06. Responsive Navigation — Адаптивна навігація

Адаптивна навігація (Responsive Navigation) — це підхід до проєктування меню сайту, за якого спосіб відображення та взаємодії з навігацією змінюється залежно від ширини екрана, типу пристрою та потреб користувача.

Головна мета — забезпечити швидкий, зрозумілий і зручний доступ до розділів сайту на смартфонах, планшетах і комп'ютерах.

Адаптивна навігація — це не просто зменшене меню. Це продумана система, яка визначає:
- які посилання показувати;
- як організувати навігацію;
- коли змінювати її структуру;
- як відкривати та закривати меню;
- як користувач взаємодіятиме з ним за допомогою миші, сенсорного екрана або клавіатури.

✔ Desktop Navigation — навігація для великих екранів.
✔ Mobile Navigation — навігація для мобільних пристроїв.
✔ Hamburger Menu — меню, яке відкривається кнопкою з трьома горизонтальними лініями.
✔ Navigation Drawer — висувна панель навігації.
✔ Dropdown Navigation — меню, що розкриває додаткові пункти.
✔ Responsive Breakpoints — точки переходу між варіантами навігації.
✔ Touch Targets — області, на які користувач натискає пальцем.
✔ Keyboard Navigation — керування меню за допомогою клавіатури.
✔ Accessible Navigation — доступна навігація для різних користувачів.
✔ Progressive Enhancement — поступове вдосконалення інтерфейсу.

# 1. Що таке Responsive Navigation

## 1.1. Призначення навігації

Навігація допомагає користувачеві зрозуміти структуру сайту та перейти до потрібного розділу.

Наприклад, сайт навчального закладу може мати такі розділи:

- Головна
- Про заклад
- Навчання
- Викладачі
- Новини
- Контакти

На широкому екрані всі пункти можуть розміщуватися в одному горизонтальному рядку.

На вузькому екрані такий рядок може не поміститися. Тому необхідно змінити спосіб представлення меню.

## 1.2. Основний принцип

**Навігація повинна адаптуватися до доступного простору, а не змушувати користувача адаптуватися до інтерфейсу.**

Під час проєктування потрібно враховувати:

- ширину екрана;
- кількість пунктів меню;
- довжину текстів;
- важливість окремих посилань;
- розмір логотипа;
- наявність кнопок входу або реєстрації;
- спосіб взаємодії;
- доступність для клавіатури та допоміжних технологій.

## 1.3. Responsive Navigation і Responsive Layout

Ці поняття пов'язані, але не тотожні.

**Responsive Layout** — адаптація загального компонування сторінки.

**Responsive Navigation** — адаптація структури та поведінки навігації.

Наприклад, на мобільному пристрої картки можуть розташовуватися в один стовпець, а навігація — перетворюватися на кнопку, яка відкриває меню.

# 2. Основні типи навігації

## 2.1. Horizontal Navigation — горизонтальне меню

Поширений варіант для настільних комп'ютерів.

    ┌──────────────────────────────────────────────────────────┐
    │ LOGO     Головна  Курси  Викладачі  Новини  Контакти     │
    └──────────────────────────────────────────────────────────┘

Переваги:

- основні розділи видно відразу;
- не потрібно відкривати додаткову панель;
- користувач швидко переходить між розділами;
- структура сайту добре помітна.

Недоліки:

- потребує горизонтального простору;
- довгі назви можуть не поміщатися;
- велика кількість пунктів перевантажує шапку;
- на малих екранах виникають конфлікти з логотипом та іншими елементами.

Коли використовувати:

- сайт має невелику кількість основних розділів;
- ширина екрана дозволяє розмістити меню;
- важливо зробити основні посилання видимими відразу.

## 2.2. Hamburger Menu — гамбургер-меню

Меню відкривається після натискання кнопки з трьома горизонтальними лініями.

    ┌────────────────────────────────┐
    │ LOGO                      ☰   │
    └────────────────────────────────┘

Після натискання може відкриватися панель:

    ┌────────────────────────────────┐
    │ LOGO                      ✕   │
    ├────────────────────────────────┤
    │ Головна                        │
    │ Курси                          │
    │ Викладачі                      │
    │ Новини                         │
    │ Контакти                       │
    └────────────────────────────────┘

Переваги:

- економить місце;
- дозволяє приховати другорядні елементи;
- добре підходить для мобільних екранів;
- дає змогу організувати довгий список розділів.

Недоліки:

- пункти меню не видно відразу;
- користувач повинен виконати додаткову дію;
- іконка без текстового пояснення може бути незрозумілою;
- прихована навігація може знижувати помітність важливих розділів.

Коли використовувати:

- горизонтальне меню не поміщається;
- є достатньо багато пунктів;
- важливо зберегти компактну шапку.

**Важливо:** гамбургер-меню не є обов'язковим рішенням для кожного мобільного сайту. Якщо є лише два-три важливі розділи, їх іноді краще залишити видимими.

## 2.3. Navigation Drawer — висувна панель

Navigation Drawer — панель із навігаційними пунктами, яка з'являється збоку екрана.

    ┌────────────────────────────────┐
    │ MENU                 [Закрити] │
    ├────────────────────────────────┤
    │ Головна                        │
    │ Курси                          │
    │ Викладачі                      │
    │ Новини                         │
    │ Контакти                       │
    └────────────────────────────────┘

Панель може:

- висуватися зліва;
- висуватися справа;
- займати частину екрана;
- займати майже всю ширину екрана;
- супроводжуватися затемненням фону.

Переваги:

- дозволяє розмістити багато пунктів;
- підтримує групування розділів;
- може містити додаткові елементи;
- підходить для складних інформаційних систем.

Недоліки:

- перекриває частину сторінки;
- потребує правильної поведінки фокуса клавіатури;
- може бути незручною, якщо містить забагато рівнів вкладеності.

Коли використовувати:

- сайт має складну структуру;
- потрібні групи посилань;
- мобільна навігація містить багато пунктів.

## 2.4. Dropdown Navigation — випадаюче меню

Dropdown Navigation показує додаткові пункти після взаємодії з основним пунктом.

    Навчання ▼
        Курси
        Розклад
        Матеріали

Випадаюче меню може використовуватися на комп'ютері, планшеті та смартфоні.

На настільних пристроях воно часто відкривається після натискання або наведення курсора.

На сенсорних екранах не можна покладатися лише на наведення, тому потрібно передбачити натискання.

Переваги:

- допомагає організувати вкладені розділи;
- зменшує кількість пунктів верхнього рівня;
- робить структуру сайту компактнішою.

Недоліки:

- додаткові рівні можуть ускладнювати навігацію;
- маленькі області натискання незручні;
- меню може перекривати інший контент;
- вкладені меню потребують продуманої клавіатурної взаємодії.

## 2.5. Bottom Navigation — нижня навігація

Основні розділи розташовуються в нижній частині інтерфейсу.

    ┌────────────────────────────────┐
    │                                │
    │         Вміст сторінки         │
    │                                │
    ├────────────────────────────────┤
    │  Головна  Курси  Профіль       │
    └────────────────────────────────┘

Часто використовується в мобільних застосунках.

Переваги:

- основні розділи постійно доступні;
- зручно для взаємодії однією рукою;
- зменшує кількість переходів через приховане меню.

Недоліки:

- займає простір внизу екрана;
- не підходить для великої кількості пунктів;
- може перекривати вміст або елементи керування;
- потребує врахування системних областей екрана.

Коли використовувати:

- є приблизно три-п'ять основних розділів;
- користувач часто переходить між ними;
- інтерфейс нагадує мобільний застосунок.

Не варто автоматично використовувати нижню навігацію для кожного адаптивного сайту. Вона найбільш корисна, коли основні розділи потрібні користувачеві постійно.

## 2.6. Sticky Navigation — закріплена навігація

Sticky Navigation залишається доступною під час прокручування сторінки.

Наприклад, шапка сайту залишається у верхній частині вікна.

Переваги:

- користувачеві не потрібно повертатися на початок сторінки;
- основні посилання залишаються доступними;
- зручно для довгих сторінок.

Недоліки:

- займає частину видимої області;
- може перекривати заголовки та якірні переходи;
- надто висока шапка зменшує корисну площу екрана.

Приклад CSS:

    .site-header {
      position: sticky;
      top: 0;
      z-index: 100;
      background-color: white;
    }

**Важливо:** `position: sticky` працює з урахуванням найближчого відповідного контейнера прокручування та обмежень його батьківських елементів.

# 3. Як вибрати правильний тип навігації

Не починай із питання: «Яке меню зараз модне?»

Починай із питань:

- Які розділи найважливіші?
- Скільки пунктів потрібно показати?
- Як часто користувач переходить між розділами?
- Чи є вкладені категорії?
- Чи потрібні в меню кнопки входу, пошуку або реєстрації?
- Чи повинні важливі дії залишатися видимими?
- Як користувач взаємодіятиме з меню на сенсорному екрані?

## 3.1. Приклади вибору

| Ситуація | Можливе рішення |
|---|---|
| 4–5 основних розділів | Горизонтальне меню |
| Багато розділів на мобільному екрані | Hamburger Menu |
| Складна структура з групами | Navigation Drawer |
| Кілька вкладених категорій | Dropdown Navigation |
| Мобільний застосунок із 3–5 основними розділами | Bottom Navigation |
| Довгі сторінки з частими переходами | Sticky Navigation |

Це рекомендації, а не жорсткі правила. Остаточне рішення залежить від реального вмісту, завдань користувачів та результатів тестування.

## 3.2. Видимість важливих дій

Припустімо, в шапці є такі елементи:

- логотип;
- головна навігація;
- кнопка «Увійти»;
- кнопка «Зареєструватися».

На мобільному екрані не обов'язково ховати всі елементи разом.

Можна залишити логотип і важливу дію видимими, а другорядні посилання перемістити в меню.

Головний принцип: **важливість дії визначає її пріоритет, а не тільки розмір екрана.**

# 4. Responsive Breakpoints для навігації

Breakpoint — це ширина viewport, на якій змінюється компонування або поведінка інтерфейсу.

Наприклад:

- на широкому екрані відображається горизонтальне меню;
- на вузькому екрані — кнопка відкриття меню.

## 4.1. Не використовуй breakpoint лише тому, що він популярний

Поширені ширини на кшталт `768px` або `1024px` можуть бути відправною точкою, але не є універсальними стандартами для всіх меню.

Breakpoint потрібно вибирати на основі реального вмісту.

Перевір:

- чи поміщається логотип;
- чи не стискаються пункти меню;
- чи не переносяться назви на кілька рядків;
- чи не перекриваються посилання;
- чи залишається достатньо місця для кнопок;
- чи не стає навігація візуально перевантаженою.

## 4.2. Mobile-first підхід

Mobile-first означає, що базові стилі розробляються для вузьких екранів, а потім доповнюються стилями для ширших.

Приклад:

    /* Базовий варіант: вузький екран */
    .desktop-nav {
      display: none;
    }

    .menu-toggle {
      display: inline-flex;
    }

    /* Ширший екран */
    @media (min-width: 768px) {
      .desktop-nav {
        display: flex;
      }

      .menu-toggle {
        display: none;
      }
    }

Цей приклад лише перемикає видимість двох варіантів. Щоб повністю реалізувати мобільне меню, додатково потрібно написати JavaScript або використати інший відповідний механізм відкриття та закриття панелі.

## 4.3. Перевіряй проміжні ширини

Не тестуй тільки два крайні варіанти: смартфон і великий монітор.

Перевір також проміжні розміри:

- вузький смартфон;
- широкий смартфон;
- планшет у вертикальній орієнтації;
- планшет у горизонтальній орієнтації;
- невеликий ноутбук;
- широкий монітор.

Проблема часто виникає саме між запланованими точками переходу.

# 5. Mobile Navigation: особливості мобільного меню

На смартфоні простір обмежений, а користувач зазвичай взаємодіє з інтерфейсом пальцем.

Тому мобільна навігація повинна мати:

- зрозумілу кнопку відкриття;
- достатні області натискання;
- читабельні назви;
- помітний стан активного розділу;
- зрозумілий спосіб закриття;
- передбачувану поведінку після вибору посилання;
- підтримку клавіатури та допоміжних технологій.

## 5.1. Розмір областей натискання

Посилання можуть виглядати невеликими, але область натискання повинна бути достатньою.

Приклад:

    .mobile-nav a {
      display: block;
      padding: 0.875rem 1rem;
    }

Внутрішні відступи збільшують область, на яку можна натиснути.

Для доступності враховуй актуальні рекомендації WCAG щодо мінімального розміру цілей натискання та відстані між ними. Рекомендований розмір залежить від конкретного критерію, рівня відповідності й винятків, тому не варто вважати одне значення універсальним для всіх випадків.

## 5.2. Зрозуміла кнопка

Іконка меню повинна бути розпізнаваною, а сама кнопка — мати доступну назву.

Погано:

    <button>
      ☰
    </button>

Краще:

    <button
      type="button"
      aria-label="Відкрити меню"
    >
      ☰
    </button>

У цьому прикладі `aria-label` задає назву для допоміжних технологій.

Якщо кнопка змінює стан, її доступна назва може змінюватися разом із ним: «Відкрити меню» та «Закрити меню».

## 5.3. Зрозуміле закриття

Користувач повинен розуміти, як повернутися до вмісту сторінки.

Можливі способи:

- повторно натиснути кнопку меню;
- натиснути кнопку закриття;
- вибрати посилання;
- натиснути Escape, якщо меню реалізовано як відповідна інтерактивна панель;
- натиснути поза панеллю, якщо така поведінка передбачена дизайном.

Не потрібно автоматично реалізовувати всі способи. Вибір залежить від типу меню та його поведінки.

Якщо панель відкривається як модальне вікно, потрібно також правильно організувати фокус клавіатури й поведінку фону.

# 6. Стан навігації (Navigation States)

Меню може мати кілька станів:

- Closed — закрите;
- Open — відкрите;
- Active — поточний розділ;
- Hover — наведення курсора;
- Focus — фокус клавіатури;
- Expanded — розгорнутий підрозділ;
- Disabled — недоступний елемент, якщо це справді потрібно.

Кожен стан повинен бути зрозумілим користувачеві.

## 6.1. Closed State

Меню закрите, а кнопка відкриття доступна.

    ┌────────────────────────────────┐
    │ LOGO                      ☰   │
    └────────────────────────────────┘

## 6.2. Open State

Меню відкрите, а кнопка відображає можливість закриття.

    ┌────────────────────────────────┐
    │ LOGO                      ✕   │
    ├────────────────────────────────┤
    │ Головна                        │
    │ Курси                          │
    │ Викладачі                      │
    │ Контакти                       │
    └────────────────────────────────┘

## 6.3. Active State

Поточний розділ повинен відрізнятися від інших пунктів.

Наприклад, активне посилання може мати:

- інший колір;
- підкреслення;
- індикатор збоку;
- зміну товщини шрифту;
- комбінацію кількох ознак.

Не покладайся лише на колір: активний стан повинен залишатися зрозумілим за достатнього контрасту та інших візуальних ознак.

Для поточного пункту навігації можна використовувати `aria-current="page"`.

    <a href="/courses" aria-current="page">
      Курси
    </a>

## 6.4. Hover і Focus

`hover` — стан наведення курсора.

`focus` — стан, коли елемент отримав фокус, наприклад через клавіатуру.

Приклад CSS:

    .site-nav a:hover {
      color: #2457c5;
    }

    .site-nav a:focus-visible {
      outline: 3px solid #2457c5;
      outline-offset: 3px;
    }

Не прибирай видимий індикатор фокуса без повноцінної альтернативи.

Сенсорні пристрої не мають звичайного наведення курсора, тому функціональність не повинна залежати виключно від `:hover`.

# 7. Ієрархія навігації

Ієрархія показує, які розділи є основними, а які належать до них.

Наприклад:

    Головна
    Навчання
      ├── Курси
      ├── Розклад
      └── Навчальні матеріали
    Про заклад
      ├── Історія
      └── Викладачі
    Контакти

На великому екрані вкладені розділи можуть відкриватися у випадаючому меню.

На мобільному екрані вони можуть відображатися як розгортувані групи.

## 7.1. Не створюй надмірну вкладеність

Чим більше рівнів, тим складніше користувачеві зрозуміти, де він перебуває.

Намагайся:

- залишати найважливіші розділи на верхньому рівні;
- використовувати зрозумілі назви;
- логічно групувати пов'язані сторінки;
- не дублювати однакові пункти без потреби;
- не створювати вкладені меню лише заради компактності.

## 7.2. Disclosure Menu — меню з розгортанням

Disclosure Menu показує або приховує підрозділи після натискання кнопки.

Приклад HTML:

    <nav aria-label="Основна навігація">
      <ul>
        <li>
          <a href="/">Головна</a>
        </li>

        <li>
          <button
            type="button"
            aria-expanded="false"
            aria-controls="learning-submenu"
          >
            Навчання
          </button>

          <ul id="learning-submenu" hidden>
            <li>
              <a href="/courses">Курси</a>
            </li>
            <li>
              <a href="/schedule">Розклад</a>
            </li>
          </ul>
        </li>
      </ul>
    </nav>

Це лише структурний приклад. Для повноцінної роботи потрібно реалізувати зміну стану `hidden` і значення `aria-expanded`.

Не використовуй кнопку для звичайного переходу на іншу сторінку, якщо елемент не відкриває або не закриває щось. Для навігації зазвичай потрібен `<a>`, а для керування станом — `<button>`.

# 8. Семантика HTML для навігації

Правильна HTML-структура допомагає браузерам, пошуковим системам і допоміжним технологіям розуміти призначення елементів.

## 8.1. Елемент `<nav>`

`<nav>` позначає блок основної навігації або інший важливий блок навігаційних посилань.

Приклад:

    <nav aria-label="Основна навігація">
      <ul>
        <li><a href="/">Головна</a></li>
        <li><a href="/courses">Курси</a></li>
        <li><a href="/contacts">Контакти</a></li>
      </ul>
    </nav>

Якщо на сторінці кілька блоків навігації, їм можна надати різні назви:

    <nav aria-label="Основна навігація">
      <!-- Основні розділи сайту -->
    </nav>

    <nav aria-label="Навігація в підвалі">
      <!-- Посилання в підвалі сайту -->
    </nav>

## 8.2. Список `<ul>` і `<li>`

Навігаційні пункти часто оформлюють як список, оскільки вони представляють групу пов'язаних елементів.

    <nav aria-label="Основна навігація">
      <ul>
        <li><a href="/">Головна</a></li>
        <li><a href="/about">Про нас</a></li>
        <li><a href="/news">Новини</a></li>
      </ul>
    </nav>

Список також полегшує подальше стилізування через Flexbox або Grid.

## 8.3. `<a>` чи `<button>`?

Використовуй `<a>`, якщо елемент переходить на іншу сторінку або до іншого ресурсу.

Використовуй `<button>`, якщо елемент виконує дію в поточному інтерфейсі.

Приклади:

    <!-- Перехід на сторінку -->
    <a href="/contacts">Контакти</a>

    <!-- Відкриття мобільного меню -->
    <button type="button">
      Відкрити меню
    </button>

Не використовуй посилання з `href="#"` замість кнопки для відкриття меню. Це створює зайву навігаційну поведінку та може змінювати позицію прокручування сторінки.

# 9. Доступність адаптивної навігації (Accessibility)

Доступна навігація повинна працювати не тільки мишею або дотиком, а й клавіатурою та допоміжними технологіями.

## 9.1. Клавіатурна навігація

Перевір:

- чи можна перейти до кнопки меню клавішею Tab;
- чи видно фокус;
- чи відкривається меню клавішею Enter або Space відповідно до типу елемента;
- чи можна пройти всіма посиланнями;
- чи можна закрити відповідну панель клавішею Escape;
- чи не губиться фокус після закриття;
- чи не потрапляє фокус у приховані пункти меню.

Звичайні посилання та кнопки вже мають стандартну клавіатурну поведінку. Не додавай зайві обробники клавіш, якщо браузер і так забезпечує потрібну взаємодію.

## 9.2. ARIA-атрибути

Для кнопки відкриття меню часто використовують:

- `aria-expanded` — повідомляє, чи розгорнуто відповідний елемент;
- `aria-controls` — вказує на елемент, яким керує кнопка;
- `aria-label` — задає доступну назву;
- `aria-current="page"` — позначає поточну сторінку.

Приклад:

    <button
      type="button"
      aria-label="Відкрити меню"
      aria-expanded="false"
      aria-controls="mobile-navigation"
    >
      ☰
    </button>

    <nav id="mobile-navigation" hidden>
      <a href="/">Головна</a>
      <a href="/courses">Курси</a>
      <a href="/contacts">Контакти</a>
    </nav>

Значення `aria-expanded` повинно відповідати фактичному стану меню. Якщо меню відкрите, значення має бути `"true"`, якщо закрите — `"false"`.

Саме додавання ARIA-атрибутів не робить меню доступним автоматично. Важливі також семантична структура, клавіатурна поведінка, видимість фокуса та коректне керування станом.

## 9.3. Фокус у висувній панелі

Якщо меню є звичайним блоком навігації, зазвичай достатньо забезпечити природний порядок фокуса та можливість закриття.

Якщо панель реалізована як модальний діалог, вимоги інші:

- фокус переходить усередину панелі;
- клавіатурна взаємодія залишається в межах модального діалогу;
- після закриття фокус повертається до кнопки, яка його відкрила;
- фон не повинен залишатися доступним для взаємодії як звичайний вміст модального вікна.

Не перетворюй кожне мобільне меню на модальне вікно без потреби. Тип поведінки має відповідати дизайну та завданню.

## 10.3. JavaScript

    const menuToggle = document.querySelector(".menu-toggle");
    const siteNavigation = document.querySelector("#site-navigation");

    if (menuToggle && siteNavigation) {
      function setMenuOpen(isOpen) {
        siteNavigation.hidden = !isOpen;

        menuToggle.setAttribute(
          "aria-expanded",
          String(isOpen)
        );

        menuToggle.setAttribute(
          "aria-label",
          isOpen ? "Закрити меню" : "Відкрити меню"
        );

        menuToggle.textContent = isOpen ? "✕" : "☰";
      }

      menuToggle.addEventListener("click", () => {
        const isOpen =
          menuToggle.getAttribute("aria-expanded") === "true";

        setMenuOpen(!isOpen);
      });

      siteNavigation.addEventListener("click", (event) => {
        const target = event.target;

        if (
          target instanceof Element &&
          target.closest("a")
        ) {
          setMenuOpen(false);
        }
      });

      document.addEventListener("keydown", (event) => {
        const isOpen =
          menuToggle.getAttribute("aria-expanded") === "true";

        if (event.key === "Escape" && isOpen) {
          setMenuOpen(false);
          menuToggle.focus();
        }
      });

      setMenuOpen(false);
    }

У цьому прикладі:

- `querySelector()` знаходить кнопку та навігацію;
- перевірка `if` захищає код від роботи з відсутніми елементами;
- `setMenuOpen()` централізує зміну стану;
- `hidden` керує видимістю меню;
- `aria-expanded` повідомляє про стан;
- `aria-label` змінюється разом із дією кнопки;
- `addEventListener()` реєструє обробники подій;
- натискання на посилання закриває меню;
- Escape закриває меню та повертає фокус на кнопку.

Це мінімальна реалізація для навчання. Вона не є повноцінним модальним drawer: не реалізує затемнення фону, блокування прокручування чи керування фокусом у межах модальної панелі.

Також важливо врахувати перехід між мобільною та настільною шириною. У реальному проєкті слід перевірити, що після зміни розміру вікна меню не залишається в неочікуваному стані. Для складнішої реалізації можна використовувати `matchMedia()` або інший узгоджений механізм керування станом.

# 11. Responsive Navigation у React

У React стан меню зазвичай зберігають у `useState`.

Приклад компонента:

    "use client";

    import { useState } from "react";

    const links = [
      { href: "/", label: "Головна" },
      { href: "/courses", label: "Курси" },
      { href: "/teachers", label: "Викладачі" },
      { href: "/contacts", label: "Контакти" },
    ];

    export default function Navigation() {
      const [isOpen, setIsOpen] = useState(false);

      function closeMenu() {
        setIsOpen(false);
      }

      return (
        <header className="site-header">
          <a className="logo" href="/">
            Навчальний сайт
          </a>

          <button
            className="menu-toggle"
            type="button"
            aria-label={isOpen ? "Закрити меню" : "Відкрити меню"}
            aria-expanded={isOpen}
            aria-controls="site-navigation"
            onClick={() => setIsOpen((open) => !open)}
          >
            {isOpen ? "✕" : "☰"}
          </button>

          <nav
            className="site-nav"
            id="site-navigation"
            aria-label="Основна навігація"
            hidden={!isOpen}
          >
            <ul>
              {links.map((link) => (
                <li key={link.href}>
                  <a href={link.href} onClick={closeMenu}>
                    {link.label}
                  </a>
                </li>
              ))}
            </ul>
          </nav>
        </header>
      );
    }

Цей компонент демонструє основну ідею керування станом, але його потрібно доповнити адаптивними стилями та перевірити взаємодію на різних ширинах екрана.

**Важливо:** у Next.js App Router компоненти з `useState` повинні бути клієнтськими компонентами, тому на початку файла використовується директива `"use client";`.

У реальному Next.js-проєкті для внутрішньої навігації зазвичай використовують компонент `Link` із `next/link`, а не звичайний `<a>`, якщо це відповідає структурі маршрутизації застосунку.

Для поточної сторінки також потрібно визначити активний пункт меню. У Next.js це можна зробити, наприклад, за допомогою `usePathname()` у клієнтському компоненті.

Не забувай про Escape, видимий фокус і узгодження стану меню після зміни ширини екрана. Ці деталі особливо важливі для складних навігаційних компонентів.

# 12. CSS-техніки для адаптивної навігації

## 12.1. Flexbox

Flexbox зручний для розташування логотипа, меню та кнопок в одному рядку.

    .site-header {
      display: flex;
      align-items: center;
      justify-content: space-between;
      gap: 1rem;
    }

Для горизонтального меню:

    .site-nav ul {
      display: flex;
      align-items: center;
      gap: 1.5rem;
    }

Для мобільного меню:

    .site-nav ul {
      display: flex;
      flex-direction: column;
      gap: 0.75rem;
    }

## 12.2. CSS Grid

Grid може допомогти, якщо шапка має три окремі зони: логотип, центральну навігацію та дії користувача.

    .site-header {
      display: grid;
      grid-template-columns: auto 1fr auto;
      align-items: center;
      gap: 1rem;
    }

На вузьких екранах структуру можна спростити:

    @media (max-width: 767px) {
      .site-header {
        grid-template-columns: 1fr auto;
      }
    }

Grid і Flexbox можна комбінувати. Наприклад, Grid організовує основні зони шапки, а Flexbox — пункти меню всередині однієї зони.

## 12.3. `gap` замість зайвих відступів

    .site-nav ul {
      display: flex;
      gap: 1rem;
    }

`gap` створює проміжки між елементами контейнера.

Це часто зручніше, ніж задавати кожному пункту меню окремий `margin`.

## 12.4. `clamp()` для гнучких відступів

    .site-header {
      padding-inline: clamp(1rem, 4vw, 2.5rem);
    }

`clamp()` приймає мінімальне, бажане та максимальне значення.

У цьому прикладі горизонтальні відступи змінюються залежно від ширини viewport, але не стають меншими за `1rem` або більшими за `2.5rem`.

Не використовуй гнучкі відступи замість перевірки реального компонування. Навіть адаптивні значення можуть не врятувати меню, якщо в ньому забагато пунктів.

## 12.5. Запобігання перенесенню тексту

Властивість `white-space: nowrap` забороняє перенесення тексту на новий рядок.

    .desktop-nav a {
      white-space: nowrap;
    }

Це може бути корисним для коротких пунктів меню, але не повинно створювати горизонтальне переповнення.

Якщо назви довгі, краще переглянути структуру навігації або змінити breakpoint, а не просто забороняти перенесення.

# 13. UX-помилки в адаптивній навігації

## 13.1. Занадто багато пунктів

Проблема:

- меню виглядає перевантаженим;
- важко визначити головні розділи;
- пункти не поміщаються в одному рядку.

Рішення:

- переглянути інформаційну архітектуру;
- об'єднати логічно пов'язані розділи;
- перенести другорядні пункти у відповідні підрозділи;
- зберегти найважливіші дії видимими.

## 13.2. Невиразна кнопка меню

Проблема:

- користувач не розуміє, що означає іконка;
- кнопка занадто мала;
- немає помітного стану фокуса.

Рішення:

- використовувати загальноприйняту іконку;
- задати доступну назву;
- забезпечити достатній розмір області натискання;
- передбачити візуальні стани.

## 13.3. Меню залежить тільки від hover

Проблема:

- сенсорний користувач не може навести курсор;
- клавіатурна взаємодія може бути неповною.

Рішення:

- використовувати натискання для відкриття;
- забезпечити доступ до всіх пунктів клавіатурою;
- зберегти зрозумілий фокус.

## 13.4. Немає індикатора активної сторінки

Проблема:

- користувач не розуміє, в якому розділі перебуває.

Рішення:

- візуально виділити поточний пункт;
- використовувати `aria-current="page"` для посилання на поточну сторінку.

## 13.5. Меню закривається несподівано

Проблема:

- користувач не встигає перейти до вкладеного пункту;
- панель зникає через випадкову взаємодію;
- стан меню змінюється непередбачувано.

Рішення:

- продумати умови відкриття й закриття;
- перевірити поведінку на сенсорному екрані;
- не закривати меню при кожній події, якщо це заважає користувачеві;
- протестувати вкладені пункти та посилання.

## 13.6. Шапка займає забагато місця

Проблема:

- на мобільному екрані залишається мало місця для контенту;
- закріплена шапка перекриває заголовки.

Рішення:

- зменшити зайві вертикальні відступи;
- переглянути висоту логотипа;
- за потреби використати компактніший варіант шапки;
- перевірити якірні переходи та прокручування.

# 14. Практичний алгоритм проєктування

Використовуй цей порядок під час створення адаптивної навігації.

## Крок 1. Визнач структуру сайту

Запиши всі основні розділи.

Наприклад:

    Головна
    Курси
    Викладачі
    Новини
    Про нас
    Контакти

## Крок 2. Розстав пріоритети

Визнач:

- які розділи повинні бути видимими відразу;
- які можна об'єднати;
- які належать до другорядної навігації;
- які дії повинні залишатися доступними.

## Крок 3. Створи desktop-варіант

Розмісти логотип, навігацію та додаткові дії.

Перевір, чи поміщається все в одному рядку без стискання та перекриття.

## Крок 4. Створи mobile-варіант

Вибери відповідний патерн:

- компактне горизонтальне меню;
- hamburger menu;
- navigation drawer;
- розгортувані групи;
- bottom navigation, якщо це відповідає типу інтерфейсу.

## Крок 5. Визнач breakpoint

Змінюй компонування в момент, коли наявна структура перестає працювати, а не лише за наперед вибраним значенням ширини.

## Крок 6. Спроєктуй стани

Перевір:

- закрите меню;
- відкрите меню;
- активний пункт;
- наведення;
- фокус;
- розгорнутий підрозділ.

## Крок 7. Реалізуй семантичну структуру

Використовуй:

- `<nav>` для навігаційного блоку;
- `<ul>` та `<li>` для групи пунктів;
- `<a>` для переходів;
- `<button>` для керування станом.

## Крок 8. Реалізуй взаємодію

Перевір відкриття, закриття, Escape, вибір посилання та поведінку після зміни ширини екрана.

## Крок 9. Перевір доступність

Перевір клавіатуру, фокус, доступні назви кнопок, контраст та області натискання.

## Крок 10. Протестуй на різних пристроях

Перевір реальний вміст, довгі назви, масштабування тексту, портретну та альбомну орієнтацію.

# 15. Практичний мініпроєкт: Responsive Navigation

Мета — створити адаптивну навігацію для навчального сайту.

## Вимоги

Desktop:

- логотип зліва;
- горизонтальне меню;
- усі основні розділи видимі;
- чіткий активний пункт;
- достатній простір між посиланнями.

Mobile:

- логотип зліва;
- кнопка меню справа;
- список пунктів відкривається після натискання;
- кнопка відображає стан відкриття;
- меню закривається після переходу;
- Escape закриває меню;
- фокус клавіатури залишається видимим.

## Структура файлів

    responsive-navigation/
    ├── index.html
    ├── styles.css
    └── script.js

## Етапи виконання

1. Створи HTML-структуру шапки та навігації.
2. Додай стилі для мобільного варіанта.
3. Реалізуй відкриття й закриття меню.
4. Додай стилі для широкого екрана через media query.
5. Познач активну сторінку.
6. Додай видимий стан `:focus-visible`.
7. Перевір клавіатурну взаємодію.
8. Перевір меню на вузьких і широких екранах.
9. Перевір довгі назви пунктів.
10. Запиши в README рішення, які ти прийняв і чому.

## Критерії готовності

- [ ] Навігація не створює горизонтального переповнення.
- [ ] Логотип і кнопка меню не перекривають одне одного.
- [ ] Мобільне меню відкривається та закривається.
- [ ] Стан кнопки відповідає стану меню.
- [ ] Усі посилання доступні з клавіатури.
- [ ] Видно індикатор фокуса.
- [ ] Поточна сторінка позначена зрозуміло.
- [ ] Важливі дії не приховані без потреби.
- [ ] Меню залишається зрозумілим на проміжних ширинах.
- [ ] HTML має семантичну структуру.
- [ ] Код не містить зайвих обробників подій.
- [ ] Після зміни ширини екрана не виникає некоректного стану.

# 16. Що потрібно запам'ятати

✔ Responsive Navigation адаптує навігацію до доступного простору та способу взаємодії.

✔ Горизонтальне меню зручне, коли основні розділи поміщаються на екрані.

✔ Hamburger Menu економить місце, але приховує пункти до взаємодії.

✔ Navigation Drawer підходить для складнішої структури з багатьма розділами.

✔ Dropdown Navigation допомагає організувати вкладені пункти, але не повинна залежати лише від hover.

✔ Bottom Navigation доречна, коли кілька основних розділів потрібні постійно.

✔ Sticky Navigation залишає меню доступним під час прокручування, але може зменшувати корисну площу екрана.

✔ Breakpoint потрібно визначати за поведінкою реального вмісту, а не лише за популярними значеннями ширини.

✔ Mobile-first допомагає почати з компактного інтерфейсу та поступово додавати можливості для ширших екранів.

✔ `<nav>` позначає навігаційний блок, `<a>` забезпечує перехід, а `<button>` виконує дію.

✔ `aria-expanded` повинен відповідати фактичному стану розгорнутого меню.

✔ `aria-current="page"` допомагає позначити посилання на поточну сторінку.

✔ Клавіатурна навігація, видимий фокус і зрозумілі назви кнопок — обов'язкові складові якісного інтерфейсу.

✔ Сенсорні пристрої не повинні залежати від наведення курсора.

✔ Адаптивне меню потрібно перевіряти на проміжних ширинах, а не лише на смартфоні та великому моніторі.

✔ Найкраща навігація — та, яка допомагає користувачеві швидко знайти потрібний розділ із мінімальними зусиллями.

# 18. Головна ідея

**Responsive Navigation — це не просто меню, яке змінює вигляд на мобільному екрані. Це система навігації, яка зберігає зрозумілу структуру, доступність і зручність взаємодії на різних пристроях.**

Під час проєктування рухайся послідовно:

    Структура сайту
        ↓
    Пріоритети розділів
        ↓
    Desktop Navigation
        ↓
    Mobile Navigation
        ↓
    Breakpoints
        ↓
    Стани та взаємодія
        ↓
    Accessibility
        ↓
    Тестування

Спочатку визнач, куди користувач повинен потрапити. Потім виріши, як найкраще показати йому ці можливості на кожному екрані.
