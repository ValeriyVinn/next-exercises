# 05. Responsive Typography — Адаптивна типографіка

## 1. Що таке Responsive Typography?

**Responsive Typography (адаптивна типографіка)** — це підхід до оформлення тексту, за якого розміри шрифтів, висота рядків, довжина текстових рядків, відступи та інші параметри пристосовуються до доступного простору й умов читання.

Мета адаптивної типографіки — зробити текст зручним для читання на смартфонах, планшетах, ноутбуках і великих моніторах.

Наприклад, великий заголовок, який добре виглядає на широкому екрані, може не поміститися на вузькому. Якщо використовувати лише фіксований розмір, текст може переноситися незручно або займати надто багато місця.

Адаптивна типографіка допомагає вирішити цю проблему.

    .page-title {
      font-size: clamp(2rem, 5vw, 4rem);
      line-height: 1.1;
    }

У цьому прикладі розмір заголовка:

- не буде меншим за `2rem`;
- плавно змінюватиметься залежно від ширини viewport;
- не перевищуватиме `4rem`.

**Головна ідея:** текст повинен залишатися читабельним і зберігати візуальну ієрархію незалежно від розміру екрана.

---

## 2. Навіщо потрібна адаптивна типографіка?

Без адаптивного підходу можуть виникати такі проблеми:

- заголовки не поміщаються в контейнер;
- текст стає надто дрібним на мобільному екрані;
- рядки стають занадто довгими на великих моніторах;
- абзаци виглядають надто щільними;
- кнопки збільшуються або зменшуються разом із текстом непередбачувано;
- порушується ієрархія заголовків;
- текст погано читається при збільшенні масштабу;
- перенесення слів створює незручну композицію.

Responsive Typography допомагає:

- ✔ адаптувати розмір заголовків і основного тексту;
- ✔ зберігати комфортну висоту рядків;
- ✔ контролювати довжину текстових рядків;
- ✔ підтримувати візуальну ієрархію;
- ✔ зменшувати кількість непотрібних медіазапитів;
- ✔ створювати гнучкі типографічні шкали;
- ✔ забезпечувати читабельність на різних екранах;
- ✔ враховувати доступність і налаштування користувача.

Адаптивна типографіка — це не лише зміна `font-size`. Вона охоплює всю систему роботи з текстом.

---

## 3. Основні параметри адаптивної типографіки

### 3.1. `font-size`

Визначає розмір шрифту.

    body {
      font-size: 1rem;
    }

    h1 {
      font-size: 3rem;
    }

Для адаптивного дизайну розмір шрифту може бути:

- фіксованим;
- відносним;
- плавно змінюваним;
- змінюваним за допомогою медіазапитів.

### 3.2. `line-height`

Визначає висоту рядка.

    body {
      line-height: 1.6;
    }

Для основного тексту часто використовують значення приблизно від `1.4` до `1.7`, але оптимальне значення залежить від шрифту, розміру тексту та довжини рядка.

Для великих заголовків може бути доречним менший інтервал:

    h1 {
      line-height: 1.1;
    }

Відносне значення без одиниць вимірювання зазвичай зручне для адаптивної типографіки.

### 3.3. `max-width`

Обмежує ширину текстового блоку.

    .article {
      max-width: 65ch;
    }

Це допомагає уникати надто довгих рядків на великих екранах.

### 3.4. `letter-spacing`

Визначає відстань між символами.

    .eyebrow {
      letter-spacing: 0.08em;
    }

Може використовуватися для невеликих підзаголовків, міток і декоративних написів.

Не варто без потреби збільшувати інтервали в основному тексті або заголовках.

### 3.5. `word-spacing`

Визначає відстань між словами.

    .text {
      word-spacing: 0.05em;
    }

Ця властивість використовується рідше. Зазвичай для корекції читабельності спочатку налаштовують розмір шрифту, висоту рядка та ширину текстового блоку.

### 3.6. `font-weight`

Визначає товщину шрифту.

    h1 {
      font-weight: 700;
    }

Візуальна ієрархія створюється не тільки розміром, а й товщиною шрифту, кольором, інтервалами та розташуванням.

### 3.7. Відступи навколо тексту

Адаптивна типографіка також включає вертикальні відступи.

    .section-title {
      margin-block-end: 1rem;
    }

    .paragraph {
      margin-block-end: 1.25rem;
    }

Розмір тексту та відступи повинні працювати як єдина система.

## 4. Одиниці вимірювання для адаптивної типографіки

У CSS є декілька одиниць, які особливо корисні для тексту.

### 4.1. `px`

Пікселі часто використовують для точних значень.

    h1 {
      font-size: 32px;
    }

Це допустимо, але для типографічних систем часто зручніші відносні одиниці, які краще враховують базовий розмір шрифту користувача.

### 4.2. `rem`

`rem` залежить від розміру шрифту кореневого елемента `html`.

    html {
      font-size: 100%;
    }

    body {
      font-size: 1rem;
    }

    h1 {
      font-size: 2.5rem;
    }

Якщо стандартний розмір кореневого шрифту становить `16px`, то:

- `1rem` дорівнює `16px`;
- `1.5rem` дорівнює `24px`;
- `2rem` дорівнює `32px`;
- `2.5rem` дорівнює `40px`.

Це приклади для базового розміру `16px`, а не гарантовані значення для кожного користувача чи браузера.

**Перевага `rem`:** розміри можуть враховувати налаштування шрифтів користувача.

Для типографічної шкали `rem` часто є хорошим базовим вибором.

### 4.3. `em`

`em` залежить від обчисленого розміру шрифту відповідного елемента для властивостей на кшталт `font-size`.

    .card {
      font-size: 1rem;
    }

    .card__title {
      font-size: 1.5em;
    }

У цьому прикладі заголовок має розмір у півтора раза більший за розмір шрифту картки.

`em` зручний для компонентів, де відступи та інші розміри повинні масштабуватися разом із текстом.

Але вкладені значення `em` можуть накопичуватися, тому їх потрібно використовувати свідомо.

### 4.4. `vw`

`vw` — одиниця, пов'язана з шириною viewport.

    h1 {
      font-size: 5vw;
    }

Якщо viewport ширший, значення `font-size` збільшується.

Однак використовувати лише `vw` для тексту небажано:

- на вузькому екрані текст може стати надто малим;
- на широкому — надто великим;
- користувач може мати недостатній контроль над розміром тексту.

Краще обмежувати діапазон за допомогою `clamp()`.

### 4.5. `ch`

`ch` — одиниця, яка приблизно відповідає ширині символу `0` у поточному шрифті.

    .article {
      max-width: 65ch;
    }

Вона часто використовується для обмеження ширини абзаців.

`65ch` не означає рівно 65 символів у будь-якому тексті. Реальна кількість символів у рядку залежить від шрифту та складу тексту.

### 4.6. `clamp()`

`clamp()` дозволяє задати мінімальне, бажане та максимальне значення.

    h1 {
      font-size: clamp(2rem, 5vw, 4rem);
    }

Це один із найкорисніших інструментів адаптивної типографіки.

### 4.7. `calc()`

`calc()` дозволяє обчислювати значення CSS.

    h1 {
      font-size: calc(1.5rem + 2vw);
    }

Проте без обмежень значення може бути надто малим або великим.

Для типографіки зазвичай зручніше використовувати `clamp()`, коли потрібно контролювати обидві межі.

## 5. Що таке Fluid Typography?

**Fluid Typography (плавна типографіка)** — це підхід, за якого розмір тексту поступово змінюється залежно від ширини viewport, а не стрибками на конкретних breakpoint.

Наприклад, заголовок може збільшуватися зі зростанням ширини екрана.

    .title {
      font-size: clamp(2rem, 4vw, 4rem);
    }

Значення змінюється плавно в межах між `2rem` і `4rem`, доки бажане значення `4vw` залишається між цими межами.

### Переваги Fluid Typography

- ✔ менше медіазапитів для розмірів шрифтів;
- ✔ плавна зміна типографіки;
- ✔ гнучкі заголовки;
- ✔ зручне масштабування;
- ✔ можливість створити цілісну типографічну систему.

### Недоліки

- без обмежень шрифт може стати надто малим або великим;
- складніше контролювати точні розміри на конкретних ширинах;
- однаковий коефіцієнт масштабування не підходить усім текстовим елементам;
- надмірне використання fluid-значень може порушити типографічну ієрархію.

**Правило:** плавно змінюй розміри там, де це покращує дизайн, але встановлюй розумні межі.

---

## 6. Функція `clamp()` для адаптивного тексту

Синтаксис:

    clamp(MIN, PREFERRED, MAX)

Де:

- `MIN` — мінімально допустиме значення;
- `PREFERRED` — бажане значення;
- `MAX` — максимально допустиме значення.

Браузер обирає бажане значення, якщо воно перебуває в межах мінімуму та максимуму. В іншому випадку використовується відповідна межа.

### Приклад 1. Великий заголовок

    h1 {
      font-size: clamp(2rem, 5vw, 4.5rem);
    }

На вузькому екрані заголовок не стає меншим за `2rem`.

На широкому екрані він не перевищує `4.5rem`.

### Приклад 2. Заголовок секції

    h2 {
      font-size: clamp(1.5rem, 3vw, 2.5rem);
    }

### Приклад 3. Основний текст

    body {
      font-size: clamp(1rem, 0.95rem + 0.2vw, 1.125rem);
    }

Тут зміна розміру значно менша, ніж для великих заголовків.

Не потрібно змушувати основний текст сильно збільшуватися на широких екранах. Його комфортний розмір залежить також від ширини рядка та дизайну сторінки.

### Приклад 4. Відступи

    .section {
      padding-block: clamp(2rem, 5vw, 5rem);
    }

`clamp()` можна використовувати не лише для шрифтів, а й для відступів, ширини та інших розмірів.

### Приклад 5. Відступ між заголовком і текстом

    .page-title {
      margin-block-end: clamp(1rem, 2vw, 2rem);
    }

### Важливо

`clamp()` не замінює всі медіазапити.

Якщо на певній ширині потрібно змінити композицію, приховати декоративний елемент або перебудувати макет, медіазапити все ще можуть бути необхідними.

## 7. Створення адаптивної типографічної шкали

**Typography Scale (типографічна шкала)** — це система узгоджених розмірів тексту для різних рівнів інформації.

Наприклад:

- дрібні підписи;
- допоміжний текст;
- основний текст;
- підзаголовки;
- заголовки секцій;
- головний заголовок сторінки.

Без системи кожен елемент може мати випадковий розмір, через що інтерфейс виглядатиме непослідовно.

### 7.1. Фіксована шкала

    :root {
      --text-xs: 0.75rem;
      --text-sm: 0.875rem;
      --text-base: 1rem;
      --text-lg: 1.25rem;
      --text-xl: 1.5rem;
      --text-2xl: 2rem;
      --text-3xl: 3rem;
    }

Це приклад шкали з фіксованими значеннями.

Вона підходить для проєктів, у яких важлива передбачуваність розмірів.

### 7.2. Адаптивна шкала

    :root {
      --text-sm: 0.875rem;
      --text-base: 1rem;
      --text-lg: clamp(1.125rem, 1rem + 0.5vw, 1.5rem);
      --text-xl: clamp(1.5rem, 1.2rem + 1vw, 2rem);
      --text-2xl: clamp(2rem, 1.5rem + 2vw, 3rem);
      --text-3xl: clamp(2.5rem, 1.5rem + 4vw, 4.5rem);
    }

Тепер великі рівні шкали плавно змінюються залежно від viewport.

Основний текст залишається стабільним, а заголовки масштабуються активніше.

Це лише один із можливих варіантів. Розміри потрібно перевіряти на реальному контенті.

### 7.3. Використання шкали

    body {
      font-size: var(--text-base);
    }

    .caption {
      font-size: var(--text-sm);
    }

    .card__title {
      font-size: var(--text-xl);
    }

    .section-title {
      font-size: var(--text-2xl);
    }

    .page-title {
      font-size: var(--text-3xl);
    }

Перевага CSS-змінних — централізоване керування типографікою.

Якщо дизайн змінюється, не потрібно шукати кожне значення в окремих селекторах.

## 8. Типографічна ієрархія

**Typographic Hierarchy (типографічна ієрархія)** — це візуальне розрізнення рівнів інформації за допомогою розміру, товщини, кольору, інтервалів і розташування тексту.

Наприклад:

- H1 — головний заголовок сторінки;
- H2 — заголовки великих секцій;
- H3 — підзаголовки всередині секцій;
- основний текст — зміст;
- підписи — допоміжна інформація.

### Приклад

    .page-title {
      font-size: clamp(2.25rem, 5vw, 4rem);
      line-height: 1.1;
      font-weight: 700;
    }

    .section-title {
      font-size: clamp(1.5rem, 3vw, 2.25rem);
      line-height: 1.2;
      font-weight: 700;
    }

    .card-title {
      font-size: clamp(1.125rem, 1rem + 0.5vw, 1.5rem);
      line-height: 1.3;
      font-weight: 600;
    }

    .body-text {
      font-size: 1rem;
      line-height: 1.6;
    }

    .caption {
      font-size: 0.875rem;
      line-height: 1.5;
    }

Розміри мають відрізнятися достатньо, щоб користувач міг швидко визначити структуру сторінки.

### Важливе розрізнення

HTML-заголовки `h1`–`h6` визначають структуру документа.

CSS-властивості визначають їхній зовнішній вигляд.

Не вибирай HTML-рівень заголовка лише через бажаний розмір шрифту. Для візуального оформлення використовуй CSS.

---

## 9. Адаптивні заголовки

Заголовки часто потребують більшої уваги, ніж основний текст.

На широкому екрані великий заголовок створює виразну композицію. На мобільному він може займати значну частину першого екрана.

### 9.1. Плавний розмір

    .hero-title {
      font-size: clamp(2.25rem, 6vw, 5rem);
      line-height: 1.05;
      letter-spacing: -0.03em;
    }

### 9.2. Обмеження ширини

    .hero-title {
      max-width: 15ch;
    }

Обмеження ширини допомагає контролювати довжину рядка.

Значення потрібно підбирати для конкретного шрифту та тексту.

### 9.3. Керовані перенесення

Не завжди потрібно дозволяти заголовку переноситися в довільному місці.

Для заголовків із чіткою композицією можна використовувати окремі текстові блоки або елементи перенесення, якщо структура залишається логічною.

Не вставляй `<br>` після кожних кількох слів лише для того, щоб заголовок виглядав правильно на одному розмірі екрана.

### 9.4. `text-wrap: balance`

Властивість `text-wrap: balance` допомагає збалансувати довжину рядків у багаторядковому тексті, особливо в заголовках.

    .hero-title {
      text-wrap: balance;
    }

Це може зробити композицію заголовка візуально гармонійнішою.

Властивість не гарантує ідеального перенесення для будь-якого тексту, тому результат потрібно перевіряти.

### 9.5. `overflow-wrap`

Для довгих нерозривних слів або URL:

    .heading {
      overflow-wrap: anywhere;
    }

Використовуй цю властивість, якщо довгі слова можуть спричиняти горизонтальне переповнення.

Не застосовуй її без потреби до всіх текстових елементів, оскільки це може створювати небажані перенесення.

## 10. Довжина рядка та читабельність

**Line Length (довжина рядка)** — це кількість тексту, яку користувач читає в одному рядку.

Надто довгі рядки ускладнюють перехід погляду до наступного рядка.

Надто короткі рядки можуть спричиняти часті перенесення й робити читання повільнішим.

Для багатьох текстових блоків орієнтиром є приблизно 45–75 символів на рядок, але це не жорстке правило. Комфортна довжина залежить від шрифту, мови, розміру тексту та контексту.

### Обмеження ширини через `ch`

    .article {
      max-width: 65ch;
    }

Це поширений спосіб обмеження ширини основного тексту.

### Інший приклад

    .article {
      width: 100%;
      max-width: 70ch;
      margin-inline: auto;
    }

Тепер текстовий блок може займати всю доступну ширину на вузькому екрані, але не ставатиме надто широким на великому.

### Важливо

`ch` не є точною одиницею кількості символів. Це орієнтир, пов'язаний із метриками шрифту.

Перевіряй результат на реальному тексті, особливо якщо використовуються кирилиця, латиниця, цифри та довгі слова.

---

## 11. Адаптивний основний текст

Основний текст повинен бути комфортним для тривалого читання.

    body {
      font-family: system-ui, sans-serif;
      font-size: 1rem;
      line-height: 1.6;
    }

Для багатьох інтерфейсів це хороший початок.

### Коли змінювати розмір основного тексту?

Можна використовувати плавну зміну:

    body {
      font-size: clamp(1rem, 0.95rem + 0.2vw, 1.125rem);
      line-height: 1.6;
    }

Але сильне збільшення тексту разом із шириною екрана не завжди покращує читабельність.

На широкому моніторі зазвичай важливіше обмежити ширину текстового блоку, ніж безперервно збільшувати шрифт.

### Не зменшуй текст лише заради вміщення

Якщо на мобільному екрані абзац не поміщається, не поспішай зменшувати `font-size`.

Краще перевір:

- ширину контейнера;
- горизонтальні відступи;
- `line-height`;
- довжину слів;
- зайві обмеження ширини;
- структуру самого макета.

Мета — не вмістити максимальну кількість тексту на екрані, а забезпечити зручне читання.

---

## 12. Адаптивні відступи навколо тексту

Відстань між заголовком і текстом впливає на візуальну ієрархію.

Якщо текст стає більшим, але відступи залишаються незмінними, композиція може виглядати занадто щільною або розрідженою.

### Плавні відступи

    .content-section {
      padding-block: clamp(2rem, 5vw, 5rem);
    }

    .section-title {
      margin-block-end: clamp(1rem, 2vw, 2rem);
    }

    .paragraph {
      margin-block-end: 1.25rem;
    }

Тут:

- відступи секції плавно збільшуються;
- проміжок після заголовка також адаптується;
- відстань між абзацами залишається стабільною.

### Чи потрібно робити всі відступи fluid?

Ні.

Плавне масштабування доречне для великих секцій і композиційних інтервалів.

Невеликі проміжки між підписом і полем форми або між іконкою та текстом часто краще залишати стабільними.

---

## 13. Responsive Typography через медіазапити

Плавне масштабування не завжди підходить.

Іноді потрібно встановити конкретні розміри для різних діапазонів ширини.

    .page-title {
      font-size: 2rem;
      line-height: 1.15;
    }

    @media (min-width: 768px) {
      .page-title {
        font-size: 3rem;
      }
    }

    @media (min-width: 1200px) {
      .page-title {
        font-size: 4rem;
      }
    }

Це приклад типографіки, яка змінюється ступінчасто.

### Переваги медіазапитів

- точний контроль розмірів;
- можливість змінити композицію на конкретній ширині;
- передбачувана поведінка;
- зручність для макетів із чіткими дизайн-специфікаціями.

### Недоліки

- більше CSS;
- можливе дублювання правил;
- зміна розміру може виглядати різкою;
- потрібно перевіряти ширини між breakpoint.

### Коли використовувати?

Використовуй медіазапити, якщо розмір тексту має відповідати конкретним станам макета.

Використовуй `clamp()`, якщо доречне плавне масштабування в межах мінімуму та максимуму.

Ці два підходи можна поєднувати.

---

## 14. Mobile-first підхід до типографіки

**Mobile-first** означає, що базові стилі спочатку створюються для вузького viewport, а потім розширюються для більших екранів.

Приклад:

    .page-title {
      font-size: 2rem;
      line-height: 1.15;
    }

    .article {
      width: 100%;
      max-width: 65ch;
    }

    @media (min-width: 768px) {
      .page-title {
        font-size: 3rem;
      }
    }

    @media (min-width: 1200px) {
      .page-title {
        font-size: 4rem;
      }
    }

Переваги:

- базові стилі залишаються простими;
- мобільний інтерфейс отримує пріоритет;
- стилі для широких екранів додаються за необхідності;
- легше контролювати складність CSS.

Водночас mobile-first не означає, що кожен текст повинен збільшуватися на планшеті й комп'ютері.

Для кожного елемента потрібно визначати, чи справді зміна розміру покращує сприйняття.

---

## 15. Адаптивна типографіка в дизайн-системі

У великому проєкті типографіку краще організовувати через CSS-змінні.

Це дозволяє створити єдину систему розмірів і використовувати її в різних компонентах.

### Приклад

    :root {
      --font-body: 1rem;
      --font-caption: 0.875rem;

      --font-heading-sm: clamp(1.25rem, 1.1rem + 0.5vw, 1.5rem);
      --font-heading-md: clamp(1.5rem, 1.2rem + 1vw, 2.25rem);
      --font-heading-lg: clamp(2rem, 1.4rem + 2vw, 3.5rem);
      --font-display: clamp(2.5rem, 1.5rem + 4vw, 5rem);

      --line-body: 1.6;
      --line-heading: 1.15;

      --content-width: 65ch;
    }

    body {
      font-size: var(--font-body);
      line-height: var(--line-body);
    }

    .caption {
      font-size: var(--font-caption);
    }

    .heading-sm {
      font-size: var(--font-heading-sm);
      line-height: var(--line-heading);
    }

    .heading-md {
      font-size: var(--font-heading-md);
      line-height: var(--line-heading);
    }

    .heading-lg {
      font-size: var(--font-heading-lg);
      line-height: var(--line-heading);
    }

    .display-title {
      font-size: var(--font-display);
      line-height: 1.05;
    }

    .prose {
      max-width: var(--content-width);
    }

### Переваги

- усі типографічні значення зберігаються в одному місці;
- легше підтримувати послідовність;
- простіше змінювати дизайн;
- компоненти можуть використовувати спільні токени;
- менше випадкових значень у CSS.

### Важливе правило

Назви токенів повинні описувати роль, а не лише конкретний розмір.

Наприклад, `--font-heading-lg` зазвичай корисніший у системі, ніж `--font-48px`, якщо один і той самий токен використовується для різних компонентів.

## 16. Адаптивна типографіка в компонентах

Типографіка повинна працювати не тільки на рівні сторінки, а й усередині компонентів.

### 16.1. Картка

    .card {
      min-width: 0;
    }

    .card__title {
      font-size: clamp(1.125rem, 1rem + 0.5vw, 1.5rem);
      line-height: 1.3;
      overflow-wrap: anywhere;
    }

    .card__description {
      font-size: 1rem;
      line-height: 1.6;
    }

### 16.2. Кнопка

    .button {
      font: inherit;
      font-weight: 600;
      line-height: 1.2;
      padding: 0.75em 1em;
    }

Використання `em` у відступах дозволяє їм масштабуватися разом із розміром тексту кнопки.

Не забувай про достатню площу для натискання та видимий стан фокусу.

### 16.3. Навігація

    .nav {
      display: flex;
      flex-wrap: wrap;
      gap: 0.75rem 1.25rem;
    }

    .nav__link {
      font-size: 1rem;
      line-height: 1.5;
    }

Навігація повинна залишатися зрозумілою навіть тоді, коли текст збільшується.

Якщо елементи не поміщаються, потрібно переглянути структуру навігації, а не лише зменшувати шрифт.

### 16.4. Форма

    .form-label {
      display: block;
      margin-block-end: 0.5rem;
      font-size: 1rem;
      font-weight: 600;
    }

    .form-help {
      font-size: 0.875rem;
      line-height: 1.5;
    }

Допоміжний текст не повинен бути настільки дрібним, щоб його було складно читати.

## 17. Адаптивна типографіка та доступність

Доступність — одна з головних вимог до якісної типографіки.

### 17.1. Не блокуй масштабування тексту

Не варто створювати інтерфейс, який працює лише за одного фіксованого розміру шрифту.

Використовуй відносні одиниці та перевіряй поведінку сторінки при збільшенні масштабу.

### 17.2. Не використовуй надто дрібний текст

Підписи й допоміжна інформація повинні залишатися читабельними.

Розмір `0.75rem` може бути доречним у деяких випадках, але не слід використовувати його для важливого тексту без перевірки.

### 17.3. Перевіряй масштабування до 200%

Після збільшення масштабу перевір:

- чи не перекриваються елементи;
- чи не обрізаються заголовки;
- чи доступні кнопки;
- чи не зникає текст;
- чи не з'являється небажане горизонтальне прокручування;
- чи можна прочитати основний контент без втрати інформації.

### 17.4. Враховуй збільшення тексту

Збільшення тексту користувачем може відрізнятися від звичайного масштабування сторінки.

Тому потрібно перевіряти, чи не задано елементам жорстку висоту, яка обрізає текст.

Краще дозволяти контейнерам збільшуватися разом із вмістом, якщо немає вагомої причини для іншої поведінки.

### 17.5. Не передавай зміст лише кольором або розміром

Візуальна ієрархія допомагає користувачеві, але семантична структура HTML також важлива.

Використовуй заголовки, абзаци, списки та інші елементи відповідно до змісту.

### 17.6. Перевіряй контраст

Розмір шрифту не компенсує недостатній контраст між текстом і фоном.

Для звичайного тексту орієнтир WCAG AA — коефіцієнт контрастності щонайменше `4.5:1`.

Для великого тексту — щонайменше `3:1`.

За WCAG великим вважається текст розміром не менше ніж `18pt` у звичайному накресленні або `14pt` у жирному накресленні. Це приблизно відповідає `24px` і `18.67px` відповідно за стандартного перерахунку CSS-пікселів у пункти.

Для практичної роботи перевіряй контраст за допомогою відповідного інструмента, а не лише візуально.

## 18. Поширені помилки Responsive Typography

### Помилка 1. Використання лише `vw`

    h1 {
      font-size: 5vw;
    }

На дуже вузькому екрані заголовок може стати надто дрібним, а на широкому — надто великим.

Краще:

    h1 {
      font-size: clamp(2rem, 5vw, 4rem);
    }

### Помилка 2. Надто великий основний текст на широкому екрані

Якщо текст збільшується разом із viewport без обмежень, читання може стати незручним.

Краще контролювати розмір тексту й обмежувати ширину текстового блоку.

### Помилка 3. Надто довгі рядки

    .article {
      width: 100%;
    }

На великому екрані абзаци можуть розтягнутися на всю ширину.

Краще:

    .article {
      width: 100%;
      max-width: 65ch;
    }

### Помилка 4. Надто малий `line-height`

    .article {
      line-height: 1;
    }

Для основного тексту це часто створює занадто щільне компонування.

Краще почати з:

    .article {
      line-height: 1.6;
    }

Після цього перевірити реальний результат.

### Помилка 5. Надто великий `line-height` у заголовку

    h1 {
      line-height: 2;
    }

Великі багаторядкові заголовки можуть займати надто багато вертикального простору.

Краще перевірити значення близько `1.05–1.2`, якщо воно відповідає шрифту та композиції.

### Помилка 6. Фіксована висота текстового контейнера

    .card__title {
      height: 3rem;
      overflow: hidden;
    }

Довший заголовок може бути обрізаний.

Не обмежуй висоту тексту без потреби. Якщо обмеження кількості рядків потрібне для конкретного компонента, перевір, чи важлива інформація залишається доступною.

### Помилка 7. Випадкові розміри шрифтів

Якщо кожен компонент використовує власні довільні значення, інтерфейс стає непослідовним.

Краще створити типографічну шкалу й використовувати CSS-змінні.

### Помилка 8. Надмірна кількість медіазапитів

Не потрібно створювати окремий breakpoint для кожного заголовка, якщо `clamp()` вирішує завдання простіше.

Водночас не потрібно замінювати медіазапитами або `clamp()` всі типографічні рішення. Вибирай підхід за потребою.

### Помилка 9. Перенесення тексту лише для одного розміру екрана

Жорстко задані перенесення можуть погіршити вигляд на інших ширинах.

Перевіряй довгі заголовки та переклади на різних екранах.

### Помилка 10. Ігнорування налаштувань користувача

Якщо дизайн працює лише за стандартного масштабу, він може бути незручним для користувачів, які збільшують текст.

Використовуй гнучкі розміри й не обрізай вміст без необхідності.

## 19. Як тестувати адаптивну типографіку

Після створення типографічної системи потрібно перевірити її на різних розмірах екрана.

### Перевір такі параметри

- ✔ Чи залишаються заголовки читабельними?
- ✔ Чи не стає основний текст надто дрібним?
- ✔ Чи не збільшуються заголовки безконтрольно?
- ✔ Чи комфортна висота рядків?
- ✔ Чи не стають рядки надто довгими?
- ✔ Чи зберігається ієрархія тексту?
- ✔ Чи не обрізаються довгі заголовки?
- ✔ Чи працюють перенесення слів?
- ✔ Чи зберігаються відступи між блоками?
- ✔ Чи залишається контент доступним при збільшенні масштабу?
- ✔ Чи не перекриваються елементи?
- ✔ Чи достатній контраст тексту?

### Практична послідовність

1. Відкрий сторінку в браузері.
2. Увімкни DevTools.
3. Перевір вузький viewport.
4. Перевір типовий мобільний розмір.
5. Перевір планшет.
6. Перевір ноутбук.
7. Перевір широкий монітор.
8. Поступово змінюй ширину viewport.
9. Перевір заголовки з різною довжиною.
10. Перевір абзаци з довгими словами та URL.
11. Збільш масштаб сторінки.
12. Перевір, чи не обрізається текст.
13. Перевір контраст.
14. Перевір реальний контент, а не лише короткі тестові фрази.

Не орієнтуйся лише на популярні ширини пристроїв. Проблема може з'явитися між двома стандартними розмірами.

## 20. Практичний алгоритм створення адаптивної типографіки

### Крок 1. Визнач ролі тексту

Склади список:

- основний текст;
- головний заголовок;
- заголовок секції;
- заголовок картки;
- допоміжний текст;
- підпис;
- текст кнопки;
- текст форми.

### Крок 2. Визнач базовий розмір

Наприклад:

    body {
      font-size: 1rem;
      line-height: 1.6;
    }

Це відправна точка, а не універсальний стандарт для кожного проєкту.

### Крок 3. Створи типографічну шкалу

    :root {
      --text-sm: 0.875rem;
      --text-base: 1rem;
      --text-lg: 1.25rem;
      --heading-md: clamp(1.5rem, 1.2rem + 1vw, 2.25rem);
      --heading-lg: clamp(2rem, 1.4rem + 2vw, 3.5rem);
    }

### Крок 4. Обери спосіб адаптації

Використовуй:

- `rem` для стабільних відносних розмірів;
- `clamp()` для плавної зміни;
- медіазапити для конкретних типографічних станів;
- `ch` для обмеження ширини текстових блоків.

### Крок 5. Налаштуй висоту рядка

    .body-text {
      line-height: 1.6;
    }

    .heading {
      line-height: 1.15;
    }

Враховуй, що різні шрифти можуть потребувати різних значень.

### Крок 6. Обмеж ширину тексту

    .prose {
      max-width: 65ch;
    }

### Крок 7. Перевір перенесення

Тестуй заголовки та абзаци на вузьких екранах.

### Крок 8. Перевір доступність

Збільш масштаб, перевір контраст і переконайся, що текст не обрізається.

### Крок 9. Перевір систему в компонентах

Типографіка повинна працювати не лише в заголовках сторінки, а й у картках, формах, кнопках, навігації та повідомленнях.

### Чому цей приклад адаптивний?

1. Основний текст має відносний розмір `1rem`.
2. Заголовок змінюється плавно за допомогою `clamp()`.
3. Максимальний розмір заголовка обмежено.
4. Ширина статті обмежена через `max-width: 70ch`.
5. Відступи між секціями змінюються плавно.
6. Заголовки мають менший `line-height`, ніж основний текст.
7. `text-wrap: balance` допомагає збалансувати перенесення заголовків.
8. `overflow-wrap: anywhere` допомагає уникнути переповнення довгими словами.
9. Структура HTML залишається семантичною.
10. Для зміни типографічних розмірів не потрібні окремі медіазапити.

## 23. Що потрібно запам'ятати

✔ Responsive Typography — це адаптація розмірів і параметрів тексту до умов читання.

✔ Fluid Typography — це плавна зміна типографічних значень у межах заданого діапазону.

✔ `font-size` визначає розмір шрифту.

✔ `line-height` контролює висоту рядка.

✔ `rem` зручний для створення відносної типографічної шкали.

✔ `em` корисний для компонентів, де розміри повинні залежати від поточного шрифту.

✔ `vw` може використовуватися для плавного масштабування, але бажано обмежувати його через `clamp()`.

✔ `ch` допомагає обмежувати ширину текстових блоків.

✔ `clamp()` задає мінімальне, бажане та максимальне значення.

✔ Типографічна шкала забезпечує послідовність між заголовками, основним текстом і підписами.

✔ Візуальна ієрархія залежить не лише від розміру, а й від товщини, кольору, інтервалів та розташування тексту.

✔ Довжина рядка впливає на комфорт читання.

✔ На широких екранах часто краще обмежувати ширину тексту, ніж безперервно збільшувати його розмір.

✔ Медіазапити потрібні, коли типографіка повинна змінюватися на конкретних точках перелому.

✔ `text-wrap: balance` може покращити перенесення рядків у заголовках.

✔ `overflow-wrap: anywhere` допомагає уникати переповнення довгими нерозривними словами.

✔ Відносні розміри не замінюють перевірку доступності.

✔ Потрібно тестувати текст зі збільшеним масштабом.

✔ Типографіка повинна залишатися читабельною на всіх ширинах viewport.

✔ Найкраща адаптивна типографіка поєднує гнучкість, контроль і читабельність.

## 25. Практичні завдання

### Завдання 1. Адаптивний заголовок

Створи головний заголовок сторінки.

Вимоги:

- мінімальний розмір — `2rem`;
- максимальний розмір — `4rem`;
- плавна зміна;
- `line-height` приблизно `1.1`.

Використай `clamp()`.

### Завдання 2. Типографічна шкала

Створи CSS-змінні для:

- підпису;
- основного тексту;
- великого основного тексту;
- заголовка картки;
- заголовка секції;
- головного заголовка.

Використай стабільні розміри для дрібного тексту й плавні значення для великих заголовків.

### Завдання 3. Ширина тексту

Створи сторінку з кількома довгими абзацами.

Обмеж ширину текстового блоку через `max-width: 65ch`.

Порівняй читабельність із текстом, який займає всю ширину монітора.

### Завдання 4. Заголовок із довгим текстом

Створи кілька заголовків різної довжини.

Перевір їх на вузькому екрані.

Спробуй використати:

    .heading {
      text-wrap: balance;
      overflow-wrap: anywhere;
    }

Переконайся, що перенесення залишаються природними.

### Завдання 5. Плавні відступи

Створи секцію з заголовком, описом і кнопкою.

Використай `clamp()` для:

- вертикальних відступів секції;
- відстані після заголовка;
- проміжку між описом і кнопкою.

### Завдання 6. Медіазапити проти `clamp()`

Створи два варіанти головного заголовка:

- перший змінює розмір через медіазапити;
- другий використовує `clamp()`.

Порівняй поведінку між стандартними ширинами viewport.

### Завдання 7. Перевірка доступності

Збільш масштаб сторінки до 200%.

Перевір:

- заголовки;
- кнопки;
- навігацію;
- текст карток;
- форми;
- допоміжні повідомлення.

Виправ випадки обрізання або накладання тексту.

### Завдання 8. Мініпроєкт — адаптивна стаття

Створи сторінку статті з:

- категорією;
- головним заголовком;
- вступним абзацом;
- підзаголовками;
- основним текстом;
- списком;
- посиланнями.

Використай:

- `rem`;
- `clamp()`;
- `line-height`;
- `max-width`;
- `ch`;
- CSS-змінні;
- логічні властивості відступів.

Перевір сторінку на вузьких і широких екранах та зі збільшеним масштабом.

## 27. Головний принцип Responsive Typography

**Адаптивна типографіка повинна змінюватися настільки, наскільки це потрібно для читабельності та композиції, але не більше.**

Використовуй `rem` для стабільних відносних розмірів, `clamp()` для плавного масштабування, медіазапити для конкретних змін, а `ch` — для контролю ширини текстових блоків.

Не намагайся розв'язати всі проблеми лише зміною `font-size`. Враховуй довжину рядків, висоту рядка, відступи, ієрархію, контраст і доступність.

Хороша адаптивна типографіка допомагає користувачеві легко читати, розуміти та сприймати інформацію незалежно від розміру екрана.
