# 03. Fluid Layouts — Гумові макети та гнучкі розміри

## 1. Що таке Fluid Layouts?

**Fluid Layout (гумовий макет)** — це підхід до вебдизайну, за якого розміри та розташування елементів інтерфейсу гнучко змінюються залежно від доступного простору.

На відміну від макета з фіксованою шириною, гумовий макет використовує відносні одиниці вимірювання, гнучкі контейнери та обмеження розмірів.

Наприклад:

- Фіксований макет: контейнер завжди має ширину `1200px`.
- Гумовий макет: контейнер займає `90%` доступної ширини.
- Гумовий макет з обмеженням: контейнер займає `90%` ширини, але не перевищує `1200px`.

    .container {
      width: 90%;
      max-width: 1200px;
      margin-inline: auto;
    }

У третьому випадку контейнер адаптується до вузьких екранів, але на широких екранах не стає надмірно широким.

**Головна ідея:** макет повинен використовувати доступний простір ефективно, не створюючи горизонтального прокручування та не погіршуючи читабельність.

---

## 2. Навіщо потрібні гумові макети?

Користувачі відкривають сайти на різних пристроях:

- смартфонах;
- планшетах;
- ноутбуках;
- настільних комп'ютерах;
- великих моніторах.

Навіть два смартфони можуть мати різну ширину екрана. Тому недостатньо створити дизайн лише для кількох конкретних розмірів.

Fluid Layouts допомагають:

- ✔ адаптувати макет до різної ширини viewport;
- ✔ використовувати доступний простір без зайвих фіксованих розмірів;
- ✔ зменшувати ризик горизонтального прокручування;
- ✔ підтримувати читабельність тексту;
- ✔ створювати гнучкі картки, колонки та секції;
- ✔ поєднувати плавну адаптацію з контрольованими точками перелому;
- ✔ підтримувати збільшення тексту та доступність інтерфейсу.

Важливо розрізняти:

- **Fluid Layout** — розміри змінюються гнучко.
- **Responsive Design** — увесь інтерфейс пристосовується до різних умов перегляду.
- **Adaptive Design** — макет може перемикатися між заздалегідь визначеними варіантами.

У сучасному веброзробленні ці підходи часто використовуються разом.

---

## 3. Що потрібно знати перед вивченням Fluid Layouts?

Для роботи з гумовими макетами необхідно розуміти:

- CSS Box Model;
- `width`, `height`, `min-width`, `max-width`;
- `min-height`, `max-height`;
- `margin`, `padding`, `gap`;
- Flexbox;
- CSS Grid;
- одиниці `px`, `%`, `rem`, `vw`, `vh`;
- функції `min()`, `max()`, `clamp()`;
- медіазапити;
- viewport браузера.

Ці знання допомагають не просто змінювати ширину елементів, а будувати макет, який передбачувано поводиться в різних умовах.

## 4. Основні одиниці вимірювання

### 4.1. Пікселі — `px`

`px` — CSS-піксель, одиниця вимірювання, яка не дорівнює фізичному пікселю екрана один до одного в усіх ситуаціях.

Пікселі зручні для значень, які потрібно контролювати досить точно:

- тонких меж;
- невеликих декоративних деталей;
- деяких тіней;
- товщини ліній.

    .card {
      border: 1px solid #ddd;
    }

    .icon {
      width: 24px;
      height: 24px;
    }

Однак якщо ширина всього макета задана тільки в пікселях, він може погано працювати на вузьких екранах.

Не потрібно повністю відмовлятися від `px`. Важливо вибирати одиницю відповідно до призначення властивості.

### 4.2. Відсотки — `%`

Відсотки задають розмір відносно відповідної величини батьківського або іншого визначеного контексту.

Для `width` відсоткова ширина зазвичай обчислюється від ширини containing block — блоку, відносно якого позиціонується елемент.

    .container {
      width: 90%;
    }

Контейнер займає приблизно 90% доступної ширини свого containing block.

Інший приклад:

    .sidebar {
      width: 30%;
    }

    .content {
      width: 70%;
    }

Такі значення можна використовувати для пропорційного поділу простору.

Але сума відсоткових ширин не враховує автоматично всі додаткові відступи, межі та проміжки.

Наприклад, дві колонки по `50%` разом із додатковим `gap` можуть не поміститися в контейнер.

Для таких випадків часто зручніше використовувати Flexbox або Grid.

### 4.3. `rem`

`rem` — одиниця, відносна до розміру шрифту кореневого елемента документа, зазвичай `html`.

    html {
      font-size: 16px;
    }

    .card {
      padding: 1.5rem;
    }

За стандартного кореневого розміру `16px` відступ `1.5rem` дорівнює `24px`.

Переваги `rem`:

- зручне масштабування типографіки;
- узгоджені відступи;
- підтримка користувацьких налаштувань розміру тексту;
- зручність створення системи дизайн-токенів.

    :root {
      --space-sm: 0.5rem;
      --space-md: 1rem;
      --space-lg: 1.5rem;
      --space-xl: 2rem;
    }

    .card {
      padding: var(--space-lg);
    }

`rem` особливо корисний для тексту, внутрішніх відступів і відстаней між компонентами.

### 4.4. `em`

`em` — одиниця, відносна до розміру шрифту відповідного контексту.

Для `font-size` вона обчислюється від розміру шрифту батьківського елемента. Для багатьох інших властивостей, наприклад `padding`, — від розміру шрифту самого елемента.

    .button {
      font-size: 1rem;
      padding: 0.75em 1.25em;
    }

Внутрішні відступи кнопки залежать від її розміру тексту.

Це зручно для компонентів, які повинні масштабуватися разом зі своїм текстом.

### 4.5. Одиниці viewport — `vw` і `vh`

`vw` — одиниця, відносна до ширини viewport.

`vh` — одиниця, відносна до висоти viewport.

    .hero-title {
      font-size: 5vw;
    }

Якщо viewport стає ширшим, розмір тексту збільшується.

Однак пряме використання `vw` для тексту може спричинити проблеми:

- на вузькому екрані текст стане надто малим;
- на широкому моніторі текст стане надто великим;
- користувачеві може бути складніше читати текст при масштабуванні сторінки.

Тому для типографіки часто краще використовувати `clamp()`.

    .hero-title {
      font-size: clamp(2rem, 5vw, 4rem);
    }

Для висоти секцій також варто враховувати особливості мобільних браузерів. Доступні одиниці `svh`, `lvh` і `dvh` можуть бути корисні, коли висота viewport змінюється через панелі браузера.

    .hero {
      min-height: 100vh;
      min-height: 100dvh;
    }

Другий рядок є сучасним перевизначенням для браузерів, які підтримують `dvh`.

### 4.6. Яку одиницю вибирати?

| Завдання | Типовий вибір |
|---|---|
| Тонка межа | `px` |
| Ширина контейнера відносно батьківського блоку | `%` |
| Відступи дизайн-системи | `rem` |
| Розміри тексту, що масштабуються разом із компонентом | `em` |
| Плавна зміна розміру залежно від viewport | `vw` у поєднанні з `clamp()` |
| Мінімальна або максимальна ширина макета | `min-width`, `max-width` |
| Гнучкий розподіл простору між колонками | `fr`, Flexbox |
| Обмежений плавний розмір | `clamp()` |

Це не жорсткі правила. Остаточний вибір залежить від задачі та поведінки компонента.

## 5. Фіксована, гумова та обмежена ширина

### 5.1. Фіксована ширина

    .container {
      width: 1200px;
    }

Перевага: легко контролювати розміри на певному екрані.

Недоліки:

- на екрані шириною `390px` контейнер не поміститься;
- з'явиться горизонтальне прокручування або обрізання;
- на дуже широкому екрані контейнер не використає додатковий простір автоматично.

Фіксована ширина може бути доречною для окремих елементів, але рідко підходить для головного контейнера сторінки без додаткових обмежень.

### 5.2. Гумова ширина

    .container {
      width: 90%;
    }

Контейнер займає 90% ширини свого containing block.

Перевага: ширина автоматично змінюється разом із доступним простором.

Недолік: на дуже широкому моніторі контейнер може стати надмірно широким.

### 5.3. Гумова ширина з максимальною межею

    .container {
      width: 90%;
      max-width: 1200px;
      margin-inline: auto;
    }

Це один із найпоширеніших підходів до побудови сучасних макетів.

На вузькому екрані контейнер займає більшу частину доступної ширини.

На широкому екрані його ширина не перевищує `1200px`.

`margin-inline: auto` центрує контейнер по горизонталі, коли доступний вільний простір.

### 5.4. Ширина з урахуванням внутрішніх відступів

    .container {
      width: 100%;
      max-width: 1200px;
      margin-inline: auto;
      padding-inline: 1rem;
    }

Цей варіант дозволяє контейнеру займати всю доступну ширину, але залишає внутрішні відступи.

Щоб ширина елементів була передбачуваною, часто використовують `box-sizing: border-box`.

    *,
    *::before,
    *::after {
      box-sizing: border-box;
    }

За `border-box` значення `width` включає внутрішні відступи та межі елемента.

Це допомагає уникати несподіваного збільшення загальної ширини.

## 6. Мінімальні та максимальні розміри

Для гумових макетів особливо важливі властивості:

- `min-width`;
- `max-width`;
- `min-height`;
- `max-height`.

Вони дозволяють поєднати гнучкість з обмеженнями.

### 6.1. `min-width`

Визначає мінімально допустиму ширину елемента.

    .sidebar {
      min-width: 220px;
    }

Це може бути корисно для бічної панелі на широких екранах.

Однак на маленькому екрані така панель може не поміститися. Тому потрібно передбачити іншу поведінку: наприклад, перехід у вертикальний макет.

### 6.2. `max-width`

Визначає максимальну ширину елемента.

    .article {
      width: 100%;
      max-width: 70ch;
      margin-inline: auto;
    }

`70ch` приблизно відповідає ширині 70 символів `0` у поточному шрифті. Це не гарантує точну кількість символів у кожному рядку, але допомагає контролювати ширину текстового блоку.

Для довгих статей обмеження ширини часто покращує читабельність.

### 6.3. `min-height`

Визначає мінімальну висоту.

    .hero {
      min-height: 400px;
    }

На відміну від `height`, властивість `min-height` дозволяє елементу збільшуватися, якщо вміст не поміщається.

Це зазвичай безпечніше для секцій із текстом, який може переноситися на додаткові рядки.

### 6.4. Чому не варто без потреби задавати фіксовану висоту?

    .card {
      height: 250px;
    }

Якщо текст збільшиться або користувач змінить масштаб сторінки, вміст може вийти за межі картки.

У багатьох випадках краще:

    .card {
      min-height: 250px;
      padding: 1.5rem;
    }

Фіксована висота доречна тоді, коли вона виправдана конкретним завданням, наприклад для певного медіаелемента або контрольованої декоративної композиції.

## 7. CSS-функції `min()`, `max()` і `clamp()`

Ці функції дозволяють задавати гнучкі розміри без великої кількості медіазапитів.

### 7.1. `min()`

Повертає найменше з переданих значень.

    .container {
      width: min(90%, 1200px);
      margin-inline: auto;
    }

Браузер вибирає менше значення між `90%` доступної ширини та `1200px`.

Це компактний спосіб створити контейнер, який звужується на маленьких екранах і має максимальну ширину на великих.

### 7.2. `max()`

Повертає найбільше з переданих значень.

    .section {
      padding-inline: max(1rem, 4vw);
    }

Внутрішні відступи не будуть меншими за `1rem`, але можуть збільшуватися залежно від ширини viewport.

Важливо: надто великі відступи на широких екранах можуть зменшити корисну ширину контенту, тому результат потрібно перевіряти.

### 7.3. `clamp()`

Функція `clamp()` приймає три значення:

    clamp(мінімальне, бажане, максимальне)

Бажане значення змінюється, але результат не виходить за визначені межі.

    .title {
      font-size: clamp(2rem, 4vw, 4rem);
    }

У цьому прикладі:

- мінімум — `2rem`;
- бажаний розмір — `4vw`;
- максимум — `4rem`.

Це зручно для плавного масштабування заголовків, відступів і деяких розмірів компонентів.

### 7.4. Fluid Typography

**Fluid Typography** — це плавне масштабування тексту залежно від доступного простору.

    h1 {
      font-size: clamp(2rem, 1.2rem + 3vw, 4rem);
      line-height: 1.1;
    }

На вузьких екранах заголовок не стає меншим за мінімум, а на широких не перевищує максимум.

Для основного тексту не завжди потрібне таке ж активне масштабування. Зазвичай важливіше зберегти комфортний для читання розмір.

### 7.5. Fluid Spacing

Відступи також можуть плавно змінюватися.

    .section {
      padding-block: clamp(2rem, 5vw, 5rem);
      padding-inline: clamp(1rem, 3vw, 3rem);
    }

Це допомагає уникнути ситуації, коли на маленькому екрані відступи завеликі, а на великому — замалі.

Проте не всі відступи мають масштабуватися. Внутрішня структура компонентів часто краще працює з послідовними значеннями з дизайн-системи.

## 8. Fluid Layouts у Flexbox

Flexbox дозволяє розподіляти доступний простір між елементами.

### 8.1. Гнучкі елементи

    .features {
      display: flex;
      gap: 1rem;
    }

    .feature {
      flex: 1;
    }

Кожен елемент може займати рівну частину доступного простору.

Однак на вузькому екрані елементи можуть стати надто вузькими.

### 8.2. Перенесення елементів

    .features {
      display: flex;
      flex-wrap: wrap;
      gap: 1rem;
    }

    .feature {
      flex: 1 1 250px;
    }

Тут `flex: 1 1 250px` задає:

- `flex-grow: 1` — елемент може збільшуватися;
- `flex-shrink: 1` — елемент може зменшуватися;
- `flex-basis: 250px` — початкова бажана основа розміру.

Коли простору не вистачає, елементи можуть переходити на новий рядок.

Важливо: `250px` тут не означає абсолютну мінімальну ширину елемента. Якщо потрібно встановити справжнє обмеження, можна додати `min-width` або використати інший спосіб побудови макета.

### 8.3. Приклад адаптивної групи карток

    .cards {
      display: flex;
      flex-wrap: wrap;
      gap: 1rem;
    }

    .card {
      flex: 1 1 16rem;
      min-width: 0;
    }

Такий макет дозволяє карткам переноситися на нові рядки та використовувати доступний простір.

Кількість карток у рядку залежить від ширини контейнера, розміру карток і проміжків.

## 9. Fluid Layouts у CSS Grid

CSS Grid зручний для макетів із рядками та колонками.

### 9.1. Колонки з однаковими частками

    .layout {
      display: grid;
      grid-template-columns: 1fr 1fr;
      gap: 1.5rem;
    }

`fr` — одиниця частки вільного простору Grid-контейнера.

Дві колонки по `1fr` отримують однакові частки доступного простору після врахування проміжків та інших обмежень.

### 9.2. Різні пропорції колонок

    .layout {
      display: grid;
      grid-template-columns: 1fr 2fr;
      gap: 1.5rem;
    }

За відсутності інших обмежень друга колонка отримує приблизно вдвічі більшу частку вільного простору, ніж перша.

Такий підхід підходить для макетів із бічною панеллю та основним контентом.

### 9.3. Автоматичні колонки з `auto-fit`

    .cards {
      display: grid;
      grid-template-columns: repeat(
        auto-fit,
        minmax(220px, 1fr)
      );
      gap: 1.5rem;
    }

Браузер розміщує стільки колонок, скільки може поміститися з урахуванням заданих розмірів і доступного простору.

`minmax(220px, 1fr)` означає, що мінімальна бажана ширина колонки становить `220px`, а її максимальна ширина може займати доступну частку простору.

На вузькому контейнері колонки можуть перейти в один стовпець.

### 9.4. Різниця між `auto-fit` та `auto-fill`

Обидва значення використовуються з автоматичним створенням колонок у Grid.

- `auto-fill` намагається зберігати доступні треки, навіть якщо деякі залишаються порожніми.
- `auto-fit` після розміщення елементів може згорнути порожні треки, дозволяючи наявним колонкам зайняти більше простору.

Для типових адаптивних сіток карток часто зручно почати з `auto-fit`.

### 9.5. Коли використовувати Grid, а коли Flexbox?

**Grid** зазвичай зручніший, якщо:

- потрібна двовимірна сітка;
- потрібно контролювати колонки та рядки;
- картки повинні розміщуватися в регулярній сітці;
- потрібно автоматично створювати колонки.

**Flexbox** зазвичай зручніший, якщо:

- потрібно розташувати елементи в одному напрямку;
- потрібно вирівняти елементи;
- елементи мають переноситися на нові рядки;
- важливо розподілити простір між елементами одного ряду.

Ці технології можна комбінувати в межах однієї сторінки.

## 10. Контейнери та внутрішні відступи

Гумовий макет повинен не лише змінювати ширину, а й зберігати комфортні відстані між контентом і краями екрана.

### 10.1. Центрований контейнер

    .container {
      width: min(100% - 2rem, 1200px);
      margin-inline: auto;
    }

Тут контейнер має:

- доступну ширину за вирахуванням `2rem`;
- максимальну ширину `1200px`;
- автоматичне центрування.

Цей варіант зручний для більшості основних секцій сайту.

### 10.2. Контентний контейнер

    .content {
      width: min(100% - 2rem, 70ch);
      margin-inline: auto;
    }

Для текстового контенту може бути доречним вужче обмеження, ніж для загального макета сторінки.

### 10.3. Розділення широкого та вузького контенту

    .container {
      width: min(100% - 2rem, 1200px);
      margin-inline: auto;
    }

    .prose {
      width: min(100%, 70ch);
    }

    .prose p {
      margin-block: 0 1rem;
    }

Загальна секція може займати ширший простір, тоді як текстова частина залишається зручною для читання.

## 11. Fluid Layouts і Responsive Breakpoints

Гумові макети не скасовують потребу в медіазапитах.

Вони дозволяють багатьом елементам адаптуватися плавно, але іноді певна структура перестає працювати правильно.

Наприклад, дві колонки можуть виглядати добре на широкому екрані, але стати надто вузькими на телефоні.

У такому разі можна змінити структуру за допомогою медіазапиту.

    .layout {
      display: grid;
      grid-template-columns: 1fr 2fr;
      gap: 2rem;
    }

    @media (max-width: 700px) {
      .layout {
        grid-template-columns: 1fr;
      }
    }

До ширини `700px` включно макет використовує одну колонку. На ширших екранах застосовується початковий двоколонковий варіант.

Число `700px` — лише приклад. Реальну точку перелому потрібно вибирати відповідно до вмісту та поведінки інтерфейсу.

### Важливий принцип

**Спочатку використовуйте гнучкі розміри, а медіазапити додавайте тоді, коли макету справді потрібна зміна структури.**

Не потрібно створювати окремий медіазапит для кожної ширини екрана.

## 12. Розміри зображень і медіаконтенту

Зображення також повинні адаптуватися до доступного простору.

### 12.1. Зображення в межах контейнера

    img {
      max-width: 100%;
      height: auto;
    }

`max-width: 100%` не дозволяє зображенню перевищувати ширину його containing block.

`height: auto` зберігає пропорції зображення.

Для більшості звичайних зображень це хороший базовий підхід.

### 12.2. Зображення однакового розміру в картках

    .card-image {
      width: 100%;
      aspect-ratio: 16 / 9;
      object-fit: cover;
      display: block;
    }

`aspect-ratio` задає співвідношення ширини та висоти.

`object-fit: cover` дозволяє заповнити область зображенням, обрізаючи частину вмісту за потреби.

Це зручно для карток статей, галерей і каталогів.

### 12.3. Коли не варто використовувати `cover`?

Якщо потрібно показати все зображення без обрізання, можна використати:

    .product-image {
      width: 100%;
      aspect-ratio: 1;
      object-fit: contain;
    }

`contain` показує все зображення, але може залишати вільний простір усередині області.

Для фотографій і декоративних прев'ю часто доречний `cover`, а для товарів, логотипів і схем — `contain`.

## 13. Приклад: повністю гумова сітка карток

Уявімо сторінку з картками навчальних матеріалів.

Потрібно, щоб:

- на вузьких екранах картки займали всю доступну ширину;
- на ширших екранах у рядку було кілька карток;
- колонки автоматично змінювали кількість;
- контейнер не ставав надто широким;
- зображення зберігали пропорції;
- відступи залишалися комфортними.

HTML:

    <section class="materials">
      <div class="container">
        <h2 class="materials__title">
          Навчальні матеріали
        </h2>

        <div class="materials__grid">
          <article class="card">
            <img
              class="card__image"
              src="/images/html.jpg"
              alt="HTML"
            >
            <h3 class="card__title">HTML</h3>
            <p class="card__text">
              Основи структури вебсторінок.
            </p>
          </article>

          <article class="card">
            <img
              class="card__image"
              src="/images/css.jpg"
              alt="CSS"
            >
            <h3 class="card__title">CSS</h3>
            <p class="card__text">
              Стилізація та побудова макетів.
            </p>
          </article>

          <article class="card">
            <img
              class="card__image"
              src="/images/js.jpg"
              alt="JavaScript"
            >
            <h3 class="card__title">JavaScript</h3>
            <p class="card__text">
              Логіка та інтерактивність сторінок.
            </p>
          </article>
        </div>
      </div>
    </section>

CSS:

    *,
    *::before,
    *::after {
      box-sizing: border-box;
    }

    body {
      margin: 0;
      font-family: system-ui, sans-serif;
      line-height: 1.5;
    }

    .container {
      width: min(100% - 2rem, 1200px);
      margin-inline: auto;
    }

    .materials {
      padding-block: clamp(2rem, 5vw, 5rem);
    }

    .materials__title {
      margin-block: 0 1.5rem;
      font-size: clamp(1.75rem, 3vw, 2.5rem);
    }

    .materials__grid {
      display: grid;
      grid-template-columns: repeat(
        auto-fit,
        minmax(min(100%, 240px), 1fr)
      );
      gap: 1.5rem;
    }

    .card {
      min-width: 0;
      padding: 1rem;
      border: 1px solid #ddd;
      border-radius: 0.75rem;
    }

    .card__image {
      display: block;
      width: 100%;
      aspect-ratio: 16 / 9;
      object-fit: cover;
      border-radius: 0.5rem;
    }

    .card__title {
      margin-block: 1rem 0.5rem;
      font-size: 1.25rem;
    }

    .card__text {
      margin: 0;
      overflow-wrap: anywhere;
    }

### Чому цей макет гумовий?

1. Контейнер змінює ширину залежно від доступного простору.
2. `max-width` обмежує максимальну ширину основного контенту.
3. `clamp()` плавно змінює вертикальні відступи та розмір заголовка.
4. Grid автоматично визначає кількість колонок.
5. `min(100%, 240px)` допомагає уникнути проблеми, коли мінімальна ширина колонки перевищує доступну ширину контейнера.
6. Зображення адаптується до ширини картки.
7. `min-width: 0` дозволяє Grid-елементу стискатися в межах свого треку.
8. `overflow-wrap: anywhere` допомагає запобігати переповненню через довгі нерозривні рядки.

У цьому прикладі не потрібні окремі медіазапити для кожної ширини смартфона чи планшета.

## 14. Типові помилки під час створення гумових макетів

### Помилка 1. Фіксована ширина основного контейнера

    .container {
      width: 1200px;
    }

Проблема: контейнер може бути ширшим за екран.

Краще:

    .container {
      width: min(100% - 2rem, 1200px);
      margin-inline: auto;
    }

### Помилка 2. Використання лише відсотків

    .content {
      width: 100%;
    }

Це не завжди помилка, але самі відсотки не забезпечують оптимальної читабельності або потрібних відступів.

Краще комбінувати ширину з обмеженнями:

    .content {
      width: min(100% - 2rem, 70ch);
      margin-inline: auto;
    }

### Помилка 3. Надто великі відступи на смартфоні

    .section {
      padding-inline: 10%;
    }

На вузьких екранах це може забрати значну частину корисної ширини.

Краще:

    .section {
      padding-inline: clamp(1rem, 4vw, 3rem);
    }

### Помилка 4. Занадто широкі текстові рядки

    .article {
      width: 100%;
    }

Якщо стаття розтягується на весь широкий монітор, читати її може бути незручно.

Краще:

    .article {
      width: min(100%, 70ch);
    }

### Помилка 5. Застосування `vw` без меж

    h1 {
      font-size: 6vw;
    }

На маленькому екрані текст може стати надто малим, а на великому — надто великим.

Краще:

    h1 {
      font-size: clamp(2rem, 4vw, 4rem);
    }

### Помилка 6. Жорстко задана висота текстової картки

    .card {
      height: 200px;
    }

Текст може не поміститися, якщо він довший або користувач збільшить масштаб.

Краще:

    .card {
      min-height: 200px;
    }

### Помилка 7. Зображення виходить за межі контейнера

    img {
      width: 600px;
    }

Для адаптивних зображень краще:

    img {
      max-width: 100%;
      height: auto;
    }

### Помилка 8. Колонки не стискаються через довгий вміст

Іноді Grid або Flexbox-елемент не стискається так, як очікується, через мінімальні розміри вмісту.

Можна перевірити:

    .grid-item {
      min-width: 0;
    }

    .flex-item {
      min-width: 0;
    }

Для довгих слів, URL або інших нерозривних рядків додатково може знадобитися `overflow-wrap: anywhere`.

### Помилка 9. Надто багато медіазапитів

Якщо макет можна побудувати за допомогою `minmax()`, `auto-fit`, відсотків і `clamp()`, не обов'язково задавати окремий медіазапит для кожного пристрою.

Медіазапити варто застосовувати там, де потрібно змінити структуру, порядок, видимість або поведінку елементів.

### Помилка 10. Перевірка тільки на одному екрані

Макет може добре виглядати на ноутбуці, але мати проблеми на вузькому смартфоні або при збільшенні тексту.

Перевіряйте не лише конкретні пристрої, а й різні ширини viewport та нестандартні умови.

## 15. Тестування гумового макета

Після створення макета потрібно перевірити його поведінку.

### Що перевіряти?

- ✔ Чи немає горизонтального прокручування без обґрунтованої потреби?
- ✔ Чи не обрізаються заголовки та абзаци?
- ✔ Чи зберігається читабельність тексту?
- ✔ Чи достатньо місця для кнопок та інтерактивних елементів?
- ✔ Чи не стають картки надто вузькими?
- ✔ Чи не розтягується контент на надмірну ширину?
- ✔ Чи адаптуються зображення?
- ✔ Чи правильно переносяться колонки?
- ✔ Чи працює макет при збільшенні тексту?
- ✔ Чи не порушується порядок читання на вузькому екрані?
- ✔ Чи не перекривають контент фіксовані елементи?

### Як тестувати?

1. Відкрийте сторінку в браузері.
2. Увімкніть DevTools.
3. Перейдіть у режим адаптивного перегляду.
4. Перевірте вузьку ширину, наприклад `320px`.
5. Перевірте ширину близько `390px`.
6. Перевірте планшетний розмір.
7. Перевірте звичайний ноутбук.
8. Перевірте широкий монітор.
9. Змініть ширину поступово, а не лише між кількома готовими пресетами.
10. Перевірте збільшення сторінки та довший вміст.

Числові значення тут — приклади для перевірки, а не обов'язкові точки перелому для кожного проєкту.

### Як знайти горизонтальне переповнення?

У DevTools можна дослідити елементи, які виходять за межі viewport.

Для тимчасової діагностики можна виконати в консолі браузера:

    [...document.querySelectorAll("*")].filter((element) => {
      const rect = element.getBoundingClientRect();

      return (
        rect.left < 0 ||
        rect.right > document.documentElement.clientWidth
      );
    });

Цей код допомагає знайти елементи, чиї межі виходять за горизонтальні межі viewport.

Однак не кожен знайдений елемент обов'язково є помилкою. Наприклад, горизонтальний слайдер може навмисно виходити за межі контейнера.

Після виявлення проблеми потрібно визначити її причину: фіксовану ширину, довгий текст, Grid-трек, відступи, позиціонування або інший чинник.

## 16. Fluid Design і доступність

Гнучкий макет повинен залишатися зручним для користувачів із різними потребами.

### 16.1. Масштабування тексту

Не задавайте тексту надто жорсткі розміри, які перешкоджають його збільшенню.

    body {
      font-size: 1rem;
      line-height: 1.5;
    }

    h1 {
      font-size: clamp(2rem, 4vw, 4rem);
      line-height: 1.1;
    }

Перевіряйте, чи не обрізається текст при збільшенні масштабу сторінки.

### 16.2. Достатня ширина для елементів керування

Кнопки та поля введення повинні залишатися доступними для натискання.

    .button {
      max-width: 100%;
      padding: 0.75rem 1rem;
    }

Не дозволяйте тексту в кнопці обрізатися без зрозумілої причини.

### 16.3. Не приховуйте важливий вміст лише через ширину

Якщо на вузькому екрані контент не поміщається, не завжди правильно просто приховати його.

Спочатку визначте, чи можна:

- змінити структуру;
- перенести елементи;
- зробити навігацію компактнішою;
- дозволити тексту переноситися;
- змінити порядок блоків;
- застосувати горизонтальне прокручування там, де воно справді доречне.

### 16.4. Перевіряйте реальний вміст

Макет, який працює з коротким тестовим текстом, може зламатися з довгим ім'ям, адресою, заголовком або перекладом іншою мовою.

Тому перевіряйте різні довжини контенту, а не лише ідеальні приклади.

## 17. Fluid Layouts та Container Queries

Медіазапити зазвичай орієнтуються на характеристики viewport або пристрою.

Але іноді компонент повинен адаптуватися до ширини саме свого контейнера.

Наприклад, одна й та сама картка може бути:

- широкою в основній колонці;
- вузькою в бічній панелі;
- частиною модального вікна.

Для таких сценаріїв можуть використовуватися **Container Queries**.

    .card-wrapper {
      container-type: inline-size;
    }

    .card {
      display: grid;
      gap: 1rem;
    }

    @container (min-width: 500px) {
      .card {
        grid-template-columns: 160px 1fr;
        align-items: center;
      }
    }

Коли контейнер досягає ширини `500px`, картка переходить до двоколонкового розташування.

Це не означає, що кожен макет потребує Container Queries. Для простих сторінок часто достатньо звичайних гнучких розмірів і медіазапитів.

Використовуйте Container Queries тоді, коли компонент повинен реагувати на власний доступний простір незалежно від загальної ширини сторінки.

## 18. Практичний алгоритм створення Fluid Layout

Під час створення нового інтерфейсу можна діяти послідовно.

### Крок 1. Визначте структуру

З'ясуйте, які елементи потрібні:

- заголовок;
- навігація;
- основний контент;
- бічна панель;
- картки;
- кнопки;
- зображення.

### Крок 2. Визначте основний контейнер

    .container {
      width: min(100% - 2rem, 1200px);
      margin-inline: auto;
    }

Не починайте з фіксованої ширини всієї сторінки.

### Крок 3. Визначте принцип розміщення

- Один напрямок — Flexbox.
- Двовимірна сітка — Grid.
- Звичайний текстовий потік — стандартне блокове розташування.
- Гнучкі картки — Grid з `auto-fit` або Flexbox із перенесенням.

### Крок 4. Визначте мінімальні та максимальні розміри

    .content {
      width: 100%;
      max-width: 70ch;
    }

    .image {
      max-width: 100%;
      height: auto;
    }

### Крок 5. Додайте гнучкі відступи та типографіку

    .section {
      padding-block: clamp(2rem, 5vw, 5rem);
    }

    .section-title {
      font-size: clamp(1.75rem, 3vw, 3rem);
    }

### Крок 6. Перевірте поведінку на різних ширинах

Змінюйте ширину viewport поступово.

Звертайте увагу на момент, коли:

- текст стає незручним для читання;
- колонки стають надто вузькими;
- навігація перестає поміщатися;
- кнопки починають перекриватися;
- зображення порушують композицію.

### Крок 7. Додайте медіазапити за потреби

    .content-layout {
      display: grid;
      grid-template-columns: 16rem minmax(0, 1fr);
      gap: 2rem;
    }

    @media (max-width: 750px) {
      .content-layout {
        grid-template-columns: 1fr;
      }
    }

Точка перелому повинна відповідати моменту, коли поточний макет перестає працювати належним чином.

### Крок 8. Перевірте доступність

Перевірте збільшення тексту, порядок вмісту, клавіатурну навігацію, читабельність та відсутність непотрібного горизонтального прокручування.

## 19. Що потрібно запам'ятати

✔ **Fluid Layout** — макет, який гнучко використовує доступний простір.

✔ Фіксована ширина всього контейнера часто створює проблеми на вузьких екранах.

✔ `%` дозволяє задавати розміри відносно containing block.

✔ `rem` зручний для типографіки та відступів, а `em` — для розмірів, пов'язаних із текстом компонента.

✔ `vw` і `vh` залежать від viewport, але їх потрібно використовувати обережно.

✔ `min-width`, `max-width`, `min-height` і `max-height` дозволяють контролювати межі гнучких розмірів.

✔ `min()`, `max()` і `clamp()` допомагають створювати адаптивні розміри без великої кількості медіазапитів.

✔ `clamp(min, preferred, max)` задає мінімальну, бажану та максимальну величину.

✔ Flexbox зручний для гнучкого розташування елементів в одному напрямку.

✔ Grid зручний для сіток, автоматичних колонок і двовимірних макетів.

✔ `minmax()`, `auto-fit` і `1fr` дозволяють створювати гнучкі сітки.

✔ `max-width` допомагає запобігати надмірній ширині контейнерів.

✔ `min-height` часто безпечніший за фіксований `height` для секцій із текстом.

✔ Зображення зазвичай повинні мати `max-width: 100%` і `height: auto`, якщо немає інших вимог.

✔ Медіазапити залишаються потрібними, коли потрібно змінити структуру або поведінку макета.

✔ Container Queries допомагають адаптувати компоненти до ширини їхнього контейнера.

✔ Макет потрібно перевіряти на різних ширинах viewport, із довгим текстом і збільшеним масштабом.

✔ Гнучкість не означає, що всі розміри мають змінюватися без обмежень.

## 20. Мінішпаргалка

### Гумовий контейнер

    .container {
      width: min(100% - 2rem, 1200px);
      margin-inline: auto;
    }

### Контейнер для тексту

    .prose {
      width: min(100%, 70ch);
      margin-inline: auto;
    }

### Плавна типографіка

    h1 {
      font-size: clamp(2rem, 4vw, 4rem);
    }

### Плавні відступи

    .section {
      padding-block: clamp(2rem, 5vw, 5rem);
      padding-inline: clamp(1rem, 3vw, 3rem);
    }

### Адаптивна сітка карток

    .grid {
      display: grid;
      grid-template-columns: repeat(
        auto-fit,
        minmax(min(100%, 240px), 1fr)
      );
      gap: 1.5rem;
    }

### Гнучкий ряд елементів

    .row {
      display: flex;
      flex-wrap: wrap;
      gap: 1rem;
    }

    .row > * {
      flex: 1 1 15rem;
    }

### Адаптивне зображення

    img {
      display: block;
      max-width: 100%;
      height: auto;
    }

### Зображення з контрольованими пропорціями

    .image {
      width: 100%;
      aspect-ratio: 16 / 9;
      object-fit: cover;
    }

### Макет із двох колонок до точки перелому

    .layout {
      display: grid;
      grid-template-columns: 16rem minmax(0, 1fr);
      gap: 2rem;
    }

    @media (max-width: 750px) {
      .layout {
        grid-template-columns: 1fr;
      }
    }

### Запобігання переповненню через довгі слова

    .text {
      overflow-wrap: anywhere;
    }

### Передбачувана модель розмірів

    *,
    *::before,
    *::after {
      box-sizing: border-box;
    }

## 22. Практичні завдання

### Завдання 1. Гумовий контейнер

Створи контейнер, який:

- займає доступну ширину;
- має горизонтальні відступи;
- не перевищує `1100px`;
- розташований по центру сторінки.

Перевір його на ширині viewport `320px`, `768px` і `1440px`.

### Завдання 2. Плавний заголовок

Створи заголовок, який:

- не менший за `2rem`;
- плавно збільшується залежно від viewport;
- не перевищує `4rem`.

Використай `clamp()`.

### Завдання 3. Сітка карток

Створи шість карток із CSS Grid.

Вимоги:

- мінімальна бажана ширина картки — `220px`;
- проміжок між картками — `1rem`;
- кількість колонок змінюється автоматично;
- на вузькому екрані картки займають доступну ширину.

Спробуй використати `repeat()`, `auto-fit` і `minmax()`.

### Завдання 4. Бічна панель

Створи макет із двох колонок:

- бічна панель має ширину `250px`;
- основний контент займає решту простору;
- на вузькому екрані колонки розташовуються вертикально.

Використай Grid і медіазапит.

### Завдання 5. Адаптивне зображення

Створи картку зображення, яке:

- займає всю ширину картки;
- має співвідношення сторін `16 / 9`;
- обрізається за допомогою `object-fit: cover`;
- не виходить за межі контейнера.

### Завдання 6. Fluid Spacing

Створи секцію, в якій вертикальні відступи плавно змінюються від `2rem` до `5rem`.

Використай `clamp()`.

### Завдання 7. Перевірка переповнення

Створи картку з довгим URL або нерозривним текстом.

Перевір, чи не виходить текст за межі картки. Виправ проблему за допомогою відповідних властивостей CSS.

### Завдання 8. Мініпроєкт — адаптивний каталог

Створи сторінку каталогу навчальних матеріалів.

Потрібно реалізувати:

- центрований гумовий контейнер;
- заголовок із плавним масштабуванням;
- адаптивну сітку карток;
- зображення з однаковими пропорціями;
- гнучкі відступи;
- коректне перенесення тексту;
- відсутність непотрібного горизонтального прокручування.

Спочатку спробуй побудувати макет без медіазапитів. Потім додай їх лише там, де справді потрібно змінити структуру.

## 23. Рівні опанування теми

### Core — базовий рівень

Ти повинен уміти:

- пояснити різницю між фіксованим і гумовим макетом;
- використовувати `%`, `rem`, `vw`;
- створювати контейнер із `max-width`;
- використовувати `min-width` і `max-width`;
- робити зображення адаптивними;
- розуміти призначення `box-sizing: border-box`.

### Junior — практичний рівень

Ти повинен уміти:

- створювати гумові контейнери;
- використовувати Flexbox і Grid;
- будувати автоматичні сітки через `auto-fit` і `minmax()`;
- масштабувати заголовки через `clamp()`;
- використовувати `min()`, `max()` і `clamp()`;
- поєднувати гумові розміри з медіазапитами;
- знаходити й виправляти горизонтальне переповнення;
- перевіряти макет на різних ширинах viewport.

### Middle — поглиблений рівень

Ти повинен уміти:

- проєктувати гнучкі дизайн-системи;
- вибирати межі контейнерів і типографіки відповідно до контенту;
- використовувати Container Queries;
- враховувати довгі переклади та динамічні дані;
- будувати компоненти, які працюють у різних контекстах;
- перевіряти макет при масштабуванні тексту;
- поєднувати Fluid Layouts, Responsive Design і доступність.

### Senior — системний рівень

Ти повинен уміти:

- визначати принципи адаптивної композиції для всього продукту;
- створювати узгоджену систему контейнерів, відступів і типографіки;
- визначати, де потрібні плавні зміни, а де — структурні переломи;
- оцінювати компроміси між щільністю інформації та читабельністю;
- проєктувати гнучкі компоненти для різних сторінок і контейнерів;
- перевіряти поведінку макета на нестандартних розмірах і з різним вмістом.

## 24. Головний принцип Fluid Layouts

**Не прив'язуй весь дизайн до одного розміру екрана. Прив'язуй його до доступного простору, змісту та потреб користувача.**

Використовуй гнучкі розміри там, де елементи можуть плавно адаптуватися. Застосовуй обмеження там, де потрібно зберегти читабельність. Використовуй медіазапити, коли структура повинна змінитися.

У результаті хороший гумовий макет не просто зменшується або збільшується. Він зберігає пропорції, читабельність, ієрархію та зручність взаємодії на різних екранах.
