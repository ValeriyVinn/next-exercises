# 07. Heading Hierarchy — Ієрархія заголовків

Ієрархія заголовків (*heading hierarchy*) — це система організації заголовків за рівнями важливості, яка допомагає користувачеві зрозуміти структуру сторінки, швидко знаходити потрібну інформацію та розрізняти головні й другорядні розділи.

У UI-дизайні ієрархія заголовків формується за допомогою HTML-рівнів `h1`–`h6`, розмірів шрифту, жирності, міжрядкового та міжлітерного інтервалів, відступів і контрасту.

**Мета:** навчитися створювати зрозумілу ієрархію заголовків, правильно використовувати HTML-заголовки та поєднувати семантичну структуру документа з візуальним дизайном.

---

## ✔ Що потрібно знати

- Що таке ієрархія заголовків і навіщо вона потрібна.
- Чим відрізняються семантична та візуальна ієрархії.
- Як працюють HTML-елементи `h1`, `h2`, `h3`, `h4`, `h5`, `h6`.
- Як визначати головний заголовок сторінки.
- Як організовувати заголовки розділів і підрозділів.
- Чому не можна вибирати HTML-рівень заголовка лише за його розміром.
- Як розміри шрифту, жирність, інтервали та відступи формують візуальну ієрархію.
- Як створювати типографічну шкалу заголовків.
- Як оформлювати заголовки адаптивно.
- Як перевіряти ієрархію з погляду доступності.
- Як застосовувати ієрархію в картках, формах, навігації та складних сторінках.
- Яких помилок варто уникати під час створення заголовків.

---

## 1. Що таке Heading Hierarchy

Ієрархія заголовків показує, як частини сторінки пов'язані між собою.

Наприклад, сторінка навчального курсу може мати таку структуру:

    h1 — Основи веброзробки

      h2 — HTML

        h3 — Структура HTML-документа

        h3 — Семантичні елементи

      h2 — CSS

        h3 — Селектори

        h3 — Flexbox і Grid

      h2 — JavaScript

        h3 — Змінні та типи даних

        h3 — Функції

Тут:

- `h1` визначає головну тему сторінки.
- `h2` визначає основні розділи.
- `h3` визначає підрозділи всередині розділів.
- Нижчі рівні використовуються для подальшого поділу складних тем.

Заголовки допомагають користувачеві зрозуміти зміст сторінки ще до того, як він прочитає всі абзаци.

### Навіщо потрібна ієрархія

- **Структура:** показує, які розділи є головними, а які вкладеними.
- **Сканування:** допомагає швидко знаходити потрібну інформацію.
- **Читабельність:** розділяє довгі сторінки на зрозумілі частини.
- **Доступність:** допомагає користувачам допоміжних технологій орієнтуватися в документі.
- **Візуальна організація:** створює зрозумілий порядок сприйняття інформації.
- **Послідовність дизайну:** дозволяє використовувати спільні правила заголовків у різних компонентах.

---

## 2. Семантична та візуальна ієрархії

Це два пов'язані, але різні поняття.

### 2.1. Семантична ієрархія

Семантична ієрархія визначає логічне місце заголовка в структурі документа.

В HTML для цього використовуються елементи від `h1` до `h6`.

    <h1>Навчальна платформа</h1>

    <h2>Курси</h2>

    <h3>Frontend-розробка</h3>

    <h3>Backend-розробка</h3>

    <h2>Про платформу</h2>

Ця структура описує зміст незалежно від того, як заголовки виглядають на екрані.

### 2.2. Візуальна ієрархія

Візуальна ієрархія визначає, наскільки помітним є кожен заголовок.

На неї впливають:

- `font-size` — розмір шрифту;
- `font-weight` — товщина символів;
- `line-height` — висота рядка;
- `letter-spacing` — міжлітерний інтервал;
- `margin` — відстань до сусідніх елементів;
- колір і контраст;
- ширина текстового контейнера;
- розташування заголовка в макеті.

Приклад:

    .page-title {
      font-size: 3rem;
      font-weight: 800;
      line-height: 1.1;
    }

    .section-title {
      font-size: 2rem;
      font-weight: 700;
      line-height: 1.2;
    }

    .subsection-title {
      font-size: 1.5rem;
      font-weight: 600;
      line-height: 1.3;
    }

### Головний принцип

HTML відповідає на запитання: **«Яке місце цей заголовок займає в структурі документа?»**

CSS відповідає на запитання: **«Як цей заголовок має виглядати?»**

Не потрібно використовувати неправильний HTML-рівень лише заради бажаного розміру шрифту.

## 3. HTML-заголовки h1–h6

HTML має шість рівнів заголовків.

| Елемент | Призначення |
|---|---|
| `h1` | Головний заголовок сторінки або основної теми |
| `h2` | Основний розділ |
| `h3` | Підрозділ усередині `h2` |
| `h4` | Підрозділ усередині `h3` |
| `h5` | Наступний рівень вкладеності |
| `h6` | Найглибший стандартний рівень заголовка |

Приклад:

    <h1>Посібник із веброзробки</h1>

    <h2>HTML</h2>

    <h3>Основи HTML</h3>

    <h4>Атрибути елементів</h4>

    <h5>Глобальні атрибути</h5>

    <h6>Приклади використання</h6>

На практиці більшості звичайних сторінок достатньо `h1`, `h2` і `h3`. Глибші рівні потрібні для складної структури.

### Чи обов'язково використовувати всі рівні?

Ні. Не потрібно створювати `h2`, `h3`, `h4`, `h5` і `h6`, якщо сторінка не має такої вкладеності.

Використовуй лише ті рівні, які відображають реальну структуру матеріалу.

---

## 4. Як правильно організовувати рівні заголовків

### 4.1. Починай із головної теми

Головний заголовок повинен чітко описувати призначення сторінки.

    <h1>Реєстрація на курс</h1>

Або:

    <h1>Основи JavaScript</h1>

Користувач має швидко зрозуміти, де він перебуває і про що ця сторінка.

### 4.2. Використовуй h2 для основних розділів

    <h1>Основи JavaScript</h1>

    <h2>Змінні</h2>

    <h2>Типи даних</h2>

    <h2>Умови</h2>

    <h2>Цикли</h2>

Кожен `h2` починає нову основну частину матеріалу.

### 4.3. Використовуй h3 для підрозділів

    <h1>Основи JavaScript</h1>

    <h2>Змінні</h2>

    <h3>Оголошення через const</h3>

    <h3>Оголошення через let</h3>

    <h2>Типи даних</h2>

    <h3>Примітивні типи</h3>

    <h3>Об'єкти</h3>

Підрозділ повинен логічно належати до попереднього основного розділу.

### 4.4. Не пропускай рівні без причини

Небажаний приклад:

    <h1>Основи JavaScript</h1>

    <h3>Змінні</h3>

    <h4>Оголошення через const</h4>

Тут структура переходить від `h1` до `h3`, хоча розділ фактично має рівень `h2`.

Краще:

    <h1>Основи JavaScript</h1>

    <h2>Змінні</h2>

    <h3>Оголошення через const</h3>

Пропуск рівнів може заплутувати структуру документа. Водночас головне — логічна семантика, а не механічна заборона кожного пропуску в усіх можливих ситуаціях.

---

## 5. Як визначити головний заголовок сторінки

`h1` зазвичай описує основний зміст сторінки.

Приклади:

| Тип сторінки | Приклад h1 |
|---|---|
| Головна сторінка | Навчальна платформа |
| Сторінка курсу | Основи веброзробки |
| Сторінка статті | Як працює CSS Grid |
| Сторінка товару | Ноутбук для програмування |
| Сторінка профілю | Профіль користувача |
| Сторінка реєстрації | Створення облікового запису |
| Сторінка категорії | Курси JavaScript |

### Чи повинен бути лише один h1?

У більшості сторінок найпростіше й найзрозуміліше рішення — один основний `h1`.

HTML допускає різні структури, але для звичайного вебінтерфейсу не потрібно створювати декілька `h1` без конкретної семантичної причини.

Приклад:

    <main>
      <h1>Курси програмування</h1>

      <section>
        <h2>Frontend</h2>
      </section>

      <section>
        <h2>Backend</h2>
      </section>
    </main>

Такий підхід легко читати, підтримувати й перевіряти.

### Чи може h1 бути візуально маленьким?

Так.

Наприклад, на сторінці профілю заголовок може бути компактним, але все одно залишатися `h1`.

    <h1 class="page-title">Налаштування профілю</h1>

    .page-title {
      font-size: 1.5rem;
      font-weight: 700;
    }

Семантичний рівень не залежить від розміру шрифту.

## 6. Типографічна шкала заголовків

Типографічна шкала (*type scale*) — це система розмірів тексту, яка забезпечує послідовність у дизайні.

Наприклад:

| Роль | Розмір |
|---|---:|
| Display | `3.5rem` |
| H1 | `3rem` |
| H2 | `2.25rem` |
| H3 | `1.75rem` |
| H4 | `1.375rem` |
| H5 | `1.125rem` |
| H6 | `1rem` |

Це лише один можливий набір значень. Розміри потрібно адаптувати до шрифту, макета та призначення інтерфейсу.

### Приклад CSS

    :root {
      --font-size-display: 3.5rem;
      --font-size-h1: 3rem;
      --font-size-h2: 2.25rem;
      --font-size-h3: 1.75rem;
      --font-size-h4: 1.375rem;
      --font-size-h5: 1.125rem;
      --font-size-h6: 1rem;
    }

    h1 {
      font-size: var(--font-size-h1);
    }

    h2 {
      font-size: var(--font-size-h2);
    }

    h3 {
      font-size: var(--font-size-h3);
    }

### Чому потрібна шкала

- Заголовки мають узгоджені розміри.
- Різні сторінки виглядають частинами одного продукту.
- Зміни дизайну простіше підтримувати.
- Менше випадкових значень у CSS.
- Нові компоненти легше оформлювати за наявними правилами.

### Чи повинні розміри завжди зменшуватися від h1 до h6?

Не обов'язково, але зазвичай це зручна відправна точка.

Важливо, щоб заголовки відрізнялися достатньо для зрозумілої візуальної ієрархії.

---

## 7. Візуальні параметри заголовків

Розмір шрифту — лише один із засобів побудови ієрархії.

### 7.1. font-size

Визначає розмір тексту.

    h1 {
      font-size: 3rem;
    }

    h2 {
      font-size: 2rem;
    }

    h3 {
      font-size: 1.5rem;
    }

Занадто близькі розміри можуть зробити рівні заголовків менш помітними.

### 7.2. font-weight

Визначає товщину символів.

    h1 {
      font-weight: 800;
    }

    h2 {
      font-weight: 700;
    }

    h3 {
      font-weight: 600;
    }

Не кожен шрифт має всі значення ваги. Перевір, які накреслення реально доступні.

### 7.3. line-height

Визначає висоту рядка.

    h1 {
      font-size: 3rem;
      line-height: 1.1;
    }

    h2 {
      font-size: 2rem;
      line-height: 1.2;
    }

    h3 {
      font-size: 1.5rem;
      line-height: 1.3;
    }

Для великих заголовків часто підходить компактніший `line-height`, а для багаторядкових — значення, яке зберігає комфортне читання.

### 7.4. letter-spacing

Визначає додатковий інтервал між символами.

    h1 {
      letter-spacing: -0.04em;
    }

    h2 {
      letter-spacing: -0.02em;
    }

Від'ємні значення можуть зробити великі заголовки компактнішими, але їх потрібно перевіряти на конкретному шрифті.

### 7.5. margin

Відступи допомагають відокремлювати заголовок від попереднього та наступного контенту.

    h2 {
      margin-top: 2.5rem;
      margin-bottom: 1rem;
    }

Відступ над заголовком часто має показувати початок нового розділу, а відступ під ним — пов'язувати заголовок із відповідним текстом.

### 7.6. Колір і контраст

Колір може посилювати візуальну ієрархію, але не повинен бути єдиним засобом розрізнення рівнів.

    h1 {
      color: #172033;
    }

    h2 {
      color: #26334a;
    }

Для важливого тексту забезпечуй достатній контраст із фоном.

---

## 8. Відступи та групування заголовків

Відступи показують, які елементи пов'язані між собою.

Заголовок зазвичай має бути ближчим до свого тексту, ніж до попереднього розділу.

Приклад:

    .section-title {
      margin-top: 2.5rem;
      margin-bottom: 0.75rem;
    }

    .section-description {
      margin-top: 0;
    }

HTML:

    <section>
      <h2 class="section-title">Наші курси</h2>

      <p class="section-description">
        Обери напрямок для навчання.
      </p>
    </section>

### Принцип близькості

- Заголовок і його опис мають бути візуально пов'язаними.
- Між різними розділами зазвичай потрібен більший відступ.
- Заголовки одного рівня повинні мати послідовне оформлення.
- Відступи допомагають розпізнати структуру навіть без читання всього тексту.

Не варто створювати ієрархію лише великими відступами. Вона має підтримуватися також семантикою та типографікою.

---

## 9. Адаптивна ієрархія заголовків

Заголовок, який добре виглядає на великому моніторі, може займати надто багато місця на мобільному екрані.

Для адаптивного розміру можна використовувати `clamp()`.

    h1 {
      font-size: clamp(2rem, 5vw, 4rem);
      line-height: 1.1;
    }

Функція `clamp()` приймає три значення:

    clamp(minimum, preferred, maximum)

У цьому прикладі:

- `2rem` — мінімальний розмір;
- `5vw` — значення, залежне від ширини вікна;
- `4rem` — максимальний розмір.

Приклад для кількох рівнів:

    h1 {
      font-size: clamp(2rem, 5vw, 4rem);
      line-height: 1.1;
    }

    h2 {
      font-size: clamp(1.5rem, 3.5vw, 2.5rem);
      line-height: 1.2;
    }

    h3 {
      font-size: clamp(1.25rem, 2.5vw, 1.75rem);
      line-height: 1.3;
    }

### Що перевіряти на мобільному екрані

- Чи не займає заголовок надто багато вертикального простору?
- Чи не стає він занадто дрібним?
- Чи не виникають незручні перенесення слів?
- Чи не виходить текст за межі контейнера?
- Чи зберігається різниця між рівнями заголовків?
- Чи не зменшується читабельність через надмірно компактний `line-height`?

Не потрібно створювати окремий медіазапит для кожного заголовка, якщо `clamp()` уже забезпечує потрібну поведінку.

## 10. Заголовки в різних компонентах UI

Одна й та сама система ієрархії може використовуватися в різних частинах інтерфейсу.

### 10.1. Заголовок сторінки

    <main>
      <h1 class="page-title">Каталог курсів</h1>

      <p class="page-description">
        Знайди курс відповідно до своїх цілей.
      </p>
    </main>

    .page-title {
      margin: 0 0 1rem;
      font-size: clamp(2rem, 5vw, 3.5rem);
      font-weight: 800;
      line-height: 1.1;
    }

    .page-description {
      max-width: 60ch;
      margin: 0;
      font-size: 1.125rem;
      line-height: 1.6;
    }

### 10.2. Заголовок секції

    <section>
      <h2>Популярні курси</h2>

      <p>
        Курси, які найчастіше обирають користувачі.
      </p>
    </section>

    section h2 {
      margin-bottom: 0.75rem;
      font-size: 2rem;
      line-height: 1.2;
    }

### 10.3. Заголовок картки

    <article class="course-card">
      <h3 class="course-card__title">
        Основи JavaScript
      </h3>

      <p>
        Вивчай основи мови та розв'язуй практичні завдання.
      </p>
    </article>

    .course-card__title {
      margin: 0 0 0.75rem;
      font-size: 1.25rem;
      font-weight: 700;
      line-height: 1.3;
    }

У цьому прикладі `h3` доречний, якщо картка є підрозділом відповідного розділу сторінки. Якщо картка використовується в іншому контексті, її рівень потрібно визначити за структурою документа.

### 10.4. Заголовок форми

    <section>
      <h2>Створення облікового запису</h2>

      <form>
        <!-- Поля форми -->
      </form>
    </section>

Заголовок форми повинен пояснювати її призначення.

### 10.5. Заголовок модального вікна

    <section
      role="dialog"
      aria-labelledby="dialog-title"
      aria-modal="true"
    >
      <h2 id="dialog-title">Видалити запис?</h2>

      <p>
        Цю дію не можна буде скасувати.
      </p>
    </section>

Для модального вікна важливо не лише правильно оформити заголовок, а й пов'язати його з діалогом через `aria-labelledby`.

Сам приклад показує зв'язок заголовка з діалогом; повноцінне модальне вікно також потребує правильної поведінки фокуса, клавіатурної взаємодії та закриття.

## 11. Доступність заголовків

Заголовки важливі для користувачів, які переглядають сторінку за допомогою скринридера або клавіатури.

### Основні правила

- Використовуй справжні HTML-заголовки, а не лише текст із великим шрифтом.
- Дотримуйся логічної структури документа.
- Вибирай рівень відповідно до змісту, а не зовнішнього вигляду.
- Не використовуй заголовки лише для отримання жирного тексту.
- Переконайся, що заголовок описує відповідний розділ.
- Забезпечуй достатній контраст тексту.
- Перевіряй, чи зрозуміла структура сторінки без CSS.

### Поганий приклад

    <div class="large-title">
      Наші послуги
    </div>

Такий елемент може виглядати як заголовок, але сам по собі не має семантики заголовка.

### Кращий приклад

    <h2 class="large-title">
      Наші послуги
    </h2>

    .large-title {
      font-size: 2rem;
      font-weight: 700;
    }

Тепер елемент має семантику `h2`, а його зовнішній вигляд контролюється CSS.

### Чи можна стилізувати h3 так само, як h1?

Так.

    <h3 class="hero-title">Створюй цифрові продукти</h3>

    .hero-title {
      font-size: 3rem;
      font-weight: 800;
    }

Це може бути доречним, якщо в структурі документа елемент справді є заголовком третього рівня, але дизайн вимагає великого розміру.

Однак спочатку переконайся, що рівень `h3` відповідає логічній структурі сторінки.

## 12. Заголовки в довгих текстах і навчальних матеріалах

Для статей, документації та навчальних посібників ієрархія заголовків особливо важлива.

Приклад:

    <article>
      <h1>Основи CSS Grid</h1>

      <p>
        CSS Grid допомагає створювати двовимірні макети.
      </p>

      <h2>Основні поняття</h2>

      <p>
        Grid працює з рядками та колонками.
      </p>

      <h3>Grid-контейнер</h3>

      <p>
        Контейнер визначає область, у якій працює сітка.
      </p>

      <h3>Grid-елементи</h3>

      <p>
        Це дочірні елементи Grid-контейнера.
      </p>

      <h2>Створення сітки</h2>

      <p>
        Для визначення колонок використовують grid-template-columns.
      </p>
    </article>

### Рекомендації

- Розділяй довгий матеріал на логічні секції.
- Використовуй заголовки, які описують зміст наступного блоку.
- Не створюй підрозділи лише для декоративного оформлення.
- Уникай надто глибокої вкладеності без потреби.
- Перевіряй, чи можна зрозуміти зміст документа, переглянувши лише заголовки.

## 13. Заголовки в React і Next.js

У React і Next.js правила семантичної ієрархії залишаються такими самими, як у звичайному HTML.

Приклад компонента:

    type PageHeaderProps = {
      title: string;
      description?: string;
    };

    export function PageHeader({
      title,
      description,
    }: PageHeaderProps) {
      return (
        <header className="page-header">
          <h1 className="page-header__title">
            {title}
          </h1>

          {description && (
            <p className="page-header__description">
              {description}
            </p>
          )}
        </header>
      );
    }

Використання:

    <PageHeader
      title="Каталог курсів"
      description="Обери напрямок для навчання."
    />

Цей компонент підходить для сторінок, на яких він представляє основний заголовок.

### Важливий нюанс

Не кожен компонент заголовка повинен автоматично створювати `h1`.

Наприклад, компонент картки курсу може використовувати `h3`, а компонент діалогу — `h2`. Семантичний рівень залежить від місця компонента в конкретній сторінці.

Для повторно використовуваних компонентів продумуй їхню роль у структурі, а не лише зовнішній вигляд.

## 14. Типові помилки

### Помилка 1. Вибір заголовка лише за розміром

    <h1>Головна сторінка</h1>

    <h4>Наші курси</h4>

Якщо «Наші курси» є основним розділом сторінки, `h4` може бути семантично недоречним.

Краще:

    <h1>Головна сторінка</h1>

    <h2>Наші курси</h2>

Потрібний розмір задавай CSS-властивістю `font-size`.

### Помилка 2. Пропуск логічного рівня

    <h1>Документація</h1>

    <h3>Встановлення</h3>

    <h4>Вимоги до системи</h4>

Краще:

    <h1>Документація</h1>

    <h2>Встановлення</h2>

    <h3>Вимоги до системи</h3>

### Помилка 3. Використання div замість заголовка

    <div class="section-title">
      Наші послуги
    </div>

Краще, якщо це справжній заголовок:

    <h2 class="section-title">
      Наші послуги
    </h2>

### Помилка 4. Занадто багато різних стилів

Якщо кожен заголовок має власні випадкові розміри, вагу та відступи, інтерфейс виглядає непослідовним.

Рішення: створи типографічну шкалу й використовуй спільні правила.

### Помилка 5. Занадто мала різниця між рівнями

    h1 {
      font-size: 2rem;
    }

    h2 {
      font-size: 1.9rem;
    }

    h3 {
      font-size: 1.8rem;
    }

Такі розміри можуть зробити ієрархію нечіткою, якщо інші параметри теж майже однакові.

Рішення: використовуй достатню різницю в розмірі, жирності або відступах.

### Помилка 6. Надмірна кількість декоративних ефектів

Тіні, градієнти, кольори та декоративні лінії не повинні замінювати логічну структуру.

Рішення: почни з семантики, розміру, жирності та відступів. Декоративні ефекти додавай лише за потреби.

### Помилка 7. Ігнорування багаторядкових заголовків

Заголовок може виглядати добре в одному рядку, але стати незручним після перенесення.

Рішення: перевіряй довгі назви, вузькі екрани та реальні тексти.

### Помилка 8. Автоматичне використання h1 у кожному компоненті

    function Card() {
      return (
        <article>
          <h1>Курс JavaScript</h1>
        </article>
      );
    }

Якщо таких карток багато, структура сторінки може стати заплутаною.

Краще вибирати рівень заголовка відповідно до контексту:

    function Card() {
      return (
        <article>
          <h3>Курс JavaScript</h3>
        </article>
      );
    }

`h3` тут лише приклад: правильний рівень залежить від загальної структури сторінки.

- `clamp()` допомагає адаптувати розміри до ширини екрана.

У результаті сторінка має зрозумілу структуру і водночас зберігає узгоджену типографіку.

## 16. Як перевіряти ієрархію заголовків

Перевіряй структуру з двох різних поглядів.

### Семантична перевірка

- Чи є зрозумілий головний заголовок сторінки?
- Чи відображають `h2` основні розділи?
- Чи належать `h3` до відповідних `h2`?
- Чи відповідають рівні реальній структурі змісту?
- Чи не використовуються заголовки лише заради оформлення?

### Візуальна перевірка

- Чи помітно відрізняються основні рівні?
- Чи достатньо контрастний текст?
- Чи відповідають відступи структурі?
- Чи комфортно читати багаторядкові заголовки?
- Чи працює шкала на мобільному екрані?
- Чи однаково оформлені заголовки однакового призначення?

### Перевірка в DevTools

1. Відкрий сторінку у браузері.
2. Відкрий DevTools.
3. Перевір елементи `h1`–`h6` у вкладці Elements.
4. Переконайся, що HTML-рівні відповідають структурі документа.
5. Перевір `font-size`, `font-weight`, `line-height` і `margin`.
6. Зміни ширину вікна й подивися, як поводяться заголовки.
7. За потреби вимкни CSS, щоб оцінити логічну послідовність документа.

## 17. Практичні вправи

### Вправа 1. Створи ієрархію навчальної статті

Створи HTML-структуру для статті «Основи CSS».

Потрібні розділи:

- Вступ.
- Селектори.
- Властивості.
- Flexbox.
- Grid.

Додай підрозділи там, де вони справді потрібні.

Завдання:

- Використай `h1` для головної теми.
- Використай `h2` для основних розділів.
- Використай `h3` для підрозділів.
- Перевір логічність вкладеності.

### Вправа 2. Створи типографічну шкалу

Задай розміри для:

- `h1`;
- `h2`;
- `h3`;
- `h4`.

Наприклад, почни з таких значень:

    h1 {
      font-size: 3rem;
    }

    h2 {
      font-size: 2.25rem;
    }

    h3 {
      font-size: 1.75rem;
    }

    h4 {
      font-size: 1.25rem;
    }

Завдання:

- Додай `font-weight`.
- Налаштуй `line-height`.
- Підбери відступи.
- Перевір, чи легко розрізняти рівні.

### Вправа 3. Зроби адаптивний заголовок

Створи великий заголовок для головного екрана сайту.

    <h1 class="hero-title">
      Навчайся створювати цифрові продукти
    </h1>

Завдання:

- Використай `clamp()`.
- Налаштуй `line-height`.
- За потреби налаштуй `letter-spacing`.
- Перевір заголовок на вузькому екрані.
- Переконайся, що він не виходить за межі контейнера.

### Вправа 4. Перероби неправильну структуру

Виправ приклад:

    <h1>Онлайн-курси</h1>

    <h3>Frontend</h3>

    <h5>HTML</h5>

    <h3>Backend</h3>

    <h5>Node.js</h5>

Завдання:

- Визнач основні розділи.
- Визнач підрозділи.
- Вибери правильні HTML-рівні.
- Окремо налаштуй візуальні розміри через CSS.

### Вправа 5. Створи заголовки для UI-компонентів

Зроби невелику сторінку з:

- заголовком сторінки;
- двома секціями;
- трьома картками в одній із секцій;
- формою;
- діалогом підтвердження.

Завдання:

- Визнач рівень кожного заголовка відповідно до структури.
- Створи узгоджену шкалу.
- Перевір відступи та розміри.
- Переконайся, що компоненти не створюють випадкових рівнів заголовків.

## 19. Типові питання на співбесіді

**1. Що таке ієрархія заголовків?**

Це логічна та візуальна система організації заголовків, яка показує структуру сторінки й допомагає користувачеві орієнтуватися в контенті.

**2. Чим відрізняються семантична та візуальна ієрархії?**

Семантична ієрархія визначає логічне місце заголовка в документі. Візуальна ієрархія визначає його зовнішній вигляд і помітність.

**3. Для чого потрібні h1–h6?**

Це HTML-елементи заголовків шести рівнів, які позначають структуру документа.

**4. Чи можна використовувати h3 замість h1, якщо потрібен менший текст?**

Так, якщо `h3` відповідає логічному місцю заголовка в документі. Але не потрібно вибирати `h3` лише через бажання отримати менший розмір шрифту.

**5. Чи повинен h1 завжди бути найбільшим заголовком на сторінці?**

Ні. Зазвичай він найбільш помітний, але його розмір визначається дизайном, а не семантикою HTML.

**6. Чому важливо не пропускати рівні заголовків без причини?**

Тому що послідовна вкладеність робить структуру документа зрозумілішою для користувачів і допоміжних технологій.

**7. Що таке типографічна шкала?**

Це набір узгоджених розмірів тексту, які використовуються для різних рівнів заголовків та інших текстових елементів.

**8. Як створити адаптивний заголовок?**

Можна використати `clamp()`, щоб визначити мінімальний, гнучкий і максимальний розміри шрифту.

**9. Чому не варто використовувати div замість h2?**

`div` не має семантики заголовка. Якщо елемент справді є заголовком розділу, краще використати `h2` та оформити його через CSS.

**10. Як заголовки впливають на доступність?**

Вони допомагають користувачам скринридерів розуміти структуру сторінки, переходити між розділами та знаходити потрібний контент.

**11. Чи можна використовувати декілька h1 на сторінці?**

HTML допускає складніші структури, але для більшості звичайних вебсторінок найпростіше й найзрозуміліше рішення — один основний `h1`.

**12. Як перевірити правильність ієрархії?**

Перевірити логічну послідовність `h1`–`h6`, переглянути сторінку без CSS, оцінити візуальні відмінності та протестувати адаптивність.

## 20. Рівні володіння

### Core — базовий рівень

- Розумієш призначення ієрархії заголовків.
- Знаєш різницю між `h1`, `h2` і `h3`.
- Розрізняєш семантичну та візуальну ієрархії.
- Умієш задавати розміри заголовків через CSS.
- Розумієш роль `font-size`, `font-weight` і `line-height`.

### Junior — практичний рівень

- Створюєш типографічну шкалу.
- Налаштовуєш відступи й міжрядкові інтервали.
- Використовуєш `clamp()` для адаптивних заголовків.
- Перевіряєш заголовки в DevTools.
- Розумієш базові вимоги доступності.

### Middle — системний рівень

- Проєктуєш єдину систему заголовків для різних сторінок.
- Створюєш повторно використовувані типографічні стилі.
- Узгоджуєш семантику заголовків у React-компонентах.
- Враховуєш адаптивність, локалізацію та довжину контенту.
- Перевіряєш ієрархію в складних інтерфейсах.
- Відокремлюєш семантичну структуру від візуального оформлення.

### Senior — експертний рівень

- Формуєш правила заголовків для великої дизайн-системи.
- Забезпечуєш послідовність між багатьма продуктами й командами.
- Враховуєш доступність, складні структури контенту та різні способи навігації.
- Проєктуєш масштабовану типографічну шкалу.
- Визначаєш правила для сторінок, модальних вікон, карток і вкладених компонентів.
- Перевіряєш, щоб дизайн-система підтримувала і семантичну правильність, і візуальну якість.

## 21. Мінішпаргалка

| Завдання | Рішення |
|---|---|
| Головна тема сторінки | `h1` |
| Основний розділ | `h2` |
| Підрозділ | `h3` |
| Глибша вкладеність | `h4`–`h6` за потреби |
| Змінити розмір заголовка | `font-size` |
| Змінити товщину | `font-weight` |
| Змінити висоту рядка | `line-height` |
| Налаштувати інтервал між символами | `letter-spacing` |
| Відокремити розділи | `margin` |
| Створити адаптивний розмір | `clamp()` |
| Створити систему розмірів | CSS-змінні |
| Перевірити семантику | Аналіз HTML-структури |
| Перевірити адаптивність | DevTools і різні ширини екрана |

### Приклад системи CSS-змінних

    :root {
      --heading-size-h1: clamp(2rem, 5vw, 4rem);
      --heading-size-h2: clamp(1.5rem, 3.5vw, 2.5rem);
      --heading-size-h3: clamp(1.25rem, 2.5vw, 1.75rem);

      --heading-line-height: 1.2;
      --heading-weight: 700;

      --heading-space-before: 2.5rem;
      --heading-space-after: 1rem;
    }

    h1 {
      font-size: var(--heading-size-h1);
      line-height: 1.1;
      font-weight: 800;
    }

    h2 {
      font-size: var(--heading-size-h2);
      line-height: var(--heading-line-height);
      font-weight: var(--heading-weight);
    }

    h3 {
      font-size: var(--heading-size-h3);
      line-height: 1.3;
      font-weight: var(--heading-weight);
    }

Це стартовий приклад дизайн-системи. У реальному проєкті змінні варто узгодити з іншими текстовими стилями, кольорами, відступами та правилами компонентів.

## 22. Підсумок

Ієрархія заголовків — це основа зрозумілої структури вебсторінки.

Щоб створювати якісні заголовки:

- спочатку визначай логічну структуру документа;
- використовуй HTML-елементи `h1`–`h6` за їхнім призначенням;
- відокремлюй семантику від візуального оформлення;
- створюй узгоджену типографічну шкалу;
- налаштовуй розміри, жирність, інтервали й відступи;
- перевіряй адаптивність і доступність;
- використовуй однакові правила в повторюваних компонентах;
- оцінюй заголовки в контексті реального контенту.

**Головне правило:** правильна ієрархія заголовків повинна бути логічною в HTML, зрозумілою візуально та зручною для всіх користувачів.
