# 08. Body Text — Основний текст інтерфейсу

Основний текст (*body text*) — це текстовий вміст інтерфейсу, який передає користувачеві основну інформацію: пояснення, описи, інструкції, повідомлення, статті, характеристики товарів та інші текстові дані.

У UI-дизайні основний текст повинен бути читабельним, зрозумілим і візуально узгодженим з іншими елементами інтерфейсу. На його сприйняття впливають розмір шрифту, міжрядковий інтервал, довжина рядка, ширина текстового контейнера, контраст, відступи та особливості шрифту.

**Мета:** навчитися оформлювати основний текст у вебінтерфейсах так, щоб користувач міг комфортно читати короткі описи, довгі статті, інструкції та повідомлення на різних пристроях.

---

## ✔ Що потрібно знати

- Що таке body text і де його використовують.
- Чим основний текст відрізняється від заголовків, підписів і допоміжного тексту.
- Як вибирати розмір основного тексту.
- Як налаштовувати `line-height`.
- Як довжина рядка впливає на читабельність.
- Як визначати ширину текстового контейнера.
- Як використовувати `font-family`, `font-weight` і `letter-spacing`.
- Як вибирати колір і забезпечувати достатній контраст.
- Як організовувати абзаци та вертикальні відступи.
- Як оформлювати списки, посилання та виділений текст.
- Як адаптувати текст до мобільних екранів.
- Як створювати повторно використовувані стилі основного тексту.
- Як перевіряти читабельність і доступність тексту.
- Яких помилок уникати під час оформлення довгого текстового вмісту.

## 1. Що таке Body Text

Body text — це основний текстовий вміст сторінки або компонента.

Приклади:

- опис навчального курсу;
- текст статті;
- пояснення біля поля форми;
- опис товару;
- інструкція для користувача;
- повідомлення про помилку;
- текст у картці;
- інформація в особистому кабінеті;
- довідковий текст у налаштуваннях.

Приклад HTML:

    <article>
      <h1>Основи веброзробки</h1>

      <p>
        Веброзробка — це процес створення вебсайтів
        і вебзастосунків за допомогою HTML, CSS,
        JavaScript та інших технологій.
      </p>

      <p>
        Навчання починається зі структури сторінки,
        продовжується стилізацією та завершується
        додаванням інтерактивності.
      </p>
    </article>

У цьому прикладі:

- `h1` — заголовок сторінки;
- `p` — основний текст;
- CSS визначає, як текст виглядає та наскільки комфортно його читати.

### Основні завдання body text

1. Передавати інформацію.
2. Пояснювати функції інтерфейсу.
3. Допомагати користувачеві виконувати дії.
4. Підтримувати загальну візуальну ієрархію.
5. Забезпечувати комфортне читання.

Основний текст не повинен конкурувати із заголовками за увагу. Його головна функція — бути зручним для сприйняття.

## 2. Body Text і Typography Hierarchy

У типовому інтерфейсі є кілька категорій тексту.

| Тип тексту | Призначення | Приклад |
|---|---|---|
| Display | Великий декоративний або презентаційний текст | Головний рекламний слоган |
| Heading | Позначення структури сторінки | Назва розділу |
| Body text | Передавання основної інформації | Опис курсу |
| Label | Назва поля або короткий підпис | Електронна пошта |
| Caption | Допоміжне пояснення | Максимальний розмір файлу |
| Helper text | Пояснення біля елемента форми | Пароль має містити 8 символів |
| Metadata | Додаткова інформація | Дата публікації |
| Button text | Назва дії | Зберегти зміни |

Приклад:

    <article class="course-card">
      <p class="course-card__category">ПРОГРАМУВАННЯ</p>

      <h2 class="course-card__title">
        Основи JavaScript
      </h2>

      <p class="course-card__description">
        Вивчай змінні, функції, масиви та інші основи
        JavaScript на практичних прикладах.
      </p>

      <a href="/courses/javascript">
        Переглянути курс
      </a>
    </article>

У цьому компоненті:

- категорія — короткий допоміжний текст;
- назва курсу — заголовок;
- опис курсу — body text;
- посилання — інтерактивний елемент.

Кожен тип тексту має власну функцію, тому необов'язково оформлювати їх однаково.

## 3. Розмір основного тексту — font-size

`font-size` визначає розмір символів.

Для звичайного тексту вебінтерфейсів часто використовують діапазон приблизно від `14px` до `18px`, але оптимальний розмір залежить від шрифту, пристрою, призначення тексту та потреб користувачів.

### Приклад базових розмірів

    body {
      font-size: 16px;
    }

    .body-text--small {
      font-size: 0.875rem;
    }

    .body-text {
      font-size: 1rem;
    }

    .body-text--large {
      font-size: 1.125rem;
    }

Якщо базовий розмір кореневого шрифту дорівнює `16px`, значення становитимуть:

| Значення | Приблизний розмір |
|---|---:|
| `0.75rem` | `12px` |
| `0.875rem` | `14px` |
| `1rem` | `16px` |
| `1.125rem` | `18px` |
| `1.25rem` | `20px` |

### Коли використовувати різні розміри

- `14px` — короткі допоміжні повідомлення, якщо вони залишаються читабельними.
- `16px` — поширена початкова точка для основного тексту.
- `18px` — довгі тексти або інтерфейси, де потрібне комфортніше читання.
- `20px` і більше — вступні абзаци, текст із підвищеним акцентом або спеціальні сценарії.

Це не жорсткі правила. Не зменшуй текст лише для того, щоб умістити більше інформації на екрані.

### Чому часто використовують rem

    html {
      font-size: 100%;
    }

    body {
      font-size: 1rem;
    }

`rem` залежить від розміру шрифту кореневого елемента. За стандартного налаштування браузера `1rem` зазвичай дорівнює `16px`.

Це допомагає створювати масштабовану систему типографіки та враховувати налаштування користувача.

## 4. Міжрядковий інтервал — line-height

`line-height` визначає висоту рядка тексту.

Для основного тексту це одна з найважливіших властивостей, оскільки вона впливає на комфорт читання довгих абзаців.

### Приклад

    .body-text {
      font-size: 16px;
      line-height: 1.6;
    }

За розміру шрифту `16px` значення `1.6` дає приблизну висоту рядка `25.6px`.

Формула:

    line-height у px = font-size у px × коефіцієнт line-height

Приклади:

    16px × 1.4 = 22.4px
    16px × 1.5 = 24px
    16px × 1.6 = 25.6px

### Орієнтовні значення

| Тип тексту | Початковий діапазон |
|---|---|
| Основний текст | `1.5–1.7` |
| Довгі статті | `1.6–1.8` |
| Короткий текст у картці | `1.4–1.6` |
| Компактний інтерфейсний текст | `1.3–1.5` |
| Великі заголовки | `1.05–1.25` |

Ці значення є орієнтирами. Результат залежить від гарнітури, розміру тексту, ширини контейнера та довжини вмісту.

### Чому для основного тексту часто підходить 1.5–1.7

- Між рядками залишається достатньо простору.
- Легше переходити поглядом від одного рядка до наступного.
- Довгі абзаци виглядають менш щільними.
- Текст краще сприймається на різних екранах.

### Поганий приклад

    .article-text {
      font-size: 16px;
      line-height: 1;
    }

Такий текст може виглядати надто щільним, особливо якщо абзац має багато рядків.

### Кращий початковий варіант

    .article-text {
      font-size: 1rem;
      line-height: 1.65;
    }

Не плутай `line-height` із `margin-bottom`: перша властивість визначає висоту рядків, друга — відстань між елементами.

## 5. Довжина рядка — line length

Довжина рядка — це кількість символів або слів, які вміщуються в одному рядку тексту.

Якщо рядки надто довгі, очам складніше повертатися до початку наступного рядка. Якщо надто короткі — читання може часто перериватися через перенесення.

Для довгих текстів часто використовують орієнтир близько `45–75` символів у рядку. Це приблизна рекомендація, а не універсальне правило для кожного шрифту та мови.

### Приклад

    .article {
      max-width: 70ch;
    }

Одиниця `ch` приблизно відповідає ширині символу `0` у поточному шрифті. Вона зручна для орієнтовного обмеження ширини тексту.

Наприклад:

    .article {
      max-width: 65ch;
      margin-inline: auto;
    }

Це може створити комфортну ширину для довгого тексту.

### Чому не варто розтягувати статтю на всю ширину екрана

    .article {
      width: 100%;
    }

Якщо контейнер дуже широкий, рядки можуть ставати надто довгими.

Краще:

    .article {
      width: min(100% - 2rem, 70ch);
      margin-inline: auto;
    }

У цьому прикладі:

- `100% - 2rem` залишає простір біля країв на вузьких екранах;
- `70ch` обмежує максимальну ширину;
- `margin-inline: auto` центрує контейнер.

### Важливо

`ch` — не точна кількість символів. Ширина символів відрізняється залежно від гарнітури, тому результат потрібно перевіряти в браузері.

---

## 6. Ширина текстового контейнера

Ширина контейнера визначає, скільки тексту поміщається в одному рядку.

Для різних типів інтерфейсу потрібні різні обмеження.

### Довга стаття

    .article-content {
      max-width: 70ch;
      margin-inline: auto;
    }

### Опис у картці

    .card-description {
      max-width: 45ch;
    }

### Вступний текст сторінки

    .page-intro {
      max-width: 60ch;
      font-size: 1.125rem;
      line-height: 1.7;
    }

### Текст у вузькій колонці

    .sidebar-text {
      max-width: 32rem;
    }

Не існує одного правильного значення для всіх ситуацій. Ширину потрібно оцінювати з урахуванням призначення компонента та довжини реального тексту.

### Контейнер і розмір шрифту працюють разом

Якщо збільшити шрифт, кількість символів у рядку зменшиться. Якщо збільшити ширину контейнера, рядок стане довшим.

Тому не варто налаштовувати `font-size` і ширину текстового блоку окремо від загального макета.

## 7. Шрифт основного тексту — font-family

`font-family` визначає гарнітуру тексту.

Приклад:

    body {
      font-family: Arial, Helvetica, sans-serif;
    }

Для основного тексту важливо вибрати шрифт, який:

- добре читається в малих розмірах;
- має достатній набір символів;
- підтримує потрібні мови;
- добре відображається на різних пристроях;
- має потрібні накреслення;
- відповідає загальному стилю продукту.

### Системний шрифт

    body {
      font-family:
        system-ui,
        -apple-system,
        BlinkMacSystemFont,
        "Segoe UI",
        sans-serif;
    }

Це приклад системного стеку шрифтів. Браузер вибирає доступний шрифт відповідно до середовища.

### Шрифт із засічками

    .article-text {
      font-family: Georgia, "Times New Roman", serif;
    }

Шрифти із засічками можуть добре підходити для статей і редакційних інтерфейсів, але не є автоматично кращими для довгого тексту.

### Шрифт без засічок

    .interface-text {
      font-family: Arial, Helvetica, sans-serif;
    }

Шрифти без засічок часто використовують у вебінтерфейсах, але остаточний вибір залежить від конкретної гарнітури та дизайну.

### Перевірка кирилиці

Якщо інтерфейс українською мовою, перевір:

- українські літери `і`, `ї`, `є`, `ґ`;
- українські лапки й апострофи;
- відображення тексту в жирному накресленні;
- перенесення довгих слів;
- вигляд тексту на різних операційних системах.

Шрифт, який добре виглядає на англійському тексті, може мати інші пропорції або неповний набір символів для української мови.

## 8. Товщина шрифту — font-weight

`font-weight` визначає товщину символів.

Для основного тексту часто використовують звичайну вагу, а для акцентів — напівжирну або жирну.

    .body-text {
      font-weight: 400;
    }

    .body-text strong {
      font-weight: 700;
    }

Типові значення:

| Значення | Назва |
|---|---|
| `300` | Light |
| `400` | Regular |
| `500` | Medium |
| `600` | SemiBold |
| `700` | Bold |

Доступні ваги залежать від шрифту. Якщо завантажено лише звичайне накреслення, браузер може синтезувати жирніший варіант.

### Основний текст

    p {
      font-weight: 400;
    }

### Виділення важливої інформації

    strong {
      font-weight: 700;
    }

### Чому не варто робити весь текст жирним

- Зменшується контраст між звичайним і важливим текстом.
- Абзаци можуть виглядати надто щільними.
- Акценти втрачають свою виразність.
- Тривале читання може стати менш комфортним.

Використовуй жирність для значущих фрагментів, а не як універсальний спосіб покращення читабельності.

---

## 9. Міжлітерний інтервал — letter-spacing

`letter-spacing` задає додаткову відстань між символами.

Для звичайного тексту часто достатньо стандартного значення.

    .body-text {
      letter-spacing: normal;
    }

У деяких випадках можна використовувати невелике додатне значення:

    .body-text {
      letter-spacing: 0.01em;
    }

Але це не обов'язкова оптимізація. Для більшості абзаців спочатку перевір стандартний інтервал.

### Чому надмірний інтервал — проблема

    .body-text {
      letter-spacing: 0.15em;
    }

Таке значення може зробити довгий текст візуально розрідженим і ускладнити сприйняття слів.

### Коли змінювати letter-spacing

- Якщо шрифт має особливі пропорції символів.
- Якщо потрібне точне типографічне налаштування.
- Якщо дизайн-система визначає конкретний інтервал для певного текстового стилю.

Не використовуй міжлітерний інтервал як заміну правильному розміру шрифту або `line-height`.

## 10. Колір і контраст основного тексту

Колір тексту впливає на його читабельність і візуальну ієрархію.

Приклад:

    body {
      color: #222;
      background-color: #fff;
    }

Основний текст часто оформлюють темним кольором на світлому фоні, але можливі й інші поєднання.

### Ієрархія кольорів

    :root {
      --color-text-primary: #202938;
      --color-text-secondary: #526071;
      --color-text-muted: #667085;
      --color-background: #ffffff;
    }

    body {
      color: var(--color-text-primary);
      background: var(--color-background);
    }

    .text-secondary {
      color: var(--color-text-secondary);
    }

    .text-muted {
      color: var(--color-text-muted);
    }

### Основний текст

Основний текст повинен мати достатній контраст із фоном.

За рекомендаціями WCAG для звичайного тексту мінімальне співвідношення контрастності рівня AA становить `4.5:1`. Для великого тексту — `3:1`.

Під великим текстом у цьому контексті зазвичай розуміють текст від `18pt` або від `14pt` за жирного накреслення. Це приблизно `24px` або `18.67px` відповідно, якщо перевести типографічні пункти в CSS-пікселі за стандартним співвідношенням.

### Не покладайся лише на колір

Наприклад, помилка у формі повинна бути зрозумілою не тільки через червоний колір.

    <p class="error-message">
      Не вдалося зберегти дані. Перевір обов'язкові поля.
    </p>

Колір може додатково підкреслювати повідомлення, але сам текст має передавати суть проблеми.

## 11. Абзаци та вертикальні відступи

Абзаци допомагають поділити довгий текст на логічні частини.

HTML-елемент `p` використовується для абзаців.

    <p>
      HTML визначає структуру вебсторінки.
    </p>

    <p>
      CSS відповідає за її візуальне оформлення.
    </p>

Для відстані між абзацами можна використовувати `margin`.

    .article-text p {
      margin: 0 0 1.25rem;
      line-height: 1.7;
    }

### Чому не варто використовувати порожні абзаци

Небажаний приклад:

    <p>Перший абзац.</p>
    <p>&nbsp;</p>
    <p>Другий абзац.</p>

Краще:

    <p>Перший абзац.</p>
    <p>Другий абзац.</p>

    p {
      margin-bottom: 1.25rem;
    }

Відстань між абзацами повинна задаватися CSS, а не порожніми елементами.

### Розмір відступу

Відступ залежить від:

- розміру тексту;
- довжини абзаців;
- ширини контейнера;
- загального ритму сторінки;
- щільності інтерфейсу.

Для довгих статей часто потрібні помітніші відступи, ніж для компактних карток.

---

## 12. Вирівнювання тексту

CSS-властивість `text-align` визначає горизонтальне вирівнювання тексту.

### Вирівнювання ліворуч

    .article-text {
      text-align: left;
    }

Для тексту з напрямком зліва направо це поширений вибір.

### Вирівнювання по центру

    .hero-description {
      text-align: center;
    }

Може використовуватися для короткого вступного тексту, заголовкових блоків або окремих повідомлень.

Для довгих абзаців центрування часто ускладнює пошук початку наступного рядка.

### Вирівнювання по ширині

    .article-text {
      text-align: justify;
    }

Браузер розподіляє додатковий простір між словами, щоб вирівняти рядки по обох краях.

Це може бути доречним у деяких редакційних макетах, але іноді створює нерівномірні проміжки між словами.

### Практичне правило

- Довгі тексти зазвичай зручно вирівнювати за початковим краєм.
- Короткий текст у презентаційних блоках можна центрувати.
- `justify` варто перевіряти на реальному тексті та різних ширинах.
- Вирівнювання має підтримувати читання, а не лише симетрію макета.

Для міжнародних інтерфейсів часто зручніше використовувати логічне вирівнювання:

    .body-text {
      text-align: start;
    }

`start` означає початковий край відповідно до напрямку тексту.

---

## 13. Списки в основному тексті

Списки допомагають структурувати інформацію, особливо якщо потрібно показати кілька умов, характеристик або кроків.

### Маркований список

    <p>Для початку роботи потрібно:</p>

    <ul>
      <li>Створити HTML-файл.</li>
      <li>Підключити CSS.</li>
      <li>Додати JavaScript.</li>
    </ul>

### Нумерований список

    <p>Послідовність роботи:</p>

    <ol>
      <li>Створи структуру сторінки.</li>
      <li>Оформи елементи через CSS.</li>
      <li>Перевір результат у браузері.</li>
    </ol>

CSS:

    .article-content ul,
    .article-content ol {
      padding-inline-start: 1.5rem;
      margin-block: 1rem 1.5rem;
    }

    .article-content li {
      margin-block: 0.5rem;
      line-height: 1.6;
    }

### Коли краще використовувати список

- Коли потрібно перелічити характеристики.
- Коли є кілька незалежних пунктів.
- Коли важлива послідовність дій.
- Коли текст містить багато умов або рекомендацій.

Не перетворюй кожен короткий абзац на список. Формат повинен відповідати структурі інформації.

---

## 14. Посилання всередині основного тексту

Посилання дозволяють перейти до іншої сторінки або ресурсу.

    <p>
      Докладніше про структуру документа читай у
      <a href="/guides/html">посібнику з HTML</a>.
    </p>

CSS:

    .article-content a {
      color: #155eef;
      text-decoration: underline;
      text-underline-offset: 0.15em;
    }

### Важливі правила

- Посилання повинно мати зрозумілий текст.
- Воно має відрізнятися від звичайного тексту.
- Не варто покладатися лише на колір.
- Інтерактивний стан має бути помітним.
- Посилання повинно залишатися читабельним у контексті абзацу.

Невдалий приклад:

    <p>
      Щоб дізнатися більше, натисни
      <a href="/guide">тут</a>.
    </p>

Краще:

    <p>
      Переглянь
      <a href="/guide">посібник із веброзробки</a>,
      щоб дізнатися більше.
    </p>

Описовий текст посилання краще пояснює, куди воно веде.

---

## 15. Виділення тексту

Для виділення важливих фрагментів можна використовувати семантичні HTML-елементи.

### Важливий текст

    <p>
      Перед збереженням
      <strong>перевір правильність даних</strong>.
    </p>

`strong` позначає важливість фрагмента.

### Смисловий акцент

    <p>
      Пам'ятай: <em>спочатку перевір структуру</em>,
      а потім додавай стилі.
    </p>

`em` позначає наголос або смисловий акцент.

### Позначення фрагмента

    <p>
      У CSS властивість
      <code>line-height</code>
      визначає висоту рядка.
    </p>

`code` доречний для назв властивостей, змінних, команд та інших фрагментів коду.

### Поширена помилка

Не виділяй жирним або кольором майже кожне речення. Якщо весь текст підкреслений акцентами, користувачеві важче визначити, що справді важливе.

---

## 16. Основний текст у формах

У формах основний текст допомагає користувачеві зрозуміти, які дані потрібно ввести та як виправити помилку.

Приклад:

    <form>
      <label for="email">Електронна пошта</label>

      <input
        id="email"
        name="email"
        type="email"
        aria-describedby="email-help"
      />

      <p id="email-help" class="helper-text">
        Використовуй адресу, до якої маєш доступ.
      </p>
    </form>

CSS:

    .helper-text {
      margin: 0.5rem 0 0;
      font-size: 0.875rem;
      line-height: 1.5;
      color: #526071;
    }

### Принципи оформлення

- Допоміжний текст має бути читабельним.
- Він повинен бути візуально пов'язаний із відповідним полем.
- Не використовуй надто низький контраст.
- Повідомлення про помилку повинно пояснювати, що потрібно виправити.
- Не покладайся лише на колір для передавання статусу.

Допоміжний текст може бути меншим за основний, але не настільки дрібним, щоб його було важко прочитати.

---

## 17. Адаптивний основний текст

На різних пристроях змінюються ширина контейнера, кількість символів у рядку та загальна композиція сторінки.

Для звичайного основного тексту часто достатньо стабільного розміру шрифту та адаптивного контейнера.

    .article-content {
      width: min(100% - 2rem, 70ch);
      margin-inline: auto;
    }

    .article-content p {
      font-size: 1rem;
      line-height: 1.7;
    }

### Адаптивний вступний текст

    .page-intro {
      font-size: clamp(1rem, 1.5vw, 1.25rem);
      line-height: 1.65;
    }

Такий підхід дозволяє розміру змінюватися в заданих межах.

### Коли потрібен медіазапит

Якщо на вузькому екрані текст або макет поводиться незручно, можна змінити окремі параметри.

    .article-content {
      width: min(100% - 3rem, 70ch);
    }

    @media (max-width: 480px) {
      .article-content {
        width: calc(100% - 2rem);
      }
    }

У цьому прикладі змінюється горизонтальний простір контейнера.

Не додавай медіазапити лише тому, що сторінка має мобільну версію. Спочатку перевір, чи адаптивні одиниці та обмеження ширини вже забезпечують потрібний результат.

### Що перевіряти

- Чи не стає текст надто дрібним.
- Чи немає горизонтального прокручування.
- Чи комфортно читати довгі абзаци.
- Чи не виникають надто короткі рядки.
- Чи зберігаються достатні відступи від країв.
- Чи не перекриває текст інші елементи.

---

## 18. Доступність основного тексту

Доступність (*accessibility*) означає, що текстом можуть користуватися люди з різними потребами та способами взаємодії з інтерфейсом.

### Основні правила

- Використовуй читабельний розмір шрифту.
- Забезпечуй достатній контраст.
- Не передавай важливу інформацію лише кольором.
- Використовуй семантичні HTML-елементи.
- Забезпечуй зрозумілу структуру абзаців і списків.
- Дозволяй тексту переноситися відповідно до ширини контейнера.
- Не обрізай важливий текст без можливості прочитати його повністю.
- Перевіряй сторінку зі збільшеним масштабом браузера.
- Враховуй довгі слова та тексти іншими мовами.

### Масштабування тексту

Не варто блокувати масштабування сторінки через налаштування viewport.

Користувач повинен мати можливість збільшити сторінку та читати її без втрати важливого вмісту або функціональності.

### Контраст

Для звичайного тексту орієнтуйся на контрастність не нижче `4.5:1` відповідно до WCAG AA.

Для великого тексту мінімум становить `3:1`.

Контраст потрібно перевіряти для фактичної пари кольорів тексту й фону, а не оцінювати лише на око.

### Читабельність — це не тільки CSS

Навіть добре оформлений текст може бути складним для сприйняття, якщо він містить:

- надто довгі речення;
- незрозумілі терміни;
- надмірну кількість інформації в одному абзаці;
- зайві повторення;
- нечіткі інструкції.

Тому якісний body text потребує і правильного оформлення, і зрозумілого написання.

---

## 19. Створення системи Body Text

У дизайн-системі корисно визначити кілька стандартних текстових стилів.

Наприклад:

    :root {
      --body-size-small: 0.875rem;
      --body-size-default: 1rem;
      --body-size-large: 1.125rem;

      --body-line-height: 1.65;
      --body-line-height-compact: 1.45;

      --body-color-primary: #202938;
      --body-color-secondary: #526071;

      --body-width-reading: 70ch;
    }

### Основний текст

    .body-text {
      font-size: var(--body-size-default);
      line-height: var(--body-line-height);
      color: var(--body-color-primary);
    }

### Великий текст

    .body-text--large {
      font-size: var(--body-size-large);
      line-height: var(--body-line-height);
    }

### Малий текст

    .body-text--small {
      font-size: var(--body-size-small);
      line-height: 1.5;
      color: var(--body-color-secondary);
    }

### Текст для читання

    .reading-text {
      max-width: var(--body-width-reading);
      font-size: var(--body-size-default);
      line-height: var(--body-line-height);
    }

### Переваги системи

- однакові правила на різних сторінках;
- менше випадкових значень;
- швидше оформлення нових компонентів;
- простіша підтримка;
- можливість змінити типографіку централізовано.

Не потрібно створювати окремий клас для кожного абзацу. Визнач основні стилі й додавай модифікатори лише тоді, коли вони справді потрібні.

- Вступний текст трохи більший за звичайний.
- Заголовки відокремлюють логічні розділи.
- Абзаци мають узгоджені вертикальні відступи.
- Списки використовуються для перелічення незалежних пунктів.
- Посилання помітне в тексті.
- Головний заголовок адаптується до ширини екрана.

## 21. Як перевіряти Body Text у браузері

Для перевірки читабельності використовуй браузер і DevTools.

### Послідовність

1. Відкрий сторінку.
2. Вибери абзац у DevTools.
3. Перевір `font-family`.
4. Перевір `font-size`.
5. Перевір `line-height`.
6. Перевір ширину текстового контейнера.
7. Перевір `color` і контраст із фоном.
8. Зміни ширину вікна браузера.
9. Перевір довгі абзаци, списки та посилання.
10. Збільш масштаб браузера й перевір, чи не втрачається вміст.

### Що оцінювати

- Чи легко читати кілька абзаців поспіль?
- Чи не надто довгі рядки?
- Чи не надто щільно розташовані рядки?
- Чи легко відрізнити заголовок від основного тексту?
- Чи достатньо помітні посилання?
- Чи добре виглядає текст на мобільному екрані?
- Чи не зникає важливий текст через обрізання?
- Чи залишається текст читабельним при збільшенні масштабу?

### Практична порада

Змінюй одну властивість за раз. Наприклад, спочатку налаштуй `line-height`, потім ширину контейнера, а після цього — розмір шрифту.

Так простіше зрозуміти, яка зміна справді покращила результат.

## 22. Типові помилки

### Помилка 1. Надто маленький основний текст

    p {
      font-size: 12px;
    }

Такий розмір може бути незручним для довгого тексту.

Краще почати з:

    p {
      font-size: 1rem;
      line-height: 1.65;
    }

### Помилка 2. Занадто низький line-height

    p {
      line-height: 1.1;
    }

Рядки можуть виглядати стиснутими.

Краще:

    p {
      line-height: 1.6;
    }

### Помилка 3. Надто довгі рядки

    .article {
      width: 100%;
    }

На широкому екрані текст може розтягнутися на надмірну ширину.

Краще:

    .article {
      width: min(100% - 2rem, 70ch);
      margin-inline: auto;
    }

### Помилка 4. Надмірно світлий текст

    .body-text {
      color: #b8b8b8;
      background: #fff;
    }

Світло-сірий текст на білому фоні може мати недостатній контраст.

Рішення: перевір співвідношення контрастності та вибери відповідне поєднання кольорів.

### Помилка 5. Центрування довгих абзаців

    .article p {
      text-align: center;
    }

Коли кожен рядок починається в іншому місці, читачеві може бути складніше знаходити початок наступного рядка.

Для довгого тексту зазвичай зручніше:

    .article p {
      text-align: start;
    }

### Помилка 6. Надмірний letter-spacing

    p {
      letter-spacing: 0.12em;
    }

Такий інтервал може зробити слова візуально роз'єднаними.

Рішення: почни зі стандартного значення та змінюй його лише за конкретної потреби.

### Помилка 7. Однакове оформлення всіх текстів

Якщо заголовок, основний текст, підпис і повідомлення про помилку мають однаковий розмір і вагу, інтерфейс втрачає візуальну ієрархію.

Рішення: створи кілька узгоджених текстових стилів.

### Помилка 8. Відступи через порожні рядки в HTML

Не використовуй порожні абзаци або повторні пробіли для створення вертикального простору.

Рішення: використовуй `margin`, `padding` і властивості компонування.

### Помилка 9. Обрізання важливого тексту

    .description {
      height: 40px;
      overflow: hidden;
    }

Якщо текст важливий, користувач може не побачити його повністю.

Рішення: дозволяй блоку збільшуватися за потреби або передбачай зрозумілий спосіб переглянути повний текст.

### Помилка 10. Перевірка лише на одному екрані

Текст може виглядати добре на робочому моніторі, але погано на телефоні.

Рішення: перевіряй кілька ширин, масштабування та реальний контент.

## 23. Практичні вправи

### Вправа 1. Оформи звичайний абзац

Створи сторінку з трьома абзацами тексту.

Завдання:

- Задай `font-size: 1rem`.
- Спробуй `line-height: 1.4`, `1.6` і `1.8`.
- Порівняй комфорт читання.
- Перевір результат на вузькому екрані.
- Вибери найкраще значення для конкретного тексту.

### Вправа 2. Налаштуй ширину статті

Створи контейнер із довгим текстом.

Завдання:

- Перевір ширину `100%`.
- Спробуй `max-width: 60ch`.
- Спробуй `max-width: 70ch`.
- Порівняй довжину рядків.
- Перевір, чи комфортно повертатися до початку наступного рядка.

### Вправа 3. Створи три текстові стилі

Створи класи:

    .body-text
    .body-text--large
    .body-text--small

Завдання:

- Визнач розміри.
- Налаштуй `line-height`.
- Вибери кольори.
- Перевір контраст.
- Переконайся, що всі стилі залишаються читабельними.

### Вправа 4. Оформи опис картки

HTML:

    <article class="card">
      <h2>Основи HTML</h2>

      <p>
        Навчися створювати структуру вебсторінки,
        використовувати семантичні елементи та
        організовувати текстовий вміст.
      </p>

      <a href="/courses/html">Детальніше про курс</a>
    </article>

Завдання:

- Обмеж ширину картки.
- Налаштуй розмір опису.
- Додай відступи між елементами.
- Перевір перенесення тексту.
- Зроби посилання помітним.

### Вправа 5. Перевір доступність

Завдання:

- Перевір контраст тексту.
- Збільш масштаб браузера.
- Переконайся, що текст не обрізається.
- Перевір довгі українські слова.
- Перевір, чи можна розпізнати посилання без опори лише на колір.

### Вправа 6. Створи мінісистему типографіки

Створи CSS-змінні для:

- основного тексту;
- великого основного тексту;
- малого допоміжного тексту;
- міжрядкового інтервалу;
- ширини читання;
- основного та другорядного кольорів тексту.

Використай ці змінні в статті, картці та формі.

## 24. Що потрібно пам'ятати

✔ Body text — це основний текстовий вміст сторінки або компонента.

✔ Для більшості вебінтерфейсів `1rem` є зручною початковою точкою для основного тексту.

✔ `line-height` впливає на вертикальний ритм і комфорт читання.

✔ Для основного тексту часто підходить `line-height` у діапазоні `1.5–1.7`.

✔ Довжина рядка впливає на те, наскільки легко читач переходить між рядками.

✔ `max-width: 65ch` або `70ch` може бути корисною початковою точкою для довгих текстів.

✔ `font-family` впливає на форму символів, ширину рядків і загальне сприйняття тексту.

✔ `font-weight` потрібно використовувати для ієрархії, а не робити весь текст жирним.

✔ Для звичайного тексту часто достатньо `letter-spacing: normal`.

✔ `margin` допомагає розділяти абзаци та логічні блоки.

✔ Списки доречні для перелічення незалежних пунктів або послідовності дій.

✔ Посилання повинні мати зрозумілий текст і бути помітними.

✔ Для звичайного тексту орієнтуйся на контрастність не нижче `4.5:1` відповідно до WCAG AA.

✔ Текст повинен залишатися читабельним при збільшенні масштабу.

✔ Не використовуй порожні абзаци для створення відступів.

✔ Не обрізай важливий текст без можливості прочитати його повністю.

✔ Перевіряй текст на різних ширинах екрана та з реальним контентом.

✔ Хороший body text поєднує якісне оформлення зі зрозумілим написанням.

## 25. Типові питання на співбесіді

**1. Що таке body text?**

Це основний текстовий вміст інтерфейсу, який передає інформацію, пояснення, описи та інструкції.

**2. Який розмір шрифту використовувати для основного тексту?**

Часто починають із `16px` або `1rem`, але остаточне значення залежить від шрифту, призначення тексту та умов читання.

**3. Що робить line-height?**

Визначає висоту рядка тексту та впливає на вертикальну відстань між рядками.

**4. Чим відрізняються line-height і margin-bottom?**

`line-height` визначає висоту рядка всередині текстового блока, а `margin-bottom` — зовнішню відстань після елемента.

**5. Що таке довжина рядка?**

Це кількість символів або слів, які поміщаються в одному рядку. Вона впливає на комфорт переходу між рядками.

**6. Для чого використовують одиницю ch?**

Вона приблизно відповідає ширині символу `0` у поточному шрифті та може використовуватися для обмеження ширини текстових блоків.

**7. Чому не варто робити текст надто світлим?**

Низький контраст між текстом і фоном може ускладнювати читання, особливо для людей із порушеннями зору.

**8. Коли варто використовувати text-align: justify?**

Коли вирівнювання по ширині відповідає макету й не створює надто великих проміжків між словами. Результат потрібно перевіряти на реальному тексті.

**9. Чому для основного тексту часто використовують line-height: 1.6?**

Це може забезпечувати достатній вертикальний простір між рядками, але оптимальне значення залежить від гарнітури та ширини текстового блока.

**10. Чому важливо обмежувати ширину довгих текстів?**

Надто довгі рядки ускладнюють повернення погляду до початку наступного рядка.

**11. Як зробити текст адаптивним?**

Використовувати відносні одиниці, адаптивні контейнери, за потреби `clamp()` і перевіряти результат на різних ширинах.

**12. Що потрібно перевірити для доступності тексту?**

Контраст, читабельність, семантичну структуру, масштабування, зрозумілість посилань і відсутність втрати важливого вмісту.

## 26. Рівні володіння

### Core — базовий рівень

- Розумієш призначення основного тексту.
- Знаєш роль `font-size`, `line-height` і `font-family`.
- Умієш оформлювати абзаци через CSS.
- Розумієш, чому важливі довжина рядка та контраст.
- Умієш використовувати `margin` для відступів між абзацами.

### Junior — практичний рівень

- Самостійно оформлюєш основний текст у картках, статтях і формах.
- Підбираєш розмір шрифту та міжрядковий інтервал.
- Обмежуєш ширину довгих текстів.
- Створюєш стилі для звичайного, великого та допоміжного тексту.
- Оформлюєш списки, посилання та виділені фрагменти.
- Перевіряєш читабельність на мобільних пристроях.
- Перевіряєш контраст і масштабування.

### Middle — системний рівень

- Створюєш масштабовану систему текстових стилів.
- Узгоджуєш body text із заголовками та іншими текстовими елементами.
- Враховуєш особливості різних шрифтів і мов.
- Проєктуєш текстові блоки для різних компонентів.
- Перевіряєш довгі та короткі тексти в реальних сценаріях.
- Забезпечуєш узгоджену читабельність у всьому продукті.

### Senior — експертний рівень

- Формуєш правила типографіки для великої дизайн-системи.
- Враховуєш доступність, локалізацію та масштабування інтерфейсу.
- Визначаєш стандарти для статей, форм, карток і повідомлень.
- Узгоджуєш текстові стилі між дизайном і реалізацією.
- Враховуєш реальний контент, а не лише демонстраційні макети.
- Перевіряєш типографічні рішення на основі читабельності та потреб користувачів.

## 27. Мінішпаргалка

| Завдання | Приклад |
|---|---|
| Базовий розмір тексту | `font-size: 1rem;` |
| Збільшений текст | `font-size: 1.125rem;` |
| Допоміжний текст | `font-size: 0.875rem;` |
| Комфортний міжрядковий інтервал | `line-height: 1.6;` |
| Обмеження ширини статті | `max-width: 70ch;` |
| Центрування контейнера | `margin-inline: auto;` |
| Відступ між абзацами | `margin-bottom: 1.25rem;` |
| Звичайна товщина тексту | `font-weight: 400;` |
| Стандартний міжлітерний інтервал | `letter-spacing: normal;` |
| Вирівнювання за початковим краєм | `text-align: start;` |
| Адаптивний розмір | `font-size: clamp(1rem, 1.5vw, 1.25rem);` |
| Основний колір тексту | `color: #202938;` |

### Базовий стиль основного тексту

    .body-text {
      max-width: 70ch;
      font-family: system-ui, sans-serif;
      font-size: 1rem;
      font-weight: 400;
      line-height: 1.65;
      letter-spacing: normal;
      color: #202938;
    }

Це стартовий стиль, який можна адаптувати до дизайн-системи проєкту.

## 28. Підсумок

Основний текст — це не просто абзаци між заголовками. Він становить значну частину інтерфейсу та безпосередньо впливає на те, наскільки легко користувач розуміє інформацію.

Щоб створювати якісний body text:

- вибирай читабельний розмір шрифту;
- налаштовуй комфортний `line-height`;
- контролюй ширину текстового контейнера;
- використовуй зрозумілі абзаци та списки;
- забезпечуй достатній контраст;
- виділяй важливі фрагменти помірно;
- оформлюй посилання зрозуміло;
- враховуй адаптивність і масштабування;
- перевіряй реальний текст у браузері;
- створюй узгоджені текстові стилі для всього продукту.

**Головне правило:** хороший основний текст не повинен змушувати користувача боротися з оформленням. Він має допомагати легко знаходити, читати й розуміти потрібну інформацію.
