# 10. Font Pairing — Поєднання шрифтів

## 1. Що таке Font Pairing?

**Font Pairing (поєднання шрифтів)** — це підбір двох або більше шрифтів, які гармонійно працюють разом в одному інтерфейсі або дизайн-проєкті.

Найчастіше різні шрифти використовують для:
- заголовків;
- основного тексту;
- підзаголовків;
- навігації;
- кнопок;
- підписів;
- акцентних елементів.

Правильно підібрані шрифти допомагають створити візуальну ієрархію, зробити інтерфейс зрозумілішим і сформувати характер продукту.

Наприклад, для навчального застосунку можна використати виразний шрифт для заголовків і нейтральний, добре читабельний шрифт для основного тексту.

    /* Заголовки */
    h1,
    h2,
    h3 {
      font-family: Georgia, serif;
    }

    /* Основний текст */
    body {
      font-family: Arial, sans-serif;
    }

У цьому прикладі заголовки мають традиційний книжковий характер, а основний текст — нейтральний сучасний вигляд.

**Головна ідея:** шрифти повинні не конкурувати між собою, а виконувати різні ролі та підтримувати єдиний стиль інтерфейсу.

---

## 2. Навіщо потрібне поєднання шрифтів?

✔ Допомагає створити виразну типографічну ієрархію.

✔ Відокремлює заголовки від основного тексту.

✔ Підкреслює характер бренду або продукту.

✔ Робить сторінку візуально цікавішою.

✔ Допомагає користувачеві швидше знаходити важливу інформацію.

✔ Підтримує цілісність дизайн-системи.

✔ Дає змогу поєднати виразність і зручність читання.

### Де використовується Font Pairing?

- Сайти та вебзастосунки.
- Блоги й онлайн-журнали.
- Освітні платформи.
- Сторінки документації.
- Інтернет-магазини.
- Портфоліо.
- Корпоративні сайти.
- Посадкові сторінки.
- Дизайн-системи.
- Мобільні інтерфейси.

### Приклад

Уявімо сторінку навчального застосунку:

    H1: Основи програмування
    H2: Як працюють змінні
    Body: Змінна — це іменоване місце для зберігання даних.
    Button: Почати урок

Заголовок може мати виразніший шрифт, а основний текст і кнопки — використовувати нейтральний шрифт із хорошою читабельністю.

Завдяки цьому сторінка має характер, але не втрачає функціональності.

## 3. Основні поняття

### 3.1. Typeface — гарнітура

**Typeface** — загальний дизайн набору символів, наприклад Inter, Roboto або Georgia.

Гарнітура визначає зовнішній вигляд букв, цифр, розділових знаків та інших символів.

Приклади:

- Inter
- Roboto
- Open Sans
- Lato
- Montserrat
- Poppins
- Georgia
- Merriweather
- Playfair Display
- Source Sans 3

У CSS гарнітуру задають через `font-family`.

    body {
      font-family: Inter, sans-serif;
    }

### 3.2. Font — файл або конкретний шрифтовий стиль

У повсякденній розмові слова *font* і *typeface* часто використовують як синоніми.

У технічному контексті `font` може означати конкретний шрифтовий файл або стиль гарнітури, наприклад Inter Regular чи Inter Bold.

Одна гарнітура може містити багато стилів:
- Regular;
- Medium;
- SemiBold;
- Bold;
- Italic.

### 3.3. Font Family — сімейство шрифтів

`font-family` — CSS-властивість, яка визначає шрифт для тексту.

    body {
      font-family: "Open Sans", Arial, sans-serif;
    }

Браузер намагається використати першу доступну гарнітуру. Якщо вона недоступна, переходить до наступної.

Назви з пробілами зазвичай записують у лапках.

### 3.4. Serif — шрифти із засічками

**Serif** — шрифти, у яких на кінцях деяких штрихів є невеликі декоративні елементи, що називаються засічками.

Приклади:
- Georgia;
- Times New Roman;
- Merriweather;
- Lora;
- Playfair Display.

Такі шрифти можуть створювати враження традиційності, редакційного стилю, книжкової культури або елегантності.

Приклад:

    .article-title {
      font-family: Georgia, serif;
    }

### 3.5. Sans Serif — шрифти без засічок

**Sans Serif** — шрифти без засічок.

Приклади:
- Arial;
- Inter;
- Roboto;
- Open Sans;
- Lato;
- Montserrat;
- Poppins.

Вони часто використовуються в сучасних інтерфейсах завдяки широкому вибору стилів і зручності читання.

Приклад:

    body {
      font-family: Inter, sans-serif;
    }

### 3.6. Monospace — моноширинні шрифти

**Monospace** — шрифти, у яких символи мають однакову ширину.

Приклади:
- Consolas;
- Courier New;
- Source Code Pro;
- IBM Plex Mono.

Вони часто використовуються для:
- коду;
- технічних значень;
- ідентифікаторів;
- команд термінала;
- фрагментів документації.

    code,
    pre {
      font-family: "Source Code Pro", monospace;
    }

### 3.7. Font Weight — насиченість

`font-weight` визначає товщину символів.

Поширені значення:
- `400` — звичайна;
- `500` — середня;
- `600` — напівжирна;
- `700` — жирна.

Приклад:

    h1 {
      font-weight: 700;
    }

    body {
      font-weight: 400;
    }

Навіть одна гарнітура з різними значеннями `font-weight` може створювати достатню ієрархію без додавання другого шрифту.

### 3.8. Typography Hierarchy — типографічна ієрархія

Типографічна ієрархія допомагає користувачеві зрозуміти, які елементи важливіші.

Її створюють за допомогою:
- розміру;
- насиченості;
- кольору;
- міжрядкового інтервалу;
- відступів;
- регістру;
- вибору гарнітури.

**Важливо:** для створення ієрархії не обов'язково використовувати різні шрифти. Часто достатньо однієї гарнітури з кількома насиченостями та розмірами.

## 4. Основні принципи Font Pairing

### 4.1. Контраст із метою

Шрифти повинні відрізнятися настільки, щоб їхні ролі були зрозумілими, але не настільки, щоб створювати хаос.

Наприклад:
- виразний Serif для заголовків;
- нейтральний Sans Serif для основного тексту.

    h1,
    h2 {
      font-family: Georgia, serif;
    }

    body {
      font-family: Arial, sans-serif;
    }

Це класичний спосіб створити контраст між заголовками й основним текстом.

Однак контраст не є обов'язковою умовою. Дві добре підібрані Sans Serif-гарнітури також можуть працювати разом.

### 4.2. Спільний характер

Шрифти повинні відповідати характеру продукту.

Наприклад:

| Тип продукту | Можливий напрям |
|---|---|
| Освітній застосунок | Спокійний, чіткий, доступний |
| Медичний сервіс | Нейтральний, професійний, читабельний |
| Культурний журнал | Виразний редакційний заголовок і спокійний текст |
| Технологічний продукт | Сучасна Sans Serif-типографіка |
| Книжковий блог | Класичний Serif для довгих текстів |
| Дитячий освітній проєкт | Дружній, простий, виразний шрифт |

Це лише дизайнерські орієнтири, а не жорсткі правила.

### 4.3. Різні ролі

Кожен шрифт повинен мати зрозуміле призначення.

Наприклад:

    Заголовки: Playfair Display
    Основний текст: Source Sans 3
    Код: Source Code Pro

Тут:
- Playfair Display формує виразний редакційний стиль;
- Source Sans 3 забезпечує нейтральний текст;
- Source Code Pro виділяє програмний код.

### 4.4. Обмежена кількість шрифтів

Для більшості невеликих сайтів достатньо:
- однієї гарнітури;
- двох гарнітур;
- іноді трьох, якщо кожна має чітку роль.

Надмірна кількість різних гарнітур може зробити дизайн неузгодженим.

Не варто додавати новий шрифт лише тому, що він виглядає цікаво.

### 4.5. Читабельність важливіша за ефектність

Виразний шрифт може добре працювати для короткого заголовка, але бути незручним для довгих абзаців.

Тому:
- декоративні гарнітури частіше використовують для акцентів;
- основний текст зазвичай потребує комфортної читабельності;
- дрібні елементи інтерфейсу вимагають особливо уважного вибору;
- довгі тексти потрібно тестувати в реальному макеті.

## 5. Популярні стратегії поєднання шрифтів

### 5.1. Serif + Sans Serif

Одна з найвідоміших стратегій.

    Заголовки: Georgia
    Основний текст: Inter

Переваги:
- помітний контраст;
- чіткий поділ ролей;
- поєднання традиційного та сучасного характеру.

Може підходити для:
- статей;
- блогів;
- освітніх сторінок;
- культурних проєктів;
- редакційних сайтів.

### 5.2. Sans Serif + Sans Serif

Можна поєднати дві гарнітури без засічок, якщо вони мають різні ролі.

Наприклад:

    Заголовки: Montserrat
    Основний текст: Open Sans

Заголовки можуть мати геометричніший характер, а основний текст — нейтральніший вигляд.

Важливо перевіряти, чи справді друга гарнітура додає цінність. Часто можна використати одну гарнітуру з різними насиченостями.

### 5.3. Serif + Serif

Дві гарнітури із засічками також можна поєднувати.

Наприклад:

    Заголовки: Playfair Display
    Основний текст: Source Serif 4

Цей варіант може добре працювати для журналів, книжкових проєктів та інформаційних сайтів.

Але потрібно перевіряти, чи достатньо гарнітури відрізняються за характером і чи не створюють візуальної конкуренції.

### 5.4. Одна гарнітура, різні насиченості

Це простий і надійний підхід.

    h1 {
      font-weight: 700;
    }

    h2 {
      font-weight: 600;
    }

    p {
      font-weight: 400;
    }

Переваги:
- цілісний вигляд;
- менша кількість шрифтових файлів;
- простіше підтримувати дизайн-систему;
- легше забезпечити послідовність.

Для багатьох вебзастосунків цього достатньо.

### 5.5. Sans Serif + Monospace

Такий підхід особливо корисний у технічних інтерфейсах.

    body {
      font-family: Inter, sans-serif;
    }

    code,
    pre {
      font-family: "Source Code Pro", monospace;
    }

Основний інтерфейс залишається нейтральним, а код легко відрізнити від звичайного тексту.

## 6. Як підібрати пару шрифтів крок за кроком

### Крок 1. Визнач характер продукту

Перед вибором гарнітури потрібно зрозуміти, який настрій повинен створювати інтерфейс.

Запитай себе:
- продукт офіційний чи дружній?
- сучасний чи традиційний?
- технічний чи редакційний?
- мінімалістичний чи декоративний?
- основна дія — читання, пошук, навчання чи робота з даними?

Не потрібно починати з випадкового вибору популярного шрифту.

### Крок 2. Вибери шрифт для основного тексту

Основний текст є фундаментом типографіки.

Перевір:
- читабельність у невеликому розмірі;
- форму букв;
- розрізнення схожих символів;
- наявність потрібних символів;
- підтримку української мови;
- доступні насиченості;
- ліцензію та можливість використання у вебпроєкті.

Якщо шрифт погано підтримує українську абетку, він може показувати частину символів через резервний шрифт, що порушує візуальну цілісність.

### Крок 3. Підбери шрифт для заголовків

Після вибору основного шрифту визнач, чи потрібна друга гарнітура.

Запитай себе:
- чи має заголовок відрізнятися від основного тексту?
- чи достатньо змінити розмір і насиченість?
- чи потрібен виразніший характер?
- чи не буде заголовок занадто декоративним?

Якщо перший шрифт уже добре підходить для всіх ролей, друга гарнітура може бути непотрібною.

### Крок 4. Перевір реальні пари

Не оцінюй шрифти лише за назвами або окремими літерами.

Використовуй реальний текст:

    H1: Як працює вебзастосунок
    H2: Основні компоненти системи
    Body: Застосунок складається з інтерфейсу,
    серверної логіки та бази даних.
    Button: Переглянути урок

Перевір, як обидві гарнітури виглядають разом.

### Крок 5. Налаштуй розміри й насиченості

Навіть хороша пара шрифтів може виглядати невдало за неправильних розмірів.

    h1 {
      font-size: 2.5rem;
      font-weight: 700;
    }

    h2 {
      font-size: 1.75rem;
      font-weight: 600;
    }

    body {
      font-size: 1rem;
      font-weight: 400;
      line-height: 1.7;
    }

Це приклад початкових значень. Для конкретного проєкту їх потрібно перевіряти на реальному контенті.

### Крок 6. Перевір на різних екранах

Переконайся, що:
- заголовки не створюють незручних переносів;
- основний текст читається на смартфоні;
- кнопки залишаються зрозумілими;
- кирилиця відображається правильно;
- різні насиченості справді доступні;
- шрифти не створюють надмірного візуального шуму.

### Крок 7. Задокументуй вибір

У дизайн-системі зафіксуй:
- назву гарнітури;
- призначення;
- допустимі насиченості;
- розміри тексту;
- міжрядкові інтервали;
- резервні шрифти;
- правила використання.

## 7. Google Fonts та вебшрифти

Для вебпроєктів можна використовувати системні шрифти або завантажувати вебшрифти.

### 7.1. Системні шрифти

Приклад:

    body {
      font-family: Arial, Helvetica, sans-serif;
    }

Переваги:
- не потрібно завантажувати окремі файли шрифтів;
- часто швидше відображення;
- проста конфігурація.

Недоліки:
- зовнішній вигляд може відрізнятися між операційними системами;
- набір доступних гарнітур залежить від пристрою.

### 7.2. Google Fonts

Google Fonts — каталог вебшрифтів, які можна підключати до сайтів.

Перед використанням перевір:
- наявність потрібної гарнітури;
- підтримку кирилиці;
- доступні стилі та насиченості;
- умови ліцензії;
- спосіб завантаження.

### 7.3. Підключення через CSS

Після отримання URL для конкретного шрифту можна використати `@import`, хоча для багатьох виробничих проєктів краще завантажувати стилі через HTML або самостійно розміщувати файли.

Приклад форми підключення:

    @import url('https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&display=swap');

    body {
      font-family: "Inter", sans-serif;
    }

Це приклад синтаксису. У реальному проєкті потрібно перевірити правильність URL, набір потрібних стилів і підтримку символів.

### 7.4. Підключення через HTML

    <head>
      <link rel="preconnect" href="https://fonts.googleapis.com">
      <link
        rel="preconnect"
        href="https://fonts.gstatic.com"
        crossorigin
      >
      <link
        href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&display=swap"
        rel="stylesheet"
      >
    </head>

    <body>
      <h1>Основи вебдизайну</h1>
      <p>Приклад тексту.</p>
    </body>

Використовуй лише ті стилі, які справді потрібні проєкту, а URL шрифтів формуй відповідно до обраних гарнітур і потрібних насиченостей.

### 7.5. Локальні шрифти через `@font-face`

Якщо файли шрифтів зберігаються у проєкті, їх можна підключити через `@font-face`.

    @font-face {
      font-family: "Project Sans";
      src: url("/fonts/project-sans-regular.woff2") format("woff2");
      font-weight: 400;
      font-style: normal;
      font-display: swap;
    }

    @font-face {
      font-family: "Project Sans";
      src: url("/fonts/project-sans-bold.woff2") format("woff2");
      font-weight: 700;
      font-style: normal;
      font-display: swap;
    }

    body {
      font-family: "Project Sans", sans-serif;
    }

Назви файлів у прикладі умовні. Потрібно використовувати фактичні файли, що є у проєкті, та коректно оголосити доступні стилі.

### 7.6. Fallback — резервні шрифти

Завжди бажано визначати резервні гарнітури.

    body {
      font-family: "Inter", Arial, sans-serif;
    }

Якщо Inter недоступний, браузер спробує Arial, а потім системний шрифт без засічок.

Резервний шрифт не обов'язково має бути ідентичним, але повинен підтримувати читабельність і не порушувати макет.

## 8. Font Pairing і підтримка української мови

Для українських проєктів важливо перевіряти не лише загальний вигляд шрифту, а й підтримку кирилиці.

### 8.1. Перевір символи

Тестовий текст:

    Ґанок, ґудзик, єдність, їжак,
    Україна, Київ, Вінниця, щастя.

Зверни увагу на:
- Ґ та ґ;
- Є та є;
- І та і;
- Ї та ї;
- апостроф;
- українські лапки;
- тире та інші розділові знаки.

### 8.2. Перевір реальні слова

Окремі літери не завжди показують проблеми з формою символів і ритмом тексту.

Тому перевір цілі речення:

    Навчання програмуванню потребує практики,
    послідовності та регулярного повторення.

Оціни читабельність у заголовках, абзацах, кнопках і дрібних підписах.

### 8.3. Перевір резервні шрифти

Якщо вебшрифт не має певних символів, браузер може використати іншу гарнітуру лише для частини тексту.

У результаті деякі букви можуть виглядати інакше.

Тому важливо перевіряти:
- чи підтримує шрифт потрібний набір символів;
- чи завантажується потрібний файл;
- чи не виникає небажана заміна гарнітури;
- чи відповідає резервний шрифт основному за загальним характером.

## 9. Font Pairing і дизайн-система

У великому проєкті не варто вибирати шрифт окремо для кожної сторінки.

Краще створити типографічні правила, які використовуватимуться в усьому інтерфейсі.

### 9.1. Визнач шрифтові ролі

Наприклад:

    Display — великі виразні заголовки
    Heading — заголовки секцій
    Body — основний текст
    UI — кнопки, навігація, форми
    Code — фрагменти коду

Не обов'язково призначати кожній ролі окрему гарнітуру.

### 9.2. Створи CSS-змінні

    :root {
      --font-heading: "Playfair Display", Georgia, serif;
      --font-body: "Source Sans 3", Arial, sans-serif;
      --font-code: "Source Code Pro", monospace;
    }

    body {
      font-family: var(--font-body);
    }

    h1,
    h2,
    h3 {
      font-family: var(--font-heading);
    }

    code,
    pre {
      font-family: var(--font-code);
    }

Таке рішення дозволяє змінити гарнітуру в одному місці.

### 9.3. Задай ролі тексту

    :root {
      --font-size-body: 1rem;
      --font-size-small: 0.875rem;
      --font-size-h1: 2.5rem;
      --font-size-h2: 1.75rem;
    }

    body {
      font-size: var(--font-size-body);
    }

    h1 {
      font-size: var(--font-size-h1);
    }

    h2 {
      font-size: var(--font-size-h2);
    }

Це приклад структури змінних. Для реального проєкту варто також задокументувати насиченості, міжрядкові інтервали та адаптивну поведінку.

### 9.4. Не створюй зайві ролі

Якщо для проєкту достатньо `heading`, `body` та `code`, не потрібно вигадувати багато схожих категорій.

Дизайн-система повинна спрощувати роботу, а не ускладнювати її.

## 10. Типові помилки

### 10.1. Використання надто великої кількості шрифтів

Коли кожен заголовок має іншу гарнітуру, сторінка може втратити цілісність.

Рішення:
- визначити основні шрифтові ролі;
- обмежити кількість гарнітур;
- використовувати різні насиченості однієї гарнітури, якщо цього достатньо.

### 10.2. Поєднання шрифтів із надто схожим характером

Дві майже однакові гарнітури можуть створювати враження непослідовності, не додаючи помітної користі.

Це не означає, що схожі шрифти не можна поєднувати. Потрібно розуміти, яку функцію виконує кожен із них.

### 10.3. Надмірно декоративний основний текст

Декоративні шрифти можуть бути ефектними в коротких заголовках, але в довгих абзацах вони часто менш зручні.

Для основного тексту обирай гарнітуру, яку легко читати в потрібному розмірі.

### 10.4. Вибір лише за популярністю

Популярний шрифт не обов'язково підходить конкретному продукту.

Потрібно враховувати:
- характер інтерфейсу;
- довжину текстів;
- підтримку мов;
- доступні насиченості;
- швидкість завантаження;
- ліцензію.

### 10.5. Ігнорування кирилиці

Якщо шрифт не підтримує потрібні символи, браузер може підставляти іншу гарнітуру.

Це може бути особливо помітно в українських заголовках і коротких акцентних написах.

### 10.6. Завантаження всіх можливих стилів

Якщо використовується лише `400`, `600` і `700`, не завжди потрібно завантажувати всі наявні насиченості.

Зайві файли можуть збільшувати обсяг завантаження сторінки.

Водночас не слід оголошувати шрифтові стилі, яких фактично немає, якщо це призводить до непередбачуваної поведінки.

### 10.7. Невідповідність шрифтів характеру продукту

Шрифт може бути красивим сам по собі, але погано відповідати завданню.

Наприклад, дуже декоративний заголовок може відволікати від інформації в інтерфейсі, де користувачеві потрібно швидко виконувати робочі завдання.

### 10.8. Відсутність резервного шрифту

    /* Менш надійний варіант */
    body {
      font-family: "Inter";
    }

Краще:

    body {
      font-family: "Inter", Arial, sans-serif;
    }

Резервні шрифти допомагають зберігати доступність тексту, якщо основний шрифт не завантажився.

### 10.9. Оцінювання шрифтів без реального контенту

Латинські літери в демонстраційному зразку можуть виглядати добре, але український текст може мати інший ритм і щільність.

Перевіряй реальні заголовки, абзаци, кнопки, числа й спеціальні символи.

## 11. Практичний приклад: освітній застосунок

Створимо просту типографічну систему для сторінки навчального матеріалу.

### HTML

    <main class="lesson">
      <header class="lesson-header">
        <p class="lesson-category">JavaScript · Основи</p>
        <h1>Як працюють функції</h1>
        <p class="lesson-lead">
          Функції допомагають об'єднувати інструкції
          в логічні блоки та повторно використовувати код.
        </p>
      </header>

      <section class="lesson-content">
        <h2>Що таке функція?</h2>
        <p>
          Функція — це блок коду, який можна викликати
          для виконання певного завдання.
        </p>

        <h2>Приклад</h2>
        <pre><code>function greet(name) {
      return `Привіт, ${name}!`;
    }</code></pre>

        <button type="button">Перейти до вправи</button>
      </section>
    </main>

### CSS

    @import url('https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&family=Playfair+Display:wght@600;700&family=Source+Code+Pro:wght@400;500&display=swap');

    :root {
      --font-heading: "Playfair Display", Georgia, serif;
      --font-body: "Inter", Arial, sans-serif;
      --font-code: "Source Code Pro", monospace;
    }

    * {
      box-sizing: border-box;
    }

    body {
      margin: 0;
      font-family: var(--font-body);
      font-size: 1rem;
      line-height: 1.7;
      color: #222;
      background-color: #f5f5f5;
    }

    .lesson {
      width: 100%;
      max-width: 65ch;
      margin-inline: auto;
      padding: 2rem 1rem;
      background-color: #fff;
    }

    .lesson-category {
      font-size: 0.875rem;
      font-weight: 600;
      color: #555;
    }

    .lesson h1,
    .lesson h2 {
      font-family: var(--font-heading);
      line-height: 1.2;
    }

    .lesson h1 {
      font-size: clamp(2rem, 5vw, 3rem);
      font-weight: 700;
    }

    .lesson h2 {
      margin-top: 2rem;
      font-size: 1.75rem;
      font-weight: 600;
    }

    .lesson-lead {
      font-size: 1.125rem;
      line-height: 1.6;
    }

    pre,
    code {
      font-family: var(--font-code);
    }

    pre {
      max-width: 100%;
      padding: 1rem;
      overflow-x: auto;
      border-radius: 0.5rem;
      background-color: #f0f0f0;
    }

    button {
      font: inherit;
      font-weight: 600;
      padding: 0.75rem 1rem;
      border: 0;
      border-radius: 0.5rem;
      cursor: pointer;
    }

### Що тут важливо?

- Playfair Display використовується для виразних заголовків.
- Inter використовується для основного тексту й елементів інтерфейсу.
- Source Code Pro відрізняє код від звичайного тексту.
- CSS-змінні централізують налаштування гарнітур.
- `font: inherit` допомагає кнопці використовувати типографіку батьківського інтерфейсу.
- `max-width` обмежує ширину навчального тексту.

У реальному проєкті потрібно перевірити, чи справді всі три гарнітури необхідні. Для невеликого застосунку двох або навіть однієї може бути достатньо.

## 12. Практичні вправи

### Вправа 1. Одна гарнітура чи дві?

Створи дві версії однієї сторінки.

**Варіант A: одна гарнітура**

    body {
      font-family: Arial, sans-serif;
    }

**Варіант B: дві гарнітури**

    h1,
    h2 {
      font-family: Georgia, serif;
    }

    body {
      font-family: Arial, sans-serif;
    }

Порівняй:
- візуальну ієрархію;
- характер сторінки;
- читабельність;
- цілісність дизайну.

Мета — зрозуміти, чи справді друга гарнітура покращує інтерфейс.

### Вправа 2. Підбери шрифти для різних продуктів

Створи три макети:
- освітній застосунок;
- блог про культуру;
- панель керування даними.

Для кожного визнач:
- характер продукту;
- шрифт основного тексту;
- шрифт заголовків;
- чи потрібен моноширинний шрифт;
- які насиченості будуть використовуватися.

Поясни, чому обрав саме такі поєднання.

### Вправа 3. Перевір підтримку української

Створи заголовок і абзац з українськими символами.

    <h1>Єдність, ґрунт і знання</h1>

    <p>
      Їжак їде через українське місто,
      а ґудзик лежить біля вікна.
    </p>

Перевір, чи всі символи відображаються однаково узгоджено.

### Вправа 4. Створи типографічні змінні

Створи файл `typography.css`.

Визнач змінні:
- `--font-heading`;
- `--font-body`;
- `--font-code`;
- `--font-size-body`;
- `--font-size-h1`;
- `--font-size-h2`.

Використай їх на тестовій сторінці.

### Вправа 5. Перевір продуктивність

Порівняй сторінку:
- із системними шрифтами;
- з одним вебшрифтом;
- із двома вебшрифтами;
- з трьома вебшрифтами.

Зверни увагу на:
- кількість завантажуваних файлів;
- доступні насиченості;
- поведінку до завантаження шрифтів;
- можливі зміни перенесення рядків.

Мета — зрозуміти, що вибір шрифтів впливає не лише на вигляд, а й на завантаження сторінки.

## 13. Що потрібно пам'ятати

- **Font Pairing** — це поєднання шрифтів для створення цілісної типографіки.
- Шрифти повинні доповнювати один одного та мати зрозумілі ролі.
- Для багатьох проєктів достатньо однієї або двох гарнітур.
- Поєднання Serif і Sans Serif — поширена, але не обов'язкова стратегія.
- Дві Sans Serif або дві Serif-гарнітури також можуть працювати разом.
- Одна гарнітура з різними насиченостями часто забезпечує достатню ієрархію.
- Основний текст повинен залишатися комфортним для читання.
- Декоративний шрифт не завжди підходить для довгих абзаців.
- Потрібно перевіряти підтримку української абетки.
- `font-family` визначає сімейство шрифтів.
- `font-weight` задає насиченість тексту.
- CSS-змінні допомагають централізувати типографічні правила.
- Резервні шрифти підтримують читабельність, якщо основний шрифт недоступний.
- Завантажуй лише потрібні гарнітури та стилі.
- Перевіряй шрифти на реальному контенті й різних розмірах екрана.
- Гарне поєднання шрифтів не повинно відволікати від змісту інтерфейсу.

## 14. Мінішпаргалка

| Завдання | CSS |
|---|---|
| Задати шрифт сторінки | `font-family: Arial, sans-serif;` |
| Задати шрифт заголовків | `font-family: Georgia, serif;` |
| Задати моноширинний шрифт | `font-family: monospace;` |
| Задати звичайну насиченість | `font-weight: 400;` |
| Задати напівжирний текст | `font-weight: 600;` |
| Задати жирний текст | `font-weight: 700;` |
| Використати CSS-змінну | `font-family: var(--font-body);` |
| Задати резервні шрифти | `font-family: "Inter", Arial, sans-serif;` |
| Успадкувати шрифт у кнопці | `font: inherit;` |
| Підключити локальний вебшрифт | `@font-face { ... }` |

### Базовий шаблон

    :root {
      --font-heading: Georgia, serif;
      --font-body: Arial, sans-serif;
      --font-code: monospace;
    }

    body {
      font-family: var(--font-body);
      line-height: 1.7;
    }

    h1,
    h2,
    h3 {
      font-family: var(--font-heading);
    }

    code,
    pre {
      font-family: var(--font-code);
    }

Це простий шаблон, з якого можна почати створення типографічної системи.

## 15. Рівні володіння навичкою

### Core — основи

Ти:
- розумієш, що таке Font Pairing;
- знаєш різницю між Serif, Sans Serif і Monospace;
- розумієш призначення `font-family`;
- можеш вибрати шрифт для заголовка й основного тексту;
- знаєш, що різні насиченості можуть створювати ієрархію.

### Junior — практичне використання

Ти:
- підбираєш гарнітури відповідно до характеру продукту;
- перевіряєш шрифти на реальних текстах;
- використовуєш `font-weight`;
- підключаєш вебшрифти;
- додаєш резервні гарнітури;
- перевіряєш підтримку української абетки;
- створюєш базові типографічні CSS-змінні.

### Middle — системний підхід

Ти:
- створюєш типографічну систему для всього застосунку;
- визначаєш ролі заголовків, основного тексту, UI та коду;
- оптимізуєш набір гарнітур і стилів;
- враховуєш читабельність, продуктивність і адаптивність;
- перевіряєш поведінку різних гарнітур на різних мовах;
- документуєш правила використання шрифтів.

### Senior — дизайн-система

Ти:
- формуєш типографічні принципи для великого продукту;
- обираєш шрифти відповідно до потреб аудиторії та продукту;
- оцінюєш компроміс між виразністю, читабельністю та продуктивністю;
- створюєш масштабовані типографічні токени;
- забезпечуєш послідовність між сторінками й командами;
- враховуєш доступність, локалізацію та довгострокову підтримку системи.

## Висновок

**Font Pairing — це не просто вибір двох красивих шрифтів, а створення узгодженої системи типографіки.**

Починай із визначення характеру продукту та вибору гарнітури для основного тексту. Потім виріши, чи потрібен окремий шрифт для заголовків, і перевір, як вони працюють разом у реальному інтерфейсі.

Не забувай про підтримку української мови, резервні шрифти, потрібні насиченості та швидкість завантаження.

Головне правило: **кожен шрифт повинен мати зрозумілу роль, а всі разом вони повинні підтримувати зміст і характер продукту.**
