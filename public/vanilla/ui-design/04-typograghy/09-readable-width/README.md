# 09. Readable Width — Оптимальна ширина тексту

## 1. Що таке Readable Width?

**Readable Width (оптимальна ширина тексту)** — це налаштування ширини текстового блоку, яке допомагає користувачеві легко читати й розуміти текст без надмірного навантаження на очі.

Якщо рядки занадто довгі, очам важче переходити від кінця одного рядка до початку наступного. Якщо рядки занадто короткі, текст розбивається на велику кількість рядків, а читання стає уривчастим.

Мета Readable Width — знайти баланс між:
- довжиною рядка;
- розміром шрифту;
- міжрядковим інтервалом;
- типом тексту;
- шириною екрана;
- загальною композицією сторінки.

У UI-дизайні цей принцип особливо важливий для статей, блогів, документації, навчальних матеріалів, описів товарів і довгих текстових сторінок.

### Приклад

    /* Занадто широка текстова колонка */
    .article {
      width: 100%;
    }

    /* Обмежена ширина для комфортного читання */
    .article {
      max-width: 65ch;
      margin-inline: auto;
    }

У другому прикладі `65ch` обмежує ширину текстового блоку приблизно шириною 65 символів `0` у поточному шрифті. Це не гарантує рівно 65 символів у кожному рядку, але допомагає контролювати довжину рядків.

**Головна ідея:** текст повинен бути не просто видимим на екрані, а комфортним для читання.

---

## 2. Навіщо потрібна оптимальна ширина тексту?

✔ Зменшує втому очей під час читання.

✔ Допомагає швидше переходити між рядками.

✔ Покращує сприйняття довгих текстів.

✔ Робить сторінку візуально збалансованою.

✔ Допомагає організувати ієрархію контенту.

✔ Підтримує адаптивний дизайн.

✔ Робить інтерфейс комфортнішим на різних пристроях.

### Де використовується?

- Блоги та статті.
- Сторінки новин.
- Навчальні матеріали.
- Документація.
- Онлайн-книги.
- Сторінки довідки.
- Описи товарів.
- Текстові блоки в картках.
- Сторінки проєктів і портфоліо.
- Інтерфейси освітніх та інформаційних застосунків.

### Приклад у реальному інтерфейсі

У навчальному застосунку можуть бути різні типи контенту:

    Заголовок уроку
    Короткий опис
    Основний навчальний текст
    Приклади коду
    Завдання
    Додаткові пояснення

Для кожного типу контенту ширина може відрізнятися. Наприклад, основний текст варто обмежити для читання, а блок із кодом може потребувати більшої ширини або горизонтального прокручування.

## 3. Основні поняття

### 3.1. Line Length — довжина рядка

**Line Length** — кількість символів, які розміщуються в одному рядку тексту.

Довжина рядка залежить від:
- ширини текстового контейнера;
- розміру шрифту;
- типу гарнітури;
- ширини конкретних символів;
- жирності та стилю шрифту;
- масштабу відображення.

Для основного тексту часто використовують орієнтир приблизно **45–75 символів у рядку**, а близько **60–70 символів** може бути зручним початковим значенням.

Це не суворе правило. Оптимальна довжина залежить від мови, шрифту, аудиторії та типу контенту.

Наприклад:

    Короткий рядок:
    Текст легко читати, але він
    займає багато рядків.

    Надто довгий рядок:
    Текст займає майже всю ширину великого екрана, тому очам може бути складніше знаходити початок наступного рядка після завершення попереднього.

    Помірна довжина:
    Текст займає комфортну ширину
    і зберігає природний ритм читання.

### 3.2. Text Container — текстовий контейнер

**Text Container** — область, у якій розміщується текст.

Контейнер може мати:
- фіксовану ширину;
- максимальну ширину;
- відносну ширину;
- внутрішні відступи;
- обмеження для різних екранів.

Приклад:

    .article {
      width: 100%;
      max-width: 65ch;
      margin-inline: auto;
      padding-inline: 1rem;
    }

Тут:
- `width: 100%` дозволяє контейнеру займати доступну ширину;
- `max-width: 65ch` обмежує його максимальну ширину;
- `margin-inline: auto` центрує контейнер;
- `padding-inline: 1rem` додає відступи зліва та справа.

### 3.3. Measure — типографічна ширина рядка

У типографіці термін **Measure** означає ширину текстового рядка або його характерну довжину.

У вебдизайні Measure допомагає визначити, наскільки широкою має бути колонка основного тексту.

Не слід плутати Measure із шириною всього екрана. Екран може бути широким, але текстова колонка — вузькою та зручною для читання.

### 3.4. Readability — зручність читання

**Readability** — наскільки легко читачеві сприймати текст.

На неї впливають:
- довжина рядків;
- розмір шрифту;
- міжрядковий інтервал;
- контраст тексту та фону;
- довжина абзаців;
- структура заголовків;
- відстань між блоками;
- складність самого тексту.

Важливо: оптимальна ширина не компенсує надто дрібний шрифт, слабкий контраст або погану структуру документа.

### 3.5. `ch` — одиниця для ширини тексту

Одиниця `ch` приблизно відповідає ширині символу `0` у поточному шрифті.

Приклад:

    .article {
      max-width: 65ch;
    }

Переваги:
- зручна для обмеження ширини текстових колонок;
- пов'язана з типографічними характеристиками шрифту;
- допомагає створювати комфортну довжину рядків.

Обмеження:
- `65ch` не означає, що в кожному рядку буде рівно 65 символів;
- різні символи мають різну ширину;
- результат залежить від гарнітури та розміру шрифту.

### 3.6. `max-width` — максимальна ширина

Властивість `max-width` визначає найбільшу дозволену ширину елемента.

    .article {
      width: 100%;
      max-width: 65ch;
    }

На широкому екрані текст не розтягується безмежно, а на вузькому може займати доступну ширину.

### 3.7. Responsive Width — адаптивна ширина

Адаптивна ширина змінюється залежно від доступного простору.

На великому екрані текст може бути обмежений значенням `65ch`, а на смартфоні — займати майже всю доступну ширину з невеликими боковими відступами.

    .article {
      width: 100%;
      max-width: 65ch;
      margin-inline: auto;
      padding-inline: 1rem;
    }

Такий підхід часто не потребує окремого медіазапиту для базової ширини тексту.

## 4. Як вибирати ширину тексту

### 4.1. Основний текст статті

Для довгого тексту варто починати приблизно з ширини **60–70 символів у рядку**.

У CSS можна спробувати:

    .article {
      max-width: 65ch;
    }

Це початковий орієнтир, а не універсальне значення для всіх сайтів.

### 4.2. Заголовки

Заголовки часто мають іншу ширину, ніж основний текст.

Короткий заголовок може бути вузьким, а довгий — потребувати ширшої колонки.

    .article-title {
      max-width: 20ch;
    }

`20ch` тут лише приклад обмеження. Для заголовків важливо перевіряти фактичне перенесення рядків і не створювати незручних розривів.

### 4.3. Короткі описи

Короткі описи в картках можуть бути ширшими або вужчими залежно від композиції.

    .card-description {
      max-width: 45ch;
    }

Для карток із кількома колонками потрібно перевіряти, чи не стають рядки надто короткими.

### 4.4. Форми

У формах ширина текстових полів залежить від призначення.

Наприклад:
- поле імені може бути коротким;
- поле електронної пошти — середнім;
- поле повідомлення — ширшим.

Для тексту-пояснення біля форми можна використовувати обмежену ширину:

    .form-description {
      max-width: 55ch;
    }

Не потрібно встановлювати однакову ширину для всіх полів і текстових блоків лише заради формальної єдності.

### 4.5. Документація та навчальні матеріали

У документації основний текст може мати помірну ширину, а приклади коду — ширшу.

    .documentation-text {
      max-width: 70ch;
    }

    .code-example {
      overflow-x: auto;
    }

Код часто містить довгі рядки, тому для нього важливо передбачити горизонтальне прокручування або інший спосіб збереження читабельності.

## 5. CSS для оптимальної ширини

### 5.1. `max-width` разом із `width`

Один із найпоширеніших способів:

    .text-content {
      width: 100%;
      max-width: 65ch;
    }

`width: 100%` дозволяє елементу використовувати доступний простір, а `max-width` обмежує його розтягування.

### 5.2. Центрування текстового контейнера

    .article {
      width: 100%;
      max-width: 65ch;
      margin-inline: auto;
    }

`margin-inline: auto` центрує контейнер у батьківському елементі, якщо для цього є доступний горизонтальний простір.

### 5.3. Бокові відступи

    .article {
      width: 100%;
      max-width: 65ch;
      margin-inline: auto;
      padding-inline: 1rem;
      box-sizing: border-box;
    }

`box-sizing: border-box` допомагає враховувати внутрішні відступи в заданій ширині елемента.

Це корисно, коли потрібно уникнути горизонтального переповнення на вузьких екранах.

### 5.4. Використання `clamp()`

`clamp()` дозволяє визначити мінімальне, бажане та максимальне значення.

    .article {
      width: clamp(0px, 100%, 65ch);
      margin-inline: auto;
    }

У цьому прикладі ширина не буде меншою за `0px`, прагнутиме займати доступні `100%` і не перевищуватиме `65ch`.

Проте `clamp()` не завжди потрібен. Для звичайної текстової колонки комбінації `width: 100%` і `max-width` часто достатньо.

### 5.5. Використання CSS Grid

Grid допомагає розмістити текст у центральній колонці.

    .article-layout {
      display: grid;
      grid-template-columns:
        minmax(1rem, 1fr)
        minmax(0, 65ch)
        minmax(1rem, 1fr);
    }

    .article-content {
      grid-column: 2;
    }

Тут:
- перша колонка створює простір зліва;
- друга колонка обмежує ширину основного тексту;
- третя колонка створює простір справа.

Такий варіант корисний для сторінок статей із центральною текстовою колонкою.

### 5.6. CSS Grid для сторінки з бічною панеллю

    .page-layout {
      display: grid;
      grid-template-columns:
        minmax(0, 1fr)
        minmax(14rem, 20rem);
      gap: 2rem;
    }

    .article {
      max-width: 65ch;
    }

У цьому прикладі стаття та бічна панель розміщуються поруч. Але сама стаття все одно має обмежену ширину.

Для вузьких екранів таку композицію потрібно адаптувати, наприклад, розташувати бічну панель під основним текстом.

## 6. Readable Width і Responsive Design

Оптимальна ширина тексту повинна працювати на різних екранах.

### 6.1. Десктоп

На широкому екрані не потрібно розтягувати основний текст на всю ширину вікна.

    .article {
      width: 100%;
      max-width: 65ch;
      margin-inline: auto;
      padding-inline: 1.5rem;
    }

### 6.2. Планшет

На планшеті контейнер може займати більшу частину доступного простору, але не повинен виходити за межі екрана.

    .article {
      width: 100%;
      max-width: 65ch;
      margin-inline: auto;
      padding-inline: 1.25rem;
      box-sizing: border-box;
    }

### 6.3. Смартфон

На смартфоні текст зазвичай використовує майже всю доступну ширину з достатніми боковими відступами.

    .article {
      width: 100%;
      max-width: 65ch;
      margin-inline: auto;
      padding-inline: 1rem;
      box-sizing: border-box;
    }

У цьому прикладі окремий медіазапит не потрібен: ширина контейнера автоматично підлаштовується до доступного простору.

### 6.4. Коли потрібні медіазапити?

Медіазапити можуть знадобитися, якщо:
- змінюється структура сторінки;
- бічна панель переходить під текст;
- змінюються відступи;
- заголовки мають іншу типографіку;
- для вузького екрана потрібне інше розташування елементів.

    .article {
      max-width: 65ch;
      margin-inline: auto;
      padding-inline: 1rem;
    }

    @media (min-width: 48rem) {
      .article {
        padding-inline: 1.5rem;
      }
    }

У цьому прикладі на ширших екранах збільшується горизонтальний внутрішній відступ.

### 6.5. Не орієнтуйся лише на назву пристрою

Не потрібно автоматично створювати окремі значення для кожного типу пристрою.

Краще перевіряти:
- чи комфортно читати текст;
- чи не стають рядки надто довгими;
- чи не з'являється горизонтальне прокручування сторінки;
- чи зберігається достатньо простору біля країв;
- чи правильно переносяться заголовки.

## 7. Readable Width і типографіка

Ширина тексту працює разом з іншими типографічними властивостями.

### 7.1. Ширина та розмір шрифту

Якщо збільшити шрифт, у тому самому контейнері зазвичай поміститься менше символів.

    .article {
      max-width: 65ch;
      font-size: 1rem;
    }

    .article--large {
      font-size: 1.125rem;
    }

Тому ширину тексту потрібно оцінювати разом із фактичним розміром шрифту.

### 7.2. Ширина та міжрядковий інтервал

Міжрядковий інтервал задається через `line-height`.

    .article {
      max-width: 65ch;
      font-size: 1rem;
      line-height: 1.7;
    }

`line-height: 1.7` — приклад значення для початкового тестування. Оптимальне значення залежить від гарнітури, розміру тексту та характеру контенту.

### 7.3. Ширина та довжина абзаців

Навіть за правильної ширини довгі абзаци можуть ускладнювати читання.

Варто:
- розділяти різні думки на окремі абзаци;
- використовувати змістовні заголовки;
- додавати списки там, де вони справді допомагають;
- залишати достатній вертикальний простір між блоками.

### 7.4. Ширина та контраст

Оптимальна ширина не замінює достатнього контрасту між текстом і фоном.

    .article {
      max-width: 65ch;
      color: #222;
      background-color: #fff;
    }

Це лише приклад кольорів. У реальному проєкті потрібно перевіряти контраст, зокрема для звичайного тексту, посилань і тексту з меншою непрозорістю.

### 7.5. Ширина та шрифт

Різні гарнітури мають різну ширину символів.

Тому однакове значення `65ch` у двох шрифтах не обов'язково створюватиме однакове візуальне враження.

Після зміни шрифту варто повторно перевірити:
- перенесення рядків;
- загальну ширину текстового блоку;
- довжину заголовків;
- комфорт читання на смартфоні.

## 8. Типові помилки

### 8.1. Текст займає всю ширину екрана

    /* Потенційна проблема */
    .article {
      width: 100%;
    }

На широкому екрані рядки можуть стати надто довгими.

Краще:

    .article {
      width: 100%;
      max-width: 65ch;
      margin-inline: auto;
    }

### 8.2. Надто вузька колонка

Якщо текстова колонка занадто вузька, речення розбиваються на багато коротких рядків.

Наслідки:
- сторінка стає надмірно довгою;
- читання сповільнюється;
- порушується візуальний ритм;
- текст може виглядати незбалансовано.

Рішення — перевірити реальну довжину рядків і поступово збільшити ширину контейнера.

### 8.3. Використання фіксованої ширини в пікселях без адаптації

    /* Невдалий підхід для адаптивного тексту */
    .article {
      width: 900px;
    }

На вузькому екрані такий контейнер може виходити за межі viewport.

Краще:

    .article {
      width: 100%;
      max-width: 65ch;
      box-sizing: border-box;
    }

### 8.4. Надто малі бокові відступи

Навіть за правильної максимальної ширини текст може опинитися надто близько до краю смартфона.

Рішення:

    .article {
      padding-inline: 1rem;
      box-sizing: border-box;
    }

### 8.5. Спроба зробити всі блоки однакової ширини

Заголовок, основний текст, підпис до зображення та блок коду мають різні завдання.

Не потрібно змушувати їх використовувати однакові обмеження.

Краще визначити ширину відповідно до типу контенту.

### 8.6. Використання `ch` як точного лічильника символів

    .article {
      max-width: 65ch;
    }

Це не гарантує рівно 65 символів у кожному рядку. `ch` вимірює довжину в типографічній одиниці, а не підраховує символи тексту.

### 8.7. Налаштування ширини без перевірки реального тексту

Текст із короткими словами може виглядати інакше, ніж текст із довгими словами.

Так само український, англійський та інші тексти можуть по-різному переноситися в однаковому контейнері.

Тому потрібно перевіряти дизайн на реальному або репрезентативному контенті.

### 8.8. Надмірне використання медіазапитів

Не завжди потрібно встановлювати окрему ширину для смартфона, планшета й десктопа.

Якщо `width: 100%`, `max-width` і бокові відступи вже забезпечують комфортне відображення, додаткові правила можуть бути зайвими.

### Що тут важливо?

- `max-width: 65ch` обмежує ширину статті.
- `margin-inline: auto` центрує текстовий контейнер.
- `padding: 3rem 1rem` створює внутрішній простір.
- `max-width: 20ch` обмежує ширину заголовка.
- `clamp()` адаптує розмір заголовка до ширини viewport у заданих межах.
- `line-height` покращує вертикальний ритм тексту.
- `box-sizing: border-box` спрощує розрахунок розмірів елементів.

## 10. Практичний приклад: текст у картці

У картці текстова колонка обмежена розмірами самої картки. Тому для неї не завжди потрібно задавати окремий `max-width`.

        з DOM на практичних прикладах.
      </p>
      <a href="#">Перейти до уроку</a>
    </article>

    .card {
      width: 100%;
      max-width: 24rem;
      padding: 1.5rem;
      border-radius: 0.75rem;
      background-color: #fff;
      border: 1px solid #ddd;
    }

    .card h2 {
      margin-top: 0;
      line-height: 1.3;
    }

    .card p {
      line-height: 1.6;
    }

    .card a {
      display: inline-block;
      margin-top: 0.5rem;
    }

### Що потрібно врахувати?

- Ширина картки вже обмежує довжину рядків.
- Занадто вузька картка може ускладнювати читання.
- Довгий заголовок повинен переноситися без переповнення.
- Кілька карток в одному рядку мають зберігати комфортну ширину.
- На мобільних пристроях картки часто розташовуються в одну колонку.

## 11. Практичний приклад: адаптивна композиція статті

### HTML

    <main class="page">
      <article class="article">
        <h1>Основи вебдизайну</h1>
        <p>
          Вебдизайн поєднує візуальну композицію,
          типографіку, кольори та зручність використання.
        </p>
      </article>

      <aside class="sidebar">
        <h2>У цій темі</h2>
        <ul>
          <li>Типографіка</li>
          <li>Композиція</li>
          <li>Колір</li>
        </ul>
      </aside>
    </main>

### CSS

    .page {
      display: grid;
      grid-template-columns: minmax(0, 65ch) minmax(12rem, 18rem);
      justify-content: center;
      gap: 2rem;
      padding: 2rem 1rem;
    }

    .article {
      min-width: 0;
    }

    .sidebar {
      min-width: 0;
    }

    @media (max-width: 48rem) {
      .page {
        grid-template-columns: minmax(0, 1fr);
      }
    }

### Пояснення

- `grid-template-columns` створює колонку статті та колонку бічної панелі.
- `minmax(0, 65ch)` обмежує ширину статті та дозволяє колонці стискатися.
- `min-width: 0` допомагає запобігти переповненню Grid-елементів через довгий контент.
- Медіазапит переводить сторінку в одну колонку на вузьких екранах.
- `gap` створює простір між статтею та панеллю.

Це приклад композиції сторінки, а не універсальний шаблон для кожного інтерфейсу.

## 12. Readable Width і доступність

Оптимальна ширина допомагає читанню, але сама по собі не гарантує доступності.

Потрібно враховувати:

✔ Користувач може збільшувати масштаб сторінки.

✔ Текст повинен залишатися доступним при збільшенні розміру шрифту.

✔ Контент не повинен вимагати горизонтального прокручування всієї сторінки для звичайного читання.

✔ Заголовки повинні мати логічну структуру.

✔ Контраст тексту та фону має бути достатнім.

✔ Міжрядковий інтервал і відстані між абзацами повинні залишатися комфортними.

✔ Довгі URL, слова та фрагменти коду не повинні ламати макет.

Для довгих рядків без пробілів можна передбачити перенесення:

    .text-content {
      overflow-wrap: anywhere;
    }

Використовуй це правило обдумано: воно може переносити довгі послідовності в незвичних місцях.

Для блоків коду часто краще окремо налаштувати горизонтальне прокручування:

    pre {
      max-width: 100%;
      overflow-x: auto;
    }

Не потрібно приховувати переповнення без альтернативи, якщо через це користувач може втратити частину важливого контенту.

## 13. Практичні вправи

### Вправа 1. Порівняй три варіанти ширини

Створи три текстові блоки:

    .text-narrow {
      max-width: 35ch;
    }

    .text-medium {
      max-width: 65ch;
    }

    .text-wide {
      max-width: 100ch;
    }

Використай однаковий текст і порівняй:
- кількість рядків;
- довжину рядків;
- висоту текстового блоку;
- комфорт читання.

**Мета:** навчитися помічати вплив ширини на сприйняття тексту.

### Вправа 2. Створи сторінку статті

Створи HTML-сторінку з:
- заголовком;
- коротким вступом;
- трьома підзаголовками;
- кількома абзацами;
- списком;
- посиланням.

Застосуй:
- `max-width`;
- `margin-inline`;
- `padding-inline`;
- `line-height`;
- різні відступи між заголовками й абзацами.

Перевір сторінку на вузькому та широкому екранах.

### Вправа 3. Порівняй `px`, `%` і `ch`

Створи три варіанти:

    .text-px {
      max-width: 700px;
    }

    .text-percent {
      width: 80%;
    }

    .text-ch {
      max-width: 65ch;
    }

Порівняй їх за різних розмірів viewport.

Зверни увагу:
- піксельне обмеження задає ширину в CSS-пікселях;
- відсоток залежить від ширини containing block;
- `ch` пов'язаний із шириною символу `0` у поточному шрифті.

### Вправа 4. Перевір український та англійський текст

Розмісти в однаковому контейнері два тексти: український та англійський.

Порівняй:
- перенесення рядків;
- довжину слів;
- висоту абзаців;
- розташування заголовків.

**Мета:** зрозуміти, чому однакове значення ширини не створює абсолютно однаковий результат для різних текстів.

### Вправа 5. Перевір адаптивність

Перевір сторінку:
- на вузькому смартфоні;
- на широкому смартфоні;
- на планшеті;
- на ноутбуці;
- на великому моніторі.

На кожному розмірі перевір:
- чи не притиснутий текст до країв;
- чи не надто довгі рядки;
- чи не виникає горизонтальне прокручування сторінки;
- чи не створюють заголовки незручних переносів.

## 14. Що потрібно пам'ятати

- **Readable Width** — це комфортна ширина текстового блоку для читання.
- Для основного тексту можна починати з орієнтира близько `60–70ch`, а потім перевіряти результат.
- `ch` приблизно відповідає ширині символу `0` у поточному шрифті, а не точній кількості символів у рядку.
- `max-width` допомагає обмежувати ширину на великих екранах.
- `width: 100%` разом із `max-width` — поширений адаптивний підхід.
- `margin-inline: auto` центрує контейнер.
- `padding-inline` створює простір між текстом і краями контейнера.
- `line-height`, розмір шрифту, гарнітура та структура абзаців впливають на комфорт читання.
- Не всі типи контенту повинні мати однакову ширину.
- Заголовки можуть потребувати іншого обмеження ширини, ніж основний текст.
- Для коду та довгих рядків потрібно окремо продумувати поведінку переповнення.
- Перевіряй дизайн на реальному тексті та різних розмірах екрана.
- Оптимальна ширина — це дизайнерський орієнтир, а не одне магічне число.

## 15. Мінішпаргалка

| Завдання | CSS |
|---|---|
| Обмежити ширину тексту | `max-width: 65ch;` |
| Дозволити займати доступну ширину | `width: 100%;` |
| Центрувати контейнер | `margin-inline: auto;` |
| Додати бокові відступи | `padding-inline: 1rem;` |
| Враховувати padding у ширині | `box-sizing: border-box;` |
| Задати міжрядковий інтервал | `line-height: 1.7;` |
| Обмежити заголовок | `max-width: 20ch;` |
| Дозволити прокручування коду | `overflow-x: auto;` |
| Допомогти перенесенню довгих рядків | `overflow-wrap: anywhere;` |
| Створити центральну колонку Grid | `minmax(0, 65ch)` |

### Базовий шаблон

    .readable-content {
      width: 100%;
      max-width: 65ch;
      margin-inline: auto;
      padding-inline: 1rem;
      box-sizing: border-box;
      line-height: 1.7;
    }

Це хороший початковий шаблон для статей, навчальних матеріалів і сторінок документації.

## Висновок

**Readable Width — це контроль ширини тексту заради комфортного читання.**

У вебдизайні важливо не просто розмістити текст у доступному просторі, а підібрати ширину, яка допомагає читачеві природно переходити від рядка до рядка.

Починай із `max-width: 65ch`, додай `margin-inline: auto` та достатні бокові відступи. Потім перевір реальний текст, розмір шрифту, міжрядковий інтервал і поведінку на різних екранах.

Головне правило: **спочатку комфорт читання, потім декоративні рішення.**
