# 03. Font Size — Розмір шрифту в UI-дизайні

## 1. Що таке Font Size?

**Font Size (розмір шрифту)** — це характеристика типографіки, яка визначає, наскільки великим або малим відображається текст в інтерфейсі.

Розмір шрифту впливає на:
- ✔ Читабельність тексту.
- ✔ Візуальну ієрархію сторінки.
- ✔ Розподіл уваги користувача.
- ✔ Щільність інформації в інтерфейсі.
- ✔ Висоту компонентів і загальний layout.
- ✔ Доступність інтерфейсу для різних користувачів.
- ✔ Адаптивність дизайну на різних екранах.

У UI-дизайні розмір шрифту — це не просто вибір числа в пікселях. Це інструмент, який допомагає показати користувачеві, **що важливо, що другорядне і в якому порядку читати інформацію**.

Наприклад, у картці курсу:

    Основи JavaScript        ← заголовок: 24 px
    Практичний курс для початківців
                              ← підзаголовок: 16 px
    12 уроків · 4 години    ← допоміжна інформація: 14 px
    Детальніше              ← текст кнопки: 16 px

Завдяки різним розмірам користувач швидше розуміє структуру картки.

---

## 2. Навіщо потрібен Font Size?

Правильно підібрані розміри шрифтів допомагають створювати зрозумілі, послідовні та зручні інтерфейси.

Основні завдання:

- ✔ Виділяти заголовки серед основного тексту.
- ✔ Розділяти інформацію за рівнями важливості.
- ✔ Забезпечувати комфортне читання довгих текстів.
- ✔ Робити кнопки, форми й навігацію зрозумілими.
- ✔ Підтримувати єдину типографічну систему.
- ✔ Адаптувати текст до мобільних і великих екранів.
- ✔ Зменшувати когнітивне навантаження.
- ✔ Підтримувати доступність інтерфейсу.

**Головний принцип:** розмір шрифту має відповідати ролі тексту, умовам читання та потребам користувача.

---

## 3. Основні поняття

### 3.1. Font Size

Розмір шрифту, наприклад:

    font-size: 16px;

Властивість CSS `font-size` визначає розмір шрифту елемента.

### 3.2. Typography Scale

**Типографічна шкала** — це набір узгоджених розмірів, які використовуються в інтерфейсі.

Наприклад:

    12px — допоміжні підписи
    14px — метадані
    16px — основний текст
    20px — невеликий заголовок
    24px — заголовок секції
    32px — великий заголовок
    48px — головний заголовок сторінки

Це лише приклад, а не універсальний стандарт. Конкретні значення залежать від шрифту, типу продукту та дизайну.

### 3.3. Text Hierarchy

**Типографічна ієрархія** — це система візуального розрізнення тексту за важливістю.

Наприклад:

    H1 — 40px
    H2 — 32px
    H3 — 24px
    Body — 16px
    Caption — 12px

Чим важливіша роль тексту, тим помітніше він може виділятися. Але розмір — не єдиний спосіб створення ієрархії. Також використовують вагу шрифту, колір, інтервали та розташування.

### 3.4. Body Text

**Body Text** — основний текст сторінки: описи, статті, інструкції, повідомлення та інший контент для читання.

Для багатьох вебінтерфейсів 16 CSS px є хорошою початковою точкою для основного тексту.

### 3.5. Display Text

**Display Text** — великий акцентний текст, який використовується для головних заголовків, hero-секцій, рекламних повідомлень або ключових цифр.

Наприклад:

    Створюй власні проєкти
    Навчайся у власному темпі

Display-текст часто має більший розмір, але потребує уважного налаштування ширини рядка та міжрядкового інтервалу.

### 3.6. Responsive Font Size

**Адаптивний розмір шрифту** — це розмір, який змінюється залежно від доступного простору або налаштувань користувача.

Наприклад, заголовок може бути меншим на смартфоні та більшим на широкому екрані.

## 4. Одиниці вимірювання Font Size у CSS

У CSS можна задавати розмір шрифту різними одиницями.

### 4.1. `px` — пікселі CSS

Приклад:

    body {
      font-size: 16px;
    }

Особливості:
- ✔ Дає зрозуміле конкретне значення.
- ✔ Зручний для базового розміру та точних значень.
- ✔ Широко використовується в дизайні й CSS.
- ✔ Не залежить безпосередньо від розміру шрифту батьківського елемента.

Важливо: CSS-піксель не завжди відповідає одному фізичному пікселю екрана.

`px` не означає автоматично, що користувач не зможе збільшити текст. Сучасні браузери можуть масштабувати сторінку, а коректні налаштування дозволяють користувачам збільшувати текст.

### 4.2. `rem` — відносно кореневого розміру шрифту

`rem` визначається відносно `font-size` кореневого елемента документа, зазвичай `<html>`.

Приклад:

    html {
      font-size: 16px;
    }

    body {
      font-size: 1rem;
    }

    h1 {
      font-size: 2rem;
    }

За базового розміру 16 px:

    1rem   = 16px
    1.25rem = 20px
    1.5rem = 24px
    2rem   = 32px
    3rem   = 48px

Формула:

    розмір у px = значення rem × розмір шрифту кореневого елемента

Переваги:
- ✔ Спільна основа для типографічної системи.
- ✔ Розміри компонентів простіше узгоджувати.
- ✔ Зручніше підтримувати масштабування тексту.
- ✔ Зміна кореневого розміру впливає на всі значення в `rem`.

Увага: не потрібно примусово встановлювати `html { font-size: 16px; }`, якщо це не потрібно проєкту. За замовчуванням браузери зазвичай використовують 16 CSS px, а користувацькі налаштування можуть відрізнятися.

### 4.3. `em` — відносно розміру шрифту

`em` зазвичай обчислюється відносно розміру шрифту відповідного контексту. Для `font-size` дочірнього елемента це, як правило, розмір шрифту батьківського елемента.

Приклад:

    .card {
      font-size: 16px;
    }

    .card__title {
      font-size: 1.5em;
    }

Результат для заголовка:

    1.5 × 16px = 24px

Переваги:
- ✔ Корисний для компонентів, які мають масштабуватися разом із текстом.
- ✔ Підходить для відносних розмірів у локальному контексті.

Недоліки:
- ⚠️ Вкладені значення `em` можуть послідовно збільшуватися або зменшуватися.
- ⚠️ Для глобальної типографічної шкали `rem` часто передбачуваніший.

### 4.4. `%` — відсотки

Відсоткові значення можуть використовуватися для визначення розміру шрифту відносно успадкованого контексту.

Приклад:

    .description {
      font-size: 90%;
    }

Якщо батьківський розмір становить 16 px:

    90% від 16px = 14.4px

Відсотки корисні в окремих контекстах, але для системи типографічних розмірів зазвичай простіше використовувати `rem`.

### 4.5. `vw` — відносно ширини viewport

`vw` дорівнює одному відсотку ширини області перегляду браузера.

Приклад:

    h1 {
      font-size: 5vw;
    }

Якщо ширина viewport становить 1000 px:

    5vw = 50px

Недолік: розмір тексту може стати надто великим на широкому екрані або надто малим на вузькому.

Тому для адаптивної типографіки краще часто використовувати `clamp()`.

### 4.6. `clamp()` — обмежений адаптивний розмір

Функція `clamp()` дозволяє задати мінімальне, бажане та максимальне значення.

Синтаксис:

    clamp(мінімум, бажане значення, максимум)

Приклад:

    h1 {
      font-size: clamp(2rem, 4vw, 3.5rem);
    }

У цьому випадку:
- Мінімальний розмір — `2rem`.
- Бажаний розмір залежить від ширини viewport.
- Максимальний розмір — `3.5rem`.

Браузер обирає значення в заданих межах.

Переваги:
- ✔ Плавне масштабування без великої кількості медіазапитів.
- ✔ Контроль мінімального розміру.
- ✔ Контроль максимального розміру.
- ✔ Зручне рішення для заголовків і великих текстових елементів.

Важливо: значення `clamp()` потрібно перевіряти на реальних ширинах екрана, а не лише на одному макеті.

## 5. Типографічна шкала (Typography Scale)

Типографічна шкала визначає, які розміри тексту доступні в дизайн-системі.

Замість того щоб довільно задавати кожному елементу окремий розмір, дизайнер створює узгоджений набір значень.

### 5.1. Приклад базової шкали

| Роль | Розмір | Приклад використання |
|---|---:|---|
| Tiny | 12px | Допоміжні підписи |
| Small | 14px | Метадані, другорядний текст |
| Body | 16px | Основний текст |
| Body Large | 18px | Акцентний текст, вступ |
| Heading Small | 20px | Невеликий заголовок |
| Heading Medium | 24px | Заголовок картки або секції |
| Heading Large | 32px | Заголовок великого блоку |
| Display Small | 40px | Великий заголовок |
| Display Large | 48px | Головний заголовок сторінки |

Це стартовий приклад. У реальному проєкті деякі розміри можна прибрати, змінити або доповнити.

### 5.2. Навіщо потрібна шкала?

Без типографічної шкали в інтерфейсі можуть з'явитися випадкові значення:

    15px
    17px
    21px
    23px
    27px
    31px

Це не обов'язково помилка, але якщо кожне значення виникає без системи, інтерфейс важче підтримувати.

Узгоджена шкала допомагає:
- ✔ Зберігати візуальну послідовність.
- ✔ Прискорювати створення нових сторінок.
- ✔ Спрощувати зміни дизайн-системи.
- ✔ Зменшувати кількість довільних значень.
- ✔ Узгоджувати роботу дизайнера й розробника.

### 5.3. Модульна шкала (Modular Scale)

Модульна шкала — це підхід, за якого сусідні розміри утворюються множенням на певний коефіцієнт.

Наприклад, базове значення — 16 px, коефіцієнт — 1.25.

    16px × 1.25 = 20px
    20px × 1.25 = 25px
    25px × 1.25 = 31.25px
    31.25px × 1.25 ≈ 39px

Так можна отримати послідовність розмірів із помітною ієрархією.

Однак не потрібно використовувати математичну шкалу заради самої математики. Розміри мають добре виглядати в конкретному інтерфейсі та підходити до контенту.

### 5.4. Шкала на CSS-змінних

Приклад:

    :root {
      --font-size-xs: 0.75rem;
      --font-size-sm: 0.875rem;
      --font-size-md: 1rem;
      --font-size-lg: 1.125rem;
      --font-size-xl: 1.25rem;
      --font-size-2xl: 1.5rem;
      --font-size-3xl: 2rem;
      --font-size-4xl: 3rem;
    }

    body {
      font-size: var(--font-size-md);
    }

    h1 {
      font-size: var(--font-size-4xl);
    }

    h2 {
      font-size: var(--font-size-3xl);
    }

    .card__title {
      font-size: var(--font-size-xl);
    }

Перевага: змінюючи токени, можна послідовно оновлювати типографіку всього застосунку.

## 6. Розмір шрифту та візуальна ієрархія

Розмір шрифту допомагає користувачеві зрозуміти структуру сторінки.

### 6.1. Ієрархія заголовків

Приклад:

    H1: 40px
    H2: 32px
    H3: 24px
    H4: 20px
    Body: 16px
    Caption: 12px

Такий підхід може працювати для інформаційного сайту або навчальної платформи.

Проте важливо пам'ятати: HTML-рівень заголовка (`h1`, `h2`, `h3`) визначає структуру документа, а не лише візуальний розмір.

Наприклад:

    <h1 class="page-title">Курс JavaScript</h1>
    <h2 class="section-title">Що ви вивчите</h2>

CSS може задавати візуальний розмір незалежно від рівня заголовка.

### 6.2. Ієрархія в картці

Приклад:

    Назва курсу          — 24px
    Короткий опис        — 16px
    Рівень: початковий   — 14px
    Оновлено вчора       — 12px

Користувач спочатку помічає назву, потім опис, а далі — другорядні деталі.

### 6.3. Ієрархія в таблиці

Для таблиці важливо зберегти баланс між читабельністю та кількістю інформації.

Приклад:

    Заголовок таблиці    — 20px
    Назви стовпців       — 14px
    Основні дані         — 16px
    Допоміжні дані       — 14px

Не варто зменшувати текст усієї таблиці до дуже малого розміру лише для того, щоб помістити більше стовпців. Краще розглянути адаптивну структуру, горизонтальне прокручування або скорочення другорядних даних.

### 6.4. Розмір — не єдиний спосіб виділення

Для створення ієрархії також використовують:
- ✔ Font Weight — товщину шрифту.
- ✔ Color — колір тексту.
- ✔ Spacing — відступи навколо тексту.
- ✔ Line Height — міжрядковий інтервал.
- ✔ Alignment — вирівнювання.
- ✔ Position — розташування елемента.

Не потрібно робити весь важливий текст дуже великим. Часто достатньо змінити вагу, колір або простір навколо нього.

## 7. Розмір основного тексту (Body Text)

Основний текст зазвичай займає найбільшу частину текстового контенту інтерфейсу.

Приклади:
- Описи курсів.
- Статті та навчальні матеріали.
- Інструкції.
- Повідомлення про помилки.
- Тексти у формах.
- Пояснення в налаштуваннях.
- Опис товарів або послуг.

### 7.1. Початкові значення

Для багатьох вебінтерфейсів можна почати з таких значень:

    Body: 16px
    Secondary text: 14px
    Small labels: 12–14px

Ці значення не є обов'язковими правилами. Текст може потребувати більшого розміру залежно від шрифту, ширини колонки, мови, довжини контенту та аудиторії.

### 7.2. Довгий текст

Для статей і навчальних матеріалів важливі:
- ✔ Комфортний розмір шрифту.
- ✔ Достатній міжрядковий інтервал.
- ✔ Помірна ширина текстового блоку.
- ✔ Чіткий контраст із фоном.
- ✔ Виразні заголовки та підзаголовки.

Зменшення шрифту не повинно бути основним способом умістити більше тексту на екрані.

### 7.3. Розмір тексту у формах

Приклад:

    label {
      font-size: 0.875rem;
    }

    input {
      font-size: 1rem;
    }

    .help-text {
      font-size: 0.875rem;
    }

Пояснення до поля може бути меншим за основний текст, але воно має залишатися читабельним і достатньо контрастним.

Не слід використовувати надто дрібний текст для обов'язкових інструкцій, помилок або важливих попереджень.

---

## 8. Розмір заголовків (Heading Size)

Заголовки допомагають сканувати сторінку та швидко знаходити потрібні розділи.

### 8.1. Приклад для навчального застосунку

    H1: 40px — назва сторінки
    H2: 32px — основний розділ
    H3: 24px — підрозділ
    H4: 20px — невеликий блок

    Body: 16px — основний текст
    Caption: 14px — другорядні деталі

### 8.2. Заголовки на мобільних пристроях

Великий заголовок, який добре виглядає на десктопі, може займати надто багато місця на смартфоні.

Наприклад:

    h1 {
      font-size: clamp(2rem, 4vw, 3.5rem);
    }

Такий заголовок поступово змінює розмір залежно від ширини viewport, але не стає меншим за `2rem` і більшим за `3.5rem`.

Важливо перевіряти:
- ✔ Чи не переноситься заголовок на надмірну кількість рядків.
- ✔ Чи не перекриває він інші елементи.
- ✔ Чи залишається зрозумілим його зміст.
- ✔ Чи не витісняє він основний контент далеко вниз.
- ✔ Чи добре виглядає на проміжних ширинах екрана.

### 8.3. Не всі заголовки повинні мати різний розмір

Якщо кожен рівень відрізняється лише на 1–2 px, ієрархія може бути майже непомітною.

Якщо кожен заголовок надто великий, сторінка стає візуально шумною.

Мета — не максимальна різниця, а **зрозуміла ієрархія, яка відповідає структурі контенту**.

---

## 9. Розмір шрифту та Line Height

`font-size` визначає розмір шрифту, а `line-height` — висоту рядка тексту.

Ці властивості тісно пов'язані, але виконують різні завдання.

Приклад:

    .description {
      font-size: 16px;
      line-height: 1.5;
    }

У цьому випадку розмір шрифту — 16 px, а висота рядка становить приблизно:

    16px × 1.5 = 24px

Для основного тексту часто використовують відносний `line-height` у межах приблизно `1.4–1.7`, але конкретне значення залежить від гарнітури та дизайну.

Для великих заголовків може бути доречним менший коефіцієнт, наприклад `1.1–1.25`.

Це орієнтири, а не жорсткі правила.

Приклад:

    body {
      font-size: 1rem;
      line-height: 1.6;
    }

    h1 {
      font-size: 3rem;
      line-height: 1.15;
    }

    h2 {
      font-size: 2rem;
      line-height: 1.25;
    }

Важливо: збільшення `font-size` без перевірки `line-height` може зробити текст надто щільним або, навпаки, надмірно розрідженим.

---

## 10. Адаптивна типографіка (Responsive Typography)

Адаптивна типографіка допомагає зберігати зручність читання на різних розмірах екрана.

### 10.1. Фіксований розмір

    h1 {
      font-size: 48px;
    }

Цей варіант простий, але заголовок може виявитися завеликим на смартфоні.

### 10.2. Різні розміри через media queries

    h1 {
      font-size: 2rem;
    }

    @media (min-width: 768px) {
      h1 {
        font-size: 2.5rem;
      }
    }

    @media (min-width: 1200px) {
      h1 {
        font-size: 3rem;
      }
    }

Перевага — точний контроль на визначених ширинах.

Недолік — потрібно підтримувати більше правил.

### 10.3. Плавне масштабування через `clamp()`

    h1 {
      font-size: clamp(2rem, 4vw + 0.5rem, 3.5rem);
    }

Переваги:
- ✔ Плавна зміна розміру.
- ✔ Обмеження мінімуму й максимуму.
- ✔ Менше необхідних медіазапитів для окремого заголовка.

### 10.4. Адаптивність — це не лише зменшення шрифту

На смартфоні іноді потрібно:
- Змінити ширину текстового контейнера.
- Переглянути довжину заголовка.
- Збільшити відстань між елементами.
- Перебудувати компонування.
- Змінити розташування кнопок.
- Дозволити тексту займати більше рядків.

Не варто автоматично зменшувати всі розміри шрифту на мобільному пристрої. Основний текст має залишатися комфортним для читання.

---

## 11. Доступність і масштабування тексту

Доступна типографіка допомагає користувачам із різними можливостями зору, різними пристроями та індивідуальними налаштуваннями.

### 11.1. Не зменшуй текст без потреби

Надто дрібний текст важко читати, особливо:
- На смартфонах.
- За недостатнього освітлення.
- У формах із довгими інструкціями.
- У таблицях із великою кількістю даних.
- Користувачам, яким потрібне збільшення тексту.

Значення `12px` можна використовувати для окремих допоміжних елементів, але воно не повинно автоматично ставати розміром для всього другорядного контенту.

### 11.2. Відносні одиниці

Для текстової системи часто зручно використовувати `rem`.

Приклад:

    body {
      font-size: 1rem;
    }

    h1 {
      font-size: 2.5rem;
    }

    .caption {
      font-size: 0.875rem;
    }

Це допомагає підтримувати масштабування відповідно до розміру шрифту кореневого елемента.

### 11.3. Не блокуй масштабування сторінки

Не варто без вагомої причини вимикати масштабування через налаштування viewport для мобільних браузерів.

Користувач повинен мати можливість збільшувати контент, якщо йому це потрібно.

### 11.4. Перевірка збільшення тексту

Під час тестування перевіряй, чи:
- ✔ Текст не обрізається.
- ✔ Кнопки не перекривають одна одну.
- ✔ Форми залишаються придатними до використання.
- ✔ Заголовки не виходять за межі контейнерів.
- ✔ Важливі елементи не зникають.
- ✔ Контент не вимагає горизонтального прокручування в ситуаціях, де воно не потрібне.

Для вебконтенту корисно перевіряти вимоги WCAG щодо масштабування тексту, зокрема збільшення тексту до 200% без втрати контенту чи функціональності.

Окремі типи контенту, наприклад великі таблиці, можуть потребувати спеціальних рішень для збереження структури.

### 11.5. Доступність не зводиться до одного розміру

Сам по собі розмір `16px` не гарантує доступності.

Також важливі:
- Контраст тексту.
- Тип шрифту.
- Міжрядковий інтервал.
- Довжина рядка.
- Масштабування.
- Структура заголовків.
- Відстані між елементами.
- Можливість змінювати користувацькі налаштування.

## 12. Розмір шрифту в різних компонентах UI

Різні компоненти мають різні типографічні завдання.

### 12.1. Кнопки (Buttons)

Приклад:

    .button {
      font-size: 1rem;
    }

    .button--small {
      font-size: 0.875rem;
    }

    .button--large {
      font-size: 1.125rem;
    }

Розмір тексту має відповідати розміру кнопки та її ролі.

Не потрібно робити текст маленьким лише для того, щоб довгий напис помістився в кнопку. Краще переглянути ширину кнопки, текст або компонування.

### 12.2. Поля форм (Inputs)

    input {
      font-size: 1rem;
    }

    label {
      font-size: 0.875rem;
    }

    .error-message {
      font-size: 0.875rem;
    }

Текст помилки має бути достатньо помітним і читабельним. Не слід покладатися лише на маленький розмір або колір для передачі важливої інформації.

### 12.3. Навігація (Navigation)

    .nav-link {
      font-size: 1rem;
    }

    .breadcrumb {
      font-size: 0.875rem;
    }

Навігація повинна бути зручною для швидкого сканування, але не конкурувати з головним заголовком сторінки.

### 12.4. Картки (Cards)

    .card__title {
      font-size: 1.25rem;
    }

    .card__description {
      font-size: 1rem;
    }

    .card__meta {
      font-size: 0.875rem;
    }

Така система відокремлює назву картки від опису та метаданих.

### 12.5. Таблиці (Tables)

    .table__heading {
      font-size: 0.875rem;
    }

    .table__cell {
      font-size: 1rem;
    }

    .table__note {
      font-size: 0.875rem;
    }

Таблиці можуть містити багато інформації, але не варто робити основні дані надто дрібними заради компактності.

### 12.6. Dashboard та аналітичні панелі

    .metric__value {
      font-size: 2rem;
    }

    .metric__label {
      font-size: 0.875rem;
    }

    .metric__description {
      font-size: 0.875rem;
    }

Великі числа допомагають швидко знаходити ключові показники. Проте довгі числа, одиниці вимірювання та пояснення повинні залишатися зрозумілими.

## 13. Типографічні токени (Typography Tokens)

**Typography Tokens** — це стандартизовані значення, які використовуються в дизайн-системі.

Вони можуть визначати:
- Розмір шрифту.
- Вагу шрифту.
- Міжрядковий інтервал.
- Міжлітерний інтервал.
- Роль тексту в інтерфейсі.

Приклад CSS-токенів:

    :root {
      --text-xs: 0.75rem;
      --text-sm: 0.875rem;
      --text-base: 1rem;
      --text-lg: 1.125rem;
      --text-xl: 1.25rem;

      --heading-sm: 1.5rem;
      --heading-md: 2rem;
      --heading-lg: 3rem;
    }

Використання:

    .article {
      font-size: var(--text-base);
    }

    .article__intro {
      font-size: var(--text-lg);
    }

    .article__title {
      font-size: var(--heading-lg);
    }

Переваги:
- ✔ Єдині значення в усьому проєкті.
- ✔ Менше повторень у CSS.
- ✔ Зручні зміни дизайн-системи.
- ✔ Зрозуміла співпраця між дизайном і розробкою.

### 13.1. Токени за значенням і за роллю

Токени можуть описувати конкретний розмір:

    --text-sm: 0.875rem;
    --text-lg: 1.125rem;

Або роль елемента:

    --body-size: 1rem;
    --caption-size: 0.875rem;
    --page-title-size: 3rem;

У невеликому навчальному проєкті можна почати з простих токенів. У більшій дизайн-системі рольові токени допомагають змінювати оформлення без необхідності редагувати кожен компонент.

## 14. Практичний приклад: типографіка навчального застосунку

Припустимо, ми створюємо сторінку навчального застосунку з курсами.

### 14.1. CSS

    :root {
      --font-size-xs: 0.75rem;
      --font-size-sm: 0.875rem;
      --font-size-base: 1rem;
      --font-size-lg: 1.125rem;
      --font-size-xl: 1.25rem;
      --font-size-2xl: 1.5rem;
      --font-size-3xl: 2rem;

      --font-size-page-title: clamp(2rem, 4vw, 3rem);
    }

    body {
      font-size: var(--font-size-base);
      line-height: 1.6;
    }

    .page-title {
      font-size: var(--font-size-page-title);
      line-height: 1.15;
    }

    .section-title {
      font-size: var(--font-size-3xl);
      line-height: 1.25;
    }

    .course-card__title {
      font-size: var(--font-size-xl);
      line-height: 1.3;
    }

    .course-card__description {
      font-size: var(--font-size-base);
      line-height: 1.6;
    }

    .course-card__meta {
      font-size: var(--font-size-sm);
      line-height: 1.5;
    }

    .helper-text {
      font-size: var(--font-size-sm);
      line-height: 1.5;
    }

### 14.2. HTML

    <main>
      <h1 class="page-title">Мої курси</h1>

      <section aria-labelledby="courses-heading">

          <p class="course-card__meta">
            12 уроків · Початковий рівень
          </p>
        </article>
      </section>
    </main>

### 14.3. Що ми отримали?

- ✔ Головний заголовок виділяється найбільше.
- ✔ Заголовок секції має другий рівень важливості.
- ✔ Назва курсу помітніша за опис.
- ✔ Основний текст має комфортний базовий розмір.
- ✔ Метадані компактніші, але залишаються читабельними.
- ✔ Токени допомагають зберігати послідовність.
- ✔ Головний заголовок адаптується до ширини viewport.

## 15. Типові помилки у Font Size

### Помилка 1. Надто дрібний основний текст

Поганий приклад:

    body {
      font-size: 12px;
    }

Чому це проблема:
- Основний текст важче читати.
- Користувачеві може знадобитися збільшення.
- Довгі матеріали стають менш комфортними.

Краще як початковий варіант:

    body {
      font-size: 1rem;
      line-height: 1.6;
    }

Конкретний розмір слід перевіряти на реальному контенті та з урахуванням аудиторії.

### Помилка 2. Випадкові розміри

Поганий приклад:

    h1 {
      font-size: 37px;
    }

    h2 {
      font-size: 29px;
    }

    h3 {
      font-size: 23px;
    }

Ці значення не є неправильними самі по собі. Проблема виникає, якщо вони обрані випадково та не узгоджені з рештою інтерфейсу.

Рішення: створити типографічну шкалу або набір токенів.

### Помилка 3. Надто багато розмірів

Якщо кожен елемент має власне значення, типографіка стає непослідовною.

Рішення: визначити основні ролі та використовувати обмежений набір розмірів там, де це доречно.

### Помилка 4. Надто великий заголовок на смартфоні

Проблема:

    h1 {
      font-size: 64px;
    }

На вузькому екрані заголовок може займати надто багато місця.

Рішення:

    h1 {
      font-size: clamp(2rem, 4vw + 0.5rem, 4rem);
    }

Після цього потрібно перевірити переноси рядків, відступи та компонування.

### Помилка 5. Використання `vw` без обмежень

Проблемний приклад:

    h1 {
      font-size: 8vw;
    }

Розмір може бути надмірним на широких екранах або недостатнім на вузьких.

Рішення: розглянути `clamp()` з відповідними мінімальним і максимальним значеннями.

### Помилка 6. Занадто велика різниця між розмірами

Наприклад, основний текст — 14 px, а заголовок секції — 64 px.

Це може бути доречно для спеціального рекламного дизайну, але в типовому інтерфейсі створює надмірний контраст.

Рішення: оцінювати співвідношення розмірів у контексті всієї сторінки.

### Помилка 7. Надто мала різниця між заголовком і основним текстом

Якщо заголовок має 17 px, а основний текст — 16 px, і немає інших відмінностей, ієрархія може бути слабкою.

Рішення: використовувати розмір разом із вагою шрифту, інтервалами та розташуванням.

### Помилка 8. Виправлення всіх проблем лише через `font-size`

Текст може виглядати незручним не лише через розмір, а й через:
- Невдалий шрифт.
- Надто довгий рядок.
- Малий `line-height`.
- Недостатній контраст.
- Невдале компонування.
- Відсутність відступів.

Рішення: перевіряти типографіку як систему, а не як одну CSS-властивість.

### Помилка 9. Жорстко фіксувати висоту текстового контейнера

Приклад:

    .card__title {
      height: 24px;
      font-size: 20px;
      overflow: hidden;
    }

За довшого заголовка або збільшення тексту вміст може обрізатися.

Рішення: дозволяти контейнеру зростати, якщо це можливо, та використовувати `min-height` замість жорсткої висоти лише тоді, коли це відповідає дизайну.

### Помилка 10. Ігнорувати масштабування користувача

Якщо макет працює лише за одного розміру тексту, інтерфейс може втрачати читабельність після збільшення.

Рішення: тестувати сторінку зі збільшеним текстом і перевіряти, чи зберігаються контент та функціональність.

## 16. Як вибирати Font Size для нового інтерфейсу

Практична послідовність:

1. Визначити тип застосунку: навчальний, інформаційний, адміністративний, комерційний тощо.
2. Визначити основний тип контенту: короткі повідомлення, довгі статті, таблиці, форми.
3. Вибрати початковий розмір основного тексту.
4. Визначити ролі тексту: заголовки, основний текст, метадані, підписи.
5. Створити обмежену типографічну шкалу.
6. Узгодити розміри з `line-height` і шириною текстових блоків.
7. Визначити адаптивну поведінку великих заголовків.
8. Перевірити компоненти на мобільних і великих екранах.
9. Перевірити збільшення тексту.
10. Зафіксувати повторювані значення в CSS-токенах.

Не потрібно починати з десятків розмірів. Спочатку створи невелику послідовну систему, а потім додавай значення, якщо цього потребує реальний інтерфейс.

## 17. Мініпроєкт: Typography Scale

Мета — створити просту типографічну систему для сторінки навчального курсу.

### Завдання

Створи сторінку з такими елементами:
- Головний заголовок.
- Заголовок секції.
- Заголовок картки.
- Основний опис.
- Допоміжна інформація.
- Кнопка.
- Підпис до поля форми.

### Крок 1. Визнач розміри

Початковий варіант:

    Page title: 2.5rem
    Section title: 2rem
    Card title: 1.25rem
    Body: 1rem
    Secondary text: 0.875rem

### Крок 2. Створи токени

    :root {
      --text-sm: 0.875rem;
      --text-base: 1rem;
      --text-xl: 1.25rem;
      --heading-md: 2rem;
      --heading-lg: 2.5rem;
    }

### Крок 3. Використай токени

    body {
      font-size: var(--text-base);
      line-height: 1.6;
    }

    h1 {
      font-size: var(--heading-lg);
      line-height: 1.15;
    }

    h2 {
      font-size: var(--heading-md);
      line-height: 1.25;
    }

    .card__title {
      font-size: var(--text-xl);
    }

      font-size: var(--text-sm);

### Крок 4. Перевір адаптивність

Зроби заголовок адаптивним:

    h1 {
      font-size: clamp(2rem, 4vw, 2.5rem);
    }

Перевір сторінку на вузькому, середньому та широкому екранах.

### Крок 5. Перевір доступність

Переконайся, що:
- Основний текст комфортно читати.
- Допоміжний текст не надто дрібний.
- Заголовки не обрізаються.
- Користувач може збільшити текст.
- Елементи не перекриваються.
- Ієрархія зрозуміла навіть без уважного розглядання кожного елемента.

### Крок 6. Проведи рефакторинг

Якщо кілька компонентів використовують однакові значення, заміни повторення токенами.

Мета — не просто підібрати красиві числа, а створити систему, яку можна підтримувати в усьому застосунку.

## 19. Типові питання на співбесіді

### Що таке font-size?

Це CSS-властивість, яка задає розмір шрифту текстового вмісту елемента.

### Чим відрізняються `px`, `rem` та `em`?

- `px` — абсолютна одиниця CSS, яка не залежить безпосередньо від розміру шрифту батьківського елемента.
- `rem` — відносно розміру шрифту кореневого елемента.
- `em` — відносно розміру шрифту відповідного контексту; для `font-size` дочірнього елемента зазвичай відносно батьківського розміру.

### Що таке Typography Scale?

Це узгоджений набір розмірів шрифту, який використовується в інтерфейсі для підтримки послідовної ієрархії.

### Навіщо потрібна типографічна ієрархія?

Вона допомагає користувачеві швидко визначати важливість тексту та розуміти структуру сторінки.

### Що робить `clamp()`?

Дозволяє визначити мінімальне, бажане та максимальне значення. У типографіці це зручно для адаптивних заголовків.

### Чому не варто використовувати лише `vw` для розміру шрифту?

Тому що текст може стати надто великим або надто малим на різних екранах. `clamp()` допомагає обмежити його розмір.

### Чим відрізняються `font-size` і `line-height`?

`font-size` визначає розмір шрифту, а `line-height` — висоту рядка, яка впливає на вертикальний простір між рядками тексту.

### Який розмір використовувати для основного тексту?

16 CSS px, або `1rem` за типового кореневого розміру 16 px, — поширена початкова точка. Остаточне значення залежить від шрифту, контенту та аудиторії.

### Чому потрібно використовувати CSS-токени?

Вони дозволяють централізовано зберігати повторювані значення та послідовно підтримувати типографіку в усьому застосунку.

### Як перевірити доступність розміру шрифту?

Перевірити читабельність, контраст, збільшення тексту, перенесення рядків і те, чи не зникає контент або функціональність після масштабування.

## 20. Рівні володіння темою

### Core — базовий рівень

- Розуміти призначення `font-size`.
- Знати одиниці `px`, `rem` та `em`.
- Визначати основний текст і заголовки.
- Розуміти принцип типографічної ієрархії.
- Вибирати початкові розміри для UI-компонентів.

### Junior — практичний рівень

- Створювати типографічну шкалу.
- Використовувати CSS-змінні для розмірів.
- Узгоджувати `font-size` і `line-height`.
- Застосовувати `clamp()` для адаптивних заголовків.
- Перевіряти типографіку на різних ширинах екрана.
- Не допускати обрізання тексту в компонентах.

### Middle — системний рівень

- Проєктувати типографічні токени для дизайн-системи.
- Враховувати різні типи контенту й компонентів.
- Узгоджувати типографіку з responsive layout.
- Перевіряти масштабування тексту та доступність.
- Визначати, де потрібні глобальні, а де рольові токени.
- Підтримувати узгодженість між різними сторінками застосунку.

### Senior — стратегічний рівень

- Проєктувати масштабовану типографічну систему для великого продукту.
- Враховувати локалізацію, довжину текстів і різні системи письма.
- Балансувати читабельність, інформаційну щільність та візуальну ієрархію.
- Визначати принципи адаптивної типографіки для дизайн-системи.
- Організовувати перевірки доступності та якості текстового інтерфейсу.
- Забезпечувати узгодженість дизайнерських токенів і реалізації в коді.

|---|---|

| Допоміжний текст | `font-size: 0.875rem;` |
| Заголовок секції | `font-size: 2rem;` |
| Великий заголовок | `font-size: 3rem;` |
| Відносний розмір від кореня | `font-size: 1.5rem;` |
| Відносний розмір від контексту | `font-size: 1.25em;` |
| Адаптивний заголовок | `font-size: clamp(2rem, 4vw, 3.5rem);` |
| Основний текст із комфортним інтервалом | `font-size: 1rem; line-height: 1.6;` |
| Токен для основного тексту | `font-size: var(--text-base);` |

## 22. Підсумок

**Font Size — це інструмент створення візуальної ієрархії, читабельності та послідовності інтерфейсу.**

Для якісної типографіки важливо:

1. Починати з комфортного розміру основного тексту.
2. Створювати узгоджену типографічну шкалу.
3. Використовувати `rem` для зручного керування системними розмірами.
4. Застосовувати `clamp()` там, де потрібне плавне адаптивне масштабування.
5. Узгоджувати розмір шрифту з міжрядковим інтервалом.
6. Використовувати CSS-токени для повторюваних значень.
7. Перевіряти текст на різних екранах і за збільшення.
8. Не жертвувати читабельністю заради компактності.

**Головне правило:** не підбирай розміри шрифтів ізольовано. Створюй типографічну систему, у якій кожен розмір має зрозумілу роль і працює разом з іншими елементами інтерфейсу.
