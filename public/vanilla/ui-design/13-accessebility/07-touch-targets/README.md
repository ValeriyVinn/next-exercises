# 07. Touch Targets — Розміри інтерактивних елементів

Touch targets — це області інтерфейсу, яких користувач торкається пальцем на сенсорному екрані або активує іншим способом введення.

До них належать:
- кнопки;
- посилання;
- іконки з діями;
- чекбокси та радіокнопки;
- елементи навігації;
- кнопки закриття модальних вікон;
- елементи керування слайдерами;
- кнопки збільшення та зменшення кількості товару.

Правильний розмір інтерактивних елементів особливо важливий для мобільних пристроїв, але він також покращує зручність інтерфейсу на комп'ютерах.

Мета — зробити так, щоб користувач міг легко активувати потрібний елемент, не натискаючи випадково на сусідній.

---

## 1. Основні принципи Touch Targets

✔ Інтерактивні елементи мають достатню область натискання.

✔ Кнопки та посилання не розташовані надто близько одне до одного.

✔ Маленькі іконки мають достатню область взаємодії.

✔ Візуальний розмір і фактична область натискання не обов'язково однакові.

✔ Відстань між сусідніми елементами зменшує ризик помилкового натискання.

✔ Інтерактивні елементи мають зрозумілий візуальний стан.

✔ Користувач може активувати елементи за допомогою клавіатури.

✔ Розмір елементів перевіряється на реальних пристроях і в різних масштабах.

**Головний принцип:** інтерактивний елемент повинен бути не лише помітним, а й зручним для точного натискання.

---

## 2. Що таке Touch Target?

Touch target — це область, у межах якої користувач може активувати певну дію.

Наприклад, кнопка з іконкою може мати видимий розмір лише 20 × 20 CSS-пікселів, але її область натискання може становити 44 × 44 CSS-пікселі.

    ┌──────────────────────┐
    │                      │
    │       ┌────┐         │
    │       │  × │         │
    │       └────┘         │
    │                      │
    └──────────────────────┘

    Зовнішня область — зона натискання.
    Внутрішня область — видима іконка.

Користувачеві не потрібно точно потрапляти пальцем у маленьке зображення. Достатньо торкнутися будь-якої точки інтерактивної області.

### 2.1. Візуальний розмір і область натискання

Ці поняття не слід плутати.

| Поняття | Що означає |
|---|---|
| Visual size | Видимий розмір кнопки або іконки |
| Touch target | Область, у межах якої можна активувати дію |
| Spacing | Відстань між сусідніми елементами |
| Hit area | Область, яку браузер або застосунок вважає активною для взаємодії |

Наприклад, маленька іконка може залишатися візуально компактною, але мати більшу область натискання завдяки `padding`.

---

## 3. Мінімальні розміри: WCAG 2.2

WCAG 2.2 містить критерій 2.5.8 — Target Size (Minimum), рівень AA.

Для відповідних інтерактивних цілей критерій встановлює мінімальний розмір **24 × 24 CSS-пікселі** або допускає виконання однієї з передбачених умов-виключень.

Водночас у практичному дизайні для мобільних інтерфейсів часто використовують більші цілі, наприклад 44 × 44 або 48 × 48 CSS-пікселів.

Це не суперечність: мінімальна нормативна вимога та рекомендований комфортний розмір — різні речі.

### 3.1. Розміри, які варто знати

| Розмір | Як використовувати |
|---|---|
| 24 × 24 CSS px | Мінімальний розмір за WCAG 2.2, критерій 2.5.8, для відповідних цілей з урахуванням винятків |
| 24 × 24 CSS px | Розмір, який також може відповідати критерію за умови достатньої відстані до інших цілей |
| 32 × 32 CSS px | Проміжний розмір для компактних контролів |
| 44 × 44 CSS px | Поширений практичний орієнтир для зручного натискання |
| 48 × 48 CSS px | Зручний орієнтир для багатьох мобільних інтерфейсів |

**Важливо:** WCAG 2.2, критерій 2.5.8, не вимагає робити абсолютно кожен елемент розміром 44 × 44 px. Він установлює мінімальні умови та містить винятки. Рекомендації 44–48 px — це практичні орієнтири для підвищення зручності.

CSS-піксель не обов'язково дорівнює одному фізичному пікселю дисплея.

---

## 4. Чому маленькі Touch Targets створюють проблеми

Надто маленькі інтерактивні елементи можуть спричиняти:

- випадкові натискання на сусідні кнопки;
- труднощі для людей із порушеннями моторики;
- незручність користування однією рукою;
- помилки під час введення на мобільних пристроях;
- складнощі з маленькими іконками;
- проблеми при збільшенні інтерфейсу;
- повільнішу взаємодію;
- розчарування під час використання форми або меню.

Наприклад, якщо кнопки «Збільшити» та «Зменшити» розташовані поруч і мають дуже маленькі області натискання, користувач може випадково змінити кількість товару в неправильний бік.

Проблема особливо помітна в інтерфейсах:
- інтернет-магазинів;
- банківських застосунків;
- медичних сервісів;
- освітніх платформ;
- форм реєстрації;
- мобільної навігації;
- інтерфейсів для людей старшого віку.

## 5. Розмір кнопок

Кнопки повинні мати достатню висоту та ширину для зручної взаємодії.

Приклад CSS:

    .button {
      min-height: 44px;
      padding: 12px 20px;
      border: 0;
      border-radius: 8px;
      font: inherit;
      cursor: pointer;
    }

Тут:
- `min-height: 44px` забезпечує мінімальну висоту;
- `padding` створює простір навколо тексту;
- `font: inherit` допомагає зберігати узгоджену типографіку;
- `cursor: pointer` змінює вигляд курсора миші.

`cursor: pointer` сам по собі не робить елемент доступним для клавіатури. Для інтерактивних дій використовуй семантичний `<button>` або `<a>` відповідно до призначення.

### 5.1. Кнопки з коротким текстом

Кнопка з коротким текстом може мати достатню висоту, але замалу ширину.

    .icon-button {
      width: 44px;
      height: 44px;
      display: inline-grid;
      place-items: center;
    }

Це зручний варіант для кнопок з іконками.

### 5.2. Кнопки з довгим текстом

Не варто жорстко задавати ширину всім кнопкам, якщо текст може змінюватися через переклад або масштабування.

    .button {
      min-height: 44px;
      padding: 12px 20px;
      max-width: 100%;
      white-space: normal;
    }

Для довгих написів дозволь кнопці збільшуватися або переносити текст, якщо це не руйнує дизайн.

### 5.3. Primary і secondary buttons

Основна кнопка може бути візуально помітнішою, але це не означає, що другорядні кнопки можуть мати незручну область натискання.

Приклад:

    .button-primary,
    .button-secondary {
      min-height: 44px;
      padding: 12px 18px;
      font: inherit;
    }

    .button-primary {
      font-weight: 600;
    }

    .button-secondary {
      border: 1px solid currentColor;
    }

Усі інтерактивні елементи повинні залишатися зручними незалежно від їхньої візуальної ієрархії.

---

## 6. Маленькі іконки та кнопки

Іконки часто мають невеликий видимий розмір, але виконують важливі дії.

Приклади:
- пошук;
- закриття модального вікна;
- відкриття меню;
- видалення елемента;
- редагування;
- перемикання видимості пароля;
- додавання або видалення товару.

Не потрібно збільшувати саму іконку до 44 px. Можна збільшити область кнопки навколо неї.

Приклад HTML:

    <button
      class="icon-button"
      type="button"
      aria-label="Закрити вікно"
    >
      <svg
        aria-hidden="true"
        width="20"
        height="20"
        viewBox="0 0 24 24"
      >
        <path
          d="M6 6 L18 18 M18 6 L6 18"
          fill="none"
          stroke="currentColor"
          stroke-width="2"
        />
      </svg>
    </button>

Приклад CSS:

    .icon-button {
      width: 44px;
      height: 44px;
      display: inline-grid;
      place-items: center;
      padding: 0;
      border: 0;
      border-radius: 8px;
      background: transparent;
      cursor: pointer;
    }

У цьому прикладі:
- кнопка має область 44 × 44 px;
- SVG має розмір 20 × 20 px;
- `aria-label` дає кнопці доступну назву;
- `aria-hidden="true"` приховує декоративну SVG-іконку від допоміжних технологій.

Якщо іконка декоративна й кнопка вже має видимий текст, додатковий `aria-label` зазвичай не потрібен.

---

## 7. Відстань між інтерактивними елементами

Розмір кожної кнопки важливий, але не менш важлива відстань між сусідніми кнопками.

Навіть відносно великі елементи можуть бути незручними, якщо вони розташовані надто близько один до одного.

Приклад:

    .button-group {
      display: flex;
      flex-wrap: wrap;
      gap: 12px;
    }

`gap` створює відстань між елементами.

### 7.1. Чому потрібен простір

Уявімо дві кнопки:

    ┌────────────┐┌────────────┐
    │  Скасувати ││  Видалити  │
    └────────────┘└────────────┘

Якщо вони розташовані впритул, користувач може випадково активувати неправильну дію.

Краще:

    ┌────────────┐   ┌────────────┐
    │  Скасувати │   │  Видалити  │
    └────────────┘   └────────────┘

Відстань між елементами допомагає розрізняти їхні області натискання.

### 7.2. Не покладайся лише на gap

`gap` — це візуальний проміжок між елементами. Він не збільшує автоматично область натискання кожної кнопки.

Для надійного результату потрібно враховувати:
- розмір самих елементів;
- відстань між ними;
- фактичну область активації;
- можливі перекриття;
- поведінку елементів у різних станах.

## 8. WCAG 2.2: Target Size (Minimum)

Критерій 2.5.8 Target Size (Minimum) належить до рівня AA WCAG 2.2.

Загальна вимога: ціль для вказівного пристрою має бути не меншою за 24 × 24 CSS-пікселі або відповідати умовам одного з винятків.

### 8.1. Основні винятки

Критерій передбачає кілька ситуацій, коли вимога до розміру може не застосовуватися.

1. **Spacing exception — виняток за відстанню.** Якщо маленькі цілі розташовані так, що коло діаметром 24 CSS-пікселі, центроване на обмежувальній рамці цілі, не перетинається з іншими цілями або відповідними такими колами інших маленьких цілей, вимога може виконуватися через достатню відстань.

2. **Equivalent — еквівалентна ціль.** Та сама дія доступна через інший елемент на цій самій сторінці, який відповідає вимозі.

3. **Inline — вбудована ціль.** Розмір визначається рядком тексту або висотою рядка для вбудованого тексту, наприклад звичайне текстове посилання в абзаці.

4. **User Agent Control — контроль браузера.** Розмір цілі визначає браузер, а не автор сторінки, і автор не може його змінити.

5. **Essential — істотність.** Конкретне подання цілі є істотним для інформації або функціональності, наприклад у певних ситуаціях із відображенням точок на карті.

Не потрібно автоматично вважати всі текстові посилання або всі маленькі іконки винятками. Потрібно перевіряти точні умови критерію.

### 8.2. Критерій 2.5.5 Target Size (Enhanced)

WCAG 2.2 також містить критерій 2.5.5 Target Size (Enhanced) рівня AAA, який установлює суворішу вимогу — 44 × 44 CSS-пікселі для відповідних цілей, з передбаченими критерієм винятками.

Це корисний орієнтир для проєктів, які прагнуть вищого рівня доступності.

**Запам'ятай:**
- 24 × 24 px — мінімум критерію WCAG 2.2 AA для відповідних цілей, з урахуванням винятків;
- 44 × 44 px — розмір критерію AAA 2.5.5 для відповідних цілей, також з винятками;
- 44–48 px — практичний орієнтир для багатьох мобільних контролів.

## 9. CSS: способи збільшення області натискання

Існує кілька підходів до створення достатньої області натискання.

### 9.1. Через width і height

Підходить для кнопок з іконками та компактних контролів.

    .icon-button {
      width: 44px;
      height: 44px;
      display: grid;
      place-items: center;
    }

Перевага: розмір області легко перевірити.

Недолік: для кнопок із текстом фіксовані розміри можуть бути незручними, якщо напис довгий.

### 9.2. Через min-width і min-height

    .button {
      min-width: 44px;
      min-height: 44px;
      padding: 10px 16px;
    }

Перевага: кнопка може збільшуватися, коли цього потребує текст.

Це часто зручніше для адаптивного інтерфейсу.

### 9.3. Через padding

    .small-icon-button {
      padding: 12px;
      border: 0;
      background: transparent;
    }

`padding` збільшує область елемента, якщо застосовується безпосередньо до інтерактивної кнопки.

Однак підсумковий розмір залежить від розміру вмісту, рамки, `box-sizing` та інших CSS-властивостей. Перевіряй фактичні розміри у браузері.

### 9.4. Через псевдоелемент

Іноді можна розширити область натискання за допомогою `::before` або `::after`.

    .icon-button {
      position: relative;
      width: 24px;
      height: 24px;
    }

    .icon-button::before {
      content: "";
      position: absolute;
      inset: -10px;
    }

Цей підхід може бути корисним для компактних інтерфейсів, але його потрібно використовувати обережно.

Потенційні проблеми:
- розширені області можуть перекривати сусідні елементи;
- складніше передбачити, яка дія спрацює;
- візуальні межі та реальна зона взаємодії можуть не збігатися;
- псевдоелемент не створює самостійного доступного елемента.

Зазвичай краще збільшити саму кнопку через `padding`, `width`, `height` або мінімальні розміри.

## 10. Touch Targets у мобільній навігації

Мобільне меню часто містить багато елементів:
- посилання на сторінки;
- кнопки розгортання підменю;
- кнопку відкриття меню;
- кнопку закриття меню;
- елементи облікового запису.

Приклад:

    .mobile-nav a,
    .mobile-nav button {
      display: flex;
      align-items: center;
      min-height: 48px;
      padding: 12px 16px;
    }

Це робить рядки навігації зручнішими для натискання.

Для вертикального списку також можна задати проміжки:

    .mobile-nav {
      display: flex;
      flex-direction: column;
      gap: 4px;
    }

Не потрібно обов'язково додавати великий `gap`, якщо кожен пункт уже має достатню висоту та чіткі межі. Головне — уникнути випадкового активування сусідніх елементів.

### 10.1. Кнопка відкриття меню

    <button
      class="menu-toggle"
      type="button"
      aria-label="Відкрити меню"
      aria-expanded="false"
      aria-controls="main-menu"
    >
      <svg aria-hidden="true" viewBox="0 0 24 24">
        <!-- SVG-іконка меню -->
      </svg>
    </button>

    <nav id="main-menu" class="mobile-nav">
      <!-- Посилання навігації -->
    </nav>

Приклад показує базові атрибути, але справжній компонент повинен оновлювати `aria-expanded` і видимість меню відповідно до поточного стану.

Не забудь про доступну назву кнопки та видимий фокус клавіатури.

---

## 11. Touch Targets у формах

Поля введення, чекбокси та радіокнопки мають бути зручними для натискання.

### 11.1. Поля введення

    input,
    select,
    textarea {
      max-width: 100%;
      font: inherit;
    }

    input,
    select {
      min-height: 44px;
      padding: 10px 12px;
    }

Для текстових полів висота близько 44 px часто забезпечує зручне введення на мобільному пристрої.

Не забувай, що доступність поля також залежить від назви, інструкцій, контрасту та видимого фокуса.

### 11.2. Checkbox із великою областю натискання

    <label class="checkbox-label">
      <input type="checkbox" name="terms" required />
      <span>Я погоджуюся з умовами використання</span>
    </label>

    .checkbox-label {
      display: flex;
      align-items: flex-start;
      gap: 12px;
      padding: 8px 0;
      cursor: pointer;
    }

Завдяки `label` користувач може активувати checkbox, натискаючи не лише на маленький квадрат, а й на відповідний текст.

Водночас не потрібно примусово розтягувати всю область на кілька рядків, якщо це може призвести до неоднозначності. Область взаємодії повинна відповідати зрозумілому елементу.

### 11.3. Radio buttons

    .radio-option {
      display: flex;
      align-items: center;
      gap: 12px;
      min-height: 44px;
      cursor: pointer;
    }

Великі області натискання допомагають зменшити кількість помилок під час вибору варіантів.

---

## 12. Touch Targets у картках і списках

У картках можуть бути різні інтерактивні елементи:
- посилання на деталі;
- кнопка додавання в обране;
- кнопка купівлі;
- кнопка відкриття меню;
- кнопка видалення.

Не роби всі елементи картки однією великою клікабельною областю, якщо всередині є незалежні дії.

Наприклад, у картці товару посилання на опис і кнопка «Додати в кошик» повинні залишатися окремими елементами.

Приклад:

    .product-card__actions {
      display: flex;
      flex-wrap: wrap;
      gap: 12px;
    }

    .product-card__actions button,
    .product-card__actions a {
      min-height: 44px;
      padding: 10px 16px;
    }

Перевір, щоб:
- області не перекривалися;
- кнопка не була вкладена в іншу кнопку;
- посилання не містило незалежних інтерактивних елементів;
- порядок фокуса відповідав логіці картки.

---

## 13. Touch Targets і типографіка

Розмір тексту та область натискання — різні характеристики.

Маленький текст може бути розташований у великій кнопці, а великий текст — у занадто низькому елементі.

Тому потрібно окремо перевіряти:
- розмір шрифту;
- висоту рядка;
- контраст;
- ширину та висоту інтерактивної області;
- відстань між сусідніми елементами;
- поведінку тексту при масштабуванні.

Приклад:

    .action-link {
      display: inline-flex;
      align-items: center;
      min-height: 44px;
      padding: 8px 12px;
      font-size: 1rem;
      line-height: 1.5;
    }

Посилання залишається текстовим за змістом, але отримує більшу область взаємодії.

Для звичайних текстових посилань у реченнях не потрібно механічно збільшувати кожну ціль до 44 × 44 px. Враховуй контекст і відповідні вимоги WCAG.

---

## 14. Touch Targets у модальних вікнах

У модальних вікнах часто є кнопка закриття, кнопки підтвердження та скасування.

Приклад:

    .modal__close {
      width: 44px;
      height: 44px;
      display: grid;
      place-items: center;
    }

    .modal__actions {
      display: flex;
      flex-wrap: wrap;
      gap: 12px;
    }

    .modal__actions button {
      min-height: 44px;
      padding: 10px 16px;
    }

Кнопка закриття може бути компактною візуально, але мати достатню область натискання.

Перевір також:
- чи кнопка не перекриває заголовок;
- чи вона не розташована надто близько до інших дій;
- чи зрозуміло, що станеться після її натискання;
- чи працює клавіатурна навігація;
- чи фокус залишається в модальному вікні, поки воно відкрите;
- чи після закриття фокус повертається до елемента, який відкрив вікно.

Достатній розмір кнопки не замінює загальну доступність модального вікна.

---

## 15. Touch Targets і дизайн-системи

У дизайн-системі варто встановити узгоджені правила для інтерактивних елементів.

Наприклад:

    :root {
      --target-size-minimum: 24px;
      --target-size-comfortable: 44px;
      --target-size-mobile: 48px;

      --control-gap: 8px;
      --control-gap-comfortable: 12px;
    }

Ці змінні — внутрішні дизайн-токени проєкту, а не офіційні назви або значення стандарту WCAG.

Їх можна застосовувати в компонентах:

    .icon-button {
      min-width: var(--target-size-comfortable);
      min-height: var(--target-size-comfortable);
    }

    .mobile-action {
      min-height: var(--target-size-mobile);
    }

Переваги:
- узгоджені розміри компонентів;
- менше дублювання CSS;
- простіше масштабувати інтерфейс;
- легше проводити аудит;
- простіше змінювати загальні правила.

Не встановлюй `24px` як універсальну висоту для всіх кнопок лише тому, що це мінімальний розмір критерію WCAG 2.2 AA.

---

## 16. Адаптивний дизайн і Touch Targets

Інтерактивні елементи повинні залишатися зручними на різних ширинах екрана.

Приклад:

    .toolbar {
      display: flex;
      align-items: center;
      flex-wrap: wrap;
      gap: 12px;
    }

    .toolbar button {
      min-height: 44px;
      padding: 10px 16px;
    }

На вузьких екранах можна:
- переносити елементи на новий рядок;
- змінювати компонування;
- розташовувати основні дії вертикально;
- збільшувати ширину кнопок;
- відокремлювати небезпечні дії;
- залишати достатній простір між елементами.

Не варто зменшувати кнопки лише для того, щоб усі вони помістилися в один рядок.

### 16.1. Кнопки на всю ширину

Для мобільних форм іноді зручно розтягувати основну кнопку на ширину контейнера.

    .submit-button {
      width: 100%;
      min-height: 48px;
      padding: 12px 16px;
    }

Це особливо корисно для основних дій у формах реєстрації, оформлення замовлення та підтвердження.

Проте не кожна кнопка повинна бути на всю ширину. Обирай компонування відповідно до контексту.

---

## 17. Touch Targets і небезпечні дії

Дії на кшталт видалення, скасування замовлення або очищення даних потребують особливої уваги.

Рекомендації:
- не розміщуй небезпечну дію впритул до основної;
- використовуй зрозумілі назви кнопок;
- забезпечуй достатні області натискання;
- не покладайся лише на червоний колір;
- за потреби проси підтвердження;
- надавай можливість скасувати дію, якщо це можливо;
- не використовуй маленьку іконку без доступної назви для критичної операції.

Приклад:

    .danger-actions {
      display: flex;
      flex-wrap: wrap;
      gap: 16px;
    }

    .danger-actions button {
      min-height: 44px;
      padding: 12px 16px;
    }

Важливо не лише зменшити ризик випадкового натискання, а й зробити наслідки дії зрозумілими.

---

## 18. Touch Targets і доступність клавіатури

Touch Targets не стосуються лише сенсорних екранів.

Інтерактивні елементи також повинні бути зручними для:
- користувачів клавіатури;
- користувачів скринрідерів;
- людей, які використовують голосове керування;
- людей із різними способами введення.

Для кнопок використовуй `<button>`, для навігації — `<a>`.

Не створюй інтерактивний елемент лише за допомогою `div` із `onClick`, якщо стандартний HTML-елемент підходить краще.

❌ Невдалий варіант:

    <div onclick="saveChanges()">
      Зберегти
    </div>

✔ Краще:

    <button type="button" onclick="saveChanges()">
      Зберегти
    </button>

У реальному застосунку обробник може бути написаний у JavaScript або React.

Переконайся, що:
- кнопка доступна через `Tab`;
- її фокус помітний;
- вона активується стандартними клавішами;
- назва зрозуміла;
- стан кнопки доступний допоміжним технологіям.

---

## 19. Touch Targets і голосове керування

Користувачі голосового керування можуть активувати елементи за їхніми назвами або видимими підписами.

Тому:
- використовуй зрозумілі назви кнопок;
- не створюй багато елементів з однаковим текстом «Детальніше» без контексту;
- уникай неоднозначних назв;
- забезпечуй відповідність доступної назви видимому тексту;
- не покладайся лише на іконки.

Наприклад, якщо кнопка візуально має текст «Надіслати», не варто задавати їй доступну назву «Відкрити меню».

Доступна назва повинна відповідати видимому призначенню елемента.

Велика область натискання сама по собі не гарантує зручності голосового керування, але є частиною загальної якості інтерактивного компонента.

---

## 20. Як перевірити фактичний розмір Touch Target

У браузері можна використовувати DevTools.

Порядок перевірки:
1. Відкрий сторінку.
2. Відкрий інструменти розробника.
3. Вибери потрібний інтерактивний елемент.
4. Перевір його розміри в CSS.
5. Перевір `padding`, `border`, `width`, `height` і `box-sizing`.
6. Перевір, чи немає перекриття сусідніми елементами.
7. Перевір область натискання за допомогою реальної взаємодії.
8. Повтори перевірку на вузькому екрані.

За допомогою JavaScript можна виміряти прямокутник елемента:

    const button = document.querySelector(".icon-button");

    if (button) {
      const rect = button.getBoundingClientRect();

      console.log({
        width: rect.width,
        height: rect.height,
      });
    }

`getBoundingClientRect()` повертає розміри елемента в CSS-пікселях у поточному відображенні.

Але самі розміри прямокутника не доводять повну відповідність WCAG. Потрібно також врахувати відстань до інших цілей, перекриття, винятки критерію та фактичну поведінку компонента.

---

## 21. Тестування на реальних пристроях

Перевірка лише на комп'ютері не завжди достатня.

На реальному телефоні перевір:
- чи зручно натискати кнопки великим пальцем;
- чи легко натискати маленькі іконки;
- чи не активуються сусідні елементи;
- чи зручні поля форм;
- чи можна користуватися інтерфейсом однією рукою;
- чи працюють кнопки в портретній та альбомній орієнтаціях;
- чи не виникають проблеми після збільшення тексту;
- чи достатньо простору в навігації;
- чи немає перекриття інтерактивних елементів.

Також перевір:
- планшети;
- вузькі вікна браузера;
- масштабування сторінки;
- різні браузери;
- клавіатурну навігацію;
- голосове керування, якщо воно важливе для цільової аудиторії.

Не покладайся лише на емулятор мобільного пристрою. Він корисний для початкової перевірки, але не повністю відтворює фізичне використання сенсорного екрана.

---

## 22. Типові помилки

### Помилка 1. Маленька іконка без додаткової області

Проблема: користувачеві складно точно натиснути на іконку.

Виправлення: збільшити інтерактивний контейнер через `padding`, `min-width`, `min-height` або явні розміри.

### Помилка 2. Кнопки розташовані впритул

Проблема: користувач може активувати не ту дію.

Виправлення: збільшити відстань між елементами й перевірити їхні реальні області взаємодії.

### Помилка 3. Однаковий розмір для всіх компонентів

Проблема: різні типи контролів мають різні потреби.

Виправлення: визначити правила для кнопок, полів, іконок, навігації та компактних компонентів.

### Помилка 4. Фіксована ширина кнопки

Проблема: довший текст або інша мова може не поміститися.

Виправлення: використовувати `min-width`, `min-height`, адаптивний `padding` і можливість перенесення тексту.

### Помилка 5. Збільшення зони натискання за рахунок перекриття

Проблема: невидимі області різних елементів можуть накладатися одна на одну.

Виправлення: перевірити фактичні межі взаємодії та використовувати простіші способи збільшення кнопок.

### Помилка 6. Орієнтація лише на мобільні пристрої

Проблема: елементи можуть залишатися незручними для клавіатури або допоміжних технологій.

Виправлення: перевіряти доступність усіма основними способами взаємодії.

### Помилка 7. Збільшення лише видимої іконки

Проблема: іконка стала більшою, але її область натискання все одно може бути недостатньою.

Виправлення: вимірювати весь інтерактивний елемент, а не лише SVG або зображення.

### Помилка 8. Вважати 24 px універсальним ідеальним розміром

Проблема: мінімальна нормативна вимога не завжди забезпечує найкращий користувацький досвід.

Виправлення: використовувати 44–48 px як практичний орієнтир для багатьох мобільних контролів, коли це відповідає контексту.

## 23. Практичний приклад: група кнопок

Приклад HTML:

    <div class="actions">
      <button class="action-button" type="button">
        Скасувати
      </button>

      <button class="action-button action-button--primary" type="button">
        Зберегти
      </button>
    </div>

Приклад CSS:

    .actions {
      display: flex;
      flex-wrap: wrap;
      gap: 12px;
    }

    .action-button {
      min-width: 44px;
      min-height: 44px;
      padding: 10px 18px;
      border: 1px solid currentColor;
      border-radius: 8px;
      font: inherit;
      cursor: pointer;
    }

    .action-button--primary {
      font-weight: 600;
    }

У цьому прикладі:
- кнопки мають мінімальну висоту;
- текст має простір навколо;
- `gap` відокремлює сусідні елементи;
- `flex-wrap` дозволяє переносити кнопки на вузькому екрані.

У готовому інтерфейсі потрібно також додати кольори, стани `hover`, `focus-visible`, `active` і `disabled`, а також перевірити контраст.

---

## 24. Практичний приклад: кнопки кількості товару

Типовий компонент інтернет-магазину має кнопки «Зменшити» та «Збільшити».

Приклад HTML:

    <div class="quantity-control">
      <button
        type="button"
        aria-label="Зменшити кількість"
      >
        −
      </button>

      <output aria-label="Кількість товару">
        1
      </output>

      <button
        type="button"
        aria-label="Збільшити кількість"
      >
        +
      </button>
    </div>

Приклад CSS:

    .quantity-control {
      display: flex;
      align-items: center;
      gap: 8px;
    }

    .quantity-control button {
      width: 44px;
      height: 44px;
      display: grid;
      place-items: center;
      font-size: 1.25rem;
    }

    .quantity-control output {
      min-width: 32px;
      text-align: center;
    }

Це приклад структури. Для повноцінного компонента потрібно:
- реалізувати зміну кількості;
- не дозволяти значення нижче допустимого мінімуму;
- повідомляти актуальне значення;
- за потреби вимикати кнопку зменшення;
- зберігати видимий фокус;
- перевірити роботу зі скринрідером.

## 25. Чекліст Touch Targets

### Розміри
- [ ] Кнопки мають достатню область натискання.
- [ ] Іконки розташовані в зручних інтерактивних контейнерах.
- [ ] Для відповідних цілей перевірено критерій WCAG 2.2 2.5.8.
- [ ] Маленькі цілі перевірено на відповідність умовам винятків, якщо вони застосовуються.
- [ ] Висота та ширина не ламаються через довгий текст.

### Відстань
- [ ] Сусідні кнопки не розташовані надто близько.
- [ ] Важливі й небезпечні дії чітко розділені.
- [ ] Області натискання не перекриваються.
- [ ] Проміжки зберігаються на вузьких екранах.

### Семантика та доступність
- [ ] Для дій використано відповідні HTML-елементи.
- [ ] Кнопки мають зрозумілі назви.
- [ ] Іконки без видимого тексту мають доступну назву.
- [ ] Фокус клавіатури видимий.
- [ ] Компоненти працюють без миші.
- [ ] Стани компонентів зрозумілі користувачеві.

### Адаптивність
- [ ] Інтерфейс зручний на мобільному пристрої.
- [ ] Кнопки не стають надто маленькими на вузькому екрані.
- [ ] Текст можна збільшити.
- [ ] Довгі написи не обрізаються без потреби.
- [ ] Важливі дії не перекриваються клавіатурою або іншими елементами.

### Тестування
- [ ] Перевірено розміри в DevTools.
- [ ] Перевірено реальне натискання.
- [ ] Перевірено різні ширини екрана.
- [ ] Протестовано на реальному сенсорному пристрої.
- [ ] Перевірено клавіатурну навігацію.

---

## 26. Що потрібно запам'ятати

1. **Touch target — це область взаємодії, а не лише видима іконка.**

2. **WCAG 2.2 AA використовує мінімум 24 × 24 CSS px для відповідних цілей із передбаченими винятками.**

3. **44–48 CSS px — практичний орієнтир для багатьох мобільних контролів.** Це рекомендація щодо зручності, а не універсальна вимога рівня AA.

4. **Відстань між елементами має значення.** Великі кнопки, розташовані впритул, можуть створювати проблеми.

5. **`padding` часто допомагає збільшити область натискання без збільшення іконки.**

6. **Не всі елементи повинні мати однакові розміри.** Враховуй призначення, контекст і спосіб взаємодії.

7. **Не збільшуй області натискання так, щоб вони перекривали сусідні дії.**

8. **Touch Targets — лише частина доступності.** Також важливі семантика, доступні назви, контраст, фокус і клавіатурна навігація.

9. **Перевіряй реальні розміри, а не лише CSS-код.** Фактична взаємодія залежить від компонування й перекриттів.

10. **Тестуй на реальних пристроях.** Емуляція не завжди передає досвід фізичного натискання.

## 28. Практичне завдання

Створи невеликий адаптивний інтерфейс інтернет-магазину з такими елементами:

- кнопка відкриття мобільного меню;
- картка товару;
- кнопка додавання до обраного;
- кнопка додавання в кошик;
- контрол кількості товару з кнопками `+` та `−`;
- checkbox згоди з умовами;
- кнопка оформлення замовлення;
- кнопка закриття модального вікна.

Реалізуй:

1. Семантичний HTML.
2. Мінімальні розміри інтерактивних елементів.
3. Зручні області натискання для іконок.
4. Достатню відстань між сусідніми діями.
5. Адаптивне компонування.
6. Видимий `focus-visible`.
7. Зрозумілі доступні назви кнопок.
8. Коректну поведінку на вузькому екрані.
9. Перевірку фактичних розмірів у DevTools.
10. Тестування на реальному сенсорному пристрої.

**Критерій готовності:** користувач може легко натискати всі важливі елементи, не активуючи випадково сусідні дії, а інтерфейс залишається доступним із клавіатури.

## 29. Основна думка

Touch Targets — це не просто питання розміру кнопки. Це частина доступності, ергономіки та якості користувацького досвіду.

Під час проєктування потрібно враховувати не лише те, як елемент виглядає, а й те, наскільки легко його знайти, активувати та використати без помилки.

**Хороший інтерактивний елемент має бути помітним, зрозумілим, достатньо великим і зручним для різних способів взаємодії.**
