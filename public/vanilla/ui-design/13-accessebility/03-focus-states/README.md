# 03. Focus States — Стани фокусу та доступність клавіатури

## Вступ

**Focus states (стани фокусу)** — це візуальні зміни елемента інтерфейсу, які показують, який елемент зараз отримує клавіатурний фокус.

Коли користувач переходить між інтерактивними елементами за допомогою клавіші `Tab`, браузер зазвичай показує, який елемент активний для взаємодії. Наприклад, навколо кнопки може з'явитися контур, змінитися колір рамки або з'явитися зовнішнє кільце.

Стани фокусу особливо важливі для:

- людей, які користуються клавіатурою замість миші;
- людей із порушеннями моторики;
- користувачів допоміжних технологій;
- людей зі зниженим зором;
- користувачів, які взаємодіють із формами, меню та складними вебінтерфейсами.

Мета focus states — **завжди допомагати користувачеві зрозуміти, де саме він перебуває в інтерфейсі та з яким елементом може взаємодіяти**.

У CSS стани фокусу найчастіше реалізують за допомогою псевдокласів:

- `:focus` — елемент має фокус;
- `:focus-visible` — браузер визначає, що фокус потрібно візуально показати;
- `:focus-within` — елемент або один із його нащадків має фокус.

---

## 1. Основні поняття

✔ Focus — поточний фокус взаємодії.

✔ Focus state — візуальний стан елемента, який перебуває у фокусі.

✔ Focus indicator — видимий індикатор фокусу, наприклад контур або кільце.

✔ Keyboard navigation — навігація інтерфейсом за допомогою клавіатури.

✔ Tab order — послідовність переходу між інтерактивними елементами.

✔ `:focus` — CSS-псевдоклас для елемента, який отримав фокус.

✔ `:focus-visible` — CSS-псевдоклас для фокусу, який браузер вважає за потрібне показати.

✔ `:focus-within` — CSS-псевдоклас для контейнера, усередині якого є елемент із фокусом.

✔ Focus ring — зовнішнє кільце навколо елемента у фокусі.

✔ Focus management — керування переміщенням фокусу в інтерфейсі.

✔ WCAG — рекомендації з доступності вебконтенту.

✔ Visible focus — видимий фокус, який дає змогу визначити поточний інтерактивний елемент.

---

## 2. Що потрібно запам'ятати

- Фокус — це не те саме, що наведення курсора миші (`:hover`).
- Користувач повинен бачити, який елемент зараз у фокусі.
- Не можна бездумно видаляти стандартний браузерний outline.
- `:focus-visible` зазвичай є хорошим вибором для сучасних інтерфейсів.
- Фокус має бути помітним на світлому й темному фоні.
- Індикатор фокусу не повинен перекриватися іншими елементами.
- Фокус не повинен губитися під час відкриття модальних вікон, меню та інших компонентів.
- Порядок переходу клавішею `Tab` має бути логічним.
- Не всі елементи сторінки повинні отримувати фокус: зазвичай це інтерактивні елементи та спеціально визначені області.
- Натискання `Enter` або `Space` повинно активувати відповідні елементи відповідно до їхньої семантики.
- Видимий фокус важливий не тільки для форм, а й для навігації, кнопок, посилань, діалогів і складних компонентів.
- Критерії WCAG щодо видимості, контрасту та неперекриття фокусу потрібно розглядати окремо.

# 3. Focus State, Hover State та Active State

Ці стани можуть виглядати схоже, але виконують різні функції.

## 3.1. Hover State

`:hover` — стан, який виникає, коли вказівник миші перебуває над елементом.

    .button:hover {
      background-color: #1d4ed8;
    }

Hover допомагає зрозуміти, що елемент інтерактивний.

Але він не замінює стан фокусу, оскільки користувач клавіатури не наводить мишу на елемент.

## 3.2. Focus State

`:focus` — стан елемента, який отримав фокус.

    .button:focus {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

Фокус дає змогу користувачеві зрозуміти, який елемент він може активувати за допомогою клавіатури.

## 3.3. Active State

`:active` — стан елемента під час його активації, наприклад у момент натискання кнопки миші або клавіші.

    .button:active {
      transform: translateY(1px);
    }

Active часто використовується для створення ефекту натискання.

## 3.4. Порівняння станів

| Стан | CSS | Призначення |
|---|---|---|
| Звичайний | базові стилі | Елемент у стандартному стані |
| Hover | `:hover` | Вказівник перебуває над елементом |
| Focus | `:focus` | Елемент має фокус |
| Focus-visible | `:focus-visible` | Фокус потрібно візуально показати |
| Active | `:active` | Елемент активується |
| Disabled | `:disabled` | Елемент недоступний для взаємодії |

**Важливо:** один елемент може одночасно мати кілька станів. Наприклад, кнопка може бути наведеною курсором і водночас перебувати у фокусі.

Не варто робити всі ці стани візуально однаковими.

# 4. Псевдоклас `:focus`

## 4.1. Як працює `:focus`

CSS-псевдоклас `:focus` застосовує стилі до елемента, який отримав фокус.

Фокус можуть отримувати, зокрема:

- посилання;
- кнопки;
- поля введення;
- текстові області;
- елементи вибору;
- елементи з відповідним атрибутом `tabindex`.

Приклад:

    input:focus {
      border-color: #2563eb;
      outline: 2px solid #2563eb;
      outline-offset: 2px;
    }

Коли користувач переходить до поля введення за допомогою клавіатури або клацає його мишею, браузер може застосувати цей стиль.

## 4.2. Стандартний браузерний фокус

Браузери зазвичай мають власні стилі фокусу.

Наприклад, навколо кнопки або поля введення може з'явитися контур.

Це корисна функція доступності, тому стандартний фокус не варто видаляти без заміни.

Поганий приклад:

    button:focus {
      outline: none;
    }

Якщо після цього не додати іншого помітного індикатора, користувач клавіатури може втратити можливість визначити поточний елемент.

Кращий приклад:

    button:focus {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

Або для сучасного інтерфейсу:

    button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

**Правило:** видаляти стандартний індикатор можна лише тоді, коли його замінює інший доступний індикатор.

---

# 5. Псевдоклас `:focus-visible`

## 5.1. Що це таке

`:focus-visible` дає змогу показувати індикатор фокусу тоді, коли браузер визначає, що його візуальне відображення потрібне користувачеві.

Наприклад:

- користувач переходить між кнопками за допомогою `Tab`;
- користувач відкриває меню клавіатурою;
- користувач переходить між полями форми.

Браузер зазвичай показує індикатор фокусу в таких випадках.

Після кліку мишею індикатор може не з'явитися, залежно від елемента та поведінки браузера.

## 5.2. Приклад використання

    button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

Це дозволяє відокремити візуальне оформлення фокусу від інших способів взаємодії.

## 5.3. Чому `:focus-visible` часто кращий за `:focus`

Якщо застосувати помітне кільце до кожного `:focus`, воно може з'являтися і після кліку мишею.

Це не обов'язково є помилкою доступності, але іноді створює зайвий візуальний шум.

`:focus-visible` допомагає зберегти індикатор для клавіатурної навігації, не показуючи його без потреби в деяких інших сценаріях.

Проте поведінку визначає браузер, а не лише спосіб введення. Не потрібно вважати `:focus-visible` точним визначником того, чи користувач натиснув клавішу або мишу.

## 5.4. Рекомендований базовий стиль

    :focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

Такий глобальний стиль може бути хорошою початковою точкою для простого проєкту.

У складніших проєктах індикатори можуть відрізнятися для різних типів компонентів, якщо всі вони залишаються достатньо помітними.

---

# 6. Псевдоклас `:focus-within`

## 6.1. Що це таке

`:focus-within` застосовується до елемента, якщо він сам або будь-який його нащадок перебуває у фокусі.

Це особливо корисно для контейнерів форм, карток і груп полів.

Приклад:

    .form-field:focus-within {
      border-color: #2563eb;
      background-color: #eff6ff;
    }

    .form-field input:focus-visible {
      outline: 2px solid #2563eb;
      outline-offset: 2px;
    }

Коли поле всередині `.form-field` отримує фокус, контейнер теж змінює вигляд.

## 6.2. Коли використовувати

`:focus-within` корисний для:

- підсвічування всього поля форми;
- позначення активної картки;
- оформлення групи елементів;
- підсвічування пошукового поля разом з іконкою;
- візуального позначення контейнера з активним дочірнім елементом.

Важливо: стиль контейнера не завжди замінює індикатор самого інтерактивного елемента. Переконайся, що користувач може визначити, яка саме кнопка або яке саме поле отримало фокус.

# 7. Як створити хороший Focus Indicator

**Focus indicator (індикатор фокусу)** — це видима ознака того, що інтерактивний елемент перебуває у фокусі.

Він може бути реалізований за допомогою:

- зовнішнього контуру;
- внутрішньої рамки;
- зміни кольору рамки;
- фонового кольору;
- контрастного кільця;
- комбінації кількох візуальних ефектів.

## 7.1. Видимість

Індикатор повинен бути достатньо помітним, щоб користувач швидко знаходив його поглядом.

Поганий приклад:

    button:focus-visible {
      outline: 1px solid #d1d5db;
    }

На світлому фоні такий контур може бути малопомітним.

Кращий початковий варіант:

    button:focus-visible {
      outline: 3px solid #1d4ed8;
      outline-offset: 3px;
    }

Точну достатність контрасту потрібно перевіряти на реальному фоні й у контексті компонента.

## 7.2. Контраст

Індикатор має відрізнятися від прилеглих кольорів.

Для критеріїв WCAG, пов'язаних із контрастом нефрагментів тексту, важливим є співвідношення контрасту щонайменше 3:1 між візуальною інформацією компонента та суміжними кольорами — там, де застосовується відповідний критерій.

Не кожен focus indicator оцінюється лише за одним числом: потрібно враховувати конкретний критерій WCAG, геометрію індикатора, його площу та фон.

## 7.3. Товщина

Надто тонкий контур може бути складно помітити.

Практичний початковий варіант:

    :focus-visible {
      outline: 3px solid #2563eb;
    }

Три пікселі — це не універсальна вимога для кожного дизайну, а зручна відправна точка.

## 7.4. Відступ від елемента

`outline-offset` відсуває контур від краю елемента.

    .button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

Переваги:

- індикатор не зливається з рамкою кнопки;
- контур краще помітний;
- стан фокусу може виглядати виразніше.

Але потрібно перевірити, чи контур не перекривається сусідніми елементами й чи не обрізається контейнером.

## 7.5. Стабільність

Індикатор має працювати на різних фонах і в різних станах компонента.

Наприклад, кнопка може мати:

- світлий фон;
- темний фон;
- кольоровий фон;
- фотографію позаду;
- стан наведення;
- стан помилки;
- активний стан.

Один колір індикатора не завжди буде достатньо контрастним у всіх цих ситуаціях.

Для складного дизайну можна використовувати кільце з кількох контрастних шарів.

    .button:focus-visible {
      outline: 2px solid #ffffff;
      box-shadow: 0 0 0 5px #1d4ed8;
    }

Це лише приклад техніки. Перевір, чи обидва шари залишаються видимими на конкретному фоні.

# 8. Focus States і WCAG

WCAG — це міжнародні рекомендації з доступності вебконтенту.

Для фокусу особливо важливі критерії, пов'язані з клавіатурною доступністю та видимістю індикатора.

## 8.1. WCAG 2.4.7 — Focus Visible

На рівні AA для вебконтенту WCAG 2.2 критерій 2.4.7 вимагає, щоб режим роботи з клавіатурою мав видимий індикатор фокусу.

Простими словами: коли користувач переміщується між елементами клавіатурою, він повинен бачити, який елемент зараз у фокусі.

## 8.2. WCAG 2.4.11 — Focus Not Obscured (Minimum)

Цей критерій WCAG 2.2 рівня AA стосується неперекриття фокусу.

Коли компонент отримує фокус клавіатури, він не повинен бути повністю прихований авторським вмістом сторінки.

Наприклад, фокус не повинен повністю зникати під фіксованою панеллю або іншим вмістом, який перекриває компонент.

## 8.3. WCAG 2.4.13 — Focus Appearance

Цей критерій WCAG 2.2 рівня AAA визначає вимоги до зовнішнього вигляду індикатора фокусу, зокрема його площі та контрасту зміни пікселів.

Для відповідності критерію потрібно перевіряти точні нормативні умови, а не покладатися лише на те, що контур має певну товщину.

## 8.4. Інші важливі критерії

- **2.1.1 Keyboard** — функціональність повинна бути доступна з клавіатури, за передбаченими винятками.
- **2.1.2 No Keyboard Trap** — користувач не повинен потрапляти в пастку клавіатурного фокусу.
- **2.4.3 Focus Order** — порядок фокусу має зберігати зміст і можливість роботи з інтерфейсом.
- **2.4.7 Focus Visible** — індикатор фокусу має бути видимим.
- **2.4.11 Focus Not Obscured (Minimum)** — сфокусований компонент не повинен бути повністю перекритий авторським вмістом.
- **2.4.12 Focus Not Obscured (Enhanced)** — суворіша вимога рівня AAA щодо неперекриття фокусу.
- **2.4.13 Focus Appearance** — вимоги до вигляду індикатора фокусу на рівні AAA.

**Запам'ятай:** видимий фокус — це лише частина доступності клавіатури. Навіть красивий outline не виправить неправильний порядок навігації або пастку фокусу.

# 9. Порядок клавіатурної навігації

## 9.1. Клавіша Tab

`Tab` зазвичай переводить фокус до наступного доступного інтерактивного елемента.

Наприклад:

    Посилання → Кнопка → Поле введення → Checkbox → Submit

Фактичний порядок залежить від структури документа, станів елементів та інших правил браузера.

## 9.2. Shift + Tab

`Shift + Tab` переводить фокус до попереднього елемента.

Це важливо, щоб користувач міг не тільки рухатися вперед, а й повертатися назад.

## 9.3. Не змінюй порядок без потреби

Погана практика — використовувати додатні значення `tabindex`, щоб штучно змінювати послідовність переходів.

    .first-button {
      tabindex: 3;
    }

Це не є правильним CSS: `tabindex` — HTML-атрибут, а не CSS-властивість.

Не рекомендовано:

    <button tabindex="5">Перша кнопка</button>
    <button tabindex="2">Друга кнопка</button>

Додатні значення `tabindex` можуть створити несподіваний порядок навігації, який складно підтримувати.

Зазвичай краще організувати логічний порядок елементів у HTML.

## 9.4. Нормальне використання tabindex

    <div tabindex="0">
      Цей блок можна включити в послідовність клавіатурної навігації.
    </div>

`tabindex="0"` робить елемент доступним для послідовного фокусу.

Використовуй його для нестандартних інтерактивних компонентів або областей, які справді мають бути доступними з клавіатури.

Не додавай `tabindex="0"` до кожного звичайного текстового блоку.

## 9.5. tabindex="-1"

    <div id="dialog-title" tabindex="-1">
      Налаштування профілю
    </div>

`tabindex="-1"` дає змогу програмно сфокусувати елемент, але не включає його до звичайної послідовності переходів за допомогою `Tab`.

Це корисно для:

- заголовків діалогових вікон;
- контейнерів із повідомленнями;
- програмного керування фокусом;
- окремих етапів роботи зі складними компонентами.

# 10. Focus States для кнопок

Кнопки — одні з найважливіших елементів, для яких потрібно правильно реалізувати фокус.

## 10.1. Базовий приклад

    .button {
      padding: 0.75rem 1.25rem;
      border: 1px solid #1d4ed8;
      border-radius: 0.5rem;
      background-color: #1d4ed8;
      color: #ffffff;
      cursor: pointer;
    }

    .button:hover {
      background-color: #1e40af;
    }

    .button:focus-visible {
      outline: 3px solid #1d4ed8;
      outline-offset: 3px;
    }

Тут наведення та фокус мають різне оформлення.

## 10.2. Не покладайся тільки на зміну фону

Поганий варіант:

    .button:focus-visible {
      background-color: #1e40af;
    }

Якщо фон змінюється незначно, користувачеві може бути складно помітити фокус.

Краще додати окремий індикатор:

    .button:focus-visible {
      outline: 3px solid #111827;
      outline-offset: 3px;
    }

Потрібно перевірити контраст цього індикатора на тлі кнопки та навколишнього інтерфейсу.

## 10.3. Кнопка з іконкою

    .icon-button {
      display: inline-grid;
      place-items: center;
      width: 2.75rem;
      height: 2.75rem;
      border: 1px solid #6b7280;
      border-radius: 0.5rem;
      background-color: #ffffff;
    }

    .icon-button:focus-visible {
      outline: 3px solid #1d4ed8;
      outline-offset: 3px;
    }

Для кнопки з іконкою важливо також передбачити зрозумілу доступну назву, якщо значення кнопки не пояснюється текстом.

---

# 11. Focus States для посилань

Посилання повинні бути доступними для клавіатурної навігації та мати помітний фокус.

    a {
      color: #1d4ed8;
      text-decoration: underline;
      text-underline-offset: 0.15em;
    }

    a:focus-visible {
      outline: 3px solid #1d4ed8;
      outline-offset: 3px;
    }

Не видаляй підкреслення посилання без іншого надійного способу відрізнити його від звичайного тексту.

Фокус і підкреслення виконують різні завдання:

- підкреслення допомагає розпізнати посилання;
- індикатор фокусу показує, яке посилання зараз вибране для взаємодії.

---

# 12. Focus States для форм

Поля форм повинні мати помітний фокус, щоб користувач розумів, куди вводиться текст.

## 12.1. Поле введення

    .input {
      width: 100%;
      padding: 0.75rem;
      border: 1px solid #6b7280;
      border-radius: 0.375rem;
      background-color: #ffffff;
      color: #111827;
    }

    .input:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 2px;
      border-color: #2563eb;
    }

## 12.2. Поле з підписом

    .field {
      display: grid;
      gap: 0.5rem;
    }

    .field:focus-within {
      color: #1d4ed8;
    }

    .field input:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 2px;
    }

Зміна кольору підпису може бути додатковою підказкою, але не повинна замінювати чіткий індикатор фокусу самого поля.

## 12.3. Поле з помилкою

    .input[aria-invalid="true"] {
      border-color: #b91c1c;
    }

    .input[aria-invalid="true"]:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 2px;
    }

Стан помилки та стан фокусу повинні залишатися зрозумілими одночасно.

Не варто використовувати один і той самий візуальний сигнал для помилки й фокусу, якщо через це користувач не може відрізнити їх.

## 12.4. Checkbox і Radio

Стандартні елементи `input type="checkbox"` та `input type="radio"` зазвичай уже мають клавіатурну поведінку браузера.

Їх можна стилізувати, але після стилізації потрібно перевірити:

- видимість фокусу;
- стан вибору;
- стан вимкнення;
- контраст;
- роботу з клавіатури.

Приклад:

    input[type="checkbox"]:focus-visible,
    input[type="radio"]:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

# 13. Focus States для меню та навігації

Навігаційні меню можуть містити багато посилань, кнопок і вкладених пунктів.

Кожен інтерактивний пункт повинен мати зрозумілий стан фокусу.

    .nav-link {
      display: inline-block;
      padding: 0.5rem 0.75rem;
      color: #111827;
      text-decoration: none;
    }

    .nav-link:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 2px;
      border-radius: 0.25rem;
    }

Потрібно перевірити:

- чи можна дістатися до кожного пункту клавіатурою;
- чи логічний порядок переходів;
- чи не обрізається індикатор;
- чи видно активний пункт на різних фонах;
- чи можна вийти з меню за допомогою клавіатури.

Не потрібно автоматично робити кожен декоративний елемент меню фокусованим.

---

# 14. Focus States для модальних вікон

Модальне вікно — це компонент, який тимчасово зосереджує увагу користувача на окремому завданні.

Наприклад:

- підтвердження видалення;
- налаштування;
- вхід до облікового запису;
- редагування профілю.

## 14.1. Керування фокусом

Коли відкривається модальне вікно, фокус зазвичай потрібно перемістити всередину нього.

Після закриття фокус, як правило, повертають до елемента, який відкрив діалог.

У межах модального діалогу клавіатурний фокус не повинен випадково переходити до інтерактивних елементів фонового вмісту.

## 14.2. Використання dialog

HTML-елемент `<dialog>` із методом `showModal()` надає вбудовану поведінку модального діалогу, зокрема блокування звичайної взаємодії з фоновою сторінкою.

Приклад:

    <button id="open-dialog" type="button">
      Відкрити налаштування
    </button>

    <dialog id="settings-dialog" aria-labelledby="dialog-title">
      <h2 id="dialog-title">Налаштування</h2>
      <p>Зміни параметри профілю.</p>

      <button id="close-dialog" type="button">
        Закрити
      </button>
    </dialog>

    <script>
      const dialog = document.querySelector("#settings-dialog");
      const openButton = document.querySelector("#open-dialog");
      const closeButton = document.querySelector("#close-dialog");

      openButton.addEventListener("click", () => {
        dialog.showModal();
        closeButton.focus();
      });

      closeButton.addEventListener("click", () => {
        dialog.close();
        openButton.focus();
      });
    </script>

Це навчальний приклад. Для реального проєкту потрібно також перевірити поведінку під час закриття клавішею `Escape`, початковий фокус, повернення фокусу та інші сценарії.

## 14.3. Видимий фокус усередині діалогу

    dialog button:focus-visible,
    dialog a:focus-visible,
    dialog input:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

Видимий індикатор має працювати для кожного інтерактивного елемента всередині діалогу.

# 15. Focus States для випадаючих списків та складних компонентів

Не кожен компонент можна реалізувати як просту кнопку або поле введення.

Приклади складних компонентів:

- dropdown menu;
- combobox;
- listbox;
- tabs;
- tree view;
- autocomplete;
- date picker;
- карусель;
- редактор із клавіатурним керуванням.

Такі компоненти можуть мати спеціальні правила переміщення фокусу.

Наприклад, у групі вкладок користувач може переміщатися стрілками між вкладками, а клавіша `Tab` переводить його до відповідної області вмісту.

Для складних компонентів потрібно визначити:

1. Які елементи отримують фокус.
2. Як користувач переміщується між ними.
3. Які клавіші використовуються.
4. Як оголошуються стани для допоміжних технологій.
5. Як виглядає активний елемент.
6. Як користувач виходить із компонента.

**Не копіюй поведінку складних компонентів навмання.** Для них важливо дотримуватися відповідної моделі взаємодії, наприклад рекомендацій WAI-ARIA Authoring Practices.

# 16. Focus States і CSS-архітектура

У реальному проєкті варто мати узгоджену систему стилів фокусу.

## 16.1. Глобальний стиль

    :focus-visible {
      outline: 3px solid var(--focus-color);
      outline-offset: 3px;
    }

    :root {
      --focus-color: #2563eb;
    }

Це проста відправна точка для невеликого проєкту.

## 16.2. Використання CSS-змінних

    :root {
      --focus-color: #2563eb;
      --focus-width: 3px;
      --focus-offset: 3px;
    }

    .button:focus-visible,
    .input:focus-visible,
    .nav-link:focus-visible {
      outline: var(--focus-width) solid var(--focus-color);
      outline-offset: var(--focus-offset);
    }

Переваги:

- єдина система оформлення;
- простіше змінювати дизайн;
- легше підтримувати компоненти;
- менше дублювання CSS.

## 16.3. Різні індикатори для різних поверхонь

Іноді глобального кольору недостатньо.

Наприклад, індикатор може бути розташований на темному фоні або на кольоровій кнопці.

Тоді можна використовувати окремі токени:

    :root {
      --focus-on-light: #1d4ed8;
      --focus-on-dark: #ffffff;
      --focus-on-color: #111827;
    }

Це приклад структури токенів, а не гарантія доступного контрасту. Кожну комбінацію кольорів потрібно перевіряти окремо.

## 16.4. Не створюй конфлікти між станами

Потрібно перевірити, як поєднуються:

- `:hover`;
- `:focus-visible`;
- `:active`;
- `:disabled`;
- стани помилки;
- стани вибору.

Наприклад, правило для `:hover` не повинно випадково приховувати контур фокусу.

# 17. Властивість outline

`outline` часто використовують для індикатора фокусу.

Синтаксис:

    outline: width style color;

Приклад:

    button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

## 17.1. Чим outline відрізняється від border

| Властивість | Особливості |
|---|---|
| `border` | Є частиною рамки елемента та його розрахункових розмірів |
| `outline` | Малюється навколо елемента й зазвичай не впливає на його розміри |
| `box-shadow` | Створює тінь, яку можна використовувати як додатковий візуальний ефект |

Для індикатора фокусу `outline` часто зручний, оскільки він не змінює розміри компонента.

## 17.2. Outline Offset

    button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 4px;
    }

Позитивне значення створює простір між елементом та контуром.

Але великий відступ може призвести до перекриття сусідніх елементів.

## 17.3. Чи можна використовувати box-shadow?

Так, але потрібно враховувати:

- контраст;
- видимість у різних браузерах;
- поведінку в режимах підвищеної контрастності;
- можливе обрізання;
- накладання на інші компоненти.

Якщо використовується `box-shadow` замість `outline`, потрібно перевірити, чи індикатор залишається доступним у відповідних середовищах.

---

# 18. Focus States у темній темі

Темна тема створює додаткові вимоги до перевірки фокусу.

Індикатор, який добре видно на білому тлі, може зливатися з темним фоном.

Наприклад, темно-синій контур може бути майже непомітним на темно-синій кнопці.

Приклад із токенами:

    :root {
      color-scheme: light;
      --focus-color: #1d4ed8;
    }

    [data-theme="dark"] {
      color-scheme: dark;
      --focus-color: #93c5fd;
    }

    :focus-visible {
      outline: 3px solid var(--focus-color);
      outline-offset: 3px;
    }

Це лише приклад: значення для темної теми теж потрібно перевірити на реальних фонах.

Перевіряй фокус на:

- основному тлі;
- кнопках;
- посиланнях;
- картках;
- полях форм;
- модальних вікнах;
- активних і вибраних компонентах.

---

# 19. Focus States і адаптивний дизайн

Індикатор фокусу має залишатися видимим на різних розмірах екрана.

Потрібно перевірити:

- мобільні пристрої;
- планшети;
- ноутбуки;
- широкі монітори;
- масштабування сторінки;
- довгі форми;
- горизонтальне прокручування;
- компоненти всередині контейнерів з `overflow`.

## 19.1. Проблема overflow

Приклад:

    .scroll-container {
      overflow: hidden;
    }

Такий контейнер може обрізати індикатор, який виходить за межі компонента.

Якщо контур не видно, потрібно перевірити структуру контейнерів, відступи й спосіб малювання індикатора.

Не потрібно автоматично прибирати `overflow: hidden`: спочатку з'ясуй, навіщо його додано, і вибери рішення, яке зберігає потрібну поведінку та доступність.

---

# 20. Focus States і prefers-reduced-motion

Індикатор фокусу іноді анімують, наприклад змінюють його колір або плавно показують кільце.

Для користувачів, які віддають перевагу зменшенню руху, можна прибрати непотрібні анімації.

    .button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
      transition: outline-offset 150ms ease;
    }

    @media (prefers-reduced-motion: reduce) {
      .button:focus-visible {
        transition: none;
      }
    }

Анімація не повинна бути необхідною умовою, щоб користувач помітив фокус.

Статичний індикатор часто є найпростішим і найнадійнішим рішенням.

---

# 21. Focus States і високий контраст

Деякі користувачі застосовують системні налаштування підвищеної контрастності.

У певних середовищах декоративні ефекти можуть відображатися інакше або бути обмежені.

Для Windows та сумісних браузерів можна перевірити поведінку за допомогою `forced-colors`.

    @media (forced-colors: active) {
      :focus-visible {
        outline: 3px solid Highlight;
        outline-offset: 3px;
      }
    }

`Highlight` — системний колір, який браузер може адаптувати до активної системної палітри.

Це додатковий спосіб зробити індикатор помітним, але він не замінює тестування в реальних режимах підвищеної контрастності.

# 22. Типові помилки

## 22.1. Повне видалення outline

Погано:

    *:focus {
      outline: none;
    }

Чому погано:

- користувач може втратити видимий індикатор;
- клавіатурна навігація стає складнішою;
- інтерфейс може не відповідати вимогам доступності.

## 22.2. Надто слабкий контраст

Погано:

    button:focus-visible {
      outline: 1px solid #d1d5db;
    }

На світлому тлі цей контур може бути майже непомітним.

## 22.3. Фокус позначається тільки кольором фону

Погано:

    button:focus-visible {
      background-color: #e5e7eb;
    }

Якщо зміна кольору майже непомітна, користувач може не розпізнати фокус.

## 22.4. Індикатор обрізається

Погано:

    .card {
      overflow: hidden;
    }

Якщо кнопка всередині картки має зовнішній outline, він може бути обрізаний.

## 22.5. Відсутність фокусу в нестандартних компонентах

Кастомна кнопка, зроблена на основі звичайного `div`, не отримує всю поведінку справжньої кнопки автоматично.

Поганий приклад:

    <div class="button">Зберегти</div>

Кращий варіант:

    <button type="button">Зберегти</button>

Використовуй семантичні HTML-елементи, коли вони відповідають призначенню компонента.

## 22.6. Плутанина між фокусом і вибором

Вибраний пункт не обов'язково перебуває у фокусі.

Наприклад, у меню один пункт може бути поточним, а інший — отримати фокус під час навігації.

Потрібно розрізняти:

- поточний вибраний стан;
- стан фокусу;
- стан наведення;
- стан активації.

## 22.7. Перевірка лише мишкою

Інтерфейс може чудово працювати при кліках, але мати проблеми під час переходу клавішею `Tab`.

Тому тестування мишкою не замінює тестування клавіатурою.

# 23. Практичний приклад: доступні стани кнопки

    :root {
      --button-bg: #1d4ed8;
      --button-hover-bg: #1e40af;
      --button-text: #ffffff;
      --focus-color: #111827;
    }

    .button {
      display: inline-flex;
      align-items: center;
      justify-content: center;
      padding: 0.75rem 1.25rem;
      border: 1px solid var(--button-bg);
      border-radius: 0.5rem;
      background-color: var(--button-bg);
      color: var(--button-text);
      font: inherit;
      cursor: pointer;
    }

    .button:hover {
      background-color: var(--button-hover-bg);
    }

    .button:focus-visible {
      outline: 3px solid var(--focus-color);
      outline-offset: 3px;
    }

    .button:active {
      transform: translateY(1px);
    }

    .button:disabled {
      cursor: not-allowed;
      opacity: 0.6;
    }

Цей приклад демонструє розділення станів, але сам по собі не гарантує відповідності всім критеріям WCAG.

Потрібно додатково перевірити:

- контраст тексту;
- контраст індикатора фокусу;
- поведінку вимкненої кнопки;
- видимість контуру на навколишньому фоні;
- чи не змінює `opacity` вигляд індикатора;
- роботу кнопки з клавіатури.

---

# 24. Як перевіряти Focus States

Перевірка фокусу має бути частиною звичайного процесу розробки.

## 24.1. Ручна перевірка клавіатурою

1. Відкрий сторінку в браузері.
2. Не використовуй мишу.
3. Натисни `Tab`.
4. Перевір, який елемент отримав фокус.
5. Переконайся, що індикатор добре видно.
6. Продовжуй переходити між усіма інтерактивними елементами.
7. Перевір `Shift + Tab`.
8. Переконайся, що можна вийти з меню, діалогу або іншого компонента.
9. Перевір активацію кнопок за допомогою `Enter` і `Space`, де це передбачено.
10. Повтори тест після зміни CSS.

## 24.2. Перевірка різних станів

Перевір:

- звичайний стан;
- `:hover`;
- `:focus-visible`;
- `:active`;
- помилку форми;
- вибраний стан;
- вимкнений стан;
- світлу тему;
- темну тему.

## 24.3. Перевірка масштабування

Збільш сторінку в браузері та переконайся, що:

- індикатор залишається видимим;
- елементи не перекривають його;
- фокус не губиться через прокручування;
- фіксовані панелі не приховують сфокусований елемент.

## 24.4. Інструменти

Для перевірки можна використовувати:

- **Chrome DevTools** — перевірка CSS і станів елементів;
- **Firefox DevTools** — перевірка стилів і поведінки фокусу;
- **axe DevTools** — автоматизовані перевірки доступності;
- **Lighthouse** — загальний аудит доступності;
- **Accessibility Insights** — допоміжні перевірки доступності;
- **NVDA** або **VoiceOver** — перевірка взаємодії з допоміжними технологіями.

Автоматизовані інструменти можуть виявити частину проблем, але не замінюють ручного тестування клавіатурою.

# 25. Практичний алгоритм створення Focus States

Для нового компонента використовуй такий порядок.

## Крок 1. Визнач тип компонента

Це кнопка, посилання, поле введення, меню чи складний кастомний компонент?

Від типу компонента залежить його семантика та поведінка клавіатури.

## Крок 2. Перевір HTML

Використовуй відповідний семантичний елемент.

Наприклад:

- дія — `<button>`;
- навігація — `<a>`;
- введення даних — `<input>`;
- вибір — `<select>` або відповідний елемент форми.

## Крок 3. Визнач стиль фокусу

Обери:

- колір;
- товщину;
- стиль контуру;
- відступ;
- поведінку на різних фонах.

## Крок 4. Реалізуй CSS

    .component:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

## Крок 5. Перевір контраст

Переконайся, що індикатор відрізняється від прилеглих кольорів і залишається помітним.

## Крок 6. Перевір сусідні компоненти

Переконайся, що outline не обрізається, не перекривається й не зливається з іншими рамками.

## Крок 7. Протестуй клавіатурою

Перевір переходи вперед і назад, активацію та вихід із компонента.

## Крок 8. Перевір складні сценарії

Відкрий модальне вікно, розкрий меню, відправ форму, виклич помилку.

## Крок 9. Перевір адаптивність

Перевір різні ширини екрана, масштабування та режими відображення.

## Крок 10. Повтори після змін

Зміна кольорів, відступів, рамок або структури може порушити видимість фокусу.

# 26. Мінішпаргалка

| Завдання | Рішення |
|---|---|
| Стилізувати елемент у фокусі | `:focus` |
| Показувати індикатор за потреби | `:focus-visible` |
| Підсвітити контейнер з активним нащадком | `:focus-within` |
| Створити зовнішній контур | `outline` |
| Відсунути контур від елемента | `outline-offset` |
| Додати елемент до Tab-порядку | `tabindex="0"` |
| Дозволити програмний фокус без звичайного Tab-переходу | `tabindex="-1"` |
| Врахувати системний режим підвищеної контрастності | `@media (forced-colors: active)` |
| Врахувати зменшення руху | `@media (prefers-reduced-motion: reduce)` |
| Перевірити клавіатурну навігацію | `Tab`, `Shift + Tab`, `Enter`, `Space`, `Escape` — відповідно до компонента |

# 27. Контрольний список доступності

Перед завершенням компонента перевір:

- [ ] Усі потрібні інтерактивні елементи доступні з клавіатури.
- [ ] Фокус можна побачити.
- [ ] Індикатор має достатній контраст.
- [ ] Індикатор не обрізається контейнером.
- [ ] Індикатор не перекривається іншим вмістом.
- [ ] Порядок переходу логічний.
- [ ] `Tab` і `Shift + Tab` працюють очікувано.
- [ ] Кнопки й посилання мають правильну семантику.
- [ ] Відкриття діалогу правильно керує фокусом.
- [ ] Після закриття діалогу фокус повертається в логічне місце.
- [ ] Немає пастки клавіатурного фокусу.
- [ ] Фокус видно в різних темах.
- [ ] Фокус не плутається зі станами помилки та вибору.
- [ ] Перевірено масштабування сторінки.
- [ ] Проведено ручне тестування клавіатурою.

# 28. Рівні знань

## Core — базовий рівень

Ти повинен розуміти:

- що таке фокус;
- чим відрізняються `:hover`, `:focus` та `:active`;
- як працює `:focus-visible`;
- як оформити `outline`;
- чому не можна бездумно видаляти стандартний фокус;
- як перевіряти сторінку клавішею `Tab`.

## Junior — практичний рівень

Ти повинен уміти:

- створювати помітні індикатори для кнопок, посилань і форм;
- застосовувати CSS-змінні для фокусу;
- перевіряти контраст індикатора;
- знаходити обрізані або перекриті індикатори;
- перевіряти клавіатурний порядок;
- тестувати світлу й темну теми;
- використовувати семантичні HTML-елементи.

## Middle — системний рівень

Ти повинен уміти:

- створювати узгоджену систему focus tokens;
- перевіряти всі комбінації станів компонентів;
- реалізовувати доступне керування фокусом у діалогах;
- перевіряти складні компоненти;
- знаходити проблеми з `overflow`, накладанням і прокручуванням;
- інтегрувати автоматизовані та ручні перевірки доступності.

## Senior — архітектурний рівень

Ти повинен уміти:

- визначати системні вимоги до фокусу;
- інтегрувати WCAG у дизайн-систему;
- формувати правила для складних інтерактивних компонентів;
- планувати перевірки доступності в CI/CD;
- оцінювати ризики кастомних компонентів;
- організовувати аудит доступності всього продукту.

# 30. Головне правило

**Користувач повинен завжди розуміти, де перебуває клавіатурний фокус, і мати змогу послідовно взаємодіяти з інтерфейсом без миші.**

Хороший focus state — це не просто декоративний outline. Це частина доступності, передбачуваності та якості користувацького досвіду.

Під час розробки запам'ятай три основні принципи:

1. **Visibility:** фокус має бути видимим.
2. **Consistency:** індикатори мають бути послідовними в усій системі.
3. **Keyboard access:** усі потрібні дії мають бути доступними й зрозумілими під час роботи з клавіатурою.

Якщо компонент красиво виглядає з мишкою, але користувач не може побачити фокус або дістатися до потрібної дії клавіатурою, компонент ще не можна вважати повністю доступним.
