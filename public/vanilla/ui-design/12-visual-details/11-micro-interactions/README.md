# 11. Micro-interactions — Мікровзаємодії в UI

Мікровзаємодії (Micro-interactions) — це невеликі інтерактивні реакції інтерфейсу на дії користувача або зміни стану системи.

Вони допомагають користувачеві зрозуміти, що відбувається в інтерфейсі: чи натиснулася кнопка, чи збереглися дані, чи завантажується контент, чи спрацювала перевірка форми.

Мікровзаємодії не повинні відволікати від основного завдання. Їхня мета — зробити інтерфейс зрозумілішим, передбачуванішим і приємнішим у використанні.

---

## 1. Що таке Micro-interactions

✔ Micro-interaction — невелика реакція інтерфейсу на дію користувача або подію системи.

✔ Interaction — взаємодія користувача з інтерфейсом.

✔ Feedback — зворотний зв'язок, який повідомляє користувачеві про результат дії.

✔ State — стан елемента або компонента в певний момент.

✔ Animation — зміна властивостей елемента в часі.

✔ Transition — плавний перехід між значеннями CSS-властивостей.

✔ Trigger — подія, яка запускає мікровзаємодію.

✔ Response — реакція інтерфейсу на подію.

Приклади:

- Кнопка трохи змінює колір під час наведення.
- Після натискання кнопка показує стан завантаження.
- Серце змінює колір після додавання до обраного.
- Форма показує повідомлення після успішного надсилання.
- Перемикач плавно переходить зі стану OFF у ON.
- Поле введення підсвічується, якщо користувач припустився помилки.
- Під час копіювання тексту з'являється повідомлення «Скопійовано».
- Індикатор показує, що файл завантажується.

**Головний принцип:** кожна мікровзаємодія повинна мати зрозумілу мету.

---

## 2. З чого складається мікровзаємодія

Типова мікровзаємодія складається з чотирьох частин:

1. **Trigger** — подія, яка запускає взаємодію.
2. **Rules** — правила, які визначають поведінку інтерфейсу.
3. **Feedback** — візуальна, звукова або тактильна реакція.
4. **Loops and modes** — повторення, тривалість або різні режими поведінки.

### Приклад: кнопка «Додати до обраного»

- Trigger: користувач натискає кнопку.
- Rules: система змінює стан елемента з `not favorite` на `favorite`.
- Feedback: іконка серця змінює колір і вигляд.
- Loops and modes: повторне натискання прибирає елемент з обраного.

Інший приклад — надсилання форми:

- Trigger: користувач натискає «Надіслати».
- Rules: система перевіряє введені дані.
- Feedback: показує помилки або повідомляє про успіх.
- Loops and modes: під час відправлення кнопка показує завантаження та тимчасово блокується.

## 3. Основні типи Micro-interactions

### 3.1. Hover interactions

Hover — реакція на наведення курсора на інтерактивний елемент.

Зазвичай використовується на комп'ютерах.

Приклади:

- Кнопка змінює колір.
- Посилання отримує підкреслення.
- Картка трохи піднімається.
- Іконка змінює колір.
- На зображенні з'являється додаткова інформація.

    .button {
      background-color: #2563eb;
      color: white;
      transition: background-color 180ms ease;
    }

    .button:hover {
      background-color: #1d4ed8;
    }

Важливо: hover не повинен бути єдиним способом отримати важливу інформацію. На сенсорних екранах наведення може бути відсутнім.

### 3.2. Press interactions

Press — реакція на натискання або активне утримання кнопки.

Приклади:

- Кнопка трохи зменшується.
- Фон стає темнішим.
- Іконка змінює вигляд.
- Елемент отримує короткий візуальний відгук.

    .button {
      transition:
        background-color 150ms ease,
        transform 150ms ease;
    }

    .button:active {
      transform: scale(0.97);
    }

Не варто сильно зменшувати кнопку: це може створювати відчуття нестабільності.

### 3.3. Focus interactions

Focus — реакція елемента, який отримав клавіатурний або програмний фокус.

Особливо важливо для доступності.

    .input:focus-visible {
      outline: 3px solid #60a5fa;
      outline-offset: 2px;
    }

Не прибирай контур фокуса без повноцінної заміни.

    /* Погано: користувач клавіатури може втратити видимий фокус. */
    .input:focus {
      outline: none;
    }

### 3.4. Toggle interactions

Toggle — перемикання між двома або кількома станами.

Приклади:

- Увімкнення темної теми.
- Додавання до обраного.
- Увімкнення сповіщень.
- Показ або приховування пароля.
- Розгортання меню.

Важливо, щоб користувач міг зрозуміти поточний стан і результат наступного натискання.

### 3.5. Loading interactions

Loading — реакція інтерфейсу під час виконання операції.

Приклади:

- Spinner — індикатор обертання.
- Skeleton — умовний макет контенту, що завантажується.
- Progress bar — індикатор прогресу.
- Текст «Завантаження…».
- Кнопка з індикатором виконання.

Завдання loading-стану — пояснити, що система працює, а не зависла.

### 3.6. Success interactions

Success — підтвердження успішного завершення дії.

Приклади:

- Повідомлення «Зміни збережено».
- Галочка після завершення операції.
- Зміна тексту кнопки на «Скопійовано».
- Іконка успішного завантаження файлу.

### 3.7. Error interactions

Error — повідомлення про помилку або неможливість виконати дію.

Приклади:

- Поле форми отримує червону рамку.
- Під полем з'являється пояснення.
- Біля кнопки з'являється повідомлення про помилку.
- Після невдалого запиту показується можливість повторити спробу.

Хороше повідомлення про помилку повинно пояснювати:
- Що сталося.
- Чому це могло статися, якщо причина відома.
- Як користувач може виправити ситуацію.

### 3.8. Reveal interactions

Reveal — поступова поява додаткового контенту.

Приклади:

- Відкриття випадаючого меню.
- Поява підказки.
- Розгортання FAQ.
- Відкриття панелі фільтрів.
- Поява додаткових кнопок у картці.

### 3.9. Scroll interactions

Scroll interactions — реакції на прокручування сторінки.

Приклади:

- Поява кнопки «Нагору».
- Зміна фону шапки.
- Поступова поява елементів.
- Індикатор прогресу читання.

Такі ефекти варто використовувати обережно: вони можуть відволікати, ускладнювати навігацію та створювати зайве навантаження.

## 4. Стани інтерактивних елементів

Кожен інтерактивний компонент може мати кілька станів.

Для кнопки типовими є:

| Стан | Значення |
|---|---|
| Default | Звичайний стан |
| Hover | Курсор наведено |
| Focus | Елемент отримав фокус |
| Active | Елемент натискають |
| Disabled | Дію тимчасово заборонено |
| Loading | Виконується операція |
| Success | Дію успішно завершено |
| Error | Сталася помилка |

Не кожному компоненту потрібні всі стани. Вони залежать від призначення компонента.

Наприклад, кнопці навігації може не знадобитися стан `loading`, а кнопці надсилання форми він часто потрібен.

### Приклад станів кнопки в CSS

    .button {
      padding: 12px 20px;
      border: none;
      border-radius: 8px;
      background-color: #2563eb;
      color: white;
      cursor: pointer;

      transition:
        background-color 180ms ease,
        transform 180ms ease,
        box-shadow 180ms ease;
    }

    .button:hover {
      background-color: #1d4ed8;
    }

    .button:focus-visible {
      outline: 3px solid #93c5fd;
      outline-offset: 3px;
    }

    .button:active {
      transform: scale(0.98);
    }

    .button:disabled {
      opacity: 0.55;
      cursor: not-allowed;
    }

## 5. CSS transitions

`transition` дозволяє плавно змінювати CSS-властивості, коли їхні значення змінюються.

Синтаксис:

    transition: property duration timing-function delay;

Де:

- `property` — властивість, яку потрібно анімувати.
- `duration` — тривалість переходу.
- `timing-function` — характер зміни швидкості.
- `delay` — затримка перед початком переходу.

Приклад:

    .card {
      transform: translateY(0);
      box-shadow: 0 2px 8px rgb(0 0 0 / 8%);

      transition:
        transform 200ms ease,
        box-shadow 200ms ease;
    }

    .card:hover {
      transform: translateY(-4px);
      box-shadow: 0 8px 24px rgb(0 0 0 / 12%);
    }

### Поширені timing functions

| Значення | Поведінка |
|---|---|
| `linear` | Рівномірна швидкість |
| `ease` | Плавний перехід зі зміною швидкості |
| `ease-in` | Повільний початок |
| `ease-out` | Плавне завершення |
| `ease-in-out` | Плавний початок і завершення |
| `cubic-bezier()` | Власна крива швидкості |

Приклад власної кривої:

    .element {
      transition: transform 250ms cubic-bezier(0.2, 0.8, 0.2, 1);
    }

### Які властивості краще анімувати

Зазвичай варто віддавати перевагу:

- `transform`
- `opacity`

Вони часто дозволяють браузеру виконувати анімацію ефективніше.

Анімація `width`, `height`, `top`, `left` та інших властивостей може спричиняти додаткові перерахунки layout. Це не означає, що їх ніколи не можна анімувати, але слід оцінювати продуктивність.

Не варто анімувати кожну властивість без потреби.

## 6. CSS animations

`transition` зазвичай реагує на зміну стану, а `animation` дозволяє описати послідовність кадрів через `@keyframes`.

Приклад появи повідомлення:

    @keyframes fade-in {
      from {
        opacity: 0;
        transform: translateY(8px);
      }

      to {
        opacity: 1;
        transform: translateY(0);
      }
    }

    .notification {
      animation: fade-in 250ms ease-out both;
    }

Пояснення:

- `@keyframes` описує кадри анімації.
- `250ms` — тривалість.
- `ease-out` — характер зміни швидкості.
- `both` дозволяє застосувати стилі з початкового та кінцевого кадрів у відповідних фазах.

### Коли використовувати animation

- Для індикатора завантаження.
- Для появи повідомлення.
- Для короткого акценту на зміні стану.
- Для послідовності кількох рухів.
- Для декоративних ефектів, які не заважають користувачеві.

### Приклад spinner

    @keyframes spin {
      to {
        transform: rotate(360deg);
      }
    }

    .spinner {
      width: 24px;
      height: 24px;
      border: 3px solid #dbeafe;
      border-top-color: #2563eb;
      border-radius: 50%;
      animation: spin 800ms linear infinite;
    }

Для безперервної анімації важливо, щоб вона не відволікала від основного контенту та не працювала без потреби.

## 7. Тривалість і швидкість мікровзаємодій

Мікровзаємодії зазвичай короткі. Якщо ефект триває надто довго, інтерфейс може здаватися повільним.

Орієнтовні діапазони:

| Тип взаємодії | Орієнтовна тривалість |
|---|---:|
| Hover кнопки | 100–200 мс |
| Натискання кнопки | 80–150 мс |
| Поява невеликого повідомлення | 150–300 мс |
| Відкриття меню | 150–250 мс |
| Перемикання стану | 150–250 мс |
| Перехід між великими панелями | 200–400 мс |

Це не суворі правила. Оптимальна тривалість залежить від розміру елемента, складності руху та контексту.

**Важливо:** анімація не повинна затримувати доступ до потрібної функції.

### CSS-змінні для тривалості

    :root {
      --duration-fast: 120ms;
      --duration-normal: 200ms;
      --duration-slow: 300ms;

      --ease-standard: ease;
      --ease-out: ease-out;
    }

    .button {
      transition:
        background-color var(--duration-fast) var(--ease-standard),
        transform var(--duration-fast) var(--ease-standard);
    }

Перевага змінних — однакові параметри руху для всього інтерфейсу.

## 8. Мікровзаємодії та зворотний зв'язок

Користувач повинен розуміти, чи відбулася його дія.

Поширені способи зворотного зв'язку:

- Зміна кольору.
- Зміна форми або розміру.
- Поява іконки.
- Текстове повідомлення.
- Індикатор прогресу.
- Звуковий сигнал, якщо він доречний.
- Вібрація на пристроях, які її підтримують.

Не варто покладатися лише на колір. Наприклад, помилку потрібно позначити не тільки червоним кольором, а й текстом або відповідною іконкою.

### Приклад: повідомлення після копіювання

HTML:

    <button class="copy-button" type="button">
      Копіювати
    </button>

    <p class="copy-status" role="status" aria-live="polite"></p>

JavaScript:

    const copyButton = document.querySelector(".copy-button");
    const copyStatus = document.querySelector(".copy-status");

    copyButton.addEventListener("click", async () => {
      try {
        await navigator.clipboard.writeText("Приклад тексту");

        copyStatus.textContent = "Скопійовано";
      } catch {
        copyStatus.textContent = "Не вдалося скопіювати текст";
      }
    });

У реальному проєкті Clipboard API зазвичай потребує захищеного контексту, наприклад HTTPS або localhost.

Тут важливо не просто змінити вигляд кнопки, а повідомити користувачеві результат операції.

## 9. Мікровзаємодії для форм

Форми — одне з найважливіших місць для використання мікровзаємодій.

### 9.1. Focus у полі введення

    .form-input {
      border: 1px solid #cbd5e1;
      border-radius: 6px;
      transition: border-color 150ms ease;
    }

    .form-input:focus-visible {
      border-color: #2563eb;
      outline: 2px solid #bfdbfe;
      outline-offset: 1px;
    }

### 9.2. Помилка введення

    .form-input[aria-invalid="true"] {
      border-color: #dc2626;
    }

    .field-error {
      color: #b91c1c;
      font-size: 0.875rem;
    }

HTML:

    <label for="email">Електронна пошта</label>

    <input
      class="form-input"
      id="email"
      type="email"
      aria-invalid="true"
      aria-describedby="email-error"
    />

    <p class="field-error" id="email-error">
      Введіть коректну електронну пошту.
    </p>

Атрибут `aria-describedby` пов'язує поле з поясненням, а `aria-invalid` повідомляє допоміжним технологіям про помилковий стан.

### 9.3. Loading під час надсилання

Після початку надсилання форми можна:

- Змінити текст кнопки на «Надсилання…».
- Показати індикатор.
- Заблокувати повторне надсилання.
- Зберегти видимість фокуса.
- Після завершення показати успіх або помилку.

Важливо: не блокуй форму назавжди, якщо запит завершився помилкою. Користувач повинен мати змогу виправити дані або повторити дію.

## 10. Мікровзаємодії для карток та іконок

### Картка при наведенні

    .product-card {
      border: 1px solid #e2e8f0;
      border-radius: 12px;
      transition:
        transform 180ms ease,
        box-shadow 180ms ease;
    }

    .product-card:hover {
      transform: translateY(-3px);
      box-shadow: 0 8px 20px rgb(15 23 42 / 10%);
    }

Використовуй такий ефект, коли картка справді інтерактивна. Не варто створювати враження клікабельності для звичайного текстового блоку.

### Іконка обраного

    .favorite-icon {
      color: #64748b;
      transition:
        color 150ms ease,
        transform 150ms ease;
    }

    .favorite-button:hover .favorite-icon {
      transform: scale(1.08);
    }

    .favorite-button[aria-pressed="true"] .favorite-icon {
      color: #e11d48;
    }

HTML:

    <button
      class="favorite-button"
      type="button"
      aria-pressed="false"
    >
      <span class="favorite-icon" aria-hidden="true">♥</span>
      <span>Додати до обраного</span>
    </button>

Для справжньої роботи потрібен JavaScript, який змінює `aria-pressed` і зберігає стан обраного. CSS лише відображає поточний стан.

## 11. Micro-interactions у JavaScript

CSS підходить для візуальних реакцій, але для зміни даних, виконання запитів або керування складнішими станами потрібен JavaScript.

### Приклад: кнопка «Показати більше»

HTML:

    <button
      class="toggle-button"
      type="button"
      aria-expanded="false"
      aria-controls="extra-content"
    >
      Показати більше
    </button>

    <div id="extra-content" hidden>
      <p>Додаткова інформація.</p>
    </div>

JavaScript:

    const toggleButton = document.querySelector(".toggle-button");
    const extraContent = document.querySelector("#extra-content");

    toggleButton.addEventListener("click", () => {
      const isExpanded =
        toggleButton.getAttribute("aria-expanded") === "true";

      toggleButton.setAttribute("aria-expanded", String(!isExpanded));
      extraContent.hidden = isExpanded;

      toggleButton.textContent = isExpanded
        ? "Показати більше"
        : "Приховати";
    });

Тут взаємодія змінює не лише зовнішній вигляд, а й реальний стан контенту.

`aria-expanded` повідомляє допоміжним технологіям, чи розгорнутий блок. Атрибут `hidden` приховує або показує контент.

## 12. Мікровзаємодії у React

У React стан компонента зазвичай керується через `useState`.

Приклад кнопки обраного:

    "use client";

    import { useState } from "react";
    import styles from "./FavoriteButton.module.css";

    export default function FavoriteButton() {
      const [isFavorite, setIsFavorite] = useState(false);

      return (
        <button
          className={styles.button}
          type="button"
          aria-pressed={isFavorite}
          onClick={() => setIsFavorite((current) => !current)}
        >
          <span aria-hidden="true">
            {isFavorite ? "♥" : "♡"}
          </span>

          <span>
            {isFavorite ? "В обраному" : "Додати до обраного"}
          </span>
        </button>
      );
    }

CSS Module:

    .button {
      display: inline-flex;
      align-items: center;
      gap: 8px;
      padding: 10px 14px;
      border: 1px solid #cbd5e1;
      border-radius: 8px;
      background: white;
      color: #334155;
      cursor: pointer;
      transition:
        color 150ms ease,
        background-color 150ms ease,
        transform 150ms ease;
    }

    .button:hover {
      background-color: #f8fafc;
    }

    .button:active {
      transform: scale(0.98);
    }

    .button[aria-pressed="true"] {
      color: #be123c;
      background-color: #fff1f2;
    }

Що потрібно запам'ятати:

- `useState` зберігає стан компонента.
- `onClick` запускає зміну стану.
- `aria-pressed` повідомляє, що кнопка має перемикальний стан.
- CSS відображає стан і додає візуальний відгук.
- Для збереження обраного між перезавантаженнями потрібне додаткове рішення: API, база даних або локальне сховище залежно від вимог.

## 13. Micro-interactions у Next.js

У Next.js App Router компоненти, які використовують `useState`, `onClick` та інші клієнтські можливості React, мають бути Client Components.

На початку такого файлу використовують директиву:

    "use client";

Наприклад, для інтерактивної кнопки, перемикача теми або відкриття меню.

Не потрібно робити весь застосунок клієнтським лише заради однієї мікровзаємодії. Інтерактивний компонент можна винести в окремий Client Component, а решту сторінки залишити Server Components.

## 14. Доступність мікровзаємодій

Мікровзаємодії повинні бути доступними для людей, які користуються клавіатурою, екранними читачами або мають підвищену чутливість до руху.

### Основні правила

✔ Інтерактивні елементи мають бути доступними з клавіатури.

✔ Фокус повинен залишатися видимим.

✔ Не можна передавати важливу інформацію тільки кольором.

✔ Повідомлення про успіх або помилку повинні бути зрозумілими.

✔ Кнопки й перемикачі повинні мати доступні назви.

✔ Анімація не повинна блокувати основну дію.

✔ Автоматичний рух не повинен бути надмірним.

✔ Варто враховувати налаштування `prefers-reduced-motion`.

### Підтримка reduced motion

Користувач може налаштувати операційну систему так, щоб зменшити кількість анімацій.

    @media (prefers-reduced-motion: reduce) {
      *,
      *::before,
      *::after {
        animation-duration: 0.01ms !important;
        animation-iteration-count: 1 !important;
        transition-duration: 0.01ms !important;
        scroll-behavior: auto !important;
      }
    }

Це загальний варіант для невеликого проєкту. У складнішому інтерфейсі краще вибірково прибирати необов'язкові рухи, залишаючи важливий зворотний зв'язок.

Наприклад, індикатор завантаження можна зробити статичним, якщо безперервне обертання створює дискомфорт.

## 15. Мікровзаємодії та продуктивність

Надмірні анімації можуть погіршувати продуктивність, особливо на слабких пристроях.

### Практичні рекомендації

- Віддавай перевагу `transform` та `opacity` для простих анімацій.
- Не запускай багато нескінченних анімацій одночасно.
- Не анімуй великі ділянки сторінки без необхідності.
- Не використовуй рух там, де достатньо зміни кольору або тексту.
- Перевіряй інтерфейс на мобільних пристроях.
- Використовуй DevTools для аналізу rendering performance.
- Переконайся, що анімації не заважають прокручуванню та введенню даних.

`will-change` не потрібно додавати до всіх елементів за замовчуванням. Це підказка браузеру, яка може збільшити споживання ресурсів. Використовуй її лише за наявності обґрунтованої потреби.

## 16. Поширені помилки

### Помилка 1. Анімація заради анімації

Якщо рух нічого не пояснює, він може відволікати користувача.

**Рішення:** кожна мікровзаємодія повинна мати функціональну або змістовну мету.

### Помилка 2. Надто довгі переходи

Кнопка повільно змінює колір або меню довго відкривається.

**Рішення:** скорочуй тривалість і перевіряй відчуття швидкості на реальному пристрої.

### Помилка 3. Hover є єдиним сигналом

Користувач на телефоні не отримує аналогічного зворотного зв'язку.

**Рішення:** передбачай зрозумілі стани натискання, фокуса та поточного стану компонента.

### Помилка 4. Важлива інформація передається лише кольором

Користувач може не помітити або не розрізнити зміну кольору.

**Рішення:** доповнюй колір текстом, іконкою або іншим сигналом.

### Помилка 5. Відсутність стану завантаження

Користувач натискає кнопку кілька разів, бо не бачить реакції.

**Рішення:** показуй loading-стан і, якщо це доречно, блокуй повторне надсилання до завершення операції.

### Помилка 6. Занадто сильне збільшення елементів

Картки або кнопки різко змінюють розмір і порушують композицію.

**Рішення:** використовуй невеликі значення `scale()` або обмежуй ефект зміною кольору й тіні.

### Помилка 7. Ігнорування клавіатурного фокуса

Користувач не бачить, який елемент активний.

**Рішення:** додавай виразний `:focus-visible`.

### Помилка 8. Анімація без урахування reduced motion

Деякі користувачі можуть відчувати дискомфорт від руху.

**Рішення:** підтримуй `prefers-reduced-motion`.

### Помилка 9. Візуальний стан не відповідає реальному

Кнопка показує «Збережено», хоча сервер не підтвердив збереження.

**Рішення:** повідомляй про успіх тільки після підтвердження операції. Якщо запит не вдався, покажи помилку та спосіб повторити дію.

## 17. Best practices — найкращі практики

✔ Використовуй мікровзаємодії для пояснення стану інтерфейсу.

✔ Додавай зворотний зв'язок після значущих дій.

✔ Встановлюй коротку, але достатню тривалість переходів.

✔ Дотримуйся єдиного стилю анімацій у всьому продукті.

✔ Перевіряй hover, focus, active, disabled і loading там, де вони потрібні.

✔ Підтримуй клавіатурну навігацію.

✔ Враховуй `prefers-reduced-motion`.

✔ Не використовуй рух як заміну текстовим повідомленням.

✔ Не змушуй користувача чекати завершення декоративної анімації.

✔ Підтверджуй успіх лише після фактичного завершення операції.

✔ Перевіряй мікровзаємодії на різних розмірах екрана.

✔ Пам'ятай: якісна мікровзаємодія часто майже непомітна, але робить інтерфейс зрозумілішим.

## 18. Практичний мініпроєкт: інтерактивна кнопка з повідомленням

Мета — створити кнопку, яка:

- реагує на натискання;
- показує стан завантаження;
- повідомляє про успіх;
- не дозволяє повторно натиснути кнопку під час виконання операції;
- підтримує зменшення руху.

### script.js

    "use strict";

    const actionButton = document.querySelector(".action-button");
    const buttonLabel = document.querySelector(".button-label");
    const statusMessage = document.querySelector(".status-message");

    actionButton.addEventListener("click", async () => {
      actionButton.disabled = true;
      buttonLabel.textContent = "Збереження…";
      statusMessage.textContent = "";

      try {
        // Імітація короткої асинхронної операції.
        await new Promise((resolve) => setTimeout(resolve, 800));

        buttonLabel.textContent = "Збережено";
        statusMessage.textContent = "Зміни успішно збережено.";
      } catch {
        buttonLabel.textContent = "Спробувати ще раз";
        statusMessage.textContent = "Не вдалося зберегти зміни.";
      } finally {
        actionButton.disabled = false;
      }
    });

У цьому прикладі `setTimeout` лише імітує асинхронну операцію. У справжньому застосунку його замінюють на запит до API та обробляють реальні успіхи й помилки.

- [ ] Під час операції кнопка показує «Збереження…».
- [ ] Повторне натискання під час операції неможливе.
- [ ] Після завершення користувач бачить повідомлення.
- [ ] Кнопкою можна користуватися з клавіатури.
- [ ] Фокус добре помітний.
- [ ] За ввімкненого `prefers-reduced-motion` перехід не відтворюється.

## 21. Що потрібно запам'ятати

- **Micro-interaction** — невелика реакція інтерфейсу на дію або подію.
- **Trigger** запускає взаємодію.
- **Feedback** пояснює користувачеві результат.
- `transition` створює плавний перехід між станами.
- `animation` описує послідовність кадрів.
- Мікровзаємодії допомагають показувати стани кнопок, форм, меню та інших компонентів.
- Візуальний стан повинен відповідати реальному стану системи.
- Loading, success та error — важливі стани асинхронних операцій.
- Анімації мають бути короткими, передбачуваними та доречними.
- Доступність і підтримка `prefers-reduced-motion` — частина якісного UI.
- Надмірні ефекти можуть відволікати користувача та погіршувати продуктивність.
- Найкраща мікровзаємодія допомагає користувачеві зрозуміти інтерфейс, а не привертає увагу лише до себе.
