# 06. Icon Size — Розміри іконок у UI-дизайні

Розмір іконки (icon size) — це фізичний або логічний розмір графічного символу в інтерфейсі, який впливає на його помітність, читабельність, візуальну вагу та зручність взаємодії.

Розмір іконок важливий для навігації, кнопок, форм, карток, панелей інструментів, мобільних застосунків і дизайн-систем.

**Головна мета правильного вибору розміру іконки — зробити її достатньо помітною, не порушуючи візуальний баланс інтерфейсу.**

Важливо розрізняти три поняття:

- **Icon size** — розмір самої графічної іконки.
- **Container size** — розмір контейнера, у якому розташована іконка.
- **Target size** — розмір клікабельної або інтерактивної області.

Ці значення можуть відрізнятися. Наприклад, іконка може мати розмір 20 × 20 px, перебуваючи в кнопці розміром 44 × 44 px.

---

## 1. Основи розміру іконок

### 1.1. Що таке icon size

Icon size — це ширина та висота графічного символу, які визначають, наскільки великим він відображається в інтерфейсі.

Наприклад:

    width: 16px;
    height: 16px;

Або:

    width: 24px;
    height: 24px;

Розмір іконки впливає на:

- Помітність.
- Читабельність деталей.
- Візуальну вагу.
- Відстань до тексту.
- Баланс між елементами.
- Зручність використання на різних пристроях.

### 1.2. Чому розмір має значення

Якщо іконка занадто мала:

- Її складно розпізнати.
- Тонкі лінії можуть втрачати чіткість.
- Вона може губитися поруч із текстом.
- Інтерфейс стає менш зрозумілим.

Якщо іконка занадто велика:

- Вона відволікає від основного вмісту.
- Порушує пропорції кнопки.
- Збільшує візуальну вагу другорядних елементів.
- Може погіршувати щільність інтерфейсу.

**Правило:** розмір іконки потрібно вибирати відповідно до її призначення, контексту та важливості.

### 1.3. Розмір іконки не дорівнює її важливості

Велика іконка не обов'язково означає важливішу дію.

Наприклад:

    Основна дія:
    [ + ] Створити курс

    Другорядна дія:
    [⚙] Налаштування

У реальному інтерфейсі обидві іконки можуть мати однаковий розмір, але відрізнятися кольором, розташуванням, типом кнопки або візуальним акцентом.

Розмір — лише один з інструментів візуальної ієрархії.

---

## 2. Основні розміри іконок

Для більшості вебінтерфейсів зручно використовувати невелику шкалу стандартних розмірів.

### 2.1. Типова шкала

Наведені значення — практичні орієнтири, а не обов'язковий стандарт.

| Розмір | Типове використання |
|---|---|
| 12 px | Дуже дрібні допоміжні символи |
| 16 px | Компактні елементи, невеликі кнопки |
| 20 px | Іконки в стандартних кнопках і формах |
| 24 px | Основна навігація та типові елементи керування |
| 32 px | Великі кнопки, акцентні компоненти |
| 40 px | Великі візуальні елементи |
| 48 px | Ілюстративні блоки, порожні стани |
| 64 px і більше | Великі ілюстрації та спеціальні сценарії |

Не потрібно використовувати всі ці розміри в одному проєкті.

Для невеликого вебзастосунку часто достатньо шкали:

    16px
    20px
    24px
    32px

### 2.2. Маленькі іконки — 12–16 px

Застосовуються для:

- Допоміжних позначок.
- Компактних кнопок.
- Невеликих індикаторів.
- Іконок поруч із дрібним текстом.
- Щільних таблиць і списків.

Приклад:

    Завантажено [✓]

Маленькі іконки потрібно перевіряти особливо уважно, оскільки тонкі деталі можуть бути непомітними.

Не варто зменшувати складну іконку до 12 px, якщо її важко розпізнати.

### 2.3. Середні іконки — 20–24 px

Це поширений діапазон для стандартних вебінтерфейсів.

Застосування:

- Навігація.
- Кнопки.
- Поля форм.
- Панелі інструментів.
- Елементи списків.
- Картки.
- Дії користувача.

Приклад:

    [Search] Пошук
    [User] Профіль
    [Settings] Налаштування

Для більшості типових функціональних іконок починай із 20 або 24 px, а потім перевіряй результат у контексті.

### 2.4. Великі іконки — 32–48 px

Застосовуються для:

- Великих кнопок.
- Карток категорій.
- Інформаційних блоків.
- Статусних повідомлень.
- Порожніх станів.
- Елементів onboarding.

Приклад:

    [BookOpen — 40px]

    Навчальні курси

    Переглядайте матеріали та виконуйте завдання.

Великі іконки зазвичай потребують більше вільного простору навколо.

### 2.5. Дуже великі іконки — 64 px і більше

Можуть використовуватися для:

- Ілюстративних блоків.
- Порожніх сторінок.
- Вітальних екранів.
- Спеціальних статусних повідомлень.
- Великих категорій на стартовій сторінці.

У таких випадках іконка іноді виконує роль невеликої ілюстрації.

Не варто використовувати дуже великі іконки в кожній картці або кнопці: це може зробити інтерфейс перевантаженим.

## 3. Icon size, container size і target size

Це одне з найважливіших розрізнень у роботі з іконками.

### 3.1. Icon size — розмір графічного символу

Визначає розмір самої іконки.

Приклад:

    width: 20px;
    height: 20px;

### 3.2. Container size — розмір контейнера

Контейнер визначає простір, у якому розміщується іконка.

Приклад:

    Контейнер: 40 × 40 px
    Іконка:    20 × 20 px

Контейнер може мати фон, рамку, заокруглення та внутрішні відступи.

### 3.3. Target size — інтерактивна область

Target size — це область, на яку користувач може натиснути або з якою може взаємодіяти.

Наприклад:

    Клікабельна область: 44 × 44 px
    Іконка:             20 × 20 px

Це дозволяє зробити кнопку зручною для натискання, не збільшуючи сам символ.

### 3.4. Приклад у CSS

    .icon-button {
        display: inline-flex;
        align-items: center;
        justify-content: center;

        width: 44px;
        height: 44px;

        padding: 0;
        border: none;
        border-radius: 8px;
    }

    .icon-button__icon {
        width: 20px;
        height: 20px;
        flex: 0 0 auto;
    }

Тут:

- Кнопка має розмір 44 × 44 px.
- Іконка має розмір 20 × 20 px.
- Іконка розташована по центру кнопки.

### 3.5. Чому не можна плутати ці поняття

Якщо збільшити саму іконку замість інтерактивної області, можна отримати:

- Надто великі символи.
- Порушення візуального балансу.
- Незручні пропорції кнопок.
- Нерівномірну навігацію.

Краще залишити іконку відповідного розміру, а контейнер зробити достатнім для взаємодії.

---

## 4. Розміри іконок і візуальна ієрархія

### 4.1. Що таке візуальна ієрархія

Візуальна ієрархія — це порядок, у якому користувач помічає та сприймає елементи інтерфейсу.

Її створюють за допомогою:

- Розміру.
- Кольору.
- Контрасту.
- Положення.
- Відступів.
- Типографіки.
- Візуальної ваги.

Розмір іконки є лише одним із цих інструментів.

### 4.2. Основні та другорядні дії

Приклад панелі інструментів:

    [Save] [Download] [Share] [More]

Усі іконки можуть мати розмір 20 px, але кнопка збереження може бути візуально виділена фоном або кольором.

Не потрібно збільшувати іконку кожної основної дії без потреби.

### 4.3. Розмір іконки в картці

Приклад:

    [BookOpen — 32px]

    Основи JavaScript

    12 уроків · Початковий рівень

    [ArrowRight — 20px] Переглянути курс

Тут більша іконка позначає категорію, а менша — дію переходу.

Це допомагає розрізняти типи елементів.

### 4.4. Не створюй зайвої ієрархії

Якщо всі іконки мають різні розміри без зрозумілої причини, інтерфейс може виглядати хаотично.

Використовуй обмежену шкалу й визначай, у яких компонентах дозволений кожен розмір.

---

## 5. Візуальний розмір іконки

### 5.1. Чому однакові розміри виглядають по-різному

Дві іконки з розмірами 24 × 24 px можуть сприйматися по-різному.

Наприклад:

- Суцільне коло виглядає масивнішим за тонкий контур.
- Іконка з довгими діагональними лініями може здаватися більшою.
- Іконка з великими внутрішніми відступами може здаватися меншою.
- Асиметрична іконка може здаватися зміщеною.

Тому важливо розрізняти математичний і візуальний розмір.

### 5.2. Оптичне вирівнювання

Оптичне вирівнювання — це візуальна корекція положення елемента, щоб він здавався правильно розташованим.

Наприклад, геометрично центрована стрілка може здаватися зміщеною відносно тексту.

Під час перевірки оцінюй:

- Чи розташована іконка по центру кнопки?
- Чи збалансовані відступи?
- Чи не виглядає вона занадто маленькою?
- Чи відповідає її візуальна вага сусіднім символам?

Не потрібно коригувати кожну іконку вручну. Використовуй такі зміни лише тоді, коли є помітна проблема.

### 5.3. Внутрішні відступи SVG

SVG може мати координатну область 24 × 24, але видима форма займатиме лише частину цієї області.

Приклад:

    viewBox="0 0 24 24"

Не гарантує, що видима форма заповнить усі 24 px.

Тому перед зміною CSS-розміру варто перевірити саму геометрію іконки.

### 5.4. Як виправити візуально маленьку іконку

Послідовність перевірки:

1. Переконайся, що CSS-розмір правильний.
2. Перевір внутрішні відступи SVG.
3. Перевір товщину ліній.
4. Порівняй іконку з іншими символами набору.
5. За потреби вибери іншу іконку з тієї самої бібліотеки.

Не збільшуй усі іконки автоматично лише тому, що одна з них виглядає малою.

## 6. Розмір іконок у кнопках

### 6.1. Кнопка з текстом

Приклад:

    [Plus — 20px] Додати курс

Для стандартної кнопки часто підходять іконки розміром 16–20 px, але остаточне значення залежить від розміру тексту та висоти кнопки.

CSS:

    .button {
        display: inline-flex;
        align-items: center;
        justify-content: center;
        gap: 8px;

        padding: 10px 16px;
        font-size: 16px;
        line-height: 1.5;
    }

    .button__icon {
        width: 20px;
        height: 20px;
        flex: 0 0 auto;
    }

### 6.2. Компактна кнопка

Для компактних кнопок можна використовувати іконки 16 px.

Приклад:

    [Copy — 16px] Копіювати

Не зменшуй іконку до такого розміру, якщо її форма стає важкою для розпізнавання.

### 6.3. Велика кнопка

Для великої кнопки можна використовувати іконку 24 px.

Приклад:

    [Download — 24px] Завантажити файл

Розмір іконки повинен бути пропорційним висоті кнопки.

### 6.4. Кнопка лише з іконкою

Приклад:

    [Search — 20px]

Можлива конфігурація:

    .icon-button {
        width: 44px;
        height: 44px;
        display: inline-flex;
        align-items: center;
        justify-content: center;
    }

    .icon-button svg {
        width: 20px;
        height: 20px;
    }

Не забувай про доступну назву:

    <button
        type="button"
        class="icon-button"
        aria-label="Відкрити пошук"
    >
        <svg
            viewBox="0 0 24 24"
            aria-hidden="true"
        >
            <!-- Геометрія іконки -->
        </svg>
    </button>

### 6.5. Розмір іконки та висота кнопки

Іконка не повинна випадково збільшувати висоту кнопки або порушувати вирівнювання.

Використовуй:

    display: inline-flex;
    align-items: center;
    gap: 8px;

Для SVG часто корисно:

    display: block;
    flex: 0 0 auto;

Це допомагає контролювати геометрію компонента.

## 7. Розмір іконок у формах

### 7.1. Іконка всередині поля

Приклад:

    [Mail] [name@example.com]

Для стандартного поля можна почати з 16–20 px.

Але іконка не повинна замінювати підпис поля.

### 7.2. Іконка показу пароля

Приклад:

    Пароль
    [••••••••••••] [Eye — 20px]

Іконка показу пароля є інтерактивним елементом. Для неї потрібно передбачити:

- Достатній розмір клікабельної області.
- Зрозумілий стан.
- Доступну назву.
- Можливість керування клавіатурою.

### 7.3. Іконки помилок

Приклад:

    [CircleAlert — 16px] Введіть коректну адресу електронної пошти.

Для повідомлень про помилки зазвичай не потрібні дуже великі іконки. Головне — достатній контраст і зрозумілий текст.

### 7.4. Узгодженість із текстом

Якщо іконка розташована поруч із текстом, перевір:

- Висоту рядка.
- Вертикальне вирівнювання.
- Відстань між елементами.
- Оптичний розмір.
- Читабельність у вузькому полі.

---

## 8. Розмір іконок у навігації

### 8.1. Header

Для верхньої панелі можна почати з розміру 20–24 px.

Приклад:

    [Search — 20px]
    [Bell — 20px]
    [User — 20px]

Вибір залежить від висоти панелі та щільності інтерфейсу.

### 8.2. Sidebar

Для бічної навігації часто використовують 20–24 px.

Приклад:

    [Home — 24px] Головна
    [Book — 24px] Курси
    [Calendar — 24px] Розклад
    [Settings — 24px] Налаштування

Однакові розміри полегшують вирівнювання елементів.

### 8.3. Bottom navigation

У мобільній нижній навігації можна почати з іконок 24 px.

Приклад:

    [Home]       [Search]       [Profile]
    Головна      Пошук          Профіль

Перевіряй не тільки розмір символу, а й відстань між інтерактивними областями.

### 8.4. Активний елемент

Активна іконка може відрізнятися кольором або стилем.

Наприклад:

    Неактивна: Outline, 24px
    Активна: Filled, 24px

Не обов'язково змінювати розмір активної іконки. Часто достатньо кольору, фону або іншого узгодженого індикатора.

---

## 9. Розмір іконок у картках і дашбордах

### 9.1. Картки категорій

Для карток категорій можна використовувати 24–40 px залежно від композиції.

Приклад:

    [BookOpen — 32px]

    Навчання

    Матеріали та курси

Великі іконки можуть допомагати швидко розпізнавати категорії.

### 9.2. Картки статистики

Приклад:

    [Users — 24px]

    125

    Користувачів

Для компактних статистичних карток достатньо невеликої іконки, яка підтримує заголовок або показник.

### 9.3. Статусні картки

Приклад:

    [CircleCheck — 24px]

    Успішно завершено

Розмір залежить від важливості повідомлення та структури картки.

### 9.4. Порожні стани

Приклад:

    [FolderOpen — 48px]

    Поки що немає файлів

    Додайте перший файл, щоб почати роботу.

У порожніх станах великі іконки можуть виконувати роль візуальної ілюстрації.

### 9.5. Не перевантажуй картки

Якщо кожна картка має велику іконку, жирний заголовок, яскравий фон і додаткові декоративні символи, візуальна ієрархія може стати нечіткою.

Вибирай розмір відповідно до ролі іконки.

## 10. Розмір іконок у Figma

### 10.1. Робота з розмірами

У Figma можна задавати ширину та висоту векторного об'єкта або компонента.

Приклади:

    Icon / 16
    Icon / 20
    Icon / 24
    Icon / 32

Зручно почати з основної шкали та застосовувати її в різних компонентах.

### 10.2. Створення компонентів

Можна створити базові компоненти:

    Icon / Search / 16
    Icon / Search / 20
    Icon / Search / 24

Але не потрібно вручну дублювати всі іконки для кожного можливого розміру, якщо Figma-компоненти або кодові компоненти дозволяють гнучко змінювати розмір.

### 10.3. Варіанти компонента

Можна організувати компонент через властивість Size:

    Icon
    ├── Size: Small
    ├── Size: Medium
    ├── Size: Large
    └── Size: Extra Large

Наприклад:

    Small: 16px
    Medium: 20px
    Large: 24px
    Extra Large: 32px

Використовуй зрозумілі назви та однакові правила в усій дизайн-системі.

### 10.4. Вирівнювання в Auto Layout

Якщо іконка розташована поруч із текстом, Auto Layout допомагає контролювати:

- Відстань між іконкою та текстом.
- Вертикальне вирівнювання.
- Внутрішні відступи.
- Поведінку компонента при зміні тексту.

Приклад структури:

    Button
    ├── Icon
    └── Label

Не потрібно використовувати ручне позиціювання для кожної кнопки, якщо можна створити компонент із повторюваними правилами.

### 10.5. Перевірка оптичного розміру

Після встановлення однакових числових розмірів порівняй іконки поруч.

Перевір:

- Чи не виглядає одна іконка значно меншою?
- Чи однакова візуальна вага?
- Чи узгоджені товщина ліній і контраст?
- Чи правильно вони розташовані в кнопках?

## 11. Розмір іконок у CSS

### 11.1. Фіксований розмір

Найпростіший варіант:

    .icon {
        width: 24px;
        height: 24px;
    }

Підходить для стандартних іконок у більшості компонентів.

### 11.2. CSS-змінні

Для дизайн-системи зручно створити змінні.

    :root {
        --icon-size-sm: 16px;
        --icon-size-md: 20px;
        --icon-size-lg: 24px;
        --icon-size-xl: 32px;
    }

Використання:

    .icon--small {
        width: var(--icon-size-sm);
        height: var(--icon-size-sm);
    }

    .icon--medium {
        width: var(--icon-size-md);
        height: var(--icon-size-md);
    }

    .icon--large {
        width: var(--icon-size-lg);
        height: var(--icon-size-lg);
    }

    .icon--extra-large {
        width: var(--icon-size-xl);
        height: var(--icon-size-xl);
    }

### 11.3. Використання `em`

`em` дозволяє задавати розмір відносно розміру шрифту поточного елемента.

Приклад:

    .button {
        font-size: 16px;
    }

    .button__icon {
        width: 1.25em;
        height: 1.25em;
    }

Якщо шрифт кнопки має розмір 16 px, іконка матиме розмір 20 px.

Це може бути зручним для компонентів, де розмір іконки повинен змінюватися разом із текстом.

Враховуй, що `em` залежить від контексту CSS, тому перевіряй його поведінку у вкладених компонентах.

### 11.4. Використання `rem`

`rem` залежить від розміру шрифту кореневого елемента.

Якщо базовий розмір становить 16 px:

    1rem = 16px
    1.25rem = 20px
    1.5rem = 24px
    2rem = 32px

Приклад:

    .icon {
        width: 1.5rem;
        height: 1.5rem;
    }

Цей варіант дає розмір 24 px за стандартного кореневого розміру шрифту 16 px.

### 11.5. Коли використовувати px, em або rem

| Одиниця | Коли доречна |
|---|---|
| `px` | Коли потрібен точний розмір іконки |
| `em` | Коли розмір має залежати від шрифту компонента |
| `rem` | Коли розмір має залежати від кореневої типографіки |

Не існує універсально найкращої одиниці. Вибирай її відповідно до поведінки компонента.

### 11.6. Запобігання стисканню

У Flexbox іконка може стискатися, якщо контейнеру бракує місця.

Приклад:

    .icon {
        width: 20px;
        height: 20px;
        flex: 0 0 auto;
    }

Це допомагає зберігати визначений розмір іконки.

## 12. Розмір SVG-іконок

### 12.1. Атрибути `width` і `height`

SVG може містити власні розміри.

Приклад:

    <svg
        width="24"
        height="24"
        viewBox="0 0 24 24"
        xmlns="http://www.w3.org/2000/svg"
        aria-hidden="true"
    >
        <!-- Геометрія іконки -->
    </svg>

CSS може задавати розмір окремо:

    .icon {
        width: 20px;
        height: 20px;
    }

У реальному проєкті потрібно уникати конфліктних правил, коли HTML-атрибути та CSS несподівано задають різні розміри.

### 12.2. Значення `viewBox`

`viewBox` задає координатну систему SVG.

Приклад:

    viewBox="0 0 24 24"

Він допомагає масштабувати графіку відповідно до ширини та висоти елемента.

Проте `viewBox` не гарантує, що видима геометрія заповнюватиме всю площу.

### 12.3. Збереження пропорцій

Більшість іконок мають квадратну композицію.

Зазвичай використовують:

    width: 24px;
    height: 24px;

Не розтягуй квадратну іконку, наприклад, до 24 × 16 px, якщо це спотворює її геометрію.

Для SVG з іншими пропорціями використовуй розміри, що відповідають його формі.

### 12.4. Розмір і товщина ліній

Під час зменшення SVG разом із ним можуть візуально зменшуватися й лінії.

Якщо іконка погано читається на малому розмірі:

- Перевір, чи підходить вона для цього масштабу.
- Спробуй простіший варіант.
- Перевір товщину ліній.
- Переконайся, що бібліотека підтримує потрібний стиль.

Не намагайся вирішити кожну проблему простим збільшенням розміру.

## 13. Розмір іконок у React

### 13.1. Використання Lucide React

Після встановлення пакета `lucide-react` можна задавати розмір через властивість `size`.

    import { Search } from "lucide-react";

    export default function SearchIcon() {
        return (
            <Search size={24} aria-hidden="true" />
        );
    }

У цьому прикладі іконка має розмір 24 px.

### 13.2. Іконка з текстом

    import { Search } from "lucide-react";

    export default function SearchButton() {
        return (
            <button type="button">
                <Search size={20} aria-hidden="true" />
                <span>Пошук</span>
            </button>
        );
    }

Іконка має розмір 20 px, а текст пояснює призначення кнопки.

### 13.3. Повторне використання розмірів

Щоб не повторювати числові значення в багатьох компонентах, можна створити спільні константи.

    export const ICON_SIZE = {
        small: 16,
        medium: 20,
        large: 24,
        extraLarge: 32,
    } as const;

Використання:

    import { Search } from "lucide-react";
    import { ICON_SIZE } from "./icon-size";

    export default function SearchIcon() {
        return (
            <Search
                size={ICON_SIZE.large}
                aria-hidden="true"
            />
        );
    }

`as const` зберігає конкретні числові значення як вузькі типи TypeScript.

### 13.4. Компонент-обгортка для іконок

У великому проєкті можна створити компонент для узгодженого відображення іконок.

Приклад:

    import type { ReactNode } from "react";

    type IconWrapperProps = {
        children: ReactNode;
        size?: number;
    };

    export function IconWrapper({
        children,
        size = 24,
    }: IconWrapperProps) {
        return (
            <span
                style={{
                    display: "inline-flex",
                    alignItems: "center",
                    justifyContent: "center",
                    width: size,
                    height: size,
                    flex: "0 0 auto",
                }}
            >
                {children}
            </span>
        );
    }

Цей приклад задає розмір контейнера. Сам SVG усередині також потрібно налаштувати відповідно до потрібного розміру.

Не створюй обгортку без потреби: якщо бібліотека вже забезпечує достатній контроль над розміром, пряме використання може бути простішим.

## 14. Адаптивний розмір іконок

### 14.1. Чи потрібно змінювати розмір на мобільному

Не кожна іконка повинна автоматично змінювати розмір на мобільному пристрої.

У багатьох випадках достатньо:

- Зберегти розмір символу.
- Збільшити клікабельну область.
- Змінити відступи.
- Перебудувати розташування компонентів.

Наприклад, іконка 24 px може залишатися 24 px на всіх екранах, тоді як розмір кнопки змінюється.

### 14.2. Адаптивні розміри через media queries

Якщо дизайн справді потребує різних розмірів:

    .navigation__icon {
        width: 24px;
        height: 24px;
    }

    @media (max-width: 600px) {
        .navigation__icon {
            width: 22px;
            height: 22px;
        }
    }

Це лише приклад. Зменшення іконок на мобільному не є обов'язковим правилом.

### 14.3. Використання `clamp()`

`clamp()` дозволяє задавати мінімальний, гнучкий і максимальний розмір.

Приклад:

    .hero__icon {
        width: clamp(32px, 4vw, 48px);
        height: clamp(32px, 4vw, 48px);
    }

Розмір змінюватиметься в межах 32–48 px залежно від ширини вікна.

Такий підхід може бути корисним для великих декоративних іконок.

Для маленьких функціональних іконок фіксовані розміри часто простіші та передбачуваніші.

### 14.4. Перевірка адаптивності

Перевір:

- Чи залишаються іконки чіткими?
- Чи не стискаються вони?
- Чи не перекривають текст?
- Чи зберігається відстань між елементами?
- Чи зручно натискати на кнопки?
- Чи не змінюється візуальна ієрархія без потреби?

## 15. Розмір іконок і доступність

### 15.1. Не плутай розмір іконки з доступністю

Велика іконка не гарантує доступності.

Потрібно також враховувати:

- Контраст.
- Зрозумілість символу.
- Доступну назву.
- Керування клавіатурою.
- Видимий фокус.
- Розмір інтерактивної області.

### 15.2. Розмір цілі натискання

WCAG 2.2, критерій 2.5.8 Target Size (Minimum), визначає мінімальний розмір цілі 24 × 24 CSS px з певними винятками.

Для зручної взаємодії на сенсорних пристроях часто використовують інтерактивні області близько 44 × 44 px або більші.

Це рекомендація для зручності, а не вимога збільшувати саму графічну іконку до такого розміру.

### 15.3. Контраст і читабельність

Функціональна іконка повинна достатньо відрізнятися від фону.

Перевір:

- Світлу тему.
- Темну тему.
- Стан наведення.
- Стан фокуса.
- Вимкнений стан.
- Активний стан.

Якщо іконка важлива для розуміння інтерфейсу, її форма та контраст повинні залишатися зрозумілими.

### 15.4. Доступна назва

Для кнопки лише з іконкою:

    <button type="button" aria-label="Відкрити налаштування">
        <svg aria-hidden="true" viewBox="0 0 24 24">
            <!-- Геометрія іконки -->
        </svg>
    </button>

Розмір іконки не впливає на необхідність доступної назви.

### 15.5. Масштабування інтерфейсу

Перевіряй, чи не ламається компонент, коли користувач збільшує масштаб сторінки або змінює налаштування тексту.

Іконка не повинна:

- Перекривати текст.
- Виходити за межі кнопки.
- Зникати через обрізання.
- Руйнувати структуру форми.

## 16. Типові помилки

### 16.1. Усі іконки мають однаковий розмір

Однаковий розмір не завжди правильний.

Маленька допоміжна іконка та велика ілюстративна іконка виконують різні функції.

**Рішення:** визначити невелику шкалу розмірів і правила використання.

### 16.2. Забагато різних розмірів

Якщо кожна іконка має довільну ширину й висоту, інтерфейс стає непослідовним.

**Рішення:** створити обмежену шкалу, наприклад 16, 20, 24 і 32 px.

### 16.3. Збільшення іконки замість контейнера

Це часто призводить до непропорційно великих символів.

**Рішення:** залишити іконку відповідного розміру, а клікабельну область збільшити через розміри кнопки та відступи.

### 16.4. Ігнорування візуального розміру

Дві іконки з однаковими CSS-розмірами можуть мати різну візуальну вагу.

**Рішення:** перевіряти іконки поруч у реальному інтерфейсі.

### 16.5. Спотворення пропорцій

Непропорційне масштабування може деформувати символ.

**Рішення:** зберігати співвідношення ширини та висоти SVG.

### 16.6. Іконка стискається у Flexbox

Якщо контейнер вузький, іконка може втратити заданий розмір.

**Рішення:**

    .icon {
        flex: 0 0 auto;
    }

### 16.7. Надто дрібні деталі

Складна іконка може погано читатися на малому розмірі.

**Рішення:** вибрати простішу іконку або відповідний варіант із бібліотеки.

### 16.8. Розмір не відповідає тексту

Маленька іконка поруч із великим заголовком може виглядати випадково.

**Рішення:** перевірити співвідношення іконки, шрифту та висоти рядка.

### 16.9. Зменшення іконок на мобільному без причини

Мобільний інтерфейс не обов'язково потребує менших іконок.

**Рішення:** спочатку перевірити композицію та інтерактивні області.

### 16.10. Зміна розміру активної іконки

Якщо активний стан збільшує іконку, це може зміщувати сусідні елементи.

**Рішення:** використовувати колір, фон або інший індикатор активності, якщо зміна розміру не є частиною задуманого дизайну.

## 17. Практичні правила

✔ Починай із розміру 20 або 24 px для типових функціональних іконок.

✔ Використовуй обмежену шкалу розмірів.

✔ Відокремлюй розмір іконки від розміру контейнера.

✔ Відокремлюй розмір контейнера від клікабельної області.

✔ Перевіряй оптичний розмір, а не лише CSS-значення.

✔ Зберігай пропорції SVG.

✔ Використовуй `flex: 0 0 auto`, якщо іконка не повинна стискатися.

✔ Використовуй CSS-змінні для спільних розмірів.

✔ Застосовуй `em`, якщо іконка повинна масштабуватися відносно тексту.

✔ Використовуй `rem`, якщо розмір має залежати від кореневої типографіки.

✔ Не збільшуй іконку лише для того, щоб зробити кнопку зручнішою для натискання.

✔ Перевіряй іконки у світлій і темній темах.

✔ Переконайся, що дрібні символи залишаються читабельними.

✔ Не змінюй розмір активної іконки без дизайнерської причини.

✔ Перевіряй поведінку на різних ширинах екрана.

## 18. Мініпроєкт: шкала розмірів іконок

### Мета

Створити просту систему розмірів іконок для навчальної платформи.

### Крок 1. Визначити шкалу

    Small: 16px
    Medium: 20px
    Large: 24px
    Extra Large: 32px

### Крок 2. Створити CSS-змінні

    :root {
        --icon-size-sm: 16px;
        --icon-size-md: 20px;
        --icon-size-lg: 24px;
        --icon-size-xl: 32px;
    }

### Крок 3. Застосувати розміри

    .icon--small {
        width: var(--icon-size-sm);
        height: var(--icon-size-sm);
    }

    .icon--medium {
        width: var(--icon-size-md);
        height: var(--icon-size-md);
    }

    .icon--large {
        width: var(--icon-size-lg);
        height: var(--icon-size-lg);
    }

    .icon--extra-large {
        width: var(--icon-size-xl);
        height: var(--icon-size-xl);
    }

### Крок 4. Визначити розміри для компонентів

    Поля форм: 16–20px
    Стандартні кнопки: 20px
    Навігація: 24px
    Картки категорій: 32px
    Порожні стани: 48px

Це початкові орієнтири, які потрібно перевірити на реальних компонентах.

### Крок 5. Створити приклади

Зроби такі компоненти:

- Кнопка з іконкою та текстом.
- Кнопка лише з іконкою.
- Поле пошуку.
- Елемент бічної навігації.
- Картка курсу.
- Статусне повідомлення.
- Порожній стан списку.

### Крок 6. Перевірити результат

- [ ] Іконки мають узгоджені розміри.
- [ ] Іконки не стискаються.
- [ ] Текст та іконки вирівняні.
- [ ] Кнопки мають зручну клікабельну область.
- [ ] Дрібні символи залишаються читабельними.
- [ ] Великі іконки не перевантажують композицію.
- [ ] Розміри залишаються доречними на мобільному.
- [ ] Інтерактивні елементи доступні з клавіатури.

---

## 19. Чекліст перевірки розмірів іконок

Перед завершенням дизайну перевір:

- [ ] Для іконок визначено основну шкалу розмірів.
- [ ] Розміри відповідають призначенню компонентів.
- [ ] Немає зайвих довільних значень.
- [ ] Іконки мають правильні пропорції.
- [ ] Візуальний розмір узгоджений між різними символами.
- [ ] Іконки не виглядають надто дрібними.
- [ ] Великі іконки не перетягують увагу без потреби.
- [ ] Відступи між іконками та текстом достатні.
- [ ] Іконки не стискаються у Flexbox.
- [ ] Розмір інтерактивної області достатній.
- [ ] Іконки читабельні у світлій і темній темах.
- [ ] Розмір не змінюється випадково між станами.
- [ ] Адаптивність перевірена на різних ширинах екрана.
- [ ] Для кнопок лише з іконками передбачено доступні назви.

## 20. Що потрібно запам'ятати

1. Розмір іконки впливає на її помітність, читабельність і візуальну вагу.
2. Icon size, container size і target size — різні поняття.
3. Для типових вебінтерфейсів часто достатньо шкали 16, 20, 24 і 32 px.
4. Для складних іконок надто малий розмір може погіршувати розпізнавання.
5. Однакові CSS-розміри не гарантують однакового візуального розміру.
6. SVG потрібно масштабувати зі збереженням пропорцій.
7. `viewBox` визначає координатну систему SVG, а не гарантований розмір видимої форми.
8. Кнопка може мати розмір 44 × 44 px, навіть якщо іконка має лише 20 × 20 px.
9. Розмір іконки не замінює правильний контраст, доступну назву та видимий фокус.
10. Не потрібно автоматично зменшувати іконки на мобільних пристроях.
11. CSS-змінні допомагають підтримувати узгоджені розміри в дизайн-системі.
12. `em` і `rem` можуть бути корисними, коли розмір іконки має залежати від типографіки.
13. Розмір активної іконки не обов'язково повинен змінюватися.
14. Найкращий розмір — той, що забезпечує читабельність і підтримує композицію інтерфейсу.

## 23. Коротка шпаргалка

| Поняття | Значення |
|---|---|
| Icon size | Розмір графічної іконки |
| Container size | Розмір контейнера іконки |
| Target size | Розмір інтерактивної області |
| 16 px | Компактні іконки |
| 20 px | Стандартні кнопки та поля |
| 24 px | Навігація та типові елементи |
| 32 px | Великі компоненти |
| 48 px | Ілюстративні блоки |
| Optical size | Сприйманий візуальний розмір |
| Optical alignment | Візуальне вирівнювання |
| `width` | Ширина іконки |
| `height` | Висота іконки |
| `viewBox` | Координатна система SVG |
| `px` | Абсолютна CSS-одиниця |
| `em` | Одиниця відносно розміру шрифту |
| `rem` | Одиниця відносно кореневого розміру шрифту |
| `clamp()` | Функція обмеження гнучкого розміру |
| CSS variables | Змінні для повторного використання значень |
| `flex: 0 0 auto` | Заборона стискання елемента у Flexbox |

**Головний принцип:** розмір іконки має відповідати її функції та контексту. Створюй невелику узгоджену шкалу, перевіряй оптичний баланс і пам'ятай, що зручність натискання забезпечує інтерактивна область, а не обов'язково велика графічна іконка.
