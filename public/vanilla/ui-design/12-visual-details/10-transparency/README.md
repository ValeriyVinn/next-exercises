# 10. Transparency — Прозорість в UI-дизайні

Прозорість (Transparency) — це властивість візуального елемента, яка визначає, наскільки крізь нього видно фон або елементи, розташовані позаду.

В UI-дизайні прозорість використовують для створення напівпрозорих поверхонь, накладання кольорів, затемнення зображень, модальних вікон, декоративних ефектів, тіней і багатошарових композицій.

Прозорість допомагає керувати візуальною ієрархією, створювати відчуття глибини та відокремлювати важливі елементи від другорядних.

**Головний принцип:** прозорість повинна допомагати сприймати інтерфейс, а не робити його менш читабельним або передбачуваним.

---

## 1. Основи прозорості

✔ Прозорість визначає, наскільки видно фон крізь елемент.

✔ Непрозорий елемент повністю закриває фон під собою.

✔ Напівпрозорий елемент частково показує фон.

✔ Повністю прозорий елемент не показує власного видимого заповнення.

✔ Прозорість можна застосовувати до кольорів, зображень, фонових шарів і цілих елементів.

✔ Надмірна прозорість може погіршувати читабельність і доступність.

### 1.1. Для чого використовують прозорість

- **Накладання** — розташування напівпрозорого шару поверх іншого елемента.
- **Затемнення** — зменшення візуальної яскравості фону.
- **Підсвічування** — створення м'якого кольорового шару.
- **Глибина** — візуальне відокремлення поверхонь.
- **Модальні вікна** — затемнення сторінки позаду діалогу.
- **Декоративні ефекти** — створення скляних поверхонь, світіння та кольорових плям.
- **Стани інтерфейсу** — відображення неактивних або тимчасово недоступних елементів.
- **Анімація** — плавна поява та зникнення компонентів.

### 1.2. Прозорість і непрозорість

Непрозорість (Opacity) показує, наскільки елемент або його заповнення є видимими.

У CSS властивість `opacity` приймає значення від `0` до `1`.

| Значення | Ефект |
|---|---|
| `opacity: 1` | Повністю непрозорий елемент |
| `opacity: 0.75` | Елемент має 75% непрозорості |
| `opacity: 0.5` | Напівпрозорий елемент |
| `opacity: 0.25` | Елемент має 25% непрозорості |
| `opacity: 0` | Елемент повністю прозорий |

Важливо: `opacity: 0` робить елемент візуально невидимим, але не обов'язково прибирає його з документа, дерева доступності або взаємодії з користувачем.

## 2. Прозорість кольору та opacity

У CSS є два поширені способи керування прозорістю:

1. Задати прозорість у самому кольорі.
2. Застосувати `opacity` до всього елемента.

Ці способи схожі за зовнішнім результатом, але працюють по-різному.

### 2.1. Прозорий колір через RGBA

Формат `rgba()` задає червоний, зелений, синій канали та альфа-канал.

    .overlay {
      background-color: rgba(0, 0, 0, 0.5);
    }

У цьому прикладі чорний колір має альфа-значення `0.5`, тому фон частково просвічує крізь нього.

Четвертий параметр — альфа-канал — визначає прозорість:

- `0` — повністю прозорий колір;
- `0.5` — 50% непрозорості;
- `1` — повністю непрозорий колір.

### 2.2. Прозорість через сучасний синтаксис RGB

Можна використовувати синтаксис `rgb()` з альфа-каналом.

    .overlay {
      background-color: rgb(0 0 0 / 50%);
    }

Цей синтаксис зручний для сучасного CSS і дозволяє явно вказувати прозорість у відсотках.

### 2.3. Прозорість через HEX

Шістнадцятковий колір може містити альфа-канал.

    .overlay {
      background-color: #00000080;
    }

Останні дві шістнадцяткові цифри задають альфа-канал.

Поширені значення:

| HEX-значення альфа-каналу | Приблизна непрозорість |
|---|---:|
| `00` | 0% |
| `40` | 25% |
| `80` | 50% |
| `BF` | 75% |
| `FF` | 100% |

Ці значення є приблизними відповідниками відсотків. HEX-альфа використовує 256 можливих рівнів.

### 2.4. Властивість opacity

    .card {
      opacity: 0.5;
    }

Цей код робить напівпрозорими не лише фон картки, а й увесь її вміст:

- текст;
- іконки;
- зображення;
- кнопки;
- дочірні елементи.

Якщо потрібно зробити прозорим тільки фон, краще задавати альфа-канал кольору.

### 2.5. Порівняння двох способів

    .card-background {
      background-color: rgb(37 99 235 / 50%);
    }

    .card-opacity {
      background-color: #2563eb;
      opacity: 0.5;
    }

У першому випадку прозорим є тільки фон картки.

У другому випадку прозорість застосовується до всієї картки разом із текстом та іншими дочірніми елементами.

**Практичне правило:** якщо потрібно зберегти текст повністю видимим, не використовуй `opacity` для всього контейнера без необхідності.

## 3. Альфа-канал (Alpha Channel)

Альфа-канал — це складова кольору, яка визначає його непрозорість.

Він використовується у форматах кольорів і зображеннях, що підтримують прозорість.

### 3.1. Альфа-канал у CSS

    .panel {
      background-color: rgb(15 23 42 / 80%);
    }

Тут колір має 80% непрозорості, тому фон під панеллю буде частково видимим.

### 3.2. Альфа-канал у зображеннях

Формати PNG, WebP та AVIF можуть підтримувати прозорість, залежно від конкретного способу кодування.

Наприклад, логотип із прозорим фоном може розташовуватися на різних кольорових поверхнях без прямокутного білого тла.

SVG також може містити прозорі області.

### 3.3. Прозорість і колір — не одне й те саме

Прозорий синій колір поверх білого фону виглядатиме інакше, ніж той самий колір поверх чорного.

Отже, видимий результат залежить від:

- кольору переднього шару;
- значення альфа-каналу;
- кольору фону;
- кількості шарів;
- порядку їх накладання.

## 4. Накладання шарів (Layering)

Накладання шарів — це розташування одного візуального елемента поверх іншого.

Прозорість дозволяє бачити частину нижніх шарів.

### 4.1. Просте накладання

    .hero {
      position: relative;
      min-height: 24rem;
      background: url("/images/hero.jpg") center / cover;
    }

    .hero__overlay {
      position: absolute;
      inset: 0;
      background-color: rgb(15 23 42 / 45%);
    }

    .hero__content {
      position: relative;
      z-index: 1;
      color: #ffffff;
    }

У цьому прикладі:

- `.hero` містить фонове зображення;
- `.hero__overlay` створює затемнення;
- `.hero__content` розташовується поверх затемнення.

### 4.2. Порядок шарів

У типовому декоративному блоці порядок може бути таким:

1. Основний фон.
2. Декоративні градієнти.
3. Напівпрозорий шар.
4. Основний контент.
5. Інтерактивні елементи.

Не кожен компонент потребує всіх цих шарів.

### 4.3. Властивість z-index

`z-index` допомагає керувати порядком накладання елементів у відповідних контекстах позиціонування.

    .background-shape {
      position: absolute;
      z-index: 0;
    }

    .content {
      position: relative;
      z-index: 1;
    }

Пам'ятай, що `z-index` залежить від контекстів накладання (stacking contexts). Властивості на кшталт `opacity`, відмінної від `1`, можуть створювати новий контекст накладання.

Якщо елементи накладаються не так, як очікується, перевір не тільки значення `z-index`, а й структуру DOM та властивості батьківських елементів.

## 5. Затемнення фону

Затемнювальний шар (Overlay) часто використовується, щоб відокремити передній план від фону.

### 5.1. Затемнення фотографії

    .image-card {
      position: relative;
      overflow: hidden;
      border-radius: 1rem;
    }

    .image-card__image {
      display: block;
      width: 100%;
      height: 20rem;
      object-fit: cover;
    }

    .image-card::after {
      content: "";
      position: absolute;
      inset: 0;
      background: rgb(0 0 0 / 35%);
      pointer-events: none;
    }

Цей шар робить зображення темнішим.

### 5.2. Градієнтне затемнення

Іноді рівномірне затемнення не потрібне. Можна затемнити лише нижню частину фотографії.

    .image-card::after {
      content: "";
      position: absolute;
      inset: 0;
      background: linear-gradient(
        to top,
        rgb(0 0 0 / 75%),
        transparent 70%
      );
      pointer-events: none;
    }

Це корисно для карток, де заголовок розташований унизу зображення.

### 5.3. Коли використовувати затемнення

- текст поверх фотографії;
- відкриття модального вікна;
- тимчасове блокування фонового інтерфейсу;
- фонові ілюстрації;
- меню поверх сторінки;
- виразне відокремлення переднього плану.

### 5.4. Чого уникати

Не затемнюй фон сильніше, ніж потрібно.

Якщо фотографія або ілюстрація є важливою частиною контенту, надто темний шар може знищити деталі та зменшити її інформативність.

## 6. Напівпрозорі поверхні

Напівпрозорі поверхні дозволяють частково бачити фон крізь панель, картку або інший компонент.

Вони можуть використовуватися в:

- навігаційних панелях;
- модальних вікнах;
- картках поверх фотографій;
- плаваючих панелях;
- декоративних компонентах;
- елементах із ефектом скла.

### 6.1. Напівпрозора картка

    .glass-panel {
      padding: 1.5rem;
      border: 1px solid rgb(255 255 255 / 30%);
      border-radius: 1rem;
      background-color: rgb(255 255 255 / 75%);
    }

Така картка частково показує фон під собою.

### 6.2. Чому важливо враховувати фон

Одна й та сама напівпрозора поверхня може мати різний вигляд на різних фонах.

Наприклад, біла поверхня з прозорістю 70%:

- на світлому фоні виглядатиме майже білою;
- на темному фоні матиме помітний сірий відтінок;
- на строкатій фотографії може виглядати нерівномірно.

Тому перевіряй напівпрозорі компоненти на тих фонах, де вони реально використовуватимуться.

## 7. Glassmorphism — ефект матового скла

Glassmorphism — це візуальний стиль, який імітує напівпрозору скляну поверхню.

Зазвичай він поєднує:

- напівпрозорий фон;
- розмиття заднього плану;
- тонку світлу рамку;
- м'які тіні;
- достатній внутрішній відступ;
- контрастний текст.

### 7.1. Приклад Glassmorphism

    .glass-card {
      padding: 1.5rem;
      border: 1px solid rgb(255 255 255 / 35%);
      border-radius: 1rem;
      background: rgb(255 255 255 / 18%);
      backdrop-filter: blur(16px);
      -webkit-backdrop-filter: blur(16px);
      box-shadow: 0 8px 32px rgb(15 23 42 / 12%);
      color: #ffffff;
    }

`backdrop-filter: blur(16px)` розмиває область позаду елемента.

Це не те саме, що `filter: blur(16px)`, який розмиває сам елемент разом із його вмістом.

### 7.2. Що потрібно для ефекту

Glassmorphism найкраще помітний, коли позаду є кольорові плями, фотографія або інший візуально насичений фон.

На однорідному фоні розмиття може бути майже непомітним.

### 7.3. Типові помилки Glassmorphism

- надто прозорий фон;
- недостатній контраст тексту;
- сильне розмиття без потреби;
- надто багато скляних панелей;
- слабка межа між панеллю та фоном;
- використання ефекту на кожній картці;
- відсутність альтернативного стилю для середовищ, де ефект не підтримується.

### 7.4. Резервний варіант

Не всі браузери та пристрої однаково підтримують усі ефекти розмиття. Тому варто задати фон, який залишається читабельним без `backdrop-filter`.

    .glass-card {
      background: rgb(15 23 42 / 92%);
      border: 1px solid rgb(255 255 255 / 20%);
      border-radius: 1rem;
      color: #ffffff;
    }

    @supports (backdrop-filter: blur(1rem)) {
      .glass-card {
        background: rgb(15 23 42 / 55%);
        backdrop-filter: blur(1rem);
      }
    }

У цьому прикладі базовий темний фон залишається читабельним, а за підтримки `backdrop-filter` додається ефект скла.

## 8. Прозорість у модальних вікнах

Модальне вікно (Modal) зазвичай відображається поверх основного інтерфейсу.

Напівпрозорий фон допомагає відокремити діалог від сторінки позаду нього.

### 8.1. Затемнювальна підкладка

    .modal-backdrop {
      position: fixed;
      inset: 0;
      z-index: 100;
      background: rgb(15 23 42 / 60%);
    }

### 8.2. Поверхня модального вікна

    .modal {
      position: fixed;
      inset: 50% auto auto 50%;
      z-index: 101;
      width: min(90vw, 32rem);
      padding: 1.5rem;
      border-radius: 1rem;
      background: #ffffff;
      color: #0f172a;
      transform: translate(-50%, -50%);
    }

У цьому прикладі підкладка розташовується нижче за модальне вікно.

### 8.3. Важливі правила

- Модальне вікно має чітко відокремлюватися від фону.
- Текст у діалозі повинен залишатися читабельним.
- Підкладка не повинна блокувати сам діалог.
- Для справжнього модального діалогу потрібно правильно реалізувати фокус, клавіатурну взаємодію та доступність.
- Самої напівпрозорої підкладки недостатньо, щоб зробити компонент доступним.

Для виробничого інтерфейсу важливо також блокувати небажану взаємодію з фоновим контентом, правильно керувати фокусом і повертати його після закриття діалогу.

## 9. Прозорість і стани компонентів

Прозорість іноді використовують для позначення станів компонентів.

Наприклад:

- неактивний елемент;
- тимчасово недоступна кнопка;
- декоративний елемент другого плану;
- поступова поява компонента.

Проте прозорість сама по собі не повинна бути єдиним способом передавання стану.

### 9.1. Неактивна кнопка

    .button:disabled {
      opacity: 0.55;
      cursor: not-allowed;
    }

Це простий приклад, але його потрібно перевірити на контраст і зрозумілість у конкретному дизайні.

### 9.2. Коли краще змінити колір

Якщо текст кнопки стає надто блідим через `opacity`, краще визначити окремі кольори для неактивного стану.

    .button:disabled {
      background: #e2e8f0;
      color: #475569;
      cursor: not-allowed;
    }

Такий підхід дозволяє точніше контролювати вигляд кнопки.

### 9.3. Важливе застереження

Не роби елемент візуально напівпрозорим, якщо користувач має сприймати його як повноцінний доступний елемент керування.

Для інтерактивних компонентів потрібно чітко визначати:

- чи доступний елемент;
- чи можна на нього натискати;
- чи можна отримати фокус;
- чи зрозумілий його стан;
- чи достатній контраст тексту та меж.

## 10. Прозорість зображень

Прозорість часто є частиною самого графічного файла.

### 10.1. Зображення з прозорим фоном

PNG, SVG, WebP та AVIF можуть використовуватися для графіки з прозорими областями за умови відповідної підтримки формату й способу кодування.

Це корисно для:

- логотипів;
- іконок;
- вирізаних об'єктів;
- декоративних елементів;
- персонажів;
- графіки поверх кольорового фону.

### 10.2. Прозорість і фоновий колір

    .illustration-container {
      padding: 2rem;
      background: #eff6ff;
      border-radius: 1rem;
    }

    .illustration-container img {
      display: block;
      width: 100%;
      max-width: 24rem;
      height: auto;
      margin-inline: auto;
    }

Якщо файл має прозорий фон, колір контейнера буде видимим крізь прозорі ділянки.

### 10.3. Чому важливо перевіряти фон

Зображення, яке добре виглядає на білому тлі, може втратити контраст на темному або кольоровому фоні.

Перед використанням перевір:

- чи не зникають світлі частини;
- чи не зливаються темні контури;
- чи немає небажаних ореолів;
- чи правильно виглядає прозорість;
- чи відповідає результат усім темам інтерфейсу.

### 10.4. Прозорість і формат JPEG

JPEG не підтримує альфа-прозорість.

Якщо зображення повинно мати прозорий фон, використовуй формат, який підтримує відповідну функцію, наприклад PNG, SVG або WebP.

## 11. Прозорість у градієнтах

Прозорість можна поєднувати з градієнтами для створення м'яких переходів і декоративних шарів.

### 11.1. Градієнт від прозорого до непрозорого

    .hero-overlay {
      background: linear-gradient(
        to bottom,
        rgb(15 23 42 / 0%),
        rgb(15 23 42 / 75%)
      );
    }

Верхня частина шару майже не впливає на зображення, а нижня затемнює його.

### 11.2. Прозора кольорова пляма

    .decorative-glow {
      position: absolute;
      width: 20rem;
      aspect-ratio: 1;
      border-radius: 50%;
      background: radial-gradient(
        circle,
        rgb(59 130 246 / 45%),
        rgb(59 130 246 / 0%) 70%
      );
      pointer-events: none;
    }

Це дає змогу створювати м'які кольорові акценти без окремого зображення.

### 11.3. Кілька прозорих шарів

    .gradient-background {
      background:
        radial-gradient(
          circle at 15% 20%,
          rgb(59 130 246 / 25%),
          transparent 35%
        ),
        radial-gradient(
          circle at 85% 75%,
          rgb(139 92 246 / 22%),
          transparent 40%
        ),
        #0f172a;
    }

Кілька шарів можуть створювати глибину, але кожен додатковий шар повинен мати зрозумілу функцію.

## 12. Прозорість і тіні

Тіні часто використовують напівпрозорі кольори, щоб імітувати м'яке затемнення.

### 12.1. Приклад тіні

    .card {
      box-shadow: 0 8px 24px rgb(15 23 42 / 12%);
    }

Тут тінь використовує темний колір із прозорістю 12%.

### 12.2. Чому прозорість важлива для тіней

Повністю непрозора чорна тінь зазвичай виглядає надто жорсткою.

Напівпрозорий колір дозволяє фону частково впливати на сприйняття тіні.

### 12.3. М'яка тінь

    .card {
      box-shadow:
        0 2px 6px rgb(15 23 42 / 6%),
        0 12px 32px rgb(15 23 42 / 8%);
    }

Дві тіні з різними параметрами можуть створити м'якший ефект, ніж одна сильна тінь.

Проте надмірна кількість тіней і напівпрозорих шарів може ускладнювати композицію.

## 13. Прозорість і доступність

Прозорість безпосередньо впливає на контраст і читабельність.

### 13.1. Контраст тексту

Якщо текст розміщено поверх напівпрозорої поверхні, його кінцевий контраст залежить від фону під нею.

Наприклад, білий текст на напівпрозорій білій картці поверх фотографії може бути важко прочитати.

Можливі рішення:

- зробити поверхню менш прозорою;
- вибрати інший колір тексту;
- використати стабільний фон під текстом;
- додати затемнювальний шар;
- змінити розташування тексту.

### 13.2. Контраст потрібно перевіряти після накладання

Не можна оцінювати контраст лише за значеннями кольорів у CSS.

Потрібно враховувати кінцевий результат після накладання шарів.

Для звичайного тексту орієнтир WCAG AA — контраст не менше 4.5:1. Для великого тексту — не менше 3:1. Для важливих графічних елементів інтерфейсу також можуть діяти вимоги до контрасту.

Перевіряй конкретні критерії відповідно до типу елемента та цільового стандарту доступності.

### 13.3. Не передавай стан лише прозорістю

Якщо кнопка недоступна, а єдина відмінність — менша непрозорість, користувач може не зрозуміти її стан.

Додатково враховуй:

- текст;
- форму;
- курсор;
- доступність дії;
- поведінку клавіатурної навігації;
- програмний стан компонента.

### 13.4. Прозорість і фокус

Фокусний індикатор інтерактивного елемента повинен залишатися помітним.

Не зменшуй прозорість фокусного контуру так, щоб він ставав непомітним на фоні.

---

## 14. Прозорість і продуктивність

Звичайні напівпрозорі кольори часто не потребують спеціальних ресурсів, але складні композиції можуть збільшувати навантаження на браузер.

### 14.1. На що звертати увагу

- кількість напівпрозорих шарів;
- площа великих накладень;
- великі області з `backdrop-filter`;
- анімація прозорості;
- складні тіні;
- кількість елементів, які перекривають один одного.

### 14.2. Backdrop-filter

Розмиття заднього плану може бути дорожчим для рендерингу, особливо якщо ефект охоплює велику площу або постійно анімується.

Використовуй `backdrop-filter` там, де він справді покращує дизайн.

### 14.3. Анімація opacity

Плавна зміна прозорості часто використовується для появи та зникнення компонентів.

    .fade-in {
      animation: fade-in 300ms ease-out both;
    }

    @keyframes fade-in {
      from {
        opacity: 0;
      }

      to {
        opacity: 1;
      }
    }

Анімація повинна мати помірну тривалість і не затримувати доступ до важливого вмісту.

### 14.4. Не використовуй прозорість як єдиний механізм приховування

Елемент із `opacity: 0` може залишатися доступним для взаємодії.

Якщо компонент потрібно повністю прибрати з інтерфейсу, вибирай відповідний спосіб залежно від завдання:

- `display: none` — прибирає елемент із візуального потоку;
- атрибут `hidden` — приховує елемент;
- умовний рендеринг — не створює елемент у DOM;
- інші методи — відповідно до вимог анімації та доступності.

Не застосовуй ці способи механічно: важливо розуміти, чи потрібно зберегти елемент у DOM, доступність для допоміжних технологій і можливість анімації.

2. Чи достатньо помітна межа картки.
3. Чи не відволікають декоративні плями.
4. Чи працює базовий вигляд без `backdrop-filter`.
5. Чи має посилання помітний стан фокуса.
6. Чи не перевантажений інтерфейс зайвими ефектами.

## 17. Типові помилки

### Помилка 1. Використання opacity для всього контейнера

У результаті стають напівпрозорими текст, іконки та кнопки.

**Рішення:** якщо потрібно змінити тільки фон, використовуй колір із альфа-каналом.

### Помилка 2. Надто прозора поверхня

Текст зливається з фотографією або декоративним фоном.

**Рішення:** зменш прозорість фону, зміни колір тексту або додай стабільну поверхню.

### Помилка 3. Надмірне розмиття

Великий `backdrop-filter` робить фон нечітким, але не додає зрозумілості.

**Рішення:** зменш розмиття або прибери ефект.

### Помилка 4. Забагато скляних компонентів

Усі картки, меню та кнопки мають напівпрозорі поверхні.

**Рішення:** використовуй ефект скла лише для компонентів, де він підтримує візуальну ієрархію.

### Помилка 5. Відсутність контрасту

Напівпрозорий фон змішується з фоном сторінки, через що межі компонента стають непомітними.

**Рішення:** додай тонку межу, стабільніший фон або інший засіб візуального відокремлення.

### Помилка 6. Прозорість як єдиний сигнал стану

Користувач не розуміє, чому елемент виглядає блідим.

**Рішення:** використовуй зрозумілі стани, текстові пояснення та передбачувану поведінку.

### Помилка 7. Неправильне накладання шарів

Текст опиняється під затемнювальним шаром або кнопка стає недоступною для натискання.

**Рішення:** перевір структуру DOM, позиціонування, `z-index` та `pointer-events`.

### Помилка 8. Прозорий елемент залишається інтерактивним

Елемент має `opacity: 0`, але користувач усе ще може взаємодіяти з ним.

**Рішення:** керуй видимістю, доступністю та взаємодією відповідно до призначення компонента.

### Помилка 9. Неправильний вигляд на різних фонах

Напівпрозорий логотип або панель добре виглядає лише на одному кольорі.

**Рішення:** перевір усі фони, на яких елемент буде використовуватися.

### Помилка 10. Ефект заради ефекту

Прозорість додається до інтерфейсу без зрозумілої мети.

**Рішення:** спочатку визнач функцію компонента, а потім вибирай візуальний ефект.

## 18. Найкращі практики

✔ Визначай призначення прозорості перед її використанням.

✔ Розрізняй прозорість кольору та `opacity` усього елемента.

✔ Використовуй альфа-канал для напівпрозорих фонів.

✔ Перевіряй результат на реальному фоні.

✔ Підтримуй достатній контраст тексту й інтерактивних елементів.

✔ Використовуй затемнення, якщо потрібно відокремити передній план від фону.

✔ Не застосовуй Glassmorphism до кожного компонента.

✔ Додавай резервний вигляд для складних візуальних ефектів.

✔ Контролюй порядок накладання шарів.

✔ Не використовуй `opacity: 0` як універсальний спосіб приховування елемента.

✔ Не передавай важливий стан лише прозорістю.

✔ Перевіряй ефекти на мобільних пристроях.

✔ Враховуй світлу та темну теми.

✔ Не перевантажуй інтерфейс розмиттям, тінями й напівпрозорими поверхнями.

## 19. Мініпроєкт: система прозорих поверхонь

Мета — створити набір стилів прозорості для освітнього вебсайту.

### Завдання

Підготуй чотири компоненти:

1. Затемнювальна підкладка для модального вікна.
2. Напівпрозора картка.
3. Скляна панель із `backdrop-filter`.
4. Градієнтний overlay для фотографії.

### Крок 1. Визнач основні значення

Наприклад:

- темна підкладка — 60% непрозорості;
- світла поверхня — 80% непрозорості;
- скляна панель — 15–25% непрозорості;
- затемнення фотографії — 30–70%, залежно від композиції.

Це лише початкові орієнтири. Остаточні значення потрібно визначати за реальним фоном і вимогами до контрасту.

### Крок 2. Створи CSS-змінні

    :root {
      --overlay-dark: rgb(15 23 42 / 60%);
      --surface-translucent: rgb(255 255 255 / 80%);
      --surface-glass: rgb(255 255 255 / 18%);
      --image-overlay: rgb(0 0 0 / 40%);
      --glass-blur: 1rem;
    }

### Крок 3. Реалізуй компоненти

Створи:

- `.modal-backdrop`;
- `.translucent-card`;
- `.glass-panel`;
- `.image-overlay`.

### Крок 4. Перевір контраст

Перевір текст на світлому, темному та фотографічному фоні.

Якщо текст стає важким для читання, зміни прозорість або колір поверхні.

### Крок 5. Перевір взаємодію

Переконайся, що декоративні шари не блокують кнопки та посилання.

Для суто декоративних шарів, які можуть перехоплювати вказівник, можна використовувати:

    .decorative-overlay {
      pointer-events: none;
    }

Застосовуй це лише до шарів, які не повинні реагувати на взаємодію.

### Крок 6. Перевір теми й адаптивність

Переглянь компоненти:

- на вузькому екрані;
- на широкому екрані;
- у світлій темі;
- у темній темі;
- за відсутності підтримки `backdrop-filter`.

### Результат

Ти отримаєш невелику систему прозорих поверхонь, яку можна повторно використовувати в різних компонентах інтерфейсу.

## 21. Що потрібно запам'ятати

1. **Прозорість визначає видимість фону крізь елемент.** Вона допомагає створювати шари та керувати увагою.
2. **Альфа-канал і opacity працюють по-різному.** Альфа-канал змінює прозорість кольору, а `opacity` впливає на весь елемент разом із його вмістом.
3. **Накладання залежить від порядку шарів.** Позиціонування та `z-index` потрібно розуміти разом зі структурою DOM.
4. **Overlay допомагає відокремити передній план.** Він часто використовується для модальних вікон і тексту поверх фотографій.
5. **Glassmorphism — це не лише прозорість.** Він поєднує напівпрозорий фон, розмиття, межі та тіні.
6. **Контраст потрібно перевіряти після накладання.** Самі значення кольорів не гарантують читабельності.
7. **Прозорість не повинна бути єдиним сигналом.** Стани та доступність мають залишатися зрозумілими.
8. **Невидимий елемент не завжди неактивний.** `opacity: 0` не вимикає взаємодію автоматично.
9. **Ефекти потрібно використовувати помірно.** Зайве розмиття та велика кількість шарів перевантажують інтерфейс.
10. **Перевіряй різні фони й теми.** Прозорість завжди залежить від того, що знаходиться позаду елемента.

## 24. Коротка шпаргалка

| Поняття | Що запам'ятати |
|---|---|
| Transparency | Прозорість елемента або кольору |
| Opacity | Непрозорість усього елемента |
| Alpha channel | Канал, що визначає прозорість кольору |
| `opacity: 1` | Повністю непрозорий елемент |
| `opacity: 0` | Візуально прозорий елемент |
| `rgba()` | Колір RGB з альфа-каналом |
| `rgb(0 0 0 / 50%)` | Сучасний синтаксис RGB із прозорістю |
| HEX alpha | Альфа-канал у шістнадцятковому кольорі |
| Overlay | Шар поверх іншого елемента |
| Layering | Організація шарів |
| `z-index` | Керування порядком накладання в контексті |
| Glassmorphism | Стиль напівпрозорих поверхонь із розмиттям |
| `backdrop-filter` | Фільтр для області позаду елемента |
| `filter` | Фільтр, який застосовується до самого елемента |
| `pointer-events` | Керування реакцією елемента на вказівник |
| Contrast | Різниця кольорів, важлива для читабельності |
| Stacking context | Контекст, у межах якого визначається порядок накладання |
| Modal backdrop | Затемнювальна підкладка модального вікна |

**Головна думка:** прозорість — це інструмент керування шарами, глибиною та увагою. Використовуй її помірно, контролюй контраст і пам'ятай, що напівпрозорий елемент завжди взаємодіє з фоном, який знаходиться позаду нього.
