# 02. Borders

Borders (рамки та межі) — це візуальні лінії навколо елементів інтерфейсу, які допомагають відокремлювати компоненти, визначати їхні межі, організовувати інформацію та створювати візуальну ієрархію.

У UI design borders використовуються для оформлення:

- buttons;
- input fields;
- cards;
- tables;
- dialogs;
- modals;
- navigation elements;
- dropdowns;
- form controls;
- separators;
- panels;
- images;
- containers.

Borders допомагають користувачу зрозуміти, де закінчується один елемент і починається інший.

Основні властивості CSS для роботи з рамками:

    border
    border-width
    border-style
    border-color
    border-top
    border-right
    border-bottom
    border-left
    border-radius
    outline

У UI design важливо не просто додавати рамки, а визначати, коли вони справді потрібні, наскільки вони мають бути помітними та як вони взаємодіють з іншими візуальними засобами.

## Що потрібно пам'ятати

• Border визначає рамку навколо елемента або його окремих сторін.

• Рамки допомагають відокремлювати компоненти та структурувати інформацію.

• Основна CSS-властивість — `border`.

• `border-width` визначає товщину рамки.

• `border-style` визначає стиль лінії.

• `border-color` визначає колір рамки.

• `border-top`, `border-right`, `border-bottom` і `border-left` дозволяють оформлювати окремі сторони.

• `border-radius` визначає заокруглення кутів, але не замінює рамку.

• `outline` відрізняється від `border` і часто використовується для позначення фокусу.

• Border не повинен автоматично додаватися до кожного компонента.

• Надмірна кількість рамок може створювати візуальний шум.

• Тонкі та малоконтрастні рамки часто використовують для другорядного розділення.

• Контрастні рамки можуть підкреслювати активні, вибрані або помилкові стани.

• Рамки можуть бути частиною дизайн-системи й використовувати спільні дизайн-токени.

• Рамка не повинна бути єдиним способом передавання важливої інформації, наприклад помилки.

• Для доступності потрібно враховувати контраст, видимість станів і зрозумілість компонентів.

• Border, shadow та background можуть використовуватися окремо або разом, залежно від задачі.

# Border

Border — рамка, яка визначає межу елемента.

Наприклад:

    .card {
        border: 1px solid #d1d5db;
    }

Це означає:

    1px       → товщина рамки
    solid     → суцільна лінія
    #d1d5db   → колір рамки

Властивість `border` є скороченим записом для кількох властивостей:

    border-width
    border-style
    border-color

Наприклад, цей запис:

    .card {
        border: 1px solid #d1d5db;
    }

еквівалентний:

    .card {
        border-width: 1px;
        border-style: solid;
        border-color: #d1d5db;
    }

У більшості звичайних компонентів зручно використовувати скорочений запис.

---

# Border Width

Border width — товщина рамки.

Для визначення товщини використовується:

    border-width

Наприклад:

    .card {
        border-width: 1px;
        border-style: solid;
        border-color: #d1d5db;
    }

Типові приклади значень:

    0px
    1px
    2px
    3px
    4px

Це приклади, а не обов'язкова шкала дизайн-системи.

## Тонка рамка

    .card {
        border: 1px solid #e2e8f0;
    }

Тонкі рамки часто використовуються для карток, полів введення та розділення блоків.

## Товстіша рамка

    .card {
        border: 2px solid #64748b;
    }

Товстіша рамка створює помітнішу межу.

Її можна використовувати для:

- активних компонентів;
- вибраних елементів;
- спеціальних акцентів;
- окремих інтерактивних контролів.

Товщина сама по собі не визначає важливість елемента. Потрібно враховувати колір, контраст, розмір і загальну композицію.

---

# Border Style

Border style — стиль лінії рамки.

CSS підтримує різні значення властивості `border-style`.

## solid

Суцільна лінія.

    .card {
        border: 1px solid #cbd5e1;
    }

`solid` — один із найпоширеніших стилів для інтерфейсів.

Використовується для:

- карток;
- кнопок;
- полів введення;
- таблиць;
- контейнерів.

## dashed

Пунктирна лінія з довшими штрихами.

    .dropzone {
        border: 2px dashed #94a3b8;
    }

Може використовуватися для:

- зон завантаження файлів;
- областей перетягування;
- тимчасових контейнерів;
- декоративного розділення.

## dotted

Лінія з крапок.

    .separator {
        border-bottom: 1px dotted #94a3b8;
    }

Може застосовуватися для декоративних або спеціальних розділювачів.

## double

Подвійна лінія.

    .element {
        border: 3px double #64748b;
    }

У сучасних інтерфейсах використовується рідше, але може бути доречною для спеціальних візуальних стилів.

## none

Відсутність рамки.

    .button {
        border: none;
    }

Використовується, коли компонент не повинен мати видимої рамки.

Важливо: якщо рамка була способом показати фокус, вибір або інший важливий стан, її видалення потрібно компенсувати іншим доступним візуальним індикатором.

## hidden

Прихована рамка.

    .element {
        border-style: hidden;
    }

Це значення має особливе значення, зокрема в алгоритмі об'єднання рамок таблиць. Для звичайного приховування рамки частіше використовують `border: none`.

# Border Color

Border color — колір рамки.

Для його визначення використовується:

    border-color

Наприклад:

    .card {
        border: 1px solid #cbd5e1;
    }

Або окремо:

    .card {
        border-width: 1px;
        border-style: solid;
        border-color: #cbd5e1;
    }

Колір рамки впливає на її помітність.

## Subtle Border

Subtle border — малопомітна рамка.

    .card {
        border: 1px solid #e2e8f0;
    }

Використовується для другорядного розділення компонентів.

## Strong Border

Strong border — виразна рамка.

    .card {
        border: 2px solid #475569;
    }

Може використовуватися для активних, вибраних або особливих елементів.

## Colored Border

Кольорова рамка.

    .card {
        border: 1px solid #2563eb;
    }

Може підкреслювати належність до певного стану або візуальної категорії.

Проте не кожен кольоровий border автоматично означає активний стан. Значення кольору має бути зрозумілим у контексті інтерфейсу.

---

# Border Shorthand

Border shorthand — скорочений запис властивостей рамки.

Синтаксис:

    border: width style color;

Наприклад:

    .button {
        border: 1px solid #cbd5e1;
    }

Інші приклади:

    .button-primary {
        border: 1px solid #2563eb;
    }

    .card {
        border: 1px solid #e2e8f0;
    }

    .divider {
        border: 0;
        border-bottom: 1px solid #e2e8f0;
    }

Порядок компонентів у скороченому записі можна змінювати, оскільки браузер розпізнає типи значень.

Наприклад:

    border: solid 1px #cbd5e1;

Також є сенс пам'ятати, що скорочена властивість `border` задає рамку для всіх чотирьох сторін.

Якщо потрібно змінити тільки одну сторону, краще використовувати відповідну властивість.

---

# Border Sides

CSS дозволяє задавати рамки окремо для кожної сторони елемента.

Основні властивості:

    border-top
    border-right
    border-bottom
    border-left

## Border Top

    .card {
        border-top: 2px solid #2563eb;
    }

Використовується для акцентування верхньої частини компонента.

## Border Right

    .card {
        border-right: 1px solid #cbd5e1;
    }

Може використовуватися для вертикального розділення блоків.

## Border Bottom

    .card {
        border-bottom: 1px solid #e2e8f0;
    }

Часто використовується для:

- розділення списків;
- нижніх меж полів введення;
- навігаційних елементів;
- заголовків секцій;
- рядків таблиць.

## Border Left

    .card {
        border-left: 3px solid #2563eb;
    }

Може підкреслювати важливий блок або позначати категорію контенту.

## Різні рамки для різних сторін

    .card {
        border-top: 1px solid #e2e8f0;
        border-right: 1px solid #e2e8f0;
        border-bottom: 1px solid #cbd5e1;
        border-left: 1px solid #e2e8f0;
    }

Такий підхід дозволяє створювати складніші візуальні ефекти, але не варто використовувати його без потреби.

# Logical Border Properties

Logical border properties — властивості рамок, які залежать від логічного напрямку тексту, а не безпосередньо від фізичних сторін елемента.

Основні властивості:

    border-block
    border-block-start
    border-block-end
    border-inline
    border-inline-start
    border-inline-end

Наприклад:

    .card {
        border-inline-start: 3px solid #2563eb;
    }

Ця властивість задає рамку на початку inline-напрямку.

У звичайному горизонтальному тексті з напрямком зліва направо це зазвичай ліва сторона.

У напрямку справа наліво логічна початкова сторона змінюється.

Інший приклад:

    .section {
        border-block-end: 1px solid #e2e8f0;
    }

Це задає рамку в кінці block-напрямку, що для звичайного горизонтального письма зазвичай відповідає нижній стороні.

Переваги:

- краща підтримка різних напрямків письма;
- менша залежність від фізичних сторін;
- зручніше створювати інтерфейси для багатомовних продуктів;
- більш гнучка CSS-архітектура.

# Borders у UI Design

У дизайні інтерфейсів рамки виконують кілька основних функцій.

## 1. Визначення меж компонентів

Рамка показує, де закінчується один елемент.

Наприклад:

    .card {
        border: 1px solid #e2e8f0;
    }

## 2. Відокремлення контенту

Рамка допомагає візуально розділити сусідні блоки.

Наприклад:

    .list-item {
        border-bottom: 1px solid #e2e8f0;
    }

## 3. Створення візуальної ієрархії

Сильніша рамка може виділяти важливіший компонент.

Наприклад:

    .selected-card {
        border: 2px solid #2563eb;
    }

## 4. Позначення стану компонента

Рамка може змінюватися залежно від взаємодії.

Наприклад:

    .input {
        border: 1px solid #cbd5e1;
    }

    .input:focus {
        border-color: #2563eb;
    }

## 5. Структурування таблиць і списків

Рамки можуть допомагати розділяти рядки та колонки.

Наприклад:

    .table th,
    .table td {
        border-bottom: 1px solid #e2e8f0;
    }

# Subtle Borders

Subtle borders — малопомітні рамки, які забезпечують розділення без надмірного візуального акценту.

Наприклад:

    .card {
        border: 1px solid #e2e8f0;
    }

Такі рамки часто використовують у:

    SaaS applications
    educational platforms
    healthcare interfaces
    admin dashboards
    content management systems
    productivity tools

Subtle borders корисні, коли потрібно відокремити компоненти, але не перетворювати кожен блок на сильний візуальний акцент.

Однак рамка не повинна бути настільки непомітною, щоб її функція зникала там, де межа важлива для розуміння інтерфейсу.

---

# Strong Borders

Strong borders — виразні рамки, які створюють чітку візуальну межу.

Наприклад:

    .selected-card {
        border: 2px solid #2563eb;
    }

Використовуються для:

- вибраних карток;
- активних контролів;
- спеціальних акцентів;
- окремих інтерактивних станів;
- важливих зон інтерфейсу.

Сильна рамка привертає увагу.

Тому не варто використовувати її одночасно для великої кількості другорядних компонентів.

---

# Borders для Cards

Card — контейнер, який групує пов'язану інформацію.

Наприклад:

    .card {
        padding: 24px;
        border: 1px solid #e2e8f0;
        border-radius: 12px;
        background: #ffffff;
    }

Рамка картки може:

- визначати межі контейнера;
- відокремлювати картку від фону;
- допомагати групувати вміст;
- підкреслювати вибраний стан.

Не кожна картка потребує рамки.

Залежно від композиції можна використовувати:

    border
    background
    box-shadow
    spacing
    combination of these techniques

Наприклад, картка може бути відокремлена від інших елементів лише фоновим кольором або тінню.

Головне — щоб структура залишалася зрозумілою.

# Borders для Buttons

Рамка кнопки може бути частиною її основного стилю.

## Primary Button

    .button-primary {
        border: 1px solid #2563eb;
        background: #2563eb;
        color: #ffffff;
    }

## Secondary Button

    .button-secondary {
        border: 1px solid #cbd5e1;
        background: #ffffff;
        color: #1e293b;
    }

## Ghost Button

    .button-ghost {
        border: 1px solid transparent;
        background: transparent;
        color: #2563eb;
    }

Це умовні приклади стилів кнопок.

Рамки допомагають розрізняти типи кнопок, але потрібно також враховувати фон, текст, контраст і стани взаємодії.

---

# Borders для Input Fields

Поля введення часто використовують рамку для позначення області, у яку користувач може вводити дані.

Наприклад:

    .input {
        width: 100%;
        padding: 12px 16px;
        border: 1px solid #cbd5e1;
        border-radius: 8px;
        background: #ffffff;
        color: #0f172a;
    }

Рамка повинна допомагати користувачу розпізнавати поле введення на тлі інших елементів.

Важливо враховувати:

- контраст із фоном;
- товщину рамки;
- стани focus, error і disabled;
- однаковість полів у формі;
- видимість компонента за різних умов відображення.

---

# Borders для Tables

Таблиці часто використовують рамки для розділення рядків, колонок і заголовків.

Наприклад:

    .table {
        width: 100%;
        border-collapse: collapse;
    }

    .table th,
    .table td {
        padding: 12px 16px;
        border-bottom: 1px solid #e2e8f0;
        text-align: left;
    }

Такий підхід розділяє рядки, не створюючи рамку навколо кожної клітинки.

Інший варіант:

    .table {
        border-collapse: collapse;
    }

    .table th,
    .table td {
        border: 1px solid #cbd5e1;
        padding: 12px;
    }

Це створює сітку з рамками навколо клітинок.

Вибір залежить від:

- кількості даних;
- щільності таблиці;
- потреби у візуальному групуванні;
- загального стилю інтерфейсу;
- доступності та читабельності.

Для складних таблиць надмірна кількість ліній може погіршувати читабельність.

---

# Borders для Lists

Рамки часто використовують для розділення елементів списку.

Наприклад:

    .list-item {
        padding: 16px 0;
        border-bottom: 1px solid #e2e8f0;
    }

Якщо нижня рамка останнього елемента не потрібна:

    .list-item:last-child {
        border-bottom: none;
    }

Це допомагає уникати зайвої лінії внизу списку.

Проте рамки не завжди потрібні. Іноді достатньо вертикальних відступів між елементами.

---

# Borders для Navigation

У навігаційних компонентах рамки можуть виконувати роль розділювачів або індикаторів активного пункту.

Наприклад:

    .navbar {
        border-bottom: 1px solid #e2e8f0;
    }

Або:

    .nav-link[aria-current="page"] {
        border-bottom: 2px solid #2563eb;
    }

Другий приклад використовує атрибут `aria-current="page"` для позначення поточної сторінки.

Рамка під активним пунктом — лише один із можливих способів позначення поточного розділу.

Також можуть використовуватися фон, колір тексту, форма індикатора або інші візуальні рішення.

---

# Borders для Dividers

Divider — візуальний розділювач між блоками контенту.

Наприклад:

    .divider {
        border: 0;
        border-top: 1px solid #e2e8f0;
    }

Розділювачі використовуються для:

- відокремлення секцій;
- поділу груп меню;
- розділення рядків;
- поділу форм;
- організації довгих сторінок.

Не кожне розділення потрібно позначати лінією.

У багатьох інтерфейсах достатньо правильно організувати spacing.

Потрібно вибирати між:

    spacing
    border
    background
    shadow

залежно від того, наскільки чітко необхідно показати межу між блоками.

---

# Border vs Spacing

Border та spacing вирішують різні задачі.

Border створює видиму лінію.

Spacing створює простір між елементами.

Наприклад, із рамкою:

    .section {
        padding: 24px;
        border-bottom: 1px solid #e2e8f0;
    }

Без рамки:

    .section {
        padding: 24px 0;
    }

У першому випадку межа підкреслюється лінією.

У другому — основним засобом розділення стає відстань між блоками.

Не потрібно додавати рамку лише тому, що два елементи розташовані поруч.

Іноді достатньо збільшити відступ.

---

# Border vs Background

Background визначає фон елемента.

Border визначає його межу.

Наприклад:

    .card {
        background: #f8fafc;
        border: 1px solid #e2e8f0;
    }

У цьому випадку фон і рамка працюють разом.

Але можна використати лише фон:

    .card {
        background: #f1f5f9;
    }

Або лише рамку:

    .card {
        background: transparent;
        border: 1px solid #cbd5e1;
    }

Вибір залежить від контрасту, структури та стилю інтерфейсу.

---

# Border vs Box Shadow

Border та box-shadow можуть допомагати відокремлювати компонент від навколишнього контенту, але працюють по-різному.

Border створює чітку лінію по межі елемента.

Box shadow створює тінь навколо елемента.

Наприклад:

    .card {
        border: 1px solid #e2e8f0;
    }

Або:

    .card {
        box-shadow: 0 2px 8px rgb(15 23 42 / 8%);
    }

Можна використовувати обидва засоби:

    .card {
        border: 1px solid #e2e8f0;
        box-shadow: 0 2px 8px rgb(15 23 42 / 6%);
    }

Однак рамка та тінь не завжди потрібні одночасно.

Якщо обидві властивості надто виразні, компонент може виглядати важким.

---

# Border vs Outline

Border — рамка елемента, яка бере участь у його геометрії.

Outline — зовнішній контур, який не займає місця в стандартному розрахунку розмірів елемента.

Наприклад:

    .input {
        border: 1px solid #cbd5e1;
    }

    .input:focus-visible {
        outline: 2px solid #2563eb;
        outline-offset: 2px;
    }

У цьому прикладі:

    border
        → основна рамка поля

    outline
        → додатковий контур видимого фокусу

Outline часто використовують для клавіатурної навігації, оскільки він дозволяє чітко показати, який елемент зараз у фокусі.

Не потрібно бездумно видаляти outline через те, що він не відповідає візуальному стилю браузера.

Якщо стандартний індикатор фокусу замінюється, новий індикатор повинен залишатися помітним і доступним.

---

# Border і Box Model

Border є частиною CSS box model.

За стандартного значення:

    box-sizing: content-box;

ширина елемента визначає ширину content area, а рамка додається зовні.

Наприклад:

    .box {
        width: 200px;
        padding: 20px;
        border: 2px solid #cbd5e1;
    }

Фактична зовнішня ширина буде:

    200px + 40px + 4px = 244px

Тут:

    200px → content width
    40px  → padding зліва та справа
    4px   → border зліва та справа

За значення:

    box-sizing: border-box;

задана ширина включає content, padding і border.

Наприклад:

    * {
        box-sizing: border-box;
    }

    .box {
        width: 200px;
        padding: 20px;
        border: 2px solid #cbd5e1;
    }

Тепер загальна ширина елемента становитиме 200px.

Це важливо для UI design, оскільки додавання рамки може впливати на розміри компонентів і вирівнювання.

---

# Border і Layout Shift

Layout shift у контексті компонента може виникати, якщо під час зміни стану змінюються його зовнішні розміри.

Наприклад:

    .button {
        border: 1px solid transparent;
    }

    .button:hover {
        border-color: #2563eb;
    }

У цьому прикладі рамка вже існує, а під час наведення змінюється лише її колір.

Це допомагає уникнути зміни товщини рамки між станами.

Інший підхід:

    .button {
        border: 1px solid #cbd5e1;
    }

    .button:hover {
        border: 2px solid #2563eb;
    }

Тут товщина змінюється з 1px до 2px, що може вплинути на геометрію елемента.

У багатьох випадках краще змінювати колір або використовувати outline, якщо потрібен додатковий контур без зміни розмірів.

---

# Borders і Component States

Рамки можуть змінюватися залежно від стану компонента.

Основні стани:

    default
    hover
    focus
    focus-visible
    active
    selected
    error
    disabled

Кожен стан повинен мати зрозуміле призначення.

## Default State

Звичайний стан компонента.

    .input {
        border: 1px solid #cbd5e1;
    }

## Hover State

Стан наведення курсора.

    .button:hover {
        border-color: #64748b;
    }

Hover не повинен бути єдиним способом передавання важливої інформації, оскільки на сенсорних пристроях наведення може бути відсутнім.

## Focus State

Стан, коли компонент отримав фокус.

    .input:focus {
        border-color: #2563eb;
    }

Зміна кольору рамки може доповнювати індикатор фокусу.

## Focus-visible State

Стан видимого фокусу.

    .button:focus-visible {
        outline: 2px solid #2563eb;
        outline-offset: 2px;
    }

Цей підхід часто використовують для доступної клавіатурної навігації.

## Active State

Стан активної взаємодії.

    .button:active {
        border-color: #1d4ed8;
    }

## Selected State

Стан вибраного елемента.

    .option[aria-selected="true"] {
        border: 2px solid #2563eb;
    }

## Error State

Стан помилки.

    .input--error {
        border-color: #dc2626;
    }

## Disabled State

Неактивний компонент.

    .button:disabled {
        border-color: #e2e8f0;
        cursor: not-allowed;
    }

Це приклади оформлення, а не повна реалізація всіх станів.

У реальному компоненті також потрібно перевіряти колір тексту, фон, семантику HTML, поведінку клавіатури та доступність.

---

# Borders і Accessibility

Accessibility — доступність інтерфейсу для користувачів із різними можливостями та способами взаємодії.

Під час роботи з рамками потрібно враховувати кілька аспектів.

## 1. Контраст

Якщо рамка є необхідною для розпізнавання компонента, вона повинна мати достатній контраст із сусідніми кольорами.

Дуже бліда рамка на білому фоні може бути майже непомітною.

## 2. Focus Indicator

Інтерактивні елементи повинні мати видимий індикатор клавіатурного фокусу.

Наприклад:

    button:focus-visible {
        outline: 2px solid #2563eb;
        outline-offset: 2px;
    }

## 3. Не покладатися лише на колір

Помилка не повинна позначатися виключно червоною рамкою.

Потрібно також надати зрозуміле повідомлення.

Наприклад:

    <label for="email">Email</label>

    <input
        id="email"
        type="email"
        aria-invalid="true"
        aria-describedby="email-error"
    >

    <p id="email-error">
        Введіть коректну адресу електронної пошти.
    </p>

Це приклад структури поля з повідомленням про помилку. Саме оформлення рамки можна додати через CSS.

## 4. Видимість станів

Користувач повинен розуміти, який елемент активний, вибраний або перебуває у фокусі.

Рамки можуть допомагати передавати ці стани, якщо вони достатньо помітні.

## 5. Розмір інтерактивної області

Рамка сама по собі не забезпечує достатнього розміру кнопки або іншого інтерактивного елемента.

Потрібно також враховувати розміри компонента та відстань до сусідніх контролів.

---

# Borders і Dark Mode

У темній темі рамки часто використовуються для відокремлення поверхонь, які мають близькі кольори.

Наприклад:

    .card {
        background: #1e293b;
        border: 1px solid #334155;
    }

У світлій темі:

    .card {
        background: #ffffff;
        border: 1px solid #e2e8f0;
    }

У темній темі не обов'язково використовувати яскраві рамки.

Часто достатньо помірного контрасту, щоб позначити межі компонента.

Однак конкретні кольори потрібно перевіряти на реальному фоні.

---

# Borders і Design Tokens

Design tokens — повторно використовувані значення дизайн-системи.

Для рамок можна створювати токени товщини, кольору та стилю.

Наприклад:

    :root {
        --border-width-thin: 1px;
        --border-width-medium: 2px;

        --border-color-subtle: #e2e8f0;
        --border-color-default: #cbd5e1;
        --border-color-strong: #64748b;
        --border-color-focus: #2563eb;
        --border-color-error: #dc2626;
    }

Використання:

    .card {
        border: var(--border-width-thin) solid
            var(--border-color-subtle);
    }

    .input {
        border: var(--border-width-thin) solid
            var(--border-color-default);
    }

    .input:focus {
        border-color: var(--border-color-focus);
    }

    .input--error {
        border-color: var(--border-color-error);
    }

Переваги:

- узгодженість рамок;
- централізована зміна стилів;
- зручніша підтримка компонентів;
- простіше створювати теми;
- менше випадкових значень у CSS.

---

# Border Tokens за призначенням

Окрім технічних токенів, можна використовувати семантичні назви.

Наприклад:

    :root {
        --border-subtle: #e2e8f0;
        --border-default: #cbd5e1;
        --border-strong: #64748b;

        --border-interactive: #2563eb;
        --border-error: #dc2626;
        --border-success: #16a34a;
    }

Такі назви пояснюють призначення токена.

Використання:

    .card {
        border: 1px solid var(--border-subtle);
    }

    .input {
        border: 1px solid var(--border-default);
    }

    .input:focus {
        border-color: var(--border-interactive);
    }

    .input--error {
        border-color: var(--border-error);
    }

Назви та значення потрібно адаптувати до конкретної дизайн-системи.

---

# Borderless Design

Borderless design — підхід, за якого в інтерфейсі використовується мало видимих рамок або вони взагалі відсутні в окремих компонентах.

Замість рамок можуть використовуватися:

    spacing
    background colors
    typography
    shadows
    alignment
    grouping

Наприклад:

    .card {
        padding: 24px;
        border: none;
        background: #f8fafc;
        border-radius: 12px;
    }

Такий підхід може створювати чистий і мінімалістичний вигляд.

Проте відсутність рамок не повинна погіршувати розуміння структури інтерфейсу.

Якщо межа важлива для сприйняття компонента, її можна позначити іншим способом.

---

# Nested Borders

Nested borders — рамки у вкладених контейнерах.

Наприклад, картка містить внутрішню панель, яка також має рамку.

    .card {
        padding: 16px;
        border: 1px solid #cbd5e1;
        border-radius: 12px;
    }

    .card__panel {
        padding: 16px;
        border: 1px solid #e2e8f0;
        border-radius: 8px;
    }

Такий підхід може бути доречним, коли внутрішня панель є окремою функціональною або змістовою групою.

Однак надмірна кількість вкладених рамок створює візуальну складність.

Перед додаванням внутрішньої рамки варто запитати:

- Чи справді потрібно відокремлювати внутрішній блок?
- Чи достатньо відступу?
- Чи допомагає рамка зрозуміти структуру?
- Чи не дублює вона межу зовнішнього контейнера?

---

# Borders і Responsive Design

Borders зазвичай зберігають однаковий стиль на різних розмірах екрана.

Однак у деяких композиціях рамки можуть змінюватися залежно від ширини viewport.

Наприклад:

    .sidebar {
        border-right: 1px solid #e2e8f0;
    }

    @media (max-width: 768px) {
        .sidebar {
            border-right: none;
            border-bottom: 1px solid #e2e8f0;
        }
    }

На широкому екрані рамка відокремлює sidebar вертикально.

На вузькому екрані вона може перейти на нижню сторону, якщо компонування змінюється.

Це лише приклад.

Не потрібно змінювати рамки на mobile без потреби. Рішення залежить від фактичної структури responsive layout.

---

# Borders у Figma

Під час роботи у Figma рамки використовуються для визначення меж компонентів та їхніх станів.

Потрібно вміти:

- задавати товщину рамки;
- вибирати колір;
- змінювати стиль лінії;
- налаштовувати окремі сторони, якщо це підтримується обраним способом побудови;
- використовувати рамки для різних станів компонентів;
- створювати узгоджені стилі та дизайн-токени;
- перевіряти контраст на різних фонах;
- підтримувати однакові правила в компонентах і варіантах.

Під час створення дизайн-системи важливо не просто копіювати рамки між елементами, а визначати правила їхнього використання.

---

# Типові помилки

## 1. Надмірне використання рамок

Якщо кожен блок, секція та вкладений елемент має свою рамку, інтерфейс може стати візуально перевантаженим.

Краще використовувати рамки лише там, де вони допомагають структурувати інформацію.

## 2. Надто низький контраст

    .card {
        border: 1px solid #f8fafc;
        background: #ffffff;
    }

На білому фоні така рамка майже непомітна.

Якщо межа важлива, потрібно перевірити контраст і видимість.

## 3. Занадто товсті рамки

    .card {
        border: 5px solid #64748b;
    }

Така рамка може перетягувати увагу на себе.

Товщина повинна відповідати призначенню компонента.

## 4. Використання різних кольорів без системи

    .card-a {
        border-color: #cbd5e1;
    }

    .card-b {
        border-color: #94a3b8;
    }

    .card-c {
        border-color: #b6c2d2;
    }

Якщо відмінності не мають конкретного призначення, краще використовувати спільні border tokens.

## 5. Видалення outline без заміни

    button:focus {
        outline: none;
    }

Це може зробити клавіатурний фокус непомітним.

Якщо стандартний outline прибирається, потрібно передбачити інший виразний індикатор.

## 6. Використання кольору як єдиного індикатора помилки

Червона рамка без пояснення може бути недостатньою.

Потрібно також надати зрозуміле повідомлення та пов'язати його з відповідним полем.

## 7. Зміна товщини рамки між станами

Якщо рамка змінює товщину, компонент може змінювати свої розміри.

У багатьох випадках краще змінювати колір або використовувати outline.

## 8. Рамка навколо кожного рядка таблиці

Надмірна кількість ліній може ускладнювати читання даних.

Іноді достатньо нижніх рамок або чергування фону рядків.

## 9. Плутати border і outline

Border є частиною box model.

Outline не займає місця в стандартному розрахунку розмірів.

Ці властивості мають різні призначення.

## 10. Забувати про box-sizing

За `content-box` рамка додається до заданої ширини та висоти.

Це може порушувати очікувані розміри компонента.

## 11. Дублювати рамку та тінь

Якщо обидві властивості надто виразні, картка може виглядати важкою.

Потрібно оцінювати їх разом.

## 12. Не перевіряти рамки в темній темі

Колір, який добре працює на білому фоні, може бути надто слабким або надто яскравим на темному.

Для кожної теми потрібно перевіряти контраст і візуальну ієрархію.

# Практичні приклади

## Приклад 1 — Card

    .card {
        padding: 24px;
        border: 1px solid #e2e8f0;
        border-radius: 12px;
        background: #ffffff;
    }

Картка має тонку рамку та заокруглені кути.

## Приклад 2 — Input

    .input {
        width: 100%;
        padding: 12px 16px;
        border: 1px solid #cbd5e1;
        border-radius: 8px;
        background: #ffffff;
    }

Поле введення має чітко визначену межу.

## Приклад 3 — Focus Indicator

    .input:focus-visible {
        outline: 2px solid #2563eb;
        outline-offset: 2px;
    }

Видимий індикатор допомагає визначити елемент у фокусі.

## Приклад 4 — Selected Card

    .card--selected {
        border: 2px solid #2563eb;
    }

Рамка допомагає показати вибраний стан.

## Приклад 5 — Error Input

    .input--error {
        border-color: #dc2626;
    }

Для повноцінного стану помилки також потрібно передбачити повідомлення та відповідну семантику.

## Приклад 6 — Divider

    .divider {
        border: 0;
        border-top: 1px solid #e2e8f0;
    }

Використовується для горизонтального розділення контенту.

# Практика UI Design

## Завдання 1 — Порівняння товщини

Створи три однакові картки.

    Card A → 1px border
    Card B → 2px border
    Card C → 4px border

Використовуй однакові кольори, розміри та радіуси.

Мета — зрозуміти, як товщина рамки впливає на візуальну вагу компонента.

## Завдання 2 — Порівняння кольорів

Створи три картки:

    Subtle border
    Default border
    Strong border

Використовуй різні рівні контрасту.

Перевір, як змінюється помітність межі на світлому та темному фоні.

## Завдання 3 — Border vs Shadow

Створи три варіанти картки:

    Card A → border only
    Card B → shadow only
    Card C → border + shadow

Порівняй, який варіант краще відповідає обраному стилю інтерфейсу.

## Завдання 4 — Input States

Створи поле введення з такими станами:

    Default
    Hover
    Focus
    Error
    Disabled

Визнач для кожного стану:

- колір рамки;
- товщину рамки;
- колір фону;
- індикатор фокусу;
- додаткове повідомлення, якщо потрібне.

## Завдання 5 — Border Tokens

Створи власну систему токенів:

    --border-subtle
    --border-default
    --border-strong
    --border-focus
    --border-error

Використай їх для карток, кнопок, полів введення та інших компонентів.

## Завдання 6 — Таблиця

Створи таблицю з десятьма рядками.

Порівняй два варіанти:

    1. Рамка навколо кожної клітинки.
    2. Лише нижня рамка кожного рядка.

Визнач, який варіант краще читається для конкретного набору даних.

## Завдання 7 — Аналіз реального інтерфейсу

Обери вебзастосунок і проаналізуй:

- рамки карток;
- рамки кнопок;
- рамки полів введення;
- розділювачі;
- рамки таблиць;
- індикатори фокусу;
- вибрані стани;
- помилкові стани;
- використання тіней замість рамок.

Спробуй визначити, чи є в інтерфейсі єдина система рамок.

# Головне

• Border визначає рамку елемента або його окремої сторони.

• Основні властивості — `border`, `border-width`, `border-style` і `border-color`.

• Рамки допомагають визначати межі компонентів, групувати контент і створювати візуальну ієрархію.

• Не кожен компонент потребує рамки.

• Надмірна кількість рамок може створювати візуальний шум.

• Тонкі рамки часто використовуються для другорядного розділення.

• Контрастні рамки можуть підкреслювати важливі або активні елементи.

• Border, background, spacing і box-shadow можуть виконувати різні, але взаємодоповнювальні функції.

• Border є частиною box model, а outline не займає місця в стандартному розрахунку розмірів елемента.

• Видимий focus indicator важливий для доступності.

• Помилки не повинні позначатися лише кольором рамки — користувачу також потрібне зрозуміле пояснення.

• Зміна товщини рамки може впливати на геометрію компонента.

• Border tokens допомагають підтримувати узгодженість у дизайн-системі.

• Рамки потрібно перевіряти на різних фонах, у світлій і темній темах та за різних станів компонентів.

• Головне завдання дизайнера — використовувати рамки там, де вони покращують структуру, зрозумілість і взаємодію, а не просто додають декоративні лінії.
