# 07. Images — Зображення в UI-дизайні

Зображення (images) — це візуальні елементи інтерфейсу, які допомагають передавати інформацію, привертати увагу, пояснювати зміст, формувати емоційне враження та підтримувати візуальну ієрархію.

У UI-дизайні зображення використовують у картках товарів і курсів, профілях користувачів, статтях, галереях, банерах, hero-секціях, порожніх станах та інших компонентах.

**Головна мета роботи із зображеннями — зробити контент зрозумілим, доречним, якісним і візуально узгодженим з інтерфейсом.**

Важливо розрізняти:

- **Image selection** — вибір відповідного зображення.
- **Image size** — розмір зображення.
- **Aspect ratio** — співвідношення ширини та висоти.
- **Image cropping** — обрізання зображення.
- **Image fit** — спосіб розміщення зображення в контейнері.
- **Image optimization** — оптимізація зображення для швидкого завантаження.
- **Image accessibility** — доступність зображення для різних користувачів.

---

## 1. Основи використання зображень

### 1.1. Для чого потрібні зображення

Зображення можуть виконувати різні функції:

- Показувати реальний об'єкт.
- Ілюструвати текст.
- Передавати емоції.
- Допомагати розпізнавати категорії.
- Пояснювати складні поняття.
- Створювати візуальну ієрархію.
- Формувати ідентичність бренду.
- Підвищувати привабливість сторінки.

Наприклад, у навчальній платформі зображення може показувати викладача, обкладинку курсу, навчальну ілюстрацію або фотографію навчального матеріалу.

### 1.2. Основні типи зображень

| Тип | Приклади використання |
|---|---|
| Фотографії | Товари, люди, події |
| Ілюстрації | Пояснення, декоративні блоки |
| Аватари | Профілі користувачів |
| Обкладинки | Курси, статті, книги |
| Банери | Акції, повідомлення, кампанії |
| Інфографіка | Дані, процеси, статистика |
| Скриншоти | Демонстрація інтерфейсів |
| Текстури | Фони та декоративні поверхні |
| Діаграми | Графіки, схеми, візуалізація даних |

### 1.3. Зображення як частина інтерфейсу

Зображення не повинно бути випадковим декоративним елементом.

Під час вибору потрібно враховувати:

- Призначення сторінки.
- Очікування користувача.
- Контекст тексту.
- Візуальну ієрархію.
- Розміри контейнера.
- Колірну палітру.
- Продуктивність.
- Доступність.

Наприклад, фотографія товару повинна допомагати оцінити товар, а не просто прикрашати картку.

### 1.4. Коли зображення не потрібне

Не кожен блок потребує фотографії або ілюстрації.

Зображення може бути зайвим, якщо воно:

- Не додає нової інформації.
- Відволікає від основної дії.
- Збільшує час завантаження.
- Порушує композицію.
- Дублює вже зрозумілий зміст.

**Правило:** кожне важливе зображення повинно мати зрозумілу роль у користувацькому інтерфейсі.

---

## 2. Вибір відповідного зображення

### 2.1. Відповідність змісту

Зображення повинно відповідати тому, що воно представляє.

Наприклад:

    Картка курсу:
    "Основи JavaScript"

    Доречне зображення:
    Ілюстрація програмування або редактора коду.

    Недоречне зображення:
    Випадкова фотографія пейзажу без зв'язку з темою.

Візуальна привабливість не компенсує невідповідність змісту.

### 2.2. Візуальна якість

Перевіряй:

- Чіткість.
- Різкість.
- Освітлення.
- Контраст.
- Композицію.
- Колірний баланс.
- Відсутність небажаних артефактів.
- Відповідність стилю проєкту.

Не використовуй розмиті або сильно стиснуті зображення, якщо їхня якість помітна користувачеві.

### 2.3. Єдиний стиль

Якщо в одному інтерфейсі використовуються фотографії, вони повинні бути узгодженими за стилем.

Наприклад, у каталозі курсів небажано без причини поєднувати:

- Темні фотографії.
- Дуже яскраві стокові зображення.
- Мінімалістичні векторні ілюстрації.
- Мальовані персонажі.
- Скриншоти різної якості.

Різні стилі можуть співіснувати, якщо це свідоме дизайнерське рішення.

### 2.4. Композиція зображення

Перед використанням перевір:

- Де розташований головний об'єкт.
- Чи є достатньо вільного простору.
- Чи не перекриває текст важливі деталі.
- Чи можна безпечно обрізати зображення.
- Чи добре воно виглядає в малому розмірі.

Особливо важлива композиція, коли зображення використовується як фон або обкладинка картки.

### 2.5. Авторські права

Не кожне зображення, знайдене в інтернеті, можна вільно використовувати.

Перевіряй:

- Ліцензію.
- Умови комерційного використання.
- Необхідність зазначення автора.
- Обмеження на редагування.
- Умови використання стокових матеріалів.

Для навчальних і комерційних проєктів використовуй власні зображення, матеріали з відповідною ліцензією або дозволені стокові ресурси.

---

## 3. Розмір зображення

### 3.1. Що таке image size

Розмір зображення — це його ширина та висота.

Наприклад:

    width: 400px;
    height: 300px;

Таке зображення має співвідношення сторін 4:3.

Важливо розрізняти розмір файлу в пікселях і розмір відображення в інтерфейсі.

Наприклад, файл 1600 × 1200 px може відображатися в контейнері 400 × 300 CSS px.

### 3.2. Розмір файлу та розмір відображення

Це різні характеристики.

| Поняття | Що означає |
|---|---|
| Image dimensions | Ширина та висота зображення в пікселях |
| CSS dimensions | Розмір зображення на сторінці |
| File size | Обсяг файлу в байтах |
| Resolution | Кількість пікселів зображення |
| Device pixel ratio | Співвідношення фізичних і CSS-пікселів пристрою |

Великий файл не обов'язково повинен відображатися великим на сторінці.

Так само зображення з великою кількістю пікселів не завжди має великий обсяг файлу: це залежить від формату, стиснення та вмісту.

### 3.3. Вибір розміру

Орієнтуйся на реальний розмір компонента.

Наприклад:

    Аватар: 48 × 48 CSS px
    Мініатюра: 160 × 120 CSS px
    Зображення картки: 360 × 240 CSS px
    Hero-зображення: залежить від макета

Це лише приклади. Остаточний розмір залежить від дизайну, адаптивності та щільності пікселів екрана.

### 3.4. Не збільшуй маленькі зображення без потреби

Якщо маленьке зображення розтягнути на великий контейнер, воно може стати розмитим.

Краще використовувати джерело з достатньою роздільною здатністю або підготувати окрему версію для великого відображення.

## 4. Aspect Ratio — співвідношення сторін

### 4.1. Що таке aspect ratio

Aspect ratio — це співвідношення ширини зображення до його висоти.

Наприклад:

    1:1 — квадрат
    4:3 — класичний прямокутний формат
    3:2 — поширений формат фотографій
    16:9 — широкий формат
    9:16 — вертикальний формат

Співвідношення сторін впливає на композицію, висоту компонента та розміщення зображення в макеті.

### 4.2. Квадратне зображення — 1:1

Приклади:

- Аватари.
- Мініатюри товарів.
- Картки категорій.
- Галереї квадратних фотографій.

CSS:

    .avatar {
        width: 48px;
        aspect-ratio: 1 / 1;
        border-radius: 50%;
        object-fit: cover;
    }

### 4.3. Співвідношення 4:3

Підходить для:

- Фотографій.
- Карток із навчальними матеріалами.
- Прев'ю статей.
- Галерей.

CSS:

    .card__image {
        width: 100%;
        aspect-ratio: 4 / 3;
        object-fit: cover;
    }

### 4.4. Співвідношення 16:9

Підходить для:

- Відеопрев'ю.
- Обкладинок уроків.
- Банерів.
- Широких зображень у картках.

CSS:

    .video-preview {
        width: 100%;
        aspect-ratio: 16 / 9;
        object-fit: cover;
    }

### 4.5. Вертикальні зображення

Вертикальний формат може використовуватися для:

- Портретів.
- Книжкових обкладинок.
- Мобільного контенту.
- Історій.
- Вертикальних галерей.

CSS:

    .portrait {
        width: 100%;
        aspect-ratio: 3 / 4;
        object-fit: cover;
    }

### 4.6. Чому важливо зберігати однакове співвідношення сторін

Якщо зображення в картках мають різні пропорції, висота карток може відрізнятися.

Це може призвести до:

- Нерівних рядів.
- Зміщення кнопок.
- Порушення сітки.
- Неузгодженої композиції.

Використання однакового `aspect-ratio` допомагає створити послідовний каталог.

## 5. Image Fit — розміщення зображення в контейнері

### 5.1. Властивість `object-fit`

CSS-властивість `object-fit` визначає, як зображення розміщується всередині заданого контейнера.

Основні значення:

- `cover`
- `contain`
- `fill`
- `none`
- `scale-down`

### 5.2. `object-fit: cover`

Зображення заповнює весь контейнер, зберігаючи пропорції.

Частина зображення може бути обрізана.

Приклад:

    .card__image {
        width: 100%;
        height: 240px;
        object-fit: cover;
    }

Використовуй `cover`, коли важливо заповнити всю площу контейнера.

Підходить для:

- Карток.
- Банерів.
- Аватарів.
- Обкладинок.
- Прев'ю.

### 5.3. `object-fit: contain`

Зображення повністю поміщається в контейнер зі збереженням пропорцій.

Навколо нього може залишатися вільний простір.

Приклад:

    .product__image {
        width: 100%;
        height: 240px;
        object-fit: contain;
    }

Підходить для:

- Товарів.
- Логотипів.
- Іконок.
- Технічних схем.
- Об'єктів, які не можна обрізати.

### 5.4. `object-fit: fill`

Зображення заповнює весь контейнер, навіть якщо його пропорції змінюються.

Приклад:

    .image {
        width: 100%;
        height: 200px;
        object-fit: fill;
    }

Це може спотворювати зображення.

Використовуй цей режим лише тоді, коли спотворення допустиме або пропорції джерела й контейнера збігаються.

### 5.5. `object-fit: none`

Зображення відображається у власному розмірі без автоматичного масштабування.

Частина зображення може виходити за межі контейнера.

Такий режим використовується рідше й потребує уважного контролю переповнення.

### 5.6. `object-fit: scale-down`

Браузер вибирає між `none` і `contain`, щоб зображення не було збільшене понад його початковий розмір.

Це може бути корисно, коли не потрібно збільшувати маленькі зображення.

### 5.7. Порівняння

| Значення | Поведінка | Типове застосування |
|---|---|---|
| `cover` | Заповнює контейнер, може обрізати | Картки, банери |
| `contain` | Показує все зображення | Товари, логотипи |
| `fill` | Заповнює контейнер, може спотворити | Рідкісні спеціальні випадки |
| `none` | Не масштабує автоматично | Спеціальні сценарії |
| `scale-down` | Не збільшує понад початковий розмір | Маленькі зображення |

## 6. Image Cropping — обрізання зображень

### 6.1. Що таке cropping

Cropping — це обрізання частини зображення, щоб воно відповідало формі або розміру контейнера.

Обрізання часто відбувається автоматично через `object-fit: cover`.

Наприклад, квадратне фото можна використати в широкій картці, але частина його верхньої та нижньої частин може не потрапити у видиму область.

### 6.2. Чому обрізання важливе

Неправильне обрізання може:

- Відрізати обличчя.
- Приховати важливу деталь товару.
- Зруйнувати композицію.
- Зробити зображення незрозумілим.
- Обрізати текст, вбудований у графіку.

### 6.3. Властивість `object-position`

`object-position` визначає, яку частину зображення потрібно показувати в контейнері.

Приклад:

    .portrait {
        width: 100%;
        height: 320px;
        object-fit: cover;
        object-position: center top;
    }

Можливі значення:

    object-position: center;
    object-position: top;
    object-position: bottom;
    object-position: left;
    object-position: right;

Можна також задавати відсотки:

    object-position: 50% 30%;

Це допомагає зміщувати видиму область, коли важливий об'єкт розташований не в центрі.

### 6.4. Приклад для портрета

    .profile-card__image {
        width: 100%;
        aspect-ratio: 4 / 3;
        object-fit: cover;
        object-position: center 25%;
    }

Так можна показати більше верхньої частини портрета.

Конкретне значення потрібно вибирати за самим зображенням.

### 6.5. Не обрізай важливу інформацію

Перед використанням `cover` перевір:

- Чи не обрізається головний об'єкт.
- Чи залишається зрозумілим зміст.
- Чи працює кадрування на мобільному.
- Чи не зникає важлива деталь у вузькому контейнері.

Для критично важливих деталей іноді краще використовувати `contain` або окремі версії зображення.

## 7. Зображення як фон

### 7.1. Коли використовувати background-image

CSS-фонові зображення доречні, коли зображення є частиною оформлення, а не самостійним інформаційним об'єктом.

Наприклад:

- Декоративні фони.
- Hero-секції.
- Текстури.
- Абстрактні композиції.
- Декоративні градієнти із зображеннями.

Приклад:

    .hero {
        background-image: url("/images/hero.jpg");
        background-size: cover;
        background-position: center;
        background-repeat: no-repeat;
    }

### 7.2. `background-size: cover`

Зображення заповнює фон, зберігаючи пропорції, але може обрізатися.

    .hero {
        background-size: cover;
    }

### 7.3. `background-size: contain`

Зображення повністю поміщається в область фону, але може залишити вільний простір.

    .hero {
        background-size: contain;
        background-repeat: no-repeat;
        background-position: center;
    }

### 7.4. Накладання градієнта

Якщо поверх зображення розміщується текст, можна використати градієнт для підвищення контрасту.

    .hero {
        background-image:
            linear-gradient(
                to right,
                rgb(0 0 0 / 65%),
                rgb(0 0 0 / 0%)
            ),
            url("/images/hero.jpg");

        background-size: cover;
        background-position: center;
    }

Це лише приклад. Прозорість і напрямок градієнта залежать від композиції та кольору тексту.

### 7.5. Коли не варто використовувати фон замість `<img>`

Не використовуй CSS-фон для важливого інформаційного зображення, якщо користувачеві потрібно:

- Ознайомитися з його змістом.
- Отримати текстовий опис через допоміжні технології.
- Зберегти або відкрити зображення як контент.
- Використати браузерні можливості завантаження адаптивних ресурсів.

Для змістовних зображень зазвичай краще підходить HTML-елемент `<img>`.

## 8. Формати зображень

### 8.1. JPEG / JPG

Поширений формат фотографій із втратами якості під час стиснення.

Переваги:

- Широка підтримка.
- Зазвичай невеликий розмір фотографій.
- Підходить для складних фотографічних зображень.

Недоліки:

- Не підтримує прозорість.
- Повторне стиснення може погіршувати якість.
- Не завжди найефективніший сучасний формат.

### 8.2. PNG

Формат растрової графіки з підтримкою прозорості.

Переваги:

- Підтримує прозорий фон.
- Добре підходить для скриншотів та графіки з чіткими межами.
- Не використовує втратне стиснення.

Недоліки:

- Файли фотографій можуть бути великими.
- Не завжди оптимальний для великих фотоколекцій.

### 8.3. WebP

Сучасний формат зображень, який підтримує стиснення з втратами й без втрат, а також прозорість.

Переваги:

- Часто менший розмір файлу порівняно з JPEG або PNG для подібного візуального результату.
- Підходить для фотографій і графіки.
- Підтримує прозорість.

### 8.4. AVIF

Сучасний формат зображень, який може забезпечувати ефективне стиснення.

Переваги:

- Часто дає невеликий розмір файлу.
- Підтримує широкий діапазон можливостей для фотографій і графіки.
- Підтримує прозорість.

Особливості:

- Час кодування та декодування залежить від інструментів і пристроїв.
- Потрібно враховувати підтримку браузерами та запасні варіанти, якщо вони потрібні цільовій аудиторії.

### 8.5. SVG

Векторний формат, який добре підходить для:

- Логотипів.
- Іконок.
- Схем.
- Простих ілюстрацій.
- Графіки з чіткими лініями.

Переваги:

- Масштабується без пікселізації.
- Часто має малий розмір для простої графіки.
- Може бути стилізований за допомогою CSS.

Недоліки:

- Складні SVG можуть містити багато геометрії.
- Неперевірені SVG-файли можуть створювати ризики безпеки.
- Фотографії зазвичай не варто перетворювати на SVG.

### 8.6. GIF

GIF може використовуватися для простої анімації, але має обмежену палітру кольорів.

Для складних анімацій і відеоподібного контенту часто краще розглянути сучасніші формати.

### 8.7. Порівняння форматів

| Формат | Найчастіше використання |
|---|---|
| JPEG | Фотографії |
| PNG | Прозорість, скриншоти, графіка |
| WebP | Фотографії та вебграфіка |
| AVIF | Ефективне стиснення фотографій і графіки |
| SVG | Іконки, логотипи, векторні ілюстрації |
| GIF | Проста анімація |

**Правило:** вибирай формат відповідно до типу зображення, потрібної якості, розміру файлу та підтримки браузерами.

## 9. Оптимізація зображень

### 9.1. Що таке image optimization

Оптимізація зображень — це зменшення обсягу даних і покращення способу доставки зображень без неприйнятної втрати якості.

Мета:

- Прискорити завантаження сторінки.
- Зменшити використання трафіку.
- Поліпшити досвід користувача.
- Зменшити витрати на передавання даних.
- Підтримати хороші показники продуктивності.

### 9.2. Вибирай відповідний розмір файлу

Не потрібно завантажувати зображення 4000 × 3000 px, якщо воно завжди відображається в області 200 × 150 CSS px.

Водночас на екранах із високою щільністю пікселів може знадобитися зображення з більшою кількістю пікселів.

Враховуй:

- Розмір компонента.
- Щільність пікселів.
- Можливе кадрування.
- Якість джерела.
- Тип контенту.

### 9.3. Стиснення

Під час стиснення потрібно знайти баланс між якістю та розміром файлу.

Надмірне стиснення може призвести до:

- Артефактів.
- Розмитих деталей.
- Спотворення кольорів.
- Помітних блоків на фотографіях.

Перевіряй результат в реальному розмірі відображення.

### 9.4. Responsive images

Адаптивні зображення дозволяють браузеру вибирати відповідний файл залежно від ширини екрана та інших умов.

Приклад:

    <img
        src="/images/course-800.jpg"
        srcset="
            /images/course-400.jpg 400w,
            /images/course-800.jpg 800w,
            /images/course-1200.jpg 1200w
        "
        sizes="
            (max-width: 600px) 100vw,
            (max-width: 1000px) 50vw,
            33vw
        "
        alt="Викладач пояснює матеріал студентам"
    />

Тут:

- `src` задає запасне або базове джерело.
- `srcset` перелічує доступні версії зображення.
- `sizes` описує очікувану ширину відображення на різних екранах.
- `alt` задає текстову альтернативу.

Браузер використовує цю інформацію, щоб вибрати відповідний ресурс.

### 9.5. Lazy loading

`loading="lazy"` дозволяє браузеру відкладати завантаження зображень, які ще не потрібні у видимій області.

Приклад:

    <img
        src="/images/article-1.webp"
        alt="Навчальний матеріал на столі"
        loading="lazy"
        width="800"
        height="600"
    />

Це може бути корисним для:

- Довгих списків.
- Галерей.
- Нижніх секцій сторінки.
- Карток за межами початкової видимої області.

Не варто автоматично застосовувати lazy loading до головного зображення сторінки, якщо воно потрібне для швидкого відображення початкового вмісту.

### 9.6. Заздалегідь визначай розміри

Атрибути `width` і `height` допомагають браузеру зарезервувати простір для зображення ще до його завантаження.

Приклад:

    <img
        src="/images/course.webp"
        alt="Навчальний курс"
        width="800"
        height="600"
    />

Це допомагає зменшити небажані зміщення макета під час завантаження.

### 9.7. Не завантажуй усе заздалегідь

Якщо сторінка містить багато великих зображень, бездумне попереднє завантаження може погіршити продуктивність.

Попереднє завантаження (`preload`) варто використовувати лише для ресурсів, які справді критичні для початкового відображення сторінки.

## 10. Доступність зображень

### 10.1. Що таке alt text

`alt` — це текстова альтернатива зображення в HTML.

Вона допомагає передати зміст зображення, зокрема користувачам, які використовують програми читання з екрана.

Приклад:

    <img
        src="/images/teacher.jpg"
        alt="Викладач проводить урок у класі"
    />

### 10.2. Як писати хороший alt

Хороший `alt`:

- Передає важливий зміст.
- Відповідає контексту.
- Є коротким і конкретним.
- Не повторює зайву інформацію.
- Не описує декоративні деталі без потреби.

Поганий приклад:

    alt="image"

Кращий приклад:

    alt="Викладач пише формулу на дошці"

### 10.3. Декоративні зображення

Якщо зображення суто декоративне й не додає змісту, використовуй порожній `alt`.

    <img
        src="/images/decorative-shape.webp"
        alt=""
    />

Це допомагає програмам читання з екрана не озвучувати зайву інформацію.

### 10.4. Не дублюй текст

Якщо біля зображення вже є повний текст, який передає ту саму інформацію, альтернативний текст може бути коротшим або порожнім — залежно від функції зображення.

Важливо оцінювати контекст, а не застосовувати одне правило до всіх зображень.

### 10.5. Зображення з текстом

Не використовуй зображення для передачі важливого тексту, якщо цей текст можна подати як справжній HTML-текст.

Наприклад, заголовок банера краще розмістити поверх зображення як HTML, а не вбудовувати в сам файл.

Переваги:

- Краща доступність.
- Адаптивність.
- Можливість виділення та копіювання.
- Легше редагування.
- Краща підтримка перекладів.

### 10.6. Контраст тексту на зображенні

Якщо текст розташований поверх фотографії, його контраст може змінюватися залежно від конкретної ділянки.

Можна використовувати:

- Напівпрозорий фон.
- Градієнт.
- Підкладку під текст.
- Іншу композицію.
- Перенесення тексту в окремий блок.

Перевіряй контраст на всій важливій ділянці, а не лише на одному фрагменті фотографії.

## 11. Зображення в картках

### 11.1. Типова структура картки

Картка може містити:

- Зображення.
- Заголовок.
- Опис.
- Метадані.
- Основну дію.

Приклад:

    ┌────────────────────────────┐
    │                            │
    │        Зображення          │
    │                            │
    ├────────────────────────────┤
    │ Основи JavaScript          │
    │ 12 уроків                  │
    │                            │
    │ [Переглянути курс]         │
    └────────────────────────────┘

### 11.2. Однакове співвідношення сторін

Для однорідної сітки карток задай спільне співвідношення сторін.

    .course-card__image {
        display: block;
        width: 100%;
        aspect-ratio: 16 / 9;
        object-fit: cover;
    }

### 11.3. Однаковий стиль

У каталозі бажано узгодити:

- Формат зображень.
- Пропорції.
- Спосіб обрізання.
- Кольоровий баланс.
- Заокруглення кутів.
- Відступи.
- Поведінку при наведенні.

### 11.4. Не покладайся лише на зображення

Назва товару або курсу повинна залишатися доступною в тексті.

Не змушуй користувача розпізнавати зміст лише за фотографією.

### 11.5. Поведінка на різних екранах

На мобільному картки можуть розташовуватися в одну колонку, а на великому екрані — у дві або три.

Перевіряй, чи:

- Зображення зберігає потрібні пропорції.
- Обрізання залишається доречним.
- Текст не перекриває важливі деталі.
- Картки не стають надто високими.
- Зображення не втрачає зміст через вузький контейнер.

## 12. Зображення в hero-секціях

### 12.1. Що таке hero image

Hero image — це велике зображення у верхній частині сторінки або ключового розділу.

Воно може бути:

- Основним візуальним акцентом.
- Фоном для заголовка.
- Ілюстрацією продукту.
- Фотографією людини.
- Демонстрацією інтерфейсу.

### 12.2. Основні принципи

Hero-зображення повинно:

- Підтримувати головне повідомлення.
- Не відволікати від основної дії.
- Добре працювати на різних екранах.
- Мати достатню якість.
- Не створювати проблем із читабельністю тексту.

### 12.3. Зображення поруч із текстом

Приклад структури:

    Hero
    ├── Content
    │   ├── Heading
    │   ├── Description
    │   └── Button
    └── Image

Це дає змогу контролювати текст незалежно від зображення.

### 12.4. Адаптивна композиція

На широкому екрані зображення може розташовуватися праворуч від тексту.

На мобільному воно може переходити під текст або над ним.

Важливо перевіряти не лише розмір зображення, а й порядок контенту та логіку сприйняття сторінки.

## 13. Галереї та великі зображення

### 13.1. Галерея

Галерея дозволяє переглядати кілька зображень в одному інтерфейсі.

Типові компоненти:

- Мініатюри.
- Основне зображення.
- Стрілки переходу.
- Індикатор поточного елемента.
- Повноекранний перегляд.

### 13.2. Узгодженість мініатюр

Для галереї можна використовувати однакові пропорції мініатюр.

    .gallery__thumbnail {
        width: 100%;
        aspect-ratio: 1 / 1;
        object-fit: cover;
    }

Важливо, щоб обрізання не приховувало унікальні деталі кожного зображення.

### 13.3. Відкриття великого зображення

Якщо користувач може відкрити повнорозмірне зображення, передбач:

- Зрозумілий спосіб закриття.
- Керування клавіатурою.
- Доступні назви кнопок.
- Коректну поведінку на мобільних.
- Достатній контраст елементів керування.

### 13.4. Зображення в модальному вікні

Велике зображення не повинно випадково виходити за межі екрана.

Приклад:

    .lightbox__image {
        display: block;
        max-width: 100%;
        max-height: 85vh;
        width: auto;
        height: auto;
        object-fit: contain;
    }

Це дозволяє зображенню масштабуватися в межах доступного простору без спотворення пропорцій.

## 14. Аватари та портрети

### 14.1. Аватари

Аватари використовуються для представлення користувачів.

Поширені форми:

- Коло.
- Квадрат.
- Квадрат із заокругленими кутами.

Приклад:

    .avatar {
        width: 48px;
        height: 48px;
        border-radius: 50%;
        object-fit: cover;
    }

### 14.2. Позиціювання обличчя

Під час кадрування портрета важливо, щоб обличчя залишалося видимим.

    .avatar {
        object-position: center;
    }

Якщо потрібно, можна змінити позицію:

    object-position: center 30%;

Значення залежить від вихідного зображення.

### 14.3. Аватар без фотографії

Якщо фотографії немає, можна використати:

- Ініціали.
- Просту іконку користувача.
- Нейтральну графічну позначку.

Приклад:

    <div class="avatar avatar--fallback" aria-hidden="true">
        VS
    </div>

Якщо аватар має бути доступним для допоміжних технологій, його призначення потрібно передати відповідним текстом у контексті компонента.

### 14.4. Не роби фотографію обов'язковою

Інтерфейс повинен залишатися зрозумілим і без завантаженого аватара.

Зображення може бути відсутнім, не завантажитися або бути недоступним через мережеву помилку.

## 15. Стани зображень

### 15.1. Loading state

Поки зображення завантажується, можна показувати:

- Нейтральний фон.
- Placeholder.
- Skeleton.
- Заздалегідь зарезервовану область.

Це допомагає зберігати стабільність макета.

### 15.2. Error state

Зображення може не завантажитися через:

- Неправильний шлях.
- Відсутність файлу.
- Мережеву помилку.
- Недоступний сервер.
- Проблеми з форматом.

Передбачай зрозумілий запасний варіант, особливо для важливих зображень.

### 15.3. Placeholder

Placeholder — це тимчасовий або запасний елемент, який займає місце зображення.

Приклад:

    .image-placeholder {
        display: flex;
        align-items: center;
        justify-content: center;
        aspect-ratio: 16 / 9;
        background: #f1f3f5;
        color: #667085;
    }

Placeholder повинен зберігати пропорції та не руйнувати композицію.

### 15.4. Broken image

Не залишай важливі зображення без контролю помилок.

Для критичних компонентів можна передбачити:

- Запасне зображення.
- Текстову назву.
- Повідомлення про помилку.
- Механізм повторного завантаження, якщо він потрібен.

Не потрібно створювати складну логіку для кожного декоративного елемента. Рівень обробки залежить від важливості контенту.

## 16. Зображення та продуктивність

### 16.1. Чому великі зображення сповільнюють сайт

Великі файли можуть:

- Збільшувати час завантаження.
- Споживати більше мобільного трафіку.
- Відкладати відображення важливого контенту.
- Погіршувати досвід користувача при повільному інтернеті.

Особливо це важливо для головних зображень, каталогів і довгих сторінок.

### 16.2. Вплив на Core Web Vitals

Зображення можуть впливати на показники продуктивності:

- **LCP** — швидкість відображення найбільшого важливого елемента.
- **CLS** — стабільність макета під час завантаження.
- **INP** — швидкість реагування сторінки на взаємодію.

Велике hero-зображення може впливати на LCP, а відсутність зарезервованого простору — спричиняти зміщення макета та погіршувати CLS.

### 16.3. Практичні кроки

✔ Використовуй відповідний формат.

✔ Оптимізуй розмір файлу.

✔ Не завантажуй надмірно великі зображення без потреби.

✔ Використовуй `srcset` і `sizes`, коли це доречно.

✔ Вказуй `width` і `height` або резервуй простір через CSS.

✔ Застосовуй lazy loading до зображень, які не потрібні відразу.

✔ Не відкладай без потреби завантаження головного зображення.

✔ Перевіряй сторінку на повільному з'єднанні.

## 17. Зображення в адаптивному дизайні

### 17.1. Що таке responsive images

Responsive images — це підхід, за якого зображення та його подання пристосовуються до різних розмірів екрана й умов відображення.

Мета — зберегти зміст, якість, пропорції та продуктивність.

### 17.2. Адаптивна ширина

Для простого адаптивного зображення:

    .responsive-image {
        display: block;
        width: 100%;
        height: auto;
    }

Це дозволяє зображенню масштабуватися за шириною контейнера зі збереженням пропорцій.

### 17.3. Адаптивне кадрування

Іноді на мобільному та десктопі потрібне різне кадрування.

Можна використовувати різні значення `object-position` або різні джерела зображення.

### 17.4. Елемент `<picture>`

`<picture>` дозволяє пропонувати різні джерела зображення залежно від медіаумов або формату.

Приклад:

    <picture>
        <source
            media="(max-width: 600px)"
            srcset="/images/hero-mobile.webp"
        />

        <source
            media="(min-width: 601px)"
            srcset="/images/hero-desktop.webp"
        />

        <img
            src="/images/hero-desktop.jpg"
            alt="Студенти працюють над навчальним проєктом"
            width="1200"
            height="700"
        />
    </picture>

Тут мобільна та десктопна версії можуть мати різну композицію.

### 17.5. Не змінюй зображення лише заради зміни

Різні джерела мають сенс, якщо вони:

- Покращують кадрування.
- Відповідають композиції екрана.
- Зменшують обсяг завантаження.
- Роблять зміст зрозумілішим.

Якщо одного адаптивного зображення достатньо, не потрібно створювати зайві версії.

## 18. Зображення в дизайн-системі

### 18.1. Навіщо потрібні правила

Дизайн-система повинна визначати, як зображення використовуються в різних компонентах.

Це допомагає уникати ситуацій, коли кожна картка має довільні пропорції, заокруглення та спосіб обрізання.

### 18.2. Приклад правил

    Image / Avatar
    - Aspect ratio: 1:1
    - Shape: Circle
    - Fit: Cover

    Image / Card
    - Aspect ratio: 16:9
    - Shape: Rounded corners
    - Fit: Cover

    Image / Product
    - Aspect ratio: 1:1
    - Fit: Contain

    Image / Article
    - Aspect ratio: 3:2
    - Fit: Cover

Це приклад системи, а не обов'язкові значення для кожного проєкту.

### 18.3. Компонентні правила

Для кожного типу зображення можна визначити:

- Призначення.
- Пропорції.
- Максимальні розміри.
- Спосіб обрізання.
- Заокруглення.
- Поведінку на мобільному.
- Правила доступності.
- Placeholder.
- Обробку помилок.

### 18.4. Іменування

Можна використовувати послідовні назви:

    image-avatar
    image-card
    image-product
    image-article
    image-hero

У CSS або дизайн-системі назви мають описувати призначення компонента, а не випадкові характеристики конкретного файлу.

## 20. Типові помилки

### 20.1. Невідповідне зображення

Зображення не підтримує зміст сторінки.

**Рішення:** вибирати матеріал, який допомагає користувачеві зрозуміти контент.

### 20.2. Різні пропорції в однакових картках

Картки мають неоднакову висоту або порушують сітку.

**Рішення:** використовувати `aspect-ratio` та відповідний `object-fit`.

### 20.3. Спотворення зображення

Зображення розтягується без збереження пропорцій.

**Рішення:** застосовувати `object-fit: cover` або `contain` відповідно до завдання.

### 20.4. Неправильне обрізання

Головний об'єкт частково зникає.

**Рішення:** перевірити `object-position` або змінити співвідношення сторін.

### 20.5. Занадто великі файли

Сторінка завантажується повільно.

**Рішення:** оптимізувати формат, розмір і якість файлу.

### 20.6. Відсутній альтернативний текст

Змістовне зображення не має належного `alt`.

**Рішення:** описати важливу інформацію, яку передає зображення.

### 20.7. Зайвий альтернативний текст

Для декоративного зображення написано довгий опис, який не додає інформації.

**Рішення:** використовувати `alt=""`, якщо зображення суто декоративне.

### 20.8. Текст поверх фотографії нечитабельний

Колір тексту зливається з фоном.

**Рішення:** змінити композицію або додати відповідну підкладку чи градієнт.

### 20.9. Немає запасного стану

Якщо зображення не завантажилося, компонент виглядає зламаним.

**Рішення:** передбачити placeholder або запасний варіант для важливих зображень.

### 20.10. Неправильне використання lazy loading

Головне зображення сторінки завантажується із затримкою без потреби.

**Рішення:** використовувати lazy loading для віддаленого контенту, а не механічно для всіх зображень.

### 20.11. Текст вбудований у графіку

Важливий текст неможливо зручно масштабувати або перекласти.

**Рішення:** розміщувати текст як HTML, якщо це можливо.

### 20.12. Зображення не перевірено на мобільному

На вузькому екрані кадрування приховує важливий об'єкт.

**Рішення:** перевіряти композицію на різних ширинах і за потреби використовувати окреме джерело.

## 21. Практичні правила

✔ Вибирай зображення відповідно до змісту та мети компонента.

✔ Дотримуйся єдиного візуального стилю.

✔ Визначай співвідношення сторін для повторюваних компонентів.

✔ Використовуй `object-fit: cover`, коли потрібно заповнити контейнер.

✔ Використовуй `object-fit: contain`, коли важливо показати зображення повністю.

✔ Коригуй кадрування за допомогою `object-position`.

✔ Не спотворюй пропорції без дизайнерської причини.

✔ Оптимізуй файли перед використанням у продакшені.

✔ Використовуй адаптивні зображення для великих або часто переглядуваних ресурсів.

✔ Вказуй `width` і `height` або резервуй простір через CSS.

✔ Використовуй `loading="lazy"` для зображень, які не потрібні відразу.

✔ Не затримуй без потреби завантаження головного зображення.

✔ Додавай змістовний `alt` до інформаційних зображень.

✔ Використовуй `alt=""` для суто декоративних зображень.

✔ Не розміщуй важливий текст усередині графічного файлу без потреби.

✔ Перевіряй контраст тексту поверх зображення.

✔ Передбачай placeholder для важливих зображень.

✔ Перевіряй кадрування на мобільних пристроях.

✔ Дотримуйся ліцензійних умов використання зображень.

## 24. Що потрібно запам'ятати

1. Зображення повинно допомагати зрозуміти зміст або підтримувати композицію.
2. Не кожен компонент потребує фотографії чи ілюстрації.
3. Розмір файлу, роздільна здатність і розмір відображення — різні поняття.
4. `aspect-ratio` допомагає зберігати пропорції компонентів.
5. `object-fit: cover` заповнює контейнер, але може обрізати зображення.
6. `object-fit: contain` показує зображення повністю, але може залишити вільний простір.
7. `object-position` дозволяє контролювати кадрування.
8. SVG підходить для іконок і векторної графіки, а не для звичайних фотографій.
9. WebP та AVIF можуть зменшувати розмір файлів за збереження прийнятної якості.
10. `srcset`, `sizes` і `<picture>` допомагають створювати адаптивні зображення.
11. `loading="lazy"` доречний для зображень, які не потрібні відразу.
12. `width` і `height` допомагають уникати небажаних зміщень макета.
13. `alt` має передавати зміст інформаційного зображення.
14. Для суто декоративного зображення часто доречний `alt=""`.
15. Текст поверх фотографії повинен мати достатній контраст.
16. Важливі зображення повинні мати продуманий запасний стан.
17. Потрібно перевіряти зображення на різних екранах.
18. Використання зображень має відповідати їхнім ліцензійним умовам.

## 26. Подальший порядок навчання

Рекомендована послідовність практики:

1. Вивчити основні типи зображень у вебінтерфейсах.
2. Навчитися вибирати зображення відповідно до змісту.
3. Розібратися з розмірами та співвідношенням сторін.
4. Практикувати `aspect-ratio`.
5. Порівняти `object-fit: cover` і `contain`.
6. Навчитися керувати кадруванням через `object-position`.
7. Ознайомитися з JPEG, PNG, WebP, AVIF і SVG.
8. Оптимізувати зображення для вебу.
9. Використовувати `srcset`, `sizes` і `<picture>`.
10. Навчитися правильно писати `alt`.
11. Створити картки з однаковими пропорціями зображень.
12. Передбачати placeholder та помилки завантаження.
13. Перевірити адаптивність і продуктивність.
14. Задокументувати правила зображень у дизайн-системі.

## 27. Коротка шпаргалка

| Поняття | Значення |
|---|---|
| Image | Зображення в інтерфейсі |
| Aspect ratio | Співвідношення ширини та висоти |
| Cropping | Обрізання зображення |
| `object-fit` | Спосіб розміщення зображення в контейнері |
| `cover` | Заповнює контейнер, обрізаючи зайве |
| `contain` | Показує зображення повністю |
| `fill` | Заповнює контейнер із можливим спотворенням |
| `object-position` | Положення видимої частини зображення |
| `background-image` | Фонове зображення CSS |
| JPEG | Поширений формат фотографій |
| PNG | Растрова графіка з прозорістю |
| WebP | Сучасний формат фотографій і графіки |
| AVIF | Формат із можливістю ефективного стиснення |
| SVG | Векторна графіка |
| `alt` | Текстова альтернатива зображення |
| `srcset` | Перелік доступних варіантів зображення |
| `sizes` | Опис очікуваного розміру відображення |
| `<picture>` | Вибір джерела зображення за умовами |
| `loading="lazy"` | Відкладене завантаження |
| Placeholder | Тимчасовий або запасний елемент |
| LCP | Показник швидкості відображення основного контенту |
| CLS | Показник стабільності макета |
| Image optimization | Оптимізація розміру та доставки зображень |

**Головний принцип:** зображення в UI повинно бути доречним, якісним, оптимізованим і доступним. Правильний вибір джерела, пропорцій, кадрування та способу завантаження допомагає створити зрозумілий, швидкий і послідовний інтерфейс.
