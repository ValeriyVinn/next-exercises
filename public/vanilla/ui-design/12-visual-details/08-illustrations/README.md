# 08. Illustrations — Ілюстрації в UI-дизайні

Ілюстрації (Illustrations) — це графічні зображення, які допомагають пояснювати інформацію, створювати настрій, підкреслювати індивідуальність продукту та робити інтерфейс зрозумілішим.

Ілюстрації можуть бути декоративними або функціональними. Вони використовуються на головних сторінках, у картках, порожніх станах, повідомленнях про помилки, навчальних матеріалах, onboarding-екранах та інших частинах інтерфейсу.

**Головний принцип:** ілюстрація повинна допомагати користувачу зрозуміти інтерфейс або посилювати його візуальну мову, а не відволікати від основної дії.

---

## 1. Основи ілюстрацій в UI

✔ Ілюстрації передають ідею за допомогою графіки.

✔ Вони можуть пояснювати складні поняття простіше за текст.

✔ Допомагають створити емоційний зв'язок із продуктом.

✔ Підсилюють візуальну ідентичність бренду.

✔ Можуть привертати увагу до важливих блоків.

✔ Повинні відповідати стилю всього інтерфейсу.

### 1.1. Навіщо потрібні ілюстрації

Ілюстрації можуть виконувати декілька завдань:

- **Пояснення** — допомагають зрозуміти функцію або процес.
- **Емоційна підтримка** — роблять повідомлення менш сухим.
- **Декорування** — заповнюють композицію та створюють настрій.
- **Брендинг** — роблять продукт упізнаваним.
- **Навігація** — допомагають візуально розрізняти розділи.
- **Підтримка користувача** — супроводжують повідомлення про помилки або відсутність даних.

### 1.2. Ілюстрація та інші візуальні елементи

| Елемент | Основне призначення |
|---|---|
| Іконка (Icon) | Позначає дію, об'єкт або категорію |
| Ілюстрація (Illustration) | Пояснює ідею, створює настрій або розповідає історію |
| Фотографія (Photo) | Показує реальних людей, місця чи предмети |
| Діаграма (Chart) | Візуалізує дані |
| Інфографіка (Infographic) | Поєднує графіку, текст і дані для пояснення теми |
| Декоративна графіка | Прикрашає інтерфейс без самостійної інформаційної функції |

**Приклад:**

- Іконка конверта біля поля email — позначає тип інформації.
- Ілюстрація людини, яка перевіряє пошту, — пояснює етап реєстрації.
- Фотографія працівника — показує реальну людину.
- Діаграма — демонструє статистику користувачів.

## 2. Основні типи ілюстрацій

### 2.1. Векторні ілюстрації (Vector Illustrations)

Векторні ілюстрації складаються з геометричних форм, ліній і кривих.

Переваги:

- добре масштабуються;
- часто мають невеликий розмір файлу;
- легко змінювати кольори;
- підходять для вебінтерфейсів;
- можуть бути адаптовані під різні розміри екрана.

Типовий формат — SVG.

Векторна графіка добре підходить для:

- onboarding;
- hero-блоків;
- порожніх станів;
- навчальних платформ;
- ілюстрацій у картках;
- простих персонажів і схем.

### 2.2. Растрові ілюстрації (Raster Illustrations)

Растрові зображення складаються з пікселів.

Вони можуть містити складні текстури, тіні, градієнти та деталізовані малюнки.

Поширені формати:

- PNG;
- WebP;
- AVIF.

Переваги:

- підходять для складних художніх робіт;
- можуть передавати текстури й тонкі переходи кольорів;
- зручні для ілюстрацій, створених у графічних редакторах.

Недоліки:

- можуть займати більше місця;
- при збільшенні можуть втрачати чіткість;
- для зміни кольорів часто потрібен графічний редактор.

### 2.3. Плоскі ілюстрації (Flat Illustrations)

Flat illustration використовує прості форми, однорідні кольори та мінімум об'єму.

Особливості:

- чіткі силуети;
- обмежена палітра;
- відсутність складних текстур;
- просте сприйняття;
- хороша сумісність із мінімалістичним дизайном.

Підходять для освітніх сайтів, SaaS-продуктів, дашбордів і корпоративних інтерфейсів.

### 2.4. Об'ємні ілюстрації (3D Illustrations)

3D-ілюстрації імітують об'єм за допомогою перспективи, освітлення, тіней і матеріалів.

Вони можуть створювати враження:

- технологічності;
- реалістичності;
- глибини;
- ігрового або експериментального стилю.

Важливо не використовувати 3D лише тому, що воно модне. Складна графіка може збільшувати вагу сторінки та конкурувати з основним контентом.

### 2.5. Лінійні ілюстрації (Line Illustrations)

Лінійні ілюстрації будуються переважно на контурах.

Вони добре підходять для:

- мінімалістичних інтерфейсів;
- освітніх ресурсів;
- технічної документації;
- сервісів із великою кількістю інформації.

Важливо підтримувати однакову товщину ліній, стиль кутів і рівень деталізації.

### 2.6. Ілюстрації з персонажами (Character Illustrations)

Такі ілюстрації використовують людей, тварин або вигаданих персонажів.

Вони допомагають:

- пояснювати дії;
- передавати емоції;
- створювати впізнаваний образ бренду;
- підтримувати користувача під час складних процесів.

Персонажі повинні відповідати аудиторії, контексту та тону продукту.

### 2.7. Абстрактні ілюстрації (Abstract Illustrations)

Абстрактна графіка використовує геометричні форми, кольорові плями, хвилі та нестандартні композиції.

Вона підходить для:

- технологічних продуктів;
- презентацій;
- промосторінок;
- фонів hero-блоків;
- брендових декоративних елементів.

Абстрактна ілюстрація може створювати настрій, але не завжди підходить для пояснення конкретної функції.

## 3. Вибір стилю ілюстрацій

Стиль ілюстрацій повинен підтримувати загальну дизайн-систему.

### 3.1. Основні параметри стилю

Під час вибору стилю визнач:

- геометрію форм;
- товщину контурів;
- палітру кольорів;
- ступінь деталізації;
- тип тіней;
- рівень реалістичності;
- характер персонажів;
- тип перспективи;
- спосіб заокруглення кутів.

### 3.2. Узгодженість стилю

У межах одного інтерфейсу бажано дотримуватися спільної візуальної мови.

Наприклад, якщо основні ілюстрації мають плоскі форми та чіткі контури, випадкове додавання фотореалістичного 3D-персонажа може порушити цілісність дизайну.

**Приклад узгодженого стилю:**

- усі ілюстрації використовують одну палітру;
- контури мають однакову товщину;
- персонажі мають подібні пропорції;
- тіні використовуються за єдиним принципом;
- рівень деталізації приблизно однаковий.

### 3.3. Стиль залежить від продукту

| Тип продукту | Можливий стиль |
|---|---|
| Освітня платформа | Дружні персонажі, прості схеми |
| Медичний сервіс | Спокійні, зрозумілі, стримані ілюстрації |
| Фінансовий сервіс | Геометрична графіка, мінімалізм |
| Дитячий застосунок | Яскраві персонажі, прості форми |
| Портфоліо дизайнера | Авторські, експериментальні ілюстрації |
| Технічний SaaS | Абстрактна графіка, схеми, мінімалізм |

Це орієнтири, а не суворі правила. Важливо враховувати аудиторію та конкретне завдання.

## 4. Ілюстрації та композиція

Ілюстрація повинна працювати разом із текстом, кнопками, заголовками й іншими елементами.

### 4.1. Візуальна ієрархія

Користувач повинен розуміти, на що дивитися спочатку.

Наприклад, у hero-блоці порядок уваги може бути таким:

1. Заголовок.
2. Короткий опис.
3. Основна кнопка.
4. Ілюстрація, яка підтримує повідомлення.

В іншому дизайні ілюстрація може бути головним елементом. Це залежить від мети сторінки.

### 4.2. Баланс між текстом та ілюстрацією

Якщо ілюстрація надто велика, вона може витісняти важливу інформацію.

Якщо надто мала — втрачається її сенс.

Під час компонування перевір:

- чи вистачає місця заголовку;
- чи не перекриває графіка кнопку;
- чи не порушений баланс порожнього простору;
- чи зрозуміло, як ілюстрація пов'язана з текстом;
- чи зберігається композиція на мобільному екрані.

### 4.3. Напрямок погляду та руху

Персонаж може дивитися на заголовок або кнопку, привертаючи до них увагу.

Лінії, стрілки та напрямки руху також можуть допомагати керувати поглядом.

Але ці прийоми не повинні замінювати зрозумілу структуру інтерфейсу.

### 4.4. Вільний простір навколо графіки

Ілюстрації часто потребують достатнього простору, щоб не виглядати затиснутими.

Приклад структури:

    .hero {
      display: grid;
      grid-template-columns: 1fr 1fr;
      align-items: center;
      gap: 3rem;
    }

    .hero__illustration {
      width: 100%;
      max-width: 32rem;
      justify-self: center;
    }

Точні значення залежать від макета. Важливо перевіряти композицію на реальному контенті, а не лише на умовних заглушках.

## 5. Колір в ілюстраціях

Колір допомагає поєднати ілюстрацію з інтерфейсом.

### 5.1. Використання кольорів дизайн-системи

За можливості використовуй кольори, які вже є в інтерфейсі:

- основний брендового кольору;
- додаткові кольори;
- нейтральні відтінки;
- кольори станів;
- кольори поверхонь і фону.

Не обов'язково обмежувати ілюстрацію лише кольорами кнопок та тексту. Вона може мати власну палітру, якщо це підтримує загальний стиль.

### 5.2. Контраст

Ілюстрація повинна залишатися помітною на своєму фоні.

Перевір:

- чи не зникають світлі деталі на білому фоні;
- чи не губляться темні елементи на темній поверхні;
- чи достатньо чітко розрізняються основні форми;
- чи не конфліктує палітра з текстом і кнопками.

Якщо графіка містить текст, вимоги до контрасту цього тексту потрібно оцінювати окремо за правилами доступності.

### 5.3. Темна тема

Для темної теми можна підготувати окремий варіант ілюстрації або адаптувати її кольори.

Не варто автоматично інвертувати всі кольори: це може зіпсувати вигляд персонажів, градієнтів і тіней.

Для простих SVG можна використовувати CSS-змінні.

    :root {
      --illustration-primary: #356ae6;
      --illustration-secondary: #b8d5ff;
    }

    .illustration__primary {
      fill: var(--illustration-primary);
    }

    .illustration__secondary {
      fill: var(--illustration-secondary);
    }

Цей спосіб працює, якщо SVG вбудований у HTML або його елементи доступні для стилізації. Для SVG, підключеного через `img`, зовнішній CSS зазвичай не може змінювати внутрішні елементи файла.

## 6. Ілюстрації в різних частинах інтерфейсу

### 6.1. Hero-блок

Hero — це головна вступна секція сторінки.

Ілюстрація тут може:

- пояснювати призначення продукту;
- демонструвати результат використання;
- створювати візуальний акцент;
- підтримувати головне повідомлення.

Не варто додавати графіку, яка не має очевидного зв'язку з темою сторінки.

### 6.2. Onboarding

Onboarding допомагає новому користувачу ознайомитися з продуктом.

Ілюстрації можуть показувати:

- послідовність дій;
- основні можливості;
- результат налаштування;
- принцип роботи функції.

Кожна ілюстрація повинна відповідати конкретному етапу, а не просто прикрашати екран.

### 6.3. Порожній стан (Empty State)

Empty state — це стан, коли в інтерфейсі ще немає даних або елементів.

Наприклад:

- немає створених проєктів;
- немає повідомлень;
- список завдань порожній;
- користувач ще не додав записи.

Хороший empty state містить:

1. Ілюстрацію, якщо вона допомагає пояснити стан.
2. Короткий заголовок.
3. Пояснення.
4. Наступну рекомендовану дію, якщо вона доречна.

Приклад:

    Ще немає проєктів

    Створіть перший проєкт, щоб почати роботу.

    [Створити проєкт]

Ілюстрація не повинна замінювати пояснення або основну кнопку.

### 6.4. Стан помилки (Error State)

Ілюстрація може пом'якшувати повідомлення про помилку, але не повинна приховувати суть проблеми.

Наприклад:

    Не вдалося завантажити дані

    Перевірте підключення до інтернету та спробуйте ще раз.

    [Спробувати знову]

Не покладайся лише на колір або сумний персонаж. Причина проблеми та доступна дія мають бути зрозумілими з тексту.

### 6.5. Успішна дія (Success State)

Ілюстрації можуть підтримувати повідомлення про успішне завершення процесу:

- реєстрації;
- надсилання форми;
- створення документа;
- завершення уроку;
- збереження налаштувань.

Візуальний ефект має відповідати важливості події. Для звичайного збереження може вистачити невеликої іконки, тоді як завершення довгого процесу може заслуговувати на окрему ілюстрацію.

### 6.6. Навчальні картки

В освітньому інтерфейсі ілюстрації можуть допомагати розрізняти предмети, уроки та теми.

Наприклад, на платформі інформатики:

- ілюстрація комп'ютера — вступ до теми пристроїв;
- блок-схема — алгоритми;
- персонаж біля коду — програмування;
- мережеві вузли — комп'ютерні мережі.

Важливо, щоб графіка підтримувала навчальну мету й не створювала хибного уявлення про матеріал.

## 7. Формати файлів

Вибір формату залежить від типу ілюстрації та способу її використання.

| Формат | Коли використовувати | Особливості |
|---|---|---|
| SVG | Векторні ілюстрації, прості схеми | Масштабується без втрати чіткості |
| PNG | Растрова графіка з прозорістю | Підтримує прозорість, може бути важким |
| WebP | Растрові ілюстрації для вебу | Підтримує стиснення та прозорість |
| AVIF | Стиснені растрові зображення | Часто забезпечує високу ефективність стиснення |
| JPEG | Складні растрові зображення без прозорості | Не підтримує альфа-прозорість |
| GIF | Проста анімація з обмеженою палітрою | Не найкращий вибір для складної сучасної анімації |

Для простої векторної графіки часто зручно використовувати SVG. Для складних растрових ілюстрацій варто порівнювати WebP, AVIF та інші відповідні формати.

### 7.1. SVG

Переваги:

- масштабування без пікселізації;
- можливість стилізації доступних елементів;
- підтримка прозорості;
- зручність для геометричної графіки.

Недоліки та застереження:

- складні SVG можуть мати великий розмір;
- зайві елементи та метадані збільшують файл;
- SVG із невідомого джерела може містити небезпечний вміст;
- зовнішні CSS-правила не завжди можуть стилізувати SVG, підключений через `img`.

Використовуй перевірені SVG-файли та оптимізуй їх перед публікацією.

### 7.2. Приклад підключення SVG

    <img
      src="/images/learning-illustration.svg"
      alt="Учень працює за комп'ютером"
      width="480"
      height="360"
    />

Атрибути `width` і `height` допомагають браузеру заздалегідь визначити простір для зображення.

Якщо ілюстрація лише декоративна й не додає інформації, можна використати порожній `alt`:

    <img
      src="/images/decorative-shapes.svg"
      alt=""
      width="480"
      height="360"
    />

## 8. Розмір і масштабування

Ілюстрації можуть використовуватися в різних компонентах, тому важливо правильно керувати їхнім розміром.

### 8.1. Не збільшуй маленькі растрові зображення

Якщо растрова ілюстрація має недостатню роздільну здатність, її збільшення може призвести до розмиття.

Для SVG це зазвичай не проблема, якщо сам файл підготовлений коректно.

### 8.2. Використовуй обмеження ширини

    .illustration {
      display: block;
      width: 100%;
      max-width: 30rem;
      height: auto;
      margin-inline: auto;
    }

`width: 100%` дозволяє графіці займати доступну ширину контейнера.

`max-width` обмежує максимальний розмір.

`height: auto` зберігає пропорції зображення.

### 8.3. Збереження пропорцій

Не змінюй ширину та висоту незалежно, якщо це спотворює оригінальну графіку.

Для звичайного зображення:

    .illustration img {
      display: block;
      max-width: 100%;
      height: auto;
    }

Якщо ілюстрація повинна заповнювати фіксовану область, можна використати `object-fit`.

    .illustration-frame {
      width: 100%;
      aspect-ratio: 4 / 3;
      overflow: hidden;
    }

    .illustration-frame img {
      width: 100%;
      height: 100%;
      object-fit: contain;
    }

`contain` показує всю ілюстрацію, зберігаючи її пропорції. Якщо потрібне заповнення всієї області з обрізанням, можна використати `cover`.

Для більшості ілюстрацій `contain` є хорошим початковим вибором, оскільки важливі деталі не обрізаються.

## 9. Адаптивні ілюстрації

Ілюстрація повинна залишатися зрозумілою на різних розмірах екрана.

### 9.1. Desktop

На широкому екрані можна розташувати текст та ілюстрацію поруч.

    .hero {
      display: grid;
      grid-template-columns: minmax(0, 1fr) minmax(0, 1fr);
      align-items: center;
      gap: 2rem;
    }

### 9.2. Mobile

На вузькому екрані елементи часто краще розташовувати вертикально.

    @media (max-width: 48rem) {
      .hero {
        grid-template-columns: 1fr;
        gap: 1.5rem;
      }

      .hero__illustration {
        max-width: 22rem;
        margin-inline: auto;
      }
    }

### 9.3. Спрощення на малих екранах

Деякі складні ілюстрації містять багато дрібних деталей. На мобільному екрані вони можуть стати нерозбірливими.

Можливі рішення:

- використовувати спрощену версію;
- зменшити декоративні деталі;
- змінити композицію;
- перемістити графіку нижче основного тексту;
- приховати лише ті декоративні елементи, які не потрібні для розуміння.

Не приховуй важливу інформацію лише тому, що екран малий.

## 10. Доступність ілюстрацій (Accessibility)

Доступність означає, що інтерфейс залишається зрозумілим для людей із різними потребами та способами взаємодії.

### 10.1. Альтернативний текст

Для змістовної ілюстрації використовуй опис, який передає її важливий зміст.

    <img
      src="/images/online-learning.svg"
      alt="Учениця проходить онлайн-урок за ноутбуком"
    />

Не потрібно починати кожен опис зі слів «зображення» або «ілюстрація», якщо це не додає корисної інформації.

### 10.2. Декоративні ілюстрації

Якщо графіка лише прикрашає сторінку та не додає змісту, використовуй порожній `alt`.

    <img src="/images/decorative-waves.svg" alt="" />

Це дозволяє допоміжним технологіям пропустити декоративний елемент.

### 10.3. Не передавай важливу інформацію лише графікою

Якщо ілюстрація показує помилку, результат або інструкцію, важливий зміст потрібно передати текстом.

Наприклад, не варто повідомляти про невдале завантаження лише червоним малюнком. Додай пояснення та, якщо можливо, спосіб виправити ситуацію.

### 10.4. Ілюстрації з текстом усередині

Якщо графіка містить важливий текст, переконайся, що він доступний для користувачів.

Краще розміщувати основний текст HTML-елементами, а не вбудовувати його в растрове зображення.

### 10.5. SVG та доступність

Якщо SVG використовується як змістовна графіка, забезпеч її зрозумілим альтернативним описом відповідно до способу підключення.

Для простих декоративних SVG, вбудованих безпосередньо в HTML, можна використати `aria-hidden="true"`, якщо вони не повинні потрапляти до дерева доступності.

    <svg aria-hidden="true" viewBox="0 0 100 100">
      <!-- Decorative shapes -->
    </svg>

Не додавай `aria-hidden="true"` до елементів, які передають важливу інформацію або містять доступні для взаємодії компоненти.

## 11. Анімація ілюстрацій

Анімація може привертати увагу, пояснювати рух або робити інтерфейс живішим.

Приклади:

- плавна поява персонажа;
- рух невеликих декоративних елементів;
- коротка анімація успішного завершення;
- послідовне відображення частин схеми.

### 11.1. Коли анімація доречна

Використовуй її, якщо вона:

- допомагає зрозуміти процес;
- підкреслює результат дії;
- не затримує роботу;
- не відволікає від тексту;
- не створює зайвого навантаження.

### 11.2. CSS-анімація

    .illustration {
      animation: illustration-appear 500ms ease-out both;
    }

    @keyframes illustration-appear {
      from {
        opacity: 0;
        transform: translateY(12px);
      }

      to {
        opacity: 1;
        transform: translateY(0);
      }
    }

Це простий приклад появи ілюстрації. У реальному інтерфейсі потрібно перевірити, чи не заважає анімація користувачам.

### 11.3. Підтримка reduced motion

Деякі користувачі віддають перевагу зменшенню анімації.

    @media (prefers-reduced-motion: reduce) {
      .illustration {
        animation: none;
      }
    }

Цей приклад вимикає зазначену анімацію, якщо користувач налаштував зменшення руху в системі.

### 11.4. Чого слід уникати

- нескінченного руху без практичної мети;
- миготіння;
- надмірних паралакс-ефектів;
- різких переміщень;
- анімації, яка затримує доступ до кнопки;
- автоматичного руху, що відволікає від читання.

## 12. Ілюстрації в дизайн-системі

У дизайн-системі потрібно визначити правила використання графіки.

### 12.1. Що варто стандартизувати

- стиль ілюстрацій;
- палітру;
- пропорції;
- типові розміри;
- правила використання SVG та растрових форматів;
- варіанти для світлої й темної тем;
- відступи навколо графіки;
- правила адаптивності;
- вимоги до альтернативного тексту;
- правила використання анімації.

### 12.2. Токени для ілюстрацій

Можна створити CSS-змінні для основних параметрів.

    :root {
      --illustration-max-width: 30rem;
      --illustration-gap: 2rem;
      --illustration-radius: 0.75rem;
    }

    .illustration {
      display: block;
      width: 100%;
      max-width: var(--illustration-max-width);
      height: auto;
      border-radius: var(--illustration-radius);
    }

Не всі ілюстрації потребують заокруглення кутів. Використовуй цей токен лише там, де це відповідає дизайну.

### 12.3. Бібліотека ілюстрацій

Зручно зберігати графіку в окремій папці з передбачуваними назвами.

    public/
    └── images/
        └── illustrations/
            ├── onboarding-learning.svg
            ├── empty-projects.svg
            ├── error-network.svg
            ├── success-complete.svg
            └── hero-education.svg

Назви повинні описувати призначення файлу, а не лише його колір або зовнішній вигляд.

Наприклад, `empty-projects.svg` зрозуміліше за `blue-person-02.svg`.

## 13. Оптимізація ілюстрацій

Великі графічні файли можуть уповільнювати завантаження сторінки.

### 13.1. Що потрібно перевіряти

- розмір файлу;
- кількість зайвих елементів;
- розмір вбудованих растрових зображень;
- складність SVG;
- наявність непотрібних метаданих;
- відповідність фактичного розміру області відображення;
- можливість використання сучаснішого формату.

### 13.2. Оптимізація SVG

Для SVG можна:

- видалити зайві метадані;
- скоротити непотрібні атрибути;
- об'єднати зайві групи, якщо це безпечно;
- спростити надмірно складні контури;
- перевірити, чи немає прихованих елементів.

Після оптимізації обов'язково перевір, що графіка не змінила вигляд і не втратила потрібні властивості.

### 13.3. Не завантажуй графіку завчасно без потреби

Якщо ілюстрація розташована далеко нижче першого екрана, її можна завантажувати відкладено.

    <img
      src="/images/illustrations/empty-projects.webp"
      alt=""
      width="400"
      height="300"
      loading="lazy"
    />

Для ключового зображення у верхній частині сторінки відкладене завантаження може бути недоречним, оскільки воно затримує появу важливого контенту.

### 13.4. Не використовуй надмірну кількість графіки

Кожна ілюстрація має виправдовувати свою присутність.

Надлишок декоративних зображень може:

- збільшити час завантаження;
- перевантажити сторінку;
- знизити помітність важливих елементів;
- створити непослідовний візуальний стиль.

## 14. Практичний приклад: ілюстрація в картці

Створимо картку навчального курсу з ілюстрацією, заголовком, описом і посиланням.

### HTML

    <article class="course-card">
      <img
        class="course-card__image"
        src="/images/illustrations/programming.svg"
        alt=""
        width="480"
        height="320"
      />

      <div class="course-card__content">
        <h2 class="course-card__title">
          Основи програмування
        </h2>

        <p class="course-card__description">
          Вивчайте алгоритми, змінні та умови на практичних прикладах.
        </p>

        <a class="course-card__link" href="/courses/programming">
          Переглянути курс
        </a>
      </div>
    </article>

У цьому прикладі `alt=""` доречний, якщо ілюстрація лише прикрашає картку, а назва та опис уже передають потрібну інформацію. Якщо малюнок містить унікальну важливу інформацію, альтернативний текст потрібно змінити.

    .course-card {

      overflow: hidden;

      border-radius: 1rem;
      background: #ffffff;

      align-content: start;

    .course-card__title {
      margin: 0;
      font-size: 1.25rem;
      line-height: 1.3;
    }

    .course-card__description {
      margin: 0;
      line-height: 1.6;
      color: #465365;
    }

    .course-card__link {
      justify-self: start;
      font-weight: 600;
      color: #2459c4;
      text-decoration: underline;
      text-underline-offset: 0.2em;
    }

### Що потрібно перевірити

1. Чи зрозуміло, про що курс.
2. Чи не переважає ілюстрація над текстом.
3. Чи не обрізається важлива частина графіки.
4. Чи читається текст на мобільному екрані.
5. Чи помітне посилання.
6. Чи не виникає горизонтального прокручування.
7. Чи відповідає стиль ілюстрації іншим карткам сайту.

## 16. Типові помилки

### Помилка 1. Ілюстрація не відповідає змісту

Зображення може бути красивим, але не пояснювати призначення сторінки.

**Рішення:** обирай графіку, пов'язану з основною темою та завданням користувача.

### Помилка 2. Змішування несумісних стилів

На одній сторінці використовуються плоскі персонажі, реалістичні 3D-об'єкти та різні набори контурів без спільного принципу.

**Рішення:** створи правила стилю та перевіряй нові ілюстрації на відповідність цим правилам.

### Помилка 3. Ілюстрація перевантажена деталями

На невеликому екрані дрібні елементи стають нерозбірливими.

**Рішення:** спрощуй графіку або готуй окремий адаптивний варіант.

### Помилка 4. Ілюстрація замінює текст

Користувач бачить малюнок, але не розуміє, що сталося або що потрібно зробити.

**Рішення:** додавай зрозумілий текст і необхідну дію.

### Помилка 5. Неправильний `alt`

Альтернативний текст може бути надто загальним, надмірно довгим або повторювати весь текст поруч.

**Рішення:** описуй важливу інформацію, яку передає саме зображення. Для суто декоративної графіки використовуй `alt=""`.

### Помилка 6. Спотворення пропорцій

Ілюстрація розтягується через одночасне встановлення несумісних ширини та висоти.

**Рішення:** використовуй `height: auto` або відповідний `object-fit`.

### Помилка 7. Надмірна анімація

Рух відволікає від основного завдання або створює дискомфорт.

**Рішення:** використовуй анімацію помірно та враховуй `prefers-reduced-motion`.

### Помилка 8. Надто великі файли

Сторінка завантажується повільно через важку графіку.

**Рішення:** оптимізуй файли, обирай відповідний формат і завантажуй зображення відповідно до їхньої важливості.

### Помилка 9. Ілюстрація не працює в темній темі

Світлі елементи зливаються з фоном, а темні стають непомітними.

**Рішення:** перевіряй контраст і за потреби готуй адаптовану версію.

### Помилка 10. Графіка конкурує з кнопкою

Великий або яскравий малюнок відвертає увагу від основної дії.

**Рішення:** керуй розміром, кольором, розташуванням і візуальною ієрархією.

Ти повинен отримати невелику, послідовну бібліотеку ілюстрацій, яку можна повторно використовувати в різних компонентах освітнього сайту.

## 19. Чекліст перевірки ілюстрації

Перед завершенням дизайну перевір:

- [ ] Ілюстрація відповідає призначенню компонента.
- [ ] Стиль відповідає загальній дизайн-системі.
- [ ] Палітра узгоджена з інтерфейсом.
- [ ] Графіка не конкурує з основним повідомленням.
- [ ] Розмір і пропорції правильні.
- [ ] Важливі деталі не обрізаються.
- [ ] Ілюстрація адаптується до вузького екрана.
- [ ] Файл має відповідний формат.
- [ ] Графіка оптимізована.
- [ ] Змістовні зображення мають відповідний `alt`.
- [ ] Декоративні зображення не створюють зайвого шуму для допоміжних технологій.
- [ ] Важлива інформація не передається лише малюнком або кольором.
- [ ] Анімація не відволікає та враховує `prefers-reduced-motion`.
- [ ] Ілюстрація добре виглядає у світлій і темній темах, якщо обидві підтримуються.
- [ ] Графіка перевірена в реальному інтерфейсі.

## 20. Що потрібно запам'ятати

1. **Ілюстрація має завдання.** Вона пояснює, підтримує повідомлення, створює настрій або формує стиль бренду.
2. **Стиль повинен бути послідовним.** Форми, контури, палітра й деталізація мають працювати разом.
3. **Композиція важливіша за кількість графіки.** Ілюстрація повинна підтримувати текст і основну дію.
4. **Формат залежить від зображення.** SVG добре підходить для векторної графіки, а WebP, AVIF та інші растрові формати — для відповідних растрових ілюстрацій.
5. **Адаптивність обов'язкова.** Перевіряй розмір, пропорції та композицію на різних екранах.
6. **Доступність потрібно враховувати.** Змістовні ілюстрації потребують альтернативного опису, а декоративні зазвичай мають порожній `alt`.
7. **Анімація повинна допомагати.** Не додавай рух лише заради ефекту.
8. **Продуктивність має значення.** Оптимізуй графіку та завантажуй ресурси відповідно до їхньої важливості.
9. **Перевіряй контекст.** Одна й та сама ілюстрація може працювати в картці, але бути недоречною в повідомленні про помилку.
10. **Менше — не означає гірше.** Одна змістовна ілюстрація часто корисніша за багато випадкових декоративних елементів.

## 23. Коротка шпаргалка

| Поняття | Що запам'ятати |
|---|---|
| Illustration | Графіка, яка пояснює, підтримує повідомлення або створює настрій |
| Vector illustration | Графіка з геометричних форм, яка добре масштабується |
| Raster illustration | Піксельне зображення, яке потребує достатньої роздільної здатності |
| Flat illustration | Простий стиль із пласкими кольорами та мінімумом об'єму |
| 3D illustration | Графіка з відчуттям об'єму та перспективи |
| Character illustration | Ілюстрація з персонажем |
| Abstract illustration | Декоративна або концептуальна графіка з абстрактних форм |
| Visual hierarchy | Порядок, у якому користувач сприймає елементи |
| Empty state | Стан інтерфейсу без даних або елементів |
| Error state | Стан, у якому виникла проблема |
| SVG | Векторний формат для графіки |
| `object-fit` | Визначає, як зображення розміщується в заданій області |
| `alt` | Альтернативний текст для зображення |
| Decorative image | Зображення, яке не додає важливої інформації |
| Responsive illustration | Ілюстрація, яка коректно працює на різних екранах |
| `prefers-reduced-motion` | Медіазапит для врахування налаштування зменшення руху |
| Design system | Спільні правила стилю та використання компонентів і графіки |

**Головна думка:** хороша UI-ілюстрація не просто прикрашає сторінку. Вона підтримує зміст, відповідає стилю продукту, правильно працює на різних екранах і не створює перешкод для користувача.
