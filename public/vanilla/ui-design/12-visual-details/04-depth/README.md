# 04. Depth — Глибина в UI Design

Глибина (depth) — це принцип візуального дизайну, який допомагає створювати відчуття простору, відокремлювати елементи один від одного та показувати їхню відносну важливість в інтерфейсі.

У реальному світі ми сприймаємо предмети як розташовані ближче або далі від нас. У цифровому інтерфейсі всі елементи фактично відображаються на площині екрана, але за допомогою кольору, тіней, перекриття, масштабу та інших прийомів можна створити враження багаторівневого простору.

Глибина допомагає користувачеві зрозуміти:

- Які елементи розташовані на передньому плані.
- Які компоненти належать до основного вмісту.
- Які елементи плавають над сторінкою.
- Які області пов'язані між собою.
- Які компоненти перекривають інші.
- Які елементи є інтерактивними.
- На що варто звернути увагу насамперед.

Наприклад, модальне вікно розташовується над основним вмістом, а затемнення фону допомагає зосередити увагу на діалозі.

Головне правило UI Design:

> Глибина повинна допомагати користувачеві розуміти структуру інтерфейсу, а не створювати зайві декоративні ефекти.

---

## 1. Навіщо потрібна глибина

Глибина — це не тільки тіні. Це система візуальних прийомів, які створюють відчуття простору та ієрархії.

### 1.1. Візуальне розділення

Глибина допомагає відокремлювати компоненти від навколишнього вмісту.

Наприклад:

- Картка на фоні сторінки.
- Випадаюче меню над формою.
- Панель інструментів над робочою областю.
- Модальне вікно поверх сторінки.

### 1.2. Візуальна ієрархія

Не всі елементи інтерфейсу повинні сприйматися однаково.

Наприклад:

- Основний вміст утворює базовий рівень.
- Картки створюють додаткове розділення.
- Dropdown-меню розташовується над основним вмістом.
- Modal привертає увагу до важливої дії.

### 1.3. Орієнтація в інтерфейсі

Глибина допомагає користувачеві зрозуміти, що відбувається на екрані.

Наприклад, якщо відкривається модальне вікно, користувач бачить, що воно тимчасово перекриває основну сторінку.

### 1.4. Відображення взаємодії

Деякі елементи можуть змінювати візуальну висоту під час наведення або натискання.

Наприклад, картка може трохи підніматися під час наведення вказівника.

Однак не потрібно застосовувати такий ефект до кожного елемента. Візуальна поведінка повинна відповідати реальній функції компонента.

---

## 2. Основні поняття

✔ `Depth` — відчуття простору та відносного розташування елементів в інтерфейсі.

✔ `Elevation` — умовна візуальна висота елемента над базовою поверхнею.

✔ `Layer` — окремий візуальний рівень інтерфейсу.

✔ `Foreground` — передній план.

✔ `Background` — фон або задній план.

✔ `Overlap` — перекриття одного елемента іншим.

✔ `Shadow` — тінь, яка допомагає створювати відчуття глибини.

✔ `Contrast` — відмінність між елементами за кольором, яскравістю, формою або іншими ознаками.

✔ `Scale` — масштаб елемента.

✔ `Opacity` — непрозорість елемента.

✔ `Z-index` — CSS-властивість, яка бере участь у визначенні порядку накладання елементів.

✔ `Stacking context` — контекст накладання, у межах якого браузер визначає порядок малювання елементів.

✔ `Surface` — візуальна поверхня, на якій розміщено вміст.

✔ `Elevation system` — узгоджена система візуальних рівнів у дизайн-системі.

✔ Глибину можна передавати без тіней — за допомогою кольору, перекриття, масштабу та композиції.

✔ `z-index` не є універсальним способом виправлення всіх проблем накладання.

✔ Надмірна глибина робить інтерфейс візуально важким і може відволікати від основного вмісту.

---

## 3. Основні способи створення глибини

У UI Design немає єдиного прийому, який створює глибину в усіх ситуаціях. Зазвичай використовують декілька способів.

### 3.1. Тіні

Тіні створюють враження, що елемент розташований вище за поверхню.

    .card {
        background-color: #ffffff;
        box-shadow: 0 4px 12px rgb(0 0 0 / 10%);
    }

Тінь допомагає відокремити картку від фону.

### 3.2. Контраст поверхонь

Світліша або темніша поверхня може візуально виділятися на тлі іншої поверхні.

    .page {
        background-color: #f3f4f6;
    }

    .panel {
        background-color: #ffffff;
    }

У цьому прикладі картка виділяється завдяки відмінності кольорів, навіть без тіні.

### 3.3. Перекриття

Один елемент може частково перекривати інший.

    .avatar {
        position: relative;
        z-index: 1;
    }

Перекриття використовується для:

- Аватарів у групах.
- Вкладених карток.
- Плаваючих панелей.
- Меню та модальних вікон.
- Декоративних елементів композиції.

### 3.4. Масштаб

Більший елемент може здаватися візуально важливішим або ближчим.

Наприклад, велике зображення на першому екрані сторінки може сприйматися як головний об'єкт композиції.

Проте масштаб сам по собі не гарантує відчуття глибини. Він також залежить від розташування, контрасту та інших елементів.

### 3.5. Накладання кольорів

Напівпрозорий елемент може створювати враження поверхні над іншим вмістом.

    .overlay {
        background-color: rgb(0 0 0 / 40%);
    }

Цей прийом часто використовують для затемнення фону модального вікна.

### 3.6. Розмиття

Розмиття може допомагати візуально відокремлювати фонові елементи від переднього плану.

Наприклад, розмиття фону іноді використовують у діалогових вікнах або декоративних панелях.

Важливо: розмиття не повинно приховувати інформацію, яку користувачеві потрібно читати або використовувати.

## 4. Візуальні рівні — Layers

Layers — це умовні рівні, на яких розташовуються елементи інтерфейсу.

У простому інтерфейсі достатньо декількох рівнів.

Наприклад:

| Рівень | Призначення | Приклад |
|---|---|---|
| 0 | Базова поверхня | Фон сторінки |
| 1 | Основний вміст | Секції та звичайні картки |
| 2 | Підняті компоненти | Інтерактивні картки |
| 3 | Плаваючі компоненти | Dropdown, popover |
| 4 | Важливі накладені елементи | Modal, dialog |
| 5 | Спеціальні верхні шари | Глобальні повідомлення або критичні накладення |

Це умовний приклад, а не обов'язковий стандарт.

Реальна система залежить від складності продукту.

### 4.1. Чому потрібні рівні

Якщо кожен компонент має випадкову тінь і власний `z-index`, інтерфейс стає складним для підтримки.

Коли рівні визначені заздалегідь:

- Компоненти поводяться передбачувано.
- Меню не перекриваються випадковим чином.
- Модальні вікна мають узгоджений вигляд.
- Команді легше розуміти структуру інтерфейсу.
- Менше конфліктів між компонентами.

### 4.2. Приклад системи рівнів

    :root {
        --z-base: 0;
        --z-raised: 10;
        --z-dropdown: 100;
        --z-sticky: 200;
        --z-overlay: 300;
        --z-modal: 400;
        --z-toast: 500;
    }

Використання:

    .card {
        position: relative;
        z-index: var(--z-base);
    }

    .dropdown {
        position: absolute;
        z-index: var(--z-dropdown);
    }

    .modal {
        position: fixed;
        z-index: var(--z-modal);
    }

Ці числа умовні. Важливо не саме значення, а узгоджена система.

Не потрібно призначати високий `z-index` кожному елементу. Використовуйте його лише там, де справді потрібне контрольоване накладання.

## 5. Elevation — візуальна висота

Elevation описує, наскільки піднятим над базовою поверхнею здається елемент.

Це концепція дизайну, а не окрема CSS-властивість.

### 5.1. Низький рівень

Елемент майже не відокремлений від поверхні.

    .surface {
        background-color: #ffffff;
        border: 1px solid #e5e7eb;
    }

Застосування:

- Звичайні панелі.
- Секції сторінки.
- Форми.
- Контентні блоки.

### 5.2. Середній рівень

Елемент має легку тінь або виразніший контраст.

    .card {
        background-color: #ffffff;
        box-shadow: 0 3px 10px rgb(0 0 0 / 9%);
    }

Застосування:

- Картки.
- Інтерактивні блоки.
- Окремі інформаційні панелі.

### 5.3. Високий рівень

Елемент виразно відокремлений від основного вмісту.

    .popover {
        background-color: #ffffff;
        box-shadow: 0 10px 28px rgb(0 0 0 / 16%);
    }

Застосування:

- Випадаючі меню.
- Popover.
- Контекстні панелі.

### 5.4. Найвищий рівень

Елемент привертає увагу та перекриває значну частину інтерфейсу.

    .dialog {
        background-color: #ffffff;
        box-shadow: 0 16px 48px rgb(0 0 0 / 20%);
    }

Застосування:

- Модальні вікна.
- Діалогові повідомлення.
- Важливі накладені інтерфейси.

### 5.5. Важливе зауваження

Вища візуальна висота не обов'язково означає більшу функціональну важливість.

Наприклад, модальне вікно може мати сильнішу тінь, ніж кнопка, але це не означає, що всі модальні вікна є найважливішими елементами продукту.

Elevation показує просторове відокремлення, а не повну ієрархію значущості.

## 6. Глибина за допомогою кольору

Колір — один із найпростіших способів створити відчуття різних поверхонь.

### 6.1. Світла поверхня на сірому фоні

    body {
        background-color: #f3f4f6;
    }

    .card {
        background-color: #ffffff;
    }

Контраст поверхонь допомагає розрізняти картку та фон.

### 6.2. Темніша панель

    .sidebar {
        background-color: #e5e7eb;
    }

    .content {
        background-color: #ffffff;
    }

Відмінність кольорів допомагає структурувати сторінку без складних ефектів.

### 6.3. Темна тема

У темній темі глибину можна передавати кількома відтінками темних поверхонь.

    :root {
        --surface-page: #111827;
        --surface-panel: #1f2937;
        --surface-raised: #374151;
    }

    body {
        background-color: var(--surface-page);
    }

    .panel {
        background-color: var(--surface-panel);
    }

    .panel--raised {
        background-color: var(--surface-raised);
    }

Важливо не робити сусідні поверхні настільки схожими, щоб структура стала непомітною.

Також не варто використовувати лише колір для передавання важливого стану. Інформація про помилку, вибір або фокус повинна мати достатньо зрозумілі візуальні ознаки.

---

## 7. Глибина за допомогою тіней

Тіні часто використовують для відокремлення компонентів від поверхні.

Докладніше властивості `box-shadow` розглядаються в темі `03-shadows`.

### 7.1. Картка

    .card {
        background-color: #ffffff;
        box-shadow: 0 2px 8px rgb(0 0 0 / 8%);
    }

### 7.2. Плаваюче меню

    .dropdown {
        background-color: #ffffff;
        box-shadow: 0 8px 24px rgb(0 0 0 / 14%);
    }

### 7.3. Модальне вікно

    .modal {
        background-color: #ffffff;
        box-shadow: 0 16px 48px rgb(0 0 0 / 20%);
    }

### 7.4. Не всі елементи потребують тіней

У мінімалістичному інтерфейсі достатньо використати:

- Колір фону.
- Межі.
- Відступи.
- Візуальне групування.
- Правильне розташування.

Тіні варто додавати тоді, коли вони покращують сприйняття структури.

---

## 8. Глибина за допомогою перекриття

Перекриття виникає, коли один елемент частково закриває інший.

Це може створювати відчуття простору, послідовності та взаємного розташування компонентів.

### 8.1. Група аватарів

    .avatar {
        width: 40px;
        height: 40px;
        border: 2px solid #ffffff;
        border-radius: 50%;
        object-fit: cover;
    }

    .avatar + .avatar {
        margin-inline-start: -12px;
    }

Аватари частково перекриваються, утворюючи компактну групу.

### 8.2. Картка поверх іншої картки

    .stack {
        position: relative;
    }

    .stack__back {
        position: absolute;
        inset: 12px -12px -12px 12px;
        background-color: #dbeafe;
        border-radius: 12px;
    }

    .stack__front {
        position: relative;
        background-color: #ffffff;
        border: 1px solid #e5e7eb;
        border-radius: 12px;
    }

Такий прийом може бути доречним у декоративній композиції або на промосторінці.

Не варто застосовувати подібне накладання до кожної інформаційної картки: воно може ускладнювати читання.

### 8.3. Зображення з накладеним текстом

    .hero {
        position: relative;
        min-height: 360px;
        background-image: url("/images/hero.jpg");
        background-size: cover;
        background-position: center;
    }

    .hero__content {
        position: absolute;
        inset-inline: 24px;
        bottom: 24px;
        color: #ffffff;
    }

Текст розташовується поверх зображення.

Для читабельності може знадобитися градієнт або затемнення фону.

### 8.4. Не плутайте перекриття з порядком DOM

Візуальне накладання не означає, що один елемент обов'язково повинен бути вкладений в інший у HTML.

Структуру DOM слід визначати відповідно до змісту та семантики. Позиціювання і накладання налаштовуються CSS.

## 9. `z-index` та порядок накладання

`z-index` впливає на порядок малювання елементів у межах відповідного контексту накладання.

### 9.1. Простий приклад

    .box {
        position: absolute;
        width: 120px;
        height: 120px;
    }

    .box--blue {
        top: 20px;
        left: 20px;
        z-index: 1;
        background-color: #2563eb;
    }

    .box--red {
        top: 60px;
        left: 60px;
        z-index: 2;
        background-color: #dc2626;
    }

Червоний елемент має вищий `z-index` і в цьому прикладі перекриває синій там, де вони перетинаються.

### 9.2. Для чого потрібен `position`

`z-index` найчастіше використовують разом із позиціюванням:

    .element {
        position: relative;
        z-index: 1;
    }

У сучасному CSS `z-index` працює не лише з позиційованими елементами: він також застосовується в деяких інших контекстах, зокрема до flex- та grid-елементів.

Тому не потрібно вважати `position: relative` обов'язковою умовою для кожного випадку.

### 9.3. Проблема stacking context

Іноді елемент із великим `z-index` усе одно залишається під іншим елементом.

Причина може полягати в тому, що елементи перебувають у різних контекстах накладання.

Контекст накладання можуть створювати, зокрема:

- Елемент із `position` і відповідним `z-index`.
- Елемент із `position: fixed` або `position: sticky`.
- Елемент із `opacity`, меншою за `1`.
- Елемент із `transform`, відмінним від `none`.
- Елемент із деякими значеннями `filter`, `isolation` та іншими властивостями.

Приклад:

    .parent {
        position: relative;
        z-index: 1;
        transform: translateZ(0);
    }

    .child {
        position: absolute;
        z-index: 9999;
    }

Навіть великий `z-index` дочірнього елемента не дозволяє йому вільно конкурувати з елементами за межами контексту його батьківського елемента.

### 9.4. Як виправляти проблеми накладання

1. Перевірте, які елементи перекривають один одного.
2. Знайдіть їхні батьківські контейнери.
3. Перевірте створення stacking context.
4. Перевірте `z-index` батьківських елементів.
5. Перевірте `overflow`.
6. Переконайтеся, що елемент розташований у правильній частині DOM.
7. Не збільшуйте `z-index` навмання.

У складних інтерфейсах доцільно мати узгоджену систему шарів.

## 10. Глибина та `overflow`

`overflow` визначає, що відбувається з вмістом, який виходить за межі контейнера.

### 10.1. Обрізання вмісту

    .container {
        overflow: hidden;
    }

Такий контейнер може обрізати:

- Тіні дочірніх елементів.
- Випадаючі меню.
- Декоративні елементи.
- Частини зображень.
- Індикатори фокусу.

### 10.2. Картка з обрізаним зображенням

    .card {
        overflow: hidden;
        border-radius: 12px;
    }

Це може бути доречним, якщо потрібно обрізати зображення відповідно до форми картки.

Але якщо та сама картка має плаваюче меню або фокусний індикатор, обрізання може створити проблему.

### 10.3. Практичне рішення

Не видаляйте `overflow: hidden` автоматично.

Спочатку визначте, навіщо він використовується.

Можливі рішення:

- Перенести плаваючий елемент за межі контейнера, який обрізає вміст.
- Розділити контейнер для обрізання зображення і контейнер для накладених елементів.
- Переглянути структуру компонента.
- Використати відповідний механізм позиціювання.

## 11. Глибина в модальних вікнах

Модальне вікно — класичний приклад багаторівневого інтерфейсу.

Зазвичай воно складається з:

1. Основного вмісту сторінки.
2. Затемнення фону — backdrop.
3. Самого діалогового вікна.

### 11.1. HTML

    <main class="page">
        <h1>Налаштування профілю</h1>
        <p>Основний вміст сторінки.</p>
    </main>

    <div class="modal-backdrop">
        <section
            class="modal"
            role="dialog"
            aria-modal="true"
            aria-labelledby="modal-title"
        >
            <h2 id="modal-title">Зберегти зміни?</h2>
            <p>Ваші зміни будуть збережені.</p>

            <button type="button">Скасувати</button>
            <button type="button">Зберегти</button>
        </section>
    </div>

Цей фрагмент демонструє лише структуру. Для повноцінного модального вікна потрібна відповідна логіка керування фокусом, клавіатурною навігацією, закриттям і станом діалогу.

### 11.2. CSS

    .modal-backdrop {
        position: fixed;
        inset: 0;
        z-index: 300;
        display: grid;
        place-items: center;
        padding: 24px;
        background-color: rgb(0 0 0 / 45%);
    }

    .modal {
        width: min(100%, 480px);
        padding: 24px;
        border-radius: 16px;
        background-color: #ffffff;
        box-shadow: 0 16px 48px rgb(0 0 0 / 20%);
    }

Backdrop і тінь виконують різні функції:

- Backdrop зменшує візуальну помітність фонового вмісту.
- Тінь підкреслює межі діалогу.
- Контраст поверхонь допомагає розпізнати діалог як окремий компонент.

### 11.3. Доступність модального вікна

Для повноцінного діалогу потрібно врахувати:

- Переміщення фокусу всередину діалогу після відкриття.
- Утримання клавіатурного фокусу в модальному вікні, коли це потрібно.
- Можливість закриття відповідно до поведінки компонента.
- Повернення фокусу до елемента, який відкрив діалог.
- Достатній контраст тексту та кнопок.
- Коректні доступні назву й семантику.

Візуальна глибина не замінює функціональної доступності.

## 12. Глибина у dropdown і popover

Dropdown або popover розташовується поверх основного вмісту.

### 12.1. Приклад CSS

    .dropdown {
        position: absolute;
        top: calc(100% + 8px);
        inset-inline-start: 0;
        z-index: 100;
        min-width: 200px;
        padding: 8px;
        border: 1px solid #e5e7eb;
        border-radius: 10px;
        background-color: #ffffff;
        box-shadow: 0 8px 24px rgb(0 0 0 / 14%);
    }

Тут глибина створюється комбінацією:

- Окремого фонового кольору.
- Межі.
- Тіні.
- Позиціювання.
- Порядку накладання.

### 12.2. Чому одного `z-index` недостатньо

Навіть якщо dropdown має великий `z-index`, його може обрізати батьківський контейнер.

Також він може опинитися під елементом із вищим stacking context.

Тому для складних меню іноді використовують механізми винесення елемента за межі локального контейнера або інші архітектурні рішення.

### 12.3. Глибина не повинна заважати взаємодії

Переконайтеся, що меню:

- Не перекриває важливі кнопки без потреби.
- Не виходить за межі екрана.
- Не обрізається контейнерами.
- Має зрозумілий візуальний зв'язок із тригером.
- Доступне для потрібних способів введення.

## 13. Глибина в картках і панелях

Картки можуть бути пласкими або візуально піднятими.

### 13.1. Пласка картка

    .card {
        padding: 24px;
        border: 1px solid #e5e7eb;
        border-radius: 12px;
        background-color: #ffffff;
    }

Відокремлення створюється завдяки межі та кольору.

### 13.2. Картка з легкою глибиною

    .card {
        padding: 24px;
        border-radius: 12px;
        background-color: #ffffff;
        box-shadow: 0 2px 8px rgb(0 0 0 / 8%);
    }

### 13.3. Інтерактивна картка

    .card--interactive {
        transition:
            transform 180ms ease,
            box-shadow 180ms ease;
    }

    .card--interactive:hover {
        transform: translateY(-2px);
        box-shadow: 0 8px 20px rgb(0 0 0 / 12%);
    }

Зміна позиції та тіні створює відчуття підняття.

Використовуйте цей ефект лише тоді, коли він підтримує реальну поведінку компонента.

### 13.4. Вкладені панелі

    .dashboard {
        padding: 24px;
        background-color: #f3f4f6;
    }

    .dashboard__panel {
        padding: 20px;
        background-color: #ffffff;
        border: 1px solid #e5e7eb;
        border-radius: 12px;
    }

Не кожна вкладена панель повинна мати сильнішу тінь за батьківську.

Часто для відображення ієрархії достатньо відступів і різних фонів.

## 14. Глибина та композиція

Глибина допомагає не тільки розділяти компоненти, а й будувати композицію сторінки.

### 14.1. Передній план і фон

Наприклад, на промосторінці:

- Фонове зображення створює атмосферу.
- Основний заголовок розташовується на передньому плані.
- Кнопка є важливим інтерактивним елементом.
- Декоративна фігура може частково перекривати зображення.

Важливо, щоб декоративні елементи не заважали читати заголовок і знаходити основну дію.

### 14.2. Контраст між планами

Елемент може здаватися ближчим завдяки:

- Більшому контрасту.
- Чіткішим краям.
- Більшому масштабу.
- Перекриттю інших елементів.
- Виразнішій тіні.

Фонові елементи можуть мати менший контраст, але важлива інформація не повинна ставати нерозбірливою.

### 14.3. Візуальний баланс

Якщо на одній стороні сторінки багато піднятих карток із сильними тінями, а на іншій — лише плаский текст, композиція може здаватися нерівномірною.

Рішення:

- Узгодити рівні тіней.
- Перевірити розподіл великих і малих елементів.
- Переглянути контраст поверхонь.
- Не створювати глибину всюди одночасно.

---

## 15. Глибина в навігації

У навігаційних інтерфейсах глибина допомагає відокремлювати елементи керування від основного вмісту.

### 15.1. Закріплена верхня панель

    .header {
        position: sticky;
        top: 0;
        z-index: 200;
        background-color: #ffffff;
        border-bottom: 1px solid #e5e7eb;
    }

### 15.2. Панель із тінню

    .header {
        box-shadow: 0 2px 8px rgb(0 0 0 / 8%);
    }

Тінь може підкреслювати, що панель розташована над вмістом сторінки.

### 15.3. Коли тінь не потрібна

Якщо верхня панель візуально відокремлена фоном або межею, тінь може бути зайвою.

Глибина повинна відповідати загальній системі компонентів, а не бути обов'язковою прикрасою кожного блоку.

## 16. Глибина у світлій і темній темах

Глибина повинна зберігатися в різних колірних темах.

### 16.1. Світла тема

    :root {
        --surface-page: #f3f4f6;
        --surface-card: #ffffff;
        --surface-raised: #ffffff;
        --border-color: #e5e7eb;

### 16.2. Темна тема

    [data-theme="dark"] {
        --surface-page: #111827;
        --surface-card: #1f2937;
        --surface-raised: #374151;
        --border-color: #374151;
        --shadow-card: 0 4px 12px rgb(0 0 0 / 24%);
    }

### 16.3. Використання змінних

    body {
        background-color: var(--surface-page);
    }

    .card {
        background-color: var(--surface-card);
        border: 1px solid var(--border-color);

### 16.4. Особливості темної теми

У темній темі чорна тінь може бути майже непомітною.

Для створення глибини можна комбінувати:

- Відмінності кольорів поверхонь.
- Межі.
- Тіні.
- Контраст.
- Позиціювання.

Не потрібно автоматично робити всі тіні яскравішими. Спочатку перевірте, чи потрібна тінь узагалі.

## 17. Глибина та доступність

Глибина допомагає сприймати інтерфейс, але не повинна бути єдиним засобом передавання важливої інформації.

### 17.1. Не передавайте стан тільки тінню

Наприклад, якщо вибраний елемент відрізняється лише тінню, користувач може не помітити цей стан.

Краще комбінувати кілька ознак:

- Колір або межу.
- Іконку чи інший зрозумілий індикатор.
- Текстовий стан, коли він потрібен.
- Доступні програмні атрибути.

### 17.2. Фокус клавіатури

    .button:focus-visible {
        outline: 3px solid #2563eb;
        outline-offset: 3px;
    }

Контур фокусу повинен бути помітним і не обрізатися контейнером.

Не замінюйте його непомітною тінню.

### 17.3. Контраст

Переконайтеся, що:

- Текст читається на фоні.
- Межі важливих компонентів помітні.
- Елементи керування можна розрізнити.
- Стан фокусу має достатню видимість.
- Затемнення фону не погіршує сприйняття активного діалогу.

### 17.4. Зменшення руху

Якщо глибина передається за допомогою анімації, враховуйте налаштування зменшення руху.

    @media (prefers-reduced-motion: reduce) {
        .card,
        .button {
            transition: none;
        }
    }

Глибина повинна залишатися зрозумілою навіть без анімації.

## 18. Типові помилки

### Помилка 1. Надмірна кількість тіней

Коли всі елементи мають виразні тіні, інтерфейс стає важким і перевантаженим.

Рішення: визначте, які компоненти справді повинні виглядати піднятими.

### Помилка 2. Випадкові рівні глибини

Якщо картка має сильнішу тінь, ніж модальне вікно, а dropdown виглядає пласким, ієрархія може бути непослідовною.

Рішення: створіть узгоджену систему elevation.

### Помилка 3. Використання `z-index` навмання

Великі значення на кшталт `999999` не є універсальним рішенням.

Рішення: перевіряйте stacking context, батьківські елементи та структуру накладання.

### Помилка 4. Спроба виправити накладання тільки тінню

Тінь не змінює порядок накладання елементів.

Рішення: перевірте `z-index`, позиціювання та контексти накладання.

### Помилка 5. Обрізані тіні

Тінь може бути обрізана контейнером із `overflow: hidden`.

Рішення: перевірте структуру контейнерів і розділіть відповідальність за обрізання та накладання.

### Помилка 6. Глибина без функціональної причини

Якщо кожна картка піднімається під час наведення, користувач може очікувати, що кожна з них інтерактивна.

Рішення: узгодьте візуальну поведінку з реальною функцією елемента.

### Помилка 7. Надмірне перекриття

Перекриті елементи можуть закривати текст, кнопки або важливі частини зображень.

Рішення: перевіряйте композицію на різних розмірах екрана.

### Помилка 8. Однакова система для світлої й темної тем

Тіні та контраст поверхонь можуть сприйматися по-різному.

Рішення: тестуйте обидві теми окремо.

### Помилка 9. Ігнорування доступності

Декоративний ефект не замінює видимого фокусу, текстових повідомлень і доступної структури.

Рішення: перевіряйте інтерфейс клавіатурою та допоміжними технологіями.

### Помилка 10. Надмірна складність

Складні багаторівневі композиції можуть ускладнювати читання простих сторінок.

Рішення: використовуйте найпростіший спосіб, який забезпечує потрібну ясність.

## 20. Мініпроєкт: багаторівневий інтерфейс

Мета — створити сторінку з базовим фоном, картками, випадаючою панеллю та модальним вікном.

## 21. Що потрібно запам'ятати

✔ Глибина — це відчуття простору та відносного розташування елементів.

✔ Глибина не обмежується тінями.

✔ Основні інструменти глибини — тіні, контраст поверхонь, перекриття, масштаб, колір і композиція.

✔ `Elevation` описує умовну візуальну висоту компонента.

✔ `Layer` — це візуальний рівень, на якому розташований елемент.

✔ `z-index` бере участь у визначенні порядку накладання елементів.

✔ Stacking context може обмежувати вплив `z-index`.

✔ `overflow: hidden` може обрізати тіні, меню та індикатори фокусу.

✔ Модальне вікно зазвичай відокремлюється від сторінки за допомогою backdrop, власної поверхні та тіні.

✔ Не всі картки повинні мати тінь.

✔ Не всі інтерактивні компоненти повинні підніматися під час наведення.

✔ Світла й темна теми потребують окремої перевірки.

✔ Глибина не замінює контраст, семантику та доступність.

✔ Візуальна висота не дорівнює функціональній важливості.

✔ Узгоджена система шарів спрощує підтримку великих інтерфейсів.

✔ Найкраща глибина — та, яка допомагає зрозуміти інтерфейс, не привертаючи зайвої уваги.

## 22. Типові питання на співбесіді

**1. Що таке depth у UI Design?**

Це відчуття простору та відносного розташування елементів, створене за допомогою візуальних прийомів.

**2. Якими способами можна створити глибину?**

За допомогою тіней, кольору, контрасту, перекриття, масштабу, розмиття та композиції.

**3. Що таке elevation?**

Концепція візуальної висоти елемента над базовою поверхнею.

**4. Чим elevation відрізняється від `z-index`?**

Elevation — концепція дизайну, а `z-index` — CSS-властивість, яка бере участь у визначенні порядку накладання.

**5. Чи достатньо використовувати тільки тіні?**

Ні. Глибину можна створювати також за допомогою кольору, меж, масштабу, перекриття та розташування.

**6. Що таке stacking context?**

Це контекст накладання, у межах якого браузер визначає порядок малювання елементів.

**7. Чому елемент із `z-index: 9999` може залишатися позаду іншого?**

Тому що він може перебувати всередині stacking context, який розташований нижче за інший контекст накладання.

**8. Як `overflow: hidden` впливає на глибину?**

Він може обрізати тіні, плаваючі елементи та інші частини вмісту, які виходять за межі контейнера.

**9. Навіщо потрібен backdrop у модальному вікні?**

Він візуально відокремлює активний діалог від фонового вмісту та допомагає зосередити увагу користувача.

**10. Чи повинна кожна картка мати тінь?**

Ні. Межі, відмінності поверхонь і відступи часто достатні.

**11. Як створити глибину в темній темі?**

Використовувати узгоджені кольори поверхонь, межі та тіні, перевіряючи їхню видимість на темному фоні.

**12. Чому глибина не повинна передавати стан тільки тінню?**

Тому що слабкий декоративний ефект може бути непомітним. Важливі стани повинні мати достатньо виразні візуальні ознаки.

**13. Як організувати рівні накладання у великому проєкті?**

Створити спільну систему рівнів і зберігати їх у CSS custom properties або інших централізованих дизайн-токенах.

**14. Чи завжди модальне вікно повинно мати найвищий `z-index`?**

Не обов'язково в усіх можливих системах, але воно повинно коректно накладатися на відповідний вміст. Рівні мають відповідати архітектурі застосунку.

**15. Яка головна помилка під час роботи з глибиною?**

Використання тіней і накладання без зрозумілої функції, що робить інтерфейс перевантаженим і непослідовним.

### Швидкі CSS-приклади

Легка тінь:

    box-shadow: 0 2px 8px rgb(0 0 0 / 8%);

Піднята картка:

    transform: translateY(-2px);
    box-shadow: 0 8px 20px rgb(0 0 0 / 12%);

Плаваюче меню:

    position: absolute;
    z-index: 100;

Модальне затемнення:

    position: fixed;
    inset: 0;
    background-color: rgb(0 0 0 / 45%);

Змінні рівнів:

    :root {
        --z-dropdown: 100;
        --z-sticky: 200;
        --z-backdrop: 300;
        --z-modal: 400;
    }

## Висновок

Глибина — це важливий принцип UI Design, який допомагає створювати зрозумілу структуру інтерфейсу та показувати відносне розташування компонентів.

Для створення глибини використовують тіні, колір, контраст, перекриття, масштаб і композицію. У CSS важливо також розуміти `z-index`, stacking context та поведінку `overflow`.

Під час роботи пам'ятайте:

- Спочатку визначайте структуру, потім додавайте декоративні ефекти.
- Використовуйте тіні лише там, де вони мають зрозумілу функцію.
- Відрізняйте візуальну висоту від функціональної важливості.
- Організовуйте рівні накладання послідовно.
- Не виправляйте проблеми `z-index` навмання.
- Перевіряйте компоненти на різних екранах і в різних темах.
- Не жертвуйте доступністю заради візуального ефекту.

**Мета — створити інтерфейс, у якому користувач легко розуміє, що є фоном, що належить до основного вмісту, а що розташоване поверх інших елементів.**
