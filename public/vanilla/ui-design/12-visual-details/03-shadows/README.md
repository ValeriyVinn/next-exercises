# 03. Shadows — Тіні в UI Design

Тіні (shadows) — це візуальний інструмент, який допомагає створювати відчуття глибини, відокремлювати елементи один від одного, підкреслювати ієрархію інтерфейсу та показувати взаємодію користувача з елементами.

У CSS тіні найчастіше створюються за допомогою властивостей `box-shadow` і `text-shadow`.

Тіні можуть допомогти користувачеві зрозуміти:

- Які елементи розташовані на передньому плані.
- Які картки або панелі відокремлені від фону.
- Який елемент зараз активний або перебуває у фокусі.
- Які елементи можна натискати або перетягувати.
- Де знаходяться модальні вікна, випадаючі меню та плаваючі панелі.

Головне правило UI Design:

> Тінь повинна допомагати сприймати інтерфейс, а не просто прикрашати його.

---

## 1. Навіщо потрібні тіні

Тіні можуть виконувати декілька функцій.

### 1.1. Створення глибини

Тінь допомагає візуально відокремити елемент від фону.

    .card {
        background-color: #ffffff;
        box-shadow: 0 4px 12px rgb(0 0 0 / 8%);
    }

Картка здається трохи піднятою над фоном.

### 1.2. Візуальна ієрархія

Різні рівні тіней допомагають розрізняти елементи за їхньою важливістю або положенням у просторі.

Наприклад:

- Невелика тінь — звичайна картка.
- Середня тінь — меню або плаваюча панель.
- Виразна тінь — модальне вікно.

### 1.3. Відокремлення елементів

Тінь може відокремлювати світлу картку від світлого фону, навіть якщо між ними немає помітної межі.

    .panel {
        background-color: #ffffff;
        box-shadow: 0 2px 8px rgb(0 0 0 / 6%);
    }

### 1.4. Відображення інтерактивності

Тіні можуть змінюватися під час взаємодії з кнопками, картками та іншими інтерактивними елементами.

    .button {
        box-shadow: 0 2px 4px rgb(0 0 0 / 12%);
    }

    .button:hover {
        box-shadow: 0 4px 8px rgb(0 0 0 / 16%);
    }

    .button:active {
        box-shadow: 0 1px 2px rgb(0 0 0 / 12%);
    }

Такі зміни можуть створювати відчуття, що кнопка піднімається під час наведення та опускається під час натискання.

Проте не кожна кнопка потребує тіні. Її використання залежить від загального стилю інтерфейсу.

---

## 2. Основні поняття

✔ `box-shadow` — створює тінь навколо прямокутної області елемента.

✔ `text-shadow` — створює тінь навколо тексту.

✔ `offset-x` — горизонтальне зміщення тіні.

✔ `offset-y` — вертикальне зміщення тіні.

✔ `blur-radius` — радіус розмиття тіні.

✔ `spread-radius` — збільшення або зменшення розміру тіні.

✔ `color` — колір тіні.

✔ `inset` — розміщує тінь усередині елемента.

✔ `multiple shadows` — дозволяє створювати декілька тіней для одного елемента.

✔ `elevation` — концепція візуальної висоти елемента над поверхнею.

✔ `shadow tokens` — повторно використовувані значення тіней у дизайн-системі.

✔ `focus shadow` — візуальний ефект навколо елемента, який перебуває у фокусі.

✔ `box-shadow` не змінює фактичні розміри елемента в CSS box model.

✔ Тіні можуть обрізатися контейнерами з `overflow: hidden` або іншими обмеженнями відображення.

✔ Тінь не повинна бути єдиним способом передавання важливої інформації про стан елемента.

---

## 3. Властивість `box-shadow`

`box-shadow` використовується для створення тіней навколо елементів.

Загальний синтаксис:

    selector {
        box-shadow: offset-x offset-y blur-radius spread-radius color;
    }

Приклад:

    .card {
        box-shadow: 0 4px 12px 0 rgb(0 0 0 / 10%);
    }

Параметри розташовуються в такому порядку:

    box-shadow: X Y BLUR SPREAD COLOR;

Де:

- `X` — горизонтальне зміщення.
- `Y` — вертикальне зміщення.
- `BLUR` — розмиття.
- `SPREAD` — розширення або звуження тіні.
- `COLOR` — колір.

Значення `spread-radius` і колір можна опускати.

### 3.1. Горизонтальне зміщення — `offset-x`

Визначає напрямок і величину горизонтального зміщення тіні.

    .element {
        box-shadow: 4px 0 8px rgb(0 0 0 / 15%);
    }

У цьому прикладі тінь зміщується праворуч.

    .element {
        box-shadow: -4px 0 8px rgb(0 0 0 / 15%);
    }

Тінь зміщується ліворуч.

Правило:

- Додатне значення — праворуч.
- Від'ємне значення — ліворуч.
- `0` — без горизонтального зміщення.

### 3.2. Вертикальне зміщення — `offset-y`

Визначає вертикальне зміщення тіні.

    .element {
        box-shadow: 0 6px 12px rgb(0 0 0 / 12%);
    }

Тінь зміщується вниз.

    .element {
        box-shadow: 0 -4px 10px rgb(0 0 0 / 12%);
    }

Тінь зміщується вгору.

Правило:

- Додатне значення — вниз.
- Від'ємне значення — вгору.
- `0` — без вертикального зміщення.

### 3.3. Розмиття — `blur-radius`

Визначає, наскільки м'якими будуть краї тіні.

    .card {
        box-shadow: 0 2px 4px rgb(0 0 0 / 12%);
    }

Тінь відносно компактна.

    .card {
        box-shadow: 0 8px 24px rgb(0 0 0 / 12%);
    }

Тінь більш розмита та розподілена на більшій площі.

Правило:

- `0` — чітка, нерозмита тінь.
- Невелике значення — компактна тінь.
- Велике значення — м'яка, широка тінь.

Занадто велике розмиття може зробити інтерфейс візуально нечітким.

### 3.4. Розширення — `spread-radius`

Визначає, наскільки збільшується або зменшується область тіні до застосування розмиття.

    .element {
        box-shadow: 0 0 0 2px #2563eb;
    }

У цьому прикладі створюється чіткий синій контур за допомогою тіні.

    .element {
        box-shadow: 0 0 0 -2px #2563eb;
    }

Від'ємне значення зменшує область тіні. У цьому прикладі зовнішня тінь практично не буде помітною.

Позитивний `spread-radius` може допомогти створити ефект контуру, а від'ємний — зробити тінь компактнішою.

### 3.5. Колір тіні

Для тіней часто використовують чорний колір із прозорістю.

    .card {
        box-shadow: 0 4px 12px rgb(0 0 0 / 10%);
    }

Прозорість дозволяє фону частково просвічувати крізь тінь.

Можна використовувати й інші кольори:

    .button {
        box-shadow: 0 4px 12px rgb(37 99 235 / 25%);
    }

Така тінь має синій відтінок.

Кольорові тіні доречні для окремих акцентних елементів, але не повинні без потреби перевантажувати інтерфейс.

## 4. Типові варіанти тіней

### 4.1. Легка тінь

    .card {
        box-shadow: 0 1px 3px rgb(0 0 0 / 8%);
    }

Застосування:

- Картки.
- Невеликі панелі.
- Елементи на світлому фоні.
- Ледь помітне відокремлення поверхонь.

### 4.2. Середня тінь

    .card {
        box-shadow: 0 4px 12px rgb(0 0 0 / 10%);
    }

Застосування:

- Картки з важливим вмістом.
- Віджети.
- Плаваючі кнопки.
- Інтерактивні елементи з ефектом підняття.

### 4.3. Виразна тінь

    .modal {
        box-shadow: 0 12px 32px rgb(0 0 0 / 18%);
    }

Застосування:

- Модальні вікна.
- Великі діалогові панелі.
- Меню, що перекривають основний вміст.
- Елементи, які мають виразно відокремлюватися від фону.

### 4.4. Тінь без зміщення

    .element {
        box-shadow: 0 0 12px rgb(0 0 0 / 12%);
    }

Тінь поширюється навколо елемента без вираженого напрямку.

Застосування:

- М'яке підсвічування.
- Декоративні ефекти.
- Окремі акцентні елементи.

Не варто використовувати такий ефект для кожної картки або кнопки.

### 4.5. Тінь тільки знизу

    .header {
        box-shadow: 0 4px 8px -4px rgb(0 0 0 / 18%);
    }

Від'ємний `spread-radius` допомагає обмежити поширення тіні.

Застосування:

- Закріплена верхня панель.
- Навігаційна панель.
- Розділення заголовка сторінки та основного вмісту.

### 4.6. Тінь усередині елемента

    .input {
        box-shadow: inset 0 2px 4px rgb(0 0 0 / 8%);
    }

`inset` створює внутрішню тінь.

Застосування:

- Поля введення.
- Заглиблені області.
- Окремі декоративні поверхні.

Внутрішня тінь може зробити поле візуально заглибленим, але надмірне затемнення погіршує сприйняття.

---

## 5. Властивість `text-shadow`

`text-shadow` додає тінь до тексту.

Загальний синтаксис:

    selector {
        text-shadow: offset-x offset-y blur-radius color;
    }

Приклад:

    .heading {
        text-shadow: 0 2px 4px rgb(0 0 0 / 20%);
    }

На відміну від `box-shadow`, властивість `text-shadow` не має параметра `spread-radius` і не використовує ключове слово `inset`.

### 5.1. Легка тінь тексту

    .heading {
        text-shadow: 0 1px 2px rgb(0 0 0 / 15%);
    }

Може застосовуватися для окремих заголовків або тексту поверх зображення.

### 5.2. Текст поверх фотографії

    .hero {
        background-image: url("/images/hero.jpg");
        background-size: cover;
        background-position: center;
    }

    .hero__title {
        color: #ffffff;
        text-shadow: 0 2px 6px rgb(0 0 0 / 55%);
    }

Тінь допомагає відокремити текст від деталей фотографії.

Однак тінь не гарантує достатньої контрастності. Якщо фон складний, краще додатково використати затемнення зображення або напівпрозорий градієнт.

### 5.3. Чому не потрібно зловживати `text-shadow`

Надмірна тінь:

- Робить текст нечітким.
- Погіршує читабельність дрібних літер.
- Створює застарілий декоративний ефект.
- Може заважати сприйняттю контрасту між текстом і фоном.

Для більшості текстових інтерфейсів достатньо звичайного тексту без тіні.

## 6. Кілька тіней для одного елемента

CSS дозволяє вказати декілька тіней, розділивши їх комами.

    .card {
        box-shadow:
            0 1px 2px rgb(0 0 0 / 6%),
            0 4px 12px rgb(0 0 0 / 8%);
    }

Браузер малює першу тінь над наступними тінями.

Кілька тіней дозволяють створити складніший, але водночас м'який ефект глибини.

### 6.1. Комбінація чіткої та розмитої тіні

    .card {
        box-shadow:
            0 1px 2px rgb(0 0 0 / 6%),
            0 8px 24px rgb(0 0 0 / 8%);
    }

Перша тінь створює невелике затемнення біля краю, а друга — м'яку глибину навколо картки.

### 6.2. Тінь і кольоровий акцент

    .button {
        box-shadow:
            0 2px 4px rgb(0 0 0 / 10%),
            0 4px 12px rgb(37 99 235 / 20%);
    }

Це поєднання можна використати для особливо важливої кнопки.

Проте кількість тіней варто обмежувати: кожен додатковий ефект повинен мати зрозумілу мету.

---

## 7. Тіні та візуальна глибина — Elevation

Elevation — це концепція візуальної висоти елемента над поверхнею інтерфейсу.

Чим вище елемент у візуальній ієрархії, тим виразнішою може бути його тінь.

Умовна система:

| Рівень | Призначення | Приклад |
|---|---|---|
| 0 | Звичайна поверхня | Фон сторінки |
| 1 | Легке відокремлення | Картка |
| 2 | Піднятий елемент | Кнопка або інтерактивна картка |
| 3 | Плаваючий елемент | Випадаюче меню |
| 4 | Високий рівень | Модальне вікно |

Це лише приклад організації системи, а не універсальний стандарт.

### 7.1. Приклад системи elevation

    :root {
        --shadow-none: none;
        --shadow-sm: 0 1px 3px rgb(0 0 0 / 8%);
        --shadow-md: 0 4px 12px rgb(0 0 0 / 10%);
        --shadow-lg: 0 8px 24px rgb(0 0 0 / 14%);
        --shadow-xl: 0 16px 40px rgb(0 0 0 / 18%);
    }

    .card {
        box-shadow: var(--shadow-sm);
    }

    .dropdown {
        box-shadow: var(--shadow-lg);
    }

    .modal {
        box-shadow: var(--shadow-xl);
    }

Переваги системи:

- Тіні мають послідовний вигляд.
- Значення можна змінювати централізовано.
- Легше підтримувати дизайн-систему.
- Компоненти різних сторінок виглядають узгоджено.

Важливо: не всі елементи повинні мати тінь. Часто достатньо фону, межі або відступу.

## 8. Тіні для карток

Картки — один із найпоширеніших випадків використання `box-shadow`.

### 8.1. Звичайна картка

    .card {
        padding: 24px;
        background-color: #ffffff;
        border-radius: 12px;
        box-shadow: 0 2px 8px rgb(0 0 0 / 8%);
    }

Тінь допомагає картці відокремитися від фону.

### 8.2. Інтерактивна картка

    .card {
        background-color: #ffffff;
        box-shadow: 0 2px 8px rgb(0 0 0 / 8%);
        transition: box-shadow 180ms ease;
    }

    .card:hover {
        box-shadow: 0 8px 20px rgb(0 0 0 / 12%);
    }

Такий варіант доречний, якщо картка справді інтерактивна.

Якщо картка не має жодної дії, зміна тіні під час наведення може створити хибне враження, що її можна натиснути.

### 8.3. Картка без тіні

    .card {
        padding: 24px;
        background-color: #ffffff;
        border: 1px solid #e5e7eb;
        border-radius: 12px;
    }

Тут межа замінює тінь.

Цей варіант може бути доречнішим для мінімалістичного інтерфейсу, таблиці або сторінки з великою кількістю карток.

### 8.4. Тінь чи межа?

Використовуйте тінь, якщо потрібно:

- Створити відчуття підняття.
- Візуально відокремити плаваючий елемент.
- Підкреслити глибину.

Використовуйте межу, якщо потрібно:

- Чітко визначити край компонента.
- Розділити сусідні області.
- Зберегти простий і стриманий вигляд.

Іноді доречні обидва ефекти, але їхня сумарна виразність повинна бути помірною.

---

## 9. Тіні для кнопок

Тінь кнопки може підкреслювати її інтерактивність і візуальну важливість.

### 9.1. Основна кнопка

    .button {
        padding: 12px 20px;
        border: none;
        border-radius: 8px;
        background-color: #2563eb;
        color: #ffffff;
        box-shadow: 0 2px 4px rgb(37 99 235 / 20%);
        cursor: pointer;
        transition:
            box-shadow 180ms ease,
            transform 180ms ease;
    }

    .button:hover {
        box-shadow: 0 4px 10px rgb(37 99 235 / 28%);
    }

    .button:active {
        transform: translateY(1px);
        box-shadow: 0 1px 2px rgb(37 99 235 / 18%);
    }

### 9.2. Кнопка без тіні

    .button {
        padding: 12px 20px;
        border: none;
        border-radius: 8px;
        background-color: #2563eb;
        color: #ffffff;
        cursor: pointer;
    }

Кнопка може бути виразною завдяки кольору, контрасту, розміру та відступам.

Тінь не є обов'язковою властивістю кнопки.

### 9.3. Тінь не замінює стани

Кнопка повинна мати зрозумілі стани:

- Default — звичайний стан.
- Hover — наведення вказівника.
- Active — натискання.
- Focus-visible — клавіатурний фокус.
- Disabled — недоступний стан.

Не потрібно покладатися тільки на зміну тіні. Можна змінювати колір, межу або положення, зберігаючи зрозумілий візуальний результат.

---

## 10. Тіні для полів введення

Тіні для полів введення зазвичай використовують обережно.

### 10.1. Звичайне поле

    .input {
        width: 100%;
        padding: 12px 14px;
        border: 1px solid #d1d5db;
        border-radius: 8px;
        background-color: #ffffff;
        box-shadow: 0 1px 2px rgb(0 0 0 / 4%);
    }

### 10.2. Поле у фокусі

    .input:focus-visible {
        outline: 3px solid rgb(37 99 235 / 25%);
        outline-offset: 2px;
        border-color: #2563eb;
    }

Тут `outline` створює додатковий контур, а `border-color` змінює колір межі.

Можна також використати тінь:

    .input:focus-visible {
        outline: none;
        border-color: #2563eb;
        box-shadow: 0 0 0 3px rgb(37 99 235 / 20%);
    }

Якщо використовується другий варіант, потрібно переконатися, що індикатор фокусу достатньо помітний. Не видаляйте стандартний контур фокусу без рівноцінної доступної заміни.

### 10.3. Важливе правило доступності

Тінь не повинна бути єдиним слабкопомітним сигналом того, що поле перебуває у фокусі.

Перевіряйте:

- Чи помітний фокус на світлому фоні.
- Чи помітний фокус на темному фоні.
- Чи не обрізається індикатор сусіднім контейнером.
- Чи не зникає індикатор при навігації клавіатурою.
- Чи відрізняється стан фокусу від звичайного стану.

---

## 11. Тіні для меню, dropdown і modal

Елементи, які перекривають інший вміст, часто потребують виразнішого візуального відокремлення.

### 11.1. Dropdown

    .dropdown {
        position: absolute;
        z-index: 10;
        background-color: #ffffff;
        border: 1px solid #e5e7eb;
        border-radius: 10px;
        box-shadow: 0 8px 24px rgb(0 0 0 / 14%);
    }

### 11.2. Modal

    .modal {
        position: relative;
        background-color: #ffffff;
        border-radius: 16px;
        box-shadow: 0 16px 48px rgb(0 0 0 / 20%);
    }

### 11.3. Backdrop модального вікна

Тінь самого модального вікна і затемнення сторінки позаду нього — різні речі.

    .modal-backdrop {
        position: fixed;
        inset: 0;
        background-color: rgb(0 0 0 / 45%);
    }

Backdrop затемнює вміст позаду модального вікна, а `box-shadow` підкреслює його краї.

Не варто намагатися замінити затемнення всього фону великою тінню навколо модального вікна.

---

## 12. Тіні та стани компонентів

У UI Design тіні можуть допомагати передавати стани, але вони повинні бути частиною загальної системи.

### 12.1. Hover

    .card {
        box-shadow: 0 2px 6px rgb(0 0 0 / 8%);
        transition: box-shadow 180ms ease;
    }

    .card:hover {
        box-shadow: 0 6px 16px rgb(0 0 0 / 12%);
    }

### 12.2. Active

    .button:active {
        box-shadow: 0 1px 2px rgb(0 0 0 / 12%);
    }

Менша тінь може створювати відчуття натискання.

### 12.3. Focus-visible

    .button:focus-visible {
        outline: 3px solid #93c5fd;
        outline-offset: 3px;
    }

Для клавіатурного фокусу важлива видимість індикатора, а не наявність саме тіні.

### 12.4. Disabled

    .button:disabled {
        cursor: not-allowed;
        box-shadow: none;
        opacity: 0.6;
    }

Це лише приклад стилізації. Не покладайтеся тільки на прозорість, щоб показати недоступність кнопки: перевіряйте контраст і зрозумілість стану.

### 12.5. Стан помилки

    .input[aria-invalid="true"] {
        border-color: #dc2626;
        box-shadow: 0 0 0 2px rgb(220 38 38 / 12%);
    }

Колір, текст повідомлення та інші ознаки повинні разом пояснювати помилку. Тінь сама по собі не повідомляє користувачу, що саме сталося.

---

## 13. Тіні та CSS transitions

`transition` дозволяє плавно змінювати значення властивостей.

    .card {
        box-shadow: 0 2px 6px rgb(0 0 0 / 8%);
        transition: box-shadow 200ms ease;
    }

    .card:hover {
        box-shadow: 0 8px 20px rgb(0 0 0 / 12%);
    }

Основні частини `transition`:

    transition: property duration timing-function delay;

Де:

- `property` — властивість, яку потрібно анімувати.
- `duration` — тривалість переходу.
- `timing-function` — характер зміни.
- `delay` — затримка перед початком.

Приклад:

    .card {
        transition: box-shadow 200ms ease-in-out;
    }

### 13.1. Не анімуйте все без потреби

    .card {
        transition: all 300ms ease;
    }

Такий запис може анімувати більше властивостей, ніж потрібно.

Часто краще явно вказувати потрібні властивості:

    .card {
        transition:
            box-shadow 200ms ease,
            transform 200ms ease;
    }

Це робить поведінку компонента зрозумілішою.

### 13.2. Підтримка reduced motion

Якщо інтерфейс має анімації, враховуйте налаштування користувача щодо зменшення руху.

    .card {
        transition:
            box-shadow 200ms ease,
            transform 200ms ease;
    }

    @media (prefers-reduced-motion: reduce) {
        .card {
            transition: none;
        }
    }

У великих інтерфейсах правила для reduced motion варто узгоджувати із загальною системою анімацій.

---

## 14. Тіні та дизайн-система

Дизайн-система повинна використовувати обмежену кількість узгоджених тіней.

Якщо кожен компонент має власне випадкове значення, інтерфейс виглядає непослідовно.

### 14.1. Shadow tokens

Shadow tokens — це змінні, які зберігають готові значення тіней.

    :root {
        --shadow-0: none;

        --shadow-1:
            0 1px 2px rgb(0 0 0 / 6%);

        --shadow-2:
            0 3px 8px rgb(0 0 0 / 8%);

        --shadow-3:
            0 8px 20px rgb(0 0 0 / 12%);

        --shadow-4:
            0 16px 40px rgb(0 0 0 / 16%);
    }

Використання:

    .card {
        box-shadow: var(--shadow-1);
    }

    .dropdown {
        box-shadow: var(--shadow-3);
    }

    .modal {
        box-shadow: var(--shadow-4);
    }

### 14.2. Семантичні назви

У великій дизайн-системі зручно називати тіні за призначенням.

    :root {
        --shadow-card: 0 2px 8px rgb(0 0 0 / 8%);
        --shadow-popover: 0 8px 24px rgb(0 0 0 / 14%);
        --shadow-dialog: 0 16px 48px rgb(0 0 0 / 20%);
        --shadow-focus: 0 0 0 3px rgb(37 99 235 / 25%);
    }

Перевага семантичних назв — код пояснює, для чого використовується конкретна тінь.

Водночас `--shadow-focus` у цьому прикладі — лише декоративний токен. Реальний індикатор фокусу потрібно перевіряти на відповідність вимогам доступності.

---

## 15. Тіні у світлій і темній темах

Тіні, які добре працюють у світлій темі, можуть бути майже непомітними в темній.

### 15.1. Світла тема

    :root {
        --surface: #ffffff;
        --text: #111827;
        --shadow-card: 0 4px 12px rgb(0 0 0 / 10%);
    }

### 15.2. Темна тема

    [data-theme="dark"] {
        --surface: #1f2937;
        --text: #f9fafb;
        --shadow-card: 0 4px 12px rgb(0 0 0 / 30%);
    }

Однак у темній темі не завжди достатньо просто збільшити прозорість чорної тіні.

На темному фоні глибину часто краще передавати поєднанням:

- Відмінностей між кольорами поверхонь.
- Меж або тонких роздільників.
- Тіней там, де вони справді помітні.
- Контрасту між сусідніми компонентами.

### 15.3. Приклад використання змінних

    .card {
        color: var(--text);
        background-color: var(--surface);
        box-shadow: var(--shadow-card);
    }

Компонент використовує ті самі CSS-властивості, а тема змінює значення змінних.

---

## 16. Тіні та доступність

Тіні — це декоративний і структурний інструмент. Вони не повинні погіршувати доступність інтерфейсу.

### 16.1. Контраст

Дуже слабка тінь може бути майже непомітною.

Не використовуйте її як єдиний спосіб:

- Позначити фокус клавіатури.
- Показати помилку.
- Вказати на активний стан.
- Відрізнити важливий елемент від фону.

### 16.2. Видимий фокус

Для інтерактивних елементів передбачайте зрозумілий індикатор фокусу.

    .link:focus-visible {
        outline: 3px solid #2563eb;
        outline-offset: 3px;
    }

Тут використовується `outline`, а не `box-shadow`. Це допустимий і часто зручний підхід.

### 16.3. Не видаляйте фокус без заміни

Поганий приклад:

    button:focus {
        outline: none;
    }

Якщо після цього не з'являється інший чіткий індикатор, користувач клавіатури може втратити можливість визначати поточний елемент.

Краще:

    button:focus-visible {
        outline: 3px solid #2563eb;
        outline-offset: 3px;
    }

### 16.4. Перевіряйте обрізання тіней

    .container {
        overflow: hidden;
    }

Тінь дочірнього елемента може бути обрізана межами контейнера.

Це особливо важливо для:

- Карток з ефектом підняття.
- Полів із фокусним кільцем.
- Dropdown-меню.
- Кнопок біля країв контейнера.

Не прибирайте `overflow: hidden` автоматично: спочатку перевірте, чи воно потрібне для інших частин компонента.

---

## 17. Тіні та продуктивність

Більшість звичайних CSS-тіней працює без спеціального налаштування. Проте складні ефекти можуть впливати на продуктивність, особливо коли багато великих елементів постійно змінюють тінь.

Рекомендації:

- Не створюйте надто багато шарів тіней без потреби.
- Уникайте величезних розмитих тіней на великій кількості елементів.
- Не анімуйте тіні на десятках компонентів одночасно без необхідності.
- Перевіряйте реальну продуктивність у браузері.
- Для плавного руху іноді доцільніше анімувати `transform` або `opacity`, якщо це відповідає потрібному ефекту.

Приклад простішої анімації:

    .card {
        transition: transform 180ms ease;
    }

    .card:hover {
        transform: translateY(-2px);
    }

Проте `transform` також може створювати новий контекст накладання, тому його слід використовувати свідомо.

Не додавайте `will-change` до всіх карток наперед. Цю властивість варто застосовувати лише після виявлення конкретної проблеми продуктивності.

---

## 18. Тіні та контексти накладання

`box-shadow` не визначає порядок накладання елементів у документі.

За порядок накладання відповідають правила малювання CSS, зокрема `z-index` і контексти накладання.

Приклад:

    .dropdown {
        position: absolute;
        z-index: 10;
        box-shadow: 0 8px 24px rgb(0 0 0 / 14%);
    }

`z-index` визначає порядок накладання в межах відповідного контексту, а тінь створює візуальне відокремлення.

Якщо меню опиняється під сусіднім компонентом, збільшення тіні не виправить проблему порядку накладання.

Потрібно перевірити:

- `position`.
- `z-index`.
- Чи створює батьківський елемент новий stacking context.
- Чи не обрізає елемент батьківський контейнер.
- Чи не впливають `transform`, `opacity` або інші властивості на контекст накладання.

## 19. Тіні для зображень та аватарів

Тіні можна застосовувати до фотографій, ілюстрацій та аватарів.

### 19.1. Зображення в картці

    .card__image {
        display: block;
        width: 100%;
        height: auto;
        box-shadow: 0 2px 8px rgb(0 0 0 / 10%);
    }

### 19.2. Аватар

    .avatar {
        width: 48px;
        height: 48px;
        border-radius: 50%;
        object-fit: cover;
        box-shadow: 0 2px 6px rgb(0 0 0 / 12%);
    }

### 19.3. Коли тінь зайва

Не кожне зображення потребує тіні.

Наприклад:

- Фотографії в галереї можуть виглядати краще без неї.
- Зображення з уже намальованою тінню можуть отримати небажаний подвійний ефект.
- На насиченому фоні тінь може майже не давати користі.

Тінь повинна підтримувати загальну композицію сторінки.

## 20. Поширені помилки

### Помилка 1. Надто темна тінь

    .card {
        box-shadow: 0 10px 20px rgb(0 0 0 / 45%);
    }

Така тінь може зробити картку візуально важкою.

Краще почати з меншої прозорості та збільшувати її лише за потреби.

    .card {
        box-shadow: 0 4px 12px rgb(0 0 0 / 10%);
    }

### Помилка 2. Однакова тінь для всіх елементів

Якщо кнопки, картки, меню та модальні вікна мають однакові тіні, візуальна ієрархія може втратитися.

Рішення: створіть обмежену систему рівнів тіней і застосовуйте їх послідовно.

### Помилка 3. Надмірна кількість тіней

Коли кожна картка, кнопка, поле, іконка та заголовок мають тінь, інтерфейс стає візуально перевантаженим.

Рішення: спочатку використовуйте відступи, контраст поверхонь і межі. Додавайте тіні тільки там, де вони допомагають.

### Помилка 4. Тінь замість видимого фокусу

    .input:focus {
        box-shadow: 0 0 2px rgb(37 99 235 / 20%);
    }

Цей індикатор може бути занадто слабким.

Рішення: зробіть фокус виразним і перевірте його в реальних умовах.

### Помилка 5. Використання `text-shadow` для всього тексту

Тіні на кожному абзаці знижують чіткість текстового інтерфейсу.

Рішення: використовуйте їх вибірково — наприклад, для заголовка на фотографії.

### Помилка 6. Непомітні тіні в темній темі

Чорна тінь на темному фоні може майже зникати.

Рішення: перевірте контраст поверхонь, межі та інші способи розділення елементів.

### Помилка 7. Тінь обрізається

Причиною може бути `overflow: hidden` на батьківському елементі.

Рішення: перевірте контейнер і структуру компонента, а не просто збільшуйте `z-index`.

### Помилка 8. Тінь використовується для імітації неправильної ієрархії

Велика тінь не повинна робити звичайну картку візуально важливішою за основну дію сторінки.

Рішення: визначайте важливість через композицію, типографіку, колір, розмір і розташування, а не тільки через тінь.

### Помилка 9. Тінь анімується без необхідності

Велика кількість постійних анімацій може відволікати користувача.

Рішення: анімуйте тільки значущі стани та враховуйте `prefers-reduced-motion`.

## 22. Як вибирати тінь для UI

Перед додаванням тіні поставте собі кілька запитань.

1. Чи потрібно відокремити елемент від фону?
2. Чи потрібно показати його візуальну висоту?
3. Чи є елемент інтерактивним?
4. Чи достатньо межі або контрасту поверхонь?
5. Чи відповідає тінь загальній системі дизайну?
6. Чи буде вона помітною в темній темі?
7. Чи не обрізається вона контейнером?
8. Чи не створює вона хибного враження інтерактивності?
9. Чи залишається інтерфейс читабельним і доступним?
10. Чи потрібна анімація тіні взагалі?

Практичне правило:

> Спочатку побудуйте правильну структуру та композицію. Потім використовуйте тіні для уточнення візуальної ієрархії.

## 23. Мініпроєкт: система тіней для карток і меню

Мета — створити невелику сторінку з картками, кнопкою та випадаючим елементом, використовуючи спільні shadow tokens.

### HTML

    <main class="page">
        <h1 class="page__title">Мої проєкти</h1>

        <section class="projects">
            <article class="card">
                <h2 class="card__title">Перший проєкт</h2>
                <p class="card__text">
                    Навчальний проєкт із використанням HTML і CSS.
                </p>
                <button class="button" type="button">
                    Відкрити
                </button>
            </article>

            <article class="card card--interactive">
                <h2 class="card__title">Другий проєкт</h2>
                <p class="card__text">
                    Проєкт для практики UI Design.
                </p>
                <button class="button" type="button">
                    Відкрити
                </button>
            </article>
        </section>
    </main>

### CSS

    :root {
        --color-page: #f3f4f6;
        --color-surface: #ffffff;
        --color-text: #111827;
        --color-primary: #2563eb;
        --color-border: #e5e7eb;

        --shadow-card: 0 2px 8px rgb(0 0 0 / 8%);
        --shadow-card-hover: 0 8px 20px rgb(0 0 0 / 12%);
        --shadow-button: 0 2px 4px rgb(37 99 235 / 20%);

✔ Hover-ефекти доречні насамперед для елементів, які справді інтерактивні.

✔ Тінь не замінює видимий фокус клавіатури.

✔ Тіні можуть обрізатися через `overflow`.

✔ Надмірні тіні роблять інтерфейс візуально важким.

## 25. Типові питання на співбесіді

**1. Що таке `box-shadow`?**

CSS-властивість для створення тіні навколо зовнішньої або внутрішньої області елемента.

**2. Чим `box-shadow` відрізняється від `text-shadow`?**

`box-shadow` створює тінь навколо області елемента, а `text-shadow` — навколо тексту.

**3. Що означають параметри `offset-x` та `offset-y`?**

Вони задають горизонтальне й вертикальне зміщення тіні.

**4. Для чого потрібен `blur-radius`?**

Він визначає розмиття тіні.

**5. Що робить `spread-radius`?**

Він збільшує або зменшує розмір тіні до застосування розмиття.

**6. Для чого використовується `inset`?**

Для створення внутрішньої тіні.

**7. Чи можна створити декілька тіней для одного елемента?**

Так. Їх записують через кому в одній властивості `box-shadow`.

**8. Чи змінює `box-shadow` розміри елемента?**

Ні. Тінь не додається до ширини й висоти елемента в CSS box model, хоча може візуально виходити за його межі.

**9. Чим тінь відрізняється від `border`?**

Межа визначає край компонента, а тінь допомагає створити глибину та візуальне відокремлення.

**10. Чим тінь відрізняється від `outline`?**

`outline` створює контур навколо елемента, часто використовується для індикатора фокусу й не займає місця в box model. `box-shadow` створює тінь і може мати розмиття та внутрішній варіант.

**11. Що таке elevation?**

Концепція візуальної висоти елемента над поверхнею інтерфейсу.

**12. Навіщо потрібні shadow tokens?**

Щоб повторно використовувати узгоджені тіні, підтримувати дизайн-систему й централізовано змінювати значення.

**13. Чи повинна кожна картка мати тінь?**

Ні. Межі, контраст поверхонь і відступи часто забезпечують достатнє розділення.

**14. Чому не можна просто видалити `outline` у кнопки?**

Це може прибрати видимий індикатор клавіатурного фокусу. Якщо стандартний контур видаляють, потрібно надати достатньо помітну альтернативу.

**15. Чому тінь може не відображатися повністю?**

Її може обрізати контейнер з `overflow: hidden` або інше обмеження області відображення.

**16. Чи керує `box-shadow` порядком накладання елементів?**

Ні. Для порядку накладання використовують правила CSS, зокрема `z-index` у відповідному контексті накладання.

**17. Як адаптувати тіні для темної теми?**

Перевірити видимість тіней і за потреби поєднати їх із контрастом поверхонь, межами та іншими візуальними засобами.

**18. Як створити плавну зміну тіні?**

За допомогою `transition` для `box-shadow`.

**19. Чому небажано анімувати `all` без потреби?**

Це може анімувати непередбачені властивості. Краще явно визначати ті, які мають змінюватися.

**20. Який головний принцип використання тіней у UI Design?**

Тінь повинна покращувати структуру, глибину та зрозумілість інтерфейсу, а не бути просто декоративним ефектом.

## Висновок

Тіні — важливий інструмент візуальної мови інтерфейсу. Вони допомагають відокремлювати поверхні, створювати глибину, виділяти плаваючі елементи та підкреслювати взаємодію.

Для якісного UI Design потрібно не просто знати синтаксис `box-shadow`, а розуміти, **де тінь потрібна, яку функцію вона виконує та як узгоджується з усією системою дизайну**.

Під час роботи пам'ятайте:

- Спочатку композиція, потім декоративні ефекти.
- Краще декілька узгоджених тіней, ніж десятки випадкових.
- Межі та контраст поверхонь можуть бути достатніми без тіні.
- Фокус клавіатури повинен залишатися помітним.
- Світла й темна теми потребують окремої перевірки.
- Кожна тінь повинна мати зрозуміле призначення.

**Мета — не зробити інтерфейс максимально об'ємним, а зробити його зрозумілим, послідовним і зручним для користувача.**
