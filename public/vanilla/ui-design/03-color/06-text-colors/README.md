# 🎨 Text Colors — Кольори тексту в UI-дизайні

> **Text Colors** — це вибір і систематизація кольорів для тексту в інтерфейсі, які допомагають створити візуальну ієрархію, забезпечити читабельність, передати значення та підтримати загальну дизайн-систему.

Кольори тексту — це не просто чорний для основного тексту й сірий для другорядного. Вони допомагають користувачеві зрозуміти, що важливо, що є допоміжною інформацією, які елементи інтерактивні та чи є повідомлення успішним або помилковим.

**Де використовується:**
- Основний текст сторінок і карток.
- Заголовки, підзаголовки та підписи.
- Допоміжні описи, підказки й метадані.
- Посилання та інтерактивні елементи.
- Повідомлення про помилки, успіх і попередження.
- Форми, таблиці, панелі керування та інформаційні повідомлення.
- Світла й темна теми інтерфейсу.

---

## ✔ Основні поняття

- **Primary text** — основний текст, який користувач читає найчастіше.
- **Secondary text** — другорядний текст, що доповнює основний.
- **Tertiary text** — текст третього рівня важливості, наприклад метадані.
- **Heading color** — колір заголовків.
- **Muted text** — приглушений текст.
- **Link color** — колір посилань.
- **Interactive text** — текст інтерактивних елементів.
- **Semantic colors** — кольори, що передають значення: успіх, помилку, попередження або інформацію.
- **Contrast** — різниця між кольором тексту та фоном.
- **Text hierarchy** — візуальна ієрархія тексту.
- **Color tokens** — іменовані кольорові змінні дизайн-системи.
- **Dark mode** — темна тема інтерфейсу.
- **Accessible text** — текст, колір якого забезпечує достатню читабельність для різних користувачів.

---

# 1. Навіщо потрібна система кольорів тексту

Уявімо картку курсу:

    Назва курсу
    Основи веброзробки
    Оновлено 12 жовтня
    Переглянути курс →

Якщо весь текст має однаковий колір, користувачеві складніше визначити його структуру.

Якщо розподілити кольори за ролями, ієрархія стає зрозумілішою:

- Назва курсу — основний темний колір.
- Опис — звичайний колір тексту.
- Дата оновлення — приглушений сірий.
- Посилання — виразний колір інтерактивного елемента.

**Головний принцип:** колір тексту повинен відповідати його ролі, важливості та стану.

Не варто призначати випадковий колір кожному окремому елементу. Краще створити невелику систему кольорів і послідовно використовувати її в усьому інтерфейсі.

---

# 2. Рівні важливості тексту

У більшості інтерфейсів достатньо трьох-чотирьох рівнів звичайного тексту.

## 2.1. Primary text — основний текст

Основний текст містить найважливішу інформацію, яку користувач повинен легко прочитати.

**Приклади:**
- Основний вміст сторінки.
- Назви елементів списку.
- Текст кнопок.
- Значення в таблицях.
- Назви полів форм.

У світлій темі зазвичай використовують темний, але не обов'язково абсолютно чорний колір.

    :root {
        --color-text-primary: #1f2937;
    }

Абсолютний чорний (`#000000`) може бути доречним, але трохи м'якший темний колір часто краще поєднується з інтерфейсом.

## 2.2. Secondary text — другорядний текст

Другорядний текст пояснює або доповнює основний.

**Приклади:**
- Короткий опис картки.
- Пояснення під заголовком.
- Адреса користувача.
- Дата створення запису.
- Опис налаштування.

    :root {
        --color-text-secondary: #4b5563;
    }

Другорядний текст повинен бути менш виразним, але залишатися зручним для читання.

Не потрібно робити його надто світлим лише для того, щоб він здавався другорядним.

## 2.3. Tertiary text — текст третього рівня

Цей рівень використовують для інформації, яка не є центральною, але може бути корисною.

**Приклади:**
- Час останнього оновлення.
- Кількість коментарів.
- Допоміжні метадані.
- Додаткові технічні відомості.

    :root {
        --color-text-tertiary: #6b7280;
    }

Третинний текст часто використовують обережніше, ніж основний і другорядний.

Важливо: якщо інформація необхідна для виконання завдання, вона не повинна ставати майже непомітною тільки через свій допоміжний характер.

## 2.4. Disabled text — текст неактивного елемента

Disabled text показує, що елемент тимчасово недоступний.

    :root {
        --color-text-disabled: #9ca3af;
    }

Наприклад, неактивна кнопка може мати приглушений текст.

    .button:disabled {
        color: var(--color-text-disabled);
        cursor: not-allowed;
    }

Проте колір сам по собі не повинен бути єдиним поясненням стану. Якщо користувачеві важливо знати, чому дія недоступна, додайте пояснення.

---

# 3. Заголовки та текст основного вмісту

Заголовки часто мають той самий колір, що й основний текст, але можуть бути темнішими або контрастнішими.

    :root {
        --color-heading: #111827;
        --color-body: #374151;
    }

    h1,
    h2,
    h3 {
        color: var(--color-heading);
    }

    body {
        color: var(--color-body);
    }

Не потрібно створювати окремий колір для кожного рівня заголовків без реальної потреби.

Візуальну ієрархію можна формувати поєднанням:

- Розміру шрифту.
- Насиченості шрифту.
- Відступів.
- Міжрядкового інтервалу.
- Положення елемента.
- Кольору.

Наприклад, `h1` і `h2` можуть мати однаковий колір, але різні розміри та відступи.

**Що запам'ятати:** колір — лише один з інструментів побудови текстової ієрархії.

---

# 4. Muted text — приглушені кольори

Muted text — це текст із менш виразним візуальним акцентом.

Зазвичай він має нижчу контрастність порівняно з основним текстом, але все одно повинен залишатися читабельним.

**Де використовується:**
- Підписи.
- Допоміжні пояснення.
- Дати й часові позначки.
- Другорядні характеристики.
- Підписи до зображень.
- Інформація про автора або категорію.

    :root {
        --color-text-muted: #6b7280;
    }

    .muted {
        color: var(--color-text-muted);
    }

Не плутайте приглушений текст із неактивним текстом.

- **Muted** — інформація доступна й читається, але має менший візуальний пріоритет.
- **Disabled** — елемент або дія недоступні.

Ці ролі можуть мати різні кольори в дизайн-системі.

---

# 5. Кольори посилань

Посилання повинні відрізнятися від звичайного тексту достатньо чітко, щоб користувач розумів, що з ними можна взаємодіяти.

    :root {
        --color-link: #2563eb;
        --color-link-hover: #1d4ed8;
        --color-link-visited: #6d28d9;
    }

    a {
        color: var(--color-link);
        text-decoration: underline;
        text-underline-offset: 0.15em;
    }

    a:hover {
        color: var(--color-link-hover);
    }

    a:visited {
        color: var(--color-link-visited);
    }

Це лише приклад палітри. Конкретні кольори потрібно перевіряти на фоні, де вони використовуватимуться.

## 5.1. Чому не варто покладатися лише на колір

Якщо посилання відрізняється від звичайного тексту тільки кольором, людям із порушеннями сприйняття кольорів може бути складніше його розпізнати.

Для текстових посилань у звичайному тексті підкреслення — надійний спосіб позначити інтерактивність.

У деяких компонентах, наприклад у навігації, інтерактивність може додатково передаватися розташуванням, формою, контекстом і станами наведення.

## 5.2. Стани посилання

Варто передбачити:

- `default` — звичайний стан.
- `hover` — курсор наведено на посилання.
- `focus-visible` — посилання отримало видимий клавіатурний фокус.
- `active` — посилання активується.
- `visited` — користувач уже відвідував адресу, якщо такий стан доречний.

    a {
        color: var(--color-link);
        text-decoration: underline;
        text-underline-offset: 0.15em;
    }

    a:hover {
        color: var(--color-link-hover);
    }

    a:focus-visible {
        outline: 2px solid currentColor;
        outline-offset: 3px;
    }

Не видаляйте видимий індикатор фокусу без створення доступної альтернативи.

---

# 6. Semantic text colors — семантичні кольори

Семантичні кольори передають значення або стан повідомлення.

Зазвичай виділяють чотири основні групи.

## 6.1. Success — успіх

Використовується для позитивного результату.

**Приклади:**
- Дані успішно збережено.
- Реєстрацію завершено.
- Оплату підтверджено.

    :root {
        --color-text-success: #166534;
    }

## 6.2. Error — помилка

Використовується для помилок і проблем, що потребують уваги.

**Приклади:**
- Неправильний формат email.
- Не вдалося зберегти дані.
- Обов'язкове поле не заповнено.

    :root {
        --color-text-error: #b91c1c;
    }

## 6.3. Warning — попередження

Використовується для потенційно небезпечних або небажаних ситуацій.

**Приклади:**
- Термін дії сесії завершується.
- Деякі зміни ще не збережено.
- Залишилося мало місця.

    :root {
        --color-text-warning: #92400e;
    }

## 6.4. Info — інформаційне повідомлення

Використовується для нейтральної інформації, яка може бути корисною користувачеві.

**Приклади:**
- Доступна нова версія.
- Оновлення заплановано на завтра.
- Дані синхронізуються.

    :root {
        --color-text-info: #1e40af;
    }

## 6.5. Не використовуйте лише колір для передачі значення

Наприклад, повідомлення про помилку краще оформити так:

    <p class="form-error">
        Будь ласка, введіть коректну адресу електронної пошти.
    </p>

    .form-error {
        color: var(--color-text-error);
    }

Якщо доречно, додайте іконку, текстове пояснення або інший візуальний індикатор.

Користувач повинен зрозуміти, що сталося, навіть якщо він не розрізняє кольори.

# 7. Contrast — контрастність тексту

Контрастність — це різниця між яскравістю тексту та фону, яка впливає на читабельність.

Темний текст на світлому фоні зазвичай читається добре. Світло-сірий текст на білому фоні може бути занадто слабким.

## 7.1. Рекомендації WCAG

Для звичайного тексту стандарт WCAG 2.2 рівня AA вимагає коефіцієнта контрастності щонайменше **4.5:1**.

Для великого тексту — щонайменше **3:1**.

Великий текст у цьому контексті — приблизно:
- 24 CSS px і більше для звичайної насиченості.
- 18.67 CSS px і більше для жирного тексту.

Це орієнтири для відповідності критеріям доступності, а не гарантія того, що будь-який текст буде зручним для кожної людини.

## 7.2. Як обчислюється контраст

Коефіцієнт контрастності порівнює відносну яскравість двох кольорів.

    contrast ratio = (L1 + 0.05) / (L2 + 0.05)

Де:
- `L1` — відносна яскравість світлішого кольору.
- `L2` — відносна яскравість темнішого кольору.

Результат виражається у форматі на зразок `4.5:1` або `7:1`.

Чим більше значення, тим більша різниця між кольорами.

Не потрібно обчислювати контраст вручну для кожного елемента. Краще користуватися перевіреними інструментами.

## 7.3. Приклад проблемного контрасту

    .hint {
        color: #d1d5db;
        background-color: #ffffff;
    }

Такий світло-сірий текст на білому фоні може бути надто слабким.

Краще перевірити темніший відтінок:

    .hint {
        color: #6b7280;
        background-color: #ffffff;
    }

Але навіть цей варіант потрібно перевірити інструментом контрастності, якщо він використовується в реальному інтерфейсі.

## 7.4. Інструменти перевірки

Для перевірки контрастності можна використовувати:

- WebAIM Contrast Checker.
- Chrome DevTools.
- Інструменти доступності у Figma.
- Axe DevTools.
- Lighthouse — для загальної перевірки доступності сторінки.

**Правило:** перевіряйте пару «текст + фактичний фон», а не колір тексту окремо.

# 8. Text colors у CSS-дизайн-системі

Замість того щоб записувати HEX-коди в кожному компоненті, створіть централізовані змінні.

    :root {
        /* Основний текст */
        --color-text-primary: #1f2937;
        --color-text-secondary: #4b5563;
        --color-text-tertiary: #6b7280;
        --color-text-disabled: #9ca3af;

        /* Заголовки */
        --color-text-heading: #111827;

        /* Посилання */
        --color-text-link: #2563eb;
        --color-text-link-hover: #1d4ed8;

        /* Стани */
        --color-text-success: #166534;
        --color-text-error: #b91c1c;
        --color-text-warning: #92400e;
        --color-text-info: #1e40af;
    }

Використання:

    body {
        color: var(--color-text-primary);
    }

    h1,
    h2,
    h3 {
        color: var(--color-text-heading);
    }

    .description {
        color: var(--color-text-secondary);
    }

    .metadata {
        color: var(--color-text-tertiary);
    }

    .error-message {
        color: var(--color-text-error);
    }

Переваги такого підходу:

- Кольори легко змінювати централізовано.
- Компоненти використовують узгоджені значення.
- Легше підтримувати світлу й темну теми.
- Зменшується кількість випадкових відтінків.
- Код стає зрозумілішим.

# 9. Primitive tokens і semantic tokens

У більшій дизайн-системі корисно розділяти палітру кольорів і їхні функції.

## 9.1. Primitive tokens — базові кольори

Це конкретні значення палітри без прив'язки до ролі.

    :root {
        --gray-50: #f9fafb;
        --gray-100: #f3f4f6;
        --gray-500: #6b7280;
        --gray-700: #374151;
        --gray-900: #111827;

        --blue-600: #2563eb;
        --green-800: #166534;
        --red-700: #b91c1c;
    }

## 9.2. Semantic tokens — кольори за ролями

Ці змінні описують, для чого використовується колір.

    :root {
        --text-primary: var(--gray-900);
        --text-secondary: var(--gray-700);
        --text-muted: var(--gray-500);

        --text-link: var(--blue-600);
        --text-success: var(--green-800);
        --text-error: var(--red-700);
    }

Різниця:

- `--gray-900` описує конкретний колір палітри.
- `--text-primary` описує роль кольору в інтерфейсі.

Завдяки цьому дизайн-система може змінювати палітру, не вимагаючи переробляти кожен компонент.

# 10. Text colors у світлій і темній темах

У темній темі не варто просто інвертувати всі кольори або робити весь текст білим.

Потрібно зберегти ієрархію тексту та перевірити контрастність на нових фонах.

Приклад змінних для двох тем:

    :root {
        color-scheme: light;

        --color-background: #ffffff;
        --color-surface: #f9fafb;

        --color-text-primary: #1f2937;
        --color-text-secondary: #4b5563;
        --color-text-muted: #6b7280;

        --color-text-link: #2563eb;
    }

    [data-theme="dark"] {
        color-scheme: dark;

        --color-background: #111827;
        --color-surface: #1f2937;

        --color-text-primary: #f9fafb;
        --color-text-secondary: #d1d5db;
        --color-text-muted: #9ca3af;

        --color-text-link: #93c5fd;
    }

Використання:

    body {
        background-color: var(--color-background);
        color: var(--color-text-primary);
    }

    .description {
        color: var(--color-text-secondary);
    }

    .metadata {
        color: var(--color-text-muted);
    }

    a {
        color: var(--color-text-link);
    }

Атрибут теми можна встановити на кореневому елементі:

    <html lang="uk" data-theme="dark">

Це лише приклад структури. Механізм перемикання теми залежить від застосунку.

## Що потрібно перевірити в темній темі

- Контраст основного тексту.
- Читабельність другорядного тексту.
- Колір посилань.
- Семантичні повідомлення.
- Стан `hover` і `focus-visible`.
- Текст на кольорових поверхнях.
- Плейсхолдери та підписи форм.
- Таблиці, картки й діалоги.

Кольори, які добре працюють на білому фоні, не обов'язково будуть читабельними на темному.

---

# 11. Text colors у формах

Форми потребують особливої уваги, адже користувач має розуміти назви полів, підказки, помилки й стани.

    :root {
        --color-text-label: #374151;
        --color-text-placeholder: #6b7280;
        --color-text-error: #b91c1c;
        --color-text-success: #166534;
    }

    label {
        color: var(--color-text-label);
    }

    input::placeholder {
        color: var(--color-text-placeholder);
    }

    .field-error {
        color: var(--color-text-error);
    }

Не використовуйте плейсхолдер як єдину назву поля. Коли користувач вводить дані, плейсхолдер зникає, і призначення поля може стати незрозумілим.

Краще поєднувати видиму назву поля з підказкою або повідомленням про помилку.

    <label for="email">Електронна пошта</label>
    <input
        id="email"
        name="email"
        type="email"
        aria-describedby="email-error"
        aria-invalid="true"
    >
    <p id="email-error" class="field-error">
        Введіть коректну адресу електронної пошти.
    </p>

Атрибут `aria-invalid="true"` доречний, коли поле справді містить помилкове значення. `aria-describedby` пов'язує поле з поясненням.

---

# 12. Кольори тексту на кольорових поверхнях

Текст може розташовуватися не лише на білому або темному фоні, а й на кольорових поверхнях:

- Кнопках.
- Банерах.
- Інформаційних картках.
- Повідомленнях про помилки.
- Акцентних блоках.
- Градієнтах і зображеннях.

Наприклад:

    .button-primary {
        color: #ffffff;
        background-color: #1d4ed8;
    }

    .alert-error {
        color: #991b1b;
        background-color: #fef2f2;
    }

    .alert-success {
        color: #166534;
        background-color: #f0fdf4;
    }

Не визначайте колір тексту лише за назвою фону. Наприклад, не кожен синій фон забезпечує достатній контраст для білого тексту.

Перевіряйте фактичну пару кольорів.

## Текст поверх зображень

Для тексту поверх фотографії контрастність може змінюватися залежно від ділянки зображення.

Можливі рішення:
- Додати напівпрозору підкладку.
- Використати градієнт за текстом.
- Розмістити текст у непрозорій картці.
- Вибрати інше зображення.

Не покладайтеся на те, що білий текст буде читабельним на будь-якій фотографії.

---

# 13. Кольори тексту в інтерактивних компонентах

Текст інтерактивних компонентів повинен залишатися зрозумілим у різних станах.

**Приклади:**
- Кнопки.
- Посилання.
- Пункти меню.
- Вкладки.
- Елементи списків.
- Елементи керування формами.

    .button-primary {
        color: #ffffff;
        background-color: #1d4ed8;
    }

    .button-primary:hover {
        background-color: #1e40af;
    }

    .button-primary:focus-visible {
        outline: 3px solid #93c5fd;
        outline-offset: 2px;
    }

    .button-primary:disabled {
        color: #e5e7eb;
        background-color: #6b7280;
        cursor: not-allowed;
    }

Ці значення наведено як приклад. Контрастність потрібно перевірити для кожної фактичної комбінації тексту й фону.

Не змінюйте колір тексту під час наведення так, щоб він зливався з фоном.

# 14. Типові помилки

## ❌ 1. Надто світлий сірий текст

    .description {
        color: #d1d5db;
        background: #ffffff;
    }

Проблема: текст може бути погано читабельним.

Рішення: вибрати темніший відтінок і перевірити контрастність.

## ❌ 2. Забагато різних кольорів тексту

Якщо кожен заголовок, підпис і опис має окремий колір, інтерфейс стає непослідовним.

Рішення: почніть із невеликої системи ролей і розширюйте її лише за потреби.

## ❌ 3. Посилання відрізняються тільки кольором

Проблема: інтерактивність може бути непомітною для деяких користувачів.

Рішення: використовуйте підкреслення або інший виразний індикатор посилання.

## ❌ 4. Червоний колір без пояснення

Проблема: користувач бачить помилку, але не розуміє її причину.

Рішення: додайте зрозуміле повідомлення, а за потреби — іконку.

## ❌ 5. Один колір для всіх другорядних станів

Проблема: підказка, неактивна дія та помилка мають різні значення.

Рішення: розділяйте ролі кольорів за призначенням.

## ❌ 6. Кольори світлої теми без перевірки в темній

Проблема: текст може втратити контрастність.

Рішення: визначайте й перевіряйте кольори для кожної теми окремо.

## ❌ 7. Використання кольору замість структури

Проблема: колір не компенсує погані відступи, слабку типографіку або незрозумілу структуру.

Рішення: поєднуйте колір із розміром, насиченістю, інтервалами та семантичною розміткою.

## ❌ 8. Надмірне використання чистого чорного

Проблема: чорний текст може візуально виглядати занадто різко в певній палітрі.

Рішення: протестуйте темно-сірий або майже чорний колір, зберігаючи необхідний контраст.

## ❌ 9. Надто блідий текст на кнопках

Проблема: кнопка може бути помітною, але її напис — ні.

Рішення: перевіряйте контраст саме тексту з фоном кнопки, а не лише загальну виразність компонента.

- Усі компоненти використовують спільні змінні.

Після створення картки перевірте контрастність усіх текстових елементів на фактичному фоні.

# 16. Як побудувати власну систему Text Colors

Для невеликого навчального проєкту можна почати з такого набору:

    :root {
        /* Text hierarchy */
        --text-primary: #1f2937;
        --text-secondary: #4b5563;
        --text-muted: #6b7280;
        --text-disabled: #9ca3af;

        /* Interactive */
        --text-link: #1d4ed8;
        --text-link-hover: #1e40af;

        /* Semantic */
        --text-success: #166534;
        --text-error: #b91c1c;
        --text-warning: #92400e;
        --text-info: #1e40af;
    }

Потім дотримуйтеся простого алгоритму:

1. Визначте основні типи тексту в застосунку.
2. Призначте кожному типу семантичну роль.
3. Виберіть базову палітру.
4. Створіть CSS-змінні.
5. Застосуйте їх у компонентах.
6. Перевірте контрастність тексту й фону.
7. Перевірте посилання, кнопки та повідомлення.
8. За потреби створіть окремі значення для темної теми.
9. Перевірте, чи можна об'єднати дубльовані кольори.
10. Задокументуйте правила використання.

Не створюйте десятки змінних заздалегідь. Почніть із базового набору та додавайте нові ролі, коли для них виникає реальна потреба.

# 18. Питання для співбесіди

**1. Що таке text color hierarchy?**

Це система розподілу кольорів за важливістю та призначенням тексту: основний, другорядний, допоміжний та інші рівні.

**2. Чим відрізняється primary text від secondary text?**

Primary text містить основну інформацію. Secondary text доповнює її, але не повинен втрачати читабельність.

**3. Що таке muted text?**

Це текст зі зниженим візуальним пріоритетом, наприклад метадані або допоміжні підписи.

**4. Що таке semantic colors?**

Кольори, які позначають значення або стан: успіх, помилку, попередження та інформацію.

**5. Що таке контрастність?**

Це різниця між відносною яскравістю тексту та фону, яка впливає на читабельність.

**6. Яка мінімальна контрастність для звичайного тексту за WCAG AA?**

4.5:1. Для великого тексту — 3:1.

**7. Чому не можна передавати помилку лише червоним кольором?**

Тому що користувач може не розрізняти цей колір або не зрозуміти значення повідомлення. Потрібне текстове пояснення чи інший індикатор.

**8. Що таке color tokens?**

Це іменовані змінні, які дають змогу послідовно використовувати кольори в дизайн-системі.

**9. Чим відрізняються primitive tokens від semantic tokens?**

Primitive tokens задають конкретні кольори палітри, а semantic tokens описують роль кольору в інтерфейсі.

**10. Чому потрібно окремо перевіряти темну тему?**

Тому що зміна фону змінює контрастність і сприйняття тексту. Кольори світлої теми можуть бути непридатними для темної.

**11. Чому не варто використовувати колір як єдиний індикатор посилання?**

Тому що інтерактивність може бути непомітною для людей із порушеннями сприйняття кольорів. Потрібні додаткові візуальні ознаки, наприклад підкреслення.

**12. Як перевірити доступність кольорів тексту?**

Перевірити контрастність пар «текст + фон» і протестувати інтерактивні стани за допомогою інструментів доступності.

# 19. Рівні володіння темою

## Core — базовий рівень

- Розуміти основні й другорядні кольори тексту.
- Вміти створювати просту ієрархію.
- Розрізняти звичайний, приглушений і семантичний текст.
- Використовувати CSS-змінні.
- Розуміти роль контрастності.

## Junior — рівень розробника-початківця

- Створювати узгоджену систему кольорів тексту.
- Використовувати семантичні токени.
- Оформлювати посилання та інтерактивні стани.
- Перевіряти контрастність.
- Розрізняти помилки, попередження та інформаційні повідомлення.
- Уникати дублювання кольорів у CSS.

## Middle — середній рівень

- Проєктувати масштабовану систему токенів.
- Підтримувати світлу й темну теми.
- Перевіряти контрастність складних компонентів.
- Визначати правила використання кольорів у різних контекстах.
- Працювати з доступністю та станами компонентів.
- Підтримувати єдину систему в багатьох сторінках і компонентах.

## Senior — просунутий рівень

- Проєктувати колірну систему для великої дизайн-системи.
- Визначати правила семантичних токенів для різних тем.
- Забезпечувати узгодженість дизайну між продуктами.
- Планувати аудит доступності.
- Керувати змінами палітри без масового переписування компонентів.
- Документувати рішення та правила для дизайнерів і розробників.

# 20. Мінішпаргалка

| Роль | Призначення |
|---|---|
| `text-primary` | Основний вміст |
| `text-secondary` | Допоміжний опис |
| `text-muted` | Метадані та підписи |
| `text-disabled` | Текст недоступного елемента |
| `text-link` | Посилання |
| `text-success` | Успішна дія |
| `text-error` | Помилка |
| `text-warning` | Попередження |
| `text-info` | Інформаційне повідомлення |

**Контрастність за WCAG AA:**
- Звичайний текст — щонайменше `4.5:1`.
- Великий текст — щонайменше `3:1`.

**Практичні правила:**
- Використовуйте семантичні CSS-змінні.
- Перевіряйте контрастність на фактичному фоні.
- Не робіть допоміжний текст надто блідим.
- Не покладайтеся лише на колір для передачі значення.
- Перевіряйте світлу й темну теми окремо.
- Використовуйте узгоджені кольори в усіх компонентах.
- Не створюйте новий токен, якщо наявний уже виконує ту саму роль.

# 21. Головне

**Text Colors — це система ролей, а не набір випадкових відтінків.**

Добре спроєктована система кольорів тексту допомагає користувачеві:
- Швидко знаходити важливу інформацію.
- Розуміти структуру сторінки.
- Розпізнавати посилання та інтерактивні елементи.
- Помічати повідомлення про стан системи.
- Читати текст із достатнім контрастом.
- Комфортно працювати зі світлою та темною темами.

Для початку достатньо створити невелику палітру, призначити кожному кольору конкретну роль, застосувати її через CSS-змінні й перевірити контрастність.

Коли ця система працює послідовно в усьому інтерфейсі, її можна розширювати до повноцінної дизайн-системи.
