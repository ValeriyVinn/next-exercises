# 🎨 Semantic Colors — Семантичні кольори в UI-дизайні

> **Semantic Colors** — це система кольорів, у якій кожен колір має конкретне значення або роль в інтерфейсі. Вона допомагає користувачеві розуміти стани компонентів, результати дій, попередження, помилки та іншу важливу інформацію.

На відміну від звичайної палітри, де кольори визначаються назвами на кшталт синього, зеленого або червоного, семантична система описує, **для чого використовується колір**.

Наприклад, зелений колір може означати успіх, червоний — помилку, жовтий — попередження, а синій — інформаційне повідомлення.

Проте семантика не повинна залежати виключно від загальноприйнятого значення кольору. Вона має бути послідовною в межах конкретного продукту, зрозумілою користувачам і доступною для людей із різними особливостями сприйняття.

**Де використовується:**
- Повідомлення про успішні дії та помилки.
- Валідація полів форм.
- Попередження про важливі події.
- Статуси замовлень, завдань і документів.
- Інформаційні банери.
- Індикатори стану компонентів.
- Таблиці, дашборди та адміністративні панелі.
- Світла й темна теми.
- Дизайн-системи та бібліотеки UI-компонентів.

---

## ✔ Основні поняття

- **Semantic Colors** — кольори, що передають певне значення або роль.
- **Success** — успішна дія або позитивний результат.
- **Error** — помилка, невдала дія або некоректні дані.
- **Warning** — попередження про потенційну проблему.
- **Info** — нейтральна інформація.
- **Neutral** — нейтральний стан або звичайний вміст.
- **Status color** — колір, який позначає стан об'єкта.
- **Feedback color** — колір, що допомагає передати результат взаємодії.
- **Semantic token** — іменована змінна, яка описує роль кольору.
- **Primitive token** — змінна з конкретним значенням кольору в палітрі.
- **Foreground** — колір тексту, іконки або іншого вмісту поверх фону.
- **Background** — колір фону компонента.
- **Border** — колір межі компонента.
- **Contrast** — різниця між кольорами, що впливає на читабельність.
- **Accessible design** — дизайн, який враховує потреби різних користувачів.
- **Dark mode** — темна тема інтерфейсу.
- **State mapping** — відповідність між станом компонента та його візуальним оформленням.

# 1. Що таке семантичні кольори

Уявімо, що користувач заповнив форму реєстрації.

Після натискання кнопки система може показати одне з повідомлень:

    Реєстрацію успішно завершено.

    Не вдалося зберегти дані.

    Пароль закінчується через 7 днів.

    Дані синхронізуються із сервером.

Це чотири різні ситуації. Щоб допомогти користувачеві швидше зрозуміти кожну з них, інтерфейс може використовувати різні семантичні кольори.

| Значення | Типовий колір | Приклад |
|---|---|---|
| Success | Зелений | Дані успішно збережено |
| Error | Червоний | Не вдалося зберегти дані |
| Warning | Жовтий або бурштиновий | Термін дії пароля завершується |
| Info | Синій | Дані синхронізуються |
| Neutral | Сірий | Чернетка документа |

Це поширена конвенція, але не універсальний закон. У конкретному продукті потрібно забезпечити послідовність значень і зрозумілість повідомлень.

**Головний принцип:** семантичний колір передає значення, а не просто прикрашає елемент.

---

# 2. Чим семантичні кольори відрізняються від звичайної палітри

Звичайна палітра описує конкретні кольори.

    --blue-600: #2563eb;
    --green-700: #15803d;
    --red-700: #b91c1c;

Ці назви повідомляють, який саме колір використовується, але не пояснюють його призначення.

Семантичні токени описують роль кольору:

    --color-success: #15803d;
    --color-error: #b91c1c;
    --color-info: #2563eb;

У більшій дизайн-системі краще розділяти ці рівні.

## 2.1. Primitive tokens — базові кольори

Primitive tokens містять конкретні значення палітри.

    :root {
        --green-50: #f0fdf4;
        --green-700: #15803d;

        --red-50: #fef2f2;
        --red-700: #b91c1c;

        --blue-50: #eff6ff;
        --blue-700: #1d4ed8;

        --amber-50: #fffbeb;
        --amber-800: #92400e;
    }

## 2.2. Semantic tokens — кольори за значенням

Семантичні токени посилаються на базову палітру.

    :root {
        --color-success-text: var(--green-700);
        --color-success-background: var(--green-50);

        --color-error-text: var(--red-700);
        --color-error-background: var(--red-50);

        --color-info-text: var(--blue-700);
        --color-info-background: var(--blue-50);

        --color-warning-text: var(--amber-800);
        --color-warning-background: var(--amber-50);
    }

Тепер компоненту не потрібно знати, що повідомлення про помилку використовує певний відтінок червоного. Він просто використовує роль `error`.

    .alert--error {
        color: var(--color-error-text);
        background-color: var(--color-error-background);
    }

**Перевага:** палітру можна змінити централізовано, не переписуючи кожен компонент.

# 3. Основні групи семантичних кольорів

Для більшості інтерфейсів достатньо чотирьох основних груп.

## 3.1. Success — успіх

Використовується для позитивного результату або успішного завершення дії.

**Приклади:**
- Дані успішно збережено.
- Реєстрацію завершено.
- Оплату підтверджено.
- Файл успішно завантажено.
- Налаштування застосовано.

    :root {
        --color-success-text: #166534;
        --color-success-background: #f0fdf4;
        --color-success-border: #86efac;
    }

Приклад повідомлення:

    <div class="alert alert--success" role="status">
        Дані успішно збережено.
    </div>

Зелений колір часто асоціюється з успіхом, але не кожен позитивний стан обов'язково потребує зеленого оформлення.

Не використовуйте success для нейтральних інформаційних повідомлень лише тому, що зелений виглядає приємно.

## 3.2. Error — помилка

Використовується для невдалих дій, некоректних даних або проблем, які потребують виправлення.

**Приклади:**
- Неправильний формат email.
- Не вдалося зберегти дані.
- Файл не завантажився.
- Поле обов'язкове для заповнення.
- Сервер повернув помилку.

    :root {
        --color-error-text: #b91c1c;
        --color-error-background: #fef2f2;
        --color-error-border: #fca5a5;
    }

Приклад:

    <div class="alert alert--error" role="alert">
        Не вдалося зберегти зміни. Спробуйте ще раз.
    </div>

Повідомлення про помилку повинно не тільки позначати проблему, а й пояснювати її та, якщо можливо, підказувати наступний крок.

## 3.3. Warning — попередження

Використовується, коли ситуація може призвести до проблеми або потребує уваги, але не обов'язково є помилкою.

**Приклади:**
- Незбережені зміни.
- Скоро завершиться термін дії документа.
- Залишилося мало місця.
- Дія може мати небажані наслідки.

    :root {
        --color-warning-text: #92400e;
        --color-warning-background: #fffbeb;
        --color-warning-border: #fcd34d;
    }

Приклад:

    <div class="alert alert--warning" role="status">
        Ви маєте незбережені зміни.
    </div>

Попередження не повинно створювати зайву тривогу. Використовуйте його лише тоді, коли користувачеві справді потрібно звернути увагу на ситуацію.

## 3.4. Info — інформація

Використовується для повідомлень, які інформують користувача, але не обов'язково означають успіх, помилку чи ризик.

**Приклади:**
- Доступна нова версія застосунку.
- Дані синхронізуються.
- Зміни набудуть чинності завтра.
- Ви можете змінити налаштування пізніше.

    :root {
        --color-info-text: #1d4ed8;
        --color-info-background: #eff6ff;
        --color-info-border: #93c5fd;
    }

Приклад:

    <div class="alert alert--info" role="status">
        Дані синхронізуються. Це може зайняти кілька секунд.
    </div>

Інформаційне повідомлення не повинно виглядати як помилка або критичне попередження.

---

# 4. Neutral — нейтральні стани

Не кожен стан потрібно позначати червоним, зеленим, жовтим або синім кольором.

У багатьох застосунках є нейтральні стани:

- Чернетка.
- Очікує обробки.
- Неактивний.
- Не налаштовано.
- Архівний.
- За замовчуванням.

Для таких ситуацій можна використовувати нейтральну палітру.

    :root {
        --color-neutral-text: #374151;
        --color-neutral-background: #f3f4f6;
        --color-neutral-border: #d1d5db;
    }

Приклад статусу:

    <span class="status status--neutral">
        Чернетка
    </span>

Нейтральний колір особливо корисний у таблицях, адміністративних панелях і списках завдань, де одночасно відображається багато статусів.

**Що запам'ятати:** не кожен статус є успіхом, помилкою або попередженням. Для звичайних станів потрібна нейтральна категорія.

---

# 5. Semantic colors і ролі компонентів

Семантичні кольори не обмежуються кольором тексту.

Для кожної групи повідомлень можуть бути потрібні різні ролі:

- Text — колір тексту.
- Background — колір фону.
- Border — колір межі.
- Icon — колір іконки.
- Indicator — колір індикатора стану.

Наприклад, для помилки:

    :root {
        --color-error-text: #b91c1c;
        --color-error-background: #fef2f2;
        --color-error-border: #fca5a5;
        --color-error-icon: #b91c1c;
    }

Застосування:

    .alert--error {
        color: var(--color-error-text);
        background-color: var(--color-error-background);
        border: 1px solid var(--color-error-border);
    }

    .alert--error .alert__icon {
        color: var(--color-error-icon);
    }

Ці ролі не завжди повинні мати різні значення. Наприклад, текст та іконка можуть використовувати той самий колір.

Важливо, щоб усі частини компонента працювали узгоджено й залишалися читабельними.

# 6. Semantic colors у повідомленнях

Повідомлення — один із найпоширеніших прикладів використання семантичних кольорів.

Зазвичай повідомлення містить:

- Заголовок або короткий статус.
- Пояснення.
- Іконку, якщо вона корисна.
- Дію, якщо користувачеві потрібно щось зробити.

## 6.1. HTML-структура

    <div class="alert alert--success" role="status">
        <strong class="alert__title">Збережено</strong>
        <p class="alert__description">
            Ваші зміни успішно збережено.
        </p>
    </div>

## 6.2. Базові стилі

    .alert {
        padding: 16px;
        border: 1px solid transparent;
        border-radius: 8px;
    }

    .alert__title {
        display: block;
        margin-bottom: 4px;
    }

    .alert__description {
        margin: 0;
        line-height: 1.5;
    }

## 6.3. Варіанти повідомлень

    .alert--success {
        color: #166534;
        background-color: #f0fdf4;
        border-color: #86efac;
    }

    .alert--error {
        color: #991b1b;
        background-color: #fef2f2;
        border-color: #fca5a5;
    }

    .alert--warning {
        color: #92400e;
        background-color: #fffbeb;
        border-color: #fcd34d;
    }

    .alert--info {
        color: #1e40af;
        background-color: #eff6ff;
        border-color: #93c5fd;
    }

Це навчальні приклади. У реальному проєкті кожну комбінацію тексту, фону й межі потрібно перевірити на контрастність.

# 7. Semantic colors у формах

Форми часто використовують семантичні кольори для позначення результату перевірки даних.

Наприклад:
- Поле без помилок.
- Поле з помилкою.
- Поле з успішною перевіркою.
- Загальне повідомлення про помилку форми.

## 7.1. Поле з помилкою

    <div class="form-field">
        <label for="email">Електронна пошта</label>

        <input
            id="email"
            name="email"
            type="email"
            aria-invalid="true"
            aria-describedby="email-error"
        >

        <p id="email-error" class="field-error">
            Введіть коректну адресу електронної пошти.
        </p>
    </div>

CSS:

    .form-field input {
        width: 100%;
        padding: 12px;
        border: 1px solid #9ca3af;
        border-radius: 8px;
    }

    .form-field input[aria-invalid="true"] {
        border-color: #b91c1c;
    }

    .field-error {
        color: #b91c1c;
        margin-top: 6px;
    }

Атрибут `aria-invalid="true"` доречний, коли значення поля справді не проходить перевірку. Повідомлення пов'язане з полем через `aria-describedby`.

## 7.2. Поле з успішною перевіркою

У деяких формах корисно показувати, що введене значення перевірено.

    .form-field input.is-valid {
        border-color: #15803d;
    }

Проте не потрібно позначати кожне коректне поле зеленим, якщо це створює візуальний шум.

Використовуйте позитивний індикатор лише тоді, коли він допомагає користувачеві зрозуміти результат дії.

## 7.3. Помилка не повинна передаватися лише кольором

Недостатньо просто зробити межу поля червоною.

Користувачеві потрібно пояснити:
- Що саме неправильно.
- Яке значення очікується.
- Як виправити проблему.

Колір допомагає помітити помилку, а текст пояснює її.

# 8. Semantic colors у статусах

У дашбордах, LMS, CRM і системах керування часто потрібно показувати статуси об'єктів.

Наприклад:

| Статус | Семантична роль |
|---|---|
| Завершено | Success |
| Помилка | Error |
| Очікує уваги | Warning |
| Виконується | Info |
| Чернетка | Neutral |
| Скасовано | Залежить від контексту |

Важливо: значення статусу визначає колір, а не навпаки.

Наприклад, скасована операція не обов'язково є помилкою. Вона може бути звичайним нейтральним результатом.

## 8.1. Статусний бейдж

HTML:

    <span class="status status--success">
        Завершено
    </span>

    <span class="status status--warning">
        Очікує уваги
    </span>

    <span class="status status--error">
        Помилка
    </span>

CSS:

    .status {
        display: inline-flex;
        align-items: center;
        padding: 4px 10px;
        border: 1px solid transparent;
        border-radius: 9999px;
        font-size: 0.875rem;
        font-weight: 500;
    }

    .status--success {
        color: #166534;
        background-color: #f0fdf4;
        border-color: #86efac;
    }

    .status--warning {
        color: #92400e;
        background-color: #fffbeb;
        border-color: #fcd34d;
    }

    .status--error {
        color: #991b1b;
        background-color: #fef2f2;
        border-color: #fca5a5;
    }

Текст статусу залишається обов'язковим. Не покладайтеся лише на зелений, жовтий або червоний бейдж.

# 9. Semantic colors у кнопках

Кнопки можуть використовувати семантичні кольори, але важливо розрізняти **значення дії** та **візуальну ієрархію кнопки**.

Наприклад:
- Primary button — основна дія.
- Secondary button — додаткова дія.
- Destructive button — небезпечна дія.
- Success action — підтвердження позитивного результату, якщо це доречно.

Не кожна основна кнопка повинна бути зеленою. Primary описує пріоритет дії, а success — її значення.

## 9.1. Destructive action

Для видалення даних може використовуватися червона кнопка.

    .button--destructive {
        color: #ffffff;
        background-color: #b91c1c;
        border: 1px solid #b91c1c;
    }

    .button--destructive:hover {
        background-color: #991b1b;
        border-color: #991b1b;
    }

Це допомагає попередити користувача про потенційно небезпечну дію.

Проте колір не замінює підтвердження дії, коли воно необхідне, або зрозумілого тексту кнопки.

## 9.2. Стан кнопки та семантичне значення

Не потрібно змінювати основну кнопку на зелену лише тому, що вона виконала успішну дію.

Наприклад, кнопка «Зберегти» може залишатися синьою, а після збереження інтерфейс показує окреме зелене повідомлення.

Це допомагає зберігати стабільну візуальну систему.

# 10. Semantic colors і доступність

Колір — корисний спосіб передавання інформації, але не всі користувачі однаково сприймають кольори.

Люди можуть мати різні особливості кольоросприйняття, працювати на екранах із низькою якістю або використовувати інтерфейс за несприятливого освітлення.

Тому важливо дотримуватися кількох правил.

## 10.1. Не використовуйте лише колір

Поганий приклад:

    <span class="status status--error"></span>

Користувач бачить лише червоний елемент без пояснення.

Краще:

    <span class="status status--error">
        Помилка завантаження
    </span>

Тепер значення зрозуміле навіть без розпізнавання кольору.

## 10.2. Використовуйте зрозумілий текст

Замість повідомлення:

    Помилка!

Краще:

    Не вдалося зберегти зміни. Перевірте з'єднання та спробуйте ще раз.

Текст повідомлення повинен пояснювати проблему, а за можливості — підказувати наступний крок.

## 10.3. Перевіряйте контрастність

Для звичайного тексту критерій WCAG AA вимагає контрастності щонайменше `4.5:1`.

Для великого тексту — щонайменше `3:1`.

Ці значення стосуються тексту та його фону. Окремі нетекстові компоненти й індикатори стану мають власні вимоги.

Для перевірки можна використовувати:
- WebAIM Contrast Checker.
- Chrome DevTools.
- Axe DevTools.
- Lighthouse.
- Інструменти доступності у Figma.

Перевіряйте кожну фактичну пару «текст + фон», а не лише колір тексту окремо.

## 10.4. Не забувайте про іконки та межі

Якщо значення передається кольоровою іконкою або межею, переконайтеся, що цей індикатор помітний і зрозумілий.

За потреби поєднуйте:
- Текст.
- Іконку.
- Колір.
- Форму.
- Положення елемента.

# 11. Семантичні кольори в темній темі

У темній темі не можна просто залишити всі кольори без змін.

Наприклад, темно-зелений текст на темно-сірому фоні може стати майже непомітним.

Для темної теми зазвичай потрібні інші значення семантичних токенів.

    :root {
        color-scheme: light;

        --color-success-text: #166534;
        --color-success-background: #f0fdf4;
        --color-success-border: #86efac;

        --color-error-text: #991b1b;
        --color-error-background: #fef2f2;
        --color-error-border: #fca5a5;

        --color-warning-text: #92400e;
        --color-warning-background: #fffbeb;
        --color-warning-border: #fcd34d;

        --color-info-text: #1e40af;
        --color-info-background: #eff6ff;
        --color-info-border: #93c5fd;
    }

    [data-theme="dark"] {
        color-scheme: dark;

        --color-success-text: #86efac;
        --color-success-background: #052e16;
        --color-success-border: #166534;

        --color-error-text: #fca5a5;
        --color-error-background: #450a0a;
        --color-error-border: #991b1b;

        --color-warning-text: #fcd34d;
        --color-warning-background: #451a03;
        --color-warning-border: #92400e;

        --color-info-text: #93c5fd;
        --color-info-background: #172554;
        --color-info-border: #1d4ed8;
    }

Тут показано принцип побудови системи, а не готова гарантія доступності всіх комбінацій.

Після створення теми обов'язково перевірте контрастність тексту, фону, меж та інтерактивних станів.

## Що перевірити

- Чи читається текст повідомлень.
- Чи помітні межі.
- Чи відрізняються success, error, warning та info.
- Чи зберігається зрозумілість у відтінках сірого.
- Чи помітний фокус клавіатури.
- Чи достатньо контрастні іконки.
- Чи не виглядають усі повідомлення однаково яскравими.

# 12. Semantic tokens у дизайн-системі

Для невеликого проєкту достатньо простого набору змінних.

    :root {
        --color-success: #15803d;
        --color-error: #b91c1c;
        --color-warning: #a16207;
        --color-info: #1d4ed8;
        --color-neutral: #4b5563;
    }

Однак у великій дизайн-системі краще розділяти кольори за функціями.

    :root {
        /* Success */
        --color-success-text: #166534;
        --color-success-background: #f0fdf4;
        --color-success-border: #86efac;

        /* Error */
        --color-error-text: #991b1b;
        --color-error-background: #fef2f2;
        --color-error-border: #fca5a5;

        /* Warning */
        --color-warning-text: #92400e;
        --color-warning-background: #fffbeb;
        --color-warning-border: #fcd34d;

        /* Info */
        --color-info-text: #1e40af;
        --color-info-background: #eff6ff;
        --color-info-border: #93c5fd;

        /* Neutral */
        --color-neutral-text: #374151;
        --color-neutral-background: #f3f4f6;
        --color-neutral-border: #d1d5db;
    }

Такий підхід дає змогу незалежно змінювати текст, фон і межу компонента.

## 12.1. Чому семантичні назви кращі за назви кольорів

Порівняймо:

    .error-message {
        color: var(--red-700);
        background-color: var(--red-50);
    }

І:

    .error-message {
        color: var(--color-error-text);
        background-color: var(--color-error-background);
    }

Другий варіант краще пояснює призначення кольорів.

Якщо в майбутньому дизайн-система змінить палітру, компоненту не потрібно знати, чи залишився error червоним, чи змінився його відтінок.

# 13. Semantic colors і стани компонентів

Не всі семантичні кольори позначають результат дії. Частина з них допомагає відображати стан компонента.

Наприклад:
- Default — звичайний стан.
- Hover — наведення.
- Focus — фокус.
- Selected — вибраний стан.
- Disabled — неактивний стан.
- Error — помилка.
- Success — успішна перевірка.

Для цих ролей варто визначити окремі правила.

    :root {
        --color-border-default: #d1d5db;
        --color-border-focus: #2563eb;
        --color-border-selected: #1d4ed8;
        --color-border-error: #b91c1c;
        --color-border-success: #15803d;
    }

    .input {
        border: 1px solid var(--color-border-default);
    }

    .input:focus-visible {
        outline: 2px solid var(--color-border-focus);
        outline-offset: 2px;
    }

    .input[aria-invalid="true"] {
        border-color: var(--color-border-error);
    }

Не плутайте семантичні стани з пріоритетом компонента.

Наприклад:
- `primary` описує важливість дії.
- `success` описує позитивне значення або результат.
- `disabled` описує недоступність взаємодії.
- `error` описує проблему.

Один компонент може мати кілька характеристик, але правила їхнього поєднання повинні бути визначені.

# 14. Як не переплутати Warning, Error і Info

Ці три категорії часто плутають, тому варто встановити прості правила.

## Error

Використовуйте, коли:
- Дія не виконалася.
- Дані некоректні.
- Є проблема, що потребує виправлення.
- Система не може завершити операцію.

Приклад:

    Не вдалося завантажити файл.

## Warning

Використовуйте, коли:
- Є потенційна проблема.
- Потрібно звернути увагу.
- Користувач може втратити дані.
- Потрібно ухвалити рішення перед продовженням.

Приклад:

    Ви маєте незбережені зміни.

## Info

Використовуйте, коли:
- Потрібно повідомити про подію.
- Немає помилки або критичного ризику.
- Користувачеві потрібна додаткова інформація.

Приклад:

    Зміни набудуть чинності після повторного входу.

**Просте правило:**
- Error — проблема вже сталася або дія не виконалася.
- Warning — є ризик або ситуація потребує уваги.
- Info — повідомлення допомагає зрозуміти процес або умови.

Не використовуйте червоний колір для кожного повідомлення, яке здається важливим. Інакше він перестане ефективно привертати увагу.

# 15. Семантичні кольори в дашбордах і таблицях

У дашбордах часто потрібно показувати багато різних статусів одночасно.

Наприклад, у системі керування навчанням:

| Об'єкт | Статус | Семантична роль |
|---|---|---|
| Курс | Опубліковано | Success або нейтральний активний стан |
| Завдання | Очікує перевірки | Warning або нейтральний стан |
| Тест | Не завершено | Neutral |
| Спроба | Невдала | Error |
| Результати | Завантажуються | Info |

Точне значення кольору залежить від бізнес-логіки.

Наприклад, «Очікує перевірки» не обов'язково означає попередження. Якщо це звичайний робочий процес, нейтральний колір може бути доречнішим.

## Практичні рекомендації

- Використовуйте однакові кольори для однакових значень.
- Не створюйте новий колір для кожного статусу.
- Додавайте текстову назву статусу.
- Уникайте надмірно яскравих бейджів.
- Перевіряйте, чи можна швидко прочитати таблицю.
- Визначайте кольори за значенням, а не за бажанням урізноманітнити дизайн.

# 16. Semantic colors і повідомлення про видалення

Видалення даних — приклад дії, для якої семантика кольору повинна відповідати наслідкам.

Наприклад:

    <button type="button" class="button button--destructive">
        Видалити документ
    </button>

    .button--destructive {
        color: #ffffff;
        background-color: #b91c1c;
        border: 1px solid #b91c1c;
        border-radius: 8px;
        padding: 10px 16px;
    }

Червоний колір допомагає відрізнити небезпечну дію від звичайної.

Однак потрібно враховувати:
- Чи є дія незворотною.
- Чи можна відновити дані.
- Чи потрібне підтвердження.
- Чи зрозумілий текст кнопки.
- Чи є інші способи скасування.

Колір не повинен бути єдиним способом пояснити наслідки.

Для важливих дій можна показати діалог:

    <div role="dialog" aria-labelledby="delete-title">
        <h2 id="delete-title">Видалити документ?</h2>

        <p>
            Документ буде видалено. Цю дію неможливо скасувати.
        </p>

        <button type="button">Скасувати</button>
        <button type="button" class="button--destructive">
            Видалити
        </button>
    </div>

Це лише структура прикладу. Повноцінний діалог також потребує керування фокусом, клавіатурної взаємодії та коректної поведінки для допоміжних технологій.

# 17. Типові помилки

## ❌ 1. Занадто багато семантичних кольорів

Якщо кожна подія має власний відтінок, користувачеві складно запам'ятати значення.

**Рішення:** почніть із Success, Error, Warning, Info та Neutral.

## ❌ 2. Червоний колір для всіх важливих подій

Якщо червоним позначають і помилки, і звичайні сповіщення, він втрачає своє значення.

**Рішення:** розрізняйте помилки, попередження та інформаційні повідомлення.

## ❌ 3. Колір без текстового пояснення

Кольорова крапка не завжди пояснює, що відбувається.

**Рішення:** додавайте текстову назву або пояснення стану.

## ❌ 4. Непослідовна семантика

Якщо зелений колір означає успіх на одній сторінці й небезпеку на іншій, користувач втрачає довіру до системи.

**Рішення:** визначте правила використання кольорів і застосовуйте їх послідовно.

## ❌ 5. Недостатній контраст

Світлий текст на світлому фоні може бути важко прочитати.

**Рішення:** перевіряйте контрастність кожної комбінації.

## ❌ 6. Ігнорування темної теми

Семантичні кольори можуть втрачати читабельність після зміни фону.

**Рішення:** створюйте й тестуйте окремі значення токенів для темної теми.

## ❌ 7. Плутанина між кольором дії та результатом

Зелена кнопка не завжди означає, що дія успішна. Вона може бути просто основною дією.

**Рішення:** відокремлюйте стилі кнопок за пріоритетом від кольорів повідомлень за значенням.

## ❌ 8. Усі повідомлення виглядають однаково

Якщо success, error, warning та info мають однаковий фон і колір, семантична система не працює належним чином.

**Рішення:** використовуйте узгоджені, але розрізнювані комбінації тексту, фону, меж і за потреби іконок.

## ❌ 9. Надмірне використання яскравих кольорів

Якщо всі компоненти виділені яскравими кольорами, увага користувача розсіюється.

**Рішення:** резервуйте виразні кольори для станів, які справді потребують уваги.

## ❌ 10. Надто складні назви токенів

Назви, які не відображають ролі кольорів, ускладнюють підтримку.

**Рішення:** використовуйте зрозумілу систему на кшталт `--color-error-text` або `--color-success-background`.

# 18. Практичний приклад: система повідомлень

Створімо невелику систему повідомлень для навчального застосунку.

## HTML

    <section class="notifications">

- Кольори винесені в змінні.
- Текст не залежить лише від кольору.
- Компоненти легко змінювати й розширювати.

`role="status"` доречний для ненав'язливих повідомлень про стан. `role="alert"` слід використовувати для важливих повідомлень, які потребують оперативної уваги, а не для кожної звичайної події.

Це приклад розподілу статусів за значенням. У реальному продукті потрібно вирішити, чи справді «Очікує перевірки» є попередженням, чи це звичайний робочий стан, який краще оформити нейтрально.

    --color-warning-text

    --color-warning-border

    --color-info-background
    --color-info-border

## Завдання 3. Створи компонент Alert

Реалізуй чотири варіанти повідомлень.

Кожен варіант повинен містити:
- Заголовок.
- Опис.
- Відповідні кольори.
- Межу.
- Заокруглення.

## Завдання 4. Створи статуси для LMS

Реалізуй статуси:
- Не розпочато.
- У процесі.
- Очікує перевірки.
- Завершено.
- Помилка.

Спочатку визнач значення кожного статусу, а потім підбери кольори.

## Завдання 5. Перевір доступність

Перевір:
- Контрастність тексту.
- Контрастність фону.
- Видимість меж.
- Зрозумілість статусів без кольору.
- Читабельність у відтінках сірого.

## Завдання 6. Створи темну тему

Додай `[data-theme="dark"]`.

Зміни значення семантичних токенів так, щоб повідомлення залишалися зрозумілими й читабельними.

## Завдання 7. Проведи аудит власного проєкту

Переглянь свої мініпроєкти й знайди:
- Повідомлення з непослідовними кольорами.
- Статуси без текстових назв.
- Червоні елементи, які не позначають помилку.
- Попередження, які виглядають як критичні помилки.
- Семантичні кольори без достатнього контрасту.

Заміни випадкові значення єдиною системою токенів.

# 21. Питання для співбесіди

**1. Що таке semantic colors?**

Це кольори, які мають визначену роль або значення в інтерфейсі, наприклад успіх, помилка, попередження чи інформація.

**2. Чим семантичні кольори відрізняються від звичайної палітри?**

Звичайна палітра описує конкретні кольори, а семантичні токени — їхні ролі в інтерфейсі.

**3. Які основні групи семантичних кольорів?**

Зазвичай Success, Error, Warning, Info та Neutral.

**4. Чим відрізняється Warning від Error?**

Warning позначає потенційну проблему або ситуацію, що потребує уваги. Error позначає проблему, невдалу дію або некоректні дані.

**5. Чим відрізняється Info від Success?**

Info передає нейтральну інформацію, а Success — позитивний результат або успішне завершення дії.

**6. Що таке semantic token?**

Це іменована змінна, яка описує призначення кольору, наприклад `--color-error-text`.

**7. Чому потрібно розділяти primitive та semantic tokens?**

Щоб відокремити конкретні кольори палітри від їхніх ролей і мати змогу змінювати палітру без переписування компонентів.

**8. Чому не можна передавати стан лише кольором?**

Тому що деякі користувачі можуть не розрізняти певні кольори. Потрібні текст, іконки або інші зрозумілі індикатори.

**9. Як семантичні кольори використовуються у формах?**

Вони допомагають показувати помилки, результати перевірки та інші стани полів.

**10. Як перевірити доступність семантичних кольорів?**

Перевірити контрастність тексту й фону, видимість індикаторів та зрозумілість станів без використання кольору.

**11. Чому потрібно окремо налаштовувати темну тему?**

Тому що зміна фону впливає на контрастність. Кольори, придатні для світлої теми, можуть бути нечіткими в темній.

**12. Чи кожна основна кнопка повинна бути зеленою?**

Ні. Primary описує пріоритет дії, а Success — значення або результат. Це різні характеристики.

# 22. Рівні володіння темою

## Core — базовий рівень

- Розуміти призначення семантичних кольорів.
- Розрізняти Success, Error, Warning, Info та Neutral.
- Створювати прості повідомлення.
- Розуміти різницю між палітрою й семантичними токенами.
- Не використовувати колір як єдиний індикатор значення.

- Створювати семантичні CSS-змінні.
- Оформлювати повідомлення й статуси.
- Використовувати кольори у формах.
- Перевіряти контрастність.
- Розрізняти стани компонентів і значення дій.
- Підтримувати послідовність кольорів між сторінками.

## Middle — середній рівень

- Проєктувати систему семантичних токенів.
- Підтримувати світлу й темну теми.
- Створювати узгоджені статуси для таблиць і дашбордів.
- Визначати правила для повідомлень і станів.
- Перевіряти доступність компонентів.
- Уникати дублювання та конфліктів між токенами.

## Senior — просунутий рівень

- Проєктувати семантичну систему для великої дизайн-системи.
- Створювати правила кольорів для різних продуктів.
- Визначати мапінг бізнес-статусів на UI-ролі.
- Забезпечувати узгодженість тем і компонентів.
- Планувати аудит доступності.
- Документувати правила використання семантичних кольорів.

# 23. Мінішпаргалка

| Семантична роль | Призначення | Типовий приклад |
|---|---|---|
| `success` | Позитивний результат | Дані збережено |
| `error` | Помилка або невдала дія | Не вдалося завантажити |
| `warning` | Потенційна проблема | Незбережені зміни |
| `info` | Нейтральна інформація | Дані синхронізуються |
| `neutral` | Звичайний стан | Чернетка |

Приклад CSS-токенів:

    :root {
        --color-success-text: #166534;
        --color-success-background: #f0fdf4;
        --color-success-border: #86efac;

        --color-error-text: #991b1b;
        --color-error-background: #fef2f2;
        --color-error-border: #fca5a5;

        --color-warning-text: #92400e;
        --color-warning-background: #fffbeb;
        --color-warning-border: #fcd34d;

        --color-info-text: #1e40af;
        --color-info-background: #eff6ff;
        --color-info-border: #93c5fd;

        --color-neutral-text: #374151;
        --color-neutral-background: #f3f4f6;
        --color-neutral-border: #d1d5db;
    }

**Практичні правила:**
- Називайте кольори за ролями, а не лише за відтінками.
- Визначайте значення повідомлення перед вибором кольору.
- Використовуйте однакову семантику в усьому застосунку.
- Не покладайтеся лише на колір.
- Перевіряйте контрастність тексту й фону.
- Створюйте окремі значення для темної теми.
- Не використовуйте Error для кожної важливої події.
- Не плутайте Primary action із Success state.

# 24. Головне

**Semantic Colors — це система значень, закладених у кольори інтерфейсу.**

Вони допомагають користувачеві:
- Розуміти результати дій.
- Помічати помилки.
- Звертати увагу на потенційні проблеми.
- Розрізняти інформаційні повідомлення та критичні стани.
- Швидко читати статуси.
- Послідовно сприймати інтерфейс у різних розділах застосунку.

Для початку достатньо визначити п'ять основних ролей: Success, Error, Warning, Info та Neutral. Потім потрібно створити семантичні токени, застосувати їх у повідомленнях і статусах та перевірити доступність.

У зрілій дизайн-системі семантичні кольори стають спільною мовою дизайнерів і розробників: вони визначають не просто те, **який колір використано**, а те, **що цей колір означає для користувача**.
