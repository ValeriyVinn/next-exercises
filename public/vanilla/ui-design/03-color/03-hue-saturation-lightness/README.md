# 🎨 Hue, Saturation та Lightness — Колірний тон, насиченість і світлота

## 📌 Що це?

**Hue, Saturation та Lightness (HSL)** — це модель представлення кольорів за трьома характеристиками:

- **Hue (H)** — колірний тон: який саме це колір.
- **Saturation (S)** — насиченість: наскільки колір інтенсивний або приглушений.
- **Lightness (L)** — світлота: наскільки колір близький до чорного або білого.

HSL допомагає дизайнеру створювати гармонійні палітри, варіації одного кольору, стани кнопок, фони, текстові акценти та світлі й темні теми інтерфейсу.

На відміну від простого вибору кольорів за HEX-кодами, HSL дає змогу мислити властивостями кольору: змінити його яскравість, насиченість або тон, не підбираючи щоразу нове значення навмання.

### Де використовується?

- Під час створення палітри UI.
- Для побудови світлих і темних відтінків одного кольору.
- Для оформлення кнопок, посилань, карток і панелей.
- Для створення hover, active, focus та disabled-станів.
- Для налаштування світлої й темної теми.
- Для створення CSS-змінних і дизайн-систем.
- Для побудови послідовних палітр на основі одного базового кольору.

---

## 🧠 Ключові поняття

✔ **Hue (H)** — колірний тон, зазвичай задається кутом від 0° до 360°.

✔ **Saturation (S)** — насиченість, яка в класичному HSL задається у відсотках від 0% до 100%.

✔ **Lightness (L)** — світлота, яка в HSL задається у відсотках від 0% до 100%.

✔ **HSL** — модель кольору, побудована на трьох компонентах: Hue, Saturation, Lightness.

✔ **HEX** — шістнадцятковий запис кольору, наприклад `#2563EB`.

✔ **RGB** — модель кольору, що задає кількість червоного, зеленого та синього світла.

✔ **Tint** — світліший варіант кольору, традиційно отриманий додаванням білого.

✔ **Shade** — темніший варіант кольору, традиційно отриманий додаванням чорного.

✔ **Tone** — варіант кольору зі зниженою інтенсивністю, традиційно отриманий додаванням сірого.

✔ **Color palette** — набір кольорів, що працюють разом у межах інтерфейсу.

✔ **Color scale** — послідовність варіантів одного кольору від світлих до темних.

✔ **Contrast** — візуальна різниця між кольорами, важлива для читабельності й доступності.

✔ **CSS custom properties** — CSS-змінні, що допомагають централізовано керувати кольорами.

✔ **Perceptual uniformity** — властивість моделі, за якої однакові числові зміни приблизно відповідають однаковим візуальним змінам. HSL не є перцептивно рівномірною моделлю.

---

## 🎯 Що потрібно пам'ятати

- HSL описує колір через тон, насиченість і світлоту.
- Hue відповідає на питання: «Який це колір?»
- Saturation відповідає на питання: «Наскільки колір інтенсивний?»
- Lightness відповідає на питання: «Наскільки колір світлий або темний?»
- У HSL `L: 0%` означає чорний, а `L: 100%` — білий незалежно від Hue та Saturation.
- За `S: 0%` колір стає відтінком сірого, тому Hue майже не має візуального значення.
- Однакове значення Lightness не гарантує однакового сприйняття яскравості різних кольорів.
- HSL зручний для створення палітр, але не гарантує рівномірних візуальних переходів.
- Збільшення Lightness не завжди робить колір кращим для UI.
- Насичений колір не обов'язково має достатній контраст із фоном.
- Контраст тексту потрібно перевіряти окремо.
- Не всі кольори однаково добре виглядають на однакових значеннях Saturation та Lightness.
- HSL — це інструмент для роботи з кольором, а не готова система вибору правильних кольорів.

# 1. HSL — три характеристики кольору

## 1.1. Hue — колірний тон

**Hue** визначає, до якої колірної категорії належить колір: червоної, жовтої, зеленої, синьої тощо.

У HSL колірний тон задається кутом на колірному колі.

Приблизні орієнтири:

| Hue | Колір |
|---:|---|
| 0° | Червоний |
| 30° | Помаранчевий |
| 60° | Жовтий |
| 90° | Жовто-зелений |
| 120° | Зелений |
| 180° | Блакитно-ціановий |
| 210° | Блакитний |
| 240° | Синій |
| 270° | Фіолетовий |
| 300° | Пурпуровий |
| 330° | Червоно-пурпуровий |
| 360° | Знову червоний |

Це орієнтовна схема. Точний вигляд кольору залежить також від Saturation та Lightness.

Наприклад, у CSS:

    .example {
        color: hsl(0 80% 50%);
    }

    .example {
        color: hsl(120 80% 50%);
    }

    .example {
        color: hsl(240 80% 50%);
    }

Тут Hue змінюється, а Saturation і Lightness залишаються незмінними.

У результаті ми отримуємо червоний, зелений і синій кольори.

### Що потрібно пам'ятати про Hue?

- Hue змінюється по колу, а не по прямій.
- Значення 0° і 360° відповідають одному напрямку на колірному колі.
- Зміна Hue змінює сам колір.
- Для побудови аналогової палітри можна використовувати сусідні значення Hue.
- Для комплементарної палітри можна почати з кольору, розташованого приблизно на 180° від базового.
- Зміна Hue сама по собі не гарантує гармонії палітри.

## 1.2. Saturation — насиченість

**Saturation** визначає, наскільки вираженим або приглушеним виглядає колір.

У класичному HSL Saturation задається у відсотках від 0% до 100%.

- `0%` — відтінок сірого.
- `100%` — максимальна насиченість для заданих Hue та Lightness.

Приклад:

    .low-saturation {
        color: hsl(210 20% 50%);
    }

    .medium-saturation {
        color: hsl(210 50% 50%);
    }

    .high-saturation {
        color: hsl(210 90% 50%);
    }

У всіх трьох випадках Hue дорівнює 210°, Lightness — 50%.

Змінюється тільки Saturation.

### Як насиченість впливає на UI?

Висока насиченість може бути корисною для:

- основних кнопок;
- посилань;
- активних елементів;
- важливих акцентів;
- невеликих іконок;
- індикаторів стану.

Нижча насиченість часто доречна для:

- великих фонових поверхонь;
- карток;
- другорядних елементів;
- декоративних блоків;
- ненав'язливих підкладок;
- інтерфейсів із великою кількістю інформації.

### Важливо

Насиченість — не те саме, що світлота.

Колір може бути насиченим і темним або насиченим і світлим.

Так само колір із низькою насиченістю не обов'язково є світлим: він може бути темно-сірим.

---

## 1.3. Lightness — світлота

**Lightness** визначає положення кольору між чорним і білим у моделі HSL.

- `0%` — чорний.
- `50%` — середня світлота в моделі HSL.
- `100%` — білий.

Приклад:

    .dark-blue {
        color: hsl(220 80% 20%);
    }

    .base-blue {
        color: hsl(220 80% 50%);
    }

    .light-blue {
        color: hsl(220 80% 80%);
    }

Hue та Saturation залишаються однаковими. Змінюється Lightness.

### Як Lightness використовується в дизайні?

Низькі значення Lightness часто застосовують для:

- темного тексту;
- темних поверхонь;
- глибоких акцентів;
- hover-станів кнопок;
- темних варіантів основного кольору.

Середні значення можуть використовуватися для:

- основних кольорових акцентів;
- кнопок;
- посилань;
- іконок;
- активних станів.

Високі значення часто використовують для:

- світлих фонів;
- підкладок карток;
- м'яких кольорових поверхонь;
- інформаційних повідомлень;
- декоративних елементів.

Це лише загальні орієнтири. Конкретне застосування залежить від кольору, контрасту та контексту.

### Важливо

`Lightness: 50%` не означає, що колір обов'язково буде візуально середнім за яскравістю.

Жовтий, синій і червоний із однаковими HSL Lightness можуть сприйматися по-різному.

Тому Lightness у HSL не можна використовувати як єдиний критерій для оцінювання контрасту або видимої яскравості.

# 2. Як читати HSL

Функція CSS `hsl()` приймає три основні компоненти:

    hsl(Hue Saturation Lightness)

Наприклад:

    .primary {
        background-color: hsl(220 85% 55%);
    }

Розбираємо:

- `220` — Hue, колірний тон.
- `85%` — Saturation, насиченість.
- `55%` — Lightness, світлота.

У сучасному CSS між компонентами можна використовувати пробіли.

Також можна задавати прозорість через `/`:

    .overlay {
        background-color: hsl(220 85% 55% / 50%);
    }

Тут останнє значення означає 50% непрозорості.

Альтернативний запис із альфа-каналом:

    .overlay {
        background-color: hsla(220, 85%, 55%, 0.5);
    }

Обидва варіанти використовують HSL із прозорістю.

### HSL і HEX

Один і той самий колір можна представити різними способами.

    .color-hex {
        color: #2563eb;
    }

    .color-hsl {
        color: hsl(221 83% 53%);
    }

Ці значення близькі за виглядом, але не обов'язково абсолютно тотожні через округлення та перетворення між моделями.

**HEX і HSL — це різні способи запису кольору, а не різні види кольорів.**

# 3. Як працювати з кольором через HSL

HSL особливо корисний тоді, коли потрібно змінити одну властивість кольору, залишивши інші приблизно незмінними.

## 3.1. Змінюємо тільки Hue

Початковий колір:

    .base {
        background-color: hsl(220 80% 50%);
    }

Варіанти:

    .red {
        background-color: hsl(0 80% 50%);
    }

    .green {
        background-color: hsl(120 80% 50%);
    }

    .purple {
        background-color: hsl(280 80% 50%);
    }

Saturation та Lightness однакові, але самі кольори різні.

**Коли корисно:** для створення кількох кольорових категорій або варіантів палітри.

## 3.2. Змінюємо тільки Saturation

    .muted {
        background-color: hsl(220 20% 50%);
    }

    .balanced {
        background-color: hsl(220 55% 50%);
    }

    .vivid {
        background-color: hsl(220 90% 50%);
    }

**Коли корисно:** щоб зробити колір спокійнішим або виразнішим, не змінюючи його базовий тон.

## 3.3. Змінюємо тільки Lightness

    .dark {
        background-color: hsl(220 80% 25%);
    }

    .base {
        background-color: hsl(220 80% 50%);
    }

    .light {
        background-color: hsl(220 80% 80%);
    }

**Коли корисно:** для побудови світлих і темних варіантів кольору.

## 3.4. Змінюємо кілька компонентів

У реальному дизайні зміна тільки одного компонента не завжди дає бажаний результат.

Наприклад, світлий колір для фону може потребувати одночасного зменшення Saturation.

    .surface {
        background-color: hsl(220 45% 95%);
    }

    .surface-hover {
        background-color: hsl(220 45% 91%);
    }

    .surface-active {
        background-color: hsl(220 45% 86%);
    }

Тут створено три близькі варіанти поверхні.

Вони мають однакові Hue та Saturation, але різні значення Lightness.

Для іншого кольору може знадобитися інша насиченість або інші відстані між значеннями Lightness.

# 4. Tint, Shade і Tone

Ці терміни допомагають описувати варіанти базового кольору.

## 4.1. Tint — світліший варіант

Tint традиційно означає базовий колір із додаванням білого.

У цифровому дизайні близький результат можна отримати, збільшуючи Lightness.

    .blue-base {
        background-color: hsl(220 80% 50%);
    }

    .blue-tint {
        background-color: hsl(220 70% 85%);
    }

Це практичне наближення, а не математично тотожна операція змішування з білим.

## 4.2. Shade — темніший варіант

Shade традиційно означає базовий колір із додаванням чорного.

У HSL близький результат можна отримати, зменшуючи Lightness.

    .blue-base {
        background-color: hsl(220 80% 50%);
    }

    .blue-shade {
        background-color: hsl(220 80% 25%);
    }

## 4.3. Tone — приглушений варіант

Tone традиційно означає колір із додаванням сірого.

На практиці приглушення кольору можна наблизити зменшенням Saturation.

    .blue-base {
        background-color: hsl(220 80% 50%);
    }

    .blue-tone {
        background-color: hsl(220 30% 50%);
    }

### Що потрібно пам'ятати?

- Tint — традиційно колір плюс білий.
- Shade — традиційно колір плюс чорний.
- Tone — традиційно колір плюс сірий.
- Зміна Lightness або Saturation у HSL дає зручне наближення, але не завжди відтворює фізичне змішування пігментів.
- Для UI важливіше оцінювати фактичний результат, ніж буквально дотримуватися термінології.

# 5. Створення колірної шкали

**Color scale** — це набір варіантів одного кольору, розташованих від світлого до темного.

Наприклад, синя шкала:

    :root {
        --blue-50: hsl(220 80% 97%);
        --blue-100: hsl(220 80% 93%);
        --blue-200: hsl(220 75% 85%);
        --blue-300: hsl(220 70% 75%);
        --blue-400: hsl(220 70% 65%);
        --blue-500: hsl(220 75% 55%);
        --blue-600: hsl(220 80% 45%);
        --blue-700: hsl(220 80% 35%);
        --blue-800: hsl(220 75% 25%);
        --blue-900: hsl(220 70% 17%);
    }

Це приклад навчальної шкали. У реальній дизайн-системі кожен колір потрібно перевірити в контексті інтерфейсу.

## 5.1. Для чого потрібна шкала?

Світліші значення можна використовувати для:

- фонових підкладок;
- виділених областей;
- м'яких інформаційних блоків;
- декоративних поверхонь.

Середні значення можна використовувати для:

- основних акцентів;
- кнопок;
- посилань;
- іконок.

Темніші значення можна використовувати для:

- тексту на світлих кольорових поверхнях;
- темних акцентів;
- обводок;
- активних станів.

Це не універсальна таблиця призначень. Наприклад, `--blue-500` не обов'язково має бути кольором кнопки в кожному проєкті.

## 5.2. Чому не варто просто змінювати Lightness на однаковий крок?

У HSL однакові числові кроки не завжди сприймаються як однакові візуальні кроки.

Наприклад, перехід від 90% до 80% може виглядати інакше, ніж перехід від 50% до 40%.

Крім того, різні Hue по-різному сприймаються людським оком.

Тому професійна шкала часто потребує ручного коригування:

- Lightness;
- Saturation;
- іноді Hue.

## 5.3. Приклад використання шкали

    .button {
        background-color: var(--blue-600);
        color: white;
    }

    .button:hover {
        background-color: var(--blue-700);
    }

    .button:active {
        background-color: var(--blue-800);
    }

    .info-card {
        background-color: var(--blue-50);
        border: 1px solid var(--blue-200);
    }

Цей підхід допомагає зберігати узгодженість кольорів у всьому інтерфейсі.

# 6. HSL у CSS

## 6.1. Змінні для базового кольору

    :root {
        --primary-h: 220;
        --primary-s: 80%;
        --primary-l: 50%;

        --primary: hsl(
            var(--primary-h)
            var(--primary-s)
            var(--primary-l)
        );
    }

    .button {
        background-color: var(--primary);
        color: white;
    }

Так базовий колір можна змінювати централізовано.

## 6.2. Варіанти одного кольору через змінні

    :root {
        --brand-h: 220;
        --brand-s: 80%;

        --brand-light: hsl(var(--brand-h) var(--brand-s) 92%);
        --brand-soft: hsl(var(--brand-h) 65% 80%);
        --brand: hsl(var(--brand-h) var(--brand-s) 50%);
        --brand-dark: hsl(var(--brand-h) var(--brand-s) 35%);
        --brand-deep: hsl(var(--brand-h) 70% 22%);
    }

    .notice {
        background-color: var(--brand-light);
        color: var(--brand-deep);
    }

    .link {
        color: var(--brand-dark);
    }

Це зручний спосіб підтримувати єдину кольорову логіку.

Водночас не потрібно примушувати всі варіанти мати однакову насиченість. Якщо колір виглядає надто різким або брудним, Saturation можна змінити окремо.

## 6.3. Hover, active та disabled

    .button {
        background-color: hsl(220 80% 50%);
        color: white;
    }

    .button:hover {
        background-color: hsl(220 80% 43%);
    }

    .button:active {
        background-color: hsl(220 80% 37%);
    }

    .button:disabled {
        background-color: hsl(220 15% 85%);
        color: hsl(220 10% 45%);
        cursor: not-allowed;
    }

HSL дозволяє будувати логічні стани, змінюючи світлоту та насиченість.

Проте disabled-стан не слід визначати лише за кольором: для доступності важливо також правильно використовувати атрибут `disabled`, коли елемент справді має бути неактивним.

## 6.4. Прозорість

    .backdrop {
        background-color: hsl(220 30% 10% / 60%);
    }

    .highlight {
        background-color: hsl(45 100% 60% / 25%);
    }

Прозорість допомагає створювати затемнення, підсвічування та накладання.

Пам'ятай: фінальний вигляд прозорого кольору залежить від того, що розташовано під ним.

# 7. HSL і вибір кольорів для UI

HSL зручний для керування кольором, але сам по собі не визначає, чи є палітра вдалою.

Під час вибору кольорів потрібно враховувати:

- призначення інтерфейсу;
- контекст використання;
- візуальну ієрархію;
- співвідношення акцентів і нейтральних поверхонь;
- читабельність тексту;
- контраст;
- доступність;
- світлу й темну теми;
- кольорові асоціації аудиторії.

## 7.1. Основний колір

Основний колір часто використовується для найважливіших інтерактивних елементів.

Наприклад:

    :root {
        --primary: hsl(220 80% 50%);
        --primary-hover: hsl(220 80% 43%);
        --primary-active: hsl(220 80% 37%);
    }

Його можна застосовувати для:

- основних кнопок;
- посилань;
- активних пунктів навігації;
- вибраних елементів;
- індикаторів активності.

Але основний колір не обов'язково має бути найяскравішим у всій палітрі. Його роль — підтримувати візуальну ієрархію.

## 7.2. Нейтральні кольори

Нейтральна палітра допомагає не перевантажувати інтерфейс акцентами.

    :root {
        --neutral-50: hsl(220 15% 98%);
        --neutral-100: hsl(220 12% 95%);
        --neutral-200: hsl(220 10% 88%);
        --neutral-300: hsl(220 8% 78%);
        --neutral-500: hsl(220 6% 50%);
        --neutral-700: hsl(220 10% 30%);
        --neutral-900: hsl(220 15% 12%);
    }

Це приклад нейтральної шкали з легким синім відтінком.

Нейтральні кольори можуть використовуватися для:

- фонів сторінки;
- карток;
- основного тексту;
- другорядного тексту;
- меж;
- розділювачів;
- полів введення.

Нейтральна палітра не обов'язково має бути абсолютно сірою. Легкий відтінок базового кольору допомагає об'єднати інтерфейс.

## 7.3. Семантичні кольори

Семантичні кольори передають значення або стан.

Наприклад:

    :root {
        --success: hsl(145 65% 35%);
        --warning: hsl(38 90% 45%);
        --danger: hsl(0 70% 48%);
        --info: hsl(210 80% 45%);
    }

Їх можна використовувати для:

- успішних повідомлень;
- попереджень;
- помилок;
- інформаційних повідомлень.

Однак конкретні відтінки потрібно перевіряти на контраст і на відповідність контексту. Не кожен зелений добре підходить для тексту, і не кожен жовтий добре читається на білому фоні.

Не покладайся лише на колір для передачі значення. Додавай текст, іконки або інші зрозумілі індикатори.

---

# 8. HSL і контрастність

**Контраст** — це різниця між переднім планом і фоном, яка допомагає розрізняти текст та інші елементи.

HSL полегшує налаштування кольорів, але не є інструментом перевірки контрастності.

Наприклад:

    .text {
        color: hsl(220 80% 45%);
        background-color: hsl(220 80% 95%);
    }

Ці кольори можуть виглядати достатньо відмінними, але остаточну контрастність потрібно перевірити спеціальним інструментом.

## 8.1. WCAG і текст

Для відповідності поширеним вимогам WCAG 2.x за контрастністю:

- звичайний текст зазвичай має досягати співвідношення контрастності не менше 4.5:1;
- великий текст — не менше 3:1;
- для важливих графічних елементів інтерфейсу та меж, потрібних для розуміння компонента, часто застосовується вимога 3:1 відносно суміжних кольорів.

Для великого тексту за WCAG зазвичай мається на увазі текст розміром щонайменше 18 pt або 14 pt жирного накреслення.

Перевіряй конкретні вимоги для свого випадку, особливо якщо проєкт має відповідати певному стандарту доступності.

## 8.2. Чому не можна визначати контраст за HSL?

Не можна просто сказати: «У фону Lightness 90%, а в тексту 30%, отже контраст достатній».

На контрастність впливають фактичні кольори, а не тільки різниця між значеннями Lightness.

Правильний порядок:

1. Вибрати кольори через HSL або іншу модель.
2. Застосувати їх до реального компонента.
3. Перевірити контрастність.
4. За потреби змінити Lightness, Saturation або Hue.
5. Повторно перевірити результат.

## 8.3. Колір не повинен бути єдиним сигналом

Невдалий приклад:

    .error {
        border-color: red;
    }

Якщо користувач не розрізняє цей колір або не помічає межу, повідомлення може бути незрозумілим.

Краще:

    .error-message {
        color: hsl(0 65% 35%);
        border: 1px solid hsl(0 65% 45%);
        background-color: hsl(0 80% 97%);
    }

    .error-message__title {
        font-weight: 700;
    }

    .error-message__text {
        margin: 0;
    }

У реальному HTML також додай зрозумілий текст повідомлення, а за потреби — відповідну іконку та доступні атрибути.

# 9. HSL і темна тема

Темна тема — це не просто інверсія кольорів і не механічне зменшення Lightness для всіх елементів.

У темній темі важливо правильно розрізняти:

- фон сторінки;
- поверхні карток;
- поля введення;
- основний текст;
- другорядний текст;
- межі;
- акценти;
- інтерактивні стани.

Приклад базових змінних:

    :root {
        color-scheme: light;

        --page-bg: hsl(220 20% 98%);
        --surface: hsl(0 0% 100%);
        --text-primary: hsl(220 20% 12%);
        --text-secondary: hsl(220 10% 38%);
        --border: hsl(220 12% 85%);
        --accent: hsl(220 80% 45%);
    }

    [data-theme="dark"] {
        color-scheme: dark;

        --page-bg: hsl(220 18% 10%);
        --surface: hsl(220 16% 14%);
        --text-primary: hsl(220 15% 94%);
        --text-secondary: hsl(220 10% 72%);
        --border: hsl(220 12% 28%);
        --accent: hsl(220 85% 70%);
    }

Це приклад структури, а не готова універсальна палітра. Контраст усіх текстів, меж та інтерактивних станів потрібно перевірити.

### Що враховувати?

- Акцент, який добре працює на світлому фоні, може бути надто темним на темному.
- У темній темі іноді потрібен світліший варіант акценту.
- Темні поверхні не обов'язково мають бути абсолютно чорними.
- Світлі поверхні не завжди мають бути чисто білими.
- Другорядний текст повинен залишатися читабельним.
- Межі повинні бути помітними там, де вони допомагають зрозуміти структуру.
- Для кожної теми потрібна окрема перевірка контрастності.

# 10. HSL, HSV та інші моделі кольору

HSL — не єдина модель, яка описує колір через тон та інтенсивність.

## 10.1. HSL

HSL означає:

- Hue;
- Saturation;
- Lightness.

Ця модель зручна для дизайну й CSS, оскільки допомагає інтуїтивно змінювати колір.

## 10.2. HSV / HSB

HSV означає Hue, Saturation, Value.

HSB означає Hue, Saturation, Brightness.

У багатьох графічних інструментах HSV та HSB використовуються як назви дуже близької або еквівалентної моделі.

Проте Value/Brightness у HSV не є тим самим, що Lightness у HSL.

Тому однакові числа в HSL і HSV не обов'язково відповідають одному й тому самому кольору.

## 10.3. RGB

RGB описує колір через три канали світла:

- Red;
- Green;
- Blue.

Це адитивна модель, яка використовується в цифрових дисплеях.

Наприклад:

    .example {
        color: rgb(37 99 235);
    }

RGB зручний для цифрового представлення кольору, а HSL — для його інтуїтивного коригування.

## 10.4. HEX

HEX — шістнадцятковий запис RGB-компонентів.

    .example {
        color: #2563eb;
    }

HEX часто використовують у дизайн-макетах, CSS-змінних, документації та передачі кольорів між інструментами.

## 10.5. OKLCH

OKLCH — сучасна модель, яка описує колір через:

- Lightness;
- Chroma;
- Hue.

На відміну від HSL, OKLCH краще пристосована до рівномірнішого сприйняття змін кольору.

Вона може бути корисною для створення плавних колірних шкал і передбачуваних варіацій.

Приклад:

    .example {
        color: oklch(55% 0.18 250);
    }

Тут:

- `55%` — Lightness;
- `0.18` — Chroma;
- `250` — Hue.

Chroma в OKLCH не тотожна Saturation у HSL.

Для початку достатньо добре розуміти HSL, а OKLCH можна вивчити пізніше, коли виникне потреба у точнішому керуванні колірними шкалами.

# 11. Типові помилки

## ❌ Помилка 1. Плутати Hue, Saturation і Lightness

Hue — це колірний тон.

Saturation — насиченість.

Lightness — світлота.

Це три різні характеристики, і зміна кожної з них має інший ефект.

## ❌ Помилка 2. Вважати, що 50% Lightness означає однакову яскравість

Жовтий і синій за однакової HSL Lightness можуть сприйматися зовсім по-різному.

HSL не є перцептивно рівномірною моделлю.

## ❌ Помилка 3. Використовувати максимальну насиченість скрізь

Якщо кожна кнопка, картка, іконка та заголовок мають максимально насичений колір, інтерфейс стає візуально перевантаженим.

Краще використовувати насичені кольори вибірково.

## ❌ Помилка 4. Змінювати тільки Lightness і очікувати ідеальну шкалу

Послідовність із однаковим Hue, Saturation та різною Lightness не завжди виглядає гармонійно.

Іноді потрібно змінювати Saturation та Hue.

## ❌ Помилка 5. Вважати, що HSL гарантує доступність

HSL допомагає створювати варіанти кольорів, але не перевіряє контрастність.

Контраст потрібно перевіряти окремо.

## ❌ Помилка 6. Вважати, що однакова насиченість дає однаковий візуальний ефект

Значення Saturation 70% для жовтого і синього не означає, що вони виглядатимуть однаково інтенсивними.

Результат залежить від самого Hue та Lightness.

## ❌ Помилка 7. Створювати палітру лише з одного кольору

Один базовий колір може дати багато варіантів, але інтерфейсу часто потрібні також нейтральні та семантичні кольори.

Наприклад, для форми знадобляться стани помилки, успіху та попередження.

## ❌ Помилка 8. Використовувати колір як єдиний спосіб передавання інформації

Помилку не слід позначати лише червоною рамкою.

Додавай текстове повідомлення та інші доречні сигнали.

## ❌ Помилка 9. Застосовувати одну палітру без змін у світлій і темній темах

Кольори, які добре працюють на білому тлі, можуть погано читатися на темному.

Для кожної теми перевіряй контраст і видимість станів.

## ❌ Помилка 10. Плутати HSL із фізичним змішуванням фарб

Зменшення Saturation не тотожне додаванню сірого, а збільшення Lightness не тотожне буквальному додаванню білого в усіх випадках.

Це математичні перетворення в моделі кольору, а не моделювання змішування пігментів.

## ❌ Помилка 11. Надмірно покладатися на магічні числа

Немає універсального правила, за яким кнопка повинна мати Saturation 80%, а фон — Lightness 95%.

Ці значення залежать від конкретного кольору, проєкту та призначення елемента.

## ❌ Помилка 12. Не перевіряти кольори в реальному інтерфейсі

Колір на великому зразку може виглядати інакше, ніж у маленькій іконці або дрібному тексті.

Перевіряй палітру на реальних компонентах і різних розмірах екрана.

# 12. Практичний алгоритм створення палітри через HSL

## Крок 1. Вибери базовий Hue

Визнач, який колір відповідає характеру проєкту.

Наприклад, синій:

    --brand-h: 220;

Не потрібно відразу створювати десятки кольорів. Почни з одного базового напряму.

## Крок 2. Вибери базову Saturation

    --brand-s: 75%;

Перевір, чи колір достатньо виразний, але не перевантажує інтерфейс.

## Крок 3. Вибери базову Lightness

    --brand-l: 50%;

Перевір колір на білому, світло-сірому та темному фоні.

Не вважай 50% універсальним оптимальним значенням.

## Крок 4. Створи світлі й темні варіанти

    :root {
        --brand-100: hsl(220 70% 92%);
        --brand-300: hsl(220 70% 75%);
        --brand-500: hsl(220 75% 50%);
        --brand-700: hsl(220 75% 35%);
        --brand-900: hsl(220 65% 18%);
    }

Перевір, чи утворюють вони логічну шкалу.

## Крок 5. Додай нейтральні кольори

    :root {
        --page-bg: hsl(220 20% 98%);
        --surface: hsl(0 0% 100%);
        --text: hsl(220 20% 12%);
        --text-muted: hsl(220 10% 40%);
        --border: hsl(220 12% 85%);
    }

Нейтральні кольори забезпечують основу, на якій акценти стають помітними.

## Крок 6. Додай семантичні кольори

    :root {
        --success: hsl(145 60% 35%);
        --warning: hsl(38 90% 45%);
        --danger: hsl(0 70% 45%);
        --info: hsl(210 80% 45%);
    }

Перевір, чи кожен колір відповідає своєму призначенню та чи добре читається на потрібному фоні.

## Крок 7. Признач кольори компонентам

    .button-primary {
        background-color: var(--brand-500);
        color: white;
    }

    .card {
        background-color: var(--surface);
        color: var(--text);
        border: 1px solid var(--border);
    }

    .muted {
        color: var(--text-muted);
    }

Це дозволяє перейти від абстрактної палітри до реального інтерфейсу.

## Крок 8. Перевір контраст

Перевір:

- основний текст;
- другорядний текст;
- кнопки;
- посилання;
- межі полів;
- повідомлення про помилки;
- фокус клавіатури;
- світлу й темну теми.

## Крок 9. Відкоригуй кольори

Якщо колір виглядає невдало, не змінюй одразу всю палітру.

Спробуй послідовно змінити:

1. Lightness.
2. Saturation.
3. Hue, якщо потрібно.

Після кожної зміни перевіряй результат у контексті.

# 13. Практичний приклад: кнопка та картка

    :root {
        --brand: hsl(220 80% 50%);
        --brand-hover: hsl(220 80% 43%);
        --brand-active: hsl(220 80% 36%);

        --page-bg: hsl(220 20% 97%);
        --surface: hsl(0 0% 100%);
        --text-primary: hsl(220 20% 12%);
        --text-secondary: hsl(220 10% 40%);
        --border: hsl(220 12% 86%);
    }

    body {
        background-color: var(--page-bg);
        color: var(--text-primary);
    }

    .card {
        padding: 1.5rem;
        background-color: var(--surface);
        border: 1px solid var(--border);
        border-radius: 1rem;
    }

    .card__description {
        color: var(--text-secondary);
    }

    .button {
        padding: 0.75rem 1rem;
        border: none;
        border-radius: 0.5rem;
        background-color: var(--brand);
        color: white;
        font: inherit;
        cursor: pointer;
    }

    .button:hover {
        background-color: var(--brand-hover);
    }

    .button:active {
        background-color: var(--brand-active);
    }

    .button:focus-visible {
        outline: 3px solid hsl(220 90% 75%);
        outline-offset: 3px;
    }

У цьому прикладі:

- основний колір використовується для кнопки;
- темніші варіанти формують hover та active;
- нейтральні кольори задають фон і поверхню картки;
- другорядний текст відрізняється від основного;
- фокус клавіатури має окремий видимий стиль.

Це демонструє, як HSL допомагає створити послідовну систему кольорів.

Проте кольори прикладу не є автоматично перевіреними на відповідність усім вимогам доступності. Перед використанням у реальному проєкті перевір контрастність кожної важливої комбінації.

    "use strict";

    const hueInput = document.querySelector("#hue");
    const saturationInput = document.querySelector("#saturation");
    const lightnessInput = document.querySelector("#lightness");

    const hueValue = document.querySelector("#hue-value");
    const saturationValue = document.querySelector("#saturation-value");
    const lightnessValue = document.querySelector("#lightness-value");

    const colorValue = document.querySelector("#color-value");

    function updateColor() {
        const hue = Number(hueInput.value);
        const saturation = Number(saturationInput.value);
        const lightness = Number(lightnessInput.value);

        const color = `hsl(${hue} ${saturation}% ${lightness}%)`;

        colorPreview.style.backgroundColor = color;
        colorValue.textContent = color;

        hueValue.textContent = hue;
        saturationValue.textContent = saturation;
        lightnessValue.textContent = lightness;

        colorPreview.style.color =
            lightness > 60 ? "black" : "white";
    }

    hueInput.addEventListener("input", updateColor);
    saturationInput.addEventListener("input", updateColor);
    lightnessInput.addEventListener("input", updateColor);

    updateColor();

# 15. Питання для співбесіди

**1. Що означає HSL?**

Hue, Saturation, Lightness — колірний тон, насиченість і світлота.

**2. Чим Hue відрізняється від Saturation?**

Hue визначає, який це колір, а Saturation — наскільки він насичений.

**3. Що означає Lightness 0%?**

Чорний колір у моделі HSL.

**4. Що означає Lightness 100%?**

Білий колір у моделі HSL.

**5. Що означає Saturation 0%?**

Відтінок сірого. Hue за такої насиченості практично не впливає на видимий результат.

**6. Чи є HSL перцептивно рівномірною моделлю?**

Ні. Однакові числові зміни не гарантують однакового візуального ефекту.

**7. Чим HSL відрізняється від RGB?**

RGB описує колір через інтенсивність червоного, зеленого й синього каналів світла. HSL описує його через тон, насиченість і світлоту.

**8. Чим HSL відрізняється від HSV?**

У HSL використовується Lightness, а в HSV — Value. Ці характеристики визначаються по-різному, тому значення однієї моделі не можна напряму переносити в іншу.

**9. Чим HSL відрізняється від HEX?**

HSL і HEX — різні способи запису кольору. HEX зазвичай представляє RGB-компоненти в шістнадцятковому форматі, а HSL використовує тон, насиченість і світлоту.

**10. Як створити темніший варіант кольору в HSL?**

Зазвичай зменшити Lightness, а потім перевірити, чи потрібно змінювати Saturation або Hue.

**11. Як створити приглушений колір?**

Зазвичай зменшити Saturation.

**12. Що таке Tint, Shade і Tone?**

Це традиційні поняття для світліших, темніших і приглушених варіантів кольору.

**13. Чи можна перевірити контрастність лише за HSL?**

Ні. Потрібно оцінювати фактичні кольори та використовувати розрахунок контрастності.

**14. Як HSL допомагає створювати дизайн-систему?**

Він полегшує побудову шкал кольору, варіантів станів і узгоджених CSS-змінних.

**15. Чому однакова Lightness не гарантує однакової видимої яскравості?**

Тому що HSL не є перцептивно рівномірною моделлю, а сприйняття кольору залежить від Hue та інших характеристик.

**16. Коли варто розглянути OKLCH замість HSL?**

Коли потрібні плавніші, візуально послідовніші переходи між кольорами та точніше керування світлотою і кольоровістю.

# 17. Міні-шпаргалка

| Властивість | Що визначає | Типовий діапазон |
|---|---|---|
| Hue | Колірний тон | 0–360° |
| Saturation | Насиченість | 0–100% |
| Lightness | Світлота | 0–100% |

### Основні значення

    hsl(220 80% 50%)

    /* Hue: 220° */
    /* Saturation: 80% */
    /* Lightness: 50% */

    hsl(220 20% 50%)
    /* Менша насиченість */

    hsl(220 80% 25%)
    /* Менша світлота */

    hsl(220 80% 85%)
    /* Більша світлота */

    hsl(220 80% 50% / 50%)
    /* 50% непрозорості */

### CSS-змінні

    :root {
        --brand: hsl(220 80% 50%);
        --brand-light: hsl(220 70% 90%);
        --brand-dark: hsl(220 80% 30%);
    }

### Запам'ятай

- Hue — який колір.
- Saturation — наскільки насичений.
- Lightness — наскільки світлий або темний.
- Tint — традиційно колір плюс білий.
- Shade — традиційно колір плюс чорний.
- Tone — традиційно колір плюс сірий.
- HSL — зручна модель для коригування кольорів.
- HEX — інший спосіб запису кольору.
- RGB — модель червоного, зеленого та синього каналів.
- HSL не гарантує перцептивної рівномірності.
- HSL не гарантує достатньої контрастності.
- Колір потрібно перевіряти в реальному UI.
- Для точнішого керування колірними шкалами можна розглянути OKLCH.

# 18. Головне

**HSL — це інструмент, який допомагає мислити кольором через його властивості, а не лише через числовий код.**

Замість того щоб навмання змінювати HEX-коди, ти можеш послідовно керувати трьома характеристиками:

- Hue — змінювати сам колір.
- Saturation — робити його виразнішим або приглушенішим.
- Lightness — створювати світліші й темніші варіанти.

Це особливо корисно під час побудови палітр, колірних шкал, станів компонентів і дизайн-систем.

Але HSL не замінює візуальну перевірку, аналіз контрасту та принципи доступності. Хороша палітра — це не просто набір математично пов'язаних кольорів, а система, у якій кожен колір має зрозуміле призначення та добре працює в реальному інтерфейсі.

**Формула для запам'ятовування:**

    HSL = Hue + Saturation + Lightness

    Hue        → який колір
    Saturation → наскільки насичений
    Lightness  → наскільки світлий або темний

**Мета дизайнера — не просто вибрати красивий колір, а створити послідовну, читабельну й доступну систему кольорів.**
