# 🌙 09. Dark Mode — Темна тема інтерфейсу

Темна тема (Dark Mode) — це варіант оформлення інтерфейсу, у якому використовуються темні фони, світлий текст і відповідні кольори компонентів.

Мета темної теми — не просто зробити фон чорним, а створити **комфортний, читабельний і візуально узгоджений інтерфейс**, у якому зберігаються контрастність, ієрархія та значення кольорів.

Темна тема використовується в:
- вебзастосунках;
- мобільних застосунках;
- редакторах коду;
- панелях адміністратора;
- сервісах для тривалої роботи;
- системних інтерфейсах.

---

## ✔ Що потрібно знати

- Що таке Dark Mode і Light Mode.
- Чим темна тема відрізняється від інверсії кольорів.
- Як створювати палітру кольорів для темної теми.
- Як використовувати CSS Custom Properties.
- Як організувати дизайн-токени для різних тем.
- Як перемикати теми через CSS і JavaScript.
- Як підтримувати системне налаштування `prefers-color-scheme`.
- Як забезпечити читабельність тексту та контрастність.
- Як адаптувати поверхні, межі, тіні та семантичні кольори.
- Як зберігати вибір користувача.
- Як тестувати темну тему.

## 1. 🌗 Light Mode і Dark Mode

### 1.1. Світла тема

Світла тема зазвичай використовує:
- світлий фон сторінки;
- білі або майже білі поверхні;
- темний основний текст;
- сірі допоміжні написи;
- помітні межі між компонентами.

    :root {
        color-scheme: light;

        --color-background: #f8fafc;
        --color-surface: #ffffff;
        --color-text: #172033;
        --color-text-muted: #64748b;
        --color-border: #dbe2ea;
    }

### 1.2. Темна тема

Темна тема зазвичай використовує:
- темний, але не обов'язково чорний фон;
- трохи світліші поверхні карток;
- світлий основний текст;
- приглушений допоміжний текст;
- видимі, але не надто яскраві межі.

    :root {
        color-scheme: dark;

        --color-background: #111827;
        --color-surface: #1f2937;
        --color-text: #f1f5f9;
        --color-text-muted: #a8b3c4;
        --color-border: #374151;
    }

### 1.3. Темна тема — це не інверсія кольорів

Не варто просто міняти всі світлі кольори на чорні, а всі темні — на білі.

Наприклад:
- логотип може мати окрему версію для темного фону;
- фотографії та ілюстрації не повинні автоматично інвертуватися;
- семантичні кольори потребують окремого налаштування;
- тіні на темному фоні працюють інакше;
- поверхні повинні зберігати візуальну ієрархію.

**Головний принцип:** темна тема — це окрема продумана система кольорів, а не механічна заміна кольорів світлої теми.

---

## 2. 🎨 Палітра кольорів для темної теми

### 2.1. Колір фону

Фон визначає загальне візуальне сприйняття сторінки.

Приклади:

    --color-background: #111827;
    --color-background: #18181b;
    --color-background: #0f172a;

Чистий чорний `#000000` можна використовувати, якщо цього вимагає дизайн, але він не є обов'язковим для кожної темної теми.

Темно-сірі та темно-сині відтінки часто допомагають створити м'якший візуальний вигляд.

### 2.2. Поверхні

Поверхні — це елементи, розташовані на фоні:
- картки;
- панелі;
- модальні вікна;
- меню;
- поля введення;
- бічні панелі.

    --color-background: #111827;
    --color-surface: #1f2937;
    --color-surface-raised: #273449;
    --color-surface-hover: #334155;

Поверхні можуть відрізнятися від фону за яскравістю, межами або іншими візуальними ознаками.

### 2.3. Основний текст

Основний текст повинен залишатися чітким і комфортним для читання.

    --color-text: #f1f5f9;

Не обов'язково використовувати чистий білий `#ffffff` для всього тексту. Світлі відтінки сірого часто виглядають м'якше.

### 2.4. Допоміжний текст

Допоміжний текст використовується для:
- підписів;
- дат;
- пояснень;
- другорядних описів;
- метаданих.

    --color-text-muted: #a8b3c4;
    --color-text-subtle: #8491a5;

Не роби допоміжний текст настільки темним, щоб він ставав важким для читання.

### 2.5. Межі та роздільники

У темній темі межі не повинні бути надто яскравими.

    --color-border: #374151;
    --color-divider: #2d3748;

Межі потрібні для відокремлення компонентів, але вони не повинні перетягувати на себе увагу.

## 3. 🧱 Ієрархія поверхонь

У темному інтерфейсі важливо показувати, які елементи належать до різних рівнів.

Наприклад:

    Сторінка
    ├── Основний фон
    ├── Бічна панель
    ├── Картка
    │   ├── Заголовок
    │   └── Вкладена область
    └── Модальне вікно

Приклад токенів:

    :root {
        --color-background: #111827;
        --color-surface: #1f2937;
        --color-surface-raised: #273449;
        --color-border: #374151;
    }

Використання:

    body {
        background-color: var(--color-background);
    }

    .card {
        background-color: var(--color-surface);
        border: 1px solid var(--color-border);
    }

    .modal {
        background-color: var(--color-surface-raised);
    }

Не потрібно створювати десятки майже однакових відтінків без конкретної причини. Достатньо кількох зрозумілих рівнів поверхонь.

## 4. 🏷️ Дизайн-токени для тем

Дизайн-токени — це змінні, які зберігають значення кольорів та інших параметрів дизайн-системи.

Для тем особливо зручно використовувати CSS Custom Properties.

### 4.1. Структура токенів

Замість прив'язки компонентів до конкретних кольорів використовуй семантичні назви:

    --color-background
    --color-surface
    --color-text
    --color-text-muted
    --color-border
    --color-primary
    --color-success
    --color-warning
    --color-danger

Компонент повинен знати, який колір йому потрібен за призначенням, а не який конкретно HEX-код слід застосувати.

### 4.2. Чому це важливо

Невдалий варіант:

    .card {
        background-color: #ffffff;
        color: #172033;
    }

Якщо таких значень багато в різних компонентах, підтримувати дві теми стає складно.

Кращий варіант:

    .card {
        background-color: var(--color-surface);
        color: var(--color-text);
    }

Тепер достатньо змінити значення токенів, щоб адаптувати компоненти до іншої теми.

---

## 5. 🌓 Реалізація двох тем через CSS

Один із найпростіших способів — зберігати значення для світлої теми в `:root`, а для темної перевизначати їх через атрибут `data-theme`.

### 5.1. CSS-токени

    :root {
        color-scheme: light;

        --color-background: #f8fafc;
        --color-surface: #ffffff;
        --color-surface-raised: #f1f5f9;

        --color-text: #172033;
        --color-text-muted: #64748b;

        --color-border: #dbe2ea;
        --color-primary: #2563eb;
    }

    :root[data-theme="dark"] {
        color-scheme: dark;

        --color-background: #111827;
        --color-surface: #1f2937;
        --color-surface-raised: #273449;

        --color-text: #f1f5f9;
        --color-text-muted: #a8b3c4;

        --color-border: #374151;
        --color-primary: #93c5fd;
    }

### 5.2. Застосування токенів

    body {
        margin: 0;
        background-color: var(--color-background);
        color: var(--color-text);
        font-family: Arial, sans-serif;
    }

    .card {
        padding: 1.5rem;
        background-color: var(--color-surface);
        border: 1px solid var(--color-border);
        border-radius: 0.75rem;
    }

    .card__description {
        color: var(--color-text-muted);
    }

    .button {
        background-color: var(--color-primary);
        color: var(--color-background);
    }

Усі компоненти використовують однакові токени. Їм не потрібно знати, яка тема активна.

## 6. 🖱️ Перемикання теми через JavaScript

Користувач може перемикати тему за допомогою кнопки.

### 6.1. HTML

    <button
        id="theme-toggle"
        type="button"
        aria-pressed="false"
    >
        Увімкнути темну тему
    </button>

### 6.2. JavaScript

    const themeToggle = document.querySelector("#theme-toggle");

    function setTheme(theme) {
        document.documentElement.dataset.theme = theme;

        const isDark = theme === "dark";

        themeToggle.setAttribute("aria-pressed", String(isDark));
        themeToggle.textContent = isDark
            ? "Увімкнути світлу тему"
            : "Увімкнути темну тему";

        localStorage.setItem("theme", theme);
    }

    themeToggle.addEventListener("click", () => {
        const currentTheme =
            document.documentElement.dataset.theme;

        const nextTheme =
            currentTheme === "dark" ? "light" : "dark";

        setTheme(nextTheme);
    });

Цей приклад показує основний механізм перемикання, але для завершеної реалізації потрібно також правильно ініціалізувати тему під час завантаження сторінки.

### 6.3. Відновлення вибору користувача

    const savedTheme = localStorage.getItem("theme");

    if (savedTheme === "dark" || savedTheme === "light") {
        setTheme(savedTheme);
    } else {
        setTheme("light");
    }

У цьому спрощеному прикладі, якщо вибору немає, використовується світла тема. Нижче розглянемо, як натомість врахувати системні налаштування.

**Важливо:** якщо ініціалізація теми відбувається лише після завантаження сторінки, користувач може побачити коротке мерехтіння іншої теми. Для реального застосунку бажано застосувати початкову тему якомога раніше.

## 7. 🖥️ Системні налаштування `prefers-color-scheme`

Операційна система або браузер можуть повідомляти, яку тему віддає перевагу користувач.

Для цього існує медіазапит:

    @media (prefers-color-scheme: dark) {
        /* Стилі для темної теми */
    }

### 7.1. Автоматична темна тема

    :root {
        color-scheme: light;

        --color-background: #f8fafc;
        --color-text: #172033;
    }

    @media (prefers-color-scheme: dark) {
        :root:not([data-theme]) {
            color-scheme: dark;

            --color-background: #111827;
            --color-text: #f1f5f9;
        }
    }

У цьому варіанті системна тема використовується лише тоді, коли атрибут `data-theme` не встановлений.

Якщо користувач вибере тему вручну, його вибір матиме пріоритет над системним налаштуванням.

### 7.2. Важливі відмінності

- `prefers-color-scheme` — визначає системну перевагу користувача.
- `data-theme` — може визначати тему, встановлену самим застосунком.
- `color-scheme` — повідомляє браузеру, яку колірну схему використовує документ або елемент.

Властивість `color-scheme` допомагає браузеру адаптувати деякі вбудовані елементи, наприклад поля введення та системні елементи керування.

Вона не замінює власні стилі компонентів.

## 8. 💾 Збереження вибору теми

Щоб не змушувати користувача перемикати тему під час кожного відвідування, вибір можна зберігати.

### 8.1. `localStorage`

    localStorage.setItem("theme", "dark");

Зчитування:

    const savedTheme = localStorage.getItem("theme");

Видалення збереженого вибору:

    localStorage.removeItem("theme");

`localStorage` зберігає дані браузера між перезавантаженнями сторінки.

### 8.2. Три можливі стани

Зручно розглядати три варіанти налаштування:

1. `light` — користувач примусово вибрав світлу тему.
2. `dark` — користувач примусово вибрав темну тему.
3. `system` — застосунок використовує системні налаштування.

Приклад визначення теми:

    function getPreferredTheme() {
        const savedTheme = localStorage.getItem("theme");

        if (savedTheme === "light" || savedTheme === "dark") {
            return savedTheme;
        }

        return window.matchMedia(
            "(prefers-color-scheme: dark)"
        ).matches
            ? "dark"
            : "light";
    }

    document.documentElement.dataset.theme = getPreferredTheme();

У цьому прикладі відсутність збереженого значення означає системну тему.

Якщо потрібно підтримувати окремий режим `system` після явного вибору користувача, варто зберігати його як самостійне значення та обробляти окремо.

### 8.3. Коли змінюється системна тема

Якщо користувач залишив режим `system`, застосунок може реагувати на зміну системних налаштувань:

    const colorScheme = window.matchMedia(
        "(prefers-color-scheme: dark)"
    );

    colorScheme.addEventListener("change", () => {
        const savedTheme = localStorage.getItem("theme");

        if (!savedTheme || savedTheme === "system") {
            const theme = colorScheme.matches ? "dark" : "light";

            document.documentElement.dataset.theme = theme;
        }
    });

Якщо користувач примусово вибрав `light` або `dark`, системна зміна не повинна скасовувати його вибір.

## 9. 🌓 Перемикання теми: повніша реалізація

Нижче — компактний приклад, який об'єднує три режими: `light`, `dark` і `system`.

### 9.1. HTML

    <label for="theme-select">Тема оформлення</label>

    <select id="theme-select">
        <option value="system">Як у системі</option>
        <option value="light">Світла</option>
        <option value="dark">Темна</option>
    </select>

### 9.2. CSS

    :root {
        color-scheme: light;

        --color-background: #f8fafc;
        --color-surface: #ffffff;
        --color-text: #172033;
        --color-text-muted: #64748b;
        --color-border: #dbe2ea;
    }

    :root[data-theme="dark"] {
        color-scheme: dark;

        --color-background: #111827;
        --color-surface: #1f2937;
        --color-text: #f1f5f9;
        --color-text-muted: #a8b3c4;
        --color-border: #374151;
    }

    body {
        background-color: var(--color-background);
        color: var(--color-text);
        transition:
            background-color 180ms ease,
            color 180ms ease;
    }

    .card {
        background-color: var(--color-surface);
        border: 1px solid var(--color-border);
    }

    .muted {
        color: var(--color-text-muted);
    }

### 9.3. JavaScript

    const themeSelect = document.querySelector("#theme-select");
    const root = document.documentElement;

    const systemScheme = window.matchMedia(
        "(prefers-color-scheme: dark)"
    );

    function applyTheme(mode) {
        const resolvedTheme =
            mode === "system"
                ? systemScheme.matches
                    ? "dark"
                    : "light"
                : mode;

        root.dataset.theme = resolvedTheme;
    }

    function saveTheme(mode) {
        localStorage.setItem("theme", mode);
    }

    const savedTheme = localStorage.getItem("theme");

    const initialMode =
        savedTheme === "light" ||
        savedTheme === "dark" ||
        savedTheme === "system"
            ? savedTheme
            : "system";

    themeSelect.value = initialMode;
    applyTheme(initialMode);

    themeSelect.addEventListener("change", () => {
        const selectedMode = themeSelect.value;

        saveTheme(selectedMode);
        applyTheme(selectedMode);
    });

    systemScheme.addEventListener("change", () => {
        const selectedMode = localStorage.getItem("theme") ?? "system";

        if (selectedMode === "system") {
            applyTheme("system");
        }
    });

Це навчальний приклад. У виробничому застосунку початкове визначення теми бажано виконувати до першого відображення сторінки, а також перевіряти коректність роботи зі збереженими налаштуваннями.

## 10. 🔤 Контрастність і читабельність

Темна тема не повинна погіршувати доступність інтерфейсу.

Важливо перевіряти:
- основний текст;
- допоміжний текст;
- посилання;
- кнопки;
- межі інтерактивних елементів;
- фокус клавіатури;
- повідомлення про помилки.

### 10.1. Орієнтири WCAG

Для звичайного тексту рівень WCAG AA зазвичай вимагає коефіцієнт контрастності щонайменше `4.5:1`.

Для великого тексту — щонайменше `3:1`.

Великий текст за WCAG визначається, зокрема, як текст від 24 CSS px або жирний текст від приблизно 18.67 CSS px.

Для важливих нетекстових елементів інтерфейсу, наприклад меж полів і значків керування, також може застосовуватися вимога `3:1` щодо контрасту з прилеглими кольорами.

Не варто визначати контрастність лише на око. Використовуй інструменти перевірки контрасту.

### 10.2. Приклад кольорів

    :root[data-theme="dark"] {
        --color-background: #111827;
        --color-text: #f1f5f9;
        --color-text-muted: #a8b3c4;
    }

Ці кольори можуть бути хорошою відправною точкою, але відповідність WCAG потрібно перевіряти для конкретних пар кольорів.

### 10.3. Типові помилки

- Сірий текст майже зливається з фоном.
- Посилання відрізняються від звичайного тексту лише слабким відтінком.
- Контури полів введення майже невидимі.
- Повідомлення про помилки мають недостатню контрастність.
- Фокус клавіатури непомітний на темному фоні.

**Правило:** перевіряй не тільки основний текст, а й усі стани компонентів.

## 11. 🎯 Семантичні кольори в темній темі

Семантичні кольори повідомляють про стан або значення:

- успіх;
- помилка;
- попередження;
- інформація.

Їх не можна просто копіювати зі світлої теми без перевірки.

### 11.1. Приклад токенів

    :root {
        --color-success: #15803d;
        --color-warning: #a16207;
        --color-danger: #b91c1c;
        --color-info: #1d4ed8;
    }

    :root[data-theme="dark"] {
        --color-success: #4ade80;
        --color-warning: #facc15;
        --color-danger: #f87171;
        --color-info: #60a5fa;
    }

Це приклади значень, а не універсальна палітра. Контрастність потрібно перевіряти з урахуванням тексту, фону та призначення кольору.

### 11.2. Не покладайся тільки на колір

Повідомлення про помилку повинно містити зрозумілий текст, а не лише червоний фон.

    <p class="error-message" role="alert">
        Не вдалося зберегти зміни. Спробуйте ще раз.
    </p>

Колір допомагає передати значення, але не повинен бути єдиним способом його передавання.

## 12. 🔘 Кнопки та інтерактивні стани

У темній темі потрібно окремо перевіряти всі стани компонентів:

- звичайний стан;
- наведення (`hover`);
- фокус клавіатури (`focus-visible`);
- натискання (`active`);
- вимкнений стан (`disabled`).

Приклад:

    .button {
        background-color: var(--color-primary);
        color: var(--color-on-primary);
        border: 1px solid transparent;
        border-radius: 0.5rem;
        padding: 0.75rem 1rem;
        cursor: pointer;
    }

    .button:hover {
        filter: brightness(1.08);
    }

    .button:focus-visible {
        outline: 2px solid var(--color-focus);
        outline-offset: 3px;
    }

    .button:disabled {
        opacity: 0.55;
        cursor: not-allowed;
    }

Для цього прикладу потрібно визначити додаткові токени:

    :root {
        --color-primary: #2563eb;
        --color-on-primary: #ffffff;
        --color-focus: #1d4ed8;
    }

    :root[data-theme="dark"] {
        --color-primary: #93c5fd;
        --color-on-primary: #172033;
        --color-focus: #bfdbfe;
    }

Не використовуй `filter: brightness()` як універсальний спосіб створення всіх станів: він може зробити текст, іконки та інші елементи недостатньо контрастними. Для важливих компонентів краще визначати кольори станів окремо.

## 13. 📝 Форми та поля введення

Поля введення повинні залишатися читабельними в обох темах.

Перевіряй:
- фон поля;
- колір введеного тексту;
- колір placeholder;
- межі;
- фокус;
- повідомлення про помилки;
- випадаючі списки;
- прапорці та перемикачі.

Приклад:

    .input {
        width: 100%;
        padding: 0.75rem;
        color: var(--color-text);
        background-color: var(--color-surface);
        border: 1px solid var(--color-border);
        border-radius: 0.5rem;
    }

    .input::placeholder {
        color: var(--color-text-muted);
    }

    .input:focus-visible {
        outline: 2px solid var(--color-focus);
        outline-offset: 2px;
    }

Не покладайся на стандартні кольори браузера. Для важливих елементів визначай стилі явно, а властивість `color-scheme` використовуй як додаткову підказку браузеру.

## 14. 🌫️ Тіні та глибина в темному інтерфейсі

У світлій темі тіні часто добре помітні на білому фоні. У темній темі чорна тінь на майже чорному фоні може бути практично невидимою.

Для створення глибини використовують:
- різні рівні яскравості поверхонь;
- тонкі межі;
- м'які тіні;
- прозорі накладки;
- зміну кольору поверхні при наведенні.

Приклад:

    .card {
        background-color: var(--color-surface);
        border: 1px solid var(--color-border);
        box-shadow: var(--shadow-card);
    }

    :root {
        --shadow-card: 0 4px 12px rgb(15 23 42 / 8%);
    }

    :root[data-theme="dark"] {
        --shadow-card: 0 8px 24px rgb(0 0 0 / 25%);
    }

Значення тіней потрібно підбирати відповідно до поверхонь і загального дизайну. Іноді в темній темі межа або світліша поверхня краще передає структуру, ніж сильна тінь.

## 15. 🖼️ Зображення, іконки та логотипи

Не всі графічні елементи однаково добре працюють у світлій і темній темах.

### 15.1. Іконки

Для монохромних іконок часто достатньо використовувати семантичний колір:

    .icon {
        color: var(--color-text);
    }

Якщо SVG використовує `currentColor`, його колір можна змінювати через CSS.

### 15.2. Логотипи

Для деяких логотипів можуть знадобитися дві версії:
- для світлого фону;
- для темного фону.

Не змінюй колір брендового логотипа без урахування вимог бренду.

### 15.3. Фотографії та ілюстрації

Фотографії зазвичай не потрібно інвертувати. Але іноді варто адаптувати:
- фон контейнера;
- рамку зображення;
- підпис;
- накладення тексту;
- тінь навколо зображення.

Якщо текст розташований поверх фотографії, його контрастність перевіряють окремо.

## 16. ♿ Доступність і комфорт користувача

Темна тема може бути зручною для багатьох користувачів, але не є автоматично кращою для всіх.

Звертай увагу на такі принципи:

- Не знижуй контрастність заради естетики.
- Не використовуй надмірно яскравий текст на дуже темному фоні без потреби.
- Зберігай видимий фокус клавіатури.
- Не передавай стан лише кольором.
- Перевіряй інтерфейс при збільшенні масштабу.
- Перевіряй читабельність довгих текстів.
- Враховуй налаштування зменшення анімації.

Якщо тема перемикається з анімацією, можна врахувати системне налаштування:

    @media (prefers-reduced-motion: reduce) {
        *,
        *::before,
        *::after {
            scroll-behavior: auto;
            animation-duration: 0.01ms;
            animation-iteration-count: 1;
            transition-duration: 0.01ms;
        }
    }

У реальному проєкті краще обмежувати вимкнення анімацій тими властивостями, які справді потрібно змінити, щоб не втратити необхідні переходи чи функціональність.

## 17. ⚡ Запобігання мерехтінню теми під час завантаження

Якщо застосунок спочатку показує світлу тему, а потім JavaScript перемикає її на темну, користувач може побачити небажане мерехтіння.

Щоб зменшити цей ефект:
1. Визначай збережену або системну тему якомога раніше.
2. Застосовуй тему до першого відображення основного вмісту.
3. Не запускай ініціалізацію лише після завантаження всього документа.
4. Уникай непотрібних переходів під час початкового встановлення теми.

Для простого HTML-проєкту початковий скрипт можна розмістити в `<head>` до відображення сторінки:

    <script>
        (() => {
            const savedTheme = localStorage.getItem("theme");
            const systemIsDark = window.matchMedia(
                "(prefers-color-scheme: dark)"
            ).matches;

            const theme =
                savedTheme === "light" || savedTheme === "dark"
                    ? savedTheme
                    : systemIsDark
                        ? "dark"
                        : "light";

            document.documentElement.dataset.theme = theme;
        })();
    </script>

Цей приклад призначений для звичайної клієнтської сторінки. У середовищах із серверним рендерингом потрібно також враховувати узгодженість початкової теми на сервері та клієнті.

## 19. ❌ Типові помилки

### Помилка 1. Просто зробити фон чорним

    body {
        background-color: #000000;
    }

Це не створює повноцінної темної теми. Потрібно адаптувати поверхні, текст, межі та стани компонентів.

### Помилка 2. Залишити кольори світлої теми

Темний фон зі старими кольорами тексту або меж може призвести до недостатньої контрастності.

### Помилка 3. Використовувати чистий білий для всього

    color: #ffffff;

Білий текст може бути доречним, але не обов'язково повинен використовуватися для кожного елемента. Другорядний текст потребує окремого токена.

### Помилка 4. Змінювати кольори без токенів

Якщо кольори визначені окремо в кожному компоненті, підтримувати дві теми буде складніше.

### Помилка 5. Ігнорувати системні налаштування

Користувач може очікувати, що застосунок автоматично підлаштується під системну тему.

### Помилка 6. Не зберігати вибір користувача

Якщо після кожного перезавантаження тема скидається, інтерфейс стає менш зручним.

### Помилка 7. Не перевіряти інтерактивні стани

Кнопка може виглядати добре у звичайному стані, але втрачати видимість при наведенні або фокусі.

### Помилка 8. Вважати, що темна тема автоматично доступна

Темний фон не гарантує достатнього контрасту, читабельності або доступності.

### Помилка 9. Використовувати тільки колір для позначення стану

Помилки, попередження та успіх повинні бути зрозумілими без залежності лише від кольору.

### Помилка 10. Не враховувати початкове завантаження

Пізнє перемикання теми може спричиняти помітне мерехтіння.

### JavaScript

    const themeToggle = document.querySelector("#theme-toggle");
    const root = document.documentElement;

    const systemScheme = window.matchMedia(
        "(prefers-color-scheme: dark)"
    );

    function applyTheme(theme) {
        root.dataset.theme = theme;

        const isDark = theme === "dark";

        themeToggle.setAttribute("aria-pressed", String(isDark));
        themeToggle.textContent = isDark
            ? "Світла тема"
            : "Темна тема";
    }

    function getInitialTheme() {
        const savedTheme = localStorage.getItem("theme");

        if (savedTheme === "light" || savedTheme === "dark") {
            return savedTheme;
        }

        return systemScheme.matches ? "dark" : "light";
    }

    applyTheme(getInitialTheme());

    themeToggle.addEventListener("click", () => {
        const currentTheme = root.dataset.theme;
        const nextTheme =
            currentTheme === "dark" ? "light" : "dark";

        localStorage.setItem("theme", nextTheme);
        applyTheme(nextTheme);
    });

5. Перевірити контрастність тексту та кнопок.
6. Додати плавний перехід між темами.
7. Переконатися, що початкова тема встановлюється без помітного мерехтіння.

| `prefers-color-scheme` | Визначає системну перевагу користувача |
| `color-scheme` | Повідомляє браузеру про використовувану колірну схему |
| `localStorage` | Зберігає вибір теми між сеансами |
| Contrast Ratio | Показник контрастності двох кольорів |
| WCAG | Рекомендації з доступності вебконтенту |
| `focus-visible` | Стиль видимого фокусу, зокрема під час клавіатурної навігації |

### Базовий шаблон

    :root {
        color-scheme: light;

        --color-background: #f8fafc;
        --color-surface: #ffffff;
        --color-text: #172033;
        --color-text-muted: #64748b;
        --color-border: #dbe2ea;
    }

    :root[data-theme="dark"] {
        color-scheme: dark;

        --color-background: #111827;
        --color-surface: #1f2937;
        --color-text: #f1f5f9;
        --color-text-muted: #a8b3c4;
        --color-border: #374151;
    }

    body {
        background-color: var(--color-background);
        color: var(--color-text);
    }

### Три головні правила

1. **Використовуй семантичні токени** замість жорстко заданих кольорів у кожному компоненті.
2. **Перевіряй контрастність і стани компонентів** в обох темах.
3. **Підтримуй вибір користувача та системні налаштування** без небажаного мерехтіння.

## 🎯 Головне

Dark Mode — це не просто темний фон і світлий текст, а повноцінна система оформлення інтерфейсу.

Якісна темна тема:
- зберігає візуальну ієрархію;
- використовує продуману палітру поверхонь;
- має достатню контрастність;
- підтримує семантичні кольори;
- адаптує форми, кнопки та інші компоненти;
- враховує системні налаштування;
- зберігає вибір користувача;
- проходить перевірку доступності.

**Запам'ятай:** спочатку проєктуй систему кольорів, потім реалізовуй перемикання теми. Саме токени роблять Dark Mode масштабованим і зручним для підтримки.
