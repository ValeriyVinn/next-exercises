# 🎨 Primary, Secondary та Accent Colors — Основний, додатковий і акцентний кольори

## 📌 Що це?

**Primary, Secondary та Accent Colors** — це ролі кольорів у дизайн-системі, які допомагають організувати візуальну ієрархію інтерфейсу.

- **Primary color (основний колір)** — головний колір бренду або інтерфейсу, який часто використовується для ключових дій та активних елементів.
- **Secondary color (додатковий колір)** — колір, який доповнює основний і допомагає розширити палітру, розділити елементи або створити додаткові акценти.
- **Accent color (акцентний колір)** — колір, який привертає увагу до важливих деталей, дій або станів.

Ці назви описують **роль кольору в інтерфейсі**, а не конкретний відтінок.

Наприклад, у синій палітрі основним може бути синій, додатковим — фіолетовий, а акцентним — помаранчевий. Але в іншому проєкті основним може бути зелений, а акцентним — синій або жовтий.

Немає універсального правила, за яким primary завжди повинен бути синім, secondary — фіолетовим, а accent — помаранчевим.

### Де використовується?

- Під час створення палітри UI.
- Для оформлення кнопок та посилань.
- Для виділення активних пунктів навігації.
- Для побудови візуальної ієрархії сторінки.
- Для створення карток, банерів та інформаційних блоків.
- Для оформлення інтерактивних станів.
- Для створення дизайн-систем.
- Для підтримки світлої й темної тем.
- Для створення впізнаваного стилю бренду.
- Для розподілу кольорів між компонентами великого застосунку.

## 🧠 Ключові поняття

✔ **Primary color** — основний колір, який має провідну роль у палітрі.

✔ **Secondary color** — додатковий колір, який підтримує основний і розширює можливості дизайну.

✔ **Accent color** — колір для вибіркового привернення уваги до важливих елементів.

✔ **Brand color** — колір бренду, який допомагає формувати його впізнаваність. Він може збігатися з primary color, але ці поняття не завжди тотожні.

✔ **Color palette** — набір кольорів, що використовуються в інтерфейсі.

✔ **Color role** — функція, яку колір виконує в дизайн-системі.

✔ **Visual hierarchy** — візуальна ієрархія, яка показує, які елементи важливіші.

✔ **CTA (Call to Action)** — заклик до дії, наприклад «Зареєструватися», «Купити» або «Зберегти».

✔ **Neutral colors** — нейтральні кольори для фонів, тексту, меж і поверхонь.

✔ **Semantic colors** — кольори, що передають значення: успіх, помилка, попередження або інформація.

✔ **Color scale** — шкала відтінків одного кольору від світлих до темних.

✔ **Design tokens** — іменовані значення дизайну, наприклад кольори, відступи, радіуси та типографіка.

✔ **Contrast** — різниця між кольорами, важлива для читабельності та доступності.

✔ **Light theme** — світла тема інтерфейсу.

✔ **Dark theme** — темна тема інтерфейсу.

✔ **60-30-10 rule** — дизайнерська евристика для розподілу кольорів, а не обов'язковий стандарт.

---

## 🎯 Що потрібно пам'ятати

- Primary, secondary та accent — це ролі кольорів, а не фіксовані кольорові значення.
- Primary часто використовують для головних інтерактивних елементів.
- Secondary допомагає розширити палітру та підтримує основний колір.
- Accent використовують вибірково, щоб привернути увагу.
- Primary та brand color можуть збігатися, але не обов'язково.
- Accent не завжди повинен бути контрастним за тоном до primary: важливіше, щоб він виконував свою функцію.
- Secondary не обов'язково має бути менш насиченим за primary.
- Один колір може виконувати різні ролі в різних дизайн-системах.
- Не кожен елемент інтерфейсу повинен бути кольоровим.
- Нейтральні кольори часто займають значну частину інтерфейсу.
- Семантичні кольори не варто бездумно використовувати як декоративні акценти.
- Колір не повинен бути єдиним способом передавання важливої інформації.
- Контрастність потрібно перевіряти для кожної важливої комбінації тексту й фону.
- Для світлої та темної тем можуть знадобитися різні значення одного кольорового токена.
- Правильна кольорова ієрархія допомагає користувачу зрозуміти, на що звернути увагу.
- Правило 60-30-10 можна використовувати як початкову підказку, але не як жорстке обмеження.

# 1. Primary Color — основний колір

## 1.1. Що таке Primary Color?

**Primary color** — це основний колір інтерфейсу, який відіграє провідну роль у його візуальному стилі.

Він часто пов'язаний із брендом і використовується для найважливіших інтерактивних елементів.

Наприклад:

- головна кнопка;
- активне посилання;
- вибраний пункт меню;
- активна вкладка;
- індикатор поточного розділу;
- важливі інтерактивні елементи.

Уявімо освітню платформу, де основний колір — синій.

    :root {
        --color-primary: hsl(220 80% 50%);
        --color-primary-hover: hsl(220 80% 43%);
        --color-primary-active: hsl(220 80% 36%);
    }

    .button-primary {
        background-color: var(--color-primary);
        color: white;
    }

У цьому прикладі primary color задає базовий стиль основної кнопки.

## 1.2. Як вибрати Primary Color?

Вибір залежить від:

- характеру продукту;
- цільової аудиторії;
- асоціацій бренду;
- емоційного враження;
- читабельності;
- доступності;
- середовища використання;
- інших кольорів палітри.

Наприклад:

| Колір | Можливі асоціації |
|---|---|
| Синій | Довіра, стабільність, спокій |
| Зелений | Природа, розвиток, добробут |
| Помаранчевий | Енергія, активність, дружність |
| Фіолетовий | Творчість, уява, індивідуальність |
| Червоний | Енергія, терміновість, увага |
| Бірюзовий | Свіжість, легкість, сучасність |

Це лише поширені асоціації, а не універсальні психологічні закони. Значення кольору залежить від культури, контексту та способу використання.

## 1.3. Primary Color і головна дія

Primary color часто використовують для основного CTA.

    .button-primary {
        background-color: hsl(220 80% 50%);
        color: white;
        border: none;
        border-radius: 0.5rem;
        padding: 0.75rem 1.25rem;
    }

    .button-primary:hover {
        background-color: hsl(220 80% 43%);
    }

Наприклад, на сторінці реєстрації основною кнопкою може бути «Створити обліковий запис».

Інші кнопки, як-от «Скасувати» або «Повернутися», не обов'язково повинні мати таку саму візуальну вагу.

Це допомагає користувачу зрозуміти, яка дія є основною.

## 1.4. Чи повинен Primary бути найяскравішим?

Не обов'язково.

Primary color має бути впізнаваним і виконувати свою функцію. Він не завжди повинен мати максимальну насиченість або бути найяскравішим кольором на сторінці.

Наприклад, стриманий зелений може бути основним кольором медичного сервісу, а яскравий помаранчевий — використовуватися для окремих важливих акцентів.

Головне — підтримувати логічну візуальну ієрархію.

# 2. Secondary Color — додатковий колір

## 2.1. Що таке Secondary Color?

**Secondary color** — це колір, який доповнює основний і допомагає урізноманітнити візуальну мову інтерфейсу.

Він може використовуватися для:

- другорядних кнопок;
- додаткових посилань;
- окремих блоків;
- декоративних елементів;
- категорій контенту;
- ілюстрацій;
- другорядних інтерактивних станів.

Наприклад, якщо primary — синій, secondary може бути фіолетовим або бірюзовим.

    :root {
        --color-primary: hsl(220 80% 50%);
        --color-secondary: hsl(270 55% 50%);
    }

    .primary-section {
        background-color: var(--color-primary);
        color: white;
    }

    .secondary-section {
        background-color: var(--color-secondary);
        color: white;
    }

Це умовний приклад. Обидва кольори потрібно перевірити на контраст і доречність для конкретних компонентів.

## 2.2. Навіщо потрібен Secondary Color?

Якщо використовувати тільки один основний колір, інтерфейс може виглядати одноманітно.

Secondary color допомагає:

- створити різноманітність;
- розділити типи контенту;
- підтримати бренд;
- оформити другорядні дії;
- додати візуальну глибину;
- виділити окремі групи елементів.

Проте додатковий колір не потрібен лише заради кількості.

Якщо інтерфейс працює добре з одним основним кольором і нейтральною палітрою, можна не додавати другий виразний колір.

## 2.3. Як вибрати Secondary Color?

Можна почати з кількох підходів:

1. Вибрати колір поруч із primary на колірному колі.
2. Вибрати комплементарний або близький до нього колір.
3. Використати споріднений відтінок основного кольору.
4. Вибрати нейтральний колір як підтримувальний.
5. Побудувати додатковий колір на основі стилю бренду.

Наприклад:

    :root {
        --color-primary: hsl(220 80% 50%);
        --color-secondary: hsl(190 65% 40%);
    }

Це синьо-бірюзова комбінація.

Інший варіант:

    :root {
        --color-primary: hsl(220 80% 50%);
        --color-secondary: hsl(280 55% 48%);
    }

Це синьо-фіолетова комбінація.

Жоден варіант не є автоматично кращим. Оцінюй кольори разом, а не окремо.

## 2.4. Secondary не означає «неважливий»

Secondary описує роль у палітрі, але не обов'язково значущість інформації.

Наприклад, у застосунку для навчання додатковий колір може позначати важливу категорію курсів.

Тому не потрібно робити кожен secondary-елемент блідим або малоконтрастним.

# 3. Accent Color — акцентний колір

## 3.1. Що таке Accent Color?

**Accent color** — це колір, який використовують вибірково, щоб привернути увагу до певного елемента.

Його завдання — створити помітний акцент на тлі інших кольорів.

Accent може використовуватися для:

- важливої кнопки;
- нового або рекомендованого елемента;
- спеціальної пропозиції;
- виділеного слова;
- маркера;
- активної іконки;
- окремого графічного елемента.

Наприклад, якщо основна палітра синя й сіра, помаранчевий може виступати акцентом.

    :root {
        --color-primary: hsl(220 80% 50%);
        --color-secondary: hsl(190 60% 40%);
        --color-accent: hsl(32 95% 50%);
    }

    .badge-featured {
        background-color: var(--color-accent);
        color: hsl(220 20% 12%);
    }

Тут помаранчевий використовується для спеціального маркера.

Перед використанням перевір контраст тексту на фоні акценту.

## 3.2. Чому Accent використовують вибірково?

Якщо акцентним кольором оформлено майже всі елементи, він перестає виконувати роль акценту.

Уявімо сторінку, де:

- усі кнопки помаранчеві;
- усі заголовки помаранчеві;
- усі іконки помаранчеві;
- усі межі помаранчеві;
- усі картки мають помаранчевий фон.

У такому випадку погляд користувача не отримує чітких підказок про важливість елементів.

Акцент стає звичайним кольором оформлення.

**Акцент працює завдяки контрасту з рештою інтерфейсу та обмеженому використанню.**

## 3.3. Чи повинен Accent бути комплементарним до Primary?

Ні.

Комплементарний колір може створювати виразний контраст, але акцентом також може бути:

- світліший варіант primary;
- темніший варіант primary;
- споріднений колір;
- нейтральний колір;
- окремий брендований колір.

Наприклад:

    :root {
        --color-primary: hsl(220 80% 50%);
        --color-accent: hsl(220 90% 72%);
    }

У цьому випадку акцент і основний колір мають близький Hue, але відрізняються насиченістю та світлотою.

Це може працювати для виділення елементів без введення нового колірного напряму.

## 3.4. Accent і CTA — не одне й те саме

Accent color — це роль кольору.

CTA — це призначення елемента, який закликає до дії.

Головна CTA-кнопка може використовувати primary color, а не accent color.

Наприклад:

- Primary — основна кнопка «Зберегти».
- Accent — маркер «Рекомендовано».
- Secondary — кнопка «Докладніше».

В іншому проєкті акцентний колір може використовуватися саме для головної CTA-кнопки.

Важливо не плутати колірну роль із функцією компонента.

# 4. Primary, Secondary та Accent — порівняння

| Характеристика | Primary | Secondary | Accent |
|---|---|---|---|
| Основна роль | Провідний колір інтерфейсу | Доповнення основного | Привернення уваги |
| Типове застосування | Головні кнопки, активні елементи | Другорядні компоненти, категорії | Особливі акценти, маркери |
| Частота використання | Регулярна | За потреби | Вибіркова |
| Обов'язковість | Необов'язковий як окремий токен, але часто центральний | Не завжди потрібен | Не завжди потрібен |
| Зв'язок із брендом | Часто тісний | Може підтримувати бренд | Може підсилювати характер бренду |
| Кількість | Зазвичай одна основна роль | Може бути кілька додаткових ролей | Може бути кілька акцентних ролей |

Це орієнтовна схема. Реальна дизайн-система може мати кілька primary-подібних кольорових ролей для різних контекстів, але їхні правила потрібно чітко визначити.

# 5. Нейтральні кольори — основа палітри

## 5.1. Чому нейтральні кольори важливі?

У багатьох інтерфейсах більшу частину простору займають не primary, secondary чи accent, а нейтральні кольори.

Вони використовуються для:

- фону сторінки;
- карток;
- панелей;
- полів введення;
- основного тексту;
- другорядного тексту;
- меж;
- розділювачів.

Приклад:

    :root {
        --color-neutral-50: hsl(220 20% 98%);
        --color-neutral-100: hsl(220 15% 95%);
        --color-neutral-200: hsl(220 12% 88%);
        --color-neutral-300: hsl(220 10% 78%);
        --color-neutral-500: hsl(220 8% 50%);
        --color-neutral-700: hsl(220 12% 30%);
        --color-neutral-900: hsl(220 18% 12%);
    }

Це приклад шкали нейтральних кольорів із легким холодним відтінком.

## 5.2. Чому не варто робити все кольоровим?

Нейтральні поверхні дозволяють:

- зменшити візуальний шум;
- підкреслити основні дії;
- зробити текст читабельнішим;
- розділити контент;
- створити відчуття простору;
- зосередити увагу на важливому.

Якщо кожен елемент має сильний колір, ієрархія стає нечіткою.

## 5.3. Приклад розподілу кольорових ролей

    :root {
        --page-bg: hsl(220 20% 97%);
        --surface: hsl(0 0% 100%);

        --text-primary: hsl(220 20% 12%);
        --text-secondary: hsl(220 10% 40%);

        --color-primary: hsl(220 80% 50%);
        --color-secondary: hsl(190 60% 40%);
        --color-accent: hsl(32 95% 50%);

        --border: hsl(220 12% 85%);
    }

У такій системі:

- нейтральні кольори формують основу;
- primary позначає головні інтерактивні елементи;
- secondary розширює палітру;
- accent використовується для вибіркового виділення.

# 6. Семантичні кольори — Success, Warning, Danger та Info

Семантичні кольори передають значення, а не просто створюють візуальний стиль.

Основні ролі:

- **Success** — успішна дія або позитивний результат.
- **Warning** — попередження про ризик або ситуацію, що потребує уваги.
- **Danger / Error** — помилка або небезпечна дія.
- **Info** — інформаційне повідомлення.

Приклад:

    :root {
        --color-success: hsl(145 60% 35%);
        --color-warning: hsl(38 90% 45%);
        --color-danger: hsl(0 70% 45%);
        --color-info: hsl(210 80% 45%);
    }

    .message-success {
        color: var(--color-success);
    }

    .message-warning {
        color: var(--color-warning);
    }

    .message-error {
        color: var(--color-danger);
    }

    .message-info {
        color: var(--color-info);
    }

Ці кольори не обов'язково є частиною primary-secondary-accent схеми.

Наприклад, якщо primary — зелений, це не означає, що зелений повинен одночасно позначати всі повідомлення про успіх і всі основні дії без окремого визначення ролей.

## 6.1. Не плутай Accent і Danger

Акцентний колір може бути яскравим і привертати увагу, але це не робить його кольором помилки.

Наприклад, помаранчевий може бути акцентом бренду, але в конкретній системі помаранчевий також може позначати попередження.

Щоб уникнути плутанини:

- визнач призначення кольорових токенів;
- не використовуй один колір для несумісних значень без чіткої системи;
- підкріплюй семантичні повідомлення текстом та іконками;
- перевіряй кольори в реальних компонентах.

---

# 7. Правило 60-30-10

**Правило 60-30-10** — це популярна дизайнерська евристика для початкового розподілу кольорів.

Зазвичай її пояснюють так:

- **60%** — домінантний колір або основа;
- **30%** — додатковий колір;
- **10%** — акцентний колір.

Наприклад, для вебсторінки:

- 60% — світлі нейтральні поверхні;
- 30% — додаткові поверхні або великі блоки;
- 10% — primary чи accent.

Але тут важливо не сприймати ці назви надто буквально.

У реальному UI 60% площі може займати нейтральний фон, а primary color — використовуватися лише на кількох кнопках.

## 7.1. Це не обов'язковий стандарт

Правило 60-30-10:

- не є вимогою доступності;
- не визначає правильний контраст;
- не встановлює обов'язкові пропорції для кожного UI;
- не означає, що потрібно буквально вимірювати площу кожного кольору;
- не гарантує гармонійного дизайну.

Його можна використовувати як початкову підказку, коли палітра ще не має зрозумілого балансу.

## 7.2. Приклад для освітнього сайту

Уявімо сайт навчальних матеріалів.

- Основна площа — світлий нейтральний фон.
- Додаткові блоки — світло-блакитні поверхні.
- Основні кнопки — сині.
- Маркери «Нове» — помаранчеві.

Це не обов'язково точне співвідношення 60-30-10. Це приклад того, як нейтральні кольори, основний колір і акцент можуть працювати разом.

---

# 8. Вибір кольорових ролей через колірне коло

Колірне коло допомагає підібрати кольори, які можуть гармоніювати між собою.

Проте геометричний зв'язок між Hue не гарантує, що готова палітра добре працюватиме в UI.

Потрібно також враховувати світлоту, насиченість, площу кольору та контраст.

## 8.1. Монохромна палітра

Використовує різні варіанти одного колірного тону.

    :root {
        --color-primary: hsl(220 80% 50%);
        --color-primary-light: hsl(220 70% 85%);
        --color-primary-dark: hsl(220 80% 30%);
    }

Переваги:

- цілісний вигляд;
- простіше підтримувати палітру;
- зручно створювати шкали;
- менше ризику випадкового перевантаження кольорами.

Недоліки:

- може бракувати виразних відмінностей між категоріями;
- акцент іноді важко виділити без зміни світлоти або насиченості.

## 8.2. Аналогова палітра

Використовує сусідні кольори на колірному колі.

Наприклад, синій, блакитний і синьо-фіолетовий.

    :root {
        --color-primary: hsl(220 75% 48%);
        --color-secondary: hsl(195 65% 42%);
        --color-accent: hsl(255 60% 55%);
    }

Переваги:

- відносно цілісний вигляд;
- плавний перехід між кольорами;
- зручно для спокійних інтерфейсів.

Недоліки:

- кольори можуть бути недостатньо відмінними;
- потрібна увага до візуальної ієрархії.

## 8.3. Комплементарна палітра

Використовує кольори, розташовані приблизно навпроти один одного на колірному колі.

Наприклад, синій і помаранчевий.

    :root {
        --color-primary: hsl(220 80% 50%);
        --color-accent: hsl(35 90% 50%);
    }

Переваги:

- виразний контраст між колірними напрямами;
- зручно виділяти окремі елементи;
- допомагає створити яскравий візуальний стиль.

Недоліки:

- надто насичені кольори можуть конкурувати;
- великі площі обох кольорів можуть створювати візуальне напруження.

## 8.4. Тріадна палітра

Використовує три кольори, розташовані приблизно на однаковій відстані на колірному колі.

Така схема може бути яскравою та різноманітною, але в інтерфейсі потрібно визначити чіткі ролі кольорів.

Не обов'язково використовувати всі три кольори однаково часто.

## 8.5. Що обрати?

- Для простого бізнес-інтерфейсу можна почати з монохромної палітри.
- Для спокійного бренду можна спробувати аналогову схему.
- Для виразного CTA можна використати комплементарний акцент.
- Для освітнього або творчого продукту можна розглянути тріадну схему.

Це стартові напрямки, а не правила, які потрібно виконувати без винятків.

# 9. Як побудувати палітру Primary, Secondary та Accent

## Крок 1. Визнач призначення продукту

Запитай себе:

- Що робить застосунок?
- Хто ним користуватиметься?
- Яке враження має створювати інтерфейс?
- Які дії є найважливішими?
- Чи є кольори, пов'язані з брендом?

Наприклад, для освітнього застосунку важливі читабельність, спокійна візуальна система та зрозумілі інтерактивні елементи.

## Крок 2. Вибери Primary Color

Почни з одного базового кольору.

    :root {
        --color-primary: hsl(220 80% 50%);
    }

Не потрібно відразу створювати багато відтінків. Спочатку перевір базовий колір на кнопці, посиланні та активному елементі.

## Крок 3. Визнач, чи потрібен Secondary Color

Запитай себе:

- Чи є окремі категорії контенту?
- Чи потрібно візуально розділити групи елементів?
- Чи достатньо primary та нейтральних кольорів?
- Чи допоможе другий колір, чи лише ускладнить інтерфейс?

Якщо вторинний колір потрібен, вибери його відповідно до стилю бренду та завдань інтерфейсу.

## Крок 4. Визнач роль Accent Color

Виріши, що саме повинен виділяти акцент:

- новий контент;
- спеціальні пропозиції;
- рекомендовані елементи;
- важливі маркери;
- окремі дії.

Не варто додавати accent лише тому, що палітра здається недостатньо кольоровою.

## Крок 5. Створи нейтральну шкалу

    :root {
        --neutral-50: hsl(220 20% 98%);
        --neutral-100: hsl(220 15% 95%);
        --neutral-200: hsl(220 12% 88%);
        --neutral-500: hsl(220 8% 50%);
        --neutral-700: hsl(220 12% 30%);
        --neutral-900: hsl(220 18% 12%);
    }

Нейтральні кольори потрібні для основного фону, тексту, карток та меж.

## Крок 6. Створи варіанти кольорів

    :root {
        --primary-100: hsl(220 70% 92%);
        --primary-300: hsl(220 70% 75%);
        --primary-500: hsl(220 80% 50%);
        --primary-700: hsl(220 80% 35%);
        --primary-900: hsl(220 70% 20%);
    }

Це приклад шкали. Відтінки потрібно підлаштувати до реальних компонентів і вимог контрастності.

## Крок 7. Признач кольорам ролі

    :root {
        --color-primary: var(--primary-500);
        --color-primary-hover: var(--primary-700);

        --color-page-bg: var(--neutral-50);
        --color-surface: white;
        --color-text: var(--neutral-900);
        --color-text-muted: var(--neutral-700);
        --color-border: var(--neutral-200);
    }

Так ти відокремлюєш палітру від її застосування.

## Крок 8. Перевір доступність

Перевір:

- текст на кольорових кнопках;
- основний текст на фоні;
- другорядний текст;
- межі полів;
- фокус клавіатури;
- стани помилок;
- світлу й темну теми.

## Крок 9. Перевір візуальну ієрархію

Подивись на сторінку й запитай:

- Чи зрозуміло, яка дія основна?
- Чи не конкурують primary та accent?
- Чи достатньо нейтрального простору?
- Чи не надто багато кольорових елементів?
- Чи зрозуміло, які елементи належать до однієї категорії?

## Крок 10. Задокументуй систему

Запиши, для чого призначений кожен токен, щоб у майбутньому не довелося вгадувати.

Наприклад:

    --color-primary:
        Основний колір головних інтерактивних елементів.

    --color-secondary:
        Додатковий колір окремих компонентів і категорій.

    --color-accent:
        Вибіркові візуальні акценти.

    --color-success:
        Позитивний результат або успішна дія.

# 10. Організація кольорів у дизайн-системі

У невеликому проєкті можна використовувати прості CSS-змінні.

У великій дизайн-системі корисно відокремлювати **базові кольори** від **семантичних токенів**.

## 10.1. Базові кольори

Базові токени описують самі значення палітри.

    :root {
        --blue-500: hsl(220 80% 50%);
        --blue-700: hsl(220 80% 35%);

        --orange-500: hsl(32 95% 50%);

        --gray-50: hsl(220 20% 98%);
        --gray-200: hsl(220 12% 88%);
        --gray-900: hsl(220 18% 12%);
    }

Вони не обов'язково описують, де саме колір використовується.

## 10.2. Семантичні токени

Семантичні токени описують призначення кольору.

    :root {
        --color-primary: var(--blue-500);
        --color-primary-hover: var(--blue-700);

        --color-accent: var(--orange-500);

        --color-page-bg: var(--gray-50);
        --color-border: var(--gray-200);
        --color-text: var(--gray-900);
    }

Тепер компонентам не потрібно знати, що primary — це конкретний синій відтінок.

Вони використовують роль:

    .button-primary {
        background-color: var(--color-primary);
    }

Якщо палітра зміниться, можна оновити токен, не переписуючи кожен компонент.

## 10.3. Чому це краще за випадкові HEX-коди?

Порівняй два підходи.

Небажаний підхід:

    .button {
        background-color: #2563eb;
    }

    .link {
        color: #2563eb;
    }

    .active-tab {
        border-color: #2563eb;
    }

У цьому прикладі значення повторюється в кількох місцях.

Краще:

    :root {
        --color-primary: #2563eb;
    }

    .button {
        background-color: var(--color-primary);
    }

    .link {
        color: var(--color-primary);
    }

    .active-tab {
        border-color: var(--color-primary);
    }

Тепер основний колір можна змінити централізовано.

Для великої системи ще краще використовувати окремі токени для різних ролей, якщо їхні кольори мають змінюватися незалежно.

# 11. Приклад палітри для освітнього застосунку

Уявімо вебзастосунок для навчання, у якому є:

- список курсів;
- картки уроків;
- кнопки;
- прогрес навчання;
- повідомлення про результати;
- навігація.

Можна почати з такої палітри:

    :root {
        /* Primary */
        --color-primary: hsl(220 80% 45%);
        --color-primary-hover: hsl(220 80% 38%);

        /* Secondary */
        --color-secondary: hsl(190 60% 38%);

        /* Accent */
        --color-accent: hsl(32 95% 50%);

        /* Neutrals */
        --color-page-bg: hsl(220 20% 97%);
        --color-surface: hsl(0 0% 100%);
        --color-text: hsl(220 20% 12%);
        --color-text-muted: hsl(220 10% 40%);
        --color-border: hsl(220 12% 85%);

        /* Semantic */
        --color-success: hsl(145 60% 35%);
        --color-warning: hsl(38 90% 40%);
        --color-danger: hsl(0 70% 45%);
        --color-info: hsl(210 80% 45%);
    }

## Приклад застосування

    body {
        background-color: var(--color-page-bg);
        color: var(--color-text);
    }

    .course-card {
        padding: 1.5rem;
        background-color: var(--color-surface);
        border: 1px solid var(--color-border);
        border-radius: 1rem;
    }

    .button-primary {
        background-color: var(--color-primary);
        color: white;
        border: none;
        border-radius: 0.5rem;
        padding: 0.75rem 1.25rem;
    }

    .button-primary:hover {
        background-color: var(--color-primary-hover);
    }

    .course-tag {
        background-color: hsl(190 60% 92%);
        color: hsl(190 70% 25%);
        border-radius: 999px;
        padding: 0.25rem 0.75rem;
    }

    .course-tag--featured {
        background-color: hsl(32 95% 90%);
        color: hsl(25 85% 25%);
    }

У цьому прикладі:

- primary використовується для основної дії;
- secondary допомагає позначати категорії;
- accent виділяє особливі елементи;
- нейтральні кольори формують основний простір;
- семантичні кольори зарезервовані для повідомлень про стани.

Це стартова палітра для практики, а не готове рішення для продакшену. Перевір контрастність усіх потрібних комбінацій.

# 12. Primary, Secondary та Accent у світлій і темній темах

Палітра може потребувати різних значень у світлій і темній темах.

Наприклад, синій primary, який добре працює на білому фоні, може виявитися занадто темним на темній поверхні.

    :root {
        color-scheme: light;

        --color-page-bg: hsl(220 20% 97%);
        --color-surface: hsl(0 0% 100%);
        --color-text: hsl(220 20% 12%);
        --color-primary: hsl(220 80% 45%);
        --color-accent: hsl(32 95% 45%);
        --color-border: hsl(220 12% 85%);
    }

    [data-theme="dark"] {
        color-scheme: dark;

        --color-page-bg: hsl(220 18% 10%);
        --color-surface: hsl(220 16% 14%);
        --color-text: hsl(220 15% 94%);
        --color-primary: hsl(220 85% 70%);
        --color-accent: hsl(32 95% 65%);
        --color-border: hsl(220 12% 28%);
    }

Використання:

    .button-primary {
        background-color: var(--color-primary);
        color: hsl(220 20% 10%);
    }

    .card {
        background-color: var(--color-surface);
        color: var(--color-text);
        border: 1px solid var(--color-border);
    }

Це лише демонстрація перемикання токенів. Колір тексту на кнопці також потрібно перевірити: для темного тексту на світлому primary він може бути доречним, але інші значення primary можуть вимагати білого тексту.

### Що важливо?

- Не інвертуй кольори механічно.
- Перевіряй primary на потрібних поверхнях.
- Переглядай secondary та accent окремо.
- Зберігай семантичні значення кольорів.
- Перевіряй читабельність тексту.
- Не покладайся лише на колір для станів.
- Тестуй обидві теми в реальних компонентах.

# 13. Доступність кольорової палітри

Хороша палітра повинна бути не тільки естетичною, а й доступною.

## 13.1. Контраст тексту

Для поширених вимог WCAG 2.x:

- звичайний текст зазвичай має відповідати контрастності щонайменше 4.5:1;
- великий текст — щонайменше 3:1;
- важливі графічні елементи та межі компонентів, необхідні для розуміння інтерфейсу, часто повинні мати контрастність щонайменше 3:1 відносно суміжних кольорів.

Для великого тексту за WCAG зазвичай мається на увазі розмір щонайменше 18 pt або 14 pt жирного накреслення.

Перевіряй вимоги відповідно до конкретного стандарту та контексту.

## 13.2. Primary не гарантує контрасту

Наприклад:

    .button-primary {
        background-color: hsl(220 80% 50%);
        color: white;
    }

Це поширена комбінація, але сам факт використання primary color не означає, що вона відповідає вимогам контрастності.

Потрібно перевірити конкретні значення.

## 13.3. Accent не повинен бути єдиним індикатором

Не варто позначати важливу інформацію лише кольором.

Наприклад, для помилки у формі використовуй:

- видимий текст повідомлення;
- відповідну іконку за потреби;
- колір межі;
- доступні атрибути для поля й повідомлення.

## 13.4. Перевіряй інтерактивні стани

Для кожного важливого компонента перевір:

- звичайний стан;
- hover;
- active;
- focus-visible;
- disabled;
- помилку або успіх, якщо доречно.

Колірна палітра повинна працювати в усіх цих станах, а не тільки у звичайному.

# 14. Типові помилки

## ❌ Помилка 1. Вважати, що Primary завжди має бути синім

Primary — це роль, а не конкретний колір.

Основним може бути зелений, фіолетовий, помаранчевий, чорний або будь-який інший доречний колір.

## ❌ Помилка 2. Вважати, що Secondary обов'язково потрібен

Невеликому інтерфейсу може бути достатньо primary, нейтральних і семантичних кольорів.

Не додавай другий виразний колір лише заради кількості.

## ❌ Помилка 3. Використовувати Accent всюди

Якщо акцентний колір займає майже весь інтерфейс, він перестає виділяти окремі елементи.

Використовуй його вибірково.

## ❌ Помилка 4. Плутати Accent із Danger

Акцентний колір не обов'язково означає помилку або небезпеку.

Визначай семантичні кольори окремо.

## ❌ Помилка 5. Робити всі кнопки однаково яскравими

Якщо всі кнопки мають однакову візуальну вагу, користувачу складніше визначити основну дію.

Використовуй primary, secondary та нейтральні стилі кнопок відповідно до їхньої ролі.

## ❌ Помилка 6. Ігнорувати нейтральні кольори

Палітра лише з яскравих кольорів часто перевантажує інтерфейс.

Нейтральні кольори забезпечують простір для контенту та акцентів.

## ❌ Помилка 7. Вибирати кольори окремо один від одного

Навіть красиві кольори можуть погано працювати разом.

Оцінюй їх у контексті спільної палітри.

## ❌ Помилка 8. Вважати правило 60-30-10 обов'язковим

Це евристика, а не стандарт.

Реальна площа кольорів залежить від структури сторінки та завдань інтерфейсу.

## ❌ Помилка 9. Не перевіряти контраст

Візуально приємна комбінація може бути нечитабельною.

Перевіряй контрастність тексту та важливих елементів.

## ❌ Помилка 10. Використовувати один primary без варіантів станів

Для інтерактивних компонентів часто потрібні hover, active та focus-стилі.

Створи послідовні варіанти кольору й перевір їх.

## ❌ Помилка 11. Використовувати ті самі кольори без перевірки в темній темі

Кольори, які працюють на білому фоні, можуть погано виглядати на темному.

Підготуй окремі значення токенів і перевір їх у контексті.

## ❌ Помилка 12. Використовувати колір як єдиний спосіб передавання інформації

Стани успіху, помилки та попередження повинні мати зрозумілий текст або інші сигнали.

## ❌ Помилка 13. Прив'язувати колір безпосередньо до компонента

Якщо в кожному компоненті записувати окремий HEX, підтримувати палітру буде складніше.

Використовуй CSS-змінні або дизайн-токени.

## ❌ Помилка 14. Надмірно ускладнювати палітру

Багато кольорів без чітких ролей ускладнюють підтримку дизайн-системи.

Починай із мінімального набору й додавай нові кольори лише за потреби.

# 15. Практичні завдання

## Завдання 1. Створи базову палітру

Вибери primary color і створи:

- три світлі варіанти;
- базовий колір;
- три темні варіанти.

Збережи їх у CSS-змінних.

## Завдання 2. Додай Secondary Color

Вибери додатковий колір за допомогою колірного кола.

Перевір, як він виглядає:

- поруч із primary;
- на нейтральному фоні;
- у великій кольоровій поверхні;
- у маленькій іконці.

## Завдання 3. Додай Accent Color

Визнач одну роль для акценту, наприклад:

- «Рекомендовано»;
- «Нове»;
- «Популярне».

Використай accent тільки там, де він допомагає привернути увагу.

## Завдання 4. Створи три типи кнопок

Реалізуй:

- Primary Button;
- Secondary Button;
- Tertiary або Ghost Button.

Порівняй їхню візуальну вагу та перевір стани hover, active і focus-visible.

## Завдання 5. Створи нейтральну палітру

Додай кольори для:

- фону сторінки;
- картки;
- основного тексту;
- другорядного тексту;
- меж;
- розділювачів.

## Завдання 6. Додай семантичні кольори

Створи повідомлення:

- Success;
- Warning;
- Error;
- Info.

Не використовуй колір як єдиний індикатор значення.

## Завдання 7. Перевір доступність

Перевір контрастність:

- primary-кнопки;
- вторинної кнопки;
- основного тексту;
- другорядного тексту;
- посилань;
- повідомлень;
- меж полів.

## Завдання 8. Реалізуй темну тему

Створи набір токенів для темної теми.

Не просто інвертуй кольори: перевір контраст, читабельність та візуальну ієрархію.

# 16. Питання для співбесіди

**1. Що таке Primary Color?**

Основний колір палітри, який часто використовується для провідних інтерактивних елементів та підтримує візуальну ідентичність продукту.

**2. Що таке Secondary Color?**

Додатковий колір, який розширює палітру та допомагає оформляти другорядні елементи або категорії контенту.

**3. Що таке Accent Color?**

Колір, який використовують вибірково, щоб привернути увагу до важливих елементів.

**4. Чим Primary відрізняється від Brand Color?**

Brand color пов'язаний із візуальною ідентичністю бренду. Primary — роль кольору в інтерфейсі. Вони часто збігаються, але не завжди.

**5. Чи обов'язково мати Secondary Color?**

Ні. Палітра може працювати з одним основним кольором, нейтральними та семантичними кольорами.

**6. Чи повинен Accent бути комплементарним до Primary?**

Ні. Він може бути комплементарним, аналоговим, монохромним або нейтральним — залежно від завдання.

**7. Чому не варто використовувати Accent скрізь?**

Тому що він перестає виділяти окремі елементи й не допомагає створювати чітку візуальну ієрархію.

**8. Чи означає Secondary, що елемент менш важливий?**

Не обов'язково. Це роль кольору в палітрі, а не універсальна оцінка важливості інформації.

**9. Що таке правило 60-30-10?**

Дизайнерська евристика, яка пропонує початковий розподіл кольорів між домінантною основою, додатковим кольором і акцентом.

**10. Чому нейтральні кольори важливі?**

Вони створюють основу інтерфейсу, забезпечують читабельність і дозволяють акцентам бути помітними.

**11. Чим Accent відрізняється від Danger?**

Accent привертає увагу, а Danger має семантичне значення помилки, небезпеки або руйнівної дії.

**12. Що таке семантичні кольори?**

Кольори, які позначають значення або стан: успіх, попередження, помилку чи інформацію.

**13. Чому потрібно перевіряти контрастність?**

Щоб текст і важливі елементи інтерфейсу залишалися видимими та доступними.

**14. Що таке кольорові токени?**

Іменовані значення кольорів, які використовуються повторно в компонентах і дизайн-системі.

**15. Чому краще використовувати CSS-змінні замість повторення HEX-кодів?**

Змінні централізують керування кольорами й полегшують оновлення палітри.

**16. Як організувати кольори для темної теми?**

Створити окремі значення семантичних токенів для темної теми та перевірити контрастність і читабельність.

# 19. Головне

**Primary, Secondary та Accent — це не три обов'язкові кольори, а три можливі ролі в системі дизайну.**

Primary формує провідний кольоровий напрям і часто використовується для основних дій.

Secondary доповнює основний колір, коли інтерфейсу потрібна додаткова кольорова різноманітність.

Accent привертає увагу до вибраних елементів і працює найкраще тоді, коли його використовують усвідомлено.

Нейтральні кольори створюють основу інтерфейсу, а семантичні передають зрозумілі значення: успіх, попередження, помилку та інформацію.

Для якісної дизайн-системи важливо не просто вибрати красиві кольори, а визначити:

- яку роль виконує кожен колір;
- де саме він використовується;
- як змінюється в інтерактивних станах;
- як працює на різних поверхнях;
- чи має достатній контраст;
- як поводиться у світлій і темній темах.

**Формула для запам'ятовування:**

    Primary   → основна кольорова роль
    Secondary → додаткова кольорова роль
    Accent    → вибіркове привернення уваги
    Neutral   → основа інтерфейсу
    Semantic  → значення та стани

**Мета дизайнера — не використати якомога більше кольорів, а створити зрозумілу візуальну ієрархію, у якій кожен колір має своє призначення.**
