# ♿ 10. Color Accessibility — Доступність кольорів

Color Accessibility — це принципи використання кольорів, які допомагають зробити інтерфейс зрозумілим, читабельним і доступним для якомога більшої кількості користувачів, зокрема людей із порушеннями сприйняття кольорів або зниженим зором.

Мета доступності кольорів — не просто підібрати красиву палітру, а забезпечити достатню контрастність, зрозуміле передавання інформації та зручну взаємодію з інтерфейсом.

Доступність кольорів важлива для:
- вебсайтів і вебзастосунків;
- мобільних застосунків;
- форм і повідомлень про помилки;
- кнопок і посилань;
- графіків і діаграм;
- панелей адміністратора;
- світлих і темних тем;
- дизайн-систем.

## 1. 🎨 Що таке доступність кольорів

Доступність кольорів — це здатність інтерфейсу передавати інформацію за допомогою кольору так, щоб нею могли користуватися люди з різними зоровими можливостями.

Наприклад, недостатньо зробити текст сірим на світло-сірому фоні лише тому, що таке поєднання гарно виглядає.

Потрібно перевірити, чи легко цей текст прочитати.

Так само недостатньо позначити помилку тільки червоним кольором. Користувач може не розрізняти цей колір або не помітити його.

### Основні принципи

1. Текст повинен мати достатню контрастність.
2. Інтерактивні елементи повинні бути помітними.
3. Інформація не повинна передаватися тільки кольором.
4. Стан елемента повинен залишатися зрозумілим у різних умовах.
5. Кольори потрібно перевіряти в реальному контексті інтерфейсу.

**Головна ідея:** колір допомагає передавати інформацію, але не повинен бути єдиним способом її сприйняття.

---

## 2. 👁️ Як люди сприймають кольори

Користувачі можуть по-різному сприймати однакову палітру.

На сприйняття впливають:
- порушення кольоросприйняття;
- зниження гостроти зору;
- контраст між сусідніми елементами;
- яскравість екрана;
- освітлення навколишнього середовища;
- розмір і товщина тексту;
- тип і якість дисплея.

### 2.1. Порушення сприйняття кольорів

Існують різні форми порушень кольоросприйняття.

Наприклад, деяким людям складно розрізняти певні відтінки червоного та зеленого.

Це може створювати проблеми, якщо інтерфейс використовує лише ці кольори для позначення станів.

Невдалий приклад:

    <span class="status status--success"></span>
    <span class="status status--error"></span>

Якщо елементи відрізняються тільки кольором, їхнє значення може бути незрозумілим.

Кращий варіант:

    <p class="status status--success">
        ✓ Операцію виконано успішно
    </p>

    <p class="status status--error">
        ✕ Не вдалося виконати операцію
    </p>

Тепер інформація передається за допомогою тексту та додаткових візуальних ознак.

### 2.2. Важливий висновок

Не потрібно відмовлятися від кольорів.

Потрібно використовувати їх разом із:
- текстом;
- формою;
- значками;
- підписами;
- межами;
- візуальними станами.

## 3. ⚖️ Контрастність кольорів

Контрастність — це різниця між двома кольорами, яка допомагає розрізняти текст, фон та інші елементи.

Для вебдоступності важливо перевіряти не лише те, чи кольори здаються різними, а й їхнє співвідношення яскравості.

### 3.1. Високий контраст

    color: #172033;
    background-color: #ffffff;

Темний текст на білому фоні зазвичай має високу контрастність.

### 3.2. Низький контраст

    color: #b8b8b8;
    background-color: #eeeeee;

Світло-сірий текст на світло-сірому фоні може бути важким для читання.

### 3.3. Контраст — це не тільки різниця кольорів

Два кольори можуть бути різними за відтінком, але мати недостатню контрастність.

Наприклад, синій і фіолетовий можуть виглядати по-різному, проте їхня відносна яскравість може бути дуже близькою.

Тому не варто оцінювати доступність лише на око.

---

## 4. 🔢 Contrast Ratio — коефіцієнт контрастності

Contrast Ratio — це числове співвідношення відносної яскравості двох кольорів.

Записується у форматі:

    1:1
    3:1
    4.5:1
    7:1
    21:1

Чим більше співвідношення, тим вища контрастність.

### 4.1. Мінімальне та максимальне значення

- `1:1` — кольори мають однакову відносну яскравість.
- `21:1` — максимальна контрастність між чорним і білим.

Контрастність залежить від відносної яскравості кольорів, а не від того, наскільки різними вони здаються за відтінком.

### 4.2. Як розраховується контрастність

Формула WCAG:

    Contrast Ratio = (L1 + 0.05) / (L2 + 0.05)

Де:

- `L1` — більша відносна яскравість;
- `L2` — менша відносна яскравість;
- значення `L1` і `L2` перебувають у діапазоні від `0` до `1`.

Спочатку для кольорів у просторі sRGB обчислюють відносну яскравість, а потім використовують формулу співвідношення.

На практиці не обов'язково вручну розраховувати кожну пару кольорів. Для цього існують спеціальні інструменти.

## 5. 📏 Вимоги WCAG до контрастності тексту

WCAG — це Web Content Accessibility Guidelines, рекомендації щодо доступності вебконтенту.

Для контрастності тексту важливо розрізняти звичайний і великий текст.

### 5.1. Рівень WCAG AA

Для відповідності критерію контрастності тексту на рівні AA зазвичай потрібні такі значення:

| Тип тексту | Мінімальна контрастність |
|---|---:|
| Звичайний текст | 4.5:1 |
| Великий текст | 3:1 |

Це вимоги критерію WCAG 2.x 1.4.3 Contrast (Minimum).

### 5.2. Що вважається великим текстом

До великого тексту належить:
- звичайний текст розміром щонайменше 24 CSS px;
- жирний текст розміром щонайменше приблизно 18.67 CSS px.

Це приблизні еквіваленти визначення великого тексту у WCAG.

Не слід автоматично вважати будь-який жирний текст великим. Важливі і розмір, і товщина шрифту.

### 5.3. Рівень WCAG AAA

Для критерію посиленої контрастності тексту використовуються такі значення:

| Тип тексту | Мінімальна контрастність |
|---|---:|
| Звичайний текст | 7:1 |
| Великий текст | 4.5:1 |

Це вимоги критерію WCAG 2.x 1.4.6 Contrast (Enhanced).

Рівень AAA суворіший за AA. Він не є обов'язковою ціллю для кожного проєкту, але може бути корисним для інтерфейсів, де особливо важлива читабельність.

### 5.4. Що потрібно запам'ятати

- AA: `4.5:1` для звичайного тексту.
- AA: `3:1` для великого тексту.
- AAA: `7:1` для звичайного тексту.
- AAA: `4.5:1` для великого тексту.

Ці пороги стосуються конкретних критеріїв WCAG, а не всіх без винятку елементів інтерфейсу.

---

## 6. 🔘 Контрастність елементів інтерфейсу

Не тільки текст повинен бути помітним.

Користувачеві потрібно розрізняти:
- межі полів введення;
- значки керування;
- стани перемикачів;
- індикатори фокусу;
- графічні елементи, необхідні для розуміння інформації.

### 6.1. Нетекстовий контраст

WCAG 2.x містить критерій 1.4.11 Non-text Contrast.

Для відповідних візуальних ознак компонентів інтерфейсу та графічних об'єктів зазвичай потрібна контрастність щонайменше `3:1` відносно прилеглого кольору.

Наприклад, межа поля введення повинна бути достатньо помітною, якщо саме вона необхідна для розпізнавання поля.

### 6.2. Приклад поля введення

    .input {
        color: #172033;
        background-color: #ffffff;
        border: 1px solid #64748b;
        border-radius: 0.5rem;
        padding: 0.75rem;
    }

    .input:focus-visible {
        outline: 2px solid #1d4ed8;
        outline-offset: 2px;
    }

Це приклад стилізації, але відповідність вимогам потрібно перевіряти для фактичних пар кольорів і станів.

### 6.3. Не кожна декоративна межа обов'язкова

Деякі декоративні елементи не підпадають під ті самі вимоги контрастності.

Однак якщо межа потрібна, щоб зрозуміти структуру або призначення компонента, її видимість має значення.

---

## 7. 🚫 Не передавай інформацію тільки кольором

Це один із найважливіших принципів доступності.

WCAG 2.x містить критерій 1.4.1 Use of Color, який забороняє використовувати колір як єдиний візуальний засіб передавання інформації, позначення дії, запиту на відповідь або розрізнення елемента.

### 7.1. Невдалий приклад

    <p class="error">
        Неправильні дані
    </p>

Якщо користувач бачить лише червоний колір, йому може бути складніше зрозуміти значення повідомлення.

### 7.2. Кращий приклад

    <p class="error" role="alert">
        Помилка: введіть коректну електронну адресу.
    </p>

Тепер повідомлення містить зрозумілий текст.

### 7.3. Приклад статусів

Невдалий підхід:

    .status--success {
        color: green;
    }

    .status--error {
        color: red;
    }

Кращий підхід:

    <p class="status status--success">
        ✓ Усі зміни збережено
    </p>

    <p class="status status--error">
        ✕ Не вдалося зберегти зміни
    </p>

Колір можна залишити як додаткову підказку, але текст і символи також передають зміст.

---

## 8. 🔗 Доступні посилання

Посилання повинні бути зрозумілими не тільки завдяки кольору.

### 8.1. Невдалий приклад

    <p>
        Докладніше читайте в
        <a href="/guide">нашому посібнику</a>.
    </p>

Якщо посилання відрізняється від навколишнього тексту тільки кольором, деяким користувачам буде складніше його розпізнати.

### 8.2. Кращий приклад

    a {
        color: #1d4ed8;
        text-decoration: underline;
        text-underline-offset: 0.15em;
    }

Підкреслення допомагає розпізнати посилання незалежно від кольору.

### 8.3. Стан фокусу

    a:focus-visible {
        outline: 2px solid #1d4ed8;
        outline-offset: 3px;
    }

Фокус повинен залишатися видимим під час навігації клавіатурою.

### 8.4. Що перевірити

- Посилання відрізняється від звичайного тексту не лише кольором.
- Колір тексту посилання має достатню контрастність.
- Стан наведення помітний.
- Стан клавіатурного фокусу помітний.
- Посилання зрозуміле за своїм текстом.

## 9. 📝 Доступні форми та повідомлення про помилки

Форми часто використовують кольори для позначення правильних і неправильних даних.

Але червона межа без пояснення не завжди допомагає користувачеві виправити помилку.

### 9.1. Приклад доступного поля

    <label for="email">Електронна адреса</label>

    <input
        id="email"
        name="email"
        type="email"
        aria-invalid="true"
        aria-describedby="email-error"
    >

    <p id="email-error">
        Введіть коректну електронну адресу.
    </p>

Атрибут `aria-invalid="true"` повідомляє допоміжним технологіям про некоректний стан поля, а `aria-describedby` пов'язує поле з поясненням.

У реальному інтерфейсі цей стан потрібно встановлювати відповідно до результату перевірки введених даних.

### 9.2. Стилі

    .input[aria-invalid="true"] {
        border: 2px solid #b91c1c;
    }

    .error-message {
        color: #b91c1c;
    }

    .input:focus-visible {
        outline: 2px solid #1d4ed8;
        outline-offset: 2px;
    }

Червоний колір у цьому прикладі є лише відправною точкою. Потрібно перевірити його контрастність із фоном, а також переконатися, що повідомлення про помилку не передається тільки кольором.

### 9.3. Важливі правила

- Пов'язуй повідомлення з відповідним полем.
- Пояснюй, як виправити помилку.
- Не використовуй тільки червону межу.
- Не прибирай видимий фокус.
- Не приховуй повідомлення за допомогою кольору або низької контрастності.

## 10. 📊 Доступність графіків і діаграм

Графіки часто використовують кольори для розрізнення серій даних.

Наприклад:
- доходи;
- витрати;
- кількість користувачів;
- кількість помилок;
- результати за місяцями.

Якщо серії відрізняються тільки кольором, частина користувачів може не розрізняти їх.

### 10.1. Невдалий підхід

Дві лінії графіка відрізняються лише зеленим і червоним кольорами.

### 10.2. Кращий підхід

Використовуй додаткові способи розрізнення:
- різні типи ліній;
- різні маркери;
- підписи безпосередньо на графіку;
- легенду;
- текстовий опис;
- таблицю з даними.

Наприклад:

    Доходи — суцільна лінія з круглими маркерами.
    Витрати — пунктирна лінія з квадратними маркерами.

### 10.3. Контрастність графічних елементів

Для графічних об'єктів, які необхідні для розуміння інформації, потрібно перевіряти відповідні вимоги нетекстового контрасту.

Не всі декоративні частини графіка мають однакові вимоги, але ключові лінії, маркери та інші змістовні елементи повинні бути достатньо помітними.

### 10.4. Альтернативне представлення даних

Якщо графік передає важливу інформацію, корисно доповнити його таблицею або текстовим підсумком.

Це допомагає користувачам, які не можуть повністю сприйняти графічне представлення.

## 11. 🌗 Доступність кольорів у Dark Mode

Темна тема не означає автоматичну доступність.

Світлий текст на темному фоні також може мати недостатню контрастність.

### 11.1. Приклад токенів

    :root {
        --color-background: #ffffff;
        --color-text: #172033;
        --color-text-muted: #64748b;
        --color-link: #1d4ed8;
    }

    :root[data-theme="dark"] {
        --color-background: #111827;
        --color-text: #f1f5f9;
        --color-text-muted: #a8b3c4;
        --color-link: #93c5fd;
    }

Це приклад організації палітри, а не гарантія відповідності WCAG.

### 11.2. Що перевіряти

- Основний текст.
- Допоміжний текст.
- Посилання.
- Межі полів.
- Кнопки.
- Стани фокусу.
- Повідомлення про помилки.
- Семантичні кольори.
- Графіки та іконки.

Перевіряй обидві теми окремо, оскільки одна й та сама пара кольорів не обов'язково буде придатною для різних фонів.

## 12. 🎯 Доступні семантичні кольори

Семантичні кольори передають значення:
- успіх;
- помилка;
- попередження;
- інформація.

Вони повинні бути зрозумілими та помітними на відповідному фоні.

### 12.1. Приклад CSS-токенів

    :root {
        --color-success: #166534;
        --color-warning: #854d0e;
        --color-danger: #b91c1c;
        --color-info: #1d4ed8;
    }

Ці значення потрібно перевіряти в контексті реального інтерфейсу.

### 12.2. Доступне повідомлення

    <div class="notice notice--warning">
        <strong>Увага:</strong>
        перед виходом збережіть зміни.
    </div>

Повідомлення містить текст, який пояснює значення попередження.

### 12.3. Чому універсальної палітри немає

Один і той самий колір може:
- мати достатній контраст на білому фоні;
- бути недостатньо помітним на сірому фоні;
- погано працювати в темній темі;
- втрачати виразність у поєднанні з іншими кольорами.

Тому потрібно перевіряти конкретні комбінації кольорів, а не тільки окремі значення палітри.

## 13. 🧪 Інструменти перевірки контрастності

Інструменти допомагають швидко перевірити співвідношення яскравості двох кольорів.

### 13.1. WebAIM Contrast Checker

Онлайн-інструмент для перевірки контрастності кольору тексту та фону.

Можна використовувати для:
- перевірки HEX-кодів;
- порівняння різних відтінків;
- перевірки відповідності порогам AA та AAA.

Посилання: https://webaim.org/resources/contrastchecker/

### 13.2. Colour Contrast Analyser

Інструмент для перевірки контрастності, який допомагає оцінювати кольори тексту та елементів інтерфейсу.

Посилання: https://www.tpgi.com/color-contrast-checker/

### 13.3. Chrome DevTools

У Chrome DevTools можна перевіряти CSS-кольори елементів і контрастність тексту в панелі стилів.

Це зручно, коли потрібно:
- перевірити колір конкретного компонента;
- дослідити стилі;
- змінити значення без редагування файлів;
- перевірити різні стани інтерфейсу.

### 13.4. Автоматизовані перевірки

Інструменти автоматизованого тестування доступності можуть знаходити частину проблем із контрастністю.

Однак автоматична перевірка не замінює ручного тестування.

Наприклад, інструмент може не визначити, чи передається значення графіка тільки кольором, або чи достатньо зрозумілим є текст повідомлення про помилку.

## 14. 🛠️ Практичний алгоритм перевірки кольорів

Коли створюєш новий компонент, перевіряй його послідовно.

### Крок 1. Визнач призначення кольорів

Запиши:
- колір тексту;
- колір фону;
- колір меж;
- колір інтерактивних елементів;
- кольори станів.

### Крок 2. Перевір контрастність

Для тексту перевір:
- `4.5:1` для звичайного тексту;
- `3:1` для великого тексту.

Якщо проєкт має відповідати AAA, використовуй суворіші пороги.

### Крок 3. Перевір нетекстові елементи

Перевір відповідні графічні ознаки компонентів та змістовні графічні об'єкти.

Для елементів, на які поширюється критерій WCAG 1.4.11, орієнтиром є `3:1`.

### Крок 4. Перевір інформацію, передану кольором

Запитай себе:

- Чи зрозуміла помилка без червоного кольору?
- Чи можна розрізнити серії графіка без кольору?
- Чи помітне посилання без розрізнення відтінків?
- Чи зрозумілий стан перемикача?

### Крок 5. Перевір інтерактивні стани

Перевір:
- звичайний стан;
- наведення;
- фокус клавіатури;
- натискання;
- вимкнений стан;
- помилковий стан.

### Крок 6. Перевір обидві теми

Якщо застосунок має Light Mode і Dark Mode, тестуй кожну тему окремо.

### Крок 7. Перевір вручну

Пройдися сторінкою клавіатурою, прочитай тексти, перевір форми та переконайся, що зміст залишається зрозумілим.

## 15. ❌ Типові помилки

### Помилка 1. Оцінювати контрастність тільки на око

Кольори можуть здаватися різними, але не відповідати потрібному коефіцієнту контрастності.

**Рішення:** використовуй Contrast Checker.

### Помилка 2. Використовувати світло-сірий текст на світлому фоні

Такий текст може бути важким для читання.

**Рішення:** перевіряй контрастність допоміжних текстів так само уважно, як і основного тексту.

### Помилка 3. Вважати, що великий текст не потребує перевірки

Великий текст має нижчий мінімальний поріг AA, але все одно потребує достатньої контрастності.

**Рішення:** перевіряй розмір, товщину та фактичну контрастність.

### Помилка 4. Передавати помилку тільки червоним кольором

Користувач може не розпізнати значення стану.

**Рішення:** додай текстове повідомлення, значок або іншу зрозумілу ознаку.

### Помилка 5. Робити посилання помітними тільки кольором

Посилання може бути важко розпізнати серед звичайного тексту.

**Рішення:** використовуй підкреслення або інший незалежний візуальний маркер.

### Помилка 6. Ігнорувати фокус клавіатури

Якщо фокус непомітний, користувачеві складно зрозуміти, де він перебуває.

**Рішення:** створюй виразний стан `:focus-visible`.

### Помилка 7. Перевіряти тільки світлу тему

У темній темі контрастність тексту, меж і станів може змінитися.

**Рішення:** перевіряй кожну тему окремо.

### Помилка 8. Використовувати тільки автоматичні перевірки

Автоматизація не може оцінити всі аспекти зрозумілості інтерфейсу.

**Рішення:** поєднуй автоматичні інструменти з ручним тестуванням.

### Помилка 9. Робити всі кольори надто яскравими

Надмірна насиченість може погіршити візуальну ієрархію.

**Рішення:** шукай баланс між контрастністю, читабельністю та композицією.

### Помилка 10. Плутати красиву палітру з доступною палітрою

Естетичність і доступність — різні характеристики.

**Рішення:** перевіряй палітру до завершення дизайну, а не після нього.

## 18. 📈 Рівні вивчення

### 🟢 Core — основи

Ти повинен уміти:
- пояснити, що таке доступність кольорів;
- розуміти поняття контрастності;
- знати основні пороги WCAG AA;
- перевіряти пари кольорів;
- розуміти, чому колір не повинен бути єдиним носієм інформації.

### 🔵 Junior — практичне застосування

Ти повинен уміти:
- перевіряти текст і фон за допомогою Contrast Checker;
- створювати доступні посилання;
- оформлювати помилки у формах;
- підтримувати помітний клавіатурний фокус;
- перевіряти світлу й темну теми;
- знаходити типові проблеми контрастності.

### 🟣 Middle — системний підхід

Ти повинен уміти:
- створювати палітри з урахуванням WCAG;
- перевіряти семантичні кольори;
- тестувати всі стани компонентів;
- враховувати доступність графіків;
- інтегрувати перевірки в процес розробки;
- поєднувати автоматизоване та ручне тестування.

### 🟠 Senior — архітектура

Ти повинен розуміти:
- як включити доступність у дизайн-систему;
- як проєктувати семантичні токени кольорів;
- як підтримувати доступність у великій кількості тем і компонентів;
- як організувати аудит доступності;
- як запобігати повторній появі проблем із контрастністю;
- як враховувати доступність на всіх етапах розробки продукту.

## 19. 📌 Мінішпаргалка

| Поняття | Що потрібно пам'ятати |
|---|---|
| Color Accessibility | Доступність інформації, переданої кольором |
| Contrast Ratio | Співвідношення відносної яскравості кольорів |
| WCAG AA | Базовий поширений рівень відповідності |
| WCAG AAA | Суворіший рівень вимог |
| 4.5:1 | Мінімальна контрастність звичайного тексту за AA |
| 3:1 | Мінімальна контрастність великого тексту за AA |
| 7:1 | Мінімальна контрастність звичайного тексту за AAA |
| 4.5:1 | Мінімальна контрастність великого тексту за AAA |
| Non-text Contrast | Контрастність відповідних графічних елементів і компонентів |
| Use of Color | Не можна використовувати колір як єдиний засіб передавання інформації |
| `:focus-visible` | Видимий фокус під час клавіатурної навігації |
| Contrast Checker | Інструмент для перевірки контрастності |

### Три основні правила

1. **Перевіряй контрастність, а не покладайся тільки на власний зір.**
2. **Не передавай важливу інформацію тільки кольором.**
3. **Перевіряй текст, компоненти та графіку в реальному контексті інтерфейсу.**

## 🎯 Головне

Доступність кольорів — це невіддільна частина якісного UI-дизайну.

Доступний інтерфейс:
- має достатню контрастність;
- використовує зрозумілу візуальну ієрархію;
- не покладається тільки на колір;
- забезпечує видимість інтерактивних елементів;
- підтримує доступні форми та повідомлення;
- враховує світлу й темну теми;
- проходить автоматичне та ручне тестування.

**Запам'ятай:** доступний дизайн — це не відмова від красивих кольорів. Це правильне використання кольорів, за якого естетика не заважає читабельності та розумінню інтерфейсу.
