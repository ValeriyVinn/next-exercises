# 🎨 Borders and Dividers — Межі та розділювачі в UI-дизайні

> **Borders and Dividers** — це візуальні засоби, які допомагають відокремлювати елементи інтерфейсу, позначати межі компонентів, структурувати інформацію та створювати зрозумілу композицію.

Межі й розділювачі здаються простими деталями, але вони суттєво впливають на сприйняття інтерфейсу. Правильно підібрані кольори, товщина та розташування ліній допомагають користувачеві розуміти, де закінчується один компонент і починається інший.

**Де використовується:**
- Картки та панелі.
- Поля введення й форми.
- Таблиці та списки.
- Розділювачі між секціями.
- Навігація та меню.
- Модальні вікна й діалоги.
- Кнопки та інтерактивні компоненти.
- Світла й темна теми.
- Дизайн-системи та UI-компоненти.

---

## ✔ Основні поняття

- **Border** — межа навколо елемента.
- **Border color** — колір межі.
- **Border width** — товщина межі.
- **Border style** — стиль межі: суцільна, пунктирна тощо.
- **Divider** — лінія, яка візуально розділяє елементи або секції.
- **Outline** — зовнішній контур, який не займає місця в моделі коробки CSS.
- **Separator** — розділювач між елементами, наприклад пунктами меню.
- **Subtle border** — малопомітна межа.
- **Strong border** — виразна межа.
- **Focus border** — межа або індикатор, що позначає фокус.
- **Semantic border** — межа, що передає значення, наприклад помилку.
- **Border radius** — заокруглення кутів.
- **Design tokens** — іменовані змінні для кольорів, товщини та інших властивостей.
- **Visual hierarchy** — візуальна ієрархія компонентів.
- **Contrast** — різниця між кольорами, яка допомагає розрізняти елементи.

---

# 1. Навіщо потрібні межі та розділювачі

Межі допомагають користувачеві зрозуміти структуру інтерфейсу.

Наприклад, у списку налаштувань є три рядки:

    Обліковий запис
    Сповіщення
    Конфіденційність

Без додаткового оформлення рядки можуть виглядати як один суцільний текстовий блок.

Якщо додати тонкі розділювачі, структура стане зрозумілішою:

    Обліковий запис
    ─────────────────────
    Сповіщення
    ─────────────────────
    Конфіденційність

У реальному інтерфейсі лінії можуть бути світло-сірими, напівпрозорими або майже непомітними.

**Основні завдання меж і розділювачів:**

- Відокремлювати сусідні компоненти.
- Позначати межі карток і панелей.
- Групувати пов'язану інформацію.
- Полегшувати сканування довгих списків.
- Підкреслювати стани компонентів.
- Допомагати користувачеві розуміти структуру сторінки.

**Головний принцип:** лінія повинна допомагати розуміти інтерфейс, а не просто прикрашати його.

---

# 2. Border і Divider — у чому різниця

Ці поняття пов'язані, але мають різні призначення.

## 2.1. Border — межа компонента

Border зазвичай обрамляє елемент або його частину.

Приклади:
- Межа картки.
- Межа поля введення.
- Межа кнопки.
- Межа модального вікна.
- Межа таблиці.

    .card {
        border: 1px solid #e5e7eb;
        border-radius: 12px;
    }

Така межа допомагає відокремити картку від навколишнього середовища.

## 2.2. Divider — розділювач

Divider розділяє два елементи або дві частини одного компонента.

Приклади:
- Лінія між пунктами меню.
- Розділювач між рядками списку.
- Лінія між заголовком і вмістом панелі.
- Розділення секцій у налаштуваннях.

    .divider {
        height: 1px;
        background-color: #e5e7eb;
    }

Для звичайного горизонтального розділювача часто краще використовувати `border-bottom` або семантичний HTML-елемент `<hr>`.

## 2.3. Коротке порівняння

| Властивість | Border | Divider |
|---|---|---|
| Основна роль | Позначає межі компонента | Розділяє елементи |
| Типове розташування | Навколо елемента | Між елементами |
| Приклад | Межа картки | Лінія між рядками |
| CSS | `border` | `border-bottom`, `border-top`, `<hr>` |
| Основна мета | Визначити область компонента | Покращити структуру |

Це не абсолютне правило. Наприклад, `border-bottom` може використовуватися і як межа компонента, і як розділювач між рядками.

---

# 3. Border width — товщина межі

Товщина межі впливає на її візуальну вагу.

Зазвичай у вебінтерфейсах використовують:

- `1px` — тонка, делікатна межа.
- `2px` — помітна межа або індикатор стану.
- `3px` і більше — виразний контур, який варто використовувати обережно.

    .card {
        border: 1px solid #e5e7eb;
    }

    .input:focus {
        border: 2px solid #2563eb;
    }

    .important-panel {
        border: 3px solid #2563eb;
    }

Не потрібно робити всі межі товстими. Надмірна кількість виразних контурів створює візуальний шум.

## 3.1. Товщина та ієрархія

Тонкі лінії зазвичай підходять для:
- Відокремлення сусідніх рядків.
- Меж карток.
- Допоміжних панелей.
- Таблиць.

Товстіші лінії можуть використовуватися для:
- Фокусу.
- Виділеного компонента.
- Активного елемента.
- Особливо важливої області.

**Важливо:** для доступного індикатора фокусу не слід покладатися лише на зміну товщини межі. Враховуйте також видимість, контрастність і вимоги доступності.

---

# 4. Border color — колір межі

Колір межі повинен відповідати її призначенню.

У більшості інтерфейсів можна почати з трьох рівнів:

- **Subtle border** — ледь помітна межа.
- **Default border** — стандартна межа.
- **Strong border** — виразна межа.

    :root {
        --color-border-subtle: #f3f4f6;
        --color-border-default: #e5e7eb;
        --color-border-strong: #9ca3af;
    }

Використання:

    .card {
        border: 1px solid var(--color-border-default);
    }

    .list-item {
        border-bottom: 1px solid var(--color-border-subtle);
    }

    .filter-panel {
        border: 1px solid var(--color-border-strong);
    }

## 4.1. Коли використовувати малопомітні межі

Малопомітні межі доречні, коли потрібно:
- Розділити рядки списку.
- Відокремити картку від фону.
- Позначити межі таблиці.
- Структурувати сторінку без зайвих акцентів.

## 4.2. Коли потрібні виразні межі

Виразніші межі можуть знадобитися для:
- Полів введення.
- Активних або вибраних елементів.
- Компонентів, які потребують чіткого відокремлення.
- Елементів керування на складному фоні.

Не варто використовувати найтемнішу межу всюди. Якщо кожен елемент однаково виразний, користувачеві складніше зрозуміти, на що звертати увагу.

---

# 5. Border style — стиль межі

CSS підтримує кілька стилів меж.

    .solid-border {
        border: 1px solid #9ca3af;
    }

    .dashed-border {
        border: 1px dashed #9ca3af;
    }

    .dotted-border {
        border: 1px dotted #9ca3af;
    }

    .double-border {
        border: 3px double #9ca3af;
    }

Основні значення:

| Значення | Призначення |
|---|---|
| `solid` | Суцільна лінія |
| `dashed` | Пунктирна лінія |
| `dotted` | Точкова лінія |
| `double` | Подвійна лінія |
| `none` | Без межі |
| `hidden` | Прихована межа, особливо важлива в табличній моделі меж |

Для більшості сучасних UI-компонентів достатньо `solid`.

Пунктирні та точкові лінії можуть використовуватися для спеціальних станів, областей перетягування файлів або допоміжних позначень.

Не використовуйте багато різних стилів меж без чіткої системи.

---

# 6. Border radius — заокруглення кутів

`border-radius` визначає заокруглення кутів компонента.

    .card {
        border: 1px solid #e5e7eb;
        border-radius: 12px;
    }

    .input {
        border: 1px solid #d1d5db;
        border-radius: 8px;
    }

    .pill {
        border-radius: 9999px;
    }

Типові приклади:

- `4px` — невелике заокруглення.
- `8px` — помірне заокруглення.
- `12px` — помітно заокруглена картка.
- `16px` і більше — виразні заокруглені компоненти.
- `9999px` — часто використовується для капсульної форми.

Це орієнтовні значення, а не обов'язковий стандарт.

## 6.1. Узгодженість радіусів

У межах одного інтерфейсу варто використовувати обмежений набір значень.

    :root {
        --radius-sm: 4px;
        --radius-md: 8px;
        --radius-lg: 12px;
        --radius-xl: 16px;
        --radius-pill: 9999px;
    }

    .input {
        border-radius: var(--radius-md);
    }

    .card {
        border-radius: var(--radius-lg);
    }

    .modal {
        border-radius: var(--radius-xl);
    }

Надмірна кількість випадкових радіусів створює враження неузгодженого дизайну.

---

# 7. Divider — горизонтальні розділювачі

Горизонтальні розділювачі допомагають відокремлювати сусідні елементи, які розташовані один під одним.

Наприклад:
- Рядки списку.
- Пункти меню.
- Розділи налаштувань.
- Рядки таблиці.
- Блоки інформації.

## 7.1. Використання border-bottom

    .settings-item {
        padding: 16px 0;
        border-bottom: 1px solid #e5e7eb;
    }

    .settings-item:last-child {
        border-bottom: none;
    }

Це зручний спосіб додати лінію після кожного елемента, крім останнього.

## 7.2. Використання `<hr>`

HTML-елемент `<hr>` позначає тематичне розділення між частинами вмісту.

    <section>
        <h2>Профіль</h2>
        <p>Особисті дані користувача.</p>
    </section>

    <hr>

    <section>
        <h2>Сповіщення</h2>
        <p>Налаштування повідомлень.</p>
    </section>

Оформлення:

    hr {
        border: 0;
        border-top: 1px solid #e5e7eb;
        margin: 24px 0;
    }

Використовуйте `<hr>`, коли розділення має відповідне смислове значення. Для суто декоративної межі між сусідніми рядками частіше достатньо CSS.

---

# 8. Vertical dividers — вертикальні розділювачі

Вертикальні лінії використовуються для розділення елементів, розташованих горизонтально.

**Приклади:**
- Групи кнопок.
- Панелі інструментів.
- Навігаційні блоки.
- Метадані в одному рядку.
- Колонки інформаційної панелі.

    .toolbar {
        display: flex;
        align-items: center;
        gap: 16px;
    }

    .toolbar__divider {
        width: 1px;
        height: 24px;
        background-color: #e5e7eb;
    }

HTML:

    <div class="toolbar">
        <button type="button">Редагувати</button>

        <span class="toolbar__divider" aria-hidden="true"></span>

        <button type="button">Видалити</button>
    </div>

Для декоративного розділювача використовуйте `aria-hidden="true"`, щоб допоміжні технології не сприймали його як окремий змістовний елемент.

Не додавайте вертикальні лінії між усіма елементами автоматично. Часто достатньо відступів.

---

# 9. Borders у картках і панелях

Межа картки допомагає відокремити її від фону.

    .card {
        padding: 24px;
        border: 1px solid #e5e7eb;
        border-radius: 12px;
        background-color: #ffffff;
    }

Але межа — не єдиний спосіб створити відокремлення.

Можна використовувати:
- Контраст фону.
- Тінь.
- Відступи.
- Розташування в композиції.
- Поєднання кількох способів.

Наприклад:

    .card {
        padding: 24px;
        border-radius: 12px;
        background-color: #ffffff;
        box-shadow: 0 2px 8px rgb(0 0 0 / 6%);
    }

Тут межа відсутня, але тінь допомагає відокремити картку.

Не потрібно одночасно використовувати товсту межу, сильну тінь і великий контраст фону, якщо для цього немає конкретної причини.

---

# 10. Borders у формах

Межі полів введення допомагають користувачеві зрозуміти, де можна вводити дані.

    .input {
        width: 100%;
        padding: 12px 14px;
        border: 1px solid #9ca3af;
        border-radius: 8px;
        background-color: #ffffff;
        color: #1f2937;
    }

Для поля введення важливо продумати різні стани.

## 10.1. Default — звичайний стан

    .input {
        border: 1px solid #9ca3af;
    }

## 10.2. Hover — наведення

    .input:hover {
        border-color: #6b7280;
    }

## 10.3. Focus — фокус

    .input:focus-visible {
        border-color: #2563eb;
        outline: 2px solid #93c5fd;
        outline-offset: 1px;
    }

## 10.4. Error — помилка

    .input[aria-invalid="true"] {
        border-color: #b91c1c;
    }

## 10.5. Disabled — неактивний стан

    .input:disabled {
        border-color: #e5e7eb;
        background-color: #f3f4f6;
        color: #6b7280;
        cursor: not-allowed;
    }

Це приклад системи станів. У реальному проєкті кольори потрібно перевірити на фактичному фоні.

**Важливо:** не видаляйте `outline` без створення іншого чіткого індикатора клавіатурного фокусу.

---

# 11. Focus border і доступність

Коли користувач переміщується інтерфейсом за допомогою клавіатури, він повинен розуміти, який елемент зараз активний.

Для цього використовують видимий індикатор фокусу.

    button:focus-visible {
        outline: 3px solid #2563eb;
        outline-offset: 3px;
    }

Чому часто краще використовувати `outline`, а не лише `border`?

- `outline` не займає місця в моделі коробки.
- Контур може бути розташований за межами компонента.
- Він може бути помітнішим за звичайну межу.
- Його можна використовувати як додатковий індикатор стану.

Межа та контур — різні CSS-властивості.

    .button {
        border: 1px solid #d1d5db;
    }

    .button:focus-visible {
        outline: 3px solid #2563eb;
        outline-offset: 3px;
    }

Звичайна межа визначає форму компонента, а контур показує його стан фокусу.

Для інтерактивних компонентів перевіряйте, щоб індикатор фокусу:
- Був помітним.
- Не зливався з фоном.
- Не обрізався контейнером.
- Не перекривався сусідніми елементами.
- Залишався видимим у світлій і темній темах.

---

# 12. Semantic borders — семантичні межі

Семантичні межі передають стан або значення компонента.

Основні варіанти:
- Default — стандартний стан.
- Success — успішний стан.
- Error — помилка.
- Warning — попередження.
- Info — інформаційний стан.
- Focus — клавіатурний або програмний фокус.
- Selected — вибраний елемент.

    :root {
        --border-default: #d1d5db;
        --border-success: #15803d;
        --border-error: #b91c1c;
        --border-warning: #a16207;
        --border-info: #2563eb;
        --border-focus: #2563eb;
        --border-selected: #1d4ed8;
    }

Приклад:

    .field {
        border: 1px solid var(--border-default);
    }

    .field.is-error {
        border-color: var(--border-error);
    }

    .field.is-success {
        border-color: var(--border-success);
    }

    .option.is-selected {
        border: 2px solid var(--border-selected);
    }

Не використовуйте колір межі як єдиний спосіб передавання стану. Наприклад, помилку поля потрібно пояснювати текстом, а вибраний пункт має бути доступним для визначення не лише за кольором.

---

# 13. Borders у таблицях

Таблиці часто потребують меж між рядками або колонками, але надмірна кількість ліній може ускладнювати читання.

## 13.1. Мінімалістичні розділювачі рядків

    .data-table {
        width: 100%;
        border-collapse: collapse;
    }

    .data-table th,
    .data-table td {
        padding: 12px 16px;
        text-align: left;
        border-bottom: 1px solid #e5e7eb;
    }

Цей підхід допомагає читати дані, не створюючи повної сітки навколо кожної комірки.

## 13.2. Межі всієї таблиці

    .data-table {
        width: 100%;
        border: 1px solid #d1d5db;
        border-collapse: collapse;
    }

    .data-table th,
    .data-table td {
        padding: 12px 16px;
        border: 1px solid #e5e7eb;
    }

Повна сітка може бути доречною для складних таблиць, але для простих списків даних часто достатньо горизонтальних розділювачів.

Вибір залежить від кількості колонок, типу даних і способу сканування таблиці.

---

# 14. Borders у навігації та меню

Межі можуть відокремлювати пункти меню або позначати активний розділ.

    .nav-link {
        display: block;
        padding: 12px 16px;
        color: #374151;
        text-decoration: none;
        border-left: 3px solid transparent;
    }

    .nav-link[aria-current="page"] {
        color: #1d4ed8;
        background-color: #eff6ff;
        border-left-color: #2563eb;
    }

У цьому прикладі активний пункт має:
- Інший колір тексту.
- Інший колір фону.
- Виразну ліву межу.

Атрибут `aria-current="page"` доречний, коли посилання відповідає поточній сторінці.

Для меню також можна використовувати `border-bottom`, фон або типографічний акцент.

Не варто одночасно підкреслювати кожен пункт, обрамляти його й додавати сильний фон без потреби.

# 15. Borders у світлій і темній темах

Межі, які добре помітні на білому фоні, можуть бути надто яскравими на темному.

Тому краще використовувати семантичні змінні, значення яких можна змінювати залежно від теми.

    :root {
        color-scheme: light;

        --color-background: #ffffff;
        --color-surface: #f9fafb;

        --color-border-subtle: #f3f4f6;
        --color-border-default: #e5e7eb;
        --color-border-strong: #9ca3af;
    }

    [data-theme="dark"] {
        color-scheme: dark;

        --color-background: #111827;
        --color-surface: #1f2937;

        --color-border-subtle: #273449;
        --color-border-default: #374151;
        --color-border-strong: #6b7280;
    }

Використання:

    .card {
        background-color: var(--color-surface);
        border: 1px solid var(--color-border-default);
    }

    .divider {
        border-top: 1px solid var(--color-border-subtle);
    }

    .panel {
        border: 1px solid var(--color-border-strong);
    }

У темній темі не потрібно робити всі межі світлими. Надто яскраві лінії можуть відволікати увагу.

Перевіряйте:
- Межі карток.
- Поля введення.
- Розділювачі.
- Активні компоненти.
- Індикатори фокусу.
- Межі на кольорових поверхнях.

# 16. Borders і модель коробки CSS

Межі впливають на розміри елемента залежно від значення `box-sizing`.

За замовчуванням використовується:

    box-sizing: content-box;

За такого значення ширина задає розмір вмісту, а межі й відступи додаються зовні.

Наприклад:

    .box {
        width: 200px;
        padding: 20px;
        border: 2px solid #9ca3af;
    }

За `content-box` фактична ширина такого елемента становитиме:

    200px + 20px + 20px + 2px + 2px = 244px

Для передбачуваного компонування часто використовують:

    *,
    *::before,
    *::after {
        box-sizing: border-box;
    }

Тепер задана ширина включає вміст, внутрішні відступи й межі.

**Що запам'ятати:** `border` — не лише декоративна властивість. Вона також може впливати на розміри та компонування елементів.

# 17. Borders і spacing — коли лінія не потрібна

Не кожне розділення потребує межі.

Іноді достатньо збільшити відстань між групами.

Наприклад:

    .section + .section {
        margin-top: 32px;
    }

Або:

    .list {
        display: flex;
        flex-direction: column;
        gap: 16px;
    }

Відступи часто краще підходять для:
- Розділення великих секцій.
- Відокремлення груп карток.
- Побудови вертикального ритму.
- Створення візуального простору.

Межі краще використовувати тоді, коли потрібно чітко показати межу або структуру.

## Як обрати між відступом і лінією

- Якщо елементи належать до однієї групи, може вистачити відступу.
- Якщо потрібно підкреслити поділ усередині групи, використовуйте розділювач.
- Якщо потрібно відокремити сам компонент, використовуйте межу або інший спосіб візуального відокремлення.
- Якщо ліній стає надто багато, спробуйте прибрати частину й посилити відступи.

# 18. Design tokens для меж і розділювачів

У дизайн-системі доцільно централізувати не лише кольори, а й товщину, радіуси та інші параметри меж.

    :root {
        /* Border colors */
        --border-subtle: #f3f4f6;
        --border-default: #e5e7eb;
        --border-strong: #9ca3af;

        /* Semantic borders */
        --border-error: #b91c1c;
        --border-success: #15803d;
        --border-focus: #2563eb;

        /* Border widths */
        --border-width-thin: 1px;
        --border-width-medium: 2px;
        --border-width-thick: 3px;

        /* Border radius */
        --radius-sm: 4px;
        --radius-md: 8px;
        --radius-lg: 12px;
        --radius-xl: 16px;
        --radius-pill: 9999px;
    }

Приклад використання:

    .card {
        border: var(--border-width-thin) solid var(--border-default);
        border-radius: var(--radius-lg);
    }

    .input {
        border: var(--border-width-thin) solid var(--border-strong);
        border-radius: var(--radius-md);
    }

    .input:focus-visible {
        outline: var(--border-width-medium) solid var(--border-focus);
        outline-offset: 2px;
    }

Переваги токенів:
- Єдиний стиль меж у всьому застосунку.
- Швидке оновлення дизайн-системи.
- Менше повторення значень.
- Зручніше створювати теми.
- Легше підтримувати компоненти.

Не потрібно створювати окрему змінну для кожної межі, якщо вона не має окремої ролі.

# 19. Типові помилки

## ❌ 1. Межі навколо кожного елемента

Якщо кожна картка, секція, рядок і текстовий блок має власний контур, інтерфейс стає перевантаженим.

**Рішення:** залишайте межі лише там, де вони допомагають розуміти структуру.

## ❌ 2. Надто темні межі

Виразні лінії можуть конкурувати з основним вмістом.

**Рішення:** використовуйте тонкі й малопомітні межі для другорядних розділень.

## ❌ 3. Надто слабкі межі полів

Поле введення може зливатися з фоном.

**Рішення:** перевіряйте видимість поля в звичайному стані, а не лише під час фокусу.

## ❌ 4. Видалення outline без альтернативи

Користувач клавіатури може втратити можливість визначити активний елемент.

**Рішення:** створюйте помітний стан `:focus-visible`.

## ❌ 5. Занадто багато стилів меж

Суцільні, подвійні, пунктирні й точкові лінії можуть створювати візуальний хаос.

**Рішення:** обмежте кількість стилів і визначте правила їх використання.

## ❌ 6. Межі різного радіуса без системи

Кнопки, поля й картки можуть виглядати так, ніби належать до різних дизайн-систем.

**Рішення:** визначте кілька стандартних значень `border-radius`.

## ❌ 7. Лінії замість відступів

Межі не завжди є найкращим способом групування.

**Рішення:** використовуйте відступи для простору між групами, а лінії — для чіткого розділення.

## ❌ 8. Однакові кольори меж у світлій і темній темах

Межа може стати надто яскравою або майже непомітною.

**Рішення:** визначайте кольори меж окремо для кожної теми.

## ❌ 9. Використання кольору як єдиного індикатора стану

Червона межа без пояснення не повідомляє користувачеві, як виправити помилку.

**Рішення:** додавайте текстове пояснення та, якщо потрібно, інші індикатори.

## ❌ 10. Зміна товщини межі порушує компонування

Наприклад, межа поля змінюється з `1px` на `3px`, і елемент візуально зміщується.

**Рішення:** використовуйте `outline`, `box-shadow` або інший спосіб індикації, якщо зміна товщини спричиняє небажані зміни розмірів.

# 22. Питання для співбесіди

**1. Що таке border у CSS?**

Це властивість, яка створює межу навколо елемента або окремих його сторін.

**2. Чим відрізняється border від divider?**

Border зазвичай позначає межу компонента, а divider — візуально розділяє сусідні елементи. Технічно divider часто реалізують через `border-top`, `border-bottom` або `<hr>`.

**3. Що таке `border-radius`?**

Це CSS-властивість для заокруглення кутів елемента.

**4. Чим відрізняється `border` від `outline`?**

Border входить до моделі коробки елемента та може впливати на його розміри. Outline малюється зовні й не займає місця в моделі коробки.

**5. Що таке subtle border?**

Це малопомітна межа, яка допомагає структурувати інтерфейс, не привертаючи надмірної уваги.

**6. Коли краще використовувати відступи замість розділювачів?**

Коли потрібно створити простір між групами або компонентами, а чітка лінія не додає корисної інформації.

**7. Як створити розділювач між рядками списку?**

Наприклад, за допомогою `border-bottom` і видалення межі в останнього елемента через `:last-child`.

**8. Чому важливо оформлювати `:focus-visible`?**

Це допомагає користувачам клавіатури розуміти, який інтерактивний елемент зараз активний.

**9. Як організувати межі в дизайн-системі?**

Визначити семантичні змінні для кольорів, товщини та радіусів і послідовно застосовувати їх у компонентах.

**10. Чому кольори меж потрібно перевіряти в темній темі?**

Тому що зміна фону впливає на видимість меж. Світлі й темні теми можуть потребувати різних значень токенів.

**11. Чи потрібно обрамляти кожну картку?**

Ні. Межа — лише один із засобів відокремлення. Залежно від композиції можна використовувати фон, тінь, відступи або їх поєднання.

**12. Чому не можна видаляти outline без альтернативи?**

Тому що користувачі клавіатури можуть втратити видимий індикатор активного елемента.

# 24. Мінішпаргалка

| Роль | Призначення |
|---|---|
| `border-subtle` | Ледь помітне розділення |

| `border-success` | Межа успішного стану |

| `border-selected` | Межа вибраного елемента |

    border: 1px solid #e5e7eb;

    border-right: 1px solid #e5e7eb;
    border-bottom: 1px solid #e5e7eb;
    border-left: 1px solid #e5e7eb;

    border-width: 1px;
    border-style: solid;
    border-color: #e5e7eb;
    border-radius: 8px;

    outline: 2px solid #2563eb;
    outline-offset: 3px;

**Практичні правила:**
- Використовуйте межі для структури, а не лише для декору.
- Не обрамляйте кожен елемент без потреби.
- Визначте обмежений набір кольорів і радіусів.
- Використовуйте відступи там, де лінії не потрібні.
- Не видаляйте видимий фокус без альтернативи.
- Перевіряйте межі в усіх темах.
- Застосовуйте семантичні CSS-змінні.

# 25. Головне

**Borders and Dividers — це інструменти структурування інтерфейсу.**

Вони допомагають користувачеві:
- Розуміти межі компонентів.
- Розрізняти сусідні елементи.
- Легше читати списки й таблиці.
- Бачити стани полів і кнопок.
- Орієнтуватися в складних панелях.
- Розпізнавати активні елементи.

Для початку достатньо визначити три рівні меж — subtle, default і strong, обрати кілька радіусів і послідовно використовувати їх у компонентах.

Не менш важливо розуміти, коли межа взагалі не потрібна: іноді достатньо відступу, зміни фону або правильної композиції.

**Якісний інтерфейс не має найбільше ліній — він має саме ті лінії, які допомагають користувачеві.**
