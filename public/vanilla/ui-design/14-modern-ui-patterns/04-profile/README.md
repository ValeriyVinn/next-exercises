# Profile UI — інтерфейси профілю користувача

> Шпаргалка з UI/UX-дизайну для папки `ui-design/14-modern-ui-patterns/04-profile`.

## 1. Що таке Profile UI

**Profile UI** — це інтерфейс, у якому користувач може переглядати інформацію про себе, керувати персональними даними, змінювати налаштування облікового запису та контролювати приватність.

Профіль є важливою частиною багатьох цифрових продуктів:
- соціальних мереж;
- освітніх платформ;
- інтернет-магазинів;
- SaaS-застосунків;
- медичних і психологічних сервісів;
- корпоративних систем;
- особистих кабінетів.

Основна мета Profile UI — зробити інформацію про користувача зрозумілою, а керування нею — простим, безпечним і передбачуваним.

### Основні завдання профілю

- показати, хто користувач;
- відобразити основну інформацію про нього;
- дозволити редагувати персональні дані;
- керувати аватаром та іншими зображеннями;
- показати активність або досягнення, якщо це потрібно продукту;
- керувати налаштуваннями приватності;
- надавати доступ до налаштувань облікового запису;
- показувати статус профілю;
- забезпечувати зрозумілу навігацію до пов'язаних розділів.

Важливо: **Profile UI не обов'язково містить усі ці функції.** Структура залежить від типу продукту, потреб користувачів і вимог до приватності.

---

## 2. Основні поняття

- **User profile** — профіль користувача.
- **Profile page** — сторінка профілю.
- **Account settings** — налаштування облікового запису.
- **Personal information** — персональні дані.
- **Avatar** — зображення, яке представляє користувача.
- **Cover image** — велике фонове зображення профілю.
- **Bio** — короткий опис користувача.
- **Display name** — ім'я, яке відображається в інтерфейсі.
- **Username** — унікальний або інший ідентифікатор користувача, залежно від системи.
- **Profile completion** — рівень заповнення профілю.
- **Privacy settings** — налаштування приватності.
- **Public profile** — профіль, доступний іншим користувачам або відвідувачам.
- **Private profile** — профіль з обмеженим доступом.
- **Edit profile** — режим редагування профілю.
- **Read-only view** — режим перегляду без можливості редагування.
- **Empty state** — стан, коли дані ще не додані.
- **Profile visibility** — налаштування того, хто може бачити профіль або його окремі дані.
- **Activity feed** — стрічка активності користувача.
- **Metadata** — додаткова інформація, наприклад дата реєстрації або роль у системі.

### Profile UI та Account Settings — це не одне й те саме

**Profile UI** зазвичай показує, хто користувач, і містить його основні дані.

**Account Settings** відповідає за керування обліковим записом: пароль, email, безпеку, сповіщення, приватність та інші параметри.

У невеликому застосунку ці розділи можуть бути об'єднані. У великому продукті їх часто розділяють.

## 3. Типи профілів

### 3.1. Personal profile — особистий профіль

Використовується для представлення конкретної людини.

Типові елементи:
- аватар;
- ім'я;
- короткий опис;
- контактна інформація, якщо її дозволено показувати;
- налаштування профілю;
- активність або досягнення.

Приклади:
- профіль учня;
- профіль викладача;
- профіль користувача соціальної мережі;
- профіль клієнта сервісу.

### 3.2. Professional profile — професійний профіль

Використовується для демонстрації професійного досвіду та компетенцій.

Може містити:
- ім'я;
- посаду;
- спеціалізацію;
- короткий опис;
- досвід;
- навички;
- портфоліо;
- посилання на професійні ресурси.

UX-принцип: інформація повинна відповідати меті профілю. Для професійного профілю важливіша релевантність досвіду, ніж декоративні елементи.

### 3.3. Social profile — соціальний профіль

Поширений у соціальних мережах і спільнотах.

Може містити:
- аватар;
- ім'я та username;
- біографію;
- кількість підписників;
- кількість підписок;
- публікації;
- фотографії;
- активність;
- кнопку Follow або Message.

Показуй соціальні показники лише тоді, коли вони мають значення для продукту.

### 3.4. Student profile — профіль учня

Може містити:
- ім'я;
- клас або навчальну групу;
- список курсів;
- прогрес навчання;
- результати завдань;
- досягнення;
- розклад;
- повідомлення від викладачів.

Для освітнього продукту важливо не перевантажувати профіль статистикою. Користувач повинен швидко знаходити інформацію, потрібну для навчання.

### 3.5. Professional dashboard profile — профіль у робочому застосунку

Може містити:
- ім'я;
- роль;
- команду;
- робочий email;
- статус;
- дозволи;
- посилання на налаштування.

У корпоративних системах потрібно чітко відокремлювати дані, які користувач може змінювати самостійно, від тих, що керуються адміністратором.

## 4. Anatomy of a profile page — будова сторінки профілю

Типова сторінка профілю може складатися з таких частин:

    ┌────────────────────────────────────────┐
    │ Header / Navigation                    │
    ├────────────────────────────────────────┤
    │                                        │
    │  [Avatar]    User Name                 │
    │              @username                 │
    │              Short bio                 │
    │                                        │
    │              [Edit profile]            │
    │                                        │
    ├────────────────────────────────────────┤
    │  Overview | Activity | About           │
    ├────────────────────────────────────────┤
    │                                        │
    │  Profile information                   │
    │  Location / Role / Interests           │
    │                                        │
    │  Recent activity                       │
    │                                        │
    └────────────────────────────────────────┘

Основні складові:

1. **Header** — загальна навігація застосунку.
2. **Profile header** — верхня частина профілю.
3. **Avatar** — візуальне представлення користувача.
4. **Display name** — ім'я користувача.
5. **Username** — ідентифікатор, якщо він потрібен.
6. **Bio** — короткий опис.
7. **Primary action** — головна дія, наприклад Edit profile або Follow.
8. **Tabs** — перемикання між розділами профілю.
9. **Profile details** — додаткова інформація.
10. **Activity section** — активність, публікації або прогрес.
11. **Settings access** — перехід до налаштувань.

Не кожен профіль повинен містити всі елементи. Вибирай структуру відповідно до завдань користувача.

---

## 5. Profile header — верхня частина профілю

Profile header — найпомітніша частина сторінки.

Зазвичай містить:
- аватар;
- ім'я;
- username або роль;
- короткий опис;
- одну або кілька основних дій.

### Принципи дизайну

- розташовуй найважливішу інформацію на видному місці;
- не роби аватар більшим, ніж потрібно для конкретного контексту;
- забезпечуй достатній контраст тексту;
- обмежуй довжину біографії, якщо це допомагає зберегти компактність;
- використовуй зрозумілі назви дій;
- не перевантажуй верхню частину другорядними кнопками.

### Приклад

    [Avatar]

    Olena Kovalenko
    @olena_k

    UI/UX designer interested in accessible interfaces.

    [Edit profile]  [Settings]

Для власного профілю основною дією зазвичай буде Edit profile.

Для чужого профілю це може бути Follow, Message або інша дія, характерна для продукту.

---

## 6. Avatar — аватар користувача

Аватар допомагає візуально ідентифікувати користувача.

### Типи аватарів

- фотографія;
- ілюстрація;
- ініціали;
- системне зображення за замовчуванням;
- логотип команди або організації.

### UX-принципи

- використовуй послідовний розмір у межах одного типу інтерфейсу;
- не розтягуй зображення;
- забезпечуй коректне обрізання;
- передбач аватар за замовчуванням;
- дозволяй змінювати зображення, якщо це передбачено продуктом;
- забезпечуй зрозумілий спосіб видалення або заміни аватара;
- не покладайся лише на аватар для розрізнення користувачів.

### Приклад HTML

    <img
      class="profile-avatar"
      src="/images/user-avatar.jpg"
      alt="Profile photo of Olena Kovalenko"
      width="96"
      height="96"
    >

Якщо зображення є суто декоративним і поруч уже є ім'я користувача, для нього може бути доречним порожній `alt`. Вибір залежить від контексту й того, яку інформацію зображення передає.

### CSS для аватара

    .profile-avatar {
      width: 6rem;
      aspect-ratio: 1;
      object-fit: cover;
      border-radius: 50%;
    }

`object-fit: cover` допомагає заповнити область зображення без спотворення пропорцій.

---

## 7. Cover image — обкладинка профілю

Cover image — велике зображення у верхній частині профілю.

Часто використовується в соціальних мережах або професійних профілях.

### Рекомендації

- визначай співвідношення сторін;
- передбачай обрізання на різних екранах;
- перевіряй читабельність тексту поверх зображення;
- не розміщуй важливу інформацію в областях, які можуть обрізатися;
- забезпечуй можливість заміни обкладинки, якщо це потрібно;
- не додавай обкладинку, якщо вона не допомагає користувачеві.

### Приклад CSS

    .profile-cover {
      width: 100%;
      aspect-ratio: 3 / 1;
      overflow: hidden;
      border-radius: 1rem;
    }

    .profile-cover img {
      width: 100%;
      height: 100%;
      object-fit: cover;
    }

Для мобільних екранів можна змінити співвідношення сторін:

    @media (max-width: 40rem) {
      .profile-cover {
        aspect-ratio: 2 / 1;
      }
    }

## 8. Display name, username та bio

Ці три елементи виконують різні функції.

### Display name

Ім'я, яке бачить користувач у профілі.

Приклад:

    Olena Kovalenko

### Username

Ідентифікатор, який може використовуватися в URL, пошуку або згадках.

Приклад:

    @olena_k

Username не обов'язково має існувати в кожному продукті.

### Bio

Короткий опис користувача.

Приклад:

    Frontend developer learning React and TypeScript.

### UX-принципи

- використовуй зрозумілі підписи;
- не змішуй ім'я та системний ідентифікатор;
- визначай обмеження довжини тексту;
- показуй лічильник символів, якщо це допомагає;
- не обрізай важливий текст без можливості перегляду;
- пояснюй правила username, якщо вони існують;
- перевіряй доступність username до завершення форми або показуй результат перевірки.

### Приклад лічильника

    Bio
    [Frontend developer learning React...]

    42 / 160 characters

Лічильник повинен оновлюватися відповідно до фактичного тексту, а не бути декоративним елементом.

## 9. Profile information — інформація профілю

У цьому розділі користувач переглядає свої дані.

Залежно від продукту це можуть бути:
- ім'я;
- дата народження;
- місце проживання;
- мова;
- професія;
- навчальна група;
- інтереси;
- контактні дані;
- посилання;
- опис;
- статус.

### Принцип мінімізації даних

Не додавай поле лише тому, що воно може бути корисним колись.

Для кожного поля запитай себе:

1. Для чого потрібна ця інформація?
2. Хто її використовує?
3. Чи обов'язково її показувати?
4. Чи може користувач приховати її?
5. Чи можна працювати без її збирання?

Особливо обережно стався до персональних і чутливих даних.

### Read-only view

У режимі перегляду дані можуть бути представлені так:

    Full name
    Olena Kovalenko

    Email
    olena@example.com

    Language
    Ukrainian

    Time zone
    Europe/Kyiv

Використовуй послідовні назви полів і зрозуміле групування.

## 10. Edit profile — редагування профілю

Редагування профілю дозволяє змінювати персональну інформацію.

### Типова структура

    Edit profile

    Profile photo
    [Current avatar] [Change photo]

    Display name
    [Olena Kovalenko]

    Username
    [olena_k]

    Bio
    [Frontend developer...]

    [Cancel] [Save changes]

### UX-принципи

- чітко показуй режим редагування;
- використовуй підписи полів;
- групуй пов'язані дані;
- пояснюй обмеження введення;
- показуй помилки біля відповідних полів;
- забезпечуй збереження лише після явної дії, якщо немає іншої зрозумілої моделі;
- повідомляй про успішне збереження;
- попереджай про втрату незбережених змін, якщо це доречно.

### Save та Cancel

Основна дія — Save changes.

Допоміжна дія — Cancel.

Вони повинні мати різний візуальний пріоритет.

Не використовуй однаково помітні кнопки для дій, які мають різну важливість, якщо це створює плутанину.

### Автоматичне збереження

Auto-save може бути зручним для окремих налаштувань, але потребує зрозумілого зворотного зв'язку.

Приклад:

    Saving changes...

    Changes saved.

Користувач повинен розуміти, чи збережені зміни, особливо перед переходом на іншу сторінку.

## 11. Profile completion — заповнення профілю

Деякі продукти показують, наскільки повно користувач заповнив профіль.

Приклад:

    Complete your profile

    Profile completion: 75%

    ✓ Add your name
    ✓ Add a profile photo
    ✓ Add a short bio
    ○ Add your interests

    [Complete profile]

### Коли це корисно

- під час onboarding;
- у навчальних платформах;
- у професійних каталогах;
- у сервісах, де додаткова інформація покращує персоналізацію.

### Коли це не потрібно

- якщо профіль уже виконує свою функцію;
- якщо додаткові дані не приносять користі;
- якщо індикатор створює зайвий тиск;
- якщо користувач не може або не хоче заповнювати необов'язкові поля.

### UX-принципи

- пояснюй, чому варто додати інформацію;
- розрізняй обов'язкові та необов'язкові кроки;
- не змушуй заповнювати дані без потреби;
- використовуй реальний стан виконання;
- надавай прямий перехід до незаповненого поля.

Не перетворюй відсоток заповнення на самоціль. Повнота профілю важлива лише тоді, коли допомагає користувачеві або продукту.

---

## 12. Profile navigation — навігація профілю

Якщо профіль містить багато інформації, розділи її на логічні частини.

Типові варіанти:
- Overview;
- About;
- Activity;
- Posts;
- Courses;
- Achievements;
- Settings.

### Tabs

Tabs використовуються для перемикання між пов'язаними розділами одного контексту.

Приклад:

    Overview | Activity | About

Рекомендації:
- використовуй короткі назви;
- показуй активний розділ;
- підтримуй клавіатурну навігацію;
- не створюй десятки вкладок;
- не використовуй tabs для непов'язаних завдань.

### Sidebar navigation

Бічна навігація підходить для складного особистого кабінету.

Приклад:

    Profile
    ├── Overview
    ├── Personal information
    ├── Account settings
    ├── Privacy
    └── Security

Використовуй sidebar, якщо розділів достатньо багато, щоб окреме меню було виправданим.

### Важливий принцип

Не змішуй усі налаштування з публічним представленням профілю.

Користувач повинен легко розрізняти:
- що бачать інші;
- що він бачить сам;
- що можна змінити;
- які параметри впливають на безпеку.

---

## 13. Privacy settings — приватність профілю

Налаштування приватності визначають, хто може бачити профіль або окремі дані.

Приклади:
- публічний профіль;
- приватний профіль;
- видимість email;
- видимість дати народження;
- доступність профілю в пошуку;
- можливість переглядати активність;
- дозволи на перегляд публікацій.

### Приклад інтерфейсу

    Profile visibility

    (●) Public
        Anyone can view your public profile.

    ( ) Private
        Only approved users can view restricted information.

    [Save changes]

Це умовний приклад. Реальні значення та правила залежать від продукту.

### UX-принципи

- пояснюй наслідки кожного параметра;
- не використовуй неоднозначні формулювання;
- показуй поточний стан;
- не змінюй важливі налаштування непомітно;
- повідомляй, коли зміни набули чинності;
- не роби приватний режим складним для пошуку;
- враховуй, що окремі поля можуть мати різні рівні видимості.

### Privacy by default

Приватність має враховуватися вже на етапі дизайну.

Не роби персональні дані публічними за замовчуванням лише заради простішої реалізації або більшої кількості заповнених профілів.

## 14. Empty states — порожні стани

Порожній стан виникає, коли профіль ще не містить інформації або певний розділ не має даних.

Приклад:

    No activity yet

    Your recent activity will appear here.

    [Explore courses]

Інший приклад:

    Add a profile photo

    Help others recognize you by adding a photo.

    [Upload photo]

### Принципи дизайну

- пояснюй, чому розділ порожній;
- пропонуй корисну наступну дію;
- не показуй помилку, якщо відсутність даних є нормальною;
- не використовуй декоративну ілюстрацію замість пояснення;
- не змушуй користувача заповнювати необов'язкові дані.

### Типи empty states

1. **First-use state** — користувач ще не додав дані.
2. **No-results state** — пошук не знайшов результатів.
3. **Filtered state** — вибрані фільтри не дають результатів.
4. **Unavailable state** — дані тимчасово недоступні.
5. **Permission state** — користувач не має доступу до вмісту.

Не плутай порожній стан із помилкою завантаження. Це різні ситуації, які потребують різних повідомлень.

## 17. Profile actions — дії в профілі

Доступні дії залежать від того, чи переглядає користувач власний профіль або чужий.

### Власний профіль

Можливі дії:
- Edit profile;
- Change photo;
- Settings;
- Preview public profile;
- Manage privacy.

### Чужий профіль

Можливі дії:
- Follow;
- Unfollow;
- Message;
- Share profile;
- Report;
- Block.

Не всі ці дії потрібні в кожному продукті.

### Primary та secondary actions

Primary action — головна дія для поточного контексту.

Secondary actions — додаткові дії.

Наприклад, у власному профілі:

    [Edit profile]  [Settings]

У соціальній мережі:

    [Follow]  [Message]

Не надавай усім діям однакову візуальну вагу, якщо одна з них є очевидно головною.

### Destructive actions

Деякі дії можуть мати серйозні наслідки:
- видалення профілю;
- блокування користувача;
- видалення публікацій;
- відкликання доступу.

Рекомендації:
- чітко називай дію;
- пояснюй наслідки;
- вимагай підтвердження, якщо це необхідно;
- не використовуй оманливі кнопки;
- відокремлюй незворотні дії від звичайного редагування.

## 20. Accessibility — доступність профілю

Профіль повинен бути зручним для користувачів, які використовують клавіатуру, екранні читачі, збільшення тексту або інші допоміжні технології.

### Основні правила

- використовуй семантичні HTML-елементи;
- дотримуйся логічної структури заголовків;
- пов'язуй labels із полями;
- забезпечуй видимий фокус;
- використовуй зрозумілі назви кнопок;
- забезпечуй достатній контраст;
- не передавай статус лише кольором;
- підтримуй клавіатурну навігацію;
- не обрізай текст без можливості перегляду;
- забезпечуй альтернативний текст для змістовних зображень;
- перевіряй роботу tabs та інших інтерактивних компонентів.

### Семантична структура

    <main>
      <section aria-labelledby="profile-title">
        <h1 id="profile-title">Olena Kovalenko</h1>

        <p>Frontend developer learning React.</p>

        <a href="/profile/edit">Edit profile</a>
      </section>

      <section aria-labelledby="about-title">
        <h2 id="about-title">About</h2>

        <p>Interested in accessible web interfaces.</p>
      </section>
    </main>

Це спрощений приклад. Структура повинна відповідати реальному змісту сторінки.

### Клавіатурна навігація

Користувач повинен мати змогу:
- переходити між інтерактивними елементами;
- активувати кнопки;
- редагувати поля;
- перемикати вкладки;
- бачити фокус;
- закривати діалоги відповідним способом;
- завершувати основні дії без миші.

## 21. Profile UI states — стани інтерфейсу

Продумай не лише стандартний профіль, а й альтернативні стани.

### Default state

Профіль має всі необхідні дані й готовий до перегляду.

### Loading state

Дані завантажуються.

Приклад:

    Loading profile...

Рекомендації:
- показуй, що система працює;
- за можливості зберігай структуру майбутнього контенту;
- не створюй зайвих стрибків компонування.

### Empty state

Профіль або його розділ ще не містить даних.

Приклад:

    Your bio is empty.

    Add a short description to introduce yourself.

### Error state

Дані не вдалося завантажити або зберегти.

Приклад:

    We couldn't load your profile.

    Please try again.

    [Retry]

### Edit state

Користувач змінює інформацію.

Потрібно:
- показувати поля;
- пояснювати обмеження;
- відображати помилки;
- надавати можливість зберегти або скасувати зміни.

### Saving state

Зміни зберігаються.

Приклад:

    Saving changes...

### Success state

Зміни успішно збережено.

Приклад:

    Your profile has been updated.

### Restricted state

Користувач не має доступу до певної інформації.

Приклад:

    This profile is private.

    You don't have permission to view this content.

Не показуй повідомлення про відсутність доступу, якщо справжня причина полягає в помилці сервера.

## 27. Common mistakes — типові помилки

### UX-помилки

- занадто багато полів у профілі;
- незрозумілий перехід до редагування;
- відсутнє підтвердження збереження;
- незрозуміло, які дані бачать інші;
- важливі налаштування заховані в неочевидних місцях;
- користувач не може скасувати незбережені зміни;
- порожні стани не пояснюють наступний крок;
- профіль перевантажений другорядною статистикою.

### UI-помилки

- аватар розтягується;
- текст має недостатній контраст;
- кнопки не мають чіткої ієрархії;
- занадто багато карток;
- довгі імена обрізаються без пояснення;
- відступи непослідовні;
- мобільна версія незручна;
- іконки незрозумілі без тексту;
- відсутні стани завантаження й помилок.

### Privacy-помилки

- зайві персональні дані збираються без потреби;
- email або інша приватна інформація показується публічно без зрозумілого контролю;
- налаштування видимості незрозумілі;
- користувач не знає, хто може переглядати профіль;
- система не пояснює наслідки важливих змін;
- публічні та приватні дані не розділені належним чином.

## 28. Profile UI checklist

Перед завершенням дизайну перевір:

### Structure

- [ ] Профіль має зрозумілий заголовок.
- [ ] Ім'я та додаткова інформація добре розрізняються.
- [ ] Основна дія легко знаходиться.
- [ ] Пов'язані дані згруповані.
- [ ] Навігація відповідає складності профілю.

### Content

- [ ] Показуються лише потрібні поля.
- [ ] Порожні стани мають зрозумілі пояснення.
- [ ] Тексти короткі й однозначні.
- [ ] Довгі імена та описи не ламають компонування.
- [ ] Дані відображаються послідовно.

### Editing

- [ ] Є зрозумілий режим редагування.
- [ ] Labels пов'язані з полями.
- [ ] Помилки пояснюють, як їх виправити.
- [ ] Save і Cancel легко розрізнити.
- [ ] Є підтвердження успішного збереження.
- [ ] Незбережені зміни обробляються передбачувано.

### Visual design

- [ ] Є чітка візуальна ієрархія.
- [ ] Відступи послідовні.
- [ ] Картки використовуються доречно.
- [ ] Аватари та обкладинки не спотворюються.
- [ ] Контраст достатній.
- [ ] Іконки зрозумілі.

### Responsive

- [ ] Профіль працює на мобільному пристрої.
- [ ] Немає горизонтального прокручування без потреби.
- [ ] Кнопки не накладаються одна на одну.
- [ ] Довгі тексти залишаються читабельними.
- [ ] Навігація адаптується до вузького екрана.

### Accessibility

- [ ] Використано семантичні елементи.
- [ ] Заголовки мають логічну структуру.
- [ ] Фокус помітний.
- [ ] Усі важливі дії доступні з клавіатури.
- [ ] Зображення мають відповідний альтернативний текст.
- [ ] Статуси не передаються лише кольором.

### Privacy

- [ ] Збираються лише необхідні дані.
- [ ] Зрозуміло, які поля публічні.
- [ ] Є потрібні налаштування видимості.
- [ ] Важливі зміни мають зрозумілі наслідки.
- [ ] Приватні дані не розкриваються без потреби.

## 29. Як тренуватися на практиці

Створи три версії профілю для одного вигаданого користувача.

### Варіант A — Minimal profile

Елементи:
- аватар;
- ім'я;
- короткий опис;
- кнопка Edit profile;
- кілька основних полів.

Мета: навчитися створювати просту структуру без зайвих елементів.

### Варіант B — Social profile

Елементи:
- аватар;
- ім'я;
- username;
- біографія;
- статистика;
- активність;
- Follow або Message.

Мета: навчитися працювати з великою кількістю інформації та діями.

### Варіант C — Account profile

Елементи:
- персональні дані;
- зміна аватара;
- редагування;
- налаштування приватності;
- стани помилок;
- підтвердження збереження.

Мета: навчитися проєктувати форми та сценарії керування даними.

### Що порівнювати

- чи зрозуміла головна мета сторінки;
- наскільки легко знайти основну дію;
- чи не перевантажений інтерфейс;
- чи зрозумілі назви розділів;
- як виглядає профіль без даних;
- як працює довгий текст;
- чи зручне компонування на мобільному пристрої;
- чи зрозуміло, які дані бачать інші;
- чи можна безпечно скасувати або виправити зміни.

## 33. Головне, що потрібно запам'ятати

1. **Profile UI — це не просто аватар та ім'я, а спосіб переглядати й керувати інформацією користувача.**
2. Відокремлюй публічне представлення профілю від приватних налаштувань.
3. Показуй лише ті дані, які справді потрібні.
4. Створюй чітку візуальну ієрархію.
5. Зроби основні дії помітними, а другорядні — менш акцентними.
6. Передбачай порожні стани, помилки, завантаження та успішне збереження.
7. Забезпечуй зручне редагування даних і зрозуміле підтвердження змін.
8. Адаптуй компонування до мобільних пристроїв.
9. Доступність і приватність мають бути частиною дизайну від початку.
10. Не додавай статистику, поля та декоративні елементи, якщо вони не допомагають користувачеві.

**Основний принцип:** хороший профіль показує потрібну інформацію, допомагає легко керувати нею та дає користувачеві зрозумілий контроль над власними даними.
