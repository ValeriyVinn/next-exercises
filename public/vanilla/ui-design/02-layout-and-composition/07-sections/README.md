# 07. Sections — Секції в UI-дизайні

## 1. Що таке Sections?

**Sections (секції)** — це логічно відокремлені частини сторінки, кожна з яких виконує певне завдання та допомагає організувати контент у зрозумілу структуру.

Секції використовують для поділу сторінки на змістові блоки, наприклад:
- Hero — головний вступний блок;
- About — інформація про продукт або компанію;
- Features — переваги та можливості;
- Services — послуги;
- Testimonials — відгуки;
- Pricing — тарифи;
- FAQ — поширені запитання;
- Contact — контактна інформація;
- Footer — нижня частина сторінки.

Секції допомагають:
- структурувати інформацію;
- створювати зрозумілу візуальну ієрархію;
- керувати увагою користувача;
- формувати послідовність ознайомлення з продуктом;
- підтримувати узгодженість дизайну;
- адаптувати сторінку до різних пристроїв.

### Простими словами

Уяви головну сторінку навчальної платформи.

Користувач відкриває сторінку й послідовно бачить:

1. Заголовок платформи та кнопку початку навчання.
2. Короткий опис платформи.
3. Перелік навчальних напрямів.
4. Переваги навчання.
5. Відгуки студентів.
6. Контактну інформацію.

Кожна з цих частин може бути окремою секцією.

**Секція — це не просто прямокутник із фоном. Це змістова одиниця сторінки, яка допомагає користувачеві зрозуміти певну частину інформації.**

---

## 2. Основні терміни

### 2.1. Section — секція

Логічний блок сторінки, присвячений певній темі або завданню.

Наприклад:

    <section>
        <h2>Наші переваги</h2>
        <p>Навчайтеся у зручному темпі.</p>
    </section>

Секція може містити:
- заголовок;
- текст;
- зображення;
- картки;
- кнопки;
- списки;
- форми;
- інші компоненти.

### 2.2. Section Heading — заголовок секції

Заголовок пояснює, про що йдеться в конкретній частині сторінки.

Приклади:
- Наші послуги;
- Як це працює;
- Популярні курси;
- Відгуки студентів;
- Часті запитання.

Хороший заголовок:
- короткий і зрозумілий;
- відповідає змісту секції;
- допомагає швидко просканувати сторінку;
- логічно продовжує загальну структуру.

### 2.3. Section Spacing — відступи між секціями

Це вертикальний простір між сусідніми змістовими блоками.

Відступи допомагають:
- відокремлювати теми;
- створювати ритм сторінки;
- не допускати візуального перевантаження;
- показувати, де закінчується одна тема й починається інша.

Приклад:

    .section {
        padding-block: 64px;
    }

`padding-block` задає внутрішні відступи зверху та знизу секції.

Важливо: внутрішній відступ секції та відстань між двома секціями — не зовсім одне й те саме. Вони можуть створювати схожий візуальний ефект, але мають різне призначення.

### 2.4. Section Background — фон секції

Фон допомагає відокремити секцію від сусідніх блоків.

Варіанти:
- основний фон сторінки;
- контрастний фон;
- світлий нейтральний фон;
- градієнт;
- зображення;
- текстура;
- декоративні елементи.

Фон має допомагати сприйняттю контенту, а не відволікати від нього.

### 2.5. Section Container — контейнер секції

Контейнер обмежує ширину контенту та допомагає вирівнювати його відносно інших секцій.

    .container {
        width: min(100% - 32px, 1200px);
        margin-inline: auto;
    }

Контейнер може містити:
- заголовок;
- текст;
- сітку карток;
- зображення;
- форму;
- інші компоненти.

Сама секція при цьому може займати всю ширину екрана.

---

## 3. Section та інші рівні структури сторінки

Щоб правильно проєктувати сторінки, важливо розуміти різницю між сторінкою, секцією, компонентом та елементом.

| Рівень | Що означає | Приклад |
|---|---|---|
| Page | Уся сторінка | Головна сторінка платформи |
| Section | Змістова частина сторінки | Секція курсів |
| Component | Повторно використовуваний блок | Картка курсу |
| Element | Окремий елемент інтерфейсу | Заголовок або кнопка |

Приклад структури:

    HomePage
    ├── Header
    ├── HeroSection
    ├── FeaturesSection
    │   ├── FeatureCard
    │   ├── FeatureCard
    │   └── FeatureCard
    ├── CoursesSection
    │   ├── CourseCard
    │   ├── CourseCard
    │   └── CourseCard
    ├── TestimonialsSection
    └── Footer

Така структура допомагає мислити не окремими кнопками чи картками, а цілою сторінкою.

**Section відповідає за змістову організацію сторінки, а Component — за реалізацію окремої частини інтерфейсу.**

## 4. Основні типи секцій

### 4.1. Hero Section — головна вступна секція

Hero — це помітна частина сторінки, яку користувач зазвичай бачить першою.

Вона має швидко пояснити:
- що це за продукт;
- для кого він призначений;
- яку користь пропонує;
- що користувач може зробити далі.

Типові елементи:
- головний заголовок;
- короткий опис;
- основна кнопка дії;
- додаткова кнопка;
- ілюстрація або фотографія;
- візуальна демонстрація продукту.

Приклад структури:

    <section class="hero">
        <div class="container hero__layout">
            <div class="hero__content">
                <h1>Навчайтеся програмування у власному темпі</h1>

                <p>
                    Практичні завдання та зрозумілі матеріали
                    для вашого професійного розвитку.
                </p>

                <a href="#courses" class="button">
                    Переглянути курси
                </a>
            </div>

            <div class="hero__visual">
                <img
                    src="/images/learning-platform.png"
                    alt="Навчальна платформа на екрані ноутбука"
                >
            </div>
        </div>
    </section>

Ключові принципи:
- один зрозумілий головний меседж;
- помітна основна дія;
- достатньо вільного простору;
- чітке співвідношення тексту та зображення;
- хороша адаптація до мобільних пристроїв.

Не варто перевантажувати Hero кількома рівнозначними заголовками та великою кількістю кнопок.

### 4.2. About Section — інформація про продукт

Пояснює, хто ви, що створюєте або яку проблему вирішуєте.

Може містити:
- короткий опис;
- історію проєкту;
- місію;
- фотографію;
- статистику;
- посилання на докладнішу інформацію.

Основне завдання — дати користувачеві потрібний контекст.

### 4.3. Features Section — переваги та можливості

Показує основні функції або переваги продукту.

Наприклад, для навчальної платформи:
- практичні вправи;
- послідовна програма;
- доступ із різних пристроїв.

Часто використовується сітка карток.

    .features-grid {
        display: grid;
        grid-template-columns: repeat(3, minmax(0, 1fr));
        gap: 24px;
    }

Кожна картка може містити:
- іконку;
- короткий заголовок;
- пояснення;
- за потреби — посилання.

Не потрібно перетворювати кожне речення на окрему картку. Обирай структуру, яка допомагає швидко порівнювати інформацію.

### 4.4. Services Section — секція послуг

Показує, що саме пропонує компанія або сервіс.

Може використовувати:
- картки послуг;
- список;
- таблицю;
- категорії;
- двоколонковий макет;
- послідовність кроків.

Для кожної послуги варто зрозуміло пояснити її призначення.

### 4.5. How It Works Section — як це працює

Пояснює процес використання продукту.

Наприклад:

1. Зареєструйтеся.
2. Оберіть навчальний курс.
3. Виконуйте практичні завдання.
4. Відстежуйте прогрес.

Для цієї секції добре підходять:
- нумеровані кроки;
- горизонтальна послідовність;
- вертикальний timeline;
- картки;
- проста схема.

Головне — щоб користувач міг легко зрозуміти послідовність дій.

### 4.6. Testimonials Section — відгуки

Містить відгуки користувачів, студентів або клієнтів.

Може включати:
- текст відгуку;
- ім'я автора;
- фотографію;
- посаду або контекст;
- посилання на першоджерело, якщо воно доречне.

Використовуй реальні відгуки та не створюй враження, що вигадані цитати є справжніми.

### 4.7. Pricing Section — тарифи

Допомагає порівняти плани або варіанти оплати.

Типові елементи:
- назва плану;
- ціна;
- період оплати;
- список можливостей;
- обмеження;
- кнопка вибору.

Для порівняння тарифів особливо важливі:
- однакова структура карток;
- зрозуміле позначення відмінностей;
- читабельність;
- доступність інформації без необхідності здогадуватися.

### 4.8. FAQ Section — поширені запитання

Відповідає на типові запитання користувачів.

Часто реалізується через акордеон.

Приклад HTML:

    <section class="faq" aria-labelledby="faq-title">
        <div class="container">
            <h2 id="faq-title">Поширені запитання</h2>

            <details>
                <summary>Чи потрібен досвід програмування?</summary>
                <p>
                    Ні. Почати можна з базових матеріалів
                    і поступово переходити до складніших завдань.
                </p>
            </details>
        </div>
    </section>

Елемент `details` дозволяє створити простий розкривний блок без JavaScript.

### 4.9. CTA Section — заклик до дії

CTA означає Call to Action — заклик до дії.

Це секція, яка пропонує користувачеві зробити конкретний наступний крок.

Приклади:
- Зареєструватися;
- Почати навчання;
- Замовити консультацію;
- Переглянути каталог;
- Зв'язатися з нами.

CTA може бути частиною Hero або окремою секцією наприкінці сторінки.

### 4.10. Contact Section — контакти

Допомагає користувачеві зв'язатися з компанією чи організацією.

Може містити:
- адресу електронної пошти;
- телефон;
- адресу;
- форму зворотного зв'язку;
- години роботи;
- посилання на соціальні мережі.

Контактні дані мають бути актуальними, зрозумілими та доступними.

### 4.11. Footer Section — нижня частина сторінки

Footer зазвичай розташований наприкінці сторінки та містить допоміжну інформацію.

Типові елементи:
- логотип;
- навігаційні посилання;
- контакти;
- політика конфіденційності;
- умови використання;
- авторські права;
- соціальні мережі.

Footer може мати кілька колонок на широкому екрані та переходити до вертикального компонування на мобільному.

## 5. Інформаційна архітектура секцій

**Information Architecture (IA)** — це організація інформації так, щоб користувач міг зрозуміти її структуру та знайти потрібне.

Перш ніж створювати секції, потрібно визначити:
- які теми мають бути на сторінці;
- у якій послідовності їх показувати;
- що є основною інформацією;
- що потрібно пояснити додатково;
- де користувач має виконати дію.

Наприклад, головна сторінка навчальної платформи може мати таку структуру:

    HomePage
    ├── Header
    ├── Hero
    ├── Benefits
    ├── Popular Courses
    ├── How It Works
    ├── Testimonials
    ├── FAQ
    ├── Final CTA
    └── Footer

Це лише один можливий сценарій. Якщо для продукту важливіше показати каталог, його можна розмістити раніше.

### Принцип послідовності

Секції мають утворювати зрозумілий шлях користувача.

Для кожної секції запитай себе:

1. Що користувач має тут зрозуміти?
2. Чому ця інформація важлива?
3. Чи потрібна вона саме в цьому місці?
4. Що користувач має зробити або знати після перегляду?

Якщо секція не додає корисної інформації, не допомагає виконати завдання й не підтримує основну мету сторінки, можливо, її варто об'єднати з іншою або прибрати.

## 6. Візуальна ієрархія всередині секції

Секція має власну внутрішню ієрархію.

Зазвичай вона може виглядати так:

    Section
    ├── Eyebrow / Label
    ├── Heading
    ├── Description
    ├── Main Content
    └── CTA

### 6.1. Eyebrow — надзаголовок

Короткий текст над головним заголовком.

Наприклад:

    <p class="section-eyebrow">НАВЧАННЯ</p>
    <h2>Оберіть свій напрям</h2>

Він може уточнювати категорію або контекст, але не є обов'язковим.

### 6.2. Heading — заголовок

Заголовок передає головну думку секції.

Він має бути помітним і зрозумілим.

### 6.3. Description — опис

Короткий текст, який розкриває зміст заголовка.

Опис не повинен дублювати заголовок іншими словами без додаткової користі.

### 6.4. Main Content — основний контент

Це центральна частина секції:
- список;
- картки;
- текст;
- форма;
- зображення;
- таблиця;
- відео.

### 6.5. CTA — дія

Кнопка або посилання, яке допомагає перейти до наступного кроку.

Не кожна секція повинна мати CTA. Додавай його, якщо він логічно випливає зі змісту.

---

## 7. Відступи та вертикальний ритм

**Vertical Rhythm (вертикальний ритм)** — це послідовна організація відстаней між елементами сторінки.

Якщо всі секції мають випадкові відступи, сторінка може виглядати неузгодженою.

### 7.1. Внутрішні відступи секції

    .section {
        padding-block: 64px;
    }

На великих екранах секція може мати більше вертикального простору, а на мобільних — менше.

    .section {
        padding-block: 64px;
    }

    @media (max-width: 600px) {
        .section {
            padding-block: 40px;
        }
    }

### 7.2. Відступи між елементами

    .section__header {
        margin-bottom: 32px;
    }

    .section__title {
        margin-bottom: 16px;
    }

    .section__description {
        margin-bottom: 24px;
    }

Це приклад можливого підходу. Не потрібно механічно використовувати ті самі значення в кожній секції.

### 7.3. Використання spacing scale

У дизайн-системі можна визначити шкалу відступів:

    :root {
        --space-1: 4px;
        --space-2: 8px;
        --space-3: 12px;
        --space-4: 16px;
        --space-5: 24px;
        --space-6: 32px;
        --space-7: 48px;
        --space-8: 64px;
    }

Використання:

    .section {
        padding-block: var(--space-8);
    }

    .section__header {
        margin-bottom: var(--space-6);
    }

Переваги:
- узгоджені відстані;
- простіше змінювати дизайн;
- менше випадкових значень;
- зрозуміліші правила для всієї сторінки.

## 8. Фони секцій і візуальне розділення

Секції можна відокремлювати різними способами.

### 8.1. Зміна кольору фону

    .section--default {
        background: #ffffff;
    }

    .section--muted {
        background: #f5f6f8;
    }

Це допомагає створити візуальне чергування блоків.

### 8.2. Межі

    .section {
        border-bottom: 1px solid #e5e7eb;
    }

Межі корисні, коли потрібно розділити блоки без значної зміни кольору фону.

### 8.3. Простір

Іноді достатньо збільшити відстань між секціями, не додаючи меж чи різних фонів.

Це особливо доречно для мінімалістичних інтерфейсів.

### 8.4. Зображення або декоративні елементи

Hero-секція може використовувати фонове зображення, градієнт або декоративну форму.

Важливо:
- забезпечити контраст тексту;
- не приховувати важливу інформацію;
- не використовувати декоративне зображення як єдине джерело змісту;
- перевіряти композицію на мобільних пристроях.

**Принцип:** візуальне розділення має допомагати розуміти структуру сторінки, а не перетворювати її на набір випадкових кольорових прямокутників.

---

## 9. Секції та композиція

Композиція визначає, як елементи розташовані один відносно одного.

Секція може використовувати різні композиційні прийоми.

### 9.1. Centered Layout — центральна композиція

Заголовок і контент розташовані по центру.

    .section__header {
        max-width: 680px;
        margin-inline: auto;
        text-align: center;
    }

Підходить для:
- коротких вступів;
- секцій із перевагами;
- CTA;
- деяких форм;
- простих інформаційних блоків.

### 9.2. Split Layout — розділена композиція

Контент поділений на дві області.

    .split-section {
        display: grid;
        grid-template-columns: 1fr 1fr;
        gap: 48px;
        align-items: center;
    }

Підходить для:
- тексту та зображення;
- опису продукту;
- демонстрації функції;
- історії компанії.

### 9.3. Card Grid — сітка карток

    .section__grid {
        display: grid;
        grid-template-columns: repeat(3, minmax(0, 1fr));
        gap: 24px;
    }

Підходить для:
- послуг;
- курсів;
- можливостей;
- відгуків;
- категорій.

### 9.4. List Layout — композиція списком

Список зручний, коли користувачеві потрібно швидко переглянути послідовність пунктів або порівняти короткі твердження.

### 9.5. Editorial Layout — редакційна композиція

Використовується для статей, історій, пояснень і великих текстових блоків.

Може містити:
- широку текстову колонку;
- підзаголовки;
- зображення;
- цитати;
- додаткову колонку з примітками.

Композиція має відповідати типу інформації, а не лише естетичним уподобанням.

## 10. Секції та адаптивний дизайн

**Responsive Sections** — це секції, які зберігають свою зрозумілість і зручність на різних розмірах екрана.

Адаптивність може змінювати:
- кількість колонок;
- ширину контейнера;
- розташування зображення;
- розмір заголовків;
- вертикальні відступи;
- порядок візуального компонування;
- спосіб відображення додаткового контенту.

### 10.1. Дві колонки на desktop, одна на mobile

    .split-section {
        display: grid;
        grid-template-columns: 1fr 1fr;
        gap: 48px;
        align-items: center;
    }

    @media (max-width: 700px) {
        .split-section {
            grid-template-columns: 1fr;
            gap: 24px;
        }
    }

### 10.2. Адаптивні картки

    .cards {
        display: grid;
        grid-template-columns: repeat(
            auto-fit,
            minmax(min(100%, 240px), 1fr)
        );
        gap: 24px;
    }

Це дозволяє браузеру автоматично визначати кількість колонок залежно від доступної ширини.

### 10.3. Адаптивні відступи

    .section {
        padding-block: clamp(40px, 6vw, 88px);
    }

`clamp()` визначає:
- мінімальне значення;
- гнучке значення;
- максимальне значення.

У цьому прикладі вертикальні відступи плавно змінюються залежно від ширини viewport, але залишаються в межах 40–88 px.

### 10.4. Адаптивна типографіка

    .hero__title {
        font-size: clamp(2rem, 4vw, 4rem);
        line-height: 1.1;
    }

Це допомагає заголовку змінюватися залежно від ширини екрана.

Однак завжди перевіряй:
- чи не стає заголовок надто великим;
- чи не утворюються незручні переноси;
- чи достатньо місця для кнопок;
- чи зберігається читабельність.

## 11. Семантичний HTML для секцій

У HTML є спеціальний елемент `<section>`.

Він призначений для тематично згрупованого контенту, зазвичай із заголовком.

Приклад:

    <section aria-labelledby="courses-title">
        <div class="container">
            <h2 id="courses-title">Популярні курси</h2>

            <p>
                Оберіть напрям, який відповідає вашим цілям.
            </p>

            <div class="courses-grid">
                <!-- Картки курсів -->
            </div>
        </div>
    </section>

### 11.1. Коли використовувати `<section>`?

Використовуй `<section>`, коли блок:
- має окрему тему;
- логічно є частиною сторінки;
- заслуговує на власний заголовок;
- утворює змістову групу.

### 11.2. Коли використовувати `<div>`?

`<div>` — універсальний контейнер без власного семантичного значення.

Він підходить для групування елементів, коли немає потреби позначати окрему змістову секцію.

Наприклад:

    <section>
        <h2>Наші переваги</h2>

        <div class="features-grid">
            <article class="feature-card">
                <h3>Практика</h3>
                <p>Закріплюйте знання на завданнях.</p>
            </article>

            <article class="feature-card">
                <h3>Гнучкість</h3>
                <p>Навчайтеся у власному темпі.</p>
            </article>
        </div>
    </section>

### 11.3. Різниця між `<section>` та `<article>`

- `<section>` групує контент за темою.
- `<article>` позначає самостійний матеріал, який потенційно може використовуватися окремо.

Наприклад:
- секція «Популярні курси» може містити кілька `<article>`;
- кожна картка курсу може бути `<article>`, якщо вона є самостійною змістовою одиницею.

Вибір залежить від значення контенту, а не від того, який CSS-клас ти хочеш застосувати.

### 11.4. Заголовки та ієрархія

На сторінці варто підтримувати логічну структуру заголовків.

Приклад:

    <h1>Навчальна платформа</h1>

    <section>
        <h2>Популярні курси</h2>

        <article>
            <h3>HTML і CSS</h3>
        </article>

        <article>
            <h3>JavaScript</h3>
        </article>
    </section>

`h1`, `h2`, `h3` та інші рівні слід обирати за структурою змісту, а не лише за бажаним розміром шрифту.

## 12. Доступність секцій (Accessibility)

Хороша секція має бути зрозумілою не лише візуально, а й для людей, які використовують допоміжні технології.

Важливі принципи:
- використовуй семантичні HTML-елементи;
- додавай змістовні заголовки;
- підтримуй логічну структуру заголовків;
- забезпечуй достатній контраст тексту;
- не передавай важливу інформацію лише кольором;
- додавай альтернативний текст для змістовних зображень;
- перевіряй порядок читання;
- роби інтерактивні елементи доступними з клавіатури.

### Доступна секція з заголовком

    <section aria-labelledby="benefits-title">
        <h2 id="benefits-title">Наші переваги</h2>

        <p>
            Ми поєднуємо теоретичні матеріали
            з практичними завданнями.
        </p>
    </section>

`aria-labelledby` пов'язує секцію з її заголовком.

Не потрібно додавати ARIA-атрибути без причини. Якщо стандартна HTML-семантика вже достатня, краще використовувати її.

## 13. Повторне використання секцій

У великих проєктах секції часто створюють як повторно використовувані компоненти.

Це дозволяє:
- зберігати однакову структуру;
- уникати дублювання;
- швидше створювати нові сторінки;
- централізовано оновлювати стилі;
- підтримувати єдиний дизайн.

Наприклад, кілька секцій можуть мати однакову структуру заголовка:

    <section class="section">
        <div class="container">
            <header class="section-header">
                <p class="section-header__eyebrow">
                    НАВЧАННЯ
                </p>

                <h2 class="section-header__title">
                    Популярні курси
                </h2>

                <p class="section-header__description">
                    Оберіть свій наступний навчальний напрям.
                </p>
            </header>

            <!-- Основний контент секції -->
        </div>
    </section>

Інша секція може використовувати той самий клас `section-header`, але мати інший заголовок і контент.

### 13.1. Модифікатори секцій

Можна використовувати модифікатори для різних варіантів оформлення.

    .section {
        padding-block: 64px;
    }

    .section--muted {
        background: #f5f6f8;
    }

    .section--compact {
        padding-block: 32px;
    }

    .section--large {
        padding-block: 96px;
    }

Це приклад підходу, схожого на BEM.

Важливо: модифікатор має описувати варіант компонента, а не бути випадковим набором стилів для кожної сторінки.

## 14. Секції в React та Next.js

У React секцію можна оформити як окремий компонент.

Приклад:

    type SectionProps = {
        title: string;
        description?: string;
        children: React.ReactNode;
    };

    export function Section({
        title,
        description,
        children,
    }: SectionProps) {
        return (
            <section className="section">
                <div className="container">
                    <header className="section-header">
                        <h2>{title}</h2>

                        {description && (
                            <p>{description}</p>
                        )}
                    </header>

                    <div className="section-content">
                        {children}
                    </div>
                </div>
            </section>
        );
    }

Використання:

    <Section
        title="Популярні курси"
        description="Оберіть свій наступний напрям."
    >
        <CourseGrid />
    </Section>

### Переваги компонентного підходу

- повторне використання структури;
- зрозуміліша архітектура сторінки;
- менше дублювання JSX;
- узгоджені заголовки та відступи;
- зручніше підтримувати дизайн.

### Важливе застереження

Не кожну секцію потрібно перетворювати на універсальний компонент із великою кількістю параметрів.

Якщо дві секції суттєво відрізняються за структурою та поведінкою, краще залишити їх окремими компонентами, використовуючи спільні базові стилі там, де це доречно.

## 15. Як спланувати структуру сторінки

Перед написанням HTML і CSS корисно скласти карту секцій.

### Крок 1. Визнач мету сторінки

Наприклад:
- представити продукт;
- продати послугу;
- показати каталог;
- допомогти користувачеві знайти інформацію;
- запропонувати зареєструватися.

### Крок 2. Визнач основного користувача

Запитай себе:
- хто відкриє сторінку;
- що ця людина шукає;
- які питання вона має;
- яку дію повинна виконати.

### Крок 3. Склади список необхідного контенту

Не починай із декоративних блоків. Спочатку визнач, яку інформацію потрібно передати.

### Крок 4. Впорядкуй секції

Розташуй їх так, щоб одна секція природно готувала користувача до наступної.

### Крок 5. Визнач композицію

Для кожної секції обери:
- одну колонку;
- дві колонки;
- сітку карток;
- список;
- таблицю;
- інший відповідний формат.

### Крок 6. Визнач візуальні відмінності

Виріши, які секції потребують:
- іншого фону;
- більшого вертикального простору;
- зображення;
- межі;
- виразнішого заголовка.

### Крок 7. Сплануй адаптивність

Подумай, як кожна секція працюватиме на:
- широкому desktop;
- планшеті;
- мобільному пристрої.

### Крок 8. Перевір логіку

Переконайся, що немає секцій, які дублюють одна одну або не допомагають досягти мети сторінки.

## 17. Типові помилки під час проєктування секцій

### Помилка 1. Занадто багато секцій

Кожна невелика думка перетворюється на окремий блок.

Наслідки:
- сторінка стає довшою без потреби;
- користувач втрачає головну думку;
- контент виглядає розрізненим.

**Рішення:** об'єднуй пов'язані матеріали в логічні групи.

### Помилка 2. Секції без чіткої мети

Блоки додаються лише тому, що так виглядає популярний шаблон.

**Рішення:** визначай, яке завдання вирішує кожна секція.

### Помилка 3. Однаковий дизайн усіх секцій

Якщо кожен блок має однакову композицію, фон і щільність, сторінка може стати монотонною.

**Рішення:** використовуй різні композиції там, де цього потребує контент, але зберігай загальну візуальну узгодженість.

### Помилка 4. Надмірна кількість кольорових фонів

Якщо кожна секція має яскравий фон, сторінка може виглядати фрагментованою.

**Рішення:** використовуй обмежену палітру та відокремлюй блоки за допомогою простору, типографіки й композиції.

### Помилка 5. Надто великі відступи

Великий вертикальний простір може створити відчуття порожнечі.

**Рішення:** узгоджуй відступи з кількістю контенту, розміром екрана та ритмом сторінки.

### Помилка 6. Надто щільні секції

Заголовок, текст, зображення й кнопки розташовані надто близько.

**Рішення:** встановлюй зрозумілу систему внутрішніх відступів.

### Помилка 7. Слабка ієрархія

Користувач не розуміє, що є заголовком, поясненням і основною дією.

**Рішення:** розрізняй рівні тексту, відстані, вагу шрифту та візуальну важливість елементів.

### Помилка 8. Ігнорування мобільного макета

Секція добре виглядає на desktop, але на телефоні текст і зображення стають надто вузькими.

**Рішення:** перевіряй кожну секцію окремо на різних ширинах екрана.

### Помилка 9. Зловживання універсальними компонентами

Усі секції примусово використовують одну композицію, навіть якщо зміст різний.

**Рішення:** повторно використовуй спільні правила та компоненти, але дозволяй різним секціям мати відповідну структуру.

### Помилка 10. Семантичні помилки

Усі блоки оформлено через `<div>`, а заголовки обрано лише за розміром.

**Рішення:** використовуй семантичні елементи й логічну ієрархію заголовків.

### Помилка 11. CTA без контексту

Кнопка закликає до дії, але користувач не розуміє, що станеться після натискання.

**Рішення:** текст кнопки має чітко описувати наступний крок.

### Помилка 12. Дублювання інформації

Кілька секцій повторюють ті самі переваги або повідомлення.

**Рішення:** перевіряй сторінку цілком і залишай кожній секції власну роль.

## 19. Питання для співбесіди

### Базовий рівень

**1. Що таке секція в UI-дизайні?**

Логічно відокремлена частина сторінки, яка виконує певне змістове завдання.

**2. Які типи секцій ти знаєш?**

Hero, About, Features, Services, How It Works, Testimonials, Pricing, FAQ, CTA, Contact і Footer.

**3. Для чого потрібен Hero-блок?**

Щоб одразу пояснити основну пропозицію сторінки та запропонувати зрозумілий наступний крок.

**4. Навіщо потрібні відступи між секціями?**

Щоб відокремлювати змістові блоки, формувати ритм і полегшувати сканування сторінки.

### Середній рівень

**5. Чим секція відрізняється від компонента?**

Секція організовує змістову частину сторінки, а компонент є окремою частиною інтерфейсу, яку можна повторно використовувати.

**6. Коли потрібно використовувати HTML-елемент `<section>`?**

Коли контент утворює тематичну групу, зазвичай із власним заголовком.

**7. Чим `<section>` відрізняється від `<div>`?**

`<section>` має семантичне значення тематичної групи, тоді як `<div>` є універсальним контейнером без власної семантики.

**8. Як зробити секцію адаптивною?**

За допомогою гнучких контейнерів, Grid, Flexbox, медіазапитів, `clamp()` та інших CSS-інструментів.

**9. Як визначити послідовність секцій на landing page?**

Врахувати мету сторінки, потреби користувача, інформаційну ієрархію та бажаний сценарій взаємодії.

### Просунутий рівень

**10. Що таке вертикальний ритм?**

Узгоджена система відстаней між елементами та секціями, яка допомагає підтримувати послідовність макета.

**11. Чому не варто використовувати однакову композицію для всіх секцій?**

Тому що різний контент потребує різного способу представлення, хоча загальна дизайн-система має залишатися узгодженою.

**12. Як організувати повторно використовувані секції в React?**

Виділити спільні структурні частини в компоненти, передавати змінний контент через props або children та не ускладнювати компонент зайвими параметрами.

**13. Чому порядок секцій впливає на UX?**

Від нього залежить, наскільки легко користувач зрозуміє пропозицію, знайде потрібну інформацію та виконає цільову дію.

**14. Як зрозуміти, що секція зайва?**

Якщо вона не додає важливої інформації, не підтримує мету сторінки та дублює інший контент, її можна об'єднати з іншою або прибрати.

## 20. Рівні засвоєння теми

### Core — основа

Ти повинен уміти:
- пояснити, що таке секція;
- назвати основні типи секцій;
- відрізняти секцію від компонента;
- створювати базову HTML-структуру сторінки;
- використовувати заголовки та відступи;
- розуміти роль Hero, Features і Footer.

### Junior — практичне застосування

Ти повинен уміти:
- спланувати структуру landing page;
- створювати секції з різною композицією;
- використовувати Grid і Flexbox;
- створювати адаптивні секції;
- застосовувати повторювану шкалу відступів;
- використовувати семантичний HTML;
- створювати прості повторно використовувані компоненти.

### Middle — системне мислення

Ти повинен уміти:
- проєктувати структуру сторінок для різних сценаріїв;
- підтримувати узгодженість секцій у великому проєкті;
- визначати, які компоненти варто повторно використовувати;
- організовувати складні композиції;
- враховувати UX, доступність і адаптивність;
- уникати дублювання контенту та стилів.

### Senior — архітектура дизайн-системи

Ти повинен уміти:
- визначати правила побудови секцій для всього продукту;
- розробляти систему компонентів і варіантів секцій;
- балансувати повторне використання та індивідуальні потреби сторінок;
- оцінювати структуру сторінок з погляду бізнес-цілей і користувацьких сценаріїв;
- підтримувати узгодженість дизайну під час масштабування продукту.

## 21. Практичні вправи

### Вправа 1. Карта головної сторінки

Створи список секцій для головної сторінки навчального проєкту.

Для кожної секції запиши:
- назву;
- мету;
- основний контент;
- можливу дію користувача;
- місце в загальній послідовності.

### Вправа 2. Hero Section

Створи Hero із:
- надзаголовком;
- головним заголовком;
- коротким описом;
- основною кнопкою;
- ілюстрацією.

Зроби двоколонковий desktop-макет і одноколонковий mobile-макет.

### Вправа 3. Features Section

Створи секцію з трьома картками переваг.

Використай:
- заголовок;
- короткий опис;
- CSS Grid;
- однакові проміжки;
- адаптивну кількість колонок.

### Вправа 4. FAQ Section

Створи секцію з п'ятьма запитаннями, використовуючи `<details>` та `<summary>`.

Перевір:
- семантику;
- читабельність;
- зручність використання з клавіатури;
- візуальне розділення запитань.

### Вправа 5. CTA Section

Створи окрему секцію із закликом до дії.

Вона повинна містити:
- короткий заголовок;
- пояснення;
- одну основну кнопку.

Порівняй центральну композицію з лівим вирівнюванням.

### Вправа 6. Редизайн сторінки

Візьми просту сторінку, яка складається з кількох блоків, і:
1. визнач межі секцій;
2. сформулюй мету кожної;
3. виправ порядок;
4. узгодь відступи;
5. перевір фони;
6. адаптуй колонки;
7. перевір семантичний HTML.

### Вправа 7. Компонент у React

Створи універсальний компонент `Section`, який приймає:
- `title`;
- необов'язковий `description`;
- `children`.

Використай його щонайменше у двох різних секціях.

Порівняй, які частини справді повторюються, а які краще залишити специфічними для кожної секції.

## 22. Мінішпаргалка

| Завдання | Рішення |
|---|---|
| Змістова частина сторінки | `<section>` |
| Основний контент сторінки | `<main>` |
| Самостійний матеріал | `<article>` |
| Універсальний контейнер | `<div>` |
| Нижня частина сайту | `<footer>` |
| Обмеження ширини контенту | `max-width` або `width: min(...)` |
| Центрування контейнера | `margin-inline: auto` |
| Вертикальні відступи секції | `padding-block` |
| Відстань між елементами | `gap` |
| Адаптивний розмір | `clamp()` |
| Адаптивні колонки | CSS Grid та медіазапити |
| Фоновий варіант секції | Модифікатор на кшталт `.section--muted` |
| Заголовок секції | Зазвичай `<h2>` на сторінці з головним `<h1>` |
| Розкривний FAQ | `<details>` та `<summary>` |

### Приклад базової структури

    <section class="section" aria-labelledby="section-title">
        <div class="container">
            <header class="section-header">
                <h2 id="section-title">
                    Заголовок секції
                </h2>

                <p>
                    Короткий опис змісту секції.
                </p>
            </header>

            <div class="section-content">
                <!-- Основний контент -->
            </div>
        </div>
    </section>

### Приклад адаптивного шаблону

    .section {
        padding-block: clamp(40px, 6vw, 88px);
    }

    .container {
        width: min(100% - 32px, 1200px);
        margin-inline: auto;
    }

    .section-header {
        max-width: 680px;
        margin-bottom: 40px;
    }

    .section-grid {
        display: grid;
        grid-template-columns: repeat(
            auto-fit,
            minmax(min(100%, 240px), 1fr)
        );
        gap: 24px;
    }

## 23. Головне, що потрібно запам'ятати

1. **Секція — це змістова частина сторінки, а не просто блок із фоном.**
2. Кожна секція повинна мати зрозумілу мету.
3. Послідовність секцій формує шлях користувача сторінкою.
4. Заголовок допомагає зрозуміти зміст секції та швидко просканувати сторінку.
5. Відступи, типографіка, фон і композиція допомагають відокремлювати секції.
6. Не всі секції повинні мати однакову структуру.
7. Семантичний HTML робить структуру сторінки зрозумілішою для браузерів і допоміжних технологій.
8. Адаптивність потрібно продумувати для кожної секції окремо.
9. Повторно використовуй спільні компоненти, але не змушуй різний контент мати однакову композицію.
10. Хороша структура сторінки допомагає користувачеві швидше знайти інформацію та виконати потрібну дію.

**Основний принцип:** спочатку визнач зміст і мету сторінки, потім побудуй послідовність секцій, а вже після цього працюй над кольорами, відступами, колонками та декоративними деталями.
