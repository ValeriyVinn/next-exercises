# 02. Containers

Container (контейнер) — це область інтерфейсу, яка групує контент і допомагає контролювати його ширину, розташування, відступи та взаємодію з навколишнім простором.

У UI Design контейнери використовуються для організації:

- основного контенту сторінки;
- текстових блоків;
- секцій;
- карток;
- форм;
- навігації;
- бокових панелей;
- зображень;
- таблиць;
- груп компонентів;
- модальних вікон;
- dashboard;
- адаптивних макетів.

Контейнер допомагає створювати передбачувану структуру інтерфейсу, підтримувати однакові лінії вирівнювання та уникати ситуації, коли контент займає весь доступний простір без обмежень.

Основна мета container — організувати контент у контрольованій області, яка відповідає призначенню сторінки та потребам користувача.

Container — це не просто прямокутник із фоном. Він може бути невидимою областю, яка визначає ширину та положення контенту.

## Що потрібно пам'ятати

• Container допомагає групувати контент і контролювати його розміщення.

• Контейнер може бути візуально невидимим.

• Page container часто використовується для обмеження ширини основного контенту сторінки.

• Section container допомагає організувати вміст окремої секції.

• Card container групує елементи окремої картки.

• Modal container організовує контент діалогового вікна.

• `width` задає ширину елемента, а `max-width` обмежує її максимальне значення.

• `min-width` задає мінімальну ширину, але може спричиняти переповнення на вузьких екранах, якщо його використовувати необережно.

• `margin` визначає зовнішні відступи елемента.

• `padding` визначає внутрішні відступи між межами контейнера та його контентом.

• `margin-inline: auto` часто використовується для горизонтального центрування контейнера з обмеженою шириною.

• `width: 100%` дозволяє контейнеру займати доступну ширину батьківського елемента, але саме по собі не обмежує максимальну ширину.

• `max-width` часто поєднують із `width: 100%` для створення адаптивного контейнера.

• Контейнер повинен враховувати довжину тексту, розміри компонентів і доступний viewport.

• Не кожному елементу потрібен окремий контейнер.

• Надмірне вкладення контейнерів ускладнює структуру та підтримку інтерфейсу.

• Контейнери на різних сторінках повинні використовувати узгоджені правила, якщо виконують однакову функцію.

• У CSS контейнер може реалізовуватися за допомогою звичайного блочного елемента, Flexbox, Grid та інших механізмів компонування.

• Хороший контейнер допомагає зберігати читабельність, вирівнювання та послідовність інтерфейсу.

# Що таке Container

Container — це область, яка визначає межі розташування певного контенту.

Наприклад, звичайна вебсторінка може мати таку структуру:

    Page
        ↓
    Page container
        ↓
    Main content
        ↓
    Section container
        ↓
    Heading
    Paragraph
    Button

Контейнер може відповідати за різні аспекти компонування:

- максимальну ширину;
- мінімальну ширину;
- горизонтальні відступи;
- вирівнювання;
- групування контенту;
- обмеження переповнення;
- поведінку на різних екранах.

Приклад сторінки з центральним контейнером:

    ┌──────────────────────────────────────────┐
    │                                          │
    │        ┌──────────────────────┐          │
    │        │                      │          │
    │        │    Main content      │          │
    │        │                      │          │
    │        └──────────────────────┘          │
    │                                          │
    └──────────────────────────────────────────┘

Зовнішня область — viewport.

Внутрішня область — container.

Контейнер може бути значно вужчим за viewport, щоб текст і компоненти залишалися читабельними.

# Навіщо потрібні контейнери

## 1. Контроль ширини контенту

Якщо текст займає всю ширину великого екрана, читати його може бути незручно.

Контейнер дозволяє встановити максимальну ширину.

    ┌──────────────────────────────────────────┐
    │                                          │
    │      ┌──────────────────────────┐        │
    │      │ Heading                  │        │
    │      │                          │        │
    │      │ Paragraph text           │        │
    │      │ Paragraph text           │        │
    │      └──────────────────────────┘        │
    │                                          │
    └──────────────────────────────────────────┘

Контейнер не дозволяє контенту розтягуватися на всю доступну ширину без потреби.

Це особливо важливо для:

- статей;
- документації;
- форм;
- сторінок налаштувань;
- навчальних матеріалів;
- landing pages.

## 2. Спільне вирівнювання

Контейнери допомагають створювати спільні вертикальні лінії для різних секцій.

Наприклад:

    Header content
    ├──────────────────────────────┤

    Hero content
    ├──────────────────────────────┤

    Features content
    ├──────────────────────────────┤

    Footer content
    ├──────────────────────────────┤

Якщо контент різних секцій вирівнюється за однаковими правилами, сторінка виглядає послідовною.

## 3. Організація груп елементів

Контейнер допомагає сприймати кілька елементів як єдину групу.

Наприклад:

    Form container
        ↓
    Form heading
    Email field
    Password field
    Submit button

Це полегшує компонування та подальшу розробку.

## 4. Responsive Design

Контейнер може змінювати ширину залежно від доступного простору.

Наприклад:

    Wide viewport:
        container → limited maximum width

    Medium viewport:
        container → flexible width

    Narrow viewport:
        container → available width
                     minus side gutters

Таким чином, контейнер допомагає адаптувати інтерфейс до різних пристроїв.

## 5. Послідовність дизайн-системи

У великому застосунку різні сторінки часто використовують спільні правила контейнерів.

Наприклад:

    Page A → max-width: 1200px
    Page B → max-width: 1200px
    Page C → max-width: 1200px

Це приклад спільного правила, а не вимога використовувати одну ширину для абсолютно всіх сторінок.

Для статей, форм, dashboard і широких таблиць можуть знадобитися різні типи контейнерів.

# Основні типи контейнерів

## 1. Page Container

Page container — контейнер, який організовує основний контент сторінки.

Наприклад:

    Page
        Header
            Page container
        Main
            Page container
        Footer
            Page container

Він може контролювати:

- максимальну ширину;
- горизонтальні відступи;
- центрування;
- вирівнювання контенту між секціями.

Приклад:

    .container {
        width: 100%;
        max-width: 1200px;
        margin-inline: auto;
        padding-inline: 24px;
    }

У цьому прикладі:

    width: 100%
        → контейнер займає доступну ширину

    max-width: 1200px
        → ширина обмежена максимумом 1200px

    margin-inline: auto
        → контейнер центрується по горизонталі

    padding-inline: 24px
        → контент має внутрішні бокові відступи

Ці значення наведені як приклад. У реальному проєкті їх потрібно узгоджувати з дизайн-системою.

---

## 2. Content Container

Content container — контейнер, який обмежує ширину конкретного текстового або інформаційного блоку.

Наприклад:

    Article
        ↓
    Content container
        ↓
    Heading
    Paragraph
    Paragraph
    Image

Його мета — зробити контент зручним для сприйняття.

Приклад:

    .article-content {
        width: 100%;
        max-width: 720px;
        margin-inline: auto;
    }

Такий контейнер може використовуватися для:

- статей;
- блогів;
- навчальних матеріалів;
- текстових сторінок;
- описів продуктів.

Ширина текстового контейнера залежить від розміру шрифту, довжини рядка, мови та типу матеріалу.

Для таблиць або широких інформаційних панелей можуть знадобитися інші обмеження.

---

## 3. Section Container

Section container — контейнер для організації контенту окремої секції.

Наприклад:

    Page
        ↓
    Features section
        ↓
    Section container
        ↓
    Section heading
    Feature grid

Приклад:

    .features-section {
        padding-block: 80px;
    }

    .features-container {
        width: 100%;
        max-width: 1200px;
        margin-inline: auto;
        padding-inline: 24px;
    }

Тут секція контролює вертикальний простір, а контейнер — ширину та горизонтальне положення контенту.

Важливо розрізняти:

    Section
        → велика логічна область сторінки

    Section container
        → область для вирівнювання
          контенту всередині секції

---

## 4. Card Container

Card container — контейнер, який групує елементи картки.

Наприклад:

    ┌──────────────────────────────┐
    │ Card container               │
    │                              │
    │ Image                        │
    │ Heading                      │
    │ Description                  │
    │ Metadata                     │
    │ Button                       │
    │                              │
    └──────────────────────────────┘

Контейнер картки може визначати:

- внутрішні відступи;
- фоновий колір;
- межі;
- радіус кутів;
- ширину;
- вертикальне розташування;
- поведінку в grid.

Приклад:

    .card {
        padding: 24px;
        border: 1px solid #ddd;
        border-radius: 12px;
    }

Внутрішні відступи дозволяють контенту не торкатися меж картки.

Не потрібно додавати декоративний фон або рамку кожному контейнеру. Частина контейнерів може бути невидимою.

---

## 5. Form Container

Form container — область, яка групує елементи форми.

Наприклад:

    Form container
        ↓
    Form heading
    Email field
    Password field
    Checkbox
    Submit button
    Additional links

Приклад:

    .form-container {
        width: 100%;
        max-width: 420px;
        margin-inline: auto;
        padding: 24px;
    }

Це дозволяє уникнути надмірної ширини форми на великих екранах.

Під час проєктування потрібно враховувати:

- ширину полів;
- довжину підписів;
- повідомлення про помилки;
- допоміжний текст;
- розташування кнопок;
- адаптацію до мобільного viewport.

Контейнер повинен залишатися зручним навіть тоді, коли текст повідомлення про помилку займає кілька рядків.

---

## 6. Sidebar Container

Sidebar container — область для навігації, фільтрів або допоміжної інформації.

Наприклад:

    ┌──────────────┬───────────────────────┐
    │ Sidebar      │ Main content          │
    │              │                       │
    │ Navigation   │ Heading               │
    │ Filters      │ Content               │
    │ Links        │                       │
    └──────────────┴───────────────────────┘

Sidebar може мати:

- фіксовану ширину;
- обмежену ширину;
- гнучку ширину;
- власні внутрішні відступи;
- незалежну прокрутку, якщо це справді потрібно.

Приклад:

    .dashboard-layout {
        display: grid;
        grid-template-columns: 260px minmax(0, 1fr);
        gap: 24px;
    }

Тут:

    260px
        → ширина першої колонки

    minmax(0, 1fr)
        → друга колонка займає доступний простір,
          допускаючи зменшення до нульового
          мінімального розміру grid-треку

`minmax(0, 1fr)` часто допомагає уникнути проблем, коли довгий контент змушує колонку ставати ширшою за доступний простір.

На вузьких екранах такий layout може потребувати іншої структури.

---

## 7. Modal Container

Modal container — контейнер діалогового вікна, яке відображається поверх основного інтерфейсу.

Наприклад:

    ┌─────────────────────────────────┐
    │ Background page                 │
    │                                 │
    │       ┌────────────────┐        │
    │       │ Modal           │        │
    │       │                 │        │
    │       │ Heading         │        │
    │       │ Content         │        │
    │       │ Actions         │        │
    │       └────────────────┘        │
    │                                 │
    └─────────────────────────────────┘

Modal container може визначати:

- максимальну ширину;
- внутрішні відступи;
- положення;
- висоту;
- прокручування;
- розташування кнопок.

Наприклад:

    .modal {
        width: min(100% - 32px, 560px);
        max-height: calc(100vh - 32px);
        overflow: auto;
        padding: 24px;
    }

Це лише базовий приклад CSS. Для повноцінного модального вікна потрібно також передбачити керування фокусом, доступне ім'я, клавіатурну взаємодію та поведінку на мобільних пристроях.

---

## 8. Full-width Container

Full-width container — контейнер, який займає всю доступну ширину батьківської області.

Наприклад:

    ┌──────────────────────────────────────┐
    │ Full-width banner                    │
    └──────────────────────────────────────┘

Використовується для:

- фонових секцій;
- hero banners;
- широких зображень;
- кольорових смуг;
- інформаційних панелей;
- деяких таблиць і dashboard.

Full-width container не означає, що весь його внутрішній контент також повинен розтягуватися на всю ширину.

Часто застосовується така структура:

    Full-width section
        ↓
    Centered content container
        ↓
    Heading
    Text
    Buttons

Приклад:

    .hero-section {
        width: 100%;
        background: #f2f4f7;
    }

    .hero-container {
        width: 100%;
        max-width: 1200px;
        margin-inline: auto;
        padding: 64px 24px;
    }

Зовнішня секція займає всю доступну ширину, а внутрішній контент має обмежену ширину.

---

# Fixed-width Container

Fixed-width container — контейнер із фіксованою шириною.

Приклад:

    .sidebar {
        width: 260px;
    }

Ширина такого елемента задана явно.

Фіксовані розміри можуть бути корисними для:

- компактних sidebar;
- іконок;
- невеликих панелей;
- деяких діалогових елементів;
- елементів із визначеним розміром.

Однак фіксована ширина може бути проблемою, якщо вона не поміщається в доступний простір.

Наприклад:

    .container {
        width: 1200px;
    }

На екрані, вужчому за 1200 CSS pixels, такий контейнер може виходити за межі viewport.

Для основного контенту сторінки частіше використовують гнучку ширину з максимальним обмеженням.

---

# Fluid Container

Fluid container — контейнер, ширина якого змінюється відповідно до доступного простору.

Наприклад:

    .container {
        width: 100%;
    }

Контейнер займає доступну ширину свого батьківського елемента.

Інший приклад:

    .container {
        width: 90%;
    }

Контейнер займає 90% ширини батьківського елемента.

Fluid containers корисні для адаптивних інтерфейсів.

Але вони потребують контролю, оскільки на широких екранах контент може стати надто розтягнутим.

Тому часто використовують поєднання fluid width і max-width.

---

# Responsive Container

Responsive container — контейнер, який змінює свою ширину та відступи відповідно до доступного простору.

Типова модель:

    Wide viewport
        ↓
    Container reaches max-width

    Medium viewport
        ↓
    Container becomes narrower

    Small viewport
        ↓
    Container fills available width
    with comfortable side gutters

Приклад:

    .container {
        width: 100%;
        max-width: 1200px;
        margin-inline: auto;
        padding-inline: 24px;
    }

У цій моделі контейнер гнучкий, але не може перевищити встановлену максимальну ширину.

Для деяких компонентів може знадобитися адаптивне зменшення відступів:

    .container {
        width: 100%;
        max-width: 1200px;
        margin-inline: auto;
        padding-inline: 24px;
    }

    @media (max-width: 600px) {
        .container {
            padding-inline: 16px;
        }
    }

Breakpoint `600px` наведено як приклад. Реальні точки переходу варто визначати відповідно до контенту та поведінки макета.

---

# Container Width

Container width — ширина контейнера.

Ширина впливає на:

- довжину текстових рядків;
- розміщення колонок;
- ширину карток;
- відстані між елементами;
- загальну щільність інформації;
- адаптивність сторінки.

Не існує однієї універсальної ширини для всіх контейнерів.

Наприклад, можуть використовуватися такі орієнтовні значення:

    Compact form:
        max-width: 420px

    Article content:
        max-width: 720px

    General page:
        max-width: 1200px

    Wide dashboard:
        max-width: 1440px

Це лише приклади можливих значень, а не обов'язкові стандарти.

Вибір залежить від:

- типу контенту;
- розміру шрифту;
- кількості колонок;
- ширини компонентів;
- потреб користувача;
- вимог продукту.

---

# Max-width

`max-width` визначає максимальну ширину елемента.

Наприклад:

    .container {
        width: 100%;
        max-width: 1200px;
    }

Якщо доступний простір становить 1440px, контейнер не перевищуватиме 1200px.

Якщо доступний простір становить 900px, контейнер зможе зайняти 900px за умови, що його батьківська область має таку ширину та немає інших обмежень.

Основна ідея:

    width: 100%
        → використовуй доступну ширину

    max-width: 1200px
        → не перевищуй 1200px

`max-width` часто використовується для:

- основного контейнера сторінки;
- текстових блоків;
- форм;
- модальних вікон;
- зображень;
- карток.

---

# Min-width

`min-width` визначає мінімальну ширину елемента.

Наприклад:

    .sidebar {
        min-width: 240px;
    }

Це означає, що елемент не повинен ставати вужчим за 240px у звичайних умовах компонування.

`min-width` може бути корисним, коли компонент потребує мінімального простору для читабельності або взаємодії.

Але необережне використання може призводити до переповнення.

Наприклад:

    .layout {
        display: grid;
        grid-template-columns: 300px 1fr;
    }

Якщо доступний простір менший за суму необхідних ширин колонок, layout може не поміститися.

Для гнучкіших структур іноді краще:

    .layout {
        display: grid;
        grid-template-columns: minmax(0, 1fr);
    }

Або передбачити окрему адаптивну структуру для вузьких екранів.

Важливо: `min-width` — це інструмент обмеження, а не автоматичне рішення для responsive design.

---

# Width vs Max-width

Це важлива відмінність.

## Width

    .container {
        width: 800px;
    }

Ширина контейнера встановлена на 800px.

За звичайних умов він не буде автоматично зменшуватися лише тому, що доступний простір став меншим.

## Max-width

    .container {
        width: 100%;
        max-width: 800px;
    }

Контейнер може займати доступну ширину, але не перевищує 800px.

Порівняння:

    width: 800px
        → задана ширина 800px

    max-width: 800px
        → верхня межа 800px

    width: 100%
    max-width: 800px
        → гнучка ширина з верхньою межею

Для багатьох основних контейнерів сторінки третій варіант є зручним початковим рішенням.

---

# Margin vs Padding

Margin і padding впливають на простір навколо контейнера, але виконують різні функції.

## Margin

Margin — зовнішній відступ.

Він створює простір за межами елемента.

    ┌───────────────────────────────┐
    │            Margin             │
    │    ┌─────────────────────┐    │
    │    │      Container      │    │
    │    └─────────────────────┘    │
    │            Margin             │
    └───────────────────────────────┘

Приклад:

    .container {
        margin-inline: auto;
    }

`margin-inline: auto` часто використовується для горизонтального центрування елемента, ширина якого обмежена.

## Padding

Padding — внутрішній відступ.

Він створює простір між межами елемента та його вмістом.

    ┌───────────────────────────────┐
    │         Container             │
    │                               │
    │       ┌───────────────┐       │
    │       │ Content       │       │
    │       └───────────────┘       │
    │                               │
    └───────────────────────────────┘

Приклад:

    .card {
        padding: 24px;
    }

Padding допомагає контенту не торкатися меж картки.

Основна різниця:

    margin
        → простір зовні елемента

    padding
        → простір усередині елемента

---

# Centered Container

Centered container — контейнер, розташований по центру доступного горизонтального простору.

Наприклад:

    ┌──────────────────────────────────────┐
    │                                      │
    │       ┌──────────────────────┐       │
    │       │                      │       │
    │       │       Container      │       │
    │       │                      │       │
    │       └──────────────────────┘       │
    │                                      │
    └──────────────────────────────────────┘

Типовий CSS:

    .container {
        width: 100%;
        max-width: 1200px;
        margin-inline: auto;
        padding-inline: 24px;
    }

Центрування не означає, що текст усередині контейнера також обов'язково потрібно центрувати.

Можна мати:

    Centered container
        ↓
    Left-aligned heading
    Left-aligned paragraph
    Left-aligned buttons

Контейнер центрується в межах сторінки, а контент усередині нього має власне вирівнювання.

---

# Container Padding

Container padding — внутрішні відступи контейнера.

Вони особливо важливі на вузьких екранах.

Без бокових відступів:

    ┌──────────────────────┐
    │Heading               │
    │Paragraph text...     │
    │[Button]              │
    └──────────────────────┘

З боковими відступами:

    ┌──────────────────────┐
    │                      │
    │  Heading             │
    │                      │
    │  Paragraph text...   │
    │                      │
    │  [Button]            │
    │                      │
    └──────────────────────┘

Відступи допомагають уникнути ситуації, коли текст або кнопки торкаються країв viewport.

Приклад:

    .container {
        padding-inline: 24px;
    }

Для вузьких екранів можна передбачити менше значення:

    @media (max-width: 600px) {
        .container {
            padding-inline: 16px;
        }
    }

Конкретні значення залежать від дизайн-системи та доступного простору.

---

# Container Gutter

Gutter — простір між контентом і краєм контейнера або між колонками сітки, залежно від контексту.

У компонуванні сторінки horizontal gutter часто означає боковий простір між контентом і краями доступної області.

Наприклад:

    Viewport
        ↓
    Left gutter
        ↓
    Content
        ↓
    Right gutter

Gutter допомагає підтримувати комфортні відступи та вирівнювання.

Не потрібно плутати:

    Container padding
        → простір усередині контейнера

    Grid gap
        → простір між елементами grid

    Margin
        → зовнішній відступ елемента

Ці властивості можуть працювати разом, але виконують різні завдання.

---

# Nested Containers

Nested containers — вкладені контейнери, коли один контейнер розташовується всередині іншого.

Наприклад:

    Page container
        ↓
    Section container
        ↓
    Card grid
        ↓
    Card container
        ↓
    Card content

Вкладення контейнерів є звичайною практикою.

Воно дозволяє розділяти відповідальність:

    Page container
        → ширина сторінки

    Section container
        → структура секції

    Grid container
        → розташування карток

    Card container
        → внутрішня структура картки

Але надмірне вкладення може ускладнювати компонування.

Наприклад:

    Container
        Container
            Container
                Container
                    Container

Якщо кожен контейнер додає власні відступи або обмеження, контент може втрачати надто багато доступного простору.

Важливо створювати вкладені контейнери лише тоді, коли вони мають зрозумілу функцію.

---

# Container vs Section

Container і section — це різні поняття.

## Section

Section — логічна частина сторінки.

Наприклад:

    Features section
    Pricing section
    Testimonials section

## Container

Container — область для організації контенту.

Наприклад:

    Features section
        ↓
    Container
        ↓
    Heading
    Feature grid

Одна секція може мати контейнер, але не кожен контейнер є секцією.

Порівняння:

    Section
        → що це за частина сторінки?

    Container
        → у якій області розміщений контент?

---

# Container vs Card

Card — компонент для подання окремого інформаційного блоку.

Container — ширше поняття, яке описує область групування або компонування контенту.

Картка часто сама є контейнером для свого вмісту.

Наприклад:

    Card
        ↓
    Image
    Heading
    Description
    Button

Але контейнер може не бути карткою.

Наприклад:

    Page container
        ↓
    Main heading
    Article
    Footer

У цьому випадку контейнер організовує контент сторінки, а не представляє окрему картку.

---

# Container vs Grid

Grid — система двовимірного компонування.

Container — область, у якій може розміщуватися grid.

Наприклад:

    Page container
        ↓
    Card grid
        ↓
    Card
    Card
    Card

Приклад CSS:

    .container {
        width: 100%;
        max-width: 1200px;
        margin-inline: auto;
        padding-inline: 24px;
    }

    .card-grid {
        display: grid;
        grid-template-columns: repeat(3, minmax(0, 1fr));
        gap: 24px;
    }

У цьому прикладі:

    .container
        → контролює доступну ширину контенту

    .card-grid
        → контролює розташування карток

Це різні рівні компонування.

---

# Container vs Flexbox

Flexbox — механізм компонування елементів в одному основному напрямку.

Container — область, у якій можуть розташовуватися елементи.

Наприклад:

    Header container
        ↓
    Logo
    Navigation
    User actions

CSS:

    .header-container {
        display: flex;
        align-items: center;
        justify-content: space-between;
        gap: 24px;
    }

Тут контейнер одночасно є flex-контейнером, оскільки для нього встановлено `display: flex`.

Важливо розрізняти поняття:

    Container
        → роль елемента в структурі

    Flex container
        → елемент, який створює flex formatting context

Один елемент може виконувати обидві ролі.

---

# Full-width Section + Centered Container

Це поширений шаблон вебдизайну.

Зовнішня секція займає всю ширину сторінки, а внутрішній контейнер обмежує ширину контенту.

Структура:

    Full-width section
        ↓
    Centered container
        ↓
    Heading
    Paragraph
    Buttons

Приклад:

    .hero {
        width: 100%;
        background: #f2f4f7;
    }

    .hero__container {
        width: 100%;
        max-width: 1200px;
        margin-inline: auto;
        padding: 64px 24px;
    }

Переваги:

- фон може простягатися від краю до краю;
- контент зберігає комфортну ширину;
- різні секції можуть вирівнюватися за спільними лініями;
- структура адаптується до різних екранів.

Цей шаблон особливо корисний для landing pages, сторінок продуктів і маркетингових сайтів.

---

# Container Queries

Container queries — CSS-механізм, який дозволяє адаптувати стилі елемента відповідно до розміру його контейнера, а не лише viewport.

Це корисно для повторно використовуваних компонентів.

Наприклад, картка може відображати зображення над текстом у вузькому контейнері та поруч із текстом у широкому контейнері.

Приклад:

    .card-wrapper {
        container-type: inline-size;
    }

    .card {
        display: grid;
        gap: 16px;
    }

    @container (min-width: 500px) {
        .card {
            grid-template-columns: 160px minmax(0, 1fr);
        }
    }

У цьому прикладі:

    container-type: inline-size
        → створює контейнерний контекст
          для вимірювання inline-розміру

    @container (min-width: 500px)
        → застосовує стилі, якщо ширина
          контейнера досягає 500px

Це відрізняється від media queries:

    Media query
        → реагує на характеристики viewport
          або середовища

    Container query
        → реагує на розмір контейнера

Container queries особливо корисні для компонентних дизайн-систем, де один компонент може використовуватися в різних областях інтерфейсу.

---

# Container Design Tokens

Design tokens — повторно використовувані значення, які забезпечують послідовність дизайн-системи.

Для контейнерів можна визначити:

    --container-narrow
    --container-content
    --container-wide
    --container-gutter
    --container-max-width

Приклад:

    :root {
        --container-content: 720px;
        --container-wide: 1200px;
        --container-gutter: 24px;
    }

Використання:

    .container {
        width: 100%;
        max-width: var(--container-wide);
        margin-inline: auto;
        padding-inline: var(--container-gutter);
    }

    .article-container {
        width: 100%;
        max-width: var(--container-content);
        margin-inline: auto;
        padding-inline: var(--container-gutter);
    }

Переваги:

- однакові правила на різних сторінках;
- простіше змінювати ширину контейнерів;
- менше довільних значень;
- легша підтримка дизайн-системи;
- узгодженість компонентів.

Назви та значення токенів залежать від архітектури конкретного проєкту.

# Типові помилки під час роботи з контейнерами

## 1. Фіксована ширина без адаптації

❌

    .container {
        width: 1200px;
    }

Проблема:

Контейнер може виходити за межі вузького viewport.

Краще для типового основного контейнера:

    .container {
        width: 100%;
        max-width: 1200px;
        margin-inline: auto;
        padding-inline: 24px;
    }

---

## 2. Відсутність max-width

❌

    .article {
        width: 100%;
    }

Такий текстовий блок може стати надто широким на великому екрані.

Можливе рішення:

    .article {
        width: 100%;
        max-width: 720px;
        margin-inline: auto;
    }

---

## 3. Надто великі бокові відступи

❌ Контейнер має великі padding на вузькому екрані, тому для контенту залишається мало місця.

Потрібно перевіряти співвідношення між:

    Viewport width
        ↓
    Container padding
        ↓
    Available content width

Відступи повинні бути достатніми, але не забирати зайвий простір.

---

## 4. Надто малі бокові відступи

❌ Текст і кнопки майже торкаються країв viewport.

Це погіршує візуальне сприйняття та може ускладнювати взаємодію.

Потрібно визначити послідовні значення горизонтальних відступів.

---

## 5. Надмірне вкладення контейнерів

❌ Кожен елемент має власний контейнер із додатковими відступами.

Це ускладнює компонування та може зменшувати корисну ширину контенту.

Кожен контейнер повинен мати зрозуміле призначення.

---

## 6. Плутати margin і padding

❌ Використовувати padding там, де потрібно відокремити сусідні елементи, або margin там, де потрібно створити простір усередині картки.

Пам'ятай:

    margin
        → зовнішній простір

    padding
        → внутрішній простір

---

## 7. Вважати, що контейнер завжди повинен мати фон

❌ Кожна область контенту оформлена окремим кольоровим прямокутником.

Контейнер може бути невидимим і виконувати лише структурну функцію.

Фон, рамка й тінь потрібні тільки тоді, коли вони допомагають візуальній ієрархії або взаємодії.

---

## 8. Ігнорувати довгий контент

❌ Контейнер добре працює з короткими заголовками, але ламається на довгих назвах або повідомленнях.

Потрібно перевіряти:

- довгі заголовки;
- довгі URL;
- довгі назви кнопок;
- повідомлення про помилки;
- великі числа;
- таблиці;
- зображення;
- код.

---

## 9. Не враховувати box-sizing

За стандартної моделі CSS `content-box` ширина елемента не включає padding і border.

Наприклад:

    .container {
        width: 100%;
        padding-inline: 24px;
    }

Без іншого `box-sizing` фактична зовнішня ширина може перевищувати 100%.

Поширене рішення:

    *,
    *::before,
    *::after {
        box-sizing: border-box;
    }

За `border-box` задана ширина включає content, padding і border.

Це спрощує контроль розмірів контейнерів.

---

## 10. Ігнорувати переповнення

❌ Вміст контейнера виходить за його межі.

Причинами можуть бути:

- фіксована ширина дочірнього елемента;
- довгий нерозривний текст;
- велика таблиця;
- неправильна grid-структура;
- зображення без обмеження ширини;
- надто великий `min-width`.

Потрібно перевіряти не тільки сам контейнер, а й усіх його дочірніх елементів.

# Головне

• Container допомагає організовувати контент і контролювати його ширину.

• Контейнер може бути невидимим і виконувати лише структурну функцію.

• Page container допомагає створювати послідовну структуру сторінки.

• Content container контролює ширину текстових та інформаційних блоків.

• Section container допомагає вирівнювати контент усередині секцій.

• Card container групує елементи картки.

• Full-width section може містити внутрішній контейнер з обмеженою шириною.

• `width` задає ширину елемента.

• `max-width` встановлює максимальну ширину.

• `min-width` встановлює мінімальну ширину, але потребує обережного використання в адаптивних макетах.

• `margin` створює зовнішні відступи.

• `padding` створює внутрішні відступи.

• `margin-inline: auto` часто використовується для центрування контейнера.

• Responsive container поєднує гнучку ширину, максимальне обмеження та бокові відступи.

• Вкладені контейнери корисні, якщо кожен із них виконує окрему функцію.

• Надмірне вкладення може ускладнювати компонування та зменшувати доступний простір.

• Контейнери потрібно перевіряти з реальним контентом, включно з довгими текстами, таблицями та зображеннями.

• `box-sizing: border-box` спрощує контроль розмірів елементів.

• Container queries дозволяють адаптувати компоненти до ширини їхнього контейнера, а не тільки viewport.

• Design tokens допомагають підтримувати однакові правила ширини та відступів у дизайн-системі.

• Основна модель контейнера:

    Viewport
        ↓
    Page container
        ↓
    Section container
        ↓
    Component container
        ↓
    Content

• Основна мета контейнера — забезпечити контрольоване, послідовне та адаптивне розміщення контенту.

• Правильно спроєктовані контейнери створюють основу для читабельного, збалансованого та масштабованого інтерфейсу.
