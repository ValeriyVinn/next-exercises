# 09. Proximity — Близькість елементів у UI-дизайні

## 1. Що таке Proximity

**Proximity (близькість)** — це принцип візуального дизайну, за яким елементи, розташовані близько один до одного, сприймаються як пов'язані між собою, а елементи з більшою відстанню — як окремі групи.

Цей принцип допомагає користувачеві зрозуміти структуру інтерфейсу без додаткових пояснень.

Наприклад, у формі реєстрації:

- Поле `Email` і його підпис мають бути розташовані близько.
- Поле `Password` і його підпис також утворюють окрему групу.
- Кнопка `Create account` має бути пов'язана з формою, але не повинна зливатися з останнім полем.
- Посилання `Already have an account? Log in` може бути розташоване трохи далі, щоб сприйматися як додаткова дія.

Основна ідея:

**Відстань між елементами передає інформацію про зв'язки між ними.**

---

## 2. Навіщо потрібен Proximity

Правильно організована близькість допомагає:

- Групувати пов'язані елементи.
- Відокремлювати різні частини інтерфейсу.
- Покращувати читабельність.
- Зменшувати когнітивне навантаження (Cognitive Load).
- Створювати зрозумілу візуальну ієрархію.
- Робити інтерфейс передбачуваним.
- Скорочувати час, потрібний для пошуку інформації.
- Покращувати сприйняття форм, карток, навігації та сторінок.

### Приклад

Погане групування:

    Email

    Password

    Confirm password

    Forgot password?

    Create account

    Already have an account? Log in

Усі елементи розташовані приблизно на однаковій відстані. Користувачеві складніше зрозуміти, які елементи належать до одного логічного блоку.

Краще групування:

    Email
    [________________]

    Password
    [________________]
    Forgot password?

    Confirm password
    [________________]

    [Create account]

    Already have an account? Log in

Відстані допомагають розділити поля, додаткові посилання, основну дію та альтернативну дію.

## 3. Proximity і принципи Gestalt

Proximity належить до принципів гештальт-психології (Gestalt Principles).

Гештальт-принципи описують, як людина природно організовує візуальну інформацію та сприймає окремі елементи як цілісні групи.

### Основні принципи, пов'язані з UI-дизайном

| Принцип | Значення | Приклад у UI |
|---|---|---|
| Proximity | Близькі елементи сприймаються як група | Підпис і поле форми |
| Similarity | Подібні елементи сприймаються як пов'язані | Однакові кнопки навігації |
| Common Region | Елементи в спільній області сприймаються як група | Картка товару |
| Continuity | Погляд рухається вздовж напрямку або лінії | Горизонтальна навігація |
| Closure | Мозок доповнює незавершені форми | Частково окреслена іконка |
| Figure-Ground | Розрізнення переднього плану та фону | Модальне вікно поверх сторінки |

### Важливо

Proximity не працює ізольовано. У реальному інтерфейсі близькість поєднується з:

- кольором;
- розміром;
- контрастом;
- типографікою;
- межами;
- фоном;
- вирівнюванням.

Якщо елементи розташовані близько, але мають різне призначення, користувач може все одно сприймати їх як одну групу. Тому відстань потрібно узгоджувати з іншими візуальними сигналами.

---

## 4. Основне правило: внутрішні та зовнішні відступи

Один із найважливіших способів застосування Proximity — різниця між внутрішніми й зовнішніми відступами групи.

**Відстань між елементами всередині групи має бути меншою за відстань між окремими групами.**

Наприклад:

    Label
    [Input]
        8 px

    Наступна група
        24 px

Це не універсальні обов'язкові значення. Це приклад співвідношення відстаней.

### Приклад із CSS

    .form {
      display: flex;
      flex-direction: column;
      gap: 24px;
    }

    .form-field {
      display: flex;
      flex-direction: column;
      gap: 8px;
    }

У цьому прикладі:

- `8px` — відстань між підписом і полем введення.
- `24px` — відстань між групами полів.

Завдяки цьому кожне поле сприймається як єдиний компонент, а різні поля — як окремі групи всередині форми.

## 5. Proximity у різних частинах інтерфейсу

### 5.1. Форми (Forms)

Форми — один із найкращих прикладів застосування Proximity.

Кожне поле зазвичай містить:

- Label — підпис поля.
- Input — поле введення.
- Hint — підказку.
- Error message — повідомлення про помилку.

Ці елементи мають бути візуально пов'язані.

Приклад:

    Email address
    [name@example.com]
    We will send a confirmation email.

    Password
    [Enter your password]
    Use at least 8 characters.

У CSS:

    .form-field {
      display: flex;
      flex-direction: column;
      gap: 8px;
      margin-bottom: 24px;
    }

    .form-field__hint {
      margin: 0;
      font-size: 0.875rem;
    }

Не варто розташовувати підказку ближче до наступного поля, ніж до того, якого вона стосується.

### 5.2. Картки (Cards)

У картці товару або статті можуть бути:

- Зображення.
- Назва.
- Опис.
- Ціна або дата.
- Кнопка дії.

Пов'язані елементи потрібно об'єднати в групи.

Наприклад:

    [Product image]

    Wireless Headphones
    Premium sound for everyday use.

    $79.00

    [Add to cart]

Назва й опис утворюють одну групу. Ціна та кнопка можуть утворювати окрему групу покупки.

Приклад CSS:

    .product-card {
      display: flex;
      flex-direction: column;
      gap: 16px;
      padding: 20px;
      border-radius: 12px;
    }

    .product-card__info {
      display: flex;
      flex-direction: column;
      gap: 6px;
    }

    .product-card__purchase {
      display: flex;
      flex-direction: column;
      gap: 12px;
      margin-top: auto;
    }

Тут `gap` визначає відстань між великими частинами картки, а менший `gap` — між назвою та описом.

### 5.3. Навігація (Navigation)

Елементи одного рівня навігації мають утворювати групу.

    Home   Courses   About   Contact

Водночас навігація, логотип і кнопка входу можуть мати окремі просторові групи.

Приклад:

    .navbar {
      display: flex;
      align-items: center;
      justify-content: space-between;
    }

    .navbar__links {
      display: flex;
      align-items: center;
      gap: 24px;
    }

Важливо відрізняти відстань між посиланнями всередині навігації від відстані між навігацією та іншими елементами шапки.

### 5.4. Секції сторінки (Sections)

Заголовок секції, короткий вступ і пов'язаний контент повинні сприйматися як одна група.

    Our courses
    Learn practical skills with structured lessons.

    [Course card] [Course card] [Course card]

Відстань між заголовком і вступом зазвичай менша, ніж відстань між вступом і сіткою карток.

Приклад:

    .section__header {
      display: flex;
      flex-direction: column;
      gap: 12px;
      margin-bottom: 32px;
    }

    .section__description {
      max-width: 60ch;
    }

Так заголовок і опис залишаються пов'язаними, а контент отримує чітке відокремлення.

### 5.5. Dashboard

На панелі керування (Dashboard) можуть бути:

- Заголовок сторінки.
- Фільтри.
- Картки статистики.
- Графіки.
- Таблиці.
- Панель останніх подій.

Proximity допомагає відрізняти групи даних і не перетворювати сторінку на суцільний масив інформації.

Приклад:

    Dashboard
    Overview of your activity

    [Revenue] [Users] [Orders]

    Recent activity
    [Activity table]

    Performance
    [Chart]

Картки статистики утворюють одну групу, таблиця та графік — окремі секції.

## 6. Proximity і spacing system

Spacing system — це система стандартизованих відступів, яка допомагає підтримувати послідовність інтерфейсу.

Замість випадкових значень дизайнер або розробник використовує обмежений набір відстаней.

Наприклад:

| Токен | Значення | Типове застосування |
|---|---:|---|
| `space-1` | 4px | Дуже близькі елементи |
| `space-2` | 8px | Підпис і поле |
| `space-3` | 12px | Елементи всередині групи |
| `space-4` | 16px | Внутрішній простір компонента |
| `space-6` | 24px | Відстань між компонентами |
| `space-8` | 32px | Відстань між великими блоками |
| `space-12` | 48px | Відстань між секціями |
| `space-16` | 64px | Великі вертикальні інтервали |

Це лише приклад системи. Реальні дизайн-системи можуть використовувати інші значення.

### CSS Custom Properties

    :root {
      --space-1: 4px;
      --space-2: 8px;
      --space-3: 12px;
      --space-4: 16px;
      --space-6: 24px;
      --space-8: 32px;
      --space-12: 48px;
      --space-16: 64px;
    }

Використання:

    .field {
      display: flex;
      flex-direction: column;
      gap: var(--space-2);
    }

    .form {
      display: flex;
      flex-direction: column;
      gap: var(--space-6);
    }

    .page-section {
      margin-bottom: var(--space-12);
    }

### Чому система краща за випадкові відступи

- Інтерфейс виглядає послідовно.
- Легше змінювати дизайн.
- Менше випадкових CSS-значень.
- Простіше створювати нові компоненти.
- Зручніше підтримувати дизайн-систему.

## 7. Proximity, margin, padding і gap

Ці CSS-властивості можуть впливати на відстані, але мають різні призначення.

| Властивість | Що контролює | Приклад |
|---|---|---|
| `margin` | Зовнішній простір навколо елемента | Відстань між секціями |
| `padding` | Внутрішній простір елемента | Відстань від краю картки до контенту |
| `gap` | Відстань між елементами Flexbox або Grid | Відстань між полями форми |
| `row-gap` | Відстань між рядками | Відстань між рядами карток |
| `column-gap` | Відстань між колонками | Відстань між картками в одному рядку |

### Приклад

    .card {
      padding: 24px;
    }

    .card__content {
      display: flex;
      flex-direction: column;
      gap: 12px;
    }

    .card + .card {
      margin-top: 24px;
    }

Тут:

- `padding` створює простір усередині картки.
- `gap` регулює відстані між елементами контенту.
- `margin-top` додає відстань між сусідніми картками в такому вертикальному розташуванні.

### Коли використовувати gap

`gap` особливо зручний для керування відстанями між елементами одного контейнера.

    .button-group {
      display: flex;
      gap: 12px;
    }

    .card-grid {
      display: grid;
      grid-template-columns: repeat(3, minmax(0, 1fr));
      gap: 24px;
    }

`gap` не додає відступ навколо всієї групи. Для зовнішнього простору використовують `padding`, `margin` або інші засоби компонування.

## 8. Proximity і візуальна ієрархія

Візуальна ієрархія (Visual Hierarchy) допомагає визначити, що користувач помітить першим, другим і третім.

Proximity допомагає зрозуміти, які елементи належать до одного змістового блоку.

Наприклад:

    Course title

    Short course description

    Instructor information

    [Start learning]

Якщо відстань між назвою й описом невелика, вони сприймаються як єдина інформаційна група.

Якщо блок інформації про викладача відділений більшим інтервалом, він сприймається як додаткова група.

Кнопка дії може бути відокремлена від тексту, але залишатися пов'язаною з карткою.

### Proximity не замінює ієрархію

Відстань — лише один із сигналів.

Також важливі:

- Розмір шрифту.
- Насиченість шрифту.
- Контраст.
- Колір.
- Позиція.
- Типографічні рівні.
- Розмір і форма компонентів.

Наприклад, навіть якщо допоміжний текст розташований близько до заголовка, він не повинен візуально конкурувати з ним.

## 9. Proximity і візуальне групування

Є кілька способів показати, що елементи належать до однієї групи.

### 9.1. Просторова близькість

    Title
    Description

Елементи розташовані близько один до одного.

### 9.2. Спільний фон

    ┌──────────────────────┐
    │ Title                │
    │ Description          │
    └──────────────────────┘

Спільна область підсилює сприйняття групи.

### 9.3. Межі

    ┌──────────────────────┐
    │ Profile information  │
    └──────────────────────┘

Межі візуально відокремлюють групу від сусідніх елементів.

### 9.4. Типографіка

Заголовок і підзаголовок можуть мати різні розміри, але залишатися пов'язаними завдяки близькому розташуванню.

### 9.5. Вирівнювання

Елементи, що починаються на одній вертикальній лінії, можуть сприйматися як частини однієї структури.

**Практичне правило:** не потрібно одночасно застосовувати всі способи групування. Якщо відстані вже чітко показують зв'язок, додаткові рамки й фони можуть бути зайвими.

## 10. Proximity у responsive design

На різних розмірах екрана просторові зв'язки мають залишатися зрозумілими.

Наприклад, картки, розташовані в три колонки на широкому екрані, можуть переходити в одну колонку на мобільному.

    .card-grid {
      display: grid;
      grid-template-columns: repeat(3, minmax(0, 1fr));
      gap: 24px;
    }

    @media (max-width: 768px) {
      .card-grid {
        grid-template-columns: repeat(2, minmax(0, 1fr));
        gap: 16px;
      }
    }

    @media (max-width: 480px) {
      .card-grid {
        grid-template-columns: 1fr;
        gap: 20px;
      }
    }

Відстані можна адаптувати під доступний простір, але не варто руйнувати логічні групи.

### На мобільних пристроях

- Підпис поля має залишатися поруч із відповідним полем.
- Кнопка має бути чітко пов'язана зі своєю дією.
- Секції повинні бути візуально відокремлені.
- Елементи навігації не повинні зливатися в нерозбірливий ряд.
- Між інтерактивними елементами має залишатися достатньо місця для зручного натискання.

Важливо: близькість — це не вимога розташовувати всі елементи максимально близько. Мета полягає в тому, щоб відстані допомагали зрозуміти структуру інтерфейсу.

## 11. Proximity та accessibility

Правильне групування покращує доступність інтерфейсу, але одних відступів недостатньо.

### Основні правила

1. Поле форми повинно мати зрозумілий підпис.
2. Помилка повинна бути пов'язана саме з тим полем, якого вона стосується.
3. Підказки мають бути розташовані поруч із відповідними елементами.
4. Групи радіокнопок і прапорців повинні мати зрозумілу спільну назву.
5. Інтерактивні елементи повинні мати достатній простір для натискання.
6. Логічна структура має зберігатися і для користувачів допоміжних технологій.

### Приклад доступної форми

    <form>
      <div class="form-field">
        <label for="email">Email address</label>

        <input
          id="email"
          name="email"
          type="email"
          aria-describedby="email-hint"
        />

        <p id="email-hint">
          We will use this address to contact you.
        </p>
      </div>

      <button type="submit">Continue</button>
    </form>

CSS:

    .form-field {
      display: flex;
      flex-direction: column;
      gap: 8px;
      margin-bottom: 24px;
    }

    .form-field p {
      margin: 0;
      font-size: 0.875rem;
    }

У цьому прикладі візуальна близькість доповнюється семантичним HTML і зв'язком підказки з полем через `aria-describedby`.

**Пам'ятай:** CSS-відступи самі по собі не створюють семантичних зв'язків для скринридерів.

## 12. Практичний приклад: форма реєстрації

Нижче — простий приклад, у якому Proximity допомагає структурувати форму.

### HTML

    <main class="page">
      <section class="signup">
        <header class="signup__header">
          <h1>Create an account</h1>
          <p>Start learning with your personal account.</p>
        </header>

        <form class="signup__form">
          <div class="form-field">
            <label for="name">Full name</label>
            <input
              id="name"
              name="name"
              type="text"
              autocomplete="name"
              required
            />
          </div>

          <div class="form-field">
            <label for="email">Email address</label>
            <input
              id="email"
              name="email"
              type="email"
              autocomplete="email"
              required
            />
            <p class="form-field__hint">
              Use an email address you can access.
            </p>
          </div>

          <div class="form-field">
            <label for="password">Password</label>
            <input
              id="password"
              name="password"
              type="password"
              autocomplete="new-password"
              required
            />
          </div>

          <button class="signup__button" type="submit">
            Create account
          </button>
        </form>

## 13. Типові помилки

### Помилка 1. Однакові відстані між усіма елементами

Якщо відстань між підписом і полем дорівнює відстані між секціями, групування стає нечітким.

**Рішення:** використовуй менші відстані всередині груп і більші — між групами.

### Помилка 2. Надто велика відстань між пов'язаними елементами

Приклад: повідомлення про помилку розташоване далеко від поля, в якому виникла помилка.

**Рішення:** розміщуй допоміжну інформацію поруч із відповідним елементом.

### Помилка 3. Надто мала відстань між різними групами

Дві окремі секції можуть сприйматися як одна.

**Рішення:** збільшуй інтервал між секціями або використовуй додаткові візуальні сигнали.

### Помилка 4. Використання рамок замість правильних відступів

Дизайнер додає рамки до всіх елементів, щоб компенсувати погане групування.

**Рішення:** спочатку спробуй виправити відстані. Рамки мають з'являтися лише тоді, коли вони справді допомагають.

### Помилка 5. Занадто багато різних значень spacing

Наприклад:

    gap: 7px;
    margin-bottom: 19px;
    padding: 23px;
    margin-top: 31px;

Такі значення не обов'язково неправильні, але без системи вони ускладнюють підтримку дизайну.

**Рішення:** використовуй узгоджені spacing-токени.

### Помилка 6. Застосування одного `gap` до всіх рівнів

Внутрішні елементи картки та великі секції сторінки мають різні потреби.

**Рішення:** створюй вкладені контейнери з окремими правилами відстаней.

### Помилка 7. Надмірне ущільнення мобільного інтерфейсу

Зменшення ширини екрана не означає, що всі відступи треба пропорційно зменшити.

**Рішення:** адаптуй відстані до контенту, читабельності та зручності взаємодії.

### Помилка 8. Покладання лише на близькість

Іноді елементи розташовані близько, але користувач усе одно не розуміє їхнього зв'язку.

**Рішення:** перевіряй також семантику, типографіку, контраст, вирівнювання та структуру HTML.

## 14. Як перевіряти Proximity у готовому дизайні

Використовуй простий практичний алгоритм.

### Крок 1. Знайди логічні групи

Подивися на сторінку та визнач:

- Які елементи належать до однієї групи?
- Які елементи мають бути відокремлені?
- Які частини сторінки утворюють секції?

### Крок 2. Перевір внутрішні відстані

Чи розташовані заголовок та його опис достатньо близько?

Чи зрозуміло, до якого поля належить підказка?

### Крок 3. Перевір зовнішні відстані

Чи достатньо відокремлені різні картки, секції та групи полів?

### Крок 4. Прибери зайве оформлення

Спробуй тимчасово прибрати декоративні рамки, фони й тіні.

Чи залишається структура зрозумілою завдяки відстаням?

### Крок 5. Перевір різні екрани

Подивися на дизайн на широкому, планшетному та мобільному екранах.

### Крок 6. Проведи тест розуміння

Покажи сторінку іншій людині й попроси відповісти:

- Які елементи належать до однієї групи?
- Яку дію потрібно виконати?
- Де починається наступна секція?
- До якого поля належить повідомлення?

Якщо структура зрозуміла без пояснень, просторове групування працює добре.

## 15. Proximity у дизайн-системі

У великому проєкті Proximity потрібно підтримувати системно, а не налаштовувати кожен компонент окремо.

### Приклад токенів

    :root {
      --space-inline-tight: 4px;
      --space-inline-normal: 8px;
      --space-group-tight: 12px;
      --space-group-normal: 16px;
      --space-component: 24px;
      --space-section: 48px;
      --space-section-large: 64px;
    }

Назви токенів можуть описувати як розмір, так і призначення. Головне — щоб їх значення та використання були послідовними.

### Приклад застосування

    .field {
      display: flex;
      flex-direction: column;
      gap: var(--space-inline-normal);
    }

    .filter-group {
      display: flex;
      flex-wrap: wrap;
      gap: var(--space-group-tight);
    }

    .toolbar {
      display: flex;
      align-items: center;
      gap: var(--space-component);
    }

    .page-section {
      margin-block-end: var(--space-section);
    }

### Переваги

- Єдина логіка відступів.
- Швидке оновлення дизайну.
- Менше випадкових значень.
- Легша співпраця дизайнерів і розробників.
- Простіша підтримка великого застосунку.

У реальній дизайн-системі значення токенів визначаються на основі потреб продукту, компонентів, типографіки та адаптивної поведінки.

## 16. Proximity у різних типах продуктів

### E-commerce

Групування назви товару, ціни, рейтингу та кнопки покупки.

### Освітні платформи

Групування назви курсу, опису, викладача, тривалості й кнопки початку навчання.

### Медичні застосунки

Чітке відокремлення особистої інформації, показників, рекомендацій і дій користувача. Особливо важливо не створювати неоднозначності щодо того, до якого показника належить підпис.

### Фінансові Dashboard

Групування показників, їхніх значень, одиниць вимірювання та періодів.

### Форми реєстрації

Зв'язок між підписами, полями, підказками та повідомленнями про помилки.

### Мобільні застосунки

Групування елементів меню, налаштувань, профілю та дій.

У кожному випадку мета однакова: зробити зв'язки між елементами очевидними.

## 17. Питання для співбесіди

### Junior

**1. Що таке Proximity?**

Принцип дизайну, за яким відстань між елементами допомагає показати їхній логічний зв'язок.

**2. Навіщо потрібен Proximity?**

Щоб групувати контент, покращувати читабельність і робити структуру інтерфейсу зрозумілішою.

**3. Як Proximity пов'язаний із Gestalt?**

Це один із гештальт-принципів, який пояснює, чому близько розташовані елементи люди сприймають як групу.

**4. Як застосувати Proximity у формі?**

Розмістити підпис, поле та підказку близько, а різні групи полів відокремити більшими відступами.

**5. Які CSS-властивості допомагають реалізувати Proximity?**

`gap`, `row-gap`, `column-gap`, `margin` і `padding`.

### Middle

**6. Як Proximity впливає на візуальну ієрархію?**

Допомагає визначити логічні групи та межі між ними, доповнюючи розмір, контраст і типографіку.

**7. Чому не варто використовувати однакові відстані всюди?**

Тому що внутрішні зв'язки груп і відмінності між групами мають різну силу.

**8. Як Proximity працює разом із Common Region?**

Близькість групує елементи через відстань, а Common Region — через спільну візуальну область, наприклад фон або картку.

**9. Як організувати Proximity у дизайн-системі?**

Створити послідовну систему spacing-токенів і застосовувати її до компонентів та секцій.

**10. Як перевірити, що групування працює?**

Перевірити візуальну структуру без зайвого декору, переглянути адаптивні версії та провести тест розуміння з користувачами.

### Senior

**11. Чи завжди близькі елементи сприймаються як пов'язані?**

Не завжди. Інші сигнали — колір, межі, типографіка, контраст і семантика — можуть підсилювати або послаблювати цей зв'язок.

**12. Як Proximity впливає на складні Dashboard?**

Допомагає організувати багато даних у зрозумілі групи, зменшуючи візуальну плутанину та полегшуючи пошук потрібної інформації.

**13. Як балансувати щільність інформації та відступи?**

Визначити пріоритети, об'єднати пов'язаний контент, використовувати послідовну шкалу відстаней і перевіряти дизайн на реальних сценаріях.

**14. Як відрізнити проблему Proximity від проблеми інформаційної архітектури?**

Якщо елементи логічно згруповані неправильно навіть за достатніх відступів, проблема може бути в самій структурі контенту. Якщо групи правильні, але візуально не читаються, слід перевірити відстані та інші візуальні сигнали.

8. Не покладайся лише на CSS-відступи для семантичної доступності.

## 21. Що потрібно запам'ятати

**Proximity — це спосіб передавати зміст через відстань.**

Коли пов'язані елементи розташовані близько, а незалежні групи розділені достатнім простором, інтерфейс стає зрозумілішим без додаткових декоративних елементів.

Під час створення UI став собі три запитання:

1. Які елементи користувач має сприймати як одну групу?
2. Якою відстанню я покажу зв'язок усередині групи?
3. Якою відстанню я відокремлю цю групу від інших?

Якщо відповіді зрозумілі й послідовно реалізовані в CSS, ти правильно використовуєш принцип Proximity.

**Наступна тема:** `10-whitespace` — негативний простір (Whitespace), його роль у читабельності, візуальному балансі та сприйнятті інтерфейсу.
