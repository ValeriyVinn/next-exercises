# 01. Layout Basics

Layout (компонування) — це спосіб організації візуальних елементів інтерфейсу на сторінці або екрані.

Layout визначає, де розташовані елементи, як вони співвідносяться між собою, скільки простору займають і як користувач сприймає структуру інтерфейсу.

У UI Design layout допомагає організувати:

- текст і заголовки;
- зображення та ілюстрації;
- кнопки та форми;
- картки та компоненти;
- навігацію;
- секції сторінки;
- списки та таблиці;
- інформаційні блоки;
- інтерактивні елементи.

Основна мета layout — зробити інтерфейс зрозумілим, послідовним, зручним для використання та візуально збалансованим.

Layout — це не просто розташування елементів. Це спосіб показати користувачеві, що важливо, як інформація пов'язана між собою та в якому порядку її сприймати.

## Що потрібно пам'ятати

• Layout визначає, як елементи інтерфейсу організовані в просторі.

• Composition — це загальна організація візуальних елементів та їхніх взаємозв'язків.

• Visual hierarchy допомагає користувачеві зрозуміти, які елементи найважливіші.

• Alignment створює порядок і візуальний зв'язок між елементами.

• Spacing допомагає відокремлювати елементи та групи інформації.

• Whitespace — це вільний простір навколо та між елементами.

• Container обмежує або організовує область, у якій розміщується контент.

• Grid допомагає розташовувати елементи відповідно до спільної структури.

• Section — це логічна частина сторінки з певною метою або темою.

• Layout повинен відповідати типу контенту, а не змушувати контент підлаштовуватися під довільну композицію.

• Хороший layout робить структуру зрозумілою навіть без декоративних ефектів.

• Responsive layout адаптується до різних розмірів екрана.

• Послідовність розташування елементів важлива для передбачуваності інтерфейсу.

• Візуальна краса не компенсує незрозумілу структуру або складну навігацію.

• Layout у UI Design визначає принципи компонування, а CSS реалізує їх у вебінтерфейсі.

# Що таке Layout

Layout — це система розташування елементів у межах певного простору.

Наприклад, сторінка навчального курсу може містити:

    Header
        ↓
    Navigation
        ↓
    Hero section
        ↓
    Course overview
        ↓
    Course modules
        ↓
    Footer

Це структурний layout сторінки.

Кожна частина має власне призначення та займає певне місце в загальній композиції.

Інший приклад — картка курсу:

    ┌─────────────────────────────┐
    │                             │
    │          Image              │
    │                             │
    ├─────────────────────────────┤
    │ Course title                │
    │ Short description           │
    │                             │
    │ Duration        Level       │
    │                             │
    │ [View course]               │
    └─────────────────────────────┘

Тут layout визначає:

- порядок елементів;
- їхнє взаємне розташування;
- відступи;
- ширину контенту;
- розміри зображення;
- положення кнопки;
- співвідношення між інформаційними блоками.

Layout може описувати як усю сторінку, так і окремий компонент.

# Layout vs Composition

Ці поняття пов'язані, але не повністю тотожні.

## Layout

Layout зосереджується на структурі та розташуванні елементів.

Наприклад:

    Header
    Main
        Sidebar
        Content
    Footer

Основні питання:

- Де розташовані елементи?
- Як організовані колонки?
- Яка ширина контенту?
- Як елементи адаптуються до екрана?

## Composition

Composition — це організація елементів у цілісну візуальну систему.

Наприклад, на hero section потрібно вирішити:

- де розташувати головний заголовок;
- як співвіднести текст і зображення;
- який елемент повинен привертати найбільше уваги;
- як розподілити візуальну вагу;
- як створити баланс між порожнім простором і контентом.

Отже:

    Layout      → структура та розташування
    Composition → цілісна візуальна організація

У реальному UI Design ці процеси постійно взаємодіють.

# Навіщо потрібен хороший Layout

Хороший layout допомагає вирішувати кілька важливих завдань.

## 1. Організація інформації

Користувач повинен розуміти, де знайти потрібну інформацію.

Наприклад:

    Page title
        ↓
    Short introduction
        ↓
    Main content
        ↓
    Additional information

Якщо елементи розташовані випадково, користувачеві складніше зрозуміти структуру сторінки.

## 2. Visual Hierarchy

Layout допомагає визначити порядок сприйняття інформації.

Наприклад:

    Main heading
        ↓
    Supporting text
        ↓
    Primary action
        ↓
    Secondary information

Важливі елементи можуть отримувати більше простору або розташовуватися у візуально помітнішій позиції.

## 3. Readability

Правильне компонування полегшує читання.

Наприклад:

- текст не повинен розтягуватися на надто широку область;
- абзаци повинні бути візуально відокремлені;
- заголовки мають бути пов'язані зі своїм контентом;
- довгі сторінки повинні мати зрозумілу структуру.

## 4. Usability

Layout допомагає користувачеві знаходити та використовувати інтерактивні елементи.

Наприклад:

- кнопка відправлення форми розташована поруч із полями;
- основна дія помітніша за другорядну;
- навігація має передбачуване розташування;
- пов'язані параметри форми згруповані разом.

## 5. Consistency

Повторення спільних правил створює послідовний інтерфейс.

Наприклад:

    Page A → однакова ширина контенту
    Page B → однакова ширина контенту
    Page C → однакова ширина контенту

Користувач швидше розуміє інтерфейс, якщо сторінки використовують схожі структурні принципи.

## 6. Responsive Design

Хороший layout повинен працювати на різних пристроях.

Наприклад:

    Desktop:
        Sidebar | Main content

    Tablet:
        Narrow sidebar | Main content

    Mobile:
        Main content
        Sidebar content below or in navigation

Адаптація залежить від призначення інтерфейсу та доступного простору.

# Основні типи Layout

У вебінтерфейсах можна використовувати різні структурні підходи.

## 1. Single-column Layout

Single-column layout — компонування в одну основну колонку.

    ┌─────────────────────────────┐
    │           Header            │
    ├─────────────────────────────┤
    │                             │
    │          Heading            │
    │          Text               │
    │          Image              │
    │          Button             │
    │                             │
    ├─────────────────────────────┤
    │           Footer            │
    └─────────────────────────────┘

Використовується для:

- статей;
- landing pages;
- простих форм;
- сторінок авторизації;
- навчальних матеріалів;
- сторінок із послідовним читанням.

Переваги:

- проста структура;
- зрозумілий порядок читання;
- зручна адаптація до мобільних пристроїв;
- легко контролювати ширину тексту.

---

## 2. Two-column Layout

Two-column layout — компонування у дві основні колонки.

    ┌─────────────────────────────┐
    │           Header            │
    ├───────────┬─────────────────┤
    │           │                 │
    │  Sidebar  │  Main content   │
    │           │                 │
    │           │                 │
    ├───────────┴─────────────────┤
    │           Footer            │
    └─────────────────────────────┘

Використовується для:

- панелей керування;
- документації;
- навчальних платформ;
- сторінок налаштувань;
- каталогів із фільтрами;
- адміністративних інтерфейсів.

Типовий розподіл простору може бути таким:

    Sidebar → 25%
    Content → 75%

Але це лише можливий приклад, а не обов'язкове правило.

Ширина колонок залежить від їхнього призначення та обсягу інформації.

---

## 3. Multi-column Layout

Multi-column layout — компонування у кілька колонок.

    ┌──────────┬──────────┬──────────┐
    │ Card 1   │ Card 2   │ Card 3   │
    ├──────────┼──────────┼──────────┤
    │ Card 4   │ Card 5   │ Card 6   │
    └──────────┴──────────┴──────────┘

Використовується для:

- карток товарів;
- галерей;
- списків курсів;
- карток послуг;
- каталогів;
- інформаційних панелей.

Кількість колонок визначається шириною екрана, мінімальною комфортною шириною картки та характером контенту.

Наприклад:

    Desktop → 3 columns
    Tablet  → 2 columns
    Mobile  → 1 column

---

## 4. Grid-based Layout

Grid-based layout — компонування на основі системи рядків і колонок.

Сітка допомагає узгоджувати положення елементів на сторінці.

    ┌──────┬──────┬──────┬──────┐
    │      │      │      │      │
    │  A   │  A   │  B   │  B   │
    │      │      │      │      │
    ├──────┼──────┼──────┼──────┤
    │      │      │      │      │
    │  C   │  C   │  C   │  D   │
    │      │      │      │      │
    └──────┴──────┴──────┴──────┘

Grid дозволяє елементам займати одну або кілька колонок.

Використовується для:

- складних landing pages;
- dashboard;
- карткових інтерфейсів;
- редакційних макетів;
- каталогів;
- сторінок із різними типами контенту.

У веброзробці такі принципи часто реалізуються за допомогою CSS Grid.

---

## 5. Modular Layout

Modular layout — компонування з повторюваних модулів.

Наприклад:

    ┌─────────────────────────────┐
    │ Module 1                    │
    ├─────────────────────────────┤
    │ Module 2                    │
    ├─────────────────────────────┤
    │ Module 3                    │
    ├─────────────────────────────┤
    │ Module 4                    │
    └─────────────────────────────┘

Модулем може бути:

- картка;
- інформаційний блок;
- віджет;
- секція;
- рядок таблиці;
- елемент списку.

Переваги:

- повторюваність;
- передбачувана структура;
- зручність підтримки;
- можливість повторного використання компонентів.

Modular layout особливо важливий для великих застосунків і дизайн-систем.

# Основні складові Layout

## 1. Viewport

Viewport — видима область вебсторінки у вікні браузера.

Його розміри впливають на те, скільки контенту можна показати одночасно.

Наприклад:

    Desktop viewport:
        широка робоча область

    Tablet viewport:
        обмежена ширина

    Mobile viewport:
        вузька робоча область

Важливо пам'ятати:

- viewport не дорівнює розміру фізичного екрана;
- розміри доступної області можуть змінюватися;
- мобільний браузер може змінювати видиму висоту під час показу панелей;
- інтерфейс повинен адаптуватися до доступного простору.

---

## 2. Content Area

Content area — область, у якій розташовується основний контент.

Наприклад:

    ┌─────────────────────────────────┐
    │             Margin              │
    │   ┌─────────────────────────┐   │
    │   │      Content area       │   │
    │   │                         │   │
    │   │  Heading                │   │
    │   │  Paragraph              │   │
    │   │  Button                 │   │
    │   │                         │   │
    │   └─────────────────────────┘   │
    │             Margin              │
    └─────────────────────────────────┘

Content area може містити текст, зображення, картки, форми або інші компоненти.

Її ширина повинна відповідати типу контенту.

Наприклад:

- довгий текст потребує контрольованої ширини;
- таблиця може потребувати ширшої області;
- форма авторизації зазвичай не потребує всієї ширини екрана;
- dashboard може використовувати значну частину доступного простору.

---

## 3. Container

Container — елемент або область, яка групує контент і допомагає контролювати його розташування та ширину.

Наприклад:

    Page
        ↓
    Container
        ↓
    Section
        ↓
    Components

Container може:

- обмежувати максимальну ширину;
- створювати бокові відступи;
- вирівнювати секції;
- задавати спільну область контенту;
- підтримувати однакову структуру різних сторінок.

У CSS container часто реалізують через `width`, `max-width`, `margin` і `padding`.

    .container {
        width: 100%;
        max-width: 1200px;
        margin-inline: auto;
        padding-inline: 24px;
    }

У цьому прикладі:

    width: 100%
        → контейнер займає доступну ширину

    max-width: 1200px
        → ширина не перевищує 1200px

    margin-inline: auto
        → контейнер центрується по горизонталі

    padding-inline: 24px
        → контент має бокові відступи

Числа наведені як приклад, а не як універсальний стандарт.

---

## 4. Section

Section — логічно відокремлена частина сторінки.

Наприклад, landing page може містити:

    Header
        ↓
    Hero section
        ↓
    Features section
        ↓
    Benefits section
        ↓
    Testimonials section
        ↓
    Pricing section
        ↓
    FAQ section
        ↓
    Footer

Кожна секція має власне завдання.

Наприклад:

    Hero
        → пояснити основну пропозицію

    Features
        → показати можливості продукту

    Benefits
        → пояснити користь для користувача

    Testimonials
        → надати соціальне підтвердження

    Pricing
        → показати умови оплати

    FAQ
        → відповісти на поширені запитання

Секції повинні бути організовані в логічній послідовності.

---

## 5. Columns

Columns — вертикальні області, на які поділяється простір.

Наприклад:

    ┌────────────┬──────────────────┐
    │            │                  │
    │ Navigation │ Content          │
    │            │                  │
    └────────────┴──────────────────┘

Колонки можуть мати:

- однакову ширину;
- різну ширину;
- фіксовану ширину;
- гнучку ширину;
- мінімальну або максимальну ширину.

Наприклад:

    Sidebar → fixed or limited width
    Content → flexible width

Не потрібно робити всі колонки однаковими. Їхні пропорції мають відповідати задачам інтерфейсу.

---

## 6. Rows

Rows — горизонтальні області, які допомагають організовувати елементи один під одним або в спільній горизонтальній структурі.

Наприклад:

    Row 1 → Heading
    Row 2 → Description
    Row 3 → Actions
    Row 4 → Additional information

Рядки використовуються в:

- таблицях;
- списках;
- формах;
- карткових компонентах;
- dashboard;
- навігаційних панелях.

У CSS Flexbox і Grid дозволяють контролювати розташування елементів у рядках.

# Visual Hierarchy

Visual hierarchy — принцип організації елементів за рівнем важливості.

Користувач повинен розуміти:

- що побачити першим;
- що прочитати далі;
- які елементи пов'язані;
- де виконати основну дію;
- яка інформація є другорядною.

Наприклад:

    1. Main heading
    2. Supporting text
    3. Primary button
    4. Secondary information

Візуальну ієрархію можна створювати за допомогою:

- розміру;
- положення;
- контрасту;
- кольору;
- типографіки;
- spacing;
- групування;
- форми;
- вільного простору.

Наприклад:

    Main heading
        → більший розмір і помітніше положення

    Supporting text
        → менший розмір

    Primary action
        → помітний інтерактивний елемент

    Additional information
        → нижчий рівень візуального акценту

Важливо: візуальна ієрархія не означає, що всі сторінки повинні починатися з великого заголовка. Структура залежить від задачі та контексту.

---

# Reading Order

Reading order — порядок, у якому користувач сприймає контент.

Наприклад:

    Heading
        ↓
    Description
        ↓
    Form
        ↓
    Submit button

Цей порядок природний для багатьох форм.

Але якщо візуальний порядок суперечить логічному, користувачеві може бути складніше зрозуміти інтерфейс.

Під час створення layout потрібно враховувати:

- логічну послідовність інформації;
- очікування користувача;
- напрямок читання;
- порядок інтерактивних елементів;
- поведінку інтерфейсу на мобільних пристроях;
- порядок елементів для клавіатурної навігації та допоміжних технологій.

Важливо: візуальне переміщення елементів не повинно без потреби порушувати логічний порядок читання та взаємодії.

---

# Alignment

Alignment — вирівнювання елементів відносно спільної лінії або області.

Приклад правильного вирівнювання:

    Heading
    Paragraph text
    Supporting text
    Button

Елементи починаються з однієї вертикальної лінії.

Alignment створює відчуття порядку та допомагає пов'язувати елементи між собою.

Основні типи:

    Left alignment
    Center alignment
    Right alignment
    Top alignment
    Middle alignment
    Bottom alignment

Наприклад:

- текст статті часто вирівнюють ліворуч;
- короткий заголовок landing page іноді центрують;
- поля форми часто мають спільну ширину;
- іконки й текст кнопки вирівнюють відносно одне одного.

Центрування не є універсальним рішенням. Вирівнювання потрібно вибирати відповідно до типу контенту та задачі.

Детальніше alignment розглядатиметься в:

    02-layout-and-composition/
    └── 03-alignment

---

# Spacing

Spacing — система відстаней між елементами.

Наприклад:

    Heading

        Paragraph

        Button

Відстані допомагають визначити:

- які елементи пов'язані;
- де закінчується одна група;
- де починається наступна;
- які елементи мають спільну функцію.

Наприклад:

    Label
    Input

    Label
    Input

    Submit button

Невеликий відступ між label та input допомагає сприймати їх як єдину групу.

Більший відступ перед кнопкою може відокремлювати основну дію від полів форми.

Основний принцип:

    Related elements
        → usually closer

    Unrelated groups
        → usually farther apart

Конкретні значення spacing залежать від контексту та дизайн-системи.

Детальніше spacing розглядатиметься в:

    02-layout-and-composition/
    └── 04-spacing

# Whitespace

Whitespace — вільний простір навколо та між елементами інтерфейсу.

Це не обов'язково білий колір. Простір може бути будь-якого кольору або прозорим.

Whitespace допомагає:

- зменшувати візуальне перевантаження;
- відокремлювати групи;
- підкреслювати важливі елементи;
- покращувати читабельність;
- створювати візуальний ритм;
- робити композицію спокійнішою.

Приклад перевантаженого компонування:

    Heading
    Text Text Text
    Button Link Image
    Text Button Text
    Image Text Link

Приклад структурованого компонування:

    Heading

    Supporting text

    [Primary button]


    Additional information

Whitespace не означає, що потрібно максимально збільшувати всі відступи.

Завдання — використовувати простір так, щоб він допомагав розуміти структуру.

Детальніше whitespace розглядатиметься в:

    02-layout-and-composition/
    └── 10-whitespace

---

# Balance

Balance — візуальна рівновага композиції.

Елементи можуть мати різну візуальну вагу залежно від:

- розміру;
- кольору;
- контрасту;
- щільності;
- положення;
- форми;
- кількості деталей.

Наприклад:

    Text content | Large image

Якщо зображення дуже велике та контрастне, воно може привертати більше уваги, ніж текст.

Це може бути бажаним або небажаним залежно від мети сторінки.

Основні підходи:

    Symmetrical balance
        → приблизно симетричне розташування

    Asymmetrical balance
        → баланс між різними за розміром
          або формою елементами

    Visual balance
        → загальне відчуття рівноваги

Композиція не обов'язково повинна бути симетричною, щоб виглядати збалансованою.

Детальніше balance розглядатиметься в:

    02-layout-and-composition/
    └── 08-balance

---

# Proximity

Proximity — принцип близькості, за яким елементи, розташовані поруч, сприймаються як пов'язані.

Наприклад:

    Course title

    Course description

    Course duration

    [View course]

Якщо між назвою курсу та описом невеликий відступ, а перед наступним блоком більший, це допомагає показати їхній взаємозв'язок.

Proximity використовується для:

- групування полів форми;
- організації карток;
- зв'язування заголовків із текстом;
- структурування меню;
- відокремлення секцій;
- організації панелей налаштувань.

Важливо: близькість повинна відображати логічні зв'язки, а не бути випадковою.

Детальніше proximity розглядатиметься в:

    02-layout-and-composition/
    └── 09-proximity

# Layout Patterns

Layout pattern — повторювана схема організації інтерфейсу.

Наприклад:

## Header pattern

    ┌─────────────────────────────────┐
    │ Logo    Navigation    User menu │
    └─────────────────────────────────┘

Використовується для головної навігації.

## Sidebar pattern

    ┌────────────┬────────────────────┐
    │ Navigation │ Main content       │
    │            │                    │
    │            │                    │
    └────────────┴────────────────────┘

Використовується в dashboard, документації та адміністративних інтерфейсах.

## Card grid pattern

    ┌──────────┬──────────┬──────────┐
    │ Card     │ Card     │ Card     │
    ├──────────┼──────────┼──────────┤
    │ Card     │ Card     │ Card     │
    └──────────┴──────────┴──────────┘

Використовується в каталогах, галереях і списках курсів.

## Split-screen pattern

    ┌────────────────┬────────────────┐
    │                │                │
    │ Visual content │ Form or text   │
    │                │                │
    └────────────────┴────────────────┘

Використовується на сторінках входу, реєстрації, презентації продукту.

## Dashboard pattern

    ┌─────────────────────────────────┐
    │ Header and controls             │
    ├─────────────┬───────────────────┤
    │ Sidebar     │ Main workspace    │
    │             │                   │
    │             │ Cards and data    │
    └─────────────┴───────────────────┘

Використовується для керування даними, користувачами та налаштуваннями.

Layout patterns не є незмінними шаблонами. Їх потрібно адаптувати до конкретного продукту та користувацьких задач.

---

# Fixed Layout

Fixed layout — компонування, у якому певні розміри задаються фіксованими значеннями.

Наприклад:

    .sidebar {
        width: 280px;
    }

У цьому випадку ширина sidebar становить 280 CSS pixels.

Fixed dimensions можуть бути корисними для:

- іконок;
- компактних панелей;
- кнопок;
- контрольованих елементів;
- деяких частин dashboard.

Але надмірне використання фіксованої ширини для великих областей може спричиняти проблеми на вузьких екранах.

Наприклад:

    .content {
        width: 1200px;
    }

Такий блок може виходити за межі вузького viewport.

Тому фіксовані розміри потрібно використовувати там, де вони справді необхідні.

---

# Fluid Layout

Fluid layout — компонування, розміри якого змінюються залежно від доступного простору.

Наприклад:

    .container {
        width: 100%;
    }

Або:

    .content {
        width: 80%;
    }

Fluid layout дозволяє елементам адаптуватися до ширини доступної області.

Переваги:

- гнучкість;
- адаптація до різних viewport;
- ефективне використання доступного простору.

Але повністю гнучка ширина не завжди оптимальна.

Наприклад, текстовий блок може стати надто широким на великому моніторі.

Тому fluid width часто поєднують із max-width.

---

# Responsive Layout

Responsive layout — компонування, яке адаптується до різних розмірів viewport.

Наприклад:

    Desktop:
        Sidebar | Content

    Tablet:
        Sidebar | Content

    Mobile:
        Content
        Sidebar navigation moved or collapsed

На різних екранах можуть змінюватися:

- кількість колонок;
- ширина контейнера;
- розміри відступів;
- порядок блоків;
- розташування навігації;
- розміри зображень;
- видимість додаткових елементів;
- спосіб взаємодії з компонентами.

Responsive design — це не лише зменшення елементів.

Іноді потрібно змінити саму структуру компонування.

Наприклад:

    Desktop:
        Image | Text

    Mobile:
        Image
        Text

Або:

    Desktop:
        4 cards per row

    Tablet:
        2 cards per row

    Mobile:
        1 card per row

Основне правило: layout повинен залишатися зрозумілим і придатним до використання на доступному просторі.

Детальніше responsive design розглядатиметься в:

    07-responsive-design

---

# Layout Constraints

Layout constraints — обмеження, які визначають допустимі розміри та положення елементів.

Наприклад:

- мінімальна ширина;
- максимальна ширина;
- мінімальна висота;
- максимальна висота;
- відступи;
- пропорції;
- доступна ширина батьківського контейнера;
- обмеження вмісту.

У CSS можна використовувати:

    width
    min-width
    max-width
    height
    min-height
    max-height
    min()
    max()
    clamp()
    aspect-ratio

Наприклад:

    .article {
        width: 100%;
        max-width: 720px;
        margin-inline: auto;
    }

Це дозволяє статті займати доступну ширину, але не ставати надто широкою.

Інший приклад:

    .hero-title {
        font-size: clamp(2rem, 4vw, 4rem);
    }

Тут розмір шрифту адаптується до ширини viewport, але має мінімальну та максимальну межі.

Layout constraints допомагають контролювати поведінку композиції.

---

# Layout та CSS

UI Design визначає, якою повинна бути структура інтерфейсу.

CSS дозволяє реалізувати цю структуру у вебсторінці.

Основні CSS-механізми компонування:

    Normal flow
    Flexbox
    CSS Grid
    Positioning
    Multi-column layout

## Normal Flow

Normal flow — стандартне розташування елементів у документі.

Наприклад:

    <h1>Page title</h1>
    <p>Description</p>
    <button>Continue</button>

Блокові елементи зазвичай розташовуються один під одним відповідно до структури документа.

Це природна основа для багатьох сторінок.

## Flexbox

Flexbox використовується для організації елементів в одному основному напрямку: рядку або колонці.

Наприклад:

    .actions {
        display: flex;
        align-items: center;
        gap: 16px;
    }

Використовується для:

- навігації;
- груп кнопок;
- вирівнювання елементів;
- компонування рядків і колонок;
- організації внутрішньої структури компонентів.

## CSS Grid

CSS Grid дозволяє організовувати компонування у двох вимірах: рядках і колонках.

Наприклад:

    .card-grid {
        display: grid;
        grid-template-columns: repeat(3, 1fr);
        gap: 24px;
    }

Використовується для:

- сіток карток;
- сторінок із кількома областями;
- dashboard;
- складних композицій;
- макетів із контрольованими колонками.

## Positioning

Positioning дозволяє контролювати положення елементів відносно визначеного контексту або viewport.

Наприклад:

    .badge {
        position: absolute;
        top: 12px;
        right: 12px;
    }

Використовується для:

- бейджів на картках;
- накладання елементів;
- декоративних деталей;
- плаваючих елементів;
- окремих UI-компонентів.

Positioning не повинен бути основним інструментом для створення всієї структури сторінки.

## Multi-column Layout

CSS Multi-column Layout дозволяє розподіляти текстовий вміст між колонками.

Наприклад:

    .article {
        columns: 2;
        column-gap: 32px;
    }

Може використовуватися для деяких редакційних макетів і текстових матеріалів.

Flexbox, Grid та інші механізми будуть детальніше розглядатися в курсі HTML/CSS.

---

# Design Tokens для Layout

Design tokens — це стандартизовані значення, які повторно використовуються в дизайн-системі.

Для layout часто створюють токени:

    Container widths
    Spacing
    Grid gaps
    Section spacing
    Breakpoints
    Sidebar widths

Наприклад:

    :root {
        --container-max-width: 1200px;
        --page-gutter: 24px;
        --section-spacing: 80px;
        --grid-gap: 24px;
    }

Використання:

    .container {
        width: 100%;
        max-width: var(--container-max-width);
        margin-inline: auto;
        padding-inline: var(--page-gutter);
    }

    .section {
        padding-block: var(--section-spacing);
    }

    .grid {
        display: grid;
        gap: var(--grid-gap);
    }

Переваги:

- послідовність;
- швидке глобальне налаштування;
- простіша підтримка;
- зручність масштабування;
- менша кількість довільних значень.

У реальному проєкті токени потрібно адаптувати до дизайн-системи, а не копіювати ці значення без аналізу.

# Layout Workflow

Створення layout краще починати не з декоративних деталей, а зі структури.

## Крок 1. Визначити мету сторінки

Потрібно зрозуміти, для чого існує сторінка.

Наприклад:

    Course catalog
        → допомогти знайти курс

    Login page
        → дозволити користувачеві увійти

    Dashboard
        → показати важливі дані
          та надати доступ до дій

Мета впливає на структуру й пріоритети.

## Крок 2. Визначити основний контент

Скласти перелік необхідних елементів.

Наприклад:

    Course catalog:
        Page title
        Search
        Filters
        Course cards
        Pagination

## Крок 3. Згрупувати пов'язані елементи

Наприклад:

    Search and filters
        → discovery controls

    Course image and description
        → course card

    Pagination controls
        → navigation through results

Групування допомагає визначити компоненти та секції.

## Крок 4. Визначити ієрархію

Потрібно вирішити, що користувач повинен помітити першим.

Наприклад:

    Page title
        ↓
    Search and filters
        ↓
    Course results
        ↓
    Pagination

## Крок 5. Вибрати структуру

Наприклад:

    Page
        Header
        Main
            Heading
            Search and filters
            Course grid
            Pagination
        Footer

## Крок 6. Визначити ширину та пропорції

Потрібно вирішити:

- чи потрібен контейнер;
- наскільки широким повинен бути контент;
- чи потрібні колонки;
- яка ширина карток;
- скільки простору залишити між групами.

## Крок 7. Визначити alignment і spacing

Узгодити:

- лінії вирівнювання;
- внутрішні відступи;
- відстані між компонентами;
- відстані між секціями.

## Крок 8. Перевірити responsive behavior

Перевірити, як layout працює:

- на широкому екрані;
- на середньому екрані;
- на вузькому екрані.

Потрібно враховувати не лише ширину, а й реальний вміст компонентів.

## Крок 9. Перевірити usability

Запитати себе:

- Чи зрозуміло, з чого почати?
- Чи легко знайти основну дію?
- Чи пов'язані елементи згруповані?
- Чи немає зайвого візуального шуму?
- Чи зберігається логічний порядок?

## Крок 10. Уточнити візуальні деталі

Лише після визначення основної структури варто остаточно налаштовувати:

- кольори;
- типографіку;
- тіні;
- декоративні елементи;
- стани компонентів.

Це не означає, що дизайн завжди створюється строго лінійно. На практиці дизайнер може повертатися до попередніх кроків.

# Wireframe

Wireframe — спрощене представлення структури сторінки без остаточного візуального оформлення.

Wireframe допомагає визначити:

- структуру;
- порядок блоків;
- розміри основних областей;
- взаємозв'язки елементів;
- розташування основних дій.

Наприклад:

    ┌─────────────────────────────┐
    │ Logo           Navigation   │
    ├─────────────────────────────┤
    │                             │
    │ Heading                     │
    │ Description                 │
    │ [Primary action]            │
    │                             │
    ├─────────────────────────────┤
    │ Feature 1 | Feature 2       │
    ├─────────────────────────────┤
    │ Feature 3 | Feature 4       │
    ├─────────────────────────────┤
    │ Footer                      │
    └─────────────────────────────┘

Wireframe зазвичай не потребує точних кольорів, тіней та декоративних деталей.

На цьому етапі важливіше відповісти на запитання:

    What belongs here?
        ↓
    What is most important?
        ↓
    How is content grouped?
        ↓
    How does the user move through the page?

Wireframe може бути намальований від руки або створений у Figma чи іншому інструменті.

# Low-fidelity vs High-fidelity Layout

## Low-fidelity

Low-fidelity layout — спрощений макет із мінімумом деталей.

Він допомагає перевірити структуру без значних витрат часу на оформлення.

Зазвичай містить:

- блоки контенту;
- умовні заголовки;
- базове компонування;
- приблизні пропорції;
- основні інтерактивні елементи.

## High-fidelity

High-fidelity layout — детальніший макет, який наближений до фінального інтерфейсу.

Може включати:

- точну типографіку;
- кольори;
- реальні зображення;
- детальні компоненти;
- продумані стани;
- уточнені відступи;
- реалістичний контент.

Типова послідовність:

    Requirements
        ↓
    Content structure
        ↓
    Low-fidelity wireframe
        ↓
    Layout refinement
        ↓
    High-fidelity design
        ↓
    Implementation
        ↓
    Testing and iteration

Це корисний робочий процес, але не обов'язкова лінійна схема для кожного проєкту.

# Layout та Information Architecture

Information architecture (IA) — організація інформації, навігації та взаємозв'язків між розділами продукту.

Layout визначає, як інформація розташована у візуальному просторі.

Наприклад:

    Information architecture:
        Courses
            Categories
            Course details
            Lessons

    Layout:
        Header
        Category navigation
        Course list
        Course details panel

IA відповідає на запитання:

    What information exists?
    How is it organized?
    How are sections connected?

Layout відповідає на запитання:

    Where is the information displayed?
    How is it grouped visually?
    How does it fit into the page?

Ці дисципліни пов'язані, але не замінюють одна одну.

Детальніше information architecture розглядатиметься в:

    10-navigation-and-information-architecture

# Layout та UX

Layout впливає на зручність користування продуктом.

Наприклад, користувач може мати труднощі, якщо:

- основна дія не помітна;
- пов'язані елементи розташовані далеко один від одного;
- сторінка перевантажена інформацією;
- навігація змінює положення без зрозумілої причини;
- форма має незрозумілу послідовність;
- контент не адаптується до екрана;
- елементи перекривають один одного.

Під час оцінювання layout варто запитувати:

    Can the user understand the page?
        ↓
    Can the user find the next step?
        ↓
    Can the user complete the task?
        ↓
    Does the layout remain usable
    across different screen sizes?

Красивий layout не обов'язково є зручним.

Хороший layout повинен підтримувати реальні задачі користувача.

# Типові помилки в Layout Design

## 1. Починати з декору замість структури

❌ Спочатку створювати тіні, градієнти та декоративні елементи, не визначивши структуру сторінки.

Правильніше:

    Content
        ↓
    Structure
        ↓
    Hierarchy
        ↓
    Layout
        ↓
    Visual styling

---

## 2. Відсутність візуальної ієрархії

❌ Усі елементи виглядають однаково важливими.

Якщо заголовок, опис, другорядні посилання та основна кнопка мають однакову візуальну вагу, користувачеві складніше визначити пріоритети.

Потрібно створювати зрозумілу систему акцентів.

---

## 3. Надмірна ширина контенту

❌ Текст займає всю ширину великого екрана.

Довгі рядки можуть ускладнювати читання.

Для текстових блоків часто використовують обмеження ширини.

Наприклад:

    .article {
        max-width: 720px;
        margin-inline: auto;
    }

Це лише можливе значення. Оптимальна ширина залежить від шрифту, розміру тексту та типу контенту.

---

## 4. Випадкові відступи

❌ Кожен компонент має довільний spacing.

Це створює непослідовність.

Краще використовувати обмежений набір узгоджених значень.

Наприклад:

    8px
    16px
    24px
    32px
    48px

Це приклад шкали spacing, а не обов'язковий стандарт.

---

## 5. Надмірне центрування

❌ Увесь текст і всі компоненти центруються без урахування контексту.

Центрування може бути доречним для коротких заголовків або компактних композицій.

Але довгі тексти, форми та складні списки часто краще організовувати з чітким вирівнюванням.

---

## 6. Відсутність логічного групування

❌ Поля, підказки, кнопки та повідомлення розташовані без зрозумілих зв'язків.

Потрібно використовувати proximity, spacing і спільні контейнери, щоб показувати взаємозв'язки.

---

## 7. Надмірна кількість колонок

❌ На вузькому екрані картки стають занадто вузькими.

Кількість колонок потрібно визначати з урахуванням:

- ширини картки;
- обсягу тексту;
- розміру зображення;
- інтерактивних елементів;
- доступного простору.

---

## 8. Ігнорування мобільних пристроїв

❌ Desktop layout просто зменшується до вузького екрана.

Потрібно перевіряти, чи залишається структура зрозумілою.

Іноді потрібно змінити:

- кількість колонок;
- положення sidebar;
- порядок елементів;
- розташування кнопок;
- спосіб показу фільтрів;
- розмір і структуру навігації.

---

## 9. Використання фіксованої ширини без обмежень

❌ Контейнер має фіксовану ширину, яка перевищує доступний viewport.

Наприклад:

    .container {
        width: 1200px;
    }

На вузькому екрані це може спричинити горизонтальне прокручування.

Для більш гнучкої структури:

    .container {
        width: 100%;
        max-width: 1200px;
        margin-inline: auto;
        padding-inline: 24px;
    }

Для production-коду також потрібно перевірити, як padding впливає на фактичні розміри елемента.

---

## 10. Надмірна складність

❌ Сторінка має занадто багато секцій, колонок, карток і візуальних акцентів.

Потрібно перевірити, чи всі елементи справді потрібні для задачі користувача.

Простота не означає відсутність функціональності. Вона означає зрозумілу організацію.

---

## 11. Ігнорування реального контенту

❌ Layout працює тільки з короткими демонстраційними текстами.

У реальному застосунку назви можуть бути довшими, зображення — різних пропорцій, а повідомлення — займати кілька рядків.

Тому потрібно перевіряти layout із реалістичними даними.

---

## 12. Плутати візуальний порядок із логічним

❌ Елементи розташовані так, що користувачеві складно зрозуміти послідовність взаємодії.

Потрібно перевіряти не тільки зовнішній вигляд, а й порядок читання, клавіатурної навігації та взаємодії.

# Layout Checklist

Перед завершенням макета перевірити:

## Structure

- [ ] Чи зрозуміла загальна структура сторінки?
- [ ] Чи логічно розташовані секції?
- [ ] Чи відповідає структура задачам користувача?
- [ ] Чи немає зайвих блоків?

## Visual hierarchy

- [ ] Чи зрозуміло, що найважливіше?
- [ ] Чи помітний основний заголовок?
- [ ] Чи зрозуміло, де виконати основну дію?
- [ ] Чи не конкурують другорядні елементи з основними?

## Alignment

- [ ] Чи мають пов'язані елементи спільні лінії вирівнювання?
- [ ] Чи послідовно вирівняні заголовки, текст і компоненти?
- [ ] Чи немає випадкових зміщень?

## Spacing

- [ ] Чи достатньо простору між елементами?
- [ ] Чи відокремлені різні групи?
- [ ] Чи використовуються узгоджені відступи?
- [ ] Чи немає надмірного скупчення елементів?

## Containers and grids

- [ ] Чи правильно обмежена ширина контенту?
- [ ] Чи узгоджені колонки?
- [ ] Чи мають картки достатню ширину?
- [ ] Чи відповідають пропорції призначенню контенту?

## Responsive behavior

- [ ] Чи працює layout на широкому екрані?
- [ ] Чи працює layout на середньому екрані?
- [ ] Чи працює layout на мобільному пристрої?
- [ ] Чи немає випадкового горизонтального прокручування?
- [ ] Чи не перекривають елементи один одного?
- [ ] Чи залишається текст читабельним?

## Usability and accessibility

- [ ] Чи зрозумілий порядок читання?
- [ ] Чи можна дістатися інтерактивних елементів клавіатурою?
- [ ] Чи збережений логічний порядок фокусу?
- [ ] Чи достатньо місця для взаємодії з елементами?
- [ ] Чи не передається важлива інформація лише через положення або колір?

# Головне

• Layout визначає, як елементи інтерфейсу розташовані та організовані в просторі.

• Composition створює цілісну візуальну організацію елементів.

• Хороший layout допомагає користувачеві зрозуміти структуру сторінки та знайти потрібну інформацію.

• Visual hierarchy визначає відносну важливість елементів.

• Container допомагає організовувати ширину та положення контенту.

• Section розділяє сторінку на логічні частини.

• Grid і columns допомагають створювати послідовні композиції.

• Alignment створює порядок.

• Spacing допомагає розділяти та групувати елементи.

• Whitespace покращує сприйняття структури.

• Proximity допомагає показувати зв'язки між елементами.

• Balance допомагає підтримувати візуальну рівновагу.

• Reading order повинен відповідати логіці інформації та взаємодії.

• Responsive layout адаптується до різних розмірів viewport.

• Fixed і fluid dimensions можна комбінувати для контрольованої гнучкості.

• Wireframe допомагає перевірити структуру до детального оформлення.

• Layout потрібно будувати з урахуванням реального контенту, а не лише демонстраційних прикладів.

• Хороший layout повинен бути не тільки візуально привабливим, а й зрозумілим, функціональним та доступним.

• У веброзробці CSS Flexbox, Grid і normal flow допомагають реалізувати дизайнерські принципи компонування.

• Основна мета layout — організувати інформацію так, щоб користувач міг легко її сприймати та виконувати свої завдання.

• Правильна послідовність роботи:

    Content
        ↓
    Structure
        ↓
    Hierarchy
        ↓
    Layout
        ↓
    Responsive behavior
        ↓
    Visual refinement

• Layout — це основа інтерфейсу, на якій будуються типографіка, кольори, компоненти та інші візуальні рішення.
