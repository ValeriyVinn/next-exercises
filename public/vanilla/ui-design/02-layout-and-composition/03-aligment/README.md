# Alignment — Вирівнювання елементів в UI

> **Alignment (вирівнювання)** — це принцип UI-дизайну, який визначає, як елементи інтерфейсу розташовуються відносно спільних ліній, країв, центрів або інших елементів.
>
> Правильне вирівнювання допомагає створити візуальний порядок, зробити інтерфейс зрозумілим і полегшити користувачеві сприйняття інформації.

---

## 1. Для чого потрібне вирівнювання?

Alignment допомагає:

- створювати чітку візуальну структуру сторінки;
- пов'язувати елементи між собою;
- формувати зрозумілу ієрархію інформації;
- полегшувати сканування тексту;
- робити інтерфейс охайним і послідовним;
- створювати візуальний баланс;
- забезпечувати однакове розташування компонентів у різних частинах інтерфейсу;
- покращувати usability — зручність користування інтерфейсом.

Наприклад, якщо заголовки, текст і кнопки в декількох картках вирівняні за однією вертикальною лінією, користувачеві легше порівнювати картки та знаходити потрібну інформацію.

    Без узгодженого вирівнювання:
    ┌─────────────────────────────┐
       Заголовок
          Опис картки
       [Кнопка]
    └─────────────────────────────┘

    З узгодженим вирівнюванням:
    ┌─────────────────────────────┐
    Заголовок
    Опис картки
    [Кнопка]
    └─────────────────────────────┘

Це спрощений приклад: конкретне вирівнювання залежить від призначення компонента та обраного дизайну.

---

## 2. Основні поняття

### 2.1. Alignment

**Alignment** — загальний термін для вирівнювання елементів відносно певної осі, лінії або іншого елемента.

В інтерфейсах можна вирівнювати:

- текст;
- зображення;
- іконки;
- кнопки;
- поля форм;
- картки;
- навігацію;
- цілі секції сторінки;
- елементи всередині контейнера.

### 2.2. Alignment line

**Alignment line (лінія вирівнювання)** — умовна лінія, уздовж якої розташовуються краї, центри або інші точки елементів.

Наприклад, ліва межа заголовка, абзацу та кнопки може збігатися з однією вертикальною лінією.

### 2.3. Axis

**Axis (вісь)** — напрямок, відносно якого відбувається вирівнювання.

Основні осі:

- Horizontal axis — горизонтальна вісь.
- Vertical axis — вертикальна вісь.

У CSS Flexbox і Grid напрямки вирівнювання також залежать від основної та поперечної осей або від властивостей для конкретних напрямків.

### 2.4. Consistency

**Consistency (послідовність)** — використання однакових правил вирівнювання в схожих ситуаціях.

Наприклад:

- усі заголовки секцій мають однакове вирівнювання;
- усі поля форми починаються з однієї вертикальної лінії;
- кнопки в однакових картках розташовані за спільним правилом;
- основний контент сторінки має узгоджені ліву та праву межі.

### 2.5. Visual hierarchy

**Visual hierarchy (візуальна ієрархія)** — порядок, у якому користувач сприймає елементи за важливістю.

Вирівнювання підтримує цю ієрархію: воно допомагає побачити, які елементи належать до одного блоку, де починається нова секція та які елементи потрібно читати разом.

## 3. Основні типи вирівнювання

### 3.1. Left alignment — вирівнювання ліворуч

Елементи вирівнюються за лівим краєм.

    ┌──────────────────────────┐
    Заголовок
    Основний текст абзацу.
    Ще один рядок тексту.
    [Докладніше]
    └──────────────────────────┘

Використовується для:

- основного тексту;
- заголовків;
- форм;
- списків;
- карток із текстовим контентом;
- більшості інтерфейсів із написанням зліва направо (LTR).

**Переваги:**

- природне читання для мов із напрямком LTR;
- чітка спільна вертикальна лінія;
- зручне сканування тексту;
- легко підтримувати послідовність між різними блоками.

**Коли використовувати:**

Якщо потрібно створити зрозумілу структуру для тексту, форм або списків, вирівнювання ліворуч зазвичай є хорошим початковим вибором.

### 3.2. Right alignment — вирівнювання праворуч

Елементи вирівнюються за правим краєм.

    ┌──────────────────────────┐
                      Заголовок
                   Короткий опис
                         1 250 ₴
    └──────────────────────────┘

Використовується для:

- сум і числових значень у таблицях;
- цін у певних композиціях;
- метаданих;
- другорядних інформаційних блоків;
- елементів інтерфейсів, де це підтримує загальну композицію.

**Переваги:**

- створює чітку праву межу;
- може полегшити порівняння чисел;
- допомагає розташувати другорядну інформацію компактно.

**Коли використовувати:**

Праве вирівнювання доречне, коли воно допомагає порівнювати значення або відповідає структурі компонента.

Для довгих текстових абзаців у LTR-інтерфейсах зазвичай зручніше вирівнювання ліворуч.

### 3.3. Center alignment — вирівнювання по центру

Елементи вирівнюються відносно центральної осі.

    ┌──────────────────────────┐
              Заголовок
          Короткий опис секції
              [Почати]
    └──────────────────────────┘

Використовується для:

- hero-секцій;
- коротких повідомлень;
- порожніх станів (empty states);
- діалогів;
- сторінок привітання;
- компактних блоків із невеликою кількістю тексту.

**Переваги:**

- створює відчуття симетрії;
- допомагає виділити головний елемент;
- підходить для коротких повідомлень;
- може зробити композицію урочистою або спокійною.

**Недоліки:**

- довгі абзаци важче читати;
- початок кожного рядка розташовується в іншому місці;
- центровані блоки можуть втратити чітку структуру, якщо в них багато різнорідного контенту.

**Важливо:** центроване вирівнювання не означає, що сам блок обов'язково розташований по центру сторінки. Вирівнювання тексту та позиціювання контейнера — різні речі.

### 3.4. Justified alignment — вирівнювання по ширині

Текст розтягується так, щоб його рядки доходили до обох країв текстового блоку, крім останнього рядка в типовому випадку.

    ┌──────────────────────────┐
    Текст заповнює рядки між
    лівою та правою межами
    текстового контейнера.
    └──────────────────────────┘

У CSS:

    .article-text {
        text-align: justify;
    }

Може використовуватися для:

- деяких довгих текстів;
- спеціалізованих редакційних макетів;
- окремих типів документів.

**Недоліки у вебінтерфейсах:**

- між словами можуть виникати великі проміжки;
- вузькі колонки можуть виглядати нерівномірно;
- читання на мобільних пристроях може ускладнюватися.

Для більшості звичайних вебінтерфейсів вирівнювання ліворуч є практичнішим.

---

## 4. Вирівнювання за горизонталлю та вертикаллю

Вирівнювання може стосуватися як положення елемента в рядку, так і положення всередині контейнера.

### 4.1. Горизонтальне вирівнювання

Визначає положення елементів уздовж горизонтальної осі.

Приклади:

- кнопка розташована по центру контейнера;
- заголовок вирівняний за лівим краєм;
- елементи навігації розташовані з однаковим проміжком;
- іконка та текст утворюють горизонтальний рядок.

### 4.2. Вертикальне вирівнювання

Визначає положення елементів уздовж вертикальної осі.

Приклади:

- іконка та текст розташовані на одному рівні;
- кнопка вирівняна по центру відносно сусіднього поля;
- вміст картки розташований по центру її висоти;
- елементи одного рядка таблиці мають узгоджене вертикальне положення.

### 4.3. Вирівнювання та відступи — не одне й те саме

**Alignment** визначає взаємне положення елементів.

**Spacing** визначає відстань між ними.

Наприклад, два елементи можуть бути вирівняні по центру, але розташовані надто близько або надто далеко один від одного.

    Alignment: елементи мають спільну центральну вісь.

    Spacing: визначає відстань між елементами.

Обидва принципи потрібні для якісної композиції.

---

## 5. Вирівнювання контейнера та вирівнювання вмісту

Це одне з найважливіших розрізнень у UI-дизайні.

### 5.1. Позиція контейнера

Визначає, де розташований сам блок на сторінці.

Наприклад, картка може бути розміщена по центру сторінки.

    ┌──────────────────────────────────┐
    │                                  │
    │       ┌────────────────┐         │
    │       │     Картка     │         │
    │       └────────────────┘         │
    │                                  │
    └──────────────────────────────────┘

### 5.2. Вирівнювання вмісту

Визначає, як елементи розташовані всередині контейнера.

    ┌────────────────────────┐
    │       Заголовок        │
    │    Короткий опис       │
    │        [Кнопка]        │
    └────────────────────────┘

### 5.3. Приклад: контейнер по центру, текст ліворуч

Це поширений і практичний патерн.

    ┌──────────────────────────────────┐
    │                                  │
    │       ┌────────────────┐         │
    │       │ Заголовок      │         │
    │       │ Основний текст │         │
    │       │ [Докладніше]   │         │
    │       └────────────────┘         │
    │                                  │
    └──────────────────────────────────┘

У CSS:

    .content-container {
        width: min(100% - 2rem, 70rem);
        margin-inline: auto;
    }

    .content-container__title,
    .content-container__text {
        text-align: left;
    }

У цьому прикладі:

- `margin-inline: auto` центрує контейнер у доступному просторі;
- `text-align: left` вирівнює текст усередині нього ліворуч;
- `width: min(...)` обмежує ширину контейнера та залишає горизонтальні відступи.

Не потрібно центрувати весь текст лише тому, що контейнер розташований по центру сторінки.

## 6. Alignment у принципах композиції

### 6.1. Вирівнювання за спільним краєм

Елементи мають однакову ліву, праву, верхню або нижню межу.

Приклад:

    Заголовок сторінки
    Опис сторінки
    Фільтри
    Список результатів

Якщо всі ці елементи починаються з однієї вертикальної лінії, сторінка сприймається як єдина структура.

### 6.2. Вирівнювання за центром

Елементи орієнтуються на спільну центральну вісь.

Доречно для:

- аватара та імені у вертикальній картці;
- короткого повідомлення;
- іконки над заголовком;
- центрального елемента hero-секції.

### 6.3. Вирівнювання за базовою лінією тексту

**Baseline alignment** — вирівнювання елементів за базовою лінією тексту.

Базова лінія — умовна лінія, на якій розташовується основна частина символів.

Наприклад, якщо поруч стоять текст і невелика іконка, потрібно зробити так, щоб вони виглядали візуально узгоджено.

    Профіль  ✓

У CSS для простого текстового рядка:

    .label-with-icon {
        display: inline-flex;
        align-items: baseline;
        gap: 0.375rem;
    }

Але `baseline` не завжди найкращий варіант для іконок: часто візуально краще працює `align-items: center`.

Вибір залежить від розміру іконки, шрифту та конкретної композиції.

### 6.4. Вирівнювання за оптичною вагою

**Optical alignment** — візуальне вирівнювання, яке враховує сприйняття форми, а не лише математичне положення.

Наприклад, кругла іконка та квадратний елемент можуть мати однакові геометричні межі, але виглядати по-різному розташованими.

У таких випадках дизайнер може застосувати невелику оптичну корекцію.

Важливо:

- спочатку використовувати правильні структурні правила;
- потім оцінювати результат візуально;
- не виправляти хаотичне компонування випадковими відступами;
- застосовувати оптичні корекції лише там, де вони справді покращують вигляд.

## 7. Alignment у різних UI-компонентах

### 7.1. Картки (Cards)

Картки одного типу мають дотримуватися спільних правил вирівнювання.

Наприклад:

    ┌─────────────────────┐
    │ [Зображення]        │
    │ Назва товару        │
    │ Короткий опис       │
    │ 1 250 ₴             │
    │ [Купити]            │
    └─────────────────────┘

Для серії карток важливо узгодити:

- положення заголовків;
- початок тексту;
- розташування ціни;
- положення кнопок;
- відступи від країв;
- вертикальне розташування контенту.

Якщо картки мають різну кількість тексту, кнопки можуть опинитися на різних рівнях. Це не завжди помилка, але в порівнюваних картках часто корисно розташувати кнопки за спільним правилом.

Приклад CSS:

    .product-card {
        display: flex;
        flex-direction: column;
        align-items: stretch;
        gap: 1rem;
    }

    .product-card__button {
        margin-top: auto;
    }

`margin-top: auto` може притиснути кнопку донизу картки, якщо сама картка має доступну висоту у відповідному flex-контексті.

### 7.2. Форми (Forms)

Форми особливо потребують послідовного вирівнювання.

    Ім'я
    [_____________________]

    Електронна пошта
    [_____________________]

    Пароль
    [_____________________]

    [Створити обліковий запис]

Рекомендації:

- усі поля повинні мати узгоджену ширину;
- підписи мають розташовуватися за одним правилом;
- повідомлення про помилки повинні бути пов'язані з відповідними полями;
- кнопки мають мати логічне положення;
- допоміжний текст не повинен випадково зміщувати інші поля.

Для більшості звичайних форм вертикальне компонування з вирівнюванням ліворуч добре працює на десктопі й мобільних пристроях.

### 7.3. Навігація (Navigation)

У навігації важливо узгодити:

- вертикальне вирівнювання тексту й логотипу;
- положення іконок;
- відступи між пунктами;
- вирівнювання пунктів меню;
- положення активного стану.

Приклад:

    [Логотип]   Головна   Курси   Про нас   [Увійти]

У CSS:

    .navigation {
        display: flex;
        align-items: center;
        gap: 1.5rem;
    }

Тут `align-items: center` вирівнює елементи по поперечній осі flex-контейнера.

### 7.4. Кнопки

У кнопках вирівнювання впливає на читабельність і візуальну стабільність.

Для кнопки з іконкою:

    .button {
        display: inline-flex;
        align-items: center;
        justify-content: center;
        gap: 0.5rem;
    }

- `align-items` вирівнює вміст по поперечній осі;
- `justify-content` вирівнює вміст по головній осі;
- `gap` задає відстань між іконкою та текстом.

### 7.5. Таблиці

У таблицях різні типи даних можуть потребувати різного вирівнювання.

| Тип даних | Типове вирівнювання |
|---|---|
| Назва | Ліворуч у LTR-інтерфейсі |
| Опис | Ліворуч |
| Кількість | Часто праворуч або по центру |
| Грошові значення | Часто праворуч |
| Статус | За структурою таблиці |
| Дії | Часто по центру або праворуч |

Це не абсолютні правила. Вирівнювання має підтримувати швидке читання та порівняння даних.

### 7.6. Модальні вікна (Modals)

У модальному вікні можуть поєднуватися різні правила:

- саме вікно розташоване по центру екрана;
- заголовок вирівняний ліворуч;
- текст пояснення вирівняний ліворуч;
- основна кнопка розташована праворуч або в окремому рядку;
- кнопка закриття розташована у верхній частині.

Не потрібно автоматично центрувати весь вміст модального вікна. Орієнтуйтеся на призначення та обсяг інформації.

---

## 8. Alignment у CSS: основні властивості

UI-дизайнеру корисно розуміти, як принципи вирівнювання реалізуються в CSS.

### 8.1. `text-align`

Вирівнює вміст текстового рядка по горизонталі в межах відповідного блоку.

    .title {
        text-align: left;
    }

    .hero-title {
        text-align: center;
    }

    .price {
        text-align: right;
    }

Поширені значення:

- `left`;
- `right`;
- `center`;
- `justify`;
- `start`;
- `end`.

Для інтерфейсів, які можуть підтримувати різні напрямки письма, `start` і `end` часто гнучкіші за `left` і `right`.

    .content {
        text-align: start;
    }

`text-align` не центрує сам блок — воно вирівнює його текстовий вміст.

### 8.2. `margin-inline: auto`

Використовується для центрування блоку в доступному горизонтальному просторі, якщо його ширина обмежена.

    .container {
        width: min(100% - 2rem, 72rem);
        margin-inline: auto;
    }

Це поширений патерн для основного контейнера сторінки.

### 8.3. Flexbox: `justify-content`

Вирівнює та розподіляє flex-елементи вздовж головної осі.

    .actions {
        display: flex;
        justify-content: center;
        gap: 1rem;
    }

Поширені значення:

- `flex-start`;
- `flex-end`;
- `center`;
- `space-between`;
- `space-around`;
- `space-evenly`.

**Важливо:** головна вісь залежить від `flex-direction`.

Для `flex-direction: row` головна вісь зазвичай горизонтальна.

Для `flex-direction: column` головна вісь вертикальна.

### 8.4. Flexbox: `align-items`

Вирівнює елементи вздовж поперечної осі.

    .navigation {
        display: flex;
        align-items: center;
        gap: 1rem;
    }

Поширені значення:

- `stretch`;
- `flex-start`;
- `flex-end`;
- `center`;
- `baseline`.

Наприклад, у горизонтальній навігації `align-items: center` часто допомагає вирівняти логотип, посилання та кнопку по вертикалі.

### 8.5. Flexbox: `align-self`

Дозволяє окремому елементу мати власне вирівнювання по поперечній осі, відмінне від `align-items` контейнера.

    .profile {
        display: flex;
        align-items: flex-start;
    }

    .profile__badge {
        align-self: center;
    }

Це корисно, коли одному елементу потрібне особливе вирівнювання.

### 8.6. Grid: `justify-items` та `align-items`

CSS Grid дозволяє керувати вирівнюванням елементів у межах їхніх комірок.

    .card-grid {
        display: grid;
        grid-template-columns: repeat(3, 1fr);
        gap: 1rem;
        align-items: start;
    }

- `justify-items` — вирівнювання елементів по горизонтальному напрямку комірок у звичайному горизонтальному письмі;
- `align-items` — вирівнювання елементів по вертикальному напрямку комірок у звичайному горизонтальному письмі.

Для конкретної осі поведінка залежить від напрямку письма та системи компонування.

### 8.7. Grid: `justify-content` та `align-content`

Ці властивості керують розташуванням сітки або її доріжок у вільному просторі контейнера, а не просто вирівнюють вміст усередині окремої комірки.

    .layout {
        display: grid;
        grid-template-columns: repeat(3, 12rem);
        justify-content: center;
        gap: 1rem;
    }

Якщо сітка займає всю доступну ширину, вільного горизонтального простору може не бути, тому `justify-content: center` не дасть помітного результату.

### 8.8. `place-items` та `place-content`

Це скорочені властивості для двох напрямків вирівнювання.

    .centered-box {
        display: grid;
        place-items: center;
    }

У Grid `place-items: center` зручно використовувати, коли потрібно вирівняти елемент по обох осях усередині його комірки.

    .centered-layout {
        display: grid;
        place-content: center;
    }

`place-content` керує вирівнюванням вмісту Grid-контейнера за двома осями. Воно не є універсальною заміною `place-items`.

### 8.9. `vertical-align`

Використовується для вертикального вирівнювання inline-елементів, inline-block-елементів і вмісту комірок таблиць.

    .icon {
        vertical-align: middle;
    }

Важливо:

- `vertical-align` не центрує довільний блок у батьківському контейнері;
- для сучасних flex- і grid-компонентів зазвичай зручніше застосовувати `align-items`;
- поведінка `vertical-align` залежить від типу елемента та контексту форматування.

## 9. Головна та поперечна осі у Flexbox

Щоб правильно використовувати CSS-вирівнювання, потрібно розуміти дві осі Flexbox.

### 9.1. `flex-direction: row`

    .row {
        display: flex;
        flex-direction: row;
        justify-content: center;
        align-items: center;
    }

У стандартному LTR-контексті:

- головна вісь проходить горизонтально;
- `justify-content` працює вздовж головної осі;
- `align-items` працює вздовж поперечної осі.

### 9.2. `flex-direction: column`

    .column {
        display: flex;
        flex-direction: column;
        justify-content: center;
        align-items: center;
    }

Тут:

- головна вісь проходить вертикально;
- `justify-content` вирівнює елементи вздовж вертикальної осі;
- `align-items` вирівнює елементи вздовж горизонтальної осі в типовому горизонтальному письмі.

Отже, `justify-content` не завжди означає горизонтальне вирівнювання.

**Запам'ятай:** у Flexbox `justify-content` відповідає за головну вісь, а `align-items` — за поперечну.

## 10. Alignment у responsive design

Вирівнювання має працювати на різних ширинах екрана.

### 10.1. Desktop

На великих екранах можна використовувати:

- горизонтальні навігаційні панелі;
- кілька колонок карток;
- двоколонкові секції;
- вирівнювання заголовка й опису за спільною лінією.

### 10.2. Tablet

На середніх ширинах може знадобитися:

- зменшення кількості колонок;
- перебудова горизонтальних блоків;
- зміна проміжків;
- узгодження висоти й положення кнопок;
- зміна вирівнювання деяких секцій.

### 10.3. Mobile

На мобільних пристроях зазвичай важливі:

- зрозуміла вертикальна структура;
- читабельний текст;
- узгоджені горизонтальні відступи;
- кнопки, які не виглядають випадково зміщеними;
- відсутність горизонтального переповнення;
- достатній простір для натискання інтерактивних елементів.

Центрована hero-секція на десктопі може залишатися центрованою на мобільному пристрої. Не потрібно змінювати вирівнювання лише заради зміни.

Змінюйте його тоді, коли це покращує композицію або зручність користування.

### 10.4. Приклад responsive alignment

    .hero {
        width: min(100% - 2rem, 72rem);
        margin-inline: auto;
        text-align: left;
    }

    .hero__actions {
        display: flex;
        justify-content: flex-start;
        gap: 1rem;
    }

    @media (max-width: 40rem) {
        .hero {
            text-align: center;
        }

        .hero__actions {
            flex-direction: column;
            align-items: stretch;
        }
    }

На широких екранах контент вирівняний ліворуч. На вузьких — текст центрований, а кнопки розташовані вертикально та розтягуються на доступну ширину.

Це лише один можливий дизайн. Вирівнювання потрібно вибирати відповідно до задачі сторінки.

## 11. Alignment і дизайн-система

У дизайн-системі варто визначити повторювані правила вирівнювання.

Наприклад:

- стандартне вирівнювання тексту;
- правила для заголовків;
- правила для форм;
- положення кнопок у картках;
- вирівнювання іконок;
- вирівнювання навігації;
- правила для таблиць;
- поведінка компонентів на мобільних пристроях.

Не кожне правило потрібно перетворювати на окремий токен. Важливіше забезпечити передбачуваність і повторне використання компонентів.

Приклад CSS:

    :root {
        --content-max-width: 72rem;
        --page-gutter: 1.5rem;
        --inline-gap: 1rem;
    }

    .container {
        width: min(
            calc(100% - 2 * var(--page-gutter)),
            var(--content-max-width)
        );
        margin-inline: auto;
    }

    .stack {
        display: flex;
        flex-direction: column;
        align-items: flex-start;
        gap: var(--inline-gap);
    }

Тут:

- `--content-max-width` визначає максимальну ширину контенту;
- `--page-gutter` задає відступи від країв;
- `--inline-gap` задає проміжок між елементами;
- `.container` центрує основну область;
- `.stack` формує вертикальну групу з узгодженим вирівнюванням.

Відокремлення цих правил допомагає підтримувати однакову композицію в різних компонентах.

## 12. Практичний приклад: секція з вирівнюванням

Створимо секцію з заголовком, описом і двома кнопками.

### HTML

    <section class="hero">
        <div class="hero__content">
            <p class="hero__eyebrow">Навчальна платформа</p>

            <h1 class="hero__title">
                Навчайся у власному темпі
            </h1>

            <p class="hero__description">
                Обирай курси, практикуйся та відстежуй свій прогрес.
            </p>

            <div class="hero__actions">
                <a class="button button--primary" href="#courses">
                    Переглянути курси
                </a>

                <a class="button button--secondary" href="#about">
                    Дізнатися більше
                </a>
            </div>
        </div>
    </section>

### CSS

    .hero {
        width: min(calc(100% - 2rem), 72rem);
        margin-inline: auto;
        padding-block: 5rem;
    }

    .hero__content {
        max-width: 42rem;
        text-align: left;
    }

    .hero__eyebrow {
        margin: 0 0 0.75rem;
    }

    .hero__title {
        margin: 0 0 1rem;
    }

    .hero__description {
        margin: 0 0 1.5rem;
        max-width: 38rem;
    }

    .hero__actions {
        display: flex;
        align-items: center;
        justify-content: flex-start;
        flex-wrap: wrap;
        gap: 0.75rem;
    }

    .button {
        display: inline-flex;
        align-items: center;
        justify-content: center;
        min-height: 2.75rem;
        padding: 0.75rem 1rem;
        text-decoration: none;
    }

    @media (max-width: 40rem) {
        .hero {
            padding-block: 3rem;
        }

        .hero__content {
            max-width: none;
        }

        .hero__actions {
            align-items: stretch;
            flex-direction: column;
        }
    }

### Що тут важливо?

1. Контейнер `.hero` центрується відносно сторінки.
2. `.hero__content` має обмежену ширину, щоб текст не розтягувався на весь екран.
3. Текст вирівнюється ліворуч.
4. Кнопки розташовані в одному рядку, якщо вистачає місця.
5. `flex-wrap: wrap` дозволяє кнопкам переноситися за потреби.
6. На мобільному екрані кнопки розташовуються вертикально.
7. Вирівнювання та відступи задаються окремо, тому їх можна змінювати незалежно.

## 13. Типові помилки у вирівнюванні

### Помилка 1. Центрувати весь текст за замовчуванням

Центрування може бути доречним для коротких повідомлень, але не завжди добре працює для довгих текстів.

**Краще:** вибирати вирівнювання відповідно до типу контенту та його призначення.

### Помилка 2. Плутати центрування контейнера з центруванням тексту

    .container {
        margin-inline: auto;
    }

Це центрує контейнер, якщо виконуються необхідні умови для його ширини та розташування.

Це не означає, що текст усередині також має бути центрованим.

**Краще:** задавати положення контейнера та вирівнювання його вмісту незалежно.

### Помилка 3. Використовувати випадкові відступи замість системного вирівнювання

    .title {
        margin-left: 13px;
    }

    .description {
        margin-left: 19px;
    }

    .button {
        margin-left: 11px;
    }

Такі значення можуть створювати непослідовну структуру.

**Краще:** використовувати спільні контейнери, правила компонування та узгоджені відступи.

### Помилка 4. Не враховувати Flexbox-осі

Розробник очікує, що `justify-content: center` завжди центрує елементи горизонтально.

Але при `flex-direction: column` головна вісь вертикальна.

**Краще:** перед вибором властивості визначити `flex-direction` і головну вісь.

### Помилка 5. Вирівнювати елементи лише геометрично

Іконка може бути математично по центру, але візуально здаватися зміщеною.

**Краще:** спочатку налаштувати правильну структуру, а потім перевірити оптичне сприйняття.

### Помилка 6. Ігнорувати довжину контенту

Заголовок може займати один рядок на десктопі й три рядки на мобільному пристрої. Через це кнопки та інші елементи можуть зміститися.

**Краще:** перевіряти компоненти з коротким і довгим текстом, різними мовами та різними розмірами екрана.

### Помилка 7. Центрувати вміст карток незалежно від їхнього призначення

Центровані картки не завжди зручні для порівняння товарів, статей або навчальних матеріалів.

**Краще:** для карток із великою кількістю тексту часто використовувати вирівнювання ліворуч.

### Помилка 8. Використовувати `vertical-align` для будь-якого вертикального центрування

`vertical-align` не центрує довільний блок у батьківському елементі.

**Краще:** для сучасних компонувань використовувати Flexbox або Grid, коли вони відповідають задачі.

### Помилка 9. Забувати про напрямок письма

У мовах із напрямком письма справа наліво фізичні лівий і правий краї не завжди відповідають логічному початку та кінцю рядка.

**Краще:** для універсальних інтерфейсів розглядати `text-align: start`, `text-align: end`, `margin-inline` та інші логічні CSS-властивості.

## 14. Як перевіряти вирівнювання в UI

Під час перевірки макета постав собі такі запитання:

- Чи мають споріднені елементи спільні лінії вирівнювання?
- Чи однаково розташовані заголовки в схожих компонентах?
- Чи зручно читати основний текст?
- Чи зрозуміло, які елементи належать до одного блоку?
- Чи не виглядають іконки та текст випадково зміщеними?
- Чи узгоджені положення кнопок?
- Чи не порушується композиція, коли текст переноситься на новий рядок?
- Чи зберігається структура на мобільному екрані?
- Чи допомагає вирівнювання швидше знаходити потрібну інформацію?
- Чи є причина для кожного винятку з основного правила?

### Швидкий практичний метод

1. Знайди основні вертикальні та горизонтальні лінії макета.
2. Перевір, які елементи мають вирівнюватися за ними.
3. Перевір заголовки, абзаци, кнопки та поля форм.
4. Переглянь макет на різних ширинах екрана.
5. Перевір компоненти з довгим контентом.
6. Прибери випадкові відступи, які не мають композиційного обґрунтування.
7. Переконайся, що вирівнювання допомагає зрозуміти структуру, а не лише робить її симетричною.

## 15. Запитання для співбесіди

### Junior

**1. Що таке alignment у UI-дизайні?**

Це принцип розташування елементів відносно спільних ліній, країв, центрів або інших елементів для створення візуального порядку.

**2. Чим вирівнювання відрізняється від spacing?**

Alignment визначає взаємне положення елементів, а spacing — відстань між ними.

**3. Чим відрізняється центрування контейнера від центрування тексту?**

Центрування контейнера визначає його положення на сторінці. Вирівнювання тексту визначає розташування текстового вмісту всередині блоку.

**4. Коли доречно використовувати `text-align: center`?**

Для коротких повідомлень, hero-секцій, порожніх станів та інших блоків, де центральна композиція покращує сприйняття.

**5. Чому вирівнювання важливе для форм?**

Воно допомагає пов'язувати підписи з полями, забезпечувати послідовність і полегшувати заповнення.

### Middle

**6. Чим відрізняються `justify-content` та `align-items` у Flexbox?**

`justify-content` працює вздовж головної осі, а `align-items` — вздовж поперечної.

**7. Коли варто використовувати `align-self`?**

Коли окремий flex- або grid-елемент потребує іншого вирівнювання, ніж задане для групи.

**8. Чому `margin-inline: auto` не центрує текст?**

Тому що ця властивість керує зовнішніми відступами елемента, а не вирівнюванням тексту всередині нього.

**9. Що таке optical alignment?**

Це візуальне коригування положення елементів з урахуванням їхньої форми та сприйняття людиною.

**10. Як responsive design впливає на вирівнювання?**

На різних ширинах екрана може змінюватися компонування, кількість колонок, положення кнопок і спосіб вирівнювання, якщо це покращує зручність користування.

### Питання для поглибленого розуміння

**11. Коли `text-align: start` краще за `text-align: left`?**

Коли потрібно підтримувати напрямок письма: `start` відповідає логічному початку рядка, тоді як `left` завжди означає фізичний лівий край.

**12. Чим `align-items` відрізняється від `align-content` у Flexbox?**

`align-items` вирівнює елементи по поперечній осі. `align-content` розподіляє лінії flex-контейнера, коли є кілька ліній і доступний вільний простір.

**13. Чому однакове геометричне вирівнювання не завжди виглядає однаково?**

Через різницю у формах, оптичній вазі, розмірах іконок, шрифтах і довжині тексту.

## 16. Рівні засвоєння теми

### Core — основа

Потрібно розуміти:

- що таке alignment;
- чим воно відрізняється від spacing;
- вирівнювання ліворуч, праворуч, по центру та по ширині;
- різницю між контейнером і його вмістом;
- важливість спільних ліній;
- базові правила вирівнювання тексту, карток і форм.

### Junior — практичне застосування

Потрібно вміти:

- створювати узгоджені композиції;
- використовувати Flexbox для вирівнювання;
- застосовувати Grid для компонування;
- правильно вирівнювати текст та іконки;
- підтримувати послідовність між компонентами;
- перевіряти макети на різних ширинах екрана;
- пояснювати, чому вибране вирівнювання підходить конкретному інтерфейсу.

### Middle — системний підхід

Потрібно вміти:

- визначати правила вирівнювання для дизайн-системи;
- проєктувати складні компонування;
- відрізняти геометричне вирівнювання від оптичного;
- працювати з довгим і змінним контентом;
- враховувати різні напрямки письма;
- підтримувати компоненти у responsive-макетах;
- знаходити та усувати непослідовні правила розташування.

### Senior — архітектура інтерфейсу

Потрібно вміти:

- формувати узгоджену систему композиційних правил;
- визначати, де потрібна стандартизація, а де — виняток;
- оцінювати вплив вирівнювання на доступність і зручність користування;
- узгоджувати принципи дизайну з технічною реалізацією;
- визначати правила для складних таблиць, форм, панелей і адаптивних інтерфейсів;
- пояснювати дизайнерські рішення через потреби користувачів, а не лише через естетичні вподобання.

## 17. Мінішпаргалка

| Задача | Що розглянути |
|---|---|
| Вирівняти текст усередині блоку | `text-align` |
| Центрувати блок із заданою шириною | `margin-inline: auto` |
| Вирівняти елементи у flex-рядку | `justify-content`, `align-items` |
| Змінити вирівнювання одного flex-елемента | `align-self` |
| Вирівняти елементи в комірках Grid | `justify-items`, `align-items` |
| Вирівняти Grid у вільному просторі | `justify-content`, `align-content` |
| Вирівняти вміст Grid по двох осях | `place-items` |
| Вирівняти inline-елемент відносно тексту | `vertical-align` |
| Узгодити іконку та текст у рядку | Flexbox або відповідний inline-контекст |
| Підтримати різні напрямки письма | Логічні CSS-властивості |
| Зберегти структуру на мобільних екранах | Responsive layout і перевірка реального контенту |

### Головне запам'ятати

1. Alignment створює візуальний порядок і допомагає зрозуміти структуру інтерфейсу.
2. Вирівнювання контейнера та вирівнювання його вмісту — різні задачі.
3. Alignment і spacing доповнюють одне одного, але не замінюють одне одного.
4. Центрування не є універсальним рішенням для всіх елементів.
5. У Flexbox `justify-content` відповідає за головну вісь, а `align-items` — за поперечну.
6. Вирівнювання має залишатися послідовним між спорідненими компонентами.
7. Правильне геометричне вирівнювання іноді потребує невеликої оптичної корекції.
8. Вирівнювання потрібно перевіряти на різних екранах і з різною довжиною контенту.
9. Хороший UI не обов'язково симетричний, але його структура повинна бути зрозумілою.
10. Мета вирівнювання — не просто зробити елементи рівними, а полегшити сприйняття та використання інтерфейсу.

## 18. Практичні завдання

### Завдання 1. Три способи вирівнювання

Створи три однакові блоки:

- перший — із вирівнюванням ліворуч;
- другий — із вирівнюванням по центру;
- третій — із вирівнюванням праворуч.

Порівняй, як змінюється сприйняття заголовка, абзацу та кнопки.

### Завдання 2. Картка профілю

Створи картку профілю користувача з:

- аватаром;
- ім'ям;
- коротким описом;
- статусом;
- кнопкою дії.

Зроби дві версії:

- із центруванням вмісту;
- з вирівнюванням вмісту ліворуч.

Поясни, для якого сценарію кожна версія підходить краще.

### Завдання 3. Форма реєстрації

Створи форму з трьома полями, повідомленнями про помилки та кнопкою відправлення.

Перевір:

- спільні лінії полів;
- вирівнювання підписів;
- положення повідомлень про помилки;
- вирівнювання кнопки;
- поведінку на мобільному екрані.

### Завдання 4. Навігація

Створи навігацію з логотипом, чотирма посиланнями та кнопкою входу.

Використай Flexbox для:

- вертикального вирівнювання елементів;
- горизонтального розподілу;
- керування проміжками;
- адаптивної зміни компонування.

### Завдання 5. Аудит вирівнювання

Вибери будь-яку сторінку свого застосунку та перевір:

- чи узгоджені ліві межі;
- чи послідовно вирівняні заголовки;
- чи не зміщені кнопки без очевидної причини;
- чи правильно вирівняні іконки;
- чи не погіршується композиція на мобільних пристроях.

Запиши щонайменше три знайдені проблеми та виправ їх.

## 19. Підсумок

**Alignment — це система взаємного розташування елементів, яка робить інтерфейс послідовним, зрозумілим і візуально організованим.**

Під час створення UI:

- починай зі спільних ліній вирівнювання;
- відокремлюй позицію контейнера від положення його вмісту;
- обирай вирівнювання відповідно до типу інформації;
- використовуй Flexbox і Grid для структурного компонування;
- не замінюй правильну структуру випадковими відступами;
- перевіряй результат на різних екранах;
- оцінюй не лише геометрію, а й візуальне сприйняття.

Хороше вирівнювання часто непомітне для користувача — але саме воно допомагає інтерфейсу виглядати цілісним і працювати передбачувано.
