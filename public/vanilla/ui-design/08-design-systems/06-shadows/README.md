# 06. Shadows — Тіні в дизайн-системі

## 1. Що таке Shadows?

**Shadows (тіні)** — це візуальні ефекти, які допомагають створювати відчуття глибини, відокремлювати елементи від фону та показувати їхню візуальну ієрархію.

У UI-дизайні тіні використовують для карток, кнопок, випадаючих меню, модальних вікон та інших компонентів.

Основні завдання тіней:

- ✔ Візуально відокремлювати елементи від фону.
- ✔ Створювати відчуття глибини та шарів інтерфейсу.
- ✔ Підкреслювати важливість окремих компонентів.
- ✔ Допомагати розрізняти поверхні, які розташовані на різних рівнях.
- ✔ Візуально позначати інтерактивні стани, наприклад наведення курсора.
- ✔ Забезпечувати єдиний стиль у всьому інтерфейсі.

**Головна ідея:** у дизайн-системі тіні мають бути системними, передбачуваними та використовуватися відповідно до ролі компонента.

---

## 2. Як працює тінь у CSS?

Для створення зовнішньої тіні в CSS використовують властивість `box-shadow`.

Загальний синтаксис:

    box-shadow: offset-x offset-y blur-radius spread-radius color;

Параметри:

- `offset-x` — горизонтальне зміщення тіні.
- `offset-y` — вертикальне зміщення тіні.
- `blur-radius` — радіус розмиття.
- `spread-radius` — розширення або зменшення тіні.
- `color` — колір тіні.

Приклад:

    .card {
      box-shadow: 0 4px 12px 0 rgb(0 0 0 / 12%);
    }

У цьому прикладі:

- `0` — тінь не зміщена горизонтально.
- `4px` — тінь зміщена вниз.
- `12px` — тінь має розмиття.
- `0` — розмір тіні не змінюється через spread.
- `rgb(0 0 0 / 12%)` — чорна тінь із прозорістю 12%.

Зверни увагу: велике значення розмиття не обов'язково означає сильнішу тінь. На сприйняття впливають також прозорість, колір і зміщення.

---

## 3. Основні параметри тіні

### 3.1. Offset — зміщення

Зміщення визначає напрямок, у якому тінь візуально відходить від елемента.

    .shadow-right {
      box-shadow: 6px 0 12px rgb(0 0 0 / 15%);
    }

    .shadow-bottom {
      box-shadow: 0 6px 12px rgb(0 0 0 / 15%);
    }

Типові значення:

- `0 2px` — невелике зміщення вниз.
- `0 4px` — помірне зміщення вниз.
- `0 8px` — помітніше зміщення вниз.
- `0 16px` — виразна тінь для елементів, які візуально підняті над поверхнею.

Не варто сприймати ці значення як обов'язковий стандарт. Конкретна шкала залежить від дизайн-системи.

### 3.2. Blur — розмиття

Розмиття визначає, наскільки м'якими будуть краї тіні.

    .shadow-sharp {
      box-shadow: 0 2px 4px rgb(0 0 0 / 18%);
    }

    .shadow-soft {
      box-shadow: 0 4px 16px rgb(0 0 0 / 12%);
    }

    .shadow-very-soft {
      box-shadow: 0 8px 32px rgb(0 0 0 / 10%);
    }

Зазвичай:

- Малий blur створює компактнішу тінь.
- Великий blur створює м'якшу та ширшу тінь.
- Надмірне розмиття може зробити інтерфейс нечітким.

### 3.3. Spread — розмір тіні

Spread визначає, наскільки тінь розширюється або стискається.

    .shadow-expanded {
      box-shadow: 0 4px 12px 3px rgb(0 0 0 / 12%);
    }

    .shadow-contracted {
      box-shadow: 0 4px 12px -3px rgb(0 0 0 / 12%);
    }

Позитивне значення розширює тінь, а негативне — зменшує її.

У багатьох дизайн-системах spread дорівнює `0`, якщо немає потреби спеціально змінювати розмір тіні.

### 3.4. Color і opacity — колір та прозорість

Колір тіні суттєво впливає на її сприйняття.

    .shadow-dark {
      box-shadow: 0 4px 12px rgb(0 0 0 / 20%);
    }

    .shadow-light {
      box-shadow: 0 4px 12px rgb(0 0 0 / 8%);
    }

Поширений підхід — використовувати нейтральний темний колір із невеликою прозорістю.

На світлому фоні тінь зазвичай має бути достатньо м'якою, щоб не виглядати як брудна пляма.

Для темної теми не завжди достатньо просто зменшити прозорість чорної тіні. Часто важливішими стають відмінності між кольорами поверхонь, межами та іншими ознаками глибини.

---

## 4. Що таке Shadow Scale?

**Shadow Scale (шкала тіней)** — це набір заздалегідь визначених тіней, які використовуються повторно в різних компонентах інтерфейсу.

Замість того щоб кожного разу придумувати нову тінь, команда використовує готові значення.

Приклад шкали:

| Токен | Призначення |
|---|---|
| `shadow-xs` | Ледь помітне відокремлення |
| `shadow-sm` | Невелика тінь |
| `shadow-md` | Помірна тінь |
| `shadow-lg` | Виразна тінь |
| `shadow-xl` | Сильний ефект підняття |
| `shadow-none` | Без тіні |

Це лише приклад структури. Не кожній дизайн-системі потрібні всі шість значень.

Головні правила:

- ✔ Кожна тінь має зрозуміле призначення.
- ✔ Кількість рівнів має відповідати складності інтерфейсу.
- ✔ Однакові компоненти використовують однакові токени.
- ✔ Значення не повинні дублюватися без потреби.
- ✔ Шкала має бути достатньо простою для підтримки.

Не потрібно створювати десятки майже однакових тіней. Краще мати невелику зрозумілу систему.

---

## 5. Shadow Tokens — токени тіней

**Shadow Tokens** — це іменовані змінні, які зберігають значення тіней і дозволяють використовувати їх у різних частинах інтерфейсу.

Наприклад, замість повторення такого CSS:

    .card {
      box-shadow: 0 2px 8px rgb(0 0 0 / 10%);
    }

    .dropdown {
      box-shadow: 0 2px 8px rgb(0 0 0 / 10%);
    }

    .popover {
      box-shadow: 0 2px 8px rgb(0 0 0 / 10%);
    }

можна створити один токен:

    :root {
      --shadow-sm: 0 2px 8px rgb(0 0 0 / 10%);
    }

    .card {
      box-shadow: var(--shadow-sm);
    }

    .dropdown {
      box-shadow: var(--shadow-sm);
    }

    .popover {
      box-shadow: var(--shadow-sm);
    }

Переваги токенів:

- ✔ Менше дублювання коду.
- ✔ Єдиний стиль компонентів.
- ✔ Швидка зміна дизайну.
- ✔ Зручна підтримка світлої та темної тем.
- ✔ Простіша співпраця дизайнерів і розробників.

Важливо: токен — це не просто змінна. Це частина системи домовленостей про те, як інтерфейс має виглядати.

---

## 6. Primitive Tokens і Semantic Tokens

У більш розвинених дизайн-системах розрізняють два типи токенів.

### 6.1. Primitive Tokens

**Primitive Tokens** — базові значення, які описують конкретні візуальні параметри.

Наприклад:

    :root {
      --shadow-color: rgb(0 0 0 / 12%);

      --shadow-offset-y-1: 2px;
      --shadow-offset-y-2: 4px;

      --shadow-blur-1: 8px;
      --shadow-blur-2: 16px;
    }

Такі змінні можна використовувати для побудови складніших значень.

Проте для початкового проєкту не обов'язково розкладати кожну тінь на окремі параметри.

### 6.2. Semantic Tokens

**Semantic Tokens** — назви, які пояснюють призначення тіні в інтерфейсі.

Наприклад:

    :root {
      --shadow-card: 0 2px 8px rgb(0 0 0 / 10%);
      --shadow-dropdown: 0 4px 12px rgb(0 0 0 / 12%);
      --shadow-modal: 0 16px 40px rgb(0 0 0 / 18%);
    }

Назви пояснюють, де можна використовувати відповідні значення.

Ще один варіант — семантична система рівнів:

    :root {
      --shadow-raised: 0 2px 8px rgb(0 0 0 / 10%);
      --shadow-overlay: 0 8px 24px rgb(0 0 0 / 16%);
      --shadow-dialog: 0 16px 40px rgb(0 0 0 / 20%);
    }

У цьому випадку назви описують не конкретний компонент, а його роль у візуальній ієрархії.

**Що вибрати?**

- Якщо проєкт невеликий — достатньо `--shadow-sm`, `--shadow-md`, `--shadow-lg`.
- Якщо проєкт має багато компонентів — можуть бути корисними семантичні токени.
- Якщо дизайн-система велика — можна поєднати базові та семантичні токени.

Не потрібно ускладнювати архітектуру до того, як виникне реальна потреба.

## 7. Рівні глибини — Elevation

**Elevation (підняття)** — це візуальне уявлення про те, наскільки елемент розташований вище за інші поверхні.

У плоскому інтерфейсі глибина може бути майже непомітною. В інших інтерфейсах вона допомагає розрізняти звичайний контент, картки, меню та модальні вікна.

Приклад умовної ієрархії:

    :root {
      /* Звичайна поверхня */
      --elevation-0: none;

      /* Легке підняття */
      --elevation-1: 0 1px 3px rgb(0 0 0 / 8%);

      /* Картки та підняті елементи */
      --elevation-2: 0 4px 12px rgb(0 0 0 / 10%);

      /* Меню та випадаючі панелі */
      --elevation-3: 0 8px 24px rgb(0 0 0 / 14%);

      /* Модальні вікна */
      --elevation-4: 0 16px 40px rgb(0 0 0 / 18%);
    }

Приклад використання:

    .page {
      box-shadow: var(--elevation-0);
    }

    .card {
      box-shadow: var(--elevation-1);
    }

    .dropdown {
      box-shadow: var(--elevation-3);
    }

    .modal {
      box-shadow: var(--elevation-4);
    }

Ці значення наведені для навчання, а не як універсальний стандарт.

Важливо розуміти:

- ✔ Більша тінь часто створює відчуття більшої глибини.
- ✔ Візуальна глибина не повинна бути випадковою.
- ✔ Не кожен компонент потребує тіні.
- ✔ Глибину можна передавати також кольором поверхні, межами та перекриттям елементів.
- ✔ Тінь сама по собі не визначає функціональну важливість компонента.

Не варто додавати велику тінь до кожного блока лише для того, щоб інтерфейс виглядав сучасніше.

---

## 8. Тіні для різних компонентів

### 8.1. Cards — картки

Картки часто використовують для групування пов'язаного контенту.

Можливі варіанти:

- Без тіні — якщо картка відокремлена фоном або межею.
- Невелика тінь — якщо картка має виглядати трохи піднятою.
- Помітніша тінь при наведенні — якщо картка інтерактивна й це відповідає дизайну.

Приклад:

    .card {
      background: white;
      border-radius: 12px;
      box-shadow: var(--shadow-sm);
    }

Не кожна картка повинна мати тінь. Іноді достатньо відступів і різних кольорів поверхонь.

### 8.2. Buttons — кнопки

Для кнопок тінь може допомагати створити відчуття фізичної поверхні.

    .button {
      box-shadow: 0 2px 4px rgb(0 0 0 / 10%);
    }

Однак багато сучасних інтерфейсів використовують кнопки без тіней.

Тінь кнопки не замінює її контраст, видимий текст, зрозумілу форму чи чіткий стан фокуса.

### 8.3. Dropdowns — випадаючі меню

Випадаюче меню зазвичай перекриває основний контент.

    .dropdown {
      background: white;
      border-radius: 8px;
      box-shadow: var(--shadow-dropdown);
    }

Тінь допомагає зрозуміти, що меню розташоване над сторінкою, а не є частиною звичайного потоку контенту.

### 8.4. Modals — модальні вікна

Модальне вікно привертає увагу та перекриває іншу частину інтерфейсу.

    .modal {
      background: white;
      border-radius: 16px;
      box-shadow: var(--shadow-modal);
    }

Для модального вікна також може використовуватися затемнення фону:

    .modal-backdrop {
      background: rgb(0 0 0 / 45%);
    }

Затемнення фону й тінь самого вікна виконують різні завдання:

- Затемнення відокремлює модальний сценарій від основної сторінки.
- Тінь підкреслює об'єм і межі самого вікна.

### 8.5. Tooltips і popovers

Підказки та невеликі спливні панелі часто використовують тінь, щоб відокремити їх від навколишнього контенту.

    .tooltip {
      background: #222;
      color: white;
      border-radius: 6px;
      box-shadow: 0 4px 12px rgb(0 0 0 / 15%);
    }

Тінь повинна відповідати загальному стилю інтерфейсу й не відволікати від тексту.

## 9. Тіні та стани компонентів

Тінь може змінюватися залежно від стану інтерактивного компонента.

Типові стани:

- `default` — звичайний стан.
- `hover` — курсор наведений на компонент.
- `focus` — компонент отримав клавіатурний фокус.
- `active` — компонент натискають або активують.
- `disabled` — компонент недоступний для взаємодії.

Приклад:

    .card {
      box-shadow: var(--shadow-sm);
      transition: box-shadow 180ms ease;
    }

    .card:hover {
      box-shadow: var(--shadow-md);
    }

Але це не означає, що кожен елемент має отримувати сильнішу тінь при наведенні.

Якщо картка не є інтерактивною, зміна тіні при наведенні може створювати хибне очікування, що на неї можна натиснути.

Для клавіатурного фокуса варто забезпечити помітний індикатор:

    .button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

Не слід покладатися лише на зміну тіні як на індикатор фокуса. Її може бути недостатньо для користувачів із порушеннями зору.

## 10. Shadows і дизайн-система в Figma

У Figma тіні зазвичай створюють за допомогою ефекту **Drop shadow**.

Під час розробки дизайн-системи корисно:

1. Створити сторінку або секцію для дизайн-токенів.
2. Визначити невелику шкалу тіней.
3. Дати кожній тіні зрозумілу назву.
4. Використовувати ті самі значення в компонентах.
5. Перевірити, як тіні виглядають на різних поверхнях.
6. Узгодити значення між дизайном і CSS.

Приклад назв:

    shadow/xs
    shadow/sm
    shadow/md
    shadow/lg
    shadow/xl

Або семантичні назви:

    shadow/card
    shadow/dropdown
    shadow/popover
    shadow/modal

Конкретний формат назв залежить від організації токенів у проєкті.

**Важливо:** тінь, налаштована у Figma, повинна мати відповідне значення в реалізації. Не обов'язково копіювати кожну дрібну особливість піксель у піксель, але візуальна система має залишатися послідовною.

## 11. Реалізація шкали тіней у CSS

Для невеликого навчального проєкту можна почати з простого набору CSS-змінних.

    :root {
      /* Shadow tokens */
      --shadow-none: none;
      --shadow-xs: 0 1px 2px rgb(0 0 0 / 6%);
      --shadow-sm: 0 2px 8px rgb(0 0 0 / 10%);
      --shadow-md: 0 4px 16px rgb(0 0 0 / 12%);
      --shadow-lg: 0 8px 24px rgb(0 0 0 / 16%);
      --shadow-xl: 0 16px 40px rgb(0 0 0 / 20%);
    }

Використання:

    .card {
      box-shadow: var(--shadow-sm);
    }

    .card--raised {
      box-shadow: var(--shadow-md);
    }

    .dropdown {
      box-shadow: var(--shadow-lg);
    }

    .modal {
      box-shadow: var(--shadow-xl);
    }

Перевага такого підходу полягає в тому, що значення тіней зосереджені в одному місці.

Якщо потрібно зробити всі тіні м'якшими, можна змінити токени, а не редагувати кожен компонент окремо.

Не забувай: назви `xs`, `sm`, `md`, `lg`, `xl` задають послідовність у твоїй системі, але не гарантують однакового вигляду в різних дизайн-системах.

## 12. Тіні у світлій і темній темах

У світлій темі тіні зазвичай помітніші, оскільки темний колір легко відрізняється від світлого фону.

У темній темі чорна тінь на темному фоні може бути майже непомітною.

Приклад:

    :root {
      color-scheme: light;

      --surface: #ffffff;
      --text: #222222;
      --shadow-card: 0 4px 16px rgb(0 0 0 / 12%);
    }

    [data-theme="dark"] {
      color-scheme: dark;

      --surface: #1f1f1f;
      --text: #f5f5f5;
      --shadow-card: 0 4px 16px rgb(0 0 0 / 35%);
    }

У темній темі важливо перевірити, чи допомагає тінь відрізняти поверхні. Іноді ефективніше використовувати:

- Трохи світліший фон піднятого компонента.
- Межу з невеликим контрастом.
- Затемнення або перекриття сусідніх елементів.
- Комбінацію кольору поверхні й тіні.

Не потрібно механічно переносити тіні зі світлої теми в темну без перевірки.

## 13. Тіні та доступність

Тіні можуть покращувати візуальне сприйняття, але не повинні бути єдиним способом передавання важливої інформації.

Основні правила:

- ✔ Не позначай помилку лише зміною тіні.
- ✔ Не використовуй тінь як єдиний індикатор клавіатурного фокуса.
- ✔ Перевіряй видимість компонентів на різних фонах.
- ✔ Забезпечуй достатній контраст тексту незалежно від тіні.
- ✔ Не використовуй надмірно сильні тіні, що ускладнюють читання.
- ✔ Перевіряй інтерфейс у світлій і темній темах.

Наприклад, якщо поле введення містить помилку, краще явно показати стан за допомогою кольору межі, текстового повідомлення та, за потреби, відповідного значка.

Тінь може бути додатковим декоративним елементом, але не повинна замінювати зрозуміле повідомлення про помилку.

---

## 14. Типові помилки

### Помилка 1. Надто сильні тіні

Якщо всі картки, кнопки, поля й секції мають темні тіні, інтерфейс виглядає перевантаженим.

**Рішення:** використовуй тіні лише там, де вони допомагають відокремити поверхні або підкреслити взаємодію.

### Помилка 2. Випадкові значення

Коли кожен компонент має власну тінь, дизайн втрачає послідовність.

**Рішення:** створи шкалу й повторно використовуй токени.

### Помилка 3. Тіні замість меж

На деяких фонах м'яка тінь майже непомітна, тому межі компонента стають нечіткими.

**Рішення:** за потреби поєднуй тінь із `border`.

### Помилка 4. Надмірна кількість токенів

Створення десятків майже однакових тіней ускладнює підтримку.

**Рішення:** почни з кількох значень і розширюй шкалу лише за необхідності.

### Помилка 5. Однакові тіні для всіх поверхонь

Картка, випадаюче меню та модальне вікно мають різні ролі, тому однакова тінь може не передавати потрібної ієрархії.

**Рішення:** визначай тінь відповідно до призначення компонента.

### Помилка 6. Зміна тіні без причини

Якщо неінтерактивна картка змінює тінь при наведенні, користувач може очікувати, що її можна натиснути.

**Рішення:** пов'язуй візуальні стани з реальною поведінкою елемента.

### Помилка 7. Ігнорування темної теми

Тінь, яка добре виглядає на білому фоні, може зникнути на темному.

**Рішення:** перевіряй контраст і глибину поверхонь у кожній темі окремо.

## 15. Практичний приклад: картка з тінню

Мета: створити картку з заголовком, описом і кнопкою, використовуючи токени тіней.

Структура HTML:

    <article class="card">
      <h2 class="card__title">UI Design</h2>

      <p class="card__description">
        Вивчення принципів дизайну інтерфейсів.
      </p>

      <button class="button" type="button">
        Докладніше
      </button>
    </article>

CSS:

    :root {
      --color-surface: #ffffff;
      --color-text: #222222;
      --color-text-muted: #666666;
      --color-primary: #2563eb;

      --radius-card: 12px;
      --radius-button: 8px;

      --shadow-card: 0 2px 8px rgb(0 0 0 / 10%);
      --shadow-card-hover: 0 8px 20px rgb(0 0 0 / 14%);
    }

    body {
      font-family: Arial, sans-serif;
      background: #f3f4f6;
      color: var(--color-text);
      padding: 32px;
    }

    .card {
      max-width: 360px;
      padding: 24px;
      background: var(--color-surface);
      border-radius: var(--radius-card);
      box-shadow: var(--shadow-card);
      transition: box-shadow 180ms ease;
    }

    .card:hover {
      box-shadow: var(--shadow-card-hover);
    }

    .card__title {
      margin: 0 0 12px;
      font-size: 24px;
    }

    .card__description {
      margin: 0 0 20px;
      color: var(--color-text-muted);
      line-height: 1.5;
    }

    .button {
      padding: 10px 16px;
      border: 0;
      border-radius: var(--radius-button);
      background: var(--color-primary);
      color: white;
      cursor: pointer;
    }

У цьому прикладі використано:

- CSS-змінні для значень тіней.
- Токен для радіуса картки.
- Окремі класи для структурних частин компонента.
- Перехід між двома значеннями тіні.

Зверни увагу: якщо картка не має бути інтерактивною, зміна тіні при наведенні може бути зайвою. У такому разі прибери правило `.card:hover`.

## 16. Як працювати з тінями під час створення дизайну

Рекомендований порядок:

1. **Визнач поверхні.** З'ясуй, які елементи мають бути візуально відокремлені від фону.
2. **Визнач ієрархію.** Виріши, які компоненти повинні виглядати трохи піднятими, а які — значно вище.
3. **Створи шкалу.** Почни з кількох тіней, що помітно відрізняються за призначенням.
4. **Створи токени.** Дай значенням зрозумілі назви.
5. **Застосуй їх до компонентів.** Використовуй токени повторно.
6. **Перевір стани.** Подивися, як виглядають `default`, `hover` та інші необхідні стани.
7. **Перевір теми.** Переконайся, що глибина поверхонь читається на різних фонах.
8. **Прибери зайве.** Якщо тінь не допомагає зрозуміти інтерфейс, можливо, вона не потрібна.

## 17. Що потрібно знати Junior UI Designer / Frontend Developer

Ти маєш розуміти:

- ✔ Що таке `box-shadow`.
- ✔ Чим відрізняються offset, blur, spread і color.
- ✔ Що таке шкала тіней.
- ✔ Що таке shadow tokens.
- ✔ Навіщо повторно використовувати CSS-змінні.
- ✔ Чим базові токени відрізняються від семантичних.
- ✔ Як тіні створюють візуальну глибину.
- ✔ Чому картки, меню та модальні вікна можуть потребувати різних тіней.
- ✔ Чому не кожен компонент повинен мати тінь.
- ✔ Як тіні взаємодіють із фоном, межами та кольорами поверхонь.
- ✔ Чому потрібно окремо перевіряти темну тему.
- ✔ Чому тінь не замінює доступний індикатор фокуса.

Для початку тобі не потрібно створювати складну систему з десятками параметрів. Достатньо розуміти принципи та вміти послідовно застосовувати невелику шкалу токенів.

## 19. Мінішпаргалка

| Поняття | Значення |
|---|---|
| `box-shadow` | CSS-властивість для створення тіні |
| Offset | Зміщення тіні |
| Blur | Розмиття тіні |
| Spread | Розширення або стискання тіні |
| Shadow Scale | Система узгоджених значень тіней |
| Shadow Token | Іменоване значення тіні |
| Primitive Token | Базове значення для побудови системи |
| Semantic Token | Токен, що описує призначення |
| Elevation | Візуальне відчуття глибини |
| Drop shadow | Ефект тіні у Figma |
| `--shadow-sm` | Приклад CSS-токена невеликої тіні |
| `box-shadow: none` | Відсутність тіні |

Короткий приклад:

    :root {
      --shadow-sm: 0 2px 8px rgb(0 0 0 / 10%);
      --shadow-md: 0 4px 16px rgb(0 0 0 / 12%);
      --shadow-lg: 0 8px 24px rgb(0 0 0 / 16%);
    }

    .card {
      box-shadow: var(--shadow-sm);
    }

    .dropdown {
      box-shadow: var(--shadow-md);
    }

    .modal {
      box-shadow: var(--shadow-lg);
    }

## Висновок

**Тіні в дизайн-системі — це не просто декоративний ефект, а інструмент створення візуальної ієрархії.**

Вони допомагають відокремлювати поверхні, показувати глибину та підтримувати послідовність інтерфейсу.

Для початкового проєкту достатньо створити невелику шкалу тіней, зберегти її у CSS-змінних і повторно використовувати в картках, меню та модальних вікнах.

Головне правило: **кожна тінь повинна мати зрозуміле призначення, а не з'являтися лише заради декоративного ефекту.**
