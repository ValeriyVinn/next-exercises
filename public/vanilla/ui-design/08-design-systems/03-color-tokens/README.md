# 03. Color Tokens

## 1. Що таке Color Tokens?

**Color Tokens (колірні токени)** — це іменовані змінні, які зберігають кольори дизайн-системи та дозволяють повторно використовувати їх у компонентах інтерфейсу.

Замість того щоб записувати конкретний колір у кожному CSS-правилі, ми створюємо токен із зрозумілою назвою та використовуємо його в різних частинах інтерфейсу.

Наприклад, замість:

    .button {
      background-color: #2563eb;
    }

    .link {
      color: #2563eb;
    }

    .badge {
      background-color: #2563eb;
    }

Використовуємо один токен:

    :root {
      --color-primary: #2563eb;
    }

    .button {
      background-color: var(--color-primary);
    }

    .link {
      color: var(--color-primary);
    }

    .badge {
      background-color: var(--color-primary);
    }

Тепер, якщо потрібно змінити основний колір сайту, достатньо змінити значення одного токена.

**Головна ідея:** колір визначається один раз, отримує зрозуміле ім'я та використовується в багатьох місцях інтерфейсу.

---

## 2. Навіщо потрібні Color Tokens?

Колірні токени допомагають:

✔ підтримувати єдину кольорову систему;
✔ уникати випадкових відтінків одного кольору;
✔ швидко змінювати оформлення всього сайту;
✔ створювати світлу й темну теми;
✔ повторно використовувати кольори в компонентах;
✔ забезпечувати кращу читабельність і доступність;
✔ спрощувати підтримку та масштабування проєкту;
✔ узгоджувати роботу дизайнерів і розробників.

### Без токенів

    .header {
      background-color: #2563eb;
    }

    .button {
      background-color: #2563eb;
    }

    .link {
      color: #2563eb;
    }

    .card__title {
      color: #1f2937;
    }

Якщо основний синій колір потрібно змінити, доведеться шукати всі місця, де використовується його значення.

### Із токенами

    :root {
      --color-primary: #2563eb;
      --color-text-primary: #1f2937;
    }

    .header {
      background-color: var(--color-primary);
    }

    .button {
      background-color: var(--color-primary);
    }

    .link {
      color: var(--color-primary);
    }

    .card__title {
      color: var(--color-text-primary);
    }

Тепер колірна система централізована.

## 3. Основні поняття

### 3.1. Color Palette — палітра кольорів

**Color Palette** — це набір кольорів і відтінків, які використовуються в дизайн-системі.

Наприклад:

- Primary — основний колір бренду.
- Secondary — додатковий колір.
- Neutral — нейтральні кольори.
- Success — успішна дія.
- Warning — попередження.
- Danger — помилка або небезпечна дія.
- Info — інформаційне повідомлення.

Приклад палітри:

    Primary:
      #eff6ff
      #dbeafe
      #93c5fd
      #3b82f6
      #2563eb
      #1d4ed8

    Neutral:
      #ffffff
      #f9fafb
      #e5e7eb
      #9ca3af
      #4b5563
      #111827

Це лише приклад. У реальному проєкті кількість відтінків і їхні значення залежать від потреб дизайн-системи.

**Важливо:** палітра — це набір кольорів, а токени — іменований спосіб використовувати ці кольори в інтерфейсі.

### 3.2. Color Value — значення кольору

Значенням токена може бути колір у різних форматах CSS.

    #2563eb
    rgb(37 99 235)
    hsl(221 83% 53%)
    oklch(54% 0.22 262)

Для більшості навчальних проєктів достатньо почати з HEX.

Не потрібно вивчати всі формати одночасно. Важливо розуміти, що токен може зберігати конкретне значення кольору незалежно від того, у якому форматі воно записане.

### 3.3. Token Name — назва токена

Назва токена має пояснювати призначення кольору.

Наприклад:

    --color-primary
    --color-text-primary
    --color-background
    --color-border
    --color-success

Завдяки назві можна зрозуміти, для чого потрібен колір, не запам'ятовуючи його HEX-код.

## 4. Два основні типи Color Tokens

У дизайн-системах важливо розрізняти **Primitive Tokens** і **Semantic Tokens**.

### 4.1. Primitive Tokens — базові токени

**Primitive Tokens** зберігають конкретні значення кольорів палітри.

Вони відповідають на запитання:

«Який саме це колір?»

Приклад:

    :root {
      --blue-50: #eff6ff;
      --blue-100: #dbeafe;
      --blue-500: #3b82f6;
      --blue-600: #2563eb;
      --blue-700: #1d4ed8;

      --gray-50: #f9fafb;
      --gray-100: #f3f4f6;
      --gray-300: #d1d5db;
      --gray-600: #4b5563;
      --gray-900: #111827;
    }

Тут `--blue-600` — це конкретний відтінок синього.

Назви `50`, `100`, `500`, `600` зазвичай позначають місце відтінку в шкалі. Вони не є універсальним стандартом, який зобов'язує використовувати певний HEX-код.

Primitive Tokens зручно використовувати як основу всієї палітри.

### 4.2. Semantic Tokens — семантичні токени

**Semantic Tokens** описують призначення кольору в інтерфейсі.

Вони відповідають на запитання:

«Для чого використовується цей колір?»

Приклад:

    :root {
      --color-primary: var(--blue-600);
      --color-primary-hover: var(--blue-700);

      --color-text-primary: var(--gray-900);
      --color-text-secondary: var(--gray-600);

      --color-background: #ffffff;
      --color-background-muted: var(--gray-50);

      --color-border: var(--gray-300);
    }

Тут `--color-primary` посилається на `--blue-600`.

Якщо дизайн зміниться, можна перенаправити семантичний токен на інший відтінок, не змінюючи стилі компонентів.

### 4.3. У чому різниця?

| Primitive Token | Semantic Token |
|---|---|
| `--blue-600` | `--color-primary` |
| `--gray-900` | `--color-text-primary` |
| `--gray-300` | `--color-border` |
| Описує конкретний колір | Описує призначення кольору |
| Зберігає значення палітри | Посилається на базовий токен або колірне значення |
| Зазвичай не залежить від теми | Може змінюватися залежно від теми |

**Що запам'ятати:**

Primitive Token — це колір.

Semantic Token — це роль кольору в інтерфейсі.

Наприклад, кнопка використовує `--color-primary`, а не безпосередньо `--blue-600`. Тоді зміна теми не потребує переписування стилів кнопки.

## 5. Основні групи колірних токенів

У дизайн-системі кольори часто групують за їхнім призначенням.

### 5.1. Brand Colors — кольори бренду

Визначають візуальну ідентичність продукту.

    :root {
      --color-primary: #2563eb;
      --color-primary-hover: #1d4ed8;
      --color-secondary: #7c3aed;
      --color-accent: #f59e0b;
    }

Застосування:

- основні кнопки;
- посилання;
- активні елементи;
- брендовані блоки;
- виділення важливої інформації.

Не кожен проєкт потребує окремих `secondary` та `accent` кольорів. Додавай їх, коли вони мають конкретну роль.

### 5.2. Text Colors — кольори тексту

Визначають колір тексту залежно від його призначення.

    :root {
      --color-text-primary: #111827;
      --color-text-secondary: #4b5563;
      --color-text-muted: #6b7280;
      --color-text-inverse: #ffffff;
      --color-text-link: #2563eb;
    }

Приклади:

- `text-primary` — заголовки й основний текст;
- `text-secondary` — допоміжний текст;
- `text-muted` — менш акцентні підписи;
- `text-inverse` — текст на темному фоні;
- `text-link` — посилання.

**Важливо:** менш помітний текст не повинен ставати настільки світлим, що його важко читати.

### 5.3. Background Colors — кольори фону

Визначають фон сторінок, секцій, карток та інших елементів.

    :root {
      --color-background: #ffffff;
      --color-background-muted: #f9fafb;
      --color-surface: #ffffff;
      --color-surface-raised: #ffffff;
      --color-overlay: rgb(17 24 39 / 60%);
    }

Приклади:

- `background` — загальний фон сторінки;
- `background-muted` — нейтральний фон секції;
- `surface` — поверхня картки або панелі;
- `surface-raised` — поверхня елемента, який візуально виділяється;
- `overlay` — напівпрозоре накладання поверх вмісту.

Назви `surface` і `surface-raised` особливо корисні, коли інтерфейс має картки, меню, модальні вікна та інші шари.

### 5.4. Border Colors — кольори меж

Визначають колір рамок, роздільників та контурів.

    :root {
      --color-border: #d1d5db;
      --color-border-strong: #9ca3af;
      --color-border-focus: #2563eb;
    }

Застосування:

- рамки карток;
- поля форм;
- роздільники;
- активні контури;
- виділення елементів у фокусі.

Не всі межі мають бути темними. Зазвичай нейтральні межі менш акцентні, ніж основний текст.

### 5.5. Feedback Colors — кольори зворотного зв'язку

Допомагають користувачу зрозуміти результат дії або стан системи.

    :root {
      --color-success: #15803d;
      --color-warning: #b45309;
      --color-danger: #b91c1c;
      --color-info: #1d4ed8;
    }

Застосування:

- `success` — успішне збереження;
- `warning` — попередження;
- `danger` — помилка або небезпечна дія;
- `info` — інформаційне повідомлення.

Колір не повинен бути єдиним способом передавання значення. Наприклад, помилку поля форми варто позначати не лише червоним кольором, а й текстом пояснення.

## 6. Шкала кольорів (Color Scale)

**Color Scale** — це впорядкований набір відтінків одного кольору.

Наприклад, синя шкала:

    --blue-50
    --blue-100
    --blue-200
    --blue-300
    --blue-400
    --blue-500
    --blue-600
    --blue-700
    --blue-800
    --blue-900

Зазвичай світліші відтінки використовують для легких фонів, а темніші — для акцентів і тексту.

Приклад:

    :root {
      --blue-50: #eff6ff;
      --blue-100: #dbeafe;
      --blue-200: #bfdbfe;
      --blue-300: #93c5fd;
      --blue-400: #60a5fa;
      --blue-500: #3b82f6;
      --blue-600: #2563eb;
      --blue-700: #1d4ed8;
      --blue-800: #1e40af;
      --blue-900: #1e3a8a;
    }

Це приклад шкали, а не вимога використовувати саме ці значення.

### Як застосовувати відтінки?

    .notice {
      background-color: var(--blue-50);
      border: 1px solid var(--blue-200);
      color: var(--blue-900);
    }

    .button {
      background-color: var(--blue-600);
      color: #ffffff;
    }

    .button:hover {
      background-color: var(--blue-700);
    }

**Що важливо:** відтінки шкали повинні працювати разом. Не варто просто вибирати довільні світлі й темні кольори без перевірки контрасту та загальної гармонії.

## 7. Naming Convention — правила найменування

Послідовні назви допомагають швидко знаходити потрібний токен.

### 7.1. Назви за кольором

    --blue-500
    --green-600
    --gray-100
    --red-700

Це зручно для Primitive Tokens.

### 7.2. Назви за призначенням

    --color-primary
    --color-text-primary
    --color-background
    --color-border
    --color-danger

Це зручно для Semantic Tokens.

### 7.3. Назви за станом

    --color-primary-hover
    --color-primary-active
    --color-border-focus
    --color-background-disabled

Такі назви пояснюють, як токен використовується у певному стані компонента.

### 7.4. Як вибрати назву?

Порівняй:

    --blue-600
    --color-primary

Перша назва повідомляє, який це відтінок.

Друга — яку роль він виконує.

Для стилів компонентів зазвичай зручніше використовувати семантичні назви:

    .button {
      background-color: var(--color-primary);
    }

Так компонент не залежить від конкретного відтінку синього.

**Правило:** використовуй єдину схему найменування в усьому проєкті. Не змішуй без потреби різні підходи до однакових ролей.

## 8. Як побудувати систему Color Tokens

Практична схема складається з кількох рівнів.

    Color Palette
        ↓
    Primitive Tokens
        ↓
    Semantic Tokens
        ↓
    Component Styles
        ↓
    UI

Розглянемо приклад.

### Крок 1. Створюємо палітру

    :root {
      --blue-50: #eff6ff;
      --blue-600: #2563eb;
      --blue-700: #1d4ed8;

      --gray-50: #f9fafb;
      --gray-300: #d1d5db;
      --gray-600: #4b5563;
      --gray-900: #111827;
    }

### Крок 2. Створюємо семантичні токени

    :root {
      --color-primary: var(--blue-600);
      --color-primary-hover: var(--blue-700);

      --color-text-primary: var(--gray-900);
      --color-text-secondary: var(--gray-600);

      --color-background: #ffffff;
      --color-background-muted: var(--gray-50);

      --color-border: var(--gray-300);
    }

### Крок 3. Використовуємо токени в компонентах

    .button {
      background-color: var(--color-primary);
      color: #ffffff;
    }

    .button:hover {
      background-color: var(--color-primary-hover);
    }

    .card {
      background-color: var(--color-background);
      border: 1px solid var(--color-border);
    }

    .card__title {
      color: var(--color-text-primary);
    }

    .card__description {
      color: var(--color-text-secondary);
    }

### Що це дає?

Якщо бренд змінює основний колір, достатньо змінити:

    --color-primary: var(--blue-600);

Наприклад, на:

    --color-primary: var(--green-600);

Компоненти продовжать використовувати `--color-primary`, тому їхні стилі не потрібно переписувати.

## 9. CSS Custom Properties для Color Tokens

У звичайному CSS колірні токени найчастіше реалізують за допомогою **CSS Custom Properties** — користувацьких CSS-змінних.

### 9.1. Оголошення змінних

Змінні глобального рівня зазвичай оголошують у `:root`.

    :root {
      --color-primary: #2563eb;
      --color-text-primary: #111827;
      --color-background: #ffffff;
    }

### 9.2. Використання через var()

    body {
      color: var(--color-text-primary);
      background-color: var(--color-background);
    }

    a {
      color: var(--color-primary);
    }

Функція `var()` отримує значення CSS-змінної.

### 9.3. Значення за замовчуванням

Якщо змінна може бути відсутня, `var()` підтримує резервне значення.

    .button {
      background-color: var(--color-primary, #2563eb);
    }

Якщо `--color-primary` не визначена або має невалідне значення для цієї властивості, браузер може використати резервне значення.

У повноцінній дизайн-системі краще визначати необхідні токени централізовано, а резервні значення використовувати там, де вони справді потрібні.

### 9.4. Наслідування змінних

CSS-змінні наслідуються відповідно до правил CSS, якщо не задані інші умови.

    :root {
      --color-primary: #2563eb;
    }

    .special-section {
      --color-primary: #7c3aed;
    }

    .button {
      background-color: var(--color-primary);
    }

Кнопка всередині `.special-section` використовуватиме фіолетовий колір, якщо не має власного перевизначення змінної.

Це корисний механізм для локальних варіантів оформлення.

## 10. Color Tokens і компоненти інтерфейсу

Токени особливо корисні, коли один колір використовується в багатьох компонентах.

### 10.1. Button

    .button {
      background-color: var(--color-primary);
      color: var(--color-text-inverse);
      border: 1px solid transparent;
    }

    .button:hover {
      background-color: var(--color-primary-hover);
    }

### 10.2. Card

    .card {
      background-color: var(--color-surface);
      border: 1px solid var(--color-border);
      color: var(--color-text-primary);
    }

### 10.3. Input

    .input {
      background-color: var(--color-surface);
      color: var(--color-text-primary);
      border: 1px solid var(--color-border);
    }

    .input:focus-visible {
      border-color: var(--color-border-focus);
      outline: 2px solid var(--color-border-focus);
      outline-offset: 2px;
    }

### 10.4. Alert

    .alert--success {
      background-color: var(--color-success-bg);
      color: var(--color-success-text);
      border-color: var(--color-success-border);
    }

Для повідомлень краще визначати окремі ролі фону, тексту та меж, а не використовувати один темний колір для всіх частин компонента.

Приклад:

    :root {
      --color-success-bg: #f0fdf4;
      --color-success-text: #166534;
      --color-success-border: #86efac;
    }

**Головне:** компонент має використовувати токени, що відповідають його ролям і станам, а не довільні HEX-коди.

## 11. Color Tokens і стани компонентів

Компонент може мати різні стани, і для кожного можуть знадобитися свої кольори.

Наприклад, кнопка:

- Default — звичайний стан.
- Hover — курсор наведений на кнопку.
- Active — кнопка натискається.
- Focus — кнопка отримала клавіатурний фокус.
- Disabled — кнопка недоступна.

Приклад:

    :root {
      --color-primary: #2563eb;
      --color-primary-hover: #1d4ed8;
      --color-primary-active: #1e40af;
      --color-disabled-bg: #e5e7eb;
      --color-disabled-text: #6b7280;
    }

    .button {
      background-color: var(--color-primary);
      color: #ffffff;
    }

    .button:hover {
      background-color: var(--color-primary-hover);
    }

    .button:active {
      background-color: var(--color-primary-active);
    }

    .button:focus-visible {
      outline: 2px solid var(--color-primary);
      outline-offset: 3px;
    }

    .button:disabled {
      background-color: var(--color-disabled-bg);
      color: var(--color-disabled-text);
      cursor: not-allowed;
    }

Не потрібно створювати окремий токен для кожного стану автоматично. Додавай токени тоді, коли вони мають чітке призначення та потрібні кільком компонентам або важливі для послідовності системи.

## 12. Color Tokens і світла та темна теми

Одна з головних переваг семантичних токенів — можливість змінювати тему без переписування стилів компонентів.

### 12.1. Світла тема

    :root {
      color-scheme: light;

      --color-background: #ffffff;
      --color-surface: #ffffff;
      --color-text-primary: #111827;
      --color-text-secondary: #4b5563;
      --color-border: #d1d5db;
      --color-primary: #2563eb;
    }

### 12.2. Темна тема

    [data-theme="dark"] {
      color-scheme: dark;

      --color-background: #111827;
      --color-surface: #1f2937;
      --color-text-primary: #f9fafb;
      --color-text-secondary: #d1d5db;
      --color-border: #4b5563;
      --color-primary: #93c5fd;
    }

### 12.3. Компоненти залишаються незмінними

    body {
      background-color: var(--color-background);
      color: var(--color-text-primary);
    }

    .card {
      background-color: var(--color-surface);
      border: 1px solid var(--color-border);
    }

    .button {
      background-color: var(--color-primary);
    }

Коли атрибут `data-theme` змінюється на `dark`, браузер використовує відповідні значення семантичних токенів.

Приклад HTML:

    <html lang="uk" data-theme="dark">
      ...
    </html>

У реальному проєкті перемикання теми можна реалізувати через JavaScript або інший механізм керування станом.

**Важливо:** темна тема — це не просто заміна білого на чорний. Потрібно повторно перевірити контраст тексту, меж, посилань, кнопок та інших елементів.

---

## 13. Primitive Tokens і Semantic Tokens у темах

Під час створення тем важливо розуміти, які токени залишаються незмінними, а які змінюються.

### Primitive Tokens

Можуть зберігати палітру незалежно від теми:

    :root {
      --blue-100: #dbeafe;
      --blue-600: #2563eb;
      --gray-100: #f3f4f6;
      --gray-900: #111827;
    }

### Semantic Tokens

Можуть змінювати призначення або значення залежно від теми:

    :root {
      --color-background: #ffffff;
      --color-text-primary: var(--gray-900);
      --color-primary: var(--blue-600);
    }

    [data-theme="dark"] {
      --color-background: #111827;
      --color-text-primary: #f9fafb;
      --color-primary: #93c5fd;
    }

Зверни увагу: в темній темі `--color-primary` більше не посилається на `--blue-600`, а використовує інше значення.

Це нормально. Семантичний токен визначає роль, а не обов'язково один і той самий відтінок у всіх темах.

## 14. Color Tokens і доступність (Accessibility)

Колірна система повинна забезпечувати читабельність і зрозумілий зворотний зв'язок.

### 14.1. Контраст тексту

Контраст — це різниця між кольором тексту та кольором фону.

Якщо контраст недостатній, текст може бути важко читати.

Для звичайного тексту WCAG 2.2 за критерієм AA вимагає коефіцієнт контрастності щонайменше **4.5:1**.

Для великого тексту — щонайменше **3:1**.

До великого тексту за цим критерієм належить текст розміром від 24 CSS px або від приблизно 18.67 CSS px для жирного тексту.

Це вимоги до контрасту тексту, а не універсальні значення для всіх елементів інтерфейсу.

### 14.2. Контраст нетекстових елементів

Для важливих візуальних компонентів інтерфейсу, зокрема деяких меж полів, значущих графічних елементів та індикаторів стану, WCAG 2.2 на рівні AA передбачає контраст щонайменше **3:1** відносно суміжних кольорів у випадках, визначених відповідним критерієм.

Не кожна декоративна межа підпадає під цю вимогу.

### 14.3. Не покладайся лише на колір

Неправильно:

    .input--error {
      border-color: red;
    }

Користувач може не помітити помилку, особливо якщо йому складно розрізняти кольори.

Краще:

    <div class="field">
      <label for="email">Електронна пошта</label>

      <input
        id="email"
        type="email"
        aria-invalid="true"
        aria-describedby="email-error"
      />

      <p id="email-error" class="field__error">
        Введіть коректну електронну адресу.
      </p>
    </div>

Тут помилка передається кольором, текстом і семантичними атрибутами.

### 14.4. Перевіряй реальні комбінації

Навіть якщо два кольори окремо добре виглядають у палітрі, це не гарантує достатнього контрасту в парі.

Перевіряй:

- основний текст на основному фоні;
- допоміжний текст на фоні картки;
- текст кнопки на її фоні;
- посилання в тексті;
- повідомлення про помилки;
- індикатори фокусу;
- кольори в темній темі.

Для перевірки можна використовувати інструменти аналізу контрастності та браузерні DevTools.

## 15. Поширені помилки

### Помилка 1. Використання HEX-кодів усюди

    .header {
      background-color: #2563eb;
    }

    .button {
      background-color: #2563eb;
    }

    .link {
      color: #2563eb;
    }

Проблема: кольори важче змінювати й підтримувати.

Рішення: використовуй централізовані токени.

### Помилка 2. Надто багато схожих кольорів

    --blue-a: #2563eb;
    --blue-b: #2764ec;
    --blue-c: #2462ea;
    --blue-d: #2563eb;

Проблема: незрозуміло, чим відрізняються ці значення і коли їх використовувати.

Рішення: створи узгоджену палітру та визнач призначення кожного токена.

### Помилка 3. Використання назв лише за кольором у компонентах

    .button {
      background-color: var(--blue-600);
    }

Проблема: компонент напряму залежить від конкретного відтінку.

Рішення:

    .button {
      background-color: var(--color-primary);
    }

Primitive Tokens залишай для палітри, а семантичні токени використовуй у компонентах.

### Помилка 4. Змішування ролей

    --color-gray: #6b7280;

Що означає цей колір: текст, межу, фон чи неактивний елемент?

Рішення: створюй токени з конкретним призначенням.

    --color-text-secondary: #4b5563;
    --color-border-strong: #9ca3af;
    --color-background-muted: #f9fafb;

### Помилка 5. Темна тема без перевірки контрасту

Проблема: колір, який добре працює на білому фоні, може бути нечитабельним на темному.

Рішення: перевіряй кожну важливу комбінацію окремо.

### Помилка 6. Надмірна кількість токенів

Проблема: система стає складною, а розробник не знає, який токен вибрати.

Рішення: починай із мінімального набору. Додавай нові токени, коли для них з'являється реальна потреба.

### Помилка 7. Надто загальні назви

    --color-one: #2563eb;
    --color-two: #111827;

Проблема: назви не пояснюють ні колір, ні його призначення.

Рішення: використовуй послідовні імена для Primitive Tokens і Semantic Tokens.

### Помилка 8. Один токен для різних семантичних ролей

Наприклад, той самий `--color-primary` використовують для фону кнопки, тексту помилки та межі поля.

Проблема: зміна основного кольору може ненавмисно змінити всі ці елементи, хоча вони мають різні ролі.

Рішення: визначай окремі токени для різних призначень.

## 17. Практичний алгоритм створення Color Tokens

Коли починаєш новий проєкт, дій послідовно.

### Крок 1. Визнач основні ролі кольорів

Наприклад:

- основний колір бренду;
- колір основного тексту;
- колір допоміжного тексту;
- колір фону;
- колір поверхні карток;
- колір меж;
- кольори повідомлень про стан.

Не потрібно одразу створювати десятки токенів.

### Крок 2. Створи Primitive Tokens

Визнач конкретні кольори та необхідні відтінки.

    --blue-50
    --blue-600
    --blue-700
    --gray-50
    --gray-300
    --gray-600
    --gray-900

### Крок 3. Створи Semantic Tokens

Пов'яжи палітру з ролями інтерфейсу.

    --color-primary
    --color-text-primary
    --color-text-secondary
    --color-background
    --color-surface
    --color-border

### Крок 4. Використовуй токени в компонентах

Не записуй одні й ті самі HEX-коди повторно в кожному класі.

### Крок 5. Перевір стани

Перевір кнопки, посилання, поля форм, повідомлення про помилки, наведення та клавіатурний фокус.

### Крок 6. Перевір контрастність

Переконайся, що текст і важливі елементи достатньо помітні на своїх фонах.

### Крок 7. За потреби додай темну тему

Змінюй семантичні токени, зберігаючи ті самі назви в компонентах.

### Крок 8. Документуй правила

Поясни, для чого призначений кожен основний токен і де його потрібно використовувати.

Для початкового рівня достатньо впевнено розуміти такі речі:

✔ Що таке Color Tokens.

✔ Чим токен відрізняється від звичайного HEX-коду.

✔ Для чого потрібні Primitive Tokens.

✔ Для чого потрібні Semantic Tokens.

✔ Як оголосити CSS-змінну в `:root`.

✔ Як використовувати змінну через `var()`.

✔ Як створити назви для тексту, фону, меж і основного кольору.

✔ Як семантичні токени допомагають створювати світлу й темну теми.

На початку не потрібно будувати складну систему токенів для великого продукту. Важливіше навчитися створювати невелику, послідовну й зрозумілу систему.

## 20. Коротка шпаргалка

### Основні поняття

    Color Palette
    Набір кольорів і відтінків.

    Primitive Token
    Іменований токен конкретного кольору.

    Semantic Token
    Іменований токен, що описує роль кольору.

    Color Scale
    Впорядкована шкала відтінків одного кольору.

    Color Contrast
    Різниця між кольорами, важлива для читабельності.

### Приклад Primitive Tokens

    :root {
      --blue-50: #eff6ff;
      --blue-600: #2563eb;
      --blue-700: #1d4ed8;

      --gray-100: #f3f4f6;
      --gray-600: #4b5563;
      --gray-900: #111827;
    }

### Приклад Semantic Tokens

    :root {
      --color-primary: var(--blue-600);
      --color-primary-hover: var(--blue-700);

      --color-text-primary: var(--gray-900);
      --color-text-secondary: var(--gray-600);

      --color-background: #ffffff;
      --color-border: var(--gray-100);
    }

### Використання

    .button {
      background-color: var(--color-primary);
      color: #ffffff;
    }

    .button:hover {
      background-color: var(--color-primary-hover);
    }

    .card {
      background-color: var(--color-background);
      color: var(--color-text-primary);
      border: 1px solid var(--color-border);
    }

### Три головні правила

1. **Primitive Tokens описують конкретні кольори, Semantic Tokens — їхнє призначення.**
2. **Компоненти мають використовувати семантичні токени замість випадкових значень кольорів.**
3. **Кожну важливу комбінацію кольорів потрібно перевіряти на контрастність і доступність.**

## 21. Як ця тема пов'язана з іншими темами UI Design?

Color Tokens — частина дизайн-системи, а не ізольована техніка CSS.

    Color Theory
        ↓
    Color Palette
        ↓
    Color Tokens
        ↓
    Component States
        ↓
    Components
        ↓
    Design System

Зв'язок із попередніми темами:

- **Color Basics** — допомагає вибирати кольори та розуміти їхні властивості.
- **Color Accessibility** — допомагає перевіряти контраст і доступність.
- **Components** — використовують токени у кнопках, картках і формах.
- **Component States** — визначають кольори для hover, focus, active, disabled та інших станів.
- **Design Systems** — об'єднують колірні токени з типографікою, відступами, компонентами та правилами використання.
- **CSS Custom Properties** — дозволяють реалізувати токени в коді.
- **Responsive Design** — працює разом із токенами, хоча самі кольори зазвичай не залежать від ширини екрана.

## 22. Підсумок

**Color Tokens — це система іменованих кольорів, яка робить інтерфейс послідовним, керованим і зручним для підтримки.**

Найважливіше запам'ятати:

- Палітра визначає доступні кольори.
- Primitive Tokens зберігають конкретні значення кольорів.
- Semantic Tokens визначають роль кольорів в інтерфейсі.
- CSS Custom Properties дозволяють оголошувати та використовувати токени.
- Компоненти використовують семантичні токени, а не випадкові HEX-коди.
- Семантичні токени полегшують зміну бренду й підтримку кількох тем.
- Кольори мають бути доступними, достатньо контрастними та зрозумілими користувачеві.
- Хороша система токенів не обов'язково велика — вона передусім послідовна й відповідає потребам проєкту.

**Практична мета:** навчитися створювати невелику колірну систему, у якій можна змінити основні кольори інтерфейсу централізовано, не переписуючи стилі кожного компонента.
