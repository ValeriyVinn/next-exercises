# 04. Active — Стан активної взаємодії в UI

> **Active state** — це стан інтерфейсного елемента, який виникає під час його натискання або активації. Він дає користувачеві миттєвий візуальний зворотний зв'язок і показує, що взаємодія відбувається.
>
> У CSS стан `:active` зазвичай відповідає моменту, коли користувач натискає кнопку миші, торкається сенсорного екрана або активує елемент іншим способом.

---

## 1. Що таке Active State

**Active state** — це короткочасний стан компонента, який показує, що користувач зараз взаємодіє з ним або натискає на нього.

Наприклад:
- користувач натискає кнопку «Зберегти»;
- користувач натискає посилання;
- користувач торкається картки на сенсорному екрані;
- користувач натискає елемент навігації;
- користувач натискає кнопку збільшення або зменшення кількості товару.

Під час цієї взаємодії компонент може трохи змінити колір, фон, тінь або положення.

### Приклад

    Default:
    [ Зберегти ]

    Active:
    [ Зберегти ]  ← фон трохи темніший, кнопка ніби натиснута

Active state зазвичай триває недовго. Після завершення натискання компонент повертається до відповідного стану, наприклад `default`, `hover` або `focus`.

### Навіщо потрібен Active State

- ✔ Підтверджує, що інтерфейс реагує на натискання.
- ✔ Робить взаємодію більш зрозумілою.
- ✔ Допомагає створити відчуття фізичного натискання.
- ✔ Покращує зворотний зв'язок у кнопках і елементах керування.
- ✔ Допомагає користувачеві відрізняти звичайний стан від натискання.
- ✔ Робить інтерфейс більш послідовним і передбачуваним.

---

## 2. Основні поняття

### 2.1. Active

**Active** — стан, у якому елемент перебуває під час натискання або відповідної фази активації.

Для CSS-елементів `:active` зазвичай застосовується від моменту натискання до завершення взаємодії.

### 2.2. Press feedback

**Press feedback** — візуальна реакція на натискання.

Приклади:
- фон стає темнішим;
- кнопка трохи зменшується;
- тінь зменшується;
- рамка змінює колір;
- елемент зміщується на 1–2 пікселі;
- з'являється коротка анімація.

### 2.3. Interaction feedback

**Interaction feedback** — загальне поняття для зворотного зв'язку на дії користувача.

Це може бути:
- `hover` — наведення курсора;
- `focus` — фокус;
- `active` — натискання;
- `loading` — виконання операції;
- `success` — успішне завершення;
- `error` — помилка.

Не плутай короткочасний `active` із тривалим станом компонента після завершення дії.

### 2.4. Pressed state

**Pressed state** — стан, у якому компонент візуально виглядає натиснутим.

У дизайні цей термін часто використовують для опису вигляду компонента під час натискання.

У CSS для звичайної реакції на натискання часто використовують псевдоклас `:active`.

### 2.5. Toggle state

**Toggle state** — стан, який перемикається та зберігається після взаємодії.

Наприклад:
- увімкнено / вимкнено;
- обрано / не обрано;
- улюблене / не улюблене;
- відтворення / пауза.

Toggle state — це не те саме, що `:active`.

Коли користувач натискає кнопку перемикання теми, `:active` може діяти лише під час натискання, а темна тема залишається увімкненою після того, як користувач відпустив кнопку.

---

## 3. Active у системі станів компонента

Інтерактивний компонент може мати кілька різних станів.

Наприклад, кнопка:

    Default  — звичайний стан.
    Hover    — курсор наведений на кнопку.
    Focus    — кнопка перебуває у фокусі.
    Active   — кнопку зараз натискають.
    Disabled — кнопка недоступна.
    Loading  — виконується операція.
    Success  — операція завершилася успішно.

Кожен стан виконує окрему функцію.

| Стан | Що означає |
|---|---|
| Default | Звичайний вигляд компонента |
| Hover | Курсор знаходиться над елементом |
| Focus | Елемент перебуває у фокусі |
| Active | Відбувається натискання або відповідна фаза активації |
| Disabled | Компонент недоступний для взаємодії |
| Loading | Виконується операція |
| Success | Дія успішно завершилася |

Ці стани можуть частково поєднуватися.

Наприклад, кнопка може одночасно перебувати у фокусі та бути натиснутою.

**Головне правило:** `active` показує короткочасну взаємодію, а не обов'язково постійний результат дії.

---

## 4. Основні способи візуалізації Active

### 4.1. Зміна кольору фону

Найпростіший спосіб показати натискання — трохи змінити фон.

    .button {
      background-color: #2563eb;
      color: #ffffff;
    }

    .button:active {
      background-color: #1e40af;
    }

Під час натискання синій фон стає темнішим.

Переваги:
- легко реалізувати;
- не змінює геометрію компонента;
- добре працює для кнопок;
- легко узгоджується з hover state.

### 4.2. Зміна кольору рамки

    .button {
      border: 1px solid #2563eb;
    }

    .button:active {
      border-color: #1e3a8a;
    }

Це корисно для кнопок із контуром або компонентів, де зміна фону небажана.

Однак слабка зміна кольору може бути непомітною, тому варто перевіряти її в реальному інтерфейсі.

### 4.3. Зменшення тіні

Кнопка з тінню може візуально «опускатися» під час натискання.

    .button {
      box-shadow: 0 4px 0 #1e40af;
    }

    .button:active {
      box-shadow: 0 1px 0 #1e40af;
    }

Зменшення тіні створює відчуття, ніби кнопка наближається до поверхні.

### 4.4. Зміщення елемента

    .button:active {
      transform: translateY(1px);
    }

Невелике зміщення вниз може імітувати фізичне натискання.

Не використовуйте надто великі зміщення: вони можуть зробити інтерфейс нестабільним або створити відчуття, що елемент рухається без причини.

### 4.5. Масштабування

    .button:active {
      transform: scale(0.98);
    }

Незначне зменшення масштабу створює відчуття натискання.

Використовуйте цей ефект обережно. Надмірне зменшення може зробити текст менш читабельним, а компонент — візуально нестабільним.

### 4.6. Комбінування ефектів

Можна поєднувати зміну фону, тіні та положення.

    .button {
      background-color: #2563eb;
      color: #ffffff;
      box-shadow: 0 4px 0 #1e40af;
      transform: translateY(0);
    }

    .button:active {
      background-color: #1d4ed8;
      box-shadow: 0 1px 0 #1e40af;
      transform: translateY(2px);
    }

Комбінація повинна бути помірною. Важливо, щоб користувач відчував реакцію, а не бачив надмірну анімацію.

---

## 5. CSS-псевдоклас :active

`:active` — CSS-псевдоклас, який застосовується до елемента під час його активної фази взаємодії.

Приклад:

    button:active {
      background-color: #1e40af;
    }

Для типової кнопки миші стан зазвичай починається під час натискання і завершується після відпускання кнопки миші.

На сенсорних пристроях поведінка залежить від браузера та способу взаємодії.

### Важливо розуміти

`:active`:
- не означає, що елемент постійно увімкнений;
- не означає, що елемент обраний;
- не замінює стан `focus`;
- не повідомляє автоматично про завершення операції;
- не замінює логіку JavaScript, якщо потрібна зміна даних або стану застосунку.

CSS-псевдоклас відповідає за оформлення стану, а не за бізнес-логіку.

---

## 6. Active, Hover і Focus: у чому різниця

Ці стани часто використовують разом, але вони мають різне призначення.

### Hover

Виникає, коли вказівник знаходиться над елементом.

    .button:hover {
      background-color: #1d4ed8;
    }

### Focus

Показує, який елемент має фокус взаємодії.

    .button:focus-visible {
      outline: 3px solid #93c5fd;
      outline-offset: 3px;
    }

### Active

Показує момент натискання.

    .button:active {
      background-color: #1e40af;
      transform: translateY(1px);
    }

### Порівняння

| Властивість | Hover | Focus | Active |
|---|---|---|---|
| Основне призначення | Реакція на наведення | Показ поточного фокусу | Реакція на натискання |
| Типовий сценарій | Курсор над кнопкою | Навігація через `Tab` | Кнопку натискають |
| Тривалість | Поки вказівник над елементом | Поки елемент має фокус | Під час активної фази взаємодії |
| Потрібен для клавіатури | Не замінює клавіатурний стан | Так | Не замінює фокус |
| Приклад | Зміна фону | Контур навколо кнопки | Зменшення тіні |

**Висновок:** hover показує наведення, focus — положення фокусу, active — короткочасну реакцію на натискання.

---

## 7. Active для кнопок

Кнопки — найтиповіший приклад використання active state.

Приклад:

    .button {
      padding: 12px 18px;
      border: 1px solid #2563eb;
      border-radius: 8px;
      background-color: #2563eb;
      color: #ffffff;
      font: inherit;
      cursor: pointer;
      transition:
        background-color 120ms ease,
        transform 120ms ease;
    }

    .button:hover {
      background-color: #1d4ed8;
    }

    .button:focus-visible {
      outline: 3px solid #93c5fd;
      outline-offset: 3px;
    }

    .button:active {
      background-color: #1e40af;
      transform: translateY(1px);
    }

У цьому прикладі:
- `default` задає початковий вигляд;
- `hover` реагує на наведення;
- `focus-visible` показує видимий індикатор фокусу;
- `active` створює ефект натискання.

### Рекомендації

- ✔ Використовуй помірну зміну кольору.
- ✔ Не роби натискання надто різким.
- ✔ Зберігай читабельність тексту.
- ✔ Не прибирай індикатор фокусу.
- ✔ Перевіряй поведінку на сенсорних пристроях.
- ✔ Не покладайся лише на анімацію для підтвердження важливої дії.

---

## 8. Active для посилань

Посилання також можуть мати стан активного натискання.

    .nav-link {
      color: #1d4ed8;
      text-decoration: none;
    }

    .nav-link:hover {
      text-decoration: underline;
    }

    .nav-link:focus-visible {
      outline: 2px solid #2563eb;
      outline-offset: 4px;
    }

    .nav-link:active {
      color: #1e3a8a;
    }

Під час натискання текст посилання може ставати темнішим.

Не варто робити active state єдиною ознакою того, що посилання можна натиснути. Посилання має бути зрозумілим і без взаємодії.

---

## 9. Active для карток

Картки можуть реагувати на натискання, якщо вони є інтерактивними.

Наприклад, картка-посилання:

    .card-link {
      display: block;
      padding: 20px;
      border: 1px solid #d1d5db;
      border-radius: 12px;
      color: inherit;
      text-decoration: none;
      transition:
        border-color 120ms ease,
        transform 120ms ease;
    }

    .card-link:hover {
      border-color: #6b7280;
    }

    .card-link:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

    .card-link:active {
      transform: scale(0.99);
    }

### Коли використовувати

Active state для картки доречний, якщо:
- вся картка є посиланням;
- картка виконує дію;
- натискання є важливою частиною взаємодії;
- ефект не заважає читанню вмісту.

Не додавай активний ефект до звичайної інформаційної картки, якщо користувач не може з нею взаємодіяти.

---

## 10. Active для навігації

У навігації важливо розрізняти два поняття:

- **Pressed state** — короткочасний стан натискання.
- **Current page state** — стан посилання, яке відповідає поточній сторінці.

Це не одне й те саме.

Наприклад, користувач натискає посилання «Про нас». Під час натискання може спрацювати `:active`. Після переходу на сторінку «Про нас» відповідний пункт меню повинен позначатися як поточна сторінка.

Для поточної сторінки часто використовують атрибут `aria-current="page"`.

HTML:

    <nav aria-label="Основна навігація">
      <a href="/">Головна</a>
      <a href="/about" aria-current="page">Про нас</a>
      <a href="/contacts">Контакти</a>
    </nav>

CSS:

    nav a:active {
      color: #1e40af;
    }

    nav a[aria-current="page"] {
      font-weight: 700;
      text-decoration: underline;
    }

Тут:
- `:active` показує короткочасне натискання;
- `[aria-current="page"]` позначає посилання на поточну сторінку.

Не використовуй `:active` для постійного виділення активного розділу навігації.

---

## 11. Active для перемикачів і вибору

Не кожен елемент, який користувач натискає, повинен залишатися в active state після натискання.

Наприклад, кнопка «Улюблене» може перемикати стан:

    Не обрано → Обрано

Після натискання стан має залишатися обраним, а не зникати відразу після відпускання кнопки.

Це вже не лише `:active`, а стан даних компонента.

### Приклад перемикача

HTML:

    <button
      class="favorite-button"
      type="button"
      aria-pressed="false"
    >
      Додати до улюбленого
    </button>

CSS:

    .favorite-button:active {
      transform: scale(0.97);
    }

    .favorite-button[aria-pressed="true"] {
      background-color: #be123c;
      color: #ffffff;
    }

У цьому прикладі:
- `:active` відповідає за короткочасний ефект натискання;
- `aria-pressed="true"` позначає постійний стан увімкненої кнопки-перемикача.

Для повноцінної роботи атрибут `aria-pressed` потрібно оновлювати відповідно до реального стану компонента за допомогою JavaScript або фреймворку.

### Запам'ятай

`Active` не дорівнює `Selected`.

- `Active` — елемент натискають.
- `Selected` — елемент обраний.
- `Pressed` у перемикачі — стан, який може зберігатися після натискання.

---

## 12. Active для форм

Поля введення також можуть реагувати на натискання, але для них важливіші стани `focus`, `error` і `disabled`.

Наприклад, для кнопки відправлення форми можна створити active state:

    .submit-button {
      padding: 12px 18px;
      border: none;
      border-radius: 8px;
      background-color: #15803d;
      color: white;
      cursor: pointer;
    }

    .submit-button:hover {
      background-color: #166534;
    }

    .submit-button:focus-visible {
      outline: 3px solid #86efac;
      outline-offset: 3px;
    }

    .submit-button:active {
      background-color: #14532d;
    }

Важливо: зміна кольору під час натискання не означає, що форма успішно відправлена.

Якщо операція триває, потрібно показати `loading`. Якщо вона завершилася успішно, можна показати `success`. Якщо сталася помилка, потрібно показати `error`.

Це окремі стани, які залежать від результату операції.

---

## 13. Active на сенсорних пристроях

На мобільних пристроях користувач взаємодіє з інтерфейсом дотиком, а не звичайним наведенням миші.

Стан `:active` може використовуватися для миттєвого зворотного зв'язку під час дотику, але конкретна поведінка залежить від браузера та пристрою.

### Що врахувати

- Не покладайся лише на `hover`.
- Перевіряй, чи помітний active state під час дотику.
- Не роби ефект настільки коротким, що його неможливо побачити.
- Не використовуй великі переміщення елемента.
- Не зменшуй інтерактивну область під час натискання.
- Перевіряй поведінку на реальному сенсорному пристрої.

Active state — це зворотний зв'язок, а не заміна зручного розміру кнопки та правильного розташування елементів.

---

## 14. Active та доступність (Accessibility)

Візуальна реакція на натискання допомагає зрозуміти, що інтерфейс реагує на дію користувача.

Однак доступність не можна забезпечити лише active state.

### Основні принципи

- ✔ Використовуй семантичні HTML-елементи.
- ✔ Зберігай видимий індикатор фокусу.
- ✔ Забезпечуй достатній контраст тексту.
- ✔ Не передавай важливий стан лише через колір.
- ✔ Не роби активну анімацію надмірною.
- ✔ Переконайся, що компонент працює з клавіатури.
- ✔ Не використовуй CSS-ефект як єдине підтвердження успішної операції.

### Чому важливий Focus

Користувач клавіатури може активувати кнопку, не використовуючи мишу.

Тому компонент повинен мати:
- доступний фокус;
- зрозумілий індикатор `focus-visible`;
- очікувану поведінку клавіатури;
- коректний результат активації.

### Не прибирай outline

Невдалий приклад:

    button:focus {
      outline: none;
    }

Якщо індикатор фокусу прибрано без заміни, користувач може не бачити, який елемент зараз має фокус.

Краще:

    button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

---

## 15. Active та анімація

Анімація може зробити натискання більш природним.

Наприклад:

    .button {
      transition:
        transform 100ms ease,
        background-color 100ms ease;
    }

    .button:active {
      transform: scale(0.98);
      background-color: #1e40af;
    }

### Рекомендації

- Використовуй короткі переходи.
- Не роби анімацію надмірно повільною.
- Не додавай різкі стрибки розміру.
- Не переміщуй компонент на велику відстань.
- Не допускай, щоб анімація заважала натисканню.
- Зберігай видимий focus state незалежно від active animation.

### Зменшення руху

Якщо інтерфейс використовує помітні рухи, варто врахувати налаштування користувача `prefers-reduced-motion`.

    @media (prefers-reduced-motion: reduce) {
      .button {
        transition: none;
      }
    }

Це вимикає переходи для зазначеного компонента, коли користувач віддає перевагу зменшенню руху.

Для простого короткого ефекту зміни кольору анімація може взагалі не знадобитися.

## 16. Active та дизайн-система

У дизайн-системі active state повинен мати узгоджені правила для всіх компонентів.

Наприклад, можна визначити такі принципи:

    Button:
      Default — базовий вигляд
      Hover   — зміна фону
      Focus   — видимий контур
      Active  — темніший фон і легке зміщення

    Link:
      Default — звичайний вигляд
      Hover   — підкреслення
      Focus   — видимий контур
      Active  — зміна кольору

    Card:
      Default — базова поверхня
      Hover   — зміна рамки
      Focus   — видимий контур посилання
      Active  — легке зменшення масштабу

Це лише приклад. Не обов'язково використовувати однаковий ефект для кожного компонента.

### Що потрібно стандартизувати

- тривалість переходів;
- силу візуального ефекту;
- правила зміни кольору;
- використання `transform`;
- поведінку кнопок і посилань;
- правила focus state;
- відмінності між pressed та selected.

### Приклад CSS-токенів

    :root {
      --interaction-duration-fast: 100ms;
      --interaction-easing: ease;
      --button-active-bg: #1e40af;
      --button-active-offset: 1px;
    }

    .button {
      transition:
        background-color var(--interaction-duration-fast)
          var(--interaction-easing),
        transform var(--interaction-duration-fast)
          var(--interaction-easing);
    }

    .button:active {
      background-color: var(--button-active-bg);
      transform: translateY(var(--button-active-offset));
    }

Токени допомагають підтримувати послідовний стиль у всьому проєкті.

## 17. Active та CSS-специфічність

Псевдоклас `:active` може конфліктувати з іншими правилами, якщо селектори мають різну специфічність або властивості перевизначаються в неправильному порядку.

Приклад:

    .button {
      background-color: #2563eb;
    }

    .button:hover {
      background-color: #1d4ed8;
    }

    .button:active {
      background-color: #1e40af;
    }

Тут стани мають окремі стилі.

Якщо для `:active` не вказати потрібну властивість, може здаватися, що стан не працює, хоча насправді його перекриває інше правило або візуальна різниця занадто слабка.

### Що перевіряти

- Чи правильно написаний селектор?
- Чи не перекриває його інше CSS-правило?
- Чи достатньо помітна різниця між станами?
- Чи застосовується `transform` до потрібного елемента?
- Чи не скасовує інша властивість очікуваний ефект?

Не потрібно використовувати `!important` як перше рішення. Спочатку перевір порядок правил і специфічність селекторів.

## 18. Типові помилки

### Помилка 1. Вважати active постійним станом

`:active` зазвичай існує лише під час активної фази взаємодії.

Якщо потрібно, щоб кнопка залишалася обраною, використовуйте стан компонента, наприклад `aria-pressed`, а не покладайтеся на `:active`.

### Помилка 2. Використовувати лише hover

Якщо кнопка змінюється тільки при наведенні, користувач може не отримати достатнього зворотного зв'язку під час натискання.

Додайте окремий active state, якщо він покращує взаємодію.

### Помилка 3. Робити ефект занадто сильним

Надмірне масштабування або зміщення може виглядати як помилка верстки.

Краще використовувати невеликі зміни.

### Помилка 4. Забувати про focus

Active state не замінює focus state.

Користувач повинен бачити, який елемент має фокус, навіть якщо активна анімація не відбувається.

### Помилка 5. Плутати натискання з успішною дією

Зміна фону під час натискання не означає, що сервер зберіг дані або форма успішно відправлена.

Для результату операції використовуй окремі стани `loading`, `success` або `error`.

### Помилка 6. Додавати active до неінтерактивного елемента

Не варто стилізувати звичайний текст як кнопку, якщо він не виконує жодної дії.

Спочатку визнач, чи повинен елемент бути інтерактивним.

### Помилка 7. Змінювати розмір так, що рухаються сусідні елементи

Зміна `width`, `height`, `padding` або `margin` під час натискання може спричинити зміщення макета.

Для простого ефекту краще розглянути `transform`, колір або тінь.

### Помилка 8. Використовувати надмірну анімацію

Довгі або різкі переходи сповільнюють сприйняття взаємодії.

Active state має бути швидким і зрозумілим.

### Помилка 9. Забувати про сенсорні пристрої

Не припускай, що поведінка `:active` однакова в усіх браузерах і на всіх пристроях.

Перевіряй компонент у реальному середовищі.

## 19. Практичний приклад: кнопка з усіма основними станами

HTML:

    <button class="button" type="button">
      Зберегти зміни
    </button>

CSS:

    .button {
      padding: 12px 18px;
      border: 1px solid #2563eb;
      border-radius: 8px;
      background-color: #2563eb;
      color: #ffffff;
      font: inherit;
      cursor: pointer;
      transition:
        background-color 120ms ease,
        transform 120ms ease;
    }

    .button:hover {
      background-color: #1d4ed8;
    }

    .button:focus-visible {
      outline: 3px solid #93c5fd;
      outline-offset: 3px;
    }

    .button:active {
      background-color: #1e40af;
      transform: translateY(1px);
    }

### Як перевірити

1. Відкрий сторінку.
2. Наведи курсор на кнопку.
3. Перевір зміну фону.
4. Натисни кнопку та утримуй її.
5. Перевір active state.
6. Відпусти кнопку.
7. Натисни `Tab`, щоб перевірити focus state.
8. Переконайся, що active і focus візуально відрізняються.

**Завдання:** зміни активний фон, додай тінь і перевір, чи залишається індикатор фокусу помітним.

## 20. Практичний приклад: кнопка-перемикач

У цьому прикладі короткочасний ефект натискання поєднується зі станом, який зберігається.

HTML:

    <button
      class="favorite-button"
      type="button"
      aria-pressed="false"
    >
      Додати до улюбленого
    </button>

CSS:

    .favorite-button {
      padding: 10px 16px;
      border: 1px solid #be123c;
      border-radius: 8px;
      background-color: #ffffff;
      color: #be123c;
      cursor: pointer;
      transition:
        background-color 120ms ease,
        transform 100ms ease;
    }

    .favorite-button:active {
      transform: scale(0.97);
    }

    .favorite-button[aria-pressed="true"] {
      background-color: #be123c;
      color: #ffffff;
    }

    .favorite-button:focus-visible {
      outline: 3px solid #fda4af;
      outline-offset: 3px;
    }

Цей приклад демонструє стилі. Для реального перемикання потрібен JavaScript, який змінюватиме значення `aria-pressed` між `true` і `false`.

### Що тут важливо

- `:active` відповідає за короткочасне натискання.
- `[aria-pressed="true"]` відповідає за збережений стан перемикача.
- `:focus-visible` забезпечує індикатор фокусу.
- JavaScript змінює стан компонента, а CSS відображає його.

## 21. Як проєктувати Active у Figma

У Figma active state можна представити як окремий варіант інтерактивного компонента.

### Крок 1. Створи базовий компонент

Наприклад, кнопку:
- визнач розмір;
- задай колір фону;
- налаштуй типографіку;
- визнач радіус заокруглення;
- перевір контраст тексту.

### Крок 2. Створи варіант Active

Зміни один або кілька параметрів:
- фон;
- рамку;
- тінь;
- положення;
- масштаб.

Не потрібно змінювати всі властивості одночасно.

### Крок 3. Збережи відмінність між станами

Приклад структури:

    Button
    ├── State=Default
    ├── State=Hover
    ├── State=Focus
    ├── State=Active
    └── State=Disabled

### Крок 4. Перевір взаємодію

У прототипі перевір:
- чи зрозуміло, що кнопку можна натискати;
- чи не надмірний ефект;
- чи зберігається читабельність;
- чи узгоджується active state з іншими компонентами.

### Крок 5. Передай правила розробнику

Опиши:
- які властивості змінюються;
- наскільки змінюється колір;
- чи використовується `transform`;
- яка тривалість переходу;
- як active state співвідноситься з focus і hover.

Figma допомагає спроєктувати зовнішній вигляд, але реальну поведінку потрібно перевірити в браузері.

## 22. Чекліст Active State

### Візуальний дизайн

- [ ] Натискання має помітний зворотний зв'язок.
- [ ] Ефект не є надмірним.
- [ ] Текст залишається читабельним.

- [ ] Focus state працює незалежно від active state.

- [ ] Компонент доступний для клавіатурної взаємодії.

## 25. Мінішпаргалка

### Основні CSS-правила

    /* Hover — наведення */
    .button:hover {
      background-color: #1d4ed8;
    }

    /* Focus — фокус клавіатурної навігації */
    .button:focus-visible {
      outline: 3px solid #93c5fd;
      outline-offset: 3px;
    }

    /* Active — натискання */
    .button:active {
      background-color: #1e40af;
      transform: translateY(1px);
    }

### Основні поняття

    Default       — звичайний стан.
    Hover         — наведення курсора.
    Focus         — елемент має фокус.
    Active        — короткочасний стан натискання.
    Pressed       — візуальний стан натиснутого елемента.
    Selected      — елемент обраний.
    Toggle        — стан перемикається і зберігається.
    Loading       — операція виконується.
    Success       — операція завершилася успішно.
    Error         — під час операції виникла помилка.

### Що запам'ятати

- `:active` показує короткочасну фазу взаємодії.
- Active не дорівнює selected.
- Active не замінює focus.
- Не використовуй active state як підтвердження успішної операції.
- Уникай надмірного масштабування та зміщення.
- Зберігай помітний індикатор фокусу.
- Перевіряй поведінку на сенсорних пристроях.
- Стандартизуй інтерактивні стани у дизайн-системі.

## 26. Головний висновок

**Active state — це короткий, але важливий сигнал, який підтверджує взаємодію користувача з інтерфейсом.**

Якісний active state повинен:
- швидко реагувати на натискання;
- бути помітним, але не надмірним;
- не порушувати геометрію макета;
- відрізнятися від hover і focus;
- не плутатися з постійним станом selected;
- працювати узгоджено на різних пристроях.

Починай із простого: додай до кнопки зміну фону або невелике зміщення через `:active`. Потім перевір поєднання з `:hover` і `:focus-visible`, а для перемикачів окремо реалізуй постійний стан компонента.

Так active state стає не просто ефектом натискання, а частиною послідовного та зрозумілого користувацького досвіду.
