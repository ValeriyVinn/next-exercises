# 03. Focus — Стани фокусу в UI

> **Focus** — це стан інтерфейсного елемента, який показує, що елемент зараз перебуває у фокусі та може отримувати введення або взаємодію з клавіатури чи інших пристроїв введення.
>
> У UI-дизайні стан `focus` допомагає користувачеві зрозуміти, де саме він перебуває під час навігації інтерфейсом, і який елемент буде активовано наступним.

---

## 1. Що таке Focus State

**Focus state** — це візуальний стан компонента, який виникає, коли компонент отримує фокус.

Наприклад:
- користувач натискає `Tab` і переходить до наступного посилання;
- користувач натискає `Tab` і фокус переходить на кнопку;
- користувач клацає поле введення;
- користувач переходить між полями форми за допомогою клавіатури.

У цей момент інтерфейс повинен візуально показати, який елемент перебуває у фокусі.

### Приклад

    Кнопка без фокусу:
    [ Зберегти ]

    Кнопка у фокусі:
    [ Зберегти ]  ← помітна рамка навколо кнопки

Фокус не обов'язково змінює сам компонент. Найчастіше змінюється його зовнішній вигляд: з'являється контур, рамка, підсвічування або інший візуальний індикатор.

### Навіщо потрібен Focus

- ✔ Показує поточне положення користувача в інтерфейсі.
- ✔ Допомагає користувачам, які працюють без миші.
- ✔ Полегшує навігацію за допомогою клавіатури.
- ✔ Покращує доступність інтерфейсу.
- ✔ Допомагає визначити, яке поле форми зараз готове до введення.
- ✔ Зменшує невизначеність під час роботи з великою кількістю інтерактивних елементів.

---

## 2. Основні поняття

### 2.1. Focus

**Focus** — стан, у якому елемент отримав фокус введення або взаємодії.

Приклади:
- текстове поле, у яке можна вводити текст;
- кнопка, на якій зупинилася клавіатурна навігація;
- посилання, на яке перейшли за допомогою `Tab`;
- елемент керування у формі.

### 2.2. Focus indicator

**Focus indicator** — видимий індикатор, який показує, що елемент перебуває у фокусі.

Найчастіше це:
- контур навколо елемента;
- зміна кольору рамки;
- зовнішнє кільце;
- зміна фону;
- підсвічування;
- поєднання декількох візуальних ознак.

Індикатор має бути достатньо помітним і не повинен залежати лише від незначної зміни кольору.

### 2.3. Keyboard navigation

**Keyboard navigation** — навігація інтерфейсом за допомогою клавіатури.

Основні клавіші:
- `Tab` — перейти до наступного доступного інтерактивного елемента.
- `Shift + Tab` — перейти до попереднього елемента.
- `Enter` — активувати посилання або кнопку в типових сценаріях.
- `Space` — активувати кнопку або змінити стан деяких елементів керування.
- Стрілки — переміщатися всередині певних компонентів, наприклад списків вибору чи вкладок, якщо це передбачено їхньою поведінкою.

Точна поведінка залежить від типу компонента та реалізації інтерфейсу.

### 2.4. Focusable element

**Focusable element** — елемент, який може отримати фокус.

Наприклад:
- `<button>`;
- `<a href="...">`;
- `<input>`;
- `<textarea>`;
- `<select>`.

Не кожен HTML-елемент автоматично доступний для клавіатурної навігації. Для спеціальних компонентів іноді потрібно правильно налаштовувати HTML-структуру та атрибути доступності.

### 2.5. Focus vs. Focus indicator

Ці поняття пов'язані, але не тотожні.

- `Focus` — фактичний стан елемента.
- `Focus indicator` — візуальний спосіб показати цей стан.

Елемент може мати фокус, але якщо індикатор непомітний або відсутній, користувачеві буде важко зрозуміти, де він перебуває.

---

## 3. Focus у системі станів компонента

Інтерактивний компонент може мати декілька різних станів.

Наприклад, кнопка:

    Default  — звичайний стан.
    Hover    — курсор миші знаходиться над кнопкою.
    Focus    — кнопка перебуває у фокусі.
    Active   — кнопку натискають.
    Disabled — кнопка недоступна.

Ці стани можуть частково поєднуватися.

Наприклад, кнопка може одночасно мати фокус і перебувати під курсором миші.

Важливо не плутати їх:

| Стан | Що означає |
|---|---|
| Default | Елемент не перебуває в особливому інтерактивному стані |
| Hover | Курсор наведений на елемент |
| Focus | Елемент отримав фокус |
| Active | Елемент перебуває в стані натискання або активації |
| Disabled | Елемент тимчасово недоступний для взаємодії |

**Головне правило:** фокус не повинен бути лише копією hover. Він має залишатися зрозумілим навіть тоді, коли користувач не використовує мишу.

---

## 4. Основні способи візуалізації Focus

### 4.1. Outline — контур

Один із найпоширеніших способів показати фокус.

    button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

Переваги:
- добре помітний;
- не потребує зміни розмірів елемента;
- зазвичай не впливає на розташування сусідніх компонентів;
- легко налаштовується.

`outline-offset` визначає відстань між елементом і контуром.

### 4.2. Border — рамка

Можна змінювати колір рамки поля введення.

    input:focus-visible {
      border-color: #2563eb;
    }

Цей підхід часто використовують у формах.

Однак зміна лише кольору рамки може бути недостатньою, якщо різниця між кольорами слабка.

### 4.3. Box shadow — зовнішнє підсвічування

Зовнішнє кільце можна створити за допомогою `box-shadow`.

    .button:focus-visible {
      outline: none;
      box-shadow: 0 0 0 3px #93c5fd;
    }

Такий ефект часто використовується в сучасних інтерфейсах.

Потрібно перевіряти, чи залишається кільце помітним на різних фонах і чи не обрізається контейнером із `overflow: hidden`.

### 4.4. Зміна фону

Фон також може допомогти візуально виділити елемент.

    .menu-link:focus-visible {
      background-color: #e0e7ff;
    }

Зміну фону краще поєднувати з контуром, підкресленням або іншою чіткою ознакою.

### 4.5. Поєднання кількох ознак

Для важливих компонентів можна поєднувати декілька способів.

    .button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
      background-color: #eff6ff;
    }

Не потрібно робити індикатор надмірно декоративним. Його головне завдання — бути помітним і зрозумілим.

---

## 5. CSS: псевдокласи :focus та :focus-visible

CSS має декілька псевдокласів для роботи зі станом фокусу.

### 5.1. `:focus`

`:focus` застосовується до елемента, який перебуває у фокусі.

    input:focus {
      border-color: #2563eb;
    }

Це означає, що стиль застосовується, поки поле має фокус.

` :focus` без пробілу перед двокрапкою — правильний запис псевдокласу. У CSS слід писати саме `input:focus`.

### 5.2. `:focus-visible`

`:focus-visible` показує стилі фокусу тоді, коли браузер визначає, що візуальний індикатор фокусу потрібен відповідно до способу взаємодії.

Цей псевдоклас особливо корисний для клавіатурної навігації.

    button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

Типовий сценарій:
1. Користувач натискає `Tab`.
2. Фокус переходить на кнопку.
3. Браузер показує індикатор фокусу.

Це дозволяє зберегти помітний індикатор для клавіатурних користувачів і водночас уникати його автоматичного показу в деяких сценаріях взаємодії мишею.

Важливо: `:focus-visible` не означає «тільки клавіатура» за будь-яких обставин. Остаточне рішення залежить від евристик браузера та контексту взаємодії.

### 5.3. `:focus-within`

`:focus-within` застосовується до елемента, якщо сам він або будь-який його нащадок перебуває у фокусі.

Наприклад, можна виділити всю групу форми, коли користувач працює з одним із її полів.

    .form-group:focus-within {
      border-color: #2563eb;
      background-color: #f8fafc;
    }

HTML:

    <div class="form-group">
      <label for="email">Електронна пошта</label>
      <input id="email" type="email">
    </div>

Коли поле `input` отримує фокус, стилі `:focus-within` застосовуються до контейнера `.form-group`.

### Коротке порівняння

| Псевдоклас | Призначення |
|---|---|
| `:focus` | Елемент перебуває у фокусі |
| `:focus-visible` | Фокус із візуальним індикатором за правилами браузера |
| `:focus-within` | Елемент або один із його нащадків має фокус |

## 6. Коли використовувати :focus і :focus-visible

У багатьох сучасних інтерфейсах `:focus-visible` є зручним вибором для візуального індикатора.

Наприклад:

    button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

Проте `:focus` залишається корисним, коли потрібно змінити поведінку або оформлення елемента при будь-якому отриманні фокусу.

Наприклад:

    input:focus {
      border-color: #2563eb;
    }

    input:focus-visible {
      outline: 2px solid #93c5fd;
      outline-offset: 2px;
    }

У цьому прикладі:
- `:focus` змінює рамку поля;
- `:focus-visible` додає помітний індикатор, коли браузер визначає його необхідність.

Не видаляйте стандартний контур фокусу без заміни на доступний і помітний індикатор.

Невдалий приклад:

    button:focus {
      outline: none;
    }

Якщо після цього не з'являється інший індикатор, користувач може втратити можливість бачити поточний фокус.

---

## 7. Focus для кнопок

Кнопки — одні з найважливіших інтерактивних компонентів.

Для кнопки фокус має бути помітним, але не повинен заважати читанню тексту чи перекривати інші елементи.

Приклад:

    .button {
      padding: 10px 16px;
      border: 1px solid #2563eb;
      border-radius: 8px;
      background-color: #2563eb;
      color: white;
      cursor: pointer;
    }

    .button:hover {
      background-color: #1d4ed8;
    }

    .button:focus-visible {
      outline: 3px solid #93c5fd;
      outline-offset: 3px;
    }

Тут кожен стан має окреме призначення:
- звичайний стан задає базовий вигляд;
- `:hover` реагує на наведення курсора;
- `:focus-visible` допомагає відстежувати клавіатурний фокус.

Не потрібно покладатися лише на зміну кольору кнопки. Контур або кільце робить фокус помітнішим.

---

## 8. Focus для посилань

Посилання мають бути доступними для клавіатурної навігації та мати чіткий фокус.

    .nav-link {
      color: #1d4ed8;
      text-decoration: none;
    }

    .nav-link:hover {
      text-decoration: underline;
    }

    .nav-link:focus-visible {
      outline: 2px solid #2563eb;
      outline-offset: 4px;
      border-radius: 2px;
    }

Під час проєктування посилань важливо:
- зберігати достатній контраст тексту;
- не прибирати індикатор фокусу без заміни;
- не плутати hover із focus;
- забезпечити видимість індикатора на різних фонах.

Для звичайних посилань варто зберігати впізнавану візуальну ознаку, наприклад підкреслення, особливо якщо контекст не очевидний.

---

## 9. Focus у формах

Форми — одна з найважливіших областей застосування focus state.

Користувач повинен розуміти:
- яке поле зараз активне;
- куди вводиться текст;
- яке поле вибране;
- чи може він перейти до наступного поля.

Приклад:

    .form-input {
      width: 100%;
      padding: 10px 12px;
      border: 1px solid #9ca3af;
      border-radius: 6px;
      background-color: white;
      color: #111827;
    }

    .form-input:focus {
      border-color: #2563eb;
    }

    .form-input:focus-visible {
      outline: 2px solid #93c5fd;
      outline-offset: 2px;
    }

HTML:

    <label for="username">Ім'я користувача</label>
    <input
      class="form-input"
      id="username"
      name="username"
      type="text"
    >

### Рекомендації для полів форми

- ✔ Зробіть рамку або індикатор фокусу помітним.
- ✔ Не прибирайте стандартний outline без доступної альтернативи.
- ✔ Зберігайте достатній контраст.
- ✔ Не використовуйте лише зміну кольору як єдину ознаку для важливих станів.
- ✔ Залишайте зрозумілі підписи полів.
- ✔ Перевіряйте, чи не обрізається зовнішнє кільце фокусу.
- ✔ Не переміщуйте поле різко під час отримання фокусу.

### Focus і placeholder

`placeholder` не замінює підпис поля.

Невдалий підхід:

    <input type="email" placeholder="Електронна пошта">

Краще:

    <label for="email">Електронна пошта</label>
    <input id="email" name="email" type="email"
      placeholder="name@example.com">

Підпис залишається доступним навіть тоді, коли користувач починає вводити текст.

---

## 10. Focus і навігація за допомогою клавіатури

Інтерфейс не повинен вимагати використання миші для доступу до основних функцій.

### Як перевірити клавіатурну навігацію

1. Перезавантажте сторінку.
2. Не використовуйте мишу.
3. Натисніть `Tab`.
4. Перевірте, чи переходить фокус до першого інтерактивного елемента.
5. Продовжуйте натискати `Tab`.
6. Перевірте, чи індикатор фокусу видно на кожному елементі.
7. Використайте `Shift + Tab`, щоб перейти назад.
8. Спробуйте активувати кнопки та посилання за допомогою клавіатури.

### Що потрібно перевірити

- Чи всі важливі інтерактивні елементи доступні через клавіатуру?
- Чи не пропускає фокус потрібні елементи?
- Чи не зникає індикатор на темному або кольоровому фоні?
- Чи логічний порядок переходу?
- Чи можна закрити діалогове вікно клавіатурою, якщо це передбачено його поведінкою?
- Чи повертається фокус до логічного місця після закриття модального вікна?

Порядок фокусу зазвичай має відповідати логічному порядку читання та взаємодії зі сторінкою.

---

## 11. Focus у картках, меню та складних компонентах

Focus важливий не лише для кнопок і полів.

Його потрібно передбачати для:
- навігаційних меню;
- карток із посиланнями;
- вкладок;
- випадаючих списків;
- модальних вікон;
- компонентів пошуку;
- пагінації;
- перемикачів і чекбоксів.

### Картка з посиланням

Якщо вся картка є посиланням, потрібно зробити її фокус зрозумілим.

    .card-link {
      display: block;
      padding: 20px;
      border: 1px solid #d1d5db;
      border-radius: 12px;
      color: inherit;
      text-decoration: none;
    }

    .card-link:hover {
      border-color: #6b7280;
    }

    .card-link:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

HTML:

    <a class="card-link" href="/courses">
      <h2>Курси</h2>
      <p>Перегляньте доступні навчальні матеріали.</p>
    </a>

Якщо вся картка є одним посиланням, не потрібно вкладати в нього інші інтерактивні елементи, наприклад окремі кнопки.

### Вкладки

Для компонента вкладок важливо визначити не тільки зовнішній вигляд фокусу, а й правила клавіатурної взаємодії.

У поширеній реалізації вкладок:
- `Tab` переходить до компонента вкладок;
- стрілки переміщують активний фокус між вкладками;
- `Enter` або `Space` можуть активувати вкладку залежно від моделі взаємодії.

Таку поведінку потрібно реалізувати відповідно до вибраного шаблону доступності. Самого CSS недостатньо для створення повноцінного компонента вкладок.

---

## 12. Focus і доступність (Accessibility)

Доступність означає, що інтерфейсом можуть користуватися люди з різними можливостями та способами взаємодії.

Focus є важливою частиною доступності, оскільки допомагає орієнтуватися в інтерфейсі без миші.

### Основні принципи

- ✔ Фокус повинен бути видимим.
- ✔ Індикатор повинен мати достатній контраст.
- ✔ Фокус не повинен повністю перекриватися іншими елементами.
- ✔ Порядок фокусу має бути логічним.
- ✔ Інтерактивні елементи повинні мати зрозуміле призначення.
- ✔ Важливу інформацію не можна передавати лише через зміну кольору.
- ✔ Модальні вікна та інші складні компоненти повинні правильно керувати фокусом.
- ✔ Стан фокусу не повинен бути єдиним способом повідомити про помилку або успішну дію.

### Контраст індикатора

Індикатор фокусу повинен чітко відрізнятися від сусідніх кольорів.

Наприклад, світло-блакитне кільце на білому тлі може бути недостатньо помітним.

Вибираючи кольори, перевіряйте:
- контраст між індикатором і фоном;
- контраст між індикатором і самим компонентом;
- видимість на світлих і темних поверхнях;
- видимість поруч із сусідніми елементами.

Для відповідності вимогам доступності WCAG 2.2 варто перевіряти критерій 2.4.7 Focus Visible (рівень AA), а для посиленого рівня — 2.4.13 Focus Appearance (рівень AAA). Критерій 2.4.11 Focus Not Obscured (Minimum) на рівні AA стосується того, щоб сфокусований компонент не був повністю прихований авторським вмістом. Точна відповідність залежить від реалізації та конкретного критерію.

---

## 13. Focus у світлій і темній темах

Індикатор фокусу повинен залишатися видимим незалежно від теми інтерфейсу.

### Світла тема

На світлому фоні можна використовувати темніший або насичений контур.

    .button:focus-visible {
      outline: 3px solid #1d4ed8;
      outline-offset: 3px;
    }

### Темна тема

На темному фоні часто потрібен світліший контур.

    .button:focus-visible {
      outline: 3px solid #93c5fd;
      outline-offset: 3px;
    }

Це лише приклади. Остаточний колір потрібно перевіряти в контексті всієї палітри.

### Рекомендації

- Не використовуйте один колір фокусу автоматично для всіх фонів.
- Перевіряйте кнопки на кольорових поверхнях.
- Переконайтеся, що кільце видно поруч із рамкою компонента.
- Не дозволяйте індикатору губитися на фотографіях або складних фонах.
- Використовуйте дизайн-токени для узгодженості між компонентами.

## 14. Focus і дизайн-система

У дизайн-системі стан фокусу варто визначити як спільне правило, а не вигадувати окремо для кожного компонента.

Наприклад, можна задати CSS-змінні:

    :root {
      --focus-color: #2563eb;
      --focus-width: 3px;
      --focus-offset: 3px;
    }

    :focus-visible {
      outline: var(--focus-width) solid var(--focus-color);
      outline-offset: var(--focus-offset);
    }

Це базовий варіант. У реальному проєкті деякі компоненти можуть потребувати окремих налаштувань, наприклад через темний фон, невеликий розмір або обмеження контейнера.

### Навіщо потрібні дизайн-токени

- ✔ Єдиний стиль фокусу в усьому продукті.
- ✔ Легше змінювати колір і товщину індикатора.
- ✔ Менше дублювання CSS.
- ✔ Простіше підтримувати світлу та темну теми.
- ✔ Легше перевіряти доступність.
- ✔ Компоненти поводяться передбачувано.

### Приклад структури токенів

    :root {
      --focus-ring-color: #2563eb;
      --focus-ring-width: 3px;
      --focus-ring-offset: 3px;
      --focus-ring-radius: 4px;
    }

    .interactive:focus-visible {
      outline: var(--focus-ring-width) solid var(--focus-ring-color);
      outline-offset: var(--focus-ring-offset);
      border-radius: var(--focus-ring-radius);
    }

Зверніть увагу: `border-radius` впливає на форму рамки самого елемента, а не завжди точно визначає форму `outline`. Якщо потрібне точне оформлення кільця, може знадобитися інший спосіб стилізації.

## 15. Focus і анімація

Фокус можна підкреслювати плавними візуальними змінами, але анімація не повинна заважати швидко визначити поточний елемент.

Приклад:

    .button {
      transition:
        background-color 150ms ease,
        box-shadow 150ms ease;
    }

    .button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

### Рекомендації

- Не затримуйте появу індикатора фокусу настільки, щоб він став непомітним під час швидкої навігації.
- Уникайте різких рухів і великих трансформацій.
- Не використовуйте миготіння, яке відволікає користувача.
- Не робіть анімацію єдиною ознакою фокусу.
- За можливості враховуйте системне налаштування зменшення руху.

Приклад:

    @media (prefers-reduced-motion: reduce) {
      .button {
        transition: none;
      }
    }

Цей медіазапит вимикає переходи в зазначеного компонента, коли користувач віддає перевагу зменшенню руху. За потреби його можна застосувати до інших анімованих елементів.

## 16. Focus і мобільні пристрої

На сенсорних пристроях немає звичного постійного наведення курсора миші, але фокус усе одно важливий.

Він може виникати:
- коли користувач торкається поля введення;
- коли відкривається клавіатура;
- під час використання зовнішньої клавіатури;
- під час роботи допоміжних технологій;
- під час навігації іншими способами введення.

### Що врахувати

- Не покладайтеся лише на hover.
- Перевіряйте вигляд полів після отримання фокусу.
- Переконайтеся, що клавіатура не перекриває важливі елементи форми.
- Зберігайте достатній простір навколо інтерактивних компонентів.
- Перевіряйте інтерфейс із зовнішньою клавіатурою, якщо це важливо для продукту.

Фокус і hover — різні стани, навіть якщо на певному пристрої вони проявляються по-різному.

## 17. Focus і HTML-семантика

Правильна HTML-структура допомагає браузеру забезпечувати очікувану клавіатурну поведінку.

### Використовуйте правильні елементи

Для дії:

    <button type="button">Відкрити меню</button>

Для переходу на іншу сторінку:

    <a href="/about">Про нас</a>

Для введення даних:

    <input type="text" name="username">

Не потрібно використовувати звичайний `div` замість кнопки, якщо елемент виконує дію.

### Чому не варто робити все через tabindex

`tabindex` дозволяє керувати фокусом, але його неправильне використання може порушити порядок навігації.

Приклад звичайного доступного елемента:

    <button type="button">Зберегти</button>

Приклад елемента, якому штучно додали можливість отримувати фокус:

    <div tabindex="0">Звичайний текст</div>

Другий варіант не робить елемент кнопкою. Він лише дозволяє йому отримувати фокус, але не додає автоматично очікуваної поведінки кнопки.

Значення `tabindex="0"` включає елемент у звичайний порядок клавіатурної навігації. Позитивні значення `tabindex`, наприклад `tabindex="1"`, зазвичай варто уникати, оскільки вони можуть створити неприродний порядок переходів.

## 18. Focus у модальних вікнах

Модальне вікно — складніший випадок, оскільки потрібно керувати не лише зовнішнім виглядом фокусу, а й переміщенням фокусу.

Коли модальне вікно відкривається:
1. Фокус має перейти в логічне місце всередині вікна.
2. Користувач повинен мати змогу працювати з елементами діалогу.
3. Для модального діалогу фокус зазвичай утримується всередині нього, доки він відкритий.
4. Після закриття фокус зазвичай повертається до елемента, який відкрив діалог.

Сам CSS не забезпечує цієї поведінки. Потрібні правильна HTML-семантика та JavaScript або відповідний компонентний механізм.

### Що перевірити

- Чи видно індикатор фокусу всередині діалогу?
- Чи не переходить фокус на фон, який має бути недоступним під час модального режиму?
- Чи можна закрити діалог передбаченим способом?
- Чи повертається фокус до логічного місця після закриття?

## 19. Типові помилки

### Помилка 1. Повністю прибирати outline

Невдалий приклад:

    button:focus {
      outline: none;
    }

Проблема: користувач клавіатури може не бачити, який елемент має фокус.

Краще:

    button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

### Помилка 2. Використовувати лише слабку зміну кольору

Якщо колір рамки змінюється дуже незначно, стан може бути непомітним.

Краще додати чіткий контур, кільце або іншу візуальну ознаку.

### Помилка 3. Робити hover, але забувати про focus

Невдалий приклад:

    .button:hover {
      background-color: #1d4ed8;
    }

Цей стиль не визначає окремого індикатора фокусу.

Краще:

    .button:hover {
      background-color: #1d4ed8;
    }

    .button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

### Помилка 4. Використовувати `div` замість кнопки

Якщо елемент виконує дію, краще використовувати семантичний `<button>`, а не звичайний контейнер.

Це забезпечує очікувану поведінку з клавіатурою та допоміжними технологіями.

### Помилка 5. Не перевіряти темну тему

Індикатор, який добре видно на білому фоні, може зникнути на темному.

Перевіряйте всі основні теми та кольорові поверхні.

### Помилка 6. Обрізати індикатор

Контур або кільце може бути обрізане контейнером із `overflow: hidden`.

Перевіряйте розташування компонента та його батьківських контейнерів. За потреби змініть відступи або спосіб оформлення фокусу.

### Помилка 7. Плутати focus з active

Фокус означає, що елемент перебуває у фокусі. `Active` зазвичай описує стан натискання або активації.

Ці стани можуть виникати одночасно, але мають різне значення.

### Помилка 8. Створювати нестандартний порядок навігації без потреби

Позитивні значення `tabindex` можуть ускладнювати навігацію. Зазвичай краще використовувати логічний порядок HTML-елементів.

### Помилка 9. Вважати, що CSS вирішує всю доступність

CSS може показати фокус, але не забезпечує автоматично:
- правильну семантику;
- логічний порядок навігації;
- керування фокусом у діалогах;
- клавіатурну поведінку складних компонентів;
- повідомлення про помилки.

Доступність — це поєднання семантичного HTML, CSS і поведінки JavaScript.

## 20. Практичний приклад: компонент із кількома станами

Нижче наведено просту кнопку з базовим станом, hover, focus і active.

HTML:

    <button class="button" type="button">
      Зберегти зміни
    </button>

CSS:

    .button {
      padding: 12px 18px;
      border: 1px solid #2563eb;
      border-radius: 8px;
      background-color: #2563eb;
      color: #ffffff;
      font: inherit;
      cursor: pointer;
      transition: background-color 150ms ease;
    }

    .button:hover {
      background-color: #1d4ed8;
    }

    .button:focus-visible {
      outline: 3px solid #93c5fd;
      outline-offset: 3px;
    }

    .button:active {
      background-color: #1e40af;
    }

### Як перевірити

1. Відкрийте сторінку.
2. Наведіть курсор на кнопку.
3. Перевірте стан `hover`.
4. Натисніть `Tab`, щоб перевести фокус на кнопку.
5. Переконайтеся, що індикатор фокусу помітний.
6. Утримуйте кнопку миші під час натискання та перевірте стан `active`.
7. Перевірте кнопку на різних фонах.

**Завдання:** змініть колір і товщину індикатора, не втрачаючи його видимості.

## 21. Практичний приклад: форма з фокусом

HTML:

    <form class="contact-form">
      <div class="form-group">
        <label for="name">Ваше ім'я</label>
        <input
          id="name"
          name="name"
          type="text"
          autocomplete="name"
        >
      </div>

      <div class="form-group">
        <label for="email">Електронна пошта</label>
        <input
          id="email"
          name="email"
          type="email"
          autocomplete="email"
        >
      </div>

      <button type="submit">Надіслати</button>
    </form>

CSS:

    .contact-form {
      display: grid;
      gap: 20px;
      max-width: 420px;
    }

    .form-group {
      display: grid;
      gap: 6px;
      padding: 8px;
      border: 1px solid transparent;
      border-radius: 8px;
    }

    .form-group:focus-within {
      border-color: #93c5fd;
      background-color: #f8fafc;
    }

    .form-group input {
      padding: 10px 12px;
      border: 1px solid #9ca3af;
      border-radius: 6px;
      font: inherit;
    }

    .form-group input:focus-visible,
    .contact-form button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

### Що демонструє приклад

- `:focus-within` підсвічує групу, коли фокус знаходиться всередині неї.
- `:focus-visible` створює індикатор для відповідних сценаріїв фокусу.
- `<label>` пов'язаний із полем через `for` та `id`.
- Фокус можна оформлювати як на самому полі, так і на контейнері.

У цьому прикладі контейнер не замінює індикатор на полі — використовуються обидва способи візуального зворотного зв'язку.

## 22. Як проєктувати Focus у Figma

Якщо ти створюєш UI-макет у Figma, стан фокусу варто передбачати на етапі дизайну компонента.

### Крок 1. Створи базовий компонент

Наприклад, кнопку:
- визнач ширину та висоту;
- налаштуй текст;
- задай фон і рамку;
- визнач радіус заокруглення.

### Крок 2. Створи варіант Focus

Зроби окремий варіант компонента, у якому:
- додано контур або кільце;
- збережено розміри кнопки;
- текст залишається читабельним;
- індикатор не перекриває сусідні елементи.

### Крок 3. Визнач стани компонента

Наприклад:

    Button
    ├── State=Default
    ├── State=Hover
    ├── State=Focus
    ├── State=Active
    └── State=Disabled

Це приклад структури варіантів. У реальному компоненті назви властивостей можуть відрізнятися.

### Крок 4. Перевір контраст

Переконайся, що індикатор:
- помітний на світлому фоні;
- помітний на темному фоні;
- не зливається з рамкою компонента;
- не обрізається сусідніми контейнерами.

### Крок 5. Передай правила розробнику

У специфікації компонента вкажи:
- товщину контуру;
- колір індикатора;
- відстань до елемента;
- поведінку для клавіатурного фокусу;
- відмінності для світлої та темної тем.

Figma допомагає спроєктувати візуальний стан, але реальну клавіатурну поведінку потрібно реалізувати та перевірити в коді.

## 23. Чекліст Focus State

Перед завершенням компонента перевір:

### Візуальний дизайн

- [ ] Фокус має помітний індикатор.
- [ ] Індикатор не залежить лише від слабкої зміни кольору.
- [ ] Контур не обрізається контейнером.
- [ ] Текст та іконки залишаються читабельними.
- [ ] Фокус добре видно на різних фонах.
- [ ] Стиль узгоджений з іншими компонентами.

### Поведінка

- [ ] Елемент доступний через клавіатуру, якщо він має бути інтерактивним.
- [ ] `Tab` переводить фокус у логічному порядку.
- [ ] `Shift + Tab` дозволяє рухатися назад.
- [ ] Кнопки та посилання працюють очікуваним способом.
- [ ] Фокус не губиться у складних компонентах.
- [ ] Після закриття діалогу фокус повертається до логічного місця.

### Доступність

- [ ] Індикатор достатньо помітний.
- [ ] Стандартний outline не видалений без альтернативи.
- [ ] Є правильна HTML-семантика.
- [ ] Складні компоненти підтримують клавіатурну взаємодію.
- [ ] Перевірено світлу та темну теми.
- [ ] Інтерфейс протестовано без використання миші.

## 26. Мінішпаргалка

### CSS-псевдокласи

    /* Елемент перебуває у фокусі */
    input:focus {
      border-color: #2563eb;
    }

    /* Помітний індикатор фокусу */
    button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

    /* Контейнер має сфокусованого нащадка */
    .form-group:focus-within {
      border-color: #93c5fd;
    }

### Основні правила

    Focus        — елемент отримав фокус.
    Focus ring   — візуальний індикатор фокусу.
    :focus       — елемент перебуває у фокусі.
    :focus-visible — браузер визначає необхідність видимого індикатора.
    :focus-within — сам елемент або його нащадок має фокус.
    Tab          — перейти до наступного доступного елемента.
    Shift + Tab  — перейти до попереднього елемента.

### Що запам'ятати

- Focus — це не те саме, що hover.
- Видимий індикатор фокусу важливий для клавіатурної навігації.
- Не видаляй `outline`, якщо не створив доступної альтернативи.
- Використовуй семантичні HTML-елементи.
- Перевіряй інтерфейс без миші.
- Створюй узгоджені стилі фокусу для всієї дизайн-системи.
- Пам'ятай, що CSS оформлює фокус, але не реалізує всю поведінку доступності.

## 27. Головний висновок

**Focus — це не просто декоративна рамка. Це важливий сигнал, який допомагає користувачеві орієнтуватися в інтерфейсі.**

Якісний focus state повинен:
- бути помітним;
- залишатися видимим на різних фонах;
- працювати під час клавіатурної навігації;
- не залежати лише від hover;
- бути узгодженим між компонентами;
- підтримувати доступність інтерфейсу.

У практичній роботі починай із простого: зроби помітний `:focus-visible` для кнопок, посилань і полів введення. Потім перевір клавіатурну навігацію, складні компоненти та відповідність вимогам доступності.

Саме так focus переходить від окремого CSS-ефекту до повноцінної частини якісного UI-дизайну.
