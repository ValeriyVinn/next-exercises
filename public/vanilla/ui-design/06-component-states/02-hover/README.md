# 02. Hover State

Hover state (стан наведення) — це стан UI-компонента, який виникає, коли користувач розміщує вказівник миші або іншого пристрою наведення над інтерактивним елементом.

Hover state використовується для того, щоб:

- показати, що елемент доступний для взаємодії;
- надати користувачу візуальний зворотний зв'язок;
- підкреслити інтерактивність кнопок, посилань і карток;
- допомогти зрозуміти, який елемент зараз перебуває під вказівником;
- зробити інтерфейс більш передбачуваним;
- створити узгоджену поведінку компонентів у межах дизайн-системи;
- покращити сприйняття інтерактивних елементів на пристроях із підтримкою наведення.

Приклади компонентів, які можуть мати hover state:

    button
    link
    navigation item
    card
    icon button
    dropdown trigger
    menu item
    tab
    table row
    image
    tooltip trigger

Hover state найчастіше використовується в інтерфейсах, якими керують за допомогою миші або іншого вказівника.

На сенсорних пристроях звичайного hover може не бути, тому основні дії та важлива інформація не повинні залежати виключно від наведення.

## Що потрібно пам'ятати

• Hover state — це візуальний або поведінковий стан компонента під час наведення вказівника.

• Hover часто допомагає користувачу зрозуміти, що елемент інтерактивний.

• Для HTML-елементів CSS має псевдоклас `:hover`.

• Hover state може змінювати фон, колір тексту, межу, тінь, прозорість або положення елемента.

• Не потрібно змінювати всі властивості компонента одночасно. Часто достатньо однієї помітної зміни.

• Hover має бути достатньо помітним, але не повинен відволікати від основного контенту.

• Hover не замінює focus state. Користувач клавіатури повинен мати власний видимий індикатор фокусу.

• Hover не замінює active state. Наведення та натискання — різні види взаємодії.

• Hover не повинен бути єдиним способом отримати важливу інформацію або виконати основну дію.

• На сенсорних пристроях hover може бути відсутнім, імітуватися або поводитися непередбачувано залежно від браузера та пристрою.

• CSS `:hover` не означає, що компонент отримав клавіатурний фокус.

• Hover не обов'язково повинен супроводжуватися анімацією.

• Якщо використовується transition, зміни мають бути короткими, зрозумілими та ненав'язливими.

• Hover state повинен відповідати візуальному стилю компонента та правилам дизайн-системи.

• У дизайн-системі варто визначати hover state окремо для кожного типу інтерактивного компонента.

• Не кожен компонент потребує hover state. Наприклад, звичайний текстовий контейнер може бути неінтерактивним.

# Hover State

Hover state — стан компонента, що виникає, коли вказівник перебуває над його областю.

Наприклад, звичайна кнопка:

    ┌──────────────────────┐
    │       Continue       │
    └──────────────────────┘

Під час наведення її фон може стати темнішим:

    ┌──────────────────────┐
    │       Continue       │
    └──────────────────────┘
             Hover

Це лише концептуальна схема. Реальна різниця між станами визначається кольорами, розмірами, межами та іншими властивостями компонента.

Типова логіка:

    Default
       ↓ pointer enters
    Hover
       ↓ pointer leaves
    Default

Коли вказівник залишає область елемента, hover state зазвичай припиняється.

Проте реальна поведінка залежить від структури DOM, CSS, JavaScript та особливостей пристрою.

---

# Навіщо потрібен Hover

Hover забезпечує візуальний feedback — зворотний зв'язок між дією користувача та реакцією інтерфейсу.

Наприклад, якщо кнопка змінює фон під час наведення, користувач бачить, що інтерфейс реагує на його дії.

Основні завдання hover:

    1. Позначити інтерактивність.
    2. Показати поточну область наведення.
    3. Зробити взаємодію передбачуваною.
    4. Підтримати візуальну ієрархію.
    5. Забезпечити узгоджену поведінку компонентів.

Hover не повинен бути самоціллю.

Його потрібно використовувати тоді, коли зміна стану допомагає користувачу краще розуміти інтерфейс.

---

# Hover vs Default

Default state — звичайний вигляд компонента.

Hover state — вигляд компонента під час наведення вказівника.

Наприклад:

    Default:
        background: blue

    Hover:
        background: darker blue

У цьому прикладі змінюється тільки фон.

Інші властивості можуть залишатися незмінними:

    padding
    font size
    font weight
    border radius
    width
    height

Це допомагає уникнути випадкових стрибків розміру або положення компонента.

Важливо, щоб hover state:

- залишався впізнаваним як той самий компонент;
- не змінював його призначення;
- не погіршував контраст;
- не приховував важливий вміст;
- не створював небажаних зсувів макета.

---

# Hover vs Focus vs Active

Ці стани часто плутають, але вони описують різні ситуації.

| State | Що означає |
|---|---|
| Default | Звичайний стан компонента |
| Hover | Вказівник перебуває над елементом |
| Focus | Елемент отримав фокус |
| Focus-visible | Фокус позначається видимим індикатором відповідно до правил браузера |
| Active | Елемент перебуває у стані натискання або активації |

Приклад послідовності взаємодії мишею:

    Default
       ↓ pointer enters
    Hover
       ↓ pointer down
    Active
       ↓ pointer up
    Hover або Default

Після відпускання кнопки миші hover може залишитися активним, якщо вказівник усе ще перебуває над елементом.

Приклад взаємодії клавіатурою:

    Default
       ↓ Tab
    Focus
       ↓ Enter або Space
    Activation

Клавіатурна взаємодія не повинна залежати від hover.

Важливо:

• Hover показує наведення вказівника.

• Focus показує, який елемент отримав фокус.

• Active показує стан активації або натискання.

• Ці стани можуть співіснувати, тому дизайн-система має визначати їхню взаємодію.

---

# Hover and Affordance

Affordance — властивість або візуальна ознака, яка допомагає користувачу зрозуміти, як взаємодіяти з елементом.

Наприклад:

    Button       → елемент для виконання дії
    Link         → елемент для навігації
    Card link    → область для переходу
    Icon button  → кнопка з іконкою
    Menu item    → пункт меню

Hover може посилювати відчуття інтерактивності.

Наприклад, посилання може змінювати колір або підкреслення під час наведення.

Однак користувач повинен мати змогу розпізнати інтерактивний елемент і до наведення.

Не варто робити важливу інтерактивність очевидною лише після того, як користувач навів вказівник.

---

# Основні типи Hover Effects

Hover effect — візуальна зміна компонента під час наведення.

Найчастіше використовуються такі ефекти:

    background color
    text color
    border color
    opacity
    box shadow
    transform
    underline
    icon movement
    image zoom
    overlay
    reveal content

Не всі ефекти підходять для кожного компонента.

Вибір залежить від призначення елемента, візуального стилю та поведінки інтерфейсу.

---

# Background Color

Один із найпоширеніших способів реалізації hover — зміна фону.

Default:

    background: #2563eb;

Hover:

    background: #1d4ed8;

Приклад CSS:

    .button {
        background-color: #2563eb;
        color: #ffffff;
    }

    .button:hover {
        background-color: #1d4ed8;
    }

Такий підхід часто використовується для primary buttons.

Переваги:

- проста реалізація;
- зрозуміла зміна стану;
- відсутність зміни розмірів компонента;
- легке узгодження з design tokens.

Важливо перевіряти контраст тексту на фоні в обох станах.

---

# Text Color

Hover може змінювати колір тексту.

Приклад:

    .link {
        color: #1d4ed8;
    }

    .link:hover {
        color: #1e40af;
    }

Цей ефект часто використовується для посилань і пунктів навігації.

Зміна кольору має бути достатньо помітною.

Не варто використовувати настільки близькі відтінки, що користувач майже не помічає різниці.

Також важливо не покладатися лише на зміну кольору, якщо потрібно чітко позначити посилання серед звичайного тексту.

---

# Border Color

Hover може змінювати колір межі компонента.

Приклад:

    .input-action {
        border: 1px solid #d1d5db;
    }

    .input-action:hover {
        border-color: #2563eb;
    }

Такий підхід можна використовувати для:

    outlined button
    selectable card
    interactive tile
    menu item
    icon button

Важливо не плутати hover із focus.

Для поля введення зміна межі під час наведення не замінює видимого індикатора фокусу.

---

# Box Shadow

Hover може змінювати тінь компонента.

Наприклад:

    .card {
        box-shadow: 0 1px 3px rgb(0 0 0 / 10%);
    }

    .card:hover {
        box-shadow: 0 8px 20px rgb(0 0 0 / 12%);
    }

Тінь може створювати враження, що картка піднімається над фоном.

Цей ефект часто застосовують до інтерактивних карток.

Однак:

• Не кожна картка повинна реагувати на hover.

• Тінь не повинна бути єдиною ознакою інтерактивності.

• Надмірні тіні можуть погіршувати візуальну ієрархію.

• Тінь має відповідати загальному стилю дизайн-системи.

---

# Transform

Transform дозволяє змінювати положення, масштаб або поворот елемента.

Наприклад, картка може трохи підніматися:

    .card {
        transform: translateY(0);
    }

    .card:hover {
        transform: translateY(-4px);
    }

Це може створити відчуття інтерактивності.

Інший приклад:

    .icon-button:hover {
        transform: scale(1.05);
    }

Такі ефекти потрібно використовувати обережно.

Вони можуть:

- створювати візуальні зсуви;
- перекривати сусідні елементи;
- відволікати користувача;
- викликати дискомфорт у деяких користувачів.

Для більшості стандартних кнопок зміни кольору часто достатньо.

---

# Opacity

Opacity визначає прозорість елемента.

Приклад:

    .image {
        opacity: 0.9;
    }

    .image:hover {
        opacity: 1;
    }

Це може бути доречним для зображень або декоративних елементів.

Але opacity не слід бездумно використовувати для тексту, кнопок або важливих елементів керування.

Зменшення прозорості може знизити контраст і погіршити читабельність.

Не потрібно плутати hover effect із disabled state.

Якщо елемент доступний для взаємодії, його не варто стилізувати так, ніби він вимкнений.

---

# Underline

Для посилань hover може додавати підкреслення.

Приклад:

    .link {
        text-decoration: none;
    }

    .link:hover {
        text-decoration: underline;
        text-underline-offset: 3px;
    }

Це поширений спосіб надати додатковий візуальний feedback.

Проте для важливих посилань у звичайному тексті постійне підкреслення часто допомагає краще розпізнавати їх без наведення.

Hover-підкреслення не повинно бути єдиною ознакою того, що текст є посиланням.

---

# Icon Movement

Hover може змінювати положення або зовнішній вигляд іконки.

Наприклад, стрілка може трохи переміщуватися вправо.

    .link-icon {
        display: inline-block;
        transition: transform 180ms ease;
    }

    .link:hover .link-icon {
        transform: translateX(3px);
    }

Це може допомагати підкреслити напрямок переходу.

Але анімація повинна бути короткою та ненав'язливою.

Не потрібно анімувати кожну іконку в інтерфейсі без конкретної причини.

---

# Image Zoom

У картках із зображеннями можна використовувати легке збільшення картинки під час наведення.

Приклад HTML:

    <a class="image-card" href="/courses">
        <span class="image-card__media">
            <img
                src="/images/course.jpg"
                alt="Students learning"
            />
        </span>

        <span class="image-card__title">
            View course
        </span>
    </a>

Приклад CSS:

    .image-card__media {
        display: block;
        overflow: hidden;
        border-radius: 12px;
    }

    .image-card img {
        display: block;
        width: 100%;
        height: auto;
        transition: transform 200ms ease;
    }

    .image-card:hover img {
        transform: scale(1.04);
    }

`overflow: hidden` допомагає обрізати частини зображення, які виходять за межі контейнера.

Потрібно перевіряти, щоб ефект не обрізав важливі деталі зображення та не порушував компонування.

---

# Overlay

Overlay — напівпрозорий шар, який накладається поверх елемента.

Наприклад, під час наведення на картку із зображенням може з'являтися затемнення.

    .image-card {
        position: relative;
        overflow: hidden;
    }

    .image-card::after {
        content: "";
        position: absolute;
        inset: 0;

        background: rgb(0 0 0 / 0%);

        transition: background-color 180ms ease;
        pointer-events: none;
    }

    .image-card:hover::after {
        background: rgb(0 0 0 / 20%);
    }

Overlay може використовуватися для:

    image cards
    gallery items
    media previews
    interactive thumbnails

Важливо не приховувати важливий текст і не погіршувати контраст.

Якщо кнопки або посилання розміщені поверх зображення, вони повинні залишатися доступними для взаємодії.

---

# Reveal Content

Іноді hover використовується для показу додаткової інформації.

Наприклад:

    Course card
        ↓ hover
    Show additional details

Це може бути доречним для:

    image gallery
    portfolio card
    media preview
    product card

Але важливий вміст не повинен бути доступний тільки через hover.

Причини:

- сенсорні пристрої можуть не підтримувати звичайне наведення;
- користувач клавіатури повинен мати доступ до важливої інформації;
- користувач може не здогадатися, що додатковий вміст приховано;
- hover-поведінка може бути незручною для людей із порушеннями моторики.

Якщо інформація важлива, її варто показувати постійно або передбачити альтернативний спосіб відкриття.

---

# CSS Pseudo-class :hover

`:hover` — CSS pseudo-class, який застосовується, коли користувач наводить вказівник на елемент.

Базовий синтаксис:

    selector:hover {
        property: value;
    }

Приклад:

    .button:hover {
        background-color: #1d4ed8;
    }

Для посилання:

    a:hover {
        text-decoration: underline;
    }

Для картки:

    .card:hover {
        box-shadow: 0 8px 20px rgb(0 0 0 / 12%);
    }

Для пункту меню:

    .menu-item:hover {
        background-color: #f3f4f6;
    }

`:hover` не обмежується кнопками.

Його можна застосовувати до різних елементів, але зміна стану має відповідати їхньому призначенню.

---

# Hover and CSS Specificity

CSS specificity визначає пріоритет CSS-селекторів у разі конфлікту правил.

Наприклад:

    .button {
        background-color: blue;
    }

    .button:hover {
        background-color: darkblue;
    }

Селектор `.button:hover` має більшу специфічність, ніж `.button`.

Тому під час наведення застосовується темніший фон, якщо немає інших правил із вищим пріоритетом.

Проте hover-правило не завжди переможе всі інші стилі.

На результат можуть впливати:

    specificity
    source order
    cascade layers
    !important
    inline styles

Не варто вирішувати всі конфлікти за допомогою `!important`.

Краще підтримувати зрозумілу структуру CSS і послідовні правила станів.

---

# Hover and Transition

Transition — плавна зміна CSS-властивостей протягом певного часу.

Без transition зміна фону може відбуватися миттєво.

З transition вона відбувається поступово.

Приклад:

    .button {
        background-color: #2563eb;
        transition: background-color 180ms ease;
    }

    .button:hover {
        background-color: #1d4ed8;
    }

Основні параметри transition:

    transition-property
    transition-duration
    transition-timing-function
    transition-delay

Короткий запис:

    transition: property duration timing-function delay;

Наприклад:

    transition: background-color 180ms ease;

Тут:

    background-color → властивість, що змінюється
    180ms            → тривалість
    ease             → функція плавності

---

## Transition vs Animation

Transition і animation — різні механізми CSS.

Transition зазвичай описує зміну між двома значеннями властивості, наприклад між default та hover.

    Default
       ↓
    Hover

Animation може описувати послідовність ключових кадрів.

    @keyframes pulse {
        0% {
            transform: scale(1);
        }

        50% {
            transform: scale(1.05);
        }

        100% {
            transform: scale(1);
        }
    }

Для простих hover-ефектів transition зазвичай достатньо.

Не потрібно використовувати складну animation, якщо завдання можна вирішити звичайною зміною властивості.

---

# Які властивості анімувати

Для hover-ефектів часто використовують:

    background-color
    color
    border-color
    opacity
    box-shadow
    transform

Не всі CSS-властивості мають однакову вартість під час відображення.

Зміни `transform` та `opacity` часто можна оптимізувати ефективніше, ніж зміни властивостей, які спричиняють перерахунок компонування, наприклад `width` або `height`.

Проте фактична продуктивність залежить від браузера, пристрою та конкретного інтерфейсу.

Практичні правила:

• Уникай анімації великих областей без необхідності.

• Не анімуй десятки властивостей одночасно без причини.

• Уникай змін `width` та `height`, якщо вони створюють небажані зсуви макета.

• Для невеликих ефектів часто достатньо короткої зміни кольору або `transform`.

• Перевіряй продуктивність на реальних пристроях, якщо ефект складний.

---

# Hover Duration

Hover duration — тривалість візуального переходу між станами.

Для простих UI-ефектів часто використовують короткі значення, наприклад:

    100ms
    150ms
    180ms
    200ms
    250ms

Це практичні приклади, а не обов'язковий стандарт.

Надто короткий перехід може бути майже непомітним.

Надто довгий перехід може сприйматися як затримка.

Наприклад:

    .button {
        transition: background-color 180ms ease;
    }

    .card {
        transition:
            box-shadow 200ms ease,
            transform 200ms ease;
    }

У дизайн-системі варто використовувати узгоджені значення для подібних ефектів.

---

# Hover and Reduced Motion

Деякі користувачі віддають перевагу зменшенню анімації.

CSS media feature `prefers-reduced-motion` дозволяє враховувати відповідні системні налаштування.

Приклад:

    .card {
        transition:
            transform 180ms ease,
            box-shadow 180ms ease;
    }

    @media (prefers-reduced-motion: reduce) {
        .card {
            transition: none;
        }
    }

Це приклад одного підходу.

У складніших інтерфейсах варто перевіряти всі значущі анімації, а не лише hover.

Зменшення руху не завжди означає, що всі зміни станів потрібно прибрати. Візуальний feedback можна зберегти за допомогою кольору, меж або інших неанімованих змін.

---

# Hover and Touch Devices

Hover найбільш передбачувано працює на пристроях із вказівником, наприклад мишею.

На сенсорних пристроях користувач взаємодіє дотиком.

Тому не можна припускати, що кожен користувач побачить hover state.

Проблемний підхід:

    .card:hover .details {
        display: block;
    }

Якщо додаткова інформація доступна лише через hover, на деяких пристроях вона може бути недоступною або незручною.

Краще:

- показувати важливу інформацію безпосередньо;
- використовувати окрему кнопку для відкриття деталей;
- забезпечувати клавіатурний доступ;
- перевіряти поведінку на сенсорних пристроях.

CSS дозволяє перевіряти можливості пристрою через media features.

Наприклад:

    @media (hover: hover) and (pointer: fine) {
        .card:hover {
            transform: translateY(-2px);
        }
    }

Цей запит застосовує ефект до середовищ, де основний пристрій наведення підтримує hover, а вказівник має високу точність.

Однак не потрібно покладатися лише на media queries для забезпечення функціональності. Важливі дії мають працювати й без hover.

---

# Hover and Accessibility

Accessibility — доступність інтерфейсу для людей із різними можливостями та способами взаємодії.

Hover потрібно проєктувати так, щоб він не створював бар'єрів.

## Не покладайся лише на hover

Важливі дії та інформація мають бути доступними також за допомогою клавіатури або іншого відповідного способу взаємодії.

## Забезпечуй видимий focus

Для клавіатурної взаємодії використовуй видимий індикатор фокусу.

Наприклад:

    .button:focus-visible {
        outline: 3px solid #93c5fd;
        outline-offset: 2px;
    }

## Перевіряй контраст

Зміна кольору під час наведення не повинна погіршувати читабельність тексту.

## Не приховуй необхідні функції

Якщо кнопка з'являється лише під час наведення, переконайся, що існує доступний спосіб її знайти та активувати.

## Уникай надмірного руху

Анімації мають бути короткими та доречними. За потреби враховуй `prefers-reduced-motion`.

## Перевіряй сенсорні пристрої

Hover не повинен бути необхідною умовою для виконання основних завдань.

# Hover in Figma

У Figma hover state часто створюється як окремий variant інтерактивного компонента.

Наприклад, кнопка може мати властивість State:

    State = Default
    State = Hover
    State = Focus
    State = Active
    State = Disabled

Це лише один із способів організації компонентів. Назви властивостей можуть відрізнятися залежно від дизайн-системи.

Для інтерактивного компонента можна налаштувати:

    Default → While hovering → Hover
    Hover → Mouse leave → Default

У прототипі Figma такі переходи допомагають продемонструвати поведінку компонента.

Важливо розрізняти:

    Design variant → візуальний варіант компонента
    Prototype interaction → налаштована взаємодія
    Production behavior → реальна поведінка в коді

Прототип може показувати hover, але сам по собі не створює відповідний CSS у готовому застосунку.

# Hover in a Design System

У дизайн-системі hover state має бути узгодженим для компонентів однакового типу.

Наприклад:

    Primary button
        Default
        Hover
        Focus
        Active
        Disabled

    Secondary button
        Default
        Hover
        Focus
        Active
        Disabled

    Navigation link
        Default
        Hover
        Focus
        Active

Це приклад можливої системи станів, а не універсальний обов'язковий перелік.

Для кожного компонента потрібно визначити:

• Яка властивість змінюється під час hover.

• Яким є значення властивості.

• Чи використовується transition.

• Яка тривалість переходу.

• Чи змінюється курсор.

• Чи існують комбінації hover і focus.

• Чи доступна відповідна дія без наведення.

• Як стан працює на сенсорних пристроях.

• Чи відповідає оформлення токенам дизайн-системи.

# Hover and Design Tokens

Design tokens допомагають підтримувати послідовність hover-ефектів.

Наприклад:

    :root {
        --color-primary: #2563eb;
        --color-primary-hover: #1d4ed8;

        --color-text: #111827;
        --color-link-hover: #1e40af;

        --duration-fast: 150ms;
        --duration-normal: 200ms;

        --ease-standard: ease;
    }

Використання:

    .button {
        background-color: var(--color-primary);

        transition:
            background-color
            var(--duration-normal)
            var(--ease-standard);
    }

    .button:hover {
        background-color: var(--color-primary-hover);
    }

Переваги:

• Однакові компоненти використовують однакові правила.

• Легше змінювати кольори та тривалість ефектів.

• Менше випадкових відмінностей між елементами.

• Простіше підтримувати дизайн-систему.

• Зручніше реалізовувати теми та варіанти оформлення.

# Practical Examples

## Приклад 1 — Button Hover

HTML:

    <button class="button" type="button">
        Continue
    </button>

CSS:

    .button {
        min-height: 44px;
        padding: 12px 16px;

        border: none;
        border-radius: 8px;

        background-color: #2563eb;
        color: #ffffff;

        font: inherit;
        font-weight: 600;

        cursor: pointer;

        transition: background-color 180ms ease;
    }

    .button:hover {
        background-color: #1d4ed8;
    }

Результат:

    Default → синій фон
    Hover   → темніший синій фон

---

## Приклад 2 — Link Hover

HTML:

    <a class="link" href="/courses">
        View courses
    </a>

CSS:

    .link {
        color: #1d4ed8;
        text-decoration: underline;
        text-underline-offset: 3px;

        transition: color 150ms ease;
    }

    .link:hover {
        color: #1e40af;
    }

Посилання залишається розпізнаваним навіть без наведення.

---

## Приклад 3 — Card Hover

HTML:

    <a class="course-card" href="/courses/javascript">
        <h2>JavaScript Basics</h2>

        <p>
            Learn the fundamentals of JavaScript.
        </p>

        <span>View course →</span>
    </a>

CSS:

    .course-card {
        display: block;
        padding: 24px;

        border: 1px solid #e5e7eb;
        border-radius: 12px;

        background-color: #ffffff;
        color: #111827;
        text-decoration: none;

        transition:
            transform 180ms ease,
            box-shadow 180ms ease;
    }

    .course-card:hover {
        transform: translateY(-2px);
        box-shadow: 0 8px 20px rgb(0 0 0 / 10%);
    }

Тут hover застосовується до посилання-картки.

Важливо: така структура доречна, коли вся картка виконує одну навігаційну дію. Не слід вкладати інтерактивні кнопки або інші посилання всередину такого посилання.

---

## Приклад 4 — Navigation Hover

HTML:

    <nav class="navigation" aria-label="Main navigation">
        <a href="/" class="navigation__link">Home</a>
        <a href="/courses" class="navigation__link">Courses</a>
        <a href="/about" class="navigation__link">About</a>
    </nav>

CSS:

    .navigation {
        display: flex;
        gap: 24px;
    }

    .navigation__link {
        color: #374151;
        text-decoration: none;

        transition: color 150ms ease;
    }

    .navigation__link:hover {
        color: #2563eb;
        text-decoration: underline;
        text-underline-offset: 4px;
    }

Hover підкреслює інтерактивність посилань.

Для поточної сторінки може додатково використовуватися окремий стан active або selected, залежно від структури навігації.

---

## Приклад 5 — Icon Button Hover

HTML:

    <button
        class="icon-button"
        type="button"
        aria-label="Open settings"
    >
        ⚙
    </button>

CSS:

    .icon-button {
        display: inline-flex;
        align-items: center;
        justify-content: center;

        width: 44px;
        height: 44px;

Іконкова кнопка повинна мати зрозуміле доступне ім'я, оскільки сама іконка не завжди пояснює призначення дії.

## Приклад 6 — Hover із Focus

HTML:

    <button class="button" type="button">
        Save changes
    </button>

CSS:

    .button {
        padding: 12px 16px;
        border: none;
        border-radius: 8px;

        background-color: #2563eb;
        color: #ffffff;

        font: inherit;
        cursor: pointer;

        transition: background-color 180ms ease;
    }

    .button:hover {
        background-color: #1d4ed8;
    }

    .button:focus-visible {
        outline: 3px solid #93c5fd;
        outline-offset: 3px;
    }

Тут:

    :hover        → реакція на наведення
    :focus-visible → видимий індикатор фокусу

Ці стани виконують різні функції та не повинні підміняти один одного.

---

## Приклад 7 — Hover для пристроїв із вказівником

CSS:

    .card {
        transition: transform 180ms ease;
    }

    @media (hover: hover) and (pointer: fine) {
        .card:hover {
            transform: translateY(-2px);
        }
    }

Цей підхід обмежує декоративний hover-ефект середовищами, які підтримують відповідний тип наведення.

Проте він не замінює необхідності забезпечувати доступність і функціональність картки на інших пристроях.

---

## Приклад 8 — Reduced Motion

CSS:

    .card {
        transition:
            transform 180ms ease,
            box-shadow 180ms ease;
    }

    .card:hover {
        transform: translateY(-2px);
        box-shadow: 0 8px 20px rgb(0 0 0 / 10%);
    }

    @media (prefers-reduced-motion: reduce) {
        .card {
            transition: none;
        }

        .card:hover {
            transform: none;
        }
    }

Цей приклад прибирає рух картки для користувачів, які попросили систему зменшити анімацію.

# Типові помилки

❌ Робити hover єдиною ознакою інтерактивності.

Користувач повинен розпізнавати важливі інтерактивні елементи ще до наведення.

---

❌ Використовувати hover замість focus.

Користувачі клавіатури повинні мати видимий focus indicator.

---

❌ Плутати hover та active.

    Hover → вказівник над елементом
    Active → елемент у стані натискання або активації

---

❌ Робити надто слабку зміну кольору.

Якщо різниця між default та hover майже непомітна, feedback може бути неефективним.

---

❌ Використовувати надмірні анімації.

Сильне збільшення, обертання, стрибки та інші ефекти можуть відволікати від основного контенту.

---

❌ Анімувати багато властивостей без потреби.

Чим складніший ефект, тим важливіше перевіряти його читабельність і продуктивність.

---

❌ Змінювати розміри компонента під час hover без необхідності.

Зміни width, height або padding можуть створювати небажані зсуви макета.

---

❌ Зменшувати opacity так, що текст стає нечитабельним.

Hover не повинен погіршувати доступність компонента.

---

❌ Приховувати важливий контент до наведення.

Такий контент може бути недоступним на сенсорних пристроях або для користувачів клавіатури.

---

❌ Робити неінтерактивні елементи схожими на кнопки.

Візуальна поведінка повинна відповідати реальній функціональності.

---

❌ Додавати `cursor: pointer` до кожного елемента.

Використовуй його для елементів, які справді реагують на натискання або відповідну взаємодію.

---

❌ Застосовувати hover лише через зміну кольору, якщо цього недостатньо.

Для деяких компонентів можуть бути корисними додаткові візуальні ознаки, наприклад зміна межі або підкреслення.

---

❌ Ігнорувати сенсорні пристрої.

Необхідні дії та інформація мають бути доступними без hover.

---

❌ Використовувати надто довгий transition.

Надмірно повільна реакція може сприйматися як затримка інтерфейсу.

---

❌ Ігнорувати `prefers-reduced-motion`.

Для користувачів, які обмежують анімацію, варто передбачити відповідну поведінку.

---

❌ Застосовувати різні hover-ефекти до однакових компонентів без причини.

Це порушує візуальну узгодженість дизайн-системи.

# Міні-шпаргалка

## Hover

    Default
       ↓ pointer enters
    Hover
       ↓ pointer leaves
    Default

Hover — стан наведення вказівника.

---

## CSS :hover

    .button:hover {
        background-color: #1d4ed8;
    }

Застосовує стилі під час наведення.

---

## Background

    .button {
        background: #2563eb;
    }

    .button:hover {
        background: #1d4ed8;
    }

---

## Link

    .link:hover {
        text-decoration: underline;
    }

---

## Card

    .card {
        transition: transform 180ms ease;
    }

    .card:hover {
        transform: translateY(-2px);
    }

---

## Transition

    transition: background-color 180ms ease;

Плавно змінює властивість між станами.

---

## Focus

    .button:focus-visible {
        outline: 3px solid #93c5fd;
        outline-offset: 3px;
    }

Focus потрібен для доступної клавіатурної взаємодії.

---

## Reduced Motion

    @media (prefers-reduced-motion: reduce) {
        .card {
            transition: none;
        }
    }

Враховує системне налаштування зменшення анімації.

---

## Touch Devices

    @media (hover: hover) and (pointer: fine) {
        .card:hover {
            transform: translateY(-2px);
        }
    }

Застосовує hover-ефект у середовищах із відповідними можливостями наведення.

---

## Design Tokens

    :root {
        --color-primary: #2563eb;
        --color-primary-hover: #1d4ed8;
        --duration-normal: 200ms;
    }

Токени допомагають узгоджувати стилі.

---

## Основні правила

    Default → звичайний стан
    Hover   → наведення вказівника
    Focus   → елемент отримав фокус
    Active  → натискання або активація
    Transition → плавний перехід між значеннями
    Transform  → переміщення, масштабування або поворот
    Opacity    → прозорість
    Overlay    → шар поверх елемента

# Головне

• Hover state — це стан компонента під час наведення вказівника.

• Hover забезпечує візуальний feedback і може підкреслювати інтерактивність.

• CSS-псевдоклас `:hover` використовується для опису відповідних стилів.

• Hover може змінювати фон, колір тексту, межу, тінь, прозорість, положення або вигляд іконки.

• Для простих ефектів часто достатньо зміни кольору та короткого transition.

• Hover не замінює focus state або active state.

• Важливі дії та інформація не повинні залежати виключно від hover.

• На сенсорних пристроях hover може бути відсутнім або працювати інакше, ніж на комп'ютері.

• Hover-ефекти повинні відповідати призначенню компонента та візуальній мові дизайн-системи.

• Transition допомагає створювати плавні переходи між станами.

• Надмірні анімації можуть відволікати, погіршувати доступність і створювати небажані візуальні ефекти.

• `transform` і `opacity` часто підходять для легких ефектів, але складні анімації потрібно перевіряти на продуктивність.

• Для користувачів, які обмежують анімацію, варто враховувати `prefers-reduced-motion`.

• Hover повинен залишатися узгодженим із focus, active та іншими станами компонента.

• Design tokens допомагають підтримувати єдині кольори й параметри переходів.

• Головний принцип: hover має допомагати користувачу, а не бути лише декоративним ефектом.
