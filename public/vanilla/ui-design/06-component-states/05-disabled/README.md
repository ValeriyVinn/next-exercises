# 05. Disabled — Недоступний стан компонента в UI

> **Disabled state** — це стан інтерфейсного компонента, у якому взаємодія з ним тимчасово недоступна. Компонент залишається видимим, але користувач не може виконати передбачену дію через цей елемент.
>
> Наприклад, кнопка «Надіслати» може бути недоступною, поки користувач не заповнить обов'язкові поля форми.
>
> У UI-дизайні важливо не лише показати, що компонент недоступний, а й зробити його стан зрозумілим для користувача.

---

## 1. Що таке Disabled State

**Disabled state** — це стан компонента, у якому його функція тимчасово недоступна для взаємодії.

Приклади:
- кнопка недоступна, поки не заповнено обов'язкові поля;
- пункт меню недоступний у поточному контексті;
- кнопка переходу на наступний крок недоступна, поки не виконано попередній;
- поле форми не можна редагувати;
- кнопка оплати недоступна, поки не вибрано спосіб доставки.

### Приклад

    Enabled:
    [ Надіслати ]  ← кнопка доступна

    Disabled:
    [ Надіслати ]  ← кнопка недоступна

Зовнішній вигляд компонента може змінюватися:
- знижується контраст фону;
- змінюється колір тексту;
- зникає тінь;
- змінюється рамка;
- змінюється курсор;
- прибирається візуальний ефект наведення.

Однак самого візуального оформлення недостатньо. Якщо компонент має бути справді недоступним, його поведінку також потрібно правильно реалізувати.

### Навіщо потрібен Disabled State

- ✔ Показує, що дія наразі недоступна.
- ✔ Допомагає запобігти передчасній взаємодії.
- ✔ Відображає обмеження поточного стану застосунку.
- ✔ Робить послідовність дій зрозумілішою.
- ✔ Допомагає керувати складними формами та багатокроковими процесами.
- ✔ Дозволяє відрізнити доступні функції від недоступних.

**Головне правило:** користувач повинен розуміти не лише те, що компонент недоступний, а й, коли це важливо, як зробити його доступним.

---

## 2. Основні поняття

### 2.1. Enabled

**Enabled** — стан, у якому компонент доступний для передбаченої взаємодії.

Наприклад, кнопку можна натиснути, поле можна редагувати, а посилання відкриває відповідну сторінку.

### 2.2. Disabled

**Disabled** — стан, у якому компонент не повинен виконувати свою звичайну дію.

Приклади:
- кнопка не запускає операцію;
- поле введення не дозволяє редагувати значення;
- кнопка переходу недоступна, поки не виконано необхідні умови.

### 2.3. Availability

**Availability** — доступність функції або дії в поточному контексті.

Наприклад, функція може бути недоступною:
- через незаповнені поля;
- через відсутність необхідних даних;
- через права доступу;
- через стан процесу;
- через тимчасові обмеження.

Availability описує загальну доступність функції, а disabled state є одним зі способів відобразити її на рівні компонента.

### 2.4. Read-only

**Read-only** — стан, у якому користувач може переглядати значення, але не може його змінювати.

Це не те саме, що disabled.

Наприклад, поле з номером замовлення може бути доступним для перегляду, але недоступним для редагування.

### 2.5. Validation

**Validation** — перевірка правильності введених даних.

Наприклад, кнопка відправлення форми може залишатися недоступною, поки не заповнені обов'язкові поля.

Проте disabled не замінює валідацію. Дані все одно потрібно перевіряти перед виконанням важливої операції.

### 2.6. Disabled vs. Loading

Це різні стани.

- `Disabled` — компонент недоступний для взаємодії.
- `Loading` — операція виконується.

Під час завантаження кнопку можуть додатково зробити недоступною, щоб запобігти повторному запуску операції. У такому випадку візуальний стан має пояснювати, що відбувається.

---

## 3. Disabled у системі станів компонента

Інтерактивний компонент може мати декілька станів.

Наприклад, кнопка:

    Default  — звичайний стан.
    Hover    — курсор наведений на кнопку.
    Focus    — кнопка перебуває у фокусі.
    Active   — кнопку натискають.
    Disabled — кнопка недоступна.
    Loading  — операція виконується.
    Success  — операція успішно завершена.
    Error    — операція завершилася помилкою.

Не всі стани взаємовиключні. Наприклад, під час завантаження компонент може бути недоступним для повторного натискання.

### Порівняння станів

| Стан | Значення |
|---|---|
| Default | Звичайний вигляд компонента |
| Hover | Вказівник знаходиться над компонентом |
| Focus | Компонент перебуває у фокусі |
| Active | Відбувається натискання |
| Disabled | Звичайна взаємодія недоступна |
| Read-only | Значення можна переглядати, але не редагувати |
| Loading | Операція виконується |
| Success | Операція завершилася успішно |
| Error | Операція завершилася помилкою |

**Важливо:** disabled — це не просто блідий вигляд кнопки. Це стан, який має відповідати реальній поведінці компонента.

---

## 4. Основні способи візуалізації Disabled

### 4.1. Зменшення контрасту

Один із найпоширеніших способів показати недоступний компонент — змінити колір фону й тексту.

    .button {
      background-color: #2563eb;
      color: #ffffff;
    }

    .button:disabled {
      background-color: #d1d5db;
      color: #6b7280;
    }

Такий підхід створює помітну різницю між доступним і недоступним станами.

Однак не варто робити текст настільки блідим, щоб його було складно прочитати.

### 4.2. Зміна рамки

Для кнопок із контуром можна змінити колір рамки.

    .button-outline {
      border: 1px solid #2563eb;
      background-color: transparent;
      color: #2563eb;
    }

    .button-outline:disabled {
      border-color: #d1d5db;
      color: #6b7280;
    }

### 4.3. Прибирання тіні

    .button {
      box-shadow: 0 3px 8px rgb(0 0 0 / 15%);
    }

    .button:disabled {
      box-shadow: none;
    }

Прибирання тіні може допомогти показати, що компонент більше не має звичайної інтерактивної поведінки.

### 4.4. Зміна курсора

    .button:disabled {
      cursor: not-allowed;
    }

Курсор `not-allowed` може додатково пояснити, що дія недоступна, коли користувач наводить мишу на компонент.

Але курсор не є достатнім індикатором: на сенсорних пристроях його немає, а користувачі клавіатури не бачать його.

### 4.5. Поєднання кількох ознак

    .button {
      background-color: #2563eb;
      color: #ffffff;
      border: 1px solid #2563eb;
      box-shadow: 0 3px 8px rgb(0 0 0 / 15%);
    }

    .button:disabled {
      background-color: #e5e7eb;
      color: #6b7280;
      border-color: #d1d5db;
      box-shadow: none;
      cursor: not-allowed;
    }

Комбінація кількох ознак може зробити стан зрозумілішим, ніж одна лише зміна кольору.

## 5. CSS: псевдоклас :disabled

CSS-псевдоклас `:disabled` вибирає HTML-елементи, які перебувають у справжньому стані disabled.

Найчастіше його використовують із:
- `<button>`;
- `<input>`;
- `<select>`;
- `<textarea>`;
- іншими елементами форми, для яких HTML підтримує атрибут `disabled`.

Приклад:

    button:disabled {
      opacity: 0.55;
      cursor: not-allowed;
    }

HTML:

    <button type="button" disabled>
      Зберегти
    </button>

У цьому випадку браузер знає, що кнопка вимкнена. Вона не виконує звичайну дію натискання.

### Важливо розрізняти CSS і HTML

CSS:

    button {
      opacity: 0.5;
    }

Це лише змінює вигляд кнопки. Кнопка залишається доступною для взаємодії.

HTML:

    <button type="button" disabled>
      Зберегти
    </button>

Це створює справжній disabled state для кнопки.

**Запам'ятай:** візуальне оформлення disabled і фактичне вимкнення компонента — це дві різні речі.

---

## 6. Атрибут disabled

Атрибут `disabled` використовується для елементів форми, які повинні бути недоступними.

Приклад:

    <button type="submit" disabled>
      Надіслати
    </button>

Або:

    <input
      type="text"
      name="username"
      value="Valeriy"
      disabled
    >

### Що робить disabled

Для підтримуваних HTML-елементів цей атрибут:
- вимикає звичайну взаємодію;
- не дозволяє користувачеві змінювати поле;
- зазвичай виключає елемент із послідовної клавіатурної навігації;
- впливає на те, які значення елементів форми надсилаються разом із формою.

Останній пункт особливо важливий.

**Disabled-поля форми не надсилаються як звичайні успішні поля форми.** Якщо значення потрібно передати серверу, не можна покладатися на disabled-поле як на джерело даних.

### Приклад

    <form>
      <input name="username" value="Valeriy" disabled>
      <button type="submit">Надіслати</button>
    </form>

Поле `username` буде недоступним для редагування, а його значення не потрапить до стандартного набору даних форми під час відправлення.

## 7. Disabled vs. Read-only

Це одна з найважливіших відмінностей у проєктуванні форм.

### Disabled

Елемент недоступний для звичайної взаємодії.

    <input
      type="text"
      value="Замовлення №125"
      disabled
    >

### Read-only

Елемент доступний для перегляду, але його значення не можна змінювати через звичайне редагування.

    <input
      type="text"
      value="Замовлення №125"
      readonly
    >

### Порівняння

| Властивість | Disabled | Read-only |
|---|---|---|
| Можна редагувати значення | Ні | Ні |
| Зазвичай можна отримати фокус | Ні | Так, для підтримуваних полів |
| Можна виділити та скопіювати текст | Залежить від елемента та браузера; звичайна взаємодія обмежена | Зазвичай так |
| Значення поля надсилається стандартною формою | Ні | Так |
| Призначення | Елемент повністю недоступний | Значення доступне для перегляду |

### Коли використовувати Disabled

- Дію поки що не можна виконати.
- Компонент недоступний у поточному контексті.
- Користувач не повинен взаємодіяти з елементом.

### Коли використовувати Read-only

- Значення потрібно показати користувачеві.
- Редагування заборонене, але перегляд важливий.
- Користувачеві може знадобитися скопіювати значення.
- Значення має бути включене до стандартного надсилання форми.

Не всі HTML-елементи підтримують `readonly`. Наприклад, цей атрибут не працює як універсальний спосіб вимкнення кнопок.

## 8. Disabled для кнопок

Кнопки часто стають недоступними, коли користувач ще не виконав необхідні умови.

Наприклад:
- форма не заповнена;
- користувач не погодився з умовами;
- дані ще не завантажені;
- операція вже виконується;
- користувач не має права виконати дію.

### Приклад

HTML:

    <button class="button" type="button" disabled>
      Продовжити
    </button>

CSS:

    .button {
      padding: 12px 18px;
      border: 1px solid #2563eb;
      border-radius: 8px;
      background-color: #2563eb;
      color: #ffffff;
      font: inherit;
      cursor: pointer;
    }

    .button:hover:not(:disabled) {
      background-color: #1d4ed8;
    }

    .button:focus-visible {
      outline: 3px solid #93c5fd;
      outline-offset: 3px;
    }

    .button:disabled {
      background-color: #e5e7eb;
      border-color: #d1d5db;
      color: #6b7280;
      cursor: not-allowed;
    }

### Чому використовується :not(:disabled)

Селектор:

    .button:hover:not(:disabled)

означає: застосувати hover-стиль лише до кнопки, яка не є disabled.

Це допомагає уникнути ситуації, коли недоступна кнопка виглядає так, ніби вона реагує на наведення як звичайна активна кнопка.

### Рекомендації

- ✔ Відрізняй disabled від enabled візуально.
- ✔ Не роби текст надмірно блідим.
- ✔ Не показуй звичайну реакцію hover для недоступної кнопки.
- ✔ Не покладайся лише на курсор `not-allowed`.
- ✔ Пояснюй причину недоступності, якщо це важливо.
- ✔ Не плутай disabled із loading.

## 9. Disabled у формах

Форми часто використовують disabled state для окремих полів або груп елементів.

Приклади:
- поле недоступне до вибору категорії;
- додаткові параметри недоступні, поки не ввімкнено відповідний перемикач;
- поле адреси недоступне, поки не вибрано спосіб доставки;
- кнопка відправлення недоступна, поки не виконано необхідні умови.

### Приклад

    <label for="username">Ім'я користувача</label>
    <input
      id="username"
      name="username"
      type="text"
      disabled
    >

CSS:

    input:disabled {
      background-color: #f3f4f6;
      color: #6b7280;
      border-color: #d1d5db;
      cursor: not-allowed;
    }

### Група полів

Якщо всі елементи групи повинні бути недоступними, можна використовувати `<fieldset disabled>`.

    <fieldset disabled>
      <legend>Дані доставки</legend>

      <label for="city">Місто</label>
      <input id="city" name="city">

      <label for="address">Адреса</label>
      <input id="address" name="address">
    </fieldset>

Атрибут `disabled` на `fieldset` вимикає більшість елементів форми всередині нього. Є окремі правила для елементів усередині першого `legend`.

Це зручно, коли потрібно тимчасово вимкнути цілу групу полів.

---

## 10. Disabled і валідація форми

Disabled state часто пов'язаний із перевіркою введених даних.

Наприклад, кнопку «Створити акаунт» можна зробити доступною після заповнення обов'язкових полів.

Але є важливий нюанс: **не завжди потрібно блокувати кнопку до того, як користувач почне взаємодіяти з формою.**

Якщо користувач бачить недоступну кнопку, але не розуміє причини, це може погіршити досвід.

### Два можливі підходи

**Підхід 1. Кнопка недоступна до виконання умов**

    Усі обов'язкові поля заповнені
      → кнопка доступна

    Не всі поля заповнені
      → кнопка недоступна

Цей підхід доречний, якщо умови доступності зрозумілі й очевидні.

**Підхід 2. Кнопка доступна, а перевірка виконується після натискання**

    Користувач натискає «Надіслати»
      → форма перевіряється
      → якщо є помилки, вони показуються біля відповідних полів

Цей підхід дозволяє користувачеві отримати пояснення, чого саме бракує.

### Що потрібно врахувати

- Чи зрозуміло, чому кнопка недоступна?
- Чи може користувач визначити, що потрібно зробити?
- Чи не приховує disabled важливу інформацію?
- Чи можна показати помилки після спроби відправлення?
- Чи перевіряються дані також на сервері?

Disabled state не замінює перевірку даних на клієнті та сервері.

---

## 11. Як пояснювати причину Disabled

Іноді недостатньо просто зробити компонент сірим.

Наприклад, кнопка «Оплатити» може бути недоступною, тому що користувач ще не вибрав спосіб доставки.

Якщо причина неочевидна, додай коротке пояснення.

### Приклад

    Спосіб доставки:
    [ Виберіть спосіб доставки ▼ ]

    [ Оплатити ]  ← кнопка недоступна

    Підказка:
    Спочатку виберіть спосіб доставки.

Пояснення може бути розташоване:
- поруч із кнопкою;
- під групою полів;
- у тексті підказки;
- у повідомленні про поточний стан форми.

Не варто робити пояснення доступним лише через наведення миші. На сенсорних пристроях і під час клавіатурної навігації така підказка може бути недоступною.

### Коли пояснення особливо потрібне

- Причина недоступності неочевидна.
- Користувач може подумати, що інтерфейс зламався.
- Для виконання дії потрібно зробити кілька кроків.
- Недоступність пов'язана з правами доступу.
- Компонент є критично важливим для завершення процесу.

---

## 12. Disabled і доступність (Accessibility)

Disabled state повинен бути зрозумілим не лише візуально.

Потрібно враховувати:
- контраст;
- клавіатурну навігацію;
- семантику HTML;
- допоміжні технології;
- зрозумілість причини недоступності.

### Основні принципи

- ✔ Використовуй справжній атрибут `disabled`, коли він відповідає потрібній поведінці.
- ✔ Не передавай стан лише через колір.
- ✔ Не роби пояснення причини недоступності доступним тільки через hover.
- ✔ Зберігай читабельність тексту.
- ✔ Перевіряй поведінку клавіатури.
- ✔ Для нестандартних компонентів правильно повідомляй стан допоміжним технологіям.
- ✔ Не вимикай важливі функції без зрозумілої причини.

### Чи повинен Disabled мати Focus?

Для нативних HTML-елементів із `disabled` звичайна клавіатурна навігація, як правило, не переводить фокус на такий елемент.

Це може створювати проблему, якщо користувачеві потрібно зрозуміти, чому дія недоступна.

Тому причину disabled state краще пояснювати текстом або іншим доступним способом, а не розраховувати на те, що користувач сфокусується на вимкненій кнопці.

### А що з aria-disabled?

Для спеціальних компонентів іноді використовують:

    <div role="button" aria-disabled="true" tabindex="0">
      Зберегти
    </div>

Однак це лише ілюстрація атрибутів, а не рекомендована заміна звичайній кнопці.

`aria-disabled="true"` повідомляє допоміжним технологіям, що елемент недоступний, але **сам по собі не вимикає його поведінку**. JavaScript повинен запобігати активації, а компонент має правильно підтримувати клавіатурну взаємодію.

Для звичайної кнопки краще використовувати:

    <button type="button" disabled>
      Зберегти
    </button>

Нативні HTML-елементи зазвичай забезпечують більш передбачувану поведінку з меншим обсягом додаткового коду.

## 13. Disabled для посилань

Звичайне посилання `<a>` не підтримує атрибут `disabled` так, як кнопка.

Наприклад:

    <a href="/checkout" disabled>
      Оформити замовлення
    </a>

Цей запис сам по собі не вимикає посилання.

Якщо посилання повинно бути недоступним, потрібно визначити, чи справді воно має залишатися посиланням у поточному стані.

### Варіант 1. Замість посилання показати текст

Якщо переходу зараз немає, можна показати звичайний текст.

    <span class="nav-item-disabled">
      Розділ недоступний
    </span>

### Варіант 2. Використати aria-disabled

Для елемента, який зберігає семантику посилання, можна використати `aria-disabled="true"`, але необхідно також реалізувати поведінку, яка не дозволяє переходити за посиланням.

Приклад:

    <a
      href="/checkout"
      aria-disabled="true"
      class="link-disabled"
    >
      Оформити замовлення
    </a>

CSS:

    .link-disabled {
      color: #6b7280;
      text-decoration: none;
      cursor: not-allowed;
    }

**Важливо:** цей CSS не вимикає перехід. Потрібна відповідна логіка, яка запобігає активації, а також правильне керування фокусом.

Якщо перехід не повинен бути доступним узагалі, часто простіше не створювати посилання до моменту, коли дія стане доступною.

## 14. Disabled і Hover

Для недоступного компонента зазвичай не потрібно показувати звичайний hover-ефект.

Приклад:

    .button:hover:not(:disabled) {
      background-color: #1d4ed8;
    }

    .button:disabled {
      background-color: #e5e7eb;
      color: #6b7280;
      cursor: not-allowed;
    }

Селектор `:hover:not(:disabled)` дозволяє застосовувати hover-стиль лише до доступних кнопок.

### Чому це важливо

Якщо disabled-кнопка змінює колір при наведенні так само, як звичайна кнопка, користувач може очікувати, що вона доступна для натискання.

Водночас не потрібно намагатися повністю заборонити всі візуальні реакції в будь-якому середовищі. Головне — щоб disabled state залишався зрозумілим і не створював хибного враження про доступність дії.

---

## 15. Disabled і Active

Disabled-компонент не повинен виконувати звичайну дію під час натискання.

Для нативної кнопки з атрибутом `disabled` браузер не запускає її звичайну активацію.

Приклад:

    <button type="button" disabled>
      Видалити
    </button>

Однак якщо недоступність реалізована лише через CSS, поведінка може залишатися активною.

Невдалий приклад:

    .button-disabled {
      opacity: 0.5;
      pointer-events: none;
    }

Такий клас може перешкоджати взаємодії вказівником, але сам по собі не забезпечує повноцінної семантики disabled і не гарантує правильну поведінку клавіатури.

Краще:

    <button type="button" disabled>
      Видалити
    </button>

**Правило:** візуальний disabled state має відповідати реальній недоступності компонента.

## 16. Disabled і Loading

Під час виконання операції кнопку часто тимчасово вимикають.

Наприклад, після натискання «Надіслати» потрібно запобігти повторній відправці тієї самої форми.

### Приклад станів

    Default:
    [ Надіслати ]

    Loading:
    [ Завантаження... ]  ← операція виконується

    Success:
    [ Надіслано ✓ ]  ← операція завершилася

У стані loading компонент може бути недоступним для повторного натискання, але користувач повинен розуміти, що відбувається.

### Приклад HTML

    <button type="submit" disabled>
      Надсилання...
    </button>

Це лише статичний приклад. У реальному застосунку стан кнопки має змінюватися залежно від процесу відправлення форми.

### Рекомендації

- Не показуй loading як звичайний disabled без пояснення.
- Використовуй текст або індикатор виконання.
- Запобігай повторному запуску операції, якщо це необхідно.
- Після завершення операції відновлюй доступність відповідно до її результату.
- Повідомляй про успіх або помилку окремо.

## 17. Disabled у дизайн-системі

У дизайн-системі disabled state потрібно стандартизувати, щоб усі компоненти поводилися послідовно.

Наприклад:

    Button
    ├── State=Default
    ├── State=Hover
    ├── State=Focus
    ├── State=Active
    └── State=Disabled

    Input
    ├── State=Default
    ├── State=Focus
    ├── State=Error
    ├── State=ReadOnly
    └── State=Disabled

    Select
    ├── State=Default
    ├── State=Open
    ├── State=Focus
    └── State=Disabled

Це приклади структури. Набір станів залежить від функції компонента.

### Що варто стандартизувати

- колір тексту;
- колір фону;
- колір рамки;
- тіні;
- курсор;
- доступність взаємодії;
- правила для hover та active;
- відмінності між disabled і read-only;
- правила пояснення причини недоступності.

### Приклад CSS-токенів

    :root {
      --disabled-bg: #e5e7eb;
      --disabled-text: #6b7280;
      --disabled-border: #d1d5db;
    }

    .button:disabled {
      background-color: var(--disabled-bg);
      color: var(--disabled-text);
      border-color: var(--disabled-border);
      box-shadow: none;
      cursor: not-allowed;
    }

Токени дозволяють змінювати вигляд disabled state в одному місці та підтримувати узгодженість компонентів.

### Важливе зауваження щодо контрасту

Не потрібно автоматично зменшувати контраст настільки, щоб текст став нечитабельним.

Для деяких неактивних елементів вимоги WCAG щодо контрасту звичайного тексту мають виняток, але це не означає, що погана читабельність є хорошим рішенням. Реальний користувач повинен розуміти назву та призначення недоступного елемента.

## 18. Disabled і світла та темна теми

Disabled state має залишатися зрозумілим у різних темах інтерфейсу.

### Світла тема

    .button:disabled {
      background-color: #e5e7eb;
      color: #6b7280;
      border-color: #d1d5db;
    }

### Темна тема

    [data-theme="dark"] .button:disabled {
      background-color: #374151;
      color: #9ca3af;
      border-color: #4b5563;
    }

Це лише приклади кольорів. Їх потрібно перевірити на реальних фонах і в контексті дизайн-системи.

### Рекомендації

- Не використовуй однакові кольори автоматично для всіх тем.
- Зберігай видимість тексту та меж компонента.
- Перевіряй різні фонові поверхні.
- Не плутай disabled із hover або active.
- Використовуй токени для світлої та темної тем.

## 19. Типові помилки

### Помилка 1. Лише зменшувати opacity

Невдалий приклад:

    .button:disabled {
      opacity: 0.3;
    }

Проблема: текст і рамка можуть стати надто блідими.

Краще визначити конкретні кольори disabled state та перевірити читабельність.

### Помилка 2. Робити компонент сірим, але залишати його активним

Невдалий приклад:

    .button-disabled {
      opacity: 0.5;
    }

Це лише змінює зовнішній вигляд.

Краще використовувати справжній атрибут `disabled` для підтримуваного HTML-елемента.

### Помилка 3. Вимикати посилання атрибутом disabled

Звичайний `<a>` не отримує повноцінної поведінки disabled лише через атрибут `disabled`.

Потрібно вибрати відповідну структуру та забезпечити правильну поведінку.

### Помилка 4. Не пояснювати причину недоступності

Користувач бачить сіру кнопку, але не розуміє, що робити далі.

Якщо причина неочевидна, додай коротке пояснення поруч.

### Помилка 5. Плутати Disabled із Read-only

Якщо користувачеві потрібно скопіювати значення, disabled може бути невдалим вибором.

Розглянь `readonly`, якщо поле повинно залишатися доступним для перегляду та копіювання.

### Помилка 6. Вимикати кнопку надто рано

Якщо кнопка недоступна ще до того, як користувач зрозумів, що потрібно заповнити, форма може здаватися зламаною.

Продумай, коли саме варто блокувати дію і як пояснити умови.

### Помилка 7. Вважати disabled засобом безпеки

Навіть якщо кнопка вимкнена на клієнті, сервер повинен перевіряти права доступу та коректність даних.

Клієнтський disabled state не захищає серверну операцію сам по собі.

### Помилка 8. Забувати про Loading

Якщо кнопка вимикається після натискання, але нічого не пояснює, користувач може подумати, що інтерфейс завис.

Використовуй відповідний loading state.

### Помилка 9. Робити текст недоступного компонента нечитабельним

Disabled не означає, що текст повинен зникнути або стати майже невидимим.

Зберігай достатню читабельність для розуміння призначення елемента.

## 20. Практичний приклад: кнопка з Enabled і Disabled

HTML:

    <button class="button" type="button">
      Продовжити
    </button>

    <button class="button" type="button" disabled>
      Недоступна дія
    </button>

CSS:

    .button {
      padding: 12px 18px;
      border: 1px solid #2563eb;
      border-radius: 8px;
      background-color: #2563eb;
      color: #ffffff;
      font: inherit;
      cursor: pointer;
    }

    .button:hover:not(:disabled) {
      background-color: #1d4ed8;
    }

    .button:focus-visible {
      outline: 3px solid #93c5fd;
      outline-offset: 3px;
    }

    .button:active:not(:disabled) {
      background-color: #1e40af;
      transform: translateY(1px);
    }

    .button:disabled {
      background-color: #e5e7eb;
      border-color: #d1d5db;
      color: #6b7280;
      box-shadow: none;
      cursor: not-allowed;
    }

### Що потрібно перевірити

1. Перша кнопка має реагувати на наведення.
2. Перша кнопка має реагувати на натискання.
3. Обидві кнопки повинні мати передбачуване оформлення.
4. Disabled-кнопка не повинна виконувати свою дію.
5. Недоступний стан має бути помітним.
6. Текст кнопки залишається читабельним.

## 21. Практичний приклад: кнопка форми

Уявімо форму, в якій кнопка доступна лише після заповнення обов'язкового поля.

HTML:

    <form class="registration-form">
      <label for="email">Електронна пошта</label>

      <input
        id="email"
        name="email"
        type="email"
        required
      >

      <button type="submit" disabled>
        Створити акаунт
      </button>
    </form>

CSS:

    .registration-form {
      display: grid;
      gap: 12px;
      max-width: 360px;
    }

    .registration-form input {
      padding: 10px 12px;
      border: 1px solid #9ca3af;
      border-radius: 6px;
      font: inherit;
    }

    .registration-form input:focus-visible,
    .registration-form button:focus-visible {
      outline: 3px solid #93c5fd;
      outline-offset: 3px;
    }

    .registration-form button:disabled {
      background-color: #e5e7eb;
      color: #6b7280;
      border-color: #d1d5db;
      cursor: not-allowed;
    }

У цьому прикладі кнопка початково недоступна.

Щоб автоматично вмикати її після заповнення поля, потрібна додаткова логіка JavaScript або фреймворку. Сам атрибут `required` не змінює `disabled` автоматично.

### Навчальне завдання

Реалізуй логіку, за якої:
1. Кнопка початково недоступна.
2. Користувач вводить електронну пошту.
3. Застосунок перевіряє значення.
4. Кнопка стає доступною лише за визначених умов.
5. Після відправлення форми користувач отримує зрозумілий результат.

Пам'ятай, що перевірка в браузері не замінює серверну валідацію.

## 22. Як проєктувати Disabled у Figma

У Figma disabled state варто передбачати як окремий варіант компонента.

### Крок 1. Створи базовий компонент

Наприклад, кнопку:
- визнач розміри;
- налаштуй текст;
- задай фон;
- визнач рамку;
- перевір контраст.

### Крок 2. Створи варіант Disabled

Зміни:
- колір фону;
- колір тексту;
- колір рамки;
- тінь;
- додаткові декоративні ефекти.

Не потрібно автоматично застосовувати однакове зменшення opacity до всіх компонентів.

### Крок 3. Визнач властивість стану

Приклад структури:

    Button
    ├── State=Default
    ├── State=Hover
    ├── State=Focus
    ├── State=Active
    └── State=Disabled

### Крок 4. Перевір зрозумілість

Переконайся, що:
- компонент виглядає недоступним;
- текст залишається читабельним;
- disabled не плутається з loading;
- причина недоступності зрозуміла, якщо це необхідно.

### Крок 5. Передай правила розробнику

У специфікації опиши:
- кольори;
- рамку;
- тіні;
- поведінку hover та active;
- умови переходу в disabled;
- спосіб повідомлення про причину недоступності.

Figma описує зовнішній вигляд. Реальне вимкнення взаємодії потрібно реалізувати в HTML, CSS та JavaScript відповідно до типу компонента.

## 23. Чекліст Disabled State

### Візуальний дизайн

- [ ] Disabled state відрізняється від enabled.
- [ ] Текст залишається читабельним.
- [ ] Рамка та фон не зливаються з поверхнею.
- [ ] Неактивний компонент не виглядає звичайною доступною кнопкою.
- [ ] Оформлення узгоджене з дизайн-системою.
- [ ] Вигляд перевірений у світлій і темній темах.

### Поведінка

- [ ] Компонент справді недоступний для передбаченої взаємодії.
- [ ] Disabled не реалізований лише через `opacity`.
- [ ] Hover та active не створюють хибного враження доступності.
- [ ] Враховано відмінність між disabled і read-only.
- [ ] Loading має зрозумілий зворотний зв'язок.
- [ ] Умови повторного ввімкнення визначені.
- [ ] Сервер перевіряє права доступу та дані незалежно від клієнтського стану.

### Доступність

- [ ] Стан передається семантично, а не лише кольором.
- [ ] Використано правильні HTML-елементи.
- [ ] Причина недоступності пояснюється, якщо вона неочевидна.
- [ ] Важливе пояснення не доступне лише через hover.
- [ ] Текст залишається достатньо читабельним.
- [ ] Нестандартні компоненти правильно повідомляють свій стан допоміжним технологіям.

## 26. Мінішпаргалка

### HTML

    <!-- Справді вимкнена кнопка -->
    <button type="button" disabled>
      Зберегти
    </button>

    <!-- Поле тільки для читання -->
    <input type="text" value="Замовлення №125" readonly>

### CSS

    /* Стиль недоступної кнопки */
    .button:disabled {
      background-color: #e5e7eb;
      color: #6b7280;
      border-color: #d1d5db;
      cursor: not-allowed;
    }

    /* Hover тільки для доступної кнопки */
    .button:hover:not(:disabled) {
      background-color: #1d4ed8;
    }

    /* Active тільки для доступної кнопки */
    .button:active:not(:disabled) {
      transform: translateY(1px);
    }

### Основні поняття

    Enabled   — компонент доступний.
    Disabled  — компонент недоступний.
    Read-only — значення можна переглядати, але не редагувати.
    Loading   — операція виконується.
    Error     — виникла помилка.
    Success   — операція завершилася успішно.
    :disabled — CSS-псевдоклас для вимкнених елементів.
    disabled  — HTML-атрибут, що вимикає підтримуваний елемент.

### Що запам'ятати

- Disabled — це стан поведінки, а не тільки зовнішнього вигляду.
- `opacity: 0.5` не вимикає компонент.
- `disabled` і `readonly` мають різне призначення.
- Звичайне посилання не вимикається атрибутом `disabled`.
- Не роби текст недоступного компонента нечитабельним.
- Пояснюй причину недоступності, якщо вона неочевидна.
- Не плутай disabled із loading або success.
- Клієнтський disabled не замінює серверну перевірку.

## 27. Головний висновок

**Disabled state — це спосіб показати, що дія наразі недоступна, але якісний інтерфейс повинен пояснювати цей стан і правильно реалізовувати його поведінку.**

Якісний disabled state повинен:
- чітко відрізнятися від доступного стану;
- зберігати читабельність;
- відповідати реальній поведінці компонента;
- не створювати хибних очікувань;
- бути узгодженим з іншими станами;
- враховувати доступність;
- пояснювати причину недоступності, якщо це потрібно.

Починай із простого: використовуй справжній атрибут `disabled` для підтримуваних HTML-елементів і додай узгоджене CSS-оформлення через `:disabled`. Потім перевір відмінності між disabled, read-only та loading, а також продумай, як користувач дізнається, що потрібно зробити для продовження.

Так disabled state стає не просто сірою кнопкою, а зрозумілою частиною поведінки інтерфейсу.
