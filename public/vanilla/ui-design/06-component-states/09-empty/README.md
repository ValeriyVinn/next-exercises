# 09. Empty States — Порожні стани інтерфейсу

## 1. Що таке Empty States?

**Empty State (порожній стан)** — це стан інтерфейсу, у якому компонент, сторінка або список не містить даних для відображення, тому користувачеві потрібно пояснити ситуацію та, за потреби, запропонувати наступну дію.

Empty State — це не просто порожній екран. Це частина UX-дизайну, яка допомагає користувачеві зрозуміти:
- Чому зараз немає даних.
- Чи є така ситуація нормальною.
- Як отримати або додати потрібні дані.
- Яку дію варто виконати далі.

Наприклад, користувач відкриває список завдань у застосунку, але ще не створив жодного завдання. Замість порожньої області інтерфейс показує повідомлення:

    У вас поки немає завдань.
    Створіть перше завдання, щоб почати працювати.

    [Створити завдання]

Такий інтерфейс не лише повідомляє про відсутність даних, а й допомагає користувачеві зробити наступний крок.

Empty States особливо важливі для:
- Dashboard — панелей керування.
- Списків товарів, завдань і повідомлень.
- Пошуку та фільтрації.
- Особистих кабінетів.
- Форм і процесів створення контенту.
- Освітніх платформ, CRM та SaaS-застосунків.
- Адміністративних панелей.

---

## 2. Для чого потрібні Empty States?

Порожній стан виконує кілька функцій.

### 2.1. Пояснення ситуації

Користувач повинен розуміти, чому список або компонент порожній.

Погано:

    Нічого немає.

Краще:

    Ви ще не створили жодного курсу.

### 2.2. Допомога новим користувачам

Користувач, який уперше відкрив застосунок, може не знати, з чого почати.

Empty State може пояснити основний сценарій використання:

    Тут відображатимуться ваші проєкти.
    Створіть перший проєкт, щоб почати роботу.

    [Створити проєкт]

### 2.3. Пропозиція наступної дії

Порожній стан часто містить кнопку або посилання, що допомагає продовжити роботу.

Приклади:
- Створити перший запис.
- Додати учня.
- Завантажити файл.
- Очистити фільтри.
- Перейти до каталогу.
- Запросити учасників.

### 2.4. Зменшення невизначеності

Без пояснення порожній екран може виглядати як помилка, незавантажена сторінка або несправність застосунку.

Правильно оформлений Empty State допомагає відрізнити нормальну відсутність даних від проблеми.

---

## 3. Основні поняття

✔ **Empty State** — стан інтерфейсу без даних для відображення.

✔ **First-use Empty State** — порожній стан для нового користувача, який ще не створив жодних даних.

✔ **No-results State** — стан, коли пошук або фільтри не повернули результатів.

✔ **Filtered Empty State** — стан, коли дані існують, але поточні фільтри приховали всі записи.

✔ **Cleared State** — стан після видалення або очищення всіх записів.

✔ **Unavailable State** — стан, коли потрібні дані тимчасово недоступні.

✔ **Call to Action (CTA)** — основна дія, яку пропонується виконати користувачеві.

✔ **Illustration** — ілюстрація, яка візуально підтримує повідомлення.

✔ **Empty Container** — компонент або область, у якій немає даних.

✔ **Recovery Action** — дія, яка допомагає користувачеві вийти з небажаного стану, наприклад скинути фільтри.

✔ **Content Hierarchy** — порядок візуальної важливості повідомлення, пояснення та дії.

✔ **Loading State** — стан очікування даних. Він не є Empty State, хоча на початку завантаження список ще може бути порожнім.

---

## 4. Типова структура Empty State

Базовий Empty State може складатися з чотирьох елементів:

    ┌─────────────────────────────────┐
    │                                 │
    │          [Ілюстрація]           │
    │                                 │
    │       Немає створених курсів    │
    │                                 │
    │  Створіть перший курс, щоб      │
    │  додати навчальні матеріали.    │
    │                                 │
    │       [Створити курс]           │
    │                                 │
    └─────────────────────────────────┘

### 4.1. Ілюстрація або іконка

Допомагає швидко зрозуміти зміст повідомлення.

Наприклад:
- Папка — немає файлів.
- Дзвіночок — немає сповіщень.
- Повідомлення — немає листування.
- Кошик — кошик порожній.
- Лупа — нічого не знайдено.

Ілюстрація необов'язкова. Для компактних компонентів часто достатньо іконки або тексту.

### 4.2. Заголовок

Коротко повідомляє про поточний стан.

Приклади:

    Немає повідомлень

    Ви ще не створили проєктів

    За вашим запитом нічого не знайдено

Заголовок повинен бути зрозумілим без необхідності читати весь текст.

### 4.3. Пояснення

Допомагає зрозуміти причину або наступний крок.

Приклади:

    Нові повідомлення з'являться тут.

    Створіть перший проєкт, щоб організувати свою роботу.

    Спробуйте змінити пошуковий запит або прибрати фільтри.

### 4.4. Основна дія

Допомагає перейти до наступного кроку.

Приклади:

    [Створити проєкт]

    [Додати учня]

    [Скинути фільтри]

    [Перейти до каталогу]

Не кожен Empty State потребує кнопки. Якщо користувачеві достатньо інформаційного повідомлення, додаткова дія може бути зайвою.

## 5. Основні типи Empty States

### 5.1. First-use Empty State

**Порожній стан першого використання** з'являється, коли користувач ще не створив жодних даних.

Приклад: новий користувач відкриває сторінку проєктів.

    Ви ще не маєте проєктів.

    Створіть проєкт, щоб зібрати завдання
    та матеріали в одному місці.

    [Створити проєкт]

Основна мета:
- Познайомити користувача з можливістю.
- Пояснити призначення розділу.
- Запропонувати перший крок.

Дизайнер повинен уникати припущення, що користувач уже знає, як працює застосунок.

### 5.2. No-results State

**Стан відсутності результатів пошуку** з'являється, коли пошуковий запит не знаходить відповідних записів.

Приклад:

    За вашим запитом нічого не знайдено.

    Перевірте написання або спробуйте
    інші ключові слова.

    [Очистити пошук]

Основна мета:
- Повідомити про результат пошуку.
- Не створювати враження, що застосунок зламався.
- Допомогти змінити запит.

Важливо: не плутати відсутність результатів пошуку з відсутністю всіх даних у системі.

### 5.3. Filtered Empty State

Цей стан виникає, коли записи існують, але вибрані фільтри не дозволяють показати жодного з них.

Приклад:

    Немає завдань із такими фільтрами.

    Спробуйте змінити статус або
    прибрати частину фільтрів.

    [Скинути фільтри]

Ключова особливість: потрібно пояснити, що проблема пов'язана з поточними критеріями відбору, а не з повною відсутністю даних.

### 5.4. Cleared Empty State

З'являється після видалення або очищення всіх записів.

Приклад:

    У кошику немає товарів.

    Додайте товари з каталогу,
    щоб продовжити покупки.

    [Перейти до каталогу]

Такий стан повинен відповідати контексту попередньої дії користувача.

### 5.5. Empty State для повідомлень

Приклад:

    Поки немає повідомлень.

    Коли ви отримаєте нове повідомлення,
    воно з'явиться тут.

Іноді кнопка не потрібна, оскільки повідомлення надходитимуть автоматично.

### 5.6. Empty State для сповіщень

Приклад:

    У вас немає нових сповіщень.

    Ми повідомимо вас, коли з'являться оновлення.

Такий стан повинен бути спокійним і не створювати враження, що користувач має щось зробити.

### 5.7. Empty State у Dashboard

Панель керування може містити кілька незалежних компонентів без даних.

Наприклад:

    Активні курси
    Поки немає активних курсів.

    Найближчі завдання
    Ви ще не додали завдань.

    Останні повідомлення
    Нових повідомлень немає.

Не обов'язково перетворювати всю панель на один великий Empty State. Часто краще показувати окремі компактні стани всередині відповідних віджетів.

### 5.8. Empty State через недоступність даних

Якщо дані не завантажилися через мережеву помилку або серверну проблему, не варто повідомляти, що список просто порожній.

Це вже інший стан — Error State.

Приклад:

    Не вдалося завантажити проєкти.

    Перевірте підключення та спробуйте ще раз.

    [Повторити]

**Важливо:** порожні дані та помилка завантаження — різні ситуації, які потребують різних повідомлень.

---

## 6. Empty State, Loading State та Error State

Ці стани можуть зовні бути схожими, але мають різне призначення.

| Стан | Що відбувається | Приклад повідомлення |
|---|---|---|
| Empty | Дані успішно отримано, але записів немає | Ви ще не створили проєктів |
| Loading | Дані завантажуються | Завантаження проєктів... |
| Error | Не вдалося отримати дані | Не вдалося завантажити проєкти |
| No results | Пошук не знайшов збігів | Нічого не знайдено |
| Filtered empty | Фільтри приховали всі записи | Немає результатів із такими фільтрами |
| Success | Дію успішно завершено | Проєкт створено |

### Приклад послідовності станів

    Початок запиту
        ↓
    Loading State
        ↓
    ┌──────────────────────────┐
    │ Результат запиту         │
    └──────────────────────────┘
        ↓
    ┌──────────┬───────────┐
    │          │           │
    Дані є    Даних немає  Помилка
    │          │           │
    Список    Empty       Error
              State       State

Під час проєктування потрібно передбачити всі основні результати запиту, а не тільки стан із даними.

---

## 7. Візуальна ієрархія Empty State

Порожній стан повинен бути зрозумілим і не перевантаженим.

Типовий порядок елементів:

1. Ілюстрація або іконка.
2. Заголовок.
3. Коротке пояснення.
4. Основна дія.
5. Необов'язкове додаткове посилання.

### Приклад

    [Іконка папки]

    Поки немає файлів

    Завантажте перший файл,
    щоб він з'явився у вашому сховищі.

    [Завантажити файл]

    Дізнатися більше про сховище

### Принципи ієрархії

- Заголовок повинен бути помітнішим за пояснення.
- Пояснення повинно бути коротким.
- Основна кнопка має чітко відрізнятися від другорядних дій.
- Ілюстрація не повинна конкурувати з текстом.
- Усі елементи повинні утворювати єдину композицію.

Не потрібно використовувати велику декоративну ілюстрацію в кожному порожньому стані. Для невеликого списку або картки достатньо лаконічного тексту.

## 8. Розташування та композиція

Empty State може розташовуватися в різних частинах інтерфейсу.

### 8.1. По центру сторінки

Підходить для:
- Першого використання розділу.
- Порожнього головного списку.
- Повноекранного робочого простору.

    ┌──────────────────────────────┐
    │                              │
    │                              │
    │       Немає проєктів         │
    │                              │
    │     [Створити проєкт]        │
    │                              │
    │                              │
    └──────────────────────────────┘

### 8.2. Усередині списку

Підходить для таблиць, каталогів і списків.

    ┌─────────────────────────────────────┐
    │ Назва       Статус       Дата       │
    ├─────────────────────────────────────┤
    │                                     │
    │         Немає записів               │
    │                                     │
    │       [Додати запис]                │
    │                                     │
    └─────────────────────────────────────┘

Тут важливо зберегти контекст компонента, щоб користувач розумів, до якого саме списку належить повідомлення.

### 8.3. Усередині картки

Підходить для Dashboard і віджетів.

    ┌──────────────────────────────┐
    │ Найближчі завдання           │
    ├──────────────────────────────┤
    │                              │
    │ Завдань поки немає           │
    │                              │
    │ [+ Додати завдання]          │
    └──────────────────────────────┘

### 8.4. Усередині модального вікна

Якщо користувач відкрив діалог, у якому немає записів, повідомлення повинно бути компактним і відповідати контексту діалогу.

### 8.5. Усередині випадаючого списку

Наприклад, користувач відкриває список доступних категорій, але жодної категорії ще не створено.

    Категорій поки немає.

    Створіть категорію в налаштуваннях.

Для такого компонента краще уникати великих ілюстрацій і складних композицій.

## 9. Відступи, розміри та читабельність

Empty State повинен мати достатньо вільного простору, але не займати більше місця, ніж потрібно.

### 9.1. Внутрішні відступи

Приклад початкових значень для дизайн-системи:

    --empty-state-padding-sm: 16px;
    --empty-state-padding-md: 24px;
    --empty-state-padding-lg: 40px;

Це приклад шкали, а не універсальний стандарт. Значення залежать від розміру компонента.

### 9.2. Розміри ілюстрацій

Приклад:

    --empty-state-icon-sm: 24px;
    --empty-state-icon-md: 40px;
    --empty-state-illustration-lg: 120px;

Маленькі компоненти зазвичай потребують невеликих іконок, а великі сторінкові стани можуть використовувати ілюстрації.

### 9.3. Ширина тексту

Не варто розтягувати коротке повідомлення на всю ширину великого екрана.

Приклад CSS:

    .empty-state__content {
      width: 100%;
      max-width: 420px;
      margin-inline: auto;
      text-align: center;
    }

Обмеження ширини допомагає зберегти читабельність і візуальну цілісність.

### 9.4. Відстані між елементами

Важливо створити послідовний ритм:

    Іконка
      ↓
    Відступ
      ↓
    Заголовок
      ↓
    Невеликий відступ
      ↓
    Пояснення
      ↓
    Відступ
      ↓
    Кнопка

Конкретні відстані залежать від дизайн-системи та розміру компонента.

## 10. Колір і візуальний стиль

Empty State зазвичай не повинен виглядати як критичне попередження.

### 10.1. Нейтральні кольори

Для звичайного порожнього стану можна використовувати:
- Нейтральний колір тексту.
- Приглушений колір допоміжного тексту.
- Нейтральну іконку.
- Основний колір бренду для CTA.

### 10.2. Не використовувати Error-стиль без потреби

Погано: червоне попередження для повідомлення «У вас немає повідомлень».

Краще: спокійна іконка, нейтральний текст і достатньо вільного простору.

Червоний колір доцільний, коли йдеться про справжню помилку або ризик, а не про звичайну відсутність даних.

### 10.3. Контраст

Текст і кнопки повинні залишатися читабельними на фоні компонента.

Не варто робити пояснення настільки світлим, що воно стає важким для сприйняття.

---

## 11. Текст і мікрокопірайтинг

Мікрокопірайтинг — це короткі тексти інтерфейсу, які допомагають користувачеві зрозуміти ситуацію та виконати дію.

Для Empty State текст особливо важливий, тому що інших даних на екрані може не бути.

### 11.1. Формула повідомлення

Зручна базова формула:

    Поточний стан
    +
    Причина або пояснення
    +
    Наступний крок

Приклад:

    Ви ще не створили курс.

    Додайте перший курс, щоб організувати
    навчальні матеріали.

    [Створити курс]

### 11.2. Заголовок повинен бути конкретним

Погано:

    Порожньо

Краще:

    У вас поки немає завдань

Ще краще, якщо контекст вимагає конкретної дії:

    Створіть перше завдання

### 11.3. Пояснення повинно бути коротким

Погано:

    У цьому розділі наразі не відображається жодного елемента,
    оскільки ви ще не виконали відповідні дії з додавання
    інформації до системи.

Краще:

    Додайте перший запис, щоб він з'явився тут.

### 11.4. Використовуйте зрозумілі дієслова

Приклади:
- Створити.
- Додати.
- Завантажити.
- Знайти.
- Очистити.
- Повторити.
- Переглянути.
- Запросити.

### 11.5. Не звинувачуйте користувача

Погано:

    Ви неправильно налаштували пошук.

Краще:

    За цими критеріями нічого не знайдено.
    Спробуйте змінити фільтри.

Текст повинен допомагати, а не створювати відчуття помилки з боку користувача.

## 12. CTA — основна дія

CTA (Call to Action) — елемент інтерфейсу, який пропонує користувачеві виконати наступну дію.

У Empty State кнопка часто є головним інтерактивним елементом.

### 12.1. Одна основна дія

Наприклад:

    У вас ще немає проєктів.

    [Створити проєкт]

Одна чітка дія допомагає швидко зрозуміти, що робити далі.

### 12.2. Основна та другорядна дії

Іноді доречно запропонувати дві дії:

    Ви ще не додали учнів.

    [Додати учня]

    Імпортувати список учнів

Основна дія повинна мати вищу візуальну вагу.

### 12.3. CTA має відповідати контексту

Якщо немає результатів пошуку, кнопка «Створити проєкт» може бути недоречною.

Для пошуку логічніше запропонувати:
- Очистити пошук.
- Змінити фільтри.
- Переглянути всі записи.

### 12.4. Не створюйте зайві дії

Не кожен порожній стан потребує кнопки.

Наприклад:

    У вас немає нових сповіщень.

Це може бути достатнім повідомленням.

## 13. Empty States у дизайн-системі

Якщо в застосунку багато списків і віджетів, доцільно створити повторно використовуваний компонент Empty State.

Можливі властивості компонента:

    EmptyState
    ├── icon
    ├── title
    ├── description
    ├── primaryAction
    ├── secondaryAction
    ├── size
    └── alignment

### 13.1. Варіанти розміру

    Small
    ├── Невелика іконка
    ├── Короткий текст
    └── Компактний відступ

    Medium
    ├── Іконка
    ├── Заголовок
    ├── Пояснення
    └── За потреби кнопка

    Large
    ├── Ілюстрація
    ├── Заголовок
    ├── Пояснення
    └── Основна дія

### 13.2. Варіанти вирівнювання

- `center` — центроване повідомлення.
- `start` — вирівнювання на початку контейнера.
- `inline` — компактний стан у рядку або невеликій області.

Назви варіантів можна адаптувати до правил конкретної дизайн-системи.

### 13.3. Чому потрібен спільний компонент?

Спільний компонент допомагає:
- Уніфікувати відступи.
- Зберігати однакову типографіку.
- Забезпечити послідовні CTA.
- Спрощувати підтримку.
- Уникати дублювання стилів.
- Легше тестувати різні варіанти станів.

Водночас не всі Empty States повинні бути абсолютно однаковими. Їхній зміст і дія залежать від контексту.

## 16. Empty State у React

У React стан інтерфейсу часто залежить від масиву даних.

### 16.1. Простий компонент

    type EmptyStateProps = {
      title: string;
      description?: string;
      actionLabel?: string;
      onAction?: () => void;
    };

    function EmptyState({
      title,
      description,
      actionLabel,
      onAction,
    }: EmptyStateProps) {
      return (
        <section className="empty-state">
          <h2 className="empty-state__title">{title}</h2>

          {description && (
            <p className="empty-state__description">
              {description}
            </p>
          )}

          {actionLabel && onAction && (
            <button
              type="button"
              className="empty-state__action"
              onClick={onAction}
            >
              {actionLabel}
            </button>
          )}
        </section>
      );
    }

У цьому прикладі:
- `title` — обов'язковий заголовок.
- `description` — необов'язкове пояснення.
- `actionLabel` — текст кнопки.
- `onAction` — функція, яка виконується після натискання.

Використовується TypeScript без `any`.

### 16.2. Відображення списку або Empty State

    type Project = {
      id: number;
      name: string;
    };

    type ProjectListProps = {
      projects: Project[];
    };

    function ProjectList({ projects }: ProjectListProps) {
      if (projects.length === 0) {
        return (
          <EmptyState
            title="У вас поки немає проєктів"
            description="Створіть перший проєкт, щоб почати роботу."
          />
        );
      }

      return (
        <ul>
          {projects.map((project) => (
            <li key={project.id}>
              {project.name}
            </li>
          ))}
        </ul>
      );
    }

У цьому компоненті:
- Якщо масив порожній, показується Empty State.
- Якщо записи є, показується список.
- `key` допомагає React ідентифікувати елементи списку.

**Важливо:** такий приклад передбачає, що дані вже отримано. Якщо запит ще виконується або завершився помилкою, потрібно окремо обробити Loading State та Error State.

### 16.3. Обробка завантаження

    type ProjectsViewProps = {
      projects: Project[];
      isLoading: boolean;
      hasError: boolean;
    };

    function ProjectsView({
      projects,
      isLoading,
      hasError,
    }: ProjectsViewProps) {
      if (isLoading) {
        return <p>Завантаження проєктів...</p>;
      }

      if (hasError) {
        return <p>Не вдалося завантажити проєкти.</p>;
      }

      if (projects.length === 0) {
        return (
          <EmptyState
            title="У вас поки немає проєктів"
            description="Створіть перший проєкт, щоб почати роботу."
          />
        );
      }

      return (
        <ul>
          {projects.map((project) => (
            <li key={project.id}>
              {project.name}
            </li>
          ))}
        </ul>
      );
    }

Послідовність перевірок важлива:
1. Спочатку очікуємо завершення завантаження.
2. Потім обробляємо помилку.
3. Після успішного завантаження перевіряємо наявність даних.
4. Якщо записи є, відображаємо список.

Це допомагає уникнути помилкового повідомлення про порожній список, поки дані ще не отримані.

## 17. Empty State у Next.js

У Next.js App Router сторінка може отримувати дані із сервера та відображати Empty State після їх завантаження.

### 17.1. Серверний компонент

    type Project = {
      id: number;
      name: string;
    };

    async function getProjects(): Promise<Project[]> {
      // Тут має бути запит до бази даних або API.
      return [];
    }

    export default async function ProjectsPage() {
      const projects = await getProjects();

      if (projects.length === 0) {
        return (
          <main>
            <h1>Мої проєкти</h1>

            <section className="empty-state">
              <h2>У вас поки немає проєктів</h2>

            </section>

      }

      return (
        <main>
          <h1>Мої проєкти</h1>

          <ul>
            {projects.map((project) => (
              <li key={project.id}>
                {project.name}
              </li>
            ))}
          </ul>
        </main>
      );
    }

У цьому прикладі `getProjects()` повертає порожній масив для демонстрації.

У реальному застосунку потрібно:
- Отримувати дані з реального джерела.
- Обробляти помилки запиту.
- За потреби показувати стан завантаження через механізми Next.js.
- Перевіряти, чи має користувач право переглядати відповідні дані.

Для навігації всередині Next.js зазвичай використовують компонент `Link` з `next/link`.

### 17.2. Loading UI та Empty State — не одне й те саме

У Next.js можна створити `loading.tsx` для відображення інтерфейсу під час завантаження сторінки.

При цьому Empty State має з'являтися після того, як застосунок отримав успішний результат і визначив, що записів немає.

Не варто використовувати порожній масив як універсальний сигнал, що дані ще не завантажені.

## 18. Empty State для пошуку та фільтрів

Пошук і фільтрація потребують окремої уваги, тому що в цих випадках записи можуть існувати, але бути прихованими умовами відбору.

### 18.1. Відсутність результатів пошуку

    Нічого не знайдено.

    Спробуйте змінити пошуковий запит.

    [Очистити пошук]

### 18.2. Відсутність результатів фільтрації

    Немає завдань, що відповідають фільтрам.

    Спробуйте вибрати інший статус.

    [Скинути фільтри]

### 18.3. Чому це важливо?

Якщо користувач бачить повідомлення «У вас немає завдань», він може вирішити, що всі завдання видалено.

Якщо насправді список просто відфільтровано, таке повідомлення вводить в оману.

Тому повідомлення повинно описувати реальну причину відсутності видимих записів.

### 18.4. Приклад логіки

    const filteredTasks = tasks.filter((task) => {
      return task.status === selectedStatus;
    });

    if (filteredTasks.length === 0) {
      // Показати Empty State для фільтрів.
    }

Це лише фрагмент логіки. У реальному компоненті потрібно врахувати, чи є початковий масив `tasks` порожнім, чи результат став порожнім саме після фільтрації.

## 19. Доступність (Accessibility)

Empty State повинен бути зрозумілим усім користувачам, включно з тими, хто використовує клавіатуру або допоміжні технології.

### 19.1. Семантичні заголовки

Використовуй логічну структуру заголовків.

Наприклад:

    <section aria-labelledby="empty-projects-title">
      <h2 id="empty-projects-title">
        У вас поки немає проєктів
      </h2>

      <p>
        Створіть перший проєкт, щоб почати роботу.
      </p>
    </section>

Рівень заголовка повинен відповідати структурі сторінки, а не вибиратися лише через його розмір.

### 19.2. Декоративні іконки

Якщо іконка не додає змісту, її можна приховати від скринридера.

    <svg aria-hidden="true">
      <!-- Декоративна іконка -->
    </svg>

Якщо зображення передає важливу інформацію, потрібно надати відповідний текстовий опис.

### 19.3. Клавіатурна навігація

Якщо Empty State містить кнопку або посилання:
- Користувач повинен мати змогу перейти до нього клавіатурою.
- Фокус повинен бути видимим.
- Натискання клавіш має працювати очікувано.
- Не можна прибирати outline без доступної альтернативи.

### 19.4. Контраст

Текст, іконки та інтерактивні елементи повинні залишатися видимими на фоні.

Не покладайся лише на колір для пояснення стану.

### 19.5. Не використовуй надмірні повідомлення

Не потрібно оголошувати скринридеру кожну декоративну зміну або повторювати одне й те саме повідомлення багато разів.

Якщо стан динамічно змінюється, механізм повідомлення про зміну потрібно продумати окремо.

## 20. Адаптивність і мобільні пристрої

Empty State повинен добре виглядати на різних розмірах екрана.

### 20.1. На великих екранах

Можна використовувати:
- Більшу ілюстрацію.
- Ширший контейнер.
- Більші відступи.
- Центровану композицію.

### 20.2. На мобільних пристроях

Потрібно:
- Зменшити надмірні відступи.
- Обмежити ширину тексту.
- Не допускати горизонтального прокручування.
- Переконатися, що кнопки поміщаються на екрані.
- Зберегти достатню висоту інтерактивних елементів.
- Перевірити довгі заголовки та локалізований текст.

### 20.3. Приклад адаптивного CSS

    .empty-state {
      padding: 40px 24px;

    .empty-state__description {
      max-width: 420px;

        max-width: 100%;

Це базовий приклад. Якщо текст або кнопка можуть бути довгими, перевір їхню поведінку на вузькому екрані.

Користувач не розуміє, чи це нормальний стан, чи помилка.

Краще:

    Тут поки немає записів.
    Додайте перший запис, щоб почати роботу.

### 22.2. Надто загальний текст

Погано:

    Нічого немає.

Краще:

    У вас поки немає збережених статей.

### 22.3. Невідповідна кнопка

Погано:

    Нічого не знайдено.
    [Створити акаунт]

Якщо користувач шукає товар або документ, така дія не відповідає його наміру.

Краще:

    Нічого не знайдено.
    [Очистити пошук]

### 22.4. Занадто багато кнопок

Погано:

    Немає проєктів.

    [Створити]
    [Імпортувати]
    [Завантажити]
    [Переглянути довідку]
    [Відкрити налаштування]

Занадто багато рівнозначних дій ускладнюють вибір.

Краще визначити одну основну дію, а додаткові пропонувати лише тоді, коли вони справді потрібні.

### 22.5. Надмірна ілюстрація

Велика ілюстрація може відволікати від основної дії та займати надто багато простору.

Використовуй її тоді, коли вона допомагає зрозуміти контекст або створює потрібне емоційне враження.

### 22.6. Empty State замість Loading State

Погано:

    Список ще не завантажився.
    Даних немає.

Якщо запит ще виконується, відсутність даних не підтверджена.

Краще спочатку показати Loading State, а потім відобразити фактичний результат.

### 22.7. Empty State замість Error State

Якщо сервер повернув помилку, не потрібно показувати повідомлення про відсутність записів.

Користувач повинен знати, що дані не вдалося отримати.

### 22.8. Не враховано фільтри

Якщо записи приховано фільтрами, не слід повідомляти, що в користувача взагалі немає даних.

Потрібно пояснити, що саме поточний пошук або фільтри не дали результатів.

### 22.9. Немає доступної дії

Якщо наступний крок очевидний і необхідний, але користувачеві не запропоновано його виконати, він може не зрозуміти, як продовжити.

Наприклад, якщо сторінка призначена для створення курсів, доречно запропонувати створити перший курс.

### 22.10. Занадто багато тексту

Empty State не повинен перетворюватися на довгу інструкцію.

Залишай лише ту інформацію, яка допомагає зрозуміти стан і зробити наступний крок.

## 23. Перевірка Empty State

Перед завершенням дизайну перевір такі сценарії.

### Функціональність

- [ ] Порожній стан показується, коли дані успішно завантажено, але записів немає.
- [ ] Кнопка виконує правильну дію.
- [ ] Посилання веде до потрібної сторінки.
- [ ] Після створення запису Empty State зникає.
- [ ] Після видалення останнього запису Empty State з'являється.
- [ ] Фільтри й пошук показують відповідні повідомлення.
- [ ] Помилки запиту не маскуються під порожній список.

### Візуальна якість

- [ ] Заголовок легко помітити.
- [ ] Пояснення читабельне.
- [ ] Ілюстрація відповідає контексту.
- [ ] Відступи послідовні.
- [ ] Кнопка не губиться в композиції.
- [ ] Компонент не перевантажений.

### Accessibility

- [ ] Заголовки мають логічну структуру.
- [ ] Інтерактивні елементи доступні з клавіатури.
- [ ] Фокус добре видно.
- [ ] Контраст тексту достатній.
- [ ] Декоративні зображення не створюють зайвого шуму для скринридера.

### Адаптивність

- [ ] Компонент працює на мобільному екрані.
- [ ] Довгі тексти не ламають макет.
- [ ] Кнопки не виходять за межі контейнера.
- [ ] Компонент працює у світлій і темній темах.

## 24. Практичні вправи

### Вправа 1. Порожній список завдань

Створи Empty State для сторінки завдань.

Умови:
- Іконка або проста графіка.
- Заголовок.
- Коротке пояснення.
- Кнопка «Створити завдання».

Мета: навчитися будувати базову композицію.

### Вправа 2. Порожній каталог курсів

Створи Empty State для освітньої платформи.

Текст:

    Поки немає доступних курсів.

    Спробуйте повернутися пізніше
    або перегляньте інші навчальні матеріали.

Мета: навчитися працювати зі станом, у якому основна дія не обов'язково є створенням нового запису.

### Вправа 3. Пошук без результатів

Створи стан для каталогу, у якому пошук нічого не знайшов.

Обов'язкові елементи:
- Заголовок.
- Пояснення.
- Кнопка очищення пошуку.

Мета: відрізняти No-results State від First-use Empty State.

### Вправа 4. Відфільтрований список

Створи Empty State для списку завдань, у якому немає записів із вибраним статусом.

Обов'язкові елементи:
- Повідомлення про відсутність збігів.
- Коротка підказка.
- Кнопка «Скинути фільтри».

Мета: навчитися пояснювати причину відсутності видимих даних.

### Вправа 5. Компонент Empty State у React

Створи компонент `EmptyState` із властивостями:
- `title`.
- `description`.
- `actionLabel`.
- `onAction`.

Потім використай його у списку проєктів.

Мета: навчитися повторно використовувати UI-компонент.

### Вправа 6. Набір Empty States для Dashboard

Створи три віджети:
- Активні курси.
- Найближчі завдання.
- Останні повідомлення.

Кожен віджет повинен мати власний Empty State.

Мета: навчитися адаптувати спільний компонент до різних контекстів.

## 26. Питання для співбесіди

### Базовий рівень

**1. Що таке Empty State?**

Стан інтерфейсу, у якому немає даних для відображення, і користувачеві потрібно пояснити цю ситуацію.

**2. Для чого потрібен Empty State?**

Щоб пояснити причину відсутності даних, зменшити невизначеність і, за потреби, запропонувати наступну дію.

**3. З яких елементів може складатися Empty State?**

З іконки або ілюстрації, заголовка, пояснення та основної дії. Не всі елементи обов'язкові.

**4. Чим Empty State відрізняється від Loading State?**

Empty State показує, що дані успішно отримано, але записів немає. Loading State означає, що дані ще завантажуються.

**5. Чим Empty State відрізняється від Error State?**

Empty State є нормальним результатом успішного запиту без записів. Error State повідомляє про проблему, через яку дані не вдалося отримати або обробити.

### Середній рівень

**6. Що таке First-use Empty State?**

Стан для користувача, який ще не створив даних у певному розділі.

**7. Що таке No-results State?**

Стан, у якому пошук не знайшов записів, що відповідають запиту.

**8. Чим No-results State відрізняється від Filtered Empty State?**

No-results State пов'язаний із пошуковим запитом. Filtered Empty State виникає, коли вибрані фільтри не залишають видимих записів.

**9. Чи повинен кожен Empty State мати кнопку?**

Ні. Кнопка потрібна тоді, коли існує корисна наступна дія. Для суто інформаційних станів достатньо повідомлення.

**10. Чому не можна показувати Empty State до завершення завантаження?**

Тому що відсутність даних ще не підтверджена. Потрібно спочатку дочекатися результату запиту.

### Просунутий рівень

**11. Як спроєктувати Empty State для дизайн-системи?**

Визначити спільну структуру, властивості, розміри, варіанти вирівнювання та правила використання CTA, а потім перевірити компонент у різних контекстах.

**12. Як забезпечити доступність Empty State?**

Використовувати семантичні заголовки, достатній контраст, доступні інтерактивні елементи та видимий фокус. Декоративні іконки не повинні створювати зайвий шум для скринридера.

**13. Як реалізувати Empty State у React?**

Перевірити стан даних і відобразити Empty State, якщо запит успішний, а масив записів порожній. Loading і Error потрібно обробляти окремо.

**14. Як тестувати Empty State?**

Перевірити відсутність даних, появу першого запису, видалення останнього запису, пошук без результатів, фільтри, помилки запитів і роботу CTA.

**15. Чому Empty State важливий для UX?**

Тому що він перетворює порожню область на зрозумілий стан інтерфейсу та допомагає користувачеві продовжити роботу.

## 29. Що потрібно пам'ятати

1. Empty State — це повноцінний стан інтерфейсу, а не просто порожній простір.
2. Користувач повинен розуміти, чому немає даних.
3. Заголовок має бути конкретним і зрозумілим.
4. Пояснення повинно допомагати, а не перевантажувати.
5. CTA доречна тоді, коли існує корисна наступна дія.
6. First-use, No-results і Filtered Empty — різні сценарії.
7. Loading State не можна плутати з Empty State.
8. Помилка завантаження не повинна маскуватися під порожній список.
9. Композиція має відповідати розміру контейнера та контексту.
10. Ілюстрація необов'язкова — іноді достатньо тексту.
11. Empty State повинен працювати на мобільних пристроях і в темній темі.
12. Доступність стосується заголовків, тексту, іконок і кнопок.
13. У React і Next.js спочатку потрібно визначити реальний стан запиту, а потім вибирати відповідний UI.
14. Повторно використовуваний компонент допомагає зберігати послідовність дизайну.
15. Найкращий Empty State пояснює ситуацію та допомагає користувачеві продовжити роботу.

**Головна ідея:** Empty State повинен відповідати на два запитання користувача: «Чому тут нічого немає?» і «Що мені робити далі?».
