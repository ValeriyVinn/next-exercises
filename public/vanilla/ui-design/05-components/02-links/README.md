# 02. Links

Links (посилання) — це UI-компоненти, які дозволяють користувачеві переходити між сторінками, відкривати зовнішні ресурси, переходити до певних секцій сторінки або запускати навігаційні дії.

У UI Design links використовуються для побудови навігації, зв'язування контенту та забезпечення зрозумілого переміщення користувача інтерфейсом.

Посилання можуть бути звичайним текстом, елементом навігаційного меню, частиною картки, кнопкою-посиланням або окремим елементом у списку дій.

Основні типи links:

    text links
    inline links
    navigation links
    external links
    anchor links
    breadcrumb links
    icon links
    button-style links
    download links
    contextual links

### Що потрібно пам'ятати

• Link — інтерактивний елемент, який веде до іншого ресурсу або місця призначення.

• В HTML для звичайних посилань використовується елемент `<a>`.

• Атрибут `href` визначає адресу або місце, куди веде посилання.

• Текст посилання має зрозуміло пояснювати, куди воно веде.

• Посилання повинно візуально відрізнятися від звичайного тексту.

• Підкреслення — один із найнадійніших способів показати, що текст є посиланням.

• Колір не повинен бути єдиним способом відрізнити посилання від звичайного тексту.

• Links повинні мати зрозумілі стани: default, hover, focus, active та, за потреби, visited.

• Клавіатурна навігація має дозволяти знаходити посилання та переходити за ними без миші.

• Focus indicator повинен бути добре помітним.

• Для зовнішніх посилань не завжди потрібно відкривати нову вкладку. Це залежить від призначення та контексту.

• Якщо посилання відкривається в новій вкладці, користувача бажано попередити про це, коли така поведінка може бути несподіваною.

• Link і button мають різне призначення: link забезпечує навігацію, button виконує дію.

• Візуальний вигляд посилання повинен відповідати його ролі в інтерфейсі.

• Надмірна кількість посилань в одному блоці може ускладнювати сканування контенту.

• Довгі або неоднозначні тексти посилань знижують зрозумілість інтерфейсу.

• Іконка без тексту потребує доступної назви.

• UI Design визначає зовнішній вигляд і поведінкові очікування компонента, а HTML та CSS реалізують його в браузері.

# Що таке Link

Link (посилання) — це елемент інтерфейсу, який дозволяє перейти до певного місця призначення.

Місцем призначення може бути:

    інша сторінка сайту
    зовнішній вебсайт
    секція поточної сторінки
    файл для завантаження
    email-адреса
    номер телефону
    інший вебресурс

Наприклад:

    Головна → Каталог → Картка товару

Користувач бачить посилання на каталог і переходить за ним, щоб переглянути товари.

У типовому вебінтерфейсі посилання повинно відповідати на запитання:

    Куди я потраплю, якщо натисну цей елемент?

---

# Hyperlink

Hyperlink — це гіперпосилання, яке пов'язує один ресурс із місцем призначення.

Термін hyperlink часто використовується як синонім link.

Наприклад:

    Переглянути документацію

Це може бути текстовим посиланням на сторінку документації.

У UI Design важливо не тільки створити hyperlink, а й зробити його:

    помітним
    зрозумілим
    доступним
    передбачуваним
    візуально узгодженим з інтерфейсом

---

# Link Anatomy

Link Anatomy — структура та основні частини компонента посилання.

Типове текстове посилання містить:

    link text
        ↓
    visual styling
        ↓
    destination

Наприклад:

    Документація React

Тут:

    Документація React → link text
    синій колір / underline → visual styling
    сторінка документації → destination

Посилання також може містити іконку.

Наприклад:

    ↗ Відкрити зовнішній ресурс

У такому випадку:

    icon → додатковий візуальний сигнал
    label → пояснює призначення
    href → визначає місце переходу

Іконка не повинна замінювати зрозумілий текст, якщо значення посилання інакше незрозуміле.

---

# Link Text

Link text — видимий текст посилання.

Він допомагає користувачеві зрозуміти призначення елемента.

Хороший link text:

    Переглянути розклад
    Завантажити інструкцію
    Прочитати умови використання
    Відкрити документацію
    Переглянути всі курси

Невдалий link text:

    Натисніть тут
    Детальніше
    Тут
    Перейти
    Читати

Такі формулювання не завжди неправильні, але часто не пояснюють, що саме відкриється.

Наприклад, замість:

    Натисніть тут

Краще:

    Переглянути програму курсу

Зрозумілий текст особливо важливий, коли користувач сканує сторінку, а не читає її повністю.

---

# Descriptive Link Text

Descriptive link text — текст, який описує місце призначення або результат переходу.

Порівняймо:

    Погано:
    Детальніше

    Краще:
    Дізнатися більше про програму навчання

Або:

    Погано:
    Завантажити

    Краще:
    Завантажити PDF-інструкцію

Однак текст не обов'язково повинен бути довгим.

Наприклад:

    Контакти
    Про нас
    Умови використання
    Документація

Ці назви зрозумілі в контексті навігації.

Головне правило:

    Link text повинен пояснювати призначення
    посилання у відповідному контексті.

---

# Link vs Button

Це одна з найважливіших відмінностей у UI Design.

## Link

Link використовується для навігації.

Наприклад:

    Відкрити профіль
    Переглянути каталог
    Перейти до контактів
    Читати документацію

Типова HTML-реалізація:

    <a href="/profile">Відкрити профіль</a>

## Button

Button використовується для виконання дії.

Наприклад:

    Зберегти
    Видалити
    Відправити форму
    Відкрити діалогове вікно
    Увімкнути налаштування

Типова HTML-реалізація:

    <button type="button">Зберегти</button>

## Порівняння

    Link → перейти до місця призначення

    Button → виконати дію

Наприклад, у формі:

    Поле email
    Поле password
    [Увійти] → button

А поруч:

    Забули пароль? → link

Кнопка виконує операцію входу, а посилання веде на сторінку відновлення пароля.

### Важливе правило

Не потрібно використовувати посилання лише тому, що його легко стилізувати як кнопку.

Так само не варто використовувати кнопку замість посилання, якщо основна мета — перейти на іншу сторінку.

Семантична роль повинна відповідати поведінці компонента.

# Types of Links

## Text Links

Text links — звичайні текстові посилання.

Вони часто зустрічаються в текстових блоках, документації, статтях і описах.

Наприклад:

    Докладніше про CSS Grid можна прочитати
    в офіційній документації.

Слова «офіційній документації» можуть бути посиланням.

Основні особливості:

    невеликий візуальний акцент
    інтеграція в текст
    зрозуміле призначення
    достатній контраст
    помітність серед звичайного тексту

Text links повинні залишатися помітними навіть тоді, коли користувач швидко переглядає абзац.

---

## Inline Links

Inline links — посилання, вбудовані безпосередньо в речення або абзац.

Приклад:

    Ви можете переглянути
    <a href="/courses">усі курси</a>
    на нашій навчальній платформі.

Inline links використовуються в:

    статтях
    інструкціях
    описах
    довідкових текстах
    повідомленнях про помилки
    підказках у формах

Важливо, щоб посилання не порушувало читабельність тексту.

Не варто оформлювати кожне друге слово як посилання.

---

## Navigation Links

Navigation links — посилання, які забезпечують переміщення між основними розділами сайту або застосунку.

Наприклад:

    Головна
    Курси
    Блог
    Про нас
    Контакти

Основні особливості:

    зрозумілі короткі назви
    послідовне розташування
    однакове оформлення елементів
    помітний активний розділ, якщо він потрібний
    передбачувана поведінка

Navigation links можуть розміщуватися в:

    header
    sidebar
    footer
    mobile navigation
    dashboard navigation

---

## Internal Links

Internal links — посилання на інші сторінки або ресурси того самого сайту.

Приклад:

    /courses
    /about
    /contacts
    /profile/settings

Вони допомагають користувачеві переміщатися між розділами продукту.

У дизайні важливо зберігати послідовність:

    однакові стилі
    зрозумілі назви
    логічну структуру переходів
    узгоджену навігацію

---

## External Links

External links — посилання на ресурси за межами поточного сайту.

Наприклад:

    Офіційна документація
    Сайт партнера
    Зовнішній навчальний ресурс
    Сторінка організації

Візуально зовнішнє посилання може мати додаткову іконку.

Наприклад:

    ↗ Офіційний сайт

Іконка може сигналізувати про перехід за межі поточного ресурсу.

Проте її використання залежить від дизайн-системи та контексту.

Не потрібно додавати індикатор до кожного зовнішнього посилання, якщо це створює зайвий візуальний шум.

### Відкриття в новій вкладці

Зовнішнє посилання не обов'язково повинно відкриватися в новій вкладці.

Рішення залежить від очікувань користувача та призначення переходу.

Якщо посилання відкривається в новій вкладці, це можна позначити текстом або іконкою, коли така поведінка важлива для користувача.

---

## Anchor Links

Anchor links — посилання на певну секцію сторінки.

Вони часто використовуються на довгих сторінках, у документації, статтях і довідкових матеріалах.

Наприклад:

    На сторінці є секції:

    Вступ
    Основні поняття
    Приклади
    Висновок

Посилання можуть переміщувати користувача безпосередньо до потрібного розділу.

HTML-приклад:

    <a href="#examples">Перейти до прикладів</a>

    <section id="examples">
        <h2>Приклади</h2>
    </section>

У цьому випадку:

    #examples → fragment identifier
    id="examples" → цільова секція

Anchor links особливо корисні, якщо сторінка має велику кількість контенту.

---

## Breadcrumb Links

Breadcrumbs — навігаційні посилання, які показують поточне місце користувача в ієрархії сайту.

Приклад:

    Головна / Курси / JavaScript / Цикли

Зазвичай попередні елементи є посиланнями, а поточна сторінка відображається як звичайний текст.

Наприклад:

    Головна → link
    Курси → link
    JavaScript → link
    Цикли → current page

Breadcrumbs допомагають:

    зрозуміти структуру сайту
    повернутися до батьківського розділу
    орієнтуватися в глибокій ієрархії
    зменшити кількість зайвих переходів

Вони особливо корисні для:

    каталогів
    навчальних платформ
    інтернет-магазинів
    документації
    великих інформаційних сайтів

---

## Icon Links

Icon links — посилання, представлені іконкою або іконкою з текстом.

Приклади:

    іконка GitHub
    іконка зовнішнього ресурсу
    іконка завантаження
    іконка документації
    іконка переходу до профілю

Icon links можуть економити простір, але мають ризик неоднозначності.

Якщо іконка не має очевидного значення, користувач може не зрозуміти її призначення.

Тому потрібно враховувати:

    зрозумілість іконки
    доступну назву
    достатню область натискання
    видимі стани
    контраст
    узгодженість із дизайн-системою

Приклад HTML:

    <a href="/profile" aria-label="Відкрити профіль">
        <svg aria-hidden="true" viewBox="0 0 24 24">
            <!-- SVG icon -->
        </svg>
    </a>

Тут:

    aria-label → доступна назва посилання
    aria-hidden="true" → декоративна іконка не дублює назву

У реальному проєкті SVG повинен містити коректну геометрію іконки.

---

## Download Links

Download links — посилання, призначені для завантаження файлів або відкриття документів.

Наприклад:

    Завантажити PDF
    Завантажити інструкцію
    Отримати шаблон
    Завантажити звіт

У дизайні корисно вказувати формат файлу, а іноді й розмір.

Наприклад:

    Завантажити інструкцію (PDF, 2 MB)

Це допомагає користувачеві зрозуміти, що саме він отримає.

HTML-приклад:

    <a href="/files/manual.pdf" download>
        Завантажити інструкцію (PDF)
    </a>

Атрибут `download` може підказувати браузеру завантажити файл, але фактична поведінка залежить від ресурсу, походження URL та налаштувань браузера.

---

## Email Links

Email links відкривають поштовий застосунок для створення листа.

Приклад:

    <a href="mailto:support@example.com">
        Написати в підтримку
    </a>

У UI Design важливо, щоб користувач розумів призначення переходу.

Наприклад:

    Написати в підтримку
    support@example.com

Обидва варіанти можуть бути доречними залежно від контексту.

---

## Phone Links

Phone links дозволяють розпочати дзвінок на пристроях, які підтримують таку дію.

Приклад:

    <a href="tel:+380441234567">
        Зателефонувати
    </a>

Вони особливо корисні в:

    мобільних інтерфейсах
    контактних сторінках
    сервісних застосунках
    медичних і довідкових сервісах

Відображуваний номер має бути зрозумілим, а посилання — доступним для натискання.

---

## Contextual Links

Contextual links — посилання, призначення яких пояснюється навколишнім контентом.

Наприклад:

    Перед початком роботи перегляньте
    інструкцію з налаштування проєкту.

Посилання в цьому реченні має зрозумілий контекст.

Contextual links часто використовуються для:

    додаткових пояснень
    документації
    пов'язаних матеріалів
    рекомендацій
    довідкової інформації

Контекст може допомагати зрозуміти посилання, але сам текст посилання також повинен бути достатньо інформативним.

---

# Visual Affordance

Visual affordance — візуальні ознаки, які допомагають користувачеві зрозуміти, як взаємодіяти з елементом.

Для links такими ознаками можуть бути:

    колір
    підкреслення
    зміна кольору при hover
    focus outline
    іконка переходу
    розташування в навігації
    характерне оформлення тексту

Наприклад:

    Звичайний текст
    Посилання на документацію

Якщо обидва елементи виглядають однаково, користувачеві складніше зрозуміти, що можна натиснути.

Основний принцип:

    Інтерактивний елемент повинен виглядати
    достатньо інтерактивним.

---

# Link Styling

Link Styling — правила візуального оформлення посилань.

Стилізація повинна допомагати користувачеві:

    знаходити посилання
    відрізняти їх від звичайного тексту
    розуміти їхню важливість
    помічати інтерактивні стани
    користуватися ними на різних пристроях

Основні властивості стилізації:

    color
    text-decoration
    font-weight
    background
    border
    outline
    transition

Важливо не використовувати всі властивості одночасно без потреби.

Хороший link style зазвичай простий, послідовний і відповідає візуальній системі продукту.

---

# Color

Колір — один із найпоширеніших способів позначити посилання.

Наприклад:

    Body text → темно-сірий
    Link → синій

Контраст між кольором посилання та навколишнім текстом допомагає помітити інтерактивний елемент.

Проте не варто покладатися лише на колір.

Якщо звичайний текст і посилання відрізняються тільки кольором, користувачам із порушеннями кольоросприйняття може бути складніше їх розрізняти.

Додаткові засоби:

    underline
    font weight
    іконка
    чіткі стани взаємодії

Для доступного інтерфейсу важливо перевіряти контраст тексту та посилання відповідно до WCAG.

---

# Underline

Underline — підкреслення тексту.

Це один із найвідоміших візуальних сигналів посилання.

Приклад:

    <a href="/about">Про нас</a>

CSS:

    a {
        text-decoration: underline;
    }

Підкреслення особливо корисне для inline links, які розташовані серед звичайного тексту.

Можна змінювати:

    text-decoration-color
    text-decoration-thickness
    text-underline-offset

Приклад:

    a {
        text-decoration: underline;
        text-underline-offset: 0.15em;
        text-decoration-thickness: 1px;
    }

У деяких дизайн-системах підкреслення може бути відсутнім у навігаційних посиланнях або в елементах із достатньо очевидною візуальною роллю.

Однак потрібно переконатися, що посилання все одно легко розпізнати.

---

# Typography of Links

Типографіка посилань повинна узгоджуватися з типографічною системою інтерфейсу.

Можна налаштовувати:

    font-family
    font-size
    font-weight
    line-height
    letter-spacing

Для звичайних текстових посилань зазвичай достатньо успадковувати типографіку навколишнього тексту та змінювати колір і підкреслення.

Для навігації можуть використовуватися інші параметри.

Наприклад:

    Inline link → типографіка абзацу
    Navigation link → стиль навігації
    Footer link → стиль нижньої навігації
    CTA link → акцентна типографіка

Не варто збільшувати вагу шрифту кожного посилання без потреби: це може порушити ритм тексту.

---

# Link Hierarchy

Link Hierarchy — візуальна ієрархія посилань.

Не всі посилання в інтерфейсі мають однакову важливість.

Наприклад:

    Primary navigation
        ↓
    Contextual links
        ↓
    Secondary links
        ↓
    Footer links

Це умовний приклад, а не універсальний порядок для кожного продукту.

Ієрархія залежить від задач користувача та структури сторінки.

Основні принципи:

    головні переходи повинні бути легко знайдені
    другорядні посилання не повинні конкурувати з головними
    пов'язані посилання повинні виглядати послідовно
    важливість не повинна визначатися лише кольором

Не потрібно робити кожне посилання яскравим або великим.

Якщо всі елементи акцентні, жоден із них не має виразного пріоритету.

---

# Primary and Secondary Links

У деяких дизайн-системах посилання поділяють на primary та secondary.

Це допомагає визначити їхню візуальну важливість.

## Primary Link

Primary link — посилання, яке має особливе значення в конкретному контексті.

Наприклад:

    Переглянути каталог
    Відкрити основний розділ
    Перейти до реєстрації

Воно може мати виразніший колір або більшу вагу шрифту.

## Secondary Link

Secondary link — менш акцентне посилання.

Наприклад:

    Докладніше про правила
    Переглянути додаткові матеріали
    Ознайомитися з довідкою

Воно може мати стриманіше оформлення.

### Важливо

Primary та secondary — це ролі в конкретному інтерфейсі, а не обов'язкові HTML-типи.

Не кожна дизайн-система потребує такого поділу.

---

# Link States

Link States — візуальні стани посилання під час взаємодії.

Основні стани:

    default
    hover
    focus
    active
    visited

Кожен стан має передавати користувачеві відповідну інформацію.

---

## Default State

Default — звичайний стан посилання.

Користувач ще не взаємодіє з ним.

У цьому стані важливо забезпечити:

    помітність
    читабельність
    достатній контраст
    відповідність дизайн-системі

Наприклад:

    color: blue
    text-decoration: underline

Це лише приклад. Конкретні значення залежать від дизайн-системи.

---

## Hover State

Hover — стан, коли вказівник миші знаходиться над посиланням.

Можливі зміни:

    колір
    підкреслення
    товщина підкреслення
    фоновий колір
    невелика зміна прозорості

Приклад:

    a:hover {
        color: #174ea6;
    }

Hover допомагає підтвердити інтерактивність елемента.

Проте hover не повинен бути єдиним способом передавання важливої інформації, оскільки сенсорні пристрої не мають такого самого механізму наведення.

---

## Focus State

Focus — стан, коли посилання отримало клавіатурний або інший програмний фокус.

Наприклад, користувач натискає Tab і переходить до наступного посилання.

Focus indicator допомагає зрозуміти:

    де зараз знаходиться фокус
    який елемент буде активовано клавіатурою
    як переміщатися інтерфейсом

Приклад CSS:

    a:focus-visible {
        outline: 2px solid currentColor;
        outline-offset: 3px;
    }

Не потрібно прибирати focus indicator без доступної альтернативи.

Наприклад, це небажаний підхід:

    a:focus {
        outline: none;
    }

Якщо індикатор фокусу прибрано, клавіатурному користувачеві може бути складно визначити поточний елемент.

---

## Active State

Active — стан під час активації посилання.

Наприклад, коли користувач натискає кнопку миші на посиланні.

CSS:

    a:active {
        color: #0b3d91;
    }

Цей стан може бути короткочасним.

Він не замінює інші стани та не повинен бути єдиним візуальним підтвердженням інтерактивності.

---

## Visited State

Visited — стан посилання, яке користувач уже відвідував.

CSS:

    a:visited {
        color: purple;
    }

Visited state може допомагати орієнтуватися у великих обсягах інформації.

Наприклад:

    документація
    навчальні статті
    результати пошуку

Використання visited залежить від призначення інтерфейсу.

У деяких компонентах або навігаційних меню цей стан не має великої практичної користі.

---

# Link States Example

Приклад базового оформлення станів:

    a {
        color: #175cd3;
        text-decoration: underline;
        text-underline-offset: 0.15em;
    }

    a:hover {
        color: #1849a9;
    }

    a:focus-visible {
        outline: 2px solid currentColor;
        outline-offset: 3px;
    }

    a:active {
        color: #123b83;
    }

Це навчальний приклад.

У реальному проєкті потрібно перевірити контраст кожного стану та узгодити кольори з дизайн-системою.

Не кожен стан обов'язково повинен мати радикально інший вигляд.

Важливо, щоб стани були зрозумілими, послідовними та доступними.

---

# Link Contrast

Link Contrast — контраст посилання відносно фону та, у відповідних випадках, навколишнього тексту.

Для тексту звичайного розміру WCAG AA зазвичай вимагає коефіцієнт контрастності щонайменше 4.5:1.

Для великого тексту — щонайменше 3:1.

Ці критерії стосуються контрасту тексту з його фоном.

Якщо посилання відрізняється від навколишнього звичайного тексту лише кольором, важливо також перевірити достатність контрасту між ними або використовувати додаткову візуальну ознаку, наприклад підкреслення.

Основні принципи:

    достатній контраст із фоном
    помітність серед звичайного тексту
    читабельність у різних станах
    перевірка світлої та темної теми
    перевірка hover та focus

Не слід визначати доступність лише за тим, чи здається колір достатньо яскравим.

Контраст потрібно перевіряти інструментально.

---

# Link Density

Link Density — кількість посилань у певному обсязі контенту.

Наприклад, абзац може містити:

    0 links
    1 link
    3 links
    8 links

Велика кількість посилань не обов'язково є помилкою.

У документації або навігаційному каталозі їх може бути багато.

Проблема виникає, коли посилання:

    конкурують за увагу
    порушують читабельність
    мають нечіткі назви
    не мають зрозумілого групування
    ускладнюють вибір наступної дії

Щоб покращити інтерфейс:

    групуй пов'язані посилання
    використовуй зрозумілі заголовки
    прибирай непотрібні переходи
    уникай повторення однакових посилань без причини
    підтримуй візуальну ієрархію

---

# Link Grouping

Link Grouping — групування пов'язаних посилань.

Наприклад, у футері:

    Навчання
        Курси
        Розклад
        Матеріали

    Про організацію
        Про нас
        Контакти
        Команда

    Підтримка
        Допомога
        FAQ
        Зворотний зв'язок

Групування допомагає користувачеві швидше знаходити потрібний напрям.

Основні правила:

    логічні групи
    зрозумілі заголовки
    достатній spacing
    однакове оформлення елементів
    передбачуваний порядок

Не варто об'єднувати в одну групу посилання, які не мають спільного призначення.

---

# Navigation Link Design

Navigation Link Design — проєктування посилань для навігації.

Навігаційні посилання часто є частиною глобальної структури продукту.

Вони можуть бути розташовані:

    у верхній панелі
    у бічній панелі
    у футері
    у мобільному меню
    у навігації особистого кабінету

Приклад:

    Логотип
    Головна
    Курси
    Бібліотека
    Контакти

Під час проєктування важливо враховувати:

    кількість пунктів
    порядок пунктів
    зрозумілість назв
    активний розділ
    адаптивність
    поведінку на мобільних пристроях

Основна навігація повинна показувати найважливіші напрямки продукту, а не кожну доступну сторінку.

Другорядні переходи можна розмістити в підменю або окремих групах.

---

# Active Navigation Link

Active navigation link — посилання, яке відповідає поточному розділу або сторінці.

Наприклад:

    Головна
    Курси ← active
    Бібліотека
    Контакти

Активний пункт може мати:

    інший колір
    underline
    фоновий акцент
    індикатор збоку
    іншу вагу шрифту

Важливо, щоб активний стан не залежав лише від кольору, якщо це може ускладнити розпізнавання.

Для поточної сторінки в навігації можна використовувати атрибут `aria-current`.

Приклад:

    <nav aria-label="Основна навігація">
        <a href="/">Головна</a>

        <a href="/courses" aria-current="page">
            Курси
        </a>

        <a href="/contacts">Контакти</a>
    </nav>

`aria-current="page"` повідомляє допоміжним технологіям, що посилання відповідає поточній сторінці.

---

# Link Spacing

Link Spacing — відстань між посиланнями та навколишніми елементами.

Правильний spacing допомагає:

    швидко сканувати навігацію
    розрізняти групи
    уникати випадкових натискань
    підтримувати візуальний ритм
    покращувати читабельність

Наприклад:

    Головна    Курси    Бібліотека    Контакти

Якщо посилання розташовані надто близько одне до одного, особливо на мобільному пристрої, користувачеві складніше вибрати потрібне.

У вертикальній навігації spacing також допомагає відокремити групи пунктів.

Важливо відрізняти:

    visual spacing → відстань між елементами
    hit area → область, яка реагує на взаємодію

Ці параметри пов'язані, але не тотожні.

---

# Hit Area

Hit Area — область, у межах якої користувач може активувати інтерактивний елемент.

Для текстового посилання hit area може збігатися з областю тексту.

Для навігаційного елемента можна зробити більшу область взаємодії за допомогою padding.

Приклад:

    .nav-link {
        display: inline-block;
        padding: 0.75rem 1rem;
    }

Збільшена hit area особливо важлива для:

    мобільної навігації
    меню
    іконкових посилань
    елементів у списках
    інтерфейсів для сенсорних екранів

WCAG 2.2 має критерій Target Size (Minimum), який за певних умов вимагає розміру цілі щонайменше 24 × 24 CSS-пікселі або достатнього проміжку між цілями. Для окремих ситуацій передбачено винятки.

Для практичного дизайну важливо не сприймати 24 × 24 px як універсальний ідеальний розмір: більші цілі можуть бути зручнішими для сенсорної взаємодії.

---

# Icon and Text Links

Посилання може містити одночасно текст та іконку.

Приклад:

    ↗ Переглянути документацію

Текст пояснює призначення, а іконка доповнює його.

Можливі варіанти:

    icon before text
    icon after text
    icon only
    text only

## Icon Before Text

Іконка перед текстом може позначати категорію або тип ресурсу.

Наприклад:

    [PDF icon] Завантажити документ

## Icon After Text

Іконка після тексту може позначати напрям переходу.

Наприклад:

    Відкрити зовнішній сайт ↗

## Icon Only

Посилання лише з іконкою потребує особливої уваги до доступності.

Приклад:

    [GitHub icon]

Користувач повинен мати можливість зрозуміти призначення цього елемента.

Для цього можуть використовуватися:

    aria-label
    видимий tooltip
    текстовий підпис у відповідному контексті

Tooltip не повинен бути єдиним способом надати критично важливу інформацію.

---

# Link vs CTA

CTA (Call to Action) — елемент, який спонукає користувача виконати важливу дію.

CTA може бути кнопкою або посиланням.

Наприклад:

    Зареєструватися
    Переглянути каталог
    Дізнатися більше
    Завантажити програму

Якщо CTA веде на іншу сторінку, це може бути link.

Якщо CTA запускає операцію, це зазвичай button.

Наприклад:

    Переглянути курси → link
    Надіслати заявку → button
    Завантажити PDF → link
    Підтвердити видалення → button

Візуально CTA-посилання може бути акцентним і нагадувати кнопку.

Однак зовнішній вигляд не змінює семантичного призначення елемента.

---

# Button-Style Links

Button-style link — посилання, яке візуально оформлене як кнопка.

Наприклад:

    [Переглянути курси]

Воно може мати:

    background
    padding
    border-radius
    font-weight
    hover state
    focus state

HTML:

    <a class="button-link" href="/courses">
        Переглянути курси
    </a>

CSS:

    .button-link {
        display: inline-block;
        padding: 0.75rem 1rem;
        border-radius: 0.5rem;
        background: #175cd3;
        color: white;
        text-decoration: none;
    }

    .button-link:hover {
        background: #1849a9;
    }

    .button-link:focus-visible {
        outline: 2px solid currentColor;
        outline-offset: 3px;
    }

Це навчальний приклад стилізації.

Button-style link доречний, коли головна мета — перейти до конкретного ресурсу, але візуально цей перехід повинен бути особливо помітним.

Якщо елемент виконує дію, а не навігацію, слід розглянути справжній `<button>`.

---

# Responsive Links

Responsive Links — посилання, адаптовані до різних розмірів екрана.

На широкому екрані навігація може виглядати так:

    Головна | Курси | Бібліотека | Контакти

На вузькому екрані ті самі переходи можуть бути розташовані у вертикальному меню.

Адаптація може змінювати:

    розташування
    spacing
    padding
    розмір шрифту
    групування
    доступність навігації
    спосіб відкриття меню

Необхідно враховувати:

    читабельність тексту
    зручність натискання
    відсутність горизонтального переповнення
    доступність клавіатурної навігації
    видимість focus indicator

Посилання повинні залишатися зрозумілими незалежно від ширини екрана.

Не варто просто зменшувати всі відступи, якщо це робить навігацію незручною.

---

# Link Accessibility

Link Accessibility — доступність посилань для різних користувачів і способів взаємодії.

Доступні посилання повинні бути зрозумілими:

    користувачам клавіатури
    користувачам скринридерів
    користувачам із порушеннями кольоросприйняття
    користувачам із порушеннями зору
    користувачам сенсорних пристроїв

Основні вимоги:

    семантичний HTML
    зрозумілий link text
    достатній контраст
    видимий focus indicator
    клавіатурна доступність
    відсутність неоднозначних назв
    коректна доступна назва для іконкових посилань

---

## Semantic HTML

Для навігації використовується елемент `<a>` з атрибутом `href`.

Правильно:

    <a href="/courses">Переглянути курси</a>

Не варто імітувати посилання звичайним елементом без необхідності.

Наприклад:

    <span onclick="goToCourses()">
        Переглянути курси
    </span>

Такий елемент не отримує автоматично всі стандартні можливості справжнього посилання, зокрема звичну клавіатурну поведінку та семантику.

Семантичний HTML зазвичай спрощує доступність і підтримку коду.

---

## Keyboard Navigation

Користувач повинен мати можливість переходити між посиланнями клавішею Tab.

Типова поведінка:

    Tab → перейти до наступного елемента
    Shift + Tab → повернутися до попереднього
    Enter → активувати посилання

Посилання з коректним `href` підтримують цю поведінку за замовчуванням.

Не потрібно прибирати посилання з природного порядку клавіатурної навігації без вагомої причини.

---

## Focus Visibility

Focus Visibility — видимість поточного фокусу.

Користувач повинен розуміти, яке посилання буде активовано після натискання Enter.

Приклад:

    a:focus-visible {
        outline: 2px solid #175cd3;
        outline-offset: 3px;
    }

Індикатор фокусу має бути помітним на відповідному фоні.

Потрібно перевіряти:

    світлий фон
    темний фон
    сусідні елементи
    різні кольорові теми
    масштабування інтерфейсу

---

## Accessible Name

Accessible name — назва елемента, яку можуть визначати допоміжні технології.

Для текстового посилання доступна назва зазвичай походить від його текстового вмісту.

Наприклад:

    <a href="/contacts">Контакти</a>

Доступна назва:

    Контакти

Для іконкового посилання видимого тексту може не бути.

Тоді потрібно забезпечити зрозумілу назву іншим коректним способом.

Приклад:

    <a href="/settings" aria-label="Налаштування">
        <svg aria-hidden="true" viewBox="0 0 24 24">
            <!-- SVG icon -->
        </svg>
    </a>

Не варто використовувати одну й ту саму неоднозначну доступну назву для багатьох посилань, якщо користувач не може визначити різницю між їхніми призначеннями.

# External Links and Security

Якщо посилання відкривається в новій вкладці через `target="_blank"`, сучасні браузери зазвичай автоматично застосовують поведінку, еквівалентну `rel="noopener"`.

Явне зазначення `rel="noopener"` також може використовуватися для зрозумілості та сумісності з наявними кодовими стандартами.

Приклад:

    <a
        href="https://example.com"
        target="_blank"
        rel="noopener"
    >
        Відкрити зовнішній сайт
    </a>

Якщо використовується `target="_blank"`, варто враховувати очікування користувача та, за потреби, повідомляти про відкриття нової вкладки.

Атрибут `rel="noreferrer"` має додатковий ефект: він не передає заголовок HTTP Referer. Його використання залежить від вимог приватності та аналітики.

Не потрібно автоматично відкривати всі зовнішні посилання в нових вкладках.

# Link Tokens in Design Systems

У дизайн-системах посилання можуть використовувати спільні дизайн-токени.

Наприклад:

    color-link
    color-link-hover
    color-link-visited
    color-focus-ring
    text-decoration-link
    spacing-link
    radius-link

Це умовні назви токенів, які команда може адаптувати під власні правила.

Приклад CSS custom properties:

    :root {
        --color-link: #175cd3;
        --color-link-hover: #1849a9;
        --color-link-visited: #6941c6;
        --color-focus-ring: #175cd3;
    }

    a {
        color: var(--color-link);
        text-decoration: underline;
        text-underline-offset: 0.15em;
    }

    a:hover {
        color: var(--color-link-hover);
    }

    a:visited {
        color: var(--color-link-visited);
    }

    a:focus-visible {
        outline: 2px solid var(--color-focus-ring);
        outline-offset: 3px;
    }

У реальній дизайн-системі токени потрібно перевіряти на контрастність і узгоджувати між світлою та темною темами.

# Practical UI Design Example

Припустимо, потрібно спроєктувати блок навчальної платформи.

Структура:

    Header
        Logo
        Navigation links

    Main
        Page title
        Description
        Inline link to documentation
        Button-style link to courses

    Related content
        Related links

    Footer
        Support links
        Legal links
        Contact links

Приклад HTML:

    <header>
        <nav aria-label="Основна навігація">
            <a href="/">Головна</a>
            <a href="/courses">Курси</a>
            <a href="/library">Бібліотека</a>
            <a href="/contacts">Контакти</a>

    </header>

    <main>
        <h1>Навчальна платформа</h1>

        <p>
            Ознайомтеся з
            <a href="/documentation">
                документацією
            </a>
            перед початком роботи.
        </p>

        <a class="button-link" href="/courses">
            Переглянути курси
        </a>
    </main>

Цей приклад показує різні ролі посилань в одному інтерфейсі.

Основні принципи:

    навігація відокремлена від основного контенту
    inline link інтегрований у речення
    важливий перехід має виразніше оформлення
    кожне посилання має зрозуміле призначення

# Common Mistakes

## 1. Посилання не відрізняється від звичайного тексту

Проблема:

    звичайний текст і link виглядають однаково

Користувач може не зрозуміти, що елемент інтерактивний.

Рішення:

    використовувати помітний колір
    застосовувати underline, де це доречно
    підтримувати зрозумілі стани

---

## 2. Використання лише кольору

Проблема:

    link відрізняється лише кольором

Це може ускладнювати розпізнавання для користувачів із порушеннями кольоросприйняття.

Рішення:

    додати underline або іншу чітку візуальну ознаку

---

## 3. Неінформативний link text

Проблема:

    Натисніть тут
    Детальніше
    Перейти

Рішення:

    Переглянути програму курсу
    Завантажити PDF-інструкцію
    Відкрити документацію

---

## 4. Невидимий focus indicator

Проблема:

    outline прибрано
    альтернативного індикатора немає

Рішення:

    забезпечити добре помітний focus indicator

---

## 5. Link замість button

Проблема:

    посилання використовується для виконання операції

Наприклад:

    <a href="#" onclick="saveData()">
        Зберегти
    </a>

Рішення:

    <button type="button">Зберегти</button>

Якщо елемент виконує дію, кнопка зазвичай є правильним вибором.

---

## 6. Button замість link

Проблема:

    кнопка використовується лише для переходу на іншу сторінку

Рішення:

    <a href="/courses">Переглянути курси</a>

Якщо основна мета — навігація, використовуйте посилання.

---

## 7. Занадто багато акцентних посилань

Проблема:

    кожне посилання яскраве
    усі мають однаковий візуальний пріоритет

Рішення:

    визначити ієрархію
    групувати посилання
    залишати акцент для важливих переходів

---

## 8. Замала hit area

Проблема:

    посилання складно натиснути на мобільному пристрої

Рішення:

    збільшити область взаємодії
    додати padding
    збільшити відстань між сусідніми елементами

---

## 9. Іконкове посилання без доступної назви

Проблема:

    є лише іконка
    призначення не пояснено

Рішення:

    додати зрозумілу доступну назву
    використовувати видимий текст, коли це доречно

---

## 10. Непослідовні стилі

Проблема:

    однакові за призначенням посилання виглядають по-різному без причини

Рішення:

    створити спільні правила
    використовувати дизайн-токени
    визначити варіанти компонента

---

## 11. Усі зовнішні посилання відкриваються в новій вкладці

Проблема:

    поведінка не відповідає очікуванням користувача

Рішення:

    відкривати нову вкладку лише тоді, коли це виправдано
    повідомляти про незвичну поведінку, якщо це важливо

---

## 12. Надмірне використання іконок

Проблема:

    кожне посилання має зайву іконку
    інтерфейс стає візуально перевантаженим

Рішення:

    використовувати іконки лише тоді, коли вони додають значення

---

# Link Design Checklist

Перед завершенням дизайну перевір:

    [ ] Призначення кожного посилання зрозуміле.
    [ ] Текст посилання інформативний.
    [ ] Посилання відрізняється від звичайного тексту.
    [ ] Колір не є єдиним сигналом інтерактивності там, де це важливо.
    [ ] Контраст тексту відповідає вимогам доступності.
    [ ] Hover state передбачений для відповідних пристроїв.
    [ ] Focus state добре помітний.
    [ ] Active state не створює плутанини.
    [ ] Visited state використовується доречно.
    [ ] Навігаційні посилання мають послідовний стиль.
    [ ] Активний пункт навігації легко визначити.
    [ ] Hit area достатня для зручної взаємодії.
    [ ] Іконкові посилання мають доступні назви.
    [ ] Зовнішні переходи поводяться передбачувано.
    [ ] Посилання працюють на клавіатурі.
    [ ] Посилання залишаються читабельними на мобільних екранах.
    [ ] Link і button використовуються відповідно до призначення.
    [ ] Пов'язані посилання згруповані логічно.
    [ ] Стилі узгоджені з дизайн-системою.
    [ ] Відсутні зайві або непрацюючі посилання.

# Головне

• Link — компонент навігації, який веде до ресурсу або місця призначення.

• У HTML стандартне посилання створюється за допомогою `<a href="...">`.

• Link і button мають різне семантичне призначення.

• Link text повинен пояснювати, куди веде посилання.

• Посилання повинно відрізнятися від звичайного тексту.

• Колір, underline та інші візуальні сигнали допомагають розпізнавати інтерактивність.

• Основні стани посилання:

    default
    hover
    focus
    active
    visited

• Focus indicator повинен бути помітним.

• Посилання повинні підтримувати клавіатурну навігацію.

• Контраст тексту потрібно перевіряти відповідно до WCAG.

• Icon links повинні мати зрозумілу доступну назву.

• Navigation links повинні бути послідовними та передбачуваними.

• Breadcrumbs допомагають орієнтуватися в ієрархії сайту.

• Anchor links забезпечують перехід до певної секції сторінки.

• Primary та secondary links допомагають формувати візуальну ієрархію, якщо такий поділ потрібний інтерфейсу.

• Link spacing і hit area впливають на зручність взаємодії.

• Responsive links повинні залишатися читабельними та зручними на різних пристроях.

• Дизайн-система повинна забезпечувати узгоджені стилі та стани посилань.

• Не потрібно відкривати всі зовнішні посилання в новій вкладці без обґрунтованої причини.

• Основне правило:

    Link → navigation
    Button → action

• Хороше посилання поєднує зрозуміле призначення, помітний візуальний стиль, передбачувану поведінку та доступність.

• У UI Design links — це не просто текст іншого кольору, а важлива частина навігації, інформаційної архітектури та користувацького досвіду.
