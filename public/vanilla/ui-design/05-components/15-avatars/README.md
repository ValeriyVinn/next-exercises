# 15. Avatars — Аватари в UI-дизайні

Аватар (Avatar) — це візуальний елемент інтерфейсу, який представляє людину, користувача, команду або організацію. Найчастіше він відображається як фотографія, ініціали, ілюстрація або тематична іконка.

Аватари допомагають швидко ідентифікувати учасників розмови, авторів матеріалів, користувачів системи та членів команди.

**Мета теми:** навчитися проєктувати аватари, вибирати їхні розміри, форми, кольори, стани й поведінку, а також реалізовувати їх за допомогою HTML, CSS, JavaScript і React.

---

## 1. Навіщо потрібні аватари

Аватар виконує кілька важливих функцій:

- ✔ Ідентифікація користувача.
- ✔ Візуальне розрізнення учасників чату.
- ✔ Представлення автора статті, коментаря або повідомлення.
- ✔ Позначення учасників команди чи групи.
- ✔ Відображення облікового запису в навігації.
- ✔ Позначення доступності користувача.
- ✔ Покращення візуальної структури списків і карток.

Приклади використання:

- профіль користувача в особистому кабінеті;
- учасники групового чату;
- автори коментарів;
- викладачі та студенти в LMS;
- працівники в корпоративній системі;
- автори статей і новин;
- список учасників відеоконференції;
- користувачі в системі керування проєктами.

### Приклад інтерфейсу

    ┌────────────────────────────────────────┐
    │  [Аватар]  Олена Коваль                │
    │            Викладачка математики       │
    │                                        │
    │  [Аватар]  Андрій Петренко             │
    │            Студент                     │
    └────────────────────────────────────────┘

Аватар допомагає швидко пов'язати ім'я з конкретною людиною.

---

## 2. Основні типи аватарів

### 2.1. Фотоаватар

Використовує фотографію людини.

    ┌──────────┐
    │          │
    │  ФОТО    │
    │          │
    └──────────┘

Застосування:

- особисті профілі;
- професійні мережі;
- корпоративні каталоги;
- системи навчання;
- месенджери.

Переваги:

- персоналізація;
- легше впізнавати людей;
- природніше сприйняття соціальних інтерфейсів.

Недоліки:

- фотографія може бути відсутня;
- зображення може мати невідповідний формат;
- потрібне коректне кадрування;
- виникають питання приватності та згоди на використання фотографії.

### 2.2. Аватар з ініціалами

Якщо фотографії немає, можна показати ініціали користувача.

    ┌──────────┐
    │          │
    │    ОК    │
    │          │
    └──────────┘

Наприклад:

- Олена Коваль → ОК;
- Андрій Петренко → АП;
- Valeriy Svystun → VS.

Переваги:

- не потребує фотографії;
- швидко генерується;
- має невеликий розмір;
- добре підходить для корпоративних застосунків.

Важливо: ініціали потрібно отримувати з імені користувача, а не задавати вручну для кожного профілю.

### 2.3. Аватар із зображенням-заповнювачем

Використовується стандартна іконка користувача.

    ┌──────────┐
    │          │
    │    ♙     │
    │          │
    └──────────┘

Підходить для:

- анонімних користувачів;
- нових облікових записів;
- профілів без фотографії;
- систем, у яких персональні фотографії необов'язкові.

### 2.4. Ілюстрований аватар

Може містити персонажа, малюнок або стилізовану ілюстрацію.

Застосовується в:

- освітніх застосунках;
- ігрових сервісах;
- дружніх користувацьких інтерфейсах;
- дитячих навчальних системах.

### 2.5. Аватар організації або команди

Замість людини представляє групу, компанію, проєкт або організацію.

Приклади:

- логотип компанії;
- іконка навчальної групи;
- зображення команди розробників;
- емблема проєкту.

Не варто використовувати аватар людини для позначення організації, якщо це може створити плутанину.

---

## 3. Форма аватара

Форма впливає на візуальний стиль, але сама по собі не повинна бути єдиним способом передавання значення.

### 3.1. Круглий аватар

Найпоширеніший варіант.

    .avatar {
      width: 48px;
      height: 48px;
      border-radius: 50%;
    }

Застосування:

- профілі;
- чати;
- коментарі;
- списки учасників.

### 3.2. Квадратний аватар

Має прямі кути.

    .avatar {
      width: 48px;
      height: 48px;
      border-radius: 0;
    }

Може використовуватися в:

- каталогах;
- адміністративних панелях;
- інтерфейсах керування файлами;
- списках організацій.

### 3.3. Аватар із заокругленими кутами

Компроміс між круглою та квадратною формами.

    .avatar {
      width: 48px;
      height: 48px;
      border-radius: 12px;
    }

Підходить для сучасних SaaS-інтерфейсів, карток і списків.

### Принцип консистентності

У межах однієї системи бажано дотримуватися єдиної логіки:

- фотографії людей — круглі;
- логотипи команд — квадратні або заокруглені;
- іконки категорій — відповідно до дизайн-системи.

Це не абсолютне правило. Головне — послідовність і зрозумілість.

---

## 4. Розміри аватарів

Розмір залежить від контексту, щільності інтерфейсу та важливості користувача.

| Розмір | Типове використання |
|---|---|
| 16 px | компактні метадані, щільні таблиці |
| 24 px | невеликі списки, короткі повідомлення |
| 32 px | компактні рядки та коментарі |
| 40 px | стандартні списки користувачів |
| 48 px | профілі, чати, картки |
| 64 px | розширені профілі |
| 96 px | сторінка профілю |
| 128 px і більше | велика фотографія профілю |

Це орієнтовні значення, а не жорсткий стандарт.

### Приклад системи розмірів

    :root {
      --avatar-xs: 24px;
      --avatar-sm: 32px;
      --avatar-md: 40px;
      --avatar-lg: 48px;
      --avatar-xl: 64px;
      --avatar-profile: 96px;
    }

Використання:

    .avatar {
      width: var(--avatar-md);
      height: var(--avatar-md);
    }

    .avatar--small {
      width: var(--avatar-sm);
      height: var(--avatar-sm);
    }

    .avatar--large {
      width: var(--avatar-xl);
      height: var(--avatar-xl);
    }

### Що потрібно враховувати

- Маленький аватар не повинен бути єдиним способом визначити користувача.
- Поруч із аватаром бажано показувати ім'я, коли воно важливе.
- Для великих фотографій потрібно зберігати пропорції.
- Розмір аватара має узгоджуватися з висотою рядка, кнопки або картки.
- На мобільному екрані не варто механічно зменшувати всі елементи без перевірки читабельності.

## 5. Кадрування фотографії

Фотоаватар зазвичай розміщується у квадратному контейнері, навіть якщо оригінальна фотографія має інші пропорції.

Для правильного кадрування використовується `object-fit`.

### `object-fit: cover`

Зображення заповнює весь контейнер, а зайві частини обрізаються.

    .avatar__image {
      width: 100%;
      height: 100%;
      object-fit: cover;
    }

Це найпоширеніший варіант для фотоаватарів.

### `object-fit: contain`

Усе зображення залишається видимим, але можуть з'являтися порожні ділянки.

    .avatar__image {
      width: 100%;
      height: 100%;
      object-fit: contain;
    }

Підходить для логотипів та іконок, якщо обрізання неприпустиме.

### Позиція кадрування

За допомогою `object-position` можна змістити видиму частину фотографії.

    .avatar__image {
      width: 100%;
      height: 100%;
      object-fit: cover;
      object-position: center 30%;
    }

Це корисно, коли обличчя розташоване вище або нижче центру.

### Типові помилки

- обличчя обрізане;
- фотографія розтягнута;
- логотип обрізаний;
- зображення не заповнює контейнер;
- аватар має різні пропорції в різних рядках.

## 6. Колір аватара з ініціалами

Якщо фотографії немає, фон аватара допомагає зробити інтерфейс виразнішим.

    .avatar--initials {
      display: inline-flex;
      align-items: center;
      justify-content: center;

      background-color: #e0e7ff;
      color: #3730a3;

      font-weight: 600;
    }

### Принципи вибору кольору

- ✔ Текст має бути достатньо контрастним.
- ✔ Колір повинен відповідати дизайн-системі.
- ✔ Кольори не повинні випадково змінювати значення користувача.
- ✔ Не слід покладатися лише на колір для передавання статусу.
- ✔ Усі аватари мають залишатися читабельними в темній і світлій темах.

### Доступність контрасту

Для звичайного тексту орієнтир WCAG AA — контраст щонайменше `4.5:1`.

Для великого тексту — щонайменше `3:1`.

Ініціали в маленькому аватарі часто мають невеликий розмір, тому безпечніше забезпечувати контраст `4.5:1` або вище.

### Не використовуй випадкові кольори без правил

Поганий підхід:

    .avatar:nth-child(1) {
      background: red;
    }

    .avatar:nth-child(2) {
      background: green;
    }

    .avatar:nth-child(3) {
      background: blue;
    }

Такий підхід пов'язує колір із позицією елемента, а не з користувачем чи дизайн-системою.

Краще використовувати узгоджені колірні токени.

    :root {
      --avatar-bg: #e0e7ff;
      --avatar-text: #3730a3;
    }

    .avatar--initials {
      background: var(--avatar-bg);
      color: var(--avatar-text);
    }

Якщо потрібно призначати користувачам стабільні кольори, це варто реалізувати окремою логікою на основі даних користувача.

## 7. Аватар зі статусом

У деяких інтерфейсах аватар має невеликий індикатор стану.

Приклади:

- онлайн;
- офлайн;
- зайнятий;
- не турбувати;
- доступний для розмови.

### Приклад структури

    <div class="avatar-wrapper">
      <img
        class="avatar__image"
        src="/images/user.jpg"
        alt=""
      />

      <span
        class="avatar__status"
        aria-label="У мережі"
      ></span>
    </div>

Для суто декоративного індикатора доступності самого `aria-label` на елементі може бути недостатньо, залежно від способу взаємодії. Якщо статус важливий для користувача, його потрібно передавати доступним текстом у відповідному контексті.

### CSS

    .avatar-wrapper {
      position: relative;
      width: 48px;
      height: 48px;
      flex-shrink: 0;
    }

    .avatar__image {
      display: block;
      width: 100%;
      height: 100%;
      border-radius: 50%;
      object-fit: cover;
    }

    .avatar__status {
      position: absolute;
      right: 0;
      bottom: 0;

      width: 12px;
      height: 12px;

      border: 2px solid white;
      border-radius: 50%;

      background-color: #16a34a;
    }

### Темна тема

Не варто завжди використовувати білу межу. У темній темі вона може виглядати неприродно.

    :root {
      --avatar-status-border: #ffffff;
    }

    [data-theme="dark"] {
      --avatar-status-border: #18181b;
    }

    .avatar__status {
      border-color: var(--avatar-status-border);
    }

### Важливо

Колір статусу не повинен бути єдиним способом передавання інформації.

Наприклад, разом із зеленим індикатором можна показувати текст «У мережі» в картці користувача або під час відкриття його профілю.

Не додавай індикатор онлайн, якщо застосунок не має реальних даних про присутність користувача.

## 8. Група аватарів

Група аватарів (Avatar Group) дозволяє компактно показати кількох учасників.

    [ОК] [АП] [МІ] [+3]

Застосування:

- учасники проєкту;
- групові чати;
- список співавторів;
- учасники навчальної групи;
- призначені виконавці завдання.

### HTML

    <div class="avatar-group" aria-label="Учасники проєкту">
      <img
        class="avatar-group__item"
        src="/images/user-1.jpg"
        alt="Олена Коваль"
      />

      <img
        class="avatar-group__item"
        src="/images/user-2.jpg"
        alt="Андрій Петренко"
      />

      <img
        class="avatar-group__item"
        src="/images/user-3.jpg"
        alt="Марія Іваненко"
      />
    </div>

### CSS

    .avatar-group {
      display: flex;
      align-items: center;
    }

    .avatar-group__item {
      width: 36px;
      height: 36px;

      border: 2px solid white;
      border-radius: 50%;

      object-fit: cover;
    }

    .avatar-group__item + .avatar-group__item {
      margin-left: -10px;
    }

Негативний відступ створює ефект накладання.

### Показ кількості учасників

Якщо учасників багато, немає потреби показувати всіх одночасно.

    [ОК] [АП] [МІ] [+7]

Наприклад, показуємо три аватари, а решту об'єднуємо в індикатор `+7`.

Важливо:

- не перекривати обличчя надмірно;
- зберігати видимість кожного аватара;
- пояснювати, що означає `+7`;
- за потреби відкривати список усіх учасників;
- забезпечити доступне ім'я для кнопки перегляду решти учасників.

## 9. Плейсхолдери та помилки завантаження

Аватар може не завантажитися через відсутність файлу, мережеву помилку або неправильний URL.

Інтерфейс повинен мати запасний варіант.

### Основні стани

1. Є фотографія.
2. Фотографія завантажується.
3. Фотографія не завантажилася.
4. Фотографії немає.
5. Користувач не має доступу до фотографії.

### HTML

    <img
      class="avatar__image"
      src="/images/user.jpg"
      alt=""
    />

### JavaScript: обробка помилки

    const avatarImages = document.querySelectorAll(".avatar__image");

    avatarImages.forEach((image) => {
      image.addEventListener("error", () => {
        image.hidden = true;

        const fallback = image.parentElement?.querySelector(
          ".avatar__fallback"
        );

        if (fallback) {
          fallback.hidden = false;
        }
      });
    });

Цей приклад передбачає, що зображення та запасний елемент розміщені в спільному контейнері.

### HTML із запасним варіантом

    <div class="avatar">
      <img
        class="avatar__image"
        src="/images/user.jpg"
        alt=""
      />

      <span class="avatar__fallback" hidden>
        ОК
      </span>
    </div>

### CSS

    .avatar {
      position: relative;
      display: inline-flex;
      align-items: center;
      justify-content: center;

      width: 48px;
      height: 48px;

      overflow: hidden;
      border-radius: 50%;

      background: #e0e7ff;
      color: #3730a3;
      font-weight: 600;
    }

    .avatar__image {
      position: absolute;
      inset: 0;

      width: 100%;
      height: 100%;

      object-fit: cover;
    }

    .avatar__fallback {
      display: inline-flex;
      align-items: center;
      justify-content: center;
    }

    .avatar__fallback[hidden] {
      display: none;
    }

Зверни увагу: у виробничому застосунку запасний елемент краще показувати відразу, якщо фотографія відсутня, або перемикати стани керовано. Не варто покладатися лише на CSS чи наявність події `error`.

## 10. Доступність аватарів (Accessibility)

Аватар може бути декоративним або інформативним. Від цього залежить значення `alt`.

### 10.1. Інформативне зображення

Якщо фотографія передає важливу інформацію про людину, використай змістовний альтернативний текст.

    <img
      src="/images/olena.jpg"
      alt="Олена Коваль"
    />

### 10.2. Декоративне зображення

Якщо поруч уже є ім'я, а фотографія не додає важливої інформації, можна використати порожній `alt`.

    <div class="user-row">
      <img
        src="/images/olena.jpg"
        alt=""
      />

      <span>Олена Коваль</span>
    </div>

Це дозволяє програмам читання з екрана не повторювати інформацію.

### 10.3. Аватар як кнопка

Якщо аватар відкриває профіль, він має бути частиною справжньої кнопки або посилання.

    <a href="/profile/olena" class="profile-link">
      <img
        src="/images/olena.jpg"
        alt=""
      />

      <span>Профіль Олени Коваль</span>
    </a>

У цьому прикладі текст посилання забезпечує зрозумілу назву дії.

Якщо кнопка містить лише аватар, її потрібно забезпечити доступною назвою:

    <button
      type="button"
      aria-label="Відкрити профіль Олени Коваль"
    >
      <img src="/images/olena.jpg" alt="" />
    </button>

### 10.4. Статус

Якщо статус важливий, передавай його текстом.

Наприклад:

    <div class="user-row">
      <img src="/images/olena.jpg" alt="" />

      <div>
        <p>Олена Коваль</p>
        <p>У мережі</p>
      </div>
    </div>

### Основні правила доступності

- ✔ Інформативні зображення мають доречний `alt`.
- ✔ Декоративні зображення можуть мати `alt=""`.
- ✔ Інтерактивні аватари мають доступну назву.
- ✔ Статус не передається лише кольором.
- ✔ Кнопки доступні з клавіатури.
- ✔ Фокус інтерактивного елемента помітний.
- ✔ Текст ініціалів має достатній контраст.

## 13. Аватари у формах

У налаштуваннях профілю користувач може завантажувати або змінювати фотографію.

Типові елементи:

- поточний аватар;
- кнопка завантаження;
- кнопка видалення фотографії;
- підказка про формат і розмір файлу;
- попередній перегляд;
- повідомлення про помилку.

### HTML

    <section class="profile-photo">
      <img
        class="profile-photo__preview"
        src="/images/default-avatar.png"
        alt=""
      />

      <div class="profile-photo__actions">
        <label for="avatar-file">
          Завантажити фото
        </label>

        <input
          id="avatar-file"
          type="file"
          accept="image/png, image/jpeg, image/webp"
        />

        <p>
          PNG, JPEG або WebP. Вибери квадратне зображення.
        </p>
      </div>
    </section>

### JavaScript: попередній перегляд

    const fileInput = document.querySelector("#avatar-file");
    const preview = document.querySelector(".profile-photo__preview");

    if (
      fileInput instanceof HTMLInputElement &&
      preview instanceof HTMLImageElement
    ) {
      fileInput.addEventListener("change", () => {
        const file = fileInput.files?.[0];

        if (!file) {
          return;
        }

        if (!file.type.startsWith("image/")) {
          return;
        }

        const objectUrl = URL.createObjectURL(file);
        preview.src = objectUrl;
      });
    }

Це демонстраційний приклад. У повноцінному застосунку потрібно також:

- перевіряти допустимі формати;
- обмежувати розмір файлу;
- обробляти помилки;
- відкликати попередні object URL через `URL.revokeObjectURL()`;
- перевіряти файл на сервері;
- не вважати клієнтську перевірку гарантією безпеки.

Важливо: атрибут `accept` лише підказує браузеру, які файли бажано вибирати. Він не забезпечує безпеку завантаження.

## 14. Адаптивність аватарів

Аватар повинен залишатися читабельним на різних екранах.

### Основні принципи

- Форма аватара не змінюється випадково між брейкпойнтами.
- Маленький аватар не повинен зникати без причини.
- Текст поруч має залишатися читабельним.
- Група аватарів не повинна виходити за межі контейнера.
- Інтерактивні елементи залишаються доступними для дотику.

### Приклад

    .user-card__avatar {
      width: 48px;
      height: 48px;
    }

    @media (max-width: 600px) {
      .user-card__avatar {
        width: 40px;
        height: 40px;
      }

      .user-card {
        gap: 10px;
        padding: 12px;
      }
    }

Не потрібно змінювати розмір аватара лише тому, що змінився екран. Спочатку перевір, чи є реальна проблема з простором або композицією.

### Адаптивна група

Якщо учасників багато, на вузькому екрані можна показувати меншу кількість аватарів і кнопку з рештою.

    <div class="avatar-group">
      <!-- Перші аватари -->
      <!-- Кнопка "+N" для решти учасників -->
    </div>

Це має бути свідомим рішенням інтерфейсу, а не випадковим обрізанням елементів.

- Не використовуй рух як єдиний сигнал взаємодії.

## 17. Аватари в React

У React аватар краще реалізувати як окремий повторно використовуваний компонент.

### 17.1. Прості пропси

    type AvatarProps = {
      name: string;
      src?: string;
      size?: "sm" | "md" | "lg";
    };

### 17.2. Компонент

    export function Avatar({
      name,
      src,
      size = "md",
    }: AvatarProps) {
      const initials = getInitials(name);

      return (
        <span className={`avatar avatar--${size}`}>
          {src ? (
            <img
              className="avatar__image"
              src={src}
              alt=""
            />
          ) : (
            <span className="avatar__initials">
              {initials}
            </span>
          )}
        </span>
      );
    }

Цей компонент використовує функцію `getInitials()`, яку потрібно реалізувати окремо.

### 17.3. Функція отримання ініціалів

    export function getInitials(name: string): string {
      const normalizedName = name.trim();

      if (!normalizedName) {
        return "?";
      }

      const parts = normalizedName.split(/\s+/);

      if (parts.length === 1) {
        return Array.from(parts[0]).slice(0, 2).join("").toUpperCase();
      }

      return (
        Array.from(parts[0])[0] +
        Array.from(parts[parts.length - 1])[0]
      ).toUpperCase();
    }

Функція працює з різними мовами краще, ніж просте звернення до `name[0]`, оскільки `Array.from()` враховує Unicode-кодові точки. Проте для складних імен, складених символів і специфічних правил іменування можуть знадобитися додаткові правила.

### Приклади

    getInitials("Олена Коваль"); // "ОК"
    getInitials("Андрій Петренко"); // "АП"
    getInitials("Valeriy Svystun"); // "VS"
    getInitials("Madonna"); // "MA"
    getInitials(""); // "?"

### 17.4. CSS для React-компонента

    .avatar {
      display: inline-flex;
      align-items: center;
      justify-content: center;

      flex-shrink: 0;
      overflow: hidden;

      border-radius: 50%;
      background: #e0e7ff;
      color: #3730a3;
      font-weight: 600;
    }

    .avatar--sm {
      width: 32px;
      height: 32px;
      font-size: 0.75rem;
    }

    .avatar--md {
      width: 40px;
      height: 40px;
      font-size: 0.875rem;
    }

    .avatar--lg {
      width: 56px;
      height: 56px;
      font-size: 1rem;
    }

    .avatar__image {
      width: 100%;
      height: 100%;
      object-fit: cover;
    }

    .avatar__initials {
      display: inline-flex;
      align-items: center;
      justify-content: center;
    }

### 17.5. Обробка помилки зображення в React

Для React краще використовувати стан компонента, а не маніпулювати DOM вручну.

    import { useState } from "react";

    type AvatarProps = {
      name: string;
      src?: string;
    };

    export function Avatar({ name, src }: AvatarProps) {
      const [imageFailed, setImageFailed] = useState(false);

      const initials = getInitials(name);
      const showImage = Boolean(src) && !imageFailed;

      return (
        <span className="avatar">
          {showImage ? (
            <img
              className="avatar__image"
              src={src}
              alt=""
              onError={() => setImageFailed(true)}
            />
          ) : (
            <span className="avatar__initials">
              {initials}
            </span>
          )}
        </span>
      );
    }

Цей варіант показує ініціали, якщо URL відсутній або зображення не завантажилося.

Якщо `src` змінюється в тому самому екземплярі компонента, потрібно також продумати скидання стану помилки для нового URL. Це можна реалізувати окремою логікою або через стабільний `key`, якщо зміна джерела означає інший екземпляр аватара.

## 18. Аватари в Next.js

У Next.js для оптимізованих зображень часто використовується `next/image`.

### Приклад

    import Image from "next/image";

    type AvatarProps = {
      name: string;
      src: string;
    };

    export function Avatar({ name, src }: AvatarProps) {
      return (
        <span className="avatar">
          <Image
            src={src}
            alt=""
            width={48}
            height={48}

### Важливі моменти

- Для зовнішніх джерел зображень потрібно налаштувати дозволені джерела відповідно до версії Next.js.
- Для локальних файлів можна використовувати шлях із `public`, наприклад `/images/user.jpg`.
- Розміри зображення мають бути визначені.
- Потрібно продумати запасний варіант, якщо зображення не завантажилося.
- Якщо аватар суто декоративний і ім'я вже наведено поруч, `alt=""` може бути доречним.
- Не передавай довільні зовнішні URL, не перевіривши політику завантаження та довіру до джерела.

### Коли достатньо звичайного `img`

У невеликому навчальному проєкті звичайного `img` може бути достатньо. Важливо розуміти різницю між базовим HTML-зображенням і можливостями оптимізації Next.js.

## 19. Типізація даних користувача в TypeScript

Аватар зазвичай отримує інформацію з об'єкта користувача.

    type User = {
      id: string;
      name: string;
      avatarUrl?: string;
      role?: string;
    };

Приклад даних:

    const user: User = {
      id: "user-1",
      name: "Олена Коваль",
      avatarUrl: "/images/olena.jpg",

Використання:

    <Avatar
      name={user.name}

      size="md"

Не потрібно використовувати `any`, коли тип даних можна описати явно.

### Розділяй дані та відображення

Об'єкт користувача описує дані:

    type User = {
      id: string;
      name: string;
      avatarUrl?: string;
    };

Компонент аватара описує відображення:

    type AvatarProps = {
      name: string;
      src?: string;
      size?: "sm" | "md" | "lg";
    };

Так компонент залишається незалежним від того, звідки надійшли дані: із масиву, API, бази даних або форми.

## 20. Продуктивність і безпека

### Продуктивність

Якщо список містить десятки або сотні користувачів:

- використовуй зображення відповідного розміру;
- не завантажуй великі оригінали для маленьких аватарів без потреби;
- застосовуй ліниве завантаження для зображень поза початковою видимою областю;
- не додавай надмірних анімацій;
- не створюй важку логіку для кожного аватара без необхідності.

Для звичайного HTML:

    <img
      src="/images/user.jpg"
      alt=""
      loading="lazy"
      width="48"
      height="48"
    />

Для найважливіших зображень у початковій видимій області стратегія завантаження може бути іншою. Не встановлюй `loading="lazy"` механічно для всіх зображень.

### Безпека

Аватар може надходити від користувача або зовнішнього сервісу.

Враховуй:

- перевірку завантажених файлів на сервері;
- обмеження розміру;
- перевірку дозволених форматів;
- безпечне зберігання файлів;
- контроль доступу до приватних фотографій;
- захист від небезпечних або підроблених файлів;
- політику довіри до зовнішніх URL.

Перевірка MIME-типу на клієнті не замінює серверної перевірки.

## 21. Типові помилки в дизайні аватарів

### Помилка 1. Різні розміри без причини

У сусідніх рядках аватари мають різну ширину та висоту.

**Рішення:** створи обмежений набір розмірів і використовуй його послідовно.

### Помилка 2. Розтягнуті фотографії

Обличчя виглядають неприродно.

**Рішення:** використовуй `object-fit: cover` для фотографій людей.

### Помилка 3. Нечитабельні ініціали

Колір тексту майже не відрізняється від фону.

**Рішення:** перевіряй контраст і розмір шрифту.

### Помилка 4. Відсутній запасний варіант

Якщо фото не завантажилося, залишається порожнє місце.

**Рішення:** показуй ініціали, стандартну іконку або інший заповнювач.

### Помилка 5. Надто багато накладання

У групі аватарів видно лише маленькі фрагменти фотографій.

**Рішення:** зменш накладання або показуй менше учасників.

### Помилка 6. Немає доступної назви кнопки

Аватар відкриває меню, але користувачі програм читання з екрана не розуміють призначення кнопки.

**Рішення:** додай зрозумілу доступну назву.

### Помилка 7. Статус передається лише кольором

Зелена крапка є єдиною ознакою доступності.

**Рішення:** додавай текст статусу в контексті, де ця інформація важлива.

### Помилка 8. Зайва анімація

Аватар постійно пульсує або сильно збільшується.

**Рішення:** використовуй анімацію лише тоді, коли вона допомагає взаємодії.

### Помилка 9. Аватар замість імені всюди

Користувачів неможливо швидко розрізнити, особливо якщо фотографії схожі або відсутні.

**Рішення:** показуй ім'я там, де воно потрібне для виконання завдання.

### Помилка 10. Надмірне кадрування

Обличчя або важливі частини логотипа обрізані.

## 22. Мініпроєкт: компонент Avatar

**Мета:** створити повторно використовуваний компонент аватара, який підтримує фотографію, ініціали, розміри й запасний варіант.

### Вимоги

1. Компонент отримує ім'я користувача.
2. Фотографія необов'язкова.
3. Якщо фотографії немає, показуються ініціали.
4. Якщо фотографія не завантажилася, показуються ініціали.
5. Підтримуються три розміри: `sm`, `md`, `lg`.
6. Аватар не стискається в flex-контейнері.
7. Фотографія не розтягується.
8. Ініціали мають достатній контраст.
9. Компонент не залежить від конкретного користувача.
10. Код має типи TypeScript без `any`.

    15-avatars/
    ├── README.md
    ├── index.html
    ├── styles.css
    └── script.js

    15-avatars/
    └── react/
        ├── Avatar.tsx
        ├── Avatar.module.css
        └── page.tsx

## 25. Що потрібно запам'ятати

1. Аватар представляє людину, команду або організацію.
2. Основні варіанти — фотографія, ініціали, іконка та ілюстрація.
3. Найчастіше для фотографій людей використовують круглу форму.
4. `object-fit: cover` заповнює контейнер і обрізає зайві частини зображення.
5. `object-position` допомагає керувати кадруванням.
6. Розміри аватарів краще організувати через дизайн-токени.
7. Якщо фотографії немає або вона не завантажилася, потрібен запасний варіант.
8. `alt` залежить від того, чи є зображення інформативним або декоративним.
9. Якщо аватар інтерактивний, йому потрібна доступна назва.
10. Статус користувача не повинен передаватися лише кольором.
11. Групи аватарів мають показувати достатньо інформації, не перевантажуючи інтерфейс.
12. У React аватар варто реалізувати як повторно використовуваний компонент із чіткими пропсами.
13. У TypeScript краще використовувати конкретні типи, а не `any`.
14. Завантаження фотографій вимагає серверної перевірки та контролю доступу.
15. Якісний аватар має бути послідовним, доступним і зрозумілим у різних контекстах.

## 28. Місце теми в UI Design

    └── 05-components/
        ├── 01-buttons/
        ├── ...
        ├── 13-tooltips/

Аватари належать до компонентів інтерфейсу, оскільки є повторно використовуваними візуальними елементами.

Вони поєднують кілька напрямів UI-дизайну:

- **Visual Design** — форма, колір, пропорції та композиція.
- **Typography** — ініціали, розмір шрифту та читабельність.
- **Layout** — розташування аватара поруч із текстом та іншими елементами.
- **Responsive Design** — поведінка на різних екранах.
- **Accessibility** — альтернативний текст, назви кнопок і контраст.
- **Component Design** — повторне використання та стандартизація.
- **Frontend Development** — HTML, CSS, JavaScript, React і TypeScript.

**Головний принцип:** аватар — це не просто кругла фотографія. Це компонент, який повинен допомагати ідентифікувати користувача, залишатися зрозумілим без фотографії та працювати послідовно в усьому застосунку.
