# 12. Modals — Модальні вікна

Модальне вікно (Modal) — це компонент інтерфейсу, який відкривається поверх основного вмісту сторінки та тимчасово переводить увагу користувача на окреме завдання або повідомлення.

Модальне вікно зазвичай затемнює фон, блокує взаємодію з основною сторінкою та пропонує користувачу виконати дію, прочитати інформацію або підтвердити рішення.

Модальні вікна використовують у формах входу, підтвердженні видалення, налаштуваннях, перегляді зображень, створенні записів та інших сценаріях.

---

## 1. Для чого потрібні модальні вікна

Модальні вікна допомагають виконати важливу дію, не переходячи на іншу сторінку.

Приклади:

- підтвердження видалення запису;
- форма входу або реєстрації;
- створення нового користувача;
- редагування профілю;
- перегляд фотографії;
- коротке повідомлення про результат дії;
- вибір налаштувань;
- підтвердження скасування змін.

### Приклад

Користувач натискає кнопку:

    Видалити користувача

Замість негайного видалення відкривається модальне вікно:

    ┌────────────────────────────────────┐
    │ Видалити користувача?          [×] │
    │                                    │
    │ Цю дію неможливо скасувати.        │
    │                                    │
    │       [Скасувати] [Видалити]       │
    └────────────────────────────────────┘

Користувач може скасувати дію або підтвердити видалення.

## 2. Modal, Dialog, Popover, Tooltip

Ці компоненти можуть виглядати схоже, але виконують різні завдання.

### Modal

Модальне вікно привертає увагу до важливого завдання та зазвичай блокує взаємодію з основною сторінкою.

Приклади:

- підтвердження видалення;
- форма створення запису;
- вхід до системи.

### Dialog

Dialog — діалоговий компонент, який представляє окреме вікно взаємодії.

У веброзробці терміни `dialog` і `modal` часто використовують разом, але вони не завжди означають одне й те саме.

HTML-елемент `<dialog>` може працювати як модальний або немодальний діалог.

### Popover

Popover — невелика панель, яка відкривається біля кнопки або іншого елемента.

Приклади:

- меню додаткових дій;
- вибір параметрів;
- коротка панель налаштувань.

На відміну від модального вікна, popover зазвичай не перекриває весь екран і не блокує всю сторінку.

### Tooltip

Tooltip — коротка підказка, яка пояснює призначення елемента.

Приклад:

    [i]  Наведіть курсор, щоб дізнатися більше.

Tooltip не призначений для складних форм або підтвердження важливих дій.

### Що запам'ятати

- Modal — важливе завдання поверх сторінки.
- Dialog — діалогове вікно для взаємодії.
- Popover — компактна панель біля елемента.
- Tooltip — коротка підказка.

## 3. Основні типи модальних вікон

### 3.1. Confirmation modal

Модальне вікно підтвердження.

Використовується перед важливою або потенційно незворотною дією.

Приклад:

    Видалити запис?

    Після видалення відновити його буде неможливо.

    [Скасувати] [Видалити]

Рекомендації:

- чітко пояснювати наслідки;
- використовувати зрозумілі назви кнопок;
- візуально відокремлювати небезпечну дію;
- не робити кнопку підтвердження активною без потреби.

### 3.2. Form modal

Модальне вікно з формою.

Приклади:

- створення нового запису;
- редагування профілю;
- додавання курсу;
- створення події.

Рекомендації:

- використовувати короткі форми;
- групувати пов'язані поля;
- показувати помилки біля відповідних полів;
- не допускати, щоб форма виходила за межі екрана;
- передбачати прокручування вмісту на мобільних пристроях.

### 3.3. Information modal

Інформаційне модальне вікно.

Приклади:

- пояснення правил;
- інформація про функцію;
- повідомлення про важливу зміну.

Якщо повідомлення коротке й не потребує взаємодії, іноді краще використати звичайне повідомлення або toast.

### 3.4. Success modal

Модальне вікно успішного завершення дії.

Приклад:

    ✓ Запис успішно створено.

    [Переглянути запис] [Закрити]

Не варто відкривати модальне вікно після кожної незначної дії. Для простих повідомлень часто достатньо toast або inline-повідомлення.

### 3.5. Image modal / Lightbox

Модальне вікно для перегляду зображень у збільшеному розмірі.

Може містити:

- зображення;
- підпис;
- кнопки попереднього та наступного зображення;
- кнопку закриття;
- лічильник зображень.

### 3.6. Full-screen modal

Модальне вікно, яке займає майже весь або весь екран.

Особливо корисне на мобільних пристроях, коли форма має багато полів або потребує значного простору.

## 4. Анатомія модального вікна

Типове модальне вікно складається з кількох частин.

    ┌────────────────────────────────────┐
    │ Заголовок                      [×] │
    ├────────────────────────────────────┤
    │                                    │
    │ Основний вміст                     │
    │                                    │
    │ Текст, поля форми або інші дані    │
    │                                    │
    ├────────────────────────────────────┤
    │                 [Скасувати] [OK]   │
    └────────────────────────────────────┘

### 4.1. Overlay / Backdrop

Overlay — затемнений фон за модальним вікном.

Призначення:

- відокремити модальне вікно від сторінки;
- зменшити візуальну активність фону;
- підкреслити важливість поточної взаємодії.

Типові стилі:

    background: rgb(0 0 0 / 50%);

Затемнення не повинно бути єдиним засобом передавання інформації. Важливі стани потрібно позначати також текстом та іншими візуальними засобами.

### 4.2. Modal container

Основна панель модального вікна.

Вона містить заголовок, вміст і дії.

Типові властивості:

- `width` або `max-width`;
- `padding`;
- `border-radius`;
- `background`;
- `box-shadow`;
- `max-height`;
- `overflow`.

### 4.3. Header

Заголовок повідомляє, що саме відбувається.

Приклади:

- Створити курс
- Редагувати профіль
- Видалити запис?
- Налаштування сповіщень

Заголовок повинен бути коротким і зрозумілим.

### 4.4. Close button

Кнопка закриття, зазвичай позначена символом `×`.

Важливо:

- реалізувати її як справжню кнопку;
- додати доступну назву;
- забезпечити достатню область натискання;
- не розміщувати її занадто близько до краю.

Приклад HTML:

    <button type="button" aria-label="Закрити вікно">
      ×
    </button>

### 4.5. Body

Основна частина модального вікна.

Може містити:

- текст;
- форму;
- зображення;
- список;
- попередження;
- інші компоненти.

Не перевантажуй body другорядною інформацією.

### 4.6. Footer / Actions

Нижня частина з кнопками.

Типові дії:

- Скасувати;
- Зберегти;
- Підтвердити;
- Видалити;
- Закрити.

Кнопки потрібно розташовувати відповідно до важливості та звичних сценаріїв взаємодії.

## 5. Принципи хорошого дизайну модальних вікон

### 5.1. Одна головна мета

Кожне модальне вікно повинно мати зрозумілу мету.

Погано:

    Налаштування, профіль, повідомлення,
    довідка та створення нового запису
    в одному вікні.

Краще:

    Одне вікно — одне основне завдання.

### 5.2. Візуальна ієрархія

Користувач повинен легко розпізнавати:

1. заголовок;
2. основний текст або форму;
3. головну дію;
4. другорядну дію;
5. спосіб закриття.

### 5.3. Мінімум зайвих елементів

Не додавай кнопки, декоративні блоки або пояснення, які не допомагають виконати завдання.

### 5.4. Зрозумілі назви кнопок

Погано:

    [Так] [Ні]

Краще:

    [Залишитися] [Видалити запис]

Назви повинні пояснювати наслідок дії.

### 5.5. Правильна ширина

Типові орієнтири для настільного інтерфейсу:

- вузьке підтвердження: приблизно 320–420 px;
- стандартна форма: приблизно 440–600 px;
- складний вміст: ширше, якщо цього потребує завдання.

Це не жорсткі правила. Розмір залежить від вмісту, типографіки та ширини екрана.

### 5.6. Достатні внутрішні відступи

Приклад базової системи:

    padding: 24px;
    gap: 16px;

Для компактного вікна можна використовувати менші відступи, але не варто стискати текст і кнопки до незручного стану.

### 5.7. Контраст і фокус

Після відкриття користувач повинен чітко бачити межі вікна та елементи керування.

Перевіряй:

- контраст тексту;
- видимість фокусу клавіатури;
- контраст кнопок;
- помітність помилок;
- доступність кнопки закриття.

## 6. Overlay, позиціювання та шари

Модальне вікно зазвичай розташовується поверх решти сторінки.

### 6.1. Позиціювання overlay

Для класичного модального вікна часто використовують `position: fixed`.

    .modal-overlay {
      position: fixed;
      inset: 0;

      display: grid;
      place-items: center;

      padding: 16px;
      background: rgb(0 0 0 / 50%);
    }

Пояснення:

- `position: fixed` прив'язує overlay до вікна браузера;
- `inset: 0` розтягує його на всю доступну область;
- `display: grid` разом із `place-items: center` центрує вміст;
- `padding` не дозволяє модальному вікну торкатися країв екрана.

### 6.2. Z-index

`z-index` визначає порядок розташування елементів у відповідному контексті накладання.

Приклад:

    .modal-overlay {
      z-index: 1000;
    }

Число `1000` не є універсальним стандартом. У реальному проєкті краще створити систему шарів.

    :root {
      --z-dropdown: 100;
      --z-sticky: 200;
      --z-overlay: 900;
      --z-modal: 1000;
      --z-toast: 1100;
    }

Потрібно пам'ятати: `z-index` залежить також від stacking context. Елемент із великим значенням не обов'язково перекриє інший елемент, якщо вони належать до різних контекстів накладання.

### 6.3. Обмеження висоти

Модальне вікно не повинно виходити за межі видимої області.

    .modal {
      width: min(100%, 520px);
      max-height: calc(100dvh - 32px);
      overflow-y: auto;
    }

`100dvh` враховує динамічну висоту viewport у сучасних браузерах. Для складніших модальних вікон варто окремо організувати прокручування заголовка, body і footer.

## 7. HTML та CSS: просте модальне вікно

Нижче — навчальний приклад без JavaScript.

### HTML

    <div class="modal-overlay">
      <section
        class="modal"
        role="dialog"
        aria-labelledby="modal-title"
        aria-describedby="modal-description"
      >
        <header class="modal-header">
          <h2 id="modal-title">Видалити запис?</h2>

          <button
            class="modal-close"
            type="button"
            aria-label="Закрити вікно"
          >
            ×
          </button>
        </header>

        <div class="modal-body">
          <p id="modal-description">
            Цю дію неможливо скасувати.
          </p>
        </div>

        <footer class="modal-footer">
          <button type="button" class="button-secondary">
            Скасувати
          </button>

          <button type="button" class="button-danger">
            Видалити
          </button>
        </footer>
      </section>
    </div>

### CSS

    .modal-overlay {
      position: fixed;
      inset: 0;
      z-index: 1000;

      display: grid;
      place-items: center;

      padding: 16px;
      background: rgb(0 0 0 / 50%);
    }

    .modal {
      width: min(100%, 440px);
      max-height: calc(100dvh - 32px);
      overflow-y: auto;

      padding: 24px;
      border-radius: 16px;

      background: #fff;
      color: #222;
      box-shadow: 0 16px 48px rgb(0 0 0 / 20%);
    }

    .modal-header {
      display: flex;
      align-items: center;
      justify-content: space-between;
      gap: 16px;
    }

    .modal-header h2 {
      margin: 0;
      font-size: 1.25rem;
    }

    .modal-close {
      display: grid;
      place-items: center;

      width: 40px;
      height: 40px;

      border: 0;
      border-radius: 8px;
      background: transparent;

      font-size: 1.5rem;
      cursor: pointer;
    }

    .modal-close:hover {
      background: #f0f0f0;
    }

    .modal-body {
      margin-block: 20px;
      line-height: 1.6;
    }

    .modal-footer {
      display: flex;
      justify-content: flex-end;
      flex-wrap: wrap;
      gap: 12px;
    }

    .button-secondary,
    .button-danger {
      min-height: 44px;
      padding: 10px 16px;

      border: 0;
      border-radius: 8px;

      font: inherit;
      cursor: pointer;
    }

    .button-secondary {
      background: #eee;
      color: #222;
    }

    .button-danger {
      background: #b42318;
      color: #fff;
    }

    .modal-close:focus-visible,
    .button-secondary:focus-visible,
    .button-danger:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

**Важливо:** це лише візуальний каркас. Він самостійно не відкривається й не закривається, не блокує фокус поза вікном і не керує клавіатурою. Для справжнього модального компонента потрібна поведінка, описана нижче.

## 8. HTML `<dialog>` — нативний діалог

HTML має вбудований елемент `<dialog>`, який може спростити створення модальних вікон.

Коли викликається метод `showModal()`, браузер відкриває діалог у верхньому шарі сторінки, створює модальний стан і забезпечує частину стандартної клавіатурної поведінки.

### HTML

    <button type="button" id="open-dialog">
      Відкрити вікно
    </button>

    <dialog id="example-dialog">
      <h2>Підтвердження</h2>

      <p>Ви хочете продовжити?</p>

      <form method="dialog">
        <button value="cancel">Скасувати</button>
        <button value="confirm">Продовжити</button>
      </form>
    </dialog>

### JavaScript

    const openButton = document.querySelector("#open-dialog");
    const dialog = document.querySelector("#example-dialog");

    if (
      openButton instanceof HTMLButtonElement &&
      dialog instanceof HTMLDialogElement
    ) {
      openButton.addEventListener("click", () => {
        dialog.showModal();
      });
    }

У прикладі використано перевірки типів DOM-елементів, щоб не звертатися до методів без підтвердження типу.

### CSS для `<dialog>`

    dialog {
      width: min(440px, calc(100% - 32px));
      max-height: calc(100dvh - 32px);

      padding: 24px;
      border: 0;
      border-radius: 16px;

      background: #fff;
      color: #222;

      box-shadow: 0 16px 48px rgb(0 0 0 / 20%);
    }

    dialog::backdrop {
      background: rgb(0 0 0 / 50%);
    }

### `show()` та `showModal()`

- `show()` відкриває діалог у немодальному режимі.
- `showModal()` відкриває діалог у модальному режимі.

У модальному режимі решта документа стає недоступною для звичайної взаємодії, доки діалог відкритий.

### Форма з `method="dialog"`

Коли кнопка форми всередині `<dialog>` активується, браузер закриває діалог. Значення її атрибута `value` стає результатом діалогу.

Приклад:

    <form method="dialog">
      <button value="cancel">Скасувати</button>
      <button value="confirm">Підтвердити</button>
    </form>

Після закриття можна перевірити `dialog.returnValue`, щоб визначити, яку кнопку вибрав користувач.

    dialog.addEventListener("close", () => {
      console.log(dialog.returnValue);
    });

Не використовуй `method="dialog"` як заміну реальному надсиланню форми на сервер. Це механізм керування діалогом, а не збереження даних.

## 9. Керування відкриттям і закриттям

Модальне вікно повинно мати зрозумілий життєвий цикл.

Типовий сценарій:

1. Користувач натискає кнопку відкриття.
2. Модальне вікно з'являється.
3. Фокус переходить усередину вікна.
4. Користувач виконує дію або скасовує її.
5. Вікно закривається.
6. Фокус повертається до елемента, який його відкрив.

### Основні способи закриття

- кнопка закриття;
- кнопка «Скасувати»;
- клавіша `Escape`, якщо це дозволено сценарієм;
- натискання на backdrop, якщо це передбачено дизайном;
- завершення успішної дії.

### Чи потрібно закривати вікно натисканням на backdrop?

Це залежить від призначення модального вікна.

Для простого перегляду зображення така поведінка часто доречна.

Для складної форми або важливого підтвердження випадкове закриття може призвести до втрати даних. У таких сценаріях варто або вимкнути закриття через backdrop, або попереджати про незбережені зміни.

### Чи потрібно завжди дозволяти `Escape`?

Для звичайних модальних вікон це очікувана поведінка. Але в окремих сценаріях може знадобитися спеціальна логіка, наприклад підтвердження виходу з форми.

Не блокуй `Escape` без вагомої причини: користувач повинен мати доступний спосіб вийти з діалогу.

## 10. Доступність модальних вікон (Accessibility)

Доступність особливо важлива для модальних компонентів, тому що вони змінюють звичайний порядок взаємодії зі сторінкою.

### 10.1. Правильний заголовок

Використовуй `aria-labelledby`, щоб пов'язати діалог із його заголовком.

    <dialog aria-labelledby="dialog-title">
      <h2 id="dialog-title">Створити запис</h2>
    </dialog>

### 10.2. Опис діалогу

Якщо додатковий текст пояснює призначення вікна, можна використати `aria-describedby`.

    <dialog
      aria-labelledby="dialog-title"
      aria-describedby="dialog-description"
    >
      <h2 id="dialog-title">Видалити запис?</h2>

      <p id="dialog-description">
        Відновити видалений запис буде неможливо.
      </p>
    </dialog>

Для довгого або структурованого вмісту не завжди потрібно призначати весь текст як один опис. Важливо, щоб читач екрана не отримував надто великий і незручний фрагмент одразу.

### 10.3. Керування фокусом

Після відкриття фокус повинен опинитися в логічному місці всередині діалогу.

Залежно від сценарію це може бути:

- перше поле форми;
- заголовок із `tabindex="-1"`;
- основна кнопка;
- інший елемент, який найкраще відповідає завданню.

У нативного `<dialog>` з `showModal()` браузер уже забезпечує частину цієї поведінки. У саморобному компоненті її потрібно реалізувати самостійно.

Після закриття фокус зазвичай повертається до кнопки, яка відкрила вікно.

### 10.4. Tab та Shift + Tab

Під час відкритого модального вікна клавіатурна навігація не повинна переходити до інтерактивних елементів основної сторінки.

У повноцінному власному компоненті потрібно правильно обмежувати фокус усередині діалогу. Не покладайся лише на CSS або `z-index`.

### 10.5. Клавіатура

Перевір:

- `Tab` — перехід до наступного елемента;
- `Shift + Tab` — перехід до попереднього;
- `Enter` — активація кнопки або надсилання форми;
- `Space` — активація відповідних кнопок;
- `Escape` — закриття, якщо це дозволяє сценарій.

### 10.6. Доступна назва кнопки закриття

Символ `×` сам по собі може бути недостатнім для зрозумілого озвучення.

    <button type="button" aria-label="Закрити вікно">
      ×
    </button>

### 10.7. Контраст та індикація фокусу

Не прибирай outline без альтернативи.

    button:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 3px;
    }

### 10.8. `aria-modal`

Для саморобного діалогу, який справді працює модально, може бути потрібен атрибут:

    <div
      role="dialog"
      aria-modal="true"
      aria-labelledby="modal-title"
    >
      ...
    </div>

Але сам по собі `aria-modal="true"` не робить елемент повноцінним модальним вікном. Він не блокує фокус, не закриває вікно і не забезпечує клавіатурну поведінку.

Якщо використовується нативний `<dialog>` із `showModal()`, браузер уже надає відповідну семантику модального діалогу.

## 11. Модальні вікна та форми

Форма всередині модального вікна повинна поводитися так само надійно, як форма на окремій сторінці.

### Основні правила

- використовуй справжні `<label>` для полів;
- показуй помилки біля відповідних полів;
- не очищай дані користувача при випадковому закритті;
- блокуй повторне надсилання, якщо запит уже виконується;
- показуй стан завантаження;
- повідомляй про успіх або помилку;
- повертай фокус у логічне місце після завершення.

### Приклад структури

    <dialog aria-labelledby="create-title">
      <form id="create-form">
        <h2 id="create-title">Створити курс</h2>

        <label for="course-name">Назва курсу</label>
        <input
          id="course-name"
          name="courseName"
          type="text"
          required
        />

        <label for="course-description">Опис</label>
        <textarea
          id="course-description"
          name="courseDescription"
          rows="4"
        ></textarea>

        <div class="modal-footer">
          <button type="button" id="cancel-create">
            Скасувати
          </button>

          <button type="submit">
            Створити
          </button>
        </div>
      </form>
    </dialog>

У цьому прикладі кнопка «Скасувати» має `type="button"`, щоб вона не надсилала форму. Кнопка «Створити» має `type="submit"`.

Для реального застосунку потрібно також додати обробник надсилання, валідацію, запит до API та обробку результату.

## 12. Анімація модального вікна

Анімація може зробити відкриття та закриття зрозумілішими.

Типові ефекти:

- плавна поява overlay;
- невелике збільшення панелі;
- переміщення панелі на кілька пікселів;
- плавне зникнення під час закриття.

Не варто використовувати довгу або надмірно декоративну анімацію для звичайного підтвердження.

### Приклад CSS

    .modal-panel {
      animation: modal-enter 180ms ease-out;
    }

    @keyframes modal-enter {
      from {
        opacity: 0;
        transform: translateY(8px) scale(0.98);
      }

      to {
        opacity: 1;
        transform: translateY(0) scale(1);
      }
    }

### Підтримка reduced motion

Деякі користувачі віддають перевагу мінімальній анімації.

    @media (prefers-reduced-motion: reduce) {
      .modal-panel {
        animation: none;
      }
    }

Цей приклад стосується появи панелі. Якщо додаєш окрему анімацію закриття, потрібно врахувати її завершення, щоб не приховати вікно до завершення анімації або не залишити його інтерактивним після закриття.

## 13. Адаптивність модальних вікон

Модальне вікно має залишатися зручним на смартфонах, планшетах і великих екранах.

### Desktop

Зазвичай використовують:

- обмежену ширину;
- центрування;
- помірні внутрішні відступи;
- затемнений фон.

### Tablet

Потрібно перевірити:

- ширину вікна;
- довгі заголовки;
- розміщення кнопок;
- висоту форми.

### Mobile

Корисні рішення:

- ширина майже на весь екран;
- менші зовнішні відступи;
- прокручування довгого вмісту;
- достатні області натискання;
- зручне розміщення кнопок;
- у відповідних сценаріях — повноекранний діалог.

### Приклад адаптивного CSS

    .modal {
      width: min(100%, 520px);
      max-height: calc(100dvh - 32px);
      overflow-y: auto;

      padding: 24px;
      border-radius: 16px;
    }

    @media (max-width: 480px) {
      .modal-overlay {
        padding: 8px;
      }

      .modal {
        width: 100%;
        max-height: calc(100dvh - 16px);
        padding: 16px;
        border-radius: 12px;
      }

      .modal-footer {
        flex-direction: column-reverse;
      }

      .modal-footer button {
        width: 100%;
      }
    }

Порядок кнопок потрібно вибирати відповідно до логіки сценарію. `column-reverse` змінює візуальний порядок, тому перед використанням перевір, чи не виникає плутанина між візуальним і DOM-порядком.

### Важливе зауваження про мобільну клавіатуру

Якщо модальне вікно містить поле введення, екранна клавіатура може зменшувати видиму область.

Перевіряй:

- чи залишається активне поле видимим;
- чи можна прокрутити форму;
- чи доступні кнопки;
- чи не обрізається заголовок;
- чи працює закриття без втрати введених даних.

## 14. Модальні вікна в JavaScript

У невеликому vanilla JavaScript-проєкті можна почати з нативного `<dialog>`.

### Мінімальна реалізація

    const openButton = document.querySelector("#open-dialog");
    const dialog = document.querySelector("#example-dialog");
    const closeButton = document.querySelector("#close-dialog");

    if (
      openButton instanceof HTMLButtonElement &&
      dialog instanceof HTMLDialogElement &&
      closeButton instanceof HTMLButtonElement
    ) {
      openButton.addEventListener("click", () => {
        dialog.showModal();
      });

      closeButton.addEventListener("click", () => {
        dialog.close();
      });
    }

HTML:

    <button type="button" id="open-dialog">
      Відкрити
    </button>

    <dialog id="example-dialog" aria-labelledby="example-title">
      <h2 id="example-title">Приклад діалогу</h2>

      <p>Це просте модальне вікно.</p>

      <button type="button" id="close-dialog">
        Закрити
      </button>
    </dialog>

Цей приклад використовує базові можливості браузера. Для складного застосунку потрібно також обробити надсилання форми, результат діалогу, повторні відкриття та інші сценарії.

### Подія `close`

Подію `close` можна використати для реакції на завершення роботи з діалогом.

    dialog.addEventListener("close", () => {
      console.log("Діалог закрито");
    });

### Подія `cancel`

Подія `cancel` зазвичай виникає, коли користувач намагається скасувати модальний діалог, наприклад натискає `Escape`.

    dialog.addEventListener("cancel", () => {
      console.log("Користувач намагається закрити діалог");
    });

Якщо потрібно заборонити закриття в окремому сценарії, можна скасувати стандартну поведінку цієї події. Але роби це лише за необхідності та завжди залишай зрозумілий спосіб вийти з діалогу.

## 15. Модальні вікна в React

У React стан відкриття модального вікна зазвичай зберігається в `useState`.

### Приклад

    "use client";

    import { useState } from "react";

    export default function ModalExample() {
      const [isOpen, setIsOpen] = useState(false);

      return (
        <main>
          <button
            type="button"
            onClick={() => setIsOpen(true)}
          >
            Відкрити модальне вікно
          </button>

          {isOpen && (
            <div className="modal-overlay">
              <section
                className="modal"
                role="dialog"
                aria-modal="true"
                aria-labelledby="modal-title"
              >
                <h2 id="modal-title">
                  Привіт!
                </h2>

                <p>
                  Це приклад модального вікна в React.
                </p>

                <button
                  type="button"
                  onClick={() => setIsOpen(false)}
                >
                  Закрити
                </button>
              </section>
            </div>
          )}
        </main>
      );
    }

### Що відбувається

1. `isOpen` зберігає стан модального вікна.
2. Початкове значення `false` означає, що вікно закрите.
3. Натискання кнопки встановлює `true`.
4. Умовний рендеринг додає модальне вікно до інтерфейсу.
5. Натискання «Закрити» встановлює `false`.
6. React прибирає модальне вікно з DOM.

### Важливо

Це навчальний приклад стану та умовного рендерингу, а не повноцінний production-ready modal.

Власна реалізація має додатково забезпечувати:

- керування фокусом;
- повернення фокусу після закриття;
- обробку `Escape`;
- ізоляцію фокусу від основної сторінки;
- правильну роботу backdrop;
- прокручування;
- коректну поведінку вкладених компонентів.

Для складних застосунків варто розглянути перевірені бібліотеки доступних компонентів або використати нативний `<dialog>` із контрольованим станом React.

## 16. Модальні вікна в Next.js

У Next.js App Router інтерактивне модальне вікно зазвичай реалізують у Client Component, якщо воно використовує React state та обробники подій.

Приклад структури:

    app/
    ├── page.tsx
    └── components/
        └── ConfirmModal.tsx

### `ConfirmModal.tsx`

    "use client";

    import { useState } from "react";

    type ConfirmModalProps = {
      title: string;
      description: string;
      onConfirm: () => void;
    };

    export default function ConfirmModal({
      title,
      description,
      onConfirm,
    }: ConfirmModalProps) {
      const [isOpen, setIsOpen] = useState(false);

      function handleConfirm() {
        onConfirm();
        setIsOpen(false);
      }

      return (
        <>
          <button
            type="button"
            onClick={() => setIsOpen(true)}
          >
            Видалити
          </button>

          {isOpen && (
            <div className="modal-overlay">
              <section
                className="modal"
                role="dialog"
                aria-modal="true"
                aria-labelledby="confirm-title"
                aria-describedby="confirm-description"
              >
                <h2 id="confirm-title">
                  {title}
                </h2>

                <p id="confirm-description">
                  {description}
                </p>

                <div className="modal-footer">
                  <button
                    type="button"
                    onClick={() => setIsOpen(false)}
                  >
                    Скасувати
                  </button>

                  <button
                    type="button"
                    onClick={handleConfirm}
                  >
                    Підтвердити
                  </button>
                </div>
              </section>
            </div>
          )}
        </>
      );
    }

### Приклад використання

    import ConfirmModal from "./components/ConfirmModal";

    export default function Page() {
      function handleDelete() {
        console.log("Запит на видалення");
      }

      return (
        <main>
          <h1>Керування записами</h1>

          <ConfirmModal
            title="Видалити запис?"
            description="Цю дію неможливо скасувати."
            onConfirm={handleDelete}
          />
        </main>
      );
    }

### Що потрібно врахувати

Це демонстрація архітектури компонента, а не завершена реалізація видалення.

У реальному застосунку:

- `onConfirm` може запускати асинхронний запит;
- потрібно обробляти помилки;
- не слід закривати вікно до завершення операції, якщо користувач має бачити її результат;
- бажано показувати стан завантаження;
- потрібно захиститися від повторного натискання;
- після успішного видалення слід оновити дані інтерфейсу;
- потрібно забезпечити повну доступність діалогу.

Не зберігай у модальному компоненті бізнес-логіку, яка належить до окремого шару застосунку, якщо це ускладнює повторне використання.

## 17. Структура багаторазового Modal-компонента

У більших React-проєктах корисно відокремити універсальну оболонку модального вікна від конкретного вмісту.

Приклад структури:

    components/
    └── modal/
        ├── Modal.tsx
        ├── Modal.module.css
        ├── ConfirmModal.tsx
        └── README.md

### Відповідальність `Modal`

Універсальний компонент може відповідати за:

- відкриття та закриття;
- overlay;
- позиціювання;
- заголовок;
- кнопку закриття;
- доступність;
- розміщення вмісту;
- адаптивність.

### Відповідальність `ConfirmModal`

Компонент підтвердження може відповідати за:

- конкретне повідомлення;
- кнопки «Скасувати» та «Підтвердити»;
- виклик переданої функції;
- стан очікування підтвердження.

Один універсальний Modal можна використати для різних завдань:

    <Modal title="Налаштування">

    <Modal title="Інформація">

Це лише концептуальний приклад. Точний API компонента залежить від його реалізації.

## 18. Коли не варто використовувати модальне вікно

Модальні вікна можуть заважати користувачу, якщо їх використовують надмірно.

Не варто відкривати modal для кожного невеликого повідомлення або кожної зміни стану.

### Краще використати inline-повідомлення, якщо:

- помилка стосується конкретного поля;
- результат потрібно показати в контексті сторінки;
- інформація має залишатися видимою;
- користувач повинен порівнювати кілька блоків одночасно.

### Краще використати toast, якщо:

- дія завершилася успішно;
- повідомлення коротке;
- не потрібно блокувати роботу;
- користувачу не потрібно приймати рішення.

### Краще використати окрему сторінку, якщо:

- форма дуже велика;
- є багато кроків;
- користувач повинен бачити додаткові довідкові матеріали;
- важливі навігація, історія або спільне посилання;
- мобільне модальне вікно стає надто складним.

**Правило:** модальне вікно має допомагати виконати завдання, а не переривати користувача без необхідності.

## 19. Типові помилки

### Помилка 1. Модальне вікно лише візуальне

Є затемнений фон і панель, але кнопки не працюють.

**Рішення:** реалізувати повний життєвий цикл компонента.

### Помилка 2. Немає закриття з клавіатури

Користувач не може закрити вікно клавішею `Escape`, навіть коли це очікувана поведінка.

**Рішення:** реалізувати стандартну поведінку або використати `<dialog>`.

### Помилка 3. Фокус залишається на фоні

Після відкриття користувач продовжує переходити клавішею `Tab` по елементах основної сторінки.

**Рішення:** правильно реалізувати модальний фокус або використати нативний діалог.

### Помилка 4. Немає повернення фокусу

Після закриття фокус зникає або опиняється в несподіваному місці.

**Рішення:** повернути фокус до елемента, який відкрив діалог, якщо він усе ще доступний.

### Помилка 5. Вікно не поміщається на екрані

На мобільному пристрої нижні кнопки недоступні.

**Рішення:** обмежити висоту та передбачити прокручування.

### Помилка 6. Закриття втрачає введені дані

Користувач випадково закриває форму і втрачає весь текст.

**Рішення:** попереджати про незбережені зміни, коли це необхідно.

### Помилка 7. Кнопки мають нечіткі назви

Користувач бачить «Так» і «Ні», але не розуміє наслідків.

**Рішення:** використовувати конкретні дії: «Скасувати», «Видалити запис», «Зберегти зміни».

### Помилка 8. Занадто багато модальних вікон

Після кожної дії відкривається нове вікно.

**Рішення:** замінювати неважливі діалоги inline-повідомленнями або toast.

### Помилка 9. Немає стану завантаження

Користувач багаторазово натискає кнопку підтвердження.

**Рішення:** блокувати повторну дію під час запиту й показувати відповідний стан.

### Помилка 10. Надмірна анімація

Вікно довго відкривається або закривається.

**Рішення:** використовувати коротку анімацію та враховувати `prefers-reduced-motion`.

Мета — створити модальне вікно підтвердження видалення запису.

- модальне вікно;
- заголовок;
- опис наслідків;
- кнопку «Скасувати»;
- кнопку «Видалити».

- тінь;
- заокруглення;

- скасування дії;

- стан очікування під час запиту до API.

## 21. Практичне завдання для твого стеку

Створи невеликий компонент підтвердження видалення для навчального застосунку.

### Версія 1 — HTML, CSS, JavaScript

Реалізуй діалог через нативний `<dialog>`.

Критерії:

- кнопка відкриває діалог;
- «Скасувати» закриває його без видалення;
- «Видалити» запускає дію;
- після завершення користувач бачить результат;
- `Escape` працює відповідно до сценарію;
- форма не виходить за межі мобільного екрана.

### Версія 2 — React + TypeScript

Винеси компонент у `ConfirmModal.tsx`.

Використай типізовані props:

    type ConfirmModalProps = {
      title: string;
      description: string;
      confirmLabel?: string;
      cancelLabel?: string;
      onConfirm: () => void | Promise<void>;
      onCancel?: () => void;
    };

Цей тип показує можливий контракт компонента, але сам по собі не реалізує стан завантаження, обробку помилок або доступність.

Додаткові завдання:

- реалізуй стан `isPending`;
- не дозволяй повторне підтвердження під час запиту;
- оброби помилки;
- не закривай діалог, якщо операція завершилася помилкою;
- після успіху закривай діалог;
- забезпеч повну клавіатурну доступність.

### Версія 3 — Next.js

Використай компонент у сторінці керування записами.

Після підтвердження:

1. відправ запит до API;
2. оброби успіх або помилку;
3. онови список записів;
4. закрий діалог лише після успішного завершення;
5. покажи користувачу зрозумілий результат.

Не розміщуй секретні операції або захист даних лише на клієнті. Сервер повинен самостійно перевіряти права користувача та допустимість видалення.

## 23. Що потрібно запам'ятати

✔ **Modal** — компонент для важливої взаємодії поверх основної сторінки.

✔ **Overlay** затемнює фон і візуально відокремлює діалог.

✔ **Header, Body, Footer** — типова структура модального вікна.

✔ Модальне вікно повинно мати зрозумілий спосіб закриття.

✔ Для простих вебзастосунків розглянь нативний HTML-елемент `<dialog>`.

✔ `showModal()` відкриває нативний діалог у модальному режимі, а `show()` — у немодальному.

✔ `z-index` не замінює правильну реалізацію поведінки та доступності.

✔ Модальне вікно має працювати з клавіатурою, керувати фокусом і повертати його після закриття.

✔ `aria-modal="true"` саме по собі не реалізує модальну поведінку.

✔ Для довгих форм потрібні обмеження висоти та прокручування.

✔ Не кожне повідомлення потребує модального вікна. Для коротких результатів часто краще підійде toast або inline-повідомлення.

✔ У React стан відкриття можна контролювати через `useState`, але стан — лише частина повноцінного компонента.

✔ У Next.js інтерактивні модальні вікна зазвичай належать до Client Components.

✔ У TypeScript описуй props компонента явно та уникай `any`.

✔ На сервері завжди перевіряй права доступу для критичних операцій незалежно від клієнтського інтерфейсу.
