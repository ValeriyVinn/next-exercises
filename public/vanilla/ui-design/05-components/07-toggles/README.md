# Toggles — Перемикачі

> Toggle (Toggle Switch) — це компонент інтерфейсу, який дозволяє користувачу швидко ввімкнути або вимкнути певну функцію чи налаштування.
>
> Основна мета перемикача — показати поточний стан параметра та дати можливість змінити його одним простим дією.

---

## 1. Що таке Toggle

Toggle — це інтерактивний компонент, який має два основні стани:

- **On** — функція ввімкнена.
- **Off** — функція вимкнена.

Наприклад, користувач може ввімкнути темну тему інтерфейсу.

### Приклад

    Темна тема                    [ ●──── ]

Перемикач перебуває у стані `On`.

Після натискання стан змінюється:

    Темна тема                    [ ────● ]

Перемикач перебуває у стані `Off`.

> Візуальне положення повзунка залежить від дизайну. Не орієнтуйся лише на його розташування: важливо, щоб стан був зрозумілим користувачу.

### Основні властивості

✔ Має два основні стани: On і Off.

✔ Відображає поточний стан параметра.

✔ Дозволяє змінити стан без окремої кнопки підтвердження, якщо це відповідає поведінці продукту.

✔ Повинен мати зрозумілий підпис.

✔ Потребує помітних станів фокусу, наведення та недоступності.

✔ Може керувати налаштуваннями інтерфейсу, сповіщеннями, приватністю та іншими функціями.

---

## 2. Toggle, Checkbox і Radio Button

Ці компоненти можуть виглядати схоже за призначенням, але відрізняються поведінкою та контекстом.

| Компонент | Основне призначення | Приклад |
|---|---|---|
| Toggle | Увімкнути або вимкнути функцію | Темна тема |
| Checkbox | Позначити один або кілька незалежних пунктів | Обрати додаткові послуги |
| Radio Button | Вибрати один варіант із групи | Спосіб доставки |
| Button | Виконати дію | Зберегти налаштування |

### Toggle

    Автоматичне збереження        [ ON ]

Перемикач показує, що функція активна.

### Checkbox

    [x] Отримувати повідомлення про оновлення

Checkbox позначає вибір у формі або списку. Він може бути частиною налаштувань, але зазвичай має іншу візуальну семантику.

### Radio Button

    Формат документа

    (●) PDF
    ( ) HTML
    ( ) JSON

Radio Button дозволяє вибрати один варіант із кількох.

### Button

    [ Зберегти налаштування ]

Кнопка запускає дію, а не обов'язково відображає постійний стан.

### Що запам'ятати

- **Toggle** — функція ввімкнена або вимкнена.
- **Checkbox** — пункт позначений або не позначений.
- **Radio Button** — один вибраний варіант із групи.
- **Button** — виконання команди або дії.

Вибирай компонент відповідно до поведінки, а не лише за зовнішнім виглядом.

## 3. Коли використовувати Toggles

Перемикач доречний, коли користувач змінює стан налаштування, який може залишатися активним або неактивним.

### Типові сценарії

**1. Темна тема**

    Темна тема                     [ ON ]

**2. Сповіщення**

    Push-сповіщення                [ OFF ]

**3. Автоматичне збереження**

    Автоматично зберігати зміни    [ ON ]

**4. Приватність профілю**

    Показувати профіль у пошуку    [ OFF ]

**5. Додаткова функція**

    Увімкнути нагадування          [ ON ]

**6. Налаштування застосунку**

    Зменшена анімація              [ OFF ]

### Коли Toggle недоречний

| Ситуація | Кращий компонент |
|---|---|
| Потрібно виконати дію один раз | Button |
| Потрібно вибрати один варіант із кількох | Radio Buttons |
| Потрібно позначити кілька пунктів у формі | Checkboxes |
| Потрібно вибрати зі списку багатьох варіантів | Select |
| Потрібно задати числовий діапазон | Slider |
| Потрібно ввімкнути або вимкнути постійне налаштування | Toggle |

Наприклад, для дії «Надіслати лист» краще використовувати кнопку. Для налаштування «Автоматично надсилати сповіщення» — перемикач.

## 4. Анатомія Toggle

Типовий Toggle складається з кількох частин.

    Темна тема                  [ ─────● ]
    ↑                             ↑    ↑
    |                             |    |
    Label                         Track Thumb

### Основні частини

**1. Track — доріжка**

Фонова область, усередині якої рухається повзунок.

**2. Thumb — повзунок**

Круглий або інший рухомий елемент, що показує поточний стан.

**3. Label — підпис**

Назва налаштування, наприклад «Темна тема».

**4. Description — опис**

Додаткове пояснення функції.

**5. State Indicator — індикатор стану**

Візуальна ознака того, чи функція ввімкнена.

**6. Focus Indicator — індикатор фокусу**

Показує, що перемикач отримав фокус клавіатури.

**7. Status Text — текст стану**

За потреби можна додати текст `Увімкнено` або `Вимкнено`.

### Приклад структури

    Автоматичне збереження       [ ON ]
    Зміни зберігаються автоматично.

Підпис пояснює, що саме контролює перемикач, а опис розкриває наслідки його активації.

## 5. Стани Toggle

Перемикач повинен мати зрозумілий вигляд у різних станах.

### 5.1. Off — вимкнено

    Сповіщення                   [ OFF ]

Функція неактивна.

### 5.2. On — увімкнено

    Сповіщення                   [ ON ]

Функція активна.

### 5.3. Hover — наведення

Коли курсор перебуває над перемикачем, можна показати:

- легку зміну фону;
- зміну кольору доріжки;
- зміну межі;
- підсилення контрасту.

Hover є додатковим зворотним зв'язком. Він не повинен бути єдиним способом показати, що елемент інтерактивний.

### 5.4. Focus — фокус

Фокус показує, який елемент зараз активний для взаємодії з клавіатури.

Перемикач повинен мати чіткий видимий контур фокусу.

### 5.5. Disabled — недоступний

    Автоматичне оновлення        [ OFF ]
    Недоступно для цього плану

Перемикач недоступний для взаємодії.

Важливо не покладатися лише на зменшення прозорості. Якщо функція недоступна з певної причини, пояснення може бути корисним.

### 5.6. Loading — очікування

Наприклад, користувач увімкнув синхронізацію, а застосунок зберігає налаштування на сервері.

    Синхронізація                [ ... ]

Стан завантаження не є обов'язковим для кожного Toggle. Використовуй його, якщо зміна потребує помітного часу або підтвердження сервера.

### 5.7. Error — помилка

Наприклад, сервер не зміг зберегти нове налаштування.

    Синхронізація                [ OFF ]
    Не вдалося зберегти налаштування.

Помилка повинна пояснювати, що сталося, і за можливості давати користувачу шлях для повторної спроби.

### Підсумок станів

| Стан | Що показує |
|---|---|
| Off | Функція вимкнена |
| On | Функція ввімкнена |
| Hover | Курсор над компонентом |
| Focus | Компонент отримав фокус |
| Disabled | Змінити стан неможливо |
| Loading | Зміна ще обробляється |
| Error | Зміна не вдалася |

Не кожен перемикач потребує всіх станів. Проєктуй лише ті, які потрібні для реальної поведінки компонента.

---

## 6. Візуальна різниця між On і Off

Користувач повинен легко визначати поточний стан перемикача.

### Що можна змінювати

- колір доріжки;
- положення повзунка;
- колір повзунка;
- межу;
- додаткову іконку;
- текст стану, якщо це необхідно.

### Приклад

    Off: [ ●──── ]   On: [ ────● ]

У цьому прикладі положення повзунка показує стан.

### Правила

✔ Стан On має бути чітко відмінним від Off.

✔ Відмінність не повинна залежати лише від кольору.

✔ Повзунок повинен бути помітним на тлі доріжки.

✔ Текст і компоненти навколо перемикача повинні залишатися читабельними.

✔ Візуальна відмінність повинна зберігатися за різних умов освітлення та контрастності.

Якщо дизайн використовує колір для позначення стану, доповнюй його положенням повзунка та, за потреби, текстом.

## 7. Розмір і зона взаємодії

Сам перемикач може бути компактним, але натискати на нього має бути зручно.

### Рекомендації

✔ Зроби всю область перемикача клікабельною.

✔ Дозволь змінювати стан натисканням на підпис, якщо це відповідає дизайну.

✔ Залиш достатньо відстані між сусідніми налаштуваннями.

✔ Не зменшуй повзунок настільки, що ним важко користуватися.

✔ Перевір сенсорну взаємодію на мобільних пристроях.

Орієнтир близько 44 × 44 CSS px може бути корисним для зони взаємодії на сенсорних пристроях. Це не обов'язково має бути фізичний розмір самої доріжки: зону натискання можна збільшити за допомогою контейнера.

### Приклад CSS

    .toggle-option {
      display: flex;
      align-items: center;
      justify-content: space-between;
      gap: 16px;
      min-height: 44px;
      cursor: pointer;
    }

    .toggle-option__label {
      flex: 1;
    }

Не збільшуй зону взаємодії так, щоб вона перекривала сусідні інтерактивні елементи.

## 8. Розташування та композиція

Toggle зазвичай розташовують поруч із назвою налаштування.

### 8.1. Горизонтальний рядок

    Темна тема                    [ ON ]

Це найпоширеніший варіант для сторінки налаштувань.

### 8.2. Назва та опис

    Автоматичне збереження        [ ON ]
    Зберігати зміни після кожного редагування.

Такий формат підходить, коли функція потребує пояснення.

### 8.3. Картка налаштування

    ┌──────────────────────────────────┐
    │ Push-сповіщення           [ ON ] │
    │ Отримувати важливі повідомлення. │
    └──────────────────────────────────┘

Картки корисні для складних налаштувань або великих сторінок із багатьма параметрами.

### 8.4. Групування налаштувань

    Сповіщення

    Email-сповіщення            [ ON ]
    Push-сповіщення             [ OFF ]
    SMS-сповіщення              [ OFF ]

    Приватність

    Публічний профіль           [ ON ]
    Показувати email            [ OFF ]

Групування допомагає користувачу швидше знаходити потрібні налаштування.

### 8.5. Відступи

Потрібно визначити:

- відстань між назвою та перемикачем;
- відстань між назвою та описом;
- відстань між сусідніми рядками;
- відстань між групами налаштувань.

Приклад дизайн-токенів:

    :root {
      --toggle-width: 44px;
      --toggle-height: 24px;
      --toggle-thumb-size: 20px;
      --toggle-label-gap: 12px;
      --toggle-row-gap: 16px;
      --toggle-section-gap: 32px;
    }

Це стартові значення, а не універсальний стандарт.

## 9. Колір і візуальна ієрархія

Колір допомагає передати стан, але не повинен бути єдиною ознакою.

### Що потрібно визначити

- колір доріжки в стані Off;
- колір доріжки в стані On;
- колір повзунка;
- колір фокусу;
- кольори Disabled;
- оформлення Loading;
- оформлення Error.

### Приклад CSS-змінних

    :root {
      --toggle-track-off: #737373;
      --toggle-track-on: #2457c5;
      --toggle-thumb: #ffffff;
      --toggle-focus: #7c3aed;
      --toggle-disabled: #b8b8b8;
      --toggle-error: #b42318;
    }

### Контраст

Перевіряй контраст:

- тексту підпису щодо фону;
- повзунка щодо доріжки;
- доріжки щодо навколишнього фону;
- фокусу щодо сусідніх кольорів.

Для звичайного тексту WCAG 2.2 AA рекомендує контраст щонайменше 4.5:1, а для великого тексту — 3:1. Для візуальних ознак інтерактивних елементів також важливо забезпечувати достатній контраст щодо сусідніх кольорів.

Не вважай наведені вище кольори автоматично доступними в кожному контексті. Контраст потрібно перевіряти для фактичних кольорів і фону.

## 10. Текст і мікрокопірайтинг

Підпис повинен пояснювати, яку функцію контролює перемикач.

### Погано

    Активність                     [ ON ]

Незрозуміло, що саме буде активним.

### Краще

    Автоматичне збереження         [ ON ]

Назва чітко описує функцію.

### Ще краще, якщо потрібне пояснення

    Автоматичне збереження         [ ON ]
    Зміни зберігаються автоматично під час редагування.

### Правила

✔ Використовуй короткі та зрозумілі назви.

✔ Формулюй підписи так, щоб стан On мав очевидний зміст.

✔ Не використовуй неоднозначні назви на зразок «Режим» або «Опція».

✔ Додавай опис, якщо наслідки перемикання неочевидні.

✔ Не змушуй користувача вгадувати, що означає On або Off.

### Позитивні та негативні формулювання

Краще:

    Отримувати сповіщення         [ ON ]

Складніше для сприйняття:

    Вимкнути сповіщення           [ OFF ]

У другому випадку користувачу потрібно додатково інтерпретувати назву та стан. Вибирай формулювання, яке описує саму функцію, а не протилежну дію.

## 11. Поведінка після перемикання

Візуальна зміна повинна відповідати реальній поведінці застосунку.

### 11.1. Негайна зміна

Користувач перемикає темну тему, і тема інтерфейсу одразу змінюється.

    Темна тема                    [ ON ]

Це доречно, якщо зміна швидка, локальна та її можна легко скасувати.

### 11.2. Зміна з відправленням на сервер

Користувач вмикає сповіщення, а застосунок зберігає налаштування в базі даних.

Можлива послідовність:

1. Користувач вмикає Toggle.
2. Інтерфейс показує, що зміна обробляється.
3. Сервер зберігає налаштування.
4. Застосунок підтверджує зміну.

### 11.3. Оптимістичне оновлення

Інтерфейс одразу показує новий стан, а запит до сервера виконується паралельно.

Якщо запит не вдався, застосунок може:

- повернути попередній стан;
- показати повідомлення про помилку;
- дозволити повторити дію.

### 11.4. Очікування підтвердження

Для важливих або повільних операцій можна спочатку показати Loading, а потім підтвердити результат.

Не використовуй довгий стан завантаження для кожного перемикача без потреби.

### Основний принцип

**Стан інтерфейсу повинен відповідати фактичному стану функції або чесно показувати, що зміна ще обробляється.**

## 12. Доступність (Accessibility)

Toggle повинен бути доступним користувачам миші, клавіатури, сенсорних пристроїв і допоміжних технологій.

### Основні правила

✔ Використовуй нативний `<input type="checkbox">` для двостанового перемикача, якщо немає вагомої причини для іншої реалізації.

✔ Пов'язуй контрол із видимим підписом.

✔ Забезпечуй видимий фокус клавіатури.

✔ Не приховуй індикатор фокусу без доступної заміни.

✔ Не покладайся лише на колір.

✔ Забезпечуй зрозумілу назву та поточний стан для скринридера.

✔ Зроби зону взаємодії достатньо великою.

✔ Повідомляй про помилки збереження, якщо вони впливають на стан налаштування.

### Чому Toggle часто реалізують через Checkbox

Нативний HTML не має окремого типу `<input type="toggle">`.

Зазвичай використовують:

    <input type="checkbox" role="switch" />

Такий елемент зберігає стандартну двостанову поведінку checkbox, але роль `switch` передає допоміжним технологіям семантику перемикача.

### Клавіатурна взаємодія

Для нативного елемента зазвичай працюють такі клавіші:

- `Tab` — перейти до перемикача;
- `Space` — змінити стан сфокусованого перемикача.

Точна поведінка залежить від браузера, операційної системи та способу реалізації.

### Не використовуй `role="switch"` без потреби

Якщо компонент за змістом є звичайним пунктом форми, Checkbox може бути кращим семантичним вибором.

Якщо він керує постійним двостановим налаштуванням і візуально представлений як перемикач, роль `switch` може бути доречною.

## 13. HTML: базова реалізація Toggle

### 13.1. Мінімальний приклад

    <label>
      <input type="checkbox" role="switch" name="darkMode" />
      Темна тема
    </label>

Це вже працюючий двостановий елемент.

### 13.2. Toggle з описом

    <div class="setting">
      <div class="setting__text">
        <label for="notifications">
          Push-сповіщення
        </label>

        <p id="notifications-description">
          Отримувати важливі повідомлення.
        </p>
      </div>

      <input
        id="notifications"
        type="checkbox"
        role="switch"
        aria-describedby="notifications-description"
      />
    </div>

Тут:

- `type="checkbox"` створює нативний двостановий контрол;
- `role="switch"` повідомляє про семантику перемикача;
- `label` задає доступну назву;
- `aria-describedby` пов'язує елемент із додатковим описом.

### 13.3. Чи потрібен `aria-checked`

Для звичайного нативного checkbox не потрібно вручну задавати `aria-checked`. Браузер передає його стан.

Для нативного checkbox із `role="switch"` стан також передається через властивості самого елемента. Не встановлюй статичне `aria-checked`, яке не оновлюється разом зі станом.

### 13.4. Початковий стан

Вимкнений:

    <input type="checkbox" role="switch" />

Увімкнений:

    <input type="checkbox" role="switch" checked />

Не додавай `checked` лише заради гарного вигляду. Початковий стан повинен відповідати логіці застосунку.

## 14. CSS: оформлення Toggle

Можна почати з нативного checkbox, а потім стилізувати його.

### Як працює цей CSS

- `display: inline-flex` вирівнює підпис і перемикач;
- `border-radius: 999px` створює заокруглену доріжку;
- `.toggle__thumb` є повзунком;
- `:checked` змінює вигляд активного стану;
- `transform: translateX(20px)` пересуває повзунок;
- `:focus-visible` показує клавіатурний фокус;
- `:disabled` оформлює недоступний стан;
- `prefers-reduced-motion` зменшує анімацію для користувачів, які віддають перевагу зменшенню руху.

### Важливо

У цьому прикладі нативний checkbox візуально прихований, але залишається доступним для клавіатури та допоміжних технологій.

Не використовуй `display: none` або `visibility: hidden` для такого input, якщо він повинен залишатися доступним для взаємодії.

Після кастомізації обов'язково перевір роботу в цільових браузерах і з допоміжними технологіями.

## 16. Toggle у React і Next.js

У React перемикач зазвичай керується через стан компонента.

### 16.1. Простий приклад на TypeScript

    "use client";

    import { useState } from "react";

    export default function DarkModeToggle() {
      const [isDarkMode, setIsDarkMode] = useState(false);

      return (
        <label>
          <input
            type="checkbox"
            role="switch"
            checked={isDarkMode}
            onChange={(event) => {
              setIsDarkMode(event.target.checked);
            }}
          />

          Темна тема
        </label>
      );
    }

### Пояснення

**`useState(false)`**

Початковий стан — вимкнено.

**`checked={isDarkMode}`**

Визначає поточний стан checkbox.

**`onChange`**

Оновлює стан після взаємодії.

**`event.target.checked`**

Містить актуальне булеве значення: `true` або `false`.

### 16.2. Додатковий текст стану

    "use client";

    import { useState } from "react";

    export default function NotificationsToggle() {
      const [enabled, setEnabled] = useState(false);

      return (
        <div>
          <label>
            <input
              type="checkbox"
              role="switch"
              checked={enabled}
              onChange={(event) => {
                setEnabled(event.target.checked);
              }}
            />

            Push-сповіщення
          </label>

          <p>
            Стан: {enabled ? "Увімкнено" : "Вимкнено"}
          </p>
        </div>
      );
    }

Цей приклад демонструє, як стан компонента може керувати додатковим текстом інтерфейсу.

### 16.3. Оновлення теми інтерфейсу

Самого перемикача недостатньо, щоб змінити всю тему застосунку.

Потрібно пов'язати його стан із системою темізації, наприклад:

- контекстом React;
- класом на кореневому елементі;
- CSS-змінними;
- механізмом тем Next.js;
- збереженим налаштуванням користувача.

Не плутай зміну локального стану Toggle зі зміною теми всього застосунку.

## 17. Toggle та збереження налаштувань

У реальному застосунку перемикач часто змінює налаштування, яке потрібно зберігати.

Наприклад:

    user_settings
    ├── user_id
    ├── dark_mode
    ├── notifications_enabled
    └── auto_save_enabled

У базі даних такі значення зазвичай зберігаються як булеві поля.

### Типова послідовність

1. Користувач змінює Toggle.
2. Frontend оновлює стан інтерфейсу.
3. Backend отримує нове значення.
4. Backend перевіряє запит і права користувача.
5. Backend зберігає налаштування.
6. Frontend підтверджує результат або показує помилку.

### Що потрібно врахувати

- чи має користувач право змінювати налаштування;
- чи зберігається значення між сеансами;
- чи потрібен Loading;
- що відбувається при помилці мережі;
- як синхронізуються кілька відкритих вкладок;
- чи можна повернути попередній стан.

### Важливо

Не довіряй значенню, яке надходить від клієнта. Сервер повинен перевіряти права доступу та допустимість операції.

## 22. Поширені помилки

### Помилка 1. Toggle використовується для одноразової дії

Наприклад, перемикач «Надіслати лист».

**Проблема:** Toggle зазвичай показує постійний стан налаштування.

**Правильно:** для одноразової команди використовуй Button.

### Помилка 2. Незрозумілий підпис

Наприклад, «Режим».

**Проблема:** користувач не розуміє, що зміниться.

**Правильно:** використовуй конкретну назву, наприклад «Автоматичне збереження».

### Помилка 3. Стан показаний лише кольором

**Проблема:** деякі користувачі не зможуть відрізнити On від Off.

**Правильно:** поєднуй колір із положенням повзунка та чіткою формою.

### Помилка 4. Немає видимого фокусу

**Проблема:** користувач клавіатури не бачить активний елемент.

**Правильно:** забезпечуй помітний `:focus-visible`.

### Помилка 5. Прихований input не працює з клавіатури

**Проблема:** повністю кастомний компонент може втратити доступність.

**Правильно:** залишай нативний елемент доступним і перевіряй його поведінку.

### Помилка 6. Немає повідомлення про помилку

**Проблема:** користувач не розуміє, чому налаштування не змінилося.

**Правильно:** повідомляй про невдале збереження та пропонуй повторити дію.

### Помилка 7. Інтерфейс показує неправильний стан

**Проблема:** перемикач показує On, хоча сервер відхилив зміну.

**Правильно:** узгоджуй стан із результатом операції або показуй, що запит ще обробляється.

### Помилка 8. Відсутнє збереження налаштування

**Проблема:** після перезавантаження сторінки користувач втрачає свій вибір, хоча очікував постійного збереження.

**Правильно:** визначай, чи налаштування локальне, тимчасове або зберігається на сервері.

### Помилка 9. Надто маленька область натискання

**Проблема:** перемикач незручно використовувати на мобільному пристрої.

**Правильно:** збільшуй область взаємодії через контейнер.

### Помилка 10. Надмірна анімація

**Проблема:** анімація може відволікати або заважати людям, які чутливі до руху.

**Правильно:** використовуй коротку анімацію та враховуй `prefers-reduced-motion`.

### Помилка 11. Немає пояснення недоступності

**Проблема:** користувач бачить вимкнений контрол, але не розуміє причини.

**Правильно:** додай пояснення, якщо воно допомагає зрозуміти обмеження.

### Помилка 12. Власний компонент не має правильної семантики

**Проблема:** візуальний перемикач може не передавати стан допоміжним технологіям.

**Правильно:** починай із нативного checkbox і додавай роль `switch`, коли вона відповідає призначенню.

### Що потренувати

1. Додай власний вигляд доріжки та повзунка.
2. Зроби стан On помітним без використання лише кольору.
3. Додай стан Disabled.
4. Додай короткий текстовий статус.
5. Реалізуй панель у React.
6. Збережи налаштування в `localStorage` для навчальної вправи.
7. Додай завантаження налаштувань із backend.
8. Реалізуй обробку помилки збереження.

> Не зберігай у `localStorage` секрети, паролі або чутливі дані. Для реальних налаштувань приватності та облікового запису визначай надійне джерело стану й перевіряй права на сервері.

## 25. Як тестувати Toggles

Перед завершенням перевір компонент у різних сценаріях.

### Функціональні тести

- [ ] Перемикач змінює стан.
- [ ] Стан On відповідає ввімкненій функції.
- [ ] Стан Off відповідає вимкненій функції.
- [ ] Незалежні перемикачі працюють незалежно.
- [ ] Після перезавантаження зберігаються налаштування, які повинні зберігатися.
- [ ] Недоступний перемикач не змінюється.
- [ ] Помилка сервера обробляється правильно.
- [ ] Повторна спроба працює, якщо вона передбачена.

### Тести доступності

- [ ] Є зрозумілий підпис.
- [ ] Стан передається допоміжним технологіям.
- [ ] Працює клавіатурна взаємодія.
- [ ] Фокус помітний.
- [ ] Контраст достатній.
- [ ] Стан не передається лише кольором.
- [ ] Зона натискання достатньо велика.
- [ ] Опис пов'язаний із контролом, якщо це необхідно.

### Візуальні тести

- [ ] Повзунок добре видно.
- [ ] On і Off чітко відрізняються.
- [ ] Відступи послідовні.
- [ ] Підписи не обрізаються.
- [ ] Мобільний вигляд зручний.
- [ ] Анімація не заважає взаємодії.
- [ ] Недоступний стан не плутається зі звичайним.

## 26. Що потрібно запам'ятати

✔ Toggle — компонент для ввімкнення або вимкнення функції.

✔ Основні стани — On і Off.

✔ Для нативної реалізації зазвичай використовують `<input type="checkbox">`.

✔ Роль `switch` можна додати, якщо вона відповідає семантиці компонента.

✔ Підпис повинен однозначно пояснювати функцію.

✔ Не покладайся лише на колір для позначення стану.

✔ Фокус клавіатури повинен бути видимим.

✔ Для кастомного компонента потрібно зберегти доступність нативного елемента.

✔ Toggle не завжди потребує кнопки підтвердження.

✔ Якщо зміна зберігається на сервері, продумай Loading і Error.

✔ Стан інтерфейсу повинен відповідати фактичному стану функції.

✔ Для важливих налаштувань сервер повинен перевіряти права користувача.

✔ У React контрольований Toggle зазвичай використовує `checked` та `onChange`.

✔ Для користувачів, які віддають перевагу зменшенню руху, враховуй `prefers-reduced-motion`.

## 28. Рівні володіння

### Level 1 — Basic

- Розумієш призначення Toggle.
- Відрізняєш його від Checkbox, Radio Button і Button.
- Створюєш базовий двостановий контрол.
- Використовуєш зрозумілий підпис.

### Level 2 — Styling

- Оформлюєш доріжку та повзунок.
- Створюєш стани On, Off, Hover і Focus.
- Налаштовуєш розміри та відступи.
- Враховуєш мобільний вигляд.

### Level 3 — Accessibility

- Використовуєш правильну семантику.
- Забезпечуєш клавіатурну взаємодію.
- Перевіряєш фокус і контраст.
- Враховуєш зменшення анімації.

### Level 4 — React / Next.js

- Керуєш станом через `useState`.
- Використовуєш контрольований `checked`.
- Реалізуєш кілька незалежних налаштувань.
- Додаєш завантаження та обробку помилок.

### Level 5 — Backend Integration

- Зберігаєш налаштування через API.
- Перевіряєш права користувача на сервері.
- Обробляєш невдалі запити.
- Синхронізуєш стан інтерфейсу з сервером.

### Level 6 — Design System

- Визначаєш токени компонента.
- Документуєш стани та правила використання.
- Забезпечуєш послідовну поведінку в різних застосунках.
- Перевіряєш доступність, браузерну сумісність і мобільну взаємодію.
