# 05. Checkboxes — Прапорці та вибір незалежних опцій

> **Checkboxes** — це UI-компоненти, які дозволяють користувачеві вибрати або скасувати вибір одного чи кількох незалежних параметрів.
>
> Checkbox зазвичай відображає стан «вибрано / не вибрано» та використовується у формах, налаштуваннях, фільтрах, списках завдань і панелях керування.
>
> Основне завдання дизайну Checkbox — зробити вибір зрозумілим, помітним, доступним і передбачуваним.

---

## 1. Що потрібно знати про Checkboxes

Checkboxes використовуються в багатьох типах інтерфейсів:

- реєстрація та налаштування профілю;
- прийняття умов використання;
- вибір категорій;
- фільтрація списків;
- налаштування повідомлень;
- списки завдань;
- вибір навчальних предметів;
- таблиці з можливістю масових дій;
- адміністративні панелі;
- керування дозволами;
- вибір кількох незалежних параметрів.

### Основні поняття

- ✔ **Checkbox** — елемент керування для вибору або скасування вибору параметра.
- ✔ **Checkbox group** — група прапорців, пов'язаних однією темою.
- ✔ **Checked state** — стан, коли прапорець вибраний.
- ✔ **Unchecked state** — стан, коли прапорець не вибраний.
- ✔ **Indeterminate state** — проміжний стан, коли вибрано лише частину дочірніх елементів.
- ✔ **Label** — текстова назва прапорця.
- ✔ **Helper text** — додаткове пояснення.
- ✔ **Disabled state** — стан, у якому взаємодія недоступна.
- ✔ **Error state** — стан помилки валідації.
- ✔ **Focus state** — стан, коли елемент отримав клавіатурний фокус.
- ✔ **Hit area** — область, на яку можна натиснути для взаємодії.
- ✔ **Selection** — вибір одного або кількох значень.
- ✔ **Select all** — дія вибору всіх елементів групи.
- ✔ **Clear all** — дія скасування всіх вибраних елементів.
- ✔ **Tri-state checkbox** — прапорець із трьома станами: вибраний, не вибраний і проміжний.
- ✔ **Accessibility** — доступність компонента для різних користувачів і допоміжних технологій.
- ✔ **Design system** — система узгоджених компонентів, стилів і правил.

## 2. Що таке Checkbox

Checkbox — це елемент інтерфейсу, який зазвичай має квадратну область із позначкою всередині, якщо параметр вибраний.

Приклад невибраного прапорця:

    ☐ Отримувати новини

Приклад вибраного прапорця:

    ☑ Отримувати новини

Користувач може перемикати його стан незалежно від інших прапорців.

Наприклад:

    Які теми вас цікавлять?

    ☑ JavaScript
    ☐ TypeScript
    ☑ React
    ☐ Node.js

Тут можна вибрати JavaScript і React одночасно, не вибираючи TypeScript або Node.js.

### Основні властивості Checkbox

- має два основні стани: checked і unchecked;
- зазвичай допускає незалежний вибір;
- може бути об'єднаний із пов'язаними прапорцями;
- повинен мати зрозумілу текстову назву;
- має бути доступним для миші, клавіатури та допоміжних технологій;
- повинен чітко показувати свій стан.

**Важливо:** Checkbox не просто декорує текст. Це інтерактивний елемент, який змінює значення або налаштування.

## 3. Checkbox, Radio Button, Switch і Toggle

Ці компоненти можуть виглядати схоже за призначенням, але їхня поведінка відрізняється.

### 3.1. Checkbox

Дозволяє вибрати кілька незалежних параметрів.

    Які технології ти використовуєш?

    ☑ HTML
    ☑ CSS
    ☐ JavaScript
    ☐ TypeScript

Checkbox підходить, коли користувач може вибрати будь-яку комбінацію варіантів.

### 3.2. Radio Button

Дозволяє вибрати лише один варіант із групи.

    Рівень складності

    ◉ Початковий
    ○ Середній
    ○ Просунутий

Якщо вибрано «Початковий», інші варіанти цієї групи не можуть залишатися вибраними.

### 3.3. Switch

Зазвичай використовується для ввімкнення або вимкнення функції.

    Темна тема              [●────]

Switch часто доречний у налаштуваннях, де користувач очікує, що зміна стану набуде чинності одразу.

### 3.4. Toggle

Toggle — загальна назва механізму перемикання між станами. У дизайні цим словом часто називають візуальний перемикач, схожий на Switch.

Залежно від дизайн-системи терміни Toggle і Switch можуть використовуватися по-різному.

### Порівняння

| Компонент | Основна функція | Типовий сценарій |
|---|---|---|
| Checkbox | Незалежний вибір | Вибір кількох предметів |
| Radio Button | Вибір одного варіанта | Вибір одного рівня |
| Switch | Увімкнення або вимкнення функції | Увімкнення сповіщень |
| Toggle | Перемикання стану | Залежить від дизайн-системи |

### Як вибрати правильний компонент

Використовуй Checkbox, якщо:

- можна вибрати кілька варіантів;
- кожен параметр має незалежне значення;
- користувач може змінювати вибір окремих пунктів.

Використовуй Radio Button, якщо:

- дозволений лише один варіант;
- користувач має вибрати один пункт із кількох альтернатив.

Використовуй Switch, якщо:

- йдеться про ввімкнення або вимкнення функції;
- зміна стану зазвичай застосовується відразу;
- така взаємодія відповідає очікуванням користувача.

**Правило:** вибирай компонент за логікою взаємодії, а не за зовнішнім виглядом.

## 4. Структура Checkbox-компонента

Типовий Checkbox складається з кількох частин.

    ☑ Отримувати сповіщення
      Отримуйте повідомлення про важливі оновлення.

Основні частини:

1. **Checkbox control** — квадратний інтерактивний елемент.
2. **Checkmark** — позначка вибраного стану.
3. **Label** — текст, що пояснює призначення параметра.
4. **Helper text** — додаткове пояснення, якщо воно потрібне.
5. **Focus indicator** — видимий індикатор фокусу.
6. **Error message** — повідомлення про помилку, якщо вибір не відповідає вимогам.
7. **Group label** — заголовок групи прапорців.

Не кожен Checkbox потребує всіх частин.

### Принципи побудови

- Checkbox повинен мати зрозуміле призначення.
- Label має однозначно пояснювати, що саме вибирає користувач.
- Область натискання повинна бути достатньою.
- Checked і unchecked мають чітко відрізнятися.
- Focus має бути помітним.
- Helper text не повинен перевантажувати інтерфейс.
- Пов'язані прапорці потрібно групувати логічно.

---

## 5. Label — текстова назва Checkbox

Label пояснює, що означає вибір прапорця.

Приклад:

    ☑ Зберегти мої налаштування

Користувач повинен розуміти, який наслідок має встановлення або зняття позначки.

### 5.1. Хороший Label

Хороший Label:

- короткий;
- конкретний;
- зрозумілий без додаткових пояснень;
- описує результат або параметр;
- не містить зайвих слів.

Приклади:

    ☐ Отримувати новини
    ☐ Зберегти пароль на цьому пристрої
    ☐ Показувати завершені завдання
    ☐ Дозволити електронні сповіщення

### 5.2. Неоднозначний Label

Погано:

    ☐ Увімкнути

Не зрозуміло, що саме буде ввімкнено.

Краще:

    ☐ Увімкнути електронні сповіщення

Погано:

    ☐ Інше

Якщо це не очевидний пункт у групі категорій, користувач може не зрозуміти значення вибору.

Краще:

    ☐ Інша категорія

### 5.3. Клікабельний Label

Бажано, щоб натискання на текст також змінювало стан Checkbox.

    ☑ Отримувати сповіщення

Користувачеві не потрібно цілитися точно в маленький квадрат.

Це покращує зручність, особливо на мобільних пристроях.

### 5.4. Довгий Label

Якщо текст довгий, він може переноситися на кілька рядків.

    ☐ Я погоджуюся з правилами використання
      навчальної платформи та політикою
      обробки персональних даних.

Перевір, щоб:

- текст не перекривав Checkbox;
- відступи залишалися узгодженими;
- рядки читалися природно;
- область натискання залишалася зручною.

---

## 6. Checkbox Group — група прапорців

Checkbox Group об'єднує пов'язані параметри.

Приклад:

    Які технології ти хочеш вивчати?

    ☑ HTML
    ☑ CSS
    ☐ JavaScript
    ☐ TypeScript
    ☐ React

Усі пункти стосуються однієї теми, тому їх зручно показувати разом.

### 6.1. Коли потрібна група

- вибір категорій;
- вибір інтересів;
- налаштування сповіщень;
- фільтрація списків;
- вибір навчальних предметів;
- вибір функцій профілю;
- вибір кількох дозволів.

### 6.2. Заголовок групи

Заголовок повинен пояснювати, що об'єднує варіанти.

    Які способи сповіщень використовувати?

    ☐ Електронна пошта
    ☐ Push-сповіщення
    ☐ SMS

Не використовуй заголовок, який дублює всі Label без додаткового змісту.

### 6.3. Helper text для групи

Якщо вибір має обмеження, поясни його заздалегідь.

    Виберіть не більше трьох предметів.

    ☐ Математика
    ☐ Інформатика
    ☐ Фізика
    ☐ Історія

Це краще, ніж дозволити вибрати десять пунктів і лише після цього повідомити про помилку.

### 6.4. Розташування

Зазвичай Checkbox Group розміщують вертикально.

    ☐ HTML
    ☐ CSS
    ☐ JavaScript

Горизонтальне розташування може бути доречним для коротких пунктів, якщо зберігається читабельність.

    ☐ День    ☐ Тиждень    ☐ Місяць

Для довгих Label вертикальний список зазвичай зручніший.

## 7. Візуальні стани Checkbox

Checkbox повинен мати продумані стани.

### 7.1. Unchecked

Прапорець не вибраний.

    ☐ Отримувати новини

Візуальні характеристики:

- видима межа;
- зрозумілий фон;
- достатній контраст;
- чітка форма.

### 7.2. Checked

Прапорець вибраний.

    ☑ Отримувати новини

Стан можна показувати за допомогою:

- галочки;
- зміни фону;
- зміни кольору межі;
- узгодженої комбінації цих ознак.

Галочка повинна залишатися помітною на фоні.

### 7.3. Hover

Вказівник миші наведений на компонент.

Можливі зміни:

- трохи темніша межа;
- легка зміна фону;
- незначне посилення акценту.

Hover не повинен бути єдиним способом показати інтерактивність, адже на сенсорних пристроях звичайного наведення немає.

### 7.4. Focus

Checkbox отримав фокус клавіатури.

    ┏━━━┓
    ┃ ☑ ┃ Отримувати новини
    ┗━━━┛

Focus indicator повинен бути чітким і видимим.

Не прибирай стандартний індикатор фокусу, якщо не замінюєш його доступним і помітним рішенням.

### 7.5. Disabled

Компонент недоступний для взаємодії.

    ▫ Отримувати новини

Disabled може означати, що параметр:

- тимчасово недоступний;
- залежить від іншого налаштування;
- недоступний у поточному режимі;
- не може бути змінений користувачем.

Якщо причина неочевидна, додай пояснення.

### 7.6. Error

Вибір не відповідає правилам форми.

    ☐ Я погоджуюся з умовами використання

    Щоб продовжити, потрібно погодитися з умовами.

Помилка повинна мати зрозумілий текст. Не покладайся лише на червону межу.

### 7.7. Indeterminate

Проміжний стан, який часто використовується для групи дочірніх прапорців.

Наприклад:

    ▣ Усі предмети

    ☑ Математика
    ☐ Фізика
    ☑ Інформатика

Батьківський Checkbox має проміжний стан, оскільки вибрано лише частину дочірніх пунктів.

### Таблиця станів

| Стан | Значення | Що важливо |
|---|---|---|
| Unchecked | Не вибраний | Видима межа |
| Checked | Вибраний | Чітка позначка |
| Hover | Наведення | Помірна візуальна реакція |
| Focus | Клавіатурний фокус | Помітний індикатор |
| Disabled | Недоступний | Зрозуміле обмеження |
| Error | Помилка | Пояснення проблеми |
| Indeterminate | Частковий вибір | Відмінність від двох основних станів |

---

## 8. Indeterminate State — проміжний стан

Indeterminate — це стан, у якому батьківський Checkbox показує, що вибрано лише частину дочірніх пунктів.

Приклад:

    Навчальні предмети

    ▣ Усі предмети
      ☑ Математика
      ☐ Фізика
      ☑ Інформатика
      ☐ Історія

Батьківський Checkbox не повністю вибраний і не повністю порожній.

### Типова логіка

- жодного дочірнього пункту не вибрано — unchecked;
- вибрано всі дочірні пункти — checked;
- вибрано частину дочірніх пунктів — indeterminate.

### Коли використовувати

- таблиці з масовим вибором;
- списки категорій;
- дерево дозволів;
- ієрархічні списки;
- панелі адміністрування.

### Важливе правило

Indeterminate — це не третій незалежний вибір у звичайній Checkbox Group. Зазвичай він відображає стан дочірніх елементів.

Поведінку натискання на батьківський Checkbox потрібно визначити окремо. Часто натискання вибирає всі дочірні елементи або знімає всі позначки.

## 9. Розміри Checkbox

Checkbox має бути достатньо великим, щоб його можна було легко побачити й активувати.

Приклад умовної системи:

    Small:   16 × 16 px
    Medium:  20 × 20 px
    Large:   24 × 24 px

Це приклад дизайн-шкали, а не універсальний стандарт.

### 9.1. Розмір самого квадрата

Розмір залежить від:

- типографіки;
- висоти рядка;
- загального стилю інтерфейсу;
- розташування компонента;
- платформи;
- вимог доступності.

### 9.2. Область натискання

Візуальний квадрат може бути невеликим, але область натискання навколо нього повинна бути зручною.

Особливо це важливо для мобільних пристроїв.

Не змушуй користувача натискати точно в маленьку галочку.

### 9.3. Вирівнювання

Checkbox потрібно вирівнювати відносно тексту.

Для короткого однорядкового Label часто підходить вертикальне центрування.

Для багаторядкового тексту потрібно перевірити, чи природно виглядає розташування квадрата відносно першого рядка.

    ☐ Я погоджуюся з умовами
      використання платформи та
      політикою конфіденційності.

Checkbox не повинен випадково вирівнюватися по центру всього високого текстового блока, якщо це ускладнює читання.

---

## 10. Відступи та компонування

У Checkbox Group важливі не лише розміри квадратів, а й відстані між елементами.

### 10.1. Відстань між Checkbox і Label

    ☑ Отримувати сповіщення

Текст не повинен торкатися квадрата, але й не повинен бути надто далеко.

### 10.2. Відстань між рядками

    ☐ HTML

    ☐ CSS

    ☐ JavaScript

Відстань повинна допомагати розрізняти варіанти та зручно натискати на них.

### 10.3. Відстань між групами

    Сповіщення

    ☑ Електронна пошта
    ☐ SMS

    Відображення

    ☑ Темна тема
    ☐ Компактний режим

Заголовки та вертикальні відступи допомагають зрозуміти, що це дві різні групи налаштувань.

### 10.4. Використання дизайн-шкали

Приклад:

    Checkbox-to-label gap:  8 px
    Option spacing:         12 px
    Group spacing:          24 px

Це умовні значення для прикладу. Важливо, щоб інтервали були послідовними в межах дизайн-системи.

---

## 11. Checkbox у формах

Checkbox часто використовується для налаштувань і згоди з умовами.

### 11.1. Необов'язковий параметр

    Налаштування повідомлень

    ☑ Отримувати новини
    ☐ Отримувати рекламні пропозиції

Користувач може змінити ці параметри незалежно один від одного.

### 11.2. Обов'язкова згода

    ☐ Я погоджуюся з умовами використання.

Якщо згода обов'язкова, форма повинна перевіряти її перед надсиланням.

Пояснення має бути зрозумілим. Не встановлюй прапорець автоматично, якщо користувач повинен самостійно надати згоду.

### 11.3. Повідомлення про помилку

    ☐ Я погоджуюся з умовами використання.

    Потрібно підтвердити згоду, щоб продовжити.

Помилка повинна бути пов'язана з конкретним полем і бути доступною для користувачів допоміжних технологій.

### 11.4. Checkbox як частина валідації

Під час перевірки форми потрібно враховувати:

- чи вибрано обов'язковий Checkbox;
- чи дозволено залишити групу без вибору;
- чи є обмеження кількості вибраних пунктів;
- чи залежить доступність параметрів від інших полів;
- чи показується повідомлення про помилку.

## 12. Checkbox у фільтрах

Checkbox зручний для фільтрації, коли користувач може вибирати кілька значень.

Приклад каталогу курсів:

    Категорії

    ☑ Програмування
    ☐ Дизайн
    ☑ Математика
    ☐ Іноземні мови

    Рівень

    ☑ Початковий
    ☐ Середній
    ☐ Просунутий

### 12.1. Чому Checkbox підходить для фільтрів

- можна вибрати кілька категорій;
- вибір кожного пункту незалежний;
- усі основні варіанти видно одночасно;
- легко зрозуміти, які фільтри активні.

### 12.2. Застосування вибору

Фільтри можуть працювати по-різному:

- результати оновлюються відразу;
- користувач спочатку вибирає параметри, а потім натискає «Застосувати»;
- вибрані значення зберігаються до підтвердження всіх налаштувань.

Вибір залежить від складності фільтрації та вартості оновлення результатів.

### 12.3. Скидання

Для довгих списків корисними можуть бути:

    [Скинути фільтри]

або:

    ☐ Усі категорії

Проте пункт «Усі категорії» не повинен створювати плутанину з окремим значенням у списку.

Якщо потрібен батьківський Checkbox для вибору всіх дочірніх категорій, його поведінку потрібно пояснити й реалізувати послідовно.

## 13. Select All — вибрати всі

Select All дозволяє вибрати всі елементи групи однією дією.

Приклад:

    ☑ Вибрати всі

    ☑ Математика
    ☑ Фізика
    ☑ Інформатика

Цей механізм корисний для довгих списків і масових операцій.

### 13.1. Поведінка

Зазвичай логіка така:

- натискання на «Вибрати всі» вибирає всі доступні пункти;
- повторне натискання скасовує всі позначки;
- якщо вибрано лише частину пунктів, батьківський Checkbox показує indeterminate.

### 13.2. Недоступні елементи

Якщо частина пунктів Disabled, потрібно визначити, чи дія Select All охоплює лише доступні елементи.

Не створюй ситуацію, у якій користувач натискає «Вибрати всі», але не розуміє, чому деякі пункти залишилися невибраними.

### 13.3. Коли Select All недоречний

Не додавай його до кожної Checkbox Group.

Для трьох коротких пунктів така дія може бути зайвою.

Використовуй її, коли вона справді економить час або допомагає працювати з великою кількістю даних.

## 14. Доступність Checkbox (Accessibility)

Checkbox повинен бути зручним для різних користувачів, зокрема тих, хто користується клавіатурою або допоміжними технологіями.

### 14.1. Доступна назва

Кожен Checkbox повинен мати зрозумілу назву.

Погано:

    ☐

Користувач не розуміє, що означає цей прапорець.

Краще:

    ☐ Показувати завершені завдання

Назва повинна бути доступною не лише візуально, а й для допоміжних технологій.

### 14.2. Клавіатурна взаємодія

Для стандартного HTML Checkbox зазвичай працюють:

- Tab — перейти до Checkbox;
- Shift + Tab — перейти до попереднього елемента;
- Space — змінити стан Checkbox.

Enter не є універсальною заміною Space для перемикання стандартного Checkbox.

### 14.3. Focus indicator

Коли Checkbox отримує клавіатурний фокус, це повинно бути помітно.

Не прибирай обведення без доступної альтернативи.

### 14.4. Контрастність

Перевіряй контраст:

- межі Checkbox;
- галочки;
- фону вибраного стану;
- тексту Label;
- Focus indicator;
- повідомлень про помилки.

### 14.5. Не покладайся лише на колір

Якщо вибраний стан відрізняється лише зміною кольору, його може бути важко розпізнати.

Використовуй виразну галочку або іншу форму позначення.

### 14.6. Групування для допоміжних технологій

Пов'язані прапорці потрібно логічно групувати.

У HTML для цього можна використовувати `fieldset` і `legend`.

    <fieldset>
      <legend>Які технології тебе цікавлять?</legend>

      <label>
        <input type="checkbox" name="technology" value="html">
        HTML
      </label>

      <label>
        <input type="checkbox" name="technology" value="css">
        CSS
      </label>

      <label>
        <input type="checkbox" name="technology" value="javascript">
        JavaScript
      </label>
    </fieldset>

`fieldset` групує пов'язані поля, а `legend` задає назву групи.

### 14.7. Розмір області натискання

Не змушуй користувача натискати лише на квадрат.

Пов'язаний Label може також активувати Checkbox, що покращує зручність взаємодії.

## 15. Нативний Checkbox чи кастомний Checkbox

### 15.1. Нативний Checkbox

Стандартний HTML-елемент:

    <input type="checkbox">

Переваги:

- вбудована клавіатурна взаємодія;
- підтримка допоміжних технологій;
- простіша реалізація;
- інтеграція з HTML-формами;
- менше ризиків помилок у поведінці.

Обмеження:

- зовнішній вигляд може відрізнятися між браузерами й операційними системами;
- контроль над оформленням обмежений без додаткового CSS.

### 15.2. Кастомний Checkbox

Кастомний Checkbox використовує власне оформлення, щоб відповідати дизайн-системі.

Переваги:

- контроль над кольорами;
- контроль над розмірами;
- власні стани;
- узгоджений вигляд із дизайном продукту.

Недоліки:

- більше CSS;
- необхідність перевіряти контраст;
- ризик приховати або втратити доступний стан;
- додаткові вимоги до клавіатурної взаємодії;
- більше тестування.

### 15.3. Практична рекомендація

Починай із нативного Checkbox.

Якщо потрібен кастомний вигляд, краще стилізувати справжній `<input type="checkbox">`, а не замінювати його звичайним декоративним `div`.

Так простіше зберегти стандартну поведінку та доступність.

## 16. Checkbox у мобільному дизайні

На мобільних пристроях Checkbox потрібно проєктувати з урахуванням сенсорного керування.

### Основні правила

- збільшуй область натискання навколо компонента;
- залишай достатню відстань між сусідніми пунктами;
- не роби Label надто дрібним;
- перевіряй довгі тексти;
- не розміщуй Checkbox занадто близько до інших дій;
- зберігай видимість checked і unchecked;
- враховуй вертикальне прокручування довгих списків.

### Приклад

    ☐ Отримувати повідомлення електронною поштою

    ☐ Отримувати push-сповіщення

    ☐ Отримувати SMS

Кожен рядок має бути достатньо зручним для натискання.

Не потрібно збільшувати лише квадрат, якщо можна зробити інтерактивною всю область рядка.

## 17. Checkbox у таблицях і списках

Checkbox часто використовується для вибору рядків у таблицях.

Приклад:

    ☐ Назва курсу          Статус
    ☑ JavaScript           Активний
    ☐ React                Чернетка
    ☑ TypeScript           Активний

Користувач може вибрати кілька рядків і виконати спільну дію.

### Типові сценарії

- видалення кількох записів;
- зміна статусу;
- архівування;
- експорт;
- масове призначення категорій;
- вибір користувачів.

### Основні правила

- Checkbox у заголовку може керувати вибором рядків;
- стан заголовка повинен відповідати вибору дочірніх рядків;
- вибрані рядки мають бути візуально помітними;
- масові дії повинні бути зрозумілими;
- Disabled-рядки потрібно враховувати в логіці вибору;
- користувач повинен розуміти, скільки записів вибрано.

Приклад:

    Вибрано 2 записи

    [Архівувати] [Видалити]

Не показуй небезпечні масові дії без зрозумілого контексту.

## 18. Візуальна стилізація Checkbox

### 18.1. Межа

Межа допомагає побачити Checkbox у невибраному стані.

Вона повинна бути достатньо помітною на фоні інтерфейсу.

### 18.2. Фон

У checked-стані фон часто набуває акцентного кольору.

Галочка повинна контрастувати з ним.

### 18.3. Галочка

Галочка повинна бути:

- чіткою;
- пропорційною квадрату;
- добре видимою;
- однаковою в усіх компонентах дизайн-системи.

Не використовуй занадто тонкий або дрібний символ, який губиться в маленькому квадраті.

### 18.4. Радіус кутів

Checkbox може мати:

- гострі кути;
- невеликий радіус;
- округлену форму.

Вибір залежить від стилю дизайн-системи.

Не варто робити Checkbox круглим, якщо це створює плутанину з Radio Button.

### 18.5. Анімація

Можна додати коротку анімацію появи галочки або зміни фону.

Проте анімація:

- не повинна затримувати взаємодію;
- не повинна приховувати поточний стан;
- має бути ненав'язливою;
- повинна враховувати налаштування зменшення руху.

## 20. Реалізація Checkbox у HTML і CSS

### 20.1. Простий Checkbox

    <label>
      <input type="checkbox" name="newsletter">
      Отримувати новини
    </label>

У цьому прикладі Label пов'язаний із Checkbox завдяки тому, що містить його всередині.

### 20.2. Checkbox з окремим Label

    <input
      id="newsletter"
      type="checkbox"
      name="newsletter"
    >

    <label for="newsletter">
      Отримувати новини
    </label>

Атрибути:

- `type="checkbox"` — створює Checkbox;
- `id` — ідентифікатор поля;
- `name` — ім'я поля у формі;
- `value` — значення, яке передається, коли Checkbox вибраний;
- `checked` — початковий вибраний стан;
- `disabled` — робить поле недоступним для взаємодії;
- `required` — вимагає встановлення позначки перед надсиланням форми.

### 20.3. Checkbox Group

    <fieldset>
      <legend>Які технології тебе цікавлять?</legend>

      <label>
        <input
          type="checkbox"
          name="technology"
          value="html"
        >
        HTML
      </label>

      <label>
        <input
          type="checkbox"
          name="technology"
          value="css"
        >
        CSS
      </label>

      <label>
        <input
          type="checkbox"
          name="technology"
          value="javascript"
        >
        JavaScript
      </label>
    </fieldset>

Усі Checkbox мають однаковий `name`, але різні `value`.

Під час надсилання форми можна отримати кілька значень одного поля.

### 20.4. CSS для групи

    .checkbox-group {
      display: grid;
      gap: 0.75rem;
    }

    .checkbox-option {
      display: flex;
      align-items: flex-start;
      gap: 0.5rem;
      cursor: pointer;
    }

    .checkbox-option input {
      flex: 0 0 auto;
      margin-top: 0.2em;
    }

    .checkbox-option__label {
      line-height: 1.5;
    }

Тут:

- `display: grid` розміщує варіанти вертикально;
- `gap` задає відстань між рядками;
- `display: flex` вирівнює Checkbox і Label;
- `align-items: flex-start` допомагає працювати з багаторядковими текстами.

### 20.5. Стилізація нативного Checkbox

    .checkbox-option input {
      width: 1.125rem;
      height: 1.125rem;
      accent-color: #2563eb;
    }

    .checkbox-option input:focus-visible {
      outline: 2px solid #2563eb;
      outline-offset: 3px;
    }

`accent-color` дозволяє змінити акцентний колір нативного елемента в браузерах, які підтримують цю властивість.

Не забувай перевіряти фактичний вигляд у браузерах і на платформах, які підтримує проєкт.

## 21. Checkbox у React і Next.js

У React Checkbox може бути контрольованим компонентом.

### 21.1. Один Checkbox

    "use client";

    import { useState } from "react";

    export default function NewsletterCheckbox() {
      const [enabled, setEnabled] = useState(false);

      return (
        <label>
          <input
            type="checkbox"
            checked={enabled}
            onChange={(event) => setEnabled(event.target.checked)}
          />

          Отримувати новини
        </label>
      );
    }

Основні принципи:

- `useState` зберігає поточний стан;
- `checked` визначає, чи встановлена позначка;
- `onChange` реагує на зміну;
- `event.target.checked` повертає логічне значення `true` або `false`.

Для Checkbox використовується `checked`, а не `value`, коли потрібно керувати станом позначки.

### 21.2. Група Checkbox

    "use client";

    import { useState } from "react";

    const technologies = [
      "HTML",
      "CSS",
      "JavaScript",
      "TypeScript",
    ];

    export default function TechnologyCheckboxes() {
      const [selected, setSelected] = useState<string[]>([]);

      function toggleTechnology(technology: string) {
        setSelected((current) =>
          current.includes(technology)
            ? current.filter((item) => item !== technology)
            : [...current, technology]
        );
      }

      return (
        <fieldset>
          <legend>Технології</legend>

          {technologies.map((technology) => (
            <label key={technology}>
              <input
                type="checkbox"
                checked={selected.includes(technology)}
                onChange={() => toggleTechnology(technology)}
              />

              {technology}
            </label>
          ))}
        </fieldset>
      );
    }

У цьому прикладі:

- `selected` містить вибрані значення;
- `includes()` перевіряє, чи вибраний конкретний пункт;
- `filter()` видаляє значення зі списку;
- spread-оператор додає нове значення;
- `key` допомагає React ідентифікувати елементи списку.

### 21.3. TypeScript

Якщо значення мають обмежений набір, можна описати їх через union type.

    type Technology =
      | "html"
      | "css"
      | "javascript"
      | "typescript";

    const [selected, setSelected] = useState<Technology[]>([]);

Це дозволяє обмежити набір значень і зменшити ризик помилок.

### 21.4. Next.js і Client Components

Директива `"use client"` потрібна, коли компонент використовує клієнтський стан, обробники подій або інші клієнтські можливості React.

Простий статичний Checkbox не обов'язково потребує окремого Client Component. Рішення залежить від способу обробки форми.

## 22. Типові помилки в дизайні Checkboxes

### Помилка 1. Checkbox використовується замість Radio Button

Користувач може вибрати кілька значень, хоча дозволене лише одне.

**Рішення:** використовуй Radio Button для взаємовиключних варіантів.

### Помилка 2. Checkbox використовується замість Switch

Налаштування передбачає миттєве ввімкнення функції, але оформлене як пункт вибору без зрозумілого контексту.

**Рішення:** розглянь Switch, якщо він краще відповідає очікуваній поведінці.

### Помилка 3. Надто маленька область натискання

Користувачеві складно натиснути на квадрат.

**Рішення:** зроби Label клікабельним і збільш область взаємодії.

### Помилка 4. Незрозумілий Label

Користувач не знає, що зміниться після встановлення позначки.

**Рішення:** використовуй конкретні назви, які пояснюють призначення параметра.

### Помилка 5. Checked відрізняється лише кольором

Вибраний стан важко розпізнати.

**Рішення:** використовуй чітку галочку або іншу помітну форму.

### Помилка 6. Немає Focus indicator

Користувач клавіатури не розуміє, який елемент активний.

**Рішення:** забезпеч видимий індикатор фокусу.

### Помилка 7. Checkbox Group не має заголовка

Користувачеві незрозуміло, що об'єднує варіанти.

**Рішення:** додай зрозумілий заголовок групи.

### Помилка 8. Занадто багато пунктів в одному списку

Користувачеві складно переглядати довгий список.

**Рішення:** групуй варіанти, використовуй пошук або інші засоби фільтрації, якщо це відповідає сценарію.

### Помилка 9. Select All працює непередбачувано

Батьківський Checkbox не відповідає стану дочірніх пунктів.

**Рішення:** визнач чітку логіку checked, unchecked та indeterminate.

### Помилка 10. Disabled не має пояснення

Користувач не розуміє, чому параметр недоступний.

**Рішення:** додай пояснення, якщо причина важлива для наступної дії.

### Помилка 11. Згода встановлена автоматично

Користувач не зробив вибір самостійно.

**Рішення:** якщо потрібна явна згода, залиш Checkbox невибраним до дії користувача.

### Помилка 12. Немає повідомлення про помилку

Форма не надсилається, але користувач не розуміє чому.

**Рішення:** покажи повідомлення біля відповідного поля.

### Помилка 13. Непослідовні стилі

Checkbox у різних частинах продукту має різні розміри й стани без причини.

**Рішення:** використовуй спільні компоненти й токени дизайн-системи.

## 23. Практичний алгоритм дизайну Checkbox

Під час створення Checkbox рухайся послідовно.

1. **Визнач завдання.** Що саме вибирає користувач?
2. **Перевір тип компонента.** Чи потрібен Checkbox, а не Radio Button або Switch?
3. **Сформулюй Label.** Чи зрозуміле призначення?
4. **Визнач групування.** Чи пов'язані варіанти однією темою?
5. **Продумай початковий стан.** Чи повинен Checkbox бути вибраний за замовчуванням?
6. **Визнач усі стани.** Unchecked, Checked, Hover, Focus, Disabled, Error.
7. **Продумай область натискання.** Чи зручно активувати елемент?
8. **Перевір контраст.** Чи добре видно межу та галочку?
9. **Продумай поведінку групи.** Чи потрібні Select All та Indeterminate?
10. **Перевір доступність.** Чи працює компонент із клавіатурою?
11. **Перевір мобільний вигляд.** Чи зручно натискати й читати?
12. **Узгодь дизайн.** Чи відповідає компонент іншим полям?
13. **Перевір валідацію.** Чи зрозуміло показано помилку?
14. **Протестуй реальний сценарій.** Чи допомагає Checkbox виконати завдання швидше?

## 24. Практичний мініпроєкт: налаштування профілю учня

Створи форму налаштувань для освітньої платформи.

### Завдання

Потрібно реалізувати такі групи.

**Сповіщення**

    ☐ Отримувати новини
    ☐ Отримувати нагадування про заняття
    ☐ Отримувати повідомлення про оцінки

**Навчальні предмети**

    ☐ Математика
    ☐ Інформатика
    ☐ Фізика
    ☐ Історія

**Відображення**

    ☑ Показувати завершені завдання
    ☐ Використовувати компактний режим

### Етап 1. Структура

- Створи заголовок кожної групи.
- Додай Checkbox із Label.
- Розташуй пункти вертикально.
- Визнач відступи між рядками та групами.

### Етап 2. Візуальні стани

Для Checkbox передбач:

- Unchecked;
- Checked;
- Hover;
- Focus;
- Disabled;
- Error, якщо сценарій передбачає валідацію.

### Етап 3. Поведінка

Переконайся, що:

- кожен Checkbox змінюється незалежно;
- вибрані значення можна скасувати;
- стан можна зчитати програмно;
- дані можна використати під час збереження налаштувань.

### Етап 4. Доступність

Перевір:

- чи пов'язаний Label із Checkbox;
- чи можна керувати ним клавіатурою;
- чи видно Focus indicator;
- чи зрозуміло названо групи;
- чи достатній контраст.

### Етап 5. Адаптивність

Перевір:

- довгі Label;
- вузькі екрани;
- відстань між пунктами;
- область натискання;
- перенесення тексту.

### Етап 6. Додаткове завдання

Додай групу з батьківським Checkbox:

    ▣ Усі навчальні предмети

    ☑ Математика
    ☐ Інформатика
    ☑ Фізика
    ☐ Історія

Реалізуй логіку:

- усі пункти не вибрані — unchecked;
- усі пункти вибрані — checked;
- вибрана частина — indeterminate.

## 25. Чекліст готовності Checkbox

### Структура

- [ ] Призначення Checkbox зрозуміле.
- [ ] Label конкретний і короткий.
- [ ] Пов'язані варіанти згруповані.
- [ ] Групи мають зрозумілі заголовки.
- [ ] Helper text додається за потреби.
- [ ] Немає зайвих або неоднозначних пунктів.

### Візуальний дизайн

- [ ] Checkbox має достатній розмір.
- [ ] Межа помітна на фоні.
- [ ] Галочка чітко видима.
- [ ] Checked і unchecked відрізняються.
- [ ] Focus indicator помітний.
- [ ] Disabled не виглядає як звичайний активний елемент.
- [ ] Відступи послідовні.
- [ ] Довгі Label відображаються коректно.

### Поведінка

- [ ] Стан змінюється передбачувано.
- [ ] Кожен Checkbox у групі працює незалежно.
- [ ] Select All працює правильно, якщо використовується.
- [ ] Indeterminate відповідає стану дочірніх пунктів.
- [ ] Помилки мають зрозумілі повідомлення.
- [ ] Обов'язкові умови перевіряються перед надсиланням форми.

### Доступність

- [ ] Кожен Checkbox має доступну назву.
- [ ] Label активує Checkbox.
- [ ] Клавіатурне керування працює.
- [ ] Фокус добре помітний.
- [ ] Контраст достатній.
- [ ] Стан не передається лише кольором.
- [ ] Групи мають логічну структуру.

### Адаптивність

- [ ] Область натискання достатня.
- [ ] Між сусідніми пунктами є простір.
- [ ] Довгі Label не перекривають компонент.
- [ ] Списки залишаються читабельними на вузькому екрані.

## 26. Що потрібно запам'ятати

1. **Checkbox призначений для незалежного вибору.** Користувач може вибрати кілька пунктів одночасно.
2. **Radio Button призначений для одного варіанта.** Не замінюй його Checkbox, якщо вибір має бути взаємовиключним.
3. **Switch зазвичай керує станом функції.** Його використовують, коли очікується ввімкнення або вимкнення параметра.
4. **Label є важливою частиною компонента.** Користувач повинен розуміти значення вибору.
5. **Область натискання має бути достатньою.** Бажано зробити весь Label клікабельним.
6. **Checked state повинен бути помітним.** Не покладайся лише на зміну кольору.
7. **Focus indicator потрібний для клавіатурної навігації.** Не прибирай його без доступної заміни.
8. **Indeterminate показує частковий вибір.** Найчастіше він використовується в ієрархічних списках і масових операціях.
9. **Checkbox Group потребує логічного групування.** Заголовок допомагає зрозуміти зв'язок між пунктами.
10. **Нативний Checkbox — хороша відправна точка.** Кастомний компонент потребує додаткового тестування.
11. **Не встановлюй згоду автоматично.** Якщо потрібна явна згода користувача, він має зробити вибір самостійно.
12. **Дизайн-система забезпечує послідовність.** Стандартизуй розміри, стани, кольори й відступи.

## 29. Місце теми в UI Design

`05-components/05-checkboxes` — частина розділу **Components**, присвяченого повторно використовуваним елементам інтерфейсу.

Тема пов'язана з:

- `02-layout-and-composition` — компонуванням груп прапорців і форм;
- `03-color` — контрастом, межами та кольорами станів;
- `04-typography` — читабельністю Label і допоміжного тексту;
- `05-components/01-buttons` — діями збереження та підтвердження;
- `05-components/03-inputs` — текстовими полями;
- `05-components/04-selects` — вибором значень зі списків;
- Forms and Accessibility — валідацією, доступністю та клавіатурною взаємодією;
- React / Next.js — керуванням станом компонентів;
- дизайн-системами — токенами, варіантами та повторним використанням.

**Головний принцип:** якісний Checkbox робить незалежний вибір простим і зрозумілим. Користувач повинен легко розпізнавати поточний стан, змінювати його та розуміти наслідки своєї дії.
