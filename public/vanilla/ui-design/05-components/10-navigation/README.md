# 10. Navigation — Навігація інтерфейсу

Навігація (Navigation) — це система елементів інтерфейсу, яка допомагає користувачеві переміщатися між сторінками, розділами, категоріями та іншими частинами застосунку.

Навігація відповідає на три основні запитання:

- Де я зараз?
- Куди я можу перейти?
- Як мені дістатися до потрібної інформації?

**Головна ідея:** хороша навігація допомагає користувачеві швидко зрозуміти структуру застосунку та знайти потрібний розділ без зайвих зусиль.

---

## 1. Для чого потрібна навігація

Навігація допомагає:

- ✔ Переміщатися між сторінками.
- ✔ Переходити між основними розділами застосунку.
- ✔ Розуміти поточне розташування в структурі сайту.
- ✔ Знаходити потрібний контент.
- ✔ Повертатися до попередніх рівнів ієрархії.
- ✔ Переміщатися між секціями однієї сторінки.
- ✔ Орієнтуватися в мобільних і складних інтерфейсах.
- ✔ Підтримувати послідовність взаємодії на всіх сторінках.

Приклади застосування:

- сайт громади — головна, новини, розклад богослужінь, святі, контакти;
- LMS — курси, уроки, завдання, оцінки, профіль;
- інтернет-магазин — каталог, категорії, кошик, обране;
- блог — статті, категорії, автори, архів;
- адміністративна панель — dashboard, користувачі, налаштування;
- медичний застосунок — послуги, спеціалісти, записи, особистий кабінет.

---

## 2. Основні типи навігації

### 2.1. Primary Navigation — основна навігація

Основна навігація містить головні розділи сайту або застосунку.

Приклад:

    ┌──────────────────────────────────────────────────┐
    │ LOGO    Головна  Курси  Статті  Про нас  Контакти │
    └──────────────────────────────────────────────────┘

Зазвичай розташовується у верхній частині сторінки або в головному меню застосунку.

Основні правила:

- показуй лише найважливіші розділи;
- використовуй зрозумілі назви;
- дотримуйся однакового порядку пунктів на різних сторінках;
- позначай поточний розділ;
- не перевантажуй меню великою кількістю пунктів.

### 2.2. Secondary Navigation — додаткова навігація

Допомагає переміщатися між підрозділами основного розділу.

Приклад:

    Курси
    ├── Frontend
    ├── Backend
    ├── Бази даних
    └── Практичні проєкти

Додаткова навігація може бути горизонтальною, вертикальною або вкладеною в меню.

### 2.3. Breadcrumbs — навігаційний ланцюжок

Breadcrumbs показують шлях від верхнього рівня структури до поточної сторінки.

Приклад:

    Головна / Курси / JavaScript / Масиви

Допомагають користувачеві:

- розуміти своє місце в ієрархії;
- переходити до батьківських розділів;
- повертатися до категорій без використання кнопки браузера.

Breadcrumbs особливо корисні для великих сайтів, каталогів і багаторівневих структур.

Для невеликих застосунків із простою структурою вони можуть бути непотрібними.

### 2.4. Sidebar Navigation — бічна навігація

Розташовується в лівій або правій частині інтерфейсу.

    ┌─────────────────┬──────────────────────────────┐
    │ Dashboard       │                              │
    │ Користувачі     │       Основний контент       │
    │ Курси           │                              │
    │ Завдання        │                              │
    │ Налаштування    │                              │
    └─────────────────┴──────────────────────────────┘

Використовується для:

- адміністративних панелей;
- LMS;
- особистих кабінетів;
- складних багаторозділових застосунків.

Бічна навігація зручна, коли користувач часто переміщується між багатьма розділами.

### 2.5. Tab Navigation — навігація вкладками

Вкладки дозволяють перемикатися між пов'язаними представленнями в межах однієї сторінки або області інтерфейсу.

Приклад:

    ┌────────────┬────────────┬────────────┐
    │ Опис       │ Програма   │ Відгуки    │
    └────────────┴────────────┴────────────┘

Вкладки доречні, коли:

- вміст належить до одного об'єкта;
- альтернативні представлення мають однаковий рівень важливості;
- користувачеві не потрібно одночасно бачити весь вміст.

Не плутай вкладки з посиланнями на окремі сторінки. Якщо елементи ведуть на різні URL і є частиною навігації сайту, часто краще використовувати звичайні посилання.

### 2.6. Footer Navigation — навігація у футері

Розташовується в нижній частині сайту.

Може містити:

- контакти;
- політику конфіденційності;
- умови використання;
- посилання на важливі розділи;
- соціальні мережі;
- довідкову інформацію.

Footer доповнює основну навігацію, але не повинен бути єдиним місцем, де доступний важливий розділ.

### 2.7. Mobile Navigation — мобільна навігація

На невеликих екранах навігація часто змінює структуру.

Можливі варіанти:

- меню-гамбургер;
- нижня панель навігації;
- компактне горизонтальне меню;
- бічна панель, що відкривається;
- комбіновані рішення.

Вибір залежить від частоти використання розділів, складності застосунку та доступного простору.

---

## 3. Інші навігаційні патерни

### 3.1. Dropdown Navigation

Випадне меню відкриває додаткові пункти після натискання або наведення.

Приклад:

    Курси ▼
      Frontend
      Backend
      Бази даних

Використовуй його, коли потрібно згрупувати пов'язані розділи.

Не ховай у dropdown усі найважливіші пункти, якщо користувачі повинні часто до них звертатися.

### 3.2. Mega Menu

Велике багатоколонкове меню для сайтів зі складною структурою.

Може містити:

- групи категорій;
- підрозділи;
- короткі описи;
- тематичні посилання;
- зображення або промоблоки.

Mega menu потребує особливо уважного проєктування для клавіатурної навігації та мобільних екранів.

### 3.3. Pagination — посторінкова навігація

Дозволяє переходити між сторінками великого набору даних.

Приклад:

    [← Назад]  1  2  3  ...  10  [Далі →]

Використовується для:

- списків статей;
- результатів пошуку;
- каталогів;
- адміністративних таблиць.

Якщо користувачеві важливо знати загальну кількість результатів, її варто показувати окремо.

### 3.4. In-page Navigation — навігація в межах сторінки

Допомагає перейти до конкретної секції довгої сторінки.

Приклад:

    На цій сторінці:
    - Що таке JavaScript
    - Змінні
    - Функції
    - Масиви
    - Практика

Для реалізації можна використовувати посилання-якорі.

    <nav aria-label="Зміст сторінки">
      <ul>
        <li><a href="#variables">Змінні</a></li>
        <li><a href="#functions">Функції</a></li>
        <li><a href="#arrays">Масиви</a></li>
      </ul>
    </nav>

    <section id="variables">
      <h2>Змінні</h2>
      ...
    </section>

### 3.5. Bottom Navigation

Нижня панель із кількома основними пунктами, особливо поширена в мобільних застосунках.

Приклад:

    ┌──────────────────────────────────────┐
    │  Головна   Курси   Завдання   Профіль │
    └──────────────────────────────────────┘

Застосовуй для невеликої кількості основних розділів, до яких користувач звертається регулярно.

### 3.6. Navigation Rail

Компактна вертикальна панель, зазвичай з іконками, іноді з короткими підписами.

Може використовуватися в планшетних і desktop-інтерфейсах, коли повнорозмірна бічна панель займає забагато місця.

## 4. Інформаційна архітектура

Перш ніж малювати меню, потрібно визначити структуру контенту.

Інформаційна архітектура (Information Architecture, IA) — це організація інформації, категорій, сторінок і зв'язків між ними.

### 4.1. Ієрархія сторінок

Приклад структури навчальної платформи:

    LMS
    ├── Головна
    ├── Курси
    │   ├── Frontend
    │   │   ├── HTML і CSS
    │   │   └── JavaScript
    │   └── Backend
    │       ├── Node.js
    │       └── Бази даних
    ├── Завдання
    ├── Мій прогрес
    └── Профіль

Така структура допомагає зрозуміти:

- які сторінки є основними;
- які сторінки належать до підрозділів;
- які пункти потрібно включити в меню;
- де будуть доречні breadcrumbs;
- як користувач переходить від загального до конкретного.

### 4.2. Не плутай структуру сайту зі структурою меню

Не кожна сторінка повинна бути пунктом основної навігації.

Наприклад, сторінка окремого уроку може бути глибоко вкладена в розділ «Курси», але не потребувати окремого пункту в головному меню.

Меню показує найважливіші маршрути, а не повний перелік усіх URL.

### 4.3. Групування

Групуй пункти за зрозумілою користувачеві логікою:

- за темою;
- за типом завдання;
- за роллю користувача;
- за частотою використання;
- за рівнем ієрархії.

Уникай групування, яке зрозуміле лише розробнику, але не користувачеві.

### 4.4. Глибина навігації

Якщо для пошуку звичайної сторінки потрібно проходити багато рівнів меню, структуру варто переглянути.

Водночас не потрібно штучно робити всі сторінки доступними одним натисканням. Глибина може бути виправданою, якщо структура зрозуміла, а переходи логічні.

## 5. Візуальна ієрархія навігації

Навігація повинна показувати, які розділи важливіші, які є вкладеними, а який пункт активний.

### 5.1. Основні рівні

Зазвичай використовують:

- основні пункти — найпомітніші;
- вкладені пункти — візуально підпорядковані;
- активний пункт — виразно позначений;
- другорядні посилання — менш акцентні.

### 5.2. Вирівнювання

Пункти одного рівня повинні мати узгоджені:

- висоту;
- відступи;
- розмір шрифту;
- положення іконок;
- відстань між елементами.

### 5.3. Відступи

Відступи допомагають показати структуру вкладеного меню.

    .nav-list {
      display: flex;
      align-items: center;
      gap: 1.25rem;
      margin: 0;
      padding: 0;
      list-style: none;
    }

    .nav-link {
      display: inline-flex;
      align-items: center;
      gap: 0.5rem;
      padding: 0.75rem;
    }

Для вертикальної навігації може бути зручніше використовувати `flex-direction: column`.

### 5.4. Не покладайся лише на колір

Активний пункт можна виділяти кольором, але варто також використовувати інші зрозумілі ознаки:

- підкреслення;
- ліву або нижню межу;
- зміну товщини шрифту;
- індикатор активного розділу.

Це допомагає підтримувати читабельність і розрізнення станів.

---

## 6. Поточний пункт навігації

Користувач повинен розуміти, де він перебуває.

Наприклад, якщо відкрита сторінка «Курси», відповідний пункт основної навігації має бути позначений як активний.

### 6.1. Візуальне оформлення

    .nav-link[aria-current="page"] {
      color: var(--color-accent);
      font-weight: 700;
      text-decoration: underline;
      text-underline-offset: 0.25em;
    }

### 6.2. Семантика

Для посилання на поточну сторінку можна використовувати:

    <a href="/courses" aria-current="page">
      Курси
    </a>

`aria-current="page"` повідомляє допоміжним технологіям, що це посилання відповідає поточній сторінці.

Не встановлюй `aria-current="page"` одночасно на всі пункти меню. Його потрібно використовувати відповідно до фактичного стану.

### 6.3. Активний пункт і фокус — різні стани

- **Active / Current** — пункт відповідає поточному розділу або сторінці.
- **Focus** — елемент зараз має клавіатурний фокус.
- **Hover** — вказівник наведений на елемент.

Ці стани можуть виглядати схоже, але виконують різні функції.

---

## 7. Колір і контраст навігації

Колір допомагає розрізняти звичайні, активні та інтерактивні елементи.

Приклад CSS-змінних:

    :root {
      --color-page: #f5f7fa;
      --color-surface: #ffffff;
      --color-text: #202938;
      --color-muted: #64748b;
      --color-border: #dbe2ea;
      --color-accent: #2563eb;
      --color-nav-hover: #eef2ff;
    }

    .site-nav {
      background: var(--color-surface);
      border-bottom: 1px solid var(--color-border);
    }

    .nav-link {
      color: var(--color-text);
      text-decoration: none;
    }

    .nav-link:hover {
      background: var(--color-nav-hover);
    }

    .nav-link[aria-current="page"] {
      color: var(--color-accent);
      font-weight: 700;
    }

Це приклад палітри, а не універсальний стандарт.

### Контраст

Для звичайного тексту WCAG рекомендує контраст не менше `4.5:1`, а для великого тексту — не менше `3:1`.

Перевіряй контраст:

- звичайного тексту;
- активного пункту;
- тексту на hover-фоні;
- підписів біля іконок;
- індикаторів фокусу.

Не роби неактивні посилання настільки блідими, щоб користувач не міг їх прочитати.

---

## 8. Типографіка навігації

Назви пунктів повинні бути короткими, зрозумілими та передбачуваними.

Рекомендації:

- використовуй знайомі слова;
- уникай незрозумілих скорочень;
- дотримуйся однакового стилю назв;
- не змінюй назви одного розділу в різних частинах сайту без причини;
- перевіряй довгі переклади;
- передбачай збільшення тексту.

Наприклад, краще:

    Курси
    Статті
    Про нас
    Контакти

ніж надмірно довгі формулювання для звичайних пунктів головного меню.

Приклад:

    .nav-link {
      font-size: 1rem;
      line-height: 1.4;
      font-weight: 500;
    }

Розмір шрифту залежить від загального дизайну. Навігація не повинна бути настільки дрібною, щоб її було складно читати або натискати.

---

## 9. Іконки в навігації

Іконки можуть допомагати швидко розпізнавати розділи, особливо в компактних меню.

Приклади:

- будинок — головна;
- книга — навчальні матеріали;
- календар — розклад;
- користувач — профіль;
- шестерня — налаштування.

### Правила використання

- використовуй зрозумілі та послідовні іконки;
- не додавай іконку до кожного пункту лише заради декору;
- підтримуй однаковий розмір і стиль;
- не замінюй зрозумілі підписи незрозумілими символами;
- якщо іконка декоративна, приховуй її від допоміжних технологій;
- якщо іконка є єдиним візуальним вмістом кнопки, забезпеч доступну назву.

Приклад:

    <a href="/profile">
      <svg
        aria-hidden="true"
        focusable="false"
        width="20"
        height="20"
        viewBox="0 0 24 24"
      >
        <!-- SVG-іконка -->
      </svg>

      <span>Профіль</span>
    </a>

Якщо в навігації використовуються лише іконки, кожна інтерактивна кнопка або посилання повинні мати доступну назву, наприклад через видимий підпис або відповідний ARIA-атрибут.

---

## 10. Адаптивна навігація

Навігація повинна працювати на великих і малих екранах, не втрачаючи зрозумілості.

### 10.1. Desktop

Зазвичай доступні:

- логотип;
- основні розділи;
- додаткові меню;
- пошук;
- кнопка входу або профіль.

### 10.2. Tablet

Можна:

- зменшити проміжки;
- об'єднати другорядні пункти;
- використовувати компактнішу структуру;
- перейти до меню, яке відкривається кнопкою.

### 10.3. Mobile

На вузькому екрані часто використовують кнопку меню.

    ┌─────────────────────────────┐
    │ LOGO                    ☰   │
    └─────────────────────────────┘

Після натискання відкривається панель із пунктами навігації.

Важливо:

- користувач повинен розуміти, як відкрити меню;
- кнопка повинна мати зрозумілу назву;
- стан відкриття має бути помітним;
- меню повинно закриватися передбачувано;
- посилання мають бути зручними для натискання;
- вміст не повинен виходити за межі екрана.

### 10.4. Приклад адаптивної навігації на CSS

    .site-header {
      display: flex;
      align-items: center;
      justify-content: space-between;

      margin: 0;
      padding: 0;
      list-style: none;

Цей приклад демонструє зміну компонування, але сам по собі не реалізує відкриття та закриття меню. Для цього потрібен відповідний HTML-стан або JavaScript/React-логіка.

## 11. Dropdown-меню та вкладена навігація

Вкладені меню допомагають організовувати велику кількість пунктів.

Приклад:

    <nav aria-label="Основна навігація">
      <ul>
        <li>
          <a href="/">Головна</a>
        </li>

        <li>
          <a href="/courses">Курси</a>

          <ul>
            <li>
              <a href="/courses/frontend">Frontend</a>
            </li>

            <li>
              <a href="/courses/backend">Backend</a>
            </li>
          </ul>
        </li>
      </ul>
    </nav>

Це спрощена структура розмітки. У реальному інтерфейсі вкладене меню зазвичай додатково оформлюють і керують його видимістю.

### Важливі правила

- батьківський пункт повинен мати зрозуміле призначення;
- вкладені пункти мають бути візуально підпорядкованими;
- меню повинно працювати з клавіатури;
- не можна вимагати наведення миші як єдиного способу відкриття;
- користувач повинен розуміти, чи пункт веде на сторінку, чи відкриває підменю.

Якщо один елемент повинен і переходити на сторінку, і відкривати підменю, часто краще розділити ці дії між посиланням і кнопкою.

## 12. Доступність навігації

Навігація має бути доступною користувачам клавіатури, екранних читачів і людей із різними можливостями сприйняття.

### 12.1. Використовуй `<nav>`

Приклад:

    <nav aria-label="Основна навігація">
      <ul>
        <li><a href="/">Головна</a></li>
        <li><a href="/courses">Курси</a></li>
        <li><a href="/articles">Статті</a></li>
        <li><a href="/contacts">Контакти</a></li>
      </ul>
    </nav>

`nav` визначає навігаційний регіон, а `aria-label` допомагає відрізняти його від інших навігаційних областей.

Якщо на сторінці є кілька навігаційних областей, наприклад основна та навігація у футері, надай їм зрозумілі назви.

### 12.2. Використовуй списки

Списки допомагають передавати структуру меню.

Для звичайної навігації сайту часто достатньо:

- `<nav>`;
- `<ul>`;
- `<li>`;
- `<a>`.

Не потрібно автоматично використовувати складні ARIA-ролі `menu` та `menuitem`. Вони призначені для специфічних інтерактивних меню й можуть вимагати додаткової клавіатурної поведінки.

### 12.3. Клавіатурна навігація

Перевір, що користувач може:

- переходити між посиланнями клавішею `Tab`;
- активувати посилання клавішею `Enter`;
- відкривати інтерактивні меню клавіатурою;
- бачити, який елемент має фокус;
- виходити з меню без пастки фокусу.

### 12.4. Видимий фокус

    .nav-link:focus-visible {
      outline: 3px solid var(--color-accent);
      outline-offset: 3px;
    }

Не прибирай `outline` без доступної та помітної заміни.

### 12.5. Достатній розмір інтерактивної області

Пункти меню повинні мати зручну область натискання, особливо на мобільних пристроях.

Не роби посилання надто тісними одне до одного.

### 12.6. Пропуск повторюваної навігації

Для сторінок із великим меню корисне посилання «Перейти до основного вмісту».

    <a class="skip-link" href="#main-content">
      Перейти до основного вмісту
    </a>

    <nav aria-label="Основна навігація">
      ...
    </nav>

    <main id="main-content">
      <h1>Головна сторінка</h1>
    </main>

Приклад стилізації:

    .skip-link {
      position: absolute;
      top: 0;
      left: 0;
      transform: translateY(-150%);
      padding: 0.75rem 1rem;
      background: #ffffff;
      color: #202938;
      z-index: 1000;
    }

    .skip-link:focus {
      transform: translateY(0);
    }

## 13. Breadcrumbs: реалізація

Приклад HTML:

    "use strict";

    const menuToggle = document.querySelector(".menu-toggle");

        const isExpanded =
          menuToggle.getAttribute("aria-expanded") === "true";

          "aria-expanded",

## 15. Навігація в React і Next.js

У React навігацію зручно розділяти на компоненти.

Приклад структури:

    src/
    └── app/
        ├── components/
        │   └── navigation/
        │       ├── SiteHeader.tsx
        │       ├── PrimaryNavigation.tsx
        │       └── PrimaryNavigation.module.css
        ├── courses/
        │   └── page.tsx
        ├── articles/
        │   └── page.tsx
        └── page.tsx

### 15.1. Статична навігація

У Next.js для внутрішніх переходів використовуй `Link`.

    import Link from "next/link";

    export default function PrimaryNavigation() {
      return (
        <nav aria-label="Основна навігація">
          <ul>
            <li>
              <Link href="/">Головна</Link>
            </li>

            <li>
              <Link href="/courses">Курси</Link>
            </li>

            <li>
              <Link href="/articles">Статті</Link>
            </li>

            <li>
              <Link href="/contacts">Контакти</Link>
            </li>
          </ul>
        </nav>
      );
    }

Для звичайного відображення посилань не потрібен `"use client"`.

### 15.2. Навігація на основі даних

Якщо список пунктів повторюється, можна зберігати його в масиві.

    import Link from "next/link";

    type NavigationItem = {
      label: string;
      href: string;
    };

    const navigationItems: NavigationItem[] = [
      { label: "Головна", href: "/" },
      { label: "Курси", href: "/courses" },
      { label: "Статті", href: "/articles" },
      { label: "Контакти", href: "/contacts" },
    ];

    export default function PrimaryNavigation() {
      return (
        <nav aria-label="Основна навігація">
          <ul>
            {navigationItems.map((item) => (
              <li key={item.href}>
                <Link href={item.href}>
                  {item.label}
                </Link>
              </li>
            ))}
          </ul>
        </nav>
      );
    }

Переваги:

- дані відокремлені від JSX;
- порядок пунктів легко змінювати;
- простіше підтримувати однакові меню;
- кожен пункт має стабільний `key`.

### 15.3. Активний пункт у Next.js

У App Router можна використати `usePathname()`.

    "use client";

    import Link from "next/link";
    import { usePathname } from "next/navigation";

    const navigationItems = [
      { label: "Головна", href: "/" },
      { label: "Курси", href: "/courses" },
      { label: "Статті", href: "/articles" },
    ];

    export default function PrimaryNavigation() {
      const pathname = usePathname();

      return (
        <nav aria-label="Основна навігація">
          <ul>
            {navigationItems.map((item) => {
              const isCurrent = pathname === item.href;

              return (
                <li key={item.href}>
                  <Link
                    href={item.href}
                    aria-current={isCurrent ? "page" : undefined}
                  >
                    {item.label}
                  </Link>
                </li>
              );
            })}
          </ul>
        </nav>
      );
    }

Це спрощений приклад точного збігу URL. Для вкладених маршрутів, наприклад `/courses/javascript`, може знадобитися окрема логіка визначення активного розділу.

Використання `usePathname()` робить компонент клієнтським. Якщо активний стан не потрібен або може бути визначений інакше, не додавай `"use client"` без потреби.

### 15.4. Мобільне меню в React

Якщо кнопка керує відкриттям меню, потрібен React-стан.

    "use client";

    import { useState } from "react";
    import Link from "next/link";

    const navigationItems = [
      { label: "Головна", href: "/" },
      { label: "Курси", href: "/courses" },
      { label: "Статті", href: "/articles" },
      { label: "Контакти", href: "/contacts" },
    ];

    export default function MobileNavigation() {
      const [isOpen, setIsOpen] = useState(false);

      return (
        <div>
          <button
            type="button"
            aria-expanded={isOpen}
            aria-controls="mobile-navigation"
            onClick={() => setIsOpen((current) => !current)}
          >
            {isOpen ? "Закрити меню" : "Відкрити меню"}
          </button>

          <nav
            id="mobile-navigation"
            aria-label="Основна навігація"
            hidden={!isOpen}
          >
            <ul>
              {navigationItems.map((item) => (
                <li key={item.href}>
                  <Link
                    href={item.href}
                    onClick={() => setIsOpen(false)}
                  >
                    {item.label}
                  </Link>
                </li>
              ))}
            </ul>
          </nav>
        </div>
      );
    }

У цьому прикладі:

- `useState` керує відкриттям меню;
- `aria-expanded` передає стан кнопки;
- `aria-controls` вказує на меню;
- `hidden` приховує закрите меню;
- після вибору посилання меню закривається.

Для production-інтерфейсу додатково перевір поведінку клавіатури, фокусу та взаємодію з рештою сторінки.

## 16. Типові помилки навігації

### Помилка 1. Забагато пунктів у головному меню

Користувачеві складно швидко знайти потрібний розділ.

**Рішення:** залиш основні маршрути, а другорядні згрупуй у підменю або розмісти в інших відповідних областях.

### Помилка 2. Незрозумілі назви

Назви зрозумілі розробнику, але не користувачеві.

**Рішення:** використовуй прості та послідовні формулювання, що відповідають змісту сторінки.

### Помилка 3. Відсутній активний стан

Користувач не розуміє, який розділ відкритий.

**Рішення:** позначай поточну сторінку візуально й, де доречно, через `aria-current`.

### Помилка 4. Меню працює лише з мишкою

Клавіатурою неможливо відкрити підменю або перейти до потрібного пункту.

**Рішення:** передбач керування клавіатурою та видимий фокус.

### Помилка 5. Dropdown відкривається тільки при наведенні

На сенсорному екрані або клавіатурі поведінка може бути незрозумілою.

**Рішення:** передбач кероване відкриття кнопкою та відповідні стани.

### Помилка 6. Усі пункти однаково виділені

Немає візуального розрізнення між основними й другорядними розділами.

**Рішення:** використовуй зрозумілу ієрархію, групування та послідовні відступи.

### Помилка 7. Мобільне меню займає весь екран без потреби

Користувачеві важко повернутися до контенту.

**Рішення:** обирай модель меню відповідно до складності застосунку, а закриття роби передбачуваним.

### Помилка 8. Надто дрібні інтерактивні області

Пункти складно натискати на смартфоні.

**Рішення:** збільшуй внутрішні відступи та відстань між сусідніми елементами.

### Помилка 9. Іконки без доступних назв

Екранний читач не може зрозуміти призначення кнопки.

**Рішення:** додавай зрозумілу доступну назву або видимий текстовий підпис.

### Помилка 10. Непослідовна структура на різних сторінках

Меню змінює порядок або назви пунктів без очевидної причини.

**Рішення:** підтримуй стабільну основну навігацію, а контекстні елементи розміщуй окремо.

### Помилка 11. Зайві ARIA-ролі

Звичайні посилання навігації оголошуються складним інтерактивним меню без реалізації відповідної поведінки.

**Рішення:** починай із семантичних HTML-елементів. Додавай ARIA лише тоді, коли це потрібно для доступного опису або поведінки компонента.

### Помилка 12. Навігація не враховує довгі назви

Після перекладу або зміни тексту пункти виходять за межі контейнера.

**Рішення:** перевіряй перенесення, проміжки, адаптивні стани й масштабування тексту.

## 17. Практичний мініпроєкт — Navigation System

**Мета:** створити узгоджену навігацію для невеликого вебзастосунку.

### Етап 1. Визнач структуру

Створи приклад структури:

    Навчальна платформа
    ├── Головна
    ├── Курси
    │   ├── Frontend
    │   └── Backend
    ├── Статті
    ├── Мій прогрес
    └── Профіль

Визнач, які пункти повинні бути в основному меню, а які — у вкладеній навігації.

### Етап 2. Намалюй макет

Продумай:

- логотип;
- основні пункти;
- активний пункт;
- підменю;
- область користувацьких дій;
- вигляд мобільного меню.

### Етап 3. Створи HTML

Використай:

- `<header>`;
- `<nav>`;
- `<ul>`;
- `<li>`;
- `<a>`;
- `<button>` там, де потрібна дія.

### Етап 4. Додай CSS

Реалізуй:

- вирівнювання;
- відступи;
- типографіку;
- активний стан;
- hover;
- focus-visible;
- адаптивну поведінку.

### Етап 5. Реалізуй мобільне меню

Додай кнопку відкриття та закриття.

Перевір `aria-expanded`, `aria-controls` і поведінку посилань.

### Етап 6. Додай breadcrumbs

Для вкладеної сторінки, наприклад окремого курсу, покажи шлях до батьківських розділів.

### Етап 7. Перенеси навігацію в React

Створи компонент `PrimaryNavigation`, винеси список пунктів у типізований масив і відобрази його через `map()`.

### Етап 8. Додай активний пункт у Next.js

Використай `usePathname()` лише тоді, коли він справді потрібен для визначення поточного маршруту.

### Етап 9. Перевір доступність

Переконайся, що:

- усі посилання працюють;
- меню доступне з клавіатури;
- фокус помітний;
- кнопки мають зрозумілі назви;
- активний пункт позначений правильно;
- мобільне меню не перекриває важливий контент без можливості його відкрити знову або закрити.

## 18. Чекліст перевірки навігації

### Інформаційна архітектура

- [ ] Структура розділів зрозуміла.
- [ ] Основні та другорядні пункти розділені.
- [ ] Назви відповідають очікуванням користувача.
- [ ] Пункти згруповані за логікою контенту.
- [ ] Меню не дублює без потреби всі сторінки сайту.

### Візуальний дизайн

- [ ] Є чітка ієрархія пунктів.
- [ ] Відступи послідовні.
- [ ] Активний пункт легко розпізнати.
- [ ] Контраст достатній.
- [ ] Іконки мають однаковий стиль.
- [ ] Довгі назви не руйнують компонування.

### Адаптивність

- [ ] Меню працює на desktop.
- [ ] Меню працює на tablet.
- [ ] Мобільний варіант зрозумілий.
- [ ] Інтерактивні області зручні для натискання.
- [ ] Немає небажаного горизонтального прокручування.
- [ ] Збільшення тексту не робить меню непридатним.

### Доступність

- [ ] Використано семантичний `<nav>`.
- [ ] Навігаційні області мають зрозумілі назви, якщо їх декілька.
- [ ] Посилання доступні з клавіатури.
- [ ] Фокус помітний.
- [ ] Поточна сторінка позначена відповідно до контексту.
- [ ] Іконки-кнопки мають доступні назви.
- [ ] Вкладені меню мають зрозумілу клавіатурну поведінку.
- [ ] Немає пастки фокусу.

### Код

- [ ] Структура HTML семантична.
- [ ] Переходи використовують посилання.
- [ ] Дії відкриття меню використовують кнопки.
- [ ] Повторювані пункти можна створювати з масиву даних.
- [ ] У React задано стабільні `key`.
- [ ] У Next.js не використовується `"use client"` без потреби.
- [ ] Стан мобільного меню синхронізований із доступними атрибутами.
