# 09. Cards — Картки інтерфейсу

Картки (Cards) — це UI-компоненти, які об'єднують пов'язану інформацію в окремий візуальний блок. Картка може містити зображення, заголовок, опис, метадані, ціну, статус або елементи керування.

Картки допомагають структурувати складний інтерфейс, розділяти інформацію на зрозумілі групи та створювати послідовну композицію сторінки.

**Головна ідея:** картка повинна об'єднувати інформацію, яка належить до одного об'єкта, завдання або змістового блоку.

---

## 1. Для чого потрібні картки

Картки використовують, коли потрібно:

- ✔ Представити окремий об'єкт: товар, курс, статтю, користувача.
- ✔ Показати список однотипних елементів.
- ✔ Згрупувати пов'язану інформацію.
- ✔ Організувати каталог або галерею.
- ✔ Виділити короткий інформаційний блок.
- ✔ Надати доступ до детальної сторінки.
- ✔ Показати статус, рейтинг, ціну або інші метадані.
- ✔ Створити адаптивну композицію з повторюваних компонентів.

Приклади застосування:

- інтернет-магазин — картки товарів;
- LMS — картки курсів і навчальних матеріалів;
- блог — картки статей;
- медичний застосунок — картки лікарів або послуг;
- сайт громади — картки новин, подій і парафіяльних матеріалів;
- панель керування — картки статистики та завдань.

---

## 2. Анатомія картки

Типова картка може складатися з таких частин:

    ┌──────────────────────────────┐
    │                              │
    │          Зображення          │
    │                              │
    ├──────────────────────────────┤
    │ Категорія або статус         │
    │                              │
    │ Заголовок картки             │
    │                              │
    │ Короткий опис інформації     │
    │                              │
    │ Додаткові метадані           │
    │                              │
    │ Ціна / дата / рейтинг        │
    │                              │
    │ [Переглянути деталі]          │
    └──────────────────────────────┘

Не кожна картка повинна містити всі ці елементи.

Наприклад, картка статистики може мати лише назву, число та зміну показника. Картка статті може містити зображення, заголовок, дату й короткий опис.

### Основні частини

- **Container** — зовнішня область картки.
- **Media** — зображення, ілюстрація або відео.
- **Label / Badge** — категорія або статус.
- **Title** — основний заголовок.
- **Description** — короткий опис.
- **Metadata** — дата, автор, тривалість, рейтинг тощо.
- **Actions** — посилання або кнопки дій.

### Що потрібно пам'ятати

Картка — це не обов'язково прямокутник із тінню. Це насамперед **структурована група пов'язаної інформації**. Межі групи можуть створюватися фоном, відступами, лініями, контрастом або композицією.

---

## 3. Основні типи карток

### 3.1. Information Card — інформаційна картка

Містить коротку інформацію про об'єкт або тему.

Приклад:

    ┌──────────────────────────────┐
    │ Основи JavaScript            │
    │                              │
    │ Вивчення змінних, функцій і   │
    │ структур даних.              │
    │                              │
    │ Рівень: Початковий           │
    └──────────────────────────────┘

Використовується для інформаційних блоків, описів функцій і коротких довідок.

### 3.2. Image Card — картка із зображенням

Містить велике зображення та текстову інформацію.

    ┌──────────────────────────────┐
    │                              │
    │          Зображення          │
    │                              │
    ├──────────────────────────────┤
    │ Заголовок                    │
    │ Короткий опис                │
    └──────────────────────────────┘

Використовується для статей, подій, місць, галерей і каталогів.

### 3.3. Product Card — картка товару

Зазвичай містить:

- зображення товару;
- назву;
- ціну;
- рейтинг або доступність;
- кнопку купівлі чи додавання до кошика.

### 3.4. Article Card — картка статті

Зазвичай містить:

- обкладинку;
- категорію;
- заголовок;
- короткий опис;
- автора;
- дату публікації;
- посилання на повний матеріал.

### 3.5. Profile Card — картка профілю

Може містити:

- аватар;
- ім'я;
- роль або професію;
- короткий опис;
- контактні дані;
- дію для перегляду профілю.

### 3.6. Statistic Card — картка показника

Відображає ключове число або стан.

    ┌──────────────────────────────┐
    │ Завершені уроки              │
    │                              │
    │ 24                           │
    │                              │
    │ +3 за цей тиждень            │
    └──────────────────────────────┘

Використовується в dashboard, адміністративних панелях і навчальних системах.

### 3.7. Interactive Card — інтерактивна картка

Картка, яка реагує на взаємодію користувача:

- відкриває сторінку;
- розгортає додаткову інформацію;
- дозволяє вибрати варіант;
- показує меню дій;
- змінює стан після натискання.

Інтерактивність потрібно робити очевидною, а поведінку — передбачуваною.

### 3.8. Horizontal Card — горизонтальна картка

Зображення та текст розташовані поруч.

    ┌──────────┬───────────────────┐
    │          │ Заголовок         │
    │ Зображення│ Опис              │
    │          │ Дата              │
    └──────────┴───────────────────┘

Підходить для списків статей, результатів пошуку, навчальних матеріалів і повідомлень.

---

## 4. Вибір структури картки

Структура залежить від типу контенту та головного завдання користувача.

| Тип картки | Головний елемент | Додаткові елементи |
|---|---|---|
| Товар | Зображення та ціна | Рейтинг, кнопка |
| Стаття | Заголовок | Обкладинка, дата, опис |
| Курс | Назва курсу | Рівень, тривалість, прогрес |
| Профіль | Ім'я та аватар | Роль, опис, контакти |
| Статистика | Числовий показник | Назва, динаміка |
| Подія | Назва та дата | Зображення, місце |
| Повідомлення | Основний текст | Автор, час, статус |

Правило:

**Спочатку визнач головну інформацію, а потім додавай лише ті елементи, які допомагають її зрозуміти або використати.**

Не потрібно робити всі картки однаковими за внутрішньою структурою, якщо їхні завдання відрізняються.

---

## 5. Візуальна ієрархія картки

Візуальна ієрархія визначає, у якому порядку користувач помічає елементи.

Типова послідовність:

1. Зображення або головний показник.
2. Заголовок.
3. Короткий опис.
4. Метадані.
5. Дія.

Але порядок може змінюватися залежно від призначення.

Для картки товару ціна може бути важливішою за опис. Для картки події — дата. Для картки статистики — число.

### 5.1. Заголовок

Заголовок повинен:

- чітко називати об'єкт;
- мати помітну відмінність від опису;
- бути достатньо коротким;
- мати передбачувану поведінку при перенесенні рядків.

Приклад CSS:

    .card__title {
      margin: 0;
      font-size: 1.25rem;
      line-height: 1.3;
      font-weight: 700;
    }

### 5.2. Опис

Опис пояснює зміст картки, але не повинен перевантажувати її.

    .card__description {
      margin: 0;
      color: var(--color-text-muted);
      font-size: 0.95rem;
      line-height: 1.6;
    }

Для карток у сітці можна обмежувати кількість рядків опису. Однак важливу інформацію не слід приховувати без можливості її переглянути.

### 5.3. Метадані

Метадані — другорядна інформація:

- дата;
- автор;
- категорія;
- тривалість;
- рейтинг;
- статус;
- кількість учасників.

Метадані мають бути помітними, але не конкурувати з головним заголовком.

### 5.4. Основна дія

Якщо картка передбачає дію, користувач повинен розуміти:

- що саме відбудеться;
- який елемент можна натиснути;
- чи відкриється нова сторінка;
- чи зміниться стан поточної сторінки.

Назви кнопок мають описувати дію: «Переглянути курс», «Читати статтю», «Додати до кошика».

---

## 6. Розміри та пропорції

Універсального розміру картки немає. Він залежить від типу контенту, ширини контейнера та кількості колонок.

### 6.1. Ширина

Картки повинні мати достатньо простору для заголовків, описів і кнопок.

Занадто вузькі картки можуть спричинити:

- надмірне перенесення тексту;
- вертикально розтягнуті блоки;
- незручні кнопки;
- порушення візуальної ієрархії.

### 6.2. Висота

Висота картки може бути:

- автоматичною — залежить від контенту;
- однаковою в межах сітки;
- обмеженою для певного типу карток;
- адаптивною відповідно до ширини.

Не варто примусово задавати однакову висоту всім карткам, якщо контент суттєво відрізняється.

### 6.3. Співвідношення сторін зображення

Для зображень часто використовують:

- `1 / 1` — квадрат;
- `4 / 3` — традиційний формат;
- `3 / 2` — фотографії;
- `16 / 9` — широкі обкладинки.

Приклад:

    .card__media {
      aspect-ratio: 16 / 9;
      overflow: hidden;
    }

    .card__image {
      display: block;
      width: 100%;
      height: 100%;
      object-fit: cover;
    }

`object-fit: cover` заповнює область, але може обрізати частину зображення. Тому потрібно перевіряти, чи не втрачається важливий об'єкт.

Для зображень, які повинні повністю залишатися видимими, може підійти `object-fit: contain`.

---

## 7. Відступи та внутрішня композиція

Відступи допомагають відокремити групи інформації.

Типові проміжки:

- 8 px — між тісно пов'язаними елементами;
- 12–16 px — між заголовком і описом;
- 16–24 px — внутрішні відступи картки;
- 24–32 px — між більшими групами елементів.

Це орієнтири, а не обов'язкові значення.

Приклад:

    :root {
      --card-padding: 1.25rem;
      --card-gap: 0.75rem;
      --card-radius: 0.75rem;
    }

    .card {
      display: flex;
      flex-direction: column;
      gap: var(--card-gap);
      padding: var(--card-padding);
      border-radius: var(--card-radius);
    }

Важливо відрізняти:

- **Padding** — відстань між вмістом і краями картки.
- **Gap** — відстань між дочірніми елементами.
- **Margin** — зовнішній відступ елемента від сусідів.

У сучасному CSS для компонування дочірніх елементів часто зручно використовувати `gap`.

---

## 8. Межі, фон, тіні та заокруглення

Картку можна відокремити від сторінки кількома способами.

### 8.1. Межа

    .card {
      border: 1px solid var(--color-border);
    }

Підходить для стриманих інтерфейсів, форм, списків і компонентів на світлому фоні.

### 8.2. Контраст фону

    .card {
      background-color: var(--color-surface);
    }

Фон допомагає відрізнити картку від загального тла сторінки.

### 8.3. Тінь

    .card {
      box-shadow: 0 2px 8px rgb(0 0 0 / 8%);
    }

Тінь створює враження глибини. Її не потрібно застосовувати до кожного блоку.

### 8.4. Заокруглення

    .card {
      border-radius: 0.75rem;
    }

Радіус має відповідати загальному стилю дизайн-системи.

### Основне правило

Не варто одночасно використовувати сильну тінь, контрастну межу, яскравий фон і велике заокруглення без конкретної причини.

Картка повинна бути помітною настільки, наскільки цього потребує її роль.

---

## 9. Колір і контраст

Колір допомагає створювати ієрархію та передавати стан.

Типова схема:

- фон сторінки — загальне тло;
- фон картки — поверхня контенту;
- основний текст — заголовки та ключова інформація;
- вторинний текст — описи й метадані;
- акцентний колір — посилання та важливі дії;
- семантичні кольори — успіх, попередження, помилка.

Приклад CSS-змінних:

    :root {
      --color-page: #f5f7fa;
      --color-surface: #ffffff;
      --color-text: #202938;
      --color-text-muted: #64748b;
      --color-border: #dbe2ea;
      --color-accent: #2563eb;
    }

    .card {
      color: var(--color-text);
      background: var(--color-surface);
      border: 1px solid var(--color-border);
    }

    .card__description {
      color: var(--color-text-muted);
    }

Це приклад палітри, а не універсальний стандарт.

### Доступність контрасту

Для звичайного тексту WCAG рекомендує коефіцієнт контрастності не менше `4.5:1`. Для великого тексту — не менше `3:1`.

Не слід передавати значення статусу лише кольором. Наприклад, стан «Помилка» потрібно позначати не тільки червоним фоном, а й текстом або відповідною іконкою.

---

## 10. Типографіка та довгі тексти

Картки часто мають обмежений простір, тому типографіка особливо важлива.

Рекомендації:

- використовуй чітку ієрархію заголовка й опису;
- підтримуй комфортну висоту рядка;
- не зменшуй текст надмірно заради компактності;
- перевіряй довгі заголовки;
- враховуй різну довжину перекладів;
- не обрізай важливу інформацію без можливості її прочитати.

Приклад обмеження опису:

    .card__description {
      display: -webkit-box;
      -webkit-box-orient: vertical;
      -webkit-line-clamp: 3;
      overflow: hidden;
    }

`line-clamp` корисний для коротких попередніх описів у каталогах. Якщо повний текст важливий, передбач можливість відкрити деталі.

Не встановлюй однакову фіксовану висоту тексту без перевірки поведінки при масштабуванні та збільшенні шрифту.

---

## 11. Сітка карток

Окрема картка зазвичай є частиною більшої композиції.

Для розташування карток використовують:

- CSS Grid — для двовимірних сіток;
- Flexbox — для одновимірних рядів;
- звичайний потік документа — для вертикальних списків.

### 11.1. Адаптивна сітка на CSS Grid

    .card-grid {
      display: grid;
      grid-template-columns:
        repeat(auto-fit, minmax(min(100%, 16rem), 1fr));
      gap: 1.5rem;
    }

Цей варіант дозволяє автоматично розміщувати картки в доступній ширині.

`minmax()` задає мінімальну та максимальну ширину колонки, а `auto-fit` допомагає адаптувати кількість колонок.

### 11.2. Коли використовувати Flexbox

Flexbox зручний, якщо картки потрібно розмістити в ряд із перенесенням:

    .card-list {
      display: flex;
      flex-wrap: wrap;
      gap: 1rem;
    }

    .card-list > * {
      flex: 1 1 16rem;
    }

### 11.3. Коли краще звичайний список

Якщо картки містять багато тексту або мають вигляд рядків результатів пошуку, вертикальний список може бути зручнішим за багатоколонкову сітку.

Не кожну колекцію потрібно оформлювати у вигляді карток.

---

## 12. Адаптивність

Картка повинна залишатися зрозумілою на різних екранах.

### На великому екрані

- кілька колонок;
- більше простору між картками;
- можливість показати додаткові метадані.

### На планшеті

- менше колонок;
- помірні проміжки;
- збереження читабельної ширини.

### На смартфоні

- одна або дві колонки залежно від ширини;
- зручні області натискання;
- коротші описи або інша композиція;
- відсутність горизонтального прокручування сторінки.

Приклад:

    .card-grid {
      display: grid;
      grid-template-columns: repeat(3, minmax(0, 1fr));
      gap: 1.5rem;
    }

    @media (max-width: 900px) {
      .card-grid {
        grid-template-columns: repeat(2, minmax(0, 1fr));
      }
    }

    @media (max-width: 600px) {
      .card-grid {
        grid-template-columns: 1fr;
      }
    }

Конкретні контрольні точки (`breakpoints`) залежать від компонента та макета, а не лише від популярних розмірів пристроїв.

---

## 13. Hover, Focus та інші стани

Інтерактивні картки повинні мати зрозумілий зворотний зв'язок.

Основні стани:

- **Default** — звичайний вигляд.
- **Hover** — вказівник наведений на елемент.
- **Focus-visible** — елемент отримав клавіатурний фокус.
- **Active** — елемент натискається.
- **Selected** — картку вибрано.
- **Disabled** — дія тимчасово недоступна.
- **Loading** — дані завантажуються.
- **Error** — сталася помилка.

Приклад:

    .card--interactive {
      transition:
        border-color 160ms ease,
        box-shadow 160ms ease,
        transform 160ms ease;
    }

    .card--interactive:hover {
      border-color: var(--color-accent);
      box-shadow: 0 6px 18px rgb(0 0 0 / 8%);
    }

    .card--interactive:focus-visible {
      outline: 3px solid var(--color-accent);
      outline-offset: 3px;
    }

    @media (prefers-reduced-motion: reduce) {
      .card--interactive {
        transition: none;
      }
    }

Не покладайся лише на `hover`: на сенсорних пристроях його може не бути.

Якщо картка вибрана, наприклад у виборі курсу, стан `Selected` повинен залишатися видимим після завершення натискання.

## 14. Доступність карток

Картки можуть містити заголовки, зображення, посилання та кнопки. Їхня HTML-структура має відображати реальне призначення.

### 14.1. Використовуй семантичний HTML

Приклад картки статті:

    <article class="card">
      <img
        class="card__image"
        src="/images/javascript.jpg"
        alt="Робоче місце з ноутбуком"
      />

      <div class="card__content">
        <h2 class="card__title">
          Основи JavaScript
        </h2>

        <p class="card__description">
          Знайомство зі змінними, функціями та масивами.
        </p>

        <a href="/courses/javascript">
          Переглянути курс
        </a>
      </div>
    </article>

`article` підходить для самостійного змістового блоку, а заголовок визначає його тему.

Для картки, яка є просто групою елементів інтерфейсу, може бути достатньо `div` або іншого відповідного контейнера.

### 14.2. Посилання чи кнопка?

Використовуй:

- `<a>` — для переходу на іншу сторінку або до іншого ресурсу;
- `<button>` — для виконання дії в поточному інтерфейсі.

Приклади:

    <a href="/articles/design">
      Читати статтю
    </a>

    <button type="button">
      Додати до обраного
    </button>

Не використовуй `div` із `onClick` як заміну кнопці без необхідності. Нативні інтерактивні елементи краще підтримують клавіатуру та допоміжні технології.

### 14.3. Чи потрібно робити всю картку клікабельною?

Можна зробити всю картку посиланням, якщо вона веде до однієї сторінки й не містить інших незалежних інтерактивних елементів.

Якщо картка має кілька дій, краще використовувати окремі посилання та кнопки.

Уникай вкладення кнопок або додаткових посилань усередину іншого посилання.

### 14.4. Зображення та альтернативний текст

Якщо зображення передає важливу інформацію, додай змістовний `alt`.

Якщо воно лише декоративне й не додає інформації, використовуй порожній `alt=""`.

## 16. Картки в React і Next.js

У React картки зазвичай створюють як повторно використовувані компоненти.

Приклад структури:

    src/
    └── app/
        └── courses/
            ├── page.tsx
            ├── CourseCard.tsx
            ├── CourseCard.module.css
            └── data.ts

### 16.1. Типізація даних

`data.ts`:

    export type Course = {
      id: string;
      title: string;
      description: string;
      level: "beginner" | "intermediate" | "advanced";
      lessonsCount: number;
      href: string;
      image: string;
      imageAlt: string;
    };

    export const courses: Course[] = [
      {
        id: "javascript",
        title: "Основи JavaScript",
        description: "Змінні, умови, цикли та функції.",
        level: "beginner",
        lessonsCount: 12,
        href: "/courses/javascript",
        image: "/images/javascript.jpg",
        imageAlt: "Ноутбук на робочому столі",
      },
      {
        id: "typescript",
        title: "Основи TypeScript",
        description: "Типи, інтерфейси та безпечніші програми.",
        level: "intermediate",
        lessonsCount: 10,
        href: "/courses/typescript",
        image: "/images/typescript.jpg",

### 16.2. Компонент картки

`CourseCard.tsx`:

    import Link from "next/link";
    import type { Course } from "./data";
    import styles from "./CourseCard.module.css";

    type CourseCardProps = {
      course: Course;
    };

    const levelLabels: Record<Course["level"], string> = {
      beginner: "Початковий рівень",
      intermediate: "Середній рівень",
      advanced: "Просунутий рівень",
    };

    export default function CourseCard({
      course,
    }: CourseCardProps) {
      return (
        <article className={styles.card}>
          <img
            className={styles.image}
            src={course.image}
            alt={course.imageAlt}
          />

          <div className={styles.content}>
            <h3 className={styles.title}>
              {course.title}
            </h3>

            <p className={styles.description}>
              {course.description}
            </p>

            <div className={styles.meta}>
              <span>{levelLabels[course.level]}</span>
              <span>{course.lessonsCount} уроків</span>
            </div>

            <Link
              className={styles.link}
              href={course.href}
            >
              Переглянути курс
            </Link>
          </div>
        </article>
      );
    }

### 16.3. Сторінка зі списком карток

`page.tsx`:

    import CourseCard from "./CourseCard";
    import { courses } from "./data";
    import styles from "./CourseCard.module.css";

    export default function CoursesPage() {
      return (
        <main>
          <h1>Навчальні курси</h1>

          <div className={styles.grid}>
            {courses.map((course) => (
              <CourseCard
                key={course.id}
                course={course}
              />
            ))}
          </div>
        </main>
      );
    }

### 16.4. Що тут важливо

- Дані відокремлені від представлення.
- Тип `Course` описує структуру даних.
- `CourseCard` відповідає за одну картку.
- `map()` створює колекцію карток.
- `key` дозволяє React правильно ідентифікувати елементи списку.
- CSS Modules допомагають ізолювати стилі компонента.
- `Link` у Next.js використовується для внутрішньої навігації.

У навчальному проєкті зручно починати зі статичних даних, а пізніше отримувати їх із API або бази даних.

### 16.5. Коли потрібен Client Component?

Для звичайного відображення даних картці зазвичай не потрібен `"use client"`.

Client Component може знадобитися, якщо картка має власний інтерактивний стан, наприклад:

- перемикач обраного;
- розгортання додаткової інформації;
- локальне керування вкладками;
- взаємодію з браузерними API.

Не додавай `"use client"` автоматично до кожного компонента.

## 17. Типові помилки під час створення карток

### Помилка 1. Занадто багато інформації

Картка перетворюється на маленьку сторінку з багатьма заголовками, описами та кнопками.

**Рішення:** залиш головну інформацію, необхідні метадані й одну основну дію. Додаткові деталі перенеси на сторінку об'єкта.

### Помилка 2. Усі картки мають однаковий дизайн незалежно від завдання

Картка статистики, профілю та статті не обов'язково повинні мати однакову структуру.

**Рішення:** використовуй спільні дизайн-токени та правила, але дозволяй компонентам мати різний склад.

### Помилка 3. Надмірні тіні та заокруглення

Кожна картка виглядає як плаваюче вікно.

**Рішення:** спробуй межу, відмінність фону або відступи замість тіні.

### Помилка 4. Непередбачувана висота

Довгі заголовки роблять картки значно вищими за сусідні.

**Рішення:** перевіряй довгі назви, вирівнюй потрібні елементи через Flexbox або Grid і не обрізай текст без потреби.

### Помилка 5. Картка клікабельна, але це не очевидно

Користувач не розуміє, чи можна натиснути на блок.

**Рішення:** додай зрозуміле посилання, кнопку, помітний стан наведення та клавіатурний фокус.

### Помилка 6. Уся картка зроблена кнопкою

Картка має заголовок, опис, кілька посилань і кнопок, але весь блок реалізований як одна кнопка.

**Рішення:** вибирай семантичний контейнер, а кожній дії надавай відповідний інтерактивний елемент.

### Помилка 7. Зображення деформуються

Картки мають зображення різних пропорцій, через що сітка виглядає нерівномірно.

**Рішення:** задай контейнеру `aspect-ratio`, а зображенню — `width`, `height` та відповідний `object-fit`.

### Помилка 8. Не перевірено мобільну версію

На смартфоні картки стають надто вузькими або текст виходить за межі.

**Рішення:** перевіряй адаптивну сітку, довгі слова, кнопки, масштабування тексту й горизонтальне переповнення.

### Помилка 9. Занадто слабкий контраст

Вторинний текст практично не читається.

**Рішення:** перевіряй контраст тексту й фону, а не орієнтуйся лише на візуальне враження.

### Помилка 10. Повторюється однакова розмітка

Кожну картку написано окремо, хоча вони відрізняються лише даними.

**Рішення:** у React винеси повторювану структуру в компонент і передавай дані через props.

## 18. Практичний мініпроєкт — Course Cards

**Мета:** створити адаптивний каталог навчальних курсів.

### Етап 1. Дані

Підготуй щонайменше чотири курси з такими полями:

- `id`;
- `title`;
- `description`;
- `level`;
- `lessonsCount`;
- `image`;
- `href`.

### Етап 2. HTML

Створи одну семантичну картку, яка містить:

- зображення;
- заголовок;
- короткий опис;
- рівень;
- кількість уроків;
- посилання.

### Етап 3. CSS

Додай:

- внутрішні відступи;
- межу та заокруглення;
- однакову пропорцію зображень;
- зрозумілу типографіку;
- адаптивну сітку;
- стан `focus-visible`.

### Етап 4. Повторення

Створи кілька карток з однаковою структурою, але різними даними.

### Етап 5. React

Перенеси картку в компонент `CourseCard`.

Використай типізовані props і метод `map()` для відображення колекції.

### Етап 6. Адаптивність

Перевір:

- три колонки на широкому екрані;
- дві колонки на середньому;
- одну колонку на вузькому екрані.

Це початкові орієнтири — підлаштуй сітку під реальний вміст.

### Етап 7. Перевірка доступності

Переконайся, що:

- посилання доступні з клавіатури;
- фокус добре помітний;
- заголовки мають правильну ієрархію;
- зображення мають відповідний `alt`;
- текст читається без збільшення контрасту вручну користувачем;
- інформація не передається лише кольором.

### Етап 8. Розширення

Після базової версії додай:

- бейдж «Новий курс»;
- індикатор прогресу;
- кнопку «Додати до обраного»;
- фільтр за рівнем;
- сторінку детального перегляду курсу.

Додавай функції поступово, щоб кожен новий елемент мав зрозуміле призначення.

## 19. Чекліст перевірки картки

- [ ] Зрозуміло, що саме представляє картка.
- [ ] Головна інформація помітна.
- [ ] Опис достатньо короткий.
- [ ] Метадані не перевантажують блок.
- [ ] Основна дія має зрозумілу назву.

### Візуальний дизайн

- [ ] Заголовок і опис мають чітку ієрархію.
- [ ] Відступи послідовні.
- [ ] Зображення не деформовані.
- [ ] Межі, фон і тіні не перевантажують дизайн.
- [ ] Контраст достатній.
- [ ] Картка відповідає загальній дизайн-системі.

- [ ] Довгі заголовки не ламають композицію.
- [ ] Кнопки й посилання не виходять за межі.
- [ ] Немає небажаного горизонтального прокручування.
- [ ] Збільшення тексту не приховує важливу інформацію.

### Доступність

- [ ] Використано семантичний HTML.
- [ ] Посилання й кнопки мають відповідні ролі.
- [ ] Інтерактивні елементи доступні з клавіатури.

- [ ] Зображення мають правильний альтернативний текст.

- [ ] Повторювані стилі винесено в класи або змінні.
- [ ] Компонент можна повторно використовувати.
- [ ] Дані відокремлені від розмітки, коли це доцільно.

## 20. Що потрібно запам'ятати

✔ Картка групує пов'язану інформацію в окремий змістовий блок.

✔ Основні типи: інформаційна, зображення, товар, стаття, профіль, статистика, інтерактивна та горизонтальна картка.

✔ Візуальна ієрархія допомагає користувачу швидко знайти головну інформацію.

✔ Для колекцій карток часто використовують CSS Grid.

✔ Для внутрішньої композиції картки часто зручний Flexbox.

✔ Адаптивність потрібно перевіряти на реальному вмісті, а не лише на порожніх блоках.

✔ Інтерактивні картки повинні мати зрозумілі стани наведення, фокусу й вибору.

✔ Посилання призначене для навігації, а кнопка — для дії.

✔ Не потрібно робити всю картку клікабельною, якщо в ній є кілька незалежних дій.

✔ У React повторювані картки варто винести в компоненти.

✔ У Next.js статичному компоненту картки зазвичай не потрібен `"use client"`.

✔ Доступність, читабельність і зрозуміла поведінка — частина дизайну, а не додаткове оформлення.

## 22. Рівні опанування

### Початковий рівень

Ти вмієш:

- створювати картку за допомогою HTML;
- стилізувати її за допомогою CSS;
- налаштовувати фон, межі, відступи та типографіку;
- використовувати зображення й посилання;
- створювати сітку з кількох карток;
- адаптувати компонування для мобільного екрана.

### Середній рівень

Ти вмієш:

- створювати різні типи карток;
- будувати дизайн із повторюваних компонентів;
- використовувати CSS Grid і Flexbox;
- реалізовувати інтерактивні стани;
- перевіряти контраст і доступність;
- обробляти довгі заголовки й різну кількість контенту;
- створювати типізований `Card`-компонент у React.

### Просунутий рівень

Ти вмієш:

- розробляти систему повторно використовуваних карток;
- підтримувати різні варіанти компонента без дублювання коду;
- узгоджувати картки з дизайн-токенами;
- проєктувати адаптивні композиції для складних каталогів;
- враховувати завантаження, помилки, порожні стани та вибір;
- створювати доступні компоненти з передбачуваною поведінкою;
- інтегрувати картки з API, авторизацією та даними бази;
- оцінювати, коли картка доречна, а коли кращим рішенням буде звичайний список.

Картки поєднують багато раніше вивчених тем:

- **Layout and Composition** — сітки, вирівнювання, відступи та баланс.
- **Color** — фони, акценти й контраст.
- **Typography** — заголовки, описи та метадані.
- **Spacing** — внутрішні й зовнішні відступи.
- **Buttons** — дії всередині картки.
- **Badges** — категорії та статуси.
- **Responsive Design** — адаптивна поведінка.
- **Accessibility** — семантика, фокус і клавіатурна навігація.
- **React** — повторно використовувані компоненти.
- **TypeScript** — типізовані дані та props.

**Практичний висновок:** картка — це невелика модель реального об'єкта у твоєму інтерфейсі. Навчившись створювати якісні картки, ти зможеш будувати каталоги, блоги, навчальні платформи, інформаційні панелі та багато інших застосунків із повторно використовуваних компонентів.
