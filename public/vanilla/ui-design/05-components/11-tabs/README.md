# 11. Tabs — Вкладки інтерфейсу

Вкладки (Tabs) — це UI-компонент, який дозволяє перемикатися між кількома пов'язаними наборами вмісту в межах однієї сторінки або області інтерфейсу.

Вкладки допомагають організувати інформацію за категоріями, не показуючи весь вміст одночасно. Користувач вибирає потрібну вкладку й бачить відповідний розділ.

**Головна ідея:** вкладки групують альтернативні представлення пов'язаного вмісту, допомагаючи зменшити візуальне перевантаження інтерфейсу.

---

## 1. Для чого потрібні вкладки

Вкладки використовують, коли потрібно:

- ✔ Розділити пов'язаний вміст на логічні групи.
- ✔ Перемикатися між альтернативними представленнями одного об'єкта.
- ✔ Зменшити довжину сторінки.
- ✔ Організувати налаштування за категоріями.
- ✔ Розділити інформацію про товар, курс або профіль.
- ✔ Перемикатися між різними наборами даних.
- ✔ Зберегти компактний інтерфейс без втрати доступу до інформації.

Приклади застосування:

- сторінка курсу — «Опис», «Програма», «Матеріали», «Відгуки»;
- профіль користувача — «Особиста інформація», «Безпека», «Сповіщення»;
- сторінка товару — «Характеристики», «Опис», «Відгуки»;
- адміністративна панель — «Усі користувачі», «Активні», «Заблоковані»;
- редактор — «Візуальний режим», «Код», «Попередній перегляд»;
- навчальний застосунок — «Уроки», «Завдання», «Результати».

---

## 2. Анатомія вкладок

Типовий компонент складається з двох основних частин:

1. **Tab List** — область із кнопками вкладок.
2. **Tab Panel** — область із вмістом активної вкладки.

    ┌────────────────────────────────────────────────┐
    │ Опис       Програма       Матеріали     Відгуки │
    ├────────────────────────────────────────────────┤
    │                                                │
    │                Вміст вкладки                   │
    │                                                │
    │     Тут відображається інформація              │
    │     відповідно до вибраної вкладки.            │
    │                                                │
    └────────────────────────────────────────────────┘

### Основні елементи

- **Tab List** — контейнер для набору вкладок.
- **Tab** — окрема кнопка перемикання.
- **Active Tab** — поточна вибрана вкладка.
- **Inactive Tab** — вкладка, яку не вибрано.
- **Tab Panel** — область відповідного вмісту.
- **Focus Indicator** — візуальний індикатор клавіатурного фокусу.
- **Disabled Tab** — вкладка, яка тимчасово недоступна, якщо це передбачено логікою інтерфейсу.

### Що потрібно пам'ятати

Вкладка — це не просто кнопка з іншим кольором. Вона пов'язана з конкретною областю вмісту та повинна мати зрозумілий стан вибору.

---

## 3. Коли варто використовувати вкладки

Вкладки доречні, якщо:

- вміст має спільний контекст;
- секції є альтернативними представленнями одного об'єкта;
- користувачеві потрібно швидко перемикатися між секціями;
- немає потреби показувати весь вміст одночасно;
- кількість вкладок дозволяє розмістити їх без надмірного ускладнення.

Наприклад, на сторінці одного курсу вкладки «Опис», «Програма» та «Матеріали» мають спільний контекст — конкретний курс.

### Коли вкладки можуть бути невдалим рішенням

Не використовуй вкладки автоматично для будь-якої групи посилань.

Вони можуть бути недоречними, якщо:

- розділи є самостійними сторінками;
- користувачеві потрібно бачити весь вміст одночасно;
- важливо порівнювати кілька секцій одночасно;
- назви вкладок надто довгі;
- вкладок настільки багато, що їх важко переглядати;
- прихований вміст містить інформацію, яку користувач повинен помітити відразу.

**Правило:** якщо користувач переходить між різними сторінками сайту, часто краще використовувати навігаційні посилання. Якщо він перемикає пов'язані представлення в одній області — вкладки можуть бути доречними.

---

## 4. Основні типи вкладок

### 4.1. Horizontal Tabs — горизонтальні вкладки

Найпоширеніший тип.

    ┌───────────┬────────────┬─────────────┐
    │ Опис      │ Програма   │ Матеріали   │
    └───────────┴────────────┴─────────────┘

Вкладки розташовані в одному горизонтальному ряду.

Підходять для:

- сторінок курсів;
- карток товарів;
- профілів;
- налаштувань;
- інформаційних панелей.

### 4.2. Vertical Tabs — вертикальні вкладки

Вкладки розташовуються вертикально поруч із панеллю вмісту.

    ┌─────────────────┬──────────────────────────┐
    │ Загальні        │                          │
    │ Безпека         │     Вміст активної       │
    │ Сповіщення      │     вкладки              │
    │ Приватність     │                          │
    └─────────────────┴──────────────────────────┘

Підходять для:

- великих форм налаштувань;
- адміністративних інтерфейсів;
- панелей керування;
- розділів із довшими назвами.

На вузьких екранах вертикальні вкладки можуть вимагати іншого компонування.

### 4.3. Tabs with Icons — вкладки з іконками

Можуть містити іконку та текст.

    [▣ Огляд]  [▤ Матеріали]  [⚙ Налаштування]

Іконки допомагають швидше розпізнавати категорії, але не повинні ускладнювати сприйняття.

Якщо іконка лише декоративна, вона не повинна дублюватися в доступній назві елемента.

### 4.4. Scrollable Tabs — вкладки з горизонтальним прокручуванням

Використовуються, коли вкладок більше, ніж може поміститися в доступній ширині.

Можуть бути доречними на мобільних екранах.

Важливо:

- користувач повинен розуміти, що список можна прокручувати;
- активна вкладка має залишатися видимою;
- прокручування не повинно заважати доступності;
- не приховуй важливі вкладки без зрозумілого способу їх знайти.

### 4.5. Segmented Control — сегментований перемикач

Візуально може нагадувати вкладки, але часто використовується для вибору одного режиму або значення.

Приклад:

    [ День ] [ Тиждень ] [ Місяць ]

Використовується для:

- вибору періоду;
- перемикання режиму відображення;
- вибору одиниць вимірювання;
- перемикання між альтернативними станами.

Сегментований перемикач не завжди має ту саму семантику, що й набір вкладок. Потрібно обирати HTML-структуру відповідно до поведінки компонента.

---

## 5. Вкладки та навігація — у чому різниця

Вкладки й навігаційні посилання можуть виглядати схоже, але виконують різні завдання.

| Ознака | Вкладки | Навігаційні посилання |
|---|---|---|
| Основна мета | Перемикання пов'язаного вмісту | Перехід до сторінки або ресурсу |
| Типовий елемент | Кнопка | Посилання |
| Контекст | Одна область інтерфейсу | Навігація між маршрутами |
| URL | Не обов'язково змінюється | Зазвичай змінюється |
| Стан | Вибрана вкладка | Поточна сторінка або маршрут |
| Приклад | Опис / Програма / Відгуки | Головна / Курси / Контакти |

У деяких застосунках вкладки синхронізуються з URL або маршрутом. Це допустимо, якщо така поведінка спроєктована послідовно.

Не варто робити звичайні навігаційні посилання вкладками лише через схожий зовнішній вигляд.

---

## 6. Візуальна ієрархія вкладок

Користувач повинен швидко визначати:

- які вкладки доступні;
- яка вкладка активна;
- де розташований вміст;
- на яку вкладку наведено вказівник;
- який елемент отримав клавіатурний фокус.

### 6.1. Активна вкладка

Активну вкладку можна виділяти за допомогою:

- контрастного кольору тексту;
- нижньої межі;
- зміни товщини шрифту;
- фонового кольору;
- видимого індикатора вибору.

Приклад:

    .tab[aria-selected="true"] {
      color: var(--color-accent);
      border-bottom: 3px solid var(--color-accent);
      font-weight: 700;
    }

### 6.2. Неактивна вкладка

Неактивні вкладки повинні залишатися читабельними й виглядати доступними для взаємодії.

Не роби їх надто блідими лише для того, щоб активна вкладка виглядала помітніше.

### 6.3. Hover

Стан наведення показує, що вкладка реагує на вказівник.

    .tab:hover {
      background: var(--color-hover);
    }

Hover не повинен бути єдиним способом зрозуміти, що елемент інтерактивний.

### 6.4. Focus

Клавіатурний фокус повинен бути помітним.

    .tab:focus-visible {
      outline: 3px solid var(--color-accent);
      outline-offset: 2px;
    }

Фокус і вибір — різні стани. Користувач може переміщати фокус між вкладками, не змінюючи вибрану вкладку, якщо реалізована модель ручної активації.

---

## 7. Розміри та відступи

Вкладки повинні мати достатню область для натискання й читабельні підписи.

Орієнтовні значення:

- 8 px — між іконкою та коротким підписом;
- 12–16 px — внутрішні горизонтальні відступи;
- 8–12 px — внутрішні вертикальні відступи;
- 16–24 px — відстань між групами компонентів.

Це орієнтири, а не жорсткі правила.

Приклад:

    .tab {
      display: inline-flex;
      align-items: center;
      justify-content: center;
      gap: 0.5rem;
      padding: 0.75rem 1rem;
      border: 0;
      background: transparent;
      font: inherit;
      cursor: pointer;
    }

Не роби вкладки надто компактними, особливо якщо вони використовуються на сенсорних екранах.

---

## 8. Колір і контраст

Колір допомагає відрізняти активний стан від неактивного.

Приклад CSS-змінних:

    :root {
      --color-page: #f5f7fa;
      --color-surface: #ffffff;
      --color-text: #202938;
      --color-muted: #64748b;
      --color-border: #dbe2ea;
      --color-accent: #2563eb;
      --color-hover: #eef2ff;
    }

    .tabs {
      border-bottom: 1px solid var(--color-border);
    }

    .tab {
      color: var(--color-text);
    }

    .tab[aria-selected="true"] {
      color: var(--color-accent);
      border-bottom: 3px solid var(--color-accent);
    }

Це приклад палітри, а не універсальний стандарт.

### Контраст

Для звичайного тексту WCAG рекомендує контраст не менше `4.5:1`, для великого тексту — не менше `3:1`.

Перевіряй:

- текст активної вкладки;
- текст неактивних вкладок;
- колір індикатора вибору;
- фон при наведенні;
- індикатор клавіатурного фокусу.

Не позначай активну вкладку лише кольором. Додатковий індикатор, наприклад нижня межа, допомагає краще розрізняти стани.

---

## 9. Типографіка вкладок

Назви вкладок повинні бути короткими й зрозумілими.

Приклади:

- Опис;
- Програма;
- Матеріали;
- Відгуки;
- Налаштування;
- Безпека.

Рекомендації:

- використовуй однаковий стиль написання;
- уникай довгих речень;
- не зменшуй шрифт надмірно заради розміщення;
- перевіряй довгі переклади;
- не допускай випадкового обрізання важливих назв.

Приклад:

    .tab {
      font-size: 1rem;
      line-height: 1.4;
      font-weight: 500;
    }

    .tab[aria-selected="true"] {
      font-weight: 700;
    }

Якщо назви довгі, розглянь вертикальні вкладки, горизонтальне прокручування або іншу структуру інтерфейсу.

---

## 10. Розташування вкладок і панелі вмісту

Типовий компонент має вкладки зверху та панель вмісту знизу.

    .tabs {
      display: flex;
      flex-direction: column;
    }

    .tab-list {
      display: flex;
      flex-wrap: wrap;
      gap: 0.25rem;
      border-bottom: 1px solid var(--color-border);
    }

    .tab-panel {
      padding-block: 1.5rem;
    }

Для вертикального компонування:

    .tabs--vertical {
      display: grid;
      grid-template-columns: 12rem minmax(0, 1fr);
      gap: 1.5rem;
    }

    .tabs--vertical .tab-list {
      flex-direction: column;
      align-items: stretch;
      border-right: 1px solid var(--color-border);
      border-bottom: 0;
    }

    .tabs--vertical .tab {
      justify-content: flex-start;
    }

У вертикальному варіанті потрібно змінити індикатор активної вкладки відповідно до напрямку компонування, наприклад використати ліву межу замість нижньої.

---

## 11. Адаптивність вкладок

Вкладки повинні залишатися зрозумілими на різних розмірах екрана.

### На великому екрані

- усі назви можуть поміщатися в одному рядку;
- доступні ширші проміжки;
- панель вмісту має достатньо простору.

### На планшеті

- може знадобитися зменшення відступів;
- довгі назви можуть вимагати додаткового місця;
- вертикальне компонування іноді стає зручнішим.

### На смартфоні

Можливі варіанти:

- горизонтальне прокручування;
- перенесення вкладок на новий рядок;
- компактніші відступи;
- перехід до іншого компонента, якщо вкладок забагато.

Приклад CSS:

    .tab-list {
      display: flex;
      gap: 0.25rem;
      overflow-x: auto;
      overscroll-behavior-inline: contain;
    }

    .tab {
      flex: 0 0 auto;
      white-space: nowrap;
    }

Цей варіант дозволяє прокручувати вкладки горизонтально, коли вони не поміщаються.

Потрібно перевірити, чи зрозуміло користувачеві, що є додаткові вкладки, та чи залишається активна вкладка видимою.

Не приховуй важливі вкладки без доступного способу до них дістатися.

---

## 12. Поведінка вкладок

Вкладки можуть мати різні моделі активації.

### 12.1. Automatic Activation — автоматична активація

Коли користувач переміщує клавіатурний фокус між вкладками, відповідна вкладка одразу активується.

Переваги:

- швидке перемикання;
- зручність, якщо вміст завантажується миттєво;
- проста взаємодія для невеликого набору вкладок.

Недоліки:

- переміщення фокусу може запускати завантаження;
- перемикання може бути незручним, якщо панель завантажується повільно.

### 12.2. Manual Activation — ручна активація

Користувач переміщує фокус між вкладками, але активує вибрану окремою дією, зазвичай клавішею `Enter` або `Space`.

Переваги:

- зручно, коли вміст завантажується повільно;
- можна переглянути назви вкладок без постійного перемикання вмісту.

Недоліки:

- потрібно реалізувати окрему логіку фокусу та активації.

### Як вибрати

Якщо всі панелі доступні локально й перемикаються миттєво, автоматична активація часто підходить.

Якщо перемикання запускає повільне завантаження або складні запити, розглянь ручну активацію.

---

## 13. Доступність вкладок

Вкладки — це інтерактивний компонент зі специфічною клавіатурною поведінкою.

Для доступної реалізації потрібно:

- використовувати правильні семантичні ролі;
- пов'язувати вкладку з відповідною панеллю;
- повідомляти, яка вкладка активна;
- підтримувати клавіатурну навігацію;
- забезпечувати видимий фокус;
- не приховувати інформацію від допоміжних технологій неправильно.

### 13.1. Основні ARIA-атрибути

- `role="tablist"` — контейнер вкладок;
- `role="tab"` — окрема вкладка;
- `role="tabpanel"` — панель вмісту;
- `aria-selected` — стан вибору;
- `aria-controls` — зв'язок вкладки з панеллю;
- `aria-labelledby` — зв'язок панелі з назвою вкладки;
- `tabindex` — керування включенням елемента в послідовність клавіатурного фокусу.

### 13.2. Клавіатурна взаємодія

У типовому горизонтальному компоненті вкладок:

- `Tab` — переходить до набору вкладок або виходить із нього;
- `ArrowRight` — переміщує фокус до наступної вкладки;
- `ArrowLeft` — переміщує фокус до попередньої вкладки;
- `Home` — переходить до першої вкладки;
- `End` — переходить до останньої вкладки.

Для вертикальних вкладок зазвичай використовують `ArrowUp` та `ArrowDown`.

Якщо застосовується ручна активація, `Enter` або `Space` активують вкладку, на якій перебуває фокус.

Необхідно враховувати напрямок компонента та коректно реалізувати переміщення фокусу.

### 13.3. Зв'язок вкладки з панеллю

Кожна вкладка повинна вказувати на відповідну панель через `aria-controls`.

Панель, своєю чергою, може використовувати `aria-labelledby`, щоб отримати назву від відповідної вкладки.

### JavaScript

    "use strict";

    const tabLists = document.querySelectorAll(
      '[role="tablist"]'
    );

    tabLists.forEach((tabList) => {
      const tabs = Array.from(
        tabList.querySelectorAll('[role="tab"]')
      );

      function activateTab(selectedTab) {
        tabs.forEach((tab) => {
          const isSelected = tab === selectedTab;
          const panelId = tab.getAttribute("aria-controls");
          const panel = panelId
            ? document.getElementById(panelId)
            : null;

          tab.setAttribute(
            "aria-selected",
            String(isSelected)
          );

          tab.tabIndex = isSelected ? 0 : -1;

          if (panel) {
            panel.hidden = !isSelected;
          }
        });
      }

      tabs.forEach((tab, index) => {
        tab.addEventListener("click", () => {
          activateTab(tab);
        });

        tab.addEventListener("keydown", (event) => {
          let nextIndex = index;

          if (event.key === "ArrowRight") {
            nextIndex = (index + 1) % tabs.length;
          } else if (event.key === "ArrowLeft") {
            nextIndex =
              (index - 1 + tabs.length) % tabs.length;
          } else if (event.key === "Home") {
            nextIndex = 0;
          } else if (event.key === "End") {
            nextIndex = tabs.length - 1;
          } else {
            return;
          }

          event.preventDefault();

          const nextTab = tabs[nextIndex];

          nextTab.focus();
          activateTab(nextTab);
        });
      });
    });

У цьому прикладі:

- кнопки мають роль `tab`;
- контейнер має роль `tablist`;
- кожна вкладка пов'язана з відповідною панеллю;
- `aria-selected` відображає стан вибору;
- `hidden` приховує неактивні панелі;
- стрілки переміщують фокус і активують вкладку;
- `Home` та `End` переміщують фокус до першої або останньої вкладки.

Це базовий приклад для навчання. У production-компоненті потрібно додатково перевірити поведінку в різних браузерах, напрямок письма, наявність вимкнених вкладок і сценарії динамічної зміни набору вкладок.

## 15. Вкладки в React і Next.js

У React вкладки зручно реалізувати як повторно використовуваний компонент зі станом.

Приклад структури:

    src/
    └── app/
        └── courses/
            ├── page.tsx
            ├── CourseTabs.tsx
            └── CourseTabs.module.css

### 15.1. Типізація вкладок

    export type TabItem = {
      id: string;
      label: string;
      content: string;
    };

Це проста модель для текстового вмісту.

Якщо різні вкладки повинні містити складні компоненти, замість `content: string` можна використати відповідну структуру React-вузлів або визначити вміст безпосередньо в JSX.

### 15.2. Компонент CourseTabs

    "use client";

    import { useState } from "react";

    const tabs = [
      {
        id: "description",
        label: "Опис",
        content: "Інформація про курс і його цілі.",
      },
      {
        id: "program",
        label: "Програма",
        content: "Перелік тем і навчальних модулів.",
      },
      {
        id: "materials",
        label: "Матеріали",
        content: "Конспекти, приклади коду та завдання.",
      },
    ];

    export default function CourseTabs() {
      const [activeTab, setActiveTab] = useState(
        tabs[0].id
      );

      const selectedTab = tabs.find(
        (tab) => tab.id === activeTab
      );

      return (
        <div>
          <div
            role="tablist"
            aria-label="Інформація про курс"
          >
            {tabs.map((tab) => {
              const isSelected = tab.id === activeTab;

              return (
                <button
                  key={tab.id}
                  id={`tab-${tab.id}`}
                  type="button"
                  role="tab"
                  aria-selected={isSelected}
                  aria-controls={`panel-${tab.id}`}
                  onClick={() => setActiveTab(tab.id)}
                >
                  {tab.label}
                </button>
              );
            })}
          </div>

          {tabs.map((tab) => {
            const isSelected = tab.id === activeTab;

            return (
              <section
                key={tab.id}
                id={`panel-${tab.id}`}
                role="tabpanel"
                aria-labelledby={`tab-${tab.id}`}
                hidden={!isSelected}
                tabIndex={0}
              >
                <p>{tab.content}</p>
              </section>
            );
          })}
        </div>
      );
    }

У цьому прикладі `useState` керує активною вкладкою, а `hidden` визначає, яка панель видима.

Змінна `selectedTab` тут не використовується в розмітці й може бути видалена. У реальному компоненті її можна застосувати, якщо потрібно відображати лише одну панель замість усіх панелей із `hidden`.

**Важливо:** цей приклад показує перемикання натисканням, але ще не реалізує повну клавіатурну поведінку вкладок зі стрілками, `Home`, `End` і керуванням `tabIndex`. Для повноцінного доступного компонента ці можливості потрібно додати.

### 15.3. Вкладки зі складним вмістом

Якщо кожна вкладка містить різні компоненти, зручно зберігати в масиві ідентифікатор і назву, а JSX панелей організувати окремо.

Наприклад:

    {activeTab === "description" && (
      <DescriptionPanel />
    )}

    {activeTab === "program" && (
      <ProgramPanel />
    )}

    {activeTab === "materials" && (
      <MaterialsPanel />
    )}

Цей підхід дозволяє не завантажувати або не монтувати неактивні панелі, якщо це відповідає вимогам застосунку.

Однак потрібно враховувати, що демонтування панелі може скидати її локальний стан. Якщо користувач повинен зберігати введені дані при перемиканні, продумай збереження стану.

### 15.4. Чи потрібен `"use client"`?

Якщо вкладки перемикаються на клієнті за допомогою `useState`, у Next.js App Router компонент повинен бути Client Component.

Якщо ж це звичайні посилання на різні сторінки, стан вкладок не потрібен — використовуй `Link` або інші відповідні механізми маршрутизації.

Не додавай `"use client"` автоматично до всіх компонентів, які візуально нагадують вкладки.

## 16. Типові помилки під час створення вкладок

### Помилка 1. Вкладки використовуються замість навігації

Елементи ведуть на незалежні сторінки, але реалізовані як вкладки без відповідної логіки.

**Рішення:** якщо головне завдання — перейти на іншу сторінку, використовуй посилання. Вкладки призначені для перемикання пов'язаного вмісту.

### Помилка 2. Активна вкладка не відрізняється

Користувач не розуміє, який вміст зараз відкритий.

**Рішення:** використовуй зрозумілий індикатор активного стану та `aria-selected` для справжніх вкладок.

### Помилка 3. Змінюється лише зовнішній вигляд

Після натискання вкладка стає іншого кольору, але вміст не змінюється.

**Рішення:** синхронізуй стан вкладки зі станом панелі.

### Помилка 4. Неправильні зв'язки між вкладками й панелями

Кілька вкладок керують однією панеллю або `aria-controls` вказує на неправильний елемент.

**Рішення:** використовуй стабільні унікальні ідентифікатори та перевіряй відповідність кожної вкладки своїй панелі.

### Помилка 5. Немає клавіатурної навігації

Користувач повинен натискати `Tab` для переходу до кожної вкладки, хоча компонент реалізований як справжній `tablist`.

**Рішення:** реалізуй передбачену модель фокусу та активації, включно зі стрілками й переходами до першої та останньої вкладок.

### Помилка 6. Фокус не видно

Користувач клавіатури не розуміє, де перебуває фокус.

**Рішення:** додай виразний `:focus-visible`.

### Помилка 7. Надто багато вкладок

Підписи не поміщаються, а користувачеві складно знайти потрібну секцію.

**Рішення:** скороти назви, згрупуй вміст або вибери інший компонент.

### Помилка 8. На мобільному екрані вкладки обрізаються

Частина вкладок недоступна або немає очевидного способу прокручування.

**Рішення:** перевіряй адаптивну поведінку, горизонтальне прокручування та видимість активної вкладки.

### Помилка 9. Усі панелі одночасно присутні на екрані

Компонент виглядає як вкладки, але вміст усіх секцій відображається одночасно.

**Рішення:** визначай, чи це справді вкладки, чи звичайна сторінка з розділами. Приховуй неактивні панелі, якщо застосовуєш модель вкладок.

### Помилка 10. При перемиканні губляться дані

Користувач заповнив форму в одній вкладці, перейшов до іншої й утратив введені значення.

**Рішення:** зберігай стан форми в потрібному місці або не демонтуй панель без необхідності.

### Помилка 11. Зловживання іконками

Кожна вкладка має іконку, яка не допомагає зрозуміти її призначення.

**Рішення:** використовуй іконки лише там, де вони підвищують зрозумілість.

### Помилка 12. ARIA-атрибути не відповідають поведінці

Наприклад, `aria-selected="true"` залишається на старій вкладці після перемикання.

**Рішення:** стан, видимість панелі, фокус і доступні атрибути повинні узгоджуватися.

- [ ] Вкладки мають правильні `aria-selected`.
- [ ] Зв'язки `aria-controls` і `aria-labelledby` правильні.
- [ ] Фокус помітний.
- [ ] Клавіатурна навігація реалізована.
- [ ] Модель активації відповідає поведінці компонента.
- [ ] Приховані панелі не створюють проблем для допоміжних технологій.

### Код

- [ ] Стан активної вкладки має одне джерело істини.
- [ ] Панелі синхронізовані зі станом.
- [ ] Ідентифікатори вкладок унікальні.
- [ ] React-компонент не дублює зайву логіку.

## 19. Що потрібно запам'ятати

✔ Вкладки перемикають пов'язаний вміст у межах однієї області інтерфейсу.

✔ Типова структура складається з `tablist`, `tab` і `tabpanel`.

✔ Вкладки не завжди є заміною звичайним навігаційним посиланням.

✔ Активний стан повинен бути помітним і синхронізованим із вмістом.

✔ Для справжнього компонента вкладок важливі `aria-selected`, `aria-controls` та `aria-labelledby`.

✔ Клавіатурна навігація зазвичай включає стрілки, `Home` і `End`.

✔ Автоматична активація зручна для швидкого перемикання, а ручна може бути кращою для повільного вмісту.

✔ Неактивні панелі повинні бути приховані відповідно до обраної моделі компонента.

✔ Не варто створювати надто багато вкладок.

✔ Адаптивність потрібно перевіряти на реальному вмісті та вузьких екранах.

✔ У React `useState` може керувати активною вкладкою.

✔ Якщо вкладки містять складні компоненти, потрібно продумати збереження локального стану.

✔ У Next.js інтерактивні вкладки потребують Client Component, якщо їхній стан керується клієнтським React-кодом.

✔ Доступність вкладок залежить не лише від ARIA-атрибутів, а й від правильної клавіатурної поведінки.
