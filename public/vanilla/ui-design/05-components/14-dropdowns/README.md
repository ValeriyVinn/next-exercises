# 14. Dropdowns — Випадаючі списки та меню

Dropdown — це компонент інтерфейсу, який відкриває додатковий список опцій або команд після взаємодії з певним елементом.

Випадаючі компоненти допомагають економити простір інтерфейсу, показуючи додатковий вміст лише тоді, коли він потрібен користувачу.

Dropdown може використовуватися для вибору значення, відкриття меню навігації, виконання дій, зміни налаштувань або вибору одного з кількох варіантів.

Важливо розрізняти кілька компонентів, які зовні можуть бути схожими:

- **Dropdown menu** — меню з командами або діями.
- **Select** — поле для вибору одного або кількох значень.
- **Combobox** — поле введення з можливістю вибору зі списку.
- **Popover** — панель із додатковим вмістом.
- **Context menu** — контекстне меню, яке відкривається, наприклад, правою кнопкою миші.

---

## 1. Для чого потрібні Dropdowns

Випадаючі компоненти допомагають організувати інтерфейс, не показуючи всі можливості одночасно.

Приклади:

- меню профілю користувача;
- меню додаткових дій над записом;
- вибір мови;
- вибір сортування;
- меню навігації;
- вибір категорії;
- список команд редактора;
- контекстне меню таблиці;
- вибір фільтра;
- список варіантів у формі.

### Приклад: меню профілю

    [Профіль ▼]

    ┌─────────────────────┐
    │ Мій профіль          │
    │ Налаштування         │
    │ Допомога             │
    ├─────────────────────┤
    │ Вийти                │
    └─────────────────────┘

Користувач натискає кнопку профілю, після чого відкривається список доступних команд.

### Приклад: сортування

    Сортувати за: [Датою ▼]

    ┌──────────────────┐
    │ Датою            │
    │ Назвою           │
    │ Статусом         │
    └──────────────────┘

Після вибору потрібного пункту інтерфейс оновлює порядок відображення записів.

### Коли dropdown корисний

- коли є кілька пов'язаних команд;
- коли потрібно приховати другорядні дії;
- коли користувач повинен вибрати один варіант;
- коли потрібно компактно організувати навігацію;
- коли інтерфейс містить таблиці або панелі керування.

### Коли dropdown не потрібен

Якщо варіантів лише два або три й вони часто використовуються, іноді краще показати їх безпосередньо.

Наприклад, для перемикання між двома режимами може бути зручнішим segmented control.

**Правило:** приховуй у dropdown лише ті елементи, для яких це справді покращує інтерфейс.

## 2. Dropdown Menu, Select, Combobox та Popover

Ці компоненти можуть виглядати схоже, але мають різне призначення.

### 2.1. Dropdown Menu

Меню команд або дій.

Приклад:

    [Дії ▼]

    ┌────────────────────┐
    │ Редагувати          │
    │ Копіювати           │
    │ Архівувати          │
    │ Видалити            │
    └────────────────────┘

Користувач обирає команду, яка виконує певну дію.

Типові елементи:

- кнопка відкриття;
- список команд;
- розділювачі;
- групи команд;
- іконки;
- стани наведення та фокусу.

### 2.2. Select

Select призначений для вибору значення з набору опцій.

Приклад:

    Країна

    [Україна             ▼]

У HTML для простого вибору часто використовують нативний `<select>`.

    <label for="country">Країна</label>

    <select id="country" name="country">
      <option value="ua">Україна</option>
      <option value="pl">Польща</option>
      <option value="de">Німеччина</option>
    </select>

Нативний select зазвичай краще підходить для стандартних форм, якщо немає особливих вимог до дизайну або поведінки.

### 2.3. Combobox

Combobox поєднує поле введення зі списком доступних значень.

Приклад:

    Місто

    [Він...               ]

    ┌─────────────────────┐
    │ Вінниця             │
    │ Віньківці           │
    └─────────────────────┘

Користувач може вводити текст, а список опцій звужується відповідно до введених символів.

Combobox особливо корисний, коли список великий.

### 2.4. Popover

Popover — панель із додатковим вмістом, прив'язана до певного елемента.

Приклад:

    [Фільтри]

    ┌──────────────────────┐
    │ Статус               │
    │ [Активні        ▼]   │
    │                      │
    │ [Скинути] [Застос.]  │
    └──────────────────────┘

Popover може містити форму, перемикачі, кнопки або інші компоненти.

### Що запам'ятати

- Dropdown Menu — команди та дії.
- Select — вибір значення.
- Combobox — введення тексту та вибір зі списку.
- Popover — додаткова панель із вмістом.

Не створюй універсальний dropdown, який намагається замінити всі ці компоненти. Краще вибирати компонент відповідно до завдання.

## 3. Основні типи Dropdowns

### 3.1. Action Dropdown

Меню дій над елементом.

Приклад:

    [⋯]

    ┌───────────────────┐
    │ Редагувати        │
    │ Дублювати         │
    │ Архівувати        │
    │ Видалити          │
    └───────────────────┘

Використовується в таблицях, картках, списках і панелях керування.

### 3.2. Navigation Dropdown

Випадаюче меню навігації.

Приклад:

    Продукти ▼

    ┌─────────────────────┐
    │ Для навчання        │
    │ Для бізнесу         │
    │ Для розробників     │
    └─────────────────────┘

Потрібно перевіряти, чи доступне меню на клавіатурі та сенсорних пристроях.

### 3.3. Profile Dropdown

Меню профілю користувача.

Типові пункти:

- профіль;
- налаштування;
- сповіщення;
- допомога;
- вихід.

### 3.4. Filter Dropdown

Меню вибору фільтра.

Приклад:

    Статус: [Усі ▼]

    ┌─────────────────┐
    │ Усі             │
    │ Активні         │
    │ Завершені       │
    │ Архівні         │
    └─────────────────┘

Після вибору значення список даних може оновлюватися.

### 3.5. Sort Dropdown

Меню сортування.

Приклад:

    Сортування: [За датою ▼]

    Варіанти:
    - За датою
    - За назвою
    - За статусом

Важливо чітко показувати поточний вибір.

### 3.6. Nested Dropdown

Вкладене меню, яке відкриває підменю.

Приклад:

    [Експорт ▼]

    ┌────────────────────┐
    │ Експорт як...   ▶  │
    │ Друк               │
    └────────────────────┘

    ┌────────────────────┐
    │ PDF                │
    │ CSV                │
    │ JSON               │
    └────────────────────┘

Вкладені меню можуть бути складними для користувачів клавіатури та сенсорних пристроїв. Використовуй їх лише тоді, коли простіша структура не підходить.

### 3.7. Context Menu

Контекстне меню показує команди, пов'язані з конкретним елементом.

Наприклад, натискання правою кнопкою миші на запис може відкрити меню:

    Редагувати
    Копіювати
    Видалити

Не роби контекстне меню єдиним способом доступу до важливих команд. На сенсорних пристроях права кнопка миші відсутня, тому потрібен альтернативний шлях.

## 4. Анатомія Dropdown Menu

Типове меню складається з кількох частин.

    ┌────────────────────────┐
    │ Кнопка відкриття    ▼  │
    └────────────┬───────────┘
                 │
                 ▼
          ┌─────────────────┐
          │ Редагувати      │
          │ Копіювати       │
          │ Архівувати      │
          ├─────────────────┤
          │ Видалити        │
          └─────────────────┘

### 4.1. Trigger

Trigger — елемент, який відкриває меню.

Зазвичай це кнопка.

    <button type="button">
      Дії
    </button>

Кнопка повинна зрозуміло повідомляти, яке меню вона відкриває.

### 4.2. Menu container

Контейнер містить список команд.

Типові CSS-властивості:

- `position`;
- `min-width`;
- `padding`;
- `background`;
- `border`;
- `border-radius`;
- `box-shadow`;
- `z-index`.

### 4.3. Menu item

Окремий пункт меню.

Приклад:

    <button type="button" role="menuitem">
      Редагувати
    </button>

У повноцінному ARIA-меню потрібно також реалізувати відповідну клавіатурну поведінку. Для звичайного списку кнопок у простому popover роль `menuitem` може бути зайвою.

### 4.4. Divider

Розділювач відокремлює логічні групи команд.

    Редагувати
    Копіювати
    ─────────────
    Видалити

Не додавай розділювачі між кожним пунктом. Використовуй їх лише для групування.

### 4.5. Icon

Іконки можуть допомагати швидше розпізнавати команди.

Приклад:

    ✎  Редагувати
    ⧉  Копіювати
    🗑  Видалити

Іконки повинні бути послідовними за стилем, розміром і вирівнюванням.

### 4.6. Caret

Caret — індикатор того, що кнопка відкриває список.

Приклад:

    Категорія ▼

Стрілка допомагає розпізнати dropdown, але не замінює зрозумілу назву кнопки.

## 5. Принципи хорошого дизайну Dropdowns

### 5.1. Чітка ієрархія

Користувач повинен легко розрізняти:

1. кнопку відкриття;
2. список опцій;
3. окремі пункти;
4. групи команд;
5. небезпечні дії.

### 5.2. Зрозумілі назви

Погано:

    [Дії ▼]

    - Опція 1
    - Опція 2
    - Опція 3

Краще:

    [Дії ▼]

    - Редагувати
    - Дублювати
    - Архівувати

Назви повинні пояснювати результат дії.

### 5.3. Розмір пунктів

Пункти повинні мати достатню висоту для зручного натискання.

Наприклад:

    min-height: 40px;
    padding: 10px 12px;

Це орієнтир, а не універсальна вимога. На сенсорних пристроях може знадобитися більша область натискання.

### 5.4. Відступи

Приклад:

    padding: 8px;
    gap: 4px;

Внутрішні відступи допомагають розділяти пункти й зменшують ризик випадкового натискання.

### 5.5. Контраст

Текст пунктів має бути читабельним на фоні меню.

Не покладайся лише на колір для позначення активного або небезпечного стану.

### 5.6. Послідовність

Якщо меню повторюється в різних частинах застосунку, воно повинно мати однакові:

- відступи;
- типографіку;
- висоту пунктів;
- стилі фокусу;
- правила відкриття;
- правила закриття.

### 5.7. Відстань від trigger

Меню зазвичай розташовують близько до кнопки відкриття.

Приклад:

    margin-top: 8px;

Занадто велика відстань може створювати відчуття, що меню не пов'язане з кнопкою.

### 5.8. Розмір меню

Ширина повинна відповідати тексту та призначенню меню.

Приклад:

    min-width: 180px;
    max-width: 320px;

Не варто робити всі меню однакової ширини незалежно від їхнього вмісту.

## 6. Позиціювання Dropdown у CSS

Для простого меню можна використати `position: relative` на контейнері та `position: absolute` на списку.

### HTML

    <div class="dropdown">
      <button
        class="dropdown-trigger"
        type="button"
      >
        Дії
        <span aria-hidden="true">▾</span>
      </button>

      <div class="dropdown-menu">
        <button type="button" class="dropdown-item">
          Редагувати
        </button>

        <button type="button" class="dropdown-item">
          Копіювати
        </button>

        <button type="button" class="dropdown-item">
          Архівувати
        </button>
      </div>
    </div>

### CSS

    .dropdown {
      position: relative;
      display: inline-block;
    }

    .dropdown-trigger {
      display: inline-flex;
      align-items: center;
      gap: 8px;

      min-height: 40px;
      padding: 8px 12px;

      border: 1px solid #ccc;
      border-radius: 8px;

      background: #fff;
      color: #222;

      font: inherit;
      cursor: pointer;
    }

    .dropdown-menu {
      position: absolute;
      top: calc(100% + 8px);
      left: 0;
      z-index: 100;

      min-width: 180px;
      padding: 6px;

      border: 1px solid #ddd;
      border-radius: 10px;

      background: #fff;
      box-shadow: 0 8px 24px rgb(0 0 0 / 12%);
    }

    .dropdown-item {
      display: flex;
      align-items: center;

      width: 100%;
      min-height: 40px;
      padding: 10px 12px;

      border: 0;
      border-radius: 6px;

      background: transparent;
      color: #222;

      font: inherit;
      text-align: left;
      cursor: pointer;
    }

    .dropdown-item:hover {
      background: #f2f2f2;
    }

    .dropdown-item:focus-visible,
    .dropdown-trigger:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 2px;
    }

Це лише базовий візуальний каркас. Щоб меню працювало як справжній dropdown, потрібно додати логіку відкриття, закриття та клавіатурної взаємодії.

## 7. Відкриття та закриття Dropdown

Dropdown повинен мати передбачувану поведінку.

### Типовий сценарій

1. Користувач натискає кнопку.
2. Меню відкривається.
3. Користувач обирає пункт.
4. Виконується дія.
5. Меню закривається.

### Основні способи закриття

- повторне натискання на trigger;
- вибір пункту меню;
- натискання поза меню;
- натискання `Escape`;
- перехід до іншої дії, якщо цього вимагає сценарій.

### Чи потрібно відкривати меню при наведенні?

На настільних пристроях це іноді використовують для навігаційних меню.

Проте відкриття лише через hover має недоліки:

- не працює належним чином на сенсорних пристроях;
- може бути незручним для користувачів із тремором;
- меню може відкриватися випадково;
- складніше забезпечити передбачувану клавіатурну взаємодію.

Для більшості меню дій краще використовувати натискання кнопки.

### Чи потрібно закривати меню після вибору?

Зазвичай так, якщо вибір виконує команду або завершує взаємодію.

Однак для деяких меню налаштувань, де можна змінити кілька параметрів, поведінка може бути іншою.

## 8. HTML та JavaScript: функціональний Dropdown

Для простого dropdown menu можна використати звичайні кнопки та JavaScript.

### HTML

    <div class="dropdown">
      <button
        id="dropdown-trigger"
        type="button"
        aria-expanded="false"
        aria-controls="dropdown-menu"
      >
        Дії
        <span aria-hidden="true">▾</span>
      </button>

      <div
        id="dropdown-menu"
        class="dropdown-menu"
        hidden
      >
        <button type="button" class="dropdown-item">
          Редагувати
        </button>

        <button type="button" class="dropdown-item">
          Копіювати
        </button>

        <button type="button" class="dropdown-item">
          Архівувати
        </button>
      </div>
    </div>

### JavaScript

    const trigger = document.querySelector("#dropdown-trigger");
    const menu = document.querySelector("#dropdown-menu");

    if (
      trigger instanceof HTMLButtonElement &&
      menu instanceof HTMLDivElement
    ) {
      function openMenu() {
        menu.hidden = false;
        trigger.setAttribute("aria-expanded", "true");
      }

      function closeMenu() {
        menu.hidden = true;
        trigger.setAttribute("aria-expanded", "false");
      }

      trigger.addEventListener("click", () => {
        const isOpen = trigger.getAttribute("aria-expanded") === "true";

        if (isOpen) {
          closeMenu();
        } else {
          openMenu();
        }
      });

      document.addEventListener("click", (event) => {
        if (!(event.target instanceof Node)) {
          return;
        }

        const clickedInside =
          trigger.contains(event.target) ||
          menu.contains(event.target);

        if (!clickedInside) {
          closeMenu();
        }
      });

      document.addEventListener("keydown", (event) => {
        if (event.key === "Escape") {
          const isOpen =
            trigger.getAttribute("aria-expanded") === "true";

          if (isOpen) {
            closeMenu();
            trigger.focus();
          }
        }
      });
    }

### Що відбувається

- `aria-expanded` показує стан відкриття;
- `aria-controls` пов'язує кнопку з меню;
- `hidden` приховує або показує список;
- натискання кнопки перемикає стан;
- натискання поза компонентом закриває меню;
- `Escape` закриває меню та повертає фокус на trigger.

### Важливе зауваження

Це базовий приклад. Він не реалізує повну клавіатурну модель ARIA menu, наприклад навігацію стрілками між пунктами.

Також він не повинен автоматично застосовуватися до кожного компонента вибору. Для стандартних полів форми краще починати з нативного `<select>`.

## 9. Dropdown Menu та доступність

Доступність залежить від призначення компонента.

Звичайний список посилань або кнопок у розкривному контейнері та ARIA-меню команд — не завжди одне й те саме.

### 9.1. Кнопка відкриття

Використовуй справжню кнопку.

    <button
      type="button"
      aria-expanded="false"
      aria-controls="actions-menu"
    >
      Дії
    </button>

`aria-expanded` має відповідати реальному стану меню.

### 9.2. `aria-controls`

Атрибут указує, яким елементом керує кнопка.

    aria-controls="actions-menu"

Значення має збігатися з `id` відповідного меню.

### 9.3. Клавіатурна навігація

Перевір:

- `Enter` — активує кнопку;
- `Space` — активує кнопку;
- `Escape` — закриває меню;
- `Tab` — дозволяє перейти до доступних елементів;
- стрілки — переміщують фокус між пунктами, якщо реалізовано відповідну модель меню.

Для звичайного списку кнопок стандартна навігація через `Tab` часто є природною.

Для компонента з `role="menu"` зазвичай потрібна спеціальна клавіатурна поведінка, включно з навігацією стрілками та керуванням фокусом.

### 9.4. `role="menu"` та `role="menuitem"`

ARIA-ролі не слід додавати лише тому, що компонент називається dropdown.

Якщо створюєш справжнє меню команд із поведінкою, подібною до меню настільного застосунку, можна використати:

    <div role="menu" aria-label="Дії із записом">
      <button type="button" role="menuitem">
        Редагувати
      </button>

      <button type="button" role="menuitem">
        Копіювати
      </button>
    </div>

Але ці ролі самі по собі не реалізують клавіатурну навігацію.

Якщо тобі потрібен звичайний список посилань чи кнопок, не обов'язково використовувати `role="menu"`.

### 9.5. Видимий фокус

Не прибирай outline без альтернативи.

    .dropdown-item:focus-visible {
      outline: 3px solid #2563eb;
      outline-offset: 2px;
    }

### 9.6. Фокус після закриття

Якщо користувач закрив меню клавішею `Escape`, фокус зазвичай потрібно повернути до кнопки відкриття.

Після вибору команди поведінка залежить від результату дії. Наприклад, після переходу на іншу сторінку фокус може змінитися відповідно до навігації.

### 9.7. Touch-пристрої

Не покладайся лише на hover.

Важливі команди повинні бути доступними через натискання, а не тільки через наведення курсора.

## 10. Dropdown та позиціювання біля країв екрана

Просте `position: absolute` добре підходить для невеликих навчальних компонентів, але може мати проблеми в реальних інтерфейсах.

Наприклад:

- меню виходить за правий край viewport;
- список обрізається батьківським контейнером;
- меню перекривається елементами з більшим `z-index`;
- меню відкривається в неправильному напрямку;
- таблиця з `overflow: auto` обрізає меню.

### Базовий CSS

    .dropdown {
      position: relative;
    }

    .dropdown-menu {
      position: absolute;
      top: calc(100% + 8px);
      left: 0;
      z-index: 100;
    }

### Відкриття праворуч

Якщо trigger розташований біля правого краю контейнера, меню можна вирівняти за правим краєм.

    .dropdown-menu--end {
      right: 0;
      left: auto;
    }

### Що робити у складному інтерфейсі

Для меню всередині таблиць, прокручуваних контейнерів або панелей керування можуть знадобитися:

- портал для рендерингу меню поза контейнером;
- обчислення позиції;
- автоматична зміна напрямку;
- перевірка меж viewport;
- керування stacking context.

У React для таких завдань часто використовують перевірені бібліотеки позиціювання.

## 11. Dropdown та анімація

Анімація може зробити появу меню плавнішою.

Приклад:

    .dropdown-menu {
      opacity: 0;
      visibility: hidden;
      transform: translateY(-4px);

      transition:
        opacity 150ms ease,
        transform 150ms ease,
        visibility 150ms;
    }

    .dropdown.is-open .dropdown-menu {
      opacity: 1;
      visibility: visible;
      transform: translateY(0);
    }

Це лише CSS-приклад. Клас `is-open` потрібно додавати та прибирати відповідно до стану компонента.

### Підтримка reduced motion

    @media (prefers-reduced-motion: reduce) {
      .dropdown-menu {
        transition: none;
      }
    }

Якщо меню приховане через `visibility`, переконайся, що його інтерактивні елементи не залишаються доступними для клавіатури в закритому стані.

Для простого компонента часто легше керувати відкритим станом через `hidden`, анімацію додавати окремо, якщо вона справді потрібна.

## 12. Dropdown у React

У React стан відкриття меню зазвичай зберігають через `useState`.

### Приклад

    "use client";

    import { useState } from "react";

    export default function DropdownExample() {
      const [isOpen, setIsOpen] = useState(false);

      function handleAction(action: string) {
        console.log(`Вибрана дія: ${action}`);
        setIsOpen(false);
      }

      return (
        <div className="dropdown">
          <button
            type="button"
            aria-expanded={isOpen}
            onClick={() => setIsOpen((previous) => !previous)}
          >
            Дії
            <span aria-hidden="true">▾</span>
          </button>

          {isOpen && (
            <div className="dropdown-menu">
              <button
                type="button"
                className="dropdown-item"
                onClick={() => handleAction("edit")}
              >
                Редагувати
              </button>

              <button
                type="button"
                className="dropdown-item"
                onClick={() => handleAction("copy")}
              >
                Копіювати
              </button>

              <button
                type="button"
                className="dropdown-item"
                onClick={() => handleAction("archive")}
              >
                Архівувати
              </button>
            </div>
          )}
        </div>
      );
    }

### Як це працює

1. `isOpen` зберігає стан меню.
2. Початкове значення `false` означає, що меню закрите.
3. Натискання trigger перемикає стан.
4. Умовний рендеринг показує або приховує список.
5. Вибір пункту запускає відповідну функцію.
6. Після виконання дії меню закривається.

### Що потрібно додати для повноцінного компонента

- закриття при натисканні поза меню;
- закриття клавішею `Escape`;
- правильне керування фокусом;
- відповідну клавіатурну навігацію;
- позиціювання біля країв viewport;
- перевірку поведінки на сенсорних пристроях.

Не всі ці можливості потрібні кожному простому списку. Спочатку визнач призначення компонента, а потім обирай відповідну модель взаємодії.

## 13. Dropdown у Next.js

У Next.js App Router інтерактивний dropdown зазвичай реалізують у Client Component, якщо він використовує `useState` та обробники подій.

Приклад структури:

    app/
    ├── page.tsx
    └── components/
        └── DropdownMenu.tsx

### `DropdownMenu.tsx`

    "use client";

    import { useState } from "react";

    type DropdownItem = {
      id: string;
      label: string;
      onSelect: () => void;
    };

    type DropdownMenuProps = {
      label: string;
      items: DropdownItem[];
    };

    export default function DropdownMenu({
      label,
      items,
    }: DropdownMenuProps) {
      const [isOpen, setIsOpen] = useState(false);

      function handleSelect(item: DropdownItem) {
        item.onSelect();
        setIsOpen(false);
      }

      return (
        <div className="dropdown">
          <button
            type="button"
            aria-expanded={isOpen}
            onClick={() => setIsOpen((previous) => !previous)}
          >
            {label}
            <span aria-hidden="true">▾</span>
          </button>

          {isOpen && (
            <div className="dropdown-menu">
              {items.map((item) => (
                <button
                  key={item.id}
                  type="button"
                  className="dropdown-item"
                  onClick={() => handleSelect(item)}
                >
                  {item.label}
                </button>
              ))}
            </div>
          )}
        </div>
      );
    }

### Приклад використання

    "use client";

    import DropdownMenu from "./components/DropdownMenu";

    export default function Page() {
      const items = [
        {
          id: "edit",
          label: "Редагувати",
          onSelect: () => console.log("Редагування"),
        },
        {
          id: "copy",
          label: "Копіювати",
          onSelect: () => console.log("Копіювання"),
        },
      ];

      return (
        <main>
          <h1>Керування записами</h1>

          <DropdownMenu
            label="Дії"
            items={items}
          />
        </main>
      );
    }

### Важливі зауваження

Це навчальний компонент, який демонструє props, типізацію та керування станом.

Для production-реалізації потрібно врахувати:

- закриття при кліку поза меню;
- `Escape`;
- фокус і клавіатурну навігацію;
- позиціювання;
- семантику меню;
- повторні або асинхронні дії.

У Next.js функції `onSelect` не можна передавати як звичайні props із Server Component у Client Component, оскільки звичайні функції не є серіалізованими props. У наведеному прикладі сторінка позначена `"use client"`, тому функції створюються на клієнті.

## 14. Типізація Dropdown у TypeScript

Для повторно використовуваного компонента потрібно описати структуру пунктів меню.

### Приклад типів

    type DropdownAction = "edit" | "copy" | "archive";

    type DropdownItem = {
      id: DropdownAction;
      label: string;
      disabled?: boolean;
    };

    type DropdownProps = {
      label: string;
      items: DropdownItem[];
      onSelect: (action: DropdownAction) => void;
    };

### Приклад використання

    const items: DropdownItem[] = [
      {
        id: "edit",
        label: "Редагувати",
      },
      {
        id: "copy",
        label: "Копіювати",
      },
      {
        id: "archive",
        label: "Архівувати",
        disabled: true,
      },
    ];

### Переваги типізації

- чітко визначені можливі дії;
- менше помилок у назвах команд;
- зрозумілий контракт компонента;
- простіше рефакторити;
- кращі підказки в редакторі.

Для реального застосунку не потрібно використовувати `any`, якщо типи можна описати явно.

## 15. Dropdown у таблицях і списках

Меню додаткових дій особливо корисні в таблицях.

Приклад:

    ┌────────────┬───────────┬─────────────┐
    │ Назва      │ Статус    │ Дії         │
    ├────────────┼───────────┼─────────────┤
    │ Курс A     │ Активний  │ [⋯]         │
    │ Курс B     │ Чернетка  │ [⋯]         │
    │ Курс C     │ Завершено │ [⋯]         │
    └────────────┴───────────┴─────────────┘

Після натискання на `⋯` відкривається меню дій конкретного рядка.

### Рекомендації

- чітко пов'язуй меню з відповідним рядком;
- не відкривай усі меню одночасно;
- закривай попереднє меню, коли відкривається інше;
- забезпечуй доступ до команд на мобільних пристроях;
- перевіряй, чи меню не обрізається контейнером таблиці;
- не покладайся лише на іконку без доступної назви.

### Приклад доступної кнопки

    <button
      type="button"
      aria-label="Дії для курсу Інформатика"
    >
      ⋯
    </button>

Назва повинна конкретизувати контекст, якщо в таблиці є багато однакових кнопок.

## 16. Dropdown та форми

Важливо відрізняти меню команд від поля вибору у формі.

Якщо користувач повинен вибрати країну, категорію або статус, спочатку розглянь нативний `<select>`.

### Приклад

    <label for="status">Статус курсу</label>

    <select id="status" name="status">
      <option value="draft">Чернетка</option>
      <option value="active">Активний</option>
      <option value="completed">Завершений</option>
    </select>

### Чому нативний select часто кращий

- браузер забезпечує стандартну поведінку;
- підтримується клавіатурна навігація;
- добре працює на сенсорних пристроях;
- простіше забезпечити доступність;
- менше власного JavaScript.

### Коли потрібен кастомний Select

Розглянь власний компонент, якщо потрібні:

- пошук серед опцій;
- групування;
- складні візуальні стани;
- асинхронне завантаження;
- спеціальні елементи в списку.

Проте складний кастомний select потребує значно більше роботи з клавіатурою, фокусом, ARIA та сенсорними пристроями.

## 17. Коли не варто використовувати Dropdown

Dropdown не завжди є найкращим рішенням.

### Краще показати кнопки безпосередньо, якщо:

- доступно лише кілька важливих дій;
- користувач часто виконує ці дії;
- приховування ускладнює взаємодію.

### Краще використати Tabs, якщо:

- потрібно перемикатися між кількома розділами;
- важливо бачити всі доступні розділи;
- кожен розділ має окремий вміст.

### Краще використати Select, якщо:

- потрібно вибрати значення у формі;
- користувач не запускає команду, а змінює значення.

### Краще використати Combobox, якщо:

- список великий;
- потрібен пошук;
- користувач може вводити текст.

### Краще використати Popover, якщо:

- потрібні додаткові налаштування;
- у панелі є кілька полів або кнопок;
- вміст складніший за звичайний список команд.

**Правило:** вибирай компонент за його функцією, а не лише за зовнішнім виглядом.

## 18. Типові помилки

### Помилка 1. Dropdown відкривається лише при hover

На сенсорних пристроях меню стає недоступним або поводиться непередбачувано.

**Рішення:** використовуй кнопку з керованим станом.

### Помилка 2. Немає стану відкриття

Користувач не розуміє, чи меню відкрите.

**Рішення:** змінюй індикатор кнопки та підтримуй `aria-expanded`.

### Помилка 3. Немає закриття через Escape

Користувач клавіатури не може швидко закрити меню.

**Рішення:** обробляй `Escape` і повертай фокус до trigger.

### Помилка 4. Меню обрізається контейнером

Меню всередині таблиці або картки частково зникає.

**Рішення:** перевір `overflow`, stacking context і потребу в порталі.

### Помилка 5. Пункти занадто малі

Користувачеві складно натискати на них.

**Рішення:** збільш висоту та внутрішні відступи.

### Помилка 6. Немає доступної назви іконки

Кнопка `⋯` не пояснює, які дії вона відкриває.

**Рішення:** додай відповідний `aria-label`.

### Помилка 7. Усі меню відкриваються одночасно

У таблиці кілька рядків показують відкриті меню.

**Рішення:** керуй активним меню або окремим станом кожного компонента.

### Помилка 8. Dropdown використовується замість Select

Поле вибору значення реалізоване як меню команд.

**Рішення:** розділяй меню дій та компоненти вибору.

### Помилка 9. ARIA-ролі додані без поведінки

Є `role="menu"` і `role="menuitem"`, але клавіатурна навігація не працює.

**Рішення:** реалізуй відповідну модель взаємодії або використай перевірений компонент.

### Помилка 10. Небезпечна дія не відрізняється

«Видалити» виглядає так само, як звичайна команда.

**Рішення:** використовуй послідовні візуальні сигнали та, за потреби, підтвердження.

### Помилка 11. Підменю надто складні

Користувачеві важко орієнтуватися у вкладених списках.

**Рішення:** спростити структуру або згрупувати команди в окремих розділах.

### Помилка 12. Меню не закривається після дії

Відкритий список залишається на екрані після виконання команди.

**Рішення:** закривай меню після завершення відповідної дії, якщо сценарій цього потребує.

- закривається через `Escape`;
- після закриття фокус повертається до trigger, якщо це доречно;
- меню не виходить за межі екрана без потреби.

### Версія 2 — React + TypeScript

Створи `DropdownMenu.tsx`.

Можливий контракт компонента:

    type DropdownItem = {
      id: string;
      label: string;
      disabled?: boolean;
      onSelect: () => void;
    };

    type DropdownMenuProps = {
      label: string;
      items: DropdownItem[];
    };

Додаткові завдання:

- використовуй `useState`;
- додавай стабільний `key` для кожного пункту;
- підтримуй disabled-стан;
- реалізуй закриття через `Escape`;
- перевір роботу фокусу;
- не використовуй `any`.

### Версія 3 — Next.js

Використай dropdown у таблиці навчальних курсів.

Кожен рядок повинен мати меню з командами:

- Редагувати курс;
- Переглянути;
- Архівувати;
- Видалити.

Після вибору команди:

1. виконай відповідну дію;
2. закрий меню;
3. онови інтерфейс;
4. покажи результат;
5. для небезпечної дії за потреби відкрий confirmation modal.

Якщо дія виконує запит до API, обробляй стан завантаження та помилки. Права доступу до критичних операцій перевіряй на сервері.

## 22. Що потрібно запам'ятати

✔ Dropdown — компонент, який відкриває список опцій або команд.

✔ Dropdown Menu призначений для команд, а Select — для вибору значення.

✔ Combobox поєднує введення тексту з вибором зі списку.

✔ Popover може містити складніший інтерактивний вміст.

✔ Для простого меню часто використовують `position: relative` та `position: absolute`.

✔ Для відкриття меню дій зазвичай краще використовувати кнопку, а не лише hover.

✔ `aria-expanded` повинен відповідати фактичному стану меню.

✔ `aria-controls` може пов'язувати trigger із меню.

✔ `role="menu"` та `role="menuitem"` не додають клавіатурну поведінку автоматично.

✔ `Escape` повинен закривати меню в типовому сценарії, а фокус має повертатися до логічного елемента.

✔ Позиціювання потрібно перевіряти біля країв viewport і всередині контейнерів з `overflow`.

✔ Для звичайного вибору у формі починай із нативного `<select>`.

✔ У React стан відкриття зазвичай контролюється через `useState`.

✔ У TypeScript описуй структуру пунктів меню явно та уникай `any`.

✔ Для складних компонентів вибору або меню варто розглянути перевірену бібліотеку.

✔ Важливі команди повинні бути доступними на клавіатурі та сенсорних пристроях.

## 24. Рівні опанування

### Рівень 1 — Basic

- розумію призначення dropdown;
- розрізняю меню команд і поля вибору;
- можу створити простий список;
- знаю основи позиціювання;

- реалізую відкриття та закриття;

- підтримую `Escape`;
- використовую `aria-expanded`;
- перевіряю клавіатурну навігацію;

- типізую props через TypeScript;
- керую станом меню;
- обробляю вибір команди;
- інтегрую меню в таблиці та списки;
- обробляю асинхронні дії.

### Рівень 4 — Production

- забезпечую повну клавіатурну доступність;
- правильно керую фокусом;
- враховую viewport і stacking context;
- реалізую потрібну ARIA-модель;
- тестую touch-пристрої;
- використовую перевірені бібліотеки для складних меню.
