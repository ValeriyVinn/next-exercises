# 04. Selects — Випадаючі списки та вибір значень

> **Selects** — це UI-компоненти, які дозволяють користувачеві вибирати одне або кілька значень із попередньо визначеного набору варіантів.
>
> Вони допомагають зменшити кількість помилок введення, стандартизувати дані та зробити взаємодію з формами передбачуваною.
>
> Основне завдання дизайну Select — допомогти користувачеві швидко знайти потрібний варіант, зрозуміти поточний вибір і за потреби змінити його.

---

## 1. Що потрібно знати про Selects

Selects використовуються в багатьох типах інтерфейсів:

- реєстрація та налаштування профілю;
- вибір країни, міста або мови;
- фільтрація списків;
- налаштування параметрів;
- створення навчальних курсів;
- оформлення замовлень;
- адміністративні панелі;
- вибір категорій і статусів;
- пошукові форми.

### Основні поняття

- ✔ **Select** — компонент вибору одного або кількох значень зі списку.
- ✔ **Dropdown** — випадаюча область із варіантами або діями.
- ✔ **Option** — окремий варіант у списку.
- ✔ **Selected value** — поточне вибране значення.
- ✔ **Placeholder** — підказка, яка показується до вибору значення.
- ✔ **Label** — назва поля, що пояснює його призначення.
- ✔ **Helper text** — додаткове пояснення під полем.
- ✔ **Multi-select** — компонент, який дозволяє вибирати кілька значень.
- ✔ **Searchable select** — список із можливістю пошуку варіантів.
- ✔ **Combobox** — компонент, який поєднує введення тексту з вибором зі списку.
- ✔ **Option group** — група пов'язаних варіантів.
- ✔ **Disabled option** — недоступний для вибору варіант.
- ✔ **Selected state** — візуальний стан вибраного варіанта.
- ✔ **Open state** — стан, коли список відкритий.
- ✔ **Keyboard navigation** — керування компонентом за допомогою клавіатури.
- ✔ **Empty state** — стан, коли відповідних варіантів немає.
- ✔ **Design system** — система узгоджених компонентів, правил і стилів.

## 2. Select, Dropdown, Combobox і Multi-select

Ці компоненти схожі зовні, але призначені для різних сценаріїв.

### 2.1. Select

Select дозволяє вибрати значення з готового списку.

    Країна
    ┌────────────────────────────────┐
    │ Україна                     ▼  │
    └────────────────────────────────┘

Після натискання відкривається список варіантів.

    ┌────────────────────────────────┐
    │ Польща                         │
    │ Україна                    ✓   │
    │ Німеччина                      │
    │ Франція                        │
    └────────────────────────────────┘

Зазвичай Select використовують, коли:

- варіанти відомі заздалегідь;
- користувач має вибрати одне значення;
- немає потреби вводити довільний текст;
- список не надто великий або його можна зручно переглядати.

### 2.2. Dropdown

Dropdown — ширше поняття. Воно описує область, яка відкривається й показує варіанти або дії.

Dropdown може містити:

- варіанти вибору;
- команди;
- посилання;
- налаштування;
- меню користувача.

Наприклад, меню профілю:

    ┌──────────────────────────────┐
    │ Мій профіль                  │
    │ Налаштування                 │
    │ Допомога                     │
    │ Вийти                        │
    └──────────────────────────────┘

Це меню дій, а не обов'язково Select.

**Важливо:** не кожен Dropdown є Select, хоча Select часто використовує випадаючий список.

### 2.3. Combobox

Combobox поєднує текстове поле та список варіантів. Користувач може вводити текст, щоб знайти відповідний пункт.

    Місто
    ┌────────────────────────────────┐
    │ Він...                          │
    └────────────────────────────────┘

    ┌────────────────────────────────┐
    │ Вінниця                        │
    │ Вінниця, інша область          │
    └────────────────────────────────┘

Combobox корисний, коли:

- список великий;
- пошук за текстом прискорює вибір;
- користувач може не знати точного написання;
- потрібна фільтрація варіантів.

Правила введення залежать від реалізації: деякі Combobox дозволяють лише вибирати запропоновані значення, а інші — вводити довільний текст.

### 2.4. Multi-select

Multi-select дозволяє вибрати кілька значень одночасно.

    Предмети
    ┌────────────────────────────────┐
    │ Математика ×  Інформатика ×  ▼ │
    └────────────────────────────────┘

Після відкриття списку:

    ┌────────────────────────────────┐
    │ ☑ Математика                   │
    │ ☐ Фізика                       │
    │ ☑ Інформатика                  │
    │ ☐ Історія                      │
    └────────────────────────────────┘

Використовуй Multi-select, якщо користувачеві справді потрібно вибирати кілька незалежних значень.

### Порівняння

| Компонент | Основна функція | Коли використовувати |
|---|---|---|
| Select | Вибір одного значення | Невеликий або помірний список |
| Dropdown menu | Вибір дії або переходу | Меню команд і навігації |
| Combobox | Введення та пошук варіанта | Великий список або пошук |
| Multi-select | Вибір кількох значень | Незалежні множинні варіанти |
| Checkbox group | Вибір кількох видимих опцій | Невеликий список, де важливо бачити всі варіанти |
| Radio group | Вибір одного видимого варіанта | Невеликий список із важливим порівнянням опцій |

## 3. Коли варто використовувати Select

Select не завжди є найкращим способом вибору.

### Select доречний, коли:

- користувач вибирає одне значення;
- набір варіантів обмежений;
- список не займає надто багато часу для перегляду;
- значення мають стандартизований формат;
- не потрібно порівнювати всі варіанти одночасно.

Приклади:

- країна;
- мова інтерфейсу;
- статус замовлення;
- категорія матеріалу;
- тип документа.

### Select може бути незручним, коли:

- є лише два варіанти;
- усі варіанти важливо бачити одночасно;
- список дуже великий;
- користувач повинен порівнювати варіанти;
- пошук є основною дією.

### Що вибрати замість Select

| Сценарій | Кращий варіант |
|---|---|
| Так / Ні | Switch, Checkbox або Radio залежно від змісту |
| Два-три важливі варіанти | Radio group або Segmented control |
| До кількох незалежних опцій | Checkbox group |
| Великий каталог | Searchable Select або Combobox |
| Вибір дати | Date picker |
| Вибір діапазону | Slider або числові поля |
| Команди користувача | Dropdown menu |
| Фільтри з миттєвим застосуванням | Checkbox, Select або інші фільтри залежно від сценарію |

**Правило:** обирай компонент за завданням користувача, а не лише за тим, як він виглядає.

## 4. Структура Select-компонента

Типовий Select складається з кількох частин.

    Країна *
    ┌────────────────────────────────┐
    │ Виберіть країну             ▼  │
    └────────────────────────────────┘
    Оберіть країну проживання.

Основні частини:

1. **Label** — назва поля.
2. **Trigger** — видима область, яка відкриває список.
3. **Selected value** — поточне значення.
4. **Placeholder** — підказка, якщо значення ще не вибрано.
5. **Dropdown indicator** — індикатор відкриття списку.
6. **Option list** — список доступних варіантів.
7. **Option** — окремий пункт.
8. **Selected indicator** — позначка вибраного пункту.
9. **Helper text** — пояснення під полем.
10. **Error message** — повідомлення про помилку.
11. **Search field** — поле пошуку, якщо воно потрібне.
12. **Clear action** — дія очищення, якщо очищення дозволене.

Не кожен Select потребує всіх цих елементів.

### Принципи побудови

- Назва поля повинна залишатися зрозумілою після вибору.
- Поточне значення має бути помітним.
- Індикатор відкриття повинен бути зрозумілим.
- Список має відкриватися передбачувано.
- Вибраний варіант повинен відрізнятися від інших.
- Недоступні варіанти повинні мати зрозумілий стан.
- Список не повинен перекривати критично важливу інформацію без потреби.

## 5. Label і Placeholder у Select

### 5.1. Label

Label пояснює, яке значення потрібно вибрати.

    Мова інтерфейсу
    ┌────────────────────────────────┐
    │ Українська                  ▼  │
    └────────────────────────────────┘

Label не повинен зникати після вибору значення.

### 5.2. Placeholder

Placeholder показує, що користувач ще не зробив вибір, або допомагає зрозуміти очікувану дію.

    Категорія
    ┌────────────────────────────────┐
    │ Виберіть категорію           ▼ │
    └────────────────────────────────┘

Хороший Placeholder:

- короткий;
- зрозумілий;
- відповідає сценарію;
- не дублює зайвий текст;
- не створює враження, що значення вже вибрано.

### 5.3. Не використовуй неоднозначні значення

Погано:

    ┌────────────────────────────────┐
    │ Інше                         ▼ │
    └────────────────────────────────┘

Якщо користувач ще нічого не вибрав, слово «Інше» може виглядати як реальне значення.

Краще:

    ┌────────────────────────────────┐
    │ Виберіть категорію           ▼ │
    └────────────────────────────────┘

Варіант «Інше» має бути окремим пунктом, якщо він справді належить до доступних категорій.

## 6. Розміри та пропорції Select

### 6.1. Висота

Select повинен мати достатню висоту для тексту, індикатора та комфортної взаємодії.

Приклад умовної системи:

    Small:   32 px
    Medium:  40 px
    Large:   48 px

Це приклад дизайн-шкали, а не універсальний стандарт.

Висоту потрібно узгоджувати з:

- розміром шрифту;
- внутрішніми відступами;
- висотою сусідніх полів;
- областю натискання;
- вимогами мобільної взаємодії.

### 6.2. Ширина

Ширина повинна відповідати значенням, які відображаються.

Наприклад:

- Select мови може бути компактним;
- Select країни має вміщувати довгі назви;
- Select категорії може займати ширину контейнера;
- Searchable Select для великого каталогу може бути широким.

Не встановлюй однакову ширину всім Select без урахування змісту.

### 6.3. Внутрішні відступи

    ┌────────────────────────────────┐
    │  Українська                 ▼  │
    └────────────────────────────────┘
      ↑                            ↑
      padding                      indicator

Залиш достатньо місця для тексту, щоб він не стикався з індикатором.

### 6.4. Радіус кутів і межі

Використовуй узгоджені:

- border radius;
- товщину межі;
- кольори меж;
- кольори фону;
- індикатори фокусу.

Select повинен візуально належати до тієї самої системи, що й Inputs, Buttons та інші компоненти.

## 7. Візуальні стани Select

Select повинен показувати, у якому стані він перебуває.

### 7.1. Default

Звичайний стан, коли список закритий і компонент доступний.

    Країна
    ┌──────────────────────────────┐
    │ Виберіть країну           ▼  │
    └──────────────────────────────┘

### 7.2. Hover

Коли вказівник миші наведений на компонент, його зовнішній вигляд може трохи змінюватися.

Наприклад:

- темніша межа;
- легка зміна фону;
- невелика зміна тіні.

Hover не повинен бути єдиним способом передати стан, адже на сенсорних пристроях немає звичайного наведення.

### 7.3. Focus

Коли Select отримує фокус, це має бути помітно.

    ┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓
    ┃ Україна                   ▼  ┃
    ┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛

Focus важливий для користувачів клавіатури й тих, хто користується іншими допоміжними засобами.

### 7.4. Open

Список відкритий, і користувач може переглядати варіанти.

    Країна
    ┌──────────────────────────────┐
    │ Україна                   ▲  │
    └──────────────────────────────┘
    ┌──────────────────────────────┐
    │ Польща                       │
    │ Україна                  ✓   │
    │ Німеччина                    │
    │ Франція                      │
    └──────────────────────────────┘

У відкритому стані важливо:

- чітко показувати межі списку;
- не приховувати поточний вибір;
- забезпечувати достатній простір для пунктів;
- показувати активний пункт під час навігації;
- уникати обрізання важливого тексту.

### 7.5. Selected

Вибраний пункт повинен відрізнятися від інших.

    ┌──────────────────────────────┐
    │ Україна                  ✓   │
    └──────────────────────────────┘

Можна використовувати:

- позначку;
- зміну фону;
- насиченість тексту;
- інший візуальний маркер.

Не покладайся лише на колір для позначення вибору.

### 7.6. Disabled

Компонент недоступний для взаємодії.

    Область
    ┌──────────────────────────────┐
    │ Виберіть область          ▼  │
    └──────────────────────────────┘

Наприклад, поле вибору області може залишатися недоступним, доки користувач не вибере країну.

Disabled-стан має бути зрозумілим, але текст повинен залишатися читабельним.

Якщо користувачеві незрозуміло, чому поле недоступне, додай пояснення.

### 7.7. Error

Значення не вибрано або вибір не відповідає вимогам форми.

    Країна *
    ┌──────────────────────────────┐
    │ Виберіть країну           ▼  │
    └──────────────────────────────┘
    Виберіть країну, щоб продовжити.

Помилка повинна бути зрозумілою, а не лише позначеною червоною межею.

### 7.8. Loading

Список або його варіанти завантажуються.

    Місто
    ┌──────────────────────────────┐
    │ Завантаження...           ◌  │
    └──────────────────────────────┘

Якщо список завантажується із сервера, потрібно враховувати:

- індикатор очікування;
- зрозумілий текст;
- можливість повторної спроби в разі помилки;
- поведінку поля до завершення завантаження.

### Таблиця станів

| Стан | Значення | Що важливо |
|---|---|---|
| Default | Звичайний стан | Зрозумілий вигляд |
| Hover | Наведення | Ненав'язлива реакція |
| Focus | Активний компонент | Видимий фокус |
| Open | Список відкритий | Чітка структура варіантів |
| Selected | Є вибір | Видима позначка |
| Disabled | Взаємодія недоступна | Зрозуміле обмеження |
| Error | Вибір не відповідає вимогам | Пояснення проблеми |
| Loading | Варіанти завантажуються | Зрозумілий стан очікування |
| Empty | Варіантів немає | Пояснення та наступна дія |

## 8. Проєктування списку варіантів (Options)

Список варіантів — основна частина Select.

### 8.1. Текст варіантів

Назви повинні бути:

- короткими, якщо це можливо;
- однозначними;
- зрозумілими без додаткових пояснень;
- стилістично узгодженими;
- послідовними за формою.

Погано:

    ┌──────────────────────────────┐
    │ Укр.                         │
    │ Україна                      │
    │ DE                           │
    │ Німеччина                    │
    └──────────────────────────────┘

Краще:

    ┌──────────────────────────────┐
    │ Україна                      │
    │ Німеччина                    │
    │ Польща                       │
    └──────────────────────────────┘

### 8.2. Порядок варіантів

Вибір порядку залежить від задачі.

Можливі способи:

- алфавітний порядок;
- логічні категорії;
- популярні варіанти на початку;
- послідовність виконання процесу;
- пріоритет за частотою використання.

Не змінюй порядок без причини: користувачі можуть звикати до розташування варіантів.

### 8.3. Групування

Якщо список містить багато пов'язаних варіантів, їх можна групувати.

    Тип курсу
    ┌──────────────────────────────┐
    │ Програмування                │
    │   JavaScript                 │
    │   Python                     │
    │   TypeScript                 │
    │ Дизайн                       │
    │   UI Design                  │
    │   UX Design                  │
    └──────────────────────────────┘

Групування корисне, коли воно полегшує пошук. Для невеликого списку воно може бути зайвим.

### 8.4. Disabled options

Деякі варіанти можуть бути тимчасово недоступними.

    ┌──────────────────────────────┐
    │ Початковий рівень            │
    │ Середній рівень              │
    │ Просунутий рівень (недоступно)│
    └──────────────────────────────┘

Використовуй disabled options лише тоді, коли користувачеві важливо знати про існування варіанта.

Якщо варіант недоступний, пояснення причини може бути корисним, особливо коли недоступність неочевидна.

### 8.5. Довгі назви

Якщо варіанти мають довгі назви:

- передбачай достатню ширину;
- допускай перенесення тексту, якщо це доречно;
- не допускай перекриття індикаторів;
- перевіряй список на вузьких екранах;
- не обрізай важливу частину назви без можливості її прочитати.

---

## 9. Пошук у Select (Searchable Select)

Коли список великий, звичайний Select може бути незручним.

Searchable Select дозволяє швидше знайти потрібний пункт.

### Приклад

    Країна
    ┌──────────────────────────────┐
    │ Пошук країни...              │
    └──────────────────────────────┘
    ┌──────────────────────────────┐
    │ Німеччина                    │
    │ Нідерланди                   │
    │ Норвегія                     │
    └──────────────────────────────┘

### Коли потрібен пошук

- список містить багато варіантів;
- користувач знає назву потрібного пункту;
- перегляд усього списку займає багато часу;
- список завантажується з сервера;
- пошук за текстом значно спрощує вибір.

### Принципи дизайну

- Пошукове поле повинно бути помітним.
- Користувач повинен розуміти, що саме шукає.
- Результати повинні оновлюватися передбачувано.
- Поточний вибір має залишатися зрозумілим.
- Порожній результат повинен мати пояснення.
- Пошук не повинен стирати вибір без причини.

### Empty state

Якщо нічого не знайдено:

    ┌──────────────────────────────┐
    │ Пошук: "Київськ"             │
    ├──────────────────────────────┤
    │ Нічого не знайдено.          │
    │ Спробуйте інший запит.       │
    └──────────────────────────────┘

Порожній стан повинен допомогти користувачеві продовжити роботу.

---

## 10. Multi-select — вибір кількох значень

Multi-select дозволяє обирати більше одного варіанта.

### 10.1. Відображення вибраних значень

Для невеликої кількості значень можна використовувати теги.

    Предмети
    ┌────────────────────────────────┐
    │ [Математика ×] [Інформатика ×] ▼│
    └────────────────────────────────┘

Кожен тег може мати кнопку видалення, якщо це дозволяє поведінка компонента.

### 10.2. Велика кількість вибраних значень

Якщо значень багато, усі теги можуть займати надто багато простору.

Можливі рішення:

- показувати перші кілька значень і лічильник решти;
- відображати короткий підсумок;
- переносити теги на кілька рядків;
- використовувати окрему область зі списком вибраного.

Наприклад:

    ┌────────────────────────────────┐
    │ Математика, Інформатика +3    ▼ │
    └────────────────────────────────┘

Вибирай рішення залежно від того, наскільки важливо користувачеві бачити всі вибрані значення.

### 10.3. Видалення вибраного значення

Кнопка видалення повинна:

- мати достатню область натискання;
- бути візуально зрозумілою;
- мати доступну назву;
- не активувати випадково інші дії;
- не дозволяти видаляти обов'язкове значення, якщо це заборонено правилами.

### 10.4. Select all і Clear all

Для великих списків можуть бути корисними:

- Select all — вибрати всі;
- Clear all — очистити вибір.

Але ці дії потрібно додавати лише тоді, коли вони відповідають реальним сценаріям користувача.

### 10.5. Обмеження кількості вибраних значень

Якщо дозволено вибрати максимум п'ять варіантів, це обмеження потрібно пояснити.

    Предмети
    Виберіть не більше 5 предметів.

Користувач не повинен дізнаватися про обмеження лише після несподіваної помилки.

---

## 11. Залежні Selects (Dependent Selects)

Залежні списки змінюють свої варіанти залежно від попереднього вибору.

Приклад:

    Країна
    ┌──────────────────────────────┐
    │ Україна                   ▼  │
    └──────────────────────────────┘

    Область
    ┌──────────────────────────────┐
    │ Вінницька область          ▼ │
    └──────────────────────────────┘

    Місто
    ┌──────────────────────────────┐
    │ Вінниця                    ▼ │
    └──────────────────────────────┘

### Основні правила

1. Спочатку користувач вибирає країну.
2. Після цього стають доступними відповідні області.
3. Після вибору області завантажуються відповідні міста.
4. Якщо країна змінюється, область і місто можуть потребувати повторного вибору.
5. Користувач повинен розуміти, чому наступні поля недоступні.

### Стан до вибору

    Країна
    ┌──────────────────────────────┐
    │ Виберіть країну            ▼ │
    └──────────────────────────────┘

    Область
    ┌──────────────────────────────┐
    │ Спочатку виберіть країну   ▼ │
    └──────────────────────────────┘

Це краще, ніж показувати незрозуміле disabled-поле без пояснення.

### Зміна попереднього значення

Якщо користувач змінює країну, попередній вибір області або міста може більше не відповідати новим даним.

У такому разі потрібно:

- скинути недійсні залежні значення;
- оновити доступні варіанти;
- показати стан завантаження;
- пояснити помилку, якщо завантаження не вдалося.

Не залишай у формі значення, які більше не відповідають поточному вибору.

---

## 12. Клавіатурна взаємодія та Accessibility

Select повинен бути зручним не лише для миші.

### 12.1. Клавіатурна навігація

Залежно від типу компонента та його реалізації користувач може очікувати:

- Tab — перейти до компонента;
- Shift + Tab — повернутися до попереднього компонента;
- Enter або Space — відкрити список або активувати пункт;
- стрілки вгору та вниз — переміщатися між варіантами;
- Escape — закрити список;
- введення літер — перейти до відповідного пункту, якщо це підтримується.

Конкретна поведінка залежить від того, чи використовується нативний HTML Select, чи спеціальний кастомний компонент.

### 12.2. Видимий фокус

Користувач повинен розуміти:

- який компонент активний;
- який пункт зараз вибраний;
- на якому пункті перебуває клавіатурна навігація;
- чи відкритий список.

Не прибирай стандартний індикатор фокусу без створення доступної заміни.

### 12.3. Контрастність

Перевіряй контраст:

- тексту Select;
- Placeholder;
- меж;
- індикатора фокусу;
- активного пункту;
- повідомлень про помилки;
- недоступних варіантів.

Недоступний стан може бути менш акцентним, але текст не повинен ставати нерозбірливим.

### 12.4. Не покладайся лише на колір

Вибраний пункт потрібно відрізняти не лише кольором.

Можна використовувати:

- позначку вибору;
- зміну фону;
- інший стиль тексту;
- програмно доступний стан.

### 12.5. Label і доступна назва

Кожен Select повинен мати зрозумілу доступну назву.

У нативному HTML використовуй пов'язаний `label`.

    <label for="country">Країна</label>

    <select id="country" name="country">
      <option value="">Виберіть країну</option>
      <option value="ua">Україна</option>
      <option value="pl">Польща</option>
    </select>

Для кастомних компонентів потрібно правильно реалізувати доступну назву, фокус, поточне значення, стан відкриття та навігацію.

### 12.6. Кастомний Select — додаткова відповідальність

Створення власного Select може вимагати значно більше роботи, ніж оформлення нативного елемента.

Потрібно правильно реалізувати:

- клавіатурну навігацію;
- керування фокусом;
- оголошення станів допоміжними технологіями;
- закриття списку;
- вибір варіантів;
- поведінку на сенсорних пристроях;
- прокручування довгих списків;
- доступні назви та повідомлення.

**Правило:** якщо нативний Select задовольняє потреби проєкту, не створюй кастомний лише заради декоративної відмінності.

---

## 13. Нативний Select чи кастомний Select

Це важливе рішення для дизайнера та розробника.

### 13.1. Нативний Select

HTML-елемент `<select>`.

Переваги:

- вбудована клавіатурна взаємодія;
- підтримка допоміжних технологій;
- звична поведінка;
- простіша реалізація;
- інтеграція з HTML-формами;
- підтримка мобільних платформ.

Обмеження:

- обмежений контроль над оформленням;
- різний вигляд на різних операційних системах і браузерах;
- складно реалізувати складні рядки варіантів;
- не завжди підходить для пошуку або тегів множинного вибору.

### 13.2. Кастомний Select

Компонент, побудований із власних UI-елементів.

Переваги:

- більше контролю над дизайном;
- власні стани та анімації;
- можливість додавати пошук;
- групування та складні варіанти;
- можливість створити Multi-select із тегами.

Недоліки:

- складніша реалізація;
- більша відповідальність за доступність;
- ризик помилок клавіатурної взаємодії;
- більше сценаріїв для тестування;
- потенційні проблеми на мобільних пристроях.

### Порівняння

| Критерій | Нативний Select | Кастомний Select |
|---|---|---|
| Простота реалізації | Висока | Нижча |
| Вбудована поведінка | Є | Потрібно реалізувати |
| Контроль над дизайном | Обмежений | Високий |
| Пошук | Обмежений або відсутній | Можна реалізувати |
| Multi-select із тегами | Ні, не в такому вигляді | Можна реалізувати |
| Доступність | Значна частина поведінки вбудована | Потрібне ретельне тестування |
| Підтримка платформ | Нативна для браузера | Залежить від реалізації |

**Висновок:** починай із нативного Select. Кастомний компонент виправданий, коли конкретні вимоги не можна якісно задовольнити нативним елементом.

---

## 14. Select у мобільному дизайні

Вибір значень на мобільному пристрої має свої особливості.

### Основні правила

- Забезпечуй комфортну область натискання.
- Не роби текст надто дрібним.
- Враховуй вузьку ширину екрана.
- Не допускай обрізання важливих назв.
- Передбачай, що список може виходити за межі доступного простору.
- Перевіряй поведінку під час появи екранної клавіатури.
- Забезпечуй зрозуміле закриття списку.
- Не розміщуй важливі дії там, де їх легко випадково натиснути.

### Нативна поведінка на мобільному пристрої

Нативний Select може відкривати системний список або інший платформний інтерфейс вибору.

Це не обов'язково недолік. Звична поведінка може бути зручнішою за повністю кастомний список.

### Довгий список

Якщо користувач вибирає країну, місто або категорію з сотень варіантів, подумай про пошук замість простого прокручування.

---

## 15. Select у формах і фільтрах

Select може виконувати різні функції залежно від контексту.

### 15.1. У формі

Приклад: створення навчального курсу.

    Назва курсу
    [____________________________]

    Рівень
    ┌────────────────────────────┐
    │ Початковий              ▼  │
    └────────────────────────────┘

    Категорія
    ┌────────────────────────────┐
    │ Програмування            ▼ │
    └────────────────────────────┘

    [Створити курс]

У формі вибране значення зазвичай потрібно зберегти разом з іншими даними.

### 15.2. У фільтрах

Приклад: список курсів.

    Рівень: [Усі рівні ▼]
    Категорія: [Усі категорії ▼]
    Мова: [Українська ▼]

У фільтрах важливо показувати поточний вибір і дозволяти зрозуміло повернутися до початкового стану.

### 15.3. Застосування фільтрів

Можливі моделі:

- фільтр застосовується одразу після вибору;
- користувач вибирає кілька параметрів і натискає «Застосувати»;
- зміни застосовуються після підтвердження всього набору налаштувань.

Вибирай модель залежно від швидкості оновлення даних і складності сценарію.

### 15.4. Скидання фільтрів

Якщо фільтрів багато, корисними можуть бути:

- «Очистити»;
- «Скинути фільтри»;
- «Усі категорії»;
- видимі теги активних фільтрів.

Користувач повинен розуміти, як повернутися до повного списку.

---

## 16. Візуальна ієрархія та стилізація

Select повинен бути помітним настільки, наскільки це потрібно для взаємодії, але не повинен домінувати над усією формою.

### 16.1. Межі

Межа допомагає зрозуміти, що елемент інтерактивний.

Вона може змінюватися залежно від стану:

- Default — нейтральна;
- Hover — трохи акцентніша;
- Focus — чіткий індикатор;
- Error — помітне позначення проблеми;
- Disabled — менш акцентна.

### 16.2. Фон

Фон може бути:

- білим;
- нейтральним;
- адаптованим до темної теми;
- відмінним у стані Disabled;
- зміненим для активного пункту списку.

Не використовуй надмірну кількість кольорів для близьких за значенням станів.

### 16.3. Стрілка або індикатор

Індикатор допомагає зрозуміти, що список можна відкрити.

Він повинен:

- бути достатньо помітним;
- не перекривати текст;
- змінюватися передбачувано, якщо це частина системи;
- залишатися декоративним, якщо доступну назву вже має сам компонент.

### 16.4. Анімація

Невелика анімація може допомогти показати відкриття або закриття списку.

Наприклад:

- плавна поява;
- зміна напрямку стрілки;
- коротка зміна прозорості.

Анімація не повинна затримувати вибір або заважати користувачам, які зменшили рух у налаштуваннях системи.

---

## 17. Дизайн-система для Selects

У великому застосунку всі Select повинні працювати за спільними правилами.

### 17.1. Що стандартизувати

- висоту;
- ширину та правила адаптації;
- внутрішні відступи;
- радіус кутів;
- товщину межі;
- типографіку;
- кольори;
- індикатор відкриття;

## 18. Реалізація Select у HTML та CSS

### 18.1. Нативний HTML Select

    <div class="form-field">
      <label for="course-level">Рівень курсу</label>

      <select id="course-level" name="courseLevel" required>
        <option value="">Виберіть рівень</option>
        <option value="beginner">Початковий</option>
        <option value="intermediate">Середній</option>
        <option value="advanced">Просунутий</option>
      </select>

      <p class="form-field__help">
        Виберіть рівень складності курсу.
      </p>
    </div>

Основні атрибути:

- `id` — ідентифікатор елемента;
- `name` — ім'я поля під час надсилання форми;
- `required` — позначає обов'язкове поле;
- `value` в `option` — значення, яке передається під час надсилання;
- текст усередині `option` — назва, яку бачить користувач.

## 19. Select у React та Next.js

У React Select часто використовується як контрольований компонент.

### 19.1. Контрольований Select

    "use client";

    import { useState } from "react";

    export default function CourseLevelSelect() {
      const [level, setLevel] = useState("");

      return (
        <div>
          <label htmlFor="course-level">
            Рівень курсу
          </label>

          <select
            id="course-level"
            name="courseLevel"
            value={level}
            onChange={(event) => setLevel(event.target.value)}
          >
            <option value="">Виберіть рівень</option>
            <option value="beginner">Початковий</option>
            <option value="intermediate">Середній</option>
            <option value="advanced">Просунутий</option>
          </select>

          <p>
            Вибраний рівень: {level || "не вибрано"}
          </p>
        </div>
      );
    }

Тут:

- `useState` зберігає поточний вибір;
- `value` визначає значення Select;
- `onChange` оновлює стан;
- `label` пов'язаний із Select через `htmlFor` та `id`.

### 19.2. Типізація TypeScript

    type CourseLevel = "" | "beginner" | "intermediate" | "advanced";

    const [level, setLevel] = useState<CourseLevel>("");

Такий тип обмежує значення визначеним набором варіантів.

### 19.3. Коли потрібен Client Component

У Next.js директива `"use client"` потрібна, якщо компонент використовує клієнтський стан, обробники подій або інші клієнтські можливості React.

Нативний Select у статичній формі не обов'язково повинен бути Client Component. Рішення залежить від того, як форма реалізована.

### 19.4. Що потрібно розуміти UI-дизайнеру

- Як значення відображається в полі.
- Як відкривається список.
- Як змінюється вибір.
- Як показується помилка.
- Як працює Disabled.
- Як обробляється порожнє значення.
- Як компонент взаємодіє з формою.
- Як змінюється зовнішній вигляд через CSS Modules або дизайн-токени.

## 20. Типові помилки в дизайні Selects

### Помилка 1. Select замість простого вибору

Для двох коротких варіантів користувачеві доводиться відкривати список без потреби.

**Рішення:** розглянь Radio group, Checkbox або Segmented control залежно від сценарію.

### Помилка 2. Надто довгий список без пошуку

Користувач змушений прокручувати сотні пунктів.

**Рішення:** використовуй Searchable Select або Combobox.

### Помилка 3. Незрозумілий Placeholder

Користувач не розуміє, чи значення вже вибране.

**Рішення:** використовуй коротку підказку на зразок «Виберіть країну».

### Помилка 4. Невидимий поточний вибір

Користувач відкриває список і не розуміє, який пункт активний.

**Рішення:** виразно позначай вибраний варіант.

### Помилка 5. Вибраний пункт відрізняється лише кольором

Це може створювати проблеми для користувачів із порушеннями сприйняття кольору.

**Рішення:** додай інший сигнал, наприклад позначку вибору.

### Помилка 6. Кастомний Select без клавіатурної навігації

Компонент працює мишею, але ним складно користуватися з клавіатури.

**Рішення:** використовуй нативний Select або реалізуй і ретельно протестуй доступну поведінку.

### Помилка 7. Немає стану завантаження

Користувач не розуміє, чому список порожній або не відкривається.

**Рішення:** показуй стан завантаження, помилку або порожній результат.

### Помилка 8. Залежні поля не оновлюються

Після зміни країни залишається місто, яке не належить до нової країни.

**Рішення:** скидай недійсні залежні значення та оновлюй список.

### Помилка 9. Надто довгі назви обрізаються

Користувач не може відрізнити схожі варіанти.

**Рішення:** передбачай ширину, перенесення тексту або пошук.

### Помилка 10. Надто багато Multi-select тегів

Поле займає кілька рядків і руйнує макет.

**Рішення:** використовуй лічильник, компактне відображення або окремий список вибраного.

### Помилка 11. Недоступний варіант без пояснення

Користувач бачить пункт, але не розуміє, чому його не можна вибрати.

**Рішення:** додай пояснення, якщо причина має значення для користувача.

### Помилка 12. Непослідовний дизайн

Однакові Select у різних частинах застосунку мають різні розміри та стани.

**Рішення:** використовуй спільні компоненти, токени й правила дизайн-системи.

## 21. Практичний алгоритм дизайну Select

Під час створення компонента рухайся послідовно.

1. **Визнач задачу.** Що саме повинен вибрати користувач?
2. **Перевір альтернативи.** Чи справді потрібен Select?
3. **Визнач кількість варіантів.** Скільки пунктів буде у списку?
4. **Вибери тип компонента.** Нативний Select, Searchable Select, Combobox або Multi-select?
5. **Сформулюй Label.** Чи зрозуміле призначення поля?
6. **Визнач Placeholder.** Чи потрібно пояснити, що вибір ще не зроблено?
7. **Продумай порядок.** Як користувач найшвидше знайде варіант?
8. **Визнач стани.** Default, Focus, Open, Selected, Disabled, Error, Loading.
9. **Продумай поведінку.** Відкриття, закриття, навігація, вибір і очищення.
10. **Перевір доступність.** Клавіатура, фокус, контраст, доступні назви.
11. **Перевір адаптивність.** Чи зручно вибирати на мобільному пристрої?
12. **Узгодь із дизайн-системою.** Чи відповідає компонент іншим полям?
13. **Протестуй помилки.** Порожній список, завантаження, недоступні варіанти, довгі назви.
14. **Перевір реальні сценарії.** Чи справді Select спрощує роботу користувача?

## 22. Практичний мініпроєкт: форма створення курсу

Створи форму для освітньої платформи.

### Завдання

Поля форми:

- Назва курсу — Input.
- Категорія — Select.
- Рівень складності — Select.
- Викладач — Searchable Select, якщо викладачів багато.
- Навчальні предмети — Multi-select, якщо курс може належати до кількох предметів.
- Опис — Textarea.

### Етап 1. Структура

    Створення курсу

    Назва курсу
    [____________________________]

    Категорія
    [Виберіть категорію        ▼]

    [Початковий                ▼]

    Викладач
    [Знайдіть викладача...     ▼]

    [Математика ×] [Інформатика ×] [▼]

    Опис
    [____________________________]
    [____________________________]

    [Створити курс]

### Етап 2. Категорії

Створи список:

- Програмування;
- Дизайн;
- Математика;
- Іноземні мови;
- Природничі науки.

Перевір, чи назви короткі й зрозумілі.

### Етап 3. Рівні складності

Використай:

- Початковий;
- Середній;
- Просунутий.

Подумай, чи потрібен Select, чи Radio group буде зручнішим для трьох видимих варіантів.

### Етап 4. Стани

Для кожного Select передбач:

- звичайний стан;
- Focus;
- Open;
- Selected;
- Disabled;
- Error;
- Loading, якщо дані надходять із сервера;
- Empty, якщо варіантів немає.

### Етап 5. Поведінка

Переконайся, що:

- вибраний варіант відображається у полі;
- список відкривається передбачувано;
- можна змінити вибір;
- залежні поля оновлюються;
- помилки зрозумілі;
- Multi-select правильно показує вибрані значення.

### Етап 6. Адаптивність

Перевір:

- ширину поля на телефоні;
- довгі назви;
- висоту списку;
- прокручування;
- роботу пошуку з екранною клавіатурою;
- закриття списку після вибору.

### Структура

- [ ] Призначення поля зрозуміле.
- [ ] Label пов'язаний із компонентом.
- [ ] Placeholder не сприймається як вибране значення.
- [ ] Поточний вибір легко прочитати.
- [ ] Назви варіантів однозначні.
- [ ] Порядок варіантів логічний.

### Візуальний дизайн

- [ ] Висота та ширина відповідають сценарію.
- [ ] Внутрішні відступи комфортні.
- [ ] Індикатор відкриття помітний.
- [ ] Focus відрізняється від Default.
- [ ] Open state має чітку структуру.
- [ ] Selected state зрозумілий.
- [ ] Disabled state не створює плутанини.
- [ ] Довгі назви не перекривають інші елементи.

- [ ] Вибір можна змінити.
- [ ] Клавіатурна навігація працює.
- [ ] Доступні повідомлення про помилки.
- [ ] Завантаження та порожній результат обробляються.
- [ ] Залежні значення оновлюються правильно.
- [ ] Multi-select не перевантажує інтерфейс.

### Доступність

- [ ] Компонент має доступну назву.
- [ ] Фокус добре помітний.
- [ ] Клавіатурна взаємодія перевірена.
- [ ] Вибір не передається лише кольором.

- [ ] Область натискання достатня.

## 24. Що потрібно запам'ятати

1. **Select призначений для вибору значень зі списку.** Він не є універсальним рішенням для всіх варіантів взаємодії.
2. **Dropdown і Select — не синоніми.** Dropdown може бути меню дій, а Select — полем вибору значення.
3. **Combobox корисний для пошуку.** Особливо коли список великий.
4. **Multi-select потрібен лише тоді, коли дозволений множинний вибір.** Його не варто використовувати без потреби.
5. **Label повинен залишатися зрозумілим.** Placeholder не замінює назву поля.
6. **Вибраний пункт має бути помітним.** Не покладайся лише на колір.
7. **Доступність важлива для кастомних компонентів.** Потрібно враховувати клавіатуру, фокус і допоміжні технології.
8. **Нативний Select часто є хорошою відправною точкою.** Кастомний варіант потребує більше роботи.
9. **Залежні поля повинні залишатися узгодженими.** Зміна попереднього значення може вимагати очищення наступних.
10. **Порожній стан теж є частиною дизайну.** Користувач повинен розуміти, що відбувається.
11. **Великі списки потребують пошуку або групування.** Не змушуй користувача переглядати сотні пунктів без допомоги.
12. **Дизайн-система забезпечує послідовність.** Стандартизуй розміри, стани, кольори та правила поведінки.

## 27. Місце теми в UI Design

`05-components/04-selects` — частина розділу **Components**, присвяченого повторно використовуваним елементам інтерфейсу.

Тема пов'язана з:

- `02-layout-and-composition` — розташуванням Select у формах і фільтрах;
- `03-color` — кольорами станів, контрастом і візуальним виділенням вибору;
- `04-typography` — читабельністю назв та довгих варіантів;
- `05-components/01-buttons` — діями підтвердження й очищення;
- `05-components/02-links` — навігаційними посиланнями в меню;
- `05-components/03-inputs` — текстовими полями та пошуком;
- Forms and Accessibility — доступністю, валідацією та клавіатурною взаємодією;
- React / Next.js — реалізацією компонентів і керуванням станом;
- дизайн-системами — токенами, варіантами й повторним використанням компонентів.

**Головний принцип:** якісний Select не просто показує список варіантів. Він допомагає користувачеві швидко знайти потрібне значення, зрозуміти поточний вибір, виправити помилку й успішно завершити дію.
