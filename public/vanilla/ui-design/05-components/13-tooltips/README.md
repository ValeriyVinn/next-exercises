# 13. Tooltips — Спливаючі підказки

Tooltip — це невеликий елемент інтерфейсу, який з'являється біля кнопки, іконки або іншого компонента та пояснює його призначення, показує коротку підказку або додаткову інформацію.

Tooltip зазвичай з'являється, коли користувач наводить курсор на елемент, переводить на нього клавіатурний фокус або активує його іншим передбаченим способом.

Основне завдання tooltip — допомогти користувачу зрозуміти інтерфейс, не перевантажуючи його постійно видимим текстом.

---

## 1. Для чого потрібні Tooltips

Tooltips допомагають пояснити елементи, призначення яких не очевидне з першого погляду.

Приклади:

- пояснення іконки без текстового підпису;
- уточнення призначення кнопки;
- пояснення скорочення або спеціального терміна;
- коротке уточнення параметра у формі;
- підказка щодо формату введення;
- опис функції у панелі інструментів;
- пояснення значення показника в інформаційній панелі.

### Приклад

У редакторі є кнопка з іконкою дискети.

    [💾]

Користувач може не знати, що саме робить ця кнопка.

Підказка:

    Зберегти зміни

Tooltip пояснює призначення кнопки, не потребуючи постійного текстового підпису.

### Коли tooltip особливо корисний

- коли інтерфейс містить багато компактних іконок;
- коли потрібно пояснити незвичний елемент;
- коли додатковий текст потрібен не всім користувачам;
- коли постійно видимий опис зайняв би забагато місця.

### Коли tooltip не потрібен

Не варто додавати tooltip до кожного елемента.

Якщо кнопка має зрозумілий текст «Зберегти», додаткова підказка «Зберегти» зазвичай нічого не додає.

---

## 2. Tooltip, Popover, Modal та Toast

Ці компоненти можуть з'являтися поверх інтерфейсу, але виконують різні завдання.

### Tooltip

Надає коротку інформацію про елемент.

Приклад:

    [i] → Пояснення параметра

Типові характеристики:

- короткий текст;
- невеликий розмір;
- не містить складної взаємодії;
- зазвичай не має власних кнопок або полів форми.

### Popover

Показує додатковий вміст біля елемента.

Приклад:

    [Налаштування]
          ↓
    ┌───────────────────┐
    │ Розмір: [Середній]│
    │ Колір:  [Синій]   │
    │       [Зберегти]  │
    └───────────────────┘

Popover може містити інтерактивні елементи, перемикачі, меню або форму.

### Modal

Перериває звичайну взаємодію зі сторінкою та переводить увагу на окреме завдання.

Приклад:

    Видалити запис?

    [Скасувати] [Видалити]

### Toast

Коротко повідомляє про результат дії.

Приклад:

    ✓ Зміни збережено

Toast зазвичай не потребує взаємодії з користувачем.

### Що запам'ятати

- Tooltip — коротке пояснення.
- Popover — додатковий вміст або невелика взаємодія.
- Modal — окреме завдання поверх сторінки.
- Toast — повідомлення про результат.

Якщо підказка містить посилання, кнопки, поля введення або складну інформацію, краще розглянути popover чи інший компонент.

## 3. Основні типи Tooltips

### 3.1. Informational tooltip

Інформаційна підказка пояснює призначення елемента.

Приклад:

    [i]

    Підказка:
    Цей параметр визначає кількість записів на сторінці.

### 3.2. Icon tooltip

Пояснює іконку без текстового підпису.

Приклади:

    [✎] → Редагувати
    [🗑] → Видалити
    [?] → Довідка
    [↻] → Оновити

Важливо: якщо дія критична, наприклад видалення, підказка не замінює зрозумілу назву доступну для допоміжних технологій.

### 3.3. Definition tooltip

Пояснює спеціальний термін.

Приклад:

    API [?]

    Підказка:
    Інтерфейс програмування застосунків,
    через який різні системи обмінюються даними.

### 3.4. Form tooltip

Допомагає зрозуміти поле форми або параметр.

Приклад:

    Пароль [?]

    Підказка:
    Використайте щонайменше 12 символів.

Важливо розрізняти tooltip і постійну інструкцію до поля. Якщо інформація необхідна для правильного заповнення форми, краще показати її безпосередньо біля поля, а не приховувати в підказці.

### 3.5. Data tooltip

Пояснює показник, скорочення або дані в інформаційній панелі.

Приклад:

    Активні користувачі [?]

    Підказка:
    Кількість користувачів, які входили
    в систему протягом останніх 30 днів.

### 3.6. Keyboard shortcut tooltip

Показує комбінацію клавіш.

Приклад:

    [Зберегти]

    Підказка:
    Ctrl + S

На пристроях Apple зазвичай використовують `⌘ Command + S`.

## 4. Анатомія Tooltip

Типовий tooltip складається з кількох частин.

    [Кнопка]
        ↓
    ┌──────────────────────┐
    │ Зберегти зміни       │
    └───────────▼──────────┘
                ▲
              стрілка

### 4.1. Trigger

Trigger — елемент, який викликає підказку.

Ним може бути:

- кнопка;
- іконка;
- текстовий елемент;
- поле форми;
- елемент панелі інструментів.

Для стандартного tooltip часто використовують наведення курсора та клавіатурний фокус.

### 4.2. Tooltip container

Контейнер містить текст підказки.

Типові CSS-властивості:

- `position`;
- `padding`;
- `background`;
- `color`;
- `border-radius`;
- `font-size`;
- `line-height`;
- `max-width`;
- `z-index`.

### 4.3. Tooltip text

Текст повинен бути коротким, конкретним і зрозумілим.

Добре:

    Відкрити налаштування

Гірше:

    Тут можна натиснути, щоб відкрити
    різні налаштування цього елемента.

### 4.4. Arrow

Arrow — маленький декоративний трикутник, який указує на елемент, до якого належить підказка.

Стрілка не є обов'язковою. Її можна не використовувати, якщо розташування підказки й так зрозуміле.

### 4.5. Position

Позиція визначає, де з'явиться підказка:

- зверху;
- знизу;
- ліворуч;
- праворуч.

Розташування залежить від доступного простору та дизайну.

## 5. Основні принципи дизайну Tooltips

### 5.1. Короткий текст

Tooltip не повинен перетворюватися на довгу статтю.

Погано:

    Ця кнопка дозволяє користувачу
    зберегти зміни, які він зробив
    у формі редагування налаштувань.

Краще:

    Зберегти зміни

Якщо потрібне докладне пояснення, використай popover, довідкову панель або окрему сторінку.

### 5.2. Однозначність

Підказка повинна пояснювати конкретний елемент або дію.

Погано:

    Виконати дію

Краще:

    Завантажити файл

### 5.3. Контраст

Текст повинен залишатися читабельним на тлі контейнера.

Приклад:

    background: #222;
    color: #fff;

Не покладайся лише на колір для передавання значення.

### 5.4. Достатній розмір тексту

Tooltip часто має менший текст, ніж основний вміст сторінки, але він усе одно повинен бути читабельним.

Наприклад:

    font-size: 0.875rem;
    line-height: 1.4;

Це орієнтир, а не універсальна вимога. Перевіряй підказки зі збільшенням масштабу сторінки.

### 5.5. Відступи

Приклад:

    padding: 8px 12px;

Відступи повинні створювати простір навколо тексту, але не робити коротку підказку надмірно великою.

### 5.6. Заокруглення

Приклад:

    border-radius: 6px;

Стиль повинен узгоджуватися з іншими компонентами дизайн-системи.

### 5.7. Тінь

Тінь може допомогти відокремити tooltip від фону.

    box-shadow: 0 4px 12px rgb(0 0 0 / 15%);

Використовуй її помірно.

### 5.8. Не перекривати важливий вміст

Tooltip не повинен без потреби закривати кнопку, поле форми або інший важливий елемент.

Якщо простору недостатньо, підказка повинна мати можливість змінити розташування.

## 6. Позиціювання Tooltip у CSS

Для простого tooltip часто використовують `position: relative` на контейнері та `position: absolute` на підказці.

### HTML

    <div class="tooltip-wrapper">
      <button type="button" class="tooltip-trigger">
        Зберегти
      </button>

      <span class="tooltip">
        Зберегти зміни
      </span>
    </div>

### CSS

    .tooltip-wrapper {
      position: relative;
      display: inline-flex;
    }

    .tooltip {
      position: absolute;
      bottom: calc(100% + 8px);
      left: 50%;
      transform: translateX(-50%);

      width: max-content;
      max-width: 240px;

      padding: 8px 12px;
      border-radius: 6px;

      background: #222;
      color: #fff;

      font-size: 0.875rem;
      line-height: 1.4;
      text-align: center;

      opacity: 0;
      visibility: hidden;
      pointer-events: none;

      z-index: 100;
    }

    .tooltip-wrapper:hover .tooltip,
    .tooltip-wrapper:focus-within .tooltip {
      opacity: 1;
      visibility: visible;
    }

### Як це працює

- `position: relative` створює контекст позиціювання.
- `position: absolute` дозволяє розташувати підказку відносно контейнера.
- `bottom: calc(100% + 8px)` розміщує її над елементом.
- `left: 50%` задає початкову точку по горизонталі.
- `transform: translateX(-50%)` центрує tooltip.
- `opacity` керує прозорістю.
- `visibility` керує видимістю елемента.
- `pointer-events: none` не дозволяє миші взаємодіяти з декоративною підказкою.

**Важливо:** цей приклад демонструє базове CSS-позиціювання. Він не вирішує автоматично проблему виходу підказки за межі viewport і не реалізує всі вимоги доступності.

## 7. Hover, Focus та Click

Tooltip може відкриватися різними способами.

### 7.1. Hover

Підказка з'являється, коли користувач наводить курсор.

    .tooltip-wrapper:hover .tooltip {
      opacity: 1;
      visibility: visible;
    }

Це звичайний сценарій для пристроїв із мишею.

### 7.2. Focus

Підказка з'являється, коли елемент отримує клавіатурний фокус.

    .tooltip-wrapper:focus-within .tooltip {
      opacity: 1;
      visibility: visible;
    }

Це допомагає користувачам, які навігують за допомогою клавіатури.

### 7.3. Click

Підказка відкривається після натискання.

Такий підхід може бути корисним на сенсорних пристроях, де наведення курсора відсутнє.

Однак якщо користувач повинен натискати на елемент, щоб відкрити й закрити додатковий вміст, компонент може вже бути ближчим до popover.

### 7.4. Touch

На сенсорних екранах не можна покладатися лише на `:hover`.

Якщо інформація важлива, зроби її постійно видимою або передбач явну взаємодію з доступною кнопкою.

**Правило:** базова інформація, необхідна для виконання дії, не повинна бути доступною лише через наведення курсора.

## 8. Tooltip з CSS та псевдоелементами

Для простого текстового tooltip можна використати `data-tooltip` та псевдоелемент `::after`.

### HTML

    <button
      type="button"
      class="icon-button"
      data-tooltip="Відкрити налаштування"
      aria-label="Відкрити налаштування"
    >
      ⚙
    </button>

### CSS

    .icon-button {
      position: relative;

      width: 44px;
      height: 44px;

      border: 0;
      border-radius: 8px;

      background: #eee;
      color: #222;

      font: inherit;
      cursor: pointer;
    }

    .icon-button::after {
      content: attr(data-tooltip);

      position: absolute;
      bottom: calc(100% + 8px);
      left: 50%;
      transform: translateX(-50%);

      width: max-content;
      max-width: 240px;

      padding: 8px 12px;
      border-radius: 6px;

      background: #222;
      color: #fff;

      font-size: 0.875rem;
      line-height: 1.4;

      opacity: 0;
      visibility: hidden;
      pointer-events: none;

      z-index: 100;
    }

    .icon-button:hover::after,
    .icon-button:focus-visible::after {
      opacity: 1;
      visibility: visible;
    }

### Переваги

- мінімум HTML;
- не потрібен окремий елемент tooltip;
- текст можна зберігати в `data-tooltip`;
- легко застосовувати до набору іконок.

### Обмеження

- складніше реалізувати складну логіку позиціювання;
- псевдоелемент не підходить для інтерактивного вмісту;
- складно керувати життєвим циклом і станом;
- потрібно окремо продумати доступність;
- підказка може виходити за межі екрана.

Для складних сценаріїв краще використати окремий компонент або готове рішення.

---

## 9. Стрілка Tooltip

Стрілку можна створити через CSS-властивість `border`.

### CSS

    .tooltip::after {
      content: "";

      position: absolute;
      top: 100%;
      left: 50%;
      transform: translateX(-50%);

      border: 6px solid transparent;
      border-top-color: #222;
    }

Цей приклад підходить для tooltip, розташованого над елементом.

Якщо підказка розміщена знизу, потрібно змінити напрямок стрілки.

### Варіант без стрілки

Багато сучасних інтерфейсів використовують tooltip без стрілки.

Це спрощує стилізацію та зменшує кількість декоративних елементів.

## 10. Анімація Tooltip

Підказка може з'являтися плавно.

### CSS

    .tooltip {
      opacity: 0;
      visibility: hidden;
      transform: translateY(4px);

      transition:
        opacity 150ms ease,
        transform 150ms ease,
        visibility 150ms;
    }

    .tooltip-wrapper:hover .tooltip,
    .tooltip-wrapper:focus-within .tooltip {
      opacity: 1;
      visibility: visible;
      transform: translateY(0);
    }

У цьому прикладі початкове `transform` змінюється під час появи підказки. Якщо одночасно використовується горизонтальне центрування через `translateX(-50%)`, потрібно поєднати обидва трансформаційні ефекти, а не перезаписувати один іншим.

### Підтримка reduced motion

    @media (prefers-reduced-motion: reduce) {
      .tooltip {
        transition: none;
      }
    }

Анімація повинна бути короткою та не заважати швидкій взаємодії.

## 11. Доступність Tooltip (Accessibility)

Tooltip має бути корисним не лише для користувачів миші.

### 11.1. Підказка не повинна бути доступна лише через hover

Користувач клавіатури повинен мати можливість отримати підказку через фокус.

    .tooltip-wrapper:hover .tooltip,
    .tooltip-wrapper:focus-within .tooltip {
      opacity: 1;
      visibility: visible;
    }

Для простого CSS-сценарію це початок, але не повна реалізація доступного tooltip.

### 11.2. Доступна назва іконки

Якщо кнопка містить лише іконку, вона повинна мати зрозумілу доступну назву.

    <button
      type="button"
      aria-label="Відкрити налаштування"
    >
      ⚙
    </button>

Tooltip не завжди замінює доступну назву кнопки. Для елементів керування потрібно забезпечувати зрозумілу назву незалежно від того, чи відкрито підказку.

### 11.3. `aria-describedby`

Атрибут `aria-describedby` може пов'язати елемент із текстом підказки.

    <button
      type="button"
      aria-label="Зберегти"
      aria-describedby="save-tooltip"
    >
      💾
    </button>

    <span id="save-tooltip" role="tooltip">
      Зберегти зміни
    </span>

Це лише приклад семантичного зв'язку. Щоб підказка працювала правильно, потрібно також реалізувати її візуальне відкриття та закриття.

Не слід бездумно використовувати `aria-describedby` для прихованого тексту в усіх сценаріях. Перевіряй, як компонент озвучується допоміжними технологіями.

### 11.4. `role="tooltip"`

Для елемента підказки можна використати:

    <div role="tooltip">
      Зберегти зміни
    </div>

Роль повідомляє допоміжним технологіям, що цей елемент є підказкою.

Вона сама по собі не забезпечує доступність, керування фокусом або правильну поведінку на сенсорних пристроях.

### 11.5. Tooltip не повинен містити інтерактивні елементи

Класичний tooltip призначений для короткого пояснювального тексту.

Не розміщуй у ньому:

- кнопки;
- посилання, які потрібно активувати;
- поля форми;
- перемикачі;
- складні інтерактивні меню.

Для таких випадків використовуй popover або інший компонент.

### 11.6. Користувач повинен встигнути прочитати підказку

Підказка не повинна зникати надто швидко, коли користувач намагається перевести курсор на сам tooltip або прочитати текст.

Якщо підказка перекриває інший вміст, важливо забезпечити передбачувану поведінку при наведенні, фокусі та закритті.

### 11.7. Контраст і масштабування

Перевір:

- контраст тексту;
- розмір шрифту;
- довгі слова;
- збільшення масштабу;
- поведінку на вузькому екрані;
- видимість підказки при клавіатурній навігації.

---

## 12. Правила поведінки Tooltip

Під час проєктування потрібно визначити, коли саме підказка з'являється і зникає.

### Типовий сценарій

1. Користувач наводить курсор на елемент.
2. Після невеликої затримки з'являється tooltip.
3. Користувач читає текст.
4. Підказка зникає після завершення взаємодії.

### Затримка появи

Затримка може зменшити кількість випадкових появ підказок, коли користувач просто переміщує курсор.

Але занадто велика затримка створює відчуття повільного інтерфейсу.

Для простого CSS-tooltip затримку можна реалізувати через `transition-delay`. Для складнішої логіки потрібен JavaScript або компонентна бібліотека.

### Закриття

Tooltip зазвичай закривається, коли:

- курсор залишає trigger;
- клавіатурний фокус залишає trigger;
- користувач переходить до іншої взаємодії.

Поведінка залежить від реалізації. Важливо уникати ситуації, коли підказка зникає раніше, ніж користувач може прочитати її текст.

### Клавіша Escape

Для доступних підказок варто передбачити зрозумілий спосіб закриття, зокрема `Escape`, якщо підказка залишається відкритою або перекриває інший вміст.

Для дуже простого CSS-tooltip окреме керування `Escape` може бути недоступним без JavaScript.

---

## 13. Tooltip та адаптивність

Tooltip повинен залишатися видимим на різних розмірах екрана.

### Desktop

Зазвичай використовують:

- появу при наведенні;
- появу при клавіатурному фокусі;
- позиціювання біля trigger;
- короткий текст.

### Tablet

Потрібно перевірити:

- чи не виходить tooltip за межі екрана;
- чи не перекриває він важливий вміст;
- чи можна його відкрити без наведення.

### Mobile

На сенсорних пристроях немає звичайного hover.

Можливі рішення:

- показувати необхідне пояснення постійно;
- відкривати коротку підказку після натискання;
- використовувати popover, якщо потрібна взаємодія;
- додавати текстові підписи до важливих іконок.

Не змушуй користувача відкривати підказку, щоб дізнатися інформацію, необхідну для виконання основної дії.

### Приклад адаптивного CSS

    .tooltip {
      max-width: min(240px, calc(100vw - 32px));
      overflow-wrap: anywhere;
    }

Це обмежує ширину тексту, але не гарантує, що підказка автоматично змінить сторону, якщо біля краю екрана недостатньо місця.

Для надійного позиціювання у складних інтерфейсах потрібна додаткова логіка.

---

## 14. Tooltip у JavaScript

JavaScript потрібен, коли підказка повинна:

- відкриватися за натисканням;
- мати затримку;
- реагувати на `Escape`;
- змінювати розташування;
- синхронізувати стан між кількома елементами;
- враховувати складні сценарії доступності.

### HTML

    <button
      type="button"
      id="help-trigger"
      aria-describedby="help-tooltip"
    >
      Довідка
    </button>

    <span
      id="help-tooltip"
      role="tooltip"
      hidden
    >
      Відкрити довідкову інформацію
    </span>

### JavaScript

    const trigger = document.querySelector("#help-trigger");
    const tooltip = document.querySelector("#help-tooltip");

    if (
      trigger instanceof HTMLButtonElement &&
      tooltip instanceof HTMLSpanElement
    ) {
      function showTooltip() {
        tooltip.hidden = false;
      }

      function hideTooltip() {
        tooltip.hidden = true;
      }

      trigger.addEventListener("mouseenter", showTooltip);
      trigger.addEventListener("mouseleave", hideTooltip);

      trigger.addEventListener("focus", showTooltip);
      trigger.addEventListener("blur", hideTooltip);

      trigger.addEventListener("keydown", (event) => {
        if (event.key === "Escape") {
          hideTooltip();
        }
      });
    }

Це навчальний приклад. У реальному компоненті потрібно врахувати, як підказка поводиться, коли користувач переводить курсор між trigger і tooltip, а також як працюють touch-пристрої та допоміжні технології.

Крім того, якщо закриття tooltip через `Escape` має зберігатися до завершення поточної взаємодії, знадобиться окремий стан, який відрізняє закриття користувачем від звичайного виходу курсора.

## 15. Tooltip у React

У React стан підказки можна контролювати через `useState`.

### Приклад

    "use client";

    import { useState } from "react";

    export default function TooltipExample() {
      const [isVisible, setIsVisible] = useState(false);

      return (
        <div className="tooltip-wrapper">
          <button
            type="button"
            aria-describedby="example-tooltip"
            onMouseEnter={() => setIsVisible(true)}
            onMouseLeave={() => setIsVisible(false)}
            onFocus={() => setIsVisible(true)}
            onBlur={() => setIsVisible(false)}
          >
            Довідка
          </button>

          {isVisible && (
            <span
              id="example-tooltip"
              role="tooltip"
              className="tooltip"
            >
              Відкрити довідкову інформацію
            </span>
          )}
        </div>
      );
    }

### Як це працює

1. `isVisible` зберігає стан видимості.
2. Початкове значення `false` означає, що підказка не показується.
3. Наведення курсора встановлює `true`.
4. Клавіатурний фокус також встановлює `true`.
5. Вихід курсора або фокусу встановлює `false`.
6. Умовний рендеринг додає або прибирає tooltip.

### Що потрібно врахувати

Це мінімальний навчальний приклад.

Для повноцінного компонента можуть знадобитися:

- затримка появи;
- обробка `Escape`;
- робота з touch-пристроями;
- позиціювання відносно viewport;
- узгоджена поведінка для миші та клавіатури;
- уникнення непотрібних повторних рендерів;
- правильний зв'язок між trigger і tooltip.

Не додавай `onClick` до tooltip лише для того, щоб він виглядав інтерактивним. Якщо в ньому є кнопки чи інші дії, це вже інший тип компонента.

## 16. Tooltip у Next.js

У Next.js App Router простий tooltip можна стилізувати через CSS, а інтерактивну поведінку реалізувати в Client Component.

Приклад структури:

    app/
    ├── page.tsx
    └── components/
        └── Tooltip.tsx

### `Tooltip.tsx`

    "use client";

    import { useState } from "react";

    type TooltipProps = {
      label: string;
      children: React.ReactNode;
    };

    export default function Tooltip({
      label,
      children,
    }: TooltipProps) {
      const [isVisible, setIsVisible] = useState(false);

      return (
        <span className="tooltip-wrapper">
          <span
            className="tooltip-trigger"
            onMouseEnter={() => setIsVisible(true)}
            onMouseLeave={() => setIsVisible(false)}
            onFocus={() => setIsVisible(true)}
            onBlur={() => setIsVisible(false)}
          >
            {children}
          </span>

          {isVisible && (
            <span
              role="tooltip"
              className="tooltip"
            >
              {label}
            </span>
          )}
        </span>
      );
    }

### Важливе зауваження щодо прикладу

Це демонстрація типізованих props і керування станом, а не готовий універсальний компонент.

У production-реалізації потрібно перевірити, чи `children` є інтерактивним елементом, і забезпечити коректне передавання фокусу та подій. Не можна автоматично вважати будь-який дочірній елемент доступним trigger.

Для компонента, що використовується з кнопками, полями або іншими інтерактивними елементами, краще спроєктувати API так, щоб доступна назва, `aria-describedby` і події працювали передбачувано.

### Використання

    <Tooltip label="Зберегти зміни">
      <button type="button">
        Зберегти
      </button>
    </Tooltip>

Для такого API потрібно окремо забезпечити, щоб `aria-describedby` був прив'язаний саме до кнопки, а не лише до зовнішньої оболонки.

### Коли використовувати бібліотеку

Якщо застосунок має багато tooltip, складні вимоги до позиціювання та доступності, доцільно розглянути перевірену бібліотеку.

Це може зменшити кількість помилок у роботі з:

- клавіатурою;
- viewport;
- затримками;
- touch-пристроями;
- вкладеними компонентами;
- доступними атрибутами.

## 19. Типові помилки

### Помилка 1. Tooltip доступний лише через hover

Користувач клавіатури не може побачити підказку.

**Рішення:** передбачити появу при фокусі.

### Помилка 2. Tooltip містить забагато тексту

Користувачеві важко прочитати довге повідомлення.

**Рішення:** скоротити текст або використати popover чи довідкову панель.

### Помилка 3. Важлива інформація прихована в tooltip

Користувач може не здогадатися, що підказка існує.

**Рішення:** необхідні інструкції показувати постійно.

### Помилка 4. Немає доступної назви іконки

Кнопка з іконкою не має зрозумілої назви для читача екрана.

**Рішення:** додати `aria-label` або інший відповідний механізм доступної назви.

### Помилка 5. Tooltip виходить за межі екрана

Підказка обрізається або частково зникає.

**Рішення:** обмежити ширину та реалізувати зміну позиції для вузьких екранів.

### Помилка 6. Підказка зникає надто швидко

Користувач не встигає прочитати текст.

**Рішення:** перевірити затримки, поведінку курсора та умови закриття.

### Помилка 7. У tooltip розміщені кнопки

Користувач не може взаємодіяти з ними належним чином.

**Рішення:** використати popover або інший інтерактивний компонент.

### Помилка 8. Tooltip дублює текст кнопки

Підказка не додає нової інформації.

**Рішення:** залишати tooltip лише там, де він справді корисний.

### Помилка 9. Використано лише колір для передавання значення

Користувач не розуміє стан або призначення елемента.

**Рішення:** додати текстове пояснення або інший зрозумілий сигнал.

### Помилка 10. Tooltip не працює на сенсорних пристроях

На смартфоні користувач не може відкрити підказку.

**Рішення:** зробити пояснення видимим або використати відповідний механізм натискання.

### Помилка 11. CSS-анімація перезаписує transform

Підказка перестає центруватися, коли додається анімація.

**Рішення:** об'єднати необхідні трансформації або використати окрему внутрішню обгортку.

### Помилка 12. `role="tooltip"` використано як єдине рішення доступності

Підказка має правильну роль, але не працює з клавіатурою або не пов'язана з trigger.

**Рішення:** реалізувати повну поведінку компонента, а не лише додавати ARIA-атрибути.

## 23. Що потрібно запам'ятати

✔ Tooltip — компактна підказка, яка пояснює елемент або дію.

✔ Tooltip не призначений для складних форм або інтерактивного вмісту.

✔ Popover підходить для додаткового вмісту та взаємодії.

✔ Tooltip зазвичай відкривається при наведенні та клавіатурному фокусі.

✔ На сенсорних пристроях не можна покладатися лише на `:hover`.

✔ Для простого позиціювання використовують `position: relative` та `position: absolute`.

✔ `data-tooltip` і `::after` дозволяють створити просту підказку без додаткового HTML-елемента.

✔ `role="tooltip"` визначає роль елемента, але не реалізує його поведінку.

✔ `aria-describedby` може пов'язати trigger із текстом підказки.

✔ Кнопка з іконкою повинна мати доступну назву незалежно від tooltip.

✔ Інформацію, необхідну для виконання завдання, краще показувати постійно.

✔ Tooltip повинен залишатися читабельним при збільшенні масштабу та на вузькому екрані.

✔ У React стан можна контролювати через `useState`, але для повноцінного компонента потрібно також продумати доступність і позиціювання.

✔ У TypeScript описуй props явно та уникай `any`.

✔ У дизайн-системі варто стандартизувати кольори, відступи, типографіку та правила поведінки tooltip.

## 25. Рівні опанування

### Рівень 1 — Basic

- розумію призначення tooltip;
- відрізняю tooltip від popover і modal;
- можу створити просту підказку через HTML та CSS;
- знаю принципи позиціювання;
- можу налаштувати кольори, відступи та типографіку.

### Рівень 2 — Practical

- реалізую появу при hover і focus;
- використовую `data-tooltip` та псевдоелементи;
- забезпечую доступну назву кнопок;
- перевіряю контраст і адаптивність;
- розумію обмеження CSS-only підходу.

### Рівень 3 — React / Next.js

- створюю повторно використовуваний компонент;
- описую props через TypeScript;
- реалізую різні варіанти розташування;
- керую видимістю через стан;
- перевіряю поведінку на клавіатурі й сенсорних пристроях.

### Рівень 4 — Production

- забезпечую надійну доступність;
- враховую межі viewport;
- реалізую передбачуване закриття;
- враховую reduced motion;
- тестую різні браузери й розміри екрана;
- використовую перевірені бібліотеки, якщо власна реалізація стає надто складною.
