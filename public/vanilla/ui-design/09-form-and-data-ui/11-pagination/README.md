# 11. Pagination — Пагінація в інтерфейсах

> Pagination — пагінація, або розбиття великого набору даних на окремі сторінки. Вона дозволяє користувачеві переглядати результати частинами, переходити між сторінками та розуміти, де він перебуває в загальному списку.
>
> Мета пагінації — зробити роботу з великими наборами даних зрозумілою, передбачуваною та зручною.

---

## 1. Що таке Pagination

Pagination — це UI-компонент, який розділяє великий список даних на кілька сторінок.

Наприклад, інтернет-магазин містить 240 товарів. Замість відображення всіх товарів на одній сторінці можна показувати по 24 товари.

    Усього товарів: 240
    Товарів на сторінці: 24
    Кількість сторінок: 10

    [← Попередня] [1] [2] [3] ... [10] [Наступна →]

Користувач може перейти на потрібну сторінку та переглядати товари частинами.

### Де використовують пагінацію

- інтернет-магазини;
- каталоги курсів;
- блоги та новинні сайти;
- таблиці адміністративних панелей;
- CRM-системи;
- списки користувачів;
- результати пошуку;
- електронні журнали;
- бібліотеки документів;
- історії замовлень;
- списки повідомлень.

### Головні завдання Pagination

- розділити великий набір даних;
- показати поточну сторінку;
- дозволити перейти до іншої сторінки;
- показати загальну кількість сторінок або записів;
- забезпечити зрозумілу навігацію;
- зберігати передбачуваність інтерфейсу під час переходів.

**Запам'ятай:** пагінація — це не просто набір кнопок із цифрами, а спосіб керування переглядом великих наборів даних.

---

## 2. Pagination, Infinite Scroll і Load More

Це три різні способи показувати великі набори даних.

### 2.1. Pagination — пагінація

    Сторінка 1
    Елементи 1–20

    [1] [2] [3] [4] [5] [Наступна →]

Користувач сам переходить між сторінками.

Підходить для:

- таблиць;
- каталогів товарів;
- результатів пошуку;
- адміністративних панелей;
- списків, де важливо переходити до конкретної частини даних.

### 2.2. Infinite Scroll — нескінченна прокрутка

    Елементи 1–20
    Елементи 21–40
    Елементи 41–60
    ...

Нові елементи автоматично завантажуються під час прокручування сторінки.

Підходить для:

- соціальних стрічок;
- фотогалерей;
- стрічок новин;
- контенту, який користувач досліджує без чіткої кінцевої мети.

Недоліки:

- складніше повернутися до конкретного місця;
- важче дістатися до футера;
- позицію прокручування може бути складно відновити;
- навігація за конкретними сторінками відсутня або прихована.

### 2.3. Load More — кнопка «Завантажити ще»

    Елементи 1–20

    [Завантажити ще]

    Елементи 21–40

Користувач натискає кнопку, щоб завантажити наступну порцію даних.

Підходить для:

- каталогів;
- стрічок контенту;
- галерей;
- списків рекомендацій.

### Порівняння

| Критерій | Pagination | Infinite Scroll | Load More |
|---|---|---|---|
| Перехід до конкретної сторінки | Так | Зазвичай ні | Зазвичай ні |
| Контроль користувача | Високий | Нижчий | Середній |
| Зрозуміле положення в списку | Так | Складніше | Частково |
| Збереження позиції | Передбачуване за правильної реалізації | Потребує уваги | Потребує уваги |
| Підходить для таблиць | Так | Рідко | Іноді |
| Підходить для соціальної стрічки | Іноді | Так | Так |

Не існує одного найкращого рішення для всіх продуктів. Вибір залежить від завдання користувача та характеру даних.

---

## 3. Анатомія компонента Pagination

Типова пагінація складається з кількох елементів.

    ┌────────────────────────────────────────────────────┐
    │ Показано 1–20 із 240                               │
    │                                                    │
    │ [←] [1] [2] [3] [...] [12] [→]                    │
    └────────────────────────────────────────────────────┘

### Основні елементи

1. **Previous button** — перехід на попередню сторінку.
2. **Page number** — номер сторінки.
3. **Current page** — поточна сторінка.
4. **Next button** — перехід на наступну сторінку.
5. **First page** — перехід на першу сторінку, якщо він потрібний.
6. **Last page** — перехід на останню сторінку, якщо він потрібний.
7. **Ellipsis** — три крапки, які позначають пропущені номери сторінок.
8. **Page size selector** — вибір кількості елементів на сторінці.
9. **Result count** — загальна кількість знайдених елементів.
10. **Range indicator** — діапазон елементів, показаних на поточній сторінці.

Не кожна пагінація повинна містити всі ці елементи.

Для невеликого списку може бути достатньо номерів сторінок і кнопок переходу.

---

## 4. Page numbers — номери сторінок

Номери сторінок дозволяють перейти безпосередньо до певної частини набору даних.

Приклад:

    [1] [2] [3] [4] [5]

Якщо сторінок мало, можна показати всі номери.

Якщо сторінок багато, показувати їх усі недоцільно.

Приклад:

    [1] [2] [3] [...] [20]

### UX-правила

- поточна сторінка повинна бути помітною;
- номери мають бути впорядкованими;
- активний номер не повинен плутатися з кнопкою переходу;
- інтерактивні елементи повинні мати достатню область натискання;
- порядок переходів має бути передбачуваним.

### Поточна сторінка

Приклад:

    [1] [2] [3] [4] [5]

    Поточна сторінка: 3

Номер `3` потрібно візуально відрізнити від інших номерів.

Це можна зробити за допомогою:

- кольору фону;
- рамки;
- контрасту тексту;
- додаткового позначення;
- доступного атрибута `aria-current="page"` у HTML.

Не покладайся лише на колір, якщо активний стан можна додатково позначити іншими засобами.

---

## 5. Previous і Next — попередня та наступна сторінки

Кнопки Previous і Next дозволяють послідовно переглядати сторінки.

    [← Попередня] [1] [2] [3] [Наступна →]

### Previous

Переходить на одну сторінку назад.

### Next

Переходить на одну сторінку вперед.

### Коли кнопки повинні бути недоступними

На першій сторінці немає попередньої сторінки.

    [← Попередня — disabled] [1] [2] [3] [Наступна →]

На останній сторінці немає наступної сторінки.

    [← Попередня] [8] [9] [10] [Наступна — disabled]

### UX-правила

- не дозволяй перейти на сторінку, якої не існує;
- показуй недоступний стан кнопок;
- не роби disabled-стан надто схожим на активну кнопку;
- зберігай однакове розташування кнопок між сторінками;
- використовуй зрозумілі назви або доступні підписи для стрілок.

Якщо використовуються лише іконки, допоміжним технологіям потрібно передати зрозумілі назви кнопок.

---

## 6. Ellipsis — три крапки

Ellipsis позначає пропущені номери сторінок.

Приклад:

    [1] [2] [3] [...] [20]

Три крапки показують, що між видимими номерами є інші сторінки.

### Навіщо потрібен Ellipsis

- зменшує візуальну кількість елементів;
- допомагає зберегти компактність;
- залишає доступ до першої та останньої сторінок;
- не дозволяє пагінації займати надто багато місця.

### Приклади

На початку списку:

    [1] [2] [3] [4] [...] [20]

У середині списку:

    [1] [...] [9] [10] [11] [...] [20]

Наприкінці списку:

    [1] [...] [17] [18] [19] [20]

Це приклади можливих схем. Точний алгоритм відображення залежить від дизайну та кількості сторінок.

### Важливе правило

Три крапки зазвичай є лише індикатором пропущених сторінок, а не кнопкою.

Якщо вони виконують інтерактивну дію, наприклад відкривають поле для введення номера сторінки, це потрібно чітко позначити в інтерфейсі.

---

## 7. Скільки номерів сторінок показувати

Пагінація повинна залишатися компактною.

### Мало сторінок

    [1] [2] [3] [4] [5]

Показуй усі номери, якщо вони легко поміщаються.

### Багато сторінок

    [1] [2] [3] [...] [50]

Не потрібно відображати десятки кнопок одночасно.

### Середина великого списку

    [1] [...] [24] [25] [26] [...] [50]

Поточна сторінка та сусідні номери допомагають орієнтуватися.

### Як вибрати кількість номерів

Враховуй:

- загальну кількість сторінок;
- ширину контейнера;
- розмір кнопок;
- розмір екрана;
- потребу в переході до першої та останньої сторінки;
- тип даних і сценарій користувача.

Не намагайся вмістити максимальну кількість номерів за будь-яку ціну.

---

## 8. Current page — поточна сторінка

Поточна сторінка показує, яку частину даних користувач переглядає зараз.

Приклад:

    [1] [2] [3] [4] [5]

    Активна сторінка: 3

### Візуальне оформлення

Поточний номер може мати:

- контрастний фон;
- інший колір тексту;
- виразну рамку;
- додаткове підкреслення.

Приклад:

    [1] [2] [ 3 ] [4] [5]
             ↑
       Поточна сторінка

### Важливі правила

- активний стан має бути помітним;
- активна сторінка не повинна виглядати як звичайна кнопка;
- стан потрібно передавати не лише кольором;
- після переходу поточна сторінка має оновлюватися;
- користувач повинен розуміти, чи змінилися результати.

Поточна сторінка має бути зрозумілою як візуально, так і для допоміжних технологій.

---

## 9. Result count — кількість результатів

Кількість результатів повідомляє, скільки записів загалом відповідають запиту.

Приклад:

    Знайдено 240 товарів

Це особливо корисно для пошуку, каталогів і таблиць.

### Варіанти відображення

    Знайдено 240 курсів

    Усього записів: 240

    240 результатів

    Показано 20 із 240 записів

Кожен варіант має трохи інший зміст.

- **Знайдено 240 курсів** — загальна кількість результатів пошуку.
- **Усього записів: 240** — кількість записів у наборі даних.
- **Показано 20 із 240 записів** — інформація про поточний обсяг відображення.

### UX-правило

Використовуй формулювання, яке відповідає реальній поведінці системи.

Не повідомляй загальну кількість результатів, якщо система її не знає або ще не обчислила.

---

## 10. Range indicator — діапазон елементів

Range indicator показує, які саме елементи відображаються на поточній сторінці.

Приклад:

    Показано 21–40 із 240

Це означає, що користувач бачить записи з 21-го по 40-й.

### Приклади

Перша сторінка:

    Показано 1–20 із 240

Друга сторінка:

    Показано 21–40 із 240

Третя сторінка:

    Показано 41–60 із 240

Остання сторінка:

    Показано 221–240 із 240

Діапазон допомагає користувачеві зрозуміти своє положення в наборі даних.

### Де це особливо корисно

- адміністративні таблиці;
- пошукові результати;
- великі каталоги;
- списки замовлень;
- списки користувачів;
- журнали подій.

Для невеликої галереї карток діапазон може бути зайвим.

---

## 11. Page size — кількість елементів на сторінці

Page size визначає, скільки елементів відображається на одній сторінці.

Приклад:

    Показувати:
    [20 на сторінці ▼]

Можливі варіанти:

- 10 елементів;
- 20 елементів;
- 50 елементів;
- 100 елементів.

### Приклад інтерфейсу

    Показано 1–20 із 240

    На сторінці:
    [20 ▼]

    [1] [2] [3] [...] [12]

### Коли потрібен Page size selector

- користувач працює з великою таблицею;
- потрібно швидко переглядати більше записів;
- користувач виконує адміністративні завдання;
- набір даних часто має різний розмір.

### Коли можна обійтися без нього

- у невеликому каталозі;
- у простому блозі;
- у мобільному інтерфейсі з обмеженим простором;
- коли кількість елементів визначається продуктивністю системи.

### UX-правила

- використовуй зрозумілі варіанти;
- не перевантажуй список вибору;
- пояснюй, що саме змінюється;
- після зміни кількості елементів коректно оновлюй результати;
- визначай, чи повертається користувач на першу сторінку.

Зміна Page size може зробити поточний номер сторінки недійсним або призвести до іншого набору видимих записів. Поведінка повинна бути передбачуваною.

## 12. Типи Pagination

### 12.1. Numeric pagination — числова пагінація

    [1] [2] [3] [4] [5] [→]

Користувач бачить номери сторінок.

Підходить для:

- каталогів;
- пошукових результатів;
- блогів;
- списків із відомою кількістю сторінок.

### 12.2. Previous / Next pagination

    [← Попередня] [Наступна →]

Показує лише кнопки переходу вперед і назад.

Підходить для:

- покрокового перегляду;
- списків, де номер сторінки не має великого значення;
- інтерфейсів з обмеженим простором.

Недолік: користувач не може безпосередньо вибрати номер сторінки.

### 12.3. First / Last pagination

    [Перша] [←] [1] [2] [3] [→] [Остання]

Додає прямий перехід до початку та кінця набору даних.

Корисно для великих таблиць і робочих інтерфейсів.

### 12.4. Compact pagination — компактна пагінація

    [←] [3 / 12] [→]

Показує поточну сторінку та загальну кількість сторінок.

Підходить для мобільних інтерфейсів або компактних блоків.

### 12.5. Pagination with page size

    Показувати [20 ▼] записів

    [1] [2] [3] [...] [12]

Дозволяє керувати кількістю записів на сторінці.

Часто використовується в таблицях адміністративних панелей.

### 12.6. Cursor-based pagination — пагінація за курсором

У деяких системах замість номерів сторінок використовується спеціальний курсор, який визначає позицію в наборі даних.

Приклад інтерфейсу:

    [← Попередні записи] [Наступні записи →]

Користувач може не бачити номерів сторінок або загальної кількості записів.

Такий підхід часто використовують у великих наборах даних, потоках подій і API, де перехід за номерами сторінок не є оптимальним.

**Для UI-дизайнера:** не кожна пагінація обов'язково повинна показувати номери. Вигляд компонента залежить від способу отримання даних і потреб користувача.

---

## 13. Pagination у таблицях

Таблиці часто містять сотні або тисячі записів. Пагінація допомагає переглядати їх без перевантаження інтерфейсу.

Приклад:

    Користувачі

    ┌──────────────┬─────────────────────┐
    │ Ім'я         │ Email               │
    ├──────────────┼─────────────────────┤
    │ Олена        │ olena@example.com   │
    │ Андрій       │ andrii@example.com  │
    │ Марія        │ maria@example.com   │
    └──────────────┴─────────────────────┘

    Показано 1–20 із 320

    Рядків на сторінці: [20 ▼]

    [1] [2] [3] [...] [16]

### Рекомендації

- розміщуй пагінацію близько до таблиці;
- показуй кількість записів;
- за потреби додай вибір Page size;
- зберігай зрозумілий зв'язок між таблицею та пагінацією;
- після зміни сторінки показуй актуальні дані;
- передбачай довгі назви та вузькі екрани.

У великих адміністративних інтерфейсах пагінація часто розташовується під таблицею. Якщо таблиця довга, можна також передбачити верхню пагінацію, але не варто дублювати її без користі.

## 14. Pagination у каталогах і картках

У каталозі пагінація зазвичай розміщується після сітки карток.

Приклад:

    Каталог курсів

    [Картка] [Картка] [Картка]
    [Картка] [Картка] [Картка]
    [Картка] [Картка] [Картка]

    [←] [1] [2] [3] [...] [10] [→]

### UX-правила

- розміщуй пагінацію після результатів;
- залишай достатній відступ від останнього ряду;
- не відволікай увагу від карток;
- використовуй помітний поточний номер;
- враховуй, як змінюється кількість карток на різних екранах.

### Важливий нюанс

Якщо користувач переходить на іншу сторінку, потрібно визначити, куди перемістити його увагу.

Можливі варіанти:

- прокрутити до початку результатів;
- залишити позицію прокручування;
- перейти до верхньої частини сторінки;
- оновити тільки область результатів.

Вибір залежить від структури сторінки та очікуваної поведінки. Головне — не залишати користувача в ситуації, коли нові результати завантажилися далеко за межами видимої області.

## 15. Pagination у результатах пошуку

Пагінація часто використовується разом із пошуком і фільтрами.

Приклад:

    Пошук: JavaScript

    Фільтр: Початковий рівень

    Знайдено 96 курсів

    Результати 1–20 із 96

    [1] [2] [3] [4] [5]

### Що потрібно врахувати

- після нового пошукового запиту зазвичай потрібно повернутися на першу сторінку;
- зміна фільтра може змінити кількість сторінок;
- очищення пошуку повинно оновлювати результати;
- пагінація має працювати з поточним набором фільтрів;
- поточний стан бажано синхронізувати з URL, якщо це корисно для навігації.

### Типова помилка

Користувач перебуває на сторінці 5, змінює пошуковий запит, але інтерфейс продовжує показувати сторінку 5 нового набору даних.

Якщо новий запит має лише дві сторінки, це може призвести до порожнього результату або некоректної поведінки.

**Рішення:** після зміни запиту або фільтрів перевіряй, чи залишається поточна сторінка дійсною. У багатьох інтерфейсах найпростіше повернутися на першу сторінку.

## 16. Mobile pagination — пагінація на смартфонах

На мобільних пристроях простору значно менше, тому повна числова пагінація може бути незручною.

### Варіант 1. Компактна пагінація

    [←] [2 / 12] [→]

Перевага — займає мало місця.

### Варіант 2. Поточна сторінка та сусідні

    [←] [2] [3] [4] [→]

Перевага — можна швидко перейти на сусідню сторінку.

### Варіант 3. Лише Previous / Next

    [← Попередня] [Наступна →]

Перевага — простота.

### Mobile UX checklist

- кнопки достатньо великі для натискання;
- між кнопками є відстань;
- активна сторінка добре помітна;
- довгі номери не ламають компонування;
- пагінація не виходить за межі екрана;
- назви кнопок зрозумілі;
- після переходу нові результати легко знайти.

### Чого не варто робити

Не намагайся зменшити всі кнопки настільки, щоб вони помістилися на вузькому екрані.

Краще використати компактніший варіант компонента, ніж зробити всі елементи надто малими.

## 17. Responsive design — адаптивність пагінації

Пагінація має підлаштовуватися під ширину контейнера.

### Desktop

    [Перша] [←] [1] [2] [3] [...] [20] [→] [Остання]

### Tablet

    [←] [1] [2] [3] [...] [20] [→]

### Mobile

    [←] [3 / 20] [→]

Це лише можливий варіант адаптації, а не обов'язкове правило.

### Що може змінюватися

- кількість видимих номерів;
- наявність First / Last;
- формат Previous / Next;
- розташування лічильника;
- вибір кількості записів;
- відступи та розміри кнопок.

### Рекомендації

- не допускай горизонтального переповнення;
- зберігай зрозумілу послідовність;
- не приховуй поточну сторінку;
- забезпечуй доступність усіх необхідних дій;
- перевіряй компонент у вузьких контейнерах, а не лише за назвами пристроїв.

## 18. Pagination states — стани пагінації

Пагінація має різні стани залежно від положення користувача та процесу завантаження.

### 18.1. Default — звичайний стан

    [1] [2] [3] [4] [5]

Користувач може перейти на доступну сторінку.

### 18.2. Current — поточна сторінка

    [1] [2] [3] [4] [5]
             ↑
          Активна

Поточна сторінка візуально відрізняється від інших.

### 18.3. Hover — наведення

Коли користувач наводить курсор на доступний елемент, його оформлення змінюється.

Hover не повинен бути єдиним способом показати інтерактивність.

### 18.4. Focus — клавіатурний фокус

Елемент має помітний focus indicator.

Це потрібно користувачам, які переходять між кнопками клавіатурою.

### 18.5. Disabled — недоступний стан

    [←] [1] [2] [3] [→]

На першій сторінці кнопка Previous недоступна. На останній сторінці недоступна Next.

### 18.6. Loading — завантаження

Після вибору сторінки система може потребувати часу для отримання даних.

У цей момент потрібно визначити:

- чи блокувати повторне натискання;
- чи залишати старі результати;
- як показувати завантаження;
- як уникати повторних запитів;
- як обробляти помилку.

Не варто блокувати весь інтерфейс, якщо можна показати локальний стан завантаження.

### 18.7. Error — помилка

Якщо дані не завантажилися, користувач має зрозуміти, що сталося.

Приклад:

    Не вдалося завантажити сторінку.

    [Спробувати ще раз]

Не показуй порожній список так, ніби на сторінці немає даних, якщо причина полягає в помилці запиту.

### 18.8. Empty — порожній набір даних

Якщо немає жодного запису, звичайна пагінація може бути непотрібною.

    Немає записів для відображення.

Не показуй номери сторінок, якщо сторінок фактично не існує.

## 19. Accessibility — доступність Pagination

Пагінація повинна бути доступною для клавіатури, скринридерів та інших допоміжних технологій.

### Основні правила

✔ Усі кнопки доступні з клавіатури.

✔ Поточна сторінка позначена програмно.

✔ Кнопки мають зрозумілі назви.

✔ Недоступні дії позначені належним чином.

✔ Focus indicator помітний.

✔ Кнопки мають достатній розмір.

✔ Інтерфейс не залежить лише від кольору.

✔ Після переходу користувач розуміє, що змінилося.

### Приклад HTML

    <nav aria-label="Навігація сторінками">
      <ul>
        <li>
          <button type="button" disabled>
            Попередня
          </button>
        </li>

        <li>
          <button
            type="button"
            aria-current="page"
          >
            1
          </button>
        </li>

        <li>
          <button type="button">
            2
          </button>
        </li>

        <li>
          <button type="button">
            3
          </button>
        </li>

        <li>
          <button type="button">
            Наступна
          </button>
        </li>
      </ul>
    </nav>

### Пояснення

- `nav` визначає навігаційну область;
- `aria-label` пояснює її призначення;
- `aria-current="page"` позначає поточну сторінку;
- `disabled` вимикає кнопку, коли перехід недоступний;
- `button` забезпечує стандартну клавіатурну взаємодію.

У реальному застосунку кнопки повинні виконувати переходи, а номери сторінок потрібно формувати на основі фактичних даних.

### Після переходу

Якщо змінилася лише частина сторінки, потрібно продумати, як повідомити про оновлення результатів.

Можна:

- перемістити фокус у відповідне місце;
- оновити заголовок результатів;
- оголосити кількість нових результатів через доступну live-область;
- перемістити прокручування до початку оновленого списку, якщо це відповідає сценарію.

Не потрібно автоматично переміщувати фокус після кожної взаємодії без урахування контексту.

## 21. Візуальний дизайн пагінації

### Розміри

Кнопки повинні бути достатніми для точного натискання.

Для сенсорних пристроїв орієнтуйся на зручну область взаємодії, часто близьку до 44 × 44 CSS-пікселів, якщо компонування це дозволяє.

Це практичний орієнтир, а не універсальна вимога для кожного інтерфейсу.

### Відступи

- зберігай однакову відстань між кнопками;
- не притискай пагінацію до списку;
- не створюй надмірно великих проміжків;
- групуй лічильник і навігацію логічно.

### Контраст

- активний номер має бути добре помітним;
- текст кнопок повинен читатися;
- disabled-стан має відрізнятися від активного;
- focus indicator повинен мати достатній контраст.

### Форма

Можна використовувати:

- квадратні кнопки;
- кнопки з округленими кутами;
- круглі компактні кнопки;
- мінімалістичні текстові посилання.

Головне — узгодженість із дизайн-системою та зрозуміла інтерактивність.

### Візуальна ієрархія

Не потрібно робити кожну кнопку однаково акцентною.

Зазвичай:

- поточна сторінка має найвиразніший стан;
- звичайні номери мають нейтральне оформлення;
- Previous і Next залишаються помітними;
- disabled-елементи виглядають недоступними.

## 22. Типові помилки Pagination

### Помилка 1. Показано забагато сторінок

Проблема: пагінація займає весь простір.

Рішення: використовуй Ellipsis та обмежену кількість номерів.

### Помилка 2. Поточна сторінка непомітна

Проблема: користувач не розуміє, де перебуває.

Рішення: виразно позначай Current page.

### Помилка 3. Немає Previous і Next

Проблема: користувачеві доводиться щоразу вибирати номер.

Рішення: додай послідовну навігацію, якщо вона корисна для сценарію.

### Помилка 4. Disabled-кнопка виглядає активною

Проблема: користувач очікує переходу, який неможливий.

Рішення: передбач окремий disabled-стан і відповідну поведінку.

### Помилка 5. Пагінація не оновлюється після фільтрації

Проблема: користувач бачить номер сторінки, який більше не існує.

Рішення: перераховуй доступні сторінки після зміни набору даних.

### Помилка 6. Після переходу користувач залишається внизу сторінки

Проблема: нові результати можуть залишитися поза видимою областю.

Рішення: продумай прокручування та відновлення позиції.

### Помилка 7. Немає кількості результатів у робочій таблиці

Проблема: користувач не розуміє загальний обсяг даних.

Рішення: додай Result count або Range indicator, якщо вони корисні для завдання.

### Помилка 8. Занадто маленькі кнопки на мобільному

Проблема: складно натискати потрібний номер.

Рішення: використовуй компактний варіант із меншою кількістю кнопок, а не зменшуй усі кнопки до незручного розміру.

### Помилка 9. Пагінація не має доступних назв

Проблема: скринридер може не пояснювати призначення стрілок.

Рішення: додавай зрозумілі назви, наприклад «Наступна сторінка».

### Помилка 10. Після зміни сторінки дані не відповідають активним фільтрам

Проблема: користувач отримує неправильний набір результатів.

Рішення: передавай актуальні параметри запиту та коректно оновлюй стан пагінації.

## 23. Основи логіки пагінації

Щоб краще розуміти компонент, корисно знати базові математичні принципи.

Припустимо:

- загальна кількість записів — `totalItems`;
- кількість записів на сторінці — `pageSize`;
- поточна сторінка — `currentPage`.

### Кількість сторінок

    totalPages = Math.ceil(totalItems / pageSize)

Наприклад:

    totalItems = 240
    pageSize = 20

    totalPages = Math.ceil(240 / 20)
    totalPages = 12

Потрібно 12 сторінок.

### Початковий індекс

Якщо сторінки нумеруються від 1, а індекси масиву — від 0:

    startIndex = (currentPage - 1) * pageSize

Для другої сторінки:

    currentPage = 2
    pageSize = 20

    startIndex = (2 - 1) * 20
    startIndex = 20

Це означає, що вибірка починається з індексу `20`.

### Кінцевий індекс

    endIndex = startIndex + pageSize

Для другої сторінки:

    startIndex = 20
    endIndex = 40

У методі `slice()` кінцевий індекс не включається.

### Приклад у JavaScript

    const items = Array.from(
      { length: 100 },
      (_, index) => `Елемент ${index + 1}`
    );

    const pageSize = 10;
    const currentPage = 3;

    const startIndex = (currentPage - 1) * pageSize;
    const endIndex = startIndex + pageSize;

    const visibleItems = items.slice(
      startIndex,
      endIndex
    );

    console.log(visibleItems);

Результат міститиме елементи з 21-го по 30-й.

### Обмеження

Цей приклад виконує пагінацію локального масиву. У реальному застосунку дані можуть надходити з сервера, а номер сторінки та розмір вибірки потрібно передавати в API.

## 24. Pagination і серверні дані

У невеликому масиві можна отримати всі дані й розділити їх на сторінки у браузері.

Але якщо записів десятки тисяч, завантажувати весь набір даних не завжди доцільно.

### Client-side pagination

Усі дані вже завантажені в браузер, а користувач перемикає видимі частини масиву.

Переваги:

- простіша логіка;
- швидке перемикання між сторінками;
- не потрібен новий запит для кожного переходу.

Недоліки:

- потрібно завантажити весь набір даних;
- значні обсяги можуть споживати багато пам'яті;
- початкове завантаження може бути повільним.

### Server-side pagination

Браузер запитує лише потрібну частину даних.

Приклад:

    GET /api/courses?page=2&limit=20

Сервер повертає записи для другої сторінки та, за можливості, інформацію про загальну кількість.

Переваги:

- менше даних передається за один запит;
- підходить для великих наборів;
- сервер може застосовувати фільтри та сортування.

Недоліки:

- переходи можуть залежати від мережі;
- потрібні стани завантаження й помилки;
- необхідно обробляти зміну даних між запитами.

### Що важливо для дизайну

UI повинен враховувати затримку запитів, повторне натискання, помилки та можливість зміни набору даних.

## 25. Pagination, сортування та фільтри

Пагінація часто є частиною складнішої системи керування даними.

Приклад:

    Рядків: [20 ▼]

    Показано 1–20 із 84

    [1] [2] [3] [4] [5]

### Правильна послідовність обробки

На концептуальному рівні система зазвичай:

1. отримує набір даних;
2. застосовує пошук;
3. застосовує фільтри;
4. сортує результати;
5. визначає потрібну сторінку;
6. відображає її елементи.

У реальному застосунку частина цих операцій може виконуватися на сервері.

### Важливі правила

- після зміни пошуку перевіряй поточну сторінку;
- після зміни фільтрів оновлюй кількість сторінок;
- після зміни сортування забезпечуй передбачуваний порядок;
- після зміни Page size коректно перераховуй діапазон;
- не дозволяй пагінації показувати сторінку поза межами доступного діапазону.

## 26. Практичний алгоритм створення Pagination

### Крок 1. Визнач розмір набору даних

Скільки елементів загалом може бути в списку?

### Крок 2. Визнач кількість елементів на сторінці

Чи буде це фіксоване значення, чи користувач зможе його змінювати?

### Крок 3. Вибери тип пагінації

- числова;
- Previous / Next;
- компактна;
- з переходом до першої та останньої сторінки;
- із вибором Page size.

### Крок 4. Визнач інформацію про результати

Чи потрібно показувати:

- загальну кількість;
- діапазон записів;
- кількість сторінок;
- поточний номер?

### Крок 5. Спроєктуй стани

- default;
- current;
- hover;
- focus;
- disabled;
- loading;
- error;
- empty.

### Крок 6. Визнач поведінку переходу

Що відбувається після натискання номера?

- які дані завантажуються;
- чи змінюється URL;
- чи змінюється прокручування;
- де опиняється фокус;
- як показується завантаження?

### Крок 7. Перевір роботу з фільтрами

Пошук і фільтри можуть змінювати кількість сторінок. Передбач цю поведінку.

### Крок 8. Спроєктуй мобільний варіант

Зменш кількість видимих номерів або використай компактний компонент.

### Крок 9. Перевір доступність

Переконайся, що всі переходи доступні з клавіатури, а поточна сторінка позначена належним чином.

### Крок 10. Протестуй граничні випадки

Перевір:

- нуль записів;
- один запис;
- одну сторінку;
- багато сторінок;
- останню сторінку з неповним набором;
- зміну кількості записів;
- зміну фільтрів;
- помилку завантаження.

## 27. Чекліст перед завершенням дизайну

### Структура

- [ ] Вибрано відповідний тип пагінації.
- [ ] Поточна сторінка помітна.
- [ ] Є зрозумілі кнопки Previous і Next, якщо вони потрібні.
- [ ] Ellipsis використовується доречно.
- [ ] Розміщення пагінації відповідає структурі сторінки.

### Дані

- [ ] Кількість сторінок відповідає реальному набору.
- [ ] Діапазон записів відображається правильно.
- [ ] Загальна кількість не вводить користувача в оману.
- [ ] Після зміни фільтрів стан пагінації оновлюється.
- [ ] Остання сторінка коректно показує неповний набір записів.

### Стани

- [ ] Поточна сторінка має окреме оформлення.
- [ ] Disabled-стан зрозумілий.
- [ ] Hover і Focus відрізняються від звичайного стану.
- [ ] Продумано завантаження.
- [ ] Продумано помилку.
- [ ] Для порожнього набору не показуються неіснуючі сторінки.

### Адаптивність

- [ ] Пагінація не виходить за межі контейнера.
- [ ] Кнопки зручні для сенсорного керування.
- [ ] На мобільному використовується відповідний варіант.
- [ ] Довгі номери не ламають компонування.
- [ ] Лічильник не перекриває навігацію.

### Доступність

- [ ] Кнопки доступні з клавіатури.
- [ ] Поточна сторінка позначена програмно.
- [ ] Стрілки мають зрозумілі назви.
- [ ] Focus indicator помітний.
- [ ] Стани не залежать лише від кольору.
- [ ] Після переходу користувач розуміє, що змінилося.

Ти розумієш:

### Рівень 3 — Системний дизайн

- створювати компоненти пагінації у Figma;
- визначати стани та властивості компонентів;
- поєднувати пагінацію з пошуком і фільтрами;
- враховувати адаптивність;
- продумувати доступність;
- визначати поведінку переходів.

### Рівень 4 — Production-ready

Ти розумієш:

- client-side та server-side pagination;

- зміну набору даних під час перегляду;
- взаємодію пагінації з URL;

## 30. Мінішпаргалка

| Елемент | Призначення |
|---|---|
| Pagination | Розбиття даних на сторінки |
| Page number | Перехід до конкретної сторінки |
| Current page | Позначення активної сторінки |
| Previous | Перехід назад |
| Next | Перехід уперед |
| First page | Перехід на першу сторінку |
| Last page | Перехід на останню сторінку |
| Ellipsis | Позначення пропущених номерів |
| Page size | Кількість елементів на сторінці |
| Result count | Загальна кількість результатів |
| Range indicator | Діапазон видимих записів |
| Client-side pagination | Пагінація вже завантажених даних |
| Server-side pagination | Отримання потрібної частини даних із сервера |
| Infinite Scroll | Автоматичне завантаження під час прокручування |
| Load More | Завантаження наступної порції кнопкою |
| Cursor pagination | Перехід за курсором, а не обов'язково за номером |

## 31. Головне, що потрібно запам'ятати

1. Pagination допомагає зручно переглядати великі набори даних частинами.
2. Поточна сторінка повинна бути чітко позначена.
3. Кнопки Previous і Next мають відповідати реальній доступності переходів.
4. Ellipsis допомагає зберігати компактність пагінації.
5. Result count і Range indicator корисні, коли користувачеві потрібно розуміти загальний обсяг даних.
6. Page size дозволяє змінювати кількість елементів на сторінці, якщо це потрібно для сценарію.
7. Пошук, фільтри та сортування повинні узгоджено працювати з пагінацією.
8. На смартфонах краще використовувати компактний компонент, ніж робити кнопки надто малими.
9. Доступність передбачає клавіатурну навігацію, помітний фокус і програмне позначення поточної сторінки.
10. Дизайн має враховувати завантаження, помилки, порожні набори та зміну кількості даних.

**Основний принцип:** хороша пагінація допомагає користувачеві не лише перейти до іншої сторінки, а й розуміти своє місце в наборі даних та зберігати контроль над навігацією.
