# 10. Search — Пошук в інтерфейсах

> Search — пошук в інтерфейсі користувача, який дозволяє знаходити потрібні дані за текстовим запитом, назвою, ключовими словами, ідентифікатором або іншими критеріями.
>
> Мета пошуку — допомогти користувачеві швидко знайти потрібну інформацію без необхідності переглядати всі доступні елементи вручну.

---

## 1. Що таке Search

Пошук (Search) — це функція інтерфейсу, яка приймає запит користувача, обробляє його та показує відповідні результати.

Наприклад, у навчальній платформі користувач може шукати:

- курс за назвою;
- урок за темою;
- учня за ім'ям;
- документ за назвою;
- запис за ідентифікатором.

Замість ручного перегляду сотень записів користувач вводить запит і отримує відповідні результати.

### Де використовують пошук

- інтернет-магазини;
- каталоги товарів;
- блоги та новинні сайти;
- пошукові системи;
- адміністративні панелі;
- CRM-системи;
- LMS та освітні платформи;
- бібліотеки документів;
- файлові менеджери;
- системи бронювання;
- мобільні застосунки.

### Головне правило

✔ Поле пошуку має бути легко знайти.

✔ Користувач повинен розуміти, що саме можна шукати.

✔ Результати мають відповідати введеному запиту.

✔ Інтерфейс повинен повідомляти про завантаження, відсутність результатів та помилки.

✔ Пошук має бути зручним для клавіатури, сенсорного екрана та допоміжних технологій.

---

## 2. Search та Filter — у чому різниця

Пошук і фільтри допомагають знаходити дані, але працюють по-різному.

### Search — пошук

Користувач вводить запит, щоб знайти конкретний елемент або елементи за текстом чи іншими пошуковими параметрами.

Приклад:

    Поле пошуку:
    [JavaScript для початківців...]

    Результати:
    JavaScript: основи
    JavaScript: масиви
    JavaScript: асинхронність

### Filter — фільтрування

Користувач вибирає критерії, щоб звузити набір даних.

Приклад:

    Категорія: Програмування
    Рівень: Початковий
    Мова: Українська

### Search + Filters

Найкращий варіант для складних каталогів — поєднання пошуку та фільтрів.

    [Пошук курсів....................]

    Категорія: [Програмування ▼]
    Рівень:     [Початковий ▼]

    Знайдено 12 курсів

Пошук знаходить курси за текстовим запитом, а фільтри обмежують результати за категорією та рівнем.

**Запам'ятай:** Search шукає за запитом, Filter звужує результати за критеріями, а Sort змінює порядок результатів.

## 3. Анатомія пошуку

Типовий компонент пошуку може містити такі елементи:

    ┌─────────────────────────────────────┐
    │ 🔍  Пошук курсів...             [×] │
    └─────────────────────────────────────┘

    Результати пошуку

    JavaScript: основи
    Вступний курс із JavaScript

    TypeScript для початківців
    Типізація у JavaScript

### Основні елементи

1. **Search field** — поле введення запиту.
2. **Search icon** — іконка, яка візуально позначає пошук.
3. **Placeholder** — підказка всередині порожнього поля.
4. **Clear button** — кнопка очищення запиту.
5. **Submit button** — кнопка запуску пошуку, якщо потрібне явне підтвердження.
6. **Autocomplete** — список пропозицій під час введення.
7. **Search results** — область результатів.
8. **Result count** — кількість знайдених елементів.
9. **Empty state** — повідомлення, коли результатів немає.
10. **Loading state** — стан очікування результатів.
11. **Error state** — повідомлення про помилку пошуку.

Не кожен пошуковий інтерфейс потребує всіх елементів. Їхня кількість залежить від сценарію використання.

## 4. Типи пошуку

### 4.1. Basic search — простий пошук

Поле введення та кнопка запуску пошуку.

    [Введіть запит................] [Знайти]

Підходить для:

- невеликих каталогів;
- пошуку документів;
- простих форм;
- адміністративних інтерфейсів.

Переваги:

- проста структура;
- зрозуміла поведінка;
- легко реалізувати.

Недоліки:

- немає підказок під час введення;
- користувач може не знати точного формулювання;
- для великих каталогів може бути недостатньо.

### 4.2. Instant search — миттєвий пошук

Результати оновлюються під час введення запиту.

    Пошук:
    [JavaScript]

    Результати:
    JavaScript: основи
    JavaScript: масиви
    JavaScript: функції

Переваги:

- швидкий зворотний зв'язок;
- не потрібно натискати кнопку;
- користувач може поступово уточнювати запит.

Недоліки:

- надто часті запити до сервера;
- результати можуть часто змінюватися;
- можливе миготіння інтерфейсу;
- потрібно обробляти затримки мережі.

Для текстового пошуку часто використовують debounce — невелику затримку перед запуском запиту після введення тексту.

### 4.3. Search with suggestions — пошук із підказками

Після введення кількох символів система пропонує можливі запити або результати.

    [JavaScript......................]

    Пропозиції:
    JavaScript для початківців
    JavaScript масиви
    JavaScript async/await

Підказки можуть містити:

- пошукові запити;
- назви сторінок;
- товари;
- документи;
- категорії;
- історію попередніх пошуків.

Підказки допомагають користувачеві знайти потрібне, навіть якщо він не знає точної назви.

### 4.4. Global search — глобальний пошук

Шукає дані в різних розділах застосунку.

Наприклад, в адміністративній панелі можна знайти:

- користувача;
- курс;
- урок;
- замовлення;
- документ.

    [🔍 Пошук по всій системі...]

    Користувачі
    Валерій Свистун

    Курси
    JavaScript: основи

    Документи
    Інструкція для викладача

Для глобального пошуку важливо групувати результати за типами, щоб користувач розумів, що саме він знайшов.

### 4.5. Advanced search — розширений пошук

Дозволяє використовувати складні критерії.

    Розширений пошук

    Назва:       [________________]
    Автор:       [________________]
    Дата від:    [________________]
    Дата до:     [________________]
    Тип:         [Усі типи ▼]

    [Очистити] [Знайти]

Підходить для:

- великих баз даних;
- бібліотек;
- CRM;
- архівів;
- адміністративних систем;
- систем управління документами.

Не варто створювати розширений пошук без реальної потреби. Для простих завдань він може ускладнювати інтерфейс.

## 5. Placeholder — текстова підказка

Placeholder — короткий текст усередині порожнього поля.

Приклади:

    [Пошук товарів...]

    [Знайти курс за назвою...]

    [Введіть ім'я або email...]

### Хороший placeholder

- пояснює, що можна шукати;
- короткий;
- використовує зрозумілу мову;
- за можливості містить приклад запиту.

### Поганий placeholder

    [Пошук...]

Якщо контекст інтерфейсу незрозумілий, така підказка не пояснює, що саме можна знайти.

### Краще

    [Пошук курсів за назвою...]

### Важливе правило

Placeholder не повинен замінювати постійну назву поля, якщо вона потрібна для розуміння форми або доступності.

Приклад:

    <label for="course-search">Пошук курсів</label>
    <input
      id="course-search"
      type="search"
      placeholder="Введіть назву курсу"
    >

Після введення тексту placeholder зникає, тому він не завжди може виконувати роль повноцінної назви поля.

---

## 6. Search icon — іконка пошуку

Іконка лупи є поширеним візуальним позначенням пошуку.

Вона може розташовуватися:

- зліва всередині поля;
- справа всередині поля;
- на кнопці запуску пошуку;
- окремо поруч із навігацією.

Приклад:

    ┌─────────────────────────────────┐
    │ 🔍  Пошук товарів...             │
    └─────────────────────────────────┘

### UX-правила

- іконка не повинна заважати введенню тексту;
- текст не повинен накладатися на іконку;
- інтерактивна іконка має мати достатню область натискання;
- якщо іконка є кнопкою, вона повинна мати доступну назву;
- декоративна іконка не повинна дублювати зайву інформацію для скринридера.

Якщо поле вже очевидно є полем пошуку, додаткова велика кнопка з лупою не завжди потрібна.

## 7. Search field — дизайн поля пошуку

Поле пошуку має бути помітним, зручним і зрозумілим.

### Основні характеристики

**Розмір**

- достатня ширина для типового запиту;
- достатня висота для зручного натискання;
- можливість побачити введений текст.

**Рамка та фон**

- допомагають відокремити поле від навколишнього контенту;
- повинні відповідати дизайн-системі;
- не мають знижувати контраст тексту.

**Відступи**

- текст не повинен торкатися рамки;
- іконки мають мати достатньо простору;
- кнопка очищення не повинна перекривати текст.

**Типографіка**

- текст введення добре читається;
- placeholder візуально відрізняється від введеного тексту;
- довгі запити не руйнують компонування.

### Приклад структури

    ┌─────────────────────────────────────┐
    │ 🔍  Введіть назву товару...      [×]│
    └─────────────────────────────────────┘

### CSS-приклад

    .search-field {
      display: flex;
      align-items: center;
      gap: 10px;
      width: 100%;
      min-height: 44px;
      padding: 0 12px;
      border: 1px solid #cbd0d8;
      border-radius: 10px;
      background: #ffffff;
    }

    .search-field input {
      flex: 1;
      min-width: 0;
      border: 0;
      outline: 0;
      background: transparent;
      font: inherit;
    }

    .search-field:focus-within {
      border-color: #2457c5;
      box-shadow: 0 0 0 3px rgb(36 87 197 / 15%);
    }

Це лише базовий приклад. У готовому компоненті також потрібно продумати кнопку очищення, стани помилки, доступні назви та адаптивність.

## 8. Search states — стани пошуку

Пошуковий компонент має різні стани залежно від дій користувача та відповіді системи.

### 8.1. Default — початковий стан

    [🔍 Пошук курсів...]

Поле порожнє, результати ще не відображаються або показуються стандартні рекомендації.

### 8.2. Focus — фокус

Користувач активував поле.

- рамка може змінити колір;
- може з'явитися focus ring;
- курсор показує місце введення;
- підказки можуть відкриватися після введення тексту.

Фокус повинен бути помітним, зокрема для клавіатурної навігації.

### 8.3. Typing — введення тексту

    [JavaScript...................]

Система може:

- чекати завершення введення;
- показувати підказки;
- відкладати запит за допомогою debounce;
- перевіряти мінімальну довжину запиту.

Не запускай важкий пошук після кожного символу без необхідності.

### 8.4. Loading — завантаження

    [JavaScript...................]

    Завантаження результатів...

Показуй індикатор, якщо користувачеві доводиться чекати.

Для коротких і миттєвих операцій індикатор може бути зайвим.

### 8.5. Results — результати знайдено

    Знайдено 8 курсів

    JavaScript: основи
    JavaScript: масиви
    JavaScript: функції

Результати мають бути зрозумілими та відповідати запиту.

### 8.6. Empty — порожній результат

    За запитом «JavaScript» нічого не знайдено.

    Спробуйте:
    - перевірити написання;
    - використати інші слова;
    - скоротити запит.

    [Очистити пошук]

Повідомлення має пояснювати ситуацію та пропонувати наступний крок.

### 8.7. Error — помилка

    Не вдалося виконати пошук.

    Перевірте з'єднання та спробуйте ще раз.

    [Повторити]

Помилка сервера або мережі не повинна виглядати так, ніби результатів просто немає.

### 8.8. Clear — очищення

    [🔍 Пошук курсів...      ]

Після натискання кнопки очищення:

- текст видаляється;
- підказки оновлюються або закриваються;
- результати повертаються до визначеного початкового стану;
- фокус залишається передбачуваним.

### 8.9. Disabled — недоступний стан

Поле тимчасово недоступне.

Використовуй цей стан лише тоді, коли є зрозуміла причина, наприклад пошук недоступний до вибору обов'язкового контексту.

Не вимикай поле без пояснення, якщо користувач не може зрозуміти причину.

## 9. Autocomplete — автодоповнення

Autocomplete показує пропозиції під час введення запиту.

Приклад:

    [Пошук: JavaScript................]

    ┌───────────────────────────────────┐
    │ JavaScript для початківців        │
    │ JavaScript масиви                 │
    │ JavaScript async/await            │
    └───────────────────────────────────┘

### Типи підказок

**Пошукові запити**

    JavaScript для початківців
    JavaScript приклади

**Назви об'єктів**

    JavaScript: основи
    JavaScript: масиви

**Історія пошуку**

    Останні запити
    React hooks
    TypeScript types

**Категорії**

    Курси JavaScript
    Статті про JavaScript

### Правила дизайну

- розміщуй підказки поруч із полем;
- візуально відокремлюй список від сторінки;
- показуй достатню кількість тексту;
- виділяй активний пункт;
- передбачай закриття списку;
- не перекривай важливі елементи без потреби;
- визнач поведінку при відсутності пропозицій.

### Не плутай Autocomplete і Search results

Autocomplete — це пропозиції під час введення.

Search results — повний список результатів після виконання пошуку.

У деяких інтерфейсах вони можуть виглядати схоже, але виконують різні функції.

## 10. Keyboard navigation — керування клавіатурою

Якісний пошук має працювати не лише мишею.

Типові клавіші:

- `Tab` — перейти до поля або наступного елемента;
- `Enter` — виконати пошук або вибрати активну пропозицію;
- `ArrowDown` — перейти до наступної пропозиції;
- `ArrowUp` — перейти до попередньої пропозиції;
- `Escape` — закрити список підказок;
- `Ctrl + A` або `Cmd + A` — виділити текст у полі;
- `Backspace` — видалити текст перед курсором.

Точна поведінка залежить від типу пошукового компонента.

### Правила

- усі дії повинні бути доступними без миші;
- поточний активний пункт має бути помітним;
- клавіатурний фокус не повинен губитися;
- `Escape` не повинен несподівано стирати введений запит;
- після вибору результату користувач повинен розуміти, куди потрапив.

## 11. Пошукові результати (Search results)

Результати повинні допомагати швидко визначити, який елемент відповідає запиту.

### Типова структура результату

    JavaScript: основи
    Навчальний курс для початківців.
    Категорія: Програмування
    [Переглянути курс]

### Що можна показувати

- назву;
- короткий опис;
- категорію;
- автора;
- дату;
- тип документа;
- зображення;
- фрагмент тексту, де знайдено збіг;
- дію для відкриття елемента.

Не потрібно показувати всі поля одночасно. Вибирай інформацію, яка допомагає розрізняти результати.

### Візуальна ієрархія

1. Назва — головний елемент.
2. Опис або фрагмент збігу — пояснює зміст.
3. Метадані — уточнюють контекст.
4. Дія — дає змогу відкрити або використати результат.

### Приклад

    Результати пошуку: JavaScript

    JavaScript: основи
    Вступ до мови JavaScript.
    Курс · Початковий рівень

    JavaScript: масиви
    Робота з масивами та методами.
    Урок · Середній рівень

    JavaScript: асинхронність
    Проміси, async/await і робота з API.
    Курс · Середній рівень

## 12. Highlighting — виділення збігів

Пошукові результати можуть підсвічувати слова, що збігаються із запитом.

Приклад:

    Запит: JavaScript

    Основи JavaScript
    Вивчення JavaScript для початківців.

### Переваги

- користувач швидше бачить причину появи результату;
- легше порівнювати схожі елементи;
- підвищується зрозумілість результатів.

### Правила

- виділяй лише релевантні збіги;
- не погіршуй читабельність тексту;
- не використовуй надто яскраве оформлення;
- перевіряй контраст виділеного тексту;
- не допускай некоректного HTML при відображенні тексту, отриманого від користувача або сервера.

Підсвічування — допоміжний елемент, а не заміна зрозумілих назв та описів.

Історія може зберігатися локально або на сервері. Вибір залежить від вимог до приватності, синхронізації та облікового запису.

## 20. Responsive design — адаптивність пошуку

Пошук має адаптуватися до доступної ширини, а не лише до типу пристрою.

### Desktop

- ширше поле;
- результати можуть розташовуватися поруч із фільтрами;
- можна показувати більше метаданих.

### Tablet

- поле може займати всю доступну ширину;
- частина фільтрів може переходити в компактний формат;
- потрібно контролювати ширину карток результатів.

### Mobile

- пошук часто займає всю ширину;
- другорядні елементи можуть переноситися на новий рядок;
- результати зазвичай розташовуються вертикально;
- підказки повинні залишатися зручними для натискання.

### Приклад

    Desktop:
    [Пошук........................] [Знайти]

    Mobile:
    [Пошук........................]
    [Знайти]

Якщо пошук запускається автоматично, окрема кнопка може бути непотрібною.

Не зменшуй поле настільки, щоб користувачеві було складно читати свій запит.

## 21. Accessibility — доступність пошуку

Пошук має бути доступним для користувачів із різними способами взаємодії.

### Основні правила

✔ Поле має доступну назву.

✔ Пошук доступний із клавіатури.

✔ Focus indicator добре помітний.

✔ Кнопки мають зрозумілі назви.

✔ Підказки можна вибирати клавіатурою.

✔ Активний пункт списку має зрозуміле позначення.

✔ Результати та помилки не передаються лише кольором.

✔ Завантаження та зміни результатів оголошуються належним чином.

✔ Користувач може очистити поле без миші.

### Приклад HTML

    <form action="/search" method="get" role="search">
      <label for="site-search">Пошук по сайту</label>

      <input
        id="site-search"
        type="search"
        name="q"
        placeholder="Введіть пошуковий запит"
      >

      <button type="submit">
        Знайти
      </button>
    </form>

### Чому це важливо

- `role="search"` позначає область пошуку;
- `label` надає полю зрозумілу назву;
- `type="search"` семантично позначає пошукове поле;
- `name="q"` задає ім'я параметра, який буде передано при надсиланні форми.

Використовуй нативні HTML-елементи там, де це можливо. Вони забезпечують багато стандартної поведінки браузера.

## 23. UX-правила для якісного пошуку

### Правило 1. Зроби пошук помітним

Якщо пошук — основна функція сторінки, його потрібно розмістити на видному місці.

### Правило 2. Поясни, що можна шукати

Використовуй зрозумілу назву та конкретний placeholder.

### Правило 3. Не запускай важкі запити надто часто

Для пошуку під час введення використовуй debounce, якщо це допомагає зменшити кількість запитів.

### Правило 4. Зберігай введений запит

Якщо користувач відкрив результат і повернувся назад, часто корисно відновити попередній запит.

### Правило 5. Показуй зрозумілі результати

Назва та опис повинні допомагати визначити, чи потрібен користувачеві цей елемент.

### Правило 6. Допомагай при нульовому результаті

Запропонуй перевірити написання, змінити запит або очистити фільтри.

### Правило 7. Відрізняй помилку від відсутності збігів

Помилка мережі не означає, що потрібних даних немає.

### Правило 8. Передбачай очищення

Користувач повинен мати можливість швидко видалити запит і почати заново.

### Правило 9. Не перевантажуй підказки

Показуй лише корисні та релевантні пропозиції.

### Правило 10. Думай про доступність

Поле, підказки, кнопки та результати повинні бути доступними з клавіатури та зрозумілими для допоміжних технологій.

## 24. Типові помилки дизайну пошуку

### Помилка 1. Поле важко знайти

Проблема: користувач не бачить, де шукати.

Рішення:

- розмістити поле у звичному місці;
- використовувати зрозумілу іконку;
- додати назву або placeholder;
- забезпечити достатній контраст.

### Помилка 2. Placeholder надто загальний

Проблема: користувач не розуміє, які дані підтримують пошук.

Замість:

    [Пошук...]

Краще:

    [Пошук курсів за назвою...]

### Помилка 3. Немає стану завантаження

Проблема: користувач не розуміє, чи система працює.

Рішення: показати індикатор, якщо запит займає помітний час.

### Помилка 4. Немає повідомлення про нуль результатів

Проблема: користувач бачить порожній список без пояснення.

Рішення: показати запит, повідомлення та наступні дії.

### Помилка 5. Підказки не працюють із клавіатурою

Проблема: список доступний лише мишею.

Рішення: реалізувати коректну клавіатурну навігацію та доступний стан активного пункту.

### Помилка 6. Надто багато підказок

Проблема: список відволікає від введення запиту.

Рішення: показувати обмежену кількість найбільш релевантних пропозицій.

### Помилка 7. Результати незрозумілі

Проблема: кілька елементів мають схожі назви, але немає додаткового контексту.

Рішення: показувати короткий опис, категорію або інші корисні метадані.

### Помилка 8. Пошук запускається після кожного символу без контролю

Проблема: зайві запити, мерехтіння результатів і підвищене навантаження.

Рішення: використовувати debounce, скасування застарілих запитів або інші відповідні механізми.

### Помилка 9. Відповіді приходять не в тому порядку

Проблема: старий запит завершується пізніше та замінює результати нового.

Рішення: передбачити скасування попередніх запитів або перевірку актуальності відповіді.

### Помилка 10. Кнопка очищення не має зрозумілої поведінки

Проблема: текст зникає, але результати або підказки залишаються в неочікуваному стані.

Рішення: визначити єдину логіку очищення поля, результатів, підказок і пов'язаних параметрів.

## 25. Основи реалізації пошуку в JavaScript

UI-дизайнеру корисно розуміти, як пошукове поле пов'язане з даними та результатами.

### Приклад даних

    const courses = [
      {
        id: 1,
        title: "JavaScript: основи",
        category: "Програмування"
      },
      {
        id: 2,
        title: "HTML і CSS",
        category: "Веброзробка"
      },
      {
        id: 3,
        title: "JavaScript: масиви",
        category: "Програмування"
      }
    ];

### Функція пошуку

    function searchCourses(courses, query) {
      const normalizedQuery = query.trim().toLowerCase();

      if (normalizedQuery === "") {
        return [];
      }

      return courses.filter((course) => {
        return course.title
          .toLowerCase()
          .includes(normalizedQuery);
      });
    }

    const results = searchCourses(courses, "javascript");

Функція поверне курси, у назвах яких є `javascript`, незалежно від регістру літер.

### Що робить код

1. `trim()` прибирає пробіли на початку та в кінці запиту.
2. `toLowerCase()` нормалізує регістр.
3. `filter()` залишає лише відповідні елементи.
4. `includes()` перевіряє, чи містить назва пошуковий рядок.

### Важливі обмеження

Цей приклад демонструє простий пошук у масиві. Він не реалізує:

- пошук за описом;
- виправлення помилок;
- пошук за синонімами;
- ранжування релевантності;
- пагінацію;
- запити до сервера;
- складну мовну нормалізацію.

У реальному застосунку правила пошуку залежать від даних, обсягу каталогу та вимог продукту.

## 26. Debounce — затримка перед пошуком

Debounce — техніка, яка відкладає виконання функції, поки користувач не припинить вводити текст на певний час.

Наприклад, користувач вводить:

    J → Ja → Jav → Java → JavaScript

Замість п'яти окремих запитів система може запустити один після короткої паузи.

### Навіщо потрібен debounce

- зменшує кількість запитів;
- знижує навантаження на сервер;
- робить пошук стабільнішим;
- зменшує зайві оновлення інтерфейсу.

### UX-компроміс

Занадто довга затримка створює відчуття повільного пошуку.

Занадто коротка може не зменшити кількість запитів достатньо.

Конкретний час потрібно визначати відповідно до швидкості системи та характеру взаємодії.

Debounce не замінює обробку помилок, скасування запитів або контроль актуальності результатів.

## 27. Пошук у великих каталогах

Коли даних багато, локальної фільтрації масиву може бути недостатньо.

### Можливі рішення

- пошук на сервері;
- індекси бази даних;
- повнотекстовий пошук;
- пагінація;
- ранжування релевантності;
- кешування результатів;
- обмеження кількості підказок;
- скасування застарілих запитів.

### Що важливо для UI

- показувати зрозумілий стан завантаження;
- не блокувати весь інтерфейс без потреби;
- зберігати актуальний запит;
- обробляти помилки мережі;
- не показувати застарілі результати як нові;
- передбачати великі набори результатів;
- давати зрозумілий зворотний зв'язок.

UI-дизайнер не обов'язково має реалізовувати пошуковий рушій, але повинен враховувати його обмеження під час проєктування взаємодії.

## 28. Search і URL

Для вебзастосунків пошуковий запит часто зберігається в URL.

Приклад:

    /search?q=javascript

Якщо використовуються фільтри:

    /courses?q=javascript&level=beginner

### Переваги

- можна скопіювати посилання;
- можна поділитися результатами;
- після оновлення сторінки запит може зберігатися;
- кнопки Back і Forward можуть відновлювати попередні пошуки;
- простіше відтворити конкретний стан інтерфейсу.

### Що потрібно врахувати

- коректно кодувати параметри;
- обробляти порожні та некоректні запити;
- синхронізувати URL із полем;
- не зберігати конфіденційні дані у відкритому URL;
- визначити поведінку при поверненні назад.

Не кожен пошуковий запит потрібно зберігати в URL. Це залежить від призначення сторінки та вимог до приватності.

## 29. Search у Figma: що потрібно намалювати

Якщо ти проєктуєш компонент пошуку у Figma, недостатньо створити лише один прямокутник із лупою.

Потрібно продумати різні варіанти компонента.

### Search field

- default;
- hover;
- focus;
- filled;
- disabled;
- invalid.

### Search suggestions

- список закритий;
- список відкритий;
- активний пункт;
- немає пропозицій;
- завантаження пропозицій.

### Search results

- результати знайдено;
- нічого не знайдено;
- завантаження;
- помилка;
- довгий список;
- результат із довгою назвою.

### Варіанти компонента

- поле з іконкою;
- поле з кнопкою;
- поле з кнопкою очищення;
- компактне поле;
- повноширинне поле;
- пошук у мобільному екрані;
- глобальний пошук.

### Auto Layout

Для компонента можна використати таку структуру:

    SearchField
    ├── SearchIcon
    ├── InputText
    └── ClearButton

Для списку пропозицій:

    SearchSuggestions
    ├── SuggestionItem
    ├── SuggestionItem
    └── SuggestionItem

Використовуй Auto Layout для керування відступами, шириною та поведінкою елементів при зміні тексту.

### Component properties

Корисні властивості компонента можуть включати:

- `State`: Default / Focus / Disabled / Error;
- `Show icon`: true / false;
- `Show clear button`: true / false;
- `Size`: Small / Medium / Large;
- `Width`: Hug / Fill;
- `Has suggestions`: true / false.

Це приклади. Не потрібно створювати властивість для кожного можливого стану, якщо це робить компонент надто складним.

## 30. Практичний алгоритм створення пошуку

### Крок 1. Визнач мету

Що користувач повинен знайти?

Наприклад:

- товар;
- курс;
- учня;
- документ;
- статтю.

### Крок 2. Визнач пошукові поля

Пошук виконується за:

- назвою;
- описом;
- ім'ям;
- ідентифікатором;
- кількома полями одночасно.

Необхідно визначити, які поля дійсно доступні для пошуку.

### Крок 3. Вибери тип пошуку

- простий пошук;
- миттєвий пошук;
- пошук із підказками;
- глобальний пошук;
- розширений пошук.

### Крок 4. Спроєктуй поле

Визнач:

- ширину;
- висоту;
- placeholder;
- іконку;
- кнопку запуску;
- кнопку очищення;
- стани фокусу та помилки.

### Крок 5. Спроєктуй підказки

Визнач:

- коли вони з'являються;
- скільки їх показувати;
- як користувач вибирає пропозицію;
- як закривається список;
- що відбувається, коли пропозицій немає.

### Крок 6. Спроєктуй результати

Визнач, які дані допомагають розпізнати потрібний елемент.

### Крок 7. Продумай всі стани

Обов'язково перевір:

- порожнє поле;
- введення тексту;
- завантаження;
- знайдені результати;
- нуль результатів;
- помилку;
- очищення;
- клавіатурну навігацію.

### Крок 8. Додай фільтри за потреби

Якщо каталогу недостатньо простого текстового пошуку, додай фільтри та сортування.

### Крок 9. Перевір адаптивність

Переконайся, що поле, підказки та результати зручні на різних ширинах екрана.

### Крок 10. Перевір сценарії користувача

Попроси користувача знайти конкретний елемент і спостерігай, чи розуміє він:

- що вводити;
- як вибрати результат;
- що робити при нульовому результаті;
- як змінити запит.

## 35. Головне, що потрібно запам'ятати

1. Пошук допомагає швидко знаходити потрібні дані за запитом.
2. Поле пошуку має бути помітним, зрозумілим і доступним.
3. Placeholder повинен пояснювати, що саме можна шукати.
4. Autocomplete допомагає користувачеві під час введення, а Search results показує результати виконаного пошуку.
5. Завантаження, нуль результатів і помилка — різні стани, які не можна плутати.
6. Користувач повинен мати можливість змінити або очистити запит.
7. Пошукові підказки мають бути зрозумілими та доступними з клавіатури.
8. Для великих каталогів пошук можна поєднувати з фільтрами та сортуванням.
9. Debounce допомагає зменшити кількість запитів, але не замінює повноцінну обробку асинхронних операцій.
10. Якісний пошук допомагає не просто ввести запит, а швидко знайти потрібний результат і зрозуміти, що робити далі.

**Основний принцип:** хороший пошук мінімізує зусилля користувача на шляху від запитання «Де знайти?» до потрібної інформації.
