# 08. Lists — Списки в інтерфейсі

> **Lists** — це компоненти інтерфейсу, які організовують інформацію у вигляді послідовності елементів, допомагаючи користувачеві швидко переглядати, знаходити, порівнювати та вибирати потрібні дані.

Списки використовуються майже в кожному цифровому продукті: від меню навігації та списків завдань до каталогів товарів, повідомлень, контактів і результатів пошуку.

---

## 1. Для чого потрібні списки

Списки допомагають представити набір пов'язаних елементів у зрозумілому й передбачуваному форматі.

Наприклад, в освітній платформі список завдань може виглядати так:

    Завдання з інформатики

    ✓ Основи HTML
    ✓ CSS-селектори
    ○ Flexbox і Grid
    ○ Форми та валідація

Користувач може швидко:
- переглянути всі елементи;
- знайти потрібний пункт;
- зрозуміти послідовність дій;
- побачити статус кожного елемента;
- вибрати один або кілька пунктів;
- перейти до детальної інформації.

### Основні завдання списків

✔ Організація однотипної інформації.

✔ Полегшення сканування вмісту.

✔ Групування пов'язаних елементів.

✔ Навігація між розділами.

✔ Вибір одного або кількох значень.

✔ Відображення статусів і результатів.

✔ Керування завданнями та записами.

**Головний принцип:** список повинен допомагати користувачеві швидко зрозуміти, які елементи доступні та що з ними можна зробити.

---

## 2. Основні типи списків

### 2.1. Unordered List — ненумерований список

Ненумерований список використовує маркери замість числової послідовності.

Приклад:

    Необхідні інструменти

    • HTML
    • CSS
    • JavaScript
    • TypeScript

Використовується, коли порядок елементів не має принципового значення.

Типові приклади:
- перелік характеристик;
- список переваг;
- список інструментів;
- перелік категорій;
- список доступних функцій.

В HTML використовується елемент `<ul>`.

    <ul>
      <li>HTML</li>
      <li>CSS</li>
      <li>JavaScript</li>
    </ul>

### 2.2. Ordered List — нумерований список

Нумерований список показує послідовність або порядок елементів.

Приклад:

    Як створити проєкт

    1. Створити папку.
    2. Додати HTML-файл.
    3. Підключити CSS.
    4. Написати JavaScript.

Використовується, коли порядок важливий:
- інструкції;
- покрокові процеси;
- рейтинги;
- послідовність завдань;
- етапи реєстрації.

В HTML використовується `<ol>`.

    <ol>
      <li>Створити папку.</li>
      <li>Додати HTML-файл.</li>
      <li>Підключити CSS.</li>
    </ol>

### 2.3. Description List — список описів

Список описів поєднує терміни з їхніми поясненнями.

Приклад:

    HTML
    Мова розмітки вебсторінок.

    CSS
    Мова стилізації вебінтерфейсів.

    JavaScript
    Мова програмування для інтерактивної поведінки.

В HTML використовується комбінація:
- `<dl>` — контейнер;
- `<dt>` — термін;
- `<dd>` — опис.

    <dl>
      <dt>HTML</dt>
      <dd>Мова розмітки вебсторінок.</dd>

      <dt>CSS</dt>
      <dd>Мова стилізації вебінтерфейсів.</dd>
    </dl>

Цей формат підходить для словників, глосаріїв, характеристик і пояснень.

### 2.4. Interactive List — інтерактивний список

Елементи такого списку дозволяють виконувати дії.

Приклади:
- список завдань із чекбоксами;
- список файлів із кнопками;
- список повідомлень;
- список налаштувань;
- список контактів.

    [ ] Вивчити Flexbox
    [✓] Повторити CSS-селектори
    [ ] Створити адаптивну сторінку

Інтерактивний список може містити:
- чекбокси;
- кнопки;
- посилання;
- перемикачі;
- меню додаткових дій;
- індикатори стану.

Важливо розрізняти звичайний список для представлення інформації та список, елементи якого мають власну інтерактивну поведінку.

### 2.5. Navigation List — навігаційний список

Використовується для переходу між сторінками або розділами.

Приклад:

    Головна
    Курси
    Завдання
    Результати
    Профіль

В HTML навігаційний список часто розміщують усередині `<nav>`.

    <nav aria-label="Основна навігація">
      <ul>
        <li><a href="/">Головна</a></li>
        <li><a href="/courses">Курси</a></li>
        <li><a href="/tasks">Завдання</a></li>
      </ul>
    </nav>

Не варто стилізувати кожен список однаково. Навігаційний список має інші завдання, ніж список характеристик або список завдань.

### 2.6. Media List — список із медіа

Кожен елемент містить зображення, аватар, іконку або мініатюру.

Приклад:

    [Фото]  Основи HTML
            Вступ до HTML-розмітки

    [Фото]  Основи CSS
            Стилізація вебсторінок

Такий формат використовується для:
- списків курсів;
- контактів;
- повідомлень;
- музичних композицій;
- товарів;
- результатів пошуку.

### 2.7. Nested List — вкладений список

Вкладений список містить групи та підгрупи.

Приклад:

    Frontend
      HTML
      CSS
      JavaScript

    Backend
      Node.js
      Express
      PostgreSQL

Використовується для:
- ієрархії категорій;
- файлових дерев;
- структури документації;
- меню з підрозділами;
- групування завдань.

Вкладеність має бути зрозумілою візуально та не надто глибокою.

## 3. Анатомія елемента списку

Один елемент списку може містити кілька частин.

Наприклад, елемент списку завдань:

    [✓] Основи HTML
        Завершено 12 жовтня
                                  [⋯]

Можливі складові:

- **Marker** — маркер або індикатор;
- **Title** — назва;
- **Description** — короткий опис;
- **Metadata** — додаткова інформація;
- **Status** — статус;
- **Action** — дія;
- **Thumbnail** — мініатюра або аватар.

Не кожен елемент потребує всіх цих частин.

### 3.1. Marker — маркер

Допомагає візуально відрізнити елементи або показати їхній тип.

Приклади:
- крапка;
- номер;
- чекбокс;
- іконка;
- кольоровий індикатор;
- аватар.

Маркер повинен відповідати призначенню списку.

Наприклад, для послідовності кроків доречна нумерація, а для виконання завдань — чекбокси.

### 3.2. Title — назва

Назва повідомляє, що саме представляє елемент.

Приклади:
- «Основи HTML»;
- «Оновлення профілю»;
- «Замовлення #1042»;
- «Повідомлення від адміністратора».

Назва зазвичай є головним текстовим елементом.

### 3.3. Description — опис

Опис пояснює або доповнює назву.

Приклад:

    Основи HTML
    Вивчення структури HTML-документа та основних тегів.

Опис має бути коротким і корисним.

Якщо користувачеві потрібна лише назва, додатковий текст може створювати зайвий візуальний шум.

### 3.4. Metadata — метадані

Метадані містять другорядну інформацію.

Приклади:
- дата;
- автор;
- розмір файлу;
- кількість коментарів;
- час оновлення;
- категорія.

    Звіт про успішність
    Оновлено 14 жовтня · PDF · 2,4 MB

Метадані повинні бути менш помітними за основний вміст, але залишатися читабельними.

### 3.5. Action — дія

Дія дозволяє взаємодіяти з елементом.

Приклади:
- відкрити;
- редагувати;
- видалити;
- завантажити;
- позначити як прочитане.

Не роби весь елемент клікабельним, якщо всередині нього є кілька незалежних кнопок і посилань без чіткої моделі взаємодії.

## 4. Візуальна ієрархія списку

Користувач часто не читає кожен елемент повністю. Він швидко переглядає список, шукаючи потрібну інформацію.

Тому важливо визначити, які частини мають привертати увагу першими.

### 4.1. Розмір тексту

Зазвичай:
- назва має найбільшу візуальну вагу;
- опис має звичайну вагу;
- метадані менш помітні;
- дії виділяються лише настільки, наскільки це потрібно.

Приклад CSS:

    .list-item__title {
      font-size: 1rem;
      font-weight: 600;
    }

    .list-item__description {
      font-size: 0.875rem;
      line-height: 1.5;
    }

    .list-item__meta {
      font-size: 0.8125rem;
      color: #64748b;
    }

Не зменшуй текст метаданих настільки, щоб його було важко прочитати.

### 4.2. Відступи

Відступи допомагають розділяти елементи та групувати пов'язану інформацію.

Приклад:

    .list {
      display: flex;
      flex-direction: column;
      gap: 12px;
    }

Внутрішні відступи елемента:

    .list-item {
      padding: 12px 16px;
    }

Необхідно розрізняти:
- відстань між елементами;
- відстань між назвою й описом;
- відстань між текстом та іконкою;
- внутрішні відступи контейнера.

### 4.3. Розділювачі

Елементи можна відокремлювати горизонтальними межами.

    .list-item {
      padding: 16px 0;
      border-bottom: 1px solid #e2e8f0;
    }

    .list-item:last-child {
      border-bottom: none;
    }

Розділювачі особливо корисні в довгих списках із щільним компонуванням.

Для коротких списків можна використовувати лише відступи.

### 4.4. Групування

Великі списки легше переглядати, якщо розділити їх на логічні групи.

Приклад:

    Сьогодні
      Повідомлення 1
      Повідомлення 2

    Учора
      Повідомлення 3
      Повідомлення 4

Групування можна виконувати за:
- датою;
- категорією;
- статусом;
- типом;
- алфавітом;
- важливістю.

Заголовки груп повинні пояснювати принцип групування.

## 5. Щільність списку (List Density)

**List Density** — це кількість інформації, яку інтерфейс розміщує в певному просторі.

Зазвичай виділяють три варіанти.

### 5.1. Compact — компактний

Елементи мають невеликі відступи й займають мало місця.

Підходить для:
- адміністративних панелей;
- довгих списків;
- таблиць із великою кількістю записів;
- досвідчених користувачів, які часто працюють із даними.

### 5.2. Comfortable — комфортний

Має помірні відступи й добре підходить для повсякденного використання.

Підходить для:
- списків завдань;
- повідомлень;
- налаштувань;
- списків документів.

### 5.3. Spacious — просторий

Має великі відступи й більше простору навколо вмісту.

Підходить для:
- невеликих списків;
- важливих завдань;
- інтерфейсів із невеликою кількістю інформації;
- сенсорних пристроїв.

### Приклад CSS

    .list--compact .list-item {
      padding: 6px 12px;
    }

    .list--comfortable .list-item {
      padding: 12px 16px;
    }

    .list--spacious .list-item {
      padding: 20px 16px;
    }

Щільність потрібно обирати відповідно до контексту, розміру екрана та способу взаємодії.

## 6. Інтерактивні стани списків

Якщо елементи списку інтерактивні, потрібно продумати їхні стани.

Основні стани:
- Default — звичайний;
- Hover — наведення;
- Focus — клавіатурний фокус;
- Active — натискання;
- Selected — вибраний;
- Disabled — недоступний;
- Completed — завершений;
- Loading — завантаження;
- Error — помилка, якщо елемент пов'язаний із операцією.

### 6.1. Hover State

Приклад CSS:

    .list-item--interactive:hover {
      background-color: #f8fafc;
    }

Hover допомагає зрозуміти, що елемент реагує на наведення.

Але на сенсорних пристроях немає постійного стану наведення, тому важливу інформацію не можна передавати лише через Hover.

### 6.2. Focus State

Фокус показує, який елемент доступний для взаємодії з клавіатури.

    .list-item--interactive:focus-visible {
      outline: 2px solid #2563eb;
      outline-offset: 2px;
    }

Не прибирай стандартний фокус без створення зрозумілої альтернативи.

### 6.3. Selected State

Вибраний елемент може мати:
- змінений фон;
- рамку;
- чекбокс;
- індикатор вибору;
- текстовий статус.

Приклад CSS:

    .list-item--selected {
      background-color: #eff6ff;
      border-color: #93c5fd;
    }

Вибір повинен бути зрозумілим і без сприйняття кольору.

### 6.4. Disabled State

Недоступний елемент не можна активувати.

Приклади:
- дія ще недоступна;
- користувач не має відповідних прав;
- процес тимчасово заблокований.

Пояснюй причину недоступності, якщо це допомагає користувачеві зрозуміти ситуацію.

## 7. Списки завдань (Task Lists)

Список завдань допомагає відстежувати роботу та її виконання.

Приклад:

    [✓] Створити HTML-структуру
    [✓] Додати CSS-стилі
    [ ] Реалізувати JavaScript
    [ ] Перевірити адаптивність

### Основні елементи

- чекбокс;
- назва завдання;
- за потреби — опис;
- термін виконання;
- статус;
- додаткові дії.

### Позначення виконаного завдання

Виконане завдання може:
- мати встановлений чекбокс;
- змінювати текстовий статус;
- отримувати менш помітний вигляд;
- показувати дату завершення.

Приклад CSS:

    .task--completed .task__title {
      color: #64748b;
      text-decoration: line-through;
    }

Не роби виконане завдання майже невидимим, якщо користувачеві потрібно переглядати історію роботи.

### Порядок завдань

Список може сортуватися:
- за пріоритетом;
- за терміном;
- за датою створення;
- за статусом.

Якщо користувач може змінювати порядок перетягуванням, інтерфейс має зрозуміло показувати, що елементи можна переміщувати.

---

## 8. Навігаційні списки (Navigation Lists)

Навігаційні списки допомагають переходити між розділами застосунку.

Приклад:

    Головна
    Навчальні курси
    Завдання
    Результати
    Налаштування

### Активний пункт

Активний пункт показує поточне розташування користувача.

Його можна виділити за допомогою:
- іншого фону;
- зміни кольору тексту;
- вертикальної межі;
- іконки;
- зміни насиченості шрифту.

Важливо, щоб активний пункт не був схожим на недоступний.

### Основна та другорядна навігація

Основна навігація містить головні розділи продукту.

Другорядна навігація може містити:
- підрозділи;
- фільтри категорій;
- локальні вкладки;
- посилання на додаткові налаштування.

Не перетворюй навігаційний список на довгий набір рівнозначних пунктів. Групуй їх за змістом.

---

## 9. Списки з аватарами та мініатюрами

Списки з візуальними елементами часто використовуються для контактів, повідомлень, товарів і курсів.

Приклад:

    [Аватар]  Олена Коваленко
              Викладач інформатики

    [Аватар]  Іван Петренко
              Учень 8-Б класу

### Рекомендації

- використовуй однакові розміри аватарів у межах одного списку;
- не допускай випадкового розтягування зображень;
- залишай достатньо місця для тексту;
- обрізай зображення послідовно;
- передбачай альтернативний текст там, де зображення передає важливу інформацію.

Приклад CSS:

    .list-item__avatar {
      width: 40px;
      height: 40px;
      flex-shrink: 0;
      border-radius: 50%;
      object-fit: cover;
    }

Якщо аватар лише дублює ім'я користувача й не додає окремої інформації, його альтернативний текст може бути порожнім.

## 10. Списки повідомлень і сповіщень

Списки повідомлень часто містять:
- відправника;
- тему;
- короткий текст;
- дату;
- статус прочитання;
- додаткові дії.

Приклад:

    Олена Коваленко
    Перевірка домашнього завдання
    Вашу роботу перевірено...
    14 жовтня

### Непрочитані повідомлення

Непрочитаний елемент можна виділити:
- насиченішим шрифтом;
- індикатором;
- міткою «Нове»;
- іншим фоном.

Не покладайся лише на зміну кольору.

### Сортування повідомлень

Часто повідомлення сортують за часом, але іноді важливіші:
- пріоритет;
- непрочитаний статус;
- тип повідомлення.

Порядок має відповідати очікуванням користувача.

## 11. Списки з групуванням і вкладеністю

Вкладені списки допомагають показувати ієрархію.

Приклад:

    Курси
      Frontend
        HTML
        CSS
        JavaScript
      Backend
        Node.js
        PostgreSQL

### Візуальне оформлення

Вкладеність можна передавати через:
- відступи;
- розділювачі;
- іконки розгортання;
- заголовки груп;
- різну візуальну вагу.

### Expand / Collapse

Користувач може розгортати й згортати групи.

Приклад:

    ▼ Frontend
        HTML
        CSS
        JavaScript

    ▶ Backend

Позначення:
- `▼` — група розгорнута;
- `▶` — група згорнута.

У реальному інтерфейсі краще використовувати відповідні іконки та доступні назви станів.

### Рекомендації

✔ Показуй, які групи можна розгортати.

✔ Не використовуй надто глибоку вкладеність.

✔ Зберігай послідовні відступи.

✔ Не змішуй навігацію та розгортання в одну незрозумілу дію.

✔ Дозволяй керувати інтерактивними групами з клавіатури.

## 12. Сортування та фільтрація списків

Для довгих списків корисно додавати сортування й фільтри.

### Sorting — сортування

Можливі варіанти:
- за алфавітом;
- за датою;
- за популярністю;
- за пріоритетом;
- за назвою;
- за статусом.

### Filtering — фільтрація

Дозволяє залишити лише потрібні елементи.

Приклад:

    Категорія: [Усі ▼]
    Статус:    [Активні ▼]

### Пошук

Для великих списків можна додати поле пошуку.

    [Пошук елементів...]

### UX-принципи

- показуй активні фільтри;
- дозволяй очистити умови;
- пояснюй, коли результатів немає;
- зберігай передбачуваний порядок;
- не додавай складні фільтри до невеликого списку без потреби.

Якщо список містить лише п'ять елементів, окреме поле пошуку може бути зайвим.

## 13. Порожній стан списку (Empty State)

Порожній стан з'являється, коли список не має елементів для відображення.

Приклад:

    У вас поки немає завдань.

    Створіть перше завдання, щоб почати роботу.

    [Створити завдання]

Хороший Empty State пояснює:
- чому список порожній, якщо це відомо;
- що користувач може зробити далі;
- як додати перший елемент;
- чи потрібно змінити умови пошуку.

### Розрізняй різні ситуації

**Список справді порожній:**

    Ви ще не додали жодного контакту.

**Пошук не дав результатів:**

    За вашим запитом нічого не знайдено.

**Фільтри приховали всі елементи:**

    Немає елементів, що відповідають вибраним фільтрам.

**Дані завантажуються:**

    Завантаження списку...

Ці стани не повинні підміняти один одного.

## 14. Loading State — завантаження списку

Під час отримання даних список може показувати індикатор або Skeleton Items.

### Skeleton Items

Це тимчасові блоки, які імітують майбутні елементи списку.

Використовуй їх, коли:
- структура елементів відома;
- завантаження займає помітний час;
- потрібно зберегти компонування сторінки.

Приклад структури:

    [████]  █████████████
            █████████

    [████]  ███████████
            ██████

Не показуй повідомлення «Список порожній», якщо система ще не завершила завантаження даних.

## 15. Error State — помилка списку

Якщо дані не вдалося отримати, повідом користувача про проблему.

Приклад:

    Не вдалося завантажити список.

    Спробуйте ще раз.

    [Повторити]

Хороший Error State:
- чітко називає проблему;
- не показує вигадані дані;
- пропонує наступну дію;
- не розкриває внутрішні технічні повідомлення;
- за можливості зберігає пошуковий запит і фільтри.

Помилка завантаження не означає, що список порожній.

## 16. Responsive Lists — адаптивні списки

Списки часто добре адаптуються до різних екранів, але все одно потребують перевірки.

### Основні принципи

- дозволяй тексту переноситися;
- зменшуй кількість другорядних елементів;
- не допускай горизонтального переповнення;
- забезпечуй достатній розмір інтерактивних областей;
- розміщуй кнопки так, щоб їх було зручно натискати;
- перевіряй довгі назви та метадані.

Приклад CSS:

    .list-item {
      display: flex;
      align-items: flex-start;
      gap: 12px;
      padding: 12px 16px;
    }

    .list-item__content {
      flex: 1;
      min-width: 0;
    }

    .list-item__title {
      overflow-wrap: anywhere;
    }

`min-width: 0` особливо корисний для дочірнього елемента Flexbox, коли його вміст не повинен розширювати контейнер понад доступну ширину.

### Мобільний інтерфейс

На мобільному пристрої:
- збільшуй зручність натискання;
- розміщуй важливі дії поруч із відповідним елементом;
- не приховуй необхідну інформацію;
- використовуй зрозумілі іконки;
- перевіряй список на довгих текстах.

## 17. Accessibility — доступність списків

Списки повинні бути зрозумілими для користувачів, які використовують клавіатуру, скринрідери та інші допоміжні технології.

### Основні правила

✔ Використовуй семантичні HTML-елементи.

✔ Зберігай логічний порядок елементів.

✔ Забезпечуй видимий клавіатурний фокус.

✔ Додавай зрозумілі назви кнопок та посилань.

✔ Не покладайся лише на колір.

✔ Не використовуй маркери як єдиний спосіб передавання важливого значення.

✔ Перевіряй доступність інтерактивних елементів.

### Семантичні елементи HTML

- `<ul>` — ненумерований список;
- `<ol>` — нумерований список;
- `<li>` — елемент списку;
- `<dl>` — список описів;
- `<dt>` — термін;
- `<dd>` — опис;
- `<nav>` — навігаційна область.

### Приклад доступного списку

    <ul aria-label="Список навчальних курсів">
      <li>
        <a href="/courses/html">
          Основи HTML
        </a>
      </li>

      <li>
        <a href="/courses/css">
          Основи CSS
        </a>
      </li>

      <li>
        <a href="/courses/javascript">
          JavaScript
        </a>
      </li>
    </ul>

Якщо список має видимий заголовок, часто краще пов'язати його з контейнером за допомогою `aria-labelledby`, а не дублювати назву через `aria-label`.

Приклад:

    <h2 id="courses-heading">Навчальні курси</h2>

    <ul aria-labelledby="courses-heading">
      <li><a href="/courses/html">Основи HTML</a></li>
      <li><a href="/courses/css">Основи CSS</a></li>
    </ul>

### Інтерактивні елементи

Якщо елемент списку є посиланням, використовуй `<a>`.

Якщо елемент запускає дію, використовуй `<button>`.

Не використовуй клікабельний `<div>` замість відповідного семантичного елемента без вагомої причини.

Для чекбоксів застосовуй справжні елементи `<input type="checkbox">` або відповідні доступні компоненти.

## 18. Список чи таблиця?

Не кожен набір даних потребує таблиці.

| Критерій | Список | Таблиця |
|---|---|---|
| Основна мета | Перегляд елементів | Порівняння значень |
| Структура | Вертикальна послідовність | Рядки та стовпці |
| Кількість характеристик | Зазвичай невелика | Часто багато |
| Мобільний перегляд | Часто простіший | Може потребувати адаптації |
| Приклад | Повідомлення | Фінансові транзакції |

### Коли краще використовувати список

- коли головне — назва та короткий опис;
- коли елементи містять різні за структурою дані;
- коли потрібна вертикальна навігація;
- коли важливо швидко переглядати окремі об'єкти.

### Коли краще використовувати таблицю

- коли потрібно порівнювати кілька характеристик;
- коли кожен запис має однаковий набір полів;
- коли важливі сортування за стовпцями;
- коли користувач працює з великим набором структурованих даних.

**Головне запитання:** користувач переглядає окремі елементи чи порівнює значення між ними?

Створимо простий список навчальних завдань.

    }

      font-size: 1rem;

### Що тут важливо

- `<ul>` задає семантичну структуру списку.
- `<li>` представляє окреме завдання.
- `display: flex` розміщує індикатор поруч із текстом.
- `gap` створює відстань між елементами.
- `min-width: 0` допомагає уникнути переповнення вмісту.
- `list-style: none` прибирає стандартні маркери, оскільки використовується власне оформлення.

У цьому прикладі індикатори декоративні. Для справжнього списку завдань, у якому користувач може змінювати стан, потрібно додати інтерактивні чекбокси або кнопки з відповідною доступністю.

## 20. Приклад інтерактивного списку завдань у JavaScript

Нижче — навчальний приклад, у якому користувач може позначати завдання як виконані.

### HTML

    <ul id="task-list">
      <li>
        <label>
          <input type="checkbox">
          Повторити HTML
        </label>
      </li>

      <li>
        <label>
          <input type="checkbox">
          Повторити CSS
        </label>
      </li>

      <li>
        <label>
          <input type="checkbox">
          Створити сторінку
        </label>
      </li>
    </ul>

    <p id="task-summary" role="status">
      Виконано 0 із 3 завдань.
    </p>

### JavaScript

    "use strict";

    const taskList = document.querySelector("#task-list");
    const taskSummary = document.querySelector("#task-summary");

    const checkboxes = taskList.querySelectorAll(
      'input[type="checkbox"]'
    );

    function updateTaskSummary() {
      const completedCount = [...checkboxes].filter(
        (checkbox) => checkbox.checked
      ).length;

      taskSummary.textContent =
        `Виконано ${completedCount} із ${checkboxes.length} завдань.`;
    }

    checkboxes.forEach((checkbox) => {
      checkbox.addEventListener("change", updateTaskSummary);
    });

    updateTaskSummary();

### Що відбувається

1. Знаходимо список і повідомлення з підсумком.
2. Отримуємо всі чекбокси.
3. Підраховуємо кількість позначених завдань.
4. Оновлюємо текст підсумку.
5. Повторюємо підрахунок після кожної зміни чекбокса.

`role="status"` допомагає допоміжним технологіям повідомляти про оновлення підсумку.

Це навчальний приклад. Стан завдань тут не зберігається після перезавантаження сторінки. У реальному застосунку його можна зберігати в базі даних або іншому відповідному сховищі.

## 21. Типові помилки дизайну списків

### Помилка 1. Забагато інформації в одному елементі

Проблема: користувач не розуміє, на чому зосередитися.

Рішення:
- виділи основну назву;
- скороти опис;
- перенеси другорядні дані в деталі;
- прибери зайві іконки.

### Помилка 2. Немає візуального розділення

Проблема: сусідні елементи зливаються.

Рішення:
- збільш відступи;
- додай делікатні розділювачі;
- згрупуй пов'язані елементи.

### Помилка 3. Усі елементи виглядають клікабельними

Проблема: користувач не розуміє, які елементи інтерактивні.

Рішення:
- використовуй зрозумілі посилання та кнопки;
- передбачай Hover і Focus;
- не додавай курсор pointer до звичайного тексту.

### Помилка 4. Незрозумілий статус

Проблема: користувач не знає, чи завдання виконане, чи повідомлення прочитане.

Рішення:
- використовуй текстові назви;
- застосовуй послідовні індикатори;
- не покладайся лише на колір.

### Помилка 5. Надмірна вкладеність

Проблема: складно зрозуміти структуру й знайти потрібний елемент.

Рішення:
- зменш глибину вкладеності;
- розділи складні групи на окремі розділи;
- використовуй зрозумілі заголовки.

### Помилка 6. Немає порожнього стану

Проблема: порожній контейнер виглядає як помилка.

Рішення: поясни відсутність елементів і запропонуй наступну дію.

### Помилка 7. Немає стану завантаження

Проблема: користувач не розуміє, чи система працює.

Рішення: використовуй індикатор або скелетони.

### Помилка 8. Занадто дрібні кнопки

Проблема: елементами важко користуватися на сенсорних екранах.

Рішення: збільш області натискання та відстань між сусідніми діями.

### Помилка 9. Не враховані довгі назви

Проблема: текст виходить за межі контейнера або перекриває кнопки.

Рішення:
- дозволяй перенесення;
- обмежуй текст обережно;
- забезпечуй доступ до повної інформації.

### Помилка 10. Неправильна семантика HTML

Проблема: допоміжні технології не розуміють структуру списку.

Рішення: використовуй `<ul>`, `<ol>`, `<li>` та інші семантичні елементи відповідно до їхнього призначення.

## 26. Мінішпаргалка

**List** — компонент для організації інформації у вигляді послідовності елементів.

**Основні типи:**
- Unordered List — ненумерований;
- Ordered List — нумерований;
- Description List — список термінів та описів;
- Interactive List — інтерактивний;
- Navigation List — навігаційний;
- Media List — список із зображеннями;
- Nested List — вкладений.

**Основні частини елемента:**
- Marker — маркер;
- Title — назва;
- Description — опис;
- Metadata — додаткова інформація;
- Status — статус;
- Action — дія;
- Thumbnail — мініатюра.

**Основні стани:**
- Default — звичайний;
- Hover — наведення;
- Focus — клавіатурний фокус;
- Selected — вибраний;
- Disabled — недоступний;
- Completed — завершений;
- Loading — завантаження;
- Error — помилка.

**Основні можливості:**
- Sorting — сортування;
- Filtering — фільтрація;
- Search — пошук;
- Grouping — групування;
- Expand/Collapse — розгортання та згортання.

**Основні принципи:**
- чітка візуальна ієрархія;
- короткі назви;
- зрозумілі статуси;
- достатні відступи;
- послідовне оформлення;
- адаптивність;
- доступність.

**Базова HTML-структура:**

    <ul>
      <li>Перший елемент</li>
      <li>Другий елемент</li>
      <li>Третій елемент</li>
    </ul>

## Висновок

Списки — універсальний компонент UI, який допомагає впорядковувати інформацію та спрощувати взаємодію з нею.

Якісний список:
- легко переглядати;
- просто сканувати;
- зручно використовувати на різних пристроях;
- зрозуміло групувати;
- легко розширювати;
- доступно використовувати за допомогою клавіатури та допоміжних технологій.

Під час проєктування завжди запитуй себе:

**«Чи зможе користувач швидко знайти потрібний елемент, зрозуміти його значення та виконати необхідну дію?»**
