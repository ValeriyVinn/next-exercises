# 05. Breadcrumbs — Хлібні крихти (навігаційний ланцюжок)

Breadcrumbs (хлібні крихти) — це елемент навігації інтерфейсу, який показує користувачеві його поточне місце в структурі сайту або застосунку та дозволяє швидко перейти до сторінок вищого рівня.

Наприклад:

    Головна → Каталог → Комп'ютери → Ноутбуки → MacBook Pro

Breadcrumbs допомагають зрозуміти, де саме перебуває користувач, як поточна сторінка пов'язана з іншими розділами та як повернутися до батьківської категорії без використання кнопки Back у браузері.

Хлібні крихти — це не заміна основної навігації. Вони доповнюють її та особливо корисні на сайтах із глибокою ієрархією сторінок.

---

## 1. Навіщо потрібні Breadcrumbs

Breadcrumbs вирішують декілька важливих UX-завдань.

### 1.1. Показують поточне місце

Користувач бачить, до якого розділу належить сторінка.

Наприклад:

    Головна → Навчання → Курси → JavaScript → Масиви

Без такого ланцюжка користувач може не розуміти, де перебуває в структурі великого освітнього сайту.

### 1.2. Допомагають перейти на рівень вище

Якщо користувач відкрив сторінку конкретного товару, він може перейти безпосередньо до категорії.

    Головна → Магазин → Одяг → Чоловічий одяг → Куртка

Користувач може натиснути «Чоловічий одяг» і переглянути інші товари цієї категорії.

### 1.3. Зменшують відчуття складності

На великих сайтах багато сторінок, категорій і підкатегорій. Breadcrumbs роблять структуру зрозумілішою та допомагають орієнтуватися без необхідності запам'ятовувати шлях.

### 1.4. Доповнюють інформаційну архітектуру

Breadcrumbs візуально відображають зв'язки між сторінками.

Наприклад, структура освітньої платформи:

    Освітня платформа
    ├── Курси
    │   ├── JavaScript
    │   │   ├── Основи
    │   │   └── Масиви
    │   └── HTML
    └── Мій профіль

На сторінці «Масиви» ланцюжок може виглядати так:

    Головна → Курси → JavaScript → Масиви

### 1.5. Підтримують навігацію у великих каталогах

Breadcrumbs особливо корисні для:

- інтернет-магазинів;
- освітніх платформ;
- документації;
- порталів із великою кількістю розділів;
- адміністративних панелей;
- бібліотек статей;
- сайтів із багаторівневою структурою.

---

## 2. Коли використовувати Breadcrumbs

Breadcrumbs потрібні не на кожній сторінці. Їхня користь залежить від структури продукту та способу навігації.

### 2.1. Коли вони доречні

✔ Сайт має декілька рівнів вкладеності.

✔ Користувачі часто переходять між категоріями та підкатегоріями.

✔ Є великі каталоги, документація або навчальні матеріали.

✔ Важливо показати зв'язок поточної сторінки з батьківськими розділами.

✔ Користувачі можуть відкривати глибокі сторінки безпосередньо з пошуку або зовнішніх посилань.

Приклад:

    Документація → React → Hooks → useEffect

### 2.2. Коли вони можуть бути зайвими

Breadcrumbs можуть не давати суттєвої користі, якщо:

- сайт має лише кілька простих сторінок;
- структура плоска;
- основна навігація вже забезпечує достатню орієнтацію;
- сторінка є самостійним екраном без очевидного батьківського розділу;
- на мобільному екрані простіший варіант навігації зрозуміліший.

Наприклад, для невеликого сайту-візитки:

    Головна | Про нас | Контакти

окремий ланцюжок breadcrumbs може бути непотрібним.

### 2.3. Breadcrumbs не замінюють основну навігацію

Основна навігація допомагає перейти до різних розділів продукту.

Breadcrumbs показують шлях до поточної сторінки.

Наприклад:

- основне меню: «Каталог», «Новини», «Про нас», «Контакти»;
- breadcrumbs: «Головна → Каталог → Ноутбуки → MacBook Pro».

Ці елементи мають різні завдання.

## 3. Основні типи Breadcrumbs

Існує декілька способів формувати навігаційний ланцюжок. Вибір залежить від інформаційної архітектури.

### 3.1. Hierarchy-based breadcrumbs — ієрархічні

Відображають шлях від верхнього рівня до поточної сторінки.

    Головна → Курси → JavaScript → Масиви

Це найпоширеніший тип.

Використовується на сайтах, де сторінки мають чіткі батьківські та дочірні зв'язки.

### 3.2. Location-based breadcrumbs — за розташуванням

Показують, де сторінка знаходиться в структурі сайту, незалежно від того, яким шляхом користувач прийшов на неї.

Наприклад, користувач відкрив сторінку «Масиви» через пошук Google.

Breadcrumbs все одно показують:

    Головна → Курси → JavaScript → Масиви

Це допомагає зорієнтуватися навіть без попереднього перегляду батьківських сторінок.

### 3.3. Attribute-based breadcrumbs — за атрибутами

Показують послідовність вибраних характеристик або фільтрів.

Наприклад:

    Каталог → Ноутбуки → Lenovo → 16 GB RAM

Такий підхід може бути корисним у каталогах, але його не варто автоматично змішувати зі звичайною ієрархічною навігацією.

Для фільтрів часто доречніші окремі chips, активні фільтри або панель пошуку.

### 3.4. Breadcrumbs з урахуванням історії переходів

Можуть показувати шлях, яким користувач фактично прийшов до сторінки.

Наприклад:

    Головна → Пошук → Результати → Товар

Цей варіант не завжди відповідає структурі сайту. Зазвичай для орієнтації краще використовувати стабільну ієрархію, а не історію переходів.

**Практичне правило:** у більшості вебінтерфейсів починай з ієрархічних breadcrumbs.

## 4. Анатомія Breadcrumbs

Типовий компонент складається з декількох елементів.

    Головна / Каталог / Ноутбуки / MacBook Pro

Основні частини:

1. **Контейнер** — область, у якій розташований ланцюжок.
2. **Навігаційна назва** — назва кожного рівня.
3. **Посилання** — елементи, що ведуть на сторінки вищого рівня.
4. **Розділювач** — візуально відокремлює сусідні елементи.
5. **Поточна сторінка** — останній елемент ланцюжка.
6. **Мобільний варіант** — за потреби скорочує довгий шлях.
7. **Контекстна область** — відступи від заголовка, основного меню та контенту.

### 4.1. Контейнер

Контейнер визначає розташування breadcrumbs відносно інших елементів сторінки.

Зазвичай він розташований:

- під основною навігацією;
- над заголовком сторінки;
- на початку основного контенту.

Приклад:

    Основна навігація
    ──────────────────────────
    Головна → Каталог → Ноутбуки

    Ноутбуки

    Список товарів...

Breadcrumbs не повинні випадково виглядати як головний заголовок або кнопка.

### 4.2. Посилання

Усі попередні рівні зазвичай є посиланнями.

    Головна → Каталог → Ноутбуки → MacBook Pro

У цьому прикладі:

- «Головна» — посилання;
- «Каталог» — посилання;
- «Ноутбуки» — посилання;
- «MacBook Pro» — поточна сторінка.

Посилання мають вести на відповідні сторінки, а не просто виглядати клікабельними.

### 4.3. Поточна сторінка

Останній елемент показує, де перебуває користувач.

Зазвичай він:

- не є посиланням;
- має трохи сильніший контраст;
- може бути позначений через `aria-current="page"`;
- не повинен виглядати як ще один звичайний рівень переходу.

Приклад:

    Головна → Каталог → Ноутбуки → MacBook Pro
                                           ↑
                                    Поточна сторінка

### 4.4. Розділювачі

Найпоширеніші варіанти:

- `/`;
- `›`;
- `>`;
- `→`;
- невелика стрілка або шеврон.

Приклади:

    Головна / Каталог / Ноутбуки

    Головна › Каталог › Ноутбуки

    Головна → Каталог → Ноутбуки

Розділювач повинен допомагати читати послідовність, а не конкурувати з назвами.

Зазвичай достатньо нейтрального кольору та невеликого розміру.

### 4.5. Іконка головної сторінки

Замість тексту «Головна» іноді використовують іконку будинку.

    [⌂] → Каталог → Ноутбуки

Це може заощадити місце, але є ризик, що користувач не зрозуміє значення іконки.

Якщо іконка використовується без тексту:

- забезпеч доступну назву посилання;
- перевір зрозумілість символу;
- не покладайся лише на tooltip;
- зберігай достатній розмір інтерактивної області.

### 4.6. Довгі назви

Назви категорій повинні залишатися зрозумілими.

Погано:

    Головна → Електроніка → Комп'ютерна техніка для професійного використання → ...

Краще переглянути назви розділів або застосувати адаптивне скорочення.

Не скорочуй назви настільки, щоб користувач не міг зрозуміти значення елемента.

## 5. Візуальна ієрархія

Breadcrumbs — другорядний навігаційний елемент. Вони мають бути помітними, але не повинні забирати увагу в основного контенту.

### 5.1. Типографіка

Зазвичай breadcrumbs мають менший розмір шрифту, ніж заголовок сторінки.

Наприклад:

    Breadcrumbs: 14 px
    Заголовок сторінки: 32 px
    Основний текст: 16 px

Це лише орієнтовні значення, а не обов'язковий стандарт.

Важливо, щоб текст залишався читабельним на реальному пристрої.

### 5.2. Колір

Типова схема:

- попередні рівні — нейтральний колір;
- поточна сторінка — сильніший контраст;
- розділювачі — приглушений колір;
- hover — помітна зміна кольору або підкреслення;
- focus — виразний індикатор клавіатурного фокусу.

Приклад:

    Головна → Каталог → Ноутбуки

    Головна     — нейтральний текст посилання
    Каталог     — нейтральний текст посилання
    Ноутбуки    — текст поточної сторінки
    →           — приглушений розділювач

Не покладайся лише на колір для передачі стану.

### 5.3. Відступи

Відступи мають забезпечувати чітке розділення елементів.

Приклад системи:

    Відстань між текстом і розділювачем: 8 px
    Відстань між breadcrumbs і заголовком: 16 px
    Відстань між секціями сторінки: 24–32 px

У реальному дизайн-системному проєкті використовуй узгоджену шкалу spacing-токенів.

### 5.4. Розділювач не є кнопкою

Розділювач виконує візуальну функцію.

Він не повинен:

- отримувати клавіатурний фокус;
- реагувати на натискання;
- мати вигляд самостійного посилання;
- створювати додаткову інтерактивність.

## 6. Інформаційна архітектура та Breadcrumbs

Якість breadcrumbs залежить насамперед від якості структури сайту.

### 6.1. Правильна ієрархія

Припустімо, структура освітнього сайту така:

    Головна
    ├── Курси
    │   ├── Frontend
    │   │   ├── HTML
    │   │   ├── CSS
    │   │   └── JavaScript
    │   │       ├── Основи
    │   │       ├── Масиви
    │   │       └── Асинхронність
    │   └── Backend
    └── Профіль

Для сторінки «Масиви» правильний ланцюжок:

    Головна → Курси → Frontend → JavaScript → Масиви

Якщо breadcrumbs показують випадковий шлях, це може свідчити про проблему інформаційної архітектури.

### 6.2. Не плутай ієрархію з URL

URL і breadcrumbs можуть бути пов'язані, але це не обов'язково однакова структура.

Наприклад, URL:

    /learn/javascript/arrays

Breadcrumbs:

    Головна → Навчання → JavaScript → Масиви

Назви можуть бути зрозумілішими за технічні сегменти URL.

Не потрібно автоматично перетворювати кожну частину URL на пункт breadcrumbs.

### 6.3. Не показуй випадковий шлях користувача

Уявімо, користувач відкрив сторінку товару через:

1. головну сторінку;
2. пошук;
3. рекламне оголошення;
4. зовнішнє посилання.

Breadcrumbs повинні залишатися стабільними, якщо структура товару не змінюється.

Для товару в каталозі:

    Головна → Каталог → Ноутбуки → MacBook Pro

Це надійніше, ніж відображати різний ланцюжок залежно від попередньої сторінки.

### 6.4. Сторінки з декількома батьківськими категоріями

Іноді одна сторінка належить до декількох категорій.

Наприклад, товар може бути одночасно в категоріях «Ноутбуки» та «Робочі станції».

Не намагайся відобразити всі можливі шляхи одночасно. Визнач основний контекст, який найкраще відповідає структурі продукту.

Якщо основного шляху немає, розглянь інші способи навігації: категорії, теги, пов'язані розділи.

### 6.5. Послідовність назв

Назви повинні бути послідовними та зрозумілими.

Погано:

    Головна → Навчання → JS → Масиви JavaScript

Краще:

    Головна → Навчання → JavaScript → Масиви

Використовуй узгоджені назви в меню, заголовках сторінок і breadcrumbs.

## 7. Стани Breadcrumbs

Хоча breadcrumbs простіші за більшість UI-компонентів, для них також потрібно продумати різні стани.

### 7.1. Default

Звичайний стан.

    Головна → Каталог → Ноутбуки

Посилання мають бути помітними та читабельними.

### 7.2. Hover

Користувач навів курсор на посилання.

Можливі зміни:

- підкреслення;
- зміна кольору;
- легке посилення контрасту.

Не потрібно застосовувати надмірні анімації або збільшувати елемент настільки, щоб він зміщував сусідні елементи.

### 7.3. Focus

Користувач перейшов до посилання клавіатурою.

Потрібно показати виразний індикатор фокусу.

Наприклад:

    Головна → [Каталог] → Ноутбуки

Фокус має бути видимим незалежно від кольору тексту.

### 7.4. Current

Поточна сторінка позначена як активний елемент.

    Головна → Каталог → Ноутбуки

«Ноутбуки» — поточна сторінка, а не звичайне посилання на батьківський рівень.

### 7.5. Long path

Коли ланцюжок надто довгий, він може не вміщуватися в контейнер.

Можливі рішення:

- перенести ланцюжок на наступний рядок;
- скоротити проміжні назви за продуманими правилами;
- показати частину шляху та кнопку розкриття;
- застосувати горизонтальне прокручування, якщо воно справді зрозуміле й зручне.

Не обрізай шлях без можливості зрозуміти контекст.

### 7.6. Loading та Error

Для звичайних breadcrumbs окремі стани завантаження часто не потрібні.

Якщо структура навігації залежить від даних, які завантажуються асинхронно, можна:

- тимчасово приховати breadcrumbs;
- показати стабільний placeholder;
- відобразити відому частину шляху.

Не показуй помилкову ієрархію лише для того, щоб заповнити місце.

## 8. Responsive Breadcrumbs

На великому екрані довгий шлях може поміститися повністю. На мобільному пристрої доступної ширини значно менше.

Тому breadcrumbs потрібно проєктувати для різних розмірів екрана.

### 8.1. Desktop

На широкому екрані можна показати повний ланцюжок.

    Головна → Каталог → Електроніка → Комп'ютери → Ноутбуки

Переваги:

- повна інформація про ієрархію;
- зрозумілі переходи;
- зручне орієнтування в глибокій структурі.

### 8.2. Tablet

На планшеті зазвичай можна зберегти повний ланцюжок, якщо назви короткі.

Якщо він не вміщується:

- скороти другорядні проміжні елементи;
- перенеси ланцюжок на новий рядок;
- використай адаптивний варіант.

Не визначай поведінку лише за назвою пристрою. Враховуй фактичну ширину контейнера.

### 8.3. Mobile

На вузькому екрані можна залишити поточну сторінку та один рівень вище.

Наприклад:

    ← Ноутбуки

Або показати скорочений ланцюжок:

    Головна → … → Ноутбуки

Перший варіант економить простір, другий зберігає більше контексту.

Вибирай варіант відповідно до того, як користувачі переміщуються сайтом.

### 8.4. Горизонтальне прокручування

Горизонтальне прокручування може бути корисним для дуже довгих ланцюжків, але часто має недоліки:

- користувач може не помітити приховані елементи;
- частина шляху може залишатися за межами екрана;
- клавіатурна навігація стає менш очевидною.

Тому спочатку перевір можливість адаптивного скорочення або перенесення рядка.

## 9. Accessibility — доступність Breadcrumbs

Навігаційний ланцюжок повинен бути доступним для користувачів клавіатури та допоміжних технологій.

### 9.1. Використовуй семантичний `<nav>`

Breadcrumbs — це навігаційний елемент.

Якщо на сторінці вже є основна навігація, назви області мають допомагати розрізняти їх.

    <nav aria-label="Breadcrumb">
      <!-- Breadcrumb items -->
    </nav>

Для україномовного інтерфейсу можна використати зрозумілу локалізовану назву:

    <nav aria-label="Навігаційний ланцюжок">
      <!-- Breadcrumb items -->
    </nav>

### 9.2. Використовуй список

Послідовність сторінок логічно оформити як список.

    <nav aria-label="Навігаційний ланцюжок">
      <ol>
        <li><a href="/">Головна</a></li>
        <li><a href="/catalog">Каталог</a></li>
        <li aria-current="page">Ноутбуки</li>
      </ol>
    </nav>

Список відображає послідовність рівнів і забезпечує семантичну структуру.

### 9.3. Позначай поточну сторінку

Атрибут `aria-current="page"` повідомляє допоміжним технологіям, що елемент відповідає поточній сторінці.

    <li aria-current="page">Ноутбуки</li>

Не потрібно робити поточну сторінку посиланням без вагомої причини.

### 9.4. Забезпеч клавіатурну навігацію

Користувач повинен мати змогу переходити між посиланнями за допомогою клавіші `Tab`.

Не прибирай стандартний outline без заміни на видимий індикатор.

    .breadcrumbs a:focus-visible {
      outline: 2px solid #2563eb;
      outline-offset: 3px;
      border-radius: 2px;
    }

### 9.5. Декоративні розділювачі

Розділювачі не повинні створювати зайвий шум для скринридерів.

Для декоративного символу можна використати `aria-hidden="true"`.

    <span aria-hidden="true">›</span>

Не роби розділювач окремим посиланням або кнопкою.

### 9.6. Контраст

Текст і стани взаємодії повинні бути достатньо контрастними.

Особливо перевір:

- приглушені посилання;
- дрібний текст;
- індикатор фокусу;
- поточний елемент;
- розділювачі на різних фонах.

Не роби посилання настільки світлими, що їх важко прочитати.

### 9.7. Розмір інтерактивної області

Хоча текст breadcrumbs часто невеликий, посилання мають бути зручними для натискання.

На сенсорних пристроях передбач достатній простір навколо інтерактивних елементів. За можливості орієнтуйся на цільовий розмір близько 44 × 44 CSS-пікселів для touch-контролів, не перетворюючи сам текст на громіздкий блок.

### 9.8. Не покладайся лише на tooltip

Tooltip може пояснювати значення іконки, але не повинен бути єдиним джерелом важливої інформації.

Якщо замість «Головна» використовується іконка, посилання повинно мати доступну назву.

Розглянемо базову реалізацію breadcrumbs для сторінки ноутбуків.

      aria-label="Навігаційний ланцюжок"

- `aria-current="page"` позначає поточну сторінку.
- `aria-hidden="true"` приховує декоративні розділювачі від допоміжних технологій.

## 12. Практичний приклад: JavaScript

Звичайні breadcrumbs часто можна реалізувати без JavaScript, використовуючи HTML і CSS.

JavaScript потрібен, якщо шлях формується динамічно на основі даних.

Наприклад, маємо масив елементів:

    const breadcrumbs = [
      {
        label: "Головна",
        href: "/",
      },
      {
        label: "Курси",
        href: "/courses",
      },
      {
        label: "JavaScript",
        href: "/courses/javascript",
      },
      {
        label: "Масиви",
        href: null,
      },
    ];

Тут `href: null` означає, що останній елемент є поточною сторінкою.

Функція створення елементів:

    function createBreadcrumbs(items) {
      const nav = document.createElement("nav");
      nav.className = "breadcrumbs";
      nav.setAttribute(
        "aria-label",
        "Навігаційний ланцюжок"
      );

      const list = document.createElement("ol");
      list.className = "breadcrumbs__list";

      items.forEach((item, index) => {
        const listItem = document.createElement("li");
        listItem.className = "breadcrumbs__item";

        const isCurrent = index === items.length - 1;

        if (isCurrent) {
          listItem.classList.add(
            "breadcrumbs__current"
          );

          listItem.setAttribute(
            "aria-current",
            "page"
          );

          listItem.textContent = item.label;
        } else {
          const link = document.createElement("a");

          link.className = "breadcrumbs__link";
          link.href = item.href;
          link.textContent = item.label;

          listItem.append(link);

          const separator = document.createElement("span");

          separator.className =
            "breadcrumbs__separator";

          separator.setAttribute(
            "aria-hidden",
            "true"
          );

          separator.textContent = "›";

          listItem.append(separator);
        }

        list.append(listItem);
      });

      nav.append(list);

      return nav;
    }

Використання:

    const breadcrumbElement =
      createBreadcrumbs(breadcrumbs);

    document
      .querySelector("#breadcrumb-container")
      .append(breadcrumbElement);

HTML-контейнер:

    <div id="breadcrumb-container"></div>

### Що варто запам'ятати

1. Для тексту використовується `textContent`, а не `innerHTML`. Це допомагає уникнути небезпечної інтерпретації довільного тексту як HTML.
2. Останній елемент позначається як поточна сторінка.
3. Батьківські елементи є посиланнями.
4. Якщо дані можуть бути неповними, потрібно перевіряти їх перед створенням компоненту.
5. У реальному застосунку краще використовувати перевірену структуру маршрутів, а не формувати навігацію з довільних рядків URL.

## 13. Breadcrumbs у React

У React breadcrumbs зручно створювати як повторно використовуваний компонент.

Приклад типу даних у TypeScript:

    type BreadcrumbItem = {
      label: string;
      href?: string;
    };

Компонент:

    type BreadcrumbsProps = {
      items: BreadcrumbItem[];
    };

    export function Breadcrumbs({
      items,
    }: BreadcrumbsProps) {
      return (
        <nav
          className="breadcrumbs"
          aria-label="Навігаційний ланцюжок"
        >
          <ol className="breadcrumbs__list">
            {items.map((item, index) => {
              const isCurrent =
                index === items.length - 1;

              return (
                <li
                  className="breadcrumbs__item"
                  key={`${item.label}-${index}`}
                >
                  {isCurrent || !item.href ? (
                    <span
                      className="breadcrumbs__current"
                      aria-current="page"
                    >
                      {item.label}
                    </span>
                  ) : (
                    <a
                      className="breadcrumbs__link"
                      href={item.href}
                    >
                      {item.label}
                    </a>
                  )}

                  {!isCurrent && (
                    <span
                      className="breadcrumbs__separator"
                      aria-hidden="true"
                    >
                      ›
                    </span>
                  )}
                </li>
              );
            })}
          </ol>
        </nav>
      );
    }

Використання:

    <Breadcrumbs
      items={[
        {
          label: "Головна",
          href: "/",
        },
        {
          label: "Курси",
          href: "/courses",
        },
        {
          label: "JavaScript",
          href: "/courses/javascript",
        },
        {
          label: "Масиви",
        },
      ]}
    />

### Важливі деталі React-компонента

- Тип `BreadcrumbItem` описує форму даних.
- `items.map()` створює елемент для кожного рівня.
- `key` допомагає React ідентифікувати елементи списку.
- Останній елемент відображається як поточна сторінка.
- Посилання використовуються лише там, де є адреса переходу.

У застосунку з Next.js варто використовувати компонент `Link` для внутрішніх маршрутів замість звичайного `<a>`, якщо це відповідає структурі проєкту.

Також у production-компоненті бажано перевіряти, що `items` не порожній, назви не повторюються випадково, а останній елемент справді відповідає поточному маршруту.

## 14. Breadcrumbs у Next.js

У Next.js breadcrumbs часто залежать від поточного маршруту.

Наприклад:

    /courses/javascript/arrays

Може відповідати:

    Головна → Курси → JavaScript → Масиви

### 14.1. Не генеруй назви лише з URL

Можна розбити URL на сегменти, але автоматичне перетворення:

    /courses/javascript/arrays

на:

    Courses → Javascript → Arrays

не завжди створює якісний інтерфейс.

Причини:

- сегменти можуть бути технічними ідентифікаторами;
- назви можуть мати локалізацію;
- сторінка може мати складнішу ієрархію;
- динамічні сегменти можуть містити ID;
- URL не завжди відображає реальну структуру контенту.

### 14.2. Краще використовувати метадані маршруту

Наприклад, можна визначити назви та адреси окремо:

    const breadcrumbMap = {
      courses: {
        label: "Курси",
        href: "/courses",
      },
      javascript: {
        label: "JavaScript",
        href: "/courses/javascript",
      },
      arrays: {
        label: "Масиви",
        href: "/courses/javascript/arrays",
      },
    };

У реальному TypeScript-проєкті потрібно типізувати цю структуру та узгодити її з маршрутизацією.

### 14.3. Використовуй актуальні дані сторінки

Для сторінки товару:

    Головна → Каталог → Ноутбуки → MacBook Pro

Назва «MacBook Pro» може надходити з даних товару, а не з URL.

Для сторінки курсу:

    Головна → Курси → JavaScript → Масиви

Назви можуть надходити з конфігурації навчальної платформи.

**Головне:** breadcrumbs мають відображати логічну структуру продукту, а не лише технічний шлях запиту.

## 15. Дизайн-система та Breadcrumbs

У дизайн-системі breadcrumbs варто визначити як окремий компонент із передбачуваними правилами.

### 15.1. Design tokens

Приклад CSS-змінних:

    :root {
      --breadcrumb-font-size: 0.875rem;
      --breadcrumb-line-height: 1.5;

      --breadcrumb-gap: 0.5rem;

      --breadcrumb-margin-bottom: 1.25rem;

Це приклад, а не універсальні значення.

У великому проєкті кольори та відступи мають відповідати загальній системі токенів.

### 15.2. Варіанти компонента

Можливі варіанти:

- `default` — звичайний ланцюжок;
- `compact` — скорочений варіант для вузького простору;
- `with-home-icon` — варіант з іконкою головної сторінки;
- `truncated` — варіант із прихованими проміжними рівнями.

Не створюй багато варіантів без реальної потреби.

### 15.3. Узгоджені правила

Для всіх breadcrumbs у продукті визнач:

- типографіку;
- кольори;
- розділювач;
- відступи;
- поведінку на вузькому екрані;
- стиль focus і hover;
- спосіб позначення поточної сторінки;
- правила скорочення довгого шляху;
- правила доступності.

Це дозволяє підтримувати однаковий UX у різних розділах продукту.

## 16. Типові помилки

### Помилка 1. Breadcrumbs не відповідають структурі сайту

Наприклад:

    Головна → Профіль → Каталог → Ноутбуки

Якщо «Каталог» не є дочірнім розділом «Профілю», шлях вводить користувача в оману.

**Рішення:** використовуй стабільну логічну ієрархію.

### Помилка 2. Поточна сторінка виглядає як звичайне посилання

Користувач не розуміє, чи можна перейти далі.

**Рішення:** візуально відрізняй поточний елемент і позначай його через `aria-current="page"`.

### Помилка 3. Breadcrumbs замінюють основне меню

Користувач може переходити лише на батьківські рівні, але не може легко перейти до іншого розділу.

**Рішення:** залиш основну навігацію та використовуй breadcrumbs як додатковий інструмент.

### Помилка 4. Занадто довгі назви

Ланцюжок займає багато місця та ускладнює читання.

**Рішення:** оптимізуй назви розділів, передбач адаптивну поведінку, перевіряй реальні сценарії.

### Помилка 5. Занадто багато рівнів

Наприклад:

    Головна → Розділ 1 → Розділ 2 → Розділ 3 → Розділ 4 → Розділ 5 → Сторінка

Це може бути ознакою надто глибокої інформаційної архітектури.

**Рішення:** перевір, чи можна спростити структуру. Самі breadcrumbs не усувають проблеми надмірної вкладеності.

### Помилка 6. Розділювачі мають інтерактивний вигляд

Користувач очікує, що стрілка або `/` також є кнопкою.

**Рішення:** використовуй декоративні символи без інтерактивності.

### Помилка 7. Недостатній контраст

Текст посилань виглядає надто блідим.

**Рішення:** перевір контраст на всіх фонах та в усіх станах.

### Помилка 8. Не передбачено мобільний екран

Довгий ланцюжок виходить за межі контейнера.

**Рішення:** перевір перенесення рядків, скорочення або інший мобільний формат.

### Помилка 9. Посилання ведуть не туди

Елементи виглядають правильно, але адреси неправильні.

**Рішення:** перевір кожне посилання та відповідність сторінці.

### Помилка 10. Залежність від історії браузера

Breadcrumbs відображають випадковий шлях переходів.

**Рішення:** зазвичай формуй їх за інформаційною архітектурою, а не за історією перегляду.

### Помилка 11. Відсутня семантика

Ланцюжок зроблено з набору `<div>` без доступної назви навігаційної області.

**Рішення:** використовуй `<nav>`, список, посилання та позначення поточної сторінки.

### Помилка 12. Скорочення приховує важливий контекст

Наприклад:

    Головна → … → Деталі

Користувач не знає, що саме приховано.

**Рішення:** скорочуй шлях передбачувано та, за потреби, надавай спосіб переглянути приховані рівні.

## 17. Практичний процес створення Breadcrumbs

Використовуй таку послідовність під час проєктування.

### Крок 1. Визнач структуру сайту

Випиши основні розділи та зв'язки між сторінками.

    Головна
    └── Навчання
        └── Курси
            └── JavaScript
                └── Масиви

### Крок 2. Визнач основний шлях

Для сторінки «Масиви»:

    Головна → Навчання → Курси → JavaScript → Масиви

Не додавай розділи, які не є частиною обраного логічного шляху.

### Крок 3. Визнач клікабельні елементи

Зазвичай усі попередні рівні — посилання, а останній — поточна сторінка.

### Крок 4. Обери візуальний стиль

Визнач:

- розмір шрифту;
- кольори;
- розділювач;
- відступи;
- відмінність поточної сторінки;
- розташування щодо заголовка.

### Крок 5. Продумай адаптивність

Перевір:

- короткий ланцюжок;
- довгий ланцюжок;
- вузький контейнер;
- довгі назви;
- мобільний екран.

### Крок 6. Перевір доступність

Переконайся, що:

- навігація має доступну назву;
- посилання доступні з клавіатури;
- фокус помітний;
- поточна сторінка позначена семантично;
- розділювачі не створюють зайвого шуму.

### Крок 7. Перевір реальні сценарії

Наприклад:

- користувач відкрив сторінку з головної;
- користувач відкрив глибоку сторінку із зовнішнього посилання;
- користувач повернувся до батьківської категорії;
- назва сторінки змінилася;
- шлях містить багато рівнів.

### Крок 8. Перевір реалізацію

Перевір адреси посилань, семантику HTML, адаптивність і візуальні стани.

## 19. Питання для співбесіди

### Junior

**1. Що таке breadcrumbs?**

Це навігаційний компонент, який показує шлях від верхнього рівня структури сайту до поточної сторінки.

**2. Для чого використовують breadcrumbs?**

Для орієнтації в структурі сайту та швидкого переходу до батьківських розділів.

**3. Чи замінюють breadcrumbs основну навігацію?**

Ні. Вони доповнюють основну навігацію.

**4. Який елемент зазвичай є останнім?**

Поточна сторінка.

**5. Чи повинна поточна сторінка бути посиланням?**

Зазвичай ні. Її позначають як поточну сторінку.

**6. Які HTML-елементи доречні для breadcrumbs?**

`<nav>`, `<ol>`, `<li>`, `<a>` та елемент для поточної сторінки.

### Middle

**7. Чим breadcrumbs відрізняються від історії переходів?**

Breadcrumbs зазвичай відображають стабільну ієрархію сайту, а історія переходів — фактичну послідовність дій користувача.

**8. Як реалізувати breadcrumbs на мобільному пристрої?**

Можна перенести ланцюжок, скоротити проміжні елементи або залишити перехід до батьківської сторінки.

**9. Як позначити поточну сторінку для скринридера?**

За допомогою `aria-current="page"`.

**10. Чому не варто генерувати breadcrumbs лише з URL?**

URL може містити технічні сегменти, ID та структуру, яка не відповідає зрозумілій ієрархії контенту.

**11. Що робити, якщо сторінка належить до декількох категорій?**

Визначити основний логічний шлях або використати інші способи навігації, не намагаючись показати всі шляхи одночасно.

### Senior

**12. Як breadcrumbs впливають на інформаційну архітектуру?**

Вони відображають зв'язки між рівнями контенту. Невідповідний ланцюжок може вказувати на проблеми в структурі або правилах маршрутизації.

**13. Як проєктувати breadcrumbs для локалізованого продукту?**

Використовувати локалізовані назви, стабільну структуру маршрутів і правила побудови ланцюжка, які враховують мову та тип контенту.

**14. Як працювати з динамічними маршрутами?**

Використовувати метадані сторінок або структуровані дані маршрутизації, а не показувати користувачеві технічні ID.

**15. Як перевіряти ефективність breadcrumbs?**

За допомогою usability-тестування, аналізу навігаційних сценаріїв, спостереження за переходами до батьківських категорій та перевірки того, чи розуміють користувачі своє місце в структурі.

## 22. Що потрібно запам'ятати

1. Breadcrumbs — це допоміжна навігація, яка показує місце користувача в структурі сайту.
2. Вони особливо корисні для великих сайтів із багаторівневою ієрархією.
3. Основна навігація та breadcrumbs виконують різні завдання.
4. Попередні елементи зазвичай є посиланнями, останній — поточною сторінкою.
5. Breadcrumbs повинні відображати логічну структуру контенту, а не випадкову історію переходів.
6. Не варто автоматично формувати назви лише із сегментів URL.
7. Довгі ланцюжки потребують продуманої адаптивної поведінки.
8. Семантичний `<nav>`, список і `aria-current="page"` допомагають забезпечити доступність.
9. Розділювачі є декоративними елементами, а не самостійними контролами.
10. Найкращі breadcrumbs — ті, які допомагають користувачеві зорієнтуватися, не відволікаючи від основного завдання.

**Головний принцип:** breadcrumbs мають відповідати на запитання користувача «Де я зараз і куди можу повернутися?».
