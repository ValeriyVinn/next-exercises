# 04. Sidebar — Бічна навігація

Sidebar (бічна панель) — це елемент інтерфейсу, який розташовується збоку від основного контенту та допомагає користувачеві переміщатися між розділами, сторінками або функціями продукту.

Sidebar часто використовується в адміністративних панелях, SaaS-застосунках, освітніх платформах, особистих кабінетах, системах керування контентом і складних вебзастосунках.

На відміну від Navbar, який зазвичай розташовується горизонтально у верхній частині сторінки, Sidebar використовує вертикальний простір і може показувати більше пунктів навігації одночасно.

Sidebar — це не просто колонка з посиланнями. Це частина інформаційної архітектури, яка допомагає користувачеві орієнтуватися в структурі продукту, розуміти своє поточне положення та швидко переходити між пов'язаними розділами.

## 🎯 Навіщо потрібен Sidebar

Sidebar допомагає:

- ✔️ організовувати велику кількість розділів;
- ✔️ створювати зрозумілу ієрархію навігації;
- ✔️ забезпечувати швидкий доступ до функцій;
- ✔️ показувати поточний розділ і вкладені сторінки;
- ✔️ відокремлювати навігацію від основного контенту;
- ✔️ підтримувати постійну структуру інтерфейсу;
- ✔️ групувати пов'язані функції;
- ✔️ адаптувати навігацію до різних розмірів екрана;
- ✔️ зменшувати кількість переходів між сторінками.

Sidebar особливо корисний тоді, коли продукт має багато функцій і горизонтального Navbar недостатньо для зручної навігації.

---

## 📌 Основні поняття

- ✔️ **Sidebar** — бічна панель інтерфейсу.
- ✔️ **Sidebar navigation** — навігація, розташована в бічній панелі.
- ✔️ **Navigation item** — окремий пункт навігації.
- ✔️ **Navigation group** — група пов'язаних пунктів.
- ✔️ **Active item** — пункт, який відповідає поточній сторінці або розділу.
- ✔️ **Nested navigation** — вкладена навігація з підрозділами.
- ✔️ **Collapsible sidebar** — панель, яку можна згорнути або розгорнути.
- ✔️ **Collapsed state** — згорнутий стан панелі.
- ✔️ **Expanded state** — розгорнутий стан панелі або групи.
- ✔️ **Persistent sidebar** — панель, яка постійно присутня в компонуванні сторінки.
- ✔️ **Overlay sidebar** — панель, яка з'являється поверх основного контенту.
- ✔️ **Drawer** — панель, що висувається з боку екрана.
- ✔️ **Mini sidebar** — компактна панель, яка часто показує лише іконки.
- ✔️ **Sticky sidebar** — бічна панель, що прилипає до заданого положення під час прокручування.
- ✔️ **Fixed sidebar** — панель, закріплена відносно вікна перегляду.
- ✔️ **Group label** — заголовок групи навігаційних пунктів.
- ✔️ **Badge** — невеликий індикатор біля пункту, наприклад лічильник сповіщень.
- ✔️ **Tooltip** — підказка, яка пояснює призначення елемента.
- ✔️ **Breadcrumbs** — навігаційний ланцюжок, що показує шлях до поточної сторінки.
- ✔️ **Information architecture** — організація інформації та взаємозв'язків між розділами.
- ✔️ **Responsive sidebar** — бічна панель, адаптована до різних екранів.

# 1. Структура Sidebar

Типова бічна панель може містити такі частини:

    ┌───────────────────────┐
    │ LOGO                  │
    │                       │
    │ ОСНОВНЕ               │
    │  ◉ Dashboard          │
    │  ◉ Projects           │
    │  ◉ Tasks              │
    │                       │
    │ РЕСУРСИ               │
    │  ◉ Documents          │
    │  ◉ Reports            │
    │                       │
    │                       │
    │ ⚙ Settings            │
    │ ◉ Profile             │
    └───────────────────────┘

Основні елементи:

1. **Brand area** — логотип або назва продукту.
2. **Primary navigation** — основні розділи.
3. **Navigation groups** — групи пов'язаних посилань.
4. **Nested items** — вкладені сторінки або категорії.
5. **Utility items** — налаштування, довідка, профіль.
6. **Status indicators** — лічильники, статуси або бейджі.
7. **Collapse control** — кнопка згортання панелі, якщо вона передбачена.
8. **Footer area** — додаткова інформація або дії в нижній частині панелі.

Не кожен Sidebar повинен містити всі ці елементи. Структура залежить від призначення продукту та кількості функцій.

Наприклад:

- освітня платформа може містити курси, уроки, завдання та оцінки;
- адміністративна панель — користувачів, ролі, налаштування й журнали;
- система керування проєктами — проєкти, завдання, команди та календар;
- особистий кабінет — профіль, документи, платежі та налаштування;
- медичний сервіс — пацієнтів, записи, календар, фахівців і звіти.

## 1.1. Brand area

Brand area — верхня частина Sidebar, де зазвичай розташовується логотип або назва продукту.

Вона допомагає:

- ідентифікувати продукт;
- підтримувати візуальну цілісність;
- забезпечувати швидке повернення до головної сторінки або робочого простору.

Приклад:

    ┌───────────────────────┐
    │ ◈ LearnSpace          │
    ├───────────────────────┤
    │ Dashboard             │
    │ Courses               │
    │ Students              │
    └───────────────────────┘

Рекомендації:

- не роби логотип надмірно великим;
- залишай достатньо місця для навігації;
- узгоджуй висоту brand area з іншими елементами інтерфейсу;
- перевіряй, як логотип виглядає у згорнутому стані.

## 1.2. Navigation items

Navigation item — окремий пункт бічної навігації.

Він може містити:

- іконку;
- текстову назву;
- лічильник;
- індикатор підменю;
- активний стан.

Приклад:

    ◉ Dashboard
    ◉ Projects
    ◉ Messages       3
    ◉ Settings

Основні правила:

- назва має бути зрозумілою;
- іконка повинна відповідати призначенню;
- активний пункт має бути помітним;
- інтерактивна область повинна бути достатньо великою;
- довгі назви не повинні ламати компонування.

## 1.3. Navigation groups

Navigation group — це група пов'язаних пунктів, яка об'єднується спільною темою.

Наприклад:

    ОСНОВНЕ
      Dashboard
      Projects
      Tasks

    КОМАНДА
      Members
      Messages
      Calendar

    НАЛАШТУВАННЯ
      Profile
      Preferences

Групування допомагає користувачеві швидше знаходити потрібну функцію.

Рекомендації:

- групуй пункти за змістом;
- використовуй короткі заголовки;
- не створюй занадто багато дрібних груп;
- не додавай заголовок, якщо він не допомагає орієнтуватися;
- дотримуйся однакових правил групування в усьому продукті.

## 1.4. Utility area

Utility area — частина Sidebar для допоміжних функцій.

Приклади:

- налаштування;
- профіль;
- довідка;
- вихід з акаунта;
- перемикач робочого простору.

Ці елементи часто розташовують у нижній частині панелі або відокремлюють від основної навігації.

Не потрібно переміщувати всі другорядні функції вниз автоматично. Розташування має відповідати частоті використання, логіці продукту та очікуванням користувачів.

# 2. Основні типи Sidebar

## 2.1. Persistent Sidebar

Persistent sidebar — бічна панель, яка постійно присутня в компонуванні сторінки.

    ┌──────────────┬────────────────────────────────┐
    │ Sidebar      │                                │
    │              │          Main content          │
    │ Dashboard    │                                │
    │ Projects     │                                │
    │ Tasks        │                                │
    │ Settings     │                                │
    └──────────────┴────────────────────────────────┘

Переваги:

- навігація завжди видима;
- користувач бачить структуру продукту;
- легко переходити між розділами;
- добре підходить для складних вебзастосунків.

Недоліки:

- займає частину горизонтального простору;
- може бути незручною на вузьких екранах;
- потребує продуманого компонування основного контенту.

Підходить для:

- SaaS-застосунків;
- адміністративних панелей;
- систем керування контентом;
- освітніх платформ;
- робочих кабінетів.

## 2.2. Collapsible Sidebar

Collapsible sidebar — панель, яку користувач може згортати й розгортати.

Expanded:

    ┌──────────────────────┐
    │ LOGO                 │
    │                      │
    │ ◉ Dashboard          │
    │ ◉ Projects           │
    │ ◉ Tasks              │
    │ ◉ Settings           │
    └──────────────────────┘

Collapsed:

    ┌──────┐
    │ LOGO │
    │      │
    │  ◉   │
    │  ◉   │
    │  ◉   │
    │  ◉   │
    └──────┘

Переваги:

- користувач може звільнити простір для контенту;
- панель залишається доступною;
- підтримується компактний робочий режим.

Недоліки:

- іконки можуть бути неоднозначними;
- приховані назви збільшують когнітивне навантаження;
- потрібні зрозумілі підказки та доступні назви.

Рекомендації:

- передбач кнопку згортання;
- показуй tooltip для іконок без видимих підписів;
- не використовуй незрозумілі іконки;
- зберігай активний стан у згорнутому режимі;
- перевіряй, чи не губляться важливі функції.

## 2.3. Mini Sidebar

Mini sidebar — компактний варіант, у якому переважно залишаються іконки.

    ┌──────┐
    │  ◈   │
    ├──────┤
    │  ▦   │
    │  ◫   │
    │  ◷   │
    │  ⚙   │
    └──────┘

Mini sidebar може бути постійним режимом або результатом згортання звичайної панелі.

Використовуй його, коли:

- користувачі добре знайомі з функціями;
- іконки достатньо зрозумілі;
- важливо максимізувати простір для основного контенту;
- доступні підказки для пунктів без тексту.

Не варто використовувати лише іконки для складної навігації, якщо користувачам доводиться постійно вгадувати їхнє призначення.

## 2.4. Overlay Sidebar

Overlay sidebar з'являється поверх основного контенту, а не займає постійне місце в компонуванні.

    ┌─────────────────────────────────┐
    │ Основний контент                │
    │    ┌──────────────────────┐     │
    │    │ Sidebar              │     │
    │    │ Dashboard            │     │
    │    │ Projects             │     │
    │    │ Settings             │     │
    │    └──────────────────────┘     │
    └─────────────────────────────────┘

Переваги:

- зберігає простір для контенту;
- добре підходить для мобільних пристроїв;
- дозволяє показувати навігацію лише за потреби.

Недоліки:

- частково або повністю перекриває контент;
- потребує зрозумілого відкриття та закриття;
- може створювати проблеми з фокусом, якщо реалізована як модальна панель.

Overlay sidebar часто використовується в адаптивних інтерфейсах.

## 2.5. Drawer Sidebar

Drawer — панель, яка висувається з лівого або правого краю екрана.

Вона може бути:

- модальною — взаємодія з основним контентом тимчасово блокується;
- немодальною — користувач може взаємодіяти з іншими частинами сторінки відповідно до реалізації.

Drawer підходить для:

- мобільної навігації;
- фільтрів;
- налаштувань;
- додаткових панелей;
- короткочасних сценаріїв взаємодії.

Якщо Drawer модальний, потрібно правильно керувати клавіатурним фокусом, закриттям і взаємодією з фоновим контентом.

## 2.6. Sticky Sidebar

Sticky sidebar прилипає до визначеного положення під час прокручування сторінки.

Приклад CSS:

    .sidebar {
      position: sticky;
      top: 1rem;
      align-self: start;
    }

Sticky Sidebar може бути корисним для довгих сторінок документації, налаштувань або навчальних матеріалів.

Важливо перевіряти:

- висоту панелі;
- висоту вікна перегляду;
- прокручування самої панелі;
- поведінку на мобільних пристроях;
- перекриття інших елементів.

## 2.7. Fixed Sidebar

Fixed sidebar закріплений відносно вікна браузера.

Приклад:

    .sidebar {
      position: fixed;
      top: 0;
      bottom: 0;
      left: 0;
      width: 16rem;
      overflow-y: auto;
    }

Оскільки панель вилучена зі звичайного потоку документа, основний контент може потребувати відступу зліва.

Приклад:

    .main-content {
      margin-left: 16rem;
    }

Цей варіант потрібно тестувати особливо ретельно, оскільки фіксована ширина може бути незручною на малих екранах.

**Різниця:**

- `persistent` описує постійну присутність панелі в компонуванні;
- `sticky` описує поведінку під час прокручування;
- `fixed` описує позиціонування відносно вікна перегляду;
- `collapsible` описує можливість згортання;
- `overlay` описує відображення поверх контенту;
- `drawer` описує панель, яка висувається з боку.

Ці характеристики можуть поєднуватися. Наприклад, Sidebar може бути persistent на десктопі та перетворюватися на drawer на мобільному пристрої.

# 3. Інформаційна архітектура Sidebar

Sidebar має відображати логічну структуру продукту.

Перед проєктуванням потрібно визначити:

1. Які розділи є в продукті?
2. Які функції пов'язані між собою?
3. Які розділи використовуються найчастіше?
4. Які сторінки належать до одного батьківського розділу?
5. Які функції повинні бути доступні постійно?
6. Які пункти можна згрупувати?
7. Чи потрібні вкладені рівні навігації?

Наприклад, освітня платформа:

    Навчання
      ├── Мої курси
      ├── Завдання
      ├── Розклад
      └── Оцінки

    Матеріали
      ├── Підручники
      ├── Вправи
      └── Бібліотека

    Обліковий запис
      ├── Профіль
      └── Налаштування

У Sidebar можна показати ці групи з відповідними заголовками.

Не потрібно відображати всі сторінки продукту одночасно. Завдання Sidebar — забезпечити зрозумілий доступ до основних напрямків.

## 3.1. Ієрархія навігації

Ієрархія визначає відношення між розділами та підрозділами.

Приклад:

    Projects
      ├── All projects
      ├── Active projects
      └── Archived projects

У цьому випадку `Projects` може бути батьківським пунктом, а інші елементи — вкладеними.

Важливо, щоб вкладеність мала зміст. Не створюй багато рівнів лише тому, що так організовані внутрішні дані продукту.

## 3.2. Групування за завданнями

Групуй навігацію за тим, що користувач хоче зробити.

Наприклад, замість хаотичного списку:

    Users
    Calendar
    Settings
    Messages
    Reports
    Profile
    Projects
    Billing

Можна створити:

    РОБОТА
      Projects
      Calendar
      Reports

    КОМУНІКАЦІЯ
      Messages
      Users

    АКАУНТ
      Profile
      Billing
      Settings

Це лише приклад. Конкретне групування залежить від продукту та користувацьких сценаріїв.

## 3.3. Кількість рівнів вкладеності

Надмірна вкладеність ускладнює навігацію.

Приклад складної структури:

    Organization
      └── Departments
          └── Teams
              └── Projects
                  └── Tasks

Щоб перейти до потрібного розділу, користувачеві доводиться розуміти кілька рівнів.

Якщо структура надто глибока:

- переглянь групування;
- винеси деякі категорії на окрему сторінку;
- використовуй локальну навігацію;
- розглянь пошук;
- зменш кількість вкладених рівнів.

Не існує універсальної максимальної глибини для всіх продуктів, але кожен додатковий рівень має бути виправданий.

# 4. Візуальна ієрархія Sidebar

Візуальна ієрархія допомагає зрозуміти, де розташовані основні розділи, які елементи пов'язані між собою та який пункт активний.

Для цього використовують:

- відступи;
- групування;
- типографіку;
- контраст;
- іконки;
- індикатори;
- фонові кольори;
- роздільники;
- відмінності між батьківськими та вкладеними пунктами.

## 4.1. Заголовки груп

Приклад:

    НАВІГАЦІЯ
      Dashboard
      Projects

    РОБОЧИЙ ПРОСТІР
      Documents
      Reports

    НАЛАШТУВАННЯ
      Profile
      Preferences

Заголовки груп можуть бути меншими за основні пункти та мати менш виражений контраст.

Але не роби їх надто блідими або дрібними. Вони повинні залишатися читабельними.

## 4.2. Відступи вкладених пунктів

Приклад:

    Projects
      All projects
      Active
      Archived

Вкладені пункти можна зміщувати вправо, щоб показати ієрархію.

Приклад CSS:

    .nav-item {
      padding-inline: 0.75rem;
    }

    .nav-item--nested {
      padding-inline-start: 2rem;
    }

Відступ — лише один зі способів показати вкладеність. За потреби можна додати інші індикатори, наприклад лінію або зміну розміру тексту.

## 4.3. Контраст і колір

Не використовуй колір як єдиний спосіб позначення активного пункту.

Краще поєднувати:

- зміну фону;
- інший колір тексту;
- індикатор зліва;
- зміну товщини шрифту.

Приклад:

    .sidebar-link {
      color: #444444;
      text-decoration: none;
    }

    .sidebar-link[aria-current="page"] {
      color: #1456c0;
      background-color: #eaf1ff;
      font-weight: 600;
      box-shadow: inset 3px 0 0 #1456c0;
    }

Значення кольорів наведені для прикладу. Перевіряй контраст із реальним фоном і в усіх станах компонента.

# 5. Іконки в Sidebar

Іконки допомагають швидко розпізнавати функції, особливо коли панель згорнута.

Приклади:

- Dashboard — панель або сітка;
- Projects — папка;
- Calendar — календар;
- Messages — повідомлення;
- Settings — шестерня;
- Profile — користувач.

## 5.1. Правила використання іконок

- ✔️ Використовуй єдиний візуальний стиль.
- ✔️ Дотримуйся послідовного розміру.
- ✔️ Враховуй оптичну вагу іконок.
- ✔️ Перевіряй зрозумілість без тексту.
- ✔️ Не використовуй декоративні іконки без функціональної потреби.
- ✔️ Забезпечуй доступні назви для кнопок, які містять лише іконки.

Не варто вибирати іконки лише тому, що вони красиво виглядають. Їхнє призначення має бути зрозумілим користувачеві.

## 5.2. Іконки у згорнутому Sidebar

У згорнутому режимі текстові назви можуть бути приховані.

Тому потрібно:

- показувати tooltip;
- забезпечувати доступну назву елемента;
- зберігати помітний активний стан;
- перевіряти, чи не плутаються схожі іконки;
- залишати достатню область натискання.

Приклад HTML:

    <a href="/projects" aria-label="Проєкти">
      <svg aria-hidden="true" viewBox="0 0 24 24">
        <!-- Графіка іконки -->
      </svg>
    </a>

Якщо поруч є видимий текст «Проєкти», додаткова доступна назва може бути зайвою. Вона особливо важлива, коли текст приховано візуально.

# 6. Active state — активний пункт

Active state показує, у якому розділі або на якій сторінці перебуває користувач.

Приклад:

    Dashboard
    Projects       ← active
    Tasks
    Settings

Активний пункт може мати:

- змінений колір;
- фонову заливку;
- вертикальну лінію;
- інший стиль тексту;
- змінену іконку.

## 6.1. Чому активний стан важливий

Він допомагає:

- підтримувати орієнтацію;
- розуміти структуру продукту;
- швидше знаходити поточний розділ;
- зменшувати невизначеність після переходу.

## 6.2. Позначення поточної сторінки

Приклад HTML:

    <nav aria-label="Основна навігація">
      <ul>
        <li>
          <a href="/dashboard">Dashboard</a>
        </li>

        <li>
          <a href="/projects" aria-current="page">Projects</a>
        </li>

        <li>
          <a href="/settings">Settings</a>
        </li>
      </ul>
    </nav>

`aria-current="page"` повідомляє допоміжним технологіям, що посилання відповідає поточній сторінці.

Візуальний активний стан і семантичне позначення повинні відповідати одне одному.

## 6.3. Активний батьківський пункт

Якщо користувач перебуває на вкладеній сторінці, можна позначити і дочірній, і батьківський пункт.

Наприклад:

    Projects              ← expanded
      All projects
      Active projects     ← current
      Archived projects

Це допомагає зрозуміти, до якого розділу належить поточна сторінка.

Не позначай усі пункти групи як поточну сторінку. Для батьківського пункту можна використовувати окремий візуальний стан, який відрізняється від стану поточної сторінки.

# 7. Collapsible Sidebar: згортання та розгортання

Collapsible Sidebar дозволяє змінювати ширину панелі.

Expanded state:

    ┌──────────────────────┐
    │ ◈ LearnSpace         │
    │                      │
    │ ◉ Dashboard          │
    │ ◉ Projects           │
    │ ◉ Messages           │
    │ ⚙ Settings           │
    └──────────────────────┘

Collapsed state:

    ┌──────┐
    │  ◈   │
    │      │
    │  ▦   │
    │  ◫   │
    │  ✉   │
    │  ⚙   │
    └──────┘

## 7.1. Коли потрібне згортання

Згортання корисне, якщо:

- користувачеві потрібен більший простір для контенту;
- Sidebar містить багато пунктів;
- користувачі працюють із великими таблицями або редакторами;
- продукт має кілька робочих режимів.

## 7.2. Як має працювати згортання

Визнач:

1. Яка кнопка відповідає за згортання.
2. Яка ширина панелі у двох станах.
3. Чи змінюється компонування основного контенту.
4. Як поводяться вкладені групи.
5. Як відображається активний пункт.
6. Чи зберігається стан під час переходів.
7. Як панель працює на вузьких екранах.

Не змушуй користувача здогадуватися, як повернути розгорнутий стан.

## 7.3. Кнопка згортання

Приклад HTML:

    <button
      type="button"
      aria-label="Згорнути бічну панель"
      aria-expanded="true"
    >
      <svg aria-hidden="true" viewBox="0 0 24 24">
        <!-- Графіка кнопки -->
      </svg>
    </button>

У реальному компоненті потрібно оновлювати доступну назву та стан відповідно до дії. Наприклад, після згортання назва може змінитися на «Розгорнути бічну панель».

`aria-expanded` має використовуватися відповідно до семантики елемента, який розкривається або приховується. Для складного компонента варто чітко визначити, який саме вміст контролює кнопка.

## 7.4. Анімація згортання

Можна анімувати:

- ширину Sidebar;
- прозорість тексту;
- появу підписів;
- зміну положення іконок.

Приклад CSS:

    .sidebar {
      width: 16rem;
      transition: width 180ms ease;
    }

    .sidebar--collapsed {
      width: 4.5rem;
    }

Не анімуй кожен елемент без потреби. Анімація повинна допомагати зрозуміти зміну стану, а не затримувати взаємодію.

Також враховуй налаштування зменшення руху:

    @media (prefers-reduced-motion: reduce) {
      .sidebar {
        transition: none;
      }
    }

# 8. Вкладена навігація

Nested navigation — це структура, у якій один пункт містить підпункти.

Приклад:

    Courses
      ├── All courses
      ├── My courses
      └── Completed

Вкладена навігація допомагає організовувати складні структури, але потребує чітких правил.

## 8.1. Батьківські та дочірні пункти

Батьківський пункт може виконувати дві різні ролі:

1. Перехід до сторінки розділу.
2. Відкриття або закриття підменю.

Не завжди варто об'єднувати ці дії в один елемент.

Якщо батьківський пункт має власну сторінку, а також містить підменю, можна використати окреме посилання та кнопку розкриття.

Приклад:

    <div class="nav-group">
      <a href="/courses">Курси</a>

      <button
        type="button"
        aria-label="Розгорнути підрозділи курсів"
        aria-expanded="false"
        aria-controls="courses-submenu"
      >
        <svg aria-hidden="true" viewBox="0 0 24 24">
          <!-- Графіка стрілки -->
        </svg>
      </button>
    </div>

    <ul id="courses-submenu" hidden>
      <li><a href="/courses/my">Мої курси</a></li>
      <li><a href="/courses/completed">Завершені</a></li>
    </ul>

Це структурний приклад. У робочому компоненті потрібно синхронізувати стан кнопки та видимість підменю.

## 8.2. Розкриті та згорнуті групи

Важливо, щоб користувач розумів, які групи відкриті.

Для цього можна використовувати:

- стрілку, яка змінює напрямок;
- зміну фону батьківського пункту;
- відступи дочірніх елементів;
- анімацію розкриття;
- доступний стан `aria-expanded`.

Не використовуй лише колір або анімацію як єдину ознаку відкритого стану.

## 8.3. Чи повинні групи відкриватися автоматично?

Це залежить від контексту.

Автоматичне відкриття може бути корисним, коли:

- поточна сторінка є дочірньою;
- користувач повинен бачити шлях до неї;
- розділ має невелику кількість підпунктів.

Збереження попереднього стану може бути корисним, коли:

- користувач працює з багатьма групами;
- часто переходить між сторінками;
- йому важливо зберігати власне компонування.

Не потрібно автоматично розкривати всі групи. Це може зробити Sidebar надто довгим.

# 9. Sidebar та інформаційні індикатори

Sidebar може показувати додаткову інформацію біля пунктів.

Приклади:

    Messages       3
    Tasks          8
    Updates       NEW

Такі індикатори називають badges або status indicators.

## 9.1. Лічильники

Лічильники можуть відображати:

- кількість непрочитаних повідомлень;
- кількість невиконаних завдань;
- кількість нових сповіщень;
- кількість елементів, що потребують уваги.

Рекомендації:

- використовуй їх лише там, де вони допомагають;
- не показуй зайві числа біля кожного пункту;
- не дозволяй лічильникам порушувати компонування;
- передбач поведінку для великих чисел.

Приклад:

    Messages       9+

Якщо точне число не важливе, можна використовувати компактне відображення. Але для критичних даних краще не приховувати важливу інформацію.

## 9.2. Статусні бейджі

Наприклад:

    Projects       NEW
    Reports        BETA

Бейджі повинні мати зрозумілий зміст і не використовуватися лише як декоративні прикраси.

Не роби всі бейджі яскравими. Їхня візуальна вага має відповідати важливості інформації.

## 9.3. Індикатори помилок

Якщо пункт веде до розділу, де є помилки або невирішені проблеми, індикатор може допомогти користувачеві звернути на них увагу.

Проте колір не повинен бути єдиним способом передавання значення. За потреби додай текст, доступну назву або пояснення.

# 10. Sticky та Fixed Sidebar

Sticky і fixed використовують для панелей, які повинні залишатися доступними під час прокручування.

## 10.1. Sticky Sidebar

Приклад:

    .sidebar {
      position: sticky;
      top: 1rem;
      align-self: start;
      max-height: calc(100vh - 2rem);
      overflow-y: auto;
    }

`position: sticky` залежить від контексту прокручування та властивостей батьківських контейнерів. Якщо панель не прилипає, перевір не лише її власні стилі, а й структуру батьківських елементів.

## 10.2. Fixed Sidebar

Приклад:

    .sidebar {
      position: fixed;
      inset-block: 0;
      inset-inline-start: 0;
      width: 16rem;
      overflow-y: auto;
    }

    .main-content {
      margin-inline-start: 16rem;
    }

Fixed sidebar потрібно узгодити з основним компонуванням, інакше контент може опинитися під панеллю.

## 10.3. Як вибрати між Sticky та Fixed

Використовуй sticky, коли:

- панель є частиною компонування;
- вона має залишатися видимою в межах певної області;
- важливо зберігати природний потік документа.

Використовуй fixed, коли:

- панель має залишатися прив'язаною до вікна;
- її позиція не повинна залежати від звичайного потоку;
- компонування спеціально передбачає постійний бічний простір.

Перевіряй довгі сторінки, низькі вікна перегляду, збільшення масштабу та мобільні пристрої.

# 11. Responsive Sidebar

Responsive sidebar адаптується до ширини екрана.

На десктопі:

    ┌──────────────┬───────────────────────────┐
    │ Sidebar      │ Main content              │
    │              │                           │
    │ Dashboard    │                           │
    │ Projects     │                           │
    │ Tasks        │                           │
    └──────────────┴───────────────────────────┘

На мобільному пристрої:

    ┌───────────────────────────┐
    │ ☰    Назва розділу        │
    ├───────────────────────────┤
    │                           │
    │      Main content         │
    │                           │
    └───────────────────────────┘

Після натискання кнопки меню:

    ┌───────────────────────────┐
    │ Sidebar                   │
    │ Dashboard                 │
    │ Projects                  │
    │ Tasks                     │
    │ Settings                  │
    └───────────────────────────┘

## 11.1. Desktop

На широких екранах Sidebar може бути постійно видимим.

Враховуй:

- ширину панелі;
- ширину основного контенту;
- довжину пунктів;
- кількість вкладених рівнів;
- можливість згортання;
- прокручування довгого списку.

## 11.2. Tablet

На планшеті можуть бути доречні:

- компактний Sidebar;
- mini sidebar;
- панель, що згортається;
- Drawer, який відкривається за потреби.

Не припускай, що планшет завжди повинен використовувати мобільний варіант. Орієнтуйся на ширину контенту та сценарії використання.

## 11.3. Mobile

На мобільних пристроях Sidebar часто перетворюється на Drawer або Overlay.

Важливо:

- залишити зрозумілу кнопку відкриття;
- забезпечити достатній розмір інтерактивних областей;
- не приховувати критичні функції;
- передбачити закриття панелі;
- врахувати клавіатуру та системні області екрана;
- перевірити, чи можна легко повернутися до основного контенту.

## 11.4. Breakpoints

Не існує одного обов'язкового breakpoint для всіх Sidebar.

Визначай його за поведінкою компонента:

1. Зменшуй ширину вікна.
2. Перевіряй, чи вміщуються назви.
3. Оцінюй доступний простір для основного контенту.
4. Визначай момент, коли панель потрібно згорнути або приховати.
5. Перевіряй рішення на різних пристроях.

Приклад CSS:

    .sidebar {
      width: 16rem;
    }

    .main-content {
      margin-inline-start: 16rem;
    }

    @media (max-width: 48rem) {
      .sidebar {
        display: none;
      }

      .main-content {
        margin-inline-start: 0;
      }
    }

Цей приклад лише приховує Sidebar на малих екранах. У готовому інтерфейсі потрібно передбачити альтернативний доступ до навігації, наприклад через Drawer.

# 12. Sidebar та доступність (Accessibility)

Доступний Sidebar повинен бути зрозумілим користувачам клавіатури, скринридерів та інших допоміжних технологій.

## 12.1. Семантична структура

Для навігаційної області використовуй `<nav>`.

Приклад:

    <aside class="sidebar">
      <nav aria-label="Основна навігація">
        <ul>
          <li>
            <a href="/dashboard">Dashboard</a>
          </li>

          <li>
            <a href="/projects" aria-current="page">Projects</a>
          </li>

          <li>
            <a href="/settings">Settings</a>
          </li>
        </ul>
      </nav>
    </aside>

`<aside>` позначає окремий допоміжний вміст, а `<nav>` — навігаційну область. Якщо Sidebar є основною навігацією застосунку, її семантика та доступна назва мають відповідати цій ролі.

## 12.2. Посилання та кнопки

Використовуй `<a>`, коли елемент веде на сторінку.

    <a href="/projects">Проєкти</a>

Використовуй `<button>`, коли елемент виконує дію в поточному інтерфейсі.

    <button type="button">
      Згорнути панель
    </button>

Для розкриття груп також доречно використовувати кнопку, оскільки вона змінює стан інтерфейсу.

## 12.3. Клавіатурна навігація

Перевір, що користувач може:

- перейти до посилань клавішею Tab;
- рухатися назад за допомогою Shift + Tab;
- активувати посилання клавішею Enter;
- активувати кнопки стандартним способом;
- розкривати та згортати групи;
- закривати модальну панель клавішею Escape;
- бачити, який елемент має фокус.

Для звичайного списку навігаційних посилань зазвичай достатньо стандартної поведінки браузера.

Не потрібно перетворювати Sidebar на складний ARIA tree лише тому, що він має вкладені пункти. Звичайні посилання та кнопки часто забезпечують простішу й зрозумілішу взаємодію.

## 12.4. Focus state

Приклад CSS:

    .sidebar-link:focus-visible {
      outline: 3px solid #1456c0;
      outline-offset: 2px;
    }

Не прибирай видимий контур фокуса без доступної альтернативи.

## 12.5. Tooltip

Якщо Sidebar згорнутий і показує лише іконки, tooltip може пояснювати призначення пункту.

Але tooltip не замінює доступну назву елемента.

Переконайся, що:

- назва доступна допоміжним технологіям;
- підказка не перекриває важливий контент;
- підказка не зникає до того, як користувач може її прочитати;
- основні функції доступні без наведення миші.

## 12.6. Доступність Drawer

Якщо Sidebar відкривається як модальна панель:

- переміщуй фокус усередину після відкриття;
- не дозволяй фокусу випадково переходити до заблокованого фонового контенту;
- забезпечуй закриття клавішею Escape, якщо це відповідає поведінці компонента;
- повертай фокус на кнопку відкриття після закриття;
- надавай доступну назву панелі;
- перевіряй взаємодію зі скринридером.

Якщо панель немодальна, правила керування фокусом можуть відрізнятися. Важливо не застосовувати модальну поведінку автоматично до кожного Sidebar.

# 13. Sidebar та основний контент

Sidebar і main content повинні працювати як єдина композиція.

Приклад:

    ┌────────────────┬─────────────────────────────┐
    │                │ Page title                  │
    │   Sidebar      │                             │
    │                │ Main content                │
    │                │                             │
    └────────────────┴─────────────────────────────┘

## 13.1. Баланс ширини

Занадто широка панель:

- забирає місце в контенту;
- зменшує доступну ширину таблиць і форм;
- може погіршувати читабельність.

Занадто вузька панель:

- обрізає назви;
- ускладнює роботу з вкладеними пунктами;
- може змушувати користувача постійно відкривати підказки.

Підбирай ширину за реальним контентом, а не лише за естетичними вподобаннями.

## 13.2. Мінімальна ширина контенту

Якщо Sidebar постійний, потрібно перевіряти, чи залишається достатньо простору для основного контенту.

Наприклад, велика таблиця може потребувати горизонтального прокручування або іншого компонування на вузьких екранах.

Не варто розв'язувати всі проблеми лише зменшенням ширини Sidebar. Іноді краще змінити адаптивну поведінку всієї сторінки.

## 13.3. Відступ між Sidebar і контентом

Приклад CSS:

    .app-layout {
      display: grid;
      grid-template-columns: 16rem minmax(0, 1fr);
      min-height: 100vh;
    }

    .sidebar {
      min-width: 0;
    }

    .main-content {
      min-width: 0;
      padding: 2rem;
    }

`minmax(0, 1fr)` і `min-width: 0` допомагають уникати деяких проблем із переповненням Grid-контейнера довгим контентом.

# 15. Sidebar у дизайн-системі

У дизайн-системі Sidebar потрібно описувати як компонент із визначеною структурою, варіантами та поведінкою.

Варто задокументувати:

- призначення;
- доступні варіанти;
- ширину;
- відступи;
- типографіку;
- кольори;
- стани пунктів;
- правила групування;
- вкладеність;
- згортання;
- адаптивну поведінку;
- доступність;
- правила використання іконок;
- поведінку Drawer.

## 15.1. Варіанти компонента

Наприклад:

    Sidebar
    ├── Expanded
    ├── Collapsed
    ├── Persistent
    ├── Overlay
    └── Mobile Drawer

Це можливі варіанти, а не обов'язковий перелік. Деякі характеристики можуть поєднуватися.

## 15.2. Стани Navigation Item

    Navigation Item
      ├── Default
      ├── Hover
      ├── Focus
      ├── Current
      ├── Expanded
      └── Disabled

Не всі стани потрібні кожному пункту.

Наприклад, `Expanded` актуальний для пункту, який керує підменю, а `Current` — для посилання, яке відповідає поточній сторінці.

## 15.3. Design tokens

Design tokens — системні значення дизайну, які забезпечують послідовність компонентів.

Приклад CSS:

    :root {
      --sidebar-width: 16rem;
      --sidebar-width-collapsed: 4.5rem;
      --sidebar-padding: 0.75rem;
      --sidebar-item-gap: 0.25rem;
      --sidebar-background: #ffffff;
      --sidebar-text: #333333;
      --sidebar-active-background: #eaf1ff;
      --sidebar-active-text: #1456c0;
      --sidebar-border: #e5e7eb;
    }

    .sidebar {
      width: var(--sidebar-width);
      padding: var(--sidebar-padding);
      background-color: var(--sidebar-background);
      color: var(--sidebar-text);
      border-inline-end: 1px solid var(--sidebar-border);
    }

Переваги:

- єдині значення в різних компонентах;
- простіша підтримка;
- швидке налаштування тем;
- менше випадкових відмінностей.

# 18. Типові помилки під час проєктування Sidebar

## ❌ 1. Надто багато пунктів

Проблема: користувачеві складно знайти потрібний розділ.

Рішення:

- групуй пов'язані функції;
- прибирай дублікати;
- визначай основні завдання;
- переглядай інформаційну архітектуру.

## ❌ 2. Надмірна вкладеність

Проблема: для переходу до потрібної сторінки доводиться розкривати багато рівнів.

Рішення:

- спрощуй ієрархію;
- використовуй локальну навігацію;
- перенось складні каталоги на окремі сторінки;
- перевіряй реальні користувацькі сценарії.

## ❌ 3. Незрозумілі іконки

Проблема: у згорнутому режимі користувач не розуміє призначення пунктів.

Рішення:

- вибирай впізнавані іконки;
- додавай tooltip;
- забезпечуй доступні назви;
- залишай текст для складних або неоднозначних функцій.

## ❌ 4. Немає активного стану

Проблема: користувач не розуміє, у якому розділі перебуває.

Рішення:

- позначай поточну сторінку;
- використовуй фоновий індикатор або інший візуальний сигнал;
- додавай `aria-current="page"` для відповідного посилання.

## ❌ 5. Sidebar займає забагато місця

Проблема: основний контент стає занадто вузьким.

Рішення:

- переглянь ширину;
- розглянь можливість згортання;
- використовуй Drawer на вузьких екранах;
- перевіряй компонування на різних розмірах.

## ❌ 6. Sidebar прихований без альтернативної навігації

Проблема: на мобільному пристрої користувач втрачає доступ до розділів.

Рішення:

- передбач кнопку відкриття;
- створюй адаптивний Drawer;
- перевіряй, чи всі основні функції залишаються доступними.

## ❌ 7. Tooltip замість доступної назви

Проблема: підказка може бути недоступною для деяких користувачів або не з'являтися під час клавіатурної взаємодії.

Рішення:

- додавай доступну назву елемента;
- використовуй tooltip як візуальну підказку, а не як єдине джерело інформації.

## ❌ 8. Fixed Sidebar перекриває контент

Проблема: основна частина сторінки опиняється під панеллю.

Рішення:

- узгоджуй ширину Sidebar з компонуванням;
- додавай відповідний простір для контенту;
- перевіряй адаптивність і прокручування.

## ❌ 9. Непослідовні групи

Проблема: схожі функції розташовані в різних місцях без зрозумілої причини.

Рішення:

- визнач єдині правила групування;
- підтримуй послідовність між сторінками;
- тестуй зрозумілість структури.

## ❌ 10. Немає клавіатурного фокуса

Проблема: користувачі клавіатури не розуміють, який елемент вибрано.

Рішення:

- забезпечуй помітний `:focus-visible`;
- перевіряй послідовність Tab;
- не видаляй стандартний контур без альтернативи.

## ❌ 11. Усі пункти мають однаковий пріоритет

Проблема: Sidebar виглядає як довгий однорідний список.

Рішення:

- використовуй групи;
- визначай головні розділи;
- застосовуй типографіку та відступи послідовно;
- не роби всі пункти акцентними.

## ❌ 12. Анімація заважає роботі

Проблема: Sidebar довго відкривається або закривається.

Рішення:

- використовуй короткі й доречні переходи;
- не анімуй усе без потреби;
- враховуй `prefers-reduced-motion`;
- перевіряй поведінку на слабших пристроях.

# 20. Питання для співбесіди

## Базовий рівень

**1. Що таке Sidebar?**

Sidebar — це бічна панель, яка містить навігацію або допоміжні функції та допомагає користувачеві орієнтуватися в продукті.

**2. Для чого використовують Sidebar?**

Для організації великої кількості розділів, групування функцій і швидкого доступу до основних сторінок.

**3. Чим Sidebar відрізняється від Navbar?**

Navbar зазвичай розташований горизонтально у верхній частині сторінки, а Sidebar — вертикально збоку від основного контенту.

**4. Що таке navigation group?**

Група пов'язаних пунктів навігації, об'єднаних спільною темою.

**5. Що таке active state?**

Стан, який показує поточну сторінку або розділ.

## Junior-рівень

**6. Чим відрізняється persistent Sidebar від overlay Sidebar?**

Persistent Sidebar присутній у компонуванні сторінки, а overlay Sidebar відображається поверх основного контенту.

**7. Що таке collapsible Sidebar?**

Панель, яку можна згортати та розгортати, змінюючи доступний простір для основного контенту.

**8. Навіщо потрібен tooltip у згорнутому Sidebar?**

Він пояснює призначення пунктів, коли текстові назви приховані. Проте tooltip не замінює доступної назви елемента.

**9. Як зробити Sidebar адаптивним?**

Потрібно визначити поведінку для різних ширин: постійна панель, компактний режим або Drawer. Breakpoint слід вибирати за поведінкою контенту.

**10. Як позначити поточну сторінку?**

Візуально — за допомогою фону, кольору, індикатора або типографіки; семантично — за допомогою `aria-current="page"` для відповідного посилання.

## Middle-рівень

**11. Як організувати Sidebar зі складною структурою?**

Потрібно групувати функції за завданнями, визначати ієрархію, уникати зайвої вкладеності та тестувати реальні сценарії.

**12. Як зробити вкладений Sidebar доступним?**

Використовувати семантичні посилання та кнопки, підтримувати клавіатурне керування, показувати стан розкриття та забезпечувати видимий фокус.

**13. Коли використовувати Drawer замість постійного Sidebar?**

Коли доступний простір обмежений або навігація потрібна лише час від часу, наприклад на мобільному пристрої.

**14. Чим відрізняються sticky та fixed Sidebar?**

Sticky прилипає в межах контексту прокручування та бере участь у потоці документа. Fixed позиціонується відносно вікна перегляду та вилучений зі звичайного потоку.

**15. Як Sidebar впливає на основний контент?**

Він визначає доступну ширину, впливає на компонування, прокручування та можливість комфортно працювати з таблицями, формами й іншими компонентами.

## Senior-рівень

**16. Як визначити інформаційну архітектуру Sidebar?**

Потрібно дослідити користувацькі завдання, згрупувати пов'язані функції, визначити ієрархію та перевірити структуру на реальних сценаріях.

**17. Як організувати Sidebar у продукті з багатьма ролями?**

Потрібно визначити спільні та рольові функції, забезпечити послідовність навігації й не показувати недоступні дії як доступні.

**18. Як підтримувати Sidebar у дизайн-системі?**

Потрібно описати варіанти, стани, ширину, відступи, токени, адаптивну поведінку, доступність та правила використання.

**19. Коли згортання Sidebar може погіршувати UX?**

Коли іконки незрозумілі, користувач втрачає контекст або йому доводиться постійно відкривати підказки, щоб знайти потрібну функцію.

**20. Як перевірити ефективність Sidebar?**

За допомогою тестування типових завдань, спостереження за користувачами, перевірки зрозумілості груп і аналізу помилок навігації.

# 21. Рівні опанування Sidebar

## 🟢 Core

Ти розумієш:

- що таке Sidebar;
- чим він відрізняється від Navbar;
- як організовувати пункти навігації;
- навіщо потрібні групи;

- як працюють відступи та візуальна ієрархія;
- чому потрібна адаптивність.

Практика:

Створи Sidebar для невеликого навчального сайту з п'ятьма пунктами навігації та одним активним пунктом.

## 🔵 Junior

Ти вмієш:

- проєктувати Sidebar для різних продуктів;
- створювати групи й вкладені пункти;
- працювати зі станами;
- проєктувати згорнутий режим;
- використовувати іконки та tooltip;
- створювати адаптивний Drawer;
- застосовувати семантичний HTML;
- перевіряти клавіатурну навігацію.

Практика:

Створи Sidebar для освітньої платформи з групами «Навчання», «Матеріали» та «Налаштування», активним пунктом і мобільною версією.

## 🟣 Middle

Ти вмієш:

- пов'язувати Sidebar з інформаційною архітектурою;
- організовувати складні ієрархії;
- визначати поведінку вкладених груп;
- обирати між persistent, collapsible та overlay;
- враховувати доступність;
- створювати компоненти дизайн-системи;
- тестувати поведінку на різних екранах.

Практика:

Спроєктуй Sidebar і основне компонування для SaaS-застосунку з проєктами, завданнями, звітами та налаштуваннями.

## 🔴 Senior

Ти вмієш:

- визначати навігаційну стратегію складного продукту;
- проєктувати структуру для різних ролей;
- обґрунтовувати рівні вкладеності;
- підтримувати узгодженість між модулями;
- оцінювати доступність;
- перевіряти навігаційні рішення дослідженнями;
- оптимізувати простір між навігацією та контентом.

Практика:

Створи навігаційну систему великої освітньої платформи з особистим кабінетом, курсами, завданнями, матеріалами, профілем і адміністративними функціями.

# 23. Головне, що потрібно запам'ятати

- Sidebar допомагає організувати навігацію в продуктах із великою кількістю розділів.
- Його структура повинна відповідати інформаційній архітектурі та користувацьким завданням.
- Групи допомагають швидше знаходити пов'язані функції.
- Надмірна вкладеність ускладнює навігацію.
- Активний стан допомагає користувачеві розуміти своє поточне положення.
- Іконки повинні бути зрозумілими, особливо у згорнутому режимі.
- Tooltip допомагає орієнтуватися, але не замінює доступної назви.
- Persistent, collapsible, sticky, fixed та overlay описують різні характеристики Sidebar.
- На мобільних пристроях Sidebar часто перетворюється на Drawer.
- Адаптивність потрібно проєктувати разом із основним контентом.
- Семантичні посилання, кнопки, видимий фокус і правильне керування станами є основою доступності.
- Sidebar має залишатися послідовним на різних сторінках продукту.
- У дизайн-системі важливо описувати не лише зовнішній вигляд, а й поведінку компонента.
- Найкращий Sidebar — той, який допомагає користувачеві швидко знайти потрібну функцію, не відволікаючи від основної роботи.

**Основний принцип:** проєктуй Sidebar від інформаційної архітектури та реальних завдань користувача, а вже потім обирай ширину, кольори, іконки, анімації та спосіб згортання.
